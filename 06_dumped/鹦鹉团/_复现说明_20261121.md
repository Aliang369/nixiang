## 2. Lua 链（2026-11-21 逐字节实测）

### 2.1 bundle → chunk

```bash
python3 04_scripts/_common/lua/lua_ab_multiframe.py \
    06_dumped/鹦鹉团/lua_ab/lua_csys_dance.unity3d <输出目录>
```

- 实测：`lua_csys_dance.unity3d` → **127 帧**，解出 127 个 Lua chunk（`<bundle>__000.luac` … `__126.luac`）
- 实测：`__014.luac` 的 md5 = `1ee2e1142a13c551893fd96824b9f3b1`，与 `lua_chunks/` 内同名文件**完全一致**
- 注意：输入必须是 `.unity3d`（LZ4 多帧容器）。喂 `.raw` 会 `frames=0` —— `.raw` 是已解压的拼接体，不含帧头

### 2.2 chunk → 反汇编

```bash
python3 04_scripts/_common/lua/lua53_dis.py <输出目录>/lua_csys_dance__014.luac > lua_csys_dance__014.txt
```

- 实测：输出 206 行，md5 = `e7867bfcecd1ee995c15a259c6390ddf`，与删除前 `lua_chunks/dis/lua_csys_dance__014.txt` **逐字节一致**
- `lua53_dis.py` 直接吃 27 字节变体头（`format=0x01`），**不要**手工改成 32 字节头
- 单包 Lua（`lua_ab/*.raw` 里的整包）走同一脚本，输入换成 `.raw` 即可

### 2.3 文档行号约定

`10_docs/鹦鹉团/` 各篇里的 `014:288`、`015:777-830` 等写法：

- `014` = `lua_csys_dance__014`（chunk 序号，对应 `lua_chunks/` 下的 `.luac` 文件名）
- `288` = **§2.2 生成的那个 txt 的文件行号**，不是 Lua 源行号
- 反汇编头里的 `@source:起-止` 才是 Lua 源码行区间

只要 §2.1/§2.2 两条命令照跑，行号可 100% 复现——这也是敢删 `dis/` 的前提。

## 3. IL2CPP 大表链

```
base/{libil2cpp.so, global-metadata.dat}
   └─ Il2CppDumper ──> il2cpp/dump.cs
                         └─ _parse_dumpcs.py ──> _methods.tsv / _types_index.tsv
```

```bash
python3 06_dumped/鹦鹉团/il2cpp/_parse_dumpcs.py \
        06_dumped/鹦鹉团/il2cpp/dump.cs <输出目录>
```

**输入指纹（2026-11-21 本机）：**

| 文件 | sha256 前 16 位 |
|---|---|
| `il2cpp/dump.cs` | `2f53b55f406b4418` |
| `base/global-metadata.dat` | `df050fd35708a091` |
| `base/libil2cpp.so` | `c4cea4c5c851d77c` |

**重要：旧表与当前 dump.cs 已脱节。** 2026-11-21 用当前 `dump.cs` 重跑，
条数一致（methods 213,927 / types 26,391 量级），但从 dump.cs 第 ~158.7 万行起行号逐段偏移
（最大 +1100 行），说明现存 `_methods.tsv` 是按**另一版** `dump.cs` 生成的。
所以：

- 引用 `_methods.tsv` 行号去 grep `dump.cs` 前，先确认两者是同一版（比对 `dump.cs` 的 sha256）
- 行号属于"生成时那一版 dump.cs"，不是永恒事实；换版本必须重跑并重记指纹
- 这也是这两张表不能入库的第二个理由：一旦输入换了，入库的表就是错的
