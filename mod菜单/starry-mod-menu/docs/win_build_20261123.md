# Windows 出包（星光菜单自身 APK）— 2026-11-23 实测

> 目的：**新会话不必重新摸索**。照本文件三条命令即可出包；工具全部已装好。
> 适用：`mod菜单/starry-mod-menu`（= `starry_link` 软链目标，同一份文件）。
> 边界：本文只讲「星光自身 APK」（`com.starry.magic`）。**注入到游戏包**仍走该游戏
> `scripts/surgical_*.sh`，不要直接安装本文产物。

## 1. 一键命令（推荐）

```bat
cd /d E:\nixiang\mod菜单\starry-mod-menu
scripts\win_build.cmd
rem 需要调试版： scripts\win_build.cmd assembleDebug
rem 需要离线：   scripts\win_build.cmd assembleRelease --offline
```

脚本自动做四件事：

1. 探测 Android SDK（`ANDROID_HOME` → `ANDROID_SDK_ROOT` → `%LOCALAPPDATA%\Android\Sdk` → `%USERPROFILE%\AppData\Local\Android\Sdk` → `E:\nixiang\01_tools\android-sdk`）；
2. 探测 JDK 17（`JAVA_HOME` → `C:\Program Files\Microsoft\jdk-17*` → `...\Java\jdk-17*` → Adoptium → Android Studio `jbr`）；
3. **临时**把 `local.properties` 改成当前机器的 `sdk.dir`（库内那份写死的是 mac 路径）；
4. 构建完成后**还原** `local.properties`（不污染 git）。

产物：`app/build/outputs/apk/release/app-release.apk`（2026-11-23 本机实测 822,908 字节，7 秒）。

## 3. 三个坑（就是「win 出包一直有问题」的真因）

1. **`local.properties` 被 git 跟踪，内容是 mac 路径** `sdk.dir=/Users/aliang/Library/Android/sdk`。
   Windows 上 gradle 会拿这个不存在的路径 → 构建直接失败。
   处理：用 `scripts\win_build.cmd`（自动换 + 还原）；**不要手工提交 Windows 路径**。
2. **`JAVA_HOME` 未设置**。gradlew 在 Windows 上不会自动找 JDK；
   设错路径会报 `JAVA_HOME is set to an invalid directory`（本机第一轮踩过）。
   处理：脚本自动探测；手工时 `set JAVA_HOME=C:\Program Files\Microsoft\jdk-17.0.20.101-hotspot`。
3. **受限环境下环境变量被清空**（例如由 agent/CI 直接 `cmd /c` 调起时 `%LOCALAPPDATA%` 为空）。
   脚本已加 `%USERPROFILE%`、`%HOMEDRIVE%%HOMEPATH%` 回退；仍失败就显式 `set ANDROID_HOME=...`。

## 4. 手工等价步骤（脚本不可用时）

```bat
set "JAVA_HOME=C:\Program Files\Microsoft\jdk-17.0.20.101-hotspot"
set "ANDROID_HOME=C:\Users\Administrator\AppData\Local\Android\Sdk"
rem 备份并改写 local.properties（正斜杠）
copy /y local.properties %TEMP%\lp.bak
echo sdk.dir=C:/Users/Administrator/AppData/Local/Android/Sdk> local.properties
call gradlew.bat assembleRelease --offline
copy /y %TEMP%\lp.bak local.properties
```

## 5. 出包后自检（三项，缺一不可）

1. 文件存在且大小合理（`app/build/outputs/apk/release/app-release.apk`）；
2. dex 里有本次新增上报端点：
   `python -c "import zipfile;z=zipfile.ZipFile(r'...app-release.apk');print(b'/v1/presence' in z.read('classes.dex'))"` → `True`；
3. so 在包里：`lib/arm64-v8a/libstarry_magic.so`。

签名（本机 debug 证书，仅用于自测，注入后会被重签）：

```bat
"%ANDROID_HOME%\build-tools\36.1.0\apksigner.bat" verify --print-certs app-release.apk
```

2026-11-23 实测：`SHA-256 32fb600a861467f0ffcae14e7c8d425cad1b943a7d98cbf26f4776a7e377cb4e`（CN=Android Debug）。
**注意**：这个证书只属于「星光自身 APK」；注入进游戏后的最终包由 `inject_*/surgical_*` 重签，
证书不同。服务端 `CLIENT_CERT_SHA256` 白名单要填**最终游戏包**的证书哈希。

## 6. 与后端（游客统计）的关系

- 本版本客户端新增 `PresenceReporter`：进程启动 8 秒后首报，之后每 5 分钟一次
  `POST /v1/presence`（游客与卡密共用），失败不影响功能；
- 服务端在线窗口 360 秒（`ONLINE_WINDOW_SECONDS`），口径见
  `auth-server/docs/STATS_DEFINITION.md`；
- 出正式包后把证书 SHA-256 配到服务端 `.env` 的 `CLIENT_CERT_SHA256`（逗号分隔），
  可疑上报才会被丢弃。

## 7. 维护约定

- `scripts/win_build.cmd` **必须保持纯 ASCII**：cmd.exe 按 OEM 代码页解析脚本文件，
  UTF-8 中文注释会让后续命令行解析错乱（2026-11-23 实测：`'：mod菜单' is not recognized`）。
- 行尾用 CRLF；改动后跑一次 `scripts\win_build.cmd` 自证。
- 不要把 Windows 的 `local.properties` 提交进库。
