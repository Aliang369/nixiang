## 0. 目标与验收原则

| 项 | 约定 |
|----|------|
| 目标 | `NativeMenuController` **零** `R.color.magic_*` / `R.drawable.magic_*`；注入不依赖宿主 `resources.arsc` |
| 观感 | 与改前 XML 版对照，差异最小化；不接受「系统 Switch / 随便 Path」当交付 |
| 不动 | `MenuService` / 入口架构 / Tab·功能表 / 鉴权 / native hook |
| 扩展 | **只**改 `MagicRes` + `NativeMenuController`（见设计规范 §1.1） |
| 测试 | 星光自测 APK（`starry_self`），**不是**公主连结外科包 |

**对照方式建议**：同一设备先装「改前正式自测包」截图/录屏 → 再装改后包，按下方清单勾项。

## 1. 阶段计划

### 阶段 A — 准备（动手前）

1. 备份到 `99_archive/星光菜单_去资源化前_20260814/`：
   - `NativeMenuController.java`
   - `MainActivity.java`（若有动）
   - （可选）整份 `app/src/main/res/drawable/` + `colors.xml` + vine PNG
2. `Android.mk`：**只开** `-DSTARRY_GAME_SELF`（关掉 `STARRY_GAME_PCR`）
3. 确认后台有 `starry_self` 与自测功能表（见 `原生菜单_星光魔法阵_20260813.md` §2.8）
4. 打一版**改前基线包**留作对照（或沿用现有可装自测包）

### 阶段 B — `MagicRes.java`（集中资源层）

新建 `app/src/main/java/com/starry/magic/menu/MagicRes.java`：

| 区块 | 内容 |
|------|------|
| `C_*` 色常量 | 与 `colors.xml` 14 个 `magic_*` **同 ARGB**（见 §2） |
| `dp(ctx,n)` | 密度换算（圆角/描边与 XML dp 一致） |
| shape 工厂 | 每个现用 drawable 一个方法，参数**照抄 XML** |
| vector/图标 | Path 或 `VectorDrawable` 等价；pathData 从 XML 原样搬 |
| selector | Switch / dropdown 开合态用 `StateListDrawable` |
| 花藤 | `vine(Context)` ← `assets/magic_vine_corner.png` |

### 阶段 C — 改引用（仅资源调用）

`NativeMenuController.java`：

- `color(R.color.x)` → `MagicRes.C_x` 或 `MagicRes.colorX()`
- `setBackgroundResource(R.drawable.x)` → `setBackground(MagicRes.x(ctx))`
- `setImageResource` / `getDrawable` → `MagicRes` 返回的 Drawable
- 删掉/停用依赖 `Resources.getColor(id)` 的旧 `color(int id)`（或改为只服务非 magic，本轮应无残留）

**禁止**：改布局常量（SPACE/ROW_PAD）、改交互、改门控文案、改入口。

### 阶段 D — assets 与工程

1. 复制 `drawable-xxhdpi/magic_vine_corner.png` → `app/src/main/assets/magic_vine_corner.png`
2. XML / 原 PNG **保留不删**
3. 自测工程仍可带 XML（Gradle 打包无妨）；**注入目标游戏时不拷 magic 资源进 arsc**

### 阶段 E — 构建与真机对照（starry_self）

```bash
export JAVA_HOME="$(/usr/libexec/java_home -v 17)"
# Android.mk 确认仅 STARRY_GAME_SELF
cd mod菜单/starry-mod-menu
# 按现有自测/assembleRelease 或 inject_self 脚本出包安装
```

装机后按 **§3 对照清单** 逐项勾。未勾完不算完成。

### 阶段 F — 收尾（对照通过后）

1. 笔记更新交接文档状态 →「MagicRes 已落地 / starry_self 已验」
2. 真机：`cleanup_device_re_residue.sh`（若本轮有 Frida/试装残留）
3. **不**在本轮做 PCR 外科；PCR 另开任务

## 6. 风险与底线

1. **五角星 Switch / 法阵 FAB / Toast 矢量**：必须 path 级复现；做不到先停、问用户，禁止系统控件顶替。  
2. 圆角/描边用 `dp` 换算，避免硬编码 px 导致糊或偏粗。  
3. 改前必备份；正式 PCR 包 `08_output/公主连结/...starry-releaseSigned.apk` **不覆盖**。  
4. 用户逐项勾完 §2–§3 再标「完成」。
