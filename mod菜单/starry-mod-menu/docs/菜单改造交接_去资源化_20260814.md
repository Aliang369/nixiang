# 星光菜单 — 去资源化改造交接（2026-08-14）

> **本文档给接手的新 AI**：改造目标 + 菜单现状 + 背景约束 + 相关文档索引。改造动机是公主连结 11.7.2 校验卡点，但方向同时让菜单更通用（对比 LGL）。

---

## 1. 为什么改：公主连结卡点（背景，必读）

- 官方 11.7.2 带 **腾讯 TSS（libtersafe2/libtprt）+ ACE 反作弊**，会校验 `classes4.dex`、`classes8.dex`、`resources.arsc`，改动后 **signal 7 (SIGBUS) 自杀**（2026-08-14 实装实测确认）。
- 已确认两条校验路径：① `App extends AceApplication` → native `initialize(sourceDir)`；② `libil2cpp/libunity` DT_NEEDED 依赖 `libtprt.so`，Unity 加载即校验（与应用无关）。
- **唯一能过的路线 = 外科组装**：官方受保护文件字节级保留，只增不改（新增 classes13.dex / so / assets / 改 manifest）。**所以菜单必须不再依赖 `resources.arsc`** → 去资源化。
- 完整分析：`10_docs/公主连结/公主连结_11.7.2_TSS-ACE校验定位与探针实验_20260814.md`
- 落地路线：`10_docs/公主连结/公主连结_11.7.2_外科组装落地路线_20260814.md`

## 2. 菜单现状（2026-08-14 结案）

**菜单视觉 100% Java**：`NativeMenuController` + `MagicRes`（色常量 / GradientDrawable / Path / 花藤 WebP q90 base64）。  
`res` 下已无 `magic_*`；assets 无花藤（仅鉴权证书）。  

**以后扩展**：只改 `MagicRes` + `NativeMenuController`，见 `设计风格美术规范.md` **v2.3 §1.1**。禁止再加 drawable/XML/arsc。

---

## 3. 改造目标：去资源化（已完成）

菜单不再引用任何 `R.drawable.*` / `R.color.*`，注入变成与游戏资源表完全解耦的"**加 dex + so + manifest**"三件套。

| 原资源 | 替代方案 | 观感影响 |
|--------|----------|----------|
| 14 个 `R.color.magic_*` | `MagicRes.java` 里 `int` 常量 | 完全一致 |
| 形状 drawable（bg/按钮/输入框/分隔线/下拉/Tab） | `MagicRes` 代码生成 `GradientDrawable`/`StateListDrawable`（参数照抄 XML） | 完全一致 |
| vector 图标（toast 对勾/星星/叉、下拉箭头、关闭） | 代码 `Path` 绘制，或转 PNG 走 assets | Path 可能略糙；PNG 则一致 |
| Switch 五角星滑块/轨道 | 代码 `StateListDrawable` | **可能退化**用系统 Switch（五角星代码化难） |
| 花藤 PNG（72KB） | WebP q90 → `MagicRes` base64 内嵌 | 观感一致，无 assets |

**base64**：原 PNG b64≈97KB 超 dex 单串 64KB；压成 WebP q90 后 b64=44740，可单串内嵌（已落地，见 §3.1）。

### 3.1 花藤体积优化（2026-08-14）

源 PNG（74KB）归档：`99_archive/星光菜单_花藤原PNG_20260814/`。

| 方案 | 体积 | 状态 |
|------|------|------|
| 原 PNG assets | 74KB | 已弃用 |
| WebP q90 assets | ~34KB | 过渡用过 |
| **WebP q90 base64 内嵌** | raw ~34KB / b64 **44740** | **现行** `MagicRes.VINE_WEBP_B64` |

运行时：`Base64.decode` → `BitmapFactory.decodeByteArray`。无 assets 花藤、无 arsc。b64 单串 < dex 64KB 上限。

## 4. 架构对比（为什么这是方向性改动）

| | 星光（现状） | LGL（典型） | 星光（去资源化后） |
|---|---|---|---|
| 核心形态 | smali + native so + **资源** | 纯 smali | smali + native so |
| 功能来源 | native hook（Dobby，改 `get_deltaTime`/内存特征） | smali 改值/判断 | 不变 |
| 资源 | 动 arsc（脆弱，公主连结卡死点） | 代码 UI，无/少资源 | 无资源 |
| 鉴权/签名绕过 | 有（卡密+SignSpoof+RootBeer） | 无 | 不变 |
| 移植量 | 重（资源合并+签名+每游戏 hook） | 轻 | 中（仍要 per-game hook + 签名，但无资源负担） |

**结论**：去资源化一石二鸟——过公主连结校验 + 菜单模板更通用（接近 LGL 的易移植性，仅保留 native so 这一功能形态差异）。

## 6. 执行提示（给新 AI）

> **⚠️ 分层澄清（2026-08-14）**：本次菜单改造**只做去资源化**，不改菜单工程入口架构（`MenuService`/`NativeMenuController`/通用入口机制保持原样，各游戏仍按各自 inject 脚本挂入口）。
>
> **公主连结入口特殊性 → 属于公主连结打包脚本的专项，不属菜单改造范围**：正式整包流程动了两个受保护文件，其中一个是 `classes4.dex`（`PermissionActivity.smali` 就在 smali_classes4，inject 脚本改它 onCreate 会死）。公主连结的**专用外科组装脚本**需改用路径①已验证的方式：`StarryApp`（放 classes12/13）+ Manifest `application:name` 换名，在 StarryApp 里做 `SignSpoof.install()` + `loadLibrary("starry_magic")` + `MenuService.start()`，**不要改 PermissionActivity/UnityPlayerActivity 的 smali**。参考 `闪退定位_dex完整性_20260813.md` 路径①探针（活）。

1. 新建 `app/src/main/java/com/starry/magic/menu/MagicRes.java`，集中生成全部颜色常量/形状/图标，`NativeMenuController` 约 50 处 `R.*` 引用改为调用它。**只改资源引用，不动入口/菜单架构。**
2. 花藤：WebP q90 base64 内嵌 `MagicRes`（见 §3.1）；assets 不再放花藤。
3. **公主连结专用外科组装脚本**（独立于菜单工程）：官方 classes.dex~12 + arsc 字节级保留；`01_tools/smali/smali-2.5.2.jar` 编 `classes13.dex`（全部 com/starry smali）；MT APK MCP 只改 manifest（`application:name` 换 StarryApp + 加权限 + 注册 MenuService）；加 so/assets；重签（注意 <2G、arsc 必须 STORED、header.size 自洽）。**勿用 `apktool b` 整包**（重编 arsc 必死）。
4. `Android.mk` 已启用 `STARRY_GAME_PCR`；现有 `scripts/inject_pcr_11.7.2.sh` 是整包流程（改 classes4 + 重编 arsc，不适合公主连结，勿直接用）。
5. 干净装测试：`pm uninstall` 后再装；真机残留清理 `04_scripts/_common/cleanup_device_re_residue.sh`。

### 6.1 MagicRes 与 dex 数量（澄清）

`MagicRes.java` **不会**多出一个 dex。它只是 `com.starry.magic.menu` 里多一个类，和 `NativeMenuController` 等一起进**同一套**星光 smali。

| 场景 | dex 怎么算 |
|------|------------|
| 菜单工程自测 APK（Gradle） | 仍由 R8/multidex 决定，与有没有 `MagicRes` 无关 |
| 注入目标游戏（常规 / PCR 外科） | 全部 `com/starry/**`（含 MagicRes）编进 **一个** 新增 dex（PCR 约定 `classes13.dex`） |
| 不会变成 | 「MagicRes 一个 dex + 其它菜单一个 dex」 |

移植件仍是：**1 个星光 dex + so + assets + Manifest**（宿主原有 dex/arsc 不动）。
