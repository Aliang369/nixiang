## 0. 工具选型总则

```
有强反调试/反 Frida（ACE/易盾新版/王朝版等）
  → 别上 Frida，用自注入 libstarry_magic.so Trace
无壳 / 无强反作弊
  → 可短探针用 Frida + dexdump

  → 按下面工具链，脱壳优先级：无损黑盒 > 主动调用 > 内存 dump
```

## 1. DEX 脱壳工具

### 1.1 frida-dexdump（秒级 dump，最常用）

- **适用**：大多数整体加密壳（百度、易盾旧版等）
- **用法**：
  - `attach` 模式：游戏已启动后 dump（部分壳已还原 dex）
  - `spawn` 模式：游戏启动时 dump（易盾新版 / 部分壳需要在 `application` 前）
- **坑**：
  - 只 dump 到「已被 ART 加载的 dex」，未触发的不出来 → 先跑到目标代码再 dump
  - **二代/三代壳**（native OpenMemory 还原）可能 dump 不干净 → 内存搜 `dex\n035\0` 兜底
  - 反 frida 游戏 dump 会崩 → 换自注入或冻住检测点

### 1.2 FART（主动调用，最全但重）

- **适用**：抽取加固、函数级抽取；逼壳逐方法还原后 dump
- **坑**：
  - 需要重新打包插桩，工程量大
  - 部分壳检测主动调用（行为异常）→ 崩溃
  - 产物是「方法级 dump」，还要**合并修复**成完整 dex

### 1.3 BlackDex（轻量，同 frida-dexdump 思路）

- **适用**：整体加密壳，一键 dump
- **坑**：只读已加载 dex；强壳 dump 不全；某些旧版本与 Android 版本不兼容

### 1.4 Youpk / HaiKun（主动调用类）

- **适用**：抽取加固、VMP 外层的函数级抽取
- **坑**：需要 root + 自定义 ROM（miui 等）适配成本高；本工作区未采用

### 1.5 内存搜 dex magic（兜底）

- **思路**：`dump /proc/<pid>/mem` 或 Frida Memory.scan 搜 hex `64 65 78 0A 30 33 35 00`（`dex\n035\0`）
- **适用**：frida-dexdump 失败或强壳 dump 不全的兜底
- **坑**：拿到的 dex 是「运行时态」，头/结构可能被 ART 改过 → 需修复

## 2. so 脱壳 / dump 工具

### 2.1 dumpso / Frida dump

- **适用**：so 整体加密壳（运行时解密后 dump）
- **用法**：从 `/proc/self/maps` 里读 so 段，dump 出解密后的 r-x 段
- **坑**：
  - mprotect 反 dump（PROT_EXEC 无 PROT_READ）→ 需要 root 改权限或模拟执行
  - dump 出的裸段缺 ELF 动态结构 → 只能静态挂 IDA 读，不能直接替换使用
  - 要和「so 自校验」区分：dump 出来 ≠ 能重打包（先评估签名/完整性绑定）

### 2.2 unidbg（模拟执行跑壳）

- **适用**：不接真机，在 PC 模拟 so 的 loader/解密过程
- **坑**：
  - 依赖 so 的 JNI 环境模拟（有些 so 反模拟执行）
  - 学习成本高；本工作区倾向真机自注入，unidbg 仅备选

## 3. dex 修复工具

### 3.0 基础反编译工具（先会用 baksmali 再说脱壳）

> 定位：脱壳前后都要「读字节、看源码、改 smali」，这几件是地基，别只会 jadx。

| 工具 | 用途 | 关键坑 |
|---|---|---|
| `apktool d` | 解开 APK 到 smali/资源（**只解不重建**） | 本工作区**禁 `apktool b` 整包重建**（雷霆战机教训：重建即破坏 v2 Signing Block / arsc 字节） |
| `baksmali.jar` | `dex → smali` 反汇编 | 主要看壳的 stub / `Application` 类怎么拉起壳 |
| `smali.jar` | `smali → dex` 回编 | 只回编**单个 patch dex**，不整包回编 |
| `dex2jar` + `jd-gui` | `dex → jar` 快速看源码 | 加壳后的 dex 常反不出（stub 空壳），先脱壳再上 |
| `readelf` / `objdump` / `llvm-readobj` | 看 ELF 头、段、dynsym、PLT/GOT、重定位 | 属**nux binutils**；`readelf -d` 判「是否壳 so」、`-s` 看符号、`--string-dump` 看字符串；OLLVM/脱壳 so 的段结构关键 |
| `zipalign` / `apksigner` | 压缩对齐 / v1-v4 签验 | 组装后 `apksigner verify --verbose` 必跑（看 v2 块坏没坏） |

### 工作区禁令（写死）

- ❌ 禁 `apktool b` 整包重建 → 只走**外科 zip 组装**（AGENTS 铁律 1；雷霆/王国 sign块破坏实锤）
- ❌ 禁 patch 后不验签就装机 → 每次组装后必跑 `apksigner verify --verbose` + `zipalign -c 4`

### 3.1 dexfixer / 相似补偏移工具

- **适用**：dump 出的 dex 修复 `code_item` / `class_def` 偏移
- **坑**：
  - 修不好反编译结果会「方法体错乱 / 交叉引用断」→ 别误判为脱壳失败
  - 本工作区原则：**能用「新增 dex」就不碰修复**（修复产物风险高）

### 3.2 jadx / GDA / JEB

- **定位**：jadx（免费快）、GDA（国产快）、JEB（付费，VMP 分析最好）
- **坑**：VMP 函数体在哪 jadx 都是解释器帧，切 JEB 也无解 → 绕不还原

## 4. IDA / Ghidra

- **IDA**：so 静态分析主力（控制流、交叉引用、字符串）
- **Ghidra**：免费替代，反编译质量可
- **坑**：
  - OLLVM 混淆函数 → IDA 图爆炸，先找「没有被混淆的关键调用」或切动态
  - dynsym 破坏（雷霆）→ 符号名不可信，用 `dlopen+dlsym` 拿运行时地址

## 5. 动态分析（本工作区核心路径）

### 5.1 自注入 `libstarry_magic.so` Trace

- **地位**：铁律第一优先，适用于强反调试/反 Frida 游戏
- **用法**：把 hook/日志编进自注入 so，走正规 `loadLibrary` 动态库链进去
- **坑**：
  - so 加载时序要卡在 `JNI_OnLoad` 之后、目标函数被调用前
  - 别用 ptrace（蜀汉传实锤加速死亡）

### 5.2 Frida / phantom（短探针，兜底）

- **适用**：无壳 / 无强反作弊的短平快验证；分级路由见 TOOLBOOK「Frida — 动态 Hook（使用矩阵）」（强检测=自注入唯一路线 / 其余=phantom-frida 短时探针，被杀立即撤回走 so）
- **phantom 实测定性**（2026-09-10 静态特征计数，`01_tools/phantom-frida/`）：~90 补丁/16 检测向量——`frida:rpc`/`frida-agent`/`frida-server`/gum-js-loop/gmain/`frida_agent_main` 全清零，端口随机化非 27042；残 GLib 内部串（re.frida.Error 域名/gdbus 源码引用）非检测主路径；与客户端 17.16.4 原生匹配。仍是症状级对抗，中级/高级行为检测不保证
- **坑**：
  - 反 frida（`re.frida` 文件、D-Bus、inline hook 行为特征）→ phantom 不能保证过，被杀即走自注入
  - 用完即清残留，别常驻

| IDA/Ghidra | so 静态 | OLLVM/符号破坏 | ✅ |
