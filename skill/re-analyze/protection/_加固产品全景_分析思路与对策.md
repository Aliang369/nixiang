## 1. 360 加固（奇虎加固保）📚

### 识别特征
- so：`libjiagu.so` / `libjiagu_x86.so`（x86 包）/ `libjiagu_art.so`（新版 ART）
- Stub Application：新版 `com.stub.StubApp`，旧版 `com.qihoo.util.StubApp`（**两个都查**，只认旧版会漏判）
- classes.dex 只有壳 stub；真 dex 加密藏在 so / assets
- 死法味道：改 dex 即死（一代整体加密）；企业版有 native 签名校验，重签死

### 校验点清单
dex 整体加密（一代）/ 方法抽取（高级版）●｜VMP（顶级版）◐｜so 自身 OLLVM 混淆 ●｜签名校验（企业版 native 读签）◐｜反调试（ptrace 占坑）●｜反 Xposed/hook ●｜反模拟器/反多开 ●｜风控上报 ○

### 分析思路
1. 拆包对号（so + stub 双特征）→ 判版本：免费版一代壳，企业版才要怕签名校验
2. A/B 起手：零改动重签基线 → 加 dex → 改 dex，圈出校验面
3. 脱壳：frida-dexdump / **BlackDex（免 root，对 360 一代壳效果好）** / FART；新版防 dump（InMemoryDexClassLoader 不落盘）→ /proc/pid/mem 手工兜底（总纲 §一.5）
4. libjiagu 自身 OLLVM，**别啃壳**，hook 业务层落点

### 解决方案 + 坑
- 默认路：壳链完全不动，新代码放新 dex（连续加载规则）
- 企业版签名校验：先 SignSpoof 试 PM 路径；不行则 IDA 定位 native 读签点
- 坑：jiagu 有 ptrace 占坑，外部 frida attach 会加速死 → 自注入
- 状态：⚠️ 本区未实机 360（stub 双包名纠错已吸收进 knowledge/_05）

## 2. 梆梆 Bangcle / SecNeo 📚

### 识别特征
- so：`libDexHelper.so` / `libDexHelper-x86.so`
- Stub 包名带 `secneo` / wrapper 字样（`com.secneo.*` 系）
- assets 有伪装成 jar 的加密 dex（classes.jar 类文件）
- 死法味道：改 dex 死；重签死（native 读签）；企业版抽取壳静态方法体空

### 校验点清单
dex 整体加密 ●（免费版）/ 方法抽取 ◐（企业版）/ VMP ◐（旗舰版）｜签名校验 ●（防二次打包）｜反调试 ●｜反模拟器 ◐｜风控上报 ○

### 分析思路
1. 对号后先判免费版/企业版：jadx 看业务方法体在不在（不在 = 抽取/VMP，别白费 dump）
2. 脱壳：frida-dexdump 常用；抽取壳走 FART；多 dex 拆分加密 → **dump 完要合并修复**（class_def 补全）
3. 签名校验在 native → 交叉引用搜证书/zip 结构特征定位（总纲三板斧）

### 解决方案 + 坑
- 壳链不动 + 新 dex 外挂（默认路）
- 抽取壳业务要改：FART dump → 修复 → 内存 hook 兜底
- 坑：梆梆多 dex 拆分，只 dump 到主 dex 不够，按 dex 数量核对
- 状态：⚠️ 本区未实机

## 3. 爱加密 Ijiami 📚（IL2CPP 形态 ✅ 无限升级）

### 识别特征
- so：`libexecmain.so` / `libexec.so`
- assets：`ijiami.dat` / `ijiami.ajm`
- Stub 包名带 `com.shell.*` 📚
- **IL2CPP/Unity 形态**（本区已实锤）：HTPX 加密 metadata（头 8 字节水印、主体明文）+ bundle blocksInfo 混淆 + so 剥符号 + ACTk/Themis 反作弊

### 校验点清单
dex 整体加密 ●｜VMP ◐（企业版）｜签名校验 ●｜反调试（fork 占坑）●｜反模拟器 ●｜IL2CPP metadata 加密 ●（Unity 包）｜风控上报 ◐

### 分析思路
1. 先分「传统 dex 形态」还是「IL2CPP 形态」（拆包看有无 libil2cpp/global-metadata）
2. dex 形态：dump 常规路
3. IL2CPP 形态：**不碰磁盘密文**——/proc/pid/mem dump mmap 段拿明文 metadata，修头后 Il2CppDumper 可读 ✅无限升级
4. so 剥符号 → dynsym 自解析（总纲 §二符号隐藏行 + ace-tss.md 终末地案例同源手法）

### 解决方案 + 坑
- IL2CPP：运行时 dump 三件套（metadata 明文 / 热更 dll 堆搜 BSJB / bundle 内存绕过）✅
- dex：壳链不动 + 新 dex
- 坑：爱加密反模拟器较凶，调试尽量真机
- 状态：✅ 无限升级（IL2CPP 形态，产品手感看工作区无限升级档案）；dex 形态 ⚠️ 未实机

## 5. 网易易盾 nesec 📚（重建路线 ✅ 无悔华夏）

### 识别特征
- so：`libnesec.so` + `libprotectClass.so`
- Stub：`com.netease.*` 系壳类 📚
- 死法味道：旧版重签可活；**新版重签静默死**（签名绑密钥）

### 校验点清单
dex 整体加密 ●｜签名绑定（密钥掺进解密链）●（新版）｜反调试 ●｜反 frida ●（新版）｜风控上报 ◐

### 分析思路
1. 先测「旧版/新版」：零改动重签基线。活着 = 旧版路；死了 = 新版签名绑密钥
2. 新版别死磕回灌——解密密钥与签名绑定， spoof 签名也解不出真 dex
3. 走**脱壳重建**：dump 全量 dex → 修复 → 剥壳重打无壳包（壳没了校验链也没了）
4. **新版推荐路线（4399 实机 2026-09-14）**：先查业务 ClassLoader 是否持有 `InMemoryDexFile`。是则按 `mCookie -> DexFile* -> begin_/file_size` 精确导出，不依赖内存搜 dex magic；随后用运行时完整基准包重建无壳 APK。

### 解决方案 + 坑
- ✅ 通用方法：[nesec-inmemory-dex.md](nesec-inmemory-dex.md)（InMemoryDexFile 精确脱壳 + 无壳重建；4399 七功能实机通过）
- 坑：重建后官方壳组件残留要清干净（Application 类名、provider 挂回真实业务）
- 状态：✅ 无悔华夏 4399 `7.6.1_857` 实机全链；好游快爆可直接按该方法重启；其余 NIS 包先验是否存在 InMemoryDexFile

## 10. 商业保护器四家（非国产壳系）📚

### DexGuard（Guardsquare）
- **不是壳，是混淆器**：无 stub、无加密 dex。特征 = 明文字符串全消失、类名 a/b/c、大量反射调用 + `javax.crypto`
- 分析：静态还原费劲 → 动态 hook 运行时解密值；关键在跑起来后内存里拿真值
- 状态：⚠️

### DexProtector（Licel）
- 商业加密：**无 Stub Application**（区别国产壳的最大特征）；assets 加密 dex + 白盒密码学
- 识别陷阱：Application 类名正常但 jadx 方法体全空 → 别误判「没加固」
- 分析：内存 dump（加载后即明文）；白盒密钥别硬抠
- 状态：⚠️（knowledge/_05 纠错记录：与百度无任何关系）

### Virbox Protector（深思数盾）
- 商业保护：so 层加壳 + VMP + 授权锁（加密狗/云授权）为主，游戏/工业软件常用
- 分析：授权锁是死结 → 先看授权形态；so 壳走内存 dump + SoFixer 修复
- 状态：⚠️ 识别细节未经实机，以 so 名 + 授权弹窗为准

### 顶象 / 通付盾 SecShell
- 顶象：风控为主（DXRisk），加固为辅 → 按阿里系打法
- 通付盾：dex 加密壳，识别以 so/包名 secshell 字样为准
- 状态：⚠️ 未实机，特征库薄，命中后回流
