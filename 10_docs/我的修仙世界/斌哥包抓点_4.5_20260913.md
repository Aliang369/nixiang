## 3. 菜单开关链

Java 侧原生方法：

```java
public static native void Changes(Context ctx, int featNum, String key, int intValue, boolean enabled, String extra);
```

壳 native 配置分发函数把 `featNum` 映射到 BSS：

| featNum | 菜单功能 | BSS 旗标 |
|---:|---|---|
| 0 | 百倍伤害 | `0x16A04C0` |
| 1 | 玩家无敌 | `0x16A04C4` |
| 2 | 货币无限 | `0x16A04C8` |
| 3 | 诊断日志（隐藏，不是用户三项功能） | `0x16A04CC` |

补充事实：

- 首次配置调用有 `0x16A0680` sentinel，第一次调用只做初始化，不写功能旗标。
- 真机基线检查时四项均为 0，功能默认全关。
- 壳自查通过后 `0x16A0514=1`，表示 Hook 已安装；当前真机实测该字节为 1。
- 菜单第三项“货币无限”虽然日志名没有单独打印，但 `featNum=2` 明确写入 `0x16A04C8`，而该字节只被货币链使用。

## 4. 三项功能语义

### 4.1 百倍伤害

- 目标方法：`BattleMgr.HurtShow`
- 官方签名：

```text
void HurtShow(CreatureControl atk_target, CreatureControl be_atk_target, long hurt,
              E_Hurt_Type e_Hurt_Type, int buffid, int type = 0)
```

- RVA：`0x1437D24`
- 开关：`0x16A04C0`
- 行为：
  - 只处理 `be_atk_target` 是敌方目标的情况。
  - 若目标类等于 `PlayerControl`，不放大。
  - 若目标类等于 `WorldBossControl`，不放大。
  - 其他目标把 `hurt` 乘 100。
  - `hurt > 10000000000` 时封顶到 `1000000000000`；结果小于等于 1 时改为 1。
  - 最后必须调用原 `HurtShow`。
- 结论：这是“对非玩家、非世界 Boss 目标的 100 倍伤害”，不是直接改攻击力，也不是全屏秒杀。世界 Boss 被排除是斌哥自带的降风险设计。

### 4.2 玩家无敌

- 目标方法：`CreatureControl.ReduceCreatureSpNum`
- 官方签名：

```text
void ReduceCreatureSpNum(CreatureControl atk_target, E_CreatureSpNum e_ReduceNum, long value)
```

- RVA：`0x1287E9C`
- 开关：`0x16A04C4`
- `E_CreatureSpNum`：`BaTiNum=1`、`ShieldValue=2`、`NowHp=3`
- 行为：
  - 只在 `e_ReduceNum == NowHp (3)` 时判断。
  - 只在 `this` 的运行时类是 `PlayerControl` 时生效。
  - 生效时直接返回，不调用原函数，也就是吞掉这次玩家当前 HP 扣减。
  - 其他情况必须调用原函数。
- 结论：这是“玩家本体当前 HP 扣减拦截”，不是把 HP 字段锁成大数。宠物、伙伴、护盾值和其它非 `NowHp` 路径不保证覆盖。

### 4.3 货币无限

货币链不是单点改数值，而是四段组合：

1. `BagDataMgr.GetMoneyId(E_ItemSubType)`，RVA `0x1238808`
   - 调用原函数，读取返回 `IntRand.realNum`（`IntRand` 字段：`numA@0x10`、`numB@0x14`、`realNum@0x18`）。
   - 把货币 itemId 缓存进本地白名单，最多 48 个。
2. `BagDataMgr.GetItemNum(int itemid, int favornpcid = 0)`，RVA `0x1239104`
   - 调用原函数。
   - 开启货币无限且满足以下条件时进入修补：
     - `itemid > 999999`，或 `itemid` 已在 `GetMoneyId` 白名单；
     - 返回的 `LongRand.realNum`（`LongRand` 字段：`numA@0x10`、`numB@0x18`、`realNum@0x20`）为负值。
   - 进入修补后调用 `LongRand.SetValue(long)`，把该值的 `realNum` 置 0。
3. `BagDataMgr.CheckConsume(List<ItemInfo>)`，RVA `0x123B858`，固定 RVA 兜底钩子
   - 开启货币无限时调用原函数。
   - 返回的 `IntRand.realNum` 非 0 时改写为：
     - `numA = 0x4D2`（1234）
     - `numB = 0xFFFFFB2E`（-1234）
     - `realNum = 0`
   - 这是壳日志里“把不足判据改成够”的实际位置。
4. `LongRand.SetValue(long)`，RVA `0x144BBA4`
   - 不靠方法名选重载，直接按固定 RVA 使用 long 版。
   - 同名 int 重载在 `0x144C198`；壳自己的自检也提示按名取到 int 重载属于重载陷阱。

结论：斌哥的“无限货币道具”核心是让消耗检查 `CheckConsume(List<ItemInfo>)` 返回“够”，再用 `GetItemNum`/`GetMoneyId` 修补货币显示与白名单，不是直接把存档货币字段写成大数。

## 5. 斌哥自带反封号/反检测

| 目标 | RVA | 斌哥做法 | 作用 |
|---|---:|---|---|
| `BaseDataMgr.GgSet()` | `0x132BED0` | 直接空实现，不调原函数 | 阻止写永久封号标记；`EncryptBaseData.dfdog` 位于 `+0x51` |
| `EncryptPlayerDataMgr.CheckZuoBi()` | `0x122AF80` | 恒返回 false | 让本地作弊检查不成立 |
| `UnityEngine.Application.Quit()` | `0x26E0120` | 默认记录调用点，只有隐藏诊断旗标 `0x16A04CC` 为真时才吞掉退出 | 默认不硬拦退出，保留系统级 kill switch |

壳内还明确记录了本地存档检测面：

- `BuildPassCheckInfo`：命中时让对象 NULL。
- `属性战力检测`：对照 RVA `0x13F8xxx/0x13F9xxx`。
- `UpdatePower` / `DailyDataMgr.GG`：`0x1320F78~0x13214A4` / `0x1333970`。
- 时间回拨：`0x13340A0`。
- 加密值不变式破坏：`0x144FCxx`。

当前没有证据证明这款游戏有服务端战斗结算或服务端货币权威。已确认的检测面主要是本地 `EncryptPlayerDataMgr` 存档、hash 和封号标记链；TapTap SDK 负责登录、合规和统计，是否还有上报需要官方包复核。

## 6. 稳定性与异常兜底

斌哥壳的自保逻辑可以复用到星光实现：

1. 启动后等待约 7 秒再解析 IL2CPP 方法，避开 Unity 初始化早期窗口。
2. 所有方法先按 `Assembly-CSharp.dll` / `UnityEngine.CoreModule.dll` + 类名 + 方法名解析，再用 RVA 校验身份。
3. 用 `HurtShow` 的 methodPointer 反推 libil2cpp 基址，并检查低 12 位页对齐；不对齐直接放弃挂功能钩子。
4. 任一方法缺失、RVA 不符或 `PlayerControl` 解析不到时，不挂三项功能钩子；只保留安全网，避免版本错配闪退。
5. `WorldBossControl` 缺失不阻断全部功能，只放弃世界 Boss 排除逻辑。
6. 所有 Hook 在非目标分支必须调用原函数。
7. 伤害乘法带溢出上限和最小 1 点保护。
