## 2. 观察、解释与候选经验

- 观察事实：①游戏 `extractNativeLibs=false`（so 不解压、从 base.apk 内映射），实测运行进程 `/proc/<pid>/maps` 中 0 行含库名 `libcocos2djs`（映射行只显示 `…/base.apk`）；②`isLibraryLoaded()`（maps strstr）永假 → 引擎检测/等待循环 120s 超时 → hook 从未安装（splice=0）；③改用 xdl 回退后 `cocosjs=1`、检测通过；④`DobbySymbolResolver("libcocos2djs.so",…)` 对内嵌库返回垃圾指针（fault addr 高位为字符串 ASCII）→ DobbyHook SIGSEGV；⑤`xdl_open`/`xdl_sym`（getSymAddress）对内嵌库工作正常。
- 拟提炼经验（带前提）：
  1. **判定**：外科包/原包 `lib/*.so` 以 STORED 方式存在且 Manifest `extractNativeLibs=false` 时，凡基于 `/proc/self/maps` strstr 找库名的检测（isLibraryLoaded、getLibraryAddressFromMaps、引擎等待循环）在该游戏上必然失效。
  2. **动作**：maps 检测失败后回退 `xdl_open(name, XDL_DEFAULT)`（linker 对内嵌库记 `base.apk!/lib/<abi>/<name>.so`，可后缀匹配）；符号解析用 `getSymAddress`（xdl_sym），不用 `DobbySymbolResolver`；若坚持用解析结果进 DobbyHook，先做库基址 ±256MB 范围校验。
  3. **预期**：检测/hook 链路对内嵌库游戏可用；无害回退（xdl 未命中再走原逻辑）。
- 适用范围：Android arm64，bionic linker，xDL 在库的星光工程；任何 extractNativeLibs=false 游戏。
- 不适用/例外：extractNativeLibs=true（so 已解压）游戏 maps 直查本来就好；xdl 版本差异未验证。

## 3. 反证、失效与最小区分实验

- 反例预测：若某 ROM 的 linker 对内嵌库 dlpi_name 不含库名后缀，xdl 回退也会失败——表现为回退后仍 cocosjs=0。
- 失效条件：xDL 库变更、linker 行为变更、游戏改回 extractNativeLibs=true。
- 最小区分实验：同一游戏内对比 maps 直查 vs xdl 回退的 isLibraryLoaded 返回值（本轮已做，单变量）。
- 停止条件：回退后仍失败即换 dl_iterate_phdr 自实现，不再堆尝试。
