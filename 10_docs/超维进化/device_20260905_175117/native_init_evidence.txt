静态还原（不是运行时 trace）
1. cocos_jni_env_init 日志 @0x717b60；随后 GetJavaVM；vm非空调用0x16d5100。
2. 0x16d52e8同步调用sub_16d16ac，早于RegisterNatives、监控线程创建。
3. sub_16d16ac从GZQYActivity.appContext取得PackageManager，getPackageInfo(name,0x40)，读取signatures，第0项toByteArray。
4. 字节循环初始a=1,b=0；a=(a+unsigned_byte)%65521；b=(b+a)%65521；结果=(b<<16)|a。
   0x16d1d90..1dbc的位运算化简为OR：两次与同一常量异或再异或消去常量，最后(X XOR Y)|(X AND Y)=X|Y。
5. 0x16d1704保存比较表指针，长度0xc；0x16d2294..22c0比较index<12/4。
   0x16d20d0..20f4做table[index]==Adler32。未命中经0x16d1fa0递增索引。
6. 命中：状态0x03b1d03e -> 0x16d22f0 -> 0x16d1ad4 -> 0x16d1ff8。
   读取global@0x1cd3090；若为0，经0x16d2274/22c8写入当前校验值；不为0则跳过写入。
   两支均到0x16d2260，设matchFlag=[sp+0x14]=1。
7. 遍历3项无命中：状态0x1085d19a -> 0x16d20fc -> 0x16d2178 -> 状态0xa49f537a -> 0x16d22e0，设matchFlag=0。
8. 清理路径0x16d21d8..225c：
   tmp=(~matchFlag)|0xfffffffe;
   pass=(tmp!=0xffffffff)=(matchFlag&1);
   [sp+0x10]=pass。
9. 0x16d1f44..1f78：pass&1非零 -> 状态0x6142343b -> 0x16d1e68/1e74 -> 正常epilogue 0x16d23b8。
   pass&1为零 -> 状态0x2b6bc709 -> 0x16d1b2c -> mov w1,#9 -> sub_16ebdf8。
   签名数组长度<=0也会保留pass=0并进入上述退出判定；JNI异常/空对象另论，不假定可靠恢复。
10. sub_16ebdf8先把w0清零，再x8=129、svc #0。AArch64 Linux __NR_kill=129，因此为kill(0,9)，而非kill(getpid(),9)。

混淆谓词依据
相关分派反复使用32位x*(x-1)最低位=0的恒等式。
例如0x16d2178: (x*(x-1) XOR 0xfffffffe) AND x*(x-1) = 0；
于是由比较y>9与该恒真/恒假值组成的(XOR/OR/NOT)表达式恒真，0x16d21d0选0xa49f537a。
0x16d20fc、0x16d22f0使用的加减常量相消，也归约为同一偶数乘积恒等式；并非读取设备状态的有效限制。
本次为指定相关块人工符号化简，未执行整个ELF，未开展全库扫描或全反汇编。

结论
原证书0xd18450ce命中表[0]：该同步签名门禁放行。
Starry证书0xbbfa5bea不在三项表：该同步签名门禁进入kill(0,SIGKILL)。
可确认原证书放行、这份Starry自签证书退出；不泛化为所有自签证书，也不代表原包能通过后续所有检查。
