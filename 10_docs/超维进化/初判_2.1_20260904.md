## 装机实测结论（2026-09-05，卡死 — 暂缓）

**现象**：星光包与原包（仅换签）装机后，游戏正常显示约 2 秒（Splash GIF/动画），随后白屏卡在中间 icon，进程每 0.5s 被系统 SIGKILL 后重启，陷入死循环。较真：**换签原包也卡死**，故与星光注入无关，是游戏本身的重包校验。

**已排查排除**：
- Java/DEX 层签名校验：`com/grinning/**` 里 `getPackageInfo/getSign` 仅 [Util.getSignature](file:///Users/aliang/Documents/nixiang/03_decompiled/超维进化/jadx_2.1/sources/com/grinning/game/utils/Util.java)（只给 SDK 传值，非校验）与 AdvertisingIdClient（广告 ID）
- JS 层（game.js 2.1MB）：`getSign/signature/verify/篡改/校验` 全部零命中
- 否认三连需修正：**不是"无校验"，是校验点不在常规位置**
- 卡死进程主线程：`libcocos2djs.so` 已加载（classes3.dex 加载），无 Java 崩溃、无 tombstone、无 ANR 记录（无 Choreographer 跳过帧）

**可疑点（未定论，下次优先查）**：
1. **GZQYActivity 的 native 方法**：`qyAn/qyEn/qyDe`（[GZQYActivity.java](file:///Users/aliang/Documents/nixiang/03_decompiled/超维进化/jadx_2.1/sources/com/cocos/game/GZQYActivity.java)）— 疑似 7Zip 解压校验/解密，native 在某个 `.so`；签名不对可能死锁
2. **cn.gravity.android.g.java 的自杀**：`Process.killProcess + System.exit(10)`（[g.java](file:///Users/aliang/Documents/nixiang/03_decompiled/超维进化/jadx_2.1/sources/cn/gravity/android/g.java#L69-L72)）— Gravity 统计 SDK 异常时自主 kill，触发条件是签名校验失败时的回调
3. **native so 层的 apk 校验**：libcocos2djs.so / libimagepipeline.so 等可能带 sofactory/签名指纹校验，静态不可见，需真机断点/IDA 或 logcat 引 native 崩溃栈

**下一步方向（三选一，下次定）**：
1. **先抓真机崩溃/卡死瞬时栈**：开 logcat 长驻 + `debuggerd -b PID`（卡死进程 PID 会变，需循环引），或直接看 `/data/tombstones/` 有无引用 so 的 abort 栈 —— 这是最快定位 native 校验的路径
2. **尝试绕过签名校验**：若定位到校验点（qy/gravity），重编译并 stub 掉；若在 cocos2djs.so 里则找常量或 patch so
3. **问用户/降级**：确认是否必须去签名校验（合规提醒），或换无校验的游戏版本

**正确结论（复盘）**：此游戏反作弊新增了**重包完整性/签名校验**，触发方式是"换签后进 AppActivity 阶段"。我之前静态 grep 只覆盖了 Java/JS，漏了 native 层与 SplashActivity 生命周期链。下次接手同类新游戏，先做"拆签重装"实测再下"无可检测"结论。
