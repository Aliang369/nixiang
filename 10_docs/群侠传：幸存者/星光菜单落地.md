## 2. 开关通道设计（为什么不用自建 starry_mod.json）

```
星光原生菜单（NativeMenuController）
   │ 玩家拨开关 / 拖滑条
   ▼
ModBridge.onToggleChanged / onSliderChanged        （Java，框架通用件）
   │ Preferences 持久化 + nativeSetFeature / nativeSetValue
   ▼
com.starry.magic.menu.StateMirror.mirror(featNum, value)   ← 现成件，**本次零改动**
   │ 写两份：外部 media 目录 + **{getFilesDir()}/starry_state.txt**
   ▼
/data/user/0/<pkg>/files/starry_state.txt   （= Godot 的 user:// 根，本作实测同一目录）
   │ GDScript FileAccess 读取（300ms 节流，static 缓存）
   ▼
assets/scripts/starry_switch.gdc → 三个挂点的开关判定
```

要点：
- 框架**已有**文件镜像通道（先例：宝石战争 6.0.012 的 HybridCLR 侧读 `starry_state.txt`）。本作直接复用 ⇒ Java/native 侧零改动、不动框架，比自建 `starry_mod.json` 少一份耦合。
- 文件格式是**单行 8 个空格分隔整数，下标 = featNum**，不是 JSON。因此「{god:1,dmg:10,silver:1}」在本作落成：`[1]=伤害倍率 / [2]=无敌 / [3]=无限银钱`。
- `user:// == /data/user/0/<pkg>/files` 的三条证据：①设备实盘该目录有 `settings.cfg`/`shader_cache`/`platform`；②`gd/taptap_sync_ledger.gd:11` 用 `user://platform`，实盘存在 `files/platform`；③运行时 `StateMirror` 写的正是该路径（§5 日志）。

## 3. 改动的 .gdc 挂点

源码：`03_decompiled/群侠传：幸存者/gd_menu/`；回编产物：`07_patched/群侠传：幸存者/gdc_menu_0.2.3.9/`。

| 功能 | 包内路径 | 原长度 | 补丁点 | 语义 |
|---|---|---|---|---|
| 无敌 | `assets/scripts/components/health_component.gdc` | 2841 | `var invulnerable` 改成**属性**：`get: return _invulnerable or (_vitals != null and StarrySwitch.on(2,0))`；`set(v): _invulnerable = v` | 只对玩家组件生效（敌人走 `bind_row_storage`，`_vitals == null`）；`take_damage` 与 `player.gd` 的 DOT 判定**同时**被覆盖；关闭即时恢复掉血 |
| 伤害倍率 | `assets/scripts/systems/combat_hit_pipeline.gdc` | 34169 | `target_damage = hit_event.settle_damage() * damage_multiplier` 之后插 `target_damage *= StarrySwitch.num(1, 1.0)` | 滑条 **1..100** ⇒ ×1..×100；1 = 原样（关闭态） |
| 无限银钱 | `assets/scripts/core/model/economy_store.gdc` | 6630 | `set_silver`：`silver = 999999999 if StarrySwitch.on(3,0) else value`；`install_draft`：同判定包住 `int(draft.get("silver", silver))` | 关闭时按存档/参数原值，开时恒满 |

复用单点（**新增文件，不受等长约束**）：

- `assets/scripts/starry_switch.gdc`（1202 B）+ `assets/scripts/starry_switch.gd.remap`（`[remap] path="res://scripts/starry_switch.gdc"`）
- 接口：`static num(idx:int, dflt:float)->float` / `static on(idx:int, dflt:int)->bool`；static 变量缓存 + 300ms 节流；文件缺失/解析失败 ⇒ 回落默认值（**绝不抛错、不阻塞战斗帧**）。
- 三个挂点各只多一行 `const StarrySwitch: = preload("res://scripts/starry_switch.gd")` + 一处判定。

### 等长铁律（本作硬约束）

替换既有 `.gdc` 时**解压后尺寸必须与原条目完全一致**，否则引擎报 `Error decompressing GDScript tokenizer buffer.`（`gdscript_tokenizer_buffer.cpp:154`）→ autoload 链编译失败 → GLThread SIGSEGV。做法：GDRE 回编 → `03_decompiled/群侠传：幸存者/pad_gdc.py <回编.gdc> <原长度> <输出>`（高压缩级别重压 + zstd skippable frame 补到原长度）。

本次填充余量：health `payload=2633 pad=196`；economy `payload=6487 pad=131`；pipeline `payload=31605 pad=2552`。

## 6. 验收结论（CLAIM / VERDICT / EVIDENCE）

- 悬浮菜单可见：**PASS**（attach 日志 + 用户实机看到并操作）。
- 三开关实时开/关并影响游戏：**PASS**（用户实机验收「功能都没问题了」；机器侧同轮抓到 `starry_state.txt` 从 `0 1 0 0…` 变为 `0 10 1 1…`，且 GDScript 同秒读到）。
- 滑条上限 10 → 100：**PASS**（`[数值] #1 Slider_伤害倍率:1:100:1`，重装后进程存活、无脚本错误；GDScript 侧无需改动，`num(1,1.0)` 直接把滑条值当倍率）。
- 全程 install -r（未卸载）、无 Fatal、无 decompress 报错：**PASS**。

注意：`1:10:1 → 1:100:1` 改变了功能列表签名 ⇒ `StarryPrefs` 按设计**清空旧功能偏好**，装完三个开关回到默认（全关、倍率 1），需重新拨一次；授权会话不受影响（`verdict=ok … has_grant=true`，无需重新登录）。

## 8. 风险与注意

- **换版本必须重取**三条目原始长度（脚本内断言会在不符时直接 die，不会静默打错），并重编/重填 gdc。
- `starry_state.txt` 双写（外部 media + 内部 files）；本作进程内模式只看内部那份，外部那份仅是框架兼容行为（系统 MediaProvider 会打 WARN，无影响）。
- 关闭「无限银钱」不会把已涨上去的银钱扣回（与原恒开补丁同语义），只停止继续拉满。
- 无敌属性对所有 `_vitals != null` 的组件生效，即玩家自身；敌人不会误伤免疫。
- 倍率上限 100 是**菜单值域**；真机数值验证按用户实际操作，未做逐档压测。
