# 群侠传：幸存者 · TapTap 登录改包方案（去签名校验 + 网页登录）

> 依据 skill/re-analyze/login/taptap-web-login.md 现行口径（改包法）。
> smali 反编译在 03_decompiled/群侠传：幸存者/smali/；官方证书在 cert/。

## 1. TapSDK 版本判定
- 包内 `Lcom/taptap/sdk/*` 可达 → **改包法**（静态改 dex），不走运行时 SPI。
- 登录 UI 类存在：`DefaultTapLoginFragmentProvider` + `ClientLoginFragment` + `WebLoginFragment` + `CloudGameFragment` → 属新版 SDK（蛋壳战机同款锚点风格）。
- 验签门闩类存在：`com/taptap/sdk/initializer/…/GatekeeperRepository`、`GatekeeperManager`、`TapTapSdkInitializer`。
- 签名套件：`com/taptap/sdk/kit/internal/utils/TapSignKit`。
- 原生侧：libtapsdkcore.so + libthemis.so（TapTap Themis Lite，GameSecurity）。

## 2. 官方证书指纹（回灌用）
- 证书主体：CN=Qunxia Internal Test, O=NenlyStudio（注意：是内部测试证书，非商店正式签）
- cert.der（787 B）MD5 = `6b013f42541e222db7f2153a138ab301`
- cert.der SHA1 = `0abb94dda962513853f1f7f820c53f8b2c7c2d7f`

## 3. 改包法四步锚点
| # | 目标 | smali 类/方法 | 改法 |
|---|---|---|---|
| 1 | 验签/初始化门闩恒放行 | `com/taptap/sdk/initializer/repository/GatekeeperRepository`（及 TapTapSdkInitializer 的 checkInitialize 类） | 恒返回成功/true（按实际 smali 指令现取，勿抄历史） |
| 2 | 验签失败弹窗掐掉 | `GatekeeperRepository.showErrorToast(...)` | 方法体改 return-void（保留 .registers） |
| 3 | 登录入口恒 Web | `DefaultTapLoginFragmentProvider.provide`：`aget v2, v3, v2`（smali 约第184行）之后插 `const/4 v2, 0x3` | 强制走 WebLoginFragment（case 3） |
| 4 | 签名回灌 | `TapSignKit.getSign` | 固定返回官方 cert.der 的 MD5 `6b013f42541e222db7f2153a138ab301`（或对应 getSign 返回值的官方指纹） |

- 已确认第 3 步锚点指令在 DefaultTapLoginFragmentProvider.smali：`aget v2, v3, v2`(184) → case 0x1(186)/0x2(190)/0x3(194) → WebLoginFragment.newInstance(199)/ClientLoginFragment.newInstance(234)。
- 第 1/2/4 步需在 smali 里按上述类现取指令再改（锚点类已定位，未逐指令展开）。
