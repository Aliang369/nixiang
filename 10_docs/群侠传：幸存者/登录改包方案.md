# 群侠传：幸存者 · TapTap 登录改包方案（去签名校验 + 网页登录）

> 依据 skill/re-analyze/login/taptap-web-login.md 现行口径（改包法）。
> smali 反编译在 03_decompiled/群侠传：幸存者/smali/；官方证书在 cert/。

## 1. TapSDK 版本判定
- 包内 `Lcom/taptap/sdk/*` 可达 → **改包法**（静态改 dex），不走运行时 SPI。
- 登录 UI 类存在：`DefaultTapLoginFragmentProvider` + `ClientLoginFragment` + `WebLoginFragment` + `CloudGameFragment` → 属新版 SDK（蛋壳战机同款锚点风格）。
- 验签门闩类存在：`com/taptap/sdk/initializer/…/GatekeeperRepository`、`GatekeeperManager`、`TapTapSdkInitializer`。
- 签名套件：`com/taptap/sdk/kit/internal/utils/TapSignKit`。
- 原生侧：libtapsdkcore.so + libthemis.so（TapTap Themis Lite，GameSecurity）。

## 2. 官方证书指纹（回灌用）
- 证书主体：CN=Qunxia Internal Test, O=NenlyStudio（注意：是内部测试证书，非商店正式签）
- cert.der（787 B）MD5 = `6b013f42541e222db7f2153a138ab301`
- cert.der SHA1 = `0abb94dda962513853f1f7f820c53f8b2c7c2d7f`

## 3. 改包法四步（0.2.3.10 已落地，现行）

> 产物：`03_decompiled/群侠传：幸存者/0.2.3.10/classes_mod_0.2.3.10.dex`，8,093,536 B，md5 `23f68abecc1b0c7720215f04c1eeee9f`。
> 改动 = **4 个类 6 个方法**；method_ids **49,334**（原版 49,335，−1：`getSign` 恒返回常量后 `getPackageInfo` 等引用被裁剪），余量 16,202，class_defs 6,186 不变；dexdump 全量反汇编 0 报错；dex 内无 `SignSpoof`。
> 锚点全部按 TapSDK **4.11.0 现取**（不复用 0.2.3.9 行号）。

| # | 目标 | 实际落点（0.2.3.10 / 4.11.0） | 改法（逐方法行数变化） |
|---|---|---|---|
| 1 | 初始化门闩恒放行 | `com/taptap/sdk/initializer/InitializerServiceImpl.checkInitialize(Z)Z`、`checkLocalInitialize(Z)Z` | 两方法恒 `true`（20→3 / 25→3 行） |
| 2 | 验签门闩恒放行 ＋ 弹窗掐掉 | `GatekeeperRepository.isGatekeeperLoadedSuccessfully()Z`、`showErrorToast(TapNetworkException)` | 前者恒 `true`（11→6 行）；后者方法体首插 `return-void`（18→2 行，**保留原 `.registers`**，改成小值会 smali 编译失败） |
| 3 | 登录入口恒 Web | `DefaultTapLoginFragmentProvider.provide`：`aget v2, v3, v2` 之后插 `const/4 v2, 0x3` | 恒落 `WebLoginFragment`（case 3；74→75 行，+1 指令） |
| 4 | **签名回灌（必需）** | `TapSignKit.getSign(Context)Ljava/lang/String;` | 原体 83 行（`getPackageInfo(...,0x40)` → `signatures` → `firstOrNull` → `Signature.toByteArray()` → `getMD5`，含 try/catch）**整段替换**为 3 行：`const-string v0, "6b013f42541e222db7f2153a138ab301"` / `return-object v0` |

第 3 步锚点（`DefaultTapLoginFragmentProvider.smali`）：`aget v2, v3, v2` → case 0x1/0x2/0x3 → `WebLoginFragment.newInstance` / `ClientLoginFragment.newInstance`；全包**只有这一处** `newInstance(ClientLoginFragment)` ⇒ 压成 case 3 即彻底切断客户端 SSO。

### 3.1 第 4 步＝必需：不回灌就 1001（真机实测）

```
11-15 16:31  E godot: TapSDK 初始化失败（1001）：TapSDK: 包名、签名错误
11-15 16:31  E TapSDK-TapSdkCore: TapSdkCore had already been started!...
```

- 全包**只有一处**取签名：`com/taptap/sdk/initializer/repository/GatekeeperRepository$initialize$1$networkData$1` → `TapSignKit.getSign(Context)`；`GateKeeperRequest(platform, packageName, signature)` 的 `signature` 就是它的返回值，服务端拿它与登记的指纹比对 ⇒ 改签包里真签名必然不匹配。
- 因此只做门闩/弹窗/入口三步**不够**：1001 发生在 native `TapSDK-TapSdkCore` 初始化，dex 门闩恒 true 也拦不住（16:31 那轮就是「三步做完仍 1001」）。
- 回灌后同一窗口复测：`TapSDK 初始化失败` / `TapSDK: 包名、签名错误` / `1001）：` 三条各 **2 条 → 0 条**（12,937 行全量 logcat 计数）。
- 旧版做法（0.2.3.9）同样是 `TapSignKit.getSign` 整段替换为同一常量 ⇒ **新版保留该做法，并把它作为第 4 步的必需项**（详见 `_state/0.2.3.10_登录改包.md` §2.D / §7）。

### 3.2 登录路由（框架侧 SPI，与 dex 侧解耦）

- 框架 dex 内新增 `com.starry.magic.games.qxzxcz.GameHookImpl`（`PKG=com.nenlystudio.qunxiasurvivor.cn`，`isTarget()` 单判据），`onActivityPreCreated` / `onActivityCreated` 转调 **`core.TapTapWebLogin`**（不是已收口的旧 `sign.TapLoginForceWeb`）。
- 实测：`I StarryTapLogin: new-impl request loginType mobile_client -> embedded_web (preCreated)` ＋ `I WebViewFactory: Loading com.google.android.webview 138.0.7204.179` ⇒ **登录成功**（用户实机完成登录）。
- 该 SPI 只解决「不拉起 TapTap 客户端、走内嵌 WebView」，**不替代签名侧**（第 4 步回灌仍在游戏 dex 里）。细节见 `_state/0.2.3.10_SPI接入.md`。

### 3.3 历史：0.2.3.9 阶段的四步锚点（已被 §3 表取代，保留作对照）

| # | 目标 | smali 类/方法（旧表述） | 改法 |
|---|---|---|---|
| 1 | 验签/初始化门闩恒放行 | `GatekeeperRepository`（及 TapTapSdkInitializer 的 checkInitialize 类） | 恒返回成功/true（按实际 smali 指令现取，勿抄历史） |
| 2 | 验签失败弹窗掐掉 | `GatekeeperRepository.showErrorToast(...)` | 方法体改 return-void（保留 .registers） |
| 3 | 登录入口恒 Web | `DefaultTapLoginFragmentProvider.provide`：`aget v2, v3, v2`（smali 约第184行）之后插 `const/4 v2, 0x3` | 强制走 WebLoginFragment（case 3） |
| 4 | 签名回灌 | `TapSignKit.getSign` | 固定返回官方 cert.der 的 MD5 `6b013f42541e222db7f2153a138ab301` |

> 读法：这张旧表的第 4 步**不是历史包袱**——0.2.3.10 沿用它并升为必需（§3 第 4 行）；变的是第 1/2 步的类名（4.11.0 把门闩拆到 `InitializerServiceImpl`）与第 3 步的行数。
