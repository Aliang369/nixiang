## 1. 新增接入点

路径：`mod菜单/starry-mod-menu/app/src/main/java/com/starry/magic/games/qxzxcz/GameHookImpl.java`（新建，包目录 `games/qxzxcz/` 之前不存在）

要点：

| 项 | 内容 |
|---|---|
| 类 | `public final class GameHookImpl implements GameHook`（`com.starry.magic.games.qxzxcz`） |
| PKG | `com.nenlystudio.qunxiasurvivor.cn` |
| `onActivityPreCreated` | `if (!isTarget(activity)) return; TapTapWebLogin.onPreCreated(activity);`（单参重载：本作无旧版路由，不传 legacy request 类名） |
| `onActivityCreated` | `if (!isTarget(activity)) return; TapTapWebLogin.onCreated(activity);` |
| `targetPackage()` | 返回 PKG（独立助手形态用） |
| `isTarget()` | `activity != null && PKG.equals(activity.getPackageName())` —— 唯一生效判据，别的游戏加载本类无副作用 |
| import | `com.starry.magic.core.GameHook` + `com.starry.magic.core.TapTapWebLogin`（**不是** `sign.TapLoginForceWeb`） |

注释里写清了三件事（均在 javadoc 内，非空话）：
1. **为什么需要**：TapSDK 4.11.0 新版路由，装了 TapTap 客户端默认走 `ClientLoginFragment`（客户端 SSO），星光包 `CN=StarryMagic` 重签后应用身份与后台登记不符必被拒 ⇒ 钉死内嵌 `WebLoginFragment`。
2. **为什么是 `core.TapTapWebLogin`**：它是 2026-11-11 收口后的平台级能力（`core/`、零白名单、判据＝谁的 GameHookImpl 调它）；`sign.TapLoginForceWeb` 是收口前旧机制（自带单游戏 request 常量、注释自述「只服务没迁移改包法的老包」）。
3. **本类只解决登录路由**：签名校验在游戏 dex 侧 —— `TapSignKit.getSign` 回灌官方 `cert.der` MD5 `6b013f42541e222db7f2153a138ab301` + `GatekeeperRepository`/`TapTapSdkInitializer` 门闩恒放行（`10_docs/群侠传：幸存者/登录改包方案.md` §3 四步）；本类不做签名伪装、不复活 `SignSpoof`。

## 6. 风险与覆盖范围（别夸大）

1. **只对 TapTap SDK 自己的登录 Activity 生效**：`TapTapWebLogin` 每一步都先比对 `activity.getClass().getName()`（`…impl.ui.activity.TapTapLoginActivity` / 旧 `com.taptap.sdk.ui.TapTapActivity`），类名不符即空转。游戏 GDScript 侧若另有独立登录/校验（`assets/scripts/autoload/platform/taptap_android_backend.gd`），本类覆盖不到。
2. **SDK 升级换类名 ⇒ 静默失效**：改 `core/TapTapWebLogin` 的类名常量，**不要**在 GameHookImpl 里加第二套判据。
3. **R8 把 `core.TapTapWebLogin` 改名了**：`-keep,allowobfuscation class com.starry.magic.core.**` 生效 ⇒ dex 里该类叫 `Lcom/starry/magic/o/U0;`（日志 tag `StarryTapLogin` 与反射锚点都在，功能不受影响，因为只有编译期直接调用、无反射引用）。**别拿 `TapTapWebLogin` 当门禁串**（已实测 MISSING）；要查就用 `StarryTapLogin` / `embedded_web` / `fallbackToWeb`。
4. **登录路由 ≠ 通过验签**：`TapSignKit.getSign` 回灌与 `GatekeeperRepository` 门闩仍需按改包法处理（`登录改包方案.md` §3）；本类只保证「不拉起客户端、走内嵌 WebView」。
5. **现存 0.2.3.10 starry 包要重打**：`08_output/…_0.2.3.10_starry-menu-releaseSigned.apk`（16:17）的 `classes2.dex` = 432,664 B / md5 `5e85721f3a7ad6ef7e7be2e185bad96f`，**不含** qxzxcz hook（实测 `False`）。组装必须换成新 dex（433,216 B / `63098790…`）。
