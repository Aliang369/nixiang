## 8. combat_hit_pipeline 的真实改动（9 个 hunk / 54 行，与补丁点相邻）

`diff 旧 gd/combat_hit_pipeline.gd 新 gd_0.2.3.10/combat_hit_pipeline.gd`：1,278 → 1,316 行。除删掉我们那行 `target_damage *= 10.0 # MOD` 外，实质改动是：

1. 新增 `const HIT_RULE_COMPILE: = preload("res://scripts/systems/hit_rule_compile.gd")`（第 36 行）
2. 命中上下文改为**复用**：`cast_plan.fill_hit_context(...)` + `hit_context_busy` 标志；原 `_fill_event_hit_context` 被拆出成独立函数（新增约 34 行）
3. 共振修饰符改走 `RunState._get_resonance_runtime().resonance_pre_hit_modifiers_reused(...)`（原 `RunState.get_resonance_pre_hit_modifiers` **已不存在**）；`crit_chance_bonus` / `crit_damage_bonus` / `force_crit` 提前取出复用
4. `RunState.get_item_status_duration_multiplier` → `RunState._get_item_passive_effects().get_item_status_duration_multiplier`（2 处，**旧名已删**）
5. 新增 `HIT_RULE_COMPILE.shadow_verify` 影子校验（SETTLE 计数 / shadow_mismatch）——纯埋点，无封禁动作

**对我们三个补丁点无影响**：`target_damage` 的计算链与插入位置逐字未变；补丁只插一行 `target_damage *= StarrySwitch.num(1, 1.0)` 和一处 preload 常量。

## 10. 给后续阶段的风险提示（会改变做法的）

1. **旧 `surgical_qxzxcz_0.2.3.9.sh` 里三条目长度断言会直接 die**（pipeline 34,169 → 35,739）——这是设计好的保护，不要绕过，必须换长度并重算 pad 余量（旧余量 2,552 不可复用）。
2. **不能复用 0.2.3.9 的 `gd_menu/` 补丁源**：110 个同名 gdc 长度变了，且 `run_state`/`_get_item_passive_effects` 等 API 已重排；补丁必须基于 `gd_0.2.3.10/` 重新打，打完再回编。
3. **apktool 3.0.3 不导出 `classes.dex`**：任何"取 `apktool_out/classes.dex` 改 dex"的旧脚本会断，改从 APK 内提取。
4. **新增 `libcloudsave_sdk.so` + 9 个 `taptap_cloudsave_*.gdc` + 云存档 UI**：本作可能已开启 TapTap 云存档。无限银钱/存档类补丁有被云端覆盖或上传异常值的风险 —— 功能验收阶段要加一条"关网/断云存档后银钱是否仍生效"的观测。
5. **`TapSignKit` 体积翻 2.3 倍（方法签名不变）**：登录改造阶段不能照抄 0.2.3.9 的结论，需重新确认 `getSign` 的实现是否引入新的校验输入。
6. **`combat_hit_pipeline` 自带 `shadow_verify` 埋点**：官方正在这块做重构自检，补丁应保持"单行乘法 + 一个 preload"，不要改动上下文构造逻辑（避免触发 shadow_mismatch 走异常分支/日志噪音）。
7. **manifest 完全没变**，因此 0.2.3.9 的星光是 SPI 方案（`GameHookImpl` + `StarryApp`/Provider 不动）在 0.2.3.10 上**结构前提不变**；菜单 dex 仍可占 `classes2.dex`（方法余量 16,201）。
8. `libgodot_android.so` 字节数未变 ⇒ **不需要重编 native**，星光重打包走"只换 dex/gdc + 重签名"路径（`STARRY_INSTALL_ONLY` 语义仍适用）。
