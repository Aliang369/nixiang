## 2. 三处 patch（锚点原文 → 插入内容）

每处都只加 **1 行** const StarrySwitch: = preload("res://scripts/starry_switch.gd")（紧跟 extends 行）＋判定逻辑；**不整段替换、不按旧版行号定位** —— 全部按唯一锚点字符串命中，命中次数 ≠ 1 即 die 并打印上下文。

### 2.1 health_component.gd:77（0.2.3.10 反编译行号）

锚点原文：

`B`
var invulnerable: bool = false
`B`

替换为（6 行）：

`B`
var invulnerable: bool:
	get:
		return _invulnerable or (_vitals != null and StarrySwitch.on(2, 0))
	set(value):
		_invulnerable = value

var _invulnerable: bool = false
`B`

- take_damage 的 if invulnerable:（原 189 行）**一字未动** —— 走的是同一 getter。
- player.gd 侧 health_component.invulnerable（1001 设置、1022/1278 DOT 与受击判定）读同一属性 ⇒ 开关只写一处、两处同时生效。
- _vitals != null 门闩 ⇒ 只对玩家组件生效（敌人走 bind_row_storage，_vitals == null），不会让敌人免疫。

### 2.2 combat_hit_pipeline.gd:399（新版行号；旧版为 398）

锚点原文：

`B`
	var target_damage: float = hit_event.settle_damage() * damage_multiplier
`B`

紧随其后插入 1 行：

`B`

`B`

- 位置与 0.2.3.9 相同（在 if target is EnemyActor: / consume_incoming_external_arts_damage_multiplier 分支**之前**），倍率是乘性；敌人减伤对乘后值生效。
- 上下文（_pt_hit_modifiers 探针、cast_plan.cast_damage_modifier、HIT_RULE_COMPILE 相关代码）**未触碰**；新版新增的 shadow_verify 埋点原样保留。

## 4. starry_switch 接口与通道

来源：03_decompiled/群侠传：幸存者/gd_menu/starry_switch.gd（0.2.3.9 已实机验收版本，原样重编，逻辑未改）。

`B`gdscript
static func num(idx: int, dflt: float) -> float   # 取第 idx 个整数；越界/读不到 → dflt
static func on(idx: int, dflt: int) -> bool        # num(idx, float(dflt)) != 0.0
`B`

- 文件：user://starry_state.txt = /data/user/0/com.nenlystudio.qunxiasurvivor.cn/files/starry_state.txt，**单行 8 个空格分隔十进制整数，下标 = featNum**。
- 通道：菜单拨动 → ModBridge.onToggleChanged/onSliderChanged → StateMirror.mirror(featNum, value) 落盘该文件 → GDScript 读。
- 下标（**不许改**）：[1] 伤害倍率 Slider 1..100（1 = 关闭态）、[2] 无敌 Toggle、[3] 无限银钱 Toggle。
- 工程约束：static 缓存 + **300ms 节流**（每次受击都能安全调用）；文件缺失/解析失败 ⇒ _ok=false、退回默认值；**不抛错、不阻塞战斗帧**。
- 内容变化时打印一次 [StarrySwitch] <原文> 作为诊断锚点（0.2.3.9 实机日志已用它确认读通）。
- starry_switch.gd.remap 内容 48 B：

`B`
[remap]

path="res://scripts/starry_switch.gdc"
`B`

## 5. 验证证据（全部实测）

1. **精确等长**：os.path.getsize 三个文件 = 2,841 / 35,739 / 6,630，差值 +0 / +0 / +0（脚本 step 5 打印）。
2. **GDSC 头**：magic=GDSC，ver=101，头内解压长度 10,848 / 121,000 / 22,976（starry_switch 3,568）。
3. **zstd 帧可解析**：tail -c +13 <gdc> | zstd -d -c 对 4 个文件全部退出 0（尾随 skippable frame 被正常跳过），解出字节数与头内声明一致。
4. **回读抽查**（GDRE --decompile 对**产物**反编译，不是对源码）：
   - health_component.gdc → _invulnerable or (_vitals != null and StarrySwitch.on(2, 0)) 命中；if invulnerable: 仍在（take_damage 未被改）。
   - combat_hit_pipeline.gdc → target_damage *= StarrySwitch.num(1, 1.0) 命中（回读行号 401）。
   - economy_store.gdc → 两条 999999999 if StarrySwitch.on(3, 0) 命中（回读行号 173 / 352）。
5. **round-trip 差异**：diff「原反编译」与「回读产物」的输出**只有我们这几处 hunk**（外加 health 里 1 个反编译器归一化的空行），其余 1,300+ 行零差异 ⇒ 回编没丢内容、没额外改写。
6. **脚本机器关**：bash -n 通过；preflight.sh PASS=3 FAIL=0；bash32_check.sh rc=0；lint_shell_traps.py rc=0。
7. **失败路径**：把锚点改成 var invulnerable: bool = true 后重跑 → ERROR: 锚点 invulnerable 声明 期望命中 1 次，实际 0 次… 并打印第 78 行前后 7 行上下文（证据目录 13_scratch/qxzxcz_negtest_anchor_missing/）。

## 6. 风险

| 风险 | 判断 | 处置 |
|---|---|---|
| pipeline 新增 HIT_RULE_COMPILE.shadow_verify（908-913 行）会不会被触发 | **不会**：它只比较 shared 与 reference 两个 **hit_context 字典**；本补丁在其之后对 target_damage 做乘法，不写 context。shadow_mismatch 只累加计数，无封禁动作 | 首装后抓一次 logcat 看有无 shadow_mismatch / Error decompressing |
| 伤害乘法位于 consume_incoming_external_arts_damage_multiplier 之前 | 与 0.2.3.9 完全一致（当时用户实机验收「功能都没问题了」）；倍率乘性叠加 | 无需改 |
| economy pad 余量仅 131 B | **最紧**，再加一行就可能失败（pad_gdc 会 SystemExit: cannot fit，不会静默打错） | 改该文件必须重跑脚本看 payload |
| 银钱恒 999999999 + 0.2.3.10 新增 TapTap 云存档（libcloudsave_sdk.so） | 云端可能上传/回滚异常值，或被云端覆盖 | 验收加一条「断网/关云存档后银钱是否仍生效」 |
| starry_state.txt 不存在（首装、或 StarryPrefs 因功能签名变化被清空） | 全开关回落默认：倍率 1（原样）、无敌关、银钱关 | 预期行为；提醒用户装后重新拨一次 |
| 本阶段未装机 | 只到「静态等长 + 回读」级别，运行期证据为 0 | 装机验收另跑；不得写成「功能可用」 |
