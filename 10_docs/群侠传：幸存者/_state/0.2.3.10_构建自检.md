## 5. smali ↔ dex 工具 / Tap 登录改包脚本（另一个 agent 要用）

**结论：`04_scripts/_common` 下没有「smali↔dex」专用封装脚本，也没有 `tap_login` 类改包脚本；但工具本体在仓内 `01_tools/smali`，可直接用。**

```bash
cd /Users/aliang/Documents/nixiang
# 反编译单 dex 为 smali 目录
JAVA_HOME=$(/usr/libexec/java_home -v 17) ./01_tools/smali/baksmali d classes.dex -o out_smali
# 列 dex 内类名（本次校验用的就是这条）
JAVA_HOME=$(/usr/libexec/java_home -v 17) ./01_tools/smali/baksmali list classes classes.dex
# smali 目录回编成 dex
JAVA_HOME=$(/usr/libexec/java_home -v 17) ./01_tools/smali/smali a out_smali -o classes.dex
# 版本
./01_tools/smali/baksmali --version   → baksmali 2.5.2
```

存在性证据：
- `01_tools/smali/`：`smali`、`baksmali` 两个 wrapper（内部 `java -cp "$DIR/*" org.jf.smali.Main`）+ `smali-2.5.2.jar` / `baksmali-2.5.2.jar` / `dexlib2-2.5.2.jar` 等；`which smali baksmali` 为空（需走上面绝对路径或自己加 PATH）。
- 注册点：`04_scripts/_common/env_deps.sh:313-319`（`ok "smali/baksmali" "01_tools/smali"`，找不到会 `warn` 说「只走 apktool 也能干」）。
- `_common` 里对 smali 的其它引用都只是**门禁提示**（`pre_install_gate.sh` 反复强调「门禁串禁写成 smali `#` 注释，汇编器会丢弃」）、`obfuscate_menu_dex.sh`（dex 再混淆）、`decode_apk.sh`（走 apktool，产出 `smali*` 目录）。
- Tap 登录改包：`_common` 下 grep `tap_login|TapLogin` 无命中。仓内现成货是**游戏私有**脚本 `04_scripts/不一样西游/patch_taptap_login_byyxy.sh`（A 轨：把 `LoginBlock.onViewCreated` 里 `new LoginClient(...)+sendLoginRequest` 换成 `new WebViewHandler(...)+authorize`，产出 `07_patched/不一样西游/classes2_patched.dex`；脚本头注释还记了两个实测失败错法，值得先读）。
- 现行口径文档：`skill/re-analyze/login/taptap-web-login.md`；框架侧另有**未跟踪新文件** `mod菜单/starry-mod-menu/app/src/main/java/com/starry/magic/core/TapTapWebLogin.java`（及其他会话新加的 `games/*` hook），做 0.2.3.10 登录改包前先看这两个，别重造。
