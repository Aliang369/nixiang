## 二、挂点

| 用途 | VA | file offset | 序言（expectInsn） | 状态 |
|---|---|---|---|---|
| **解释器执行入口** | 0x17E9220 | **0x17E5220** | `stp x29,x30,[sp,#-0x60]!` = **0xA9BA7BFD** | ✅ 实测在跑（12 s / 17,780 次） |

**签名（桩侧实测）**：`(x0 = MethodInfo*, x1 = argsPtr, x2 = nullptr)`
- 74 个不同 methodPointer 中最大一支（1009 个方法共用）指向桩 `0x18C7A08`，桩体：
  ```
  str x30,[sp,#-0x10]! ; mov x8,x1 ; str x0,[sp,#8] ; add x1,sp,#8
  mov x0,x8 ; mov x2,xzr ; bl 0x17e9220 ; ret
  ```
  即：x0=MethodInfo、x1=&args、x2=null ⇒ 与本表签名一致。
- 函数体特征：`sub sp,sp,#0xc40`（3136 B 栈帧）+ TLS 访问 + `bl 0x17d800c` 取方法信息。

**已否**（在此阶段 hits=0，不是入口）：
- 0x29FFF2C（序言 0xF81D0FFE，三参但 x1 为 int32 并做符号位判断）
- 0x29FFEA8（序言 0xF81E0FFE，只用两个参数）

**待验证**：0x17E9220 目前采样到的是 Unity 生命周期方法（`GameMotor.Update` / `StageEngine.LateUpdate` / 协程 MoveNext 等），即**引擎→热更**路径。
战斗扣血若为 **C#→C#**，按长生天机降世的经验可能走 `CallInterp → EnterFrameFromInterpreter`（另一函数），需战斗中采样确认；若确认漏，再补挂该函数。

## 六、禁止事项

1. **禁止用 ELF base + RVA 直接算地址**：本 so `va − file = 0x4000`，frida 侧要用 **VA**（`lib.base + va`），用 file offset 会差 0x4000 踩空（本轮已踩：读到 `0x34000068` 而非 `0xF81D0FFE`）。
2. **禁止只挂桩目标就断言覆盖战斗**：桩路径只证引擎→热更；C#→C# 需另行确认。
3. **禁止遍历 Config/Proto（2219+1831 类）**：只在 `QLD.Fight.Runtime.dll` 内定位。

## 七、真机动态逆向结论（2026-11-10，关键证据）

### 7.1 斌哥改包的 hook 点（内存对比法定位）

方法：装斌哥改包 → 运行时读 libil2cpp 全部可执行段 → 与官方 so 逐字节比对。
结果：**仅 2 处差异**，均为 Dobby inline hook（libSDKloading.so 导入 dlopen/dlsym/mprotect，导出 Dobby 特征符号 A0000000bxxx…）。

| VA | file | 磁盘原值 | 内存现值 | 性质 |
|---|---|---|---|---|
| **0x17E7750** | **0x17E3750** | 0xF81D0FFE | 0x16000000（b −128 MB 到 mmap 跳板） | **EnterFrame 变体 A（真实入口）** |
| 0x17E798C | 0x17E398C | 0xF81E0FFE | 0x16000000（同上） | 解释器栈操作：64 B 元素、count-1 弹栈 |

### 7.2 三个入口的覆盖差异（实测，务必区分）

| 挂点 | 时长 | 调用数 | 实测覆盖 |
|---|---|---|---|
| **0x17E7888**（本文件 §2 最初写的） | 15 s | 19,645 | **只有 UI/框架层**：90 个不同方法里无一个战斗类 |
| **0x17E7750**（斌哥挂的） | 13 s | 1,609,338 | **GameFightPlaySystem.Update** / A68PrivilegeCardSystem.Update |
| 0x17E9220（Execute） | 12 s | 17,780 | 引擎→热更顶层（Update/协程/MoveNext） |

**结论：0x17E7888 与 0x17E7750 是同型的两个不同函数，覆盖范围完全不同。实现必须挂 0x17E7750。**
（§2 表格里的 0x17E7888 保留作历史对照，不要再用。）

### 7.3 扣血不走方法调用（核心机制，别再来回试）

在 0x17E7750 上过滤 RemoveHp|CurHp|MaxHp|Hurt|Invincible|SkillCd|AddHp|Dead：**160 万次调用中命中 0**。

| 目标桩 | 地址 | 实测调用数 |
|---|---|---|
| Monster/Tower/ChildTower/Hero/SummonEntity.DoRemoveHp 共用桩 | 0x76f78bdad4 | **0** |
| MonsterEntity / EntityBase.set_CurHp 桩 | 0x76f799ccfc | **0** |
| TickAfter / TickState 桩 | 0x76f79a0e48 | **0** |

⇒ 战斗扣血是**纯 C# 到 C# 解释执行**：既不经过 methodPointer 桩，也不产生新的 EnterFrame。
⇒ 只能走「在帧更新前后改实体数据」，不能走「拦方法改参数」。旷野征途那套（ApplyHp 被 AOT 侧调用、走桩）在本作不成立。

### 7.4 下一轮实现方案

1. 挂点改为 **0x17E7750**（file 0x17E3750，序言 0xF81D0FFE），签名仍 (x0=frameGroup, x1=MethodInfo, x2=argsPkt)
2. hook 内识别 methodInfo == GameFightPlaySystem.Update 的 MI
3. 在该方法调用**前后**遍历实体改 EntityBase._curHp@88：
   - 无敌：我方实体（Tower/ChildTower/Hero/Summon）血量回填
   - 百倍伤害：怪物（Monster）额外扣 99 倍差值
4. 加速：A68PrivilegeCardSystem（月卡特权）；另需查内置最高倍速
5. 实体地址获取：在 frida 里用 klass 扫描确认对象头布局（本轮 Memory.scan 未命中，因当时已无战斗；下轮须在战斗中扫）

### 7.5 本轮踩过的坑（勿重犯）

1. **别把 file offset 当 VA 用在 frida 侧**：本 so va − file = 0x4000，用错会读到 0x34000068 这种野值。
2. **别用 Backtracer.ACCURATE 在热函数里 backtrace**：直接把游戏进程拖崩过一次。
3. **别用二进制 Manifest 字节匹配判断注入**：字符串是 UTF-16，直接搜类名恒失败，要用 aapt2 dump xmltree。
4. **斌哥包里 libil2cpp.so 与官方 md5 完全一致**（7affdf06…）⇒ 他纯运行时 hook，静态对比 so 找不到东西，必须比内存。
