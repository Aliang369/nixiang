## 2. 真正有的检测 / 风控面

### 2.1 关卡结算上报（主风险）🟡～🔴

链路符号（同批出现）：

`OnStageOver` → `SettleStage` → `GetSettleData` / `battleResult` → `OnStageSettled`  
失败路径：`OnSettleTimeOut` / `ResettleStage` / `OnStageServerError`

说明：战斗主要在客户端演算，**通关要向 `ws.fattoy.cn` 一类网关交结算**；服端可拒结算、回滚奖励，并可据此标记账号。

### 2.2 怪物伤害异常计数（强相关）🔴（对菜单功能）

SLua 暴露给逻辑层的战斗信息里明确有：

| 符号 | 含义（字面） |
|------|----------------|
| `ON_MONSTER_DAMAGE_ABNORMAL` | 怪物伤害异常事件 |
| `OnMonterDamageAbnormal` | 处理入口（拼写缺 s） |
| `m_MonsterDamageAbnormalTimes` / `GetMonsterDamageAbnormalTimes` | **异常次数累计，可进结算/上报** |

同批还可上报（节选）：

- `GetSignatureMD5Hash` / `GetPackageName` / `GetPackageVersion`
- `GetBattleConfigMD5Hash`
- `GetHeroHP` / `GetReviveTimes` / `GetUltTimes` / `GetExecuteTimes` / `GetNoCostDashTimes`
- `GetMonsterDamageAbnormalTimes`
- `GetHeroProperty` / `IsInBattle`

→ **×100 伤害、全屏扩散、异常秒杀** 极易推高 `MonsterDamageAbnormalTimes`，并让通关时长/击杀曲线离谱。  
这与技能表「服务端结算 🟡」一致，且比原先描述更具体。

### 2.3 退款惩罚（独立通道）🟡

- `IsRefundPunish` / `CheckRefundPunish`
- UI：`RefundPunishPanel` / `RefundPunishTip` / `REFUND_PUNISH_TIP`

与战斗外挂无关；**退款/支付争议**也会罚号或限制功能。若你曾退款，需与外挂风险分开看。

### 2.4 登录 / 渠道 / 签名 🟡

- Tap：强制网页 + 伪 `TapSign` MD5（星光已做）— 挡的是登录失败，不是战斗封号
- QQ/微信 SSO：对方进程读系统真签 →「非官方正版」（**不是游戏内封号**，是渠道拒登）
- 改签包本身：服端若校验 `GetSignatureMD5Hash` 与渠道包不一致，可能加重标记（⚠️ 待验证是否强校验）

### 2.5 PVP 🟡～🔴

存在 `ON_CONNECT_TO_PVP_SERVER`、LiteNetLib、FrontLine 等。  
PVP 若权威在服或对手可举报，**开挂上排位/竞技风险高于单机闯关**。

### 2.6 运营侧销号能力 🟢（能力存在）

`GM.ACCOUNT_REMOVED` / `GM.DATA_CLEARED` / `GM:TryRemoveRole` — 运营可清号；不证明自动封，但说明账号可被服务端消灭。

## 4. 对「之前号被封」的合理解释（按概率）

1. **最可能**：长时间开三件套打主线/可结算内容 → 结算遥测 + `MonsterDamageAbnormalTimes` → 人工或自动封禁  
2. **次可能**：退款惩罚通道（若有过支付退款）  
3. **较少**：仅因改签/星光包签名（若从未开挂也可能被渠道拦登录，但「封号」更像账号状态）  
4. **需你补充**：封禁弹窗原文、是否还能登录、是否退款、是否打过 PVP、用的斌哥包还是星光包  

没有弹窗原文时，**不能断定唯一原因**。

## 5. 使用建议（降风险，非免死）

1. **有结算 / 要冲榜 / PVP：功能全关**  
2. 练手法、看剧情、无奖励练习模式可酌情开（仍不保证）  
3. 不要长时间 ×100 + 无敌 + 全屏同时挂机清图  
4. 换号后不要用同一极端打法短时间冲进度  
5. 日常登录继续 **TapTap 网页**；勿指望 QQ/微信改签过检  
6. 真机逆向结束照旧 `cleanup_device_re_residue.sh`（对本游戏封号帮助有限，防污染其它游戏）
