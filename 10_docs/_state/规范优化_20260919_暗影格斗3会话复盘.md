## 2. 优化候选（按价值排序）

### 2.1 归档脚本白名单不得包含跨会话共享文件（候选，高价值）

- **证据**：`archive_sf3.sh` 初版白名单含 `SignSpoof.java`；该文件在 15:52 被弓箭传说2 会话追加国服证书。若直接归档，会把别的会话未完成改动提交进本作提交。
- **现状**：sf3 已摘除；但 `archive_yntt.sh`、`archive_es2.sh`、`archive_zzbx2.sh` 三份仍白名单该文件。
- **候选动作**：归档脚本对共享文件（`sign/SignSpoof.java`、`sign/TapLoginForceWeb.java`、`bridge/ModBridge.java`、`StarryInitProvider.java`、`jni/MainModern.cpp`）不做路径白名单直加，改为「只提交本次会话确有改动且已确认归属的文件」；或在提交前打印共享文件的改动 diff 要求确认。
- **目标落点**：`skill/starry-mod/SKILL.md` 归档节 + 各 `archive_*.sh`。

### 2.2 归档提交必须做 blob 体积门禁（候选，高价值）

- **证据**：本次首个提交用 `git add -f` 把 130.2 MB `script.json` 入库，推送必失败；事后才发现。
- **现状**：6 份 `archive_*.sh` 均无体积校验；`archive_zjmc.sh`/`cleanup_zjmc.sh` 仍在用 `git add -f` 绕过 `.gitignore`。
- **候选动作**：归档脚本提交前跑一次「暂存 blob 体积检查」（`git diff --cached --name-only` → `git cat-file -s`，>100 MiB 即拒绝），并禁止对 `06_dumped` 用 `git add -f`。
- **目标落点**：`_common/stages.md` 归档阶段 + archive 脚本模板。

### 2.3 收尾裁剪会让下游 inputs 快照指向已删文件（候选，本次实测）

- **证据**：`prune_output_final.sh --apply` 删除 unsigned APK 后，`sign` 阶段 inputs 仍记录该文件 md5 → status 显示「上游已更新，本阶段过期」，archive 的 `check_stale` 直接拦。
- **候选动作**：收尾流程固定加一步「清理下游 inputs 中对已裁剪产物的引用」，或由 `prune_output_final.sh` 输出提示；**不要**为此重跑整条构建链。
- **目标落点**：`_common/stages.md` 收尾/归档节。

### 2.4 菜单模板 JSON 只列真实功能，feat 0 分类占位不入模板（用户已明确）

- **依据**：用户 2026-09-19 指令「0 是分类占位就不需要在菜单模板 JSON 出现，需要功能的序列」。
- **现状**：存量 4 份仍含 feat 0——`yntt`（战斗）、`rsjy`（战斗）、`dhss`（战斗）、`dcsl`（基础功能）。
- **候选动作**：模板一律从 feat_num ≥ 1 开始列；`Category_*` 只存在于 so 的 `featureList`（客户端渲染分组用），不进后台模板。
- **目标落点**：`skill/starry-mod/SKILL.md` 菜单模板节 + 存量 4 份模板。

### 2.5 `.install_ok` 装机戳应进根 `.gitignore`（候选，低成本）

- **证据**：`04_scripts/暗影格斗3/.install_ok` 每次装机重写（hash+时间），本次才加了 per-game `.gitignore`；其余游戏若新增该戳会一直出现在 `git status`。
- **已落地（本次）**：根 `.gitignore` 增加 `04_scripts/*/.install_ok`；sf3 另有 per-game `.gitignore`。
- **目标落点**：根 `.gitignore`。

### 2.6 文档引用 commit 必须核验真实 hash（候选）

- **证据**：交接文档写 `commit 4922cad`，该 hash 在仓库中不存在（实际 `1fe92ef`），归档时才发现。
- **候选动作**：收尾文档引用提交时用 `git rev-parse --short HEAD` 取真实值，或只写提交标题 + 分支，不写 hash。
- **目标落点**：`10_docs/_templates/游戏收尾与最小复现清单.md`。

### 2.7 大产物校验耗时长导致会话让出（候选）

- **证据**：2.7 GB 正式包的 md5/sha256、`apksigner verify`、`du` 各需 10–30 s，期间会话被交还，用户感知为「老是断开」。
- **候选动作**：大包 hash 一次算完写入 `pipeline.json` 的 `artifacts` 复用；需要重复核验时后台跑并轮询日志，不在前台反复重算。
- **目标落点**：`_common/stages.md` 大包操作节。

### 2.8 会话记录缺固定落点（候选）

- **证据**：2026-09-17 两份经验候选卡引用 `会话记录/`，但工作区内无该目录；本次复盘只能落在 `_state/`。
- **候选动作**：定义会话记录目录（建议 `10_docs/_state/session-notes/`）并在 `TOOLBOOK.md` 目录规范中登记。
- **目标落点**：`TOOLBOOK.md` 目录结构规范。
