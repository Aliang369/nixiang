## 2. 已验证、可复用的关键事实

### 2.1 本作机制（实测，锚点齐全）

- `DS_Advertising::OnGetADInfoRsp 0x06001253` 的 IL：`IL_0043 get_result()` → `IL_0049 brtrue.s` ⇒ **`result != 0` 即游戏自带的「免广告特权跳过观看」分支**；否则 `IL_0064 callvirt BaseSDKAdapter::PlayADVideo` 出画。证据：`06_dumped/冒险与征途/aot/_tgt_il_ad2.txt`。
- 服务端响应经 `ProtocolManager::sendEvent(EventItemInt)` 分发，**`Proto_CSRsp` 就挂在 `EventItemInt+0x20`**（结构发现实测，日志 `AD50 结构发现：容器 cls=EventItemInt 的 +0x20 就是 Proto_CSRsp`）。
- 交付与装机锚点：正式包 `08_output/冒险与征途/冒险与征途_1.5.9_starry-final-releaseSigned.apk`（886768575 B / md5 `c2d7c44cd28fdb834e4e2df9baff816d` / sha256 `8ae5450a1ec350a94592f50ec0db852ebe93077e0240934a3135d0def319b235`），包内 so `560b562fc6da744bf31e752985ea4b92`（2,264,760 B）。
- 验收三条断言实测值：`AD52 retval 约定定案=B(读 r+0x10)（adid=18 result=0 uuid=131202526972572400）`；`AD50[sendEvent] ★set_result(2)：result 0→2（getter 复核 ok=1）`；`STATS 分流 … | AD43 见=0` 且 `TTRewardVideoActivity` 出现 **0** 次、`AD43 已回调=1`、`FATAL EXCEPTION|Fatal signal` = 0。

### 2.2 通用结论（已由并行优化会话回灌，本节只记来源与边界）

- **`runtime_invoke` 返回值口径**：引用类型**直接给对象指针**；值类型是**装箱对象、真值在 `+0x10`**。规则正文 `skill/re-implement/il2cpp-abi-pitfalls.md:222`（坑 9）、`skill/re-implement/hook-rules.md:488`（§28.6「读侧变体：读错偏移的返回值同样是恒真」），单游戏细节 `10_docs/冒险与征途/技能先例.md`。**实证**：同一次调用的三个标量双读 —— 候选A `adid=-1608307296 result=-1608307296 uuid=500902869376`（klass 残段，错）vs 候选B `adid=18 result=0 uuid=131202526972572400`（真值，且与 AD43 从字符串独立解析的 uuid 完全一致）。
- **自证姿势（本作实现，可复用）**：不赌约定 —— 双读 + **业务约束自证**（`uuid` 量级 >1e15、`ad_id ∈ (0,1e5)`、`result ∈ [0,16]` 三条同时成立才定案并缓存），任一不成立即不动手。

### 2.3 L2 边界核验：这条 ABI 坑的**影响面**（本轮新查，实测）

- `mod菜单/starry-mod-menu/app/src/main/jni/Games/*.cpp` 共 **14 个模块**用 `runtime_invoke`：`MxytzMod.cpp` 38 处、`DkzjMod.cpp` 4、`WhrhxMod.cpp` 4、`SlcbMod.cpp` 3、`EndfieldMod.cpp`/`TlgdMod.cpp`/`YnttMod.cpp`/`ZhmrMod.cpp`/`我本布衣世家录Mod.cpp` 各 2、`HzsjMod.cpp`/`JfqsMod.cpp`/`TlgdTapTapMod.cpp`/`WorMod.cpp`/`nhsy2Mod.cpp` 各 1。
- 抽样核对读侧：`DkzjMod.cpp:1200` **忽略返回值**（void 效果）；`SlcbMod.cpp:549` 把 `runtime_invoke` 包成 `SlcbInvoke` **把原始指针透传**给调用方（不在本文件解引用）；`WhrhxMod.cpp:1123` 用它是为「泛型共享 thunk 的调用约定交给 runtime」，同样是 void 效果。
- **结论（推断，证据见上）**：**把返回值当标量/对象解引用**的写法目前**只在本作** `MxytzMod.cpp`（`CdInvoke`/`KILLDEAD` 判据）出现 ⇒ 该 ABI 坑的**跨游戏影响面已收敛**；且 `MxytzMod.cpp:6450` 已由并行会话加**双读探针**（提交 `46c1ac8e`，注释标「**未装机**」）。**未验证**：探针真机效果（需下次装机）。

## 4. 优化方案（可执行，按价值排序）

### P0-1 挂点落点前先取「调用链栈证据」，再决定挂哪一帧
- 问题：v48 因「委托跳不可见」的直觉推断选错落点，白烧一轮装机 + 用户点击（黑洞 1）。
- 方案：在 `hook-rules.md` 挂点五步门禁第 1 步（先定目标语义）与第 2 步（找落点）之间插入**硬前置**：「先取目标方法的调用栈或交叉引用，标注每一跳是**热更解释**还是 **AOT/委托**；委托/反射跳默认假设**不可见**，因此优先挂它的**上游热更调用者**」。
- [落点] `skill/re-implement/hook-rules.md` §22（挂点五步门禁）第 1–2 步之间。
- 成本/风险：低（纯规则补充，无脚本改动）；边界：仅对 IL2CPP + 热更（HybridCLR）成立，AOT 游戏无此问题。
- 验收：下一个游戏出现「委托/事件回调里调 SDK」时，第一版装机即命中（不再出现「有奖励但没拦住」）。
- 状态：**候选**（证据齐，落点明确）。

### P0-2 能调游戏自己的 getter/setter，就不要去解析它背后的字段
- 问题：v48/v49 两轮花在猜 `Proto_CSRsp` 子消息字段名（该族用 `<X>k__BackingField`），而 IL 里 `get_start_watch_ad_rsp()`/`set_result()` 是现成 API（黑洞 2）。
- 方案：在指纹铁律 §24 旁补一条**优先级**：① 游戏自己的**公开方法**（名字来自 IL/dump，长且非混淆）＞② 按名取字段（注意 `<X>k__BackingField`/`_X`/`m_X` 变体）＞③ 结构扫描（仅当前两者都不可行，且必须按类缓存 + 类名自证）。
- [落点] `skill/re-implement/hook-rules.md` §24（指纹铁律）末尾；实例落 `10_docs/冒险与征途/技能先例.md`（已存在，由并行会话建立）。
- 成本/风险：低；边界：`runtime_invoke` 有开销（每次调用跨层），**热路径慎用**（本作只在广告响应这种低频帧上用）。
- 验收：新游戏写「改某个响应/状态」类功能时，不再出现连续两轮猜字段名。
- 状态：**候选**。

### P0-3 「借道游戏自带分支」代替「拦调用」——写完即用可证伪断言验收
- 问题：把 SDK 拉起调用拦掉（不调 orig）在解释器建帧桩上物理不成立，且无可观测判据；用户肉眼也判不准（假 PASS）。
- 方案：写成通用套路：**若目标行为被游戏自己的一个显式分支门控（`brtrue`/`if`），优先改「门控数据」让游戏走它自己的另一条分支**，而不是拦调用/改返回值；交付时必须同时给出**三条可机检断言**（①写入被游戏自己的 getter 复核到 ②被旁路的调用点计数为 0 ③外部副作用（本例广告 Activity）出现 0 次），**肉眼观察不作为验收**。
- [落点] `skill/re-implement/hook-rules.md` 新增一节（建议接在 §28「恒真判据」之后，与 §28.6 同类）。
- 成本/风险：低；边界：仅当游戏**自带**目标分支（本例 `result==2` 的官方「免广告特权」）时可用，否则回到拦调用路线。
- 验收：同类需求（跳过广告/跳过确认/跳过强制引导）第一版即可给出机检断言并通过。
