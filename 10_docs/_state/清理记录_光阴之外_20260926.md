## 8. 遗留事项

1. **`GyzwMod.cpp:199-213 SyncJsState()` 与 `GYZW_FEAT_NOAD` 不一致**：把 `g_noAd` 写进 `ret[4]`，而 `enum GyzwFeat` 里 `GYZW_FEAT_NOAD = 5`（`[4]` 是 `Category_广告` 占位）。当前**无功能影响**（免广告实际由 Java 侧 `GyzwHooks.shouldSkipAd()` 驱动，不走 JS 数组），但属命名/索引错位，建议下次顺手改为 `ret[5]`。
2. **PVP 对账风险未处理**：斌哥 boot JS 头注释自注「竞技场有 replay 战报上报 + 战斗种子确定性 ⇒ PVP 大概率服务器可对账」。星空版保持同样保守策略（伤害只放大「英雄/领主→怪物」单向、无敌留 91~95% 血地板），**未做任何屏蔽上报/防封号**。
3. **免广告的服务端校验风险**：客户端直接伪造激励视频回调（`onResult(0,"视频观看完成")` + `onAdClose("广告页面已关闭")`），若服务端对奖励发放做对账，理论上可被发现。
4. **`libtoolChecker.so`（RootBeer）未移植**：斌哥包独有（5,512 B），官方原版与本作均无。
5. **热更锚点脆性**：4 处 JS 锚点是源码串匹配，游戏热更改动这几行时对应功能会静默失效（替换体自带 `try/catch` 兜住，不会崩游戏）；届时需重跑 `dump` 阶段取新 `gyzw_boot.js` 重核锚点。广告门控依赖 `classes3/4.dex` 具体方法体，游戏更新 dex 后需重跑 `surgical`。
6. **免广告是否应改到 JS 层未决**：当前用 smali 门控（因 boot JS 加密、广告流锚点未确认）；若后续能在解密后的 boot JS 里定位到 `adsPlay`/`watchAd` 类调用点，可改为纯 JS 短路，从而与 dex 结构解耦。
