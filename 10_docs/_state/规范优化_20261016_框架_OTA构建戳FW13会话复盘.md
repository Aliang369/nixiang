### 2.2 `--gc-sections` × 可见性 × `retain`（机制 A/B，已自证）

微用例（NDK 27 / clang 18，`aarch64-linux-android21-clang -shared -fPIC -O2 [-fvisibility=hidden] -fdata-sections -ffunction-sections … -Wl,--gc-sections,--strip-all`）：

| 变体 | `STAMP_KEEP`（带 `retain`） | `STAMP_DROP`（无引用无 `retain`） | 结论 |
|---|---|---|---|
| 默认可见性 | 在 | **在** | 未引用符号是动态符号表 GC 根 ⇒ 不被回收（**不能用来复现**） |
| `-fvisibility=hidden`（镜像真实构建） | 在被回收（A 版） | 被回收 | 复现了本仓缺陷 |
| `-fvisibility=hidden` + 只给 KEEP 加 `retain` | **在** ✅ | 被回收 | **`retain` 有效** |

真实构建对照：修复前包内 so `grep -a -c STARRYSTAMP` = **0**；修复后构建期断言打印 `STARRYSTAMP1:EPOCH=1792090972`（戳＝`git log -1 --format=%ct`，注入点 `Application.mk:11`）⇒ **同源重建戳相同**（不会误清玩家已下载补丁），且比任何更早发布的 OTA so 都大 ⇒ 覆盖安装会正确清 OTA。**判定：实测事实。**

- 方案：① `archive_scoped_git.sh` 在检测到暂存区含**共享文件**时，强制完整逐行打印该文件的 `git diff --cached`，并要求显式 `--ack-shared`（否则中止）；② `stage_shared_file.py` 默认 `--dry-run`，且要求至少给出一个 `--drop-pattern` 或 `--ack-shared` 才写索引；③ 在 `AGENTS.md` §2 把「逐行确认」写成可执行的命令而非纪律文字。
- [落点] `04_scripts/_common/archive_scoped_git.sh`（STAGED_ONLY 分支前的共享文件校验处，约 §「共享文件硬门禁」段）；`04_scripts/_common/stage_shared_file.py`（argparse 与写索引前）；`AGENTS.md` §2 第 4 条。
- 成本/风险：低（纯校验与提示）。验证：造一个「两行改动、只应提交其中一行」的 fixture，跑一次应被拦；`--ack-shared` 后放行。
- 状态：**候选**。

- 问题：FW-13 的成因是「编译到 ≠ 在产物里」。仅靠各游戏 mk 自觉加 `--undefined` 会漏（32 个 mk）。

- 成本/风险：低。验证：故意删掉 Utils.cpp 的 `retain` 重编一次 ⇒ 门禁必须 FAIL。
- 状态：**候选**（本游戏私有断言已落地，通用化未做）。

### P1-1 装机闭环核对补「运行中的 so」（通用，源自本次事故的核心盲区）
- 问题：`verify_installed_apk.sh` 只比**设备 base.apk md5**；而 `extractNativeLibs=true` 的包**运行时加载解出来的那份 so**，可被 root/热替换改掉 ⇒ 出现「核对通过、跑的是别的 so」。

- [落点] `04_scripts/_common/verify_installed_apk.sh`（末尾新增判定）；`04_scripts/_common/install_starry_apk.sh` 调用处同步（其已复用该脚本）。
- 成本/风险：中低（需 root 读 `/data/app`；非 root 设备降级为 SKIP+提示）。验证：在真机上 `so_hotswap.sh` 换一份 so ⇒ 该门禁应 FAIL。
- 状态：**候选**。

### P1-2 编辑效率：同一文件多改的往返（通用）
- 问题：本轮 ≥10 次「读态失效」往返（§1 黑洞 2）。
- 方案：在编辑纪律里补可操作写法：「同一文件多处改动 ⇒ 先一次读全/分段读全，再在同一轮内连续 edit；若位置已知且改动大，直接一次 `write` 覆盖（write 不依赖读态）」。同时把「`edit` 报 `file changed since it was read`」视为**读态过期**的固定含义，不要再当成冲突告警反复排查。
- [落点] `AGENTS.md` §5「同文件串行编辑」条；`TOOLBOOK.md`（工具与目录 → 编辑工具行为）。
- 成本/风险：低。验证：下一会话同文件 3 处改动应 ≤2 次工具调用。
- 状态：**候选**。

### P1-3 OTA 守卫的存量兼容边界要写进分发说明（框架相关）

- [落点] `skill/starry-mod/SKILL.md`（「清数据 = Mod + 热更资源双杀」节内或紧随其后）。
- 成本/风险：低。状态：**候选**。

### P2-1 外科脚本的输入默认值应「能找到」，并前置核对（单游戏专属，但有通用启示）
