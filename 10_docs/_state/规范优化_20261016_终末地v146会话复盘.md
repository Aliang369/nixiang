## 2. 已验证、可复用的关键事实

### 2.1 「首启幸存 / 重开必崩」=「init 前触碰 il2cpp」的指纹（跨游戏可复用）

- 两例实锤：`Games/ZhmrMod.cpp:59-78`（3.6.0 根因注释 + `Hooked_Il2cppInit`）与本作 v14.5→v14.6。机制：mod 线程在 `il2cpp_init` 完成前碰 il2cpp ⇒ 进 GC「未知线程」毒态 ⇒ UnityMain 触发 GC 即 `abort()`。
- 本机指纹（小米 `96f0d883`）：`ApplicationExitInfo` 显示 12:44 **首启存活 5 分钟（RSS 1.5GB）**、12:50 起**每次开必崩**（status 11→6），且崩前我们**早于** Unity `MemoryManager` 触碰 il2cpp（`21:03:06.681` vs `21:03:07.162`）。
- **处置铁律**：首次触碰 il2cpp 必须有**真就绪信号**；固定延迟与「捕获异常后重试」都不算（本作 v14.5 的 SafeProbe 就是反例：接住了 SIGSEGV，但毒态已种下 ⇒ 0.5s 后换成游戏自己 abort）。

### 2.2 无 root 也能拿全崩溃证据（不必换设备）

- `logcat -b crash` 的 `F DEBUG` 块含系统 `debuggerd` 的**完整 27 帧**（调用栈不因无 root 缺失）。
- `dumpsys activity exit-info <pkg>` 给**完整崩溃史**：`reason=5 APP CRASH(NATIVE)` + `status` = 11/6/5 ⇒ SIGSEGV/SIGABRT/SIGTRAP，附时间/进程/RSS。
- root 只多给 `files/tombstone_*`（0600）、`/data/tombstones`、`/data/data/**` —— **本轮不需要**（同一份帧 logcat 里已有）。

### 2.3 「打开就闪退」常是多层，修好一层会露出下一层

本作实测三层，各自归属不同：`SIGSEGV`（我们 so 内，v14.5 修）→ `SIGABRT`（FW-20 就绪门，v14.6 修）→ `SIGTRAP`（**游戏自身** Vulkan 断言，慢启窗口出现，FW-23 定案**不改**）。

### 2.4 `ModEntry` 的 `*Ms` 字段实际单位是**微秒**（FW-22）

- 锚点：`Games/ModEntry.h:41`（字段注释）+ `MainModern.cpp:230/238/248/262`（一律 `usleep(...)`）；框架默认 `tickIntervalMs=200000` = 200ms 可证。
- 本作原值 `2000`/`2000`/`300` ⇒ 实等 2ms / 2ms / **0.3ms**；实测 **~2300 次 tick/秒**（`precheck_20261016_212826`：479 条就绪门日志 / 4.1s）。
- 后果：按 **tick 计数**设计的退避节拍（`tickNo + (1<<shift)*7`，本意 2.1s）退化为 ~67ms ⇒ 指数退避**实际失效**（FW-18 的高频重解析风险复发）+ 日志噪声。
- 已改：`0` / `2000000` / `300000`（commit `199d3226`）。

### 2.5 ndk-build 只改 `-D` 不重编 ⇒ 构建戳陈旧

- 戳来源 `Application.mk:12` 的 `git log -1 --format=%ct`；定义在 `Includes/Utils.cpp`。
- 实测：`obj_mrfzzmd/local/arm64-v8a/objs/starry_magic/Includes/Utils.o` mtime 停在 20:33 ⇒ v14.4/v14.5/v14.6 三连构建共用 `1792153771`。修法：构建前 `touch jni/Includes/Utils.cpp`（本次人工做过，未写进脚本）。

### 2.6 MIUI 抓栈会让预检的裸 `tombstone` 关键字误判（FW-21）

- 锚点：`04_scripts/_common/post_install_precheck.sh:108`（`RE_CRASH` 含裸 `tombstone`）、`:133`（`crash_ignore` 是**覆盖**语义 `RE_CRASH_IGNORE="$v"`）。
- MIUI 的 `ScoutManager`/`DumpScoutTraceThread` 为前台 App 抓 Java 栈时会连打四行（`registered intercept … kDebuggerdJavaBacktrace` / `received crash request for pid …` / `found intercept fd …` / `skipping tombstone file creation due to intercept`）⇒ 每次抓栈都 FAIL_A（本轮连吃两次）。
- 本作已用游戏私有标记收窄（精确 `crash` 签名 + 带默认四项的 `crash_ignore`）：`10_docs/终末地/预检标记.txt`。

### 2.7 就绪门实现要点（可抽公共头）

`Games/EndfieldMod.cpp` 的 `ArmIl2cppInitGate()`：`dlopen(sec_lib_il2cpp(), RTLD_NOLOAD)` + `dlsym("il2cpp_init")` → 失败退 `Il2Cpp::ResolveExport`（dynsym 自解析 + 诱饵过滤）→ `Il2Cpp::IsExecutableRange(fn,16)` 校验 → `DobbyHook`；回调**先调原函数再**置 `g_il2cppInitDone`；`SyncHooks()` 在 `EnsureApi()` **之前**过门（门未开时**一次 il2cpp 调用都不做**）；30s 时间兜底防死锁；v14.5 的「登记线程 + SafeProbe」降为最后兜底。L2 实证本机 `dlsym` 即命中（`就绪门已挂 @0x… (dlsym)`），无需走 dynsym 兜底。

## 4. 优化方案（可执行，按价值排序）

### P0-1（FW-21 根治）预检的 MIUI 抓栈误报
- 问题：`RE_CRASH` 默认含裸 `tombstone`；`crash_ignore` 是**覆盖**语义 ⇒ 想在标记里加一条就得手抄默认四项（本作已被迫如此）。
- 方案：默认 `RE_CRASH_IGNORE` 追加 `kDebuggerdJavaBacktrace|Wrote stack traces to tombstoned|skipping tombstone file creation|received crash request for pid|found intercept fd`；把 `:133` 的赋值改成**追加**（`RE_CRASH_IGNORE="${RE_CRASH_IGNORE}|$v"`）。
- [落点] `04_scripts/_common/post_install_precheck.sh:108`（`RE_CRASH` 定义）、`:115`（默认 `RE_CRASH_IGNORE`）、`:133`（`crash_ignore)` 分支）。
- 收益/风险：所有 MIUI/HyperOS 真机的 L2 预检不再误判 FAIL_A；风险低（精确签名仍覆盖真崩）。验证：在小米机上跑一次预检命中 Scout 抓栈窗口，不再 FAIL_A，且默认四项仍生效。

### P0-2（FW-22 根治）`ModEntry` 的 `*Ms` 字段实际单位是微秒
- 问题：字段名与单位不一致，编译器与现有审查维度都拦不到，只在真机日志节拍上暴露；同仓另有多款按毫秒写（`ArknightsEntry` 200 / `CzbhzEntry` 1000 / `DcslEntry` 1000 / `DkzjEntry` 15000）。
- 方案：① `ModEntry.h` 改名 `*Us`（或 `MainModern.cpp` 改 `usleep(v*1000)` 并为旧名留兼容）；② 过渡期各 entry 统一微秒；③ 加机器关：`.tickIntervalMs = <10000` 即告警。
- [落点] `mod菜单/starry-mod-menu/app/src/main/jni/Games/ModEntry.h:41`、`MainModern.cpp:230/238/248/262`、`04_scripts/_common/preflight.sh`（新增 lint 段）。
- 收益：消除一整类静默性能/退避失效缺陷。验证：`grep -rnE '\.tickIntervalMs = [0-9]{1,4},' Games/*.cpp` 无命中。

### P1-1（FW-20 通用化）把就绪门抽成可复用头 + 写进框架契约
- 问题：机制只在 `Games/EndfieldMod.cpp` 内；下一个「框架 tick 早于引擎就绪」的游戏会重写一遍。
- 方案：抽 `Includes/Il2cppInitGate.h`（照 `Includes/ModThread.h` 的收口先例），并在 `MainModern.cpp` 契约注释写明「首次触碰 il2cpp 必须有真就绪信号」。
- [落点] 新文件 `mod菜单/starry-mod-menu/app/src/main/jni/Includes/Il2cppInitGate.h` + `Games/EndfieldMod.cpp` 改为调用方 + `MainModern.cpp` 顶部契约注释。
- 验证：抽头后 Endfield 重编 + L2 复跑日志链不变（`就绪门已挂 → 返回 1 → hooks sync`）。

### P1-2 构建戳缓存（一条命令消除）
- 问题：`Utils.o` 缓存导致「同源不同提交共用一戳」，覆盖安装可能不清旧 OTA so。
- 方案：外科脚本在 `ndk-build` 前 `touch app/src/main/jni/Includes/Utils.cpp`（或修 `Android_*.mk` 对该 `-D` 的依赖）。
- [落点] `mod菜单/starry-mod-menu/scripts/surgical_endfield_1.6.4.sh:198`（`[1/6] ndk-build` 之前）；通用化到全部 `surgical_*.sh` 或模板 mk。
- 验证：连做两次构建（中间提交一次），两次戳分别等于各自 HEAD 的 `git log -1 --format=%ct`。

### P2-1 预检自证退出码

### P2-3 崩溃追因的固定第一步
