## 3. 可执行方案（按 ROI 排序）

### P0 · 开工 preflight（最高 ROI，半天内可落地）
- **产物**：`04_scripts/_common/session_start.sh <游戏>`，一条命令打印/生成：
  1. `10_docs/{游戏}/硬约束.md`（缺失则**报错退出**并从 [`_templates/硬约束.md`](../_templates/硬约束.md) 生成骨架，要求当轮抄用户原话）；
  2. `路线锁定.md` 的「未确认偏离」条数（>0 拒绝装机）；
  3. 台账的**已否证清单**（禁止重试区，见 P3）；
  4. 本游戏 pipeline 注册状态（无 ⇒ 提示"机械动作将无管线出口"）；
  5. `TOOLBOOK.md`「本机 / 真机坑位」节（见 P4）；
  6. 会话预算：当前消息序号 / 活跃压缩块数（对 P6 会话预算：工具调用 ≈600、装机 ≈40、阴影 ≈150K）。
- **判据（写进 AGENTS.md 一行）**：未跑 preflight 不得改功能代码、不得装机。
- **工时** ≈1 h。**收益**：直接消灭第 1 / 4 / 9 类；本次会话的两个最大损失（自定交付形态、服务器事故）都在覆盖内。

### P1 · 方案选型卡（20 min）
- **产物**：`10_docs/_templates/方案选型卡.md` + AGENTS.md 一行硬规则。
- **触发**：任何**写外部机器 / 出网 / 改用户资产 / 变更交付形态**的动作。
- **卡片内容**：3 个方案 × {做法 / 影响面 / 回滚方式 / 残留风险 / 需要你决定的一点}，**等用户选，未选不动**。
- **收益**：消灭第 2 类事故（本次 1 次事故 + 全量还原 ≈1 h 与信任损失）。

### P2 · 判据先行 + 先例检索（规则，0 工时）
- **判据先行**：凡「投递 / 加载 / 生效」类问题，先用**单变量对照实验**确定客户端判据（改名 / 改内容 / 改时间戳各一次），把判据行写进台账，**再**设计实现。本次靠两轮被证伪才发现「判据＝文件名存在性」。
- **先例检索**：动手前 3 分钟 `grep -ril "<机制关键词>" 10_docs/ skill/ 04_scripts/`；命中即照先例（本次若先读蜀汉传 AB-14/15/23，可省掉 11.4 GB 的死路实验）。

### P3 · 结论台账 `10_docs/{游戏}/台账.md`（15 min）
- **格式**：append-only 三列 —— `结论 | 决定性证据行（log 原文 + 时间） | 状态（成立 / 已否证 + 日期）`。
- **已否证区 ⇒ 禁止重试清单**，由 P0 preflight 打印。
- **收益**：本次结论散落在 7 个压缩块里，多次重新推导（同名结论推导两次、404 因果两次）；台账是抗压缩的最小载体。

### P4 · `TOOLBOOK.md` 增「本机 / 真机坑位」节（40 min）
- 把 §2 第 5 行那批坑逐条写成命令级短文：**现象 → 正确写法 → 判据**（例：`su -c` 重定向必须 `adb exec-out su -c "cat f" > local`）。
- **纪律**：踩到新坑**当轮落一行**（30 s 成本），跑同类命令前先 grep 本节。
- **收益**：每次省 1–3 轮；本次同类坑重复 ≥8 次。

### P5 · 一键构建/装机/取证链路（2–3 h）
- **产物**：`04_scripts/{游戏}/cycle.sh`（或 `_common/pkg_cycle.sh <游戏> <模块>`）：
  `gradlew assembleRelease` → 自动 `versionCode+1` → `zipalign -f -p 4` → `apksigner`（保留既有证书，可覆盖升级）→ `verify` → `install -r -d` → 可选 **root 直拉服务自测** → 抓 4 条决定性日志 → 输出汇总表。
- **顺带**：把 `flight_recorder.sh`（游玩期连续取证 + 用户「标记」）接进链路，替代手工 `logcat`。
- **收益**：9 版 × 6 步 → 1 条命令；同时消灭 versionCode/命名/证书类低级错。

### P6 · 出包判据（1 h）
- **正式包扫描**：出包前 grep `BuildConfig.DEBUG` / 诊断 extra（`--ez starry_selftest` 类）/ 诊断文案，命中即拒绝出包或明确标注为诊断包（对应 `经验候选卡_诊断脚手架隔离与干净正式包`）。
- **预检脚本**：`post_install_precheck.sh` 加 `--helper-pkg`，开跑先 `am force-stop <助手包>` 再录制，消除第 9 类假阴性。

### P7 · 门禁即时记账（0.5 h）
- 每过一门禁（G1 静态/构建/签名 → G2 运行 → G3 可交付）**当轮**在收尾表记一行 + `pipeline.sh <游戏> gate <阶段>`，不留到收尾补。

### 4.2.2 为什么第一轮的 P0–P7 又失效了

第一轮落地的机制**全部还在**（`session_start.sh` / `prior_art.sh` / `台账.md` / TOOLBOOK 坑位节 / `gradle_cycle.sh` / `check_release_apk.sh` / `gate_note.sh`）。本轮失效的共同结构：

1. **纪律靠人记**：P10「未跑 preflight 不得装机」是写在 AGENTS.md 里的**一句话**，没有任何东西会因为你没跑而拒绝执行 ⇒ 本会话装了 8 次机、改了 4 版代码，全程没跑 preflight。
2. **触发点被跳过**：P13 方案选型卡的触发条件写了「变更交付形态 / 需要用户做额外动作」——v3.6 加自启动恰好命中，但**由 AI 自评是否命中**，自评即失效。
3. **出包证据靠调用方**：P15 要求当轮记账，但脚本只「提醒」、md5 只打在 verify 行 ⇒ 一旦日志被截断就永久丢失。
4. **自测没有影响面概念**：三条自伤全部发生在**直接动用户正在用的链路/设备**时（DNS、探针、`am force-stop` 助手），做之前没有 before 快照，做完不复原，也不在汇报里写「已复原」。

⇒ 第二轮的原则：**能机械拦的一律做成闸门，拦不住的一律做成模板 + 快照**，不再新增「请记住」型规则。

### 4.2.4 本轮又踩到的本机坑（已进 TOOLBOOK / 本机坑位节）

- **macOS bash 3.2 + `set -u`：`$VAR` 紧跟中文会被吞进变量名**（`gradle_cycle.sh:137: LOG_FILE）： unbound variable`）。本轮新写的脚本一次命中 10 处，用一次性 python 正则 `\$([A-Za-z_]\w*)([^\x00-\x7f])` → `${VAR}` 全量修掉；写中文串时**一律写 `${VAR}`**。
- **进程替换 `exec > >(tee …)` 是异步的**：脚本立刻退出时日志可能还没落盘（`ls` 看不到新日志）。退出前 `sleep 0.3`。
