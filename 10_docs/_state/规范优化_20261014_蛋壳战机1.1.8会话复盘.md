### 本会话 token/时间黑洞（按代价排序，top-5）

1. **把「用户口述的功能缺口」直接当成必做需求深挖** —— 现象：为「偷盗技能对武器不升级」连开三轮静态探查
   （配置包解包 → `SkillGroup_UpgradeSkillGroup` 表映射 → capstone 逐函数反汇编），
   用户 m01299 直接发问「你在干什么？我让你修偷盗技能不能升级的问题」。根因：没有先做
   **3 行最小验证**（把 `PickNextTier` 的 `next` 源提前到第 3 位即可用真机日志判定武器走不走得到 `next`），
   也没先问「武器升级要不要做」。本可：需求到手先问收益/成本，或先出最小可判定改动再决定深浅。
2. **配置包 LZMA 解包白写一轮** —— `localmodel_assets_all_*.bundle` 的 block 压缩类型实际是 LZMA
   （`fl&0x3f == 1`，数据起点 0x8E），而 `04_scripts/无限升级/unityfs_uget.py` 硬编码 LZ4 ⇒ 直接失败。
   本可：先 `od -A d -t x1` 读头判压缩类型，不支持下就放弃；且技能表本可由运行时 API 读，
   配置包最终确实没用上。
3. **1.1.7 旧 dump 反复重跑** —— `il2cpp_dump_1.1.7_recheck`(103 MiB) + `static_inspect_1.1.7_recheck`(218 MiB)
   在收尾时被整批清掉。本可：接手新版本时先确认「旧版本 dump 是否还要用」，只保留当前版本一份。
4. **`edit` 误删两行** —— `ResolveSkillAux()` 的 `GameGetTableFn fn = reinterpret_cast<GameGetTableFn>(` 行与
   `ReadIntArrayField()` 的 `if (!OkPtr(obj) || !out || capacity <= 0) return 0;` 行被「插入」操作误做成删行，
   两次编译前返工。本可：插入类编辑的 `old_string` 取「锚点行 + 上下各 1 行」，改完 `sed -n` 目视复核。
5. **`trash_paths.sh --suggest` 静默失败** —— 该游戏 `pipeline.json` 无 `game_id`，
   `suggest_paths()` 里 `id="$(grep -o '"game_id"…' | head -1 | sed …)"` 在 `set -euo pipefail` 下
   命令替换失败即整个脚本退出（约 `04_scripts/_common/trash_paths.sh:104-110`），白跑一轮。

`LocalModelEx.GetSkillDeepType` `0x68F3910`)，把升级技能**加权放进随机池**而非立即授予。

## 4. 优化方案（可执行，按价值排序）

### P0-1 需求成本前置：口述缺口先做「3 行最小验证」
- 问题：把用户一句「武器不会升级进化」当成必做需求，连开三轮深挖，最后被叫停全部回退。
- 方案：功能缺口类需求一律先给出**最小可判定改动**（例：调整 sources 顺序/加一行日志）→ 真机跑一次 →
  用证据决定是否继续；用户未表态前不做表结构级逆向。
- [落点] `skill/re-analyze/SKILL.md`（决策树之后新增「需求成本前置」小节）。

### P0-2 长链路探查的强制汇报点
- 问题：探查期间用户不知进展，触发 m01299 式质疑。
- 方案：同一方向连续 ≥15 次工具调用仍无结论时，先输出一段「已知/未知/下一步/预计代价」再继续。
- [落点] `AGENTS.md` 协作节 + `skill/re-analyze/SKILL.md`。

### P1-1 `trash_paths.sh` 的 `game_id` 容错
- 问题：`--suggest` 在该游戏无 `game_id` 时静默 rc=1。
- 方案：`id` 取值改为 `grep -o … || true` + 空值回退到游戏名匹配；空值时打印明确原因。
- [落点] `04_scripts/_common/trash_paths.sh:104-110`。

### P1-2 空白门禁给「收到的第三方证据」加豁免
- 问题：vendor 原始日志尾部空行会中止提交，只能归一化（改了字节）。
- 方案：`archive_scoped_git.sh` 的 `git diff --check` 排除列表追加 `':(exclude,glob)10_docs/**/收到_*/**'`。
- [落点] `04_scripts/_common/archive_scoped_git.sh:271-285`。

### P2-1 旧版本 dump 的生命周期
- 问题：1.1.7 recheck 两份 dump（≈321 MiB）在新版本接手当天生成、当天清理。
- 方案：接手新版本时先确认旧 dump 是否复用；不再复用则不生成「_recheck」双份。
- [落点] `04_scripts/_common/stages.md` 收尾节（可再生候选表说明）。
