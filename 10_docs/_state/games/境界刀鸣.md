## 闪退根因与修复（核心成果）

- 根因：**非官方签名**会触发 `libhhld-rt.so` 内一条 thread_local 析构回调路径，记录里的析构函数指针 `[x19+8]` 被破坏成野地址 `0x18a44`，随后 `blr x8` 跳过去必崩（`pc=lr=fault_addr=0x18a44`，四份 tombstone 逐字节一致）。
  - `libhhld-rt.so` 是**受害点不是校验者**；真正的校验者仍未定位。
  - `hhld` 三件套（`lib/arm64-v8a/libhhld-rt.so` 1199664 B、`lib/x86_64/libhhld-rt.so` 1265008 B、`assets/hhld_info.json` 240 B）是 APK 内唯三 18:27 时间戳（其余 18:22~18:23）⇒ 构建后注入。
- 修复（两 ABI 各一处 NOP）：
  | ABI | 文件偏移 | 原字节 | 指令 | 补丁字节 |
  |---|---|---|---|---|
  | arm64-v8a | `0x5c270` | `00 01 3f d6` | `blr x8` | `1f 20 03 d5` (nop) |
  | x86_64 | `0x5f99d` | `ff 53 08` | `callq *0x8(%rbx)` | `0f 1f 00` (nopl) |
- **已固化进构建脚本** `mod菜单/starry-mod-menu/scripts/surgical_jjdm_1.39.211507.sh`：`[6/6] zip surgical merge` 内 `HH_PATCH` 常量 + 补丁点断言 + 透传 hash 排除 + 签名后成品字节二次校验（`hhld NOP 2/2`、两处 `OK`）。
- 对照实验（同一设备、冷启）：官方签名原版稳 80s+；零注入重签（全新数据）t=14s DEAD；同包就地 NOP 后稳 80s+；完整成品包 + 数据恢复后稳 120s 且进到服务器列表。
- 附带发现：`libhhld-rt.so` 是启动 ~13s 才被 dlopen（`ApkSoSource: not allowing consideration of lib/arm64-v8a/libhhld-rt.so: deferring to libdir`），重签包正是崩在这个时刻；所有 `lib/*.so` 均 DEFLATED、Manifest 无 `extractNativeLibs`（默认 true）⇒ 可直接改 APK 内 .so 再签名。

## 三功能不生效的真正原因：4 个注入侧 bug（已全部修复，真机验证生效）

全部在 `Games/JjdmMod.cpp`，与游戏加固/校验无关。完整版见 `10_docs/境界刀鸣/三功能不生效_根因与修复_20260924.md`。

| # | bug | 症状 | 修复 |
|---|---|---|---|
| A | `g_wantSync`（只被写）与 `g_needSync`（只被读）是两个变量 | 菜单已 ON，`state` 恒为启动值 | 删 `g_needSync`，统一到 `g_wantSync` |
| B | `char buf[1024]` 截断拼好的脚本（实际 1823 B） | `loadstring: 27: 'end' expected ... near 'an'`，补丁从未装上 | `char buf[sizeof(kInstallScript)+128]` + 溢出守卫 |
| C | `CF.DoSubHp.__jjdm` —— **Lua 的函数不是表，不能挂字段** | `pcall: 4: attempt to index a function value (field 'DoSubHp')`，`patched=0` | 用 `__jjdm_wrap` 表做身份比对（`W.cf==CF and W.sub==CF.DoSubHp`） |
| D | 安装脚本命中守卫时提前 `return`，与写开关拼在**同一个 chunk** 里 | `patched=1 wrap=yes` 但 `dmg/inv/nocd` 永不更新 | 拆成两个独立 chunk；加 `[Jjdm] sync …` 限流探针 |

另有两处同链修复：Dobby arm64 patch 宽 16 B，`lua_pcall`(size=12) 会被越界踩坏紧随的 `lua_tonumber`(size=8) → SIGILL，改为只 hook `lua_gettop`(28 B) / `lua_pcallk`(332 B)；`SignalQuarantine` 的 seccomp 拦致命信号 ⇒ 注入包无 tombstone，SIGILL 只能靠 `Zygote:` 行发现。

## 装机流程铁律（本轮踩坑）

1. **`pm uninstall` 前必须先 `mv /sdcard/Android/data/<pkg>` 挪开**，否则热更缓存（本次 2.9G）被删。
2. **恢复 `/data/data/<pkg>` 绝不能 `rm -rf` 顶层再 `mkdir`**：installd 建的顶层带 `u:object_r:app_data_file:s0:c116,c259,c512,c768`，手工重建后子项会被 `restorecon` 打成 `system_data_file:s0`，app 读 `shared_prefs/tt_game.xml` 报 `EACCES`，导致 `requestCheckHasAgreePrivacy` 每 33ms 死循环、游戏卡隐私门（表现为"不崩但永远进不去"）。正确顺序：先安装 → 覆盖内容 → `chown -R <新uid>:<新uid>` → `CTX=$(ls -Zd /data/data/<pkg> | awk '{print $1}'); chcon -R "$CTX" /data/data/<pkg>`。脚本：`/tmp/jjdm_test_full.sh`。
3. 卸载重装必换新 uid；取 uid 用 `cmd package list packages -U | grep blade`。内嵌 base.apk 须 `su -c` 读。

## 实现（四件套 + 外科脚本，modern 注册表）

- `mod菜单/starry-mod-menu/app/src/main/jni/Games/JjdmMod.{h,cpp}` + `JjdmEntry.cpp` + `Android_jjdm.mk`（`LOCAL_SRC_FILES` 必须含 `SignalQuarantine.cpp/FgoBoot.cpp/CrashTrap.cpp/AceStub.cpp/Ts2DummyExports.c`）。
- 挂点（**已改为纯 Lua VM 入口路线，零 il2cpp 依赖**）：Dobby hook `libgame.so` 的 `lua_gettop`(0x515e38, 28 B) 与 `lua_pcallk`(0x518fec, 332 B) → 直接从参数拿 `lua_State*`，再用 `luaL_loadstring` + `lua_pcall` 注入。
  - **放弃 il2cpp 路线**：本游戏 `libil2cpp.so` 的 dynsym 名↔址被 TP 打乱（readelf 标 `il2cpp_class_from_name` 的 `0x257b278` 实际是 `il2cpp_domain_get_assemblies`），按名取 `GameFramework.LuaManager` 不可靠。
  - 实测只有**一套** `lua_State`（`nstates=1`），且 Lua 逻辑跑在非主线程（hook 首次触发 tid≠主线程）。
- 补丁：包 `CombatFunc.DoSubHp`（英雄攻击 ×N / 英雄受击 return 无敌）+ 包 `CombatFunc.EnterSkillCd`（英雄 no-op）；英雄集 `CTXDefine.ENTITY_TYPE.HERO=2 / AID_HERO=11 / MONSTER=3`。
- 菜单：`Category_战斗` / `Slider_伤害倍率:1:100:1`（**默认 1 = 无加成，铁律**）/ `Toggle_无敌` / `Toggle_无限技能`（默认 OFF）；`tickIntervalMs=200000`（微秒=200ms）。
- `initRetryMax=0` 语义坑：框架只在 `initRetryMax>0` 时调 `tryInit`，模块须自己在 Tick 里补 `Jjdm_TryInit(nullptr)`（每 ~400ms）。
- 签名伪装：`sign/SignSpoof.java` 的 `JJDM_PKG` + `JJDM_CERT_B64`；强制网页登录：`sign/TapLoginForceWeb.java` 白名单加 `com.blade.bd`。
