## 当前摘要

- **底包身份**：雷霆渠道包名但内置 TapTap SDK；versionName `1.26.0.331`／versionCode 231／minSdk 24／targetSdk 30／`arm64-v8a`／v2 签名／单 base.apk 无 split；`assets/leiting.properties` → `game=slcb`、`channels=leiting`、`channelType=110001`。
- **引擎**：Unity **2018.4.30f1** IL2CPP + xLua（`libxlua.so`），metadata version **24.1**；游戏代码命名空间 = `Teran.*`（1654 类）+ `Tera_OB.*`（核心系统层），`Assembly-CSharp` 5116 类。
- **保护 = 网易易盾 NIS 4.22.117**（`application android:name="com.netease.nis.wrapper.MyApplication"`；`assets/shellinfo`、`libnesec.so`、`libNetHTProtect.so`）。它同时做了四件事，**全部已实测确认**：
  1. `classes.dex` 只是壳 stub（16,353,120 B／792 strings／31 classes）；**5 个真 dex 在 APK 里无明文**（全包扫 `dex\n0` 只命中 `classes.dex` 与两个 `libthemis.so`），只存在于运行时 `InMemoryDexFile`（magic 是 **`dex\n037`**，不是 035）。
  2. `libil2cpp.so` 磁盘 [0, `0x3993000`) 整段加密（熵 8.00 + 40 MB 假零区），**装载时在内存解密**：内存映像与磁盘件差异 51,583,232 B（**69.9%**）。
  3. `global-metadata.dat` 磁盘为密文（头部 magic 是 **`HTPX`**，不是 il2cpp 的 `AF 1B B1 FA`），运行时被 **MAP_PRIVATE 原地解密**（内存里读得到 `af1bb1fa 18000000`）——所以外部存储 `Android/data/.../files/il2cpp/Metadata/global-metadata.dat` 也只是密文副本。
  4. ELF 节表被整体错位、符号名被改成随机短名（**strtab 里 `il2cpp_*` 名字个数 = 0**，2698 个 dynsym 全是 `n5`/`d85J_2` 一类）⇒ dlsym/xdl_sym 与所有按名解析必死。
- **决定性结论**：`global-metadata.dat` 解密后**完好** ⇒ 类型/方法/字段名与字符串字面量都能静态读出，而星光框架的 `HookByName` 运行时用 `il2cpp_class_get_method_from_name` 解析指针、**不需要 RVA**。因此路线定为「**metadata 静态枚举名字 + .so 按名 hook**」，完全绕开脱壳后的 so 复原问题。
- **注入路线**（沿用易盾先例 `无限升级`）：**保留壳**，走 ContentProvider `com.starry.magic.StarryInitProvider`（`exported=false`、`authorities={pkg}.starryinit`、**`android:initOrder="2147483647"`**、声明位置不动）+ `MenuService`（`foregroundServiceType=specialUse`）；**绝不替换 `application@name`**（换掉壳就无法解密 dex，启动即 `ThemisProvider ClassNotFoundException`）。注入物 = `classes2.dex`（官方只有 `classes.dex`）+ `lib/arm64-v8a/libc++_shared.so`（官包没有）+ `assets/certs/starlight.crt`。
- **去签名**：外科合并只删 v1 签名 `META-INF/{LC.SF,LC.RSA,MANIFEST.MF}`，**保留 `META-INF/services/*`**（`kotlinx.coroutines.*` 与 `com.qiyukf...UnicornService` 是 ServiceLoader 必需）。官方证书从 `unzip -j base.apk META-INF/LC.RSA` + `openssl pkcs7 -inform DER -in LC.RSA -print_certs` 导出（`keytool -exportcert -jarfile` 在本机不可用），运行时由 `SignSpoof` 回灌。
- **网页强制登录**：设备已装 `com.taptap`，改签后客户端 SSO 必失败 ⇒ 已把包名加进 `TapLoginForceWeb` 的 `PKG_WHITELIST`，实测登录落到 `com.taptap.sdk.login.ui.TapTapLoginActivity`（TapTap 手机号/邮箱 **embedded_web 网页登录页**）。
- **环境阶段已验收**：用户实测「游戏可以正常游玩」；日志证据 `StarrySignSpoof: spoof hit pkg=com.leiting.lostcastle.leiting md5=4c6f8f0aa4506f3db70ffe02c2399d0e`、`MenuService: overlayVisible=true attached=true`、`[Slcb] lib ready (feature stage, kSlots=27)`、`[验证] grant ok`、`MenuService: host layout changed → show ACTIVITY overlay host=TapTapLoginActivity`。
- **功能阶段（当前 22 槽）**：无敌／伤害倍率／无限技能／无限金币／无限魂石 **五项已由用户实测验收**（m01186「无限技能没问题了」）；**免广告**实测命中（`noad.show type=0 -> OnTodayAdFinished`，今日广告直接发奖）。
- **已撤销**：**宝藏猎人执照全解锁**——用户 m01462 决定不做，⑨ 执照段（含 ACTk `ObscuredInt`/`ObscuredBool` 结构体装箱那套自标定）已整块删除。删除后「档案数据存在异常」的嫌疑源随之消失（见下「反作弊」）。
- **反作弊体系实测（与「档案数据存在异常」弹窗相关）**：包内带完整 **ACTk（Anti-Cheat Toolkit）** 程序集 `ACTk.Runtime.dll`（`CodeStage.AntiCheat.Detectors.{ObscuredCheatingDetector,InjectionDetector,SpeedHackDetector,WallHackDetector,TimeCheatingDetector}`、`ObscuredTypes.*`、`Genuine.CodeHash.CodeHashGenerator`）；游戏侧中央惩罚器 = **`Teran.DDSystem`**（`OnCheaterDetectedForObscured/ForSpeed/ForInjection`、`RecoverDetectCheating`、`TurnToMainMenuBecauseCheating`、`OtherPunishmentForCheating`、`QuitGame`、`IsCheckingCheating`）；弹窗文案字段 = **`Teran.UITextCtrl.gamedata_execption_str`**（原文拼写如此），判定/处理器 = **`Teran.GameDataMgr.CheatLoadRecord(argc=2)` + `Teran.GameDataMgr.RecordHash(argc=1, static)`**；另有一路易盾心跳上报 `Teran.LCYiDunInfoReceiver.{CheatInfoAnalyze,HeartBeatError,HeartBeatNetError}`（文案不同：「作弊系统检测到异常,将会退出游戏!」）。**档案本身走服务端**（`Tera_OB.LCServerMgr` + `Teran.GameDataPersistance.DownloadServerDataOver`），设备上无本地存档文件 ⇒ 该弹窗是「从服务器拉回档案后做哈希/字段校验失败」触发的。

## 功能实现（`mod菜单/starry-mod-menu/app/src/main/jni/Games/SlcbMod.cpp`，22 槽）

| 功能 | 目标类/方法 | 手法 |
|---|---|---|
| 无敌 | `Tera_OB.HeroBase.SetIsCanBeAttacked(bool)` / `SetCanBeAttacked_Force()` / `BeAttacked(AttackInfo,float,bool)` | 钉 `isCan=false`／不调 orig／直接 `return 0` |
| 伤害倍率 | `Teran.Creature.calPureDamange(int,int,float,bool,float) -> int` | self 是玩家且无敌 → 0；self 非玩家 → `d *= g_dmg`（int64 中间量防溢出） |
| 无限技能 | `HeroBase.get_Skill`/`DoAction_Skill_GetInfo`（**捕获玩家那个 ActionInfo 指针**）+ `Teran.ActionInfo.{get_IsCanUsed,UsedSkill,UpdateCoolingTime}` + `HeroBase.UseSkill` + `Teran.SkillInfo.{IsCanUsed,get_CoolingTime}` | `IsHeroSkill(self)` = 指针身份比对—— `ActionInfo` 是英雄/怪物**共用**的动作描述对象，直接改全类会连怪物一起加速。**真解是快进 `UpdateCoolingTime` 收到的每帧 `dt`**，让游戏自己的冷却循环一帧走完；**禁止强改 `get_IsCanUsed` 返 true**（游戏只在 `!IsCanUsed` 时才调 `UpdateCoolingTime`，强改会把冷却卡死）；`ActionInfo.get/set_CD_Base` 与 `cdCutDown` 三槽已证明有害，已删 |
| 无限金币 | `Tera_OB.BagSystem.{set_m_money,get_m_money,GetMoney,UpdateMoney}` | 钉 `999`（`kMoneyLock`） |
| 无限魂石 | `Tera_OB.BagSystem.{set_m_soul,get_m_soul,GetSoul,UpdateSoul}` | 钉 `999`（`kSoulLock`）；**魂石＝用户说的「旁边那个货币」（HUD 紫色旋涡图标），字段 `m_soul`** |
| 免广告 | `Teran.OpenAdSDK.{ShowAd(4 参),IsAdReady}` | 开关 ON 时不播广告，按 `adType` 直调游戏自己的 `OnXxxAdFinished()`（映射**运行时从 `Teran.AdType` 静态枚举值读出**，不猜顺序），让「看广告→发奖」路径照常走完；`IsAdReady` 恒 true 保证按钮可点 |

- 全部槽 `rva=0`（易盾毁掉 RVA/符号）⇒ 走 `HookByName`；`SyncHooks()` 懒装，**开关全关 = 0 hook**。
- 🔑 **菜单位号铁律**：`featNum == featureList 下标`（`ModBridge.resolveSpec(int)` 用 `features[featNum]` 取规格、`reapplySavedFeaturesToNative()` 用 `nativeSetFeature(i, …)` 回推）⇒ **挪动菜单项位置必须同步改 `SlcbMod.h` 的 enum 位号**。「免广告」从下标 8 挪到 7 后，`SLCB_FEAT_NOAD` 也改成 7。
- 关键陷阱（已踩）：`Teran.ActionInfo` 的玩家实例**必须在 hook 装上之后**才捕获得到 ⇒ `get_Skill`/`DoAction_Skill_GetInfo` 只做捕获、`IsHeroSkill()` 不看开关状态，否则「先开游戏后开开关」时恒 false（这就是「无限技能没效果」的真因）。
- `Il2Cpp::Api` 成员名易错：是 **`class_get_field`**（不是 `class_get`）、`class_method`（不是 `class_get_method`）、`field_static_get`、`class_name`。非 il2cpp 线程（我们的 Tick 线程）调 `runtime_invoke` 前**必须 `api.thread_attach(api.Domain())`**。
- 值类型（结构体）参数**不要绕过 `runtime_invoke` 的装箱语义自己拼内存**：给它装箱对象 vs 装箱对象 `+16`（跳过 `klass*`+`monitor*` 对象头）两种模式必须**自标定**才知道游戏用的是哪种，猜错会静默写脏 ACTk 的 `ObscuredInt` 后备字段。
