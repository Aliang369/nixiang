## 2026-10-07 建档：4399 星空包稳定架构移植 + 菜单 dex 换新

> 用户原话（m00001）：「真机上面有一个弹力果冻游戏是星空包，这个游戏做的功能经常别人使用闪退或者是功能失效的问题。然后taptap渠道的安装包进行了一次修复，好很多，现在需要借鉴taptap渠道的方式对这个游戏进行一次修改。让功能稳定使用。然后菜单的dex也是旧版的需要更换成新版」

**渠道身份**：`com.ginicat.sweet.m4399` / vc4412 / versionName 2.4.0 / game_id **`tlgd`**（TapTap 为 `com.ginicat.sweet` / vc4409 / `tlgdtt`）。
**真机**：`f9a116a2`（KernelSU root）。

### 起因（问题基线）

设备上已装的 4399 包**确实是星光包**，但两件东西都停在 2026-08-20：

| 项 | 设备上 | 问题 |
|---|---|---|
| `lib/arm64-v8a/libstarry_magic.so` | 132,560 B，mtime 2026-08-20 01:24 | **旧 native**：仍是「后台线程直接调热更方法」的崩溃架构（TapTap 侧已定案根因：`Il2CppExceptionWrapper` 穿 native 边界 → SIGABRT） |
| `classes2.dex` | 293,612 B | **旧菜单**，用户点名要换 |

### 本轮做法

1. **底包来源**：用户决策「从真机 `f9a116a2` 拉当前已装星光包的 `base.apk` 当底包」→ `02_apks/弹力果冻4399/弹力果冻4399_2.4.0_vc4412_device_base.apk`（2,140,909,132 B / md5 `9d20e5b550b442bdab557d041af912f7`）。理由：vc4412 与官方 4399 2.4.0 一致、`classes.dex`/`resources.arsc` 是官方原始字节、且天然与设备已装包**同签名**（可覆盖安装）。
2. **移植 TapTap 七条稳定架构**：整份 `Games/TlgdTapTapMod.cpp` 复用，**唯一差异 = 解释器公共点偏移**。`0xBAAB0C`（4399，历史定稿）vs `0xBABB0C`（TapTap，前移 0x1000）用 `#if defined(STARRY_TLGD_M4399)` 编译期切换，避免复制文件后双份维护漂移。
3. **偏移独立复核**（不信记忆）：`llvm-readelf -l` 确认可执行段 `off==vaddr`（`off 0x0 / vaddr 0x0 / filesz 0x33A3420 / R E`）→ 文件偏移定位前提成立；`llvm-objdump` 确认 `0xbaab0c: a9bd57f6 stp x22, x21, [sp, #-0x30]!` 是干净函数入口。
4. **菜单 dex 换新**：旧 293,612 B → 新 **481,608 B**（当前 HEAD 源码 → apktool 收 `com/starry` smali → `smali assemble -o classes2.dex`）。底包只有 `classes.dex`+`classes2.dex` → 置换不产生下标缺口。
5. **功能位顺序对齐 TapTap**：1秒杀 2全屏秒杀 3无敌 4无限技能（旧 4399 顺序 1秒杀 2无敌 3全屏秒杀 4无限技能 废弃）。
