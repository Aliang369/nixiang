  1. **过检测**：「检测到战斗作弊」＝大厅 `CheckPlay` 本地重放校验失败 → `UIManager.OpenWindow("ForcedWindow", cheat_play_tip)`。
     真实签名是 **`CheckPlay(self, levelData, cb)`（异步回调型）**；压法＝`ShouldCheckPlay` 恒假
     + `CheckPlay` **补偿式**（照游戏通过分支 `pcall(cb,false)`，并把 `_customData.CheatCheckCount` 递减 `n-1`）
     + `TipCheatWarning`/`OnCheatWarning` 吞并清 `CheatWarningTimeLeftKey`
     + `UIManager.OpenWindow` 按「窗口名 + 文案」兜底（**`ForcedWindow` 是通用多选窗，只拦文案含 `cheat`/「作弊」的**）。
     ⚠ 教训：`CheckPlay` 曾写成裸 `return` ⇒ 回调永不到达 ⇒ **打完不结算卡死**（用户 m00726 报障，已修）。
  2. **上报拦截（分层，均为「照发、只改值」）**：L1 第三方 SDK 走 **native DNS 黑名单**（4 个入口：`getaddrinfo` / `android_getaddrinfofornet` / `gethostbyname` / `gethostbyname2`，

     `taptap-ad-callback.service.alina-game.cn`（TapTap 广告归因，本包唯一允许被切的 alina-game.cn 主机）。
     L2 游戏自家域名上的 BI 埋点只能在 **Lua 漏斗层**处理（`BIRequest` 8 出口 + `BINetworkManager` 4 函数 + **重指 `CS.LuaManager.Instance.LuaBISend`**）：
     `WrapForward` 记录→清洗→**原样转发**（表走深拷贝副本，调用方表零改动），压 `RealDamagePerRound` 到 `≤Predicted×1.8`、同比例缩明细、作弊类布尔键置 false；
     `[[9]]`＝设备指纹请求头 `Microfun-Client` 内 `root/jailbroken/hacked` 段 → `stock`。
     L3 `ApiRequest`/`ApiClient.Send("BL*")`（登录/进度/主关卡结算/回放）**刻意不动**。
  3. **为什么这条链路能治本**：`_BIEndQuest` 里 `Cheated = (predicted*5 < real)`（**5× 容忍带**；十倍伤害必判真），而 `Cheated/RealDamagePerRound/PredictedDamagePerRound`
     全仓只被 `SideQuestApi` 写、只经 `BIRequest.EndQuest` 出设备 ⇒ **改 BI ＝ 同时改掉「判你作弊」的输入**。
