## 机制要点

- **与同作者圣翼传说的本质差异**：圣翼传说是 15 处 `ADRP X17/ADD X17/BR X17` Dobby 跳桩；爆裂防线 il2cpp 代码段**跳桩 0 处**。斌哥机制 = 壳运行时用 `il2cpp_class_get_field_from_name` / `il2cpp_field_static_get_value|set_value` **按名反射读写**。
- **Dobby 在本作永久无效（已实测定案）**：对 `zbMonster.ChangeHp` / `zbCombatDefense.ChangeHp` 装桩 `rc=0`，指针 60s 稳定，但 141 次采样 `hits` 恒 `0/0/0` ⇒ HybridCLR 解释器内部分发**不走 `methodPointer`**。⇒ 只能字段写入或改 IL。
- **解析策略**：L1 遍历全部已加载 image（实战 73 个 image、`hotfix loaded=1` 时命中率 100%），L2 按程序集名 open。**v1 的 L3 全内存按类名扫描已整体删除**（1545 MB/s × 4s 跑在游戏线程 ⇒ 启动闪退）。
- **`zbSafeLong` 双副本铁律**：`_obfValue@0 _key@8 _shadowObf@16 _shadowKey@24 _fieldName@32`（40 B）。写入必须 `p[0]=v^key` **且** `p[16]=v^skey`；只写一份 ⇒ getter 校验失败 ⇒ `zbCheatContext.ReportCheat` **主动上报服务器**。
- 取 `field_static_set_value`：dynsym 中与 `field_static_get_value` 相邻 4 字节（`0x2120f6c` / `0x2120f68`）⇒ `set = (void*)((uintptr_t)api.field_static_get + 4)`；`dlsym(RTLD_DEFAULT,…)` 返回 0（GNU hash 未重建）。

## 反作弊审计（结论）

- **本作没有任何屏蔽上报/防封号/反检测处理**；客户端两条上报通道会真发服务器：`zbCheatContext.ReportCheat`（`csout/zbCheatContext.cs:8`，:20 发 `Abnormal_ClientReport_Req`，由 `zbSafeLong/Int/Float` 双影子不一致自动触发）与 `zbCombatHandler.Abnormal_ClientReportOnce`（`csout/zbCombatHandler.cs:716`，由 `IsZuobi()` 触发）。
- `IsZuobi()` 检查项共 8 类（`csout/zbCombatHandler.cs:446/:497/:504/:510/:516/:522/:528/:534-593`）；我方三处写操作**都不落在任何检查项上**。时间加速检查 `:528` 因 `speed3` 与 `Time.timeScale` 同写而恒有 10s 余量、不可能触发。
- 弹窗「系统检测到异常行为，禁止作弊！—6」= `[lang.10668+"_6"]`，全局只有 `csout/zbModSelectWnd.cs:387` 与 `csout/zbEndlessHordeFightForwardWnd.cs:400` 两处，均 `if (IsZuobi())` ⇒ **纯客户端判定结果**。`zbCombatState_Balance.cs:39` 在战斗结算处也调 `IsZuobi()`，命中即**跳过战斗结果上报（丢奖励）**。
- 斌哥包独有 `libtoolChecker.so`（5,512 B，**RootBeer** root 检测库，符号 `Java_com_scottyab_rootbeer_RootBeerNative_checkForRoot`）**未移植**。

## 坑

1. **PyPI 网络已断**（SSL EOF）⇒ UnityFS 只能自制纯 Python 解包器，本会话已把当年的临时脚本固化归档为 `04_scripts/爆裂防线/blfx_unityfs_extract.py`（纯 Python + 手写 LZ4，用法 `python3 blfx_unityfs_extract.py <bundle> [输出文件]`）。同时无法安装 `UnityPy`/OCR，**不能读游戏截图**。
2. `monodis --method` **SIGABRT 崩溃**、`--field` 无输出 ⇒ 改用 `ilspycmd`。
3. `device_scriptdll.ab` 有 16 字节自定义前缀 `ABHEADER12345678`（**非加密**）；blocksInfo 需 16 字节对齐；数据块间无填充。
4. 热更 DLL 在 APK 内的 `assets/assetbundle/hotfixdlls/android/{scriptdll,aotdlls}/*.ab`（UnityFS 包裹），**不是裸文件**；设备 `/data/data/com.muyegame.blfx/files/` 下也没有裸 DLL。
5. pipeline 阶段必须**整链按序**跑：单独 `reset surgical` 报「上游链路已过期」⇒ 用 `for st in build_so surgical sign install; do … done`。
6. **探针读取**：`adb -s f9a116a2 shell su -c 'cat …/blfx_probe.txt'` —— `su -c` 里**不要加双引号**（adb shell 吃掉引号 → `L2: inaccessible or not found`）；探针是追加写，读前先清空。
7. `dlsym(RTLD_DEFAULT, "il2cpp_field_static_set_value")` 返回 **0**（GNU hash 未重建）⇒ 用 dynsym 相邻地址 +4 推导。
8. 伤害倍率观感是「一击秒杀」而非「翻 N 倍」：`capHp=maxHp/mul` 且怪 `maxHp≈503`、单击伤害 ~50 ⇒ `mul≥10` 即秒杀，**设计必然**。
