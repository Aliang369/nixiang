## 菜单方案：已放弃并清理（2026-11-04）

**用户决定**：本作不做 MOD 菜单，只保留静态补丁（改 libil2cpp 偏移）。

**放弃的直接原因**（实测，非推测）：
- so 注入链路本身是通的：改 `DT_INIT` 到 code cave 里 `dlopen("libstarry_magic.so")` 成功，构造函数执行、引导线程运行、日志正常输出。
- 但**注入后在这个进程里再取 JNIEnv 一律卡死**：`dlsym(RTLD_DEFAULT,"JNI_GetCreatedJavaVMs")`、`dlopen("libnativehelper.so")` 都会让进程卡住直到被信号打死；
  推迟到 5 s（`DT_INIT` 早已返回、链接器锁早释放）后仍然一样 ⇒ 与链接器锁无关，是「二次动态加载」这个动作被挡
  （推断：`libtprt` 的 dlopen hook，未直接取证）。
- 自己解析 ELF 动态符号表能命中符号（libart `st_value=0x1600`、libnativehelper `0x11c78`），但地址落在只读段，直接调用即崩。
- 没有 JNIEnv 就建不了 Android View ⇒ 游戏内原生菜单这条路在本作不可行。
