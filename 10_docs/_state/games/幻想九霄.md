# 幻想九霄 状态摘要

> 新建于 2026-11-28。后续只更新本文件。

## 2026-11-28 第一阶段：斌哥改包抓点（真机 f9a116a2）

- **样本**：`com.hundunjidian.hxjx` `1.0.212`/`611150841`，389,761,267 B，sha256 `ff38f5676b06…`，签名 `CN=binge2.keystore`，Application `bin.mt.signature.KillerApplication193`，归档 `02_apks/幻想九霄/base.apk`。Unity 2022.3.62f3 + IL2CPP metadata v31，仅 arm64-v8a、无 split。
- **结构**：菜单 `classes4.dex`（`bin.wb`，只有 1 项「战斗→无敌」）+ `libwbmod.so`（RC4 解 `.main` 的装载器 + 运行期落 `.bss` 的加密子模块，7 个 `Java_bin_wb_*` 入口）。
- **Hook 链**：`JNI_OnLoad` → `hack_thread` → `HT_FindInterpEntry` → `DobbyHook` + `HT_InstallFramePoints`；myhook 内再挂 AOT 两点 `+0x6CA8900`/`+0x6C9FE10`。

## 2026-11-28 第二阶段：为什么无效 + 真正可行的无敌（静态闭环）

- **失效三重根因（实测复现）**：① `HT_FindInterpEntry` 的"特征串→adrp/add→BL 回溯→投票"在本包命中 `0x3e2e988`（栈回溯帧压栈）/ `0x3e2e9fc`（栈槽分配器），不是解释器；② `HT_CName/HT_MName` 返回裸名，8 字节前缀 + 2 参 strcmp 必不等（`AttackSy` vs `AttackSystem`）；③ dump.cs 174,679 方法 RVA 全非 0，无解释执行方法。⇒ 同版本同包在任何设备上都不该有效（"部分设备有效"推断为不同游戏版本/不同 libil2cpp 构建）。
- **真实逻辑层**：HotFix.dll（6,694,400 B，4,927 类/31,639 方法）从 YooAsset bundle `46a5ff5a3ebf95dc.dat` **静态取出**（UnityFS v8+LZ4HC、仅假头伪装、未加密）。
- **唯一减血点**：`FECS.Game.AttackSystemLogic.EnemyAttackHit` IL_02E9（`hp -= dmg`），近战/碰撞与投射物两条入口都汇入；`HealthComponent` 布局 `+0x0 currentHealth(long)/+0x8 maxHealth`。
- **补丁方案（A+A'，4 字节）**：0x48995 `11 0D`→`16 00`（伤害置 0）；0x1971A0 `31 09`→`00 00`（maxHealth 变化后无条件回填）。已打副本并重编译验证。**禁止**只改 `get_ratio`（满血暴毙）。
- **分发判定**：APK 内自带同名 bundle 但是旧版；`HotFixIntegrityVerifier` 比对**服务端下发的 DLL sha256**（`webData.dat`），失败清缓存+重启 ⇒ 静态改 bundle/缓存均死循环，**必须运行期打**。
- **待办**：① 原版 TapTap 包（用户下载的那份 = 斌哥包本身，sha256 一致，需重下）；② TapTap 过签名 + 网页登录（口径见 `plan/taptap_channel.md`）；③ 星空版 + 运行期 IL 补丁 + 双侧验证。

技术正文见 `10_docs/幻想九霄/斌哥包抓点_1.0.212.md`（含 §11–§16）。
