## 2026-11-16 v2.1 三问题修复（已交付·用户实测通过）

- **口令**：用户报三个问题（伤害倍率对怪物也生效 / 无敌偶尔失效 / 无限技能菜单控制不了），要求「全部静态分析 → 代码反推验证 → 得出结论再下手」。
- **团队**：lead 仲裁+改码+出包；dmg-analyst / god-analyst / skill-checker 三路静态闭环（报告 `12_修复_伤害倍率阵营.md` / `13_修复_无敌.md` / `14_修复_无限技能.md`）。
- **根因（实测）**：
  1. 伤害倍率：`Unit::BLKEJBDMGAB`(0x354B388) 的 this 是**受击者**（扣血落 `this+0x120` 的 state），来源在 `payload+0x14`（`Unit::BMNEKPDMFCK` 0x3541284 解析）；v2.0 拿「a0 阵营∈[0,2]」当门控恒真 ⇒ 敌我通吃；且 `+0x24` 是 `KCIMFCENEIN` 元素枚举被误乘。
  2. 无敌：写入的是 `state+0x58`（`IFEHBJOMMMB` 返回，**重算产物**）；脏标记 `state+0x60` 置位时 `FGFFAOCKMEG`(0x36A22BC) 用 `+0x50`+`+0xC0` 合并新对象写回 `+0x58`(0x36A2374)，而伤害路径「先重算(0x3642A2C)再读 62(0x3646840)」⇒ 写入随旧容器作废。
  3. 无限技能：`VoidRun(kind8)`/`SetByteRun(kind4)` **无 g_skill 判定** ⇒ 装上恒生效（0x35547E4 写冷却起点 / 0x3006D98 恒写 ActionButton+0xE8）。
- **改法**：`Stub_Dmg` 按来源阵营门控（仅 PLAYER 乘，且只乘 `+0x28/+0x38`）+ 无敌同帧清零；attr62 每 tick 无条件重写/读回重试/覆盖全部 player；两桩加 `g_skill` 透传（宏传 4 参，`orig==null` 返回 0）。
