## 四条路线全部实测失败

| 路线 | 结果 | 硬证据 |
|---|---|---|
| 改包 + 伪造签名 | 失败 | 签名过（10004 InvalidFingerprint → 10005 InvalidHashes），内容哈希过不去 |
| frida 注入 | 失败 | 官方包 + frida 必报 InvalidHashes；官方包不注入零错误 |
| ptrace / wrap 注入 | 部分通 | wrap + chcon 可加载 so、hook 生效、功能可用，但触发 InvalidHashes |
| root 内存读写 | 失败 | 值确实改掉（0.5→0.1 读回确认），血条不变，数据源是服务端下发 |

## 关键技术事实（有实测）

- **sum 每次运行都不同**：同一包连跑四次得到四个不同值（F27F08E4… / F233F5A2… / CD75BC4E… / 31C7AB8F…）
- **sum 依赖 APK 内容**：官方内容包 BDA35C9A…；只加两个 so 变 DDA1AF18…；去掉 sum 或注入固定值，服务端一律 InvalidHashes
- **不是标准 SHA1**：libil2cpp.so 内搜不到 SHA-1 四个轮常量
- **ACTk 三入口零调用**：Generate(0x37720ec) / get_LastResult(0x3772094) / OnSuccess(0x3773dc8) 在 JNI_OnLoad 挂上，跑 50 秒零调用
- **填 sum 的方法**：ILOGMEDLFML.MLKOKOFBGDF（rva 0x6822f94），从别的 map 拷贝；上游是混淆委托/反射（unwind 调用链 0x6823224 → 0x6560970 → 0x3879ae8 → 0x3878660 DHIPLEBIELB.HFAOLCHDGEA(Type,Object)）
- **错误文案复用**：10004 与 10005 都显示 error_InvalidFingerprint，看弹窗文字无法区分

## wrap 注入可用性（已跑通，但有副作用）

前置命令：

    setprop wrap.com.nekki.shadowfight3 LD_PRELOAD=/data/local/tmp/libsf3g.so

- 必须先 chcon u:object_r:system_lib_file:s0 <so>，否则 app_process 读不了（Permission denied）
- wrap 模式不调 JNI_OnLoad，初始化必须在 __attribute__((constructor)) 里起线程
- 结果：so 加载成功、hook 装上、伤害倍率生效（日志 ENEMY 0.020 -> 0.198）
- 但：进程里多出的 so 被 ACTk 发现 → InvalidHashes → 服务端判违规
- 已试 self-hide 两路（hook open/openat/fopen 过滤 maps；hook dl_iterate_phdr 过滤模块枚举），均无效，检测走 raw syscall 或其它路径

## 封号记录（教训）

| 次数 | 时长 | 原因 |
|---|---|---|
| 第 1 次 | 1 小时 | 打完后 InvalidHashes + 伤害 100 倍（A/C 双路叠加） |
| 第 2 次 | 1 天 | **在 InvalidHashes 未解决的情况下继续上功能验证** |

**硬教训：InvalidHashes 是服务端在报警，出现后必须立刻停手，绝不能继续跑功能。** 正确顺序：注入但功能全关 → 打 3~5 场确认零 InvalidHashes → 才能开功能，且倍率不超过 2。

## 2026-11-08 决定性实验：零内容改动 + 只重签 → 10004（签名关）

- 做法：`13_scratch/sf3g_apkpure/base.apk`（APKPure universal，官方 Nekki 签名）**内容一字节未改**，仅用 `01_tools/starry_release.jks` 重签 → `08_output/暗影格斗3国际/暗影格斗3国际_1.46.1_resignonly-releaseSigned.apk`（264,141,761 B，md5 `5c2b3fc2671bdc97b4dd560db7d7b7bb`，`CN=StarryMagic`）。卸载后装机，设备包 md5 与产物一致。
- 结果：能进到 `create_player`，随后被拒——
  - 客户端上报 `"etype":"WRONG_APK_FINGERPRINT"`、`"actualFP":["821C92E404AB5FDAC8DBF157C2E467E71440917D"]`（正是 StarryMagic 证书 SHA-1）
  - 服务端 `cmd=create_player error=<b>InvalidFingerprint</b>` → 弹窗 `（10004）error_InvalidFingerprint`
- 证据：`10_docs/暗影格斗3国际/evidence_20261108/resignonly_apkcheck.txt`
- **结论**：签名指纹是独立的第一道硬关，**内容零改动也会被拒**；与内容哈希（10005）无关。结合 11-07「改包 + 伪造签名 → 10004 变 10005」，两关关系确定为：**签名关可用运行时伪造通过，内容关（服务端哈希）是最后一道**。
- 由此确定下一步的唯一判别点：**dex 层改动是否也进内容哈希**（签名 killer 必须落 dex）。实验设计＝内容零改动 + 仅加签名 killer，看结果是 10005 还是能进游戏。
- 副产物：国际服 `AndroidManifest` 的 `application` **无 `android:name`**（默认 `android.app.Application`），不能照搬国服「改 MultiDexApplication.super」的挂载法，需显式指定自定义 Application 类。

## 2026-11-08 实验二：killer 过签名关 → 卡 10005（内容哈希覆盖 dex，终局）

- 做法：在 `classes7.dex` 注入 MT `ApkSignatureKillerEx`（`bin/mt/signature/KillerApplication193`，证书改为国际服官方 DER 的 base64、包名改 `com.nekki.shadowfight3`），挂载点＝`NekkiNativeActivity.onCreate` 首行 `new-instance`（触发 `<clinit>`）；**APK 其余内容零改动**（so / metadata / assets 全原样）。产物 `08_output/暗影格斗3国际/暗影格斗3国际_1.46.1_sigkiller-releaseSigned.apk`（264,276,929 B，md5 `e6b1fab53b1bed4ec4fa2dccad5c5bbc`）。
- 结果：**10005 InvalidHashes**（`cmd=create_player error=InvalidHashes`），且日志中**不再出现 `WRONG_APK_FINGERPRINT` / `actualFP`**。
- 判读：① 签名关已被 killer 突破（游戏读到的指纹＝官方）；② 内容哈希关仍拒，而本次相对官方包**只改了 `classes7.dex`** ⇒ **内容哈希覆盖 dex**。
- **终局结论：国际服直装包不可行**。任何直装包都要重签 → 重签必须靠 killer 过签名关 → killer 必须落 dex → dex 一变内容哈希即挂，闭环锁死；与包来源（Google Play / APKPure）无关。
- 保留资产：官方基线包 `13_scratch/sf3g_apkpure/base.apk`（257 MB，官方 Nekki 签名）。killer 原件已随清理删除；重做方法：源在 `07_patched/暗影格斗3/surgical/killer_smali/bin/mt/`，替换 `<clinit>` 的证书 base64（国际服官方 DER，SHA-1 `D61109D768EDAA3AD2EFA9EF357BD1AE33D5F0AB`）与包名常量，再在 `NekkiNativeActivity.onCreate` 首行插 `new-instance`／`invoke-direct` 即可。
- 现场已恢复：官方原包重装（1.46.1，last_update `16:32:56`），可正常游玩。
- 证据：`evidence_20261108/resignonly_apkcheck.txt`（10004 签名关）、`evidence_20261108/sigkiller_hashes.txt`（10005 内容关）。
