**关键方法论修正**：3.6.0 那条「拉 CDN `GameLogic.dll.bytes` 比 md5 ⇒ 零漂移」**在 3.7.0 是假阴性**——CDN 文件 `last-modified` 仍 2025-01-22、md5 与 3.6.0 逐字相同，但游戏实际加载的是另一份 **20,034,048 B**（md5 `96507386…`）程序集。正确取法：frida hook `System.Reflection.Assembly.Load(byte[])`（按参数类型 `System.Byte[]` 选重载）在加载时刻落盘 → `ilspycmd -p` 得 6726 个 .cs（陈旧基线 4680）。运行中扫 PE 无效（原始字节已释放）。

**三个失效根因（都由陈旧基线导致）**
1. **无敌/秒杀**：`Character.isBlockDamage/_currentHealth/_currentShield` 在 `!hasOriginProperties` 时转发 `NetworkBodyOwl`（`Character._networkBody`=312）⇒ 必须双写；旧实现只写 Character 本体。
2. **皮肤**：解释器类上用 `il2cpp_field_get_value_object` 取枚举字面量恒 null（`皮肤枚举映射 0 项`）⇒ 改为直写 `_resourceDic[HeroSkin]` 内层 dict 的 165 条 `EncryptValue`（`ok=165 失败=0`）。
3. **道具缺项**：真程序集 `ResourceId` 27 项（陈旧基线 19）⇒ 补 扭蛋币 `ResourceDic[ActivityIntegration]("GachaMachine202510_GachaCoinAmount")`、催熟剂 `PlayerArchive._fertilizer`；净化之水 = `ResourceDic[SixCycleOrb]("OrbRefineTicketCount")`。

**附加修复**：`LevelProcess.singleton.<AllMonster>` 在菜单/换房间时为空表，旧实现静默 return（两轮「秒杀没效果」的真形态）⇒ 双路（AllMonster 主 + `NetworkBodyOwl.netIDtoBody` 兜底）+ `Character._camp` 敌我过滤 + 每次必有带失败码的节流日志。另：`Archive.LoadResourceData` 与云存档会对 `_resourceDic[tag]` **整体换表** ⇒ 道具/皮肤重放 60 s→5 s。

**运行证据**：`ApplyOneHit lp=ok allMonster(size=1,hit=1)`（战斗内）、`道具重放 ok=7/6 值=999`、`皮肤重放 ok=165`、frida 读回 `OrbRefineTicketCount._showValue=999`（`716^299` 一致）、`isCheated=false`、无 `ram_cheat_detected`；用户确认「秒杀好了」「洗练页显示 999」。

**备注**：商店顶部资源条那格「净化之水 0」不是本字段（真程序集里除洗练页/资源提示外无第二处读 `OrbRefineTicketCount`），属另一资源（`ESROrbUpgradeTicket` 等，存档无条目恒读 0），功能扩张须用户点名。

**清档回归修复（2026-10-28 18:3x）**：用户清应用数据后「全皮肤」再次失效。根因=皮肤实现 v2 只遍历 `_resourceDic[HeroSkin]` **已存在**条目，清档后内层字典为空（`iEntries=0x0 iCount=0`）⇒ 空转；此前能用只因旧档已含 165 条。v3 改为 `il2cpp_class_get_fields` 取 `HeroSkinName` 枚举字段名（只要名字，绕开解释器类枚举字面量为空的坑）逐条建条目 → `皮肤重放(枚举建条目) ok=164 失败=0 总数=164`，内存复核 tag1=164 条全部=1。新包 md5 `d525f997db7b249cb484f6f0ff73d70b`、so md5 `69291997a64297de6e5c2315444237f0`（覆盖安装，未清数据）。教训：**「直写已存在条目」类实现在空档下必然空转**，新号/清档是必检场景；清档后 mod 开关回默认，「无限道具/无限货币」需在菜单重开。
