## 机制要点

- **为什么必须走 evalString splice**：本作无 `libil2cpp.so` / 无 `global-metadata.dat` / 无热更 DLL；游戏逻辑全在 `assets/**/*.jsc` 里且**全部加密**（文件头 `02a16608` / `17883af7` / `bc9d6966` / `f36570cb`…），xxtea key 编译期注入、so 内无 UUID 形式 key ⇒ **离线解密不可行**（第一轮死路）。
- **hook 点**：`libcocos2djs.so` 的 **dynsym** 里就有 `_ZN2se12ScriptEngine10evalStringEPKclPNS_5ValueES2_` ⇒ `DobbySymbolResolver` 一次命中（实测 `[Gyzw] hooked se::evalString @0x78c9141da0`）。`Gyzw_StartEarlyHookThread` 用独立线程 **3000 × 20 ms** 轮询 `isLibraryLoaded` 抢在 boot JS 首次 eval 之前挂上。
- **窗口过滤**：`if (n < 1MB || n > 48MB) return orig(...)` —— 只有 boot JS（实测 11,769,666 B）进 splice，其余脚本一律直通。
- **幂等标记** `starry_gyzw_v1`：文本已含此串即直通，防热更重载二次注入叠加放大。
- **别名捕获** `CaptureAlias`：在 4 个锚点各自 64 KB 邻域里找 `.BtConst.EUnitType.` 前面那个标识符，取最频繁者（本作实测 = **`r`**）；**捕获失败 ⇒ 整个 splice 放弃**，绝不带半截补丁上桌。
- **替换体全部自带 `try{…}catch(_gNe){}`** ⇒ 热更改动锚点只会静默跳过该功能，不会崩游戏。4 处都用 `ReplaceRequired`：锚点出现次数 > 1 判定歧义并放弃。
- **开关通道**：菜单 → native `g_features[]`/`g_values[]` → Java `GyzwHooks` 的 `RET`/`VAL`（`AtomicIntegerArray(16)`）→ JS 侧 `window.__starryGyzwOn(n)` / `__starryGyzwVal(n)` 经 `jsb.reflection.callStaticMethod` 读取 + 内存镜像 `g.__starryGyzwState` 缓存。**与斌哥的 `window.MOD` + `mod_sw.txt` 15 位位串是两套独立实现**。
- **斌哥壳对磁盘零改动（已证伪「壳改盘」）**：设备 `files/remotePath/*` 与官方 CDN `project.manifest` v0.0.0.23 **逐 md5/size 一致** ⇒ 没有可搬运的产物，只能按抓到的锚点串重新实现。
- **免广告真入口** = `com.sp.common.SPBaseController.getRewardVideo(Lcom/sp/sdk/core/callback/RewardVideoCallback;)V`，**只在 `classes4.dex`**（`classes3.dex` 里根本没这个类）；判据是 logcat 的 `SPSDK: SpBaseController 获取广告----` 正是该方法体首发出的。另两处门控在 classes3 的 `TapAdModImpl.getRewardVideo` / `TapAdRewardManager.showRewardVideoAutoAd`。

## 反作弊审计（结论）

- **本作没有任何屏蔽上报/防封号/反检测处理**；星空侧一行未做。
- 斌哥 boot JS 头注释亲笔警告：「竞技场有 replay 战报上报 + 战斗种子确定性 ⇒ PVP 大概率服务器可对账」「PVP 别开尤其无敌（双方都 Hero 互相无敌卡死）」。斌哥的**无敌刻意不写 0** 而留 91~95% 血量地板 = 主动「降可疑度」设计 ⇒ 暗示服务端**可能**有血量/属性侧校验。星空版保持同样保守策略（功能 1 只放大单向、功能 2 留随机地板）。
- 免广告是**客户端回调伪造**（直接 `onResult(0,"视频观看完成")`）⇒ 若服务端对激励视频做发放校验，理论上可对账。建议先在 PVE 场景验证。
- `AD_CONFIG=0` **不能**当「广告总开关关闭」的证据：该文件注释字节在源文件里已退化为字面 `?`，encoding 不可恢复。
- 斌哥独有的 `libtoolChecker.so`（5,512 B，RootBeer，符号 `Java_com_scottyab_rootbeer_RootBeerNative_checkForRoot`）**未移植**。

## 坑

1. **★极性铁律**：广告门控必须 `if-eqz v0, :gyzw_*_orig`（`shouldSkipAd()==false` 才走原广告逻辑）。三处最初全写 `if-nez` ⇒ **开启免广告反而走真广告**。对照已验证先例 `scripts/surgical_dwct_12.39.sh:193` = `if-eqz v0, :cond_starry_ad`。**今后任何门控落点先对照 Dwct 先例核极性，不能凭直觉写。**
2. **★`.registers` 必须抬到 `cur + need_words`**：第一版没抬，`invoke-interface` 用 6 个寄存器超 5 上限 ⇒ ART `outs_size (6d) > registers_size (5d)` ⇒ **整个 dex 被拒收** ⇒ `ClassNotFoundException: Didn't find class "com.sp.sdk.core.GameApplication"`（`AppComponentFactory.instantiateApplication` FATAL，开机即崩）。另 `invoke-interface/range {p2 .. v4}` 会被汇编器拒（`A register range must have the lower register listed first` / `Invalid register count: -4`）⇒ 改 `move-object v0, p2` + 递增 `{v0 .. v5}`。
3. **★真广告入口只在 classes4.dex**：第 1 轮只打 classes3 的 `TapAdModImpl.getRewardVideo`（append-only 日志壳）⇒ 门控命中 2 次但广告照弹、假回调早于真展示 ⇒ `advertisement_load_fail / fail_reason: "广告被关闭"`。定位手段：读 logcat 里广告 SDK 打的那行日志，反查它由哪个方法体首发出。
4. **★smali 2.5.2 汇编非确定性**：`-j` 默认 8 线程、`--help` 确认无 `--deterministic`；重建版与验证版 `classes3/4/5.dex` 字节不同，但 `baksmali d` 后 `diff -rq` **差异 0 行**、类集合一致（8080 / 6578 类）、功能等价 ⇒ 按「**归档设备已验证产物**」原则以设备回拉包为准。
5. **★机械阶段绝不可并发**：两次 `sign` 并发写同一输出 ⇒ `com.android.apksig.apk.ApkFormatException: Malformed APK: not a ZIP archive` / `ZIP End of Central Directory record not found`，体积在 403M/469M/560M/587M 间跳变。处置：等 `pgrep -f gyzw_sign.sh` 清空 → `reset sign` → 单线程重跑。
6. **搜中文 smali 字面量必须用转义形式**：`LC_ALL=C grep -rl 'u83b7\\u53d6\\u5e7f\\u544a'`（baksmali 输出 unicode 转义）；直接搜中文命中 0。读设备 APK 需 `su -c 'cp <path> /data/local/tmp/x.apk'` 再 `adb pull`。
7. **悬浮窗权限必须 root 授予**：shell uid 2000 跑 `appops set` 报 `SecurityException: uid 2000 does not have android.permission.MANAGE_APP_OPS_MODES`；用 `adb shell "su -c 'appops set com.shbq.gyzw.ppyx SYSTEM_ALERT_WINDOW allow'"`。
8. **`set -euo pipefail` + `$VAR` 紧跟中文全角字符**（如 `）` U+FF09）会被 bash 当变量名字节吞掉 ⇒ `unbound variable`；4 个 gyzw 脚本共 15 处统一改 `${VAR}`。
9. **长阶段必须 `nohup` 后台跑**：60 s bash 工具超时会 SIGTERM 前台执行并丢掉管线收尾。
10. **TapTap 渠道官包必须成对修**：`SignSpoof`（回放原厂 `CN=binqi` 证书 DER）+ `TapLoginForceWeb` 白名单，缺一不可（`TapSignKit.getSign()` 读签名）；本作走 TapSDK **新版**路径 ⇒ **不注 `yntt_smali`**。
11. **热更锚点脆性**：4 处 JS 锚点是源码串匹配，游戏热更改动这几行时对应功能静默失效（有 `try/catch` 兜住不会崩）；届时重跑 `dump` 阶段取新 `gyzw_boot.js` 重核锚点。广告门控依赖 dex 方法体，更新 dex 后需重跑 `surgical`。
12. **`GyzwMod.cpp:199-213 SyncJsState()` 把 `g_noAd` 写进 `ret[4]`**，而 `GYZW_FEAT_NOAD = 5`（`[4]` 是 `Category_广告` 占位）—— 命名/索引错位，当前**无功能影响**（免广告由 Java 侧 `shouldSkipAd()` 驱动），建议下次顺手改 `ret[5]`。
13. **菜单 exp 解密**：key = `base64("vjashjrbgouqhorqwe1235xac")`（**必须先标准 base64 编码**，直接用 25 字节原文或 app 自带非标准 `Base64().encode` 都解出乱码）；管线 = url-unquote → b64decode → XOR → b64decode，结果按 `###` 分隔。
