## hhld kill-switch 定点（本版新，国服是 0x5c270）

`libhhld-rt.so`（在 `split_config.arm64_v8a.apk` 内，文件偏移 = vaddr）：

```asm
7938c: stp  x20, x19, [sp, #-0x20]!
7939c: bl   0x12262c                ; 取 pthread key
793a0: ldr  x1, [x19]               ; node->arg
793ac: bl   pthread_setspecific     ; 清 TLS
793b0: ldr  x8, [x19, #0x8]         ; node->func  ← 国服同构的 [x19+8]
793b8: blr  x8                      ; ★ NOP：00 01 3f d6 -> 1f 20 03 d5
```

- 定位方法：全量扫 `ldr xN,[xM,#8]`→`blr xN` 共 348 处，按国服 `[x19+8]` 基址收窄到两处（`0x3b6e0`/成对 JNI 表、`0x793b0`/TLS 析构链），按 `pthread_setspecific` 上下文确认本处。
- 实测：NOP 后进程 60 s 存活、crash buffer 空；未打补丁的零注入重签包必崩。
- 扫描脚本：`04_scripts/境界刀鸣国际/patch_hhld_nop_intl.sh`（含补丁点断言 + 成品二次校验）。

### 根因判断
设备在跑 **ClashMetaForAndroid**（fake-ip + 分应用代理），游戏进程内的 DNS 解析拿不到 CDN 地址：
- `lf16-bladeglobalcdn-alisg.bytedgame.com` 偶尔能通（`init TGRP 0 success`）
- `lf19-…` / `pxgametw.com` 解析失败 → 4 个通道里多数失败 → TGRP 整体失败

**同一环境、同一时段，三件套与单包表现一致 ⇒ 包结构不是变量，代理 DNS 才是。**
