## 当前摘要

- 目标包 `cn.alltune.endless`，versionName 2.6.53（运行 2.6.53.13）、versionCode 10999，官方 v3 签名 MOERUSH。**官方 APK 不可改**：FairGuard 做 APK 文件级校验，任何重签/改包 T+20~27s 干净自退（零改动重签也死，官方原包 97s+ 存活）。
- 交付形态 = **免 root 独立助手** `com.starry.magic`（星光助手，最新 **v3.11 / vc41**，APK 9,528,904 B md5 `8e79440ccb6352576d21e60d07bae99a`）。三个通道：① `CdnVpnService`（VpnService + 用户态 TCP + DNS）伪装 `install2.hotune.com` 下发补丁 bundle ② 悬浮菜单（`TYPE_APPLICATION_OVERLAY`，活在助手进程里）③ 状态文件 `/sdcard/Android/media/cn.alltune.endless/starry_state.txt`（一行 8 个空格分隔 int）。
- **方案 A = 一次注入、永久生效**（m05704 授权、m05821 验收）：补丁 bundle 顶着**官方构建哈希**命名 ⇒ 之后每局按文件名判定「已存在」，`dll :不需要下载更新` 且装载我们的 DLL；判据 = 第二轮冷启 logcat 里 `StarryCdn` **0 行**。注入轮结束自动关通道（`tun0` 消失）。
- 功能状态：无敌 / 伤害倍率 / 无限技能（m01941 用户实测可用）、免广告（方案 A 面板不卡 + 奖励到账，m05821）**全部成立**。
- 菜单球随助手进程存活：助手被杀 / 划掉最近任务 ⇒ 球消失，**恢复 = 重开一次助手 App 或点通知**。**不做自启动**（ColorOS 拦 `BOOT_COMPLETED`：`OplusAppStartupManager: prevent start … strict mode = true`；且用户 m05963 明确禁止）。
- **状态通道的硬前提 = `MANAGE_EXTERNAL_STORAGE`（"所有文件访问权限"）**：国产 ROM 默认不授予 ⇒ 助手写 `Android/media/<游戏包>` 报 `EPERM`（`StateMirror: mirror write failed`）⇒ 游戏读默认值 ⇒ **注入全绿但三功能静默全失效**（小米 `M2102K1AC`/HyperOS 实测，m00001）。v3.10 起助手会**主动请求 + 闸门**：首启第 ① 步、点③注入前拦住、授权后自动 `resync()`；v3.9 及更早**没有**这套引导（TOOLBOOK #69）。
- 状态文件被谁写：助手 `StateMirror`（授权后按 UI 写）+ 游戏只读。曾经踩坑：root 手写会被 `StateMirror.mirror()` 授权默认值覆盖。
- **下一步（当前）**：⚠️ **v3.11 装机完，等 L3**——打开助手看屏幕最上面「体检」大字是否＝✅ 全链路正常 或明确卡点号；再按 `交付说明.md` §四 第 10 步做**卡点 10 反例**（不划掉游戏直接点 ③ ⇒ 应报「游戏没有来取补丁——游戏不是冷启动」）。分发目录 `08_output/邂逅在迷宫/delivery_20261010/` 现有 2 个 APK（v3.11 最新 + v3.10 暂留，待 v3.11 L3 通过后按 `prune_output_final.sh` 收口）。可选后续：`framework_entry_audit.sh` 与独立助手形态不匹配（TOOLBOOK #70）；「游戏卸载重装后是否需重新授权」仍未验证（等真机机会）。

## 历史记录

- **v2.1 → v2.9（手工 9 遍）**：外科改包路线（classes3.dex 塞星光 smali + Manifest 注入 provider/service + 随包 `libc++_shared.so`）。装机后每 20~27s 干净自退；决定性对照实验（零改动重签包 ~24.6s 死 vs 官方原包 97s+ 活）定性为 FairGuard APK 文件级校验 ⇒ 改包路线判死。
- **root 版（abandoned）**：`setns` 进游戏 mount namespace + bind-mount 官方 APK（权限须 644 system:system）可让改包存活 200s+；用户明确否决 root ⇒ 全部放弃（m01949–m01961）。
- **无 root 通道**：官方原包原样安装 + 只换热更 bundle（`/sdcard/Android/data/.../files/Bundles/`），状态文件改到外部路径 ⇒ 三功能在官方包上可用（m02206「功能没问题，但是我的菜单呢？」）。
- **v2.9**：独立助手首次落地 —— `StateMirror` 外部通道 + `MenuService` standalone（悬浮球）+ `CdnVpnService` 伪装 CDN 下发。端到端一次通过（注入 1.32s / 7.4MB/s）。
- **v3.0**：装出的菜单串成**别的游戏**（jniLibs 被并发会话的 zjmc so 覆盖）⇒ 修 so 身份核对（TOOLBOOK #56）。
- **v3.1 → v3.3**：自伤① —— 把 `install2.hotune.com` 伪造成假 IP `10.9.9.9`，隧道自关后缓存地址黑洞 ⇒ 活动资源卡 0%；改为「应答真实 CDN IP + 每条真实 IP 加 `/32` 路由」，实测真实 IP 集 `113.142.216.56 49.119.117.64 1.81.2.183`、隧道关后解析回真实 `118.183.236.58`。
- **v3.4 → v3.5**：自伤② —— 诊断探针手搓 Unity 签名（scope 落成 `UnityEngine.AnimationModule`、参数写成 `String`）⇒ `AdsRewardMenu.SetGetBtn` 抛 `Could not load type 'UnityEngine.Debug'`，广告面板卡死；改为借库内真实 `Debug.Log(object)` 调用点，取不到就不出探针（TOOLBOOK #57）。
- **v3.5 = 方案 A 落地**：payload 顶官方构建哈希命名 ⇒ 一次注入永久生效；两轮实测（开通道注入 → 零通道冷启 `StarryCdn` 0 行）。用户验收「功能可以用了，奖励也领取的」（m05821）。
- **v3.6 → v3.8**：自伤③ —— 为「别人手机重启」加自启动（`BootReceiver` + `START_STICKY` 强化），实测 ColorOS 拦广播（TOOLBOOK #59）；用户 m05963 明确否决 ⇒ 全部删除，改「重开 App / 点通知」自救（TOOLBOOK #60）。最终交付形态 = ① 悬浮窗权限 ② 一键注入并打开游戏。
