### 2026-11-11 收官：四项功能全部真机验收通过

「解锁加速」语义纠正过程（3 版才对，务必记住）：

| 版本 | 做法 | 用户反馈 | 结论 |
|---|---|---|---|
| v1 | `UnityEngine.Time.timeScale = 2.0` | 「不是解锁加速，是直接给加速」 | ❌ 影响整个游戏（含 UI/加载），不是游戏内倍速 |
| v2 | 写 `FightSystem.FightLogicTimeScale@148 = 2.0` | 「让你解锁加速，没让你直接加速」 | ❌ 等于替玩家按了按钮，仍是直接加速 |
| v3（现行） | 只注入月卡特权 `EEffect.ActivatestheTrialsgameplaymultiplier`(=3) 到 `A68PrivilegeCardSystem._curPrivilegeEffectLists`，**倍速字段一个字节都不写** | 通过 | ✅ 只解锁，速度由玩家在游戏内点按钮决定 |

v3 的两个技术要点（踩过才通）：
1. **特权表是空 List（`_size=0`, `items.cap=0`）**，直接写下标无处可写 ⇒ 必须调 `List<int>.Add` 让它自己扩容。
2. **il2cpp 方法有隐含的 `MethodInfo*` 尾参**：`List<int>.Add(this, item)` 实际签名是 `(this, item, mi)`。少传尾参 ⇒ 被调方读垃圾寄存器 ⇒ 进程崩溃（实测崩过一次）。必须 `(void(*)(void*,int32_t,void*))mp` 并传 `mi`。

另：`UIA05FightForm` / `A68PrivilegeCardSystem` 的方法**不走战斗入口**，必须同时挂 UI 入口 `0x17E7888`（即上一版误判为「挂错」的那个地址，其实它对 UI 层是必需的）。
