## 2026-11-10 挂点定位完成 + native 模块编译通过（未出包）

### 结论：不需要解加密热更 dll

此前判定「hook 方法待解热更 dll」是**走错了路**。本作与旷野征途同为 HybridCLR，业务类在热更 dll 里由解释器执行，**运行时用 il2cpp API 就能枚举**（73 个程序集全部可读），不必解 `update.dll` 的加密。

### 挂点（真机实测）

| 项 | 值 |
|---|---|
| 函数 | HybridCLR `InterpFrameGroup::EnterFrameFromInterpreter` |
| VA / file | 0x17E7888 / **0x17E3888** |
| 序言 | `stp x30,x25,[sp,#-0x40]!` = **0xA9BC67FE** |
| 签名 | (x0=frameGroup, x1=MethodInfo, x2=argsPkt) |
| 实测 | 12 秒 14,321 次调用 |

调用环：桩(0x18C7A08) → Execute(0x17E9220) ──处理 call 指令──→ EnterFrame(0x17E7888) ──`br x10`──→ 回 Execute。**C#→C# 与 native→C# 都必经此函数**（长生天机降世「只承接 native→C#」的结论不适用于本作）。

### 2026-11-10 深夜 关键修正：挂点挂错了

**已交付但无效的包**：`农场守护者_2.1.21_starry-releaseSigned.apk`（513,809,682 B，md5 ab5d5543…）—— 菜单、Manifest 注入、so 加载、hook 安装全部正常（`hooked enter-interp @ 0x76f78bc888`），但三个功能无效。**根因不是参数偏移，是挂点地址错了**。

| 事实 | 证据 |
|---|---|
| 我挂 0x17E7888 | 15 s / 19,645 次，90 个方法全是 UI/框架层，无一个战斗类 |
| 斌哥挂 0x17E7750 | 13 s / 1,609,338 次，含 GameFightPlaySystem.Update、A68PrivilegeCardSystem.Update |
| 扣血不走方法调用 | DoRemoveHp 桩 / set_CurHp 桩 / TickAfter 桩 实测调用数全为 0 |

**定位方法**：装斌哥包 → 读 libil2cpp 全部可执行段内存 → 与官方 so 逐字节比对 → 仅 2 处差异（0x17E7750、0x17E798C），均为 Dobby inline hook。两包 libil2cpp.so md5 完全一致（7affdf06…），说明他纯运行时 hook。

**下一轮只改两处**：挂点 0x17E7888 → **0x17E7750**（file 0x17E3750，序言 0xF81D0FFE）；实现方式从「拦方法改参数」改为「在 GameFightPlaySystem.Update 前后改 EntityBase._curHp@88」。详见 `路线锁定.md` §7。

**设备现状**：装的是斌哥改包（可正常游玩、功能可用）；本项目的星光包已被卸载。
