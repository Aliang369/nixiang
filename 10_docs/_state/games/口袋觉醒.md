## 脚本加密（已解，工具已固化）

- 文件格式：`"ccc"` + 密文（长度 −3 恒为 4 的整数倍）；合法第三字节为 `c/e/m/z`（`libcocos2dlua.so+0x5d6524` 的位图 0x00800405）。
- 解密器 = **`libcocos2dlua.so + 0x5d5f68`**：`int dec(uint8_t* data, int len, void** out, const char* tag)`，返回长度、`*out` 为 malloc 缓冲。
- LuaStack 的 xxtea 通道实测 **enabled=0**（`[LuaStack+0x24]=0`），"ccc" 全由上面这个解密器处理。
- 明文 = **自定义头部 `e37ac4930a04a27f0b625cfa37…` 的 LuaJIT 定制字节码**（hook `lua_load` 入参实测同样的头，`luaL_loadbufferx` 之后才由 LuaJIT 解析）⇒ 源码不可读，走运行时内省。
- 工具：`06_dumped/口袋觉醒/tools/kd_decrypt_rpc.py`（frida RPC 调游戏自身解密器，**275/275 全出**，落 `06_dumped/口袋觉醒/src_plain/`）。

## 壳的完整性自检（本轮最大坑，已解）

- 现象：任何改动后的包启动 ~2s 自退，logcat `I/Process: Quit itself, Pid:… StackTrace:c.a.a.a.e.f.ۣۣ۟۠ۢ.۟ۦ۠ۨ۟:6 org.cocos2dx.lua.AppActivity.x5:36`，
  系统侧 `desc=exit_self_<pid>_<uid>`（不是崩溃、无 tombstone）。
- 根因：**np 资源壳读 PackageManager 签名做完整性判定**，异签即自杀；`AppActivity.x5()` 是一个
  `sparse-switch` 控制流平坦化的状态机（不可静态读），退出口集中在 4 处原始调用：
  `System.exit(int)`×2（含 `np/protect/assets/a/…`）、`Runtime.halt(int)`、`Process.killProcess(int)`。
- 实测否定：把上述 4 处 `invoke-*` 改成 `nop` 重编 classes.dex → **不成立**：退出被吞后状态机继续跑，
  `AppActivity` 不再调 `super.onCreate()` ⇒ `SuperNotCalledException` 崩溃。**禁再走这条路**。
- 正解：**SignSpoof（按包名回灌原厂证书）**。原包无自定义 `appComponentFactory`
  ⇒ manifest 加 `android:appComponentFactory="com.starry.magic.sign.SignSpoofAppComponentFactory"`，
  并在 `SignSpoof.java` **纯追加**本作块：`KDJXSF_PKG="com.zcdsg.xmgm"` +
  `KDJXSF_CERT_B64`（CN=cc / SHA256 0b0c84de… / MD5 addaa5ff…）。
  `StarrySignFactory` 报 `ClassNotFoundException: androidx.core.app.CoreComponentFactory` 是**正常降级**（框架默认 factory 生效）。
  ⇒ 改签名后游戏正常运行（pid 存活、菜单初始化、hook 成功）。
- 结论：**本作后续任何出包都必须带 SignSpoof factory + 该证书块**，否则一启动就自退。


## 注入期两次真实崩溃（教训已固化到实现）

| # | 现象 | 根因 | 处置 |
|---|---|---|---|
| 1 | 离线程调 Lua → `SIGABRT in GLThread` | 必须在**拥有该 lua_State 的线程**（= GL 线程）调用 | 只在 `nativeRender` hook 里动 Lua |
| 2 | 进关时 `SIGSEGV`，栈=脚本加载路径，崩点 `libcocos2dlua.so+0x6342ec: str w11,[x10,#8]`（LuaJIT 表节点写，x10=坏指针） | **每帧从 C++ pcall 进 Lua 下发开关**（`__kdjx_set`）破坏 VM；且游戏会重建 Lua VM（登录/进关），首版只装了第一个 VM | ①开关改**文件通道**：C++ 写 `files/kd_state.txt`，游戏侧 `scheduleScriptFunc(…,1.0,)` 每秒轮询；②每个新 state 都装补丁，但只装**同线程且栈顶为 0**的 state；③补丁缩到只包 `beAttack`/`strike` |

- 另：`_G` 有 `__newindex` 保护，普通全局赋值直接 raise（`USE "globals.xxx = value" INSTEAD OF SET GLOBAL VARIABLE`）⇒ 一律 `rawset`；v6 起干脆**零全局写入**。
- 设备侧 `files/` 曾被 root 误建导致「无法更新」（App 无写权限）：**任何 su 写入 app 目录后必须 chown 回 app uid**。
- 热更版本已从 patch 54 升到 **patch 56**（287 个脚本，md5 全部与 v56.dat 一致，无损坏）。
