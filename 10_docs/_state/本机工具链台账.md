### 根因：为什么 macOS 必须自建运行包

- GitHub **源码分发不含 `runtimes/`**（该目录被 Git 排除）；官方发行 ZIP **全部是 Windows x64**（`IG5-*-Windows-x64-*.zip`，约 1.06 GB），`install.ps1` 亦仅 Windows。macOS 唯一路径＝用插件自带的 `scripts/prepare_macos_runtime.mjs` 本地组装 `darwin-arm64` 包（步骤见 `docs/MACOS_RUNTIME.md`）。
- 缺件时的症状：`ig5_doctor` 报 `Missing matching darwin-arm64 runtime pack: the loaded plugin has no matching runtime.json`，`ig5_status` 的 ghidra/reverse 均 `available: false`、`readiness: missing-runtime`。**插件代码本身是正常的**，不要误判为插件损坏或下载错误。

### 重建配方（2026-10-17 实测可用）

前置状态（截至上文记录时间）：
- Python 前缀 `~/IG5Runtime/python`（python-build-standalone 3.12.15 arm64，已装 pyghidra/JPype/packaging/org.jpype.jar）——**已保留**（74 MB；原始下载包 `pbs.tar.gz` 24 MB 已删）；其中 `_jpype.cpython-312-darwin.so` 已 `lipo -thin arm64` 并验证签名＋dlopen。
- Homebrew `ghidra`、`openjdk@21`——**已于 2026-10-17 卸载**（二者与运行包内容重复，共占 1.14 GB）。重建前需装回。

```sh
# 1) 装回构建输入（openjdk@21 由 ghidra 依赖自动带入；keg-only）
brew install ghidra

# 2) 组装运行包（--output 必须是不存在的新目录；其父目录须已存在且无软链别名）
cd ~/.dsh/profiles/desktop/node_modules/dsh-infinite-gen-5
mkdir -p runtimes
node scripts/prepare_macos_runtime.mjs \
  --ghidra "$(brew --prefix)/Cellar/ghidra/12.1.4/libexec" \
  --python "$HOME/IG5Runtime/python" \
  --jdk    "$(brew --prefix)/Cellar/openjdk@21/21.0.12.1/libexec/openjdk.jdk/Contents/Home" \
  --output "$PWD/runtimes/darwin-arm64"

# 3) 完全退出并重开 DSH（Cmd+Q，不是关窗口），然后验收：
#    ig5_doctor engine=ghidra          → runtimeReady / startupVerified = true
#    ig5_open → ig5_funcs → ig5_decompile → ig5_close
```

可选：不依赖 GUI 的整链路验收（走仓库真实 `runtimeConfiguration → workerLaunch`，需一个已授权的本地样本）

```sh
node scripts/test_macos_runtime_native.mjs "$PWD/runtimes/darwin-arm64" '/abs/path/to/sample.so' 'JNI_OnLoad'
```

### 已知坑（都踩过，别再踩）

1. **JDK 必须是 21**：打包脚本硬校验包内 `jdk/Contents/Home/release` 的 `JAVA_VERSION="21..."`，且要求 `jmods/java.base.jmod`、`legal/`、`lib/libjli.dylib` 齐全。本机原有的 JDK 25 / 17 **会被直接拒绝**。
2. **`_jpype.cpython-312-darwin.so` 必须 thin arm64**：Ghidra 自带 wheel 是 `macosx_10_9_universal2`，会被运行包的 `machArchitecture` 校验拒（fat 头 magic 不符）。用 `lipo -thin arm64` 处理后签名**仍然有效**（实测 `codesign --verify --strict` 通过且真实 dlopen 成功），无需额外重签。
3. **运行包必须放在插件自身 `runtimes/` 下**：`bundled` 来源校验要求 `realpath` 落在 `PLUGIN_ROOT` 内，且需要 `<包根>/manifest.json`。也可用 `IG5_RUNTIME_ROOT` / `IG5_GHIDRA_RUNTIME` 指向外部包，但**从 Finder 启动的 GUI 不继承 shell 临时变量**，故不推荐。
4. **分析数据库默认落在非隐藏路径**：`~/Library/Application Support/DeepSeek Harness/IG5/projects`。Ghidra 拒绝项目路径含以 `.` 开头的目录段，`~/.dsh` 下会报 `Path element starting with '.' is not permitted`。
5. **装完/重建后必须完全退出重启 DSH**：`index.js` 只在插件加载时算一次引擎配置（`runtimeConfiguration` 单次调用），热改 `runtimes/` 不会被运行中的进程识别——本次即因此重启过一次。
6. **运行包内 JDK 依赖 6 个 Homebrew 库（不在包内）**：`libfontmanager` / `libsplashscreen` / `libjavajpeg` / `liblcms` 的 `LC_LOAD_DYLIB` 指向 `/opt/homebrew/opt/{freetype,harfbuzz,libpng,giflib,jpeg-turbo,little-cms2}` 的 `.dylib`。这 6 个配方同时被 `apktool`/`jadx`/`openjdk` 依赖，**卸载 `ghidra`/`openjdk@21` 不受影响**（已实测：卸载后双路由验收仍全通过）；但若将来 `brew upgrade` 把其中某个库换成新的 `.dylib` 主版本名，引擎会失效 ⇒ 按上文配方重建。
7. **插件升级/重装会覆盖 `runtimes/`**：`install.ps1` 或重新下载都会重写该目录，静态引擎随之失效 ⇒ 重建 + 重启 DSH。
