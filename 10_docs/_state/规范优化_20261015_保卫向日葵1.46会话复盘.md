## 2. 已验证、可复用的关键事实

> 标注口径：**实测**＝本轮真机/命令直接产出；**推断**＝由实测反推；**待验证**＝未测。

### 2.1 本作身份与「双构建」结构（实测）

- `com.bwxrk.yqmy.ty4` 保卫向日葵 **1.46 / vc46**，arm64-v8a，Unity IL2CPP(metadata v29) + xLua + HybridCLR.Runtime + Obfuz；渠道 TapTap + dodjoy juhe 聚合。
- **运行时 dlopen 的不是 APK 内嵌的 libil2cpp**，而是 dodjoy 热更落地的 `/data/data/{pkg}/files/libil2cpp.so`：
  - 热更构建 62,235,240 B md5 `895b34890507bcbcf76e9c312693fb10`（＋ metadata 14,295,428 B md5 `e2645ec3ad447e070e84cd140bf85595`）
  - APK 内嵌 62,032,888 B md5 `f06868ccce285aae828ab7deb825805f`（＋ metadata 14,253,536 B）
  - 判据：`su -c 'grep libil2cpp /proc/<pid>/maps'`；RX 段 `off 0x153b000`、**RVA == 文件偏移**（PH2 va==off）
- 锚点：`10_docs/保卫向日葵/斌哥包抓点_20261015.md` §2。

### 2.2 抓点方法：RX 段 diff 只差 24 字节（实测）

- 全 RX 段 34,508,800 B 中**仅 24 B 不同** = 2 处 12 字节跳桩（`ADRP X17/ADD X17,#imm/BR X17`），目标落在 `libSDKloading.so +0x2CEC5C / +0x2CE0A4`。
- **壳 BSS 里有自述式中文字符串池**（`[BW路标] n/3 准备装 <类::方法>(★功能名)`、`[BW☠] … 不装这个钩子`、已判死清单）⇒ 抓点第一步应先 dump 壳 rw/BSS 抽 UTF-8 串（`so_inspect.py strings --utf8`），可省大量反汇编。
- 锚点：抓点文档 §3/§5；原件 `09_test/保卫向日葵/shell_bss_strings.txt`（137 行）。

### 2.4 功能实现口径（实测，L3 通过）

- 拿全部技能＝**改输入**：钩 `SelectRandomSkill`（**替换**单选，不追加 —— 追加会变 4 个，顶到游戏自检上限 `GetIntParam(545)=4`），改投游戏自带 API `BattleCoreSys::SendThreeStarSelectSkill(uint uid, List<sbyte> idxList)`（RVA `0x250A5D4`，UI 同路径），产出帧指令 `FrameCmdThreeStarSelectSkill{gid, idxList=[0,1,2]}`；每局配额 30，换局重置。
- **跳过 orig 的安全性有反汇编依据**：`0x2508CF0` 函数体只有 3 个守卫 + `GetCurBattlePlayer()` + 取 `[this+0x10]`，末尾 `b 0x1A04BE4` **尾调**，零内存写、零簿记。
- `List<sbyte>` 无静态引用可查 ⇒ 从方法第 2 形参 `method_param(mi,1)` → `il2cpp_class_from_il2cpp_type` 反推 inflate 类；`_items@0x10` / `_size@0x18`；`sbyte[3]` 数据区 `+0x20`。
- 真机锚点：`install pass: ok=2 dead=0/2`（**零 by-name 回退**）＋ `拿全部技能 hit gid=1/2/3 -> idxList=[0,1,2]`（全会话 13 次）＋ 用户判词「点一个技能真的拿到 3 个」「功能没问题奖励到账了」。

### 2.5 TapTap 两项的**可复用判据与验证法**（实测）

- **证书回灌自检三段法**（本次用来证明没抄错）：① `openssl pkcs7 -inform DER -in META-INF/*.RSA -print_certs` 取官方 DER；② 从 Java 源抽 `XXX_CERT_B64` 拼接解码；③ 两者 `md5` 必须相等，且等于 `apksigner verify --print-certs` 的证书 MD5 指纹。本次：727 B，**逐字节相同**，md5 `63e2fa8906a18d0f46b527e2d74760a8`。
- 本作 TapSDK 是**新版路径**（包内字符串实证）：`impl/ui/activity/TapTapLoginActivity` + `com_taptap_sdk_login_request` + `embedded_web` + `fallbackToWeb` 全在；**无**旧版 `com.taptap.sdk.ui.TapTapActivity`、**无** `loginHandlers`。⇒ 命中 `TapLoginForceWeb` 的 new-impl 分支。
- 登录入口是 dodjoy 聚合壳 `com.juhe.sdk.TapTapLoginActivity`，但它最终仍走 TapSDK 的 activity（故白名单反射有效）。
- 判据：改前三条报错（`TapInitializer … 签名未配置` / `JuHeSDK TapTap CONFIG_ERROR` / `TapTapException: SDK not initialized`）**全消失**；`StarryTapLogin: new-impl request loginType mobile_client -> embedded_web (preCreated)`；`juhe login success {code:0}`；全量 logcat **无** `targetName=com.taptap`。

## 4. 优化方案（可执行，按价值排序）

- **问题**：每款 TapTap/渠道游戏都必须往 `SignSpoof.java` 追加一段证书常量（现存 ~70 段，全部由游戏会话追加），但该文件被列为禁改 ⇒ 执行者要么违规、要么无法交付登录功能。本轮即在此冲突下违规（§3 #1）。
- **方案**：`AGENTS.md` 禁改项括注改为——「`SignSpoof.java`：**禁止修改已有游戏块/共用逻辑**；**允许追加**一款游戏的 `XXX_PKG` / `XXX_CERT_B64` 常量与对应 `fakes.put` 行（追加须附证书逐字节验证证据，并在复盘/CHANGELOG 记一条）」。
- **[落点]** `AGENTS.md`「授权与测试边界」节（禁改项括注那一段）；配套新增 `10_docs/_state/框架待办.md` **FW-6**。
- **成本/风险**：1 段规则 + 1 条台账；风险低（限定「追加」，改已有块仍禁）。适用边界：仅 `SignSpoof` / `TapLoginForceWeb` 这类**表驱动、按包名追加**的共享表；不推广到 `Main.cpp` 等结构性文件。
- **验收**：对任一后续新游戏，`git diff --stat -- SignSpoof.java` 只增不减（无删除行）即视为合规追加；审计脚本可断言。

### P0-2 把「证书回灌逐字节自检」固化进技能
- **问题**：`XXX_CERT_B64` 抄错的症状是「TapTap CONFIG_ERROR / SDK not initialized」，**不会报证书错** ⇒ 极难定位（本作首装即踩，见 m00004 的改前日志）。
- **方案**：把本次三段验证写成一行自检（openssl 取官方 DER → Java 源抽 base64 解码 → md5 与 apksigner 指纹比对），落进 TapTap 登录技能；可另做小工具。
- **[落点]** `skill/re-analyze/login/taptap-web-login.md`（新增「证书回灌自检」小节）＋ 可选 `04_scripts/_common/verify_signspoof_cert.py`。
- **成本/风险**：小；纯只读校验。**验收**：对任一已上线游戏跑一遍，输出 `byte-exact ✓` 且 md5 == apksigner 指纹；对故意改坏一位的 base64 输出 ✗ 且非零退出。

### P1-1 出包前「本包是否已登记进两张共享表」断言（可省一整轮装机）
- **问题**：本作首次装机后登录失败，根因是 `SignSpoof` 未含本包 + `TapLoginForceWeb` 白名单未含本包 —— 两者都是**纯静态可查**的，却花掉一轮装机 + 一次用户实测。
- **方案**：出包前用包名 grep 两张表（`SignSpoof.java` 的 `XXX_PKG`、`TapLoginForceWeb.java` 的 `PKG_WHITELIST`），缺则 WARN（TapTap 渠道包则 FAIL）。
- **[落点]** 新增 `mod菜单/starry-mod-menu/scripts/_lib/check_shared_tables.sh`，在 `surgical_*.sh` 的 `[1/6] 输入检查` 调用（先只接本作与后续新游戏）。
- **成本/风险**：小；只读断言。**验收**：用未登记包名跑 → 非零退出并打印「缺 SignSpoof/TapLoginForceWeb 登记」。
