## 双机协作（每台机器，每轮开工第一步）

本仓由 **mac 端**与 **Windows 端**共用同一个仓库（`git@github.com:Aliang369/nixiang.git`，分支 `main`）。
**任何机器上的任何 AI，接手任务后的第一步先做本节，再读其它内容。**

```bash
cd "$NIXIANG_ROOT"                 # Win 端在 Git Bash 里；mac 端在 zsh 里
bash 04_scripts/双机协作/twin_status.sh   # 双机体检：有 FAIL 先修再开工（同时自动重写本机心跳）
git status -sb                     # 必须干净；不干净先报告处理，不要 pull
git pull --rebase --autostash      # 拿到另一台机器已推送的提交
git log --oneline -5               # 确认拿到了什么
sed -n '1,6p' "10_docs/_state/机器心跳/win.md" 2>/dev/null    # pull 后看对方心跳（win 端则看 mac.md）：超 7 天未更新或含 FAIL → 先提醒对方复检
```

- **顺序不可颠倒**：先 `status` 再 `pull`。工作区不干净时 pull/rebase 会把未提交改动卷进去。
- **一机一游戏**（`10_docs/双机协作/双机协作同步方案.md` §2.1）：同一轮只由一台机器写同一个游戏；开工前先划定归属（如 `mac → 游戏 A`，`win → 游戏 B`），登记 `bash 04_scripts/双机协作/claim_game.sh <游戏>`（收工 `--done` 释放，占用表 `10_docs/双机协作/本轮归属.tsv`）；pull 后发现对方已认领未释放的游戏禁止写。两台要改同一游戏须先协调，否则会产生真实合并冲突。
- **机器心跳**：`twin_status.sh` 每次运行自动重写 `10_docs/_state/机器心跳/{mac|win}.md`（只写本机那台，收工随 git 提交）。对方心跳超 7 天未更新或含 FAIL 时，先提醒对方复检，不默认其环境正常。
- **跨机接手先看重建行**：接手另一台机器分析过的游戏时，先核对该游戏 `games/{游戏}.md` 摘要里的「接手重建：」行（需重新 dump/下载的产物与再生成命令）；没有就先补写再动手——dump 产物不入库，按历史路径找文件会扑空。
- **状态索引单一写者**（§2.2）：`10_docs/_state/current.md` 与 `10_docs/_state/games/{游戏}.md` 由本轮动了该游戏的那台机器写，另一台只读。
- **push 被拒**（另一台已先推）→ `git pull --rebase --autostash` 后再 push；**禁止 `push --force`**（§6.3）。
- **push 一律经 `push_main`**（2026-10-10 追迹迷城复盘 P0-5；2026-10-11 m03016 升 v2.1）：收官脚本 `archive_scoped_git.sh` / `archive_close_git.sh` 已接线 `04_scripts/_common/git_push_main.sh` 的 `push_main` —— **四通道** `ssh22 / ssh443 / https-proxy / https-direct` 按序试，每条先用 `git ls-remote --heads origin <branch>` 探测（与 push 同一条认证/DNS/代理路径），**一次调用内自愈重试**（`--attempts 6 --wait 20`，`--selftest` 只体检），全程 `git push origin <branch>`（刷新跟踪引用）、不改 remote 配置；被 `Updates were rejected` 即判分叉**短路返回 3，绝不强推**。**别再裸 `git push` 盲等超时。**
- **收工**（§6.2）走现成口令对应的 `04_scripts/_common/archive_scoped_git.sh`：只按本机归属范围做白名单 `git add`，禁止 `git add -A`。
- Git Bash 里可直接用：`nixst` / `nxfetch` / `nxpull` / `nxlog` / `nxclean`。

## 同批落地（2026-10-16：`push_main` HTTPS 通道修复 —— 关闭上一轮未解决项 4）

### 根因（上一轮已定位，本轮复现并留证）

`origin` = `git@github.com:Aliang369/nixiang.git`（SSH 形态），且本仓/全局均无 `url.insteadOf` 映射。
`_pg_run_route` 的 https-proxy / https-direct 分支虽然传了 `-c http.proxy=` 与 `-c credential.helper=`，
但 **git 按 origin 的 URL 决定传输方式**，这两个参数对 SSH 传输完全无效 ⇒ 两条通道退化成「再试一次 SSH」，
「四通道自愈」实际只剩 ssh22/ssh443。附带缺陷：`_PG_GIT_OPTS` 里 `http.lowSpeedLimit=0` = **不做低速判定**
（`lowSpeedTime=600` 随之失效）⇒ 单条通道可挂 10 分钟。

**第二处缺陷（把传输修好之后才暴露出来）**：内联 credential helper 原先把引号写成 `\"`：
`helper='!f(){ … echo \"password='"$(_pg_token)"'\"; };f'`。git 执行该 helper 时 `\"` 被 sh 还原为字面引号，
于是 helper 输出的一行是 **`"password=<token>`** —— 键名带了前导引号 ⇒ git 认为**没有** password ⇒ 转而交互式索要密码，
无 tty 时报 `fatal: could not read Password for 'https://x-access-token@github.com': Device not configured`。
**为什么探测发现不了**：本仓是**公开仓库**，`ls-remote` **匿名即可成功** ⇒ 通道探测全绿，
只有真正需要认证的 push 才会红。这也解释了 v2.1 为何一直没踩到：它的 HTTPS 通道压根没真正走通过。
A/B 实测（同一 token、同一代理，只改引号写法）：

```

B) 普通 "   ： [pre-push] 机器关 PASS → To https://github.com/… main -> main              rc=0
```

### 修法（四处）

1. **新增 `_pg_https_insteadof_cfg "$url"`**（+ 包装 `_pg_origin_insteadof_cfg`）：把 SSH 形态 origin

3. **低速阈值改为有界且可调**：`PUSH_HTTP_LOWSPEED_LIMIT`(默认 1000) / `PUSH_HTTP_LOWSPEED_TIME`(默认 60)，

4. **新增 `_pg_cred_helper`**：集中生成内联 credential helper，改用**普通双引号**（去掉 `\"`），

## 同批落地（2026-10-16 第三批：`archive_scoped_git.sh` / `archive_close_git.sh` 退出码修复）

依据：用户当轮指令「修 archive_scoped_git.sh 吞退出码」（承接上一批末尾自检发现）。

### 缺陷与影响

两个收尾入口的尾部都是：

```bash
push_main main || echo "[push] 未推送：本地提交已保留，汇报里写明 ahead"
```

`||` 后面的 `echo` 成功 ⇒ 脚本**仍以 rc=0 结束**，于是「已提交但没推上去」被当成成功。真实影响有两处，
都是**现成代码被这行变成死代码**：

- `finalize_round.sh:117` 写的是 `rc=$?; [ "$rc" -eq 0 ] || step_fail "$rc"` —— 它本来就打算在 push 失败时 `step_fail`，但这行永远拿不到非 0。
- pipeline 的 `archive` / `archive_close` 阶段（`run_stage` 按 rc 判成败）同样会把未推送当成功。

### 修法（两处同款）

保留「本地提交不丢 + 提示照打」，只把结果经退出码传出去：

```bash
PUSH_RC=0
if [[ "$PUSH" == "1" ]]; then
  push_main main || PUSH_RC=$?
  if [[ "$PUSH_RC" != "0" ]]; then
    echo "[push] 未推送（push_main rc=${PUSH_RC}）：本地提交已保留（$(git rev-parse --short HEAD)），汇报里写明 ahead"
  fi
fi
...（原有输出/manifest 复核照旧）...
if [[ "$PUSH_RC" != "0" ]]; then
  echo "==> 退出码 ${PUSH_RC}：提交已在本地，**远端未同步**，调用方请按失败处理" >&2
fi
exit "$PUSH_RC"
```
