## 0. 一句话诊断

本会话的浪费**不是不懂技术，而是「诊断与修复捆在同一个重量级周期里」**：一个「开关点了没反应」的猜测，就要付出「重编 so → apktool/zip 重打包 1.8 GB → 签名 → 装机 → 用户手测」≈ 20 分钟 + 用户真人时间。
两次无效装机（14:45 / 15:01）各让用户白测一轮，根因（`OkPtr` 判据过严 + 诊断行被提前 return 吞掉 + 装钩在 UI 线程同步做）在代码里都是**一分钟能看出来的**。
⇒ 方向：**把「改 so」从 20 分钟压到 1 分钟（P0-1 热替换）**，**让每个包自带可判读的自诊断（P0-2）**，**让机器关先于用户关（P0-3 / P1-3 / P2）**。

## 3. 落地清单（含验证命令）

### P0-1 so 热替换通道（≈20 min → ≈1 min）

```bash
# 通用（任意游戏，包 extractNativeLibs=true 即可）
bash 04_scripts/_common/so_hotswap.sh --serial f9a116a2 --pkg com.hypergryph.arknights \
     --lib-name libstarry_magic.so --so <本地so> [--restart] [--judge] [--dry-run]
# 明日方舟包装（serial/包名取自 04_scripts/明日方舟/official_apk.json）
bash 04_scripts/明日方舟/so_hotswap_mrfzz.sh [--restore] [--dry-run]
```

原理：包 `extractNativeLibs=true` ⇒ so 已在 `/data/app/~~<rand>/<pkg>-<rand>/lib/arm64/`，该目录 **root 可写**；脚本 push 到 `/data/local/tmp/_hs_$$.so` → `su -c 'cp … && chmod 755 && chcon u:object_r:apk_data_file:s0 …'` → 回读 md5 比对 → 写设备台账 `hotswap_state.txt`。
硬边界（脚本末尾会打印）：热替换态与包内 so 已不一致，**本轮任何结论都要标注 so md5**；改 dex/清单/签名或交付轮 ⇒ 回 `pipeline.sh <游戏> reset build_so → run → next --loop`。

### P0-2 诊断层 / 证据层分离

- `mod菜单/starry-mod-menu/app/src/main/jni/Includes/JudgeSelfCheck.h`：`#ifndef STARRY_DIAG → 1`；`SDIAG(...)` 用 **`#if`**（不是 `if(常量)`，否则字符串仍进 `.rodata`）；`SDIAG_ONCE(name, ...)`。
- 分界：证据层（`hooked/hit/method miss/nested miss/dobby fail/重试/lib ready`）永久保留；诊断层（`diag:/calib:/OkPtr probe/by-name ok/ext api assignable/feature #N/status/SELFCHECK`）随包剥除。

```bash

bash            04_scripts/明日方舟/mrfzz_build_so.sh      # 正向断言：诊断串 ≥1
```
实测：交付态 so 174,536 B md5 `cb31cfece9ef5dda1c1ac34408057caa`（`SELFCHECK`/`calib: guard2`/`diag: ready=`/`OkPtr probe` 全 0）；诊断态 181,744 B md5 `ea5ce2c06dd59f17a04f869bfc8bb5ea`（全 1）。**注意**：已交付的正式包（md5 `310e1a74bd1d05392f7828e4ebbdf005`，L3 已通过）仍是含诊断串的旧 so，本次未重出包。
