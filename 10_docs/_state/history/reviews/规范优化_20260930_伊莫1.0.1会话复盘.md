## 2. 已验证、可复用的事实（本会话真正值钱的产出）

### 2.1 零 il2cpp 的 xLua 游戏注入路线
- 符号取用：**`nm -D` 可读，`readelf` 读不到**。可钩点只有两个：
  - `lua_pcall @0x1096dac`，size `0xcc`（可钩）；
  - `lua_gettop @0x1090be0`，size `0x10`（＝Dobby 的 16 字节下限，刚好）；
  - `lua_setglobal @0x9a8ed4` only 12 B ⇒ **太短，钩不了**；`lua_pcallk` **未导出**。
  - `luaL_loadbuffer @0x10a41a8` 序言 `d103c3ff` 可当指纹。
- 注入方式＝`luaL_loadstring` + `lua_pcall` 执行**整段 chunk**（≈19 KB），而不是 il2cpp 方法 patch。
- LOAD2 口径：`fileoff = vaddr − 0x4000`（直接按 vaddr 读文件字节会错位）。

### 2.2 Lua 全局表是白名单式
`Core/Framework/Global.lua:106 __index` → `:73 __logGlobalError` → `:40`：**裸读未声明的全局返回 nil 并记一条 error（不抛异常）**。
⇒ 一律 `rawget`/`rawset`；**永远不要写 `Y = Y or {}`**。诊断计数用 `rawset(_G,"__YM_N",…)`。
（踩坑现场：`if YM then YM.dmg=… end` 永远 false，功能静默不生效；修好后 `grep -c "undeclared global variable"` = 0。）

### 2.3 C# 对象经 Lua 暴露的方法返回**活引用**
`pawn.getPosition()` 返回共享的 `self.posRef`（`ClientPosRotComponent.lua:112`），`forceSetPosRot` 传送成功后就地改写 ⇒ **传送之后再读等于读落点**。
后果：诊断里「计划距离」恒为 `0.0m`、「弹回」判据恒假 ⇒ 整条「弹回原地」是**死代码**，而我一度拿它当证据。
⇒ 铁律：**返回值当值用之前先拷标量；读的时机就是语义的一部分**；且**诊断字段恒为常数 = 诊断本身可能错**。

### 2.4 重发型伤害放大的生效条件
服务端只认一条上报的**实例首命中** ⇒ 只有「RPC 里没有实例身份」的通道才放大得动：
- ✅ 精灵 `RPC_CS_DoActOnActorActions`（实测重发 55 次有效，本作主输出是宠物）；
- ✗ 人物 `RPC_CS_ProjectileHitTarget`（首参是 projectile id，且紧跟 `RPC_CS_ProjectileDestroy` 同 id ⇒ 重发白费）。

### 2.5 其它
- 游戏自带 `Core.Log.LoggerManager` **不落 logcat** ⇒ 诊断只能自建文件通道（本轮已按用户要求全部拆除）。
- `adb logcat -s TAG:V` 是**前缀匹配**，`[Yimo]` 匹配不到 ⇒ `adb logcat -d | grep "\[Yimo\]"`。
- 大热更游戏换签必须卸载，热更数据在 `/sdcard/Android/data/<pkg>` 会一起清。

## 3. 优化方案（可执行，按价值排序）

### P0-1 诊断脚手架编译期隔离（本次最大浪费的正解）

**目标**：一套代码出两种包，永久不再「先写日志再手术拆除」。

1. 新增 `mod菜单/starry-mod-menu/app/src/main/jni/ModDiag.h`：

```c
#pragma once
#include <android/log.h>
#ifdef STARRY_DIAG
#define DLOG(fmt, ...) __android_log_print(ANDROID_LOG_INFO, "StarryDiag", fmt, ##__VA_ARGS__)
#define STARRY_DIAG_LUA 1
#else
#define DLOG(fmt, ...) ((void)0)
#define STARRY_DIAG_LUA 0
#endif
```

2. `Games/*.cpp`：native 侧诊断一律 `DLOG(...)`；Lua 侧诊断**整段**独立成常量（如 `kYimoDiagLua`），patch 组装处用 `%s` 拼 `STARRY_DIAG_LUA ? kYimoDiagLua : ""`。
3. 构建脚本：`STARRY_DIAG=1` 时给 `ndk-build` 传 `STARRY_DIAG=1`，产物名后缀 `-diag`；**默认（不带）＝干净包**。
4. 新增门禁 `04_scripts/_common/check_release_clean.sh`：正式包构建前扫 `Games/*.cpp`，命中 `ym.log` / `io.open("/sdcard` / `_dbg(` / `LOG(` 且未处于 `#ifdef STARRY_DIAG` 块内 ⇒ **拒绝出包**（照抄 `surgical_*.sh` 现有「缺菜单串即 fail」的门禁风格）。
**落点**：`ModDiag.h` + `surgical_*.sh` + `check_release_clean.sh` + `skill/starry-mod/surgical-build.md`。
