### 2.7 复用方法：怎么读 DSH 会话日志（本次取证关键）

```js
// node（v24，自带 zlib.zstdDecompressSync）；捆绑 python 3.12 没有 zstandard 模块
const buf = fs.readFileSync('C:\\Users\\Administrator\\.dsh\\sessions\\--E-nixiang--\\<sid>\\session.v4.jsonl.zstd');
// 坑：该文件是 zstd 多帧拼接（13.8 MB ≈ 7383 帧）。整块 zstdDecompressSync 只解出第 1 帧（191 B）。
// 必须扫魔数 28 B5 2F FD 逐帧解压再拼接，才是完整 JSONL。
```

事件类型与取数位置：`user/message`→`data.content[].text`；`assistant/message`→`data.message.content[]`（含 reasoning 与 tool-call）；`tool/call`→`data.name/arguments`；`tool/result`→ 错误行在 `[exit code: N]`；`compaction/prune`→`data.shadowedTokenCount`；`llm/retry`→`data.failure.code`；`subagent/catalog`→`data.label`。

## 4. 建议的落地顺序

1. **先落"抗压缩"两件**（P1 硬约束 + P3 路线锁定）：它们决定后续所有轮次的约束力，且不依赖任何机器门禁。
2. **再落机器门禁**（P4 轮次门禁 + P5 包装器）：同一份代码同时解决"软纪律没牙"和"即兴重试烧 token"。
3. **再落判据与诊断**（P2 §30 + P8 §29.5）：下次换游戏/换模拟器时才用得上，但必须提前写好。
4. **最后落效率项**（P7 `dump-class` + P6 预算 + P0 本文重排 + P9 防误删）。
5. **每次落地后跑机器关**：`bash 04_scripts/_common/preflight.sh <改过的文件>`（.sh 会连带 bash 3.2 门禁）。
6. **下次新游戏接手时的验证点**：① `stage_next.sh status` 能钉出硬约束；② 装钩日志有三行自检；③ 路线锁定表在装机前已填；④ 连续 3 轮无效时 `install` 真被拒绝。
