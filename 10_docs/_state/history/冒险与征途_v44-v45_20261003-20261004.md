## 2026-10-04 真机回归：四项全失效 + 免广告卡死 → v45 修复

**现象**：v44 包在 win/MuMu 模拟器四项全过，换真机（OPD2404 / KernelSU root）后
①开免广告整个游戏卡住像断网 ②四项功能全无效果。

**判定段 = B（装上了没命中）**：`interp DobbyHook rc=0` 已 arm，但 `interp calls` / `learn slow` 恒为 0
（对照模拟器历史 `interp calls=540000`）⇒ 钩子装上了，却没钩在游戏执行的那份内存上。

**根因：真机上 `libil2cpp.so` 被双映射（同 dev:inode `fe:48 594484`）**

| | 映射形态 | 判据 |
|---|---|---|
| 影子 A | 单行 `r--p off 0` 整段只读（本例 `73288f3000-732dbef000`） | **无任何 rw-p**；Frida `Process.enumerateModules()` 里根本没有它；尾部紧邻的是 libunity.so（无 bss） |
| 真身 B | `r--p 0` → `r-xp 01d73000` → `r--p 04cfe000` → `rw-p 05045000` | rw-p `Private_Dirty` 数 MB（重定位已应用）；尾部紧邻 `[anon:.bss]`；Frida 模块表只列它 |

旧 `LibBaseFromMaps` 判据是「off==0 **且地址最小**」⇒ 真机上影子 A 地址更低，恒定选中 A
⇒ 入口 hook / push-frame hook 全落到不执行的只读副本 ⇒ 四项功能集体失效；免广告的帧分发也挂在这条路上，故一开就卡死。
win/MuMu 只有单份映射，所以「win 做完在模拟器测都有用」完全自洽。

**v45 修法**（`mod菜单/starry-mod-menu/app/src/main/jni/Games/MxytzMod.cpp`）：
按「同 dev:inode 且地址首尾相接」把 maps 切成**映像组**，取**含 rw-p 的那一组里 off==0 那行的起点**当模块基址；
新增 `LibBaseResolve()`（`std::atomic` 缓存，只解析一次）与 `LogLibMaps()`（把每份映射逐行打进 logcat 便于比对）。
⚠️ **踩坑记录**：初版取的是「rw-p 那一行的起点」，那是偏移 `0x5045000` 的第三个 LOAD 不是基址 ⇒
`base=0x7437700000`、`entry=0x743977f798` 直接落到模块外、`rd=0`、hook 写飞。**必须先选组、再取组内 off==0 行。**
不用 `dl_iterate_phdr`/`xdl_info`/`dlsym` 取 `dli_fbase`：`InstallInterpHook` 跑在启动早期，进 linker 抢 `g_dl_mutex` 有死锁风险，而解析 `/proc/self/maps` 无锁。

### 根因（两条互不知情的代回调路径，且都在我们自己的 hook 帧内当场调托管）

| 路径 | 代码 | 旧做法 |
|---|---|---|
| A 静态挂点 | `MxytzMod.cpp` `kAdSlots` 的 `PlayAD2`（`required=true`）→ `Hooked_PlayADVideo2` | `CallOnAdResult` 拿 `g_onAdResultMP` **方法指针直调** |
| B 解释器分发 | `kKinds` 的 `K_PLAYAD` → `ApplyNoAdV43` | `api.runtime_invoke(g_miOnAdResultV43, …)` |

一次广告请求发**两次** `OnADVideoResult`；而回调内游戏再触发广告请求时，就与「仍在栈上的我们」**互相递归** ⇒ 帧内 invoke 帧，栈涨破 8MB。

**「兜底」核查结论（回答用户）**：`MxytzMod.cpp` 里 `static thread_local int t_interpDepth` 只有**声明无使用**（死代码）；全文件无 `try`/`catch`/`sigaction`/`setjmp` —— **C++ 异常拦不住 SIGSEGV，重入闸才是唯一有效手段**。

### 修复（v46，`MxytzMod.cpp`）

1. **闸① `t_modInvoke`**（`thread_local`，声明上移到 ⑦ 广告路径之前）：mod **主动发起**的托管调用期间任何派发一律跳过。这是唯一真正必需的闸 —— 它把「我们自己引发的再入」与「游戏正常的托管→托管嵌套」区分开，后者**绝不能拦**（`Hurt`/`DoAttack` 本就出现在嵌套深度 >0 处，拦了 #1/#2/#3 全哑，v30 已踩过同型坑）。
2. **闸② `InterpGateGuard` + `kInterpMaxDepth = 24`**：只统计**我们自己派发期间**的嵌套（进 `InterpDispatch` 前 +1，调 `orig` **之前**已 -1）⇒ 合法游戏嵌套永远看到 0，只作硬上限兜底。
3. **闸③ 免广告改帧外执行**：`ApplyNoAdV43` / `Hooked_PlayADVideo2` **只往同一个待办槽登记**（`EnqueueNoAdV43`，覆盖式 ⇒ 天然合并两条路径的重复登记），真正的 `runtime_invoke` 交给 `DrainPendingAdV43`，由**下一次解释器入口**（上一次派发的帧已退干净）取走一次、执行一次；`Hooked_Interp` / `Hooked_PushFrame` 在 `orig` 返回后、`t_modInvoke==0` 时 drain。
4. **熔断降级**：`g_adV43Fuse` 从「一次异常永久关死整条链路」改成 `g_adV43FuseUntilMs` **30 秒自动重试**（旧语义一旦触发游戏就永远等不到 `OnADVideoResult` = 玩家看到的「玩法进不去」，与栈溢出是同一功能的两张面孔）。`CdInvoke` 也统一打 `t_modInvoke` 标。
5. 免广告 uuid 解析失败时**降级出处真广告**（宁可看广告也不要把玩法卡死）；`STATS` 行扩展为 `… | AD43 见= 排队= 已回调= 熔断= 重入闸=`。
