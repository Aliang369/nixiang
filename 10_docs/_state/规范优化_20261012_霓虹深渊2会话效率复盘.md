## 二、五个黑洞：烧掉的上下文与替代做法（均已落地）

### 黑洞 1：`nhsy2Mod.cpp` 被读 202 次 / 608 KB（占 read 总量 915 KB 的 66%）

证据：`read` 该文件 202 次，另有多次 `bash sed -n` 重复切片。

**落地做法（锚点索引一次落盘）**：`10_docs/霓虹深渊2/侦察笔记_锚点索引.md` —— §1 给 `Games/nhsy2Mod.cpp`（4008 行）的 24 段行区间锚点表（例：`1092–1335 Dobby 16 字节入口补丁吃邻居方法入口 = r7/r12 闪退根因`、`:1347 Hooked_Hearts_DeductHP`、`3881–4008 ⑧:3883 bool nhsy2_TryInit(JavaVM*) 签名受 ModEntry.h 约束`），§2 是「按功能# 查挂点 + logcat 判据」表，§3 六条铁律级结论，§4 其它文件锚点。
- 约定：改该文件前先查锚点索引，只按行段 `read offset=… limit=…`。
- 省：read 体量 608 KB → 约 60 KB（**-90%**），少 150+ 次往返。

### 黑洞 2：状态/台账文档反复整读（台账 14 次 38KB、game 摘要 9 次 34KB、TOOLBOOK 10 次 29KB、current.md 7 次 21KB、路线锁定 3 次 15KB）

证据：同一文件相同 offset/limit 的**整读**重复 ≥8 组；`10_docs/霓虹深渊2/台账.md` 已涨到 73 KB / 355 行（表格行 210、其中「已否证」44 条），`轮次台账.tsv` 37 KB —— 都远超 AGENTS 的「单文档 ≤12 KB」摘要阈值。

**落地做法（速读摘要 + 禁整读，代替原方案的"分片"）**：
- 原方案要"把 44 条已否证下沉 history"，实施时发现 **`台账.md` 的 charter 是 append-only（永不删行）** ⇒ 分片不以删行实现。
- 改为**派生速读摘要**：`bash 04_scripts/_common/state_digest.sh <游戏> --write` 生成 `10_docs/<游戏>/_digest.md`（带行号 `:<行号> | 首列` + 小节标题），实测 `10_docs/霓虹深渊2/`：台账 73,372 B / 355 行 + 硬约束 7,038 B + 路线锁定 12,085 B ≈ **92 KB → 19 KB / 283 行**（5 倍压缩且可 grep）；`--check` 在摘要过期时 rc=1。
- 读取纪律进 `AGENTS.md` P24：≥20 KB 状态文档禁止无 offset/limit 整读，先 cat `_digest.md` 再按行号取段。

### 黑洞 3：logcat 现场 grep 176 次 / 448 KB

证据：`logcat` 出现 176 次，多为「换关键词再搜一遍」，无固定取证入口。

**落地做法（把取证做成工具）**：`04_scripts/_common/evidence.sh`
`--game/--serial/--pkg/--needle（可重复）/--source/--buf-lines/--lines/--dir/--quiet` → 一次落 `09_test/<游戏>/evidence_<ts>/{logcat.txt,slice_*.txt,meta.txt}`，固定 8+1 项关键行计数（`install pass` / `install skip` / `nhsy2` / `libstarry_magic` / `Fatal signal|SIGSEGV|fault addr` / `Cause:` / `Start proc|MenuService|ModBridge` / `async_safe|护盾` / 包名），**终端只回显 ≤40 行**。
- 省：448 KB → 约 120 KB；也避免同一段日志被反复搜。

### 黑洞 4：200 次内联 python 一次性分析脚本

证据：`python3 - <<PY` 200 次，其中很大一部分在做同一批事（so 段/符号/字符串窗口、md5、zip 条目、反汇编）。

**落地做法（一件六子命令工具箱，代替原方案的三个脚本）**：`04_scripts/_common/so_inspect.py`
`sha`（size+md5+sha256）/ `strings`（**UTF-8 感知**，`--grep/--min/--max`）/ `zip`（`--list/--grep/--entry/--extract`）/ `hex`（`--off/--n`）/ `disasm`（capstone，`--off/--n/--va/--arch`）/ `ptr`（8 字节指针表）。
- **实测证据**：`strings --grep '无限|全屏'` 在包内 `libstarry_magic.so` 命中 **37 条**（`Toggle_无限水晶`、`无限水晶：用完退款`、`[nhsy2] shop probe #%u IsFree real=%d tt=%d -> 1 (无限金币：该道具按免费结算)`…），而系统 `strings | grep -c 无限` = **0** —— 这正是会话里「strings 取不到中文」的根因（系统 strings 把 ≥0x80 当不可打印）。
- **方案修正（有意缩范围）**：**不建** `rva_table.py` / `il_query.py` —— 本作 RVA 不可得（`DumpRva` 报 `Failed to find code registration or metadata registration!`），离线 IL2CPP 元数据查询对该游戏的 by-name 路线无增益；离线取证需求已被 `so_inspect.py` 6 个子命令覆盖。
- 省：分析输出 287 KB → 约 140 KB。

### 黑洞 5：编译与装机链路手敲（ndk-build 43 + surgical 74 + apksigner 13 + zipalign 4 + 手敲 adb install 3，而 gradle_cycle 只用了 2 次）

**落地做法（一键轮次环，方案修正后）**：`04_scripts/霓虹深渊2/round.sh <标签> [--loop N] [--dry-run]`
- **修正理由**：`pipeline.sh` 头部铁律要求「机械操作唯一合法入口 = pipeline.sh」，且它**已内置** `next --loop N`；再写一个 `nhsy2_cycle.sh` 手搓 ndk-build/surgical/apksigner 就是重复造轮子。
- 现在的做法：`round.sh` 只干三件事 —— ① 改 `pipeline.json` 的 `params.version`（`version_code` 保留尾部源码指纹）② 转发 `bash 04_scripts/pipeline.sh 霓虹深渊2 next --loop N`（默认 9，即 check_apk→anchor→impl_mod→build_surgical→sign→device_ready→install→archive→archive_close）③ 按 rc 打印下一步：rc=3 ⇒「被轮次门禁拦住，先填假设矩阵」；否则打印 `post_install_precheck.sh` 与台账回写命令行。
- 省：每轮从 ~8 条手敲命令降到 1 条；本会话约 130+ 条手工链路命令可压到 ~17 次调用。
