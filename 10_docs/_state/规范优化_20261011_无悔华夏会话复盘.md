# 会话效率复盘与可执行方案（无悔华夏 3.8.280 四新增功能 · 20261011）

> 目的：把本轮（m00001 → m01980）里**重复出现**的坑固化成机器门禁，下一轮同类任务从「摸索 + 反复装机」压到「一条命令验收」。
> 用法：§3 的 P0 三条做完，同类任务的无效轮次 ≈ 归零；P1 六条做完，跨游戏通用。

## 1. 本轮的账（量化，全部来自本轮实测日志）

| 项 | 实测值 | 说明 |
|---|---|---|
| 签名打包次数 | 4 次（R1/R2/正式 + 早期一次） | 每次 ~1.5 GB 读写 + 签名 2–4 min |
| 白造产物 | **2.98 GB**（R1+R2 及其 `.idsig`） | 收尾时全删 ⇒ 纯浪费；根因=迭代期也出签名包 |
| 装包失败 | 1 次 `adb install -r` ⇒ 乐变负载失效，游戏回退包内加密 so | 触发 `[Il2Cpp] core api missing`，用户硬约束第 4 条本就禁它 |
| 清装耗时 | 1 次 `--uninstall` 卸载+全新安装 **63,671 ms**，负载回填再等 ~60 s | 迭代期不可承受 ⇒ 必须热换 so |
| ANR | 2 次（`anr_16850_…02-35-52`、`anr_20129_…02-37-53`） | 根因=主线程跑未缓存 `/proc/self/maps` 全扫（`FindClassNs`×119 程序集） |
| 日志噪声 | `rva miss` 占流日志 **221/5954 ≈ 3.7%**；单符号最高 **72 次重试**（`CheckPolicyDisable`、`GetResCnt`） | 源于 kExpect/RVA 基准仍是旧 so `c04afff4…` |
| 装钩方式分布 | **按名 46 次 vs 按 RVA 2 次** | ⇒ RVA 表已基本失效，真正干活的是 il2cpp-name 兜底 |
| 被噪声掩盖的真缺陷 | `policy panel gate incomplete` **71 条**（等速刷）⇒ 面板门整轮「永不 ready」没人发现 | 若日志噪声为 0，这条会在第 1 分钟就暴露 |
| 卡密阻塞 | 验收前置=用户卡密登录（缓存 600 s） | 无登录 ⇒ 4 项功能全 OFF、装钩函数不执行 ⇒ 只能等 |
| 工程性反复 | ① `bash build.sh \| tail` 把 ndk-build rc=2 掩成 0；② `logcat` 默认 256 KiB 把首启日志刷掉；③ `/data/app/.../libstarry_magic.so` 只读（incremental-fs）；④ `su` 下 `cat/md5sum` 被拒、`ls/cp` 正常；⑤ ANR 里的 pc 无法符号化（本地 so 无 DWARF、macOS 无 readelf） | 每条都花了 ≥1 轮才摸清 |

## 2. 反复出现的问题 → 根因 → 结构性修法

| 现象（每轮都重演） | 根因 | 结构修法（见 §3） |
|---|---|---|
| 装钩每轮大批 `rva miss`，个别函数重试到刷屏 | RVA 常量 + `kExpect[]` 序言表绑死在某个 so 版本，乐变一换 so 就整体漂移；而按名兜底其实是主力 | P0-② 自动重标 + **把优先级反转为「先按名、RVA 只作加速」** |
| 面板门/资源门「永不 ready」却无人察觉 | 同上的漂移 + 状态日志本身无限速 | P0-② 重标；P1-⑤ 日志限流门禁 |
| 菜单动作卡死/ANR | 装钩与全表扫描跑在菜单（主）线程；热路径逐帧 `LOGI` | P1-⑤ lint 门禁（线程闸 + `HotLog` 强制） |
| 「功能被开启了但没反应」的验证歧义 | 判据没有工具化，每轮靠人肉 grep 猜 | P0-① 一键验收器（PASS/FAIL 表） |
| 覆盖安装把乐变负载搞坏（**用户已重复提醒十几次**） | 规则只在文档里，没有机器闸门；且仓库另有「优先覆盖安装」的通用规则冲突 | P1-⑥ `install_policy` 声明 + 门禁脚本；P0-③ 装机只走一个入口 |
| 迭代期就出签名包，白造 3 GB、命名 R1/R2/正式混乱 | 没有「迭代=热换 so，收尾=打包」的分工 | P1-⑦ 只出唯一正式包 + 同批旧包自动清理 |
| 设备侧操作反复摸索（写不进去、读不出来） | 没有封装好的设备助手 | P0-③ `dev_swap_so.sh` / `dev_pull_root.sh` |
| 构建「假成功」 | 管道 `| tail` 吞退出码 | P1-④ 构建脚本自证 `BUILD_OK` |
| ANR/崩溃栈无法符号化，只能靠源码猜 | 出货 so 已 strip，本地缺符号与 BuildId 映射 | P1-④ `--debug` 变体 + `so_symbolize.sh` |
| 验收被「卡密登录」卡住几十轮 | 功能装钩有会话闸门（设计如此），但没有免登录的自证路径 | P2-⑨ 冷启自检 `Whrhx_SelfTest()` |
| 跨会话/跨轮重新推导上下文 | 每轮结束没有 5 行接力气 | P2-⑩ 接力卡 |

## 3. 可执行方案

### P0（本轮/下轮立刻可用，三条，投入 <2 h）

**P0-① 一键验收器 `04_scripts/无悔华夏/whrhx_verify.sh`**

```bash
# 用法：bash 04_scripts/无悔华夏/whrhx_verify.sh [--feat 10,11,12,13] [--pid auto]
# 产出：每项一行 PASS/FAIL + 决定性日志原文（缺什么就打印要抓的字符串）
```
- 判据表（写死在脚本里，即本轮的验收标准）：
  | 项 | 必需日志 | 失败时打印 |
  |---|---|---|
  | 身份链 | `identity api ready mgrOff=0x30 countryOff=0xE0` + 心跳 `idApi=1` | `identity miss: <why>` |
  | 装钩方式 | `hooked ArmyGetMaxCanSendNum …` 且区分 `(rva)`/`(il2cpp-name)` | `rva miss <sym>` |
  | #10 | `noCD-policy finish … no active remain=0.000` | `policy panel gate incomplete …` |
  | #11 | `minister favor pinned=1` | `minister hooks=0` |
  | #12 | `noCD-minister finish id=… ` | — |
  | #13 | `army maxSend type=0 A→B (+N%)` / `army cap target=… A→B` | — |
- 验收命令：`bash 04_scripts/无悔华夏/whrhx_verify.sh --feat 10,11,12,13` 全 PASS ⇒ 收尾。
- 收益：把本轮 ~10 次人肉 grep 会话压成 1 条命令，且**新缺陷不再被噪声掩盖**。

**P0-② 自动重标 + 优先级反转（消掉 `rva miss` 整类问题）**

```bash
# 1) 从当前 dump.cs 重算常量与期望序言，生成只读头（人工 review 后替换）
bash 04_scripts/无悔华夏/whrhx_rebaseline.sh \
  --dump 06_dumped/无悔华夏/current_20261011/runtime/il2cpp_dump/dump.cs \
  --so   06_dumped/无悔华夏/current_20261011/runtime/libil2cpp_runtime_20261011.so \
  --out  mod菜单/starry-mod-menu/app/src/main/jni/Games/WhrhxRvaGen.h
# 2) 校验（应为 0 失配；本轮为 39 处、其中 2 处每轮重试 72 次）
python3 04_scripts/无悔华夏/whrhx_check_kexpect.py --so … --cpp …
```
- 代码侧一处改动（`WhrhxMod.cpp` `HookRvaOrIl2Cpp`）：**先按名解析，命中即装钩（打 `@ … (il2cpp-name)`）；未命名/需加速时才用 RVA**。理由=本轮实测 46:2。
- 收益：日志噪声 3.7%→≈0；`policy panel gate incomplete` 这类**被噪声淹没的真缺陷**第一分钟暴露；维护成本从「每轮手工重校」降为「一条命令」。

**P0-③ 设备助手（把本轮摸索出的 4 条坑固化）**

```bash
# 热换菜单 so（迭代期唯一推荐做法；/data/app 那份只读，lebian 副本才是被执行体）
bash 04_scripts/_common/dev_swap_so.sh mod菜单/starry-mod-menu/libs_whrhx/arm64-v8a/libstarry_magic.so
#   = adb push /data/local/tmp/libsm_<md5前8>.so + su cp 到 lebian/…/lib/arm64/ + ls 尺寸校验
# su 下只能 ls/cp 的文件（prefs 等）走 /sdcard 中转
bash 04_scripts/_common/dev_pull_root.sh /data/data/com.yhhy.whrhx.aligames/shared_prefs/starry_magic_prefs.xml /tmp/smp.xml
# 设备预置（并入 session_start.sh）：logcat -G 16M，避免 256 KiB 把首启日志刷掉
```
- 验收：热换后 `adb logcat -d | grep ImageOfRaw` 出现新串 ⇒ 生效。

### P1（本周，六条）

**P1-④ 构建自证 + 可符号化**
- `whrhx_build_so.sh` 末尾必须 `echo "BUILD_OK md5=$md5 stamp=$stamp"`，失败 `exit != 0`；调用处**禁止** `| tail`（本轮被掩码 1 次）。
- 加 `--debug`：`ndk-build APP_OPTIM=debug` + `-g`，产物落 `obj_whrhx_dbg/`；`04_scripts/_common/so_symbolize.sh <buildid|so> <pc…>` 用 NDK `llvm-symbolizer` 还原 ANR 栈。
- 落 `04_scripts/无悔华夏/so_build_map.txt`：`so md5 ↔ BuildId ↔ git commit`，ANR 的 BuildId 可直接反查到源码行。
- 验收：拿本轮 ANR 的 `libstarry_magic.so+0x1ec48` 能打印出 `Il2CppApi.cpp:<行>`。

**P1-⑤ 线程/日志门禁 `04_scripts/_common/lint_mod_thread.sh`**（并入构建前检查）
- 规则：① `Whrhx_SyncHooks`/`Install*Hooks` 只能在 `t_<game>Tick` 线程闸后执行；② 热路径（被 hook 的函数体）内 `LOG*` 必须走 `HotLog(n)`；③ 禁止在 hook 内直接调 `api.ImageOf(` / `fopen("/proc/self/maps")`（必须走缓存版或 `ImageOfRaw`）。
- 验收：脚本对当前 `WhrhxMod.cpp` 报 0 violation；人为插一条主线程装钩 ⇒ 报 violation 且构建失败。

**P1-⑥ 装包策略机器化（直击用户重复十几次的那条）**
- `04_scripts/无悔华夏/pipeline.json` 增字段：`"install_policy": "uninstall_only"`。
- `session_start.sh <游戏>`：读该字段，把本游戏**硬约束行**打印到首屏（与 `10_docs/无悔华夏/硬约束.md` 第 4 条同源）。
- 新 `04_scripts/_common/install_guard.sh`：任何脚本出现 `adb install -r` 且目标游戏 `install_policy=uninstall_only` ⇒ 直接 `exit 65`（本轮 `whrhx_clean_reinstall.sh:102` 的 `--wipe` 分支即为唯一合法例外，且已有 `WHRHX_ALLOW_WIPE=1` 闸门）。
- 验收：在仓库根跑 `grep -rn "adb .* install" 04_scripts/ | grep -v install_guard`，只剩清装入口。

**P1-⑦ 只出唯一正式包**
- 规则：迭代期**不打包**（热换 so；dex 改动才打包）；收尾一次打包，产物名固定 `<游戏>_<版本>_<功能集>_<YYYYMMDD>-releaseSigned.apk`，打包前自动删除同批次旧包（本轮白造 2.98 GB）。
- 实现：`whrhx_menu_latest_repack.sh` 增 `WHRHX_PRUNE_SAME_BATCH=1`（默认开）：打包成功后删同目录 `*_<YYYYMMDD>-releaseSigned.apk*` 中非本次产物**且**已在 `10_docs/<游戏>/台账.md` 记录指纹的文件。

**P1-⑧ 跨游戏共用头**（可选，收益随时间放大）
- `Includes/ModThread.h`：`EnsureIl2cppThreadAttached()`（domain 非空才 attach；Wor/Endfield/Hzsj/Whrhx 四处复制粘贴收口，`il2cpp_init` 前 attach = abort 的坑只留一处）。
- `Includes/HotLog.h`：`HotLog(n)` / `HotLogEvery(ms)`。

### P2（结构，两周内）

**P2-⑨ 免登录冷启自检 `Whrhx_SelfTest()`**
- 冷启在 mod 线程跑纯读自证：`CountryDataMgr.get_Instance` 非空 → `m_countryId` 偏移读值 ∈ 已知国度集合 → 政策/名臣两本字典 size > 0 → 打印 `[Whrhx] selftest ok countries=N policies=M ministers=K`。
- 意义：**把「等用户卡密」从验证链路里摘掉**（装钩受会话闸门限制这点不变，但链路正确性不再依赖登录）；本轮若早有它，身份链断裂会在第 1 分钟暴露，而不是等用户手动开菜单。
- 注意：只读、不写游戏数据、不开功能，不触碰卡密闸门语义。

**P2-⑩ 每轮 5 行接力卡 `10_docs/_state/rounds/<游戏>_<YYYYMMDD>.md`**
```
目标：<一句> | 已完成：<清单> | 下一步命令：<可直接粘> | 阻塞：<人/物> | 关键 ref/mNNNNN：<…>
```
- 验收：下一轮开工只需读这一张卡 + `session_start.sh` 首屏。

## 5. 需要拍板的两件事

1. **把 RVA 降级为「可选加速」、按名为主**（P0-②）：会让 `kExpect[]` 的 `want` 字段不再参与装钩判定，只用于日志标注 —— 同意即可，本轮 46:2 的实测支持这个方向。
2. **把 lint 门禁做成构建硬失败**（P1-⑤）：好处是同类 ANR 不再复发；代价是每加一个新 hook 要过一遍门禁。

## 6. 本轮已生效的规则（保留，勿回退）

- 判据纪律：**功能是否「看起来生效」不是判据，唯一判据=日志里 `@rva` 还是 `@il2cpp-name` + 功能自身的决定性日志串**。
- 本游戏装机只许 `whrhx_clean_reinstall.sh --uninstall`（`10_docs/无悔华夏/硬约束.md` 第 4 条）；迭代期只热换 lebian 副本。
- 加功能项会让 `feature_list_sig` 变化 ⇒ `clearFeaturePrefsIfListChanged` 清空旧数值键，全 OFF 属预期，不是 bug。
- `77_patched`/`06_dumped` 的 dump.cs、`*.so` 等大件不入库。
