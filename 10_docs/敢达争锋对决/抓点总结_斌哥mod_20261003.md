## 0. 结论速览（TL;DR）

1. 斌哥对本包共 **4 个内联钩**，全部改在 `libil2cpp.so` 的**可执行段**，每条只覆盖目标方法序言的**第 1 条指令**（4 字节 `B <imm26>`）：
   | # | 方法 | RVA | 形态 | 功能 |
   |---|------|-----|------|------|
   | H0 | `xRole::CalcDamage` | `0x3DB99CC` | 4B `B` → handler | **输入伤害**（返回值 += 用户输入整数） |
   | H1 | `xRole::UpdateAI` | `0x3D9CF54` | 4B `B` → handler | **超级定怪**（开关非 0 则整个函数 `ret`） |
   | H2 | `Time::get_deltaTime` | `0x67BE180` | 4B `B` → 12B stub → handler | **全局加速**（每帧把倍率写进 `Time.timeScale`） |
   | H3 | `Time::set_timeScale` | `0x67BE458` | 4B `B` → 12B stub → handler | 纯透传（无行为变化，壳模板占位） |
2. 改动**只有这 4 处**：全 RX 段逐字节内存 diff 恰好 4 个 4 字节差异，且与壳 rw 页里的 4 组「dll+类+方法」描述串**一一对应** ⇒ 既无遗漏钩、也无多余钩。
3. 菜单声明 3 项功能（`输入伤害` / `超级定怪` / `全局加速`）+ 1 个被 `//` 注释的占位槽，与 H0/H1/H2 完全闭合。

## 4. 注入机制（壳 libSDKloading.so）

### 4.1 两级跳（H2/H3 特有）

H2/H3 的 `B` 不直跳 handler，而是落到一块 **4 KB 匿名页 `0x4000237bf000`**（夹在 libunity.so 两段之间）里的 12 字节 stub：
```
0x4000237bf000: → 0x4000213e770c（H2 handler）
0x4000237bf00c: → 0x4000213e774c（H3 handler）
0x4000237bf018: udf #0 填充（后续 12 B/条）
```

### 4.2 跳板页（trampoline，还原原函数的钥匙）

- 位置 **`0x7a8c46e83000-0x7a8c46e84000`（4 KB anon r--p）**，紧邻 `7a8c46e7b000-7a8c46e83000 rw-p [anon:thread signal stack]`。
- 条目 **stride = 0x18（24 字节）**，形态 = `被窃取的原始序言 4 字节` + `ldr x17,#8 ; br x17` + `8 字节绝对目标`。
- **目标恒为 guest 原函数体 = `0x400025000000 + RVA + 4`**（即被覆盖的那条指令之后）：

| 槽 | 地址 | stolen prologue | 跳转目标 |
|---|---|---|---|
| CalcDamage | `0x7a8c46e83018` | `sub sp,sp,#0xe0` | `0x400028db99d0` |
| UpdateAI | `0x7a8c46e83030` | `str x30,[sp,#-0x30]!` | `0x400028d9cf58` |
| set_timeScale | `0x7a8c46e83060` | `str d8,[sp,#-0x20]!` | `0x40002b7be45c` |
| get_deltaTime | `0x7a8c46e83048` | `stp x30,x19,[sp,#-0x10]!` | `0x40002b7be184` |

⇒ stolen prologue 与磁盘首 4 字节一致、跳转目标与 `base+RVA+4` 一致、内存 diff 的补丁位置一致 —— **三方交叉吻合**，这是本轮抓点可信度的核心证据。

## 7. 取证方法与可复现命令

1. `adb -s emulator-5554 root`（默认 shell 无 su）；`ps -A | grep kingnet` ⇒ pid 5716。多设备时必须 `-s emulator-5554`，否则 `more than one device/emulator`。
2. dump guest 别名镜像：按 maps 逐段 `dd` `/proc/5716/mem`（→ `memdump2/`）。
3. `python memdiff3.py`：guest 镜像 vs 磁盘 so 按 `PT_LOAD` 4 字节 diff（RX 段得 4 处 / rw 段 147,779 处噪声）。
4. `python bdecode.py`：capstone（**必须 `md.detail=True`**）解码 4 条补丁 = `B <imm26>`，得 handler 地址。
5. `python findname.py`：在 `script.json` 的 `ScriptMethod[].Address`（**十进制、与 RVA 精确相等**）反查 4 个 RVA → 方法名。
6. `python findmethod.py`：在 `dump.cs` 取签名行/类声明行/TypeDefIndex。
7. live dump 三块页（`dd bs=1 skip=<十进制> count=N iflag=skip_bytes,count_bytes`）：
   - stub 页 `0x4000237bf000` 4 KB（`[Convert]::ToInt64('4000237bf000',16)` = 70369339502592）
   - flag 页 `0x4000227b8000` 233,472 B（= 70369322696704）
   - 跳板页 `0x7a8c46e83000` 4 KB
8. `python collect_evidence.py`：反汇编 4 个 handler + 解析 stub 的 adrp/add 目标 + flag 槽取值 + 串表导出。
9. `node menu_decode.js`：vm 沙箱 + 自返回 Proxy 假 DOM，直调 `app1.js` 的 `strencode()` 解菜单 exp。
10. `keytool -printcert -jarfile apk/base.apk`（pwsh 下必须写 `"-J-Duser.language=en"` 带引号，否则被拆成多个参数）。

## 8. 陷阱与教训

1. **★flag 槽位按 handler 的 `adrp` 页对齐算**：`adrp x8,#0x4000227ba000 ; ldr x8,[x8,#0x390]` ⇒ `+0x2390`，不是 `+0x390`。差 0x2000 会读到全 0。
2. **必须 dump guest 别名**：host 别名 `0x7a897703c000` 与磁盘逐字节相同（斌哥的补丁写在壳 mprotect+COW 出来的 guest 页）⇒ 比 host 会得出 patch=0 的假结论。
3. **guest 代码段在 maps 里全是 `r--p`**（houdini/Intel Bridge 不在 guest 页上标 X）⇒「无 `r-xp` 段」**不能**当「无 hook」的判据，且执行 guest 代码不需要 X 位。
4. rw 段 diff 有 147,779 处差异，全是运行态重定位噪声，**只看 `PT_LOAD(RX)`**。
5. capstone：读 `ins.operands` 前必须 `md.detail=True`（否则 `CS_ERR_DETAIL`）；全量扫需 `md.skipdata=True`，否则遇首个非法指令即停、返回 0 条。
6. `script.json` 的 `ScriptMethod[].Address` 是十进制且等于 RVA（**不要 ±0x4000**），按十六进制字符串搜会全部落空。
7. 本包 metadata **不在 APK 内**（外置 `/sdcard/Android/data/<pkg>/files/il2cpp/Metadata/`）。
8. Windows 算大地址用 `[Convert]::ToInt64('<hex>',16)`，手算 `0x4000_xxxx_xxxx` 极易错（本次手算偏差 0x2800）。
9. 真机 UI 严禁自行点屏/截图（用户硬约束），界面状态一律请用户人工配合。
