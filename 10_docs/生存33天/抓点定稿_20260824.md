## 实锤 vs 推断（读本文先看这节）

本轮 **memdiff + prefs** 真正抓到的是 **开关编号（prefs → get_ret）**，不是 Unity/il2cpp 那种「函数 RVA + patch 字节」。战斗逻辑在 **运行时 evalString 拼接的 JS** 里，和镇邪人同类：**heap 里抓不到 mod 明文**，所以文档里若只写「baseDmg / FightChangeEntityHp」那是 **ZxrMod 已验证模板**，不是从本游戏 dump 里 grep 出来的。

| 类别 | 内容 | 来源 | 状态 |
|------|------|------|------|
| **实锤** | prefs `"0"`…`"4"` ↔ 菜单 1–5 ↔ `get_ret(1)`…`(5)` | 5 次单开 dump 的 `prefs.xml` | ✅ |
| **实锤** | `shell_rw_bss` / `sdk_rw` 开/关 **无字节差** | base vs feat1–5 `cmp` | ✅ |
| **实锤** | 进程 maps（so 加载 VA） | `mem_feat*/maps.txt` | ✅ |
| **静态符号** | `se::ScriptEngine::evalString` 等 **引擎导出**（非斌哥 hook） | `06_dumped/…/libcocos2djs.so` llvm-nm | ✅ |
| **推断** | Dobby hook `evalString` + JS 锚点 `baseDmg` 等 | 斌哥栈惯例 + `ZxrMod.cpp` | ⚠️ 待 Trace |
| **未抓到** | 斌哥 `libSDKloading.so` 内 hook 桩 **文件偏移/VA** | so stripped，strings 无 Dobby | ❌ |
| **未抓到** | 斌哥拼接的 **完整 JS payload** | anon/heap 无 `isChecked_RET` 明文 | ❌ |
| **不适用** | BSS `@+0x1798` 四枚 int32 旗标 | 镇邪人有；本游戏 prefs 门控 | N/A |

## prefs 门控（实锤）

斌哥 `Main.java` 用 `SharedPreferences` 布尔键 `"0"`…`"4"` 对应菜单 1–5；native/JS 侧经 `JMYBTActivity.get_ret(int)` 读取。

逐功能单开 dump（pid 5871）：

| 目录 | 唯一 true 键 | 对应 get_ret |
|------|--------------|--------------|
| `mem_feat1_百倍伤害` | `"0"` | 1 |
| `mem_feat2_无敌` | `"1"` | 2 |
| `mem_feat3_全屏秒杀` | `"2"` | 3 |
| `mem_feat4_免广告` | `"3"` | 4 |
| `mem_feat5_攻速` | `"4"` | 5 |
| `mem_base_all_off` | （全无） | — |

memdiff：`shell_rw_bss` / `sdk_rw` 各 feat 相对基线 **无字节差异** → 与弹力果冻同类，**逻辑在 Cocos evalString 明文拼接**，非 BSS 常量 patch。

## JS 锚点（推断 · 沿用 ZxrMod 模板）

> 下列锚点 **未** 在本游戏 memdump 中以明文出现；同源 JMYBT+Cocos 栈 + 镇邪人 `ZxrMod` 已落地。正式包需 `StarryTrace` 或进战斗 log 确认锚点字符串未变。

参考 `Games/ZxrMod.cpp` → fork 为 `Games/Sc33Mod.cpp`：

1. **百倍 + 无敌** — `t=c.baseDmg` 后插入 `get_ret(1)` ×100、`get_ret(2)` t=0  
2. **攻速** — `e=Math.max(e,.01)` 后插入 **`get_ret(5)`** ×10（Sc33 专用编号）  
3. **全屏秒杀** — `FightChangeEntityHp` 内 `var f=o&&o.force` 前插入 **`get_ret(3)`** AOE 循环  
4. **免广告** — `JmybtHooks.setRet(4, …)` + Java 广告 hook（同 Zxr）

Hook 点：`se::ScriptEngine::evalString`（Dobby），与镇邪人一致。
