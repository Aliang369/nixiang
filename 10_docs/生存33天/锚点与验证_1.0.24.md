## 2. 崩溃根因与修复（本轮最大坑）

**现象**：装机后启动约 2s SIGABRT，logcat 里连 `StarryApp` 都没有。

```
Abort message: Invalid 0x78c760d740 passed to free: value not allocated,
               chunk: 0x78c7600000 mapbits: 283ff0 msg:
```

**符号化**（临时去掉 `-s` / `--strip-all`、加 `-g` 后 `llvm-symbolizer`）：

```
mod_thread                     Main.cpp:1545
Sc33_TryInit                   Games/Sc33Mod.cpp:627
TryHookEvalString              Games/Sc33Mod.cpp:605   ← DobbySymbolResolver(...)
resolve_elf_internal_symbol    dobby_symbol_resolver.cc:171
ProcessRuntimeUtility::GetProcessModule / GetProcessModuleMap
get_process_map_with_proc_maps → tinystl::vector<_RuntimeModule>::push_back
  → tinystl::buffer_append → allocator::static_deallocate (operator delete)
  → je_free → ifree → dalloc_abort_dump → abort
```

反汇编 `tinystl::buffer_insert<_RuntimeModule,…>` 证实 `operator new` / `operator delete` **成对**（`23028: bl _Znwm` … `2306c: bl _ZdlPv`），是**旧 `buffer->begin` 指针本身非法**（每元素 1032 B，含 1024 B 路径缓冲）。即崩溃在 **Dobby 预编译静态库 `libdobby.a` 的符号解析器内部**，本机 ROM/时序相关；1.0.23 时同一份 `libdobby.a` 可用。

**修复**：绕开 `DobbySymbolResolver`。`libcocos2djs.so` 的目标符号**本就在 `.dynsym` 导出**：

```
llvm-nm -D --defined-only libcocos2djs.so
_ZN2se12ScriptEngine10evalStringEPKclPNS_5ValueES2_                    0x441d80 T
Java_org_cocos2dx_lib_Cocos2dxJavascriptJavaBridge_evalString          0x3e9a64 T
```

`Games/Sc33Mod.cpp` 新增：

```cpp
static void* ResolveLibSymbol(const char* lib, const char* sym);  // dlopen(RTLD_NOW) → dlsym
#ifndef SC33_ALLOW_DOBBY_RESOLVER
#define SC33_ALLOW_DOBBY_RESOLVER 0
#endif
```

`TryHookEvalString()` 两个调用点（`SE_EVAL_STRING` / `EVAL_STRING`）改用 `ResolveLibSymbol`，`DobbySymbolResolver` 仅在该宏为 1 时兜底（默认关闭）。修复后启动零崩溃，`[Sc33] init ok se=1 jni=1 …`。

> 同仓库先例：`Games/CwjhMod.cpp:472-489`（`Cwjh_ResolveLibSym()` 注释「DobbySymbolResolver 内部 dlopen/名字查找会拿到垃圾指针」）、`Games/WjtxdMod.cpp:414-419`（注释「会遍历 /proc/self/maps 且可能踩特殊段 BUS_ADRERR」）。

### 已被排除的假设（勿重走）

1. `operator new` / `operator delete` 不配对 —— 反汇编证明成对。
2. 两份 `libc++_shared.so` 冲突（游戏自带 1,058,904 B + 本包 NDK r27 1,794,776 B）—— 排除，`libcocos2djs.so` 的 `NEEDED` 根本不含它。
3. `/proc/self/maps` 路径超 1024 字节 —— 排除。

## 3. 1.0.24 锚点重定（Trace 实锤）

Trace 手法同 1.0.23：`STARRY_TRACE=1` 构建 → 启动 → 游戏把运行时明文写到

### 代码改造（`Games/Sc33Mod.cpp`）

- `BuildFightHook(const char* em, const char* neg)` —— 参数化 EntityManager 别名与 `(i<0)` 变量名；1.0.24 用 `em="h", neg="f"`，1.0.23 用 `em="f", neg="h"`。
- `TryInsert1023FightHooks` 用四变体锚点表（1.0.24 / 1.0.23 × 带/不带 `var p`）。
- `BuildBaseDmgHook(const char* tgt)`；锚点表 `{{"t = u.baseDmg;", "a"}, {"t = c.baseDmg;", "r"}}`。
- `NeedsCombatSplice()` 增加 `t = u.baseDmg`。
- `LogAnchorScanOnce` 的针表补入 1.0.24 全部锚点。
- `TryInsertAtkHook` / `TryInsertViewAtkHook` **未改**（锚点与语义 1.0.24 一致）。

## 8. 已知限制

- 免广告仅覆盖**激励视频** `SdkShowAdReward`，不含插屏/横幅。
- 攻速倍率在 `CalcFinalAtkSpeedValue` 的 `Math.min` cap 之后应用，极高滑条仍受游戏内上限影响。
- 本包**替换了游戏自带 `libc++_shared.so`**（NDK r27 版 1,794,776 B 覆盖官方 1,058,904 B），沿用 1.0.23 实证配方；`libcocos2djs.so` 不依赖它，暂未观察到副作用。
- 异签名无法覆盖时脚本需 `STARRY_ALLOW_UNINSTALL=1` 才卸载；本次因渠道 MD5 未变，走的是**同签覆盖**（`[install] cover ok`）。
