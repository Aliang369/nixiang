## 2. 引擎/保护实测（决定移植路线的四件事）

1. **代码段磁盘加密、装载期原地解密**：内存 r-xp `0x728ddc7000–0x729a91c000`（file off `0x670f000`）与磁盘同段前 3472 B 一致、之后大面积为密文差异（keystream 无周期、256 值均匀）⇒ **不能用磁盘件做静态反编译**，必须用内存映像。
2. **段表被搅乱**：磁盘件 `e_shnum=16` 但节名被换（`.text` 只有 0x10 字节、真代码在 `.note.gnu.text`/`.note.gnu.content`），`dynsym` 2575 条里 il2cpp 导出名全改随机短名 ⇒ Il2CppDumper 的 `SymbolSearch` 必失败。
3. **`global-metadata.dat` 同样被处理**：磁盘/APK 内件首 324 B 是易盾头（随机），第 324 B 起是 `c2baf26a`+`CODEPHIL` 标记 + 真 metadata（`af1bb1fa…`），且约 31%（9,270,648 B）字节被改；**运行内存在 `0x7393200144` 起是明文可用的 v31 metadata**（已 dump，见 §6）⇒ metadata 侧不再是障碍。
4. **加载基址 = `0x72876b8000`**（`maps` 段 + `p_vaddr/p_offset` 反推，两处独立核对一致）。所有内存地址→RVA 一律减它。

## 3. ★抓点总表：8 个 Dobby 桩（斌哥挂在 il2cpp 原生代码上的 patch 点）

**桩体结构（固定套路，复刻时按此判据读）**

```
ldrb w8, [壳data + flagOff]      ; 功能开关
cbz  w8,  <call_orig>
... 计数/日志（每个功能一个 4B 计数器，上限 7~15 条，防刷屏）
<改值>                            ; 百倍=×100.0f；无敌=0；免CD=w0=1；不耗蓝=w0=0
call_orig:  ldr xN,[壳data + origSlot]; br xN     ; 原函数指针槽：+0x780/+0x790/+0x7a0/+0x7b0/+0x7c8/+0x7d0
```

- 日志字符串是**逐字节 XOR 就地解码**的（形如 `ldrb w10,[x9]; mov w11,#0xa1; eor; strb`，7 字节一组 + 末尾补 0）。第一段（`0x72d9379000+0xd40/0xd50/0xd60/0xd70/0xd80/0xd90/0xda0`）解出来是功能名/中文提示，第二段（`0x72d930a000+0x59a/0x605/0x636/0x677/0x6b6/0x6f3`）是**明文格式串**（上表第 5 列就是从这里读出的）。
- 壳中文串还有免责/提示：`测试插件是免费测试 / 不盈利 / 只为手游技术安全防护测试 / 请问候他全家 / 如果菜单显示异常…请尝试重新安装 到大厅打开游戏`。

## 5. 免广告判定（用户附加条件）

**结论：本游戏确实有「看广告获得奖励」的位置，因此星空版需要新增「免广告」。斌哥包里没有这个功能（8 桩里没有任何广告相关桩）。**

| 方法/协程 | `CheckRewardVideoAvailable`、`PlayRewardVideo`、`WatchAd`、`GetDeviceAdvertisingId` |

⚠️ 风险（写进下一轮方案，不要当结论）：奖励领取链是 **`Ad_ClaimAdvertReward` 服务端校验**（有 `ServerData_`/`ServerCallbackData_` 两类数据类）。客户端侧"假回调 → 直发奖励"是否被服务端二次校验（如广告平台 S2S 回传）**未验证**；移植时必须先做「服务端权威 / 客户端权威」判定，再决定免广告实现层级（SDK 回调层 vs 领奖请求层）。

## 7. 未完成项（下一轮第一步，方法名）

**缺口**：8 个被挂函数的 **il2cpp 方法名/类名**（含命名空间）尚未取到。已排除的取法与本轮实测结论：

1. 直接把内存重建 so 喂 Il2CppDumper（`ForceVersion:31`，metadata 已解密）：
   - `Searching... → CodeRegistration : 0` → `SymbolSearch` 报 `No symbol is detected`（易盾改符号名，必失败）；
   - 手动模式可交互，但需要人工给出 CodeRegistration / MetadataRegistration 的地址。
2. 全内存（所有 ≥1 MB 可读区间）多模式搜 8 个目标地址：**0 命中** ⇒ 这 8 个入口不是经 `MethodInfo.methodPointer` 引用的（无指针引用，纯 BL 直调，或 MethodInfo 已被壳改写）。
3. `data_mem.bin` 里 in-range 指针只有 1345 个 ⇒ 易盾对 `data` 段做了"按需解密"，未访问页仍是密文；但 **`bss1.bin`（VA `0x13267000`）里有 509,469／189,972／134,251 … 这样的大指针表**，是最像 `methodPointers`/`codeGenModules` 的地方，尚未逐项比对。

**下一轮推荐路线（按成本排序，先 1 后 2）**

1. **用 bss1 的大指针表反查**：`methodPointers` 数组与 metadata 方法序一一对应（Il2CppDumper `GetMethodPointer` 在 v31 用 `codeGenModuleMethodPointers[image][token&0xFFFFFF-1]`），先确认哪个表是 `codeGenModules`（264 images/225 assemblies 长度的指针数组，元素指向 `{moduleName, methodPointerCount, methodPointers}`），再据此把 8 个 RVA 翻成 `Type::Method`。
2. **官方原版到手后做内存三态/两包对照**：官方包装机 → 同样 dump → 与斌哥包内存代码段做**页级 diff**（两边同版本时差异应只有 8 处 12 字节跳桩）⇒ 反过来证明「斌哥未改 so 字节」，并给出这 8 个函数的原始序言（`anon_rwx_1.bin` 的 Dobby 蹦床里也存着原序言，可交叉验证）。
3. 兜底：按 §3 的签名/语义（float 单参、w0 返回 bool、`w1,w2,w3,x4` 参数形态）在 `LC2.Core`/`Assembly-CSharp` 的 AOT 方法里按「调用点 + 参数形态 + 触发时机」人工锁定（慢，但不需要 CodeRegistration）。
4. 顺带复核：`War`/`Battle` 是否 Netcode 多人（`Unity.Netcode.Runtime`、`SmoothSync.Netcode` 在册）⇒ 伤害若有服务端权威，百倍伤害只在房主/单机成立（先例：独奏骑士、境界守望者）。

## 8. 移植（星空版）时的已知坑

1. **别改 `application@name`**：乐变 `LBApplication` + 易盾壳，换掉就起不来。
2. **保持壳**（`libSDKloading.so` 等斌哥件不进星空包；星空包只用官方原版为底）。
3. 8 个挂点全是 **Dobby 运行时 patch**；星空版走 `HookByName` 时需要方法名，且**不得与斌哥桩叠加**（双 Dobby 叠同一函数必崩，先例：`binge-memdiff.md` §六.3）。
4. ACTk 在册 ⇒ 改血量/伤害类数值要留意 `ObscuredTypes` 与 `Genuine.CodeHash` 反作弊上报（失落城堡 1 的「档案数据存在异常」弹窗即此类）。
5. 菜单功能位铁律：`featNum == featureList 下标`（挪位必须同步 enum 位号）。
6. 用户点名功能只有三项（百倍伤害/无敌/无限技能）+「有广告位才加免广告」；**本游戏已确认有广告位 ⇒ 免广告要做**，但不要顺手加其它（营地社区入口/Q群按钮这类斌哥"常驻"项不搬）。
