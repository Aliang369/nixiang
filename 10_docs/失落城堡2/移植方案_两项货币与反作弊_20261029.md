## 2. 两项货币的抓点（已定位到类与方法，来自解密 metadata 的类型/方法表）

货币语义确认（本地化 `UI_UniformType_SimplifiedChinese.json` / `UI_GamePanel.json`）：

| 用户说法 | 游戏内字段/前缀 | 本地化原文 |
|---|---|---|
| **魔铁锭** | `Iron` / `IronPowder`（`UI_Text_Iron`） | `Iron_IconText → 魔铁锭`、`_warning_ironPowder_notEnough → 魔铁锭不足`、`_toIronPower → 转化为魔铁锭` |
| **魂晶** | `Crystal` / `CrystalCommon`（`UI_Text_SoulCrystal`） | `Crystal_Text → 魂晶`、`_warning_crystal_notEnough → 魂晶不足` |

### 2.1 主目标：`LC2.BagSystem`（对局内背包/资源容器，236 个方法）

与失落城堡 1 的 `Tera_OB.BagSystem` 同构，货币成对出现「getter + Check + Force/Change + Save」：

| 类别 | 方法（逐字） |
|---|---|
| 魂晶 | `get_Crystal`、`CheckCrystal`、`DisassembleGetCrystal` |
| 魔铁锭 | `get_IronPowder`、`CheckIronPowder`、`CompareEnoughIronPower`、`DisassembleGetIronPowder`、`GetFurnaceIronCost`（炉子消耗）、`UpdateCostIronPower` |
| 同类参照（金币/魂花，说明套路一致） | `get_Coin`、`CheckCoin`、`ForceChangeCoin`、`ChangeCoin`、`ForceSetCoin_LocMul`；`SoulFlower`、`ForceChangeSoulFlower`、`ChangeSoulFlower` |
| 网络同步（重点） | `SetNetValue_Internal_Rpc`、`ChangeValueItem_Internal_Rpc`、`ApplyNetValue`、`PickUp_OnlyServer(_Rpc)`、`ShareResource_Rpc`、`PrepareResourceShare_ServerRpc`、`ServerControlsResourceShares`、`ReconcileResourceShares` |
| 反作弊相关 | **`RandomizeAntiCheatCryptoKeys`**、`RandomizeLocalResourceCryptoKeys`、`RandomizeNetResourceCryptoKeys`、`RandomizeObscuredItemValue` |

**推荐实现（方案 A，读取侧 pin，不写内存）**
- `BagSystem::get_Crystal` → 夹紧成固定值（如 999），`CheckCrystal` → 恒 `true`
- `BagSystem::get_IronPowder` → 同上，`CheckIronPowder` / `CompareEnoughIronPower` → 恒 `true`
- 理由：值在字段里是 **ACTk `ObscuredInt`**（见 §3.1 与 `Randomize*CryptoKeys`），**直接写字段会被 `ObscuredCheatingDetector` 抓到**；只改 getter 返回值不触碰混淆存储，也不进 `SetNetValue_Internal_Rpc`，网络侧看到的是原始值 ⇒ 对端/服务端校验不矛盾（风险见 §4）。

### 2.2 意外发现：客户端里带着**完整 GM 工具类** `LC2.GMToolsForMobile`（37 方法）

`Show` / `Hide` / `Init` / `CampEnter` 之外，功能列表逐字如下：

```
ChangeCrystal  ChangeCoin  ChangeIron  ChangeBlackStone  ChangeAtk
GodMode  NoDamageMode  KillAllMonster  Revive  OpenDoor  ResetPos
DropItem  DropAllItem  DropItemByID  DropAllAlchemy  DropAlchemy
LoadMap  LoadMapInit  GenerateOnePartner  GenerateRandomPartner
SetHeroBeAtkBoxesEnabled  InitList  AddChildObject  GetItemLevelColCount …
```

这条线索价值很高（也是风险最高的）：
- **`GodMode` / `NoDamageMode`** 就是官方自带的「无敌」；**`ChangeAtk`** 像「攻击力调整」（百倍伤害的另一条路）；`ChangeIron` / `ChangeCrystal` 直接给魔铁锭/魂晶。
- 走游戏自身代码路径 ⇒ **不碰 Obscured 存储、不走 Dobby 改内核指令**，理论上最"合规"、最不容易被 ACTk 抓。
- 但：①是否只在开发/内网包生效（`Show` 有无开关/白名单）**未验证**；②GM 调用是否会被服务端识别为异常来源（如 GM 专用 RPC / 房间校验）**未验证**；③一旦被识别，封号风险比读侧 pin 更高。
- 处置：**先做只读探测**（下一轮：hook `GMToolsForMobile.Init`/`Show` 看是否被调用、`ChangeCrystal` 是否走 ServerRpc），再决定是否采用。

### 2.3 抓点候选清单（实现顺序）

1. `LC2.BagSystem::get_Crystal` / `get_IronPowder`（显示与消费判定都读它）
2. `LC2.BagSystem::CheckCrystal` / `CheckIronPowder` / `CompareEnoughIronPower`（够不够的判定）
3. `LC2.CrystalMine::GrantCrystalWithoutVisual` / `ChangeCrystalNum_Rpc`（魂晶矿脉发放，仅作对照）
4. （备选）`LC2.GMToolsForMobile::{ChangeIron,ChangeCrystal}`

> 命名空间：本作游戏代码在 **`LC2.*`**（对应 `LC2.Core.dll`/`Assembly-CSharp`），不再是失落城堡 1 的 `Teran.*`/`Tera_OB.*`。

## 3. 反作弊/封号面全景（metadata 实测名单）

### 3.1 ACTk（Anti-Cheat Toolkit）全套在册

- 命名空间：`CodeStage.AntiCheat.{Detectors, ObscuredTypes, Storage, Time, Genuine.CodeHash, Common, Utils}`
- 检测器：**`ObscuredCheatingDetector`**、**`InjectionDetector`**、**`SpeedHackDetector`**、**`TimeCheatingDetector`**、`WallHackDetector`
- 事件/回调：`OnCheaterDetectedFor{Obscured,Injection,Speed,Time}`、`InvokeCheatingDetectedEvent`、`StartCheatCheck`/`StopCheatCheck`/`ReStarCheatCheck`、`CheatDetectorType`、`AntiCheatCoreValueTypes`、`AntiCheatListener`、`realCheatThreshold`、`AutoQuitApplicationAfterReport`、`SavesTampered`、`foreignSavesReported`
- 值保护：`RandomizeAntiCheatCryptoKeys`（BagSystem 内）、`ObscuredInt/Bool/…` 全家族、`CodeStage.AntiCheat.Genuine.CodeHash`（**代码哈希**）

### 3.2 结算/数据校验（最需要小心的一层）

- `SettlementDataMgr`、`CollectSettlementData`、`SyncSettlementData{,_Server,_Server_Rpc,_Server_ClientResult}`、`SyncSettlementDataCoroutine`
- **`LocalVerifyData` / `PeerVerifyData` / `VerifyResult` / `ValidateDataIntegrity` / `CalculateVerifyData` / `AuthBox`**（`_runtimeCacheAtkBoxDataDamageRate`）⇒ 结算数据存在**本地↔对端/服务端双向比对**
- 房内校验：`ReportCurrentRoomValidation(_Rpc)`、`ReportNetworkDefenseDamageProtection(_ServerRpc)`、`ReportNetworkInjuryProtectionWindow_ServerRpc`
- 服务端权威资源：`ServerControlsResourceShares`、`PickUp_OnlyServer`、`PrepareResourceShare_ServerRpc`、`PrepareServerControlledResourceShare`

### 3.3 时间/速度

`TimeCheatingDetector`、`IsTicksCheated`、`ForceTimeCheatingDetectorCheck`、`SpeedHackProofTime`、`SpeedHackDetector` ⇒ **改 `Time.timeScale`/系统时间/tick 会被抓**

### 3.4 上报链（用户要求"上报正常"，即这条链一律不动）

`CrashSight`（`ReportToCrashSight`/`ReportJank`/`ReportStuck`/`ReportException`）、数数（`ShushuReport`/`ServerShuReportHttpUrl`/`HttpsPostJsonForShuShuReport`）、雷霆侧 `LTVerifyError`、`AutoQuitApplicationAfterReport`、`LC2LogMonitorReportBy{Login,Register,CreateRole}`、易盾（`libNetHTProtect`/`libnesec`/`libthemis` 在包内，运行时心跳）

## 4. 「数据合规 / 时间合规 / 结算合规 / 上报正常 / 屏蔽检测」的落地方案

原则：**只改"读"，不改"写"；只改客户端行为，不改上报内容；宁可少给效果，不做会自相矛盾的数值。**

| 维度 | 做法（建议） | 明确禁止 | 依据 |
|---|---|---|---|
| **数据合规** | ①货币/资源用**getter pin**（返回夹紧值，如 999，不写回字段）；②伤害倍率走"乘法后的返回值"而**不改角色属性面板**（属性面板会进结算/档案） | 直接写 `ObscuredInt` 字段；改 `MaxWeight`/`CurWeight`/装备数值；改存档 | ACTk `ObscuredCheatingDetector` 检的是混淆值被写；`SaveCoinToGameSaveData` 等会把值写进档案 |
| **时间合规** | 完全不动时间相关（`timeScale`、`Time.realtimeSinceStartup`、系统时间、`ticks`） | 加速/减速 Hook、改系统时间 | `SpeedHackDetector` + `TimeCheatingDetector` + `IsTicksCheated` |
| **结算合规** | ①倍率与货币夹紧到"结算能自圆其说"的量级（例如伤害倍率默认 10 而非 100，魂晶上限 ≤ 单局自然产出上限的若干倍）；②**不动结算上报字段**（`SettlementDataMgr`/`SyncSettlementData*` 一律放行）；③不修改房间校验 RPC | 伪造结算数据、屏蔽/篡改 `ReportCurrentRoomValidation` | `LocalVerifyData`/`PeerVerifyData` 双向比对；`ServerControlsResourceShares` |
| **上报正常** | 保留 CrashSight/数数/雷霆/易盾上报原样通过（**不 block、不替换返回值、不摘 so**） | 拦 `Report*`/`ShushuReport`/`ReportToCrashSight`；删 `libNetHTProtect.so` | 用户本轮明确要求"上报是正常的" |
| **屏蔽检测** | 只压制**客户端判定**：①`ObscuredCheatingDetector` 的探针触发路径（`OnObscuredTypeCheatingDetected`/`TryDetectCheating`/`InvokeCheatingDetectedEvent` 返回"未检测"）；②`CheatDetected`/`IsCheatDetected` 置 false；③`StartCheatCheck` 不启或 `realCheatThreshold` 不达 | 关掉整个 ACTk 组件/删 DLL（会触发 `Genuine.CodeHash` 差异与 `InjectionDetector`） | 检测器在册清单见 §3.1；`AutoQuitApplicationAfterReport` 说明"被抓=直接杀进程+上报" |

### 风险分级（先说清，再开工）

| 功能 | 风险 | 原因 |
|---|---|---|
| 魔铁锭/魂晶 getter pin（不写字段、不进 RPC） | 中低 | 只影响本地显示与本地消费判定；但**在多人房里**若消费了服务端不认的货币，可能被 `ReportCurrentRoomValidation` 抓到 ⇒ 建议只在本机单人/单机房间使用，或与"服务端资源分享"隔离 |
| 百倍伤害 | **中高** | 结算里伤害会进 `SettlementData`，与 `_runtimeCacheAtkBoxDataDamageRate` 校验相冲突的概率大 ⇒ 建议默认 10 倍、可调，多人房提示风险 |
| 无敌 | 中 | 若只改"受击判定"，结算的 `takeDamage` 会异常（0 伤害）——正常玩家也可能 0 伤害，风险可接受 |
| 无限技能（免CD/不耗蓝） | 中低 | 属本地逻辑，与结算统计弱相关 |
| 免广告 | **高** | 奖励领取是 `Ad_ClaimAdvertReward` 服务端校验 + 广告平台可能有 S2S 回传 ⇒ 可能直接被判异常 |
| GM 工具（`GMToolsForMobile`） | **高** | 走 GM 通道，服务端可能直接识别（且来源可疑） |

**结论（写进方案，不当结论用）**：本作不是纯客户端权威；能不能"不被封"取决于服务端到底校验到哪一步。**必须先做只读探测**（下一轮）：hook `SettlementDataMgr`/`ValidateDataIntegrity`/`ReportCurrentRoomValidation` 打印字段，确认服务端到底比对什么，再决定数值上限与实现层级。在这之前**不建议**把倍率开满、不建议碰免广告领奖链。
