## 2. 为什么「+4 处序言」当指纹（而不是首指令）

- 斌哥已用 Dobby 把每个目标的**首指令**改成 `br x17`（`0xD61F0220`），所以**官方首指令拿不到**；
- +4 起的序言指令仍在原位，且跨进程/跨加载基址**编码不变**（含 `adrp` 也是 PC 相对）⇒ 可作指纹；
- 反证式自检：装钩前若发现首指令**就是** `br x17` ⇒ 说明还有别的 Dobby 在挂（双挂必 SIGSEGV）⇒ **拒绝安装**并打 WARN。见 `HookAtRvaFP()`。

## 3. 已确认偏离（与斌哥做法不同，逐条写理由）

| 项 | 斌哥做法 | 我们的做法 | 理由 |
|---|---|---|---|
| 伤害倍率 | 桩内直接返 `输入 × 100.0f`，**不调 orig** | **调 orig 再乘倍率** | ①我们要 1..100 可调（滑块）；②不调 orig 会绕过原函数的其它结算（减伤、暴击、抗性），数值容易与结算对不上（用户 B7「结算合规」）；③orig 路径出问题能立刻回滚成纯透传 |
| 货币 | 无此功能 | `getter` 读取侧 pin `999`，**不写 Obscured 字段、不进 RPC** | ACTk `ObscuredCheatingDetector` 只抓混淆字段被写；读写侧不影响网络侧真实值（`SetNetValue_Internal_Rpc` 照常发原值） |
| 免广告 | 无 | **不做**（用户 2026-10-29 16:38 指令「免广告不做了」） | — |

## 8. 重大实测：本作 Dobby trampoline 不可用 ⇒ 一律「不回跳 orig」+ 按功能拆钩

**现象**：17:09 与 17:21 两次崩溃，均为 `SIGSEGV / SEGV_ACCERR / "trying to execute non-executable memory"`，
pc 落在匿名非执行映射（`<anonymous:70de9f5000 + 0x1b575f0>`），且 17:21 那次是**全部功能关闭、滑块=1** 时打怪即崩。

**归因**：崩溃点不是我们的判断逻辑，而是「hook 命中后回跳 `g_orig*`（Dobby 生成的 trampoline）」这条路径。
本作（易盾 4.23 + HybridCLR + PAC/MTE 开启）上，Dobby 为这些函数生成的 trampoline 位于不可执行匿名页
⇒ 只要走到 orig 就跳进数据区。斌哥的桩**从不回跳**（桩内直接返回计算值），这与其可正常游戏的事实一致。

**定案（已落地）**：
1. **hook 体内绝不调用 `g_orig*`**：伤害 `return in*mult`、无敌 `return 0.0f`、免CD `return true`、不耗蓝 `return 0`；关闭态用常量兜底（不回跳）。
2. **按功能装/拆钩**（`SyncHooks` 收敛式）：功能开＝挂该功能自己的槽，功能关＝`DobbyDestroy` 还原原始指令。
   ⇒ 全关时 `hook 状态: want=0 have=0/6`（实测日志），与官方包零差异，不可能再因我们的钩子闪退。
3. `kSlots` 增加 `feat` 字段；`g_slotTarget[]` 记录被挂地址供 `DobbyDestroy`。

**代价（已知并接受）**：伤害函数内部其它结算（减伤/暴击/抗性）不参与 —— 与斌哥版行为一致；若后续需要「先算后乘」，
必须换不依赖 trampoline 的方案（例如在同一函数内偏移处二次挂钩，或改用 斌哥 的桩位结构）。


## 9. 两个真凶（2026-10-29 17:35 定位）

### ① 滑块状态被判成「关」⇒ 装了又拆的抖动（"伤害倍率没效果"的真因）
`Slcb2_Tick` 首版直接 `g_dmg.store(features[FEAT_DMG])`，但**菜单对 Slider 项 `features[]` 恒为 false**（开关语义在 `values[]`）。
于是每 200ms：Tick 置 false → 拆钩；`OnValueChanged` 置 true → 再装钩。实测日志：
```
DmgMul hooked @rva 0x110829A0 → hook 状态: want=2 have=2/6
slot[0] DmgMul 已拆钩（功能关闭）→ want=1 have=1/6
伤害倍率 = x100 → DmgMul hooked … → 又拆 …
```
战斗里大部分时间钩子处于「已拆」⇒ 表现为没效果。
**已修**：滑块判据只用 `values[]`（`g_mult>1` 即开），Tick 不再覆盖 `g_dmg`。

### ② 部分 RVA 是 **PLT 式跳板**，直接 hook 会打断所有走该跳板的调用（"无敌闪退"的真因）
活体进程实测（`/proc/<pid>/mem` 直读，绕过 Bin-ge 已改写的首指令）：

| RVA | 首指令 | 形态 |
|---|---|---|
| `0x110829a0` DmgMul | `stp x30,x25,[sp,#0x40]` | 真实函数（返回＝其内部 `bl 0x110648bc` 的返回值；函数体是「算+应用」复合体） |
| `0x110649cc` Inv | `adrp x17,#0x739c323000; add x17,#0x8f0; br x17` | **跳板** → 真实函数在 `0x739c3238f0`（易盾私有映射） |
| `0x10ce8c24` CD | `stp x20,x19,[sp,#0x20]` | 真实函数（`cset w0,ge` 返 bool） |
| `0x118dd824` MP | `stp x22,x21,[sp,#0x10]` | 真实函数（`csel w0` 返 int32） |

**已修**：`HookAtRvaFP` 增加跳板解析（识别 `adrp x17 + add x17 + br x17` 三元组，按 immhi/immlo 与 imm12 算出真实目标再挂），日志会打 `是跳板 → 真实目标 0x…`。

### 方法要点（下一轮直接复用）
- 想拿「未被斌哥改写」的原始首指令：`/proc/<pid>/mem` 直读本进程（加载基址每次启动都变，必须先解析 maps 里 `r-xp <文件偏移>` 那条算 base）。
- 斌哥桩对跳板类目标会覆盖 **12 字节**（3 条指令），所以从斌哥包内存 dump 里取的「+4 序言指纹」对这类目标是错的，必须从活体/官方进程重新取。


## 10. 伤害挂点的最终形态（2026-10-29 17:50，三层教训全记录）

### 教训链（三次崩溃各对应一层错）
| 版本 | 做法 | 结果 | 根因 |
|---|---|---|---|
| v1 | hook 内 `return orig(...)*mult` | SIGSEGV **ACCERR / 执行不可执行内存**，pc 在匿名页 | Dobby 的 orig trampoline 落在**不可执行匿名页**（Android 14 起 app 域禁止可执行匿名内存） |
| v2 | 不调 orig，`return in*mult` | 打怪即崩（SEGV_MAPERR 0x2395 / 又一处 ACCERR 于 r--p 段） | 该函数是「算+应用」复合体，跳过它⇒下游读到空指针；且我们声明的返回类型与真实返回寄存器不符（链尾 `ldr x0,[x8]; b …` 说明返回的是 **x0**，不是 s0） |
| v3 | **自建代码空洞跳板 + 裸汇编 thunk** | 本版待验 | 见下 |

### v3 做法（本版实现）
1. **不使用 Dobby**：入口改写成 16B 绝对跳转 `ldr x17,#8; br x17; .quad hook`，原始 16B 自己保存，卸载时原样写回（`WriteCode` 做 mprotect RW→写→RX + clear_cache）。
2. **跳板放进 libil2cpp 自己的 r-xp 文件映射**：`FindCodeCave()` 在该映射里找 32B 全 0 空洞，写入「原始 16B + 跳回 `入口+16`」，天然可执行，绕开匿名可执行内存限制。日志标记 `+cave`。
3. **裸汇编 thunk（`Slcb2DmgThunk`）**：只把入参 `s0`（伤害值）按倍率改写，**保存/还原 x0–x7、x8(sret) 与 q0–q7 全部寄存器**，然后**尾跳**跳板回原函数 ⇒ 原函数的返回值一个寄存器都不动，彻底避开设错返回类型的坑。
4. 倍率判定在 `Slcb2_ScaleDmg()` 里（开/关、NaN、±1e9 夹紧、前 5 次打日志）。

### 仍未验证
- 本版是否还有「补丁被反作弊发现」的问题（v2 的第二次 ACCERR 也可能是易盾校验代码段后自杀；v3 的 ACCERR 已用 thunk 解释，但仍需实测确认）。

## 11. 定案：为什么"跳进自己的 so"必崩，以及现行做法（2026-10-29 20:40）

### 对照实验（决定性）
| 形态 | 结果 |
|---|---|
| 0 hook 进对局 | 正常跑（85s+，无异常） |
| 纯图片内跳板：入口 `b cave`，cave=原4指令+跳回 `entry+0x10`，**全程不进 libstarry** | **不崩**（20:32 实测，用户确认） |
| 任何"入口→cave→**跳到 libstarry_magic.so 里的 thunk/C 函数**→再回来" | 钩子命中后 **~386–394ms 必崩**（三次不同实现延迟一致） |

⇒ 真凶＝**进入我们自己的 so 这一步**（Android 16 + 易盾环境下模块边界/分支保护/信号处理），
与 RVA、ABI、反作弊检测、寄存器保存都无关。延迟恒定 390ms 就是证据：崩的不是钩子执行那一刻。

### 现行做法（已验证有效）
功能一律做成**图片内自足 stub**：入口 4B 原子 `b` → libil2cpp 自己 r-xp 页里的 64B 空洞，
空洞内自带指令 + 原 4 条序言 + 跳回 `entry+0x10`。**零外部调用、零外部数据**。

| 功能 | stub 形态 | 状态 |
|---|---|---|
| 无敌（0x110649cc） | `ldr s1,[pc,#48]; fmul s0,s0,s1`(s1=0.0f) + 原4指令 + 跳回 | ✅ **用户实测有效**（20:38） |
| 伤害倍率（0x110829a0） | 同上，字面量＝滑块值（改滑块时由 Java 回调写回 cave+48） | 待实测 |
| 免CD（0x10ce8c24） | `mov w0,#1; ret`（函数体不执行） | 待实测 |
| 不耗蓝（0x118dd824） | `mov w0,#0; ret` | 待实测 |

### 附带修掉的两个真 bug（都曾造成崩溃）
1. 汇编 thunk 保存 q0–q7 用 0x10 步进（`stp q` 占 32B）⇒ 两两重叠 ⇒ q1/q3/q5/q7 还原成垃圾 ⇒ 抛 `Il2CppExceptionWrapper`。跨 0x20 步进、帧 0xD0。
2. 金标序言 adrp 判定掩码把 Rd(bit4-0) 也掩进去 ⇒ adrp 永远判不成 PC 相对；且 Inv 第二字手抄错（正确 `0x6D1123E9`）。

### 取证通道的坑
- `frida-server` 一起来，易盾把游戏和 frida-server 一起杀（对照：关掉即正常）⇒ 活体取证走 root `/proc/pid/mem` 直读。
- 自装的 SIGSEGV 兜底 handler 会挡住 debuggerd/墓碑 ⇒ 致命信号必须先把 `sig/addr/pc/lr/sp` 打进 logcat 再交回系统。

## 12. 三项战斗功能已实测通过（2026-10-29 21:36）

| 功能 | 实现形态 | 证据 |
|---|---|---|
| 无敌 | `0x110649cc` 图片内 stub：`s0×0.0f` + 原4指令 + 跳回 `entry+0x10` | 用户实测「无敌有效果」；三项同开再测仍正常 |
| 伤害倍率 | `0x110829a0` 同形态，字面量=滑块值（改滑块时写回 `cave+48`） | 用户实测「伤害变 10 倍」 |
| 无限技能 | **结果指令补丁**：`0x10ce8c80 cset w0,ge → mov w0,#1`；`0x118dd904 csel w0,w8,w9,eq → mov w0,wzr` | 用户实测「无限技能没问题了有效果」 |

**关键教训**：`免CD/不耗蓝` 最初做成「跳过整个函数体返回常量」，进局 43s 崩；改成「函数体照跑、只换末尾结果指令」后正常。
⇒ **带副作用的函数禁止整段跳过**；能改入参就别改体，能改结果指令就别跳体。

## 13. 两项货币：当前卡点（未实现）

已排除的三条路（都有实测/扫描证据）：
1. **按名取方法指针**：`il2cpp_class_from_name` 等 API 被易盾摘掉，不可用。
2. **metadata magic 定位**：进程内**扫不到** `0xAF1BB1FA`（metadata 被加密），但**四个方法名字符串是明文**，
   可在活体里找到（示例 21:34 那轮：`get_Crystal=0x7260b9b955` / `get_IronPowder=0x7260b9b96e` /
   `CheckCrystal=…61` / `CheckIronPowder=…84`，同段 `seg1314`）。
3. **MethodInfo 反查**：以这四个字符串 VA 为值，全可读段（8.4GB，含 1GB malloc 区）**零命中** ⇒
   没有任何结构体指针指向这些字符串（易盾把名字表隔离/重定位了）。
4. **methodPointers 数组反查**：用 4 个已实测函数地址（`base+0x110829a0` 等）当锚，全可读段扫描
