## 2. 四个战斗挂点为什么落在「入口 +8」

`ChangeCurrentHp` 系列与 `get_PowerCoolDownFinish` 的方法入口前两条指令是「开栈 + 存寄存器」（`sub sp,sp,#0x80` / `str d8,[sp,#0x30]`），挂点在入口 +8 处，即这两条已执行、尚未触碰浮点入参的位置：

- 全部调用点都是 `bl` 到**方法入口**，无一处直接跳到 +8（已扫 213 MB 代码区：免CD 341、不耗蓝 5、魔铁锭 44、魂晶 401，+8 命中数为 0）⇒ 「前两条已执行」在调用路径上成立；
- cave 回放挂点起 4 条序言后跳 `hook+0x10`，栈帧与寄存器现场完整闭合；
- 伤害/无敌的 4 条序言全是 `stp`，**不含 `adrp`**，搬到 cave 不会算错页（`adrp` 是页相对，禁止跨位置搬家）。

## 3. 技能的「CD」是次数 + 回复，不是时间轴

技能可用性由 `CDLogic` 维护的三个量决定：`CurUseNum`（可用次数）、`MaxUseNum`（上限）、`mCurCDValue`（恢复进度）。判定链：

```asm
Skill_Logic::IsCDOK  0x118e1c34  bl  CDLogic::get_CurUseNum
                     0x118e1c38  cmp w0,#0
                     0x118e1c3c  b.le ...        ; <=0 ⇒ 不可用
                     0x118e1c44  mov w0,#1       ; >0 ⇒ 可放

CDLogic::UIFunc_GetCD_Time  0x118dc8b8  bl get_CurUseNum
                            0x118dc8bc  cbz w0, ...   ; 只有次数=0 才算剩余时间
                            0x118dc8c0  mov w8,wzr    ; 有次数 ⇒ CD 时间返 0（图标不转圈）
```

⇒ 把 `get_CurUseNum` 读侧 pin 成 99，`IsCDOK` 与 UI 冷却显示同时成立；写侧 `SpendUseNum` 照常扣真实字段。
`PowerBase::get_PowerCurCoolDown` / `get_PowerCoolDownFinish` 属「显示与派生计算」层，**不参与可用性判定**，改它们不影响技能能否释放。

## 4. ABI 与返回约定（内存镜像反汇编实测）

| 挂点 | 尾部证据 | 结论 |
|---|---|---|
| `0x110829A0` 伤害 | 主出口仅 `ldp/add sp/ret`，无写 s0/w0；`s0` 在 `0x110829B0 fmov s8,s0` 才被搬走 | void 入参型，改 `s0` 必须在 hook 点（早于 `fmov`） |
| `0x110649CC` 无敌 | 同上；`0x11064A4C fcmp s8,#0.0` + `b.eq` 有 0 伤早退分支 | 乘 0 后走早退分支，整段跳过受击结算 |
| `0x118DD904` 不耗蓝 | `0x118dd8e8 fcvtps w9,s8` 证 float→int32；改点之后仅 `ldr d8`+`ret`，无指令再读 w0/w8/w9 | 改 `mov w0,wzr` 无副作用 |
| `0x118DA974` 次数 | `cmp w0,#0` / `cbz w0` 证明返回 w0 为 int32 | `mov w0,#99; ret` 不破坏栈（prologue 未执行） |
| `0x114D97D0` / `0x114CA960` | 尾部 `mov w1,#7` / `mov w1,#4` + `b GetValue_Internal`；TypeIndex 与 `get_Coin` 同值 | System.Int32，入口 stub 安全 |

## 5. 登录链路：deviceSalt

游戏自有接口 `POST https://shilcbbgamerelease.leiting.com/lc2-server/login` 会校验上报体里的 `deviceSalt`；该值为空串时返回：

```
{"code":201,"msg":"登录失败，设备验证信息异常。请重启游戏并更新至最新版本后重试。"}
```

`deviceSalt` 由 `LC2.StringCryptUtil::GetOrCreatePersistentSaltForServer`（RVA `0x10bc88c4`，配套 `GetOrCreatePersistentSalt` `0x10bc7d20`）从外部存储读取/生成：

```
/sdcard/Android/data/com.leiting.slcb2/files/lc2Salt_<hash>.enc     （密文，与生成时的环境绑定）
```

**卸载重装 / uid 变化后必须删掉该文件再登录**：旧密文在新环境解不开，方法走失败分支交空串，表现为上述 201。删除后游戏重建（本次重建为 64 B），接口返回 `{"code":200,"msg":"操作成功"}`。

## 8. 边界与风险

1. 技能次数 pin 在**读侧**：`SpendUseNum` 仍扣真实字段，重连/结算上报的是真实值；UI 可能显示 `99/上限`。
2. `get_CurUseNum` 入口 stub 跳过函数体的类初始化检查；该函数首次调用必然早于战斗（技能栏构建时即调用），实测无异常。
3. 货币两项只 pin 读侧，写侧仍走真实字段 ⇒ `CompareEnoughIronPower` 一类「先判后扣」处会出现「显示够、实际扣」的背离，属已知低风险。
4. 无敌走 `fcmp s8,#0.0` 的 `b.eq` 早退分支，跳过伤害数字与受击表现——这是期望效果，不是缺陷。
5. 版本漂移判据：6 个指纹任一不符即不装钩（`oldW` 校验），换版本必须重跑 §7 重建 RVA。
