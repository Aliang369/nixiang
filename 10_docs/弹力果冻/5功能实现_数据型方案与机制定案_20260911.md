## 0. 范围（用户定案）

只做 **5 项**：秒杀 / 全屏秒杀 / 无敌 / 无限技能 / 移速。**其它一切功能（货币/内购/广告/掉落…）全部不做**。
「全屏秒杀」语义经用户确认：**压血 1 + 清盾（一轮攻击清屏）**，不采用游戏 GM 那种 `1e8` 真实伤害（见 §5）。

## 1. 设计基线：为什么必须"零 hook、零 invoke"

旧 4399 版（`com.ginicat.sweet.m4399`）三个血功能闪退，复核结论指向同一类动作：

| 编号 | 反面动作 | 后果 |
|---|---|---|
| R-1 | **未 attach 的 mod 线程**调热更托管方法（`get_Stuff` / `FindBattleUnitByTeam`） | 解释器态不一致 → SIGSEGV |
| R-2 | 批量 `il2cpp_runtime_invoke(HpHandle)` + 栈上自造 `DamageHandle` | 生命周期/GC/线程无据 → 崩 |
| R-7 | 按地址 hook **共享** MethodPointer 入口（4399 的 `0xBAAB0C` 落在解释器主体 `[0xBA3CE8,0xBAB884)`） | 入口被多方复用 → 崩 |

本实现把三者**结构性**去掉：

* 单例：读静态字段 `BattleStuff<BattleEntityManager>._Stuff`；兜底用 `ScanInstances` 全堆扫（只读）。
* 单位枚举：读 `BattleEntityManager.battleUnits`（`List<BattleUnit>`），**不调** `FindBattleUnitByTeam`。
* 功能生效：**只做字段读写**，不调任何热更方法、不装任何 hook。

## 3. 四条机制定案（决定"怎么写才生效"）

### 3.1 属性是**双通道**（`hotfix.decompiled.cs:110929+`）

```csharp
private HeroAttribute heroAttribute;   // 只有玩家主角
private PetAttribute  petAttribute;    // 敌人/宠物/怪物
public HeroAttribute HeroAttr => attrType == BattleAttributeType.Hero ? heroAttribute : null;
public PetAttribute  PetAttr  => attrType == BattleAttributeType.Pet  ? petAttribute  : null;
enum BattleAttributeType { Hero, Weapon, Pet }
```
`BattleUnitAttribute.Hp/Shield` 访问器同样按 `attrType` 路由（`:111130` / `:111239`），且 setter 带 `Clamp`。
→ **只取 `heroAttribute` 时敌人全为 null**（首轮 `压血=0` 的真因）。
→ 本实现**直写底层字段**（绕过 setter 的 Clamp），并同时写 `FullShield` 以保证护盾语义成立。

### 3.2 死亡链**只在受伤回调**里（`HpHandle` 尾部 `:130338`）

```csharp
battleUnit.onDamEvent?.Invoke(handle);
if (battleUnit.unitAttr.isDead) {                      // isDead => Hp <= 0f
    battleUnit2?.onKillEvent?.Invoke(battleUnit);      // 击杀记账
    battleUnit.onDeadEvent?.Invoke();                  // BattleEnemyUnit.OnCreate 里 += OnDead
}
```
* **全库无血量轮询**：`Dead()` 仅 2 处调用（`BattleTreeUnit` 的限时自毁与受伤回调）；`BattleEnemyUnit.OnDam` 只播特效/记伤害，**不判死**。
* 因此 **外部写 `Hp=0` 不会死**；更糟的是 `HpHandle` 开头有 `if (unitAttr.isDead) return;` → 后续伤害被丢弃 → 敌人变**"打不到也死不了"的僵尸**（首轮"全屏秒杀无效"的真因）。
* **正解：压到 1 血**（`isDead` 仍假）→ 下一次伤害事件结算后 `isDead` 为真 → 真死亡链 + 击杀记账，且伤害数字保持正常量级。
* 佐证：游戏自带清场 GM **`BattleUtility.KillAllEnemy`**（`:132694`，`BattleCmds.Z`，别名 `z/whoisyourdaddy`）也是先 `item.unitAttr.Hp = 1f` 再 `atk=1e8 + isReal=true` 造一次 `CreateDamage` —— **连官方清场都必须借一次伤害事件**。

### 3.3 技能可用性由 `CanUseTimes` 决定（`Skill.skillState` `:264308`）

```csharp
public SkillState skillState {
    get { if (skillTimeCounter > 0f) return Running;
          if (CanUseTimes > 0)      return Usable;    // ← 可用判据
          return CD; }
}
public virtual bool CanUse() => !unit.buffDriver.HasBuffKind(BuffKind.Silent)
                              && skillState == SkillState.Usable;
```
`cdCounter` 只是回复进度（`OnUpdate` 里 `cdCounter < 0` 才 `AddCanUseTimes()`，且要求 `CanUseTimes != MaxCanUseTimes`）。
→ 无限技能必须写 **`CanUseTimes`**（并清零 `cdCounter` 让 UI 同步），且要**遍历 `SkillContainer._skills`** 点亮全部技能——只改 `curSkill` 不够：技能选择循环里 `CanUse()` 为假会被跳过，永远轮不到它成为 `curSkill`（`:115477`）。
→ 技能类指针自检**必须走继承链**：`Skill` 有几十个子类（`ActiveSkill`/`EasySkill`/`Skill_4010701`…），用"类相等"会把真实技能全判掉（首轮 `技能=0` 的真因）。

### 3.4 移速与护盾（字段路径已验证）

```csharp
// MovmentDriver.AiMovement(dt)（:115122，每帧）
((AIBase)aiPath).maxSpeed = unit.unitAttr.MoveSpeed * 5f + num;   aiPath.Simulate(dt);
// BaseMoveSpeed（:111166）
return (attrType == Hero ? (float)heroAttribute.MoveSpeed : (float)petAttribute.MoveSpeed) + baseAttribute;
// HpHandle 伤害结算：先扣 Shield，超出部分才扣 Hp
if ((float)handle.finalDamage > battleUnit.unitAttr.Shield) { Shield -= shield; Hp -= finalDamage - shield; }
else Shield -= handle.finalDamage;
```
→ 移速写 `HeroAttribute.MoveSpeed` 每帧被读走 ✔；无敌写 `Shield = FullShield = 1e9` 让伤害先被护盾吸收 ✔（实测 `锁血=0`：主角血量从未低于上限）。

## 3.5 【第三轮根因】标准战斗是"联机(代理)流"，本地属性字段根本不是真值

用户实测反馈：**只有无限技能有效果，其余四项无效果** —— 而日志证明四项的写入都落地了。两者不矛盾，根因是**属性真值分层**：

```
MovmentDriver.useAi 是静态开关：NetableBattleManager.CreateBattleAsync 置 false(:190031)、CloseAsync 置 true(:190180)
MovmentDriver.OnUpdate = useAi ? AiMovement(dt) : RigidMovement()   // 标准战斗走后者（:115095）

真值分层：
  A 本地属性  BattleUnitAttribute.heroAttribute/petAttribute（ObscuredFloat）
  B 远端缓存  BattleUnitAttribute.remoteAttributeCache : BattleAttributeCache（float）
              —— remoteAttributeCache != null 时，HeroAttr/PetAttr 会「用缓存重建属性对象」(:111929/:111958/:111985)
  C 代理缓存  BattleUnit.proxy(Proxy) → Proxy.cacheSystem → CacheSystem.cacheDic(Dictionary<Type,Cache>)
              → UnitHpCache（**long** Hp/FullHp/Shield/FullShield，默认 int.MaxValue 哨兵）
              —— Hp/Shield 访问器在 isNet 时直接返回它（:111130 / :111239）
              —— isNet => proxy != null && !proxy.isLocalOrProxyedProxy（:115698）
```

* 只写 **A** 时，代理流会用 B/C 覆盖或直接绕过 ⇒ 表现为"**写入计数增长，但游戏无感**"。
* `MoveSpeed` 访问器本身**没有** isNet 分支（读 `BaseMoveSpeed` → `heroAttribute.MoveSpeed`），但属性对象可能由 B 重建；且 `RigidMovement` 读的是 `unit.unitAttr.MoveSpeed`（属性）⇒ 同样需要写 B。
* **只有纯字段类功能天然生效**：`Skill.CanUseTimes` 不在任何缓存路径上 ⇒ 精确解释"只有无限技能有效果"。

**修法（第三轮）**：A/B/C **三通道同时写**，全部是普通字段写，仍保持零 hook / 零 invoke：

| 通道 | 敌血压血 | 全屏秒杀清盾 | 无敌护盾 | 移速 |
|---|---|---|---|---|
| A 本地属性 | `petAttribute.Hp=1` | `petAttribute.Shield=0` | `Shield=FullShield=1e9`、`Hp=FullHp` | `heroAttribute.MoveSpeed=want` |
| B 远端缓存(float) | `RACache.Hp=1` | `RACache.Shield=0` | `Shield=FullShield=1e9`、`Hp=FullHp` | `RACache.MoveSpeed=want` |
| C 代理缓存(long) | `HpCache.Hp=1` | `HpCache.Shield=0` | `Shield=FullShield=1e9`、`Hp=FullHp` | —（位置无缓存字段） |

**新增诊断**（决定性证据，进战斗首拍逐单位打印）：`通道[i] proxy=? 远端缓存hp=?/? 代理缓存hp=?/? shield=?` —— 直接看出哪条通道有真值。

## 5. 边界与检测面

* **联机不生效（有意）**：`unitAttr.Hp/Shield` 访问器对 `battleUnit.isNet` 走 `proxy.cacheSystem.TryGetCache<UnitHpCache>()` → 本版只改本地属性字段，**联机/世界Boss/排行场不生效**（也避免在联机里被同房玩家察觉——`DamageNumMsg` 会 `Broadcast`）。
* **不放大伤害**：全程不写 `atk`、不伪造 `DamageInfo`，伤害数字与 `TotalDamageCounter`（`:132705`，累加进 `totalDamage` 并作为 `ToTleDamager` 随 `C2S_NormalBattleEnd` 上报 🔴）保持正常量级。这正是**不采用 GM 式 1e8 真实伤害**的原因：那样 `maxDamage/totalDamage` 会出现 1e8，最易被后台识别。
* **日志**：取证日志每 25 拍（5 s）一条 + 进战斗首拍逐单位自检；无逐帧打印。
