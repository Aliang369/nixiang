# 弹力果冻 TapTap 2.4.0 —— 秒杀/全屏秒杀/无敌/移速 的架构边界与检测结论

- 日期：2026-09-12
- 目标：`com.ginicat.sweet`（TapTap 渠道，2.4.0 / versionCode 4409，arm64-v8a，Unity 2020.3.22f1c1 IL2CPP + HybridCLR）
- 交付范围：仅 `秒杀 / 全屏秒杀 / 无敌 / 无限技能 / 移速` 五项（用户划定，不含货币/IAP/广告）
- 设备：真机 `f9a116a2`（KernelSU root）；此前为 MuMu `127.0.0.1:16384`（已关闭，其日志随模拟器丢失）

## 0. 一句话结论

**只有「无限技能」可以做出来并已确认有效；「秒杀 / 全屏秒杀 / 无敌 / 移速」在本游戏架构下：纯改字段落地但不生效，改调游戏自己的伤害管线（invoke）会被反作弊当场拦截。**
即：这四项不是"还没找对方法"，而是被"权威模拟 + 在线反作弊"两条硬约束同时挡住。

## 1. 已证实事实（均有日志或字节级依据，标注证据来源）

| # | 事实 | 证据 |
|---|---|---|
| 1 | 字段偏移解析全部正确 | `HeroAttribute`/`PetAttribute` 声明序推导与运行时按名解析逐字段吻合：`PetAttribute: Attack@0x18 Defense@0x30 MoveSpeed@0x48 Hp@0x60 FullHp@0x78 AttackSpeed@0x90 ShieldRecover@0xA8 FullShield@0xC0 Shield@0xD8`；`HeroAttribute: FullHp@0x18 Hp@0x30 Defense@0x48 MoveSpeed@0x60 Shield@0x78 FullShield@0x90`（ObscuredFloat 步长 24 字节） |
| 2 | 我们迭代的单位对象**就是战场对象** | ① 游戏自己的清场 GM `BattleUtility.KillAllEnemy()`(:132694) 与 `BattleServer.CreateDamage()`(:130119) 都用 `BattleStuff<BattleEntityManager>.Stuff.FindEntityByID / FindBattleUnitByTeam` —— 与我们同一集合；② 每个单位的 `MovmentDriver` 非空且 `driver.unit == unit` |
| 3 | 写入确实落在这些对象上 | 回读监视：`我方0 本地(hp=312.2/312.2 shield=1000000000.0 spd=20.00)`、`敌方0 本地(hp=1.0/270.0)` —— 我们写的值可读回 |
| 4 | **但 `unitAttr` 是模拟器的输出、不是输入** | 判定版日志（写入前原值）：`敌[eid=53] 原值 hp=810.0 → 压血1`、`hp=738.0`、`hp=554.0`；即我们写 1.0 后，下一拍（200ms）该字段已被权威状态覆盖回 ~500（486 = 526−40，正是伤害结算器的数字） |
| 5 | **全游戏没有血量轮询，只有伤害事件判死** | `HpHandle` 尾部：`battleUnit.onDamEvent?.Invoke(handle); if (battleUnit.unitAttr.isDead) { …onKillEvent…; battleUnit.onDeadEvent?.Invoke(); }`；`Dead()` 仅 2 个调用点，均来自伤害/lifetime |
| 6 | 官方自己也要借伤害事件 | `BattleUtility.KillAllEnemy()`：先 `item.unitAttr.Hp = 1f`，**紧接着** `DamageInfo{atk=1e8, isReal=true}` + `BattleStuff<BattleServer>.Stuff.CreateDamage(...)` —— 证明"写血即秒杀"在原版逻辑上也不成立 |
| 7 | `isNet` 通路在本模式下为空 | 探针实测 `proxy=0x0 / cacheSystem=0x0 / cacheDic=0x0 (cnt=-1)`（全部单位）⇒ 本地属性即唯一通路，`UnitHpCache`/`BattleAttributeCache` 等代理缓存通路在此模式下不可用（`ac=0 hc=0` 同源） |
| 8 | 无限技能有效且不触发检测 | 用户多轮实测确认；技能可用性 `CanUse()` 只读 `skillState ← CanUseTimes`（普通 int 字段），属客户端判定 |

## 2. 被否证的路线（每条都有反证，避免重复投入）

| 路线 | 反证 |
|---|---|
| 写 `heroAttribute/petAttribute` 字段即可 | 事实 4：被权威状态每帧覆盖；多轮实测无效果 |
| 敌人用 `heroAttribute` → 改 `petAttribute` | 已修正确，仍无效果（不是字段选错） |
| 代理缓存通路（`Proxy.cacheSystem` → `UnitHpCache`/`BattleAttributeCache`/`InfoCache.attribute`） | 事实 7：本模式 `proxy=0x0`，通路不存在；且 `Hp` 的 `isNet` setter 只写本地、getter 只读缓存 ⇒ 若 `isNet` 为真，伤害会被整个丢掉，游戏自身无法运作 ⇒ 实战中必为假 |
| "怪物有护盾导致压血看起来无效" | 用户更正 + 实测：怪物无护盾 UI；`0xD8` 字段虽被伤害消耗但非体感来源（该诊断已撤回） |
| 写错对象（`battleUnits` 是旧/假单位） | 事实 2：官方 GM 用同一集合；事实 3：写入可回读；判定版计数 `压血1: 0→119` 且原值实时下降 ⇒ 对象正确 |
| 全堆扫描兜底（静态单例为空时） | **会导致闪退**：主菜单下 `_Stuff` 为空 → 触发约 2GB 活动堆扫描并每 10s 连扫 → mod 线程 SIGSEGV（`fault addr 0x7a000012a1`）。已彻底移除（`ScanInstances/SafeScan` 残留 0），之后零崩溃 |
| 主线程 hook `BattleDriver.Update` + 调 `BattleUtility.KillAllEnemy()` | **触发反作弊**：2026-09-12 01:18:29 开「秒杀+全屏秒杀」→ 进对局立即弹【发现异常】，无法进入对局。该版本已回退 |

## 3. 检测触发点（2026-09-12 01:18 事件）

- 时间线：`01:15:24` mod 装载并打印 `主线程 hook 已装：BattleDriver.Update@0x7331da1308`、`KillAllEnemy@0x71be770b18` → `01:18:29` 用户开「秒杀/全屏秒杀」→ 进对局弹【发现异常】。
- 触发面（按可能性排序）：
  1. **服务端可见的伤害数字**：官方 GM 走权威管线，`DamageInfo{atk=1e8, isReal=true}` 经 `TotalDamageCounter` 记为 `maxDamage` 并由 `C2S_NormalBattleEnd.ToTleDamager` 上报；
  2. **代码段完整性**：Dobby 内联 hook 改写 libil2cpp 代码段，场景加载时校验即可发现；
  3. 纯改字段的多轮测试**从未**触发该提示 ⇒ 触发源在本次新增的 hook / GM 调用。
- 处置：已停止在该版本上继续测试；代码已回退为零 hook、零 invoke。

## 4. 五项功能最终状态

| 功能 | 状态 | 说明 |
|---|---|---|
| 无限技能 | ✅ 有效（已实测） | 置 `Skill.CanUseTimes`，客户端判定，不触发检测 |
| 秒杀 | ❌ 不可实现（纯数据） | 需伤害事件；invoke 会被检测 |
| 全屏秒杀 | ❌ 不可实现（纯数据） | 同上 |
| 无敌 | ❌ 不可实现（纯数据） | 护盾/血量写入被权威状态覆盖；`Hp=0` 还会造成"打不死也杀不掉的僵尸" |
| 移速 | ❌ 不可实现（纯数据） | `MoveSpeed` 写入可见（回读 20.00）但移动由模拟决定，体感无变化 |
