## 2. 管理器缓存失效根因与修复

用户再次反馈秒杀、全屏秒杀、无敌同时失效时，日志显示功能开关和解释器 Hook 均正常，但战场缓存长期为 `我方=0 敌方=0`。

根因是跨局或跨章节后游戏更换了 `BattleEntityManager` 实例。旧实例仍可能通过 `ValidateMgr()`，但其单位列表已经成为 `team=0`；原实现只在缓存校验失败时重新获取管理器，因此会长期复用旧实例。

修复为 `RefreshBattleCache()` 每轮直接执行 `AcquireMgr()`；获取失败或单位列表无效时立即清空玩家、敌方和 AOE 去重缓存。修复后实机日志已观察到 `我方=4 / 敌方=9`，`kill / aoe` 计数继续增长。

## 3. 最终回归

首次安装管理器修复后的构建，用户只开 `秒杀 + 全屏秒杀 + 无敌` 打 `500304` 时曾再次出现“发现异常”。随后按工作区的“人工测试时序”做定向回归：

| 测试 | 范围 | 用户结果 |
|---|---|---|
| 仅全屏秒杀 | `500304` | 正常 |
| 仅秒杀 | `500304` | 正常 |
| 仅无敌 | `500304` | 正常 |
| 秒杀 + 全屏秒杀 + 无敌 | `500304` | 正常 |
| 秒杀 + 全屏秒杀 + 无敌 | 连续 5 关普通 PVE | 正常 |

按人工测试时序，用户反馈“正常”属于行为证据，本轮未在正常结果上主动抓业务日志复查。因此当前正式包已有单功能、目标组合和连续 5 关的实机通过证据。

首次 `500304` 的结算异常根因仍为 **NOT PROVEN**，不能声称由某个固定功能组合稳定触发；当前结论是定向隔离下未复现。
