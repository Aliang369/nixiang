## 3. 本轮稳定性根因与修复

小米 `M2102K1AC` 连续多关后复现进程退出。崩溃证据：

```text
libc++abi: terminating with uncaught exception of type Il2CppExceptionWrapper
tid=12376, name=m.ginicat.sweet
```

`tid=12376` 是 mod 后台线程。根因是后台 `Tick` 仍直接调用热更 `get_Stuff()` / `FindBattleUnitByTeam()`，跨章节对象失效时托管异常穿过 native 边界，直接触发 `SIGABRT`。

修复：

- 后台线程只设置 `refreshWanted`，不再调用热更方法。
- `RefreshBattleCache()` 移到解释器 Hook 的游戏线程上下文中执行。
- 游戏线程刷新期间用 RAII 重入标记隔离；`get_Stuff()`、`FindBattleUnitByTeam()`、`BattleServer.get_Stuff()` 都有异常兜底。
- 主目标秒杀只修改 `DamageInfo`，随后调用一次原 `CreateDamage`，不再二次 invoke。
- 全屏秒杀其余敌人走已反汇编确认的 `HpHandle` 原生桥，标记 `isBuff + isFromNet`。
- `DamageInfo` 增加完整字段范围校验，避免把普通堆对象或网络 FlatBuffer 误判为伤害结构。
- 敌我 EID 缓存使用发布序号快照，避免读取“新数量 + 旧槽位”的撕裂状态。

## 4. 最终回归

用户在小米设备连续测试多关后确认“测试没问题啦”，此前连续出现的 `发现异常`、后台线程 `Il2CppExceptionWrapper` 和 SIGABRT 未再复现。

按工作区的“人工测试时序”，用户“正常/没问题”作为行为证据；正常结果不再追加抓业务日志复查。干净整包重新安装到真机 `f9a116a2`，装机指纹与本地 APK 一致。

此前 `ArgumentOutOfRangeException -> ItemCacheBase.SurplusItemLength` 的历史异常保留为对照记录。本轮修复消除了已验证的后台线程异常和错误挂点路径，但不对未保留日志的每一次历史异常单独宣称根因已证明。

## 5. 4399 闪退边界

4399 玩家反馈的闪退仍没有可直接对应的 tombstone。本轮发现并实测修复的“后台线程托管异常 + 批量/重复伤害调用”属于同一高风险实现家族，但不宣称已经直接覆盖 4399 所有闪退场景。
