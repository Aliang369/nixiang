## 1. 纠偏结论

本包**不能按“纯离线单机战斗”处理**。正常战斗存在客户端发包、服务器回包和服务端技能 CD 同步：

- 客户端发送 `battle.C2SBattleSkill` 技能意图。
- 服务器返回 `battle.S2CBattleSkill`，其中 `harms/harm/extra_harm/hp/d_hp/shield/d_shield` 是伤害与状态结果。
- 客户端用服务器回包里的 `hp/d_hp/shield/d_shield` 调用 `updateEntityBrief()` 更新实体。
- 技能 CD 由 `S2CBattleSkillCd()` 收到的服务端数据写入本地 CD 表。

因此，“免广告、无敌、秒杀、倍攻、无限技能”不能给成同一档可行性：

| 功能 | 结论 | 级别 |
|---|---|---|
| 免广告 | 客户端可跳过广告播放路径；服务器是否稳定发奖待运行验证 | 客户端路径已证实，服务端条件可做 |
| 无限技能 | 可绕过客户端 CD 检查并发更多技能请求；服务器是否接受待运行验证 | 条件可做 |
| 无敌 | 可改客户端 HP/受击显示，但不能证明服务器会接受免伤结果 | 只能客户端/视觉伪装 |
| 秒杀 | 客户端没有实际伤害计算入口可改，服务器回包决定伤害 | 不支持按常规秒杀实现 |
| 倍攻 | 同上，本地没有可放大并上报的最终伤害字段 | 不支持按常规倍攻实现 |
| 战斗表现类修改 | 动画、飘字、特效、客户端自动化等属于客户端可控面 | 可评估，但不等于改变服务器结算 |

总体判断：**星空版工程本身不是完全不能做，但“无敌、秒杀、倍攻都做成有效战斗功能”这一承诺没有本包静态证据支持。** 可以继续做的是客户端免广告、客户端 CD 门槛绕过和界面/表现层功能；前三项战斗数值功能必须先找到服务器接受路径或通过受控真机实验证明，否则只能宣称视觉伪装。

## 3. 广告与免广告可行性

### CLAIM

免广告，或至少跳过广告视频播放并由客户端上报完成。

### VERDICT

**客户端播放路径已证实可跳过；奖励是否由服务器稳定下发还没证明。**

### EVIDENCE

`06_dumped/地城狩猎/51b6d469.pretty.js`

- `133423-133433`：`Eat.watchAd(t, e)`。
  - `isFree()` 为真时，直接发送 `tosPlayerLookAdvertisement(t, 2, i)`。
  - 非免费状态下，先记录 `_adId/_arg`，随后**立即调用 `this.watchAdFinish(true)`**。
- `133450-133473`：`watchAdToVideo()` 存在，会播放本地视频或调用 `sdk.SDKCore.inst.showVideoAd()`。
- `133434-133449`：`watchAdToPay()` 存在。
- 全文件中 `watchAdToVideo()`、`watchAdToPay()` 只有定义，没有调用点；实际广告按钮调用链走 `Eat.inst.watchAd(...)`。
- `133474-133478`：`watchAdFinish(true)` 发送 `player.C2SPlayerLookAdvertisement`，参数 `result=1`。
- 广告协议注册位于 `104773-104778`，对应 `MSG_PLAYER_LOOK_ADVERTISEMENT`。

### 解释

静态代码已经表现出“非免费时不等视频播放、不调用支付广告，直接上报完成”的行为。星空版如果只需保证客户端不播放广告，路线可行。

但奖励是否发放由服务器根据 `C2SPlayerLookAdvertisement` 处理，客户端没有最终决定权。需要真机验证服务器是否接受该完成上报；否则可能出现“无广告动画但无奖励”或错误码。

### 待验证项

1. 任选一个广告奖励入口，真机观察是否发放奖励。
2. 确认服务器返回的广告奖励协议与 `error_code`。
3. 验证 DCC 更新后该调用链是否仍存在。

## 4. 战斗权威与五项战斗功能

### 4.1 客户端发技能，服务器回伤害

`06_dumped/地城狩猎/51b6d469.pretty.js`

- `142149-142158`：`C2SBattleSkillMulti()` 发送：
  - `a_type`
  - `a_uuid`
  - `skill_id`
  - `x`
  - `y`
  - `ry`
  - `attacked`
- 该请求**没有客户端最终伤害字段**。
- `78979-78999`：本地技能命中后，`onSkillHit()` 才调用 `C2SBattleSkillMulti()` 发包；它是技能意图上报，不是本地结算。
- `142160-142231`：`S2CBattleSkill(t)` 处理服务器回包：
  - 先检查 `t.error_code`
  - 遍历 `t.harms`
  - 读取 `o.harm`、`o.extra_harm`
  - 处理 `hp`、`d_hp`、`shield`、`d_shield`
  - 调用 `z7.inst.updateEntityBrief(h)`
- `99380-99502`：`updateEntityBrief()` 进入同步队列，最终在 `Qot.inst.updateEntity(e.data)` 更新实体状态。

这说明伤害、HP、护盾的实际结果由服务器回包决定；`playHurt()` 主要负责表现层。

### 4.2 技能 CD 和公共 CD

- `65469-65475`：`checkSkillCD()` 读取本地 `skillCDs` 并和服务端时间戳比较。
- `65476-65490`：`syncSkillCd()` 会把服务器返回的 skill CD 写入本地 CD 表。
- `142343-142357`：`C2SBattleSkillCd()` 请求同步；`S2CBattleSkillCd(t)` 接收 `{skill_id, cd}` 并调用 `syncSkillCd()`。
- `78966-78977`：技能可用性同时检查 `isInPublicCD()`、`checkSkillCD()` 与 `costEnough()`。
- `73304-73307`、`73326-73329`、`73437-73440`：AI/自动战斗也通过同一套 CD 检查。

因此，客户端可以做成“视觉上无 CD”或“绕过本地门槛连续发技能请求”，但服务器仍会用它自己的 CD/资源校验处理请求。

### 4.3 各项判定

#### 免广告

- CLAIM：跳过广告视频。
- VERDICT：客户端路径可做；服务器奖励待验证。
- EVIDENCE：`Eat.watchAd()` `133423-133433`；`watchAdFinish()` `133474-133478`；协议注册 `104773-104778`。
- 待验证：真机奖励发放与服务器错误码。

#### 无敌

- CLAIM：战斗实际免伤。
- VERDICT：不能按常规客户端无敌实现；最多伪造 HP/受击显示。
- EVIDENCE：伤害与 HP 从 `S2CBattleSkill()` 的 `harm/hp/d_hp` 回包进入；`updateEntityBrief()` 只是客户端同步显示。
- 风险：如果伪改回包，客户端状态可与服务器状态不一致，可能触发回滚、死亡、掉线或异常上报。
- 待验证：不存在“本地免伤但仍能正常结算”的现成路径。

#### 秒杀

- CLAIM：一次攻击让服务器认为敌人死亡。
- VERDICT：静态证据不支持常规实现。
- EVIDENCE：`C2SBattleSkillMulti()` 请求没有伤害结果字段；死亡/伤害结果由服务器 `S2CBattleSkill()` 返回。
- 可行替代：只能在客户端把 `harm` 显示成大数字或把实体表现成死亡，不能保证服务器奖励、掉落和任务状态。
- 待验证：需要网络协议实验证明服务端是否接受修改后的特殊请求；当前没有证据。

#### 倍攻

- CLAIM：实际伤害为原值 N 倍。
- VERDICT：静态证据不支持。
- EVIDENCE：没有找到客户端最终伤害计算字段；服务器回包 `harm` 才驱动表现与 HP 更新。
- 待验证：若服务端存在可伪造的技能参数，必须用受控请求验证；不能把本地面板攻击力修改当作倍攻。

#### 无限技能

- CLAIM：技能可以连续释放。
- VERDICT：客户端门槛可绕过，服务器是否接受为 `NOT PROVEN`。
- EVIDENCE：`checkSkillCD()` `65469-65475`；公共 CD `653xx` 附近；技能发包 `78979-78999`；服务端 CD 回传 `142343-142357`。
- 实现面：可尝试让 `checkSkillCD()` 对指定技能返回 `false`、或让客户端的本地 CD 记录失效；这不等于修改服务器 CD。
- 风险：客户端仍可能收到 `error_code`，或服务器回传 CD 把本地状态重新锁回去。

#### 战斗表现与体验类

- 客户端可评估：自动释放已学技能、跳过/加速本地动画、隐藏特效、战斗提示、界面操作辅助。
- 但服务器仍能覆盖 HP、伤害、CD 和战斗结果。
- `m_speedRate` 相关逻辑可见 `136150-136304` 等区域；地图/战斗加速受 `tosMapSpeedUp()` 和服务端返回控制，单纯改本地速率不等于服务器承认加速。
- 这些功能应单独标记为“客户端表现/自动化”，不能和“实际秒杀/倍攻/无敌”混为一谈。

## 5. 技术可行性边界

### 可以做星空版的理由

1. APK 是普通 LayaAir/Conch 结构，主游戏逻辑是 JS，不是只有加密 native 逻辑。
2. Java 层存在 `ConchJNI.RunJS()`，且 `ExportJavaFunction` 已封装调用，具备运行时 JS 注入入口。
3. 广告和技能 CD 都有明确的客户端触发点。
4. 可以通过外科 DEX/so 注入保持原包主体，但本轮未做构建或装机验证。

### 不能直接承诺的原因

1. 战斗伤害、HP、护盾和 CD 都有服务器回包。
2. DCC 会从远程 CDN 更新脚本，静态改包内容可能失效。
3. `libthemis.so`、`libsecsdk.so`、`libCtaApiLib.so` 等安全/SDK 组件存在；本轮只做了静态识别，没有运行时验证其完整性或反作弊行为。
4. 真实奖励、死亡、结算、掉落和任务状态目前都没有运行证据。

## 7. 最终可行性判断

**能做星空版外壳与客户端注入，不能在同一前提下承诺五项战斗功能全部有效。**

- 免广告：客户端路径已证实。
- 无限技能：条件可做，重点验证服务器接受度。
- 无敌、秒杀、倍攻：静态包内没有支持“真实生效”的权威计算入口；最多做客户端表现层修改，必须标 `视觉/客户端效果 NOT PROVEN`。
- 若用户接受“服务器权威下只做客户端表现和自动化”，可以继续设计菜单；若要求改动真实战报、奖励或死亡结果，当前证据不足，需要另行做受控真机协议实验。
