## 2. 实现结构

本作是 LayaAir/Conch H5 2.1.3.1，没有 Unity/IL2CPP 和可 hook 的原生游戏逻辑，因此不使用 Dobby 原生 Hook。

数据流：

```text
星光菜单 Toggle_无限技能
        ↓
DcslEntry.cpp featureList[1]
        ↓
DcslMod.cpp 原生状态
        ↓
DcslConchProvider.java（Manifest initOrder=101）
        ↓
StarryConch.java 读取授权/开关状态
        ↓
ConchJNI.RunJS(window.__starryDcslState + dcsl_patch.js)
        ↓
GSkillUtil.checkCanUseSkill / CFightMgr.inst.getAutoSkillId
```

关键点：

- `StarryConch` 每 3 秒幂等注入一次，DCC 重载 JS 运行时会自动恢复补丁。
- 状态由 Java 侧每次注入时刷新，补丁包装器每次调用都读取
  `window.__starryDcslState`，因此菜单 OFF 后立即回退原逻辑。
- 不修改 DCC 业务 JS 文件，不依赖本地缓存包静态替换。
- 不修改原包 Application。
- 原包 `classes*.dex` 与 `resources.arsc` 全部逐字节保留。
- 只新增 `classes5.dex`、`libstarry_magic.so`、`dcsl_patch.js`，并替换
  `AndroidManifest.xml` 增加菜单 Provider、Conch Provider 和 MenuService。

## 3. 锚点与补丁逻辑

### 3.1 为什么不是直接 Hook `C0.inst.checkSkillCD`

技能 CD 管理类位于格式化主包：

- `06_dumped/地城狩猎/51b6d469.pretty.js:65395`：`C0` 类。
- `:65469`：`checkSkillCD()`。
- `:65482`：`isInPublicCD()`。

但 `C0` 没有被 `debugGlobal` 暴露为全局对象，运行时无法稳定取得
`C0.inst`。本包 `h5game.Conf.DEBUG = true`，以下公开对象已经挂到
`window`：

- `GSkillUtil`：`:78963`
- `CFightMgr`：`:112201`
- `SkillMgr`：`:112724`
- `CSkillService`：`:66026`
- `CBattleMgr`：`:136508`

因此补丁采用“调用点放行”，不改 `C0` 内部数据。

### 3.2 手动技能

`GSkillUtil.checkCanUseSkill()` 是手动技能和外部战斗接口的共同入口：

- `:78964-78977`
- 它检查公共 CD、技能 CD、怒气/消耗和敌我/战斗状态。
- 补丁先调用原函数；原函数返回 `true` 时原样放行。
- 原函数返回 `false` 时，仅在以下条件全部满足才返回 `true`：
  - 星空授权 `live=1`
  - `Toggle_无限技能=ON`
  - `CBattleMgr.inst.isStart=true`
  - 玩家对象存在且未死亡
  - 技能配置存在，且技能属于当前角色或允许的变身/进化技能
  - 附近敌人检查、召唤技能冷却/存在检查、战斗使用限制通过
- 这样保留地图切换、死亡、非战斗状态等基本边界，只跳过客户端
  `isInPublicCD`、`checkSkillCD` 和本地 `costEnough` 门槛。

### 3.3 自动战斗技能

`CFightMgr.getAutoSkillId()`：

- `:112006`
- 原函数首先检查 `C0.inst.isInPublicCD()`，CD 中直接返回 `-1`。
- 原函数返回正常技能时不改动。
- 原函数返回 `-1` 且功能开启时，按游戏自身的
  `SkillMgr.getAutoBattle()` 顺序选择候选技能，并保留
  `doingSkillId/_nextSkillId/_lastSkillId` 的轮换约束。

### 3.4 服务器边界

补丁只改变客户端“允许发技能请求”的门槛。

- 客户端仍然发送原协议 `battle.C2SBattleSkill`。
- 服务器仍可通过 `S2CBattleSkillCd` 回传 CD。
- 服务器是否接受连续技能请求、是否扣除资源或是否返回 `error_code`
  必须在真机运行验证。
- 因此本功能目前状态为：
  - 客户端逻辑：离线回归通过
  - 构建/签名/结构：通过
  - 服务器行为：`NOT PROVEN`

## 8. 最终结论（2026-09-13）

### 已证实

- 客户端技能按钮 CD 可以清掉。
- `GSkillUtil.checkCanUseSkill`、`CFightMgr.inst.getAutoSkillId`、技能按钮实例层均有运行时回执。
- 客户端确实连续发送了 `C2SBattleSkill` 请求；日志出现 `tx` 增长。
- 服务端回包含 `S2CBattleSkill`，并存在 `extra_harm` 字段回传。

### 未达到交付标准

- 用户真机多次实测反馈：无可见伤害、无有效连续命中效果。
- 回包中的 `extra_harm` 混有全场单位事件，不能证明用户额外点击的技能请求被服务端重复结算。
- 本地 HP/护盾/伤害结果仍由服务端 `S2CBattleSkill` 驱动，客户端放行不能替代服务端结算。

### VERDICT

`无限技能`：**FAILED（客户端表现层可放行，真机有效战斗结果不成立）**。

不能交付为有效星空功能。继续加客户端 Hook、清 CD 或增加请求数量，不能改变服务端权威结算。
