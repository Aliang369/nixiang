## 1. 结论一句话

**这不是游戏包，是一个 1.4 MB 的纯 WebView 壳**；整个游戏（引擎 + 玩法 + 资源）都由
`http://43.248.140.201:8888/` 明文 HTTP 下发，玩法逻辑是 **5.4 MB 可读明文 JS**，
⇒ 改法在 **JS 层**，不需要 IL2CPP / RVA / so hook。

## 4. 战斗与「无敌 / 伤害」挂点（静态）

### 4.1 客户端权威的战斗账本

每次血量变化都往 `battleMgr.battleData` 推一条带 `index` 的记录，例如：

```js
this.battleMgr.battleData.push(l);   // "子弹伤害改变生命" / "DeBuff伤害改变生命"
                                     // "反弹伤害吸血" / "buff伤害" / "生命值伤害"
this.battleMgr.battleData.push(i);   // type: N.LIFE_RECOVERY
```

⇒ **整场战斗在客户端逐帧模拟并记流水**，不是服务端下发回放（与同仓 `仙逆` 的
`game.fightbegin` 服务端定稿模式**不同**）。服务端是否复核该流水尚未验证（见 §6 未决项）。

### 4.2 `invincible` —— 无敌就是英雄身上的一个属性对象

```js
this.invincible = new f(0, "invincible", this.heroId);   // 属性对象，带 .value
```

全包 33 处引用，且**每个受伤入口都先查它**：

```js
r.reboundHp     = function(e){ if(a(this.node,!0) && !(this.invincible.value>0) && this.bloodBar){...} }
r.buffDamege    = function(...){ if(a(this.node,!0) && !(this.invincible.value>0) && this.bloodBar){...} }
   ... if(this._bearer.invincible>0) return;                 // 掉血 buff
   ... if(713!=t.realBId && this.invincible.value>0) return; // DEBUFF 施加
   ... if(e[t].invincible>0) continue;                       // 群体伤害跳过
```

⇒ **把 `invincible.value` 顶住 = 受伤路径全短路**，这是最干净的【无敌】挂点。

### 4.3 伤害链路

```
伤害入口 → getBaseReduceHp(e,t,isHero)   // 基础减伤
        → getExtraRealReduceHp(e,t)      // 额外减伤（hitedExtraType/ENERGIES 分支）
        → setHeroHp(Math.max(1, i-h))    // 真正落血
        → bloodBar / lifeCur.value 账本
```

相关属性：`physicsDamage`、`magicDamage`、`critical`（`seedRandom()<100*critical.value`）、
`lifeInjury`、`damageReduce2`、`criticalHurtResist`、`OnearHurt`/`OremoteHurt`。
⇒【伤害倍率】的候选挂点＝`getBaseReduceHp` / `getExtraRealReduceHp` 的返回值，或英雄
`physicsDamage.value` / `magicDamage.value` 的读取点。

> 注：`getBaseReduceHp=function` 未用正则直接命中，说明该方法名在压缩产物里是
> `f.getBaseReduceHp=function` 之外的形式（如 `r.getBaseReduceHp=function`），
> 精确函数体待 JS 层动态定位（见 §6 下一步）。

## 5. 可改路径（三条，按代价排序）

| 路线 | 做法 | 代价 | 迭代速度 |
|---|---|---|---|
| **A. 本地反向代理 + 改 APK 的 loadUrl 指向 Mac**（推荐） | Mac 跑 `192.168.10.25:8899` 反代 `43.248.140.201:8888`，只对指定 JS 返回补丁副本；APK 一次性把 URL 改成反代地址 | 一次性重打 1.4 MB APK；游玩时需 Mac 开机跑代理 | ★★★ 改 JS 即生效，不用重打包 |
| **B. Frida 注入（设备已 root/KernelSU）** | hook `WebView.loadUrl` 改 URL，或 `onPageFinished` 时 `evaluateJavascript` 注入补丁脚本 | 每次要起 frida-server | ★★★ 零重打包 |
| **C. 整站镜像进 APK 的 assets + `file://` 加载** | 全量下载站点，补丁后内嵌，改 `allowUniversalAccessFromFileURLs` | 站点体积大、跨域/相对路径风险高 | ★ 每次改动要重打包 |

**设备网络已具备条件**：设备 `wlan0 = 192.168.10.7/24`，Mac `en0 = 192.168.10.25`，
设备 ping Mac 2/2 通（RTT 20–123 ms）。
