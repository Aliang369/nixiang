# 境界守望者 · C1 热重载（改配置不重启游戏）

> 游戏：`com.ap.watcherofrealms`（Watcher of Realms 国际服 1.6.38.829.1）
> 构建 tag：`wor-e2-20261004b` ｜ 真机：`96f0d883` ｜ 日期：2026-10-04
> 前置文档：`境界守望者_C1设备侧配置化与C2诊断分档_20261004.md`（`wor_cfg.txt` 键表 / `WOR_DIAG_FULL` 两档）
> 通用规范：`04_scripts/_common/GAME_CONFIG_PATTERN.md`

## 1. 为什么要有热重载

C1 第一版（tag `wor-e2-20261004a`）只在 `Wor_TryInit()` 里读一次配置。
改完 `wor_cfg.txt` 必须**杀掉游戏重进**才生效。

也就是说那一版省掉了「改 `.cpp` → 重编 so → 重打包 → 重签名 → 重装 206 MB」，
但**没省掉「重启游戏」** —— 调一个数值仍然要重进游戏、重走一遍登录和加载。

本版（tag `wor-e2-20261004b`）在 `Wor_Tick()` 里加轮询：

| 动作 | tag `a`（旧） | tag `b`（本版） |
|---|---|---|
| 改一个已有键的值 | `adb push` + **杀游戏重进** | `adb push` → **约 2 s 生效** |
| 重编 so / 重打包 / 重装 | 不需要 | 不需要 |
| 加一个**全新**的键 | 要重编 | 仍要重编（键表是编译期的） |

## 2. 实现（`Games/WorMod.cpp`；**行号会漂移，请用符号名 grep**）

新增/改动对象：

| 符号 | 作用 |
|---|---|
| `WorCfgStamp(path, &mtime, &size)` | `stat` 取 `(mtime, size)` 元数据指纹；文件不存在返回 `found=false` |
| `WorCfgReloadCheck()` | 轮询主体；**只由 `Wor_Tick()` 调用**（Unity 主线程） |
| `g_cfgPollMs` | 轮询间隔；新键 `cfg_poll_ms` 覆盖，默认 `WOR_CFG_POLL_MS_DEFAULT`（2000） |
| `g_cfgMtime` / `g_cfgSize` | 上次看到的指纹（文件消失时置 `-1`） |
| `g_cfgLastPollMs` | 节流用（`WorMonoMs()` 单调时钟） |
| `g_cfgReloadN` | 重载次数，用于 `cfg-reload #N` 编号 |
| `g_offBase[WOR_CFG_OFF_N]` + `g_cfgOffBaseTaken` | 偏移基线快照与「已取过基线」闩，在 `WorCfgApplyOffsets()` 末尾取 |

判定流程（每 `cfg_poll_ms` 毫秒一次）：

1. `g_cfgPollMs <= 0` → 直接返回（轮询可关）。
2. 依次 `stat` 主/备候选路径（`kWorCfgCands[]`），取 `(mtime, size)`。
3. 与上次相同 → 返回（**不 fopen**，这一步是绝大多数帧的全部开销）。
4. 变了 → 先把所有可调项**重置为内建默认值**；
   若之前取过基线，则把 15 项偏移**恢复为基线值**并清空 `g_cfgOffSet[]`。
5. 重新解析文件（`WorCfgLoadFile`）→ 置 `g_cfgOk` / `g_cfgPath`；
   打开失败则 `LOGW` 「保持内建默认值」。
6. 重跑 `WorCfgApplyOffsets()` 重新接管偏移。
7. 逐项打差异日志（见 §4）。

### 2.1 为什么用 mtime+size，不用内容哈希

`sdcardfs` / `FUSE` 上的 `stat` 只读元数据，代价极低；算哈希要把整个文件读进来。
唯一漏判窗口 = **同一秒内写入且长度完全不变**的修改 —— 配置值是数字文本，改值几乎必然改长度。

### 2.2 为什么不加锁

`WorCfgReloadCheck()` 只做 fopen / stat / 字符串解析，**不调 il2cpp、不扫内存、不遍历对象**。

钩子侧把 `g_off_*` 读成对齐的 `int32_t`，ARM64 上对齐的 32 位读写不会撕裂；
最坏情况是某一帧读到「一半新一半旧」的偏移 —— 此时写闸门 `rawSane`（`raw < 0 && raw > -g_rawSaneMax`）
会拒绝这次改写，结果是**那一帧没效果**，不会崩。

### 2.3 只置真的闩不能回退

`g_offHdataRuntime` 是「只置 true」的闩（`ApplyRuntimeOffsets()` 也会置它，表示 hData 偏移已在运行时确认）。
重载路径**故意不动它** —— 把它清掉会让功能以为自己还没解析出布局。

## 3. 键的生效时机分三类

| 类别 | 键 | 行为 |
|---|---|---|
| **立即生效** | `diag`（运行时静音）、`probe_max`、`raw_sane_max` | 重载后下一帧即用新值，日志标「立即生效」 |
| **仅初始化期生效** | `layout_min_asm`、`layout_min_ms`、`scan_max_classes`、`scan_max_sec`、`tbl_path` | 布局/扫描已经跑过，热重载改不了；日志标「需重启游戏」并计数 |
| **热路径直接寻址** | 15 项 `off.*` 字段偏移 | 立即生效，但**值写错会静默失效**（写闸门拒绝），必须靠对账日志核对 |

`diag` 的注意点：它只负责**运行时静音**。`#if WOR_DIAG_FULL` 是编译期闩，
`diag=1` **不会**把已经编掉的 `SELFTEST` / `SECTION 1` / S3 扫描变回来。

## 4. 日志锚点（可 grep）

```text
[Wor] cfg: <path> ok=N bad=M                                  # 首次加载（启动期）
[Wor] cfg: diag=… probe_max=… … tier=diag-tier=RELEASE        # 生效值汇总（非默认值会原样回显）
[Wor] cfg-off: N 项由 <file> 覆盖（优先于内建/国服真值）
[Wor] cfg-reload #N: <path> 已重载（mtime=… size=…）
[Wor] cfg-reload #N: (文件已删除)                               # mtime=-1 size=-1
[Wor] cfg-reload: <key> <old>→<new>（立即生效）
[Wor] cfg-reload: <key> <old>→<new> 属「仅初始化期生效」→ 需重启游戏
[Wor] cfg-reload: off.<key>  0x<old>→0x<new>（当帧起生效）
[Wor] cfg-reload: 配置文件已消失 → 全部回退内建默认值
```

验收时**必须看到配置里那个非默认值被原样回显**，否则可能是「没读到文件、全用默认」也能凑出静默通过。

担忧：每 2 s 的轮询若基线闩判断有误，可能在战斗中途把 `off.*` 重置回默认 ⇒ 直接打死伤害/无敌功能。

## 6. 已知边界 / 未验证

- **`off.*` 写错值是否真改变行为**仍未验证：目前只证明「值被采用」（对账日志回显），
  未证明「值被使用后行为改变」。配置里写的都是正确值。
- **删文件回退的偏移恢复没有正向日志**：当恢复后的偏移恰好等于基线值时，
  逐项 `cfg-reload: off.<key>` 差异行不会打印 —— 只有 `配置文件已消失 → 全部回退内建默认值` 这一行。
  排查时不能以「没有 off 差异行」推断回退失败。
- **`cfg_poll_ms = 0` 只在本次运行有效**：重载进来的配置若自己写了 `cfg_poll_ms = 0`，
  会把 `g_cfgPollMs` 重置回默认 2000（代码里显式做了这一步，避免「关掉就再也开不回来」）。
- **首帧时序假象**：`lib ready … hooked=0` 与 `feature stage: 运行时布局未解析(hData miss) — 拒绝装机`
  都是首帧打印；布局约 1.6 s 后由 `Wor_Tick` 重试路径解析完。
  判定以 `runtime layout ok` / `runtime layout end … hdataRT=1` + `hasComponent bound` 为准。
- 游戏在后台时 Unity 主循环暂停 ⇒ `Wor_Tick` 不跑 ⇒ 热重载不触发。
  验证热重载必须让游戏**在前台**。
