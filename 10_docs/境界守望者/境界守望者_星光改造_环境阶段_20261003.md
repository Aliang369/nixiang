## 3. 关键结论：split 必须一起改签

本作是 **Qigsaw Split 包**（`requiredSplitTypes="base__abi"` + `com.android.vending.splits.required`）。

- **base 里一个 `.so` 都没有**（960 entries，最大的是 `assets/Resources.dat` 133 MB，是自解压壳载荷，运行时落盘成 `liblogic.so` 137,648,336 B）。
- 35 个 `.so` **全在** `split_config.arm64_v8a.apk`：`libil2cpp.so`（仅 232 KB，是加载壳）、`libResources.so` 15.6 MB、`libunity.so` 23 MB、`libhades.so`、`libshadowhook.so`、`libxlua.so`、`libMufSDK.so`…
- ⇒ 只装 base 会 `INSTALL_FAILED_MISSING_SPLIT`。
- ⇒ 同一次 `install-multiple` 会话内所有 APK **必须同一张证书**。官方 split 是 BNDLTOOL 签名 + Play 来源戳 `stamp-cert-sha256`，base 被改签后直接混装必然 `INSTALL_FAILED_INVALID_APK`。
- 所以 surgical 第 **[5b/6]** 步剥掉 split 的 `stamp-cert-sha256` / `META-INF/BNDLTOOL.*` / `META-INF/MANIFEST.MF`，wor_sign.sh 用同一把钥匙重签。
- base manifest 是 `android:extractNativeLibs="true"` ⇒ `.so` 压缩存储合法，**逐条保留原 compress_type**，不需要 STORED、不需要 4096 对齐。

## 4. Windows 管线排障记录（都是实测踩出来的，换机器会再撞）

### 4.1 gradle 卡死（两个独立原因）

**原因 A — 镜像**：项目 `build.gradle` 只有 `google()` + `mavenCentral()`。`dl.google.com` 在国内时通时不通：`maven-metadata.xml` 能 200（0.08~8.64 s 抖动），但下大 jar 会挂在 socket read 上 —— Gradle daemon 75 线程全 `Wait`、CPU 不涨、日志停在 `Starting a Gradle Daemon`，唯一线索是两条到 `120.232.234.33:443`（= dl.google.com）的 Established 连接。
`--offline` 3 秒失败并列出真缺的 4 个 jar：`gradle-8.6.0.jar` / `builder-8.6.0.jar` / `bundletool-1.16.0.jar` / `protos-31.6.0.jar`。

**原因 B — SDK 组件自动下载**：项目写死 `compileSdkVersion 35`、不写 `buildToolsVersion`（AGP 8.6.0 默认 34.0.0），本机只有 `platforms/android-36` + `build-tools/{35.0.0,36.1.0}`，且**没有 `cmdline-tools`/`sdkmanager`**（装不了新组件）⇒ AGP 去 `dl.google.com/android/repository` 自动下载，死循环打印 `Still waiting for package manifests to be fetched remotely.`

**修法**：新增 `04_scripts/_common/gradle_localize.py`（幂等，只作用于 surgical 的临时副本 `$WORK/starry`）：
1. 所有 `build.gradle` 的 `repositories {}` 块首插阿里云三镜像（google/public/gradle-plugin），`google()`/`mavenCentral()` 兜底；
2. `compileSdkVersion` 回落到本机已装最高 platform；模块内 `buildToolsVersion` 写死为已装最高 build-tools；
3. `gradle.properties` 写 `android.suppressUnsupportedCompileSdk=<n>` 与 `android.builder.sdkDownload=false`（缺组件立刻报错，别静默挂网）。

修完：`BUILD SUCCESSFUL in 32s`（此前 5 分钟零进展）。

### 4.2 gradle-wrapper.jar 从来不在仓库里

两份 `.gitignore` 都有 `*.jar` ⇒ `gradle/wrapper/gradle-wrapper.jar` 从未被跟踪，原 macOS 机器本地有一份才跑得起来。
- `~/.gradle/wrapper/dists` 无缓存；PATH 上无 `gradle`。
- 下载 `https://mirrors.cloud.tencent.com/gradle/gradle-8.13-bin.zip`（136,983,045 B）→ `tar -xf` 解到 `01_tools/gradle/gradle-8.13/`；`wor_env.sh` 导出 `WOR_GRADLE_CMD`。
- **不要手工合成 wrapper jar**：把 `gradle-wrapper-main` + `gradle-wrapper-shared` + `gradle-cli` 合并会逐层撞 `NoClassDefFoundError`（`CommandLineParser` → `ExclusiveFileAccessManager`…），追依赖是無底洞。
- 正确做法：空目录里放个 `settings.gradle`，跑 `gradle wrapper --gradle-version 8.13 --distribution-type bin`，把生成的 `gradle-wrapper.jar`（43,705 B）拷回去。
- 顺带纠正一个误判：`java -jar gradle-wrapper.jar` 报「没有主清单属性」是**正常**的 —— 官方 `gradlew` 走的是 `java -classpath <jar> org.gradle.wrapper.GradleWrapperMain`。

### 4.3 `apksigner.bat` 没有 x 位

Windows 上 `build-tools/36.1.0/apksigner.bat` 的文件位是 `-rw-r--r--`。
⇒ 判可用性必须用 `-f`，**不能用 `-x`**（用了会误报 `apksigner/zipalign missing`，或者静默跳过证书一致性闸）。
Git Bash 直接 `"$BT/apksigner.bat" --version` 是可以的（内部走 cmd.exe，实测 rc=0 / `0.9`）。

### 4.4 adb + Git Bash 路径转换

Git Bash(MSYS2) 会把传给原生 Windows 程序的、看起来像 unix 绝对路径的参数自动翻译成本机路径：

```
adb shell mkdir -p /data/local/tmp/x
  → 设备上收到 mkdir -p C:/Program Files/Git/data/local/tmp/x
  → mkdir: 'C:': Read-only file system / mkdir: 'Files': Read-only file system
```

- `MSYS2_ARG_CONV_EXCL='/data/*:/sdcard/*'` 在 Git for Windows 上**实测无效**。
- 有效的是 `MSYS_NO_PATHCONV=1`，但它顺手也关掉本机路径转换 ⇒ 本机路径必须先 `cygpath -m` 成 `E:/...`。
- 已封成 `wor_env.sh` 里的 `adbx()` 助手。
- 若设备侧路径**不进 argv**（塞进 shell 命令串）则普通 `adb` 也安全：`adb shell "md5sum $DEV_PATH"`（参数不以 `/` 开头 ⇒ 不转换）。

### 4.5 设备侧 `pm install-multiple` 已被移除

Android 14 / SDK 34 上：

```
adb shell pm install-multiple ...
  → Unknown command: install-multiple
```

`pm help` / `cmd package help` 只剩 `install`。
⇒ 必须用**宿主侧** `adb install-multiple`（adb 1.0.41 / 33.0.0 支持，自己走 install-create/write/commit 会话，也省掉 push 200 MB 到 `/data/local/tmp`）。

### 4.6 adb.exe 的 argv 走 ANSI 代码页

非 ASCII 路径会被解坏：

```
Exception occurred while executing 'install-write':
java.lang.IllegalArgumentException: Invalid name: .
  at com.android.server.pm.PackageInstallerSession.doWriteInternal(...)
```

（split 名从被解坏的文件名推出来变成 `"."`）
⇒ 装机前先把两份 APK `cp` 到纯 ASCII 目录 `E:/nixiang/_install_stage/wor_<ver>/`。换 ASCII 路径后立刻变成预期的 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`。

### 4.7 其它小坑

- `verify_installed_apk.sh` 原来只写 `md5 -q`（macOS）⇒ 补 `md5sum` 兜底。
- PowerShell 里 `bash -c @'...'@` 会把 `$` 变量吃掉/引号吃坏 ⇒ **shell 代码一律写成 `.sh` 文件再 `bash file.sh`**。
- `PYTHONIOENCODING=utf-8` / `PYTHONUTF8=1` 必须设（Windows CPython 默认 cp936，脚本里的 `✓`/`→` 会让内联 python 片段 UnicodeEncodeError 崩掉）。
