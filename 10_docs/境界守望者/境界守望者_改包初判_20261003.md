## 5. 登录链路分析（实测 + dex 验证）

### 5.1 实测证据（游戏自带日志 Flog）

```
[Info]-Current.Channel:gp
[Info]-libNativeMufSDK, InitApp: {"appID":"watcherofrealms_ap","appSecret":"watcherofrealms2","enviroment":"production","channel":"gp"...}

[Debug]-Push ---> Name:Form_SystemTips
```

- 首次启动直接走 `Login_Auth`，返回 `-22`（未认证）
- channel=`gp`（Google Play），无 QuickSDK 聚合层

### 5.2 平台登录入口（Manifest + dex）

| 登录方式 | 证据 | 所在 |
|---|---|---|
| **Google Sign-In** | `com.google.android.gms.auth.api.signin.internal.SignInHubActivity` + dex 字节命中 `googleplay.*login/GoogleSignIn` | Manifest + classes.dex |
| **Facebook** | `com.facebook.FacebookContentProvider` / `com.facebook.FacebookActivity` | Manifest |
| **VK** | `com.vk.api.sdk.ui.VKWebViewAuthActivity` | Manifest |
| **MufSDK** | `libMufSDK.so` + init 日志 | split arm64 |

### 5.3 与国服登录链路的本质差异

- 国服：**QuickSDK 聚合 TapTap** → `libqkcheck.so` 校验签名 → `login.cxswz.moontonapp.com`
- 国际服：**MufSDK 直接** → 平台账号（Google/FB/VK）获取 token → `login.zgame-ap.moontontech.com`
- **无 TapTap → 不需要 TapLoginForceWeb**，无需强制网页登录
- **签名校验机制不同于 qkcheck**：待定位（可能是 libmoba.so 内或 MufSDK 自身）

## 6. 与国服「复刻功能」的对应分析

### 6.1 可复用的部分

| 国服实现 | 国际服适用性 | 说明 |
|---|---|---|
| 7z 自解压壳认知 | ✅ **完全相同** | 仍从 `files/dragon2019/assets/` 取真代码 |
| `liblogic.so` 为 hook 目标 | ✅ **完全相同** | 仍为运行时加载的真 IL2CPP 库 |
| `HpChangeEntitySystem.ExcuteOnce` 挂点 | ⚠️ **RVA 必然不同** | 类名/方法名大概率不变（同引擎同产品线），by-name 兜底可自动命中 |
| 敌我判定（MonsterSign/TowerSign/CardSoldier） | ✅ **很可能相同** | 同产品线，Enum 值和业务逻辑不会大变 |
| Fix64 Q20.12 定点数 | ✅ **相同** | Unity 引擎 + 同一套战斗公式 |
| 星光菜单 Java 桥 | ✅ **复用** | SignSpoof 证书不同，其余 smali 可直接复用 |
| surgical zip 组装 | ⚠️ **需适配 Split APK** | 国服单 APK → 国际服 Split（base + split arm64），需要不同的组装策略 |
| NoAceStubs | ✅ **仍需要** | 本作仍无 ACE（无 libtprt.so），用 B 类兜底 |
