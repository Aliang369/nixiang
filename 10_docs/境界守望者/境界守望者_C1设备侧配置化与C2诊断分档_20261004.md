# 境界守望者 C1 设备侧配置化 + C2 诊断分档（2026-10-04）

> 目标：把「只有重编才改得动」的调参项挪到**设备侧文件**（C1），
> 把「排障代码」与「正式代码」拆成**编译期两档**（C2），
> 使同一份源码既能出排障包、又能出可分发的正式包。

## 1. C1：设备侧 `wor_cfg.txt`

### 1.1 文件位置（两个候选，只试一次）

| 主 | `/sdcard/Android/data/com.ap.watcherofrealms/files/wor_cfg.txt` |

两者都读不到时**全部保持内建默认值**，不报错、不影响游戏（配置是可选的）。

### 1.2 支持的键

| 键 | 作用 | 内建默认 |
|---|---|---|
| `diag` | 运行时诊断静音开关（与 C2 相乘：`g_cfgDiag`） | = `WOR_DIAG_FULL` |
| `probe_max` | `P#` 探针行最大条数 | `PROBE_MAX` |
| `raw_sane_max` | 写闸门量级上限（超过视为垃圾值，不写回） | `RAW_SANE_MAX_DEFAULT` |
| `layout_min_asm` | 布局解析闸门：最少程序集数 | `6` |
| `layout_min_ms` | 布局解析闸门：最少等待毫秒 | `1500` |
| `scan_max_classes` | S3 结构扫描类数预算 | `40000` |
| `scan_max_sec` | S3 结构扫描秒数预算 | `60` |
| `tbl_path` | 覆盖侦察表 dump 路径 | 主/备候选 |
| `off.<KEY>` | **字段偏移覆盖**（15 项，见 `kWorCfgOffs[]`） | 国服真值 |

- `off.` 键名：`off.sys_com_hp` / `off.sys_hdata` / `off.hpcomp_lvalues` / `off.hpd_stride` /
  `off.hpd_fvalue` / `off.hpd_src` / `off.hpd_settle` / `off.hpd_show` / `off.hpd_atk_euid` /
  `off.hpd_atk_cuid` / `off.hpd_atk_unit` / `off.hpd_skill` / `off.hpd_formula` /
  `off.entity_muid` / `off.hpd_skill`（同名去重，实际 15 项以 `kWorCfgOffs[]` 为准）。
- 解析：`键 = 值`，`#` 起首到行尾为注释，数值走 `strtoll(base 0)`（支持 `0x…`），
  尾部只允许空白；未知键只 `LOGW` 不致命。

### 1.3 生效顺序（关键）

`ApplyRuntimeOffsets()`（HybridCLR 对账，**对值类型统一多报 +0x10**）

即优先级：**`wor_cfg.txt` > 国服真值 > HybridCLR 对账值**。
（顺序不能反：对账值本身就是错的，必须先在它之后。）

## 2. C2：`WOR_DIAG_FULL` 编译期诊断总开关

### 2.1 传递链

```
wor_build_so.sh  DIAG=0|1
   → ndk-build  STARRY_WOR_DIAG=$DIAG
      → Android_wor.mk  LOCAL_CFLAGS += -DWOR_DIAG_FULL=$DIAG
```

- **不传 或 `STARRY_WOR_DIAG=1`** → 排障构建（`WOR_DIAG_FULL=1`）：S1 镜像诊断 / SELFTEST /
  S3 结构扫描 / 字段与方法 dump 全编入。
- **`STARRY_WOR_DIAG=0`** → 正式构建：上述对象**连同全部调用点**整段编掉。

被 `#if WOR_DIAG_FULL` 包掉的对象：
`DumpClassFields` / `DumpClassMethods` / `ProbeName` / `ProbeShortAll` / `ProbeMethodName` /
`WorSafeStr` / `WorClassLookupSelfTest` / `DumpBattleDiagnostics` / `ScanOneImage` /
`ScanAllImages` / `WorScanThread` / `StartScanThread` / `DumpTargetFields`。

> 这些符号**没有跨文件引用**（`Archero2Mod.cpp` / `EndfieldMod.cpp` 里只是各自同名的私有副本，
> 签名不同）⇒ 包掉不会引发链接错误。

### 2.2 构建期自证（`wor_build_so.sh` 内建检查）

| DIAG | 必须**含** | 必须**不含** |
|---|---|---|
| `0` | `diag-tier=RELEASE` | `diag-tier=FULL`、`===== SELFTEST =====`、`===== SECTION 1: images =====`、`===== SECTION 3: structural-scan =====` |
| `1` | `diag-tier=FULL`、`===== SELFTEST =====` | `diag-tier=RELEASE` |

判据**故意不用** `HpChangeEntitySystem` —— 功能代码 `FindSysClass` 也引用它，两档都会出现。

### 2.3 两档产物体积

| 档 | so 大小 | md5 |
|---|---|---|
| FULL（排障） | 2,240,856 B | `904d0673cebbb92470cfdb0c77550d61` |
| RELEASE（正式） | **2,217,480 B** | `7b754b2c1e1d594a1afe3b03a400ad79` |

差 **23,376 B**（≈1.05%），即被编掉的诊断代码量。

### 2.4 运行时静音（不改重编）

若只想在**运行时**静音而不重编：设备侧 `wor_cfg.txt` 写 `diag = 0`（C1）。
两者相乘，任一为 0 即静音。

## 3. 顺带修掉的日志洪水

原实现把 `P#` 探针行放在 `if` 块内**无条件**执行，`n` 到 0 之后仍每帧打 `P#0 …`
⇒ 开关一打开就洪水。改为 `if (n > 0)` 后才打。
`INV` / `DMG` 行不受影响（由 `g_modCount < MOD_LOG_MAX` 单独限流）⇒ 正式档仍能凭 `INV`/`DMG` 判定生效。

## 4. 构建链修复（2026-10-04）

### 4.1 根因：NDK 输出目录经 junction 被解析回非 ASCII 真路径

症状：`unable to open output file 'E:/nixiang/mod菜单/…/obj_wor/…/WorEntry.o'`
而 make 侧同一路径显示为 `E:/nixiang/mod<乱码>/…` —— **两种拼写 = 同一个路径**，
mkdir 建了一个、clang 往另一个写。

链条 ①：`MSYS2_ARG_CONV_EXCL='*' cmd //c mklink /J …` —— 关掉参数转换后 `//c` 不会被折成 `/c`，
cmd 进交互式 shell、rc=0，而 `>/dev/null 2>&1 || true` 把失败吞了 ⇒ **junction 根本没建成**。
正确写法：`MSYS2_ARG_CONV_EXCL='*' cmd /c mklink /J "E:\nixiang\starry_link" "E:\nixiang\mod菜单\starry-mod-menu"`。
脚本现在失败即 `exit 1`，不再 WARN 后继续。

链条 ②：即便 junction 正常，`cygpath -w /e/nixiang/starry_link/obj_wor`
→ `E:\nixiang\mod菜单\starry-mod-menu\obj_wor`（**MSYS 会解析 junction**）。
⇒ 「用 ASCII junction 绕开中文路径」对**输出目录无效**，只对 `-C` 有效。

**修法**：`NDK_OUT`/`NDK_LIBS_OUT` 改到仓库根纯 ASCII 目录 `$NIXIANG/.wor_build/{obj,libs}`，
编完由脚本 `cp -f` 回填契约路径 `mod菜单/starry-mod-menu/libs_wor/arm64-v8a/libstarry_magic.so`。
`.gitignore` 加 `/.wor_build/`（理由已写进忽略文件注释）。

> 踩坑：首次修改只换了 `OUT_LIBS=` / `SO=`，遗留的一行 `OBJ="$STARRY_SRC/obj_wor"`
> 又把 `OBJ` 覆盖回中文路径 ⇒ 看起来「改了没用」。该行已删。

### 5.3 e2 功能（本版 RELEASE 包上重验）

| 功能 | 判据行 | 条数 |
|---|---|---|
| 伤害倍率 ×5 | `[Wor] DMG x5 e=0x744b5bbf50 uid=6 raw=-1142784->-5713920` … | **35** |
| 无敌 | `[Wor] INV e=0x7455fb01e0 uid=9 raw=-860160->0` … | **10** |

- 倍率是**精确 ×5**：`-1142784→-5713920`、`-1114112→-5570560`、`-991232→-4956160`、
  `-868352→-4341760`、`-565248→-2826240`、`-442368→-2211840`（全部整除）。
- 无敌：我方单位 `uid=9` 连续承伤 10 次，**每次都清零**（`raw=-860160->0`）。
- pid 全程不变，`FATAL EXCEPTION` / `SIGSEGV` / `SIGABRT` / `tombstone` **全 0**。
- 判据取不到 `P#` 探针行（RELEASE 档无探针）——**证明正式档靠 `INV`/`DMG` 就能判定生效**。

运行分支（`WorMod.cpp:830/875/883`）：
```cpp
const bool isFriendly = (twr == 1 || cs == 1);          // 我方 = 塔 / 卡牌士兵
if (wantInv && rawSane && isFriendly) { …清零…  INV e=… }
else if (mul > 1 && rawSane && mon == 1) { …放大…  DMG x%d … }   // 敌方 = MonsterSign
```
> 注意二者是 `if/else if`：**伤害倍率调到 5 时我方往往不会挨打**（秒杀），此时 `INV` 天然为 0 条 ——
> 验无敌要把倍率**调回 1**、只留无敌开，再进一局让敌人反击。

## 6. 遗留

- `lib ready` 行的 `hooked=0` 是**时序假象**：`Wor_TryInit` 先打这行，布局要 ~1.6 s 后才由
  `Wor_Tick` 的重试路径解析完（`EnsureLayout: 未就绪 asm=63 elapsed=0ms probe=1 等待中`）。
  同理 `feature stage: 运行时布局未解析(hData miss) — 拒绝装机` 也是首帧假警报。
  **判定时不要拿这两行当真**，以 `runtime layout end … hdataRT=1` 与 `hasComponent bound` 为准。
- 已知限制（服务端战斗校验 `FightVerify`）见 `正式包_单APK合并_20261003.md` §4.1，本版无变化。
