## 1. 为什么不能照搬国服的 RVA

国服 `CxswzMod.cpp` 的挂点是**硬编 RVA**（`HpChangeEntitySystem.ExcuteOnce` @ `0x4927B28`）。国际服这条路走不通，三条独立理由：

### 1.1 静态符号表里没有方法级符号
`06_dumped/境界守望者/base_1.6.38.829.1/liblogic.bytes`（137,648,336 B，真 ELF：`e_machine=0xB7` AARCH64、`e_type=3` DYN、10 PH / 28 SH）的 `.dynsym` 共 2503 条：

| 类别 | 条数 | 说明 |
|---|---|---|
| `il2cpp_*` 导出 | **229** | 全部 `shndx=15`（`.text`），运行时 API 齐全 |
| 其余 | 2273 | **全部是 UND 导入**（`memcpy/malloc/dlopen/socket/sinf…`，`st_value=0`，`SHN_UNDEF`） |

专项搜索 `ExcuteOnce` / `ExecuteOnce` / `HasComponent` / `HpChange` / `codegen` / `MetadataRegistration` **全部 0 命中**。
⇒ **没有任何方法级符号可依据**，RVA 只能靠反汇编分析或运行时取。

### 1.2 Il2CppDumper 6.7.46 对这份 `.so` 无法自动定位
`01_tools/il2cppdumper/Il2CppDumper.exe liblogic.so global-metadata.dat out` 原文：

```

Applying relocations...

Searching...

MetadataRegistration : 7c59f50

System.IO.EndOfStreamException: Unable to read beyond the end of the stream.
   at Il2CppDumper.Il2Cpp.Init(...) Il2Cpp.cs:line 165   ← ReadClassArray

```

- `MetadataRegistration = 0x7C59F50` 落在 `.data.rel.ro`（`addr=0x75310C0 size=0x72EFF0`，末端 `0x7C600B0`）内 ⇒ **合理**
- 但 `CodeRegistration = 0x1226bd8` 落在 `.rela.dyn`（`0x33240–0x1E3C678`）里 ⇒ **假阳性**，后续按错误 count 读数组越界

## 2. 路线决策：运行时「按名解析 + 运行时字段偏移」，零静态 RVA

三条理由（任一独立成立即选此路）：

1. 静态符号表无方法级符号（§1.1）；
2. Il2CppDumper 无法自动定位 CodeRegistration（§1.2）；
3. **但** `.dynsym` 导出齐全 229 个 `il2cpp_*`（§1.1），且 `WorMod.cpp` 的 `HookSlotInstall` **本就实现了「RVA 优先 → 失败转按名」双路径**。

### 2.1 关键安全要求：`RVA_EXCUTE_ONCE` 必须置 0
`WorMod.cpp:300-304`：
```cpp
if (s.origPtr && *s.origPtr) return true;      // 幂等防双钩
if (s.rva && HookAtRva(s.tag, s.rva, s.expectInsn, s.hookFn, s.origPtr)) return true;
return HookByName(s.tag, s.ns, s.cls, s.method, s.argc, s.hookFn, s.origPtr);
```
`rva = 0` 时短路到 `HookByName`。**绝不能保留国服 RVA**：`HookAtRva` 只在 `expectInsn != 0` 时校验序言，若 `RVA=0x4927B28` 且 `expectInsn=0`，就会往一个与国际服无关的地址写 Dobby trampoline ⇒ **必闪退**。

### 2.2 为什么 `HookByName` 的取址方式可靠
`WorMod.cpp:256-285` 用 `void* fn = *reinterpret_cast<void**>(mi);` —— 直接读 `MethodInfo` 首指针（`methodPointer`）取实现地址。这是 IL2CPP 的稳定 ABI 布局，**与 metadata 版本无关**。

### 2.3 可用的运行时导出（实测 VA）

## 4. 三个「名字未知」字段的解析兜底链

`stHpChangeData` 的 `src`/`settle`/`show` 三项，按**三段兜底**解析，任一段命中即用，并在对账表标明命中的是哪一段：

1. **按字段名**：`eDamageSourceType` / `eDamageSettleType` / `eTextShowType`
2. **按备选字段名**：`eSourceType` / `textShowType`
3. **按字段类型名**（`field_get_type` → `class_from_type` → `api.class_name`，短名或后缀相等）：`EDamageSourceType` / `EDamageSettleType` / `ETextShowType`

第 3 段若命中多个字段，取第一个但打全候选（`[Wor] off HPD_SHOW multi-cand` + 逐条 `cand %s @0x%X`），便于从对账表复核。

### 4.1 类结构：只依赖一个名字
```
CSharpBattle.Battle.HpChangeEntitySystem     ← 唯一按名字找的类（已实测存在）
   ├─ com_hp     ──类型链─→  HPChangeComponent   ── lValues ──→ List<stHpChangeData>
   ├─ hData      ──类型链─→  stHpChangeData      （值类型嵌入，class_from_type 同样可取 klass）
   ├─ mAtkEntity ──类型链─→  Entity             （★必须走类型链，禁止按名找）
   └─ fDamage
```
⇒ 其余三个类全从字段类型链拿，**这是最抗版本变化的结构**。

## 5. 硬性安全闸门（e2 新增，e1 没有）

| 闸门 | 位置 | 理由 |
|---|---|---|
| `RVA_EXCUTE_ONCE = 0u` | `WorMod.cpp` 宏 | 见 §2.1 |
| `IsExecutableRange((uintptr_t)fn, 16)` | `HookByName` 取到 `fn` 后、`DobbyHook` 前 | `MethodInfo::methodPointer` 在 HybridCLR/解释器方法上可能是 `0x400000000000` 这类**标记值**，直接解引用即致命故障 |
| `argc == 1` 才许钩 `ExcuteOnce` | 候选筛选 | 若国际服重载改变，宁可不钩也不许猜 argc 去钩别的重载（不匹配则 `FATAL no ExcuteOnce(1) candidate`） |
| 写前合理性闸门 `raw < 0 && raw > -(1LL<<44)` | 无敌清零 / 倍率放大两处 | 挡「偏移解析错误时 raw 是垃圾值」被写回游戏内存 |
| 全程走 `SafeProbe`/`SafeScan` | 所有解析与全域扫描 | 已有设施（sigsetjmp + SIGSEGV/SIGBUS 处理器） |
| 解析阶段**只读**，绝不写游戏内存 | `ResolveRuntimeLayout()` | 初始化期写入 = 直接崩 |

## 6. 全域结构化侦察（B6）—— 让一次装机就能定案

按名解析依赖国服的名字。虽然 §1.3 已确认名字全在，但为了**万一**，`ResolveRuntimeLayout()` 一开
始就**无条件全跑**下面 6 段诊断，落到同一个文件里（每段前打 `===== SECTION n: xxx =====`）：

| 段 | 内容 |
|---|---|
| S1 `images` | 每个 image：`img#%d cnt=%u name=%s`，全部打 |
| S2 `name-probe` | 4 个类 × 每种合理名字（含大小写变体）逐个试并报 `HIT`/`MISS` |
| S3 `structural-scan` | **关键段**。全域遍历所有类的方法表，**按结构特征而非名字**找目标：<br>判据 A：方法名（大小写不敏感）**包含** `xcute`<br>判据 B：类内**同时**有 `hData`/`HData` 字段与 `com_hp`/`comHp` 字段（这组搭配极特征化）<br>判据 C：类短名包含 `HpChange`/`HPChange`/`ChangeHp`<br>判据 D：类短名含 `Battle` 且字段表有 `hData` 或方法表有含 `xcute` 的名字<br>命中即整类 dump（字段表 + 方法表） |
| S4 `candidate-methods` | 目标类的**所有**方法 name/argc/mi/fn/返回类型名；名字含 `xcute` 的额外打 `p0=%s` |
| S5 `field-offsets-runtime` | 目标类每个字段的运行时真值 `off %s.%s = 0x%X` |
| S6 `reconcile` | 国服兜底值 vs 运行时值对账：`off %-24s cn=0x%-4X rt=0x%-4X match\|DIFF\|keep-cn` |

**性能与安全**：S3 是 O(全类数) ⇒ ① 包在 `SafeScan` 里；② 每扫完一个 image 打进度 `scan img#%d/%d cls=%d hits=%d`；③ 设预算（类数上限 40000 或挂钟 60s），超预算打 `scan ABORT budget` 并停；④ 放**后台线程**（`pthread_create`），`Wor_TryInit` 立即返回，**绝不卡主线程**；⑤ 每次命中 `fflush(fp)`，避免中途被杀丢数据。

### 10.3 三个真正卡点的最终结论（后续复刻别的游戏必读）

**① API 指针被壳劫持**（round-4）
split 里那个 232,520 B 的 `libil2cpp.so` 转发壳与真 `liblogic.so` **DT_SONAME 相同**，`Api::Load("libil2cpp.so")` 命中壳、把 27 个指针解析到壳内并置 `api.ready=true`，之后真符号再无机会 ⇒ 全部按名 probe `MISS`。
**解法**：`WorForceApiFromRealLib()` —— 用 maps-path 句柄 `WorDlopenTarget()` 走本地 `dlsym` 覆盖 **28 个** `Api` 成员，核心集齐才置 `ready=true`（`Api::Load` 有 `if (ready) return true;`，盖不回去）。

**② `Api::ImageOf()` 全线判空**（round-5）
`Unity/Il2CppApi.cpp:895-909` 的 `IsValidHeapPtr()` 是按传统堆区间判的，**拒绝 Android 14+ 的 tagged 堆指针**（本机形如 `0xb400007420945000`）⇒ 63 个程序集全部返回 `nullptr`。
**解法**：`WorImageOf()` —— 优先真导出 `api.assembly_image(asm_)`，失败退回 `asm_` 自身。自证：`rawFirst == export`，且 `cand[asm自身]` 不可用（`cnt=116 name='i???t'`）而 `cand[export]` 可用（`cnt=1361 name='mscorlib.dll'`）。

**③ 值类型字段偏移 `+0x10` 偏置**（round-7，**最隐蔽**）
`stHpChangeData`（及其嵌套的 `eRelationData`）是值类型，本机 HybridCLR 的 `il2cpp_field_get_offset()` 对它们**统一多报 0x10**。前几轮把偏置值当真心写进 `g_off_*` ⇒ `fValue` 读在 `0x10`，读到的其实是 `{ETextShowType=1, eShowText=1}` 两个枚举 ⇒ `raw` 恒为 `0x1_0000_0001`（正数），写闸门 `raw<0` **永不通过**，功能形同未装。
**判据 = 全 64bit 视图 `qmap(hd)`（真机实拍，与国服表逐字段吻合）**：
```
00:FFFFFFFFFFF5C000  fValue=-671744 (÷4096=-164.0)      CN:0x00
08:0000000000000000  {SRC=0, SETTLE=0}                   CN:0x08/0x0C
10:0000000100000001  {SHOW=1, eShowText=1}               CN:0x10/0x14
1C:9 20:1 24:2001    {eUid=9, cUid=1, iUnitID=2001}      CN:0x1C/0x20/0x24
28:00030DB5=200117   iAttackSkillID                      CN:0x28
2C:00000067=103      iFormularID                         CN:0x2C
```
**解法**：`ApplyRuntimeOffsets()` 里 `stHpChangeData` 这一组**只记对账日志、随后强制恢复国服真值**（`HPD 值类型 +0x10 偏置已纠正 -> FVALUE=0x0 SRC=0x8 SETTLE=0xC SHOW=0x10 SKILL=0x28 FORMULA=0x2C`；`ATK … -> EUID=0x1C CUID=0x20 UNIT=0x24`）。
**通用教训**：**类字段**的运行时偏移可以信（本作 `com_hp 0x50`/`hData 0x60`/`mAtkEntity 0xD8` 都由「读出来的指针 klass == Entity」交叉验证过）；**值类型字段**必须用「内存实证 + 国服表对账」定案，别信 `field_offset`。

**④ 早于 `il2cpp_init` 调 `il2cpp_thread_attach` = abort**（round-3/4 无限重启的根因）
崩溃栈 `#11 liblogic.so+0x3A74A78` = `il2cpp_thread_attach+8`，`#12` = 本 so 的 `EnsureThreadAttached()`（`Api` 结构体偏移实测：`domain_get +0x20`、`thread_attach +0xC0`）。进程起来 ~1.0s 就跑了解析，而游戏此刻连 `Resources.dat` 都没解压完。
**解法**：`EnsureLayout()` 两道硬闸门 —— ① 目标库未映射（`WorLibRealPath()` 为空）一个 il2cpp API 都不碰；② `SafeProbe(api.Assemblies(&n))` 且 `asmN >= 6 && elapsed >= 1500ms` 才继续，`EnsureThreadAttached()` 移到闸门 2 之后。
