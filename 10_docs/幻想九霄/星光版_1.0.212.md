## 2. 引擎与地址

- Unity 2022.3.62f3，IL2CPP metadata v31，**HybridCLR** 热更；仅 arm64-v8a，无 split。

- 玩法逻辑在热更程序集 **HotFix.dll**（6,694,400 B，sha256 `4b9966cf…`）；AOT（`FECS.Game`）只有表现层。

## 3. 热更 DLL 的取得（纯静态）

- 位置：`/sdcard/Android/data/com.hundunjidian.hxjx/files/<16hex>.dat`（YooAsset bundle，UnityFS v8 + LZ4HC）。
- 保护只有“假 PNG 头 + 假 UnityFS 诱饵头”：取**最后一个** `UnityFS\0`（版本 ∈ {6,7,8}、后跟 `5.`）砍前缀即为合法 bundle，UnityPy 直接读。
- 命中 `46a5ff5a3ebf95dc.dat` → TextAsset `HotFix.dll` + `HotFix.pdb`；程序集 HotFix：4,927 类 / 31,639 方法。
- 不能改包分发：`HotFixIntegrityVerifier.Verify` 比对服务端下发的 DLL 载荷 sha256（`assets/webData.dat` 第 4 段），失败 → 清缓存重启 ⇒ 只能运行期改。

## 4. 无敌：抓点四点（菜单 1 项）

菜单：`战斗 → 无敌`（`feat_num=1`）。开关在每次调用/每帧判断，开即生效。

| 点 | 落点 | 实现 | 首指令指纹 |
|---|---|---|---|
| ① | 解释器入口 `0x3E30454`（HybridCLR 派发函数） | `AttackSystemLogic.EnemyAttackHit` 实参块 `+8`（attack）= 0 | `0xa9ba7bfd` |
| ② | 同上 | `UnitUpdate.AttribCh*` 且参数 ≥3 时，`+0x10` 负值 = 0 | 同上 |
| ③ | AOT `HealthViewComponent.get_ratio` RVA `0x6C9FE10` | 仅当 `maxHealth` 命中已登记玩家快照：`hp := maxHp` 后走原 getter | `0xf9400408` |
| ④ | AOT `HUDBloodSystem.Execute` RVA `0x6CA8900` | 对登记玩家血量逐帧 `cur<max ⇒ cur=max`，并同步玩家 `maxHealth` 快照 | `0xd10103ff` |

配套（抓点第 2 组）：解释器 `HealthComponent.Create` 在 `CreatePlayer` 窗口内、`healthUnit==0` 时登记玩家血量指针（`+0=currentHealth`、`+8=maxHealth`）。

同时保留 HotFix.dll 两处 IL 字节补丁（A 保证伤害真为 0，A' 兜住最大血变化）：

```
A  0x48995  `11 0D` → `16 00`   EnemyAttackHit  hp -= dmg ⇒ 0
A' 0x1971A0 `31 09` → `00 00`   _changeHpMax    最大血变化后回填 hp = max
```

- 入口过滤用 MethodInfo 的完整类指针 + 方法名（`MethodInfo+0x18=name`、`+0x20=klass`），不用斌哥的 8 字节前缀。
- 所有 hook 前校验首指令指纹，不符即拒绝挂载；版本内固定 RVA 随版本更新重标。
- 日志：`adb logcat -s Mod_Menu`；`[hxjx] hooks installed …`，每 5s 一行
  `[hxjx] pts inv=.. atk0=.. attr=.. reg=n/.. ratio=.. hud=..`。
