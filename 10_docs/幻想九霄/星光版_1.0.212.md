## 2. 引擎与地址

- Unity 2022.3.62f3，IL2CPP metadata v31，**HybridCLR** 热更；仅 arm64-v8a，无 split。
- 镜像基址 0 ⇒ RVA == VA；代码段 `file = RVA − 0x4000`。
- 玩法逻辑不在 AOT：AOT(`FECS.Game`) 只有表现层（血条/飘字/死亡动作），真实扣血在热更程序集 **HotFix.dll**（6,694,400 B，sha256 `4b9966cf…`）。

## 3. 热更 DLL 的取得（纯静态）

- 位置：`/sdcard/Android/data/com.hundunjidian.hxjx/files/<16hex>.dat`（YooAsset bundle，UnityFS v8 + LZ4HC）。
- 保护只有"假 PNG 头 + 假 UnityFS 诱饵头"：取**最后一个** `UnityFS\0`（版本∈{6,7,8}、后跟 `5.`）砍掉前缀即为合法 bundle，UnityPy 直接读。
- 命中包 `46a5ff5a3ebf95dc.dat` → TextAsset `HotFix.dll` + `HotFix.pdb`；程序集 HotFix：4,927 类 / 31,639 方法。
- 不能改包分发：`HotFixIntegrityVerifier.Verify` 比对服务端下发的 DLL 载荷 sha256（`assets/webData.dat` 第 4 段），失败 → 清缓存重启 ⇒ 只能运行期改。

## 4. 无敌实现（抓点四点齐备）

> 2026-11-29 起：按斌哥抓点把无敌四点全部落地；解释器入口用 HybridCLR 真实派发函数
> `0x3E30454`（逐方法 stub 都汇入它），过滤用 MethodInfo 完整类指针 + 方法名。
> 抓点里那套「扫 opcode + 8 字节前缀」在本包必然失效（见 §5），只保留其语义。

| 点 | 落点 | 实现 | 首指令指纹 |
|---|---|---|---|
| ① | 解释器 `AttackSystemLogic.EnemyAttackHit` | 实参块 `+8`（attack）= 0 | `0xa9ba7bfd` |
| ② | 解释器 `UnitUpdate.AttribCh*`（参数 ≥3 时） | 实参块 `+0x10` 负值 = 0 | 同上 |
| ③ | AOT `HealthViewComponent.get_ratio` RVA `0x6C9FE10` | `hp := maxHp` 后走原 getter | `0xf9400408` |
| ④ | AOT `HUDBloodSystem.Execute` RVA `0x6CA8900` | 对登记玩家血量逐帧 `cur<max ⇒ cur=max` | `0xd10103ff` |
| 配套 | 解释器 `HealthComponent.Create` | 在 `CreatePlayer` 窗口内、`healthUnit==0` 时登记玩家血量指针（`+0/+8`） | — |

- 原 IL 补丁 A（`EnemyAttackHit` 0x48995 `11 0D→16 00`）与 A'（`_changeHpMax` 0x1971A0 `31 09→00 00`）保留：A 保证伤害真为 0，A' 兜住最大血变化。
- 版本内固定 RVA，装前逐条校验首指令；不符即拒绝挂载（不盲挂）。
- 日志（`adb logcat -s Mod_Menu`）：`[hxjx] hooks installed …` 与每 5s 一行
  `[hxjx] pts inv=.. atk0=.. attr=.. reg=n/.. ratio=.. hud=..`。

**BOSS 血条恒 100%（2026-11-29 已修，待真机确认）**：根因是 ③ 对所有 `HealthViewComponent` 无条件回填。现改为只对「已登记玩家的 maxHealth 快照」生效（④ 每帧同步快照），敌方原样返回。修后包 sha256 `394cb911…`，so md5 `27495d5d…`。

## 5. 与斌哥改包的差异（为什么他的无效）

斌哥挂在 libil2cpp "解释器入口"，但静态复现证明其扫描器实际命中的是 **栈帧簿记函数**（`0x3e2e988/0x3e2e9fc/0x3e2ea68`），且用 8 字节前缀 + 2 参 strcmp 比对裸名（`AttackSy` vs `AttackSystem` 必不等）；本包 metadata 174,679 个方法 RVA 全非 0，也不存在"被解释执行"的 AOT 方法。三条同时不成立 ⇒ 同版本同包上不生效。

我们改用直接改热更层 IL，反而绕开了这三条。
