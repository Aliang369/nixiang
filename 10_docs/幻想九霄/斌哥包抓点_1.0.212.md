## 3. 改包结构（两层：loader + 加密子模块）

- `libwbmod.so` 3,484,152 B：外层只有 `JNI_OnLoad` 等少量导出，实质是**装载器**。
- 落盘加密：`.ced` 自描述段（`{0x64b5c,0x2680,0x0a09}`）+ RC4 解密 `.main`（9,856 B）。
  解密链：`init_array[0]=0x1e5ec` → `0x30338` 驱动 → KSA `0x304d0` → RC4 `0x30730`。
- `JNI_OnLoad(0x661c4)`：`GetEnv` → `prctl(PR_SET_DUMPABLE,1)` → `dladdr` 取 base → 子模块装载器 `0x64ba4`（描述符 `0x671e0`）→ 调 `*(base+0x5f55f0)` 即**二代 JNI_OnLoad**。
- 运行期落点（实测）：解密子模块在 `[anon:.bss]` 可执行段（324 KB，rt = base + st_value，起始 vaddr `0x360000`）。
- 子模块自带 179 条私有 stub（不用 ELF `.plt`），Dobby（`DobbyHook/DobbyInstrument/DobbyCodePatch`）**静态编入**；`il2cpp_*` 走 230 条名字表 `0x3b57f0` 运行期 `dlsym` 填充。

- 状态全在内存 `ON[16]/VALUES[16]`，**无 SharedPreferences**。
- native 状态机 `wb_cheatNative_impl`：

| cmd | 行为 |
|---:|---|
| `>=1000` | `level=clamp(cmd,1000,1100)-1000` → `0x…cdb8`；flag=(level>1) → `0x…cd70` |

## 5. Hook 安装链（库加载即生效，不依赖菜单）

1. 子模块 `JNI_OnLoad(0x37d350)` 用 once 标志 `0x…dcdc8` → `pthread_create(hack_thread 0x37c760)`，返回 JNI 1.6。
2. `hack_thread`：`fopen /proc/self/maps` 反调试打分 → `HT_FindIl2cppBase` 缓存基址。
3. `HT_FindInterpEntry(base)`：**opcode 掩码特征扫描**（`0x94000000`=BL、`0x91000000`=ADD、`0xB9000000`=STR、`0x7100001F`=SUBS + 寄存器一致性链）在 libil2cpp 里定位**解释器入口**（函数符号名未证实）。
4. `dobby_enable_near_branch_trampoline` → `DobbyHook(target, myhook 0x37b600, &orig)`。
5. 成功后再把同一入口经 12 B thunk（`0x37d0c0`）注册为 `HT_InstallFramePoints` 帧点回调，配套 `HT_ResolveRetLayout/HT_RetSlot` 解析解释器帧。

myhook 体内另装两处 **AOT 硬 RVA** hook（每版需重标）：

| 目标 | AOT 符号 | 替换体 | 语义（实测指令链） |
|---|---|---|---|
| `il2cpp+0x6CA8900` | `FECS.Game.HUDBloodSystem.Execute(JobHandle)` | `0x37d470` | 对已登记血条对象巡检/纠偏 + 计数，末尾调原函数 |
| `il2cpp+0x6C9FE10` | `FECS.Game.HealthViewComponent.get_ratio` | `0x37d7d0` | 把实例 `hp := maxHp` 后调原函数 ⇒ **血条恒满**（字段义为推断） |

旁路 `hook_unity`：`libunity+0x514a3c → myhook_unityrun`，替换体只做「转发原函数 + 把 name→&slot 回填 + 打 IL2CPP_HOOK 日志」= 被动解析捕获，对游戏零行为。本机 libunity 该偏移不是函数入口 ⇒ 推断空转。

`HT_CName/HT_MName` 取类名/方法名，与懒解密（XOR 16 B 常量）的 8 字符前缀 `strcmp`；第 3 参是解释器实参块，`+8`=arg1、`+0x10`=arg2（**改的是实参，不是对象字段**）。

## 7. 【无敌】= 四点叠加

1. **解释器层**：`AttackSy.* / EnemyAtt*` 命中时把伤害实参（1..999999）清 0 —— 只对**解释执行的热更方法**生效，AOT 方法不经过该入口。
2. **解释器层**：`UnitUpda.* / AttribCh*` 命中时把负的属性变更量归 0（防掉血/防减益路径）。
3. **AOT 表现层**：`get_ratio` 里 `hp:=maxHp` 后放行 ⇒ 血条恒满。
4. **AOT 巡检**：`HUDBloodSystem.Execute` 对登记对象纠偏，防回退。

⇒ 这是「**调用边界改参 + 表现层回填**」型无敌，不是锁血量字段，也不是 GOT/PLT 改写。

## 8. 证据等级

- **实测**：包/签名/版本、metadata 版本与地址换算、RC4 解 `.main`、子模块 `.bss` 定位、7 个 JNI 入口、状态机分支、7 组名字配对与 `str wzr` 清零指令、repl1/repl2 指令链、131 条文案明文。
- **推断**：repl2 的 `hp/maxHp` 字段义；`hook_unity` 目标错位导致空转；`+0x8/+0x10` 的业务名（伤害/属性量）。

## 9. 对移植星空版的含义

- **不能只靠 AOT RVA**：数值结算在热更层，AOT 层只有表现。三条路线：
  a) 复刻斌哥：hook 解释器入口 + 按类名/方法名前缀过滤（版本无关性最好，但需要解释器入口扫描器）；
  b) 拿到热更 DLL 后按名 hook 具体方法（最干净，前置是解热更 DLL，本作尚未取得）；
  c) 只在 AOT 表现层做（血条恒满）＝ 视觉无敌，不解决掉血。
- **版本重标**：解释器入口靠 opcode 扫描可复用；两个 AOT RVA（`0x6CA8900/0x6C9FE10`）每版必须按新 dump 重算。
- 移植前需要原版做对照：确认热更层类/方法全名、确认改包是否对 `libil2cpp.so` 做过字节补丁（本轮无原版，未验证）。

# 第二阶段：为什么斌哥的【无敌】不生效，以及真正能落地的无敌

> 2026-11-28 追加。本节全部为静态结论（反汇编 + IL 反编译）；运行期实测仅用于「现场状态」旁证。

## 11. 斌哥失效的三个必然条件（静态坐实）

1. **扫描器根本没找到解释器**：`HT_FindInterpEntry`(子模块 vaddr 0x37e360) 的判据是"在 maps 段里找 3 个硬编码字符串 → 找 adrp+add 引用点 → 往前回溯最近 BL 作为函数入口 → BL 投票"。离线按同一判据在我们 libil2cpp 上复现，命中：
   | 特征串 | libil2cpp VA | 回溯入口 |
   |---|---|---|
   | `invalid runtime option id` | 0x1809fbc | 0x3dbdc60（runtime option 注册桩） |
   | `AllocStackSlot` | 0x17fbc1c | 0x3e2e9fc（栈槽分配器） |
   | `AllocFrame` | 0x1879a15 | 0x3e2ea68（帧分配器） |
   投票首名 **0x3e2e988 = 栈回溯帧压栈**（~0x100B，无 bytecode 分派循环）。⇒ hook 挂在簿记函数上，`myhook` 永远拿不到 `(instance, MethodInfo)` 语义。
2. **名字比较必然不等**：`HT_CName`/`HT_MName` 返回 metadata **裸名**（`Il2CppClass::name` / `methods->name`，不含命名空间、不截断），而 myhook 用 **8 字节前缀 + 2 参 strcmp**：`"AttackSy"` vs `"AttackSystem"` 必不等；实测全 so 35 个 strcmp 调用点无一设置 w2（无长度上限）。
3. **本包没有任何方法走解释执行**：dump.cs 174,679 个方法 **RVA 全非 0**（0 个 RVA=0），即 AOT 全覆盖；`InterpExecute`/`InterpFrame`/`il2cpp::interpreter` 三个串在 libil2cpp 里 **0 命中**。⇒ 即便挂对入口，也拦不到"被解释的方法"。

旁证：取证时 6 组名字缓存与就绪标志全 0（懒解密/比较路径从未跑通）。

**"部分设备有效"的解释（推断）**：换设备不会换 so，但换**游戏版本**会——不同 libil2cpp 构建里这些字符串的引用点不同，回溯可能落到真正的解释器派发函数上；此时 8 字节前缀恰好也能命中旧版类名（如 `AttackSy` 同名的旧类型），于是"看起来有效"。同版本同包的设备上则应一律无效。

## 12. 真正的战斗逻辑：HotFix.dll（静态取出，未用任何运行时 hook）

- 分发：YooAsset bundle（`files/<16hex>.dat`，424 个 / 117 MB），格式 **UnityFS v8 + LZ4HC，内容未加密**，唯一保护是"假 PNG 头 + 假 UnityFS 诱饵头"；取**最后一个** `UnityFS\0`（版本∈{6,7,8}、后跟 `5.`）砍前缀即为合法 bundle。
- 命中：`46a5ff5a3ebf95dc.dat` → TextAsset `HotFix.dll` **6,694,400 B**（sha256 `4b9966cf…`）+ `HotFix.pdb`。Assembly **HotFix**：4,927 类 / 31,639 方法 / 27,740 字段。
- 斌哥 8 字节前缀的真实全名对上了：

| 前缀 | 真实全名 |
|---|---|
| `AttackSy`/`EnemyAtt` | `FECS.Game.AttackSystemLogic.EnemyAttackHit` |
| `AttackSy`/`PlayerAt` | `FECS.Game.AttackSystemLogic.PlayerAttackHit` |
| `HealthCo` | `FECS.Game.HealthComponent` |
| `UnitUpda`/`AttribCh` | `HotFix.Game.UnitUpdate.AttribChangeEvent` |
| `WPlayerL` | `HotFix.Game.WPlayerLogic` |

⇒ 斌哥的设计意图没错（就是打 `EnemyAttackHit` 的伤害），错在"找入口 + 比名字"两步。

## 13. 数据结构与唯一减血点

`FECS.Game.HealthComponent`（Sequential/blittable，sizeof 0x28）：
`+0x00 currentHealth(long)`、`+0x08 maxHealth(long)`、`+0x10 healthUnit(int)`、`+0x18 Progress2Health(long)`、`+0x20 fatalRecoveryUsed(bool)`。

`currentHealth` 全 DLL **19 处写点**（16 `stfld` + 3 引用写），其中**唯一减少玩家血量的是 `AttackSystemLogic::EnemyAttackHit` IL_02E9 的 `stind.i8`**（`hp -= dmg`），怪物近战/碰撞与投射物两条入口（`EnemyMeleeAttackColliderEvent`、`ProjectileSystemLogic::CheckCollision`）全部汇入它；其余写点都是"回满/治疗/置 0/敌人侧缩放"。

## 14. 无敌的最小补丁（A + A'，共 4 字节）

| 案 | 位置（文件偏移） | 原字节 → 新字节 | 效果 |
|---|---|---|---|
| **A** | `EnemyAttackHit` IL_02E9 → 0x48995 | `11 0D` → `16 00`（`ldc.i4.0` + `nop`） | 伤害参与运算但为 0 ⇒ **hp 不减**；飘字/受击动画/护盾消耗/濒死判定照旧 |
| **A'** | `UnitUpdate::_changeHpMax` IL_00B8 → 0x1971A0 | `31 09` → `00 00`（`ble.s` → `nop nop`） | 最大血变化后**无条件**把 hp 回填到 max，血条恒满 |

已对副本实打并重编译验证：`IL_02e9: ldc.i4.0 / IL_02ea: nop`、`IL_00b8: nop / IL_00b9: nop`，文件大小与节表不变。

**禁止**只改 `get_ratio` 返回 1：`get_isAlive` 仍判死 ⇒ "满血暴毙"。

**覆盖缺口**（A+A' 之外）：护盾/吸收仍会被打光并播放破碎；濒死护符链仍在（A 后不可达，属静默禁用）；`maxHealth` 下降时若无 A' 会掉条；UI 逐帧同步在 `[Main]FECS.Game.HudSystem`，只能静态证明"读的字段没变"。

## 15. 为什么不能"静态改包"，只能运行期打

- APK 内确实自带同名 bundle（`assets/46a5ff5a3ebf95dc.dat`，5,695,944 B），但比线上旧 41 KB，启动即被版本清单更新覆盖。
- 完整性校验真实存在：`HotFixIntegrityVerifier.Verify(assetName, dllBytes)` 比对**服务端下发的 DLL 载荷 sha256**（`assets/webData.dat` 第 4 段 64 hex = 包内 HotFix.dll 的 sha256；`HotFixIntegrityConfig.Reset()` 在 `ProcedureCheckVersion.OnWebRequestSuccess` 调两次，每次版本检查覆盖）。
- 失败链：`HotfixManager.LoadHotFixDll` → `FireHotfixFailure` → `OnHotfixFailure` → `TriggerRecovery` → `ClearPersistentResourceCache()` + 退出/重启 ⇒ 改 bundle/改缓存都会撞哈希，进"清缓存重启"死循环。
⇒ **必须运行期打**（装载后改内存里的 IL 或改判定），本仓 `plan/invincible_routes.md` 的 L2/L3 与之一致。
