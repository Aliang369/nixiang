# 宝石战争 6.0.012 防封号、上报与存档链审计

> 日期：2026-09-16
> 范围：TapTap 原版 `com.acing.gow.adv` 6.0.012；只读静态审计。
> 结论先行：未发现游戏自研的“检测作弊 -> 客户端上报作弊 -> 服务端处罚”专用链；服务端隐藏风控、结算校验和封号判定仍为 NOT PROVEN。

## 1. 游戏业务层检测

在 `System.Network.dll` 反编译结果中检索：

- `anti_cheat` / `anticheat`
- `detect_cheat` / `report_cheat`
- `tamper`
- `frida` / `xposed`
- `root` 检测业务类
- 对战中的异常/作弊上报类

未发现上述游戏专用检测实现。

存在的是：

- `GWParseLoader` 的服务端错误处理。
- 服务端返回文本包含 `<banned>` 时，客户端进入 `Banned` 状态并显示封禁提示。
- `report_error` / `user_log_client_error` 等客户端错误日志接口。
- ThinkingData、Adjust、U8/归因等第三方分析上报。

这些接口可能存在服务端侧记录能力，但客户端代码中没有发现“三项功能打开后立即上报作弊”的硬编码路径。

## 2. 战斗结果上报

战斗结束调用：

- `GWSubmitResultLoader`
- 服务端函数：`submit_result`
- 关键字段：
  - `BattleToken`
  - `Result`
  - `TroopHealth`
  - `OpponentTroopHealth`
  - `OpponentTroopArmor`
  - `TroopIdsKilled`
  - `TroopsSummoned`
  - `TroopsTransformed`
  - `Stats`
  - `StatsCRC`
  - `BattleActions`

`StatsCRC` 的计算方式较弱：

- `GetCRC()` 对可打印 ASCII 字符求和；
- 用户数据 CRC = 用户名、宝石、金币拼接后求和；
- 最终 CRC = 战斗 Stats CRC XOR 用户数据 CRC。

它不是强完整性签名，但也没有发现客户端在结算前对比“伤害是否落在合法范围”的本地反作弊逻辑。

## 3. 存档与权威数据流

战斗结算后：

1. 客户端提交 `submit_result`；
2. 服务端返回 `NewHeroData`；
3. `GWGameState.SetUserData()` 解析并覆盖本地权威用户数据；
4. 奖励、等级、货币、任务进度等以服务端响应为准。

其他存档接口包括：

- `save_hero`
- `save_team`
- `save_arena_troops`
- `save_hero` / `save_team` 等配置保存请求
- `refresh_user` / `refresh_user` 等刷新接口

本地 `SaveDataManager` / Cloud Save 主要保存设置、用户列表和本地偏好，不是战斗伤害的客户端权威存档。

结论：**战斗资源不是单靠客户端文件上传，而是服务端结果为权威。** 三项功能能否稳定拿到奖励，取决于服务端是否接受本次提交；客户端代码本身没有完整风控判定。

## 4. 第三方安全组件

当前进程或包内可见：

- `libthemis.so`：TapTap 设备/GID 安全。
- `libmsaoaidsec.so`：OAID/设备标识安全；含 `ptrace` 字符串，当前进程已加载。
- `libluster.so`：字节广告归因相关；当前进程已加载。
- `libturingad.so`：腾讯广告风险 SDK；含 debugger 相关字符串，当前未见加载。
- `libA3AEECD8.so`：SONAME `libjdog.so`，含 Xposed/Hook 检测字符串，当前未见加载。
- `libtkdna.so`：第三方归因库，未见战斗业务调用。

这些不是游戏专用战斗反作弊。它们可能导致调试器/Xposed/Hook 环境被第三方 SDK 记录，但当前 Root 设备原版可运行，说明 Root 本身不是阻断条件。

## 6. 风险判断

| 项目 | 判定 |
|---|---|
| 游戏业务层本地反作弊 | 未发现 |
| 客户端专用作弊举报路径 | 未发现 |
| Battle result 上报 | 存在，服务端权威 |
| Save/云存档 | 服务端返回覆盖本地用户数据 |
| Root 阻断 | 当前原版未阻断 |
| 第三方 Hook/Xposed 检测 | 包内存在，当前未加载/未阻断三项功能 |
| 服务端隐藏风控 | NOT PROVEN |
| PvP/竞技场/公会战/排行榜风险 | 未屏蔽，按用户要求保持原逻辑 |

最终说明：**没有发现可直接屏蔽的“作弊上报函数”**。当前三项功能的风险主要不在客户端上报点，而在服务端结算与隐藏风控；本次没有伪装 `submit_result`，也没有屏蔽联机模式。
