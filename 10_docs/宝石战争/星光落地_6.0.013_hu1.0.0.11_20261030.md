## 8. 追加修复（2026-10-30 20:39）：TapTap 验签未过 → 补 B 轨签名杀手

> 用户反馈（20:33）：「taptap签名没过掉」。实测根因不是猜的，是取证到的。

### 8.1 根因（实测证据）

- 首版产物（md5 `d4a5f9ab…`）**只做了外科注入 + 菜单 Provider，没有 B 轨签名杀手**：
  manifest 无 `android:appComponentFactory`，包内 dex 无 `bin.mt.signature.KillerApplication193`。
- 设备侧判据：`{filesDir}/sigkiller.txt` = `fail: java.lang.ClassNotFoundException: bin.mt.signature.KillerApplication193`
  （`StarryInitProvider` 的 `SignatureKillerBootstrap.install` 打点）⇒ 运行时签名替换**根本没装**，
  TapSDK 读到的仍是 CN=StarryMagic 证书 ⇒ 验签失败。
- 底包 `classes.dex` 含 TapSDK 门闩 `com/taptap/sdk/initializer/repository/GatekeeperRepository`（13 处引用），
  确认走的是 TapSDK 验签链。
- 该游戏属 `04_scripts/宝石战争/bszz_surgical_*.sh` 的老口径产物（09 月写的脚本，双轨制是 2026-10-29 才定），
  所以脚本里没有 killer 步骤。

### 8.2 修法（双轨制 B 轨：签名/完整性 = 运行时签名替换）

1. `07_patched/宝石战争/6.0.013/surgical/killer_smali`：MT ApkSignatureKillerEx 的
   `bin.mt.signature.KillerApplication193`（+ `$a…$l` 内部类），源取自 `07_patched/暗影格斗3/surgical/killer_smali`。
2. `07_patched/宝石战争/6.0.013/surgical/official.der`：官方证书 DER，从底包 `META-INF/ANDROID_.RSA`
   `openssl pkcs7 → x509 -outform DER` 现取；**sha256 `8943b316…` == `apksigner verify --print-certs` 的
   Signer #1 摘要**（喂错证书 killer 会静默失效，故写死断言）。
3. killer smali 两处锚点改写：包名 `com.acing.gow.adv`、证书 base64（76 字符折行）⇒ 汇编成 **`classes4.dex`**；
   回读断言 `.super Landroid/app/Application;` + 包名 + 证书 base64 在 dex 内。
4. manifest 注入 `android:appComponentFactory="com.starry.magic.sign.StarryAppComponentFactory"`
   （底包无该属性；`U8Application` 与既有属性一字不动）。该类在 `instantiateApplication`
   （早于真实 Application 构造、更早于 ContentProvider）触发 killer 的 `<clinit>`，
   换 `PackageInfo.CREATOR` + 清 `Parcel.mCreators`/`sPairedCreators`/`PackageManager.sPackageInfoCache`。
5. 官方 dex **一个字节不改**（同为 B 轨特征）；`StarryInitProvider` 的 `SignatureKillerBootstrap.install`
   作为第二道挂载点冗余。
6. `bszz_surgical_6.0.013.sh` 新增 `[2b/6]` 段与对应断言；zip 组装纳入 `classes4.dex`（回读校验）。
