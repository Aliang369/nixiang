## 3. 执行链（15 阶段，`04_scripts/宝石战争/pipeline.json`）

```
device_ready → pull_official → check_official
device_ready → pull_current → dump_static → { fetch_hotupdate_full, impl_mod→build_so, patch_dll }
{ build_so, patch_dll, fetch_hotupdate_full } → surgical → sign → { extract_ota_so, install }
```

- `pull_official`：真机只读 `adb pull` base.apk（root 兜底 `su -c cp`），落 `02_apks/`。
- `pull_current`：只读拉 base.apk + 外部 HotUpdate 的 4 个小文件（Network/Platform bytes、manifest、receipt）。
- `dump_static`：XOR key `bytes((0x04,0x10,0x05,0x1B,0x0A,0x01))`（仅前 0x100 字节）解密 DLL；1.0.0.04 解密后 PE 头 `4d5a9000…` 合法，锚点字符串齐全。
- `fetch_hotupdate_full`：按官方 1.0.0.04 manifest 取全量 142 文件，逐条 size+md5 校验；**cached 115 / downloaded 27**（114 个文件 hash 与包内 1.0.0.01 相同）。
- `patch_dll`：Il2CppDumper（Metadata Version 31，CodeRegistration `30e75a8`，MetadataRegistration `31cea40`）→ Cecil 注入 → 重新加密。
- `surgical`：gradle 出菜单 dex → apktool 产二进制 AndroidManifest（保留 `com.u8.sdk.U8Application`，加 StarryInitProvider + MenuService + 3 条权限）→ 外科 zip 组装（142 个官方资源 + 补丁 DLL + 官方 manifest/receipt + classes3.dex + so）。
- `sign`：zipalign + apksigner（`01_tools/starry_release.jks`）。
- `install`：`BSZZ_ALLOW_UNINSTALL=1` → force-stop + uninstall + install，随后 `_common/verify_installed_apk.sh` 比对设备 base.apk md5 ✓。

## 4. 与 6.0.012 的差异点

1. **热更版本 1.0.0.01 → 1.0.0.04**，`System.Network.dll.bytes` 变了（`dc99a966…` → `3e49c987…`），所以必须重拉热更、重 dump、重注入；脚本内「官方 hash 守门断言」同步改为 `3e49c987…`。
2. 包内 manifest/receipt **仍保持官方原文**（本次是 1.0.0.04），只替换 `System.Network.dll.bytes` 为补丁版——与 2026-09-20 的热更修复结论一致。
3. 新增脚本 `04_scripts/宝石战争/bszz_surgical_6.0.013.sh`（由 6.0.012 版复制改造，`MF_CACHE` 版本隔离为 `07_patched/宝石战争/surgical-6.0.013/AndroidManifest.xml`）；6.0.012 版保留原样以维持历史可复现路径。
4. 各阶段脚本的版本号统一参数化为 `BSZZ_VERSION`（默认 6.0.013），不再硬编码 6.0.012。
5. 补丁 DLL 比原始小约 73KB（Cecil 重写 PE 所致，6.0.012 时同现象，非异常）。
