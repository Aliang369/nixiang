2. 向程序集添加 `StarryMagic.StarryGwBridge`。
3. 添加对 `libstarry_magic.so` 的 P/Invoke：
   - `AdjustDamage`
   - `AdjustHealthValue`
   - `ShouldKeepMana`

### 5.3 回合结束卡死根因与修复（2026-09-16 22:24）

**现象**：星光包在关卡内，自己回合结束后直接卡死（无闪退、无 ANR、无 SIGSEGV）。

**根因**：注入 IL 的 P/Invoke 入口名与 so 实际导出符号不一致。

- 注入侧声明：`[DllImport("starry_magic", EntryPoint = "AdjustDamage")]` 等四个短名。
- so 实际导出：`StarryGw_AdjustDamage` / `StarryGw_ShouldKeepMana` / `StarryGw_AdjustHealthValue` / `StarryGw_ShouldBlockRunAway`（`nm -D` 确认无短名）。
- 后果：每次进入断点都 `dlsym` 失败 → `EntryPointNotFoundException` → 战斗协程在回合结算第一条伤害路径被打断 → 界面停在原地，表现为“卡死”。
- 该注入是无条件插入的，因此即使三个开关都关掉也照样会卡；三项功能也因此一直未真正生效。

**修复**：

1. `04_scripts/宝石战争/dllpatch/Program.cs` 的 `AddPInvoke` 改为写入导出全名 `StarryGw_*`，并对已存在的桥接类型做入口名归一化。
2. patcher 新产出 `System.Network.patched.pinvoke.json`（库名 + 四个入口名）。
3. `bszz_surgical_6.0.012.sh` 新增硬门：组装前用 `llvm-nm` 逐个核对入口名存在于 `libstarry_magic.so` 导出表，不一致直接拒装。
4. 重跑 `patch_dll → build_so → surgical → sign`，得到修复包（§4 新 hash）；`install` 阶段被自动回退为 pending。

**装机**：2026-09-16 22:27 用户授权卸载安装，`mode=uninstall_install_authorized`，设备 `f9a116a2` base.apk md5 == `355cfba0369c91cbb55993eb62b07f2d` ✓（`firstInstallTime=lastUpdateTime=22:27:59`，原官方版数据已清除）。结果文件 `04_scripts/宝石战争/install_result.txt`；`install_official` 阶段已回退 pending。

**待验证**：回合结束卡死是否消失、三项功能是否真正生效均为 NOT PROVEN。

- 日志出现 `[Bszz] AdjustDamage in=...` → P/Invoke 已打通；再卡就不是 dlsym 问题，转为功能语义问题（逐项开关二分）。
