## 2. 引擎与保护判定（关卡②：壳与注入点）

- 引擎：**Unity IL2CPP**（`lib/arm64-v8a/libil2cpp.so` 39,663,720 B、`libunity.so` 17,983,552 B）+ **libxlua.so**（1,562,928 B）→ Lua 玩法层可用（同厂《境界刀鸣》即走 Lua 注入）。
- **无 ACE / 无 TSS**：包内无 `libtprt.so` / `libtersafe2.so` / `libhhld-rt.so`；无百度/梆梆/kwprotect 壳。
- 有**乐变（Lebian）插件化框架**：`application@name = com.excelliance.open.LBApplication`，独立进程 `:lebian.base`，`assets/plugin-release.zip`(190,974,219 B) 内是小七 SDK 的功能插件（`appPlugin` 202 MB，hostWhiteList 全是 `com.smwl.smsdk.*`）——**游戏本体在 host `base.apk`**，dex 注入落点仍是 base.apk。

- **注入路线定案 = ContentProvider 注入**（非换 `application@name`）：
  - 理由：乐变 `LBApplication` 是热更框架入口，替换 risk 高且违背「绝不改 application@name」铁律。

## 4. 大包外科组装（>2 GB 三坑与对策）

脚本：`mod菜单/starry-mod-menu/scripts/surgical_jjssjd_1.38.2.sh`（骨架 = `surgical_phigros_3.20.0.sh` 大包路径 + `surgical_yntt_739.sh` 的 provider 注入路径）。

- **坑① dex 下标**：ART 要求 `classes*.dex` 连续，写死下标会在缺口处停止加载 → `StarryInitProvider` ClassNotFoundException 启动即崩。本包官方连续占用 `classes.dex`..`classes8.dex` ⇒ 新增必须是 `classes9.dex`，脚本用 `04_scripts/_common/next_free_dex.py` 复核（不写死）。
- **坑② zip64**：python zipfile 的 `ZIP64_LIMIT = 2^31-1`（**不是 4 GiB**）⇒ 2.47 GB 产物会被写成 zip64 EOCD + 晚期条目 CD zip64 extra（`hoff=0xFFFFFFFF`、`vneed=45`），build-tools 36.0.0 zipalign 走 zip64 路径直接 `Unable to open as zip archive`。脚本内 `normalize_zip()` 剥离逐条目 zip64 extra 还原真实 hoff、vneed 回填本地头版本、尾部改写纯经典 EOCD（**实测本次修复 519 条**）。
- **坑③ utf8 flag**：官方 3,025 条 zip 条目的 General Purpose Flag **全部带 0x800**（UTF-8），其中 2,380 条另带 0x08（data descriptor）。python `_open_to_write` 会把 `flag_bits` 清零 ⇒ 若不显式保留，Unity/Android 侧按非 UTF-8 解条目名，AssetBundle 会 `Unable to open archive file`。脚本用 `RawNameZipInfo._out_flags` 保留 0x800、有意丢弃 0x08（我们一律写真实 local header，不写数据描述符）。
- **坑④ 磁盘峰值**：unsigned + aligned 两份全包并存 ≈ 5 GiB，脚本前置 `df -g` 预检 ≥ 6 G，zipalign 后立即删 unsigned。
- 保护条目 11 项 sha256 断言：`classes.dex`..`classes8.dex` + `resources.arsc` + `libil2cpp.so` + `libxlua.so`；另加全量 3,022 条 `CRC / size / compress_type / 名字字节 / utf8 flag` 逐条一致断言（本次实测 mismatch=0）。

## 6. 装机（⭐ 换签名必须走「官方包回装 → 彻底卸载」，`-k` 是死路）

- ⚠️ 官方包与星光包**签名不同**，设备无签名绕过模块（`/data/adb/modules/` 空、`ksud module list` 为空、无 LSPosed）⇒ `pm install -r` 必然
  `Failure [INSTALL_FAILED_UPDATE_INCOMPATIBLE: Existing package com.cmge.ssjd.x7sy signatures do not match newer version; ignoring!]`。
- **坑（本次实测，务必记住）**：`pm uninstall -k --user 0 <pkg>`（要保数据）**返回 `Success` 但会把包卡死**——残留的 `PackageSetting` 仍带旧签名
  （`dumpsys package` 仍显示 `signatures=PackageSignatures{db39639 …, signatures:[cab58636], …}`、`Key Set Manager: Signing KeySets: 340`），此后：
  `pm install` 依旧 UPDATE_INCOMPATIBLE；补 `rm -rf /data/data/<pkg>` 无效；再执行 `pm uninstall --user 0` 只回 `Failure [not installed for 0]`。
  ⇒ **换签名场景绝对不要用 `-k` 卸载**，它保住的是签名记录而不是数据价值。
- **可行解（已实测通，全链路 ≈ 4 min）**：
  1. `adb push /tmp/ssjd/base.apk /data/local/tmp/ssjd_orig.apk`（官方原包，md5 `befa9c606746fe8fa5d084ece3547949`，70 s）
  2. `pm install -r -d --user 0 /data/local/tmp/ssjd_orig.apk` → `Success`（用同证书恢复包记录，覆盖掉残留签名）
  3. `pm uninstall --user 0 com.cmge.ssjd.x7sy`（**不带 `-k`**）→ `Success`
  4. `pm install -r --user 0 /data/local/tmp/jjssjd.apk` → `Success`，新签名 `PackageSignatures{6c3d5c5 version:3, signatures:[6f4dda0b]}`
- 数据保全：卸载前已把 `/data/data/com.cmge.ssjd.x7sy`（680 MB，原 uid `u0_a970`）与 `/sdcard/Android/data/com.cmge.ssjd.x7sy`（2.2 GB）
  整目录备份到设备 `/data/local/tmp/jjssjd_{data,ext}_bak`；内容主要是乐变插件解包（`plugin-release.zip` 190 MB + `ShadowPlugin_appPlugin/`）+ SDK prefs + `oat/`，
  **无账号/存档价值**，本次未回灌（全新装）。装机后包 uid 变为 `u0_a971`。
- `verify_installed_apk.sh f9a116a2 com.cmge.ssjd.x7sy <本地APK> --su` → `设备 base.apk md5 == 本地产物 (5064414ea642c9d8b3135e2f015ec749) ✓`（exit 0）。
  设备路径 `/data/app/~~RjnMdlyyxeyiggjvOfsLiA==/com.cmge.ssjd.x7sy-2My-5zmB6xOF2gRYCIhyjg==/base.apk`。
- 装机后公共收尾：`source 04_scripts/_common/starry_post_install.sh; starry_post_install com.cmge.ssjd.x7sy` →
  `appops get … SYSTEM_ALERT_WINDOW` = `allow`；卡密设备指纹种子 `dev_760f1cc7de536cd8c34dd8f79c6f62b4`（冲突时以 `/sdcard/Android/starry_magic/device_id` 为准）。
- 首启 `topResumedActivity` 停在 `com.android.permissioncontroller/.permission.ui.GrantPermissionsActivity`（装机后权限弹窗）；`am force-stop` + `monkey` 重启后进入

  （注：`adb shell` 直接 `pm grant` 会 `SecurityException: Neither user 2000 nor current process has android.permission.GRANT_RUNTIME_PERMISSIONS`，必须包 `su -c`。）
