## 2. 路线（三条硬事实支撑）

### 2.1 装载入口 = AOT 的 `System.Reflection.Assembly.Load(byte[])`

- `libil2cpp.so` 内 RVA **`0x11832AC`**，序言 16 字节：
  `f3 0f 1e f8 fd 7b 01 a9 fd 43 00 91 f3 03 00 aa`
  （`str x19,[sp,#-32]! ; stp x29,x30,[sp,#16] ; add x29,sp,#16 ; mov x19,x0`）
- Frida spawn 实测（`/tmp/ssjd2/fs_loadhook.js`）：该点**命中 1 次**，`x0` = il2cpp `byte[]`，
  `arr.max_length(@+0x18)` = **11,800,576**，`arr.data(@+0x20)` 头 `4d 5a 90 00`（MZ，原生 PE 文件而非映射镜像）。
- 同进程另 4 次命中 `HybridCLR.RuntimeApi.LoadMetadataForAOTAssembly`（base+0x14F1CFC），
  长度 2,382,336 / 780,800 / 445,952 / 2,719,232 = System.Data 系 / Mono.Security / System.Core / Unity.ThirdParty。

### 2.2 容器格式

`Assembly-CSharp.assetbundle` = **8 字节头 + 原始 DLL**：
头 4 字节 LE `04 60 00 00` = `0x6000` = **被混淆的前缀长度**；后 4 字节随版本变。
设备版 `dev[8:]` 与运行时内存 dump **仅前 0x6000 字节不同，其余逐字节相同** ⇒
前缀算法无需破解（内存 dump 已是解密态，hook 直接换缓冲区即可）。
（abconfig 的 AES-128-CBC key/iv `26a6b4e4…`/`820c6522…` 只服务 `miscFlag&2` 的 bundle，
本作 1059 项无人置位，**不适用**。）

### 2.3 补丁规模

官方 11,800,576 B → 补丁版 **11,804,672 B（+4,096 B）** ⇒ 超出原 `byte[]` 容量，
必须用 `il2cpp_array_new` + `il2cpp_class_from_name(get_corlib(),"System","Byte")` 新开数组替换 `x0`。
（`il2cpp_array_new` / `il2cpp_class_from_name` / `il2cpp_get_corlib` 均**未进 `Il2Cpp::Api`**，须 `dlsym`。）

## 3. 五个补丁（`04_scripts/境界死神激斗/ilpatch/Patch.cs`，Mono.Cecil）

全部为**入口前置门控**：配置缺失/关闭 → 原 IL 原样执行（与《无限升级》同一铁律）。

| # | 目标方法 | 注入逻辑 | 开关 |
|---|---|---|---|
| 1 | `BleachBattle.ActorDataControl::get_IsInvincible` | `if (GetBool("inv_full") && Camp==Camp.Player) return true;` | `inv_full` |
| 2 | `BleachBattle.ActorDataControl::ModifyHealth`（6 参） | `if (GetBool("inv") && delta<0 && Camp==Camp.Player) return;`（正 delta=治疗放行） | `inv` |
| 3 | `BleachBattle.ActorDataControl::_finalAttrImpl`（10 参） | `if (attacker!=null && attacker.Camp==Camp.Player && finalDamage>0){ int v=GetInt("dmg_mul",1); if(v>1&&v<=1000) finalDamage*=v; }` | `dmg_mul` |
| 4 | `BleachBattle.SkillInstance::get_iSkillState` | `if (GetBool("nocd")) return _skillState & ~(Cooling\|NotEnoughMp\|NotEnoughFury);`（掩码 `-12`，保留 Casting/Forbid/Disable） | `nocd` |
| 5 | `BleachBattle.SkillInstance::get_CDLeftTimeUs` | `if (GetBool("nocd")) return 0L;` | `nocd` |

- `Camp` 枚举：`Player=0, Enemy=1, ThirdCamp=2`（`Assembly-CSharp.decompiled.cs:7258`）；
  `LevelManager.AddActor` 用 `GetCamp() == Camp.Player` 分类 ⇒ **Player 即我方**。
- 补丁 3 的 Camp 判据落在 **`ldarg.1` = 攻击者**（`_finalAttrImpl(mainAttackerDataCtrl, sufferDataCtrl, long finalDamage, …)`
  @ `Assembly-CSharp.decompiled.cs:979884`），因此是**放大我方造成的伤害**，同时不会放大敌人打我们的伤害。
- 无敌是双层：`inv_full`（`IsInvincible=true`）在最外层 `Hurt()` 早退（顺带免疫硬直/冻结/被索敌），
  `inv` 兜住所有**直接调用** `ModifyHealth` 的旁路（`cs_src:997936 / 1001937 / 1020547` 等 14 处）。
  两键由同一个菜单开关驱动。

## 4. 开关通道

- 配置文件：**`/data/user/0/com.cmge.ssjd.x7sy/files/starry_config.ini`**（每行 `key=value`）
  格式：`inv=1 / inv_full=1 / dmg_mul=N / nocd=1`
- **路径必须硬编码**：HybridCLR 解释器下 `Application.persistentDataPath` 返回空串（2026-09-05 实测）。
- 注入类型 `Starry.StarryConfig` 提供 `static bool GetBool(string)` / `static int GetInt(string,int)`，
  `Environment.TickCount` 2 秒缓存，读文件异常 → 全默认（关）。
- native 侧 `WriteConfig()` 只在开关串变化时落盘；菜单回调 `OnFeatureChanged/OnValueChanged` 立即触发。

## 5. native 侧（`Games/JjssjdMod.cpp`）

- `Jjssjd_OnLoad`（Entry `.onLoad`，`.initDelayMs=0`）起 20ms 轮询线程
  （框架等库是 `sleep(1)` 粒度太粗；实测 hook 在进程 ~1.9s 装上，`Assembly.Load` 在 ~6.6s 发生）。
- `HookAtRvaStrict`：**双路径**（`dl_iterate_phdr` 基址 / `/proc/self/maps` 最大 RX 段换算）+
  序言 16 字节 `memcmp` 不符即拒绝，**绝不盲打**。
- `Hooked_AssemblyLoad`：`g_reenter` 防递归 → 校验 `max_length==11800576` 且 `data[0..1]=='M','Z'`
  → 新开数组 + `memcpy` 内嵌 DLL → 交 orig。任一失败分支都放行官方并打日志。
- 内嵌 DLL：`Games/JjssjdPatchedDll.a`（`llvm-objcopy -I binary`，符号 `_binary_jjssjd_dll_start`），
  mk 里 `LOCAL_MODULE := jjssjd_dll` + `LOCAL_STATIC_LIBRARIES := Dobby jjssjd_dll`。
- so 体积：2,131,208 B（阶段一）→ **11,921,264 B**（内嵌 11.8 MB DLL）。
- **装载 hook 无条件武装**（`Assembly.Load` 早于用户点菜单）；行为 100% 由 DLL 侧配置门控。

## 7. 踩坑记录

1. **Cecil 写盘必须给 AssemblyResolver**：否则 `AssemblyResolutionException: Failed to resolve assembly: 'Unity.ThirdParty…'`
   （`MetadataBuilder.GetConstantType ← AddParameter`）。搜索目录 = `dump 同级 refs/` → `/tmp/ssjd2/refs` → `DummyDll`。
2. **`Starg` 参数下标 ≠ `Ldarg` 槽号**：`_finalAttrImpl` 的 `Parameters[3]` 是 `attackerSkillId`（Int32），
   而 arg slot 3 是 `finalDamage`（Int64）。写成 `Parameters[3]` 会写坏 `attackerSkillId`
   （紧随其后就是 `if (attackerSkillId>0) GetSkill(attackerSkillId)`）。**必须 `Parameters[2]`**。
3. **Frida 调 il2cpp 必须先 `il2cpp_thread_attach(domain)`**，否则解释器访问 TLS 崩（`access violation accessing 0x10`）。
4. Frida 17 已删 `Memory.readByteArray`，改 `ptr(addr).readByteArray(size)`。
5. `luaL_loadbuffer` 未导出（只有 `luaL_loadbufferx`）；`frida` 的 `getExportByName` 对它直接抛错。

功能边界（无任何关卡/模式判断，只有「配置开关 + `Camp.Player`」两道门槛）：

| 边界 | 说明 |
|---|---|
| 适用面 | 任何关卡 / 章节 / 玩法，开关一开即生效；无白名单/黑名单 |
| `Camp.Player` | 本地视角的我方阵营；实时 PVP 也成立（各客户端本地都是 `Player`） |
| 观战 / 录像 / 托管玩法 | 控制对象不属于 `Player` 时**静默不生效**（不误伤我方），此类模式未实测 |
| 服务器结算的模式 | 客户端只改本地上报前的伤害值；服务器权威模式下只影响表现 |
| 伤害倍率上限 | 菜单滑块 `1..100`（native clamp）；IL 侧另设 `>1 && <=1000` 兜底防溢出 |
