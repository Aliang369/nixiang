## 2. 已验证、可复用的关键事实

> 这些是本会话新产出、`skill/re-implement/hotfix-dll-replace-pattern.md` 目前**没有**收录的。

1. **装载入口是可定位的**：`System.Reflection.Assembly.Load(byte[])` 在 `libil2cpp.so` 里是 AOT 导出路径，可用 Frida spawn + 序言 16 字节锁定 RVA（本包 `0x11832AC`）；`x0` 即 `byte[]`，`@+0x18` = `max_length`、`@+0x20` = 数据首地址。
2. **同进程另有 4 次 `LoadMetadataForAOTAssembly`**（2,382,336 / 780,800 / 445,952 / 2,719,232 B），**不需要**动它们。
3. **补丁后 DLL 比原 DLL 大 → 必须新开数组**：`il2cpp_class_from_name(il2cpp_get_corlib(),"System","Byte")` + `il2cpp_array_new`；这三个 API **不在 `Il2Cpp::Api` 里，必须 `dlsym`**。
4. **hook 要早于 ~6.6 s**：框架 `sleep(1)` 粒度太粗 ⇒ 自建 20 ms 轮询线程（本包 i=92~93 命中，~1.85 s 装上）。
5. **Cecil 写盘必须给 `AssemblyResolver`**，否则 `AssemblyResolutionException: Failed to resolve assembly: 'Unity.ThirdParty'`（栈 `MetadataBuilder.GetConstantType ← AddParameter`）。搜索目录：`dump 同级 refs/` → Il2CppDumper 的 `DummyDll/`。
6. **`Starg` 的下标 ≠ `Ldarg` 的槽号**：Cecil `method.Body.Instructions` 里 `ldarg.N` 的 N 含 `this`，但 `method.Parameters[N]` **不含** `this` ⇒ 实例方法要 `Parameters[N-1]`。写错会把值写进**下一个参数**（本包写坏 `attackerSkillId`）。
7. **Frida 调 il2cpp 前必须 `il2cpp_thread_attach(il2cpp_domain_get())`**，否则解释器访问 TLS 崩。

## 3. 优化方案（可执行，按价值排序）

### P0-1 `skill/re-implement/hotfix-dll-replace-pattern.md` 的「Cecil 四项检查」→ 七项

新增三节（直接追加在「4. 求值栈平衡」后）：

- **5. 参数下标：`Parameters[i]` 不含 `this`**
  - 实例方法中 `Ldarg_N` 的槽位 `N = param.Index + 1`，而 `method.Parameters[i].Index == i`。
  - 读侧用 `Ldarg_N`、写侧用 `Parameters[N-1]`，两边口径必须显式对齐并各写一行注释。
  - 反例（实测）：`_finalAttrImpl` 10 参实例方法，`finalDamage` 在槽 3，写成了 `Parameters[3]`（= `attackerSkillId`），把 Int64 写进技能 id，紧随其后就是 `GetSkill(attackerSkillId)`。
  - **自检**：改完后 `ilspycmd -t <类型>` 反编译目标方法，看 **C# 语义**是否等于意图（只看 IL 前 10 条会漏，见 P0-3）。
- **6. 写盘期解析：`ReadAssembly` 必须给 `AssemblyResolver`**
  - 现象：读取正常，`Write` 抛 `Mono.Cecil.AssemblyResolutionException: Failed to resolve assembly: '…'`，栈顶在 `MetadataBuilder.GetConstantType ← AddConstant ← AddParameter`。
  - 处置：`DefaultAssemblyResolver` 加 `dump 同级 refs/` → `DummyDll/` → 环境变量；并把 Il2CppDumper 的 `DummyDll/*.dll` 与 `Unity.ThirdParty.dll` 一并拷入。
  - 与「第 1 项基础类型编码」是**不同**故障：那条改的是类型构造，这条改的是**引用解析**。
- **7. 字节容器容量：+1 byte 就必须换缓冲区**
  - 在 `Assembly.Load(byte[])` 处原地 memcpy 只适用于**输出 ≤ 输入**；否则必须 `il2cpp_array_new` 新开 + 复制 + 替换参数。
  - 判定顺序：先比对输出/输入长度 → 再看是否需要在 hook 内新开数组 → 最后才写 patch。

### P0-2 落 `04_scripts/_templates/ilpatch/` 骨架（从本包抽出）

### P0-3 出包前「补丁全量自检」写进 ilpatch 收尾输出

现状只打印 5 个方法**前 10 条** IL，`starg` 在第 11 条之后 ⇒ 漏检。
改为：

1. 打印每个补丁方法**完整** IL（方法体通常 <200 条，成本可忽略）；
2. 追加**断言式自检**：对每个补丁打印「意图 ↔ 实测」一行，例如
   `[assert] _finalAttrImpl: starg→Parameters[2](finalDamage slot 3) OK`；
3. 失败即 `exit 1`，阻断出包。
