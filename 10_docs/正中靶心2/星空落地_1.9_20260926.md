## 三、月卡门机制（本轮核心发现）

游戏内战斗加速按钮是 `Battle.SpeedUpBtn`（`GameLogic.js` 约 163400–163448 行），只有 **1x / 1.8x** 两档：

```js
i.prototype.getSpeed = function () {
  if (Shop.ShopVipMgr.inst.outStatusAdvip) {                 // ← 月卡门
    if (egret.localStorage.getItem(e.BattleDataKey.getKey(e.BattleDataKey.SPEED_BTN)) > 0) {
      e.GameWorld.inst.gameSpeed = 1.8; this._speedTyep.selectedIndex = 2;
    }
  }
};
i.prototype.setSpeed = function () {
  if (0 == this._speedTyep.selectedIndex)
    if (Shop.ShopVipMgr.inst.outStatusAdvip || e.BattleMgr.battle.battleType == e.BattleGameType.AtOnce) {
      e.GameWorld.inst.gameSpeed = 1.8; this._speedTyep.selectedIndex = 2;
      egret.localStorage.setItem(e.BattleDataKey.getKey(e.BattleDataKey.SPEED_BTN), this._speedTyep.selectedIndex);
    } else Core.TipsUtils.showTipsFromCenter(Core.StringUtils.TEXT(60051));
  else { e.GameWorld.inst.gameSpeed = 1; this._speedTyep.selectedIndex = 0;
         egret.localStorage.setItem(e.BattleDataKey.getKey(e.BattleDataKey.SPEED_BTN), this._speedTyep.selectedIndex); }
};
```

- 门控字段 `Shop.ShopVipMgr.inst.outStatusAdvip` 由**服务端**下发：`Shop.ShopVipMgr.inst.setOutStatusVip(e.Statuses)`（33268），
  内部 `statusId2vipID = { advip: ADRVIP, forbidChat, forbidGame_1..3 }`，`VipType.ADRVIP = "1"`。
- 它的 getter 是可配置的：`Object.defineProperty(n.prototype, "outStatusAdvip", { get(){ return this._outStatusAdvip; } })`。
- 全文 24 处引用**只做真值判断，没有任何成员访问**（不读 `.EndTime`），所以覆写 getter 返回任意真值对象即可放行。
- localStorage 加速位键名：`__xgw_speedBtn`（`BattleDataKey.SPEED_BTN`，59103）。
- `BattleGameType.AtOnce`（扫荡/直通）**本来就免月卡**可加速。

星空实现（`04_scripts/正中靶心2/patch_main.js` 的 `applyVipGate()`）：懒安装原始 getter，
重定义为「原值真 → 返回原值；假 && 开关 ON → 返回 `{StatusId:'advip', EndTime: now+3153600000}`」。
**不写任何服务端数据、不改月卡购买链路**，真月卡账号行为不变。

### 首版失败根因：`ShopVipMgr.prototype` 上没有自有的 `outStatusAdvip`（已修）

首版 `applyVipGate()` 用 `Object.getOwnPropertyDescriptor(Shop.ShopVipMgr.prototype, "outStatusAdvip")`
取原始 getter，取不到就**静默早退**（只打一行日志）。实机打桩（注入走 `android.util.Log` tag `ZZBX2JS`）实测：

```
boot: jsb=object cc=object egret=object Shop=object Battle=object Reward=object window=object
gate: no prototype getter, desc=none
hb: spdUnlock=0 gate=0 n=3 err=0 retFail=0 | own=false isOurs=false inst=true live=undef
```

即 `getOwnPropertyDescriptor` 返回 **undefined**，但 `Shop.ShopVipMgr.inst` 可用、`inst.outStatusAdvip` 可读。
原因：类收尾是 `n = r = __decorate([ MVC.autoModelName ], n)`——装饰器返回**派生类**，
导出到 `Shop.ShopVipMgr` 的是派生类，而 `Object.defineProperty(n.prototype, "outStatusAdvip", …)`
打在**基类**原型上。`getOwnPropertyDescriptor` 只看**自有**属性，故取不到；
首版补丁因此从未安装 gate ⇒ `outStatusAdvip` 恒 falsy ⇒ 点加速必弹「开启特权月卡」。

修复（同一文件）：
- `findGetterInChain(obj, prop)`：沿 `Object.getPrototypeOf` 链搜描述符，取到真正的原始 getter；
- 在**原型**和**单例实例**上各盖一个自有 getter（游戏全部经 `Shop.ShopVipMgr.inst` 读取，实例层遮蔽最稳）；
- 找不到链上 getter 时退化为直接读 `this._outStatusAdvip`（官方 getter 本体就是 `return this._outStatusAdvip`）。

修复后实测（同 tag）：

```
gate installed: chainFound=true inst=true | own=true isOurs=true inst=true live=undef
dump(installed) statics=length|name|prototype|_inst
  protoOwn=constructor|outStatusAdvip|__starry_zzbx2_advip|__starry_zzbx2_fake
  instOwn=$hashCode|$EventDispatcher|_watchers|_isUpdateVipStatus|_isUpdateAdvipStatus|statusId2vipID|outStatusAdvip
```

> **打桩通道教训**：补丁日志不能只用 `cc.log`。首版补丁其实**一直在跑**，但 `cc.log` 不进 logcat，
> 导致一度被误判为「补丁没执行」。现 `dbgRaw()` 走
> `jsb.reflection.callStaticMethod("android.util.Log","i","(Ljava/lang/String;Ljava/lang/String;)I","ZZBX2JS",msg)`，
> 抓取用 `adb logcat | grep -a ZZBX2JS`。另：`cc.director.getScheduler()` 在此刻为 `null`（`scheduled=0` 属预期），
> tick 走 `setInterval` 回退，功能正常。
