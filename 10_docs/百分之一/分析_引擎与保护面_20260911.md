## 二、引擎判定（实测）

Unity **2022.3.62f2c1** + **IL2CPP** + **HybridCLR 热更**。

证据：
- `META-INF/com.android.games.engine.build_fingerprint` = `2022.3.62f2c1;IL2CPP;Release;StripEngineCode:0;OptimizedFramePacing:0;`
- `lib/arm64-v8a/libil2cpp.so`（80,611,624 B）+ `assets/bin/Data/Managed/Metadata/global-metadata.dat`（11,743,568 B，magic `0xFAB11BAF`，**metadata version 31**）
- `libil2cpp.so` 字符串含 `HybridCLR.RuntimeApi::LoadMetadataForAOTAssembly`、`HybridCLR.RuntimeApi::PreJitClass`、`hybridclr doesn't support %s`，工程路径 `E:/UnityProject/OnePercent_Tap/HybridCLRData/...` → **HybridCLR 确认**
- `lib/arm64-v8a/liblz4.so` + `lz4-unity.dll` → 包内自带的 LZ4（热更容器就是 LZ4 frame）

### 产物指纹（实测）

| 文件 | 大小 | md5 |

Il2CppDumper 结果：`CodeRegistration 0x46a24c0` / `MetadataRegistration 0x483a2b8`，成功导出 **`dump.cs` 28,036,289 B** + 110 个 DummyDll。

### 热更结构（实测，关键）

| APK 内文件 | 大小 | LZ4 解压后 | 内含程序集 |
|---|---|---|---|
| `assets/Hybrid/hotupdatedll` | 2,868,624 | 7,013,189 | **OnePercent.dll 6,697,472 B（游戏主逻辑，含完整 IL）** + Onepercent.AOT.dll 313,856 B（防裁剪引用程序集） |
| `assets/Hybrid/aotmetadatadll` | 4,115,754 | 9,186,916 | 8 个 AOT 补充元数据程序集：mscorlib / System / System.Core / UniTask / DBreeze / Sirenix.Serialization / Sirenix.Utilities / UnityEngine.AndroidJNIModule |
| `assets/Hybrid/hotupdatescene` | 2,877,576 | 非 LZ4 | UnityFS AssetBundle（`UnityFS\0...5.x.x...2022.3.62f2c1`） |

- 两个容器都是 **LZ4 frame**（magic `04 22 4D 18`，FLG=0x48 → 有 content size、无 block checksum；BD=0x40）。
- 解压后的明文是 **.NET `BinaryFormatter` / MS-NRBF 序列化容器**（**2026-09-11 更正**：先前「疑似 Sirenix Odin Binary」判断有误）。独立复核依据：头 17 字节 = MS-NRBF `SerializedStreamHeader{RootId=1, HeaderId=-1, Major=1, Minor=0}`；记录类型字节 `0C`=BinaryLibrary、`05`=ClassWithMembersAndTypes（根对象 `Script.Main.InitModules.HotUpdateDll`/`AotMetadataDll`，成员 `_guid`/`_version`/`_assemblies`）、`06`=BinaryObjectString、**`0F`=ArraySinglePrimitive（PrimitiveType `02`=Byte）**。字段布局见 `dump.cs:745522`/`:745621`：`_guid` +0x10、`_version` +0x18、`_assemblies` +0x20（**注意：不存在 `_vm` 字段，先前记录有误**）。
  > 区分：**Sirenix Odin** 走的是**资源/配置**序列化线（`Script.AssetManagers.Helpers/Reflector.cs` 的 `Serializer.Get<T>()`），与热更容器不是同一个东西。
  > MS-NRBF **无校验和、无绝对偏移、无总长度** → 替换程序集只需改 4 字节 `Length` + 载荷，**容器可重建**（详见《热更容器与出包链路》）。
- **OnePercent.dll 已用 ilspycmd 完整反编译**：`06_dumped/百分之一/hotfix/src/`，**5,162 个 .cs / 34 MB**；`Onepercent.AOT.dll` → `06_dumped/百分之一/hotfix/src_aot/`。
- 加载器 `Script.Main.InitModules.AotMetadataDll` / `HotUpdateDll` 位于 **AOT（原生）** 侧，含 `Load(serverUrl, version, ...)` + `UnityWebRequest` + `DownloadUtil` + `LoadAotMetadataDllCode.{DownloadVersionError,DownloadUnzipError,CacheWriteError,AssemblyLoadError}` → **存在「包内 origin + 服务端下载缓存」双路径**，是否被服务端覆盖见出包链路文档。

## 三、资源形态（实测）

`assets/assets.resource` = **1,575,592,337 B 的嵌套 ZIP（全部 Stored 不压缩）**，内层 16 个条目：

```
Database/10000001              13,178,807      ← 资源表
Database/_DBreezeResources  1,867,607,954      ← 主体资源库
Database/_DBreezeSchema           164
Database/_DBreezeResources.rol  1,245,487      ← DBreeze 索引
Database/10000001.rol             1,564
+ _DBreezeTextIndexer / _DBreezeTranJrnl（空表）
Original/Video/video_cg1.mp4    3,480,649
```

内层是 **DBreeze 嵌入式数据库**（`.rol` 索引 + `breeze.tiesky.com` 标识）。`Database/10000001` 的值形如 `mat.sprites-default` → UTF-16 类型串 `Script.AssetManagers.Databases.ResourceMeta, OnePercent...`。

**运行时会解包到本地可写目录**：`Script.UI.CheckUpdates/CheckUnZip.cs` 的 `UnZipAssetAndroid()` 用 `BetterStreamingAssets.OpenRead("assets.resource")` + `FastZip.ExtractZip(stream, AssetManager.RootPath, Overwrite=2, ...)` → 把 1.57 GB 整包解到 `AssetManager.RootPath`（即 `Application.persistentDataPath` 下）。
> 这意味着 **DBreeze 资源库在设备上是明文可写的**，是一个独立于 so/dll 的改动面（数据层）。

## 四、保护面判定（实测，结论：**软目标，无壳**）

| 层次 | 组件 | 结论 |
|---|---|---|
| 加固壳 | **无** | 只有一个明文 `classes.dex`（6,866,264 B），无 `libbaiduprotect` / `libnesec` / `libkwprotect` / ACE / 易盾 / 爱加密 |
| DEX 完整性校验 | **未发现** | Java 层全量扫描 `getPackageInfo/GET_SIGNATURES/checkSignature` 只命中 androidx / alipay / unity 自身，无游戏自研签名或 dex 哈希校验 |

| 反调试 | **未发现（native 层）** | `libil2cpp.so` 无 ptrace/frida/xposed 关键字 |
| 腾讯 Themis 反作弊 | **仅 Themis-Lite（设备指纹）** | `lib/arm64-v8a/libthemis.so`（853,816 B）由 `com.taptap.sdk.themis.lite.ThemisProvider` 初始化；导出符号只有 4 个 JNI：`Z8f7JxQk` / `vQe8bYsT` / `xJ3kLm9Q` / `zXq3tVwP`，回吐 `tdid`（设备 ID）与 `gidData`；**由 TapTap SDK 的 GID/OneID 链路调用**（`com/taptap/sdk/gid/TapSdkGid.java:89` → `new ThemisLiteManager.Builder()...setInitThemisTapaid(true)`），**不是行为反作弊**，不影响战斗数值 |

| TapTap 数据上报 | `libtapsdkcore.so` + `com.taptap.sdk.rep.*` | TapTap 官方上报 SDK（`BridgeRepService`），游戏侧封装见 `Script.TapRep/` |
| Java 异常回传 | **有（重要）** | `MainActivity.setDefaultUncaughtExceptionHandler()` → `UnityPlayer.UnitySendMessage("Logic","HandleNativeException", 线程+完整堆栈)` → C# `Logics/Logic.cs:108` → `GameLogger.HandleNativeException` (`Logics.Auxiliary/GameLogger.cs:170`) → 落本地 HTML 日志 + 进 DBreeze `InsertLogger` 表，`GameLogger._uploadLimit=1` 表明有上报链路 |
| 签名绑定的第三方 SDK | **有（需注意）** | 微信支付 `WXPayEntryActivity`、支付宝 `com.alipay.sdk.*`、TapTap 登录：**换签名后微信/支付宝支付与部分登录会因签名不匹配失败** —— 出包时必须处理（SignSpoof 或实测确认） |

**判定**：这是工作区里少见的「**无壳 + 明文 IL 热更**」目标。改动面从易到难为
**①数据层（DBreeze 本地库）→ ②IL 层（OnePercent.dll）→ ③AOT 层（libil2cpp.so 原生 hook）**。
