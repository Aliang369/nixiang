## ① 结论摘要

### 1.1 一句话结论

**《百分之一》把战斗拆成了两套完全不同的权威模型：**

- **卡牌对战（TCG，`Script.UI.CardBattle.*`）= 客户端本地模拟**：伤害、血量、死亡、胜负全部在客户端算，**排位赛匹配超时还会自动落到 AI 分支**，胜负由客户端上报服务端。→ **可逆性最高，秒杀/无敌/伤害倍率/自动战斗全部可行。**
- **消除系战斗（`GemsBattle` / `DuelBattle` / `MatchMaster` / `MatchMultiple`）= 独立战斗服务器权威**：客户端只是「输入发送 + 演算回放器」，服务端下发 `CBattleCommandArray`（含单位生成/移除/攻击/伤害统计），胜负由服务端 `MID_CHARACTER_BATTLE_FINISHED` 下发。→ **改本地数值无收益，只会本地表现错乱。**

**主线冒险推图（Adventure 默认分支）走的正是服务端权威的 `GemsBattle`**，因此「推图秒杀/无敌」在本版本**不可行**（这点与常见预期相反，是本轮最重要的纠偏）。

### 1.2 最强可逆功能 Top 5（详见 §③）

| # | 功能 | 挂点 | 权威性 | 可行性 |
|---|---|---|---|---|
| 1 | **卡牌对战直接胜利/秒杀**（PvE、教学、日记、娱乐场 PvE、排位 AI 分支） | `Script.UI.CardBattle.Servers.Battlefields.Card::BeHurt` / `set_Health`；或复用官方跳教学模板 `TutorialSkipPanel::OnConfirmClick` 直接投递 `GameOver{LosterId=敌}` | **客户端权威** | ★★★★★（官方自身就有等价调用） |

### 1.3 分界线（最重要的一条）

> **分界线不在「PVE vs PVP」，而在「是否拿到战斗服务器 host/port/room」。**
>
> - 走 `Helper.Owner.Battle.SearchBattleAsync(...)` → `IBattleInstance.StartAsync(host, port, room)` 的玩法，**一律服务端权威**。
> - 不走 BattleServer、只用 `AIAgent.Start(...)` 在本地开打的玩法，**一律客户端权威**。

### 1.4 关于「出包定位」的关键事实（纠偏）

**[实测]** `dump.cs` **不包含任何游戏代码**：

```
$ grep -c "Script.UI" dump.cs     → 0
$ grep -c "OnePercent" dump.cs    → 0
$ grep -c "elapsing" dump.cs      → 0
$ grep -c "BeHurt" dump.cs        → 0
```

`dump.cs` 头部只列出 **109 个 AOT 镜像**（mscorlib / System / UnityEngine.* / DBreeze / HybridCLR.Runtime.dll / Sirenix / UniTask / TapSDK…），**没有 `OnePercent.dll`**——因为它由 HybridCLR 在运行时从 `assets/Hybrid/hotupdatedll` 解释加载。

**推论（对出包定位的直接影响）**：
- 本文件所有战斗挂点**无法通过 dump.cs 的 RVA/Offset 定位**；只能通过 **IL 方法名**（`OnePercent.dll` 的元数据）定位。
- dump.cs 仍可用的是 **AOT 侧**少数门控点，本轮已取到（RVA 为该 `libil2cpp.so` 构建专有，换包必须重新核对）：

| AOT 挂点 | RVA（File Offset） | 用途 |
|---|---|---|
| `UnityEngine.Time::set_timeScale(float)` | `0x43BB170`（`0x43B7170`） | 全局倍速的最终门控（覆盖所有 `Time.timeScale=` 写入点） |
| `UnityEngine.Time::get_timeScale()` | `0x43BB148`（`0x43B7148`） | 读取侧 |
| `UnityEngine.Application::set_targetFrameRate(int)` | `0x4352910`（`0x434E910`） | `Logic.Awake` 里按 `GetGameUtils("HighFrameRate")` 设置帧率 |
| `HybridCLR.RuntimeApi::LoadMetadataForAOTAssembly` | `0x38B9134`（`0x38B5134`） | 热更补充元数据加载入口 |

- **[待验证/经验迁移]** 按工作区既有经验《经验_HybridCLR直写三铁律》，HybridCLR 游戏内调用走**解释器分发**，`MethodInfo.methodPointer` 上的 Dobby hook **命中率可能为 0**；热更方法的外部线程 `runtime_invoke` 会导致解释器 SIGSEGV。因此本目标的战斗改动**优先走 IL 层直写（`OnePercent.dll`）或数据层**，而不是原生 MethodPointer hook。这条是**经验迁移，未在本目标实测**。

**AI 对战的胜负上报链路（[实证]）**
```
RankOverPanel/SportOverPanel/TutorialOverPanel
```

而 `InstanceSign` 是**纯客户端可算**的（[实证]）：
```csharp
// <SRC>/Script.Config.Script.Card/BattleInitData.cs:58
public string InstanceSign => Convert.ToBase64String($"{InstanceId}{TimeSign}".ToRawMd5());
// <SRC>/Extensions/StringExtension.cs:125  →  MD5(UTF8(content))
```
- `InstanceId` = 客户端配置里的 instance 号（`instanceId` 局部变量，本来就传给 `AIAgent.Start`）；
- `TimeSign` = `InstanceLog.LaunchAsync` 从服务端拿回的 `long`（`CharacterInstanceLog.cs:387-396` 及内部状态机 `ReadI64`）。

**结论**：签名 = `Base64(MD5(InstanceId + TimeSign))`，**不绑定 `result`**。上报报文为 `(uint index, sbyte result, string sign)`（`MID_CHARACTER_INSTANCE_LOG_FINISH_TUTORIAL_REQUEST`，`CharacterInstanceLog.Finish` 附近）。因此：
- 服务端**可以**校验"这次 instance 确实被 Launch 过、签名自洽"；
- 服务端**无法**从签名判断"这一胜是真的打出来的"。
→ **客户端有构造一个"合法签名 + 任意胜负"报文的能力。[实证=签名不含结果；待验证=服务端是否还有其它校验]**

### 3.4 倍速机制的精确结论（Q5 汇总，[实证]）

全源码 `grep -rn "timeScale"` 共 22 处（含编辑器 Tweener）；战斗相关全部是 **`UnityEngine.Time.timeScale` 直接赋值**，**不存在逻辑帧步进（fixed-step）或自定义逻辑时钟**。

| 模式 | 机制 | 上限/来源 | 位置 |
|---|---|---|---|
| GemsBattle（含 PvE 推图/挑战/Boss/合作） | `Time.timeScale = _normalScale`；追赶时固定 `9f` | `_normalScale = GemsBattleSpeedCfg.Gears[CharacterData.GemsBattleSpeedIndex]`；追赶 = `_currentRound < _targetRound` | `Script.UI.GemsBattle.Speed/GemsBattleSpeedRenderer.cs:304-337` |
| 宝藏 TreasureHunt | `Time.timeScale = Gears[TreasureSpeedIndex]`（`Refresh()` 里无条件赋值） | 同上配置族 `HuntCfg.Value.SpeedCfg.Gears` | `Script.UI.TreasureHunt.Speed/TreasureSpeedRenderer.cs:56-119` |
| 大师赛 MatchMaster | 只有追赶：`Time.timeScale = value ? 9f : 1f` | `_targetRound` 仅在 `QueryRoundAsync()`（服务端）报新回合时前移 | `Script.UI.MatchMasters.Speed/MatchMasterSpeedRenderer.cs:24-109` |
| 卡牌 TCG PvP | 追赶：掉线/暂停后按丢失时长 `1.1/1.25/1.8/2.5/3.5f` | 硬编码 | `Script.UI.CardBattle.Agents/PvPAgent.cs:81-114` |
| 卡牌 TCG 回放 | `Time.timeScale = isPause ? 0f : ReplaySpeeds[level-1]` | `CardBatCfg.ReplaySpeeds` | `Script.UI.CardBattle.Agents.Replays/ReplayAgent.cs:60-66` |
| 巴别塔 | **无倍速**（`grep timeScale` 在 `Script.UI.BabelTowers*` 命中 0） | — | — |

**三条关键推论**：
1. **`Time.timeScale` 不影响服务端计时**。服务端时间由 `TimerManager.ServerUtcNow = _serverTime + (Time.realtimeSinceStartup - _recordTime)` 估算（`<SRC>/Logics.Auxiliary.TimeUtils/TimerManager.cs:256-273`，含 `_maxPreciseError=1f` / `_maxAllowError=10f` / `_queryInterval=30f`），底数是 **`realtimeSinceStartup`（不受 timeScale 影响）**。→ 倍速只省"看动画"的时间，**不会**让你多出操作时间；反而压缩你的真实反应时间。
2. 服务端回合轴 `elapsing.tagTimeAxis<T>` 的 `relate=false` 分支用 `system.Time()`（服务端赋值）与 `TimerManager.ServerUtcNow` 比较来算 `remain`（`<SRC>/elapsing/tagTimeAxis.cs:47-52, 88-97, 103-113`）→ **服务端中继模式的回合计时是服务端时间驱动**，本地改不了。`relate=true`（本地/追赶）才用 `Time.realtimeSinceStartup`。
3. `Time.timeScale` 的 AOT 侧最终门控 = `UnityEngine.Time::set_timeScale` RVA `0x43BB170`（见 §1.4），**这是唯一"一处生效、覆盖全部模式"的原生点**。
