## 1. 结论摘要

| 目标 | 结论 |
|------|------|
| 过签名/完整性检测 | 注入 `libqkcheck.so` + `com.game.apkverify.Check`，校验时返回**官方证书特征**（硬编码 MD5 `526b7295424a894979a5bf5c4a9c3123`），而 APK 实际签名 MD5 为 `e571e96ec9428b88c9d3e358cbd3d655` |
| 壳 / 入口伪装 | 百度 Sagittarius：`com.sagittarius.v6.StubApplication`；Launcher 被换成 QK 框架 `com.qk.game.SplashActivity` → `MainActivity`，真实 Application 字符串指向 `com.qk.game.GameApplication` |
| 无敌 | **不是另写一套免伤**，而是打游戏自带字段 `StatusC.wudi`（offset `0x269`）。`OnDamage` 里若 `wudi!=0` 直接返回，不进扣血 |
| 秒杀 / 全屏秒杀 | 战斗核在 `StatusC`：`CalDamage` / `OnDamage` / `OnMagicDamage` / `ReduceHp` / `Death`。秒杀=放大伤害或对敌方 `ReduceHp`/`Death`；全屏=遍历非友军 `StatusC` 批量处决 |
| 菜单实现 | Java 层条款 UI 可见；功能菜单为游戏内叠加（无障碍树只有 `Game view`）。逻辑应在 QK/斌哥运行时 Hook（DEX 在百度壳内，静态 jadx 看不到 `SplashActivity` 实现） |

## 2. 过检测怎么做的

### 2.1 签名伪造（`libqkcheck.so`）

导出：

- `Java_com_game_apkverify_Check_getAPKCharacteristic`
- `Java_com_game_apkverify_Check_getSignInfo`
- 内部：`get_md5` / `check_sha1` / `deal_check_fail` / 读 `PackageInfo.signatures`

硬编码字符串：`526b7295424a894979a5bf5c4a9c3123`（与当前改包证书 MD5 **不一致** → 当作原包指纹回灌给校验）。

改包实际证书：

- DN: `CN=binge2.keystore, ...`
- MD5: `e571e96ec9428b88c9d3e358cbd3d655`
- SHA1: `dde5c4a389c45d64c3802df7fc911171f3537019`

### 2.2 壳与启动链

```
StubApplication (baiduprotect)
  → 解密 DEX
  → com.qk.game.GameApplication
  → SplashActivity → MainActivity（包 Unity）
```

`libbaiduprotect.so` 已加载；`libtoolChecker.so` 为 RootBeer（原厂反 Root，未必被改包关掉）。  
Frida 直接 attach 会被打掉（`agent connection closed`），动态分析需 spawn + 反检测或纯 mem 读写。

### 2.3 借鉴到原包时的过检策略

1. 原包自签后，用同等思路 patch `apkverify` / 签名校验点，或直接 nop `deal_check_fail`。  
2. 若原包无 QK，不必整套换 Activity；**战斗功能可只改 `libil2cpp.so` / 运行时 Hook**。  
3. 先对比原包是否也有百度壳；有壳则改 so / 资源比改 DEX 更稳。

## 3. 战斗漏洞点（可直接借鉴）

引擎：Unity IL2CPP（metadata v31）。  
产物：`06_dumped/物质与魔法/il2cpp/`（`dump.cs` / `script.json`）。

### 3.1 核心类型 `StatusC`

| 字段 | Offset | 用途 |
|------|--------|------|
| `isHero` | `0x7D` | 英雄单位 |
| `isBoss` | `0x84` | Boss |
| `isAlly` | `0x91` | 友军 |
| `myTeam` | `0xA4` | 队伍枚举 |
| `isDead` | `0xD9` | 死亡 |
| `huDunHp` | `0x154` | 护盾 |
| `curHp` | `0x1E0` | 当前血 |
| `backMiss` | `0x268` | 背击/闪避类 |
| **`wudi`** | **`0x269`** | **无敌开关** |
| `inWudiTime` | `0x310` | 无敌剩余时间 |

官方 Buff：`BuffType.BuffWuDi = 2`，协程 `StatusC.OnWudi`。

### 3.2 关键方法 RVA（`script.json` / dump）

| 方法 | RVA |
|------|-----|
| `StatusC$$ReduceHp` | `0x162DCDC` |
| `StatusC$$CalDamage` | `0x162DEB8` |
| `StatusC$$OnDamage` | `0x162E950` |
| `StatusC$$OnMagicDamage` | `0x162F9C0` |
| `StatusC$$Death` | `0x1630D4C` |
| `StatusC$$OnWudi` | `0x163275C` |
| `StatusC.<OnWudi>d__204$$MoveNext` | `0x163BE24` |

文件偏移（第二个 PT_LOAD：`va=0x125bbf4` → `off=0x1257bf4`）：

- `OnDamage` 内读 `wudi` 的指令 VA `0x162EB28` → file `0x162AB28`

### 3.3 无敌：游戏原逻辑（改包应是“强制置位”）

`OnDamage` 片段：

```text
ldrb w8, [x19, #0xd9]   ; isDead
cbnz → return
ldrb w8, [x19, #0x269]  ; wudi
cbnz → return           ; 无敌则直接返回（不扣血）
```

`OnWudi.MoveNext` 会 `strb` 写 `0x269`，结束时清零。

**原包复现无敌（任选）：**

1. **运行时**：对 `isAlly==true` / `isHero==true` 的 `StatusC*` 循环写 `*(bool*)(obj+0x269)=1`（可顺带刷 `inWudiTime`）。  
2. **静态 patch**：在 `OnDamage`/`ReduceHp` 对友军提前 `ret`。  
3. **调用官方 API**：对己方 `StartCoroutine(OnWudi(null, 999999f))`（需找齐参数/实例）。

### 3.4 秒杀 / 全屏秒杀（推断 + 落点）

菜单文案未在明文 so/dex 出现（多半壳内或贴图字），但数值落点清晰：

**单体秒杀**

- Hook `StatusC$$OnDamage`：若 `atk.isAlly && !this.isAlly`，把 `damage`/`realDamage` 改为极大，或直接 `ReduceHp(this, this.curHp, false)` / `Death()`。  
- 或 Hook `CalDamage` 出口，放大 `totalDamage`。

**全屏秒杀**

- 枚举场景内所有 `StatusC`（或战斗单位列表，需再找 `SpawnPlayerC` / Unit 管理器）。  
- 过滤 `!isAlly && !isDead`（按需跳过建筑 `isBuild`）。  
- 批量 `curHp=0` + `Death()`，或 `ReduceHp(amount=curHp)`。

`ReduceHp` 本体会：`curHp -= amount`，`<=0` 时 `isDead=1` 并跳 `Death`。

## 4. 建议的原包改造路径（星光菜单）

1. 抓一份同版本**原包**进 `02_apks/物质与魔法/`，对 `libil2cpp.so` 做二进制 diff（确认斌哥是否静态改过指令；当前看 `OnDamage`/`ReduceHp` 像原版逻辑，功能更像运行时 Hook）。  
2. 星光菜单侧新增 `WzymMod`（或同类）：  
   - 无敌：写 `wudi` / 调 `OnWudi`  
   - 秒杀：Hook `OnDamage`/`CalDamage`  
   - 全屏：扫 `StatusC` 列表后 `Death`  
3. 过检：只处理原包实际校验点（签名 MD5、百度/渠道校验）；不必整套移植 QK Splash。  
4. 动态验证：进战斗后开菜单，用 Frida/`mem` 看友军 `+0x269` 是否变 1、敌军 `curHp` 是否被打穿（需绕过百度反 Frida）。
