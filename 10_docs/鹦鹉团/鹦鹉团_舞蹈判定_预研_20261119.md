## 1. 对标样本：音舞光年到底怎么做的

### 1.1 自动跳舞（"模拟真人"）

来源：`10_docs/音舞光年/音舞光年_0.300.42_星光菜单_模拟真人_20260822.md` §2/§5.3、
`mod菜单/starry-mod-menu/app/src/main/jni/Games/YwgnMod.cpp`（373 行，已通读）。

实际落地形态**不是**"模拟手指点击"，而是**在评分提交函数的入口按概率改分数**：

~~~
菜单 ON → hook libil2cpp 里 HybridCLR 的 invoke 4 参桩（file=0x2BAC188，fallback 0x2660BDC）
        → 桩入参 a1 = MethodInfo*，桩内 il2cpp_method_get_name 判定方法身份
        → 命中 SendScore / AddScoreToSendList（pre）或 CalculateTheScore / CalcNoteScore（post）
        → 改 a2 参数块 +0x8（或 valuetype params[0]）= ScoreType（2/3/4/5）
        → 原函数继续执行 ⇒ 局内自动出分、角色自动跳
~~~

关键细节（这三条是反复返工后才定下来的）：

1. **必须带方法身份过滤**：无过滤钩全局 invoke（每秒数千次）→ SIGSEGV@+0x18（`YwgnMod.cpp` 头注释）。
2. **pre / post 时机不同**：`SendScore` 族在调用**前**改分；`CalculateTheScore` / `CalcNoteScore` 在调用**后**改分——调用前改参会破坏 timing，实测**全 Miss**（0.300.42 文档 §6 末行）。
3. **枚举值必须实测**：该作 `ScoreType` = Good 2 / Great 3 / Perfect 4 / Perfect+ 5（`YwgnMod.cpp` SCORE_* 常量）。

历史弯路（防止在鹦鹉团重犯）：
- 先试 `BubbleConfig.isAutoPlay` 写静态/实例字段：日志有、局内无感（§5 明确"不必再绕 isAutoPlay 写字段"）。
- `il2cpp_runtime_invoke` 过滤：HybridCLR 热更方法 `score=0`，不走导出。
- MethodPointer 白名单：对局 `patch=0`，且 MP 常为 invoke 4 参，native 三参钩 → SIGSEGV。

### 1.2 判定概率可调

同一挂点的第二件事：菜单 4 条滑条（Perfect+ / Perfect / Great / Good，0–100，默认 85/13/1/1）→
`PickHumanScore()` 用 xorshift 生成 0..9999，按累计权重落到某个枚举值（`YwgnMod.cpp` L175-215）。

- **不需要凑满 100**：按 total 归一化，全 0 回落默认。
- **写入前校验**：`WriteScoreSlot()` 只在当前值 ∈[0,6] 时写；`IsValidHeapPtr` 做指针校验。
- **热路径不打日志**：`LogScoreHit` 只打前 8 次与每 50 次。

### 1.3 抓点文档的补强

`10_docs/音舞光年/音舞光年_菜单功能抓点_20260809.md`：
- 斌哥壳下"功能开关"不在 prefs，而在壳 BSS 旗标 `shell_rw_bss+0x172c`；对局内会清 0 ⇒ 不能当对局内唯一镜像。
- 玩法在 HybridCLR 热更层时 il2cpp dump 看不到，必须运行时 dump 明文 PE（该作在 `0x7640000000` 命中 `MZ+PE`）。
- 静态 dump 里 `AutoPlay` 命中全是 DOTween 枚举 —— **同名不等于同义**。

## 2. 挂点类型学（四类，按可靠性排序）

| 类型 | 做法 | 适用 | 可靠性 | 典型反例 |
|---|---|---|---|---|
| **T1 判定结果写入** | hook 判定函数，改返回值或返回前的结构体字段 | 判定在可 hook 的 native 方法里 | ★★★★ | 音舞光年：pre 改参破坏 timing → 全 Miss |
| **T2 评分/结算结构体写入** | 在"上交"边界改分数容器字段 | 判定不透明，但有明确的提交点 | ★★★★ | 需指针与值域校验，否则写飞闪退 |
| **T3 时间轴驱动 / 输入模拟** | 按谱面时间自动触发按键 | 判定依赖真实输入时间戳；或只能"表演" | ★★☆ | 拿不到谱面；模拟时序误差 → Good/Miss |
| **T4 解释器桩（invoke / pcall）** | hook 通用调用桩，按方法名过滤后改参 | 判定在脚本层（HybridCLR/Lua），无稳定符号 | ★★★（必须带过滤） | 无过滤 = 每秒数千次，必崩 |

**选择顺序**：T1 → T2 → T4 → T3。
T3 排最后不是难，而是它**回答不了"判定概率"**：输入模拟只能"跳得像人"，不能"必出 Perfect"。

| 引擎 | T1 | T2 | T4 | T3 |
|---|---|---|---|---|
| Unity IL2CPP(AOT) | Dobby hook 具体方法（RVA + 序言校验） | 结构体/消息体直写 | 有符号就别用 | 调 C# 输入组件（需伪造 PointerEventData） |
| HybridCLR 热更 | 无 RVA，退化为 T4 | T4 附带 | invoke 4 参桩 + 方法名过滤 | 同上 |
| xLua | Lua 函数替换（DoString monkey-patch） | 改 Lua 表 / 改包字节 | `lua_pcall` hook 注入 | Lua 定时器 / 动画事件驱动 |

## 3. "判定在哪"——三条互斥假设与判定方法

| 假设 | 快速判据 | 若成立首选 |
|---|---|---|
| H-C# 判定在 AOT | dump.cs 存在**返回判定枚举的方法**；判定枚举被 setter 之外的代码引用 | T1 |
| H-Lua 判定在脚本 | xLua/HybridCLR 存在；判定枚举**只出现在协议类**；包 ID 在脚本侧定义 | T4 / 脚本内替换 |
| H-服务端权威 | 存在"逐键提交 + 结果回包"协议（客户端报分、服务端回判定与真实分） | 只能改**表现**，成绩不可信 |

**决定性做法**：对判定枚举的 setter 做 **native xref 计数**（BL/B 目标扫描）。
setter 调用者 = 0 且无 native 方法返回该枚举 ⇒ 判定不在这层，别再猜。
> 该方法在鹦鹉团已实测生效，见 `鹦鹉团_1.0.7_判定与自动跳舞_20261119.md` §3。

## 4. 迁移 checklist

1. **引擎三定**：`libil2cpp.so` / `global-metadata.dat` / `libxlua.so` / HybridCLR 特征（`Assembly-CSharp.dll` 是否 QK）。
2. **枚举定名与顺序**：Perfect/Great/Miss 的数值顺序决定"强制 max"写哪个值。
3. **位置定层**：按 §3 证伪，得出 C#/Lua/服务端结论，每条都要 xref 或字符串证据。
4. **协议定边界**：找 commit / end / balance 包与包 ID；确认服务端是否回传判定。
5. **挂点定级**：按 §2 选，写 RVA/file_off + 序言期望值 + 指纹（只用不被混淆改名的锚点，`hook-rules.md` §24）。
6. **五步门禁**（`skill/re-implement/hook-rules.md` §22）：静态定位 → calls>0 → 跨版本 diff → 首装日志 hit 计数 → 对照 1:1。
7. **概率可调**：滑条只做权重，归一化在代码里；全 0 回落默认；热路径不打日志。
8. **不改判定的时间语义**：只改"结果"，不动"何时算"。

## 5. 通用风险清单（方案必须覆盖）

| 风险 | 说明 | 缓解 |
|---|---|---|
| 服务端权威分 | 客户端报 nScore，服务端回 nRealScore 并累计 | 只承诺本地表现；方案明写 |
| 逐键时序校验 | 每键 nTimeSep/beatType 若被校验，乱改被拒 | 先只改分数不改键序；看回包 errorCode |
| 判定与动画耦合 | 只改分数会出现"Perfect 音效 + 失败动作" | 优先改判定结果，让下游一致 |
| 时序破坏 | 判定前改参数会改内部状态机 | pre/post 分别验证 |
| 指针写飞 | 未校验直接写 → SIGSEGV | 指针校验 + 值域校验 + 写后复核 |
| 热更覆盖 | 改本地 Lua/bundle 会被热更覆盖 | 运行时注入，不落盘改包 |
| 反作弊/签名 | 渠道 SDK 校验（TapTap）与包完整性 | 与过检分开做（`login/taptap-web-login.md`） |
