### 3.1 挂点与通道

| 项 | 值 |

### 3.2 注入的脚本

- 载体：`ywtMod.cpp` 内 `static const char kYwtPatch[] = R"YWT(...)YWT"`，**不落盘、不改 assets 里的 lua bundle**（理由：热更按文件名整替下发，落盘改 lua 会被下次热更覆盖）。
- 幂等守卫：脚本首行 `if rawget(_G, "__ywt_ver") == 7 then return 1 end`；全成功才写 `__ywt_ver = 7`。
- 执行方式（`RunPatch(L)`）：
  1. `int top = lua_gettop(L)`（**存绝对高度**）；
  2. 用 `xpcall(function() … end, debug.traceback)` 把脚本包一层，异常带 Lua 行号；
  3. `luaL_loadstring(L, src)` → 成功则 `g_origPcall(L, 0, 1, 0)`；
  4. 返回值 `1`＝装好、`0`＝目标未 require（1 s 后重试）；
  5. 结尾 `lua_settop(L, top)`（**绝对高度，不是 -1**）。

### 3.4 注入成功判据（日志行原文，`grep '\[Ywt\]'`）

按出现顺序，一条链都出现才算装好：

1. `[Ywt] lua api ok loadstring=%p pcall=%p tolstring=%p` ← 符号齐（缺则 `[Ywt] libxlua 符号缺失 …`）
2. `[Ywt] hooked lua_pcall @ %p orig=%p` ← 装钩成功（失败 `[Ywt] DobbyHook lua_pcall rc=%d orig=%p`）
3. `[Ywt] lua_pcall hit L=%p` ← 首次命中（只打一次）
4. `[Ywt] state registered slot=%d L=%p` ← 每个 lua_State 一条
5. `[Ywt] patch try slot=%d ok=%d ctrl=%d (native view) tries=%d` ← **主判据**（`ok=1` 才算该 state 装好；`ctrl` 位仅供参考，native `lua_getglobal` 与 xLua 的 `_G` 未必同表）
6. Lua 侧副作用行（出现即证明脚本真跑到）：`[Ywt] env cands=%d` / `[Ywt] env HIT src=… keys=… hasCtrl=… fn=…` / `[Ywt] ctrl wrapped OnJudgeResult src=…` / `[Ywt] AdjustJudge hooked src=typeMode` / `[Ywt] OnUpdate armed (per-frame env check)` / `[Ywt] late ok ojr=… wrapped=%d`
7. 收官：`[Ywt] patch ok ojr=no (env 未出现，late fix armed)`（进了玩法但 env 未出现时）或静默成功；未就绪：`[Ywt] patch pending miss=RhythmMasterVM`
8. 运行期观测：`[Ywt] AJ obs=%d auto=%s judge=%s in=%s use=%s norm=%d pick=%d skip=%d`（每 50 次一条）、`[Ywt] OJR count=%d pick=…`（每 50 次）、`[Ywt] OJR in=%s out=%s w=%d src=%s`（首次）

失败行（出现即失败）：`[Ywt] loadstring err: %s` / `[Ywt] patch err: %s` / `[Ywt] patch give up slot=%d tries=%d`。

### 3.5 栈漂移自检（**必须实现**，这是已发生过的真实事故）

- 事故：`lua_settop(L,-1)` 在 Lua 5.3 是**空操作**（实现是 `L->top += idx+1`，`idx=-1` ⇒ `+0`），注入返回值 0/1 留在栈顶，业务 `lua_pcall` 按 `func = top - nargs - 1` 反推时把 number 当函数 ⇒ `LuaException: attempt to call a number value`，登录协程中断。
- 现行规则：
  1. `Hook_lua_pcall` 入口 `const int topEntry = lua_gettop(L)`；
  2. 所有中间 C API 序列（`PushCfg` / 取 `__ywt_ojr` 等）用完立刻 `lua_settop(L, topEntry)`；
  3. 出口无条件复核：`now != topEntry` ⇒ `LOGE("[Ywt] stack drift %d -> %d, restoring", topEntry, now)` + `lua_settop(L, topEntry)`；
  4. `RunPatch` 自己的 `top` 与 `topEntry` 是两层独立保护。
- **通过标准**：整局 `logcat` 里 `[Ywt] stack drift` **0 行**。出现即视为注入层未复刻到位（先查 `settop` 是否写成 `-1`）。

### 5.3 关键陷阱（都踩过，复刻必须保留对策）

1. **`libc++_shared.so` 必须一起进包**：`libstarry_magic.so` 以 `APP_STL=c++_shared` 编出，`DT_NEEDED` 含 `libc++_shared.so`，而底包 `lib/` 里**没有**（【实测 2026-11-25】新包同样没有）⇒ 不加则 `dlopen failed: library "libc++_shared.so" not found`，`JNI_OnLoad` 永不执行、菜单只剩 Java 壳。
2. **压缩方式跟底包**：底包 `extractNativeLibs=true` ⇒ so 允许 Deflate；新增 so 的 `compress_type` 取底包 `libil2cpp.so` 的值，脚本有断言；`classes14.dex` 用 Deflate。
3. **`SO_TAG` 默认值坑**：`build_ywt.sh` 默认 `[ywt]`（小写），so 里实际烘焙的是 `[Ywt]` ⇒ `--install` 会在校验处误报「包内 so 不含标签 [ywt]」；绕过法是单独跑 `install_starry_apk.sh --so-tag '[Ywt]'`。复刻时建议先改默认值（属脚本改动，需 lead 放行）。
4. **AXML 两个坑**：resource map chunk 头是 **8 B**（`(size-8)//4` 算条数，本包 `size=184` ⇒ 44 条）；新增属性必须有 res id（`foregroundServiceType`=`0x01010599`），否则 `aapt2` 能复读、平台读到 0。
5. **`aapt2` 只能在完整 APK 上用**（裸 AXML 报 proto 反序列化失败）⇒ 放在第 8 步成品上做，脚本内用 `axml_inspect.py --assert-map` 做结构 + res id 双断言。
6. **超时**：2 GB 包签名阶段曾被 120 s 前台预算打断并留下截断 APK（`apksigner verify` 报 not a ZIP）⇒ 后台跑 + 轮询日志。

### 5.4 装机与验收纪律

- 重签证书（`starry_release.jks`，CN=StarryMagic）与原包（CN=Meta48）不同 ⇒ **不能覆盖安装**，须卸载重装（外置数据由 `install_starry_apk.sh` 备份+归位+chown）。
- `stage=inject` 装机前门禁需 `TAP_MODE_CHECK=0` 逃生门（本就不改登录 dex）；`stage=full` 是真改，**禁用逃生门**。
- 装机后 `post_install_precheck.sh --game 鹦鹉团`，再请用户上手；验收以运行证据为准，不以构建成功替代。
