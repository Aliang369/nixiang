### 1.1 xref 复算方式（下次换版本照抄）

~~~python
text = so[0x31057fc : 0x31057fc+0x4b9edb4]        # R|X 段
w = np.frombuffer(text, '<u4'); op = w >> 26
idx = where(op in (0b100101 BL, 0b000101 B))
target = (0x31097fc + idx*4) + sign_extend26(w[idx] & 0x03FFFFFF, 26)*4
# 找 target == 目标 RVA 的 pc ⇒ 调用者；再查 _methods.tsv 最近的小于等于地址
~~~
说明：dump.cs 的 `RVA` 是 ELF VA，`Offset` 是文件偏移，两者差恒为 0x4000（本包实测），与 `hook-rules.md` §6 口径一致。

## 3. 判定位置定层：三条硬证据排除 C#

| # | 检查 | 结果 | 含义 |
|---|---|---|---|
| E1 | `OperationResult` 在 dump.cs 的全部出现 | 16 处，除枚举定义外只有 `KeyResult` 的字段/属性/`get_`/`set_`，**没有任何方法签名返回它** | 没有 C# 判定函数 |
| E2 | xref：`KeyResult.set_operationResult` @ `0x3F69D38` | **callers = 0**（唯一相关是 `ResetoperationResult` 调 `set_operationResultSpecified`） | 判定结果从不被 native 代码写入 |
| E3 | xref：`KeyCommit.set_nScore` @ `0x3F691E4`、`GASCommitOperationReq..ctor` @ `0x4069EE0` | **callers = 0 / 0** | 提交包不是 C# 造的 |
| E4 | 类型普查（Assembly-CSharp 6,267 类型） | 无"局内玩法控制器"：`*Mgr/*Manager/*Ctrl` 里只有 `RoomSceneMgr/RoomPlayerMgr/PlayerInputMgr/ActorCacheMgr/DanceFileManager/MusicLightManager`，全是房间/装配/灯光 | 对局循环不在 C# |
| E5 | `PressKeyBaseScoreConfig(ID,Socre)`(22714) / `PressKeyRateConfig(ID,Rate)`(22730) | 同段是 `DataFactory → TrackData/ClipData/ModuleDataBase`（BeamEditor 编辑器管线） | **是编辑器配置表，不是判定**（Lead 的判断正确） |
| E6 | `DanceResultTool`(34073) | 只有 `OnTransformChildrenChanged / SetCharacterLayer` | 名字像结算，实为**换层**，勿挂 |
| E7 | Lua 侧 | `lua_core_net` 定义提交/回包/通知包 ID；Lua→C# 桥 `Net4Lua.CallServer(ushort,byte[],ushort)` 的**唯一** native 调用者是 `DanceStartupNet4LuaWrap._m_CallServer_xlua_st_`(0x3BECE08) | 判定 + 发包都在 Lua |

**结论（实测级，已按 §11 修正）**：`OperationResult` 的产生点**不在 libil2cpp 托管代码里**；提交包构造同样不在 C#（E3）。APK 内 Lua 也没有判定算法 ⇒ 判定载体仍是**待验证项**（远端热更 Lua / 服务端二选一，§11）。C# 只提供「发包(bytes)」「输入组件」「资源/动画」三件基础设施。
⇒ **"判定概率可调"的主战场是 Lua**（recon 归口），IL2CPP 侧只能做「注入桥 / 包体改写 / 输入模拟」。

## 5. 自动跳舞：三条实现路线与取舍

| 路线 | 做法 | 能否同时控判定 | 可靠性 | 结论 |
|---|---|---|---|---|
| **A. Lua 侧驱动（推荐）** | 在判定入口按谱面时间自动产生"按键事件/判定结果"（recon 定位判定函数后注入） | ✅ 直接产出 Perfect/SPerfect | ★★★★ | 主方案 |
| B. C# 输入模拟 | hook `LuaManager` 实体做 tick，按谱面时间调 `PressActionCtrl.OnPointerDown/Up`（或直接调 `OnPress` 委托） | ❌ 只能"按得准"，判定仍由 Lua 算；时序误差 → Good | ★★★ | 仅作 A 的补充（A 不可行时） |
| C. 直接改判定/分数结果 | 在 `Net4Lua.CallServer`（2372/2403）改包体 | ⚠️ 只改上报值，服务端 `nRealScore` 可能覆盖 | ★★★ | 兜底（§6 备份） |

**推荐组合**：A 为主（自动跳舞 + 判定概率同一注入点），C 为兜底（A 失效时保底出分）。
B 只在"必须走纯 native、不能注入 Lua"时使用，且必须能读到谱面时间（`lua_config_music` 里是 `{id,time}` 表，recon 已验证可解）。

## 6. 判定概率：实现方案

### 6.1 主方案（Lua，与音舞光年等价）

在判定结果落地处（recon 定位的 Lua 函数）注入权重采样：
`Miss/Good/Great/Perfect/SPerfect/SPerfectPlus` 六档，菜单滑条只给权重，代码内归一化，全 0 回落默认（85/13/1/1 那套沿用）。
**关键约束**（音舞光年血证）：只改"结果"，不改"何时算/参数"——否则破坏 timing → 全 Miss。

### 6.2 兜底方案（IL2CPP，H1 包体改写）

`Net4Lua.CallServer(reqId, bytes, rspId)` 入口处：

- `reqId == 2372`：protobuf 解码 `GASCommitOperationReq` → 对每个 `KeyCommit` 按权重把 `nScore` 改成对应档位的分值（**需要先取到每档基准分**：`PressKeyBaseScoreConfig` 或实测对比）。
- `reqId == 2403`：改 `SingleBalanceResult` 的 `nScore / nKeyPerfect… / nAccuracy`（注意总和自洽，否则服务端大概率判异常）。

改包实现要点：只动 varint 字段、保持字段顺序与长度可重算；改完长度变了必须重建包体（不能原地覆盖）。

### 6.3 "强制 max"（全 SPerfectPlus）为什么不建议

- 判定结果若同时驱动动画/音效/连击，只改上报值 → 本地表现与服务端记录不一致，结算页会"翻车"（音舞光年踩过：hits>0 但仍全 Miss 的表现）。
- `nMaxComb`/`bAllPerfect`/`nAccuracy` 与逐键结果必须自洽，硬拉 max 极易被服务端一致性校验拒绝。

## 7. 联网校验与成绩上传风险（必须写进交付说明）

| 风险点 | 依据 | 影响 | 缓解 |
|---|---|---|---|
| 服务端权威分 | `KeyResult.nRealScore`（dump.cs:166096 区块）与 `SingleBalanceResult.nRealScore`(168051) | 本地改的分不进排行/成长 | 明写"仅本地表现" |
| 逐键提交 | `GASCommitOperationReq.arrKeyCommit[KeyCommit.nScore]` | 每键都上报，服务端可做上限/一致性校验 | 只改分数、不改键序列与 `beatType` |
| 键时序 | `KeyGoal.nTimeSep` / `CommitOperationReq.nKey` | 乱序/跳键可能触发 `nErrorCode`（`GASCommitOperationResp`） | 观察回包 errorCode 再决定强度 |

| 优先级 | 注入点 | 理由 |
|---|---|---|
| **P1** | `RhythmMasterVM.GetJudgeResult`（`__052` proto#4）**＋** `DanceRhythmVM.GetJudgeResult`（`__012`）**＋** `DanceKeyFallingVM` 同名 | 三处同名覆盖，注入必须全覆盖；改这里下游 `AddCombo/AddScore/AddSendKey/GetClientGrade` 全部一致 |
| P2 | `RhythmMasterVM.GetJudgeResultByOffset`（proto#5，评分档） | 只影响"分数档"，不影响"判定档"，会和上报档位不一致 ⇒ 仅作 P1 的补充校正 |
| P3 | `AddScore` 单改 | 档位与分数矛盾，**不推荐** |

注入实现（Lua monkey-patch，运行时）：
~~~lua
local VM = rawget(_G, "RhythmMasterVM")           -- 全局读写一律 rawget/rawset
local orig = VM.GetJudgeResult
VM.GetJudgeResult = function(self, diff, ...)
  local ms = rawget(_G, "__mod_menu_cfg")
  if not ms or not ms.judge_on then return orig(self, diff, ...) end
  local r = math.random(1, 100)                    -- 权重表：SPP/SP/P/G/Good/Miss
  ...
  return VM.JudgeResultType.<pick>
end
~~~
要求：① 权重滑条只给权重，归一化在代码里；② 全 0 回落默认；③ 热路径不打日志（每 50 次一条）；④ **不改 diff、不改 GetJudgeOffset**（只改档位，不动时间语义）。
