## 6. 安全与幂等

- **不覆盖输入**：只读底包，所有中间物落 `13_scratch/`，成品落 `08_output/鹦鹉团/`；
- **不卸载/不清数据**：装机只走 `install_starry_apk.sh`（默认 `-r` 覆盖安装，异签名才升级行为），脚本内无 `uninstall`/`pm clear`；
- **装机是单独一步**：必须显式 `--install`，否则第 9 步只打印「跳过」；
- **幂等**：中间目录每次重建（`rm -rf login_dex`、`rm -f unsigned/aligned`），同名成品按日期覆盖当日文件；重跑不会在包里叠加 dex（`assert menu_name not in names` 会挡住下标冲突）；
- **dry-run 不写盘**：`mkdir` 在 dry-run 分支之后，实测未创建 `08_output/鹦鹉团` 与 `13_scratch/ywt_build_*`。

### 8.4 本轮踩到的两个真坑（都已修，写进脚本注释）

1. **resource map chunk 头是 8 B 不是 16 B**。按 `(size-16)//4` 算条数会少数 2 条 ⇒ 追加起点错位 ⇒ 后续所有属性的 res id 整体偏移（`aapt2` 照样能复读，平台读到的却是 0）。本包实测 `size=184` ⇒ 正确是 `(184-8)//4 = 44` 条。
2. **新属性名必须有 res id**。首版给 `<service>` 加了 `android:stopWithTask`，它不在本包 map 里、脚本也没给补 res id ⇒ `axml_inspect --assert-map` 直接判 `res id == 0`。修法是**去掉该属性**（MenuService 不需要它，默认 false）。同理 `foregroundServiceType` 必须显式补 `0x01010599`（常青 attr）。

### 8.5 aapt2 为什么没在本脚本里跑

实测 `aapt2 dump xmltree --file AndroidManifest.xml <裸 AXML 或只含 manifest 的 zip>`：
```
$ aapt2 dump xmltree --file AndroidManifest.xml stub.apk     # stub 只含 AndroidManifest.xml
error: failed to deserialize proto AndroidManifest.xml      # rc=1
$ （加 resources.arsc 后）warn: resource …:anim/abc_fade_in … no such path exists  # rc=1，解析不出树
```
⇒ aapt2 需要一个**完整 APK**（含 res 与 arsc）才能复读 Manifest。
因此把 aapt2 关放在**组包脚本第 8 步**（成品已是完整 APK）：`aapt2 dump xmltree --file AndroidManifest.xml <成品>` + 断言含 `E: provider`、`StarryInitProvider`、`MenuService`，失败即 `die`。脚本内则用 `axml_inspect --assert-map` 做结构 + res id 双断言（比 aapt2 更严，专治 res id 错位）。
