## 3. frida 可用性评估（本轮的核心负结果）

### 3.1 三种注入方式对比（选定：frida-server attach）

| 方式 | 是否改动包 | 成本 | 本轮结论 |

### 3.2 实测：frida-server 无法注入任何 app 进程

```
# 1) 游戏进程对 frida 不可见（但 adb 能看到）
adb shell pidof com.jinsaina.auditionsgo.gw        -> 10416
frida-ps -U | grep jinsaina                        -> (无)
dev.enumerate_processes() 命中                -> []        # 全量 283~286 条里没有它

# 2) 按 pid 直接 attach
dev.attach(10416)  -> TransportError: agent connection closed unexpectedly

# 3) 换系统应用验证「是不是游戏反调试」
dev.attach(10867 Calendar) -> TransportError: agent connection closed unexpectedly
dev.attach(14321 Camera)   -> InvalidArgumentError: dlopen failed: unable to stat file for the library
                              "/proc/14321/fd/5": Permission denied

# 4) 环境侧线索
/proc 挂载：proc on /proc type proc (rw,relatime,gid=3009,hidepid=invisible)
frida-server 启动日志：Unable to save SELinux policy to the kernel: Out of memory
```

**判读（只写能直接看出的）**：
- `Camera` 的报错把原因指得很明确：frida 读不到目标进程的 `/proc/<pid>/fd/*`（`Permission denied`）⇒ 注入前的前置访问就被拒；
- 同样的失败发生在**系统应用**上 ⇒ 不是《鹦鹉团》/QGSDK 的反调试，而是 frida-server 所处的 SELinux 域（`u:r:ksu:s0`）缺少对 app 域的 proc 访问授权；
- frida-server 启动时自述「Unable to save SELinux policy」与之一致。


- 含义：登录**没有拉起 TapTap 客户端**，是在内嵌 WebView 里完成的 ⇒ `DefaultTapLoginFragmentProvider.provide` 的「路由恒 Web」（改包方案 P3）**确实生效**。
