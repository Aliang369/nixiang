## 2. 改动点（before / after，行号＝当前文件）

三处改动全部在 `armAdjust()` 内对 `typeMode.AdjustJudge` 的包装里（当前 `ywtMod.cpp:423-467`）。

### 2.1 ① 先调原函数，再返回伪档（确定性缺陷修复）

旧（`ywtMod.cpp:439-443`）：

```lua
        return v                     -- 旧：pickJudge 命中后直接 return，aj() 根本没跑
      end
      AJ.skip = AJ.skip + 1
    end
    return aj(tm2, judgeType, ...)
```

新（`ywtMod.cpp:459-467`）：

```lua
    -- ★2026-11-20 task-5 ① 先调原函数、再返回伪档：
    --   原版在 judge_on 分支「pickJudge 后直接 return v」，把 aj() 整段跳过了；而
    --   OnAdjustJudge（加血/护盾/OnAttrSyncMyBlood）与 AddMyEnergy（能量）全在这个原函数里
    --   (__015:741-752) ⇒ 判定概率一开就「一定不加血、不加能量」。
    local r = aj(tm2, judgeType, ...)
    if v ~= nil then return v end
    return r
```

效果：`judge_on` 打开时，`DanceTMBattleBase:OnAdjustJudge`（hp 结算 + `OnAttrSyncMyBlood`）与 `AddMyEnergy` 照常执行，返回值仍用伪档（判定显示/后续档位不变）。

### 2.2 ② 自动档归一 7 → 6（只改送进原函数的入参）

新（`ywtMod.cpp:433-436`，插在 pickJudge 之前）：

```lua
    if c and c.auto_on and type(judgeType) == "number" and judgeType >= 7 then
      judgeType = 6
      AJ.norm = AJ.norm + 1
    end
```

依据（静态分析已定案，本任务直接采信）：
- 自动命中 `AutoHitTap` 硬编码 `SuperPerfectPlusPlusAdd=7`（`__117:4237-4240`）；
- `016/020 calcReduceHp` 用 judgeType 当 `Judge_Basehp` 的行键、缺行回退 `Miss` 行（`__020:321-338` / `__016:156-173`）；
- `015 AdjustJudge` 本身把 1..5 归一到 6（`__015:741-752`）⇒ 6 是「手动最高有效档」。

只降「送进原函数」的档位；`judge_on` 的伪档返回值不动（判定显示仍可为高档）。`auto_on` 关时完全不动，手动档位 1..6 也不受影响（条件要求 >=7）。

### 2.3 ③ 低频观测日志（每 50 次一条）

新（`ywtMod.cpp:452-458`）：

```lua
    AJ.obs = AJ.obs + 1
    if AJ.obs % 50 == 0 then
      log(string.format("[Ywt] AJ obs=%d auto=%s judge=%s in=%s use=%s norm=%d pick=%d skip=%d",
          AJ.obs, tostring(c and c.auto_on or false), tostring(c and c.judge_on or false),
          tostring(inType), tostring(judgeType), AJ.norm, AJ.cnt, AJ.skip))
    end
```

计数器 `AJ` 增补 `obs` / `norm`（`ywtMod.cpp:407`）。旧版「每 50 次 pick」日志保留（仅在 `judge_on` 命中时打）。
