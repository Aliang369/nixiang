## 1. native 侧逐项证据

### 1.1 `libqkcheck.so`（14,016 B）——**有指纹计算，无本地判定**

**导出符号（实测 `objdump -T`）**：
```
Java_com_game_apkverify_Check_getAPKCharacteristic   @0x0cfc
Java_com_game_apkverify_Check_getSignInfo            @0x0e10   （4 字节，纯跳转 getCertificateInfo）
_Z10check_sha1PcPKc                                  @0x1778   （4 字节：b strcmp@plt）
_Z15deal_check_failP7_JNIEnvP8_jobject               @0x177c
_Z10get_digestP7_JNIEnvP8_jobjectPKc                 @0x0e18
_Z18getCertificateInfoP7_JNIEnvP8_jobject            @0x1134
_Z18getX509CertificateP7_JNIEnvP8_jobject            @0x1350
_Z7get_md5P7_JNIEnvPc                                @0x18a0
```

**① `check_sha1` 不是哈希校验**：`0x1778: 17fffd2e b 0xc30 <strcmp@plt>` —— 函数体只有一条 `b strcmp`，
即「两个字符串直接比」，不计算任何摘要。

**② `check_sha1` / `deal_check_fail` 在本 so 内**无任何调用者****（实测：`objdump -d | grep -E "0x177[8c]"` 零命中；
`adrp 0x1000 + add #0x77c/0x778` 也零命中）。`deal_check_fail`（会拿 `Activity` 调 `finish`）因此**不可达**。
> 证据级别：实测（静态指令级）。残余风险：若有外部 `dlsym` 调用者（本包 Java 侧只声明了 2 个 native 方法，未见其它），
> 判 **推断：不可达**。

**③ `getAPKCharacteristic(Context, String)` 的语义＝**算一个指纹串**（反汇编逐段读）**：
`0xd1c` `getX509Certificate` → `0xd30` `get_digest(env, cert, "SHA1")` 得证书 SHA1（40 hex）
→ `0xd44` 取 JNI `GetStringUTFChars`（第 2 个 Java 参数）→ `strcpy`+`strcat` 拼成 `certSHA1 + 入参`
→ `0xda4-0xdb8` 从 `.rodata 0x1c8d` 一次性 `ldp q1,q0` 搬 **32 字节常量** `526b7295424a894979a5bf5c4a9c3123` 追加，并在 +`0x20` 处补 `\0`
→ `0xddc` `get_md5` → `0xdfc` 返回。
⇒ 返回值 = `MD5(certSHA1 + 调用方字符串 + "526b7295…3123")`。**该常量是拼接盐，不是「期望签名」**。
> 证据级别：推断（反汇编级，链路完整无分支歧义）。补证：全 so 只有一个 32-hex 常量（实测 `strings | grep -E "^[0-9a-f]{32,40}$"` 仅此一条）。

**④ 这个常量不是本包的签名/整包哈希**（实测）：官方 cert DER SHA1 = `35a8e7b1…`；APK 文件 SHA1 = `21f45f57…`，均 ≠ `526b7295…`。

**⑤ 加载条件**：`com/quicksdk/QuickSdkApplication.smali:107-126` —— 先判 `nativeLibraryDir/libqkcheck.so` 是否存在，
存在才 `System.loadLibrary("qkcheck")`；`QGSdkUtils.smali:3371/3388` 同款判断。
⇒ **把 so 删掉也不会崩**（代码自带 exists 兜底），但没必要（它不阻塞）。

## 5. 改包后开机验收自查顺序（照这个顺序看，最快定位）

1. **进程活着吗**（最先看，排除自杀式门闩）：
   `adb shell pidof com.jinsaina.auditionsgo.gw` → 启动后 20 s 仍在且 pid 不变 ⇒ 无「改包即退」类检测。
2. **so 加载是否正常**：`logcat | grep -E "libqkcheck|qkcheck|UnsatisfiedLinkError|dlopen"`
   —— 预期出现一次 loadLibrary qkcheck；出现 `UnsatisfiedLinkError` 说明 so 被误删/abi 不匹配（非签名问题）。
3. **QGSDK 初始化**：`logcat -s BaseLib:V` → 期望 `QuickSdkApplication onCreate`；
   `logcat | grep "quickgame.ThirdManager"` → 期望 `start init tap` / `end init tap`。
4. **TapSDK 初始化（最关键）**：`logcat | grep -E "TapInitializer|TapSDK-TapSdkCore"`
   —— 出现 `1001`/`包名、签名错误`/`CONFIG_ERROR` ⇒ **P4 没生效或回灌值写错**，不要去查登录流程。
5. **登录入口**：点登录后 `adb shell dumpsys window | grep mCurrentFocus`
   —— 期望 `…TapTapLoginActivity`；`logcat | grep -iE "showSoftInput|WebView"` 出现 WebView ⇒ 网页登录已出。
6. **QGSDK 换票**：`logcat | grep "thridLogin"` → 有 `thridLogin tap loginWithScopes :` 与 openId/token 段。
7. **进游戏**：Unity 侧收到 `onLoginSuccess`；此步若失败但 4/5/6 都过 ⇒ 问题在 QGSDK 中台或游戏服（对应上表 #2/#3）。
8. **辅助判据**：`logcat | grep -c StarrySignSpoof` 必须为 0（运行时签名伪装未复活）。
