## 0. 结论速览（5 问 5 答）

| # | 问题 | 结论 |
|---|---|---|
| 1 | 注入通道 | **选 (b) 运行时注入**：hook `lua_pcall` 拿 `lua_State*` + `dlsym` 取 `luaL_loadstring`/`lua_pcall`，执行一段 monkey-patch 脚本。(a) 被否（要自造 27 字节变体头字节码，且换包即失效）；(c) 被否（热更整体替换 + 签名校验） |
| 2 | 注入时机 | **首次 `lua_pcall` 命中且 `__starry_targets_ready` 时注入**；在此之前每次 pcall 用 1s 节流重试；`luaL_newstate` 只用来存 L，不在此注入 |
| 3 | 三处 VM | **三处都是 Lua 全局类表**（`GETTABUP U0 "RhythmMasterVM"` + `CLOSURE` + `SETTABLE`），可直接替换表字段；**无 C# 注入的判定** |
| 4 | 两个功能 | 见 §5 完整骨架（概率包装 / 自动跳舞包装） |
| 5 | 崩溃与幂等 | 见 §6：`thread_local` 重入闸 + 每目标单次包装 + `pcall` 全包 + 失败静默 + 只在 Lua 线程调 API |

## 1. 通道选型

| 方案 | 做法 | 优点 | 致命问题 | 判定 |
|---|---|---|---|---|
| **(a) hook `LuaManager._LuaLoader`(RVA 0x3754CC4)** | 拦模块名，返回我们改过的字节码 | 早期、干净 | 必须自产 **27 字节变体头 + format=0x01 + sizes=4,4,8,8** 的 luac；换包/换引擎即失效；一处写错整块加载失败 | **否** |
| **(b) 运行时注入（选）** | hook `lua_pcall` → 拿 L → `luaL_loadstring` + `lua_pcall` 跑 patch 脚本 | 不需要编译字节码；不动资源；热更不影响；可幂等重试 | 需要在 Lua 线程、要防重入 | **是** |
| (c) 改 assets 里的 lua bundle 重打包 | 直接改 `lua_csys_dance.unity3d` | 最省事 | ① 包体签名/完整性 ② **CDN 热更整体替换**（`FileList_1.0.1.231.json` 的 lua 集合 = APK 120 项，说明热更按文件整替）③ 我们已确认 Lua 容器是多帧 LZ4，重打包要自己写 packer | **否** |

### 1.1 为什么 (c) 一定活不过热更（判断依据）

- 实测：设备 `files/Android/FileList_1.0.1.231.json` 里 lua 模块集合 = APK 的 120 项（APK 多 1 个 `lua.unity3d`），**说明热更按"文件名整替"下发**，不是增量补丁。
- 实测：`files/Android/` 下已有 4 个被替换过的 lua bundle（`lua_main` 20,528 B vs APK 20,461 B；`lua_csys_act` 382,529 vs 382,346），证明"改本地会被下一次整体替换覆盖"是真的。
- ⇒ 任何"落盘改 Lua"的方案在下次热更后失效；运行时注入不受影响。

## 2. libxlua.so 符号实测（方案 b 的地基）

文件：`06_dumped/鹦鹉团/base/libxlua.so`（1,367,864 B，来自 APK `lib/arm64-v8a/`）
命令：`llvm-nm -D -S --defined-only`（**实测**，489 个动态符号，未 strip）

| 符号 | 偏移 | size | 用途 / 可 hook |
|---|---|---|---|
| `lua_pcall` | 0x64FA4 | 0x44 (68 B) | **hook 点**（拿 L）；序言 `d100c3ff a9027bfd 910083fd f81f83a0`（16 B 干净） |
| `luaL_newstate` | 0x2CD04 | 0x48 (72 B) | 备选（拿 L 的最早点，但此时不能注入） |
| `luaL_loadstring` | 0x2C524 | 0x64 | 注入用的编译入口（**源码**，非字节码） |
| `luaL_loadbufferx` | 0x2C43C | — | 备选（带 chunkname，便于报错定位） |
| `lua_getglobal` / `lua_setfield` / `lua_rawget`/`lua_rawset` | 0x28524 / 0x28FF0 / 0x288DC / 0x291B0 | — | patch 后读写全局用 |
| `lua_gettop`/`lua_settop`/`lua_type`/`lua_pushboolean`/`lua_pushinteger`/`lua_pushstring`/`lua_tolstring`/`lua_pushcclosure` | 见 nm | — | 菜单开关回传用 |

**解析器实测在编**：`luaY_parser`、`luaX_next`、`luaX_syntaxerror` 等符号存在；字符串表里有 `unexpected symbol` / `malformed number` / `Lua 5.3` ⇒ **`luaL_loadstring` 可直接吃 Lua 源码**，不需要我们编译字节码。（推断→已有强证据：符号 + 报错串都在）

> 结论：方案 (b) 不需要自制 luac 变体头，彻底绕开 27 字节头的坑。

## 3. 注入时机

| 候选 | 为什么不用 |
|---|---|
| `luaL_newstate` 返回时 | 太早：此时 `_G` 里连 `require` 都没装，patch 目标表还不存在 |
| `LuaManager._LuaLoader` 命中 | 可用但不如 pcall 通用：只覆盖"按名加载"路径，热更走的加载分支可能不同 |
| **`lua_pcall` 首次命中（选）** | pcall 是"Lua 正在跑代码"的通用信号；此时 lua 已初始化完；且能天然拿到正确线程的 L |

**策略（C++ 侧状态机）**

~~~text
hook lua_pcall(entry):
  if in_inject (thread_local) → 直接转 orig        // 防重入
  if !L_saved → L_saved = L                        // 只存不注入
  if !patched && now - last_try > 1000ms:
      last_try = now
      in_inject = true
      run_patch_script(L)                          // pcall 包裹，失败静默计数
      in_inject = false
  return orig(L, nargs, nres, errfunc)
~~~

**"目标还没 require" 的处理**：patch 脚本自身不假设目标存在，而是
①先 `rawget(_G, "RhythmMasterVM")` 判空；②空则 `return 0`（表示"未完成"，C++ 侧 1s 后重试）；
③非空则包装，并把已包装目标记进 `__starry_patched[name]=true`；④三处都完成后再写 `__starry_patched_all=1`，C++ 侧见到就永久停止重试。
**上限**：最多重试 600 次（10 分钟）；超过后打一条 `[Ywt] patch give up targets=…` 并停（不刷屏）。

## 4. 三处判定目标的可 patch 形态（实测）

| 全局名 | chunk | 定义形态（反汇编证据） |
|---|---|---|
| `RhythmMasterVM` | `lua_csys_dance__052` | `GETTABUP R2 U0 "RhythmMasterVM"` … `CLOSURE R4 -> proto#4` … `SETTABLE R3 R3 "GetJudgeResult" R4` ⇒ **全局表字段** |
| `DanceRhythmVM` | `__012` | 同型：`GETTABUP R1 U0 "DanceRhythmVM"` + 多次 `SETTABLE …`（含自己的 `GetJudgeResult`） |
| `DanceKeyFallingVM` | `__008` | 同型全局表（该 chunk 定义了它，判定函数同名） |

`GETTABUP … U0 "X"` 中 `U0` 是模块 `_ENV`，即 **`_G["X"]`** ⇒ 用 `rawget(_G,"X")` 拿到的是**同一张表**，改它的字段即对全模块生效（**推断→高置信**：Lua 5.3 语义 + 反汇编双证）。

**若将来某处变成 C# 注入（当前没有）**：该名字在 `_G` 里不存在，patch 脚本的"判空重试"会一直等 → 表现为"目标缺失"日志。处理：把它加入 `__starry_skip` 名单，只 patch 存在的那几个，功能按"部分生效"降级，不阻塞。

## 5. 注入脚本骨架（builder 直接内联成 C++ 字符串）

> 约定：全局读写一律 `rawget/rawset`（xLua 的 `_G` 常有 `__index` 白名单，裸读未声明全局会返回 nil 且记 error）。
> 菜单开关：native 侧维护 `_G.__starry_ywt_cfg`（table），字段见 §5.4。

### 5.1 头部：幂等守卫 + 工具

~~~lua
-- chunkname: @starry_ywt_patch
if rawget(_G, "__starry_ywt_patch_ver") == 20261119 then return 1 end   -- 已装过，直接成功返回
local G = _G
local rg, rs = rawget, rawset
local function log(msg)                                                 -- 只在首次/异常时打
  local f = rg(G, "__starry_log")
  if type(f) == "function" then pcall(f, "[Ywt] " .. tostring(msg)) end
end
local patched = rg(G, "__starry_patched")
if type(patched) ~= "table" then patched = {}; rs(G, "__starry_patched", patched) end
local origs = rg(G, "__starry_orig")
if type(origs) ~= "table" then origs = {}; rs(G, "__starry_orig", origs) end

-- 权重归一化：读菜单配置，返回 0..1 累计区间，全 0 回落默认
local function read_cfg()
  local c = rg(G, "__starry_ywt_cfg")
  if type(c) ~= "table" then return nil end
  return c
end
local function pick(weights)                                            -- weights = {spp,sp,p,g,good,miss}
  local tot = 0
  for i = 1, 6 do local v = weights[i]; if type(v) ~= "number" or v < 0 then v = 0 end; weights[i] = v; tot = tot + v end
  if tot <= 0 then weights = {60, 25, 10, 3, 1, 1}; tot = 100 end
  local r = math.random() * tot
  local acc = 0
  for i = 1, 6 do acc = acc + weights[i]; if r <= acc then return i end end
  return 6
end
~~~

### 5.2 判定概率：三处 `GetJudgeResult` 包装

~~~lua
-- 档位顺序必须与游戏一致（实测 RhythmMasterVM.JudgeResultType）
-- 1=SuperPerfectPlus 2=SuperPerfect 3=Perfect 4=Great 5=Good 6=Miss
local TYPES = { "SuperPerfectPlus", "SuperPerfect", "Perfect", "Great", "Good", "Miss" }

local function wrap_judge(ownerName)
  local cls = rg(G, ownerName)
  if type(cls) ~= "table" then return false end
  local key = ownerName .. ".GetJudgeResult"
  if patched[key] then return true end
  local orig = cls.GetJudgeResult
  if type(orig) ~= "function" then return false end
  origs[key] = orig
  cls.GetJudgeResult = function(self, diff, ...)
    local cfg = read_cfg()
    if not cfg or not cfg.judge_on then return orig(self, diff, ...) end
    -- 先按真实结果判（保留"自然 Miss"的语义：diff 超窗就该 Miss，不被概率强行拉高）
    local real = orig(self, diff, ...)
    local jt = cls.JudgeResultType
    if cfg.judge_natural_miss and real == jt.Miss then return real end
    local w = { cfg.w_spp or 0, cfg.w_sp or 0, cfg.w_p or 0, cfg.w_g or 0, cfg.w_good or 0, cfg.w_miss or 0 }
    local idx = pick(w)
    local name = TYPES[idx]
    return jt[name] or real
  end
  patched[key] = true
  return true
end

local done = true
for _, n in ipairs({ "RhythmMasterVM", "DanceRhythmVM", "DanceKeyFallingVM" }) do
  if not wrap_judge(n) then done = false; log("wait " .. n) end
end
~~~

**为什么这样写能保证全链自洽**：`AddCombo / AddScore / AddSendKey / GetClientGrade` 都在同一个 VM 表里，且都以 `GetJudgeResult` 的返回值为输入（实测调用链）⇒ 只改这一个返回值，下游全部跟着走，不需要分别改分。

**"不影响自然 Miss"**：默认 `judge_natural_miss = true`（超出最大窗口的按键仍然是 Miss）；想全 Perfect 时把它设 false。**不改 `diff`、不改 `GetJudgeOffset`**（时间语义不动）。

### 5.3 自动跳舞：`RhythmMasterMode.OnUpdate` 包装

~~~lua
local function wrap_auto()
  local mode = rg(G, "RhythmMasterMode")
  if type(mode) ~= "table" or type(mode.OnUpdate) ~= "function" then return false end
  if patched["RhythmMasterMode.OnUpdate"] then return true end
  local orig = mode.OnUpdate
  origs["RhythmMasterMode.OnUpdate"] = orig
  local rnd = math.random

  mode.OnUpdate = function(self, ...)
    local r = orig(self, ...)                       -- 先跑原生：elasped_time / 音符推进都靠它
    local cfg = read_cfg()
    if not cfg or not cfg.auto_on then return r end
    if cfg.auto_skip and rnd() < cfg.auto_skip then return r end   -- 随机漏几个，像人

    local now = self.music_elasped_time             -- 实测字段名（RhythmMasterMode）
    if type(now) ~= "number" then return r end

    local list = self.noteList or self.waitNoteList -- 实测两个字段都存在
    if type(list) ~= "table" then return r end

    local budget = cfg.auto_per_frame or 2          -- 每帧最多按几个（防一帧全判）
    for i = 1, #list do
      if budget <= 0 then break end
      local it = list[i]
      if type(it) == "table" and type(it.CheckJudge) == "function" then
        local dur = it.duration
        local el  = it.elasped_time
        if type(dur) == "number" and type(el) == "number" then
          local win = it.check_offset or 0
          -- 只有"已经进入判定窗"的音符才按，且带 0~win 的随机抖动
          if el >= dur - win - rnd() * (win > 0 and win or 1) and el <= dur + win then
            local key = it.key_info and it.key_info.key
            if key ~= nil then
              pcall(it.CheckJudge, it, key)          -- 与玩家按下同一条路径
              budget = budget - 1
            end
          end
        end
      end
    end
    return r
  end
  patched["RhythmMasterMode.OnUpdate"] = true
  return true
end
if not wrap_auto() then done = false end
~~~

**"像人"的三条**：① 每帧最多 `auto_per_frame` 次（默认 2）；② 命中时机在判定窗内随机抖动（不是 `diff=0` 全 SPP）；③ `auto_skip` 概率性漏按（默认 0，可调 1–3% 让结算不是全 AP）。

**待验证**：`noteList` 元素是"音符容器"（`LongKeyItem`/`SingleKeyItem`，字段 `key_items[] / judge_index / GetKey() / CheckJudge(key)`）还是"单音符"，两种形状都要兼容 —— §5.3 的 `type(it.CheckJudge)=="function"` + `key_info.key` 判断已经做了形状容错；若容器层的字段不同，用 `it:GetKey()` 兜底（L2 探针确认）。

### 5.4 菜单开关约定（starry 侧取值，native → Lua）

| 字段 | 类型 | 含义 | 建议控件 |
|---|---|---|---|
| `auto_on` | bool | 自动跳舞 | Toggle |
| `judge_on` | bool | 判定概率生效 | Toggle（挂在同一分类下） |
| `judge_natural_miss` | bool | 保留自然 Miss | Toggle，默认 **true** |
| `w_spp/w_sp/w_p/w_g/w_good/w_miss` | int 0–100 | 六档权重 | 6 条 SeekBar，默认 **60/25/10/3/1/1** |
| `auto_per_frame` | int | 每帧最多按几个 | SeekBar 1–4，默认 2 |
| `auto_skip` | float 0–0.05 | 漏按概率 | SeekBar 0–5（%），默认 0 |

**写入方式（C++，主线程，低频）**：
1. 首次注入成功后调用一次 `lua_getglobal(L,"_G")` → `lua_createtable` → 逐字段 `lua_pushinteger/lua_pushboolean` + `lua_setfield` → `lua_setfield(L,-2,"__starry_ywt_cfg")`；
2. 菜单回调（`OnFeatureChanged` / `OnValueChanged`）里同样整表重写一次（不加锁，Unity 主线程 = Lua 线程；见 §6.4）。
3. 提供 `__starry_log` 全局：`lua_pushcclosure` 包一个 C 函数，转发到 mod 的 `LOGI`。

## 6. 崩溃 / 幂等 / 线程 风险清单

| # | 风险 | 后果 | 对策（必须实现） |
|---|---|---|---|
| 6.1 | **重入**：在 `lua_pcall` 钩子里再调 `lua_pcall` 跑 patch → 递归 | 栈爆 / 崩 | `thread_local bool in_inject`；钩子内 `in_inject` 为真时直接转 orig |
| 6.2 | **重复包装**：多次注入把 `GetJudgeResult` 包成洋葱 | 判定被叠加、性能塌 | ①脚本头 `__starry_ywt_patch_ver` 守卫；②每目标 `patched[key]`；③原函数只存一次到 `origs` |
| 6.3 | **lua error 冒泡**：patch 里字段缺失/类型不对 | 游戏 Lua 异常 → 卡死/闪退 | 所有关键调用 `pcall`；整段注入本身用 `lua_pcall(L,0,1,0)`；失败只计数并打**一条**日志 |
| 6.4 | **跨线程调 Lua** | 未定义行为/崩 | 只在 `lua_pcall` 钩子（=Lua 线程）与 Unity 主线程回调里调 API；菜单回调若不在主线程，改为置原子变量 + 由 Lua 侧 tick 读 |
| 6.5 | **GC 引用**：C++ 侧缓存 Lua 对象（note/cls） | 悬垂 | **C++ 不缓存任何 Lua 表/闭包引用**；全部逻辑放 Lua 闭包里（表字段自持有引用，GC 安全） |
| 6.6 | **栈失衡**：push 了不 pop | 后续 Lua 行为错乱 | 每次 API 序列记 `int top = lua_gettop(L)`，结尾 `lua_settop(L, top)` |
| 6.7 | **早注入**：`_G` 还没 `require` | patch 落空且被标记成功 | 判空→返回 0→重试；完成标记只在"三处都成"时写 |
| 6.8 | **晚注入**：进关后才装 | 首局无效 | 重试节流 1s，且不设"只装一次"闸（以 `patch_ver` 为准） |
| 6.9 | **Dobby 16 字节窗口** | 踩邻居入口 | `lua_pcall` 入口 16 B 已实测干净（`sub/stp/add/stur`），仍需装前序言校验 |
| 6.10 | **热更/换版本** | libxlua 偏移变 | 用 `dlsym` 拿符号，**不写死偏移**；偏移只作交叉校验 |
| 6.11 | 关功能不彻底 | 关掉仍在自动按 | 包装器第一步 `if not cfg.auto_on then return orig(...)`，且 `read_cfg` 每次现读（不缓存布尔） |

## 8. 与 starry 菜单的对接（给 builder 的字段名）

| 菜单项 | featNum 建议 | 控件 | 默认 |
|---|---|---|---|
| 自动跳舞 | `YWT_FEAT_AUTO_DANCE` | Toggle | 关 |
| 判定概率 | `YWT_FEAT_JUDGE_ON` | Toggle | 关 |
| 保留自然 Miss | `YWT_FEAT_JUDGE_NATURAL_MISS` | Toggle | 开 |
| SPP / SP / P / Great / Good / Miss | `YWT_FEAT_W_*` ×6 | SeekBar 0–100 | 60/25/10/3/1/1 |
| 每帧按键上限 | `YWT_FEAT_AUTO_PER_FRAME` | SeekBar 1–4 | 2 |
| 漏按概率(%) | `YWT_FEAT_AUTO_SKIP` | SeekBar 0–5 | 0 |

命名沿用音舞光年惯例（`YWGN_FEAT_*`），本作前缀用 `YWT_`（YingWuTuan）。

int top = lua_gettop(L);
if (luaL_loadstring(L, kYwtPatch) == 0) {

### 9.1 Lua 源（raw string 用 `R"YWT(...)YWT"` 包起来，内容不含 `)YWT"`）

~~~lua
-- @starry_ywt_patch (鹦鹉团 1.0.7)  由 native 用 luaL_loadstring+lua_pcall 执行，可重复执行（幂等）
-- 依赖 native 先写好 _G.__ywt_cfg(table) 与 _G.__ywt_log(function)；缺失时自动降级为只重试、不报错
-- 返回值：1=全部装好  0=目标还没 require（native 1s 后重试）
if rawget(_G, "__ywt_ver") == 1 then return 1 end
local G, rg, rs = _G, rawget, rawset
local type, pcall, math, ipairs = type, pcall, math, ipairs

-- [1] 工具：读配置 / 打日志 / 幂等表（P=已包装目标，O=原函数）
local function cfg() local c = rg(G, "__ywt_cfg"); if type(c) == "table" then return c end end
local function log(m) local f = rg(G, "__ywt_log"); if type(f) == "function" then pcall(f, tostring(m)) end end
local P = rg(G, "__ywt_p"); if type(P) ~= "table" then P = {}; rs(G, "__ywt_p", P) end
local O = rg(G, "__ywt_o"); if type(O) ~= "table" then O = {}; rs(G, "__ywt_o", O) end

-- [2] 判定档：顺序必须与游戏一致（实测 RhythmMasterVM.JudgeResultType）
local TN = { "SuperPerfectPlus", "SuperPerfect", "Perfect", "Great", "Good", "Miss" }

-- [3] 权重归一化：全 0 回落 60/25/10/3/1/1，返回 1..6
local function pick(c)
  local w = { c.w1 or 0, c.w2 or 0, c.w3 or 0, c.w4 or 0, c.w5 or 0, c.w6 or 0 }
  local tot = 0
  for i = 1, 6 do if w[i] < 0 then w[i] = 0 end; tot = tot + w[i] end
  if tot <= 0 then w = { 60, 25, 10, 3, 1, 1 }; tot = 100 end
  local r = math.random() * tot
  for i = 1, 6 do r = r - w[i]; if r <= 0 then return i end end
  return 6
end

-- [4] 判定概率：包三处 GetJudgeResult（先跑 orig 拿真实结果；keep_miss 时真 Miss 仍 Miss）
local function wrapJudge(name)
  local k = "j:" .. name
  if P[k] then return true end
  local cls = rg(G, name)
  if type(cls) ~= "table" or type(cls.GetJudgeResult) ~= "function" then return false end
  local JT, orig = cls.JudgeResultType, cls.GetJudgeResult
  if type(JT) ~= "table" then return false end
  O[k] = orig; P[k] = 1
  cls.GetJudgeResult = function(self, diff, ...)
    local c = cfg()
    if not c or not c.judge_on then return orig(self, diff, ...) end
    local real = orig(self, diff, ...)          -- 不改 diff、不改时间语义
    if c.keep_miss and real == JT.Miss then return real end
    return JT[TN[pick(c)]] or real
  end
  return true
end

-- [5] 自动跳舞状态：arg 记住 CheckJudge 第二参是 key 还是 slot；首局只 dump 一条
local st = { frames = 0, try = 0, ok = 0, fail = 0, dumped = false, arg = "key" }

-- [6] 按一下：双兼容参数顺序（key / slot），成功者记住
local function press(it, slot)
  local key = it.key_info and it.key_info.key
  if st.arg == "key" and key ~= nil then
    local ok, r1 = pcall(it.CheckJudge, it, key)
    if ok and r1 ~= nil and r1 ~= false then return true end
    st.arg = "slot"
  end
  local ok, r1 = pcall(it.CheckJudge, it, slot)
  if ok and r1 ~= nil and r1 ~= false then st.arg = "slot"; return true end
  st.arg = "key"; return false
end

-- [7] 自动跳舞：包 RhythmMasterMode.OnUpdate（必须先跑 orig，elasped_time 靠它推进）
local function wrapAuto()
  local k = "a:Update"
  if P[k] then return true end
  local M = rg(G, "RhythmMasterMode")
  if type(M) ~= "table" or type(M.OnUpdate) ~= "function" then return false end
  local orig = M.OnUpdate
  O[k] = orig; P[k] = 1
  M.OnUpdate = function(self, ...)
    local r = orig(self, ...)
    local c = cfg(); if not c or not c.auto_on then return r end
    local now = self.music_elasped_time
    local L = self.noteList or self.waitNoteList
    if type(now) ~= "number" or type(L) ~= "table" then return r end

    st.frames = st.frames + 1
    if not st.dumped and st.frames == 30 then                      -- 首局一条汇总，不刷屏
      st.dumped = true
      local e = L[1]; local shape = "?"
      if type(e) == "table" then
        if type(e.CheckJudge) == "function" then shape = "item"
        elseif type(e.key_items) == "table" then shape = "container" end
      end
      log(string.format("[Ywt] dump notes=%d shape=%s arg=%s per=%s", #L, shape, st.arg, tostring(c.per_frame or 2)))
    end

    if c.skip and math.random() < c.skip then return r end          -- 概率漏按，像人
    local budget = c.per_frame or 2                                  -- 每帧最多按几个
    for i = 1, #L do
      if budget <= 0 then break end
      local e = L[i]
      if type(e) == "table" then
        local it, slot = e, i
        if type(e.CheckJudge) ~= "function" and type(e.key_items) == "table" then
          slot = e.judge_index or 1; it = e.key_items[slot]          -- 容器形态
        end
        if type(it) == "table" and type(it.CheckJudge) == "function" then
          local done = (it.is_press == true)
          if not done and type(it.IsAllJudge) == "function" then local o2, v2 = pcall(it.IsAllJudge, it); done = (o2 and v2 == true) end
          if not done then
            local d, el, win = it.duration, it.elasped_time, it.check_offset or 0
            if type(d) == "number" and type(el) == "number" then
              local lag = (win > 0) and win or 1
              if el >= d - lag * (1 + math.random()) and el <= d + lag then   -- 进窗 + 抖动
                st.try = st.try + 1
                if press(it, slot) then st.ok = st.ok + 1 else st.fail = st.fail + 1 end
                budget = budget - 1
              end
            end
          end
        end
      end
    end
    return r
  end
  return true
end

-- [8] 收尾：三处判定 + 主玩法（只做 RhythmMaster，实测只有它全链路齐全）
local ok = wrapJudge("RhythmMasterVM")
if not wrapJudge("DanceRhythmVM") then ok = false end
if not wrapJudge("DanceKeyFallingVM") then ok = false end
if not wrapAuto() then ok = false end
if ok then rs(G, "__ywt_ver", 1); log("[Ywt] patch ok"); return 1 end
log("[Ywt] patch pending"); return 0
~~~
