# 经验卡：热更指纹漂移与令牌浪费（勇士之心 1.0.3 / res 1.0.98.10）

> 状态：**已合并**（2026-09-21，用户「按照你说的进行优化」）。
> 来源：2026-09-21 勇士之心热更后自动战斗失效的完整修复会话。
> 落地位置见文末「合并去向」。

## 1. 问题

游戏内热更（`localResVsersion` 1.0.98.10）后功能失效。用户报"功能失效"，
菜单能开但自动战斗不放行。

## 2. 根因（决定性证据）

自动战斗指纹写死了**会被混淆器改名**的短标识符：

```js
// 09-15 旧 res
t.prototype.fsl = function () { return $fc.buff.bVy.bVs(a.$fe.tblEnum.BuffTableEnum.AUTO_BATTLE); };
// 1.0.98.10：$fc→$eZ、bVy→bXV、bVs→bXP、fsl→fwW
t.prototype.fwW = function () { return $eZ.buff.bXV.bXP(a.$fb.tblEnum.BuffTableEnum.AUTO_BATTLE); };
```

旧指纹 `indexOf("AUTO_BATTLE")>=0 && indexOf("bVs(")>=0` → 热更后全部落空 →
`tryAuto` 静默跳过 → feature5 永不生效。

同时确认 **native 未漂移**：`libcocos2djs.so` SHA-256 与 09-15 一致，
`kEvalRva=0x3138e4`/序言 `0xD10543FF` 有效 → 失效点在 JS 指纹，不在 native。

## 3. 复用方法

### 3.1 三查分流（先判是不是热更漂移）

| 查什么 | 位置 | 判据 |
|---|---|---|
| 热更资源版本 | `files/res/version` 的 `localResVsersion` | 与上次交付不同 = 漂移 |
| 核心 so 同源性 | 安装包内 `libcocos2djs.so` / `libil2cpp.so` SHA-256 vs 历史绑定表 | 相同 → 别改 native |
| 玩法分包位置 | `unzip -l base.apk \| grep 'assets/assets/.*/index.js'` | 只有 internal/main → 玩法靠热更 |

### 3.2 离线复现发现逻辑的两条铁律

1. **先校准基线**：旧 res + 旧指纹必须跑出 `OK`，否则是复现器错了。
2. **粒度与运行时一致**：运行时 `findFn(exports)` 按**函数**遍历源码字符串；
   按"整文件/整模块"判指纹必然假阴性（模块上万行，长度约束/跨函数串味）。

三组对照定位根因：旧res+旧指纹=OK / 新res+旧指纹=`MISSING:auto` / 新res+新指纹=OK。

### 3.3 指纹写法（两级 + 失败留痕）

主指纹只用明文锚点（字符串字面量、枚举成员全路径、明文属性名），
兜底指纹用结构特征（短函数 + `return X.Y(...)`），命中失败必须 `log` 候选名与长度。
每条指纹配一条静态断言，禁止回退到写死标识符。

## 4. 令牌浪费（本次实测）

| 浪费点 | 量级 | 对策（已落地） |
|---|---|---|
| 全缓冲 `logcat -d \| grep -Ei` 被超长系统行（`AppOrder{...}`）淹没 | 单次数千 token | 白名单 tag：`logcat -v time -s Mod_Menu:V Ysxz:V StarryMagic:V MenuService:V` |
| 逐文件 `exec-out` 拉 22,000 个 json | 10 分钟超时 + 零产出 | 先量后拉；>50 文件或 >20MB 走 `tar -cf -` 单流 |
| 探测 `02_apks`/`08_output` 是否还在 | 4~6 条命令 | 两目录由用户手动增删 → 开工等用户声明 |
| 离线复现器粒度不对 | 2 次返工 | 先校准基线 + 函数级粒度 |
| 全量 `git status` 带出无关会话改动 | 27 行 × N 次 | 只查白名单路径 |
