## 2. 观察、解释与候选经验

- 观察事实（不夹带因果解释）：
  1. 7.6.0 期 `WdyzMod.cpp` 的三个锚点常量与 `dump.cs` 的 **RVA** 字段相等（如 HeroSettle 记 `0x45F6308`），而 `Offset` 字段为 `0x45F2308`，差 `0x4000`。
  2. 同期 `expectInsn` 写作 `0xEB2BBB6D`；而 `Offset` 处 4 字节 `eb 2c bb 6d` 小端读作 `0x6DBB2C6D`（前版为 `0x6DBB2BEB`）。
  3. 7.6.1 改用 `Offset` + 小端序言值后，三个锚点在静态层面命中（`dump.cs:571366 / 573758 / 576292`，xxd 复核通过）。
  4. 7.6.0 的 logcat 记录里只有 `@by-name`，未见 `@rva`（§11.1）；但 7.6.0 功能当时可用。
- 候选解释 H1：`FileOffToVa` 的入参语义是 **file_off**（dump.cs 的 `Offset` 字段）。填 RVA 使 RVA 快路径永不命中，**静默**退回按名；`expectInsn` 字节序写反使序言校验必然失败，同样退回按名。两者独立成立。
- 替代解释 H2：该游戏运行时 so 与 dump 的 so 不同源（热更替换），RVA 天生不匹配 → 即使口径正确也会退回按名。
- 拟提炼的经验（带前提、动作、预期结果）：
  - 前提：Unity IL2CPP + 由 `dump.cs` 派生锚点 + 自写 inline hook/Dobby。
  - 动作：写锚点时**注明取的是哪个字段**；`Offset` 是文件偏移（本例 `RVA − Offset = 0x4000`，但 **0x4000 不是通用常数**，须按 PT_LOAD 实测）；序言期望值按小端 4 字节读成 u32（`eb 2c bb 6d` → `0x6DBB2C6D`，不要写成字节序反转的形式）；锚点表必须绑定 so 的 SHA-256。
  - 预期结果：RVA 快路径命中；若未命中会静默走按名，**功能照样通过**，因此“功能生效”不能作为口径正确的证据。
  - 唯一判据：logcat 中该锚点打印的是 `@rva` 还是 `@by-name`。
- 适用范围：ARM64、Unity IL2CPP、dump.cs 可见目标方法（非 HybridCLR 热更方法）
- 不适用范围 / 已知例外：HybridCLR/热更方法在 dump.cs 中不可见，走 invoke 桩，见 `version-update-relocate.md` §0；首段 `p_offset = 0` 的 so 上 RVA 与 Offset 可能相等。

## 3. 反证、失效与最小区分实验

- 可推翻该经验的观察或反例：某游戏使用 RVA 值却打印 `@rva`（推翻 H1）；同一 so 哈希下 `@rva` 与 `@by-name` 交替出现（推翻“口径单一决定”）。
- 已收集反证及其证据位置：`hook-rules.md` §6 已明确 `0x4000` 不是通用常数、`file_off ≠ RVA` —— 本卡不主张常数，只主张“必须写明字段并绑定 so”。
- 失效条件：换版本/渠道导致 so 变化；或 mod 框架把 `FileOffToVa` 语义改为 VA（需查框架源码）。
- 失效后的处置：降为待验证 / 撤销 / 替代卡，保留历史。
- 最小区分实验：在 7.6.1 上打开任一功能开关，`adb logcat -s StarryMagic:V` 抓 `[Wdyz] … hooked @rva 0x45F2308`。H1 预测 `@rva`，H2 预测 `@by-name`；单变量、可直接判定。
- 停止条件：抓到一次 `@rva` 即样本内证实 H1；若为 `@by-name`，转为查运行时 so 来源（`/proc/<pid>/maps` + 文件哈希）后再判 H2。
