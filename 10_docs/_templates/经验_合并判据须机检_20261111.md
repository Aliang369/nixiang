# 经验候选卡：判「已合并」要靠结构证据，不能全文搜标识符

> 范围声明：本条是**静态维护**经验（脚本 + 文档生命周期），跨游戏通用，与设备、真机、
> 具体游戏参数无关；证据只来自本轮脚本改动与一次性 fixture 测试，没有设备实测。

## 1. 现场

- 创建日期 2026-11-11；来源：本轮体验生命周期脚本维护（04_scripts/_common）。
- 关联证据：`04_scripts/_common/test_audit_experience_registry.py`（一次性临时目录 fixture，不碰真实卡片）。
- 真实数据：本轮开始时全仓 24 张经验卡（22 张无 frontmatter 的 legacy 卡），
  另 1 张既有卡的 evidence 路径已不存在（审计报 invalid，属既有债务，未在本轮修改）。

## 2. 观察、解释与候选经验

- 观察事实：旧实现判「卡已合并」的做法是**在落点全文里搜 experience_id**；只要文中出现该串
  就返回「已合并」。于是「待合并：exp-…」这类待办行、索引行、以及卡片自己引用的路径，
  都能让一张没写进正文的卡显示成已合并。
- 候选解释 H1：状态与事实脱节不是因为人忘了合并，而是**判据选错**——可搜到的字符串不等于
  已写入的结构证据。替代解释 H2：只是没人跑脚本（否证：跑与不跑都会给出同样的误判）。
- 拟提炼的经验：判「已写入」只认**起止标记 + 内容 hash**；散文里的标识符只算线索。
- 适用范围：静态维护类脚本（文档/校验/门禁），跨游戏通用。
- 不适用范围：二进制/运行时校验（那里需要的是样本 hash 与运行日志，与此判据无关）。

## 3. 反证、失效与最小区分实验

- 可推翻该经验的观察：若某落点正文里根本没有标记体系，则「必须带标记」会把正常流程卡死
  ⇒ 处置：只对**卡里点名的唯一锚点**启用标记要求，legacy 卡与无片段卡直接跳过（已实现）。
- 已收集反证：把 id 写进散文的 fixture 仍被判 merged（旧行为）—— 现测试
  `test_id_only_prose_is_not_merge_evidence` 断言其为 invalid。
- 失效条件：目标文件被别的工具整体重写、标记被人工删掉；此时脚本报
  「status=merged 但正文里没有该 id 的合并块」，不静默重插。
- 最小区分实验：同一张卡连续两次 apply，第二次必须零写入（mtime 不变）——
  `test_second_run_is_zero_write`；改一行片段后必须只更新同一个块（`test_changed_snippet_updates_block_in_place`）。
- 停止条件：出现「标记在、内容不符」的冲突时停手交人工，不覆盖。

## 合并片段（去游戏化）

- 判「已写入正文」只认**结构证据**：起止标记 + 内容 hash；散文、索引、待办行里出现标识符只是线索，不是证据。
- 幂等靠「先比 hash、命中即零写入」，不靠重写同样的内容；内容变了只原地更新该块，绝不追加第二份。
- 同一段正文挂在两个不同 id 上 ⇒ 判冲突报错交人工，宁可停下也不覆盖。

| CLAIM（限定范围） | EVIDENCE（可定位原始记录） | VERDICT |
