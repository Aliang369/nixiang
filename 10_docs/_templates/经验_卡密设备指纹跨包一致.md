# 经验卡片：全游戏卡密 · 设备指纹必须跨宿主包一致

> 状态：可汇总素材 · **已验证**（2026-08-10）  
> 首发：音舞光年后切本地菜单报「卡密绑定其他设备」

## 现象

- 后台全游戏卡密、跨 `game_id` 登录逻辑本身正常；**不必改后台代码**。  
- 在 A 游戏（音舞）登录成功后，同机 B 菜单（`com.starry.magic` / 其它旧包）登录 → **「卡密已绑定其他设备」**。

## 根因

服务端按**整张卡**绑一个 `card.device_id`（与游戏无关）。客户端若在不同包算出不同 `dev_*`，必 403。

真机三包三 ID（OnePlus PLK110，修前）：

| 包 | 指纹版 | device_id |
|----|--------|-----------|
| `com.uniugame.ywgn` | v2 | `dev_99fc6229923668b7…` |
| `com.starry.magic` | v2 | `dev_c1e869930df5ccc…`（与音舞不同） |
| `com.chillyroom.zhmr.yw` | v1 | `dev_c76dac2b0849641…` |

| 算法 | 为何跨包失败 |
|------|----------------|
| v1 `ANDROID_ID` | 系统按包名隔离 |
| v2 Widevine | **部分 OEM（ColorOS）仍按应用隔离**（本机实证） |

## 修法（v3）

实现：`mod菜单/starry-mod-menu/app/src/main/java/com/starry/magic/auth/DeviceFingerprint.java`  
文档：`auth-server/docs/GRANT_AUTH.md` §3.1.1

**权威 id = 仅 `Build.*` + `FINGERPRINT` 哈希**（本机算例 `dev_760f1cc7de536cd8…`）。  
共享文件只作尽力落盘，**不再用共享文件覆盖权威 id**。

### 复发（2026-08-10 造梦）

曾把旧 Widevine id（`dev_99fc…`）写入 `/sdcard/Download/.starry_magic/device_id`，且目录权限 `drwxrws---`（仅写入方 UID 可读）。  
造梦读不到共享文件 → 落到硬件 `dev_760f…` → 卡仍绑 `dev_99fc…` → 再报「绑定其他设备」。

处理：后台**解绑一次**；客户端以硬件 v3 为准重登。勿再依赖 `Download/` 跨包读种子。

说明：

- **后台不用改代码**；换算法 / 清掉旧共享种子后解绑一次即可。  
- 指纹在 **Java**，只换 so 无效，须重打含菜单 DEX 的包。

## 复发（2026-08-11 雷霆）

v3 把 `Build.DISPLAY` / `Build.FINGERPRINT` 算进哈希。本机 OTA 后指纹从  
`dev_760f1cc7…`（其它游戏已绑卡）变成 `dev_7ddbfe49…`（雷霆新建）→ 再报绑定其他设备。

**v4**：权威计算去掉 DISPLAY/FINGERPRINT；**可读共享种子优先**（`Android/starry_magic`、`.starry_magic`），写盘强制 `chmod 666`。  
同机已有共享 id 时换游戏/OTA 不再换设备；无共享才用硬件 v4。

处理：装含 v4 dex 的包；`chmod` 共享 `device_id` 为全局可读；一般**不必再解绑**（沿用已绑共享 id）。若共享已丢且算出新 id，再后台解绑一次。

## 复发（2026-08-12 霓虹九游）

sdcard 上已有 `dev_760f…`，但宿主 `targetSdk≥30` **无存储权限**，普通 `File` 读不到；  
`/data/local/tmp/starry_magic` 又未建 → 落到硬件 v4 `dev_5c09…` → 再报绑定其他设备。

**补强**：

1. 客户端：读/写失败时用 `su -c` 旁路，并把种子落到 `/data/local/tmp/starry_magic`（666，后续免 su）。  
2. 装机脚本：`04_scripts/_common/ensure_starry_device_id_seed.sh`（把已有种子同步到 tmp）。

处理：跑 seed 脚本或装含补强 dex 的包；把 prefs 里错误的 `auth_device_id` 清掉/改回；**不必解绑**（卡仍绑 `760f`）。

完整复现矩阵与红线：`全游戏卡密_复现路径与防再发.md`。

## 复发（2026-10-01 霓虹 TapTap 星光包：**签名证书不一致**）

**v5（当前）权威 id 只用 SSAID**（`Settings.Secure.ANDROID_ID`，`raw = "ver=v5|ssaid=<lower>"`）。

关键性质：**Android 8+ 的 SSAID 按「签名证书 + 系统用户 + 设备」隔离** ⇒ 同一台手机上，
**签名证书不同**的两个星光包必然算出不同 `dev_*`，共享种子文件不再救场（v5 不拿它们当权威）。

实测（OnePlus `f9a116a2`，2026-10-01）：

| 包 | 签名哈希（dumpsys） | v5 指纹 `source=ssaid` | 结果 |
|---|---|---|---|
| 霓虹（debug 证书 `CN=Android Debug`） | `[520f898a]` | `dev_89fd2216081394bf9639e0064f4c8ea5` | `403`「已绑定其他设备」 |
| 失落城堡（release 证书 `CN=StarryMagic`） | `[6f4dda0b]` | `dev_b2206b052abedaaa2fa35d43e732666b` | `grant ok` |

推断链：卡原绑 v4 共享 id `dev_760f…`；失落城堡首次 v5 登录时服务端按 legacy 证据把绑定**原子迁移**到
`dev_b2206b05…`；霓虹因换签算出 `dev_89fd…`，既非主绑定也不在可迁移路径上 ⇒ 403。

**修法（本次采用，不用后台解绑）**：把该游戏的星光包**换成与其它星光包同一把证书**
（`01_tools/starry_release.jks`，alias `starry`，`CN=StarryMagic`，cert SHA-1 `821c92e4…` / MD5 `161fca32…`），
内容不变、只重签 ⇒ SSAID 相同 ⇒ 命中绑定。霓虹脚本已改为默认用该证书 + 提供 `NEON_RESIGN_APK=` 换签模式。

代价与前置：**换签后无法覆盖安装，必须卸载重装（清存档/菜单设置），须用户授权**。

**硬规则（v5 起）**：

1. 同一台设备上的所有星光包**必须用同一把签名证书**（工作区统一 `01_tools/starry_release.jks`）。
2. 任何游戏脚本的签名段**默认就必须是这把 release 证书**；不要沿用历史上的 uber DEBUG_EMBEDDED / 自造 debug 证书。
   只改 so / 只换 dex 而不重签，问题不会消失（签名变了才会变 `dev_*`）。
3. 先查设备现有星光包的签名哈希（`adb shell dumpsys package <pkg> | grep signatures=`）—— 哈希不同就别指望卡密能同时在两边用。
4. 万不得已才后台解绑；解绑会把绑定迁到当前包的 `dev_*`，因此**先统一签名再解绑**，否则会轮流顶掉其它游戏。

## 验证

```bash
bash 04_scripts/_common/ensure_starry_device_id_seed.sh
adb logcat -s DeviceFingerprint:V AuthClient:V | grep -E 'fingerprint|device_id|403'
# 期望：各宿主包同一 id；source=shared；tmp 有 device_id
adb shell "su -c 'cat /data/local/tmp/starry_magic/device_id; grep auth_device_id /data/data/*/shared_prefs/starry_magic_prefs.xml'"
# v5：同机各星光包签名哈希必须一致（SSAID 按签名证书隔离）
adb shell 'for p in com.shangyoo.neon com.leiting.lostcastle.leiting; do echo -n "$p "; dumpsys package $p | grep -m1 signatures=; done'
# 期望：同名哈希（如 [6f4dda0b]）→ 同一 SSAID → 同一 dev_*
```
