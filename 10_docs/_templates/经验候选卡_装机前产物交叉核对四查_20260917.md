## 2. 观察、解释与候选经验

- 观察事实（不夹带因果解释）：
  - 黑暗领域：新 so 注册 19 个 JNI 方法、旧 dex 仅 17 个声明 → 装机即 SIGABRT
  - 无悔华夏热更修复：只换 so、新 so JNI 方法旧 dex 无声明 → 装机即闪退
  - 宝石战争：DllImport 入口名 `AdjustDamage` 与 so 导出 `StarryGw_*` 不符 → 装机后回合卡死两轮才定位
  - 勇士之心：注入 JS 按内存边界截断缺尾 `}`，未做语法校验即装机 → 失效
  - 勇士之心：滑块功能写 getVal 而 JS 判 getRet 布尔 → 移速无效
- 候选解释 H1：这四类错误全部是「产物间交叉核对」可在装机前机器化拦截的（已实现 `04_scripts/_common/pre_install_gate.sh` 四查并用构造用例验证 FAIL/PASS 路径）；H2（替代）：部分错误（如 JS 内部语义）仍需人工
- 拟提炼的经验（带前提、动作、预期结果，不写无条件定律）：装机前对产物跑四查（JS 语法/JNI 配套/P/Invoke 符号/控件读取），FAIL 即拦——在「产物由本工作区管线生成」前提下可将该类装机失败拦截在装机前
- 适用范围：本工作区星光包产物；注入 JS 为落盘可读文件；cpp 中 JNI 注册为 regOne/Java_* 可识别形态
- 不适用范围 / 已知例外：控件查仅覆盖字面量索引调用（`getRet(4)`），变量传参（`getRet(n)`）需人工；故意保留的兼容空实现需用户确认放行
