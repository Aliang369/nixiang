# 路线锁定表（对照方 → 我们，逐项 1:1 核对）

> 用途：把「照 XX 做」从口号变成**一张必须填满的表**；填不满不许装机。
> 落点：`10_docs/{游戏}/路线锁定.md`（一游戏一份，跨版本追加/更新）。
> 配套：`skill/re-implement/hook-rules.md` §22 挂点五步门禁**第 5 步**。
> 适用：存在参考改包 / 参考文档 / 参考抓包（如「斌哥包」这类对照方），或用户明确说「照 XX 做」时**必须建**。

---

## 回读时机

1. 写任何功能实现代码之前；
2. **装机之前**（第 5 步门禁：表里无「未确认偏离」才准装机）；
3. 每次换挂点 / 换实现路线之后（回来更新）；
4. 用户再次强调「照 XX 做」时（说明上一张表没起作用，先看表再动手）。
5. **用表里任何 RVA / 偏移 / 哈希之前**：先核它的来源 —— 标「同轮真机日志」的可用；标「文档历史 / 会话摘要 / 压缩摘要」的**只作线索**，装机前必须当轮复算一次。
   （2026-10-15 实例：压缩摘要给的一组桩表 RVA 是 `0x1E0xxxx`，真值 `0x300Cxxx`，差 24 MB，差点写进台账。）

## 硬规则

1. **一行一行填**。合法值包含「未实现」「未解析」；**「不填」不合法**。
2. 任何「1:1？= 否」必须在装机前取得用户确认；**未确认的偏离禁止装机**。
3. 对照方的机制**读不懂**时，写「未解析」并**停下先解析**——禁止用自己的方案填坑。
4. 「无参考实现」（对照方没有该功能，如某些免广告路径）时，写「无参考实现」+ 我们的假设矩阵 +
   验证方法 + 状态（候选/待验证），并与上表同格式留痕；不得因此跳过本表。
5. 每轮改挂点后回来更新；本表同时充当「本会话已否定方案」的持久容器。
6. 收尾时把本表的「1:1？= 是」的行数与功能清单逐项对照：数量不符 = 有功能走了自研路线，必须汇报。

## 反面教训（为什么需要这份表）

- 冒险与征途 1.5.9：对照包（斌哥包）已把机制写在脸上（`Character::Damage` 改 BigInt、
  `StarsCollider::DoAttack` 置空 arg2、`BattleElementCenter::get_localDamage`→1），
  AI 仍自建「插桩学窗口」路线，跑了 11.6 小时 / 2428 次工具调用 / 99 条用户消息，
  最终回到对照方案。**缺的不是资料，是「偏离必须落盘并经确认」这条约束力。**
- 对照包被当成「参考读物」而不是「规格书」时，每一次偏离都不会被察觉，
  直到用户第 N 次说「照他的改」——那就是本表的用途。
