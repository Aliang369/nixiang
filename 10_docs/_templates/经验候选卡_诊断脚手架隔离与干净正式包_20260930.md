# 经验候选卡：诊断脚手架必须编译期隔离（"干净正式包" 的正确做法）

> 来源：伊莫 1.0.1 星空版第三轮（用户明确要求「正式包不需要任何调试与日志」）2026-09-30
> 状态：**候选**（未审批，未改 `skill/`）

## 一、现象与代价

功能调试期把诊断写进产物包是常态，但**用户要的正式包必须是零调试**。本次的做法是「先写进包、最后手术式拆除」：

- `Games/YimoMod.cpp` 拆掉 **115 行 / 35 处**：`_dbg(s)`/`_dbgN(s)`（含写 `ym.log` 的 `io.open`/`f:write` 通道与 `__YM_N` 计数）、`LOG(tag,…)` + `LOG_LIMIT_EXTRA` + `_cnt`、全部 Lua/native `LOG(...)` 调用点、以及**只为打印日志而存在的函数参数**（`patchLite(cls,key,wrap)`、`patchEntityClass(cls,key,wrap)`、`fullWrap(cls)`、`hookCheckValidTarget(U)`）。
- 代价：**一整轮全量重建 + 389 MB 装机**，且手术过程本身有风险（本次靠「每处 `s.count(old)==1` 断言 + diff 复核证明唯一非日志变化是形态塌缩」才敢交付）。
- 附带代价：调试期**两次**为改诊断行为重建重装 —— ① 日志上限每 tag 写死 5 条，看不出距离趋势，改成 24 条；② 补 TRACE 采证据，多出一版整包（`d6b630a9…`）。

## 二、铁律

1. **诊断代码必须能被一个开关整体关掉，默认关**：native 用 `DLOG(...)` 宏（`#ifdef STARRY_DIAG`），Lua 诊断整段独立常量，patch 组装时按开关 `%s` 拼接。
2. **正式包构建默认＝干净包**；诊断包显式 `STARRY_DIAG=1` 且产物名带 `-diag` 后缀，两者可并存分发。
3. **诊断上限不许写死**：从设备上的配置文件读（如 `/sdcard/.starry_magic/logcfg`，一行一条 `tag=上限`），改一行文本 + 重启游戏即可，零重建零重装。
4. **干净包要有机械门禁**：正式包构建前扫 `Games/*.cpp`，命中 `ym.log` / `io.open("/sdcard` / `_dbg(` / `LOG(` 且不在 `#ifdef STARRY_DIAG` 块内 ⇒ **拒绝出包**（照抄现有「so 内缺菜单串即 fail」的构建守卫风格）。
5. 保留**一条**正向装机日志（`patch installed (state=%p)`）＋错误路径日志，用于「补丁到底装上没有」的判据；这类日志属**证据**，不属于调试脚手架。

## 三、配套的证据纪律（同源教训）

- 诊断优先：新功能第一阶段**只出 `-diag` 包采证**，再写正式实现；机制假设（例："伤害放大对人物也生效"）必须先被 Trace 证实/证伪。
- 诊断必须打印**自检行**（钩成功/失败/符号未找到），否则「没命中」分不清「没发生」还是「没装上」。
- **诊断字段恒为常数 ⇒ 先怀疑诊断**（本次「计划距离恒 0.0m」其实是读了被就地改写的共享引用）。
