# 经验卡：原生退出拦截（seccomp 只拦 exit_group）

> 首次发现：勇士之心 1.0.4（2026-09-30）｜已固化：`skill/re-implement/anti-cheat-pattern.md` 模式五
> 相关：`skill/re-analyze/native-probe-on-device.md`（探针范式）、`skill/re-implement/hook-rules.md` §25（探针自检行）

---

## 现象

改包能跑到游戏界面（splash/公告/甚至角色选择），随后**干净退出**：

```
ActivityManager: Process com.fightingstars.games.warrior (pid N) has died: fg TOP
Zygote: Process N exited cleanly (0)
```

无 Java 异常栈、无 native 崩溃、无 JS 报错、无生命周期回调 —— 是应用**主动 exit(0)**，
与是否 root 无关（root 机 5~9 s、非 root 小米机 9~13 s，时长不定）。

## 判定顺序（别跳步）

1. **先排除误判**：权限弹窗未响应 / Activity 未 attach 被系统回收，也表现为 clean exit（实测约 12 s）。
2. 装 native 探针钩 `libc` 的 `exit/_exit/_Exit/abort/kill/pthread_exit/syscall`
   + JNI 的 `System.exit/Runtime.exit/exitInternal/Process.killProcess`。
   ⚠️ **Android 14 上后四个 JNI 符号不在 `libandroid_runtime.so` 导出表**，"符号未找到"属正常，不是探针失败。
3. 全部无命中 ⇒ 保护组件用**内联 `svc #0` 直发 `exit(93)`/`exit_group(94)`** 绕过 libc 导出
   （bionic 的 `_exit` 本身也是内联 `exit_group`）。此路只能拦 syscall。

## 四轮实验（结论：只拦 94 + TRAP + 只杀该线程）

| 拦法 | 结果 |
|------|------|
| 93 + 94，`SECCOMP_RET_TRAP` | 每进程约 270 ms `exited due to signal 31 (Bad system call)`，SIGSYS 处理器来不及执行 ⇒ 不可用 |
| 93 + 94，`RET_ERRNO\|EPERM` | 变 `signal 4 (Illegal instruction)`（`pthread_exit(0x0)` 后约 12 ms）；栈 `libstarry_magic.so+0x1b2d0 ← +0x1a524(trampoline) ← libc.so+0xfd530 ← libc.so+0x96b28` ⇒ **拦 93 会让线程从 svc 之后继续执行落进 `udf`，整进程陪葬** |
| 只拦 94 + TRAP + 只杀当前线程 | 进程存活 60 s+，正常进游戏（**采用**） |
| 只拦 94 + `RET_ERRNO` | 留 destroyed-mutex 二次崩溃 `F libc: FORTIFY: pthread_mutex_lock called on a destroyed mutex` ⇒ 必须 TRAP |

## 正确实现要点

```c
prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0);
prctl(PR_SET_SECCOMP, SECCOMP_MODE_FILTER, &prog);   // BPF: 只匹配 __NR_exit_group，其余 ALLOW，命中 TRAP

static void OnSys(int sig, siginfo_t *si, void *uc) {  // SIGSYS，SA_SIGINFO
    /* 打 pc/lr/regs[8]/regs[0] + dladdr 库名+偏移 */
    syscall(__NR_exit, 0);   // 只结束该线程；绝不 return（返回会从 svc 之后执行 → udf → 整进程死）
}
```

- 参考实现（可直接复用）：`mod菜单/starry-mod-menu/app/src/main/jni/Games/YsxzExitTrace.cpp`
  —— `InstallSyscallTrap()`、SIGSYS 处理器、`InstallFaultHandler()` 覆盖 SIGILL/SEGV/BUS/ABRT/FPE；
  装配点：`Games/YsxzMod.cpp::Ysxz_OnLoad` 首句 `YsxzExitTrace_Start(vm)`。
- **每类退出调用独立计数**：共用一个计数器时首个命中会被计数门限吃掉、栈不打印，反而掩盖真凶。
- **必须有装配自检行**（`hook ok libc.exit` / `符号未找到 …`），否则分不清"没装上"和"没命中"。

## 边界与限制

- 只杀保护线程后保护逻辑可能重试；反复被杀时先改成"命中只留痕、不改行为"定位真凶，再决定中和。
- 非 root 机不能起 `frida-server`，探针必须编进自家 so（见 `re-analyze/native-probe-on-device.md`）。
- seccomp 过滤器一旦装上不可撤销：装了就要保证只影响目标 syscall（这里是 94），其他全部 ALLOW。
- 本机制只解决"被主动退进程"，不解决 root 机环境检测闪退那类**主动检测后自杀**（本会话用户明确不处理）。
