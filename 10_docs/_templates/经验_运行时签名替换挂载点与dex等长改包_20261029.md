# 经验候选卡：签名杀手挂载点、dex 等长改包与 Windows so 构建三则

## 1. MT 签名杀手不必改游戏父类：`appComponentFactory.instantiateApplication` 触发即等价

- **事实**：MT `bin/mt/signature/KillerApplication193` 的安装动作**全在 `<clinit>`**（`killPM(pkg, base64Cert)`：换
  `PackageInfo.CREATOR` → 清 `PackageManager.sPackageInfoCache` / `Parcel.mCreators` / `Parcel.sPairedCreators`；
  `killOpen(...,"","","")` 三参空串即刻返回，是空操作）。
- **推论**：只要在**首次读签名之前**让该类被初始化即可，不必走暗影格斗3 的「改 `androidx/multidex/MultiDexApplication.super`」。
  在 manifest 已挂的 `AppComponentFactory.instantiateApplication` 里 `Class.forName(KILLER_CLASS, true, cl)` 即可，
  时序上更早（早于 Application `attachBaseContext/onCreate` 与全部 ContentProvider），且**官方 dex 零字节改动**。
- **证据**：魂坠深境 1.1.3（雷电 Android 14，x86_64）连续 3 次冷启均
  `StarryAppFactory: SignatureKiller mounted: … PM/Parcel caches cleared`，且 `CONFIG_ERROR`/`包名、签名` 0 行、3 分钟后无崩溃；菜单 3/3、`auth game_id hzsj` 3/3。
- **反例/边界**：① 只测一次不够——自研「CREATOR-only + Provider 挂载」版首启过、二启必挂（SF3 实测），
  故验收判据必须是**连续 ≥3 次冷启**；② 挂载点是共享源（`StarryAppComponentFactory`）时，缺 killer 类的包会
  `ClassNotFoundException`，必须 try/catch 静默跳过，否则影响其它游戏；③ 目标类被 proguard/加固改名时此法失效（改走改包法）。

## 2. 超大 dex 的「改包法」可以等长就地替换字符串，不必 baksmali/smali 整份

- **事实**：TapSDK 4.x 的 client-SSO 分支点在 `com/taptap/sdk/login/impl/data/model/Actions$CN.getAction()`
  返回常量 `"com.taptap.sdk.action"`（`ClientLoginUtils.isClientLogin` 用它 `resolveActivity`）；改成等长串即恒 resolve 不到 ⇒ 落内嵌网页。
- **做法**：`dex.count(old)==1` 断言 → 字节等长替换 → **重算 header**（`signature = SHA-1(bytes[32:])`、
  `checksum = adler32(bytes[12:])`）→ 回读断言「尺寸不变 / 新串 1 / 旧串 0 / 两摘要自洽」。
  魂坠深境 classes3.dex 10,429,708 B 全程未反编，装机与 3 次冷启正常，`com.taptap` 客户端零拉起。
- **边界**：替换串必须**等长**；命中数 ≠1 视为锚点漂移直接失败；dex 是 STORED 还是 DEFLATE 不影响（重新写 zip 条目即可）。

## 3. Windows 侧 so 构建：`wxsj_dll` 预编译残留会让 `ndk-build` 直接 FAIL

- **事实**：`Android_*.mk`（约 40 个）里都带着「无限升级 patched targetfunctional.dll」的
  `LOCAL_MODULE := wxsj_dll / LOCAL_SRC_FILES := Games/WxsjPatchedDll.a` + `LOCAL_STATIC_LIBRARIES := Dobby wxsj_dll`；
  该 `.a` **未被 git 跟踪**，只在跑过 wxsj 构建的机器上存在 ⇒ Windows 树 `ndk-build` 报
  `LOCAL_SRC_FILES points to a missing file` 直接 Abort。
- **做法（魂坠深境已落地）**：用 `ifneq ($(wildcard $(LOCAL_PATH)/Games/WxsjPatchedDll.a),)` 守卫模块与链接项 ⇒
  有文件时行为完全一致（mac 不受影响），无文件即跳过。
- **副作用（必记）**：跳过会让 so 少掉 `.data` 里约 2 MB 的 patched-.dll 载荷（实测 2,224,328 → 199,096 B，
  `.text/.rodata` 字节数一致；`llvm-readelf -S` 对比可复现）。该载荷与 Unity il2cpp 游戏无关，属死重量。
- **附带**：`framework_entry_audit.sh` 的 [D]（激活分支 vs 游戏名）只读共享 `jni/Android.mk`（`MK="$JNI/Android.mk"`），
  看不到本游戏走的是 `Android_hzsj.mk` ⇒ 会在现代 per-game mk 的包上报假 ✗；判「so 是否为本游戏编的」应以
  `hzsj_build_so.sh` 的 `MK=` 变量 + so 内游戏标签串 + 构建戳为准。
