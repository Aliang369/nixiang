## 2. 观察、解释与候选经验

- **观察事实**：
  1. 用户口令里的"所有安装包文件都清理、只保留 10 的文档"与现行规则存在两处口径差：`02_apks/` 原包必须点名授权；`04_scripts/` 属复现链、规则规定永留。
  2. 实际执行分两轮：第一轮删除 03/06/09 三类滚动物（约 1.17G）并保留 `04_scripts/` 与 `02_apks/`；第二轮用户点名 `02_apks/闪耀吧噜咪/闪耀吧噜咪_1.5.3_taptap_official_from_device.apk` 后才删除。
  3. 现行规则本身正确（`AGENTS.md`：收尾/省空间/全部清理不能代替未明确的路径与边界），代价是**每次收尾都要多一轮澄清**。
- **候选解释 H1**：歧义不在"要不要清"，而在"口令覆盖哪些目录"。把常见口令与默认范围的对应关系写死，可以在**不放宽授权**的前提下消掉这轮澄清。
- **替代解释 H2**：这类澄清应当保留为人工确认，不应表格化（担心表格被当作默认授权）。缓解措施：表中明确写"默认范围只定义被覆盖的路径，未列出的路径一律视为未授权"。
- **拟提炼的经验**（表格草案）：
  | 口令 | 默认覆盖范围 | 明确不覆盖（需点名） |
  |---|---|---|
  | 收尾 + 清理 + git | `03/06/09/07` 本作滚动物；`08_output` 按 `prune_output_final.sh` 裁剪为唯一正式包；提交本地 git | `02_apks`、`04_scripts`、`mod菜单` 源码、其他游戏目录 |
  | 全部清理 | 上一行 + 本作 `02_apks` 原包/候选包 | 其他游戏 `02_apks`；`04_scripts` 自写工具 |
  | 只保留 10_docs | 上一行 + 本作 `04_scripts`（会破坏复现链，必须先提示） | 其他游戏任何目录；10_docs 内文档一律保留 |
  另附动作约定：AI 收到口令后先执行**默认范围内**的可逆清理，然后用一句话列出"未覆盖项（路径 + 大小）"请用户点名，不重复询问已覆盖部分。
- **适用范围**：本工作区所有游戏的收尾/清理会话（流程层，与游戏、引擎无关）。
- **不适用范围 / 已知例外**：涉及设备侧残留、密钥/签名材料、其他会话并发写入的文件时，仍按 `AGENTS.md`「真机残留清理」与「备份与执行顺序」单独处理，不并入本表。

## 3. 反证、失效与最小区分实验

- **可推翻的观察**：如果某次收尾用户明确说了"全部都要删（含 02/04）"，则本表的默认口径被显式覆盖，不构成反证，只需按点名范围执行。
- **已收集反证**：无。本次两轮确认的实际耗时约一轮往返。
- **失效条件**：工作区目录规范变化（例如 `04_scripts` 改为可清理），或 `08_output` 裁剪策略变更。
- **失效后处置**：同步更新表内对应行，并在表中标注生效日期；不与更早记录混用。
- **最小区分实验**：下一次收尾时，AI 按本表先执行默认范围并只列未覆盖项；若用户仍需多轮澄清，说明表格不解决问题，应回退为纯人工确认。
- **停止条件**：任何一次清理出现"用户以为已授权、实际未列路径"的情况，立即停用本表并回收。
