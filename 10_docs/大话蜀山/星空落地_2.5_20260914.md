### 2.2 免广告（新增，非斌哥功能）

游戏广告链路（静态 + 动态实证）：

```
客户端 GameAdReq{platformCode,args,adType,adTypeDetail}
  → 服务端 GameAdRsp{code,platformCode,adId,args,avoidAd,adType}
  → 客户端播 SDK 广告 → GameAdCompleteReq{platformCode,adId,args,avoidAd,adType}
  → 服务端 GameAdCompleteRsp → 发奖
编排类：Cylj.Game.GamePlatformManager（PullAD / PullADDown / OnGameAdNotify / AdCallBack / GameAdCompleteReq）
缓存静态字段：requestADID / requestADArgs / requestADAvoid / requestAdCode
异步状态机 GamePlatformManager.<PullADDown>d__24.MoveNext 内存在「avoidAd 为真 → 直接 GameAdCompleteReq」分支
广告位常量（AdSourceConst）：update_skill / update_artifacts / resurrection / artifact_gacha / Partner_GACHA / item_buy / sweep_elite
```

实现：钩 `GamePlatformManager.OnGameAdNotify(GameAdRsp)`，放行原逻辑后用 il2cpp 反射
（`il2cpp_class_get_field_from_name("requestADAvoid")` + `il2cpp_field_static_set_value`）把该静态字段置真
→ 客户端走官方免广告分支，跳过 SDK 播放直接完成。

实测日志（用户开关 #3 后连续 3 次广告位触发，均正常发奖）：

## 3. 关键技术发现（本作特有，值得跨会话复用）

### 3.1 libil2cpp **双副本**（v1/v2 两次翻车的根因）

真机 `/proc/<pid>/maps` 实测同进程存在两份 libil2cpp：

| 路径 | 大小 | 角色 |
|------|------|------|
| `/data/data/<pkg>/files/libil2cpp.so` | 118,366,896 B（build-id `fbf1e94a51114940`） | **壳解密后的真身，游戏实际执行** |
| `/data/app/~~…/lib/arm64/libil2cpp.so` | 117,854,832 B（build-id `4a3d76449b446b9f`，=APK 内那份） | 宿主/诱饵副本 |

后果与对策：

- **v1 崩溃**：`dlsym("libil2cpp.so")` 命中诱饵副本的导出 API → 调 `il2cpp_domain_get` 时 `Class::Init(NULL)` SIGSEGV（tombstone 实证）。
- **v2 静默失效**：静态 dump 的 RVA 属诱饵副本坐标系，在真身副本上序言不符 → 拒绝安装（功能不生效，但**不崩**，属设计内失败）。
- **v3 定稿**：`/proc/self/maps` 按路径收集副本，**优先 `*/files/libil2cpp.so`**，`dlopen` 该路径拿真身 handle，再从该 handle `dlsym` il2cpp API；挂点用「MethodInfo.methodPointer」而非 RVA。

真身副本 rva（本次实测，供后续版本对照）：`ServerStep 0x333ED08`、`ApplyDamage 0x356328C`、`OnGameAdNotify 0x336702C`。

### 3.2 反作弊 / 上报调查（结论：不需要额外处理）

| 项 | 实证 | 处置 |
|----|------|------|
| 服务端战斗校验 | `BattleOverReq{isWin,damageValue,maxSerial,duration,killMonsterNum,wave,damageJson,args}` 由 `BattleRoom.SendGameOver` 发送（全库唯一发送点），服务端回 `BattleResultNotify{isWin,rewards,verifyStatus}` | 保持 `isSingle==1` 门控；单机档不走该上报链路 |
| 本地内存校验 | `Cylj.Core.SafeBool/SafeInt/SafeLong/SafeUInt/SafeULong/SafeFP` getter 自校验，失败调 `AntiCheatHelper.OnDetected()` | 注册入口 `OnMemoryCheatDetected(Action)` 全库 **0 调用点** → `_onDetected` 恒空，`OnDetected()` 实为空操作；且本方案不写这些 Safe* 字段 |
| native 反调试/反注入 | `libEncryptorP/libluster/libthemis/libturingad/libzeus_direct_dex/libbootstrap` 内 frida/xposed/magisk/ptrace/tamper/root 关键字命中 **0**（libunity/libil2cpp 命中为 `PTRACE_EVENT_*` 与英文词表误报） | 无需处理 |
| root 检测 | 仅存在于斌哥自加壳 `libtoolChecker.so`（RootBeer 家族），官包无 | 与本包无关 |
| 公告屏蔽 | 斌哥壳常开（`NoticeUI::OnOpen`），用户未要求 | **未做** |

### 3.3 TapTap 登录

- 官包 TapSDK 4.9.0 路由实测：`LoginTypes$Companion.from` → `ClientLoginUtils.isClientLogin` → `CLIENT/CLOUD_GAME/WEB`；`TapTapLoginActivity` 读 extra `com_taptap_sdk_login_request` 的 `LoginRequest.loginType`，`DefaultTapLoginFragmentProvider` 按 `embedded_web` 分流到 `WebLoginFragment`。
- 本包用运行时反射强制网页（`TapLoginForceWeb`，包名已入白名单）+ `SignSpoof` 回灌官方证书（`CN=tom`，MD5 `9ff0bc6e9ac45a30901da7584436487f`），**未改官方任何 dex**。
- 实测：用户正常登录并进入游戏（卡密 `grant ok`）。强制网页分支本身缺独立日志证据 → **NOT PROVEN**（不影响交付，登录可用）。

## 5. 遗留 / NOT PROVEN

1. 真身副本无法静态 dump（`Il2CppDumper` 报 protected）→ 现用「运行时按名取 methodPointer」；若后续版本改类名/方法名，需重新抓点。
2. 免广告依赖服务端接受客户端置位的 `avoidAd=true`：本次服务端接受并发奖（3/3 次）；若未来服务端改用广告平台 S2S 回调核验，该功能会失效（届时标记不可行）。
3. `Toggle_免广告` 属**新增功能**（斌哥包没有），非「复刻」项；若用户要求严格只复刻斌哥原样，可关掉不启用。
4. TapTap 强制网页分支无独立日志证据（登录本身可用）。
5. 官包验证：`verifyStatus` 分支在本包单机玩法下不触发；联机玩法下三功能按设计**不生效**（`isSingle==0`）。
