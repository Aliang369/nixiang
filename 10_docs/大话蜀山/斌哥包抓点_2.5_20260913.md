结论（与用户口述「秒杀、无敌」的对应关系）：

| 菜单位 | 斌哥显示的菜单名 | 实际实现（壳内自述） | 用户口述 |
|--------|------------------|----------------------|----------|
| `featNum=0` | 百倍伤害 | 对目标**连击 N 次**（`连击looped/实打actual`，`AddHp` 用于死亡提前收手） | 秒杀 |
| `featNum=1` | 玩家无敌 | **敌人攻击不生效**（计数 `blocked`） | 无敌 |
| —（常开） | 无开关 | 公告屏蔽（`NoticeUI::OnOpen`） | 本轮不复刻（越出用户范围） |

门控（三条同时成立才动手，否则安全失败）：

1. `ServerStep` 被调用过且 2 秒内仍在调（`在战斗=1`）；
2. `BattleRoom.isSingle == true`（联机档一律不生效）；
3. 钩子自身安装成功（`ready=1`）。

斌哥壳还挂了结算上报探针（`isWin/playCode/damageValue/maxSerial/duration/killMonsterNum/wave/isExit` + 服务器 `verifyStatus/rewards`）与 `BuildPassCheckInfo` 反作弊探针，**只用于日志观察，不是功能实现**（壳内自述「结算探针缺 %d 个 -> 只少 verifyStatus 日志, 两个功能不受影响」）。本轮不投入。

## 3. 原版锚点（静态 dump 实测）

### 3.1 伤害主链

```csharp
// Namespace: Cylj.LockStep
public abstract class AnimalEntity : BaseEntity            // TypeDefIndex 844
{
    public AttributesBaseInfo info;       // 0x378   （info.hp 在 +0x80 ⇒ 对象内 +0x3f8）
    public CampType Camp;                 // 0x670
    public BuffSet <buffSet>;             // 0x770

    // Slot 19（虚方法，子类未覆写 5 参版本）
    public virtual void ApplyDamage(int damage, AnimalEntity other, bool isCrit = false,
                                    string skillCode, MagicType magicType = 0);
        // RVA 0x3450138（官包内 so 坐标系）

    public bool AddHp(long hp, AnimalEntity byEntity, bool isCrit = false, MagicType magicType = 0);
        // RVA 0x34503C4
}
```

`ApplyDamage` 反汇编可读出的确定性语义（官包 so 0x3450138–0x34503C4）：

1. 按 `isCrit` / `magicType` 给 `buffSet` 挂受击状态（magicType 3→0x10 / 2→0x8 / 1→0x4 / 其它→1；暴击→2）；
2. 走受击表现与伤害数字（`buffSet` + `animalView.ApplyDamage(damage, other)`，后者是 `AnimalView` 的 2 参虚方法）；
3. **`AddHp(-damage, other, isCrit, magicType)`** ← 真正扣血；
4. 扣血返回 true（死亡）→ 走 `battleSystem` 死亡/结算分支；
5. 未死亡时比对 `self.Camp(+0x670)` 与 `other.Camp(+0x670)`：同阵营直接返回，异阵营继续做伤害统计/被动等后续。

⇒ **`self` 是被打的一方**，`other` 是攻击者；改 `damage` 参数即可改变实际扣血，语义明确、无共享入口（不碰 `runtime_invoke`）。


`MagicType { NoReplacement=0, Fire=1, Water=2, Electric=3 }`；`FP` 为 8 字节定点的 `struct{ long _serializedValue; }`（AArch64 走整型寄存器）。

## 4. 本轮实现设计（星光 modern）

功能位号（`g_featureList` 下标，Category 占 0）：

| featNum | 菜单 | 语义 |
|---------|------|------|
| 0 | `Category_战斗` | 占位 |
| 1 | `Toggle_秒杀` | 对怪物目标伤害 ×100（斌哥菜单名「百倍伤害」） |
| 2 | `Toggle_无敌` | 玩家侧目标受到伤害置 0（斌哥菜单名「玩家无敌」） |

Hook 计划（**全部按名解析，零 RVA**，默认 0 hook 懒装）：

| Hook | 类/方法 | argc | 作用 |
|------|---------|------|------|
| 1 | `Cylj.Game.BattleRoom.ServerStep` | 1 | 取 `self`，读 `+0x10` 得 `isSingle`，刷新「在战斗」时间戳（2s 超时） |
| 2 | `Cylj.LockStep.AnimalEntity.ApplyDamage` | 5 | 门控通过后：怪物目标 `damage*=100`；玩家侧目标 `damage=0`，随后**照常转发 orig** |

约束与取舍：

- 两条 hook 只在 feat 1/2 打开时安装（`SyncHooks`），全关 = 0 改写；
- 所有分支都调用 `orig`，只改参数不吞事件（遵守 hook-rules §3）；
- `isSingle != true` 或 2 秒内没有 `ServerStep` → 一律不生效（与斌哥同款安全失败），避免联机档改伤害引发不同步/风控；
- 伤害做溢出保护（`damage > INT_MAX/100` 时钳到 `INT_MAX`）；
- 解析失败只降级并打日志，不阻断另一条 hook（hook-rules §17）；
- 不复刻公告屏蔽（用户未要求）；结算/反作弊探针不引入。

## 5. TapTap 强制网页登录（同包一并做）

官包 TapSDK 结构实测（`03_decompiled/大话蜀山/apktool_2.5_official/smali_classes2/`）：

```
com/taptap/sdk/login/impl/data/model/LoginTypes$Companion.from(Activity, Actions)Z
    → ClientLoginUtils.isClientLogin(Activity, Actions) → CLIENT / CLOUD_GAME / WEB
com/taptap/sdk/login/impl/ui/activity/TapTapLoginActivity
    EXTRAS_REQUEST = "com_taptap_sdk_login_request"
    onCreate: getParcelableExtra(EXTRAS_REQUEST) → request；savedInstanceState==null → fragmentProvider.provide(request)
    public final fallbackToWeb(LoginRequest)
com/taptap/sdk/login/impl/ui/fragment/DefaultTapLoginFragmentProvider.provide(request)
    按 request.getLoginType() 分流（embedded_web → WebLoginFragment）
```

⇒ 本作走**运行时反射强制网页**（与凡尘西游/我的修仙世界同族方案，**不改官方任何 dex**）：

1. `onActivityPreCreated`（Android 10+，本机 Android 16）：把 intent extra 里的 `LoginRequest.loginType` 反射改成 `embedded_web`，首建即直接进 `WebLoginFragment`，不拉起 TapTap 客户端；
2. `onActivityCreated` 兜底：当前 fragment 非 `WebLoginFragment` 时反射调 `TapTapLoginActivity.fallbackToWeb(request)`；
3. 包名 `com.cylj.rogue.tp479` 需加入 `TapLoginForceWeb.PKG_WHITELIST`；
4. 签名回灌由 `SignSpoof.install()` 负责（进程内 PackageManager 返回官方签名 `9ff0bc6e9ac45a30901da7584436487f`），与网页登录配套。

**NOT PROVEN**：本作是否真的从 `TapTapLoginActivity` 走登录、网页登录是否一次成功，需真机点一次 TapTap 登录看日志（`StarryTapLogin` / `mobile_client` vs `embedded_web`）。
