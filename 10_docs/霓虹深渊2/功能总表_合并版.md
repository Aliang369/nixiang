**关键语义变更（三次定稿）**
1. **一功能一开关（1:1）**：手雷/金币/水晶/钥匙 各自独立原子 `g_bomb/g_coin/g_crystal/g_key`，互不牵连 —— 开「无限手雷」不会顺带改金币。
2. **闸门从「万能闸」改为四通道白名单**：`ResGateOn(ct)` 只在 `ct ∈ {Bomb,Coin,Crystal,Key}` 且**该项自己的开关为开**时返回 true，其余 **33 个 CostType 一律走游戏原逻辑**（`Curse/Cooling/Unlocked/RewardDepleted/Heart/Shield/…` 不再被改写）。
3. **「彩色钥匙」以原生通道补回（四次定稿）**：NHY2 metadata 里确实**没有**独立的「彩色钥匙」货币字段/枚举项（`GameplayKey / ColorKey / SpecialKey / 彩色 / 彩虹` 全量搜索 0 命中；HUD 属性资源面板 `attribute-resources` 只有 `resources1{bomb,coin,key,item}` + `resources2{crystal,egg,jump,pet}`；NHY1 的彩色钥匙＝`GameplayKey` 属性机制，本作无对应物）。但游戏自带 **InfiniteKey / KeySuit（钥匙套装）**通道：`NEONPlayerState{_keySuitInfiniteKey, SetKeySuitInfiniteKey, ResolveInfiniteKeySources, get_HasInfiniteKey, get_InfiniteKey}` + `NEON.Game.PowerUps.HackerMarkPowerUp.KeySuitPowerUp` + `NEON.UI.KeyImageSync{normalSprite, infiniteKeySprite}` ⇒ 置真后 HUD 钥匙图标变彩色/∞，所有读该状态的消耗路径全免。该通道与「无限钥匙」(数量 9999 + `CostType.Key` 免费) **是两条不同的挂点** ⇒ 满足一功能一开关 1:1。
4. **「无限体力」用户明确不要**；斌哥 feat7–14 的 9 个未命名槽不采用；环境补丁 E01 去签名 / E02 强制网页登录不占菜单槽。

### 0.1.1 参考：`NEON.Game.PowerUps.Skills.CostType` 全 37 项

枚举位置：`NEON.Game.PowerUps.Skills.CostType`（TYPE index=9563，fields=38＝`value__` + 37 项，token `0x0400BD22`–`0x0400BD47`）。运行时开机日志会打全表：`CostType 全表: value__=… Bomb=0 Coin=1 …`。

### 2.1 斌哥的两个实现机制（可复用）

1. **40 字节特征码扫内存定位 + 期望地址一致性校验**，不用符号表（本作 so dynsym 加密，符号不可用）；
   4 条挂点：`Killable::TakeDamage` / `Killable::Update` / `Hearts::TakeDamage` / `Framework.Attri::TryGetValue`。
2. **按字段名强写常量**（大小写不敏感匹配，**只提升不降低**），目标就是本作的全局常量表
   `NEON.Game.Managers.GameConstVariables`（TYPE index=10208，methods=1 `.cctor`，**fields=380**）：
   `DefaultBomb / FireBomb / IceBomb / ThunderBomb / Liquor_Bomb / FinalBombCount / MaxBomb` → **9999.0**（手雷组）；
   `MultipleJumpCountLimit / ExtraMultipleJumpCountLimit / FinalMultipleJumpCountLimit` → **99.0**（跳跃组）。
   另有一个「全屏」类别标签在静态表里**没有条目** ⇒ 条目由服务端远程下发（这就是 N02 抓不全的原因）。
