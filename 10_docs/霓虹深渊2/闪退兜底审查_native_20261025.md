# 霓虹深渊2 — 菜单/战斗代码「异常兜底防闪退」审查与补齐（native 侧，20261025 / r24）

> 触发：用户 m00001「之前有部分人反馈打开闪退或者是开启功能闪退，顺便检查下菜单战斗代码异常兜底防闪退有做吗」
> 本文只回答「有没有做 / 缺什么 / 补了什么」，**不改任何功能的判据与落点**。
> 证据分级：**实测**（真机日志）/ **代码自证**（当前源码可见）/ **推断**（有机制依据，未实测）。

## 一、结论先说

| 问题 | 结论 |
|---|---|
| 有没有兜底？ | **有，但只覆盖了「已知出过事的少数热路径」**：`§④` 骨架（信号处理器 + 备用信号栈 + 保护区栈 + 槽位熔断）+ 12 处装钩走 `DobbyHookGuarded` + 热路径 `OkPtr/SafeRead/SafeWrite`。 |

## 三、本轮改动（全部不改变功能语义）

### 3.1 native（`mod菜单/starry-mod-menu/app/src/main/jni/Games/nhsy2Mod.cpp`）

1. **`GuardedOr<R>/GuardedVoid`（§④.9b）**：`FS_GUARDED` 的「带回退值」封装。
   - 语义：正常 ⇒ 返回 orig 原值；orig 内部崩 ⇒ 记一行 `★原函数崩溃已拦下 <tag> SIG(n) pc=模块+偏移 lr=… sp=… addr=…`，返回调用方给的**安全默认值**（0/false/nullptr），**进程继续**。
   - 覆盖：52 处 `调 orig`（战斗：移速/跳跃/全屏攻击 Attri 五连/Stat.get_Value/射程/DamageSize；资源：金币/钥匙/水晶/手雷/彩色钥匙/消耗漏斗/交易闸/标准版 8 个宏族；登录保命 3 处；Task.Delay 2 处）+ 水晶精灵 3 处。
   - 代价：每次多一次 `sigsetjmp`（arm64 ~10–20 ns），只在被挂钩的方法上付出；**热路径未新增日志、未新增 maps 查询**。

2. **装钩路径兜底（`SyncHooks`）**：
   - `ResolveOffsetsAndEnums()` 与 `InstallAllHooks()` 各自纳入保护区；
   - 失败/崩溃时**不置 `g_installPassDone`**，下一拍（200 ms）重试 —— 旧行为是一崩就死，新行为是「这次不装，下次再试」。
   - **为什么不全函数包**：`SyncHooks` 持有 `std::lock_guard`，`siglongjmp` 会跳过 C++ 析构 ⇒ `g_installMutex` 永久上锁、Tick 线程死锁。护栏刻意只包在两个内层调用的**同一函数帧**内。

3. **Tick 入口兜底**：`SyncHooks()` / `InstallLoginAssistHooks()` / `PushStandardEditionEntitlement()` 三个入口都套 `GuardedVoid`（它们跑在 mod 线程，崩了同样带走整个进程）。

4. **保护区外崩溃取证（§④.4a）**：
   - 信号处理器内只做「写 8 槽定长环 + 一次 `LOGE`（纯整数，不 malloc、不 fopen、不加锁）」；
   - 守护线程（500 ms 一拍）把环里的 `pc/lr/sp` 解析成 `模块名+0x偏移` 打印（`★未捕获崩溃定位 #n …`），可与静态反汇编/IG5 的 vaddr 直接对齐；
   - 行为中性：**取证不改变控制流**，之后仍按原逻辑链给系统处理器（该崩还是崩，但终于有证据）。

### 3.2 出包脚本（`scripts/surgical_nhsy2_2026.10.22.sh`）

- vc646 官方包**不再自带 `lib/arm64-v8a/libc++_shared.so`**（`libil2cpp.so`/`libunity.so` 的 `DT_NEEDED` 里都没有它 ⇒ 官方静态链接了），而本 mod so 的 `DT_NEEDED` **仍含** `libc++_shared.so`
  ⇒ 不自带一份就 **dlopen 失败**，表现就是「菜单不出现 / 打开即闪退」，且 logcat 里只有 linker 的符号错误，极易被误判成挂点问题。
- 处置：原包有 ⇒ 用官方那份（不覆盖）；原包没有 ⇒ 带 NDK 那份（1,794,776 B），并把它从「逐字节不变」断言里改成条件项。

### 3.3 Java 菜单层（详见 Java 报告，摘要）

`MenuService`（onCreate 裸段三段、`registerResumeWatcher`、`showMenu()`、`attachHostFocusWatcher`、`onActivityDestroyed`、两处 `catch(Exception)→catch(Throwable)`）、`ModBridge`（`tryCall` + native 推送失败 ⇒ 偏好回写 + UI 回弹）、`NativeMenuController`（`authExec` 任务体统一隔离）、`PlayOtaManager`（补 `catch(Throwable)`）、`StarryInitProvider`（Activity 生命周期回调里的 TapTap 登录补丁兜底）。

## 四、证据门禁

- **PROVEN（代码自证 + 构建/门禁实测）**：`GuardedOr/GuardedVoid` 54 处落地、编译通过；`check_release_clean.sh --tag nhsy2 --so …` PASS（0 违规、so 无诊断 chunk）；`check_release_apk.sh` 干净正式包；包内 so md5 与构建产物一致。
- **NOT PROVEN（本轮不能宣称）**：
  1. 「用户反馈的打开闪退 / 开启功能闪退已被修掉」**不可宣称** —— 我们手里**没有那批崩溃机的 logcat / tombstone / `crash_logs/*.txt`**；本轮是**消除风险面 + 补取证**，不是「已复现→已修复」。
  2. 新增的每处兜底**没有一条**在真机上被触发过（本机 r23 全程 0 崩溃）⇒ 兜底路径本身的正确性只有静态保证。
  3. `sigsetjmp` 在 52 处热路径上的实际开销未做帧率实测（推断：可忽略）。
  4. 用户机若崩在 **Java 层**，native 兜底无效；若崩在 **native 保护区外**（如游戏自身线程），本轮只能取到 `★未捕获崩溃定位` 一行，**仍然会闪退**（只能定位，不能救）。
