## 3. 「OTA 注册名已消失」的反证与该判据的局限

**局限先说**：本 so 的 JNI 名字串在产物中是 `OBFUSCATE(…)` 加密态，明文 grep 无判别力 ——
`nativeInit` / `nativeApplyGrant` / `nativeHasLiveSession` / `nativeGetPinnedCert`（这些确实注册了）在新旧 so 里 `grep -ac` 全为 **0**。
因此「新 so grep 不到 OTA 名」单独不构成证据，下面用替代判据。

| 判据 | 命令 | 结果 |
|---|---|---|
| ① 产物差分 | `grep -aoE '[ -~]{0,40}OTA[ -~]{0,50}'` | 旧 so **3 处 `[OTA] `** → 新 so **0 处** |
| ② 字符串表差分 | `strings -a -n 3 | sort -u` 后 `comm` | 旧 3,387 条 → 新 3,232 条（−155） |
| ③ 源码注册表 | `grep -c 'regOne(env, bridge' MainModern.cpp` | **18**；ModBridge.java native 声明 **18**，逐一对应，无 OTA 名 |
| ④ 下线提交 | `git show e08b8ba1 -- MainModern.cpp | grep '^-'` | 删除 nativeVerifyOtaSig / nativeApplyPlayPatch 两条 regOne 与 3 条 `[OTA]` 日志 |
| ⑤ dex 交叉核对 | 包内 classes5/classes3 的 ModBridge | 无这两个方法（Java 侧仅剩注释 `ModBridge.java:702`） |
| ⑥ 导出符号 | `llvm-nm -D` | 无 `Java_com_starry_magic_*` 静态绑定符号（全走 RegisterNatives），无 ota/playpatch |

结论：新 so 注册表 = 当前源码 18 项，与 dex 的 18 个 native 声明一一对应；旧 so 的 `[OTA]` 串已消失。
缺口（r34 装机判据已记）：`so 注册名 vs dex 声明` 的静态机检需先解密 `OBFUSCATE`，当前无此能力。
