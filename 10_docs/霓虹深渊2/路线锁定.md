**由此确立的三条事实（本版特有）**
1. `dynsym` 本版**只有 SysV `DT_HASH`、没有 `DT_GNU_HASH`** ⇒ 老代码 `nsyms` 恒 0（"dynsym self-parse: 0 syms"）。已修：`LocateDynsym` 增加 `DT_HASH.nchain` 作符号数 + `symtab/strtab` 可读性前置校验（不再造故障）。**但名字层已被整体替换成凯撒+1 诱饵，按名解析本就无效**（3 个 API 继续走 `ClassFromNameScan`/`GetMethodScan`/`ImageOf` 降级路径，r18 就是这么交付的）。
2. **themis 的崩溃处理器在本版是"坏的"**：它自己要 `pthread_mutex_lock` 一个已失效的锁 ⇒ 任何**真实** SIGSEGV 都会把它拖进无限递归。ART 的隐式空指针检查不会走到它（ART 自己处理），所以官方包能玩；而我们历史上所有"故意造故障"的手段（`SafeProbe` 探针、seccomp 触发、停线程）在本版全部会引爆它。
3. **seccomp 方案在本版整体作废**：装不装 seccomp 都会风暴（E6），且多次 `exit_group` 不是单线程可停。→ 依赖 seccomp 的 r20c 中和链路不能再作为交付依赖。
