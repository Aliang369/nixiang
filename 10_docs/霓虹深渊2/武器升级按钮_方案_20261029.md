# 霓虹深渊2「武器升级」做成执行按钮 — 可行性与实现方案（2026-10-29，未实现）

> 用户原话（本轮 m00001）：「第二就是帮我看看武器满级这个能不能做成执行的点击按钮，
> 就是当我点击执行的时候武器升级一次，你看看能实现吗？比如凭空出现经验，然后给角色吸收，
> 又或者直接点击后执行到武器升级的那一步，你看怎么来实现」

## 1. 结论

- **交互层零成本：能做。** 菜单框架原生就有「执行」按钮，端到端链路已经存在，不需要改框架：
  `FeatureListParser`（`Kind.BUTTON`，规格 `Button_标签`）→ `NativeMenuController` 的
  `case BUTTON:`（渲染「执行」按钮 + toast「已执行：…」）→ `ModBridge.onButtonClicked`
  → `nativeExecButton` → `MainModern.cpp` 的 `mb_nativeExecButton`
  → `g_btnTrigger[featNum]=true` + `g_mod->onFeatureChanged(featNum, true)`。
  先例：`Games/SelfEntry.cpp` 有 `"Button_测试执行"`（下标 12）。
- **难的是「点了之后怎么让武器真升一级且属性真提升」。** 我们现有实现是「只把升级所需经验压到 1」
  （`SoulLevelConfig.GetLevelUpRequireExp(Int32,UpgradeRules)` @ `libil2cpp.so+0xc54`，返回 1），
  它本身不产生经验；要有经验进来才会触发游戏自己的升级流程。
- 因此「点一次升一级」＝**给当前武器喂 1 点经验 + 只在这一瞬间把需求压到 1**。经验一进来，
  游戏自己的 `ProcessExpGain → IsMaxLevel 判定 → LevelUpWeaponCore(应用 UpgradeRules) → HUD 刷新`
  全链走完 ⇒ 等级 +1、属性按游戏规则真实提升。**不使用任何"伪造 UI"手段。**

## 2. 四条候选路线（按风险/成本排序）

| 路线 | 做法 | 风险 | 结论 |
|---|---|---|---|
| **R1 喂经验（推荐）** | 点击 → 对「当前武器实例」喂 1 点经验；同时开一个 one-shot 窗口让 `GetLevelUpRequireExp` 返回 1 | 中：需要拿到实例指针 + 一个「加经验」入口的真实 ABI；仍属"调游戏自己的方法" | **走这条** |
| R2 直接推进升级 | 直接调 `FirearmsPowerUp.LevelUpWeaponCore(exp, level, rules)` | 高：r29a 已实测——`UpgradeRules` 是值类型（4×float），当指针传 ⇒ ABI 不符；强改入参把游戏踢进死循环、分解即卡死（挂点已永久删除） | 不做 |
| R3 凭空造经验球 | Instantiate 一个经验球 prefab 让角色吸收 | 最高：要跨 ABI 走 Resources.Load + Instantiate + 拾取链，还在 themis 保护下凭空造宿主对象 | 不做（成本/风险都不划算） |
| R4 纯写存档字段 | 只把 `CurSoulData` 的 level/exp 改大 | 低但**不满足需求**：HUD 会变，属性不会真提升（用户要的是"属性也提升"） | 不做 |

## 3. R1 的实现拆解（下一轮的具体动作）

1. **取证（必须先做，被阶段闸门挡着）**：运行期 metadata 枚举 `FirearmsPowerUp` 的 104 个方法，
   找「加 Soul 经验」的入口（候选名字形如 `AddSoulExp/AddExp/GainExp/…`），并用
   `debug.starry.nhsy2_wlv_probe=1` 那套「打印 MethodInfo→methodPointer 地址 + 本地 capstone 反汇编」
   确认它**只收标量参数**（`(Int32)` 之类）。r29f 已证明这条路可行（当时就是这样定案 `0xc54` 的）。
2. **拿当前武器实例**：只读钩 `FirearmsPowerUp.GetRequiredExpForNextLevel(PlayerActor,Int32)` 或
   `EnsureSoulDataInitialized()`（HUD/初始化必经）把 `this` 记下来；两个都是**已在用的探针**，风险最低。
3. **喂经验 + one-shot 需求窗口**：点击瞬间置 `g_wlvClick=true` → 调入口喂 1 点 →
   在 `Hooked_WlvReqExp2` 里「`g_wlvClick` 为真时返回 1」→ 升级一次后清标志。
   （正常游玩时需求走原值，不污染原版经验曲线。）
4. **兜底**：全部调用包 `GuardedVoid`；失败只打日志、不重试、不影响其它功能（r29a 的教训）。
5. **判据**：`wlv: click 喂经验 ok=1` → `OnWeaponSoulDataChanged level=N+1` → 属性面板同步变化。

## 4. 槽位（需要你定，涉及既有硬约束 #3）

现在 14 槽（2 分类 + 12 项），「解锁标准版」按硬约束 #3 固定槽 8。加「执行」按钮会多一项：

- **方案 A（推荐）**：把槽 6 的 `Toggle_武器满级` **换成** `Button_武器升级（点一次升一级）`
  ⇒ 槽位总数不变、槽 8 不动、战斗分类语义不变；满级＝连点 8 次（1→9）。
- **方案 B**：保留开关，另加一个按钮 ⇒ 只能塞到资源分类末尾（槽 14，分类语义变味），
  或者让「解锁标准版」挪到槽 9（**违反硬约束 #3**，需你明确点头破例）。
