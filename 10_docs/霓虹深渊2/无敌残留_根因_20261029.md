# 霓虹深渊2「无敌关掉后仍然无敌」根因定案 — 2026-10-29（r30）

> 用户原话（本轮 m00001）：「有一个bug需要修复，就是角色掉血的时候，开了无敌，在把无敌关了，
> 任务就一直保持无敌的状态，没有因为功能关闭而失效，定位下问题。」

## 1. 结论先行（代码级定案）

**根因＝「无敌」钩子只写不还**：`NEON.Game.Hearts.DeductHP` 的钩子体在开关打开时把
玩家 `Hearts` 实例上的两个字段写成 1，**全仓没有任何一处把它们写回 0**。
开关关掉后钩子只做「原样转发」，但游戏自己的无敌判定读的是**那两个字段**（不是我们的开关），
所以依然判玩家无敌 ⇒ 表现为「关了也一直掉不了血，直到换角色/重开一局」。

## 3. 修法（r30 已改）

`Games/nhsy2Mod.cpp` §6.1 新增「写后回滚」：

1. `InvLatchRemember(thiz)`：写 1 之前把实例地址 + **写之前**的两个字段原值记进小表（≤4 个实例，
   同实例只记第一次 ⇒ 原值不会被后续覆盖）。
2. `InvLatchRelease(why)`：把两个字段写回记录的原值；写前用**对象头 klass == `NEON.Game.Hearts`**
   校验实例仍活着（防对象被释放后内存复用 ⇒ 盲写别人对象）。
3. 三个触发点：`nhsy2_OnFeatureChanged(NHSY2_FEAT_INV,false)`、`nhsy2_ForceClear()`、
   `nhsy2_Tick` 兜底（`!g_inv && 表非空` 才动作，每 200 ms 一次，表空零成本）。

判据日志（L2 用）：

```
[nhsy2] inv: 挡下受伤 #1 inst=0x…                      ← 开无敌期间挡下扣血
[nhsy2] inv: 无敌残留回滚（toggle_off）inst=0x… inv 1->0 unk 1->0
[nhsy2] inv: 残留回滚完成（toggle_off）回滚实例=1
[nhsy2] inv: 无敌已关，DeductHP 放行 #1 inst=0x… orig_ok=1 r=…
```

## 4. 未决 / 风险

- 「回滚到原值」而非一律写 0：若游戏自己当时正给玩家无敌帧（原值=1），我们保持 1，不主动解除游戏的无敌帧。
- 若玩家 Hearts 实例在关开关前就被销毁（换角色/重开一局），klass 校验不过 ⇒ 只打 `残留回滚跳过（实例已失效）`，
  不会盲写（此时残留字段随旧对象一起消失，无副作用）。
- 本轮交付方式＝**只换 so**（硬约束 A#7：更小改动优先 root 覆盖已释放的 so，不碰包安装）；
  正式包（APK）本轮**未重打**，`08_output` 里的 r29 包与设备当前 so 不再逐字节一致 ——
  若要出交付包，下一轮按管线 `build_surgical → sign → install` 重打一次即可（需要官方底包 APK）。

## 5. 复现 / 验收（用户侧最小操作）

1. 进一局，菜单开「无敌」→ 让怪打一下（不掉血、日志出「挡下受伤」）。
2. 关「无敌」→ 让怪再打（应正常掉血、日志出「放行」）。
3. 需连续验证：再开、再关各一次，确认不再残留。
