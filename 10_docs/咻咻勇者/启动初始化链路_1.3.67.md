## Q6. 可注入点建议（Java 层，按稳定性排序）

1. **`com.taptap.sdk.login.impl.utils.ClientLoginUtils#isClientLogin(Landroid/app/Activity;Lcom/taptap/sdk/login/impl/data/model/Actions;)Z` → 强制 `return false`**
   - 理由：这是 CLIENT/WEB 分支的**唯一真值来源**（`LoginTypes$Companion.smali:82` 唯一调用方），改它不会破坏任何其它逻辑，且**直接消除** `ClientLoginFragment` 无 try/catch 的 `startActivityForResult` 崩溃风险。等价于「永远走网页登录」。
   - 位置：`s_classes6/com/taptap/sdk/login/impl/utils/ClientLoginUtils.smali:61`。

2. **`com.taptap.sdk.login.impl.data.model.LoginTypes$Companion#from(Landroid/app/Activity;Lcom/taptap/sdk/login/impl/data/model/Actions;)Lcom/taptap/sdk/login/impl/data/model/LoginTypes;` → 直接返回 `LoginTypes.WEB`**
   - 理由：位于 `isClientLogin` 之上游、`LoginCoordinator` 之下游，双保险绕过；同时天然绕过 `CloudGameUtils.isCloudGame` 带来的 CLOUD_GAME 分支。`LoginTypes.WEB` 静态字段见 `LoginTypes.smali`。

3. **`com.taptap.sdk.login.impl.ui.fragment.DefaultTapLoginFragmentProvider#provide(Lcom/taptap/sdk/login/impl/data/model/LoginRequest;)Landroid/app/Fragment;` → 恒返回 `WebLoginFragment.INSTANCE.newInstance(request)`**
   - 理由：UI 选择的**最终仲裁点**，无论前面 `LoginTypes` 如何算，落到 Fragment 一定是网页登录。

4. **`com.ultrasdk.official.third.taptap.HeroTapHelper#tapTapLogin(Landroid/app/Activity;Lcom/ultrasdk/official/third/interfaces/OnLoginListener;Lcom/taptap/sdk/kit/internal/callback/TapTapCallback;)V`**
   - 理由：本包自研的 TapTap 集成收口，**唯一的 `TapTapLogin.loginWithScopes` 调用方**（`HeroTapHelper.smali:385`）。在此改写可：① 换成自建账号体系；② 用自定义 `TapTapCallback` 伪造 `TapTapAccount` 直接回调成功；③ 先 `initTap` 再登录。`initStat` 未初始化时会走「未初始化TapTap」失败分支，注意一并处理 `HeroTapHelper#initTap`（`:178`，`TapTapSdk.init` 的真实点 `:259`）。

5. **`com.ultrasdk.SdkSplashActivity#checkAgreementMsg(Landroid/app/Activity;)V` → 直接调用 `l()`**
   - 理由：跳过隐私政策/权限弹窗（`com.ultrasdk.dialog.w` / `.x`），免去人工同意；`l()` 是进入 `onSplashStop()` 的唯一出口。若不 hook 此项，必须有本地协议版本记录（`com.ultrasdk.utils.c1#b/j/k`）或 `swStatus`/`swPermission` 非 "1"。
   - 备选：`com.ultrasdk.SdkSplashActivity#k()` 或 `#l()` 直接强制调用，可**完全绕过 Splash 等待与协议**。

6. **`com.hero.herousdkcocos.HeroUSDKCocosBridge#login(Landroid/app/Activity;)V` + `com.ultrasdk.channel.ultra.User#login(Landroid/app/Activity;Z)V`**
   - 理由：JS→Native 的登录入口与渠道登录收口（`showLoginView(handler, 0x7de, true, true)`），可用于① 记录 JS 何时发起登录；② 直接把登录请求重定向到自建登录/网页登录；③ 跳过 `LoginDialog` 自绘 UI。

**辅助（非登录，但影响能否到达登录界面）**：`com.ultrasdk.SdkApplication#attachBaseContext` 中的 `MultiDex.install(this)` 与 `i0.X().S1/S1/j1/e1` **不可跳过**，否则 SDK 全局配置缺失（appKey/上下文）会导致服务端初始化与后续登录签名失败。
