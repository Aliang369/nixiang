菜单 HTML：`06_dumped/冒险与征途/menu_1194.html` / `menu_1194.txt`（194 行）。结构：三 tab（首页/用户中心/设置）、`#home-box` 动态填功能卡、脚本 `public/Game/app1.js?var=0517`、`onload → initGame(exp)`。

**功能配置是加密串** `var exp = "…"`（约 3.4KB）。解密链路（子代理复刻，纯标准库，与页面原生 `strencode` 输出逐字节一致）：

3. 逐字节 `data[i] ^= key[i % 36]`
4. 再 `base64dec`（过滤非 base64 字符）→ `utf8dec`

## 4. 开关链与旗标落点（实测）

**实测 prefs**（三项全开时，设备 `shared_prefs/com.mxyzt.gzmy_preferences.xml`）：

```xml
<map>
    <boolean name="0" value="true" />
    <boolean name="1" value="true" />
    <boolean name="2" value="true" />

```

**完整链路**：

```
菜单按钮 → injectedObject.startFunction(id, on)
   → BinGe;->startFunction(II)V            @0x264D8  (new Handler + new BinGe$2(this,id,on))
   → BinGe$2;->run()V                      @0x17E64  (取 val$id / val$b / prefs 文件名)
   → ۠ۢۤۥ;->ۥۣ۟(Object,IZ)V                @0x6A040  (check-cast + 转发)
   → Preferences;->changeFeatureBool(String,IZ)V @0x62658
   → Preferences;->writeBoolean(IZ)V       @0x65A80  (SharedPreferences.edit)
   → ۢۢۦۥ;->ۤۢۡ۠(Context,int,String,int,boolean,String)V @0x6B1C4
   → Preferences;->Changes(Landroid/content/Context;ILjava/lang/String;IZLjava/lang/String;)V   ← Java→native 唯一出口
   → 壳把该 id 的旗标置位（壳 rw 段 int32：0 → 1）
   → 游戏侧调用点读旗标（0=放行原逻辑 / 1=走修改逻辑）
```

**prefs 键名 = id 的十进制字符串**：`ۢۢۦۥ;->۟ۡۥۢۨ(I)String` @0x6A7B8 全 8 条指令就是 `if (v <= 0) return null; else return String.valueOf(v);`（readBoolean/readInt/writeInt/… 共 8 处共用）。

**`com/android/support/Preferences;->Changes(Context;ILjava/lang/String;IZLjava/lang/String;)V` 是 native（access=0x109, code_off=0）**，Java 交给 native 的只有 **int id + boolean on**（外加 Context、常量 prefs 名、两个 String）——**菜单侧不存在任何方法名**。

**旗标落点（差分实测，两次 dump 交叉验证）**：壳 anon rw 区 base `0x400020CC7000`（文件 `06_dumped/冒险与征途/mem_sdk2/anon4b.bin`）

|---|---|---|---|---|
| `+0x1728` | `0x400020CC8728` | 0 | 1 | id 0 → 秒杀小怪 |
| `+0x172C` | `0x400020CC872C` | 0 | 1 | id 1 → 超级无敌 |
| `+0x1730` | `0x400020CC8730` | 0 | 1 | id 2 → 全模式秒杀 |

- `+0x1F78` 与 `+0x2178` 两处均为 `32 00 00 00 | 32 00 00 00 | 01 00 00 00`（50/50/1；疑似伤害参数对与开关位），关态全 0

## 5. Hook 机制：DobbyHook HybridCLR 解释器入口 + 按方法名分发

**证据**：`libSDKloading.so` 里命中 `DobbyHook`、`dobby_enable_near_branch_trampoline`、`dobby_disable_near_branch_trampoline`；内存 anon1 区命中壳自己的中文诊断串：`IL2CPP_HOOK`、`捕获IL2CPP函数：%s，地址：%p`、`哈希表初始化完成，共加载 %d 个IL2CPP函数映射`、`已绑定函数：%s -> %p`、`[hook防护]第%d次收到不像指针的参数…按名字匹配的功能用不了`、`[MI-API]★本游戏第2参是【包装指针】,已自动解一层引用取名字(其它游戏是直接用)`。

**壳的工作流**（与日志逐条对应）：

1. `[hook等待]` 轮询本进程是否出现 `libil2cpp.so`
2. `[基址诊断]` 第 1 轮（要求代码段可执行）→ 失败 → 第 2 轮判据锁定
3. `[特征定位]` 解析 ELF：找引用字符串 `AllocFrame` / `AllocStackSlot` 的指令 → **向后扫 prologue 得函数入口** → 找调用 `AllocFrame` 的地方 → 找其调用者 = **HybridCLR 解释器入口** → `★解释器入口已定位`（`[定位方式]特征自动定位`）
4. `DobbyHook(入口)` → `HOOK函数成功`
5. 运行时经 il2cpp API（`自解析导出表` 方式，不依赖 `.dynsym`）把 `MethodInfo*` 解成 `类::方法` 名 → 与内置名字表匹配 → 匹配上就分发到对应功能实现

**解释器入口（子代理独立复现，llvm-objdump 逐行验证）**：

| 项 | 值 |
|---|---|
| RVA | `0x207F798` |
| 运行时 vaddr | `0x40002527F798`（= libil2cpp 基址 `0x400023200000` + RVA） |
| file offset | `0x207E798` |
| prologue | `stp x29,x30,[sp,#-0x60]!` + `sub sp,sp,#0xc40` + `mrs TPIDR_EL0` 栈保护 + `bl 0x205FF04`(pthread_getspecific 取每线程帧池) + `bl 0x207DE04` 建帧 → 巨型 dispatch 循环 |
| AllocFrame | RVA `0x207DDAC`；AllocStackSlot RVA `0x207DD40`（冷路径抛 `System.StackOverflowException`，消息串即 "AllocStackSlot"/"AllocFrame"） |
| 调用者统计 | 5,221 个 `bl` 调用点，其中 **5,219 个落在连续 AOT 解释器桩群 `0x21C7950–0x220BA00`**（桩形如 `sub sp,sp,#0x20; add x1,sp,#0x18; add x2,sp,#0xc; bl 0x207F798; ldrb w0,[sp,#0xc]; ret`） |
| 签名倾向 | `Interpreter::Execute(MethodInfo*, void*, void*)`（待运行时确认） |

每条记录 = 名字（ASCII，NUL 结尾，**补齐到 8 字节边界**）+ 8 字节 meta `{u16 0x0101, u16 0, u32 运行期值}`（那 u32 是每次运行都变的值：0x4063=16483 / 0x4032=16434 / 0x3FD8=16344=PID，**不是 id**；两版 dump 对比已证）。**注册顺序与偏移**：

**8 个名字的来源判定：不在 Java 侧，也不在磁盘上的任何文件（已证据穷尽）**

- **不在 Java**：`_hunt.py` 对 7 个 dex 的**全部 314 个 `fill-array-data` 数组**做 0..0xFFFF 全 key 单 short XOR 搜 8 个目标名 → **0 命中**（唯一真命中是 `Menu.<clinit>`@0x4BC94 用 609-short 池 + off=0 + len=^21 + key=0x360 解出的 `Menu.TAG = "Mod_Menu"`）；classes5.dex 2,683 串里 733 条非类描述符全查过，无一条是目标名；`GetFeatureList`/`startFunction` 这两个字符串在 dex 里也 **0 处被 const-string 引用**（纯反射调用）。
- **不在磁盘 so / metadata**：7 个 dex 原始字节（ASCII + UTF-16LE）、`libSDKloading.so`(3,893,752B)、`global-metadata.dat` 全 0 命中；`DoAttack`/`ShowWin` 在整个解包 APK 内 0 命中；壳 so 的 `.dynsym` 只导出 `JNI_OnLoad`。
- **真实来源**：壳运行期把名字**解密到自己的匿名段**（`anon4b` 名字池 + `anon1b` 解密后 rodata/日志串 + `anon5b` 疑似解密后 `.text`），并按名字匹配分发（壳自带日志 `[hook防护]…按名字匹配的功能用不了`、`连试%d个方法…都取不到合法名字`）。
- 旁证：`aot/Assembly-CSharp.dll` 的 .NET metadata 里 8 个名字全部正命中（`Damage`@17,486,489、`Character`@17,497,858、`DoAttack`@18,585,205、`StarsCollider`@19,173,329、`AddProjectile`@17,524,243、`ShowWin`@17,490,289、`MW_GameNotice`@18,210,887）。
- **要拿「id → 名字」的硬证据只剩两条路**（移植不需要，仅在需要证明时做）：① Frida hook `Preferences.Changes(Context,int,String,int,boolean,String)` 逐个 id 触发，同时 hook `il2cpp_method_get_name`/`il2cpp_class_get_name` 读返回值；② dump 壳解密后的匿名段（`anon4b` 名字池 / `anon1b` rodata / `anon5b` text）。

**8 个名字 ↔ 归属**（同上 §6 表）；壳 JNI 方法表也在同名池邻近区（`Icon`/`IconWebViewData`/`IsGameLibLoaded`/`Init`/`SettingsList`/`GetFeatureList`/`getGoHomeUrl`/`getNotNetworkMessage`/`AAA`/`getStringEX`/`getVersion` + `Menu; Changes;(Landroid/content/Context;ILjava/lang/String;IZLjava/lang/String;)V; Preferences; CheckOverlayPermission;(Context;)V;`）——**再次印证 id→名字映射不由 Java 提供**。
