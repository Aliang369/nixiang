## 2. 实现点

  `waitLib = libil2cpp.so`；`initRetryMax = 0`（禁止启动期 init，避加载窗死锁）
- Hook / 数据写入点：

    → DobbyHook → `Hooked_Interp` → `InterpDispatch`（64 槽自学习表：

## 4. NOT PROVEN

- **四项功能是否真在真机生效** —— 本版一行日志都没跑过，纯编译通过。
- **学习期能否把 8 个目标全部登记上**（`LEARN ok` 行是否出现）。
- **掉帧是否真的解决**（用户主观 + 入口 hook 本身仍在每次热更调用上过 Dobby trampoline）。
- **免广告只做到「强制成功回调 + 强制发奖」，没有做到「跳过视频播放」**（见 §5 限制 1）。
- **无敌是否挡得住服务端同步伤害**（`Character::Damage` 本版只取证、不改行为；目前靠 C 层兜底）。
- 验证所需条件：装机 1 次 → 打一场战斗 + 点一次广告 → 取 logcat。
- 观察点（按 hook-rules §25 装配自检）：`interp hooks armed` / `interp learn 窗口开启` /
  `LEARN ok <类>::<方法>` / `INTERP <tag> … hit=N` / `IHURT#` / `INV cancel DoAttack` /
  `AD force … -> 1` / `IEVID#`。
- 停止条件：若 `interp hooks armed` 不出现 ⇒ 入口 hook 没装上，后面全部无从谈起（先解决这一层）。

## 5. 已知限制

1. **免广告不是真免广告**：本版只做「`OnADVideoResult` 强制成功 + `DispatchResult` 强制发奖」，
   **视频仍会播放**。真正做到「跳过播放」需要在拿不到视频回调的前提下**代替 SDK 去调
   `DS_Advertising::OnADVideoResult(true, adid, uuid)`** —— 这需要跨方法调用（`runtime_invoke`
   在本项目已作为崩溃向量整段删除；解释器 thunk 共享又无法直接调）。**未做，不猜。**
2. **热更 DLL 换版本后**：`g_lslot` 里存的是**旧名字指针**，指针比较不解引用 ⇒ **不会崩**，
   但该目标不再命中。重开任一功能会重开学习期，然而已登记项(`g_kindDone==1`)默认不重学
   ⇒ 需重启 App。（设计上的取舍：热路径 0 字符串比较优先。）
3. **`InterpLearn` 只在学习期内有效**：广告链路的 3 个目标只在玩家点广告时才会被调用；
   若玩家在「打开免广告」之前从不点广告，可能学不到（重开功能会重开学习期）。
4. **路线冲突（必须让用户知道）**：`mod菜单/starry-mod-menu/docs/GAME_MOD_GUIDE.md` §1
   明令「只 hook 具体方法，**绝不 hook 共享入口**」。本包因「具体方法 methodPointer = 解释器共享桩」
   **没有别的挂点**，故按 `斌哥包抓点_20261002.md` 的复刻要求走了入口路线。本版把热路径压到
   「1 次读 + 2 次指针比较」，**没有任何字符串比较**，正是为了消掉指南点名的那条掉帧反例。
   回退办法：`kInterpEntryRva` 那条 hook 整块 `#if 0` 即可回到纯 C 层（= 只有无敌可用）。
5. 适用范围：仅本包 1.5.9 / vc159；换版本必须重做 §2 的挂点确认（`g_interpEntryRva` 绑 so SHA）。
6. 用户决定：记录 / 修复 / 暂停 —— **待用户**。
7. **下一条最小区分实验**：装机后**只开「无敌」**打一场，看 `INV cancel DoAttack` 是否出现。
   出现 ⇒ 入口分发链路通，其余三项只是参数/量级问题；不出现但 `interp hooks armed` 在 ⇒
   学习期没登记上 `DoAttack`（看 `LEARN 拒 …` 行）；两者都没有 ⇒ 入口 RVA/so 版本不对。
