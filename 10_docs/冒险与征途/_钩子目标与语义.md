## 2. 四个功能的 hook 目标

> 星光框架写法统一为：
> ```c
> void* mi = api.GetMethod(klass, "方法名", argc);          // 重载用 api.GetMethodBySig(klass,name,argc,typeA,typeB)
> DobbyHook(*reinterpret_cast<void**>(mi), Hooked_X, &orig);
> ```
> HybridCLR 字段偏移**一律运行时取**：`FieldOffset(klass, "字段名", HYBRIDCLR_FIELD_BIAS)`，本文不给静态偏移当结论。

### 2.1 「秒杀小怪」（菜单 1）

**主 hook 点：`ActionGameLibrary.CBattleActorUtil::Hurt`**

| 项 | 值 |
|---|---|
| 类 | `ActionGameLibrary.CBattleActorUtil`（程序集 `Assembly-CSharp`） |
| 方法 | `Hurt` |
| argc | **5** |
| 参数类型 | `(ref ActionGameLibrary.CtagHurtHPPara, ref bool, bool, ref BigInt, bool)` |
| 返回 | `int` |
| 方法 token | **0x0601E25A** |
| 是否静态 | **是（PROVEN）**：IL_0000 `ldarg.0` 直接 `ldind.ref` → arg.0 就是第一个 ref 参数，说明没有 `this` |
| 证据 | `_tgt_il_hp.txt:5-183`（全文 183 行，body len 由 `_tgt_dump2.py` dump 得出） |

**为什么它是"唯一真正的伤害出口"（PROVEN 链）**

1. `DamageFactory::ExecDamageCalc`（0x0601E571）算出伤害后调 `DamageFactory::ProcDmgHit`
   （`_tgt_il_df4.txt:295-567`，生效分支 `IL_01FD-024E`）。
2. `DamageFactory::ProcDmgHit(IActionGameObject attacker, IActionGameObject target, TSpellHitPara, BigInt damage, ref List<HurtShowInfo>, ref bool, int) -> int`（**0x0601E578**，argc=7，`_tgt_il_df4.txt:1041-1215`）：
   - `IL_0052: CtagHurtHPPara::Alloc(target, attacker, damage, para.iSpellID, 1, 0)`（**0x0601E558**，注意 **target 在前 attacker 在后**）
   - `IL_0092: CBattleActorUtil::Hurt(ref para, ref arg5, true, ref loc1, false)` ← **本 hook 点**
   - `IL_0170-0171`：给 `CHitNotifier::AddOneHitHurt` 传的伤害值是 **`para->GetValue()`**（不是 `arg.3`！）
   - `IL_01B4: CHitNotifier::AddOneHitHurt(...)`（**0x0601E456**，14 参）→ `IL_01BA: CHitNotifier::Broadcast()`（**0x0601E45F**）
3. `CHitNotifier::Broadcast()` → `EffectToCast()`（**0x0601E461**，`_tgt_il_hp.txt:2196-2260`）：
   ```il
   IL_0036: callvirt proto_ff.CSOneEffect::get_hurt() -> CSEffectHurt
   IL_0049: callvirt proto_ff.CSEffectHurt::get_value() -> MsgInt128
   IL_004E: call    Int128Convert::ToBigInt(MsgInt128) -> BigInt
   IL_0053: ldc.i4.1        // DamageEnumerate.DamageType.DAMAGE
   IL_0055: callvirt ActionGameLibrary.Character::Damage(BigInt, DamageType, bool) -> void   // 0x0601F132
   ```
   → **`Character::Damage(BigInt, 1, true)` 才是真正把 HP 扣到 0 并触发 `CheckDead`/死亡动作的地方。**
4. `CBattleActorUtil::HurtHp`（**0x0601E25B**，`_tgt_il_hp.txt:184-257`）里有钳制：
   ```il
   IL_0024: GetCalculateDamage() -> BigInt
   IL_002D: if (hp <= dmg) { dmg = hp - 1; if (dmg <= 0) return -1; }   // IL_0036-0052
   ```
   **⇒ `HurtHp` 永不致死**（最多打到 hp-1）。所以"秒杀"的效果必须靠 `para.m_llValue` 被放大后经 `AddOneHitHurt` 写进通知包、再由 `EffectToCast → Character::Damage` 落地。
   **这正是"改 `m_llValue` 就能一击必杀"的机制证明。**

**建议 hook 写法（伪代码）**

```c
// 静态方法：arg0 = CtagHurtHPPara** ，arg1 = bool*，arg3 = BigInt*
static int (*orig_Hurt)(void** paraRef, bool* p1, bool p2, void* pBigInt, bool p4);

int Hooked_Hurt(void** paraRef, bool* p1, bool p2, void* pBigInt, bool p4) {
    if (paraRef && *paraRef) {
        void* para = *paraRef;
        void* klassPara = api.object_class(para);
        // 1) 取被打者
        void* target = *(void**)((uint8_t*)para + api.FieldOffset(klassPara, "m_pTarget", HYBRIDCLR_FIELD_BIAS));
        // 2) 判"不是玩家" —— 见第 4 节
        if (target && !IsPlayerLike(target)) {
            // 3) 取/改伤害（BigInt，走 accessor，避免手解 ABI 布局）
            void* miGet = api.GetMethod(klassPara, "GetValue", 0);        // 0x0601E55B
            void* miSet = api.GetMethod(klassPara, "SetValue", 1);        // 0x0601E55D
            // 简易做法：直接用 op_Implicit(long) 造一个极大 BigInt 再 SetValue
            // BigInt v = BigInt::op_Implicit((long)999999999);  // 0x06000BE6
            // runtime_invoke(miSet, para, &v);
            // 秒杀档：SetValue(BigInt 极大，如 9.99e17)
        }
    }
    return orig_Hurt(paraRef, p1, p2, pBigInt, p4);
}
```

**兜底/替代 hook 点（若 `Hurt` 挂不上或想确保必死）**

| 备选 | 类.方法 | argc | token | 说明 |
|---|---|---|---|---|
| B1 | `ActionGameLibrary.Character::Damage` | 3 | **0x0601F132** | 参数 `(BigInt damage, DamageEnumerate.DamageType type, bool b)`；`type==1` 是扣血分支（PROVEN：`IL_0013 ldarg.2 / ldc.i4.1 / bne.un IL_0158`）。目标非玩家时把 damage 改为极大 → HP 归零 → `CheckDead` → 死亡。**这是必死保险丝。** |
| B2 | `ActionGameLibrary.DamageFactory::ProcDmgHit` | 7 | 0x0601E578 | 直接改 `arg.3`(BigInt 值参数)。缺点：BigInt 按值传参的寄存器布局**未验证**，不如 B1/Hurt 稳。 |

**依据汇总**：`_tgt_il_df4.txt:1041-1215`、`_tgt_il_hp.txt:5-257`、`_tgt_il_hp.txt:2196-2260`。

### 2.2 「无敌」（菜单 2）

**主 hook 点：`ActionGameLibrary.StarsCollider::DoAttack`**

| 项 | 值 |
|---|---|
| 类 | `ActionGameLibrary.StarsCollider` |
| 方法 | `DoAttack` |
| argc | **7** |
| 参数类型 | `(IAttack, IAccept, AttackData, AcceptData, UnityEngine.Vector3, int, SynHitData)` |
| 返回 | `void` |
| 方法 token | **0x0601E8D9** |
| 是否静态 | 否（实例方法，arg.0 = this） |
| 证据 | `_tgt_il_damage.txt:3-1439` |

**"命中作废"是官方现成路径（PROVEN，函数开头）**

```il
IL_0039: ldarg.2                              // arg.2 = accepter (IAccept)
IL_003A: brfalse.s   8                        // accepter == null → 跳到 IL_0044
IL_003C: ldarg.2
IL_003D: callvirt    IAccept::get_interactiveGameObject()
IL_0042: brtrue.s    1
IL_0044: ret                                  // ← 直接返回，不结算、不飘字、不触发死亡
```

⇒ **把 `arg.2`（accepter）置 null 再调 orig，就等价于斌哥日志里的「打中玩家的命中已作废(accepter置null,原函数自行返回)」。**

**建议 hook 写法（伪代码）**

```c
static void (*orig_DoAttack)(void* self, void* attacker /*arg1*/, void* accepter /*arg2*/,
                             void* attackData, void* acceptData, Vector3 hp, int i, void* syn);

void Hooked_DoAttack(void* self, void* attacker, void* accepter, void* aD, void* cD,
                     Vector3 hp, int i, void* syn) {
    if (g_wudi && accepter) {
        // arg.2 = IAccept；取它的 interactiveGameObject 判是不是玩家
        void* ao = Invoke_GetInteractiveGameObject(accepter);   // IAccept::get_interactiveGameObject()
        if (ao && IsPlayerLike(ao)) {
            orig_DoAttack(self, attacker, NULL, aD, cD, hp, i, syn); // accepter=null → 原函数 IL_0044 自行返回
            return;
        }
    }
    orig_DoAttack(self, attacker, accepter, aD, cD, hp, i, syn);
}
```

**必须同时挂第二个钩子（否则只挡客户端命中，挡不住服务端同步伤害）**

`ActionGameLibrary.Character::Damage(BigInt, DamageEnumerate.DamageType, bool) -> void` **0x0601F132**（argc=3）：
hook 内 `if (Type == 1 && IsThisPlayer(self)) return;` —— 因为 `EffectToCast()`（`_tgt_il_hp.txt:2196`）会用**服务器同步过来的效果包**直接调这个方法扣血，这条路径**不经过 `DoAttack`**。

可选第三层：在 `CBattleActorUtil::Hurt` 里判 `para->m_pTarget` 是自己就直接 `return 0`（一条顶两条，但会连飘字一起吞）。

**依据**：`_tgt_il_damage.txt:3-1439`（DoAttack）、`_tgt_il_hp.txt:2196-2260`（EffectToCast）、`_tgt_q.py il 0x0601F132`。

### 2.3 「全模式技能伤害增加」（菜单 3）

**与「秒杀小怪」共用同一 hook 点，只是倍率不同**：

| 项 | 值 |
|---|---|
| 类.方法 | `ActionGameLibrary.CBattleActorUtil::Hurt` |
| argc | **5** |
| token | **0x0601E25A** |
| 语义 | `para->m_llValue`（BigInt）= 本次伤害原始值；`para->m_llCalculateDamage`（BigInt）= 扣盾后值 |

改写策略：`m_llValue *= N`（N 为用户配置倍率；"秒杀"就是 N 取极大）。
`m_llValue` 会经由 `AddOneHitHurt` 的第 3 参数（PROVEN：`IL_0170-0171 call GetValue()`）写进命中通知包，因此飘字、`EffectToCast` 落地血、死亡判定**全部一致生效**，不会有"数字变了血没掉"的错位。

**若目标是"全模式"（对所有战斗模式生效）**，还需让DoAttack走客户端权威伤害分支。`DoAttack` 里的判定（`_tgt_il_damage.txt`，约 `IL_03CC-03E0`）：

```il
ldfld ActionGameLibrary.StarsCollider::localDamage      // 字段 0x0401764D
brtrue  → 走本地权威分支 (ProcDamageByClient)
ldsfld ActionGameLibrary.ActionGameLibraryConfig::IsEditorMode   // 静态字段 0x04017507
brtrue  → 同上
callvirt ActionGameLibrary.BattleElementCenter::get_localDamage() -> bool
```

⇒ **附加钩子（可选）**：`ActionGameLibrary.BattleElementCenter::get_localDamage` **argc=0**，token **0x0601E7FB**，恒返回 `true` —— 一条就够（不用逐个改实例字段）。它让每个命中都走 `DamageFactory::ProcDamageByClient(AttackData, AcceptData, IActionGameObject, IActionGameObject, bool, int, string, int)`（**0x0601E570**，argc=8）这条客户端权威管线，而不是读服务端的 `CHitNotifier::GetDamageInfo(int)`。

**风险**：`localDamage=true` 会让客户端伤害成为权威并同步给服务端；`BattleElementCenter` 的该属性是全局开关，可能被其它系统读取（如断线重连校验）。建议做成菜单项可关。

**依据**：`_tgt_il_df4.txt:1041-1215`、`_tgt_il_damage.txt`（DoAttack 的 localDamage 判定段）。

**建议 hook 写法（伪代码）**

```c
// 目标：点"看广告" → 不播视频 → 服务端照常按"看完"入账
static void (*orig_PlayADVideo)(void* self, int adid, void* jstr /*Il2CppString* uuid*/);

void Hooked_PlayADVideo(void* self, int adid, void* jstr) {
    if (!g_free_ad) { orig_PlayADVideo(self, adid, jstr); return; }
    // 1) uuid 十进制串 → ulong
    unsigned long long uuid = strtoull(api.string_to_utf8(jstr), NULL, 10);
    // 2) 直接"当作看完"：调 DS_Advertising::OnADVideoResult(true, adid, uuid)  （token 0x06001255，argc=3）
    void* dsAdvKlass = api.FindClassByShortName("DS_Advertising");       // 无命名空间
    void* mi = api.GetMethod(dsAdvKlass, "OnADVideoResult", 3);
    void* inst = /* DataService::advertising 静态字段 或 Singleton 取实例 */;
    bool b = true; unsigned long long u = uuid; int a = adid;
    api.runtime_invoke(mi, inst, /*args: */ &b, &a, &u);
    // 不调 orig_PlayADVideo → 不拉起 SDK，不播视频
}
```

**备选（纯本地发奖，省一层协议）**：hook `DS_Advertising::WatchAdvertisements` **argc=1**，token **0x06001251**：不调 orig，直接 `DispatchResult(adid, true)`（0x06001258，注意它 `arg.2==true` 才发 `Event_WatchADResult`）。适用于"奖励由客户端本地按配置表发放"的入口。

**不建议单用**：hook `DS_Privilege::MonthCardSkipAD() -> bool`（**0x06007E5F**，`_tgt_il_priv.txt:2958-2965`：`return MonthCardPrivilegeEnable(25) || MonthCardPrivilegeEnableEX(25);`）恒 true —— 它只去掉确认框，之后仍然发 `start_watch_ad_req`，服务端按账号是否真有月卡决定 `result`，**没月卡还会照常播视频**。

**风险（PROVEN 事实 + 判断）**

1. **`finish_watch_ad_req` 有 `sign` 字段，但客户端从不赋值。**
   `Proto_CSFinishWatchAdReq` 字段：`adId_` 0x04011F81 / `uuid_` 0x04011F84 / `result_` 0x04011F87 / **`sign_ : string` 0x04011F8A**；而 `ReqADVideoResult` 的 IL（`_tgt_il_ad2.txt:412-449`）只调 `set_ad_id` / `set_uuid` / `set_result`，**没有 `set_sign`**。
   → 服务端要么不校验 sign，要么由 SDK 侧（`com.hnyl.core.YLAPI$ADTTCallback`，见 `MiaoYueADCallBack::.ctor`，`_tgt_il_my.txt`）另路报送。**属于本方案最大不确定点。**
2. **`result` 语义是反的，别写错**：`ret==true → result=0`（成功），`ret==false → result=1`（PROVEN：`IL_002F ldarg.1 / brtrue.s 3 → IL_0035 ldc.i4.0；IL_0032 ldc.i4.1`）。而 `OnGetADInfoRsp` 侧 `result != 0` 才是"该跳过"。
3. **服务端可能校验 start→finish 的时间间隔**（0 秒完成）。
4. **奖励不一定由客户端发**：`DispatchResult` 只发事件 `Event_WatchADResult`；而 `finish_watch_ad_rsp` 的字段只有 `ad_id/uuid/result`（`Proto_SCFinishWatchAdRsp`：0x04011F90/93/96），**不含任何物品字段** ⇒ 奖励不是这个包下发的；具体发放者（本地配置 `CFG_AdvertisingRewards` vs 另一个通用奖励包）**未验证**。
   → 若实测拿不到物品：回退方案 A = 改 hook `DS_Advertising::DispatchResult` 让 `arg.2` 恒 true（"失败也发奖"）；方案 B = 直接 hook 具体奖励发放入口。

**同类其它入口（同功能，供交叉验证，未逐一读 IL）**
`AdMascotManager::OnClickWatchAd()` 0x06004383 / `CanClaimReward()` 0x0600436A / `GetAdRewardInfo(ref int,ref int,ref bool)` 0x06004382（悬浮广告）；
`MiaoYueSDKGameObject::OnADVideoResult(string)` 0x0600364B、`OnWindMillAd(string)` 0x06003648；
`BaseSDKAdapter::PlayADVideo(int,string)` **0x060035FF 是空桩（body len=1，仅 `ret`）**，实际实现只在 `MiaoYueSDKProxy` —— 所以**必须 hook 子类**，hook 基类拦不到虚派发。

## 5. 免广告：最优 hook 点 + 调用顺序 + 风险

见 §2.4（含完整时序图与伪代码）。要点复述：

* **最优单点 = `MiaoYueSDKProxy::PlayADVideo(int, string)` argc=2 / token 0x0600368D**（无命名空间）。
  hook 内**不调 orig**，改为 `DS_Advertising::OnADVideoResult(true, adid, uuid)`（argc=3 / token 0x06001255），
  uuid 用 `strtoull(arg2, 10)` 从字符串还原 → 客户端照常发 `finish_watch_ad_req{ad_id, uuid, result=0}` → 服务端走正常奖励流程。
* **必须成对**：服务端侧是 `start_watch_ad_req` → `start_watch_ad_rsp{ad_id, uuid, result}` → `finish_watch_ad_req{ad_id, uuid, result, sign}` 三段。
  `finish` 必须带**服务端在 start_rsp 里下发的 uuid**，所以**不能跳过 `StartWatchAdReq`**（否则没有合法 uuid）。本方案保留了 start 包，只跳过"播放"这一段。
* **不要在 `WatchAdvertisements` 里完全不发包**（除非用本地发奖的备选方案）——那会拿不到 uuid。
* **`sign` 恒空**（客户端从不 set）是本方案最大不确定点。
* **`result` 语义反置**：success → 0。

## 7. 不确定项清单（必须装机 diag 实测才能定）

1. **BigInt 的 ABI 布局未验证**：`BigInt` 是 struct（值 = `double m_mantissa` + `int m_exponent`，共 12 B，实际栈/寄存器布局按 16 B 对齐的可能性大）。凡**按值传 BigInt 的 hook 参数**（如 `ProcDmgHit` 的 `arg.3`、`Character::Damage` 的 `arg.1`）都必须装机确认寄存器/栈位置；**`SetValue/GetValue` 访问器路径不受影响，优先用它。**
2. **`CharacterType` 各字面量的数值**未从 Constant 表逐条验证（仅 `PLAYER=0` 有旁证）。
3. **`DamageEnumerate.DamageType` 各字面量数值**：仅 `DAMAGE=1` 有 PROVEN 证据（`Character::Damage` 里 `arg.2==1` 走扣血），`HEAL/Font/NQ/Shield/SkillTip/EXP/MAX` 的数值未验证（枚举声明序 ≠ 数值，不可假设）。
4. **`CBattleActorUtil::Hurt` 的 hook 能否挂上解释器桩**：需装机验证 `GetMethod(CBattleActorUtil,"Hurt",5)` 返回的 `*mi` 非空且 DobbyHook 生效（该类是静态工具类，方法可能被内联到调用者 —— 若内联，需改挂 `ProcDmgHit` 或 `Character::Damage`）。
5. **`HurtHp` 与 `Character::Damage` 是否重复扣血**：`HurtHp`（AttrType 23 走 `CBuffTriggerManager::OnAttrChange`，且钳到 hp-1）与 `EffectToCast→Character::Damage`（真扣 `secondaryAttribute.healthPointNowBigInt`）两条路径都动 HP，**实际扣血账目需装机观测**（若 `Hurt` 放大后怪"秒死"但血条异常，说明两条都要改）。
6. **`m_llValue` 放大后是否会被服务端回包纠正**（AFK/远征等远端权威战斗）：`DS_AFKBattle::get_IsRemoteBattle()` / `get_IsEndlessBattle()` 会影响 `Character::Damage` 的扣血分支（`IL_001A-0024`），需实测各玩法模式。
7. **免广告奖励的发放者未确认**：`finish_watch_ad_rsp` 不含物品字段，奖励可能由 `Event_WatchADResult` 的本地监听者按 `CFG_AdvertisingRewards` 发放，也可能由另一个通用奖励包下发。**必须装机看拿到什么、日志里 `DS_Advertising OnADVideoResult, adid:{0}, uuid:{1}, result:{2}` 与 `DS_Advertising OnGetADInfoRsp, adid:{0}, adname:{1} result:{2}` 的输出**（这两条日志是现成的 diag 抓手）。
8. **服务端是否校验 `sign` 与 start→finish 间隔**：未知。失败时的回退 = hook `DS_Advertising::DispatchResult` 让 `arg.2` 恒 true。
9. **`AdMascotManager`（悬浮广告）链路未逐方法读 IL**：若目标包含悬浮广告领取，需补 `OnClickWatchAd` 0x06004383 / `CanClaimReward` 0x0600436A / `GetAdRewardInfo` 0x06004382 的 IL。
10. **`_tgt_q.py strrefs` 命令有 bug**（对已确认存在的 #US 字符串也返回 0 命中），枚举"某字符串的所有引用者"暂时不可靠；本次未依赖该命令下结论。（`Event_WatchADResult` 与 `已使用免广告特权跳过观看` 的 UTF-16 原文均已在 DLL 字节中确证存在。）

## 给主控的结论摘要

判决：Assembly-CSharp.dll 是真 IL 体（MethodDef=173184，RVA!=0 的 172085，99.365%），HybridCLR 解释执行；DobbyHook 解释器桩可行（斌哥壳已证）。
命名：Assembly-CSharp 是程序集名；ActionGameLibrary / ActionData / GameConfigData / proto_ff 是命名空间；DS_Advertising / DS_Privilege / MiaoYueSDKProxy / BaseSDKAdapter / BigInt / CharacterType 无命名空间。
反作弊：热更 DLL 内无完整性校验/反作弊/上报类；OnJudgeCheat 是空实现，Proto_CSCheatReportReq 无人发送 ⇒ 4 个 hook 不与客户端反作弊冲突。
关键结构：伤害值 = CtagHurtHPPara.m_llValue(BigInt) = double m_mantissa + int m_exponent（斌哥日志的 m/e）；HurtHp 把伤害钳到 hp-1 永不致死，真正打死靠 EffectToCast → Character::Damage(BigInt,1,true)。
推荐 4 个 hook 点（一行一个，类名+方法名+argc+token）：
1 秒杀小怪 → ActionGameLibrary.CBattleActorUtil::Hurt argc=5 token=0x0601E25A（para=*(CtagHurtHPPara**)arg0；目标非玩家则 SetValue(BigInt 极大)）
2 无敌 → ActionGameLibrary.StarsCollider::DoAttack argc=7 token=0x0601E8D9（arg2=IAccept 是玩家则置 null，原函数 IL_0044 自行返回）；必须加 ActionGameLibrary.Character::Damage argc=3 token=0x0601F132 兜底挡服务端同步伤害
3 全模式技能伤害增加 → ActionGameLibrary.CBattleActorUtil::Hurt argc=5 token=0x0601E25A（m_llValue 乘 N）；需全模式客户端权威时附挂 ActionGameLibrary.BattleElementCenter::get_localDamage argc=0 token=0x0601E7FB 恒 true
4 免广告 → MiaoYueSDKProxy::PlayADVideo argc=2 token=0x0600368D（无命名空间；不调 orig，改调 DS_Advertising::OnADVideoResult(true, adid, uuid) argc=3 token=0x06001255 发 finish 包）；纯本地发奖备选 = DS_Advertising::WatchAdvertisements argc=1 token=0x06001251 → DispatchResult(adid,true) 0x06001258
风险：广告 finish 包的 sign 字段客户端从不赋值、result 语义反置（成功=0）、服务端可能校验 start→finish 间隔；BigInt 按值传参的 ABI 布局与 CharacterType 数值未验证，须装机 diag。
