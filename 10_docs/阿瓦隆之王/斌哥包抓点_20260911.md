## 二、抓点方法（三态 memdiff）

- dump 工具：`04_scripts/_common/dump_binge_shell_mem.sh`（需 `-s` 指定 serial；MuMu 双端口同一台机根）
- 状态：off（全关）/ on_1kill（仅秒杀）/ on_2skill（仅无限技能）
- 产物：`06_dumped/阿瓦隆之王/memdiff/{off,on_1kill,on_2skill}/`

**关键差分结果**：
1. `libil2cpp.so` 运行时内存三态**完全一致**（rx_1..7 全部 SAME）→ hook 固化在磁盘 libSDKloading.so？
   否——真相是二元：il2cpp 磁盘文件与内存有 3 处差异（见下），但 off/on 不因开关变化（hook 常驻，功能靠 flag 门控）
2. 开关 flag：`libSDKloading.so` .data 段（sdk_rw.bin）内
   - `+0x9D0`：秒杀 flag（off=0 → kill=1）
   - `+0x9D1`：无限技能 flag（off=0 → skill=1）
3. 三处 memdiff patch（文件=原 getter 序言，内存=`adrp+add+br x17` 跳桩）：


## 三、Hook 点定位（script.json RVA → 方法名）

Il2CppDumper（net6.0）已跑：`06_dumped/阿瓦隆之王/dump_out/{dump.cs,script.json,il2cpp.h}`（240 万行级）

| hook | RVA | 方法（dump.cs 反查） | 功能 |

| 1 | `0x8045bd0` | `GW.Table.Tab_tower_defense_attack_calculate_Row$$get_DamageAttack` | **秒杀**（攻击伤害 getter） |
| 2 | `0x80927d8` | `GW.Table.Tab_tower_defense_skills_Row$$get_EnergyRecovery` | **无限技能**（技能能量恢复 getter） |

skyhook 是塔防系（Tower Defense）意义：阿瓦隆之王 = 王城防守/英雄塔防玩法，攻击伤害与技能能量恢复即核心 battle getter。

## 四、桩函数语义（libSDKloading.so 反汇编）

符号表直接暴露中文桩名，证实在 `lib/arm64-v8a/libSDKloading.so`：

- `_Z6伤害Pv` @ VA 0x64754：flag@`[.data:0x8d738]` 读 4 字节 → tbnz bit0；ON=返回 float `0x4b18967f`（≈1074 万）→ 秒杀
- `_Z7伤害2Pv` @ 0x647b0：ON=返回 64 位 `0x98967F`（≈千万级能量）
- `_Z7伤害3Pv` @ 0x6480c：同 flag 组，返回同上 → 技能无限
- OFF 分支全部 `lib/data 指针 → blr x8` 调原 getter 原样放行

其余桩（`伤害4-15` / `能量` / `加密值`）存在但**未接线**到 il2cpp（斌哥预留或废弃）。

**樽式 = flag 门控 getter 返回替换：无状态改写、无副作用 —— 对复刻最友好。**

## 五、复刻方案（星空包）

- **目标**：官方 24.7.21 原版 + 星光菜单，2 功能 = 秒杀 + 无限技能
- **hook 点**：RVA `0x8045bd0`（DamageAttack）、`0x80927d8` + `0x8fea408`（EnergyRecovery×2）
- **方法**：Dobby hook getter 入口，ON 时 `return [巨大值]`，OFF `return orig(...)`（getter 无参/自持 this）
- **零重定位**：原版与斌哥包 il2cpp md5 一致，RVA 免重定位
- **返回值细节**：DamageAttack → 目标签名是什么？需读 dump.cs 确认返回类型（float/float32 或 int64）
- **风险点**：getter 可能被服务端校验数值（塔防数值 getter 一般纯读表，风险低）；禁止清数据只覆盖装
