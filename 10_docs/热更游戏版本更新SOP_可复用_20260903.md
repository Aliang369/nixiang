# 热更游戏（HybridCLR）版本更新 SOP —— 可复用方法论

> 来源：魂坠深境 1.0.5→1.1.0 对齐（2026-09-03，15h，含 10 版无效循环）。
> 适用：Unity IL2CPP + HybridCLR 热更的单机游戏。目标：下次同类更新 **≤2h**。

---

## 铁律（按此顺序，禁止跳步）

1. **第一步永远是抽热更 DLL 反编译**，不是 native 黑盒。黑盒观测（hook/探针追方法）对热更游戏结构性低效：虚调用/内部派发不走 methodPointer，内部互调不走签名桥——**追不到就是追不到，换路线**。
2. **直写模式优先，hook 模式例外**。能静态链直写的字段（血量/货币/CD/费用）绝不 hook 方法。
3. **实例驱动 > 名字驱动**。要改某个类，先找到活对象反查 klass，再迭代字段拿偏移。禁止 `FindClass`/`ClassFromName` 裸按名（通用名撞杂类 + 热更类 get_field_from_name 可能失效）。
4. **2 次验证不收敛 → 强制换路线**（不许修观测代码续命）。每次装机前写下「本轮验证什么假设」，结果否定假设就换。
5. 装机循环成本低（换 so 重签 ~5min），但每轮都要有明确的「预期日志」，没出现预期日志 = 假设被否定。

## 流程（六步）

### Step1 抽热更 DLL（30min，决定性）
- 设备：`files/Asset/hotfix`（UnityFS bundle）+ `manifest_hotfix.json`；部分游戏在 `files/il2cpp/Metadata/`
- `UnityPy` 解 bundle → TextAsset 中 `MZ` 头 bytes = DLL（42 个）
- `ilspycmd -p -o decompiled Assembly-CSharp.dll` → **直接读 C# 源码**
- 拿到：全部字段名/类型/字段序、方法真实调用链、判定逻辑（如 `IsCoolDowning => cooldown > 0`）、属性 vs 字段（属性不可直写，找 backing field 或替代字段）

### Step2 字段偏移解析（runtime，20min）
- `il2cpp_field_get_offset` 按名解析（照抄 HzsjMod `EnsureFields` 模式：FindClassExact → ResolveOff，失败有 fallback 兜底）
- **已知坑**：通用类名（Item/ItemContainer）会撞杂类 → 用「实例反查 + 字段存在性验证」；
  `get_field_from_name` 对部分热更类返回 0 → 用 `il2cpp_class_get_fields` 迭代按名匹配
- 解析失败时打「一次性字段迭代 dump」（全字段名@offset），人工核对 ilspy 源码

### Step3 直写实现（40min）
- 货币/数值：静态单例链每 tick 直写（参考 HzsjMod `ResolveLivePgsi` + `WriteProtectedInt` 12B 自洽）
- 敌我校验写前必做（isPlayer 判定，防链错写自己）
- List<T> 遍历：il2cpp 布局 `_items@0x10, _size@0x18, 元素@0x20+i*8`，count 上限防御

（接下段）

### Step4 语义确认（10min，问用户或读源码）
- 「秒杀」= 敌人血 0 还是 1？（0 会被 CheckDeath 事件连动「有动作就死」；1 = 一碰即死）
- 「无限卡牌」的约束是费用、CD 还是行动力？（分别对应 costCount/deltaCost、cooldown、WillPower 链）
- UI clamp、反作弊标记（ReportTamper）等已知边界提前告知用户

### Step5 构建+装机（15min）
- 换 so 重签：手机现装星光包 `adb pull` 当 base（**省 20min apktool 全流程**）→ `zip -u` 换 lib → uber-apk-signer
- 磁盘预检：base.apk 882MB × 操作份数，<3GB 先清理（本次两次中断教训）
- 日志口径：logcat `%lX` 是**大写**十六进制；多进程日志按 PID 分组

### Step6 验证+归档（10min）
- 四件套实测（战斗内出牌/挨打/看血条/商店）
- 成品归档 08_output（只留 final）、日志归档 09_test、文档更新

## 效率对比表

| 旧做法（1.1.0 实际） | 新 SOP | 节省 |
|---|---|---|
| native 黑盒追方法 ~4h | Step1 反编译 0.5h | 3.5h |
| hook 改参数 10 版循环 ~3h | Step3 直写一次成 | 2.5h+ |
| FindClass 按名连环坑 ~1.5h | 实例反查自学习 0.2h | 1.3h |
| 语义人肉循环 ~1h | Step4 提前确认 | 0.8h |
| **合计 ~15h** | **~2.5h** | **~12h** |

## 何时才用 hook / 探针

- hook：仅当「必须改方法行为/返回值」且**方法本体确认可拦**（先证明它在某入口出现）
- 探针（STARRY_HZSJ_PROBE 模式）：确认字段偏移、观察运行时值、枚举类与方法表——**不用于追调用链**
- 两者都是诊断工具，不是功能实现工具
