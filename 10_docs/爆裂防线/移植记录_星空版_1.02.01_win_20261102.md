## 1. 本轮做了什么

用户要求：把游戏更新/替换成星空版，按已有分析文档复刻三条功能（免广告历史上判定不可达，不做）。

处理原则：**不改原 mac 脚本**（留作口径对照），另起 `*_win.sh` 后端，公共层落在

## 5. 签名轨（双轨制 B）：签名杀手 dex

**为什么必须有**：本作「包名、签名错误」判定在 **TapSDK native 层**（`libtapsdkcore.so`，
日志 TAG `TapInitializer`），dex 补丁拦不住。只做 ①–④ 时实测仍反复弹：

```
E TapInitializer: ┃   TapSDK: 包名、签名错误。详见 ErrLog   ┃
```

而框架侧当时只有 `I StarryAppFactory: SignatureKiller absent, skip: ClassNotFoundException`。

`StarryAppComponentFactory.mountSignatureKiller()` 在 `instantiateApplication` 阶段
`Class.forName("bin.mt.signature.KillerApplication193", true, cl)`，killer 的 `<clinit>`：
`killPM(包名, 官方证书Base64)` → 替换 `PackageInfo.CREATOR` + 清 `Parcel.mCreators` /
`sPairedCreators` / `PackageManager.sPackageInfoCache`；`killOpen(...)` 保留空参（不启用 APK 读取重定向）。

补上后的日志（pid 4583，2026-11-02 21:14）：

```
I StarryAppFactory: SignatureKiller mounted: PackageInfo.CREATOR replaced, PM/Parcel caches cleared
I StarrySigKiller: signature killer installed (bin.mt.signature.KillerApplication193)
```

此后 `TapInitializer` 不再出现签名错误，用户实测 **TapTap 登录成功**。

## 7. 坑（按踩坑顺序）

1. **killer 模板父类绑定原包**：模板 `KillerApplication193.super = Lcom/mxyzt/gzmy/wuJvNQvtpQZhnd;`（冒险与征途包内桥接类）。直接复用 ⇒ 本包无该类 ⇒ `ClassNotFoundException` ⇒ killer 静默跳过。必须把 `.super` 与 `<init>` 调用一并改成 `Landroid/app/Application;`（脚本已断言产物无 `mxyzt` 残留）。
2. **`pm install <file>` 在本机失败**：`INSTALL_FAILED_MEDIA_UNAVAILABLE: Failed to restorecon`（`/data/local/tmp` 文件上下文问题，`restorecon` 也修不好）。改走 `adb install -r`（流式）后正常。
3. **Git Bash 路径自动转换**：`adb push … /data/local/tmp/x.apk` 会被 MSYS 改写成 `C:/Program Files/Git/data/local/tmp/x.apk`。所有 adb 远端路径要 `MSYS_NO_PATHCONV=1`（安装脚本已封 `adbx()`）。
4. **中文路径传给原生 exe**：`adb push` 源路径含「爆裂防线」时静默失败；安装脚本先把 APK 复制到 `.workbuddy/scratch/blfx_install.apk`（ASCII）再推。
5. **dex 选择不能取最大下标**：注入 killer 后 `classes4.dex` 不是星光 dex；签名脚本改为「找出含 `StarryInitProvider` 的那个 dex」。
6. **smali 往返 dex 变大 42%**（9.4 MB → 13.4 MB）：baksmali 保留 `.line`/`.local` 调试信息。功能无影响，APK 压缩后仅增约 0.5 MB。
7. **雷电 ABI**：设备 `primaryCpuAbi=arm64-v8a` + `libhoudini.so` 转译，官方包本身只有 `arm64-v8a` 库；我方菜单 so 同为 arm64 可直接加载（实测 so md5 校验通过）。
