## 3. 反检测修复（用户要求：不只去弹窗，要提高防封）

**触发项**：`zbCombatHandler.IsZuobi()` 的「时间加速」检查（`zbCombatHandler.cs:613`）：

```csharp
if (serverElapsed < accumTime / zbCombatSpeed.speed3 - 10f) → 命中
```

**根因**：旧实现关闭加速时把 `speed1/2/3` **全部写成 1.0**，而游戏默认 `speed1=1 / speed2=1.5 / speed3=2.5`。上一段高倍速累积出的 `accumTime` 除以被改成 1.0 的 `speed3` 后远超真实耗时 ⇒ 结算命中「时间加速」并调用 `Abnormal_ClientReportOnce` 上报服务端（弹窗 `lang.10668+"_4"`）。

**修复（BlfxMod.cpp）**：
1. 关闭加速时恢复游戏默认 `speed1=1 / speed2=1.5 / speed3=2.5`（不再全写 1.0）。
2. 新增 `ServerElapsedMs()` 持续跟踪战斗开始（`startServerTime` 变化即新战斗，用本机单调时钟换算真实耗时）。
3. 新增 `CorrectAccumTime()`：speed 开关切换时把 `zbCombatSystem.accumTime` 校正为 `真实耗时 × 目标 speed3`，使 `accumTime/speed3 ≡ 真实耗时`，检查恒不成立，同时阻断对应上报通道。
4. 新增 `SlfWrite()` 按 zbSafeFloat 双影子协议（`_obfValue@0/_key@4/_shadowObf@8/_shadowKey@12`）写入，避免触发 zbSafeFloat 自身 ReportCheat。

**实证**：`blfx_probe.txt` 中 `SET speed=1 → SPEEDREAD f1=1.000 f2=1.500 f3=2.500`、`ACCUMFIX ms=… speed3=… target=…`，两局结算 `AC out="UUID:…battleFuncType=MainQuest"` **均无任何检查项后缀**（无「时间加速」）。
