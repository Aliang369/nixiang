## 3. 为什么不能用 Dobby（本作与圣翼传说的本质差异）

- 圣翼传说（同作者、同瘦壳）：热更前 il2cpp 代码段有 **15 处 `ADRP X17/ADD X17/BR X17` 跳桩**，hook 可用。
- 爆裂防线：il2cpp 代码段 memdiff **跳桩 0 处**，只有 1 处无关 4 字节杂音；斌哥的壳走 **`il2cpp_class_get_field_from_name` / `il2cpp_field_static_get_value|set_value` 反射按名读写**（壳内 BSS 配置表实测含 `zbMonster`/`ChangeHp`/`zbCombatSpeed`/`SetSpeed`/`speed1..3`）。
- 实测验证：对 `zbMonster.ChangeHp` 与 `zbCombatDefense.ChangeHp` 各装一次 Dobby hook，返回 `rc=0`，指针 60s 稳定不变（`PTRMON mon==def==hookedMon==hookedDef`），但 **`hits` 恒为 0** —— HybridCLR 解释器内部分发不经过 `methodPointer`。
- ⇒ 结论：**hook 路线在本作永久无效**，改用「在游戏线程之外周期读写游戏字段」的字段路线（tick 200ms + `SafeProbe` 包裹防崩）。

## 4. 实现要点

源码：`mod菜单/starry-mod-menu/app/src/main/jni/Games/{BlfxEntry.cpp,BlfxMod.cpp}`

### 4.1 类/字段解析（L1 优先，无内存扫描）
`ResolveClass(name, memberName, argc)`：先 L1 遍历全部已加载 image（实战 `images=73`，`hotfix loaded=1` 时命中率 100%），再 L2 按程序集名 open。命中记录：

| 类 | klass |
|---|---|
| `zbMonster` | 经 image[72] 命中 |
| `zbCombatDefense` | 命中 |
| `zbCombatSpeed` | 命中 |

字段偏移：`zbMonster.curHp=1048` / `maxHp=1088`；`zbCombatDefense.curHp=280` / `maxHp=320`。
> ⚠️ v1 曾用「L3 全内存按类名扫描」，在游戏线程上以 1545 MB/s 扫 4 秒 ⇒ **启动闪退**。该路径已**整体删除**。

### 4.2 zbSafeLong 双副本写入协议（反作弊关键）
`zbSafeLong` 布局：`_obfValue@0`、`_key@8`、`_shadowObf@16`、`_shadowKey@24`、`_fieldName@32`（40 B）。
`Value` getter 会同时校验两份；不一致即调 `zbCheatContext.ReportCheat(...)` **主动上报服务器**。
⇒ 写入必须两份同改：

```cpp
static int64_t SlRead(const void* p) { return RdI64(p,0) ^ RdI64(p,8); }
static void    SlWrite(void* p, int64_t v) {
    int64_t k  = RdI64(p,8),  sk = RdI64(p,24);
    WrI64(p,0, v ^ k);  WrI64(p,16, v ^ sk);
}
```

### 4.3 伤害倍率 = 有效血量钳位（不是改伤害数值）
`capHp = maxHp / mul`，每 200ms 把 `curHp > capHp` 的怪压回 `capHp`。
实测证据（探针 `FAPPLY` 行）：`m0c=38 m0m=503`，mul=13 ⇒ `503/13=38` 精确成立。

> **为什么用户观感是「秒杀」而不是「翻 13 倍」**：怪 `maxHp≈503`、玩家单击伤害 ~50 ⇒ mul≥10 后一次攻击就打掉等于满血的血量，必然是「一击秒杀」。**这是设计必然，不是 bug**。上限 100 由用户指定；若要「看得见倍率差异」，建议上限收到 10（未决议）。

### 4.4 无敌 = 防线血量钉扎
每 200ms：`if (dcur < dmax) SlWrite(defense.curHp, dmax)`。探针 `FAPPLY inv=1 dcur=3100 dmax=3100`。

### 4.5 战斗加速 = 静态字段 + timeScale
`zbCombatSpeed.speed1/2/3` 是 `private/public static readonly float`（1f / 1.5f / 2.5f），游戏自身**只在静态构造里赋值、永不改写**，所以运行时用 `field_static_set_value` 写一次即长期生效。
- 取 API：`field_static_set_value` 的 dynsym 地址与 `field_static_get_value` 相邻 4 字节（`0x2120f6c` / `0x2120f68`）⇒ `set = (field_static_set_value_t)((uintptr_t)api.field_static_get + 4)`；`dlsym(RTLD_DEFAULT,…)` 返回 0（GNU hash 未重建）。
- 每秒维持重写（`sp>1` 时），并一次性把 `Time.timeScale` 设为同一值。
- 回读校验：探针 `SPEEDREAD after-write f1=N.000 f2=N.000 f3=N.000` 全部成立。

**装机铁律**：pipeline 阶段必须按序；单独 `reset surgical` 会报「上游链路已过期」，必须整链跑：

```bash
export BLFX_ALLOW_UNINSTALL=1
for st in build_so surgical sign install; do
  bash 04_scripts/pipeline.sh 爆裂防线 reset $st
  bash 04_scripts/pipeline.sh 爆裂防线 run   $st
done
```

**探针读取铁律**：`adb -s f9a116a2 shell "su -c 'cat /data/data/com.muyegame.blfx/files/blfx_probe.txt'"` —— `su -c` 里**不要加双引号**（adb shell 会吃掉，报 `L2: inaccessible or not found`；外层用双引号包住整条 `su -c '…'` 才安全）。

**诊断开关（正式包默认零写盘）**：`PD()` 首行是 `if (!DiagOn()) return;`，而 `DiagOn()` 只在 `<游戏私有目录>/blfx_diag` 存在时返回 true（5 秒缓存一次 `access()`）。要复现取证时先开开关再启动：

```bash
adb -s f9a116a2 shell "su -c 'touch /data/data/com.muyegame.blfx/files/blfx_diag'"
```
