## 1. 结论摘要

- 本次四项功能均在客户端执行；PVE 可见，PvP 与真实 replay 路径已在 JS 包装层短路。
- 旧版把 PVE Boss 的正常 `Args.seed` 误当 replay，导致 Boss 攻击倍率失效；现改为 `delegate.isReplay()` 判定，修复版已装机。
- Boss 战后无奖励、`LvNum` 不前进时，客户端会按同一关再次重开；现已记录 `LvNum/Rewards/KillNum`，同关连续两次返回即进入 5 分钟保护。
- 为避免 Boss 在服务端 `GS_WLevelStartFight_R` 确认前被 10x 速度/倍率提前打死，挂机 Boss 速度封顶原生 2x，伤害倍率等待开战确认后才启用。
- 未发现 `addCheat`、`onStageCheat`、`BuildPassCheckInfo` 这类与战斗作弊直接绑定的上报入口。
- 游戏存在 Bugly 异常日志、TapTap/Themis 组件和 JS 日志上报，但未发现需要为本次战斗补丁全局屏蔽的专用作弊上报链。
- 云存档 `C_CloudGet/C_CloudSet` 当前主要承载聊天已读、引导状态、挂机设置等键值；本次补丁没有修改云存档、货币、背包或结算奖励。
- 客户端存在 `9000004: 账号存在异常行为，请联系客服` 错误码，说明服务端具备账号异常处置面；“客户端未触发”不能证明“服务端不会判定”。
- 不建议无依据全局屏蔽 Bugly、TapTap 或 Themis：这些组件同时参与崩溃归因、登录、签名或完整性链路，误杀会先破坏登录/运行稳定性，且不能消除服务端重放与统计风控。

### 2.3 风险评估

| 场景 | 风险 | 当前保护 |
|---|---|---|
| 普通 PVE | 中 | 攻击倍率仅改最终受伤 `delta`；数值可控 |
| PvP / 竞技场 | 高 | `handler.isPvp()` 已短路，不修改 |
| 真实回放观看 | 高 | `delegate.isReplay()` 判定已短路 |
| PVE Boss 的正常 seed | 中 | 不再因 seed 误拦，只在 PvP 或真实 replay 跳过 |
| 排行榜/公会/组队结算 | 高 | 客户端不改结算字段，但服务端统计仍可能识别异常 |
| 云存档 | 低 | 本次未触碰 |
| 登录/渠道请求 | 中 | 官方签名回灌 + TapTap 内嵌网页路径 |

建议使用线：

- 攻击倍率先用 `5-20`，不建议长期 `100`。
- 战斗速度先用 `2-5`，高倍速会增加时间统计与动画/伤害同步偏差。
- PvP、排行榜、公会战、组队结算、回放场景不要开启。
- 先关功能再结算需要服务端发奖的玩法，不把“客户端成功”当成“服务端接受”。

## 3. 战斗代码异常兜底

### 3.1 native 侧

`Games/RsjyMod.cpp`：

- `g_origSeEval` 为空时直接返回失败，不调用空指针。
- `thread_local t_inSplice` 阻止同线程重入。
- 只处理 512 KB–64 MB 且包含 `window.__require`、`changeHp`、`getBattleSpeed` 的主 bundle。
- 已注入标记 `starry_rsjy_v1` 时不重复注入。
- 包装异常时回退原脚本；补丁 tick 在热更脚本再次执行时会重新调用。

### 3.2 JS 侧

`04_scripts/燃烧纪元/patch_rsjy.js`：

- 状态读取 `ret/val/require` 均包 `try/catch`。
- `changeHp` 修改段包 `try/catch`，异常后仍调用 `orig.apply`。
- `isPvp()` 与 `delegate.isReplay()` 调用都纳入保护；PVE Boss 的正常种子不再被当作 replay。
- 攻击倍率 >1 时最多输出 20 条 `[rsjy] dmg` 诊断行，记录 module/PvP/replay/group/伤害变化，避免日志刷屏。
- 五个 `getBattleSpeed` 包装失败时回退 `orig.apply`。
- 免广告的直接回调使用 `setTimeout`，失败再同步调用；关闭时保留原广告路径。
- 错误日志最多记录 3 条，避免热路径日志刷屏。
- Cocos scheduler 调度失败时回退 `setInterval`。

### 3.3 Java/菜单侧

`RsjyHooks.java`：

- `setRet/getRet/setVal/getVal` 全部做数组边界检查。
- 未使用反射调用，菜单状态桥不会因缺失业务类抛异常。
- native 侧调用前缓存类和方法，并清理 JNI 异常。

### 3.4 残余风险

- 长时间挂机、连续结算、广告奖励服务端校验仍标 `NOT PROVEN`。
- 如果游戏后续热更改变 `changeHp` / `getBattleSpeed` 调用约定，补丁应保持“异常即回退原逻辑”。
- 当前静态兜底不能证明服务端一定接受修改后的战斗结果。
