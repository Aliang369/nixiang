## 1. 结论先行

1. **引擎是 Cocos Creator 3.x（JSB），不是 Unity/IL2CPP** ⇒ 斌哥走的是 re-extract skill 里的**路径 A：运行时注入 JS**，与先例「爆裂防线」（Unity HybridCLR）机制完全不同。
2. **斌哥壳对磁盘零改动**。设备 `files/remotePath/*` 与官方 CDN `hot_res` 逐 md5/size 一致（已实测证伪「壳改盘」）；热更版本设备已是 `0.0.0.23`，APK 内 manifest 仅 `0.0.0.18`。三个功能**全部**由运行时 `se::ScriptEngine::evalString` inline hook 改写 boot JS 实现。
3. **斌哥对外只有 3 个功能**：`百倍伤害` / `超级无敌` / `战斗加速`。已用两条独立证据链交叉确认（① boot JS 里只有 4 处 replace 锚点 + feature1..3 开关；② 解开菜单页 `exp` 得到的功能列表只有 idx 0/1/2 三个 btn）。
4. **本游戏确实有「看广告换奖励」**（TapAD 激励视频模块 + SpaceID/media 齐备 + `classes3.dex` 里 `TapAdRewardManager`/`TapAdRewardVideo`）⇒ **按用户规则「有则新增」，星空版必须补免广告（第 4 个功能）**；斌哥本包**没有**实现它。
5. 移植面很干净：boot JS 是**纯文本 JS**（注入内存后用 python 按 UTF-8 切即可得全文），幂等闸门、自愈安装器、绑定字母捕获都齐全，可直接作为星空版第 4 功能挂载点的宿主。

## 3. 注入机制：`se::ScriptEngine::evalString` inline hook

### 3.1 hook 目标（来自壳自身 C++ 字符串池）
`06_dumped/光阴之外/binge_mem_20260926/shell_rx_bss_7820623000_7820720000.bin` 内的 mangled 符号：

```
_ZN2se12ScriptEngine10evalStringEPKclPNS_5ValueES2_
```

即 `se::ScriptEngine::evalString(char const*, long, se::Value*, se::Value*)`（Cocos Creator 3 的 `se` 命名空间）。

同段内的运行期错误串证明它是**双路定位 + 序言校验**：

```
evalString 定位失败（dlsym 与特征扫描都没命中）：
定位到的首指令不是序言，放弃 Hook：
HOOK失败
内存分配失败
ScriptEngine::evalString script
ScriptEngine::evalString catch exception:
```

## 4. 三个功能的完整抓点（4 处补丁）

补丁全部在注入 JS 里，用 **锚点字符串 + 模块表改写**（`MOD_rebuild` 重编译工厂函数）实现；**不改磁盘、不写 dex、不碰 so**。

### 4.0 安装器骨架

| 组件 | 作用 |
|---|---|
| `MOD_patchSource(src, log)` | 开头幂等闸门 `if (/\b_mOn[1-3]\b/.test(src)) return null;`，然后依次 4 处 replace，返回 `{src, hit}` |
| `MOD_rebuild(src)` | `/^function\s*[\w$]*\s*\(([^)]*)\)\s*\{/` 取形参 → `body = src.slice(m[0].length, src.lastIndexOf("}"))` → `Function.apply(null, args.concat([body]))` |
| `MOD_wrap(fn)` | `return function(){ try{ MOD_boot(arguments[0]) }catch(x){ MOD_log("hook 异常 "+x) } return fn.apply(this, arguments) }` |
| `MOD_SCREEN` | 便宜预筛数组：4 条锚点串，模块 toString 不含则跳过 |
| `MOD_boot(reg)` | 遍历模块表 → toString 预筛 → 补丁 → 重编译 → `ent[0] = nf`；`toString` 返回 `[native code]` 则整套失效并打 `☠☠☠` |

### 4.1 功能1 · 百倍伤害 —— `BtDmgMgr.updateTargetHp`

- 锚点：`var u = t.isDie();`
- 绑定捕获：`var mR = /(\w+)\.BtConst\.EUnitType\./.exec(out); var RV = mR[1];`（捕不到就放弃安装）
- 注入（RV 为运行时捕获的绑定字母）：

```js
var _mOn1 = "undefined" != typeof MOD && MOD.feature1, _mE0 = e;
if (_mOn1 && e < 0
    && o && (o.type === RV.BtConst.EUnitType.Hero || o.type === RV.BtConst.EUnitType.Lord)
    && t.type === RV.BtConst.EUnitType.Monster)
  e = Math.floor(100 * e);
e < 0 && o && t.type === RV.BtConst.EUnitType.Monster && window.MOD_q("伤害", _mOn1) && window.MOD_log(...);
var u = t.isDie();
```

- 语义：**只对「英雄/领主 → 怪物」的负伤害 ×100**；MONSTER→英雄不放大（避免 PVP 双向被对账）。`MUL=100`。
- 幂等：注入码自带 `_mOn1`，二次调用会被闸门拦下（注释明确说「不挡的话二次调用会叠加放大」）。

### 4.2 功能2 · 超级无敌 —— `BtRoleData.updateHp`

- 锚点：`this.setCurHp(this.curHp + e, t);`

- 语义：**不是硬无敌（不写 0）**，而是每只英雄首次随机取一个血量地板 `0.91 ~ 0.95 × maxHp`，扣血被夹到「不低于地板」。`FLOOR=0.91`、`FLOOR_SPAN=0.04`。
- 设计意图（从代码注释与实现可读）：留 5~9% 血量为「看起来在掉血」，降低被服务端属性对账判作弊的概率。

## 6. 反检测 / 风险提示（从斌哥自己的注释与代码读出）

- boot JS 头部作者亲笔警告：**竞技场有 replay 战报上报、战斗种子确定性 ⇒ PVP 大概率服务器可对账**；建议三功能只在 PVE 主线/推图测，「PVP 别开尤其无敌（双方都 Hero 互相无敌卡死）」。
- 无敌刻意不写 0 而留 91~95% 地板，是作者主动做的「降可疑度」设计 ⇒ 说明本作服务端有血量/属性侧校验的**可能性**，星空版应保持同样保守策略。
- 反调试：壳内有一段 HTML 实体编码的骂人彩蛋串（解码为「操你妈！调试你爹的程序呢？…」），属作者风格，无技术作用。
- `libtoolChecker.so`（5,512 B，RootBeer）是斌哥壳独有的**反 root/反调试**组件 —— 星空版**不要**移植它。
- 斌哥菜单页自身有 `.ad_box` + `#dtime` 30 秒倒计时 + `closeAD()`（是「斌哥游戏宝盒」APP 自己的广告位），**与游戏内广告无关**，移植时不要混淆。
