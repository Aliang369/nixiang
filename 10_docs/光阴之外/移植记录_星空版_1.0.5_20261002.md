## 3. 为什么仍然走 evalString splice

与 1.0.3 §3 同因，无变化：

- 引擎是 **Cocos Creator 3.x（JSB）**，无 il2cpp / 无 `global-metadata.dat` / 无 HybridCLR ⇒ 先例里的「字段路线」不适用。
- 游戏逻辑全在 `assets/script/index.jsc`（加密，头 16 B `0a4fad78 2da5de50 cb565382 8b03d444`），由 `libcocos2djs.so` 在运行时解密后交给 `se::ScriptEngine::evalString`。
- 该符号在 1.0.5 里**仍在 dynsym 导出表**且偏移未变（0x453da0）⇒ 1.0.3 的 hook 代码与偏移策略可原样复用（仍是 `HookByName` 式按符号名定位，不硬编码 RVA）。

### 4.6 ★修了一个真 bug：`gyzw_build_so.sh` 归属防呆恒真误报

- 修法：改为 `"\[Ysxz\]" "\[Dwct\]" "\[Tlgd\]" "\[Blfx\]"` 并加注释。
- 重跑成功：`[build_so] done → libs_gyzw/arm64-v8a/libstarry_magic.so (5937f56b538f1c10f66f5ca71757c52f, 2159720 B)`，so 内标签全部为 `[Gyzw]`。

## 7. 遗留项

1. ~~用户实机确认未闭环~~ → **已闭环（2026-10-02）**：用户在设备上验收六项菜单、战斗三项功能、免广告「看视频领奖」，反馈「**功能都没问题**」（本项目禁截图/禁 `input tap`，界面操作由用户完成）。
2. **`GyzwMod.cpp:199 SyncJsState()` 索引不一致（沿用未修）**：把 `g_noAd` 写进 `ret[4]`，而 `GYZW_FEAT_NOAD = 5`（`[4]` 是 `Category_广告` 占位）。当前免广告只走 Java `GyzwHooks.shouldSkipAd()`（smali 门控），JS 侧 `__starryGyzwOn(4)` 从未被读 ⇒ **无功能影响**。
3. **PVP 可对账风险未处理**：见 §5。
4. **免广告未做服务端校验规避**：客户端伪造回调，若服务端校验激励视频发放，理论上可对账。
5. **热更兼容性**：锚点是 boot JS 源码串，游戏一旦热更改这几行，对应功能会静默失效（`try/catch` 兜住，不会崩）。届时重跑 dump 阶段取新的 `gyzw_boot.js` 重新核对锚点；`classes3/4.dex` 广告门控同理，需重跑 surgical。
