## 1. 一句话结论

这包 = **商业壳（远程菜单 + ByteHook）** + **双重签名伪装** + `binge2` 重签。

你看到的菜单「无敌 / 秒杀 / 瞬间结束战斗」：
- **不在 APK 静态资源里**（搜不到中文文案）

- 功能生效靠 `account/pro/ByteHook.init`（native，落在加壳的 `libSDKloading.so`，几乎无符号）+ 可能 WebSocket 指令

因此：
- **想直接用他的菜单** → 继续用这份改包 + 对方卡密即可（菜单是壳的一部分）
- **想干净复刻进原版 / 星光** → **不能整菜单拷走**；要动态抓三次开关对应的 Hook 点再自写（工作量≈新做一款游戏的战斗外挂）

## 4. 「过检测」怎么做的（可借鉴点）

### 4.1 MT 签名杀手（主路径）

文件：`smali_classes4/bin/mt/signature/KillerApplication193*.smali`

启动时：

```text
killPM("com.blina.match2.tt", <原厂证书 Base64 DER>)
```

效果：Hook `PackageManager` / `PackageInfo` 创建路径，对本包包名查询签名时**塞回 Ranhao Kang 原证书**。  
因此 `TapSignKit.getSign()` 仍走 `getPackageInfo(..., GET_SIGNATURES)` + MD5，读到的是**原厂 MD5**，不是 `binge2`。

`TapSignKit.getSign` **本身未被改成写死字符串**（仍是正常读签名）；靠杀手在 PM 层撒谎。

### 4.2 壳自带 SignatureSpoof（第二层）

`smali_classes5/account/pro/SignatureSpoof*.smali` — 同类 PM 签名替换。  
`natives/cn/shell/killPath` → native `hookApkPath`（伪装 APK 路径，防部分「读自己 base.apk 校验」）。

### 4.3 和堡垒之战那套的对比

| 手段 | 堡垒之战星光 | 本改包 |
|------|-------------|--------|
| 写死 `TapSignKit.getSign` 返回值 | ✅ 用过 | ❌ 未改 smali |
| Hook PM 返回原证书 | — | ✅ MT Killer + SignatureSpoof |
| 改包名 | 否 | 疑似加 `.tt` |
| 商业账号壳 / 共享号 | 否 | ✅ |

**可复刻到原版时优先学：签名伪装（MT Killer 或自写 PM Hook），而不是抄整套账号壳。**

## 8. 拿到原版后建议怎么复刻（学习路径）

1. **确认原包包名**是否为 `com.blina.match2`（无 `.tt`），版本是否同为 `1.2.26`。  
2. **二进制 diff**：`libil2cpp.so`、`libxlua.so`、`assets/a/*`、`classes*.dex` 体积/哈希。  
   - 若 so/bundle 一致 → 功能几乎全在 Java 壳，按第 4 节做签名伪装即可支撑自签安装。  
   - 若 so/bundle 有 diff → 再针对 diff 做 IDA/Il2Cpp 对比。  
3. **签名过检（可自用）**：对原版注入 MT Killer / 自写 PM Hook，嵌入原厂证书（从本改包已提取），再用自己的 keystore 签。  
4. **不要整包抄账号壳**：依赖 `APP_ID=44643` 对方服；法律与稳定性都差。  
5. **真·玩法外挂**：等原版确认后，再从 xLua 加载点 / 支付回调 / 本地货币字段入手（本包尚未证实有这些补丁）。
