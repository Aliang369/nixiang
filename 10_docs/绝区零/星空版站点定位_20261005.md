## 1. 本轮新增关键技术事实（复用入口）

1. **地址空间换算（重要，已踩坑）**：
   - `disasm_so.py` 以**文件偏移**为反汇编基准，它打印的 `bl #0x…`、`adrp …#0x…`、`b #0x…`
     目标全部是**文件偏移空间**；`RVA = 文件偏移 + 0x4000`；运行时 `VA = libil2cpp 基址 + RVA`
     （MuMu 本次基址 `0x400023000000`）。
   - `xref_bl.py` 的 target 参数用 **RVA**（ELF vaddr 空间）。
   - 判断某 file 偏移是否在文件外：so 大小 489,604,968 B（≈0x1d2d…）；`0x1d5af3d0` 等
     已属 **BSS**（运行时读取，初始为 0）。
2. **MethodInfo 记录布局**（步长 0x40，运行期实测）：
   `+0x00`（多数为 0；部分=klass/名称结构指针）、`+0x08`=methodPointer(`0x4000…`)、`+0x10`=klass、
   `+0x18`=nameIndex/常量、`+0x20`=`0xffffffff,0`、`+0x28`=invoker(`0x4000276d1b80` 等)、
   `+0x30`=token（`0x06xxxxxx` 低 32 位 + 高 32 位常量）、`+0x38`=attributes/参数计数。
   校验样例：Object.Equals M=`0x5f814d2d10` → code `0x40003c3ee86c`(RVA 0x193ee86c)、klass `0x5f814d2b60`。
3. **类名全量枚举**：`04_scripts/绝区零/enum_classes.py`（klass+0x20→类名串、+0x40→0x7f38 区校验）
   产出 **207,074 条**（含噪声）→ `%TEMP%\nx_zzz_a_20261005\classes_all.txt`。
   其中与移动/速度相关的重要类：
   `SpeedCalculator`、`ConfigSpeedLevel`、`ConfigSpeedModifier_Boost/MinMax/Switch/Slope/SlopeV2`、
   `SpeedClamp`、`SpeedMode_Tangent_FinalSpeed_Acceleration/Resistance`、`SpeedParam_Physics`、
   `NPCAbilityMovementStyleSpeedParameters`(及 `F…` 版)、`NPCApplyMovementProcessor`、
   `AnimatorZoneApplyMoveByJoystickNoSteer`(`0x16571aac`，实测仅置组件 `[+0x275]=1` 的开标志器)、
   `SetMoveSpeedRatio`(`0x5f884179b0`)、`MonitorMoveSpeed`(`0x5f8899b3d8`)。
4. **metadata 为 MHY 加密头**：APK 内 `global-metadata.dat` 头 4 字节 `MH Y\0`（magic `0x0059484D`），
   非标准 `0xFAB11BAF`；Il2CppDumper 直接不可用（`il2cpp_dump_429/` 为空）。
   方法名只能从运行期内存捞：`mem_read.py` 精确读 + `scan_names.py` 结构扫描（已有雏形，未完善）。
5. **方法名 entry 结构**（Object.Equals 实测）：entry=`0x5f814d2fd8`：
   `+0x00` 指针、`+0x08..0x1F` 24B hash、`+0x20` 名称 ASCIIZ（≤0x1f），步长 0x40；
   但存在多种变体（扫描 1476 条后名字多被截尾）⇒ **扫描器还需修**，暂不能替代人工反汇编。
6. **速度属性系统**：`MonitorMoveSpeed`(`0x147062ec`) 每帧从属性容器读两个 float
   （懒加载 getter `0x168af120` idx=`0x20`、`0x168ae7dc` idx=`0x22`），再经
   `Behavior.SetVariable`(`0x1a7e58c8`) 写入行为变量 ⇒ 游戏速度值走统一「属性系统」。
7. **frida 在 MuMu 的限制（结论性）**：MuMu 是 x86_64 + Houdini 转译 ARM64，frida-server 为 x86_64，
   `Interceptor.attach` 在 ARM64 guest 代码地址上不可用（写 x86 断点字节不会被执行路径命中）。
   运行期验证/测试只能靠「池鸳式运行时内存代码页改写（启动早期）」，只读采样用 `/proc/<pid>/mem`。
8. **SetMoveSpeedRatio 类实际 4 个方法**（此前只报 1 个）：方法表数组从 `0x5f88417c08` 起，
   每 0x40 一条，4 条记录 code RVA = `0xfb2af14 / 0xfb2ad74 / 0xfb2b0e4 / 0xfb2b20c`
   （nameIndex `0xba1b7..0xba1ba`，token `0x0605ebef..f2`）。
   - `0xfb2ad74`：把两个委托注册到某处理器（`0xa44f03c`，w3=2），像系统注册器；
   - `0xfb2af14`：从 `this+0x20` 的配置结构（24B：`+0x08` float、`+0x14` 状态字节，默认值在
     BSS `0x1d5b33d0`，运行时全 0）取比率；`state==3 && value>0` 时用该值，否则用 `this+0x64`；
     然后按 `this+0x60`(id) 查组件（`0x110a17f0`），把 float 写入目标组件 `[+0xf8]`、`[+0x100]`，
     并置 `[+0x104]=1`。

## 2. 无敌（✅ 站点与语义都已确认）

- 站点：RVA `0x11521138`，文件偏移 `0x1151d138`；
  16B 指纹 `fe57bea9 f44f01a9 880306d0 f503022a`（与池鸳闸门第 3 条一致）。
- 池鸳 handler `0x4e2c8`：`ldr x24,[原函数槽0x130f78]`；解析事件字段；`[event+0x16](u16)==0x85`（伤害事件）
  且 `[event+0x38](u32)==actorId` 时**不调原函数**（拦截），否则 `blr x24`。另有开关 `.bss[0x130f38]`。
- 星空版方案：同站点 12B 桩（`adrp/add/br`）+ 自有 handler；开关关闭时直接 `blr` 原函数；
  开启时按同样过滤条件跳过（或调原函数后丢弃效果）。

## 4. 无限技能（⚠️ 候选，未定稿）

已确认事实：

- SP setter（属性写入口）RVA `0x1391de04`（file `0x13919e04`）**只有 3 簇 9 个 BL 调用者**：
  `0x106e1504 / 0x106e15a4 / 0x106e16e0`、`0x10d27114 / 0x10d271b4 / 0x10d272ec`、
  `0x13d03fb4 / 0x13d04054 / 0x13d041a4`。
- 其中一簇所在函数入口 `0x13d03eec`（file `0x13cffeec`）是多参数函数：先取组件、调 SP setter
  （描述符 `[0x1d97be48]`），再按 `[x22+0x50]` 做条件调用（`0x10b9d990`），然后 getter `0x13923eb8`
  与 setter（描述符 `[0x1d97be48+8]`）成对、并用 `this+0x58` 在 0/1 间选择 float（fcsel s0, 0, 1）。
  暂判为「SP 消耗/写回链」之一，**未确认哪一个分支是技能扣费**。
- SP getter RVA `0x138fbc4c` 有 **117** 个 BL 调用者（含技能 UI `0x13749940` 等），不可全局 hook。
- 其他候选：`CommonSkill.EnableFinal / EnableByForceUnlock` 类方法 `0xc352b5c / 0xc352b64`（上轮定位）。

候选方案（三选一，出包前定一条）：

## 5. 移动速度（⚠️ 候选，方案已具体化）

主候选：`SetMoveSpeedRatio` 类的应用方法 `0xfb2af14`（写组件 `[+0xf8]/[+0x100]`，语义见 §1.8）。

**mid-function 写入点方案**（推荐，12B 桩正好覆盖 3 条指令）：

- 站点：file `0xfb2700c`（RVA `0xfb2b00c`）三条指令：
  ```
  str s8, [x0, #0xf8]
  str s8, [x0, #0x100]
  strb w8, [x0, #0x104]
  ```
- handler（开关开时）：
  1. `s8' = s8 × mult`（mult 来自菜单输入）；
  2. 写 `[x0+0xf8]=s8'`、`[x0+0x100]=s8'`、`[x0+0x104]=1`；
  3. 跳回 `0xfb27018`（原函数收尾）。
- 开关关时：直接执行原三条指令并跳回。
- **风险**：`[+0xf8]/[+0x100]` 是否就是角色移动速率的应用字段，尚未运行期验证；
  验证方法＝出包后先做 L2（MuMu）观察角色位移是否随倍率变化，不行则换 Plan B。

Plan B（备用）：属性系统——找到写 `MoveSpeed` 属性（idx 0x20/0x22 同一容器）的入口，
用「属性修正符」方式加乘区（`0x1ab5c980/0x1ab5c004` 家族是属性读写 helper）。

Plan C（备用）：`AnimatorZoneApplyMoveByJoystickNoSteer`(`0x16571aac`) 属于「按摇杆移动」状态开关，
不是速度计算点，**已排除**。

## 6. 定怪（⚠️ 候选）

- 主候选：`BehaviorManager.Tick` RVA `0x19ce6164`（file `0x19ce2164`），**唯一调用者** `0x1a7f0710`。
  反汇编语义：参数检查 → `0x19cdabbc(this,arg,0,0)` 判定 → 从 `this+0x50` 表按 id 取条目
  （步长 0x18，字段 `+0x30`）→ 尾调 `0x19ce1a64(this, entry)`。
  （即「按类型分发到某个行为处理器」，未确认是全量 AI 更新）
- 备选：`BehaviorManager.CoroutineUpdate` RVA `0x19ce5508`（唯一调用者 `0x1acc4ee4`）。
- 方案：开关开时在 handler 直接返回（不调原函数）⇒ 该行为管理器不再推进（定怪）；
  代价：同类 NPC 行为也停（可接受，作为第一版）。若效果不对，改从 `0x1a7f0710` / `0x1acc4ee4`
  向上找更精确的「怪物行为更新」点。
