
## 8. R4 实测回执 + 第五轮（R5b）——三项失效根因与修复

### 8.1 用户实测回执（R4 包，L3）

用户口述：「定怪和无限技能有效果，其他三个功能没效果」（2026-10-06 02:0x）。
- ✅ 定怪：R3 起持续有效，路线保留不动。
- ✅ 无限技能（＝无限大招）：R4 的字节补丁路线**首次实证有效**（RVA `0x11541510`，`cset w0,ls` → `mov w0,#1`）。
- ❌ 无敌、❌ 伤害倍率、❌ 移动速度：三项全无效。

### 8.2 三项失效的决定性证据（R4 战斗窗口）

1. **actor 链在战斗场景失效**（无敌＋伤害倍率同时哑的真因）：
   - R4 战斗窗口 logcat（01:57–02:01）连续 10 条 `actor 链根全候选失败`，`me=0`；
   - 对照 `_codex_tmp/chain_now.txt`（02:04，大世界）链通 `actorId=5`，`chain_probe.py` 现在（标题界面）在 `[5]` 层得 `0x0`；
   - 结论：该链只在特定场景成立，战斗/标题场景取不到玩家 id ⇒ 无敌与伤害倍率的过滤判定全部落空。
     这也解释了池鸳「无敌只在非战斗生效」的旧观察。
2. **事件记录自带的归属字段可绕开链**：R2/R4 两局 EVT dump 一致 —— 玩家攻击事件 `+0x1C=5`（攻击方所有权字段），
   怪物事件 `+0x1C=0`，`+0x3C` 多为 0。⇒ 用「+0x1C 所有权值 + 已知 id 集」判归属，不再依赖 actor 链。
3. **移速站点在实战零命中**：R4 已开倍率 30s，`MoveSpeed` 三处计数全 0 ⇒ 站 `file 0xfb2700c` 不在移动路径上。
4. **移速 handler 寄存器用错**：反汇编核对（`_codex_tmp/dis1.sh`/`dis2.sh`，file 偏移口径＝RVA-0x4000）
   确认站点 ratio 在 **s0**，而 R5a handler 用的是 `fmul s8, s8, s9`（v8 是被调用者保存寄存器）⇒ 即便命中也是错算。
5. **新增两个 reset 站点（本轮关键发现）**：`file 0xfb2716c`（方法3 内 3 条写指令，原字节 `3904101f b900f808 b9001008`，
   recovery `0xfb27178`）与 `file 0xfb27294`（方法4 同构，recovery `0xfb272a0`）都是「ratio=1.0f（`0x3f800000`）+ flag=0」的**重置**，
   x0＝速度组件（由 `[x19+0x60]` 查表得），x19＝实体 ⇒ 只要这两处每帧把倍率清回 1.0，apply 站点上的乘法就永远看不出效果。

### 8.5 轮次口径

R1 无效 → R2（`c58ff50e`）无效 → R3（`06cb5086`）仅定怪有效 → R4（`a0a8a0b0…`）定怪+无限大招有效 → **R5b＝本包**
（R5a 为中间调试包，未留正式产物）。
R5b 相对 R4 的可区分变量：① 无敌/伤害＝归属判定从 actor 链换成 id 集 + `+0x1C` 所有权投票；
② 移速＝寄存器修正（s0）＋两个 reset 站点拦截；③ 大招/定怪不动（已实证有效）。
若再无效，按下列分流（下一轮先填 `pipeline round` 假设矩阵，不瞎换站）：
- `无敌拦截` 无日志 ⇒ 看 `ChainSelfTest` / `IsMineOwner` 投票是否符合预期（set/vote 值）；
- `MoveSpeed 命中 apply=0` 且 reset 也 0 ⇒ 站仍不在移动路径，需换站（本包已把两处 reset 纳入口径）；
- `MoveSpeed 命中 apply>0` 但数值无感 ⇒ reset 之外还有第三处清零点或乘区在别的字段，按 id 命中的站点继续追。
