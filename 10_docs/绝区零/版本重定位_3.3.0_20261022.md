## 2. 关键技术事实（实测，决定路线）

1. **框架换算不变**：两版 so 均 `RVA = file_off + 0x4000`（首段 `p_vaddr-p_offset=0x4000`）。
2. **函数边界可离线取**：两版都有 `.eh_frame_hdr` FDE 表；3.2.0 **1,632,716** 个函数、3.3.0 **1,684,963** 个（`04_scripts/绝区零/version_relocate/ehtool.py`）。四个旧站点的函数起点/长度见下表：

   | 功能 | 旧函数起点(RVA) | 长度 |
   |---|---|---|
   | 无敌 | `0x1152104c` | `0x688` |
   | 无限技能 | `0x11541340` | `0x38c` |
   | 伤害倍率 | `0xc02a21c` | `0x954` |
   | 定怪 | `0x19ce6084` | `0x2f8` |

3. **两版同源、按区段整体平移**（本轮最大发现）：随机 32B 窗口两版相同率仅 16%，但同一段代码在两版中**偏移恒定**。实证：`ldr x,[x,#0x28]; ldr w,[x,#0x38]`（同基址）序列在两版各 40 余处，前 6 处逐条对应且偏移恒为 **`+0x28D180`**：
   `0x5225230→0x54b23b0`、`0x5225554→0x54b26d4`、`0x5226cf8→0x54b3e78`、`0x5226d28→0x54b3ea8`（RVA 空间）。
   ⇒ **不能假设单一全局偏移**（不同区段偏移不同），但对单个站点可用「区段投票」求偏移。
4. **符号/元数据路线全部不通（避免重复尝试）**：
   - `libil2cpp.so` 动态符号仅 3,295 条，`il2cpp_*` 只导出 `il2cpp_get_api_table`（3.2.0 与 3.3.0 相同），且该符号指向一段与 API 表无关的 thunk（TP 改写符号层）。
   - APK 与磁盘 metadata 均为 `MHY\0` 加密头，魔数非 `FAB11BAF`；字符串区多为密文/填充。
   - 运行期内存：`/proc/<pid>/maps` 映射的是加密文件（`files/il2cpp/Metadata/global-metadata.dat`，113MB，头仍 `MHY\0`）；整进程扫 `AF 1B B1 FA` 未命中（曾用 frida `Memory.scanSync`，后进程退出，未复测）。
   - 运行期 182MB `rw-p` 匿名堆里**有明文类/方法名**（实测命中 `BehaviourManager`、`SpeedCalculator`、`MonitorMoveSpeed`、`get_`×1856），但只是名字字符串表（8 字节对齐、前置 16B 头），**没有与代码地址配对的 MethodInfo 记录**（按「ptr@0 + name@+0x10」扫描 2385 万 qword 仅 1 条噪声）。
   - frida 可用（17.16.4，`/data/local/tmp/frida-server-17`，需 `su` 起），但 attach 后大范围内存扫描导致游戏主进程退出（未确认是 OOM 还是反调试）。

## 9. 纠正（2026-10-22 04:15）：17 个「事件分发候选」不是无敌挂点同族

- 核对：3.2.0 真·无敌函数（FDE 起点 `0x1152104c`，418 条指令）内 **`cmp #0x85/#0x86` = 0 处、`ldrh #0x16` = 0 处**。
  ⇒ 事件类型 `0x85` 的判定发生在**池鸳自己的 handler（libcymod 0x4e2c8）**里，不在游戏函数里。
- 所以那 17 个「`ldrh #0x16` + `cmp #0x85/#0x86`」函数**与无敌挂点不是同一族**，是扫描判据的假朋友。
- 另：候选地址是**函数中部指令**，`DobbyHook` 的 orig 语义（从该指令起继续执行）对中部指令不成立 ⇒ 即便要动态验证也不能用 DobbyHook，得用 12B 内联桩（`InstallInlineStub` 那套）。
- v0.2 计数钩子已 **`#ifndef ZZZ_PROBE_HOOKS` 默认关闭**，探针包仍为 scan-only（so md5 `13a349fa…`）。
- **不要再用「ldrh #0x16 + cmp #0x85」当无敌/伤害倍率的定位判据。**

| 无限技能闸门 | `0x11541340` (0x38c) | 53 | **0** |
