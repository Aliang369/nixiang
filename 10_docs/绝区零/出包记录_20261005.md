## L2 首轮（MuMu）：so 加载失败根因 + 修法（2026-10-05 深夜）

> 本节结论上盖掉前面的 so/包 hash（修复前一份 md5 `00a841dc…`）。

**现象**：预检 rc=1。logcat 里菜单能弹（`MenuService: native menu shown mode=ACTIVITY`），但同时有
`StarryNativeLoad: loadLibrary starry_magic failed` /
`UnsatisfiedLinkError: dlopen failed: cannot locate symbol "__emutls_get_address" referenced by libstarry_magic.so`，
以及 `ModBridge nativeGetAuthGameId/nativeApplyGrant Unavailable`、`No implementation found for …`。
⇒ 菜单是 **Java 降级路径**，native 根本没加载，五项功能全哑。

**根因**：`ZzzMod.cpp` 的 7 个 `thread_local`（故障保护区）在 Android clang 默认 `-femulated-tls` 下
生成 UND `__emutls_get_address`；该符号**只有 NDK 版 libc++_shared.so 弱定义**（llvm-nm 实测）：
- MuMu `/system/lib64/arm64/libc.so` 与 `libc++.so`：都不导出
- 官包自带 `lib/arm64-v8a/libc++_shared.so`（985,464 B）：不导出
- 真机 `/system/lib64/libc.so`（1,393,176 B）：不导出
⇒ **不是 MuMu 专有**；真机同包同样会挂。定位：staged obj 里只有 `Games/ZzzMod.o` 带这条 UND。

**修法**（`Android_zzz.mk`）：`-fno-emulated-tls`（改原生 TLS）＋ `-Wl,--exclude-libs,ALL`（符号卫生）。
依据：MuMu 的 arm64 libc 导出 `__tls_get_addr` 且 libc/libc++ 自身带 `R_AARCH64_TLS` 重定位 ⇒
转译层支持原生 TLS；属运行时判据，无编译期设备分叉。同一改法已进 `Android_modern_template.mk`（全游戏模板）。

**复检（同一个包，非重出）**：新 so md5 `6cc87112d984dbd400324e92c5b52826`（2,178,768 B）、
包 sha256 `6529589fe01827573573a924d50341435e621579b0638e4a3c8b3b6b8705ce84`（492,272,003 B）、
包内 so/dex md5 与构建产物逐字节一致；L1 PASS。
