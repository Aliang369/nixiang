## 二、两条路的死结（为什么之前一直原地打转）

**保留壳**：壳不是"校验器"，是**启动驱动器**。它依次做三件事——① 解密 `apksecurefile` 得到真实 dex；② 跑 native 更新泵（"数据检查"界面就是它的进度）；③ 泵完成后调用 `runScript` 启动 JS。
壳在 ② 之前就停了（自检不过 / 状态机半成品），所以 ③ 永远不发生。凡"壳跑通后才有意义"的补救（改接口表、hook 导出、改状态字）全部落空——F6 就是这个结论的直接证据。

**无壳**：③ 由壳发起，壳被我们删了，**没人再调 ③**。所以引擎加载了、so 加载了，JS 一行不跑（F10）。之前一直在 hook `runScript` 等它自己出现，方向是反的——它不是"没跑到"，是"没人叫"。

**结论**：1.0.23 能成，是因为那代壳的可骗点被踩中、壳活到了 ③。1.0.25 的壳骗不动，那么正确的做法不是继续骗，而是**在无壳包里自己补上 ③**。

## 三、新路线（按成本从低到高，逐条可判定）

### 方案 A：无壳 + 手动驱动 runScript（首选，成本最低）
- 做法：在 `nativeInit` 返回后（引擎已完成 `Application::run` 的初始化），手动调用 `libcocos2djs+0x1fde78`，观察是否起 JS。
- 前置：需要确认 `0x1fde78` 的真实签名（无参/返回 int）与调用时机（必须在 `nativeInit` 之后、GL 线程就绪后）。
- 判定：日志出现 `jswrapper` 或 `BOOTTRACE runScript return 1`，界面出现 Cocos 渲染。
- 停止条件：调用即崩（说明前置状态缺失，转方案 B）。

### 方案 B：无壳 + 补齐 runScript 的前置（jswrapper 注册）
- 依据：`runScript` 内部遍历 `jswrapper` 表（F10 里该表 0 条）。表由 `ScriptingCore::addRegisterCallback` 在引擎初始化时填充；无壳包里引擎初始化被跳过了一半。
- 做法：hook `ScriptingCore::getInstance()` 或直接构造 `ScriptingCore` 并注册 `jsb` 模块，再调 `runScript`。
- 成本：高（要还原 cocos 的注册链），但比继续骗壳可控。

### 方案 C：保留壳 + 让壳「真通过」而不是「假通过」 —— **2026-11-08 用户定论：当前走这条**
- 依据：F11/F12 证明「改返回值/改分支」会破坏后续语义。真正的通过需要 `apksecurefile` 解密成功。
- 做法：不 patch 代码，而是**让 KEY 正确** —— 把 `.data` 的 `const32`（`0x660de`，32B）/ `const16`（`0x660fe`）按 `KEY_run ^ KEY_official` 修正。
- **前置（顺序不能反）：先取到「运行时」KEY/IV 全量**（`.bss` 三处：KEY `0x786b0`、IV `0x787a0`、flag `0x788a0`）。上一轮硬编码后 `.bss` 仍是星光派生值（KEY `ab3fbe3a…`、hex64 `83c5cc0b…`）⇒ 说明没改到运行期生效的那份。**先解决「哪一份在生效、从哪读」，再谈改常量。**
- **取法（2026-11-08 用户口径）：改为 `ImgReadable` 保护的进程内读**，不再走跨进程 `/proc/<pid>/mem`（Enforcing 下被拦）。具体保护域、注入点、复现脚本由接手会话展开，本文件不预设实现。
- 成本：前置取证低；改常量＋出包为中（一次 32 字节 + 重算 `.text` 摘要）。
- 判定（2026-11-08 已达成）：`.bss` KEY == 官方 `01e45f2b…`／IV == `73f80704…`，`libcocos2djs.so` 解密落地、`nativeInit` 执行 ⇒ **key-unwrap + 解密已真通过**；新卡点转为「`PluginHelper` 静态 `mApp` 为空」（见 `_state/games/动物大联盟.md` 第十八轮）。
- 停止条件：`.bss` 仍为星光值 ⇒ **停止改常量**，回到「定位生效映像」，不要回去骗壳。

## 四、执行顺序（2026-11-08 修订：C 提到第一位，A/B 降为备选）

1. **C-1（当前唯一在做的）**：用 `ImgReadable` 保护的进程内读取出运行时 KEY/IV 全量 → 确认运行期生效的 `libsecret.so` 是哪一份（单映像/双映像）→ 按 `KEY_run ^ KEY_official` 修正 `const32/const16` → 出包装机，看壳是否真通过。
2. **C-2**：若证明「改常量无效」（`.bss` 仍星光值）⇒ 先定位生效映像，不要回退去骗壳（F11/F12 已证伪）。
3. **A/B 暂缓**（仅在 C 被判定为「壳另有一道非 KEY 的门」时再启用）：A＝手动调 `runScript(0x1fde78)`；B＝补 `jswrapper` 注册前置。
