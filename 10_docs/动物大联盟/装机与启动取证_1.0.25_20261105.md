## 6. 最小修复建议（交源码侧；本轮**未改任何 native/Java 源**）

按「最可能 → 最省事」排序，每条都只需**一次**装机即可判别：

1. **把看门狗启动从 `instantiateApplication` 移出**：当前 `startNativeEnv()` 在 Application 构造期就把 native 拉起来并立刻写 `dirty=0`（早于壳自己的初始化，早 4 s）。建议改为 Application `onCreate()` 之后、或由 Provider 在壳完成解密后再触发，并给写回加门控（检测到壳就绪再写）。风险最低、最贴近 1.0.23 已验证次序。
2. **复核 `appComponentFactory` 注入是否必需**：官方根本没有这个属性；若工厂只为 `nativeEnvStart` 服务，可退回「不加 appComponentFactory、只留 Provider」形态做一次对照装机——这条能一刀切开「工厂是否破坏壳的 Application 建立」。
3. **修 delegate 常量**：`androidx.core.app.CoreComponentFactory` 在本包不存在，属无效兜底（只是噪声，但它让每次实例化多一次 `Class.forName` 失败）。要么改成"无 delegate 直接 super"，要么只记一次日志。
4. 若上述都不动而崩溃照旧：需要抓 `ActivityThread`/`LoadedApk` 侧证据（`mInitialApplication` 为什么没被赋值：`makeApplicationInner` 返回值、壳是否二次 bind），这已属下一轮源码分析范围。
