## ② dump 工具原理与复用判断

**whrhx_dump_inmemory_dex.py（Frida）**：枚举全部 ClassLoader → cast BaseDexClassLoader → pathList.dexElements[].dexFile → 显示名以 InMemoryDexFile 开头者入选 → 反射 DexFile.mCookie（long[]，values[1]=DexFile*）→ 在 DexFile* 的 +0x8..+0x80 每 8B 读指针，命中 64 65 78 0A 30 33 35 00 即起点 → 取 +0x20 file_size（≤64MB）→ send 落盘。

**whrhx_mem_dex.c（root 只读 /proc/pid/mem）**：不 attach 不注入；扫 maps 全部 r 段（64KB..3GB）三路定位：① 边界 dex（起点前 4B 已是 dex\n，B 站实测形态）② 逐字节找 dex\n0[3-9] 后校验 header_size==0x70／endian==0x12345678／file_size≤256MB ③ needle 命中回退 64MB 找最近 magic；按 file_size 8MB 分块 pread→write 落盘。

**header 修复：两者都不做**，只按 +0x20 整段拷贝；需修仅两种——checksum(0x8)/signature(0xC) 不符（重算 adler32+sha1）、file_size 被改小（交叉校验）。仓内无现成脚本，需现写约 10 行。

**复用判断**：**C 工具可直接复用**（无包名硬编码，只传 pid/outdir）＝首选——1.0.25 实测有 avc{ptrace} 拦截、壳有反调试；本作 dex 落**可写匿名堆**（Anonymous-DexFile@442084367.vdex 实测 num_dex=4／dex_size=0，无 memfd、无落盘 dex），扫 r-/rw-p 正好覆盖。**Frida py 不能直接用**：包名须改、注入会被反调试杀；若壳走原生 direct-dex（libzeus_direct_dex.so 在位），Java pathList 可能不出现 InMemoryDexFile ⇒ miss（待验证），仅备选。dump 后 sha256 去重、按 class_defs 降序重编号（num_dex=4 为份数线索）。

## ⑤ 风险与验证方法

| # | 风险 | 验证方法 |
|---|---|---|
| R1 | **真实 dex 依赖壳初始化顺序**（BingoApplication 或桥接层调 SecShell_Require／壳 ticket） | dump 后 grep dex 的 secret|SecShell|EncryptorP|zeus；命中⇒保留 libsecret 或编空实现 stub so；L2 看最早 UnsatisfiedLinkError/CNFE |
| R2 | JNI 注册断链（Java_ 符号需 Java 侧声明） | llvm-nm -D 的 Java_ 符号 vs dump dex native 声明逐条对照 |
| R3 | 资源索引是否在壳内 | 已实测反证：arsc 987,632B 明文、apktool 解出 15 个 @style ⇒ 在壳外；仍保留 C10 |
| R4 | Java 侧完整性/签名校验（重签弹窗、拒登）、TapSDK Gatekeeper | dump 后 grep getPackageInfo|GET_SIGNATURES|MessageDigest|GatekeeperRepository；L2 查 check-signature/Gatekeeper |
| R5 | dump 的 dex 头不完整 | dexdump -c／jadx；失败重算 adler32+sha1；再失败按 maps 长度重切 |
| R6 | dex 份数不足（num_dex=4 线索） | C 工具＋Frida 双路交叉；首启 CNFE 即回查 |
| R7 | so 对齐/页大小（p_align=0x1000） | 保默认 extractNativeLibs（装时解压无对齐要求）；显式 false 须 zipalign -P 16；dlopen failed: unaligned 即此因 |
| R8 | ABI（删了 v7a 壳 so） | dumpsys package primaryCpuAbi＝arm64-v8a；回落 v7a 则补 cocos so 或整删 v7a |

**最可能失败**：R1（真 dex 与壳 native 隐式绑定）／R4（Java/渠道签名与完整性校验）。
