# 绿梦：时空之声 — FairGuard 逆壳：解密 IV 判定（是否固定）

- 问题：`libFairGuard.so` 运行期把加密载荷解密到 rwxp 段（文件 offset 0，约 0x400000）。**同一份磁盘文件在不同次冷启下，解密结果是否相同**（=IV/key 固定）？直接决定「改盘」能不能用 `C' = P' ⊕ KS`（参见 `FairGuard逆壳_阶段1_解包器.md` §6 分流）。
- 判定日期 / 设备：2026-10-20，设备 `f9a116a2`（KernelSU，`u:r:ksu:s0`）
- **结论：IV 固定（解密确定性）。** 三次独立冷启，加密载荷区 `0x400..0x1F0000`（2,030,592 B）**逐字节全同**。证据级别：**实测**。

## 1. 取证方法（可复算，零屏幕交互、零改字节、零装包）

对每次冷启：
1. `adb shell am start -n com.zhuziplay.lvmengnew.op/com.bamboo.game.SplashActivity`（第 3 次前先 `am force-stop`，保证冷启）；
2. `pidof com.zhuziplay.lvmengnew.op` → `su -c 'cat /proc/<pid>/maps'`；
3. 取「`rwxp 00000000` + libFairGuard.so」那一段，记 start(hex)/size(hex)；
4. `su -c 'dd if=/proc/<pid>/mem of=/data/local/tmp/fg_ivN.bin bs=4096 skip=$((start/4096)) count=1024'`。
   段起始地址经核验**页对齐**（`start % 4096 == 0`，skip×4096 与 start 十进制完全相等），故 `bs=4096` 与 `bs=1 skip=<start> count=4194304` 等价，但耗时 0.02 s 而非数十秒 —— 在「约 30 s 后进程退出」的窗口内更安全（第 1 次用 14 s 等待时进程已退出，dd 读到 0 字节，即为此原因重取）。
5. `adb pull` → `06_dumped/绿梦_20261016/fg_runtime/`，与基线 `libFairGuard_rwxp.bin` 逐字节比对（均取前 0x400000 字节）。

| **加密载荷 `0x400..0x1F0000`** | **2,030,592** | **0 差异** | **0 差异** | **相同** | **解密结果确定性** |
| 运行期写入区 `0x1F0000..0x400000` | 2,162,688 | 6,159 差异 | 6,159 差异 | 6,159 差异 | 全部落在尾部 24 KB |

载荷区熵：基线 6.399、第 2 次 6.399、第 3 次 6.399（磁盘密文为 7.97）⇒ 三次都**已完全解密**，差异不是「解到一半」。
尾部差异区熵：6.587 / 6.585 / —（基本不变，说明是同构数据在变址，不是不同内容）。

### 4.1 那 6,159 B 差异是什么（已定性，与解密无关）

- 只占 6 个 4 KB 页：`0x3FA000`…`0x3FF000`（镜像最后 24 KB），每页 447/1221/1368/1107/1200/816 B。
- 按 **8 字节对齐切词 = 2,053 个指针**，每对指针差值**完全一致**：第 2 次 `-0xb8d4000`、第 3 次 `-0xed5e000`（2,053/2,053 命中）。例：
  `0x3faa08`: 基线 `0x0000734e4382ec` → 第2次 `0x00007342b642ec`（低 12 位不变、高位整体平移）。
- 即：这些是**指向另一个模块（不同映射）的运行期绝对指针**，随 ASLR 平移；平移量与 libFairGuard 自身基址平移量（第2次 `0x3ce0000`）不同，正是「另一个库的基址随机化」。
- ⇒ 尾部 24 KB 是**运行期填的指针表**，非解密产物；它不影响载荷区结论。

## 5. 结论

1. **解密 IV 固定（确定性）**：三次独立冷启（不同 ASLR 基址、不同时刻 14 s/21 s），加密载荷 `0x400..0x1F0000` 逐字节全同 ⇒ key/IV 与文件绑定，不随运行随机。
2. **对改盘的意义（可直接用）**：已有完整 (C,P) 对即可导出 `KS = C ⊕ P`（2,030,592 B），改盘用 `C' = P' ⊕ KS` 重新加密写回磁盘，**不必逆出 key**。适用范围 = 磁盘 `0x400..0x1F0000`。
3. **不适用 / 仍受限于另一条未闭环**：`0x1F0000..0x400000` 磁盘上全零、运行期写入，改盘无从投递；且其尾 24 KB 含 ASLR 指针，运行时内容本就每次不同。

## 6. 未闭环

1. 载荷区（0x400..0x1F0000）确定 IV 固定；但**未验证 payload 之外的 KS 可延伸性**（如 0x1F0000 之后是否另有独立密钥流）——本判定按任务书只覆盖已观测的密文区。
2. `fg_t20.bin` / `fg_t26.bin`（历史 4,993,024 B 样本）**不可用作对照**：首 16 字节全零、首个 ELF 魔数在 `0x7D000`，说明当时 dump 起点不在段首（偏移错），本次未采信、也未据此下结论。
3. 完整离线解包器（`04_scripts/绿梦/fg_unpack.py` 的 `decrypt()`）仍未完成——本判定不依赖它，但「不逆 key 直接改盘」这条路现在可由它之外的 KS 导出实现。
