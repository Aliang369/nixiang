## 二、已确证的事实（含证据）

### 2.1 运行时签名伪装在真机上失效
小米 M2102K1AC / Android 14 user 版，每次启动必现：

```
E StarrySignSpoof: exemptHiddenApis(meta) failed
java.lang.reflect.InvocationTargetException  ← SignSpoof.java:67
```

雷电（userdebug，隐藏 API 宽松）能过 ⇒ 换机型即失效，与用户判断一致。

### 2.2 弹窗的真正内容（TapSDK 自己打出来的）

```
E TapInitializer: ┃  注意：TapSDK 未正确配置，无法使用 TapTap 开发者服务
                  ┃  应用的包名（package name）、签名（certificate fingerprint）未在 TapTap 开发者中心正确配置
                  ┃  Client ID: 20f4hzlckinbznul5f
                  ┃  包名: com.zhuziplay.lvmengnew.op
                  ┃  签名: 161fca32a36d3df274458682a44cb774     ← 我们 StarryMagic 证书 MD5
                  ┃  https://developer.taptap.cn/104175/app/237561/configuration_center_v4
```

官方原包证书：MD5 `dbcb6bbc8cfbef125cb598fb862e207a` / SHA-1 `85f4a11e736d1112e912a7ad50e97c5590f115e8`。
我们签名：MD5 `161fca32a36d3df274458682a44cb774` / SHA-1 `821c92e404ab5fdac8dbf157c2e467e71440917d`。

### 2.3 该文案不在 APK 内（关键结论）
- 3 个 dex 原文、`resources.arsc`、16 个 `.so` 全部搜过：`未正确配置` / `注意：TapSDK` / `certificate fingerprint`(模板) 均**不在**；
- `┏ ━ ┃` 制表符在 classes2.dex 有，但归属**天翼一键登录 / RangersAppLog** 的框线工具类，不是 TapTap；
- `certificate fingerprint` 的 4 处命中属 RangersAppLog（"Failed to get application signature certificate fingerprint"）。

⇒ **这条拒绝是 TapTap 服务端下发的**（客户端上报 包名 + 证书指纹，服务端比对开发者中心配置）。客户端无法"把校验改掉"，只能改"显示/后续动作"。

### 2.4 TapSDK 4.8.2 内部结构（可用于明天的锚点）
| 位置 | 作用 |
|---|---|
| `com/taptap/sdk/login/internal/LoginActivityImpl` | handler 数组 `[CloudLoginHandler, ClientLoginHandler]`，逐个 `canHandle()` 选第一个，`instance-of` 决定 `LoginEntrance`（CLOUD/CLIENT/else⇒WEB） |
| `…/handlers/client/ClientLoginHandler.canHandle()` | `Intent.resolveActivity()` 能否解析 ⇒ **只是判断"TapTap 客户端是否安装"**，不是签名校验 |
| `…/handlers/web/WebHandler` | `canHandle()` **恒 true**，`getFragment()` → `WebLoginFragment` |
| `com/taptap/sdk/initializer/TapTapSdkInitializer` | `initialize()`（339–1878 行）、`isGatekeeperLoadedSuccessfully()`、`showGatekeeperError()` |
| `…/initializer/manager/GatekeeperManager` | `showGatekeeperError()`、`setupGateKeeperFlow`（服务端配置拉取） |
| `com/taptap/sdk/license/internal/LicenseInitializeTask.execute()` | 调 `TapLicenseInternal.init()`（license 服务往返） |
| `…/license/billingservice/AbsIabService.signatureRight(PackageInfo)Z` | 本地算证书 SHA-1 并比对常量 `A9:99:C3:…`（**该常量匹配官方包都不成立**，属无关历史代码） |
| `libtapsdkcore.so` | 只有 OpenSSL；**无** "signature/cert/APK 签名校验" 语义字符串 |

**重要旁证**：`isGatekeeperLoadedSuccessfully()` 在 `com/taptap/sdk/**` 里**没有任何消费者** ⇒ 这个弹窗大概率只是提示，不拦 Java 侧登录。

## 三、今晚打过的补丁（已回退，明天可原样复用）

1. 摘除运行时签名伪装：`StarryInitProvider.smali` 里 `SignSpoof;->install()` 调用 → 注释掉（dex 级，不改共享源码）。
   验证方法：logcat 里 `StarrySignSpoof` 行消失。
2. 强制网页登录：`LoginActivityImpl` 里两处 `new-instance …/cloud/CloudLoginHandler;` 与 `…/client/ClientLoginHandler;`（含各自 `invoke-direct <init>`）→ 换成 `…/web/WebHandler`。保留 `instance-of` 不动，entrance 自动落到 WEB。
3. `GatekeeperManager.showGatekeeperError()` → `return-void`（`.registers 1`）。
4. `LicenseInitializeTask.execute(Context, TapTapSdkOptions)` → `return-void`（**`.registers 3`**，少写会 smali 编译失败）。

工程支撑（保留未删）：`E:\_build\lvmeng\assemble.py` 现在支持在 `classes2_patched.dex` 存在时替换 `classes2.dex`（不存在则自动跳过，并保持 4 个 untouched 断言）。

**补丁效果实测**：1✅ 2✅（dex 内 `handlers/web/WebHandler` 引用存在）3✅ 4✅（TapStartUp 任务表里 license 任务消失）；**但弹窗仍在** ⇒ 与 2.3 的结论一致（服务端文案，显示点不在上述位置）。

## 四、明天的候选路线（按性价比排序）

1. **先做判定（1 分钟）**：弹窗点掉后能否完成登录（网页授权）。能 ⇒ 弹窗纯提示，只需掐显示；不能 ⇒ 服务端拒绝影响登录态，走 2/3。
2. **找显示点**：`GatekeeperManager.setupGateKeeperFlow` 失败回调（含 `$setupGateKeeperFlow$1$1`），以及 `TapTapSdkInitializer.initialize()` 内的失败分支。注意 smali 里中文是 `\uXXXX` 转义或原文，两种都要搜。
3. **改上报指纹**：若确认要过服务端校验，需要找到上报 `certificate fingerprint` 的代码（Java 层未见 MessageDigest，怀疑在 `libtapsdkcore.so` 或 JNI），改成官方指纹 `dbcb6bbc8cfbef125cb598fb862e207a`。**注意：这是伪造上报值，服务端若另有校验仍可能拒**。
4. **绕开 SDK**：不经过 TapSDK 的登录，直接走 TapTap 独立网页 OAuth（浏览器授权回跳）。需要拿 client_id + 回调协议，工作量大但最不依赖 SDK 内部实现。
5. **保留兜底**：SignSpoof（隐藏 API 豁免）在 userdebug 类设备仍可用，作为降级路径保留，但不再作为首选。
