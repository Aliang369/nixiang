# 绿梦 · Phase 1：libil2cpp rwxp 影副本窗口时序快照（翻转时刻取证）

> 日期：2026-10-20 04:31–04:34　设备 f9a116a2　当前装机包 = 绿梦_tgk_spy2.apk（prop=0，闸不生效）
> 工具：新增 \`04_scripts/绿梦/il2cpp_win_snap.sh\`（preflight PASS）＋ \`04_scripts/_common/memdump64\`（pread /proc/<pid>/mem，不 attach、不改 TracerPid）
> 目标：判定 libil2cpp 影副本 0x3630000–0x3650000（128 KB）里「非法指令」是启动解密就坏，还是运行期被写坏

## 0. 结论（先看这段）

1. **翻转时刻 = 冷启后 t≈12 s**，**不是持久翻转**：这段内存在两轮实测里都是
   「t≤11 s 全合法 → t≈12–17 s 出现零星 4 字节非法字 → t≥18 s 又全部恢复合法」。
   ⇒ 不是「解密密钥错导致整段解成垃圾」（那种会是整段、且不恢复），也不是「37.8 s 被写死」。
2. **改动是「按 3256 字节步长的单字滚动变换」**：非法字都落在 stride = **3256 (0xcb8)** 的格点上，
   每拍只在格点上改一个 4 字节字；波形从窗口低地址向高地址推进（t=12 从 0xa78 起，t=16 只剩 0x171d8 以后的尾巴），
   然后被逐字还原。128 KB 窗口约 4–6 s 扫完一遍。
3. **之前三个「疑似故障点」全部是误判**：+0xb118 / +0x1a500 / +0x56e8（对应 libil2cpp 0x363b118 /
   0x364a500 / 0x36356e8）在 19 拍里**字节完全一致、且都是合法指令**：
   - +0xb118 = \`b9403a68  ldr w8, [x19, #0x38]\`
   - +0x1a500 = \`395fc2a8  ldrb w8, [x21, #0x7f0]\`
   - +0x56e8  = \`a95f8509  ldp x9, x1, [x8, #0x1f8]\`
   ⇒ 崩溃报告里的 \`#00 pc\` 是 **CrashSight 重投信号时的落地帧**，不是故障点（上一份文档 A2 §0.3 的
   「故障窗 0x3635xxx–0x364axxx」应降级为「重投落地帧聚集区」）。
4. **非法指令的产生机制（本轮最有价值的推断，证据 3 条）**：这段代码页有一套**运行期滚动变换**
   （解密↔加密/校验），变换经过的那个字在**变换瞬间不可解码**；若执行正好落到该字上 ⇒
   \`SIGILL / ILL_ILLOPC\`（与 mode 2 那次 \`pc==lr=libil2cpp+0x363b118\` 完全吻合，因为 +0xb118 就是格点邻位）。
   ⇒ 这是「**执行撞上正在变换的字**」的竞态，而不是「有人写了一条 udf 不还原」。
5. **变换本身是常态**：第二轮（t=12–17 s 同样出现滚动变换）**整轮没有崩溃**（进程活到 90 s+，
   logcat 无 \`get signal\`）⇒ 滚动变换≠处决动作；处决仍取决于 cert 比较分支（未定位）。

## 2. 判据对照

| 判据 | 结果 |
|---|---|
| (A) 翻转时刻 | **t≈12 s 起、t≥18 s 恢复**（两轮一致；不是持久翻转） |
| 翻转 offset 表 | stride 3256 的格点；轮 A 从 0xa10/0x16c8 起，轮 B 从 0xa78 起；完整表见 §1 |
| 是否「解密时坏」 | 否：t=4 s 起整窗就是合法指令 |
| 是否「37.8 s 被写死」 | 否：窗口在 18 s 后直到 44 s 完全静止 |
| (B) 写入者「模块+RVA」 | **本轮未取得**（未上 ptrace watchpoint；见 §3 下一步） |
| 证据留档 | 19×2 拍原始 128 KB 快照 + 逐拍统计 + 崩溃块，脚本可一键复跑 |

## 3. Phase 2 精确目标（按本轮数据重排）

硬件写观察点应打在**确实会被改的格点**上（而不是之前误判的 0x363b118）：
\`\`\`
运行时地址 = il2cpp rwxp 基址 + 0xa78    （轮 B 首个被改字；轮 A 为 0xa10）
运行时地址 = il2cpp rwxp 基址 + 0x171d8  （轮 B 尾巴仍被改的字，命中窗口更宽）
基址获取：/proc/<pid>/maps 里 libil2cpp.so 的 rwxp 段起始（每轮 ASLR 不同）
时机：t=8 s 起布点（变换 12 s 才开始），命中窗口 12–17 s
\`\`\`
工具要求：\`PTRACE_SEIZE\`（不改 TracerPid 语义）→ \`PTRACE_SETREGSET\` + \`NT_ARM_HW_WATCH\`
（aarch64 只 4 个槽，先打 2 个格点）→ 等 \`SIGTRAP\` → 读 \`siginfo\`/\`NT_PRSTATUS\` 的 pc/lr/x29 →
归一「模块+RVA」。命中者应落在 libFairGuard.so（滚动变换的执行者），拿到它下一步才能顺藤摸到 cert 比较。

## 4. 未闭环

1. 本轮仍未直接观测到「真正的故障字」：轮 A 崩溃时的 \`#00\` 是重投落地帧（0x37b16c8，窗口外）；
   要抓故障字需**把快照窗口扩大到 0x37b1xxx 一带**并在崩溃瞬间（±1 s）加密采样。
2. 滚动变换的步长 3256 与页大小 4096 不同源，机制未定（是"逐字解密"还是"校验写回"）⇒ watchpoint 命中后看写入宽度/循环结构即可判定。
3. 「变换 + 执行撞上 = SIGILL」目前是**推断**（证据：格点邻位与 mode 2 的 pc==lr 吻合；两轮都出现变换；
   但轮 B 有变换无崩溃）⇒ 需在崩溃轮用 watchpoint 复核。
4. cert 比较点仍未定位；本轮把「故障窗」这个错误目标清掉，等于把搜索空间缩到「滚动变换的执行者」+「cert 分支」。
