# 绿梦：时空之声 — libFairGuard.so 解包镜像离线分析（Stage 3，纯离线）

- 输入：磁盘 `06_dumped/绿梦_20261016/libFairGuard.so`（4,477,792 B, md5 `7bee7f8b…`）＋运行期镜像 `06_dumped/绿梦_20261016/fg_runtime/libFairGuard_rwxp.bin`（4,194,304 B, md5 `8297e6b9…`）。
- 工具：`04_scripts/绿梦/fg_image_analyze.py`（变换/关键字/指纹/svc）、`fg_disasm.py`（capstone 5.0.7 反汇编）、`fg_calls.py`（BL 调用图）。全部只读，未改任何字节、未动设备。

## 1. 结论摘要

1. **解包变换不是"可逆改盘"类**：既不是 XOR/流密码（`xor(disk,img)` 零率 0.0035、周期 1/4/8/16/32/64/256/4096 全不重复），也不是压缩容器（无 ZIP/LZ4/GZIP 头），也不是单一整体重定位（4 K 页同一性 **1/1021**；按 1 MB 分区求最优位移，最好也只有 **17.6%** 字节相同）。⇒ **镜像 = 解密后的载荷 + 重排**，磁盘侧不存在"改字节 → 运行期生效"的简单通路 ⇒ **磁盘 patch 方案不可行**。
2. **但有一处是逐字节可对应的**：镜像 `0x35B100..` 与磁盘 `0x42EB00..` **完全相同**（位移 −0xD3B00），即"壳的 mini-libc/系统调用桩"被**原样复制**到载荷区。这说明重排以"段/函数"为粒度，而非全文件加密后平移。
3. **期望证书指纹不在任何明文里**（与决策官的补充事实一致，本轮独立复核）：4 个指纹的**二进制形态与十六进制文本形态**在磁盘、镜像中各 **0 命中**；对 7 个关键字做 **全 256 单字节 XOR** 扫描同样 **0 命中**。⇒ 指纹要么二段懒解密、要么运行时现取（APK/服务器）、要么校验方式根本不是"比固定指纹"。
4. **退出桩存在 8 个静态调用点**（payload 自带 exit_group 桩 `0x35BE00`，其镜像位置与磁盘壳同名桩同源），但调用点上下文是 **MBA 混淆块**，不能仅凭静态断言"30 s 走哪条"。
5. **两套桩表是同一份代码的两个副本**：`0x42E000`（磁盘壳原位）+ `0x35B000`（镜像内原样副本）。被大量调用的是**镜像副本**（296 处 BL）；磁盘原位副本在壳代码里只有 `0x418184` 一处 exit_group 调用，且运行期 5 次 hook 零命中（Stage 2 已证）。

## 2. 解包变换刻画（任务 1）

| 检验 | 结果 | 判读 |
|---|---|---|
| 4 K 页完全相同（disk vs img，0..0x400000） | **1 / 1021** | 不是整体平移 |
| `xor(disk,img)` 零率（0x400..0x1F0000） | **0.0035** | 不是单字节/多字节固定 key |
| xor 流周期 1/4/8/16/32/64/256/4096 | 全部 **不重复** | 不是周期性流密码 |
| ZIP(`PK\x03\x04`) / LZ4 / GZIP 头 | 0 / 0 / 仅误命中 | 不是压缩容器 |
| 逐 1 MB 分区最优位移的字节相同率 | 最高 **17.6%**（0x200000 区，shift −0xBA00） | 不是分段整体平移 |
| 镜像 `0x35B100` vs 磁盘 `0x42EB00`（0x400 B） | **逐字节相同**（shift −0xD3A00/−0xD3B00） | 壳代码被原样复制 |

> 结论：`libFairGuard.so` 在加载时把磁盘上的加密载荷**解出来并按新布局摆放**（含把明文壳里的 syscall 桩整段复制过去）。这套变换**不可由磁盘字节线性推导**，所以"改磁盘 so 的某个字节"不会等价出现在运行期代码里。

## 3. 字符串 / 常量（任务 2）

- 单字节 XOR 全键扫描（key 1..255，镜像全量 4 MB）：
  `META-INF`、`base.apk`、`signature`、`AndroidManifest`、`APK Sig Block 42`、`sha256`、`/data/app` → **全部 0 命中**。
- 已知指纹（二进制 + 十六进制文本，两种形态）：

| 指纹 | 磁盘 so | 运行期镜像 |
|---|---|---|
| cert SHA256 `cb41e01e…` | 0 / 0 | 0 / 0 |
| cert SHA1 `85f4a11e…` | 0 / 0 | 0 / 0 |
| cert MD5 `dbcb6bbc…` | 0 / 0 | 0 / 0 |
| pubkey SHA256 `520fa5f2…` | 0 / 0 | 0 / 0 |

- 解读（三种可能，均未证）：
  1. **二段懒解密**：指纹在第二次解密/按需解密的表里，15 s 时刻尚未解开；
  2. **运行时现取**：校验把 APK 里读到的签名与"服务器下发 / 其它存储"的值比，so 里本来就没有常量；
  3. **非指纹比对**：比的是整套签名块的哈希/长度/结构，而非预置指纹。
- 另：镜像里唯一可读的符号类字符串集中在 `0xd800` 附近（`libFairGuard.so`@0xd9f4、`__register_frame_info`@0xd891），与磁盘 `.dynstr`（0x40b3c8）位置完全不同 ⇒ 也印证"重排"。

## 4. 退出路径（任务 3）

- 镜像内 `svc #0` 共 **62** 处；系统调用桩表位于 `0x35B000` 起、步长 0x100：

| EA | x8 | 调用 | EA | x8 | 调用 |
|---|---|---|---|---|---|
| 0x35B100 | 0x38 | openat | 0x35B900 | 0xE2 | mprotect |
| 0x35B200 | 0x3F | read | 0x35BD00 | 0xA9 | 169（存疑） |
| 0x35B300 | 0x40 | write | **0x35BE00** | **0x5E** | **exit_group** |
| 0x35B400 | 0x39 | close | 0x35BF00 | 0xA7 | prctl |
| 0x35B500 | 0x75 | **ptrace** | 0x35C700 | 0xDE | mmap |

- BL 全量扫描：**37,305** 条 `bl`；其中 **296** 条指向该桩表。`exit_group` 桩的静态调用者 **8 个**：

| # | 调用点 EA | 紧邻上下文（节选） |
|---|---|---|
| 1 | `0x2F08C` | `cmp x1,x0 ; csetm w0,ne ; bl exit_group ; b 0x2E7C4` |
| 2 | `0x459EC` | `eor/orn … ; bl exit_group ; b 0x2B56C` |
| 3 | `0x462BC` | （同类混淆块尾部） |
| 4 | `0x46534` | `and w0,w0,#0xff ; sub w0,w0,#3 ; bl exit_group` |
| 5 | `0x47E1C` | `cmp x5,x0 ; csetm w0,ne ; bl exit_group` |
| 6 | `0x484A0` | （同类） |
| 7 | `0x1AA824` | `eor/orn … ; bl exit_group ; b 0x1A9228` |
| 8 | `0x1B0200` | （同类） |

- 判读（**推断，非实测**）：这些块的形态是"MBA 混淆算术 → `bl 桩` → 无条件跳回分发器"，是典型的**混淆分发器**写法；`0x2F08C`/`0x47E1C` 的 `csetm w0,ne` 意味着**退出码是"比较结果"（0 或 −1）**，与现场 `exited cleanly (0)` 相容。
- **未发现的**：镜像里没有明显的"第二段解密/懒加载入口"证据（无第二个 ELF 头、无新 mmap 表）；但镜像只覆盖 `0..0x400000`，`0x400000` 以上（壳本体）没进 dump。

## 5. 两套桩表的关系（任务 4）

| 项 | `0x42E000` 段（磁盘壳原位） | `0x35B000` 段（镜像内） |
|---|---|---|
| 来源 | 磁盘明文壳 `0x413AB0..0x431350` 里自带的 mini-libc | 壳代码被 loader **整段复制**到载荷区（逐字节相同，位移 −0xD3B00） |
| 内容 | openat 0x42EB00 / read 0x42EC00 / mprotect 0x42EF00 / **exit_group 0x42F100** | openat 0x35B100 / read 0x35B200 / mprotect 0x35B900 / **exit_group 0x35BE00** / ptrace 0x35B500 / prctl 0x35BF00 |
| 静态调用者 | 壳内：exit_group 仅 `0x418184` 1 处；openat 2 处（`0x42A488/0x42A61C`，mini-libc 封装） | payload 代码：**296 处**（含 exit_group 8 处） |
| 运行期命中（Stage 2） | 5 次 hook `0x42F100`，**0 命中** | 1 次 hook `0x35BE00`，**0 命中** |

⇒ 两套是**同一份桩代码的两个副本**；真正被调用的是镜像副本（296 处 BL）。磁盘原位那份对 payload 无用（位移后不再被引用），这解释了为什么 hook 磁盘偏移 `0x42F100` 永远不命中。

## 6. patch 候选（供决策官复核，**本阶段未改任何字节**）

| 候选 | EA（镜像内偏移） | 改法 | 前提 / 风险 |
|---|---|---|---|
| **PC1–PC8** | `0x2F08C / 0x459EC / 0x462BC / 0x46534 / 0x47E1C / 0x484A0 / 0x1AA824 / 0x1B0200` | 把 `bl 0x35BE00`（`94000000|imm26`）改成 `nop`(`D503201F`)，或改跳板返回 | **只能运行期 patch**：镜像地址对应的是解密后内存，磁盘同偏移不是同一内容；\n且要先确认 8 处里哪一处是 30 s 实际路径（否则一改可能只是改掉异常路径） |
| **PC9** | 壳 loader（磁盘 `0x413AB0..0x431350`） | 逆出 loader 的解密/重排算法，改为"解密后覆写判定点" | 这是唯一能落成**静态改盘**的形态；工作量大，但壳是明文可反编译 |
| **PC10** | 判定分支（未定位） | 恒真/跳过 | 需要先拿到"指纹来源"，见 §3 未闭环 |

> **建议**：不要走"改磁盘 so 字节"（PC1–PC8 的磁盘等价物不存在）。两条现实路线：① 运行期（由已注入的 StarryMagic so 在 `libFairGuard.so` 解包完成后改写上面 8 个调用点或分支）——但必须先解决反调试；② 逆向壳 loader（PC9），做成"解密产物被替换"的静态补丁。

## 7. 未闭环

1. **8 个 exit_group 调用点哪个在 30 s 触发**：静态无法定；需要运行期在**调用点**（不是桩）下钩，且要先绕开反调试（Stage 2 已证 frida 在机会让死亡提前、一次 SIGILL）。
2. **指纹缺失的含义**：二段懒解密 / 运行时现取 / 非指纹比对，三者未区分。
3. **晚时刻镜像（~26 s）未取得**：第一次用 `dd` 直读 `/proc/pid/mem`（无 frida）时 `skip` 单位算错（把字节偏移当 1 MB 块），只得到 4.99 MB 的零区；第二次 frida 晚 dump 因脚本路径替换失误未执行。**只试了一次，按纪律未硬刚**。
4. **镜像只覆盖 `0..0x400000`**：`0x400000` 以上（壳本体 + `.data`）未 dump，无法排除"第二段表在更高地址"。
5. **未验证**：镜像里 296 条指向桩表的 BL 是否真被 VMP 分发器使用（部分可能是混淆产生的合法但不可达路径）。
