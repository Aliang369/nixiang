# 绿梦：时空之声 — FairGuard 逆壳：B 区生成（0x1F0000 的 17.6 KB 高熵块）

- 背景：B 区（运行期镜像 0x1F0000..0x400000）内容在磁盘上几乎全零，唯一高熵块在 0x1F0000 起约 17.7 KB。
- 本轮三个问题：①这 17.6 KB 的精确分布（是不是 47 个独立加密块）；②它与运行期 B 区是否逐字节对应；③用 A 区 `KS=C⊕P` 试解，看像 AArch64 码还是"长度/偏移描述表"。
- 日期 / 设备：2026-10-20，`f9a116a2`。样本：磁盘 `.so` `7bee7f8b…`（4,477,792 B）、运行期镜像 `8297e6b9…`。**全部为离线计算，本轮未动设备。**

## 1. ① 分布：不是 47 个独立块，是**一个连续的 17,710 B 块**

按"非零连续段"切分确实得到 **47 段、非零字节合计 17,664 B**，但**段与段之间只隔 1 个零字节**（例：首段 0x1F0000+161=0x1F00A1 结束，下一段正好从 0x1F00A2 开始）：
⇒ 真实结构是 **0x1F0000..0x1F452D（含端点，跨度 17,710 B）的一整块**，内部夹了 **46 个零字节**（位置：0xa1、0x512、0x696、0xc49、0xcc5、0xccd、0xcdd、0xce4、0xdc1、0xe3d、0xe9c、0xecc、0xf8e、0x10ef、0x112a、0x14b5、0x151d、0x1790、0x179a、0x19b6 …（相对偏移））。
- 零密度 46/17,710 = 0.26%（随机期望 ≈ 1/256 = 0.39%，≈69 个）⇒ **零字节本身没有结构意义**，不是分隔符。
- **块之后到 0x400000 全零**；块长度 17,710 不是 16 的倍数（17,710 = 16×1,106 + 14）⇒ 也没有按 16 B 分组对齐的特征。

| 指标 | 值 |
|---|---|
| 块区间 | 0x1F0000 .. 0x1F452E（不含端），17,710 B（非零 17,664 B） |
| 熵 | **7.982**（近均匀：256 个字节值全出现，最高频字节仅 102 次） |
| 16 B 分组 | 1,106 组，**全部互不相同**（无 ECB 特征） |
| zlib / raw-deflate / gzip / bz2 / lzma | **全部解不开**（试过跳过 0/4/8/16/32/64 B 头） |

## 2. ② 与运行期 B 区是否逐字节对应：**不对应**

| 检验 | 结果 |
|---|---|
| 块内 3 处 64 B 特征（头/中/尾）在运行期镜像里搜索 | **0 命中**（整块 `.find` 也是 −1） |
| 块 ⊕ 镜像@0x1F0000（同址） | 熵 7.99，逐字节相同数 71/17,710（随机水平） |
| 块 ⊕ 镜像@0x3FA000（GOT 区）/ @0x3E0000 / @0x200000 | 熵 7.98–7.99，相同字节 57–67（随机水平） |
| 块本身当密文直接反汇编 | 可解码 36.1%、**ret 0 条**（与随机字节的基线一致） |

⇒ **17.6 KB 既不是 B 区同址密文，也不在 B 区里**；B 区（2,162,688 B）不是这 17.6 KB 直接展开的结果（要 122:1 的膨胀比，且 B 区熵 6.6，不符合压缩展开特征）。

## 3. ③ 用 A 区 KS=C⊕P 试解：**三种对齐全部失败**

`KS = C⊕P`（0x400..0x1F0000，2,030,592 B，熵 8.00）。把 17,710 B 块分别与：

| 做法 | 熵 | 可解码率 | ret | u64<4 MiB 占比 |
|---|---|---|---|---|
| 原样（密文基线） | 7.98 | 36.1% | 0 | 0.0% |
| ⊕ KS[0:]（从头对齐） | 7.99 | 36.0% | 0 | 0.0% |
| ⊕ KS[尾部 17,710 B] | 7.99 | 36.3% | 0 | 0.0% |
| ⊕ KS 反向 | 7.99 | 34.7% | 0 | 0.0% |
| ⊕ 镜像@0x3FA000 | 7.98 | 34.4% | 0 | 0.0% |

**没有一种解出"像 AArch64 代码"（ret 0 条）或"像长度/偏移表"（8 字节值没有一个 < 4 MiB）的结果。**
⇒ 这 17.6 KB **不是用 A 区那条密钥流加密的**（换密钥/换计数基址，或在别处生成）。

## 4. ③ 补充：B 区生成假设（按现有证据排序）

| # | 假设 | 支持 | 反对 | 状态 |
|---|---|---|---|---|
| H1 | 17.6 KB 是 B 区密文，解密后直接铺到 0x1F0000 | 位置紧接 A 区密文之后、高熵 | 同址 XOR 熵 7.99；体积 122:1 不可能；不在镜像里 | **否定** |
| H2 | 17.6 KB 是 **B 区的描述表**（加密的 offset/length 对） | 体积巧合：17,710/8 ≈ **2,213 条**，B/2,213 ≈ **977 B/条**，正好是可用的分块粒度 | 三种 A-KS 解不开；密文下看不到任何表结构 | **待验证（最值得先查）** |
| H3 | 17.6 KB 是 **GOT/重定位种子**（运行期 B 区尾 0x3FA000..0x3FFFF3 有 2,053 个指针 = 16,424 B） | 16,424 + 1,286 ≈ 17,710，体积吻合；指针簇正是运行期才出现 | 指针是 ASLR 值，不可能原样存盘；与 GOT 区 XOR 熵 7.99 | **待验证** |
| H4 | B 区由 A 区明文 P 展开/翻译得到，17.6 KB 只是某个 key/表 | A 区 2,030,592 B 与 B 区 2,162,688 B 同量级 | 上轮翻转实验：改 A 区密文**不改变** B 区内容 | **与实测冲突，未解** |
| H5 | **壳读的是包内 `lib/arm64-v8a/libFairGuard.so` 的 comp=8 压缩条目**（而非 /data 抽取出来的那份） | 能同时解释"改抽取文件不改解密输入、却破坏一致性"、以及"磁盘 0x1F0000 块打不开" | 包内条目与抽取文件**同样是这 17,710 B**（md5 逐字节相同），故本假设不改变本节的块内容结论，只改变"谁是输入" | **待验证**（A 子代理 Unicorn 正在离线判 `read(fd=0xa)` 指向包内还是抽取文件） |

**当前唯一硬结论**：17.6 KB 是一整块高熵数据（非 47 块、非压缩、非 A 区密钥流加密），B 区的生成输入**仍然没有定位到磁盘载体**。

## 5. 未闭环 / 下一步

1. **17.6 KB 的密钥流**未知（A 区那条不适用）。要打开它，必须先找到"谁读 0x1F0000 这 17,710 B"——建议在 A 区壳代码里搜 `0x1F0000`/`0x1F452E` 这类立即数（`movz/movk` 组合）或其 `adrp+add` 形式。
2. **H2/H3 的区分**：若能拿到 17.6 KB 的明文（哪怕是部分），看它是不是 2,213 条 (off,len)，或 2,053 个重定位描述，即可定案。
3. **与上轮翻转实验的矛盾仍未消**：改 A 区密文不改变运行期明文/B 区，却导致 0.5 s 崩溃——说明"磁盘抽取的 .so"不是壳的解密输入（详见 `FairGuard逆壳_完整性闸门.md` §7.3）。
4. 本轮零设备操作，无残留。
