### TP 1.5.3 dynsym 改写结论（v0-v5 实测）

- 名字层+地址层双改写：30 样本 17 个运行时地址无磁盘落点；磁盘 .text **加密**（磁盘偏移≠运行时真址）
- `il2cpp_domain_get_assemblies` 被 TP **整条删除** → strtab 明文反查（PLAINTEXT 命中）+ `il2cpp_domain_assembly_open` 按名开 11 程序集兜底
- 运行时 dynsym 的函数地址本身可用（TP 只加垫片位移）

### 大弯路（勿重蹈）

1. **磁盘静态偏移覆盖（v1/v2）**：磁盘推导地址处是密文，hook 装进去=SIGILL 闪退。磁盘偏移一律不可用。
2. **堆扫描找实例 + runtime_invoke 写数据（v11-v13，五连闪退主因）**：/proc 扫 klass 指针命中 5000+ 全是元数据假阳性，真实例从未命中；invoke 失败值 -1 撞上未解析阵营值 -1 → 对垃圾对象写 HP。**游戏实例定位不要走堆扫**。
3. **hook 回调里做对象学习（v6-v8）**：主线程解引用参数 = 必崩；学习线程+SEGV handler 也被 TP 毒杀。

### 桩签名三查（v14.0/v14.1 伤害恒 0 的根因，血泪教训）

1. **返回类型**：`double` 返回在 d0，float/int 桩读 s0/x0 位型全错；wrapper 内调其他函数还会清掉 d0
2. **FP 参数寄存器**：参数含 float/double 时，整数桩（void*）会打坏 d0-d7 → 公式拿垃圾。本例参数恰好全 byref 指针才幸免
3. **static 判定**：`il2cpp_method_get_flags & 0x10`；static=argc 槽+method，instance=+this。V4 兜底少转发 1 槽 = 伤害恒 0（v14.0）
- **SOP**：装 hook 前先打 `CalcSig`（`method_get_return_type`/`method_get_param`/`type_get_name`/`method_get_flags` 一次拿全），按签名写桩

### 其他实锤

- **基类方法指针 ≠ 派生 override**：敌我判定若直调基类 `get_factionIndex` 指针，怪（`AbilitySystemForEnemyPart` 等派生类）读不到正确阵营 → 必须按对象 klass 解析 override
- **SyncHooks 并发**：浮窗线程与主线程同时装 hook → 对同一函数重复 DobbyHook → 毒杀（v10）。修复：互斥 + 装成即停 + 熔断（3 次 dobby fail 放弃）
- 构建机磁盘满 → zip 组装 `Errno 28` 且 EXIT 非 0，但管道 `| tail` 会吞退出码导致误装旧包——构建后必须校验 APK 时间戳
- `pause()` 挂起的学习线程保留在 EndfieldMod.cpp（v12/v13 数据写代码也在，已弃用未删，回滚参考用）

## TP 符号隐藏三件套（2026-09-03 静态复核完全破解）

从 PT_DYNAMIC→DT_SYMTAB 视角解析（section header 全被污染不可用），
libil2cpp 1.5.3 的 4344 条导出符号（sym[350..4706]）**信息零丢失**，全部恢复：

| 域 | TP 动的手脚 | 恢复方法 | 命中率 |
|------|------|------|------|
| st_value | b7=0x80「已处理」标志 + 真址存 b3~b6 **大端** | `addr = (st_value>>24) & 0xFFFFFFFF` | 4344/4344 |
| st_name | 改成**字符串终止符偏移**（不是起始偏移），标准工具读到空名 | 从 `strtab+st_name` **回扫到上一个 NUL**，中间即真名 | 4344/4345 |
| 符号顺序 | dynsym 条目重排，GNU hash 表不重建 | 不用 hash，线性扫全表即可 | — |

## 新方案：进程内 dynsym 自解析（替代 BNM，大幅简化）

EndfieldMod/Il2CppApi 增加 `resolveDynsym()`，**彻底替代 xdl_sym/dlsym**：

```c
// 1. /proc/self/maps 找 libil2cpp.so 基址 base
// 2. base 处解析 ELF header → PT_DYNAMIC → DT_SYMTAB / DT_STRTAB
// 3. 线性扫 sym[i] (i=350..4706，或按 st_value b7==0x80 过滤):
//      addr = (st_value >> 24) & 0xFFFFFFFF;      // b3~b6 大端真址
//      p    = strtab_fileaddr + st_name;          // 指向终止符
//      name = 从 p-1 往回扫到上一个 '\0' 的 (p-1 .. q+1]
// 4. 建 name→addr map，il2cpp_domain_get 等 467 条 API 全部可解
//    （API 表已静态解出: /tmp/ef153_api.json, 467 条 il2cpp_/mono_/lua_）
```

优势：零依赖（不需要 TP 恢复、不需要 BNM 结构遍历、不需要 metadata 解密）、
一次性建立 4344 符号表、EndfieldMod.cpp 现有按名 hook 逻辑**零改动**。
BNM 结构遍历降级为 fallback。

**静态分析面**：`/tmp/ida_import_ef153.py` 已向 IDA 导入全部 4344 符号
（`/tmp/ef153_full.json` name+addr+size+type），并经 IDA MCP 交叉验证完成。

**0x9a0a824~0x9a0bf44 = TP 加密岛**（磁盘高熵，运行时由 DT_INIT=0x1aece51c 的
解密器还原为有效代码）。铁证：.got.plt 11 条 R_AARCH64_RELATIVE 重定位直接命中
岛内符号——il2cpp_object_new@0x9a0b418、il2cpp_class_from_il2cpp_type@0x9a0a8b8、
il2cpp_class_get_methods@0x9a0a890、il2cpp_array_new@0x9a0b8ac、
il2cpp_object_get_virtual_method@0x9a0b9b4 等；游戏自身运行时经 PLT 必调这些地址，
岛上必然是解密后的有效代码。mono_* 123 条同理聚在 0x9a0c0000 附近另一加密岛。

**IDA 交叉验证结果（2026-09-03，via IDA MCP py_exec）**：4344 条中 4066 条
名称精确落位（93.6%）；功能相关 API 组 100% 全中——il2cpp 234/234、mono 128/128、
lua 105/105、luaL 47/47、xlua 81/81、SystemNative 25/25、luaopen 24/24、
socket 24/24、opt 31/31、auxiliar 11/11；10 个关键符号点检全对。
278 条未命中全部为良性：C1/C2、D0/D1 构造析构别名、链接器 ICF 同码折叠
（如 0x7eb9418 有 12 个名、0x7eda0a0 有 7 个名共用）、IDA 数据项合并导致的
假阴性。~~符号地址解码公式 (st_value>>24)&0xFFFFFFFF + base 100% 正确，
Il2CppApi.cpp 无需修改。~~

## 开启即闪退根因与修复（2026-09-03 深夜）

现象：四功能任意开关开启即 SIGSEGV 闪退（toggle → SyncHooks → EnsureApi →
Api::Load 首跑 → BuildDynsymMap，崩溃窗口内无 `dynsym self-parse` 日志）。

根因 3 处（`mod菜单/starry-mod-menu/app/src/main/jni/Unity/Il2CppApi.cpp`）：

1. **TP 真址字节序反装（主因）**：BuildDynsymMap TP 分支
   `(st_value>>24)&0xFFFFFFFF` 缺 `__builtin_bswap32` → 解出错误且非对齐地址
   → hook 写跳板/调用即崩。修复：`uint32_t packed = (st_value>>24)&0xFFFFFFFF;
   addr = base + bswap32(packed)`。
2. **解析无 SEGV 防护**：DynsymLookup 的 call_once 裸跑 BuildDynsymMap，
   SafeProbe/SetScanThread 基建齐备但从未使用。修复：SetScanThread(当前线程)
   + SafeProbe 包整个解析；SEGV 兜底并打 `(probe=SEGV-caught)` 日志。
3. **d_ptr bias 兜底**：LocateDynsym 把 DT_SYMTAB/STRTAB/GNU_HASH 的 d_ptr
   直接当绝对地址。bionic linker 通常写回 bias，但 TP 自加载器不保证。
   修复：按 PT_LOAD 算 [base, mapend) 范围，d_ptr 落范围外而 +base 落内则补 bias。

验证方法：装机后开任一功能，`adb logcat -v threadtime | grep Il2Cpp` 应见
`[Il2Cpp] dynsym self-parse: <数百> syms (probe=ok)`，且不再 signal 11。
