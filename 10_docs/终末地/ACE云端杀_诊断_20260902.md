# 终末地星空包"卡进程"诊断 — ACE 云端杀实锤（2026-09-02）

## 现象

星空包（surgical-trace，1.4.3/43）安装后启动卡 Splash，~22 秒被杀，无限重启循环。
死法混合：SIGBUS(7) / SIGSEGV(11) / SIGKILL(9，含外部 force-stop)，无 crash_dump、无 dropbox 记录。

## 排除法阶梯（最小差分 + OTA + 断网）

| 变体 | 内容 | 结果 |
|------|------|------|
| T1 | 原包仅换 starry 签名 | ✅ 存活（62s+） |
| T2 | Manifest→StarryApp 无 classes7 | ❌ 秒死（ClassNotFoundException，测试设计缺陷，非检测） |
| T3 | +classes7.dex（不动 Manifest，不加载） | ✅ 存活 |
| T4 | +libstarry_magic.so + libc++_shared.so（解压在场，未加载） | ✅ 存活（37s，未测延迟窗） |
| T6 | Manifest+classes7+certs，无 so | ✅ 存活（120s+） |
| T7 | T6 + stub so（lib/ 解压在场，未加载） | ⚠️ 首启 120s 稳定，**~7 分钟后进入 22s 死亡循环** |
| 完整包 | T6 + 真 so（attach 时 dlopen） | ❌ 22s 循环 |
| OTA so 文件（data 目录在场，未加载成功） | ❌ 循环；移走文件即恢复稳定 |
| **T7 断网（飞行模式）** | **✅ 稳定 300s+** |
| 原版直装（联网，SukiSU/adb 在线） | ✅ 稳定 120s+ |

## 结论

**杀手 = ACE/TSS 云端 verdict，本地检测全部绿灯。**

- 本地不杀：换签名、新增 dex、新增 so（在场）、Manifest/StarryApp/SignSpoof、
  lib/ 目录陌生解压 so、data 目录陌生 so（断网时全绿灯）
- 云端杀：首启 60-120s"稳定"是上报+判定延迟窗；verdict 下发后周期击杀（~22s 循环）
- SignSpoof 在 Android 16 需要 `settings put global hidden_api_policy 1` 才能装上
  （VMRuntime.setHiddenApiExemptions 被拒），但装不装都会被云端杀，非死因
- 设备残留（/data/local/tmp 的 fs-arm64 等）未触发杀（原版联网带着这些也活），
  但按规范仍应清理
- ColorOS tombstone 全 0 字节，crash 取证靠 logcat 缓冲 + dropbox

## 两个工程教训

1. **logcat 主缓冲 ~60s 轮转**：事后 grep 全是空。必须后台常驻抓取
   （`logcat -b main -b system -b crash -b events`），存活判断要连续监测而非单点。
2. **zsh 只读变量 `UID`** 赋值直接报错，脚本里用 APPUID 之类命名。

## 后续选项（星光落地终末地）

# 最终结论修正（2026-09-03 凌晨，用户现场观察纠正后重查）

> 用户指出：① 真实现象是"卡黑屏+icon 的 Splash"，不是单纯被杀；② T1~T4 之前都能正常进游戏（亲眼确认）。
> 据此推翻上文"云端杀"主结论，重新取证。

## 真正根因（实锤）

**ACE 壳校验 Manifest 的 Application 类名，非预期值即毒丸挂起/击杀。**

- kill -3 抓到主线程卡死在 `AceApplication.initialize` → libtprt.so 内 `sem_timedwait` 永不返回
- T8 跳过 SignSpoof 仍卡同处 → SignSpoof 排除（fakes 表本无 endfield，纯引雷，之后默认关闭）
- **T5（+certs）正常进标题画面；T9a（保留原版 U8Application，仅加 MenuService+权限+惰性 classes7+certs）正常进协议页**
- 完整星空包（Application 替换为 StarryApp）必死/必卡，与 so 是否加载无关（T7 空壳也进循环）

## 修复方案（已落地）

不替换 Application，改用 **ContentProvider 注入**：新增 `StarryInitProvider`，
surgical 脚本 manifest 段只加 provider 条目（T9a 已证明组件条目不触发 ACE 校验）。
provider 版星空包 2026-09-02 23:17:03 安装（1.4.3/43）。
