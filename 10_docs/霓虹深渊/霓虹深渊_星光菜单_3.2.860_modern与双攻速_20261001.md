## 4. 静态分析：两项攻速的挂钩点

分析链：真机拉 `base.apk` → 提取 `libil2cpp.so`（md5 `61c2eecb0b60c1c2645fdd87d299d117`）＋ `global-metadata.dat`（md5 `fb51f49fb3e59d05c564ab6fdb18c1fc`）→ Il2CppDumper（**必须在 `01_tools/Il2CppDumper/` 内跑，否则缺 `config.json` 报 `FileNotFoundException`**）→ `06_dumped/霓虹深渊/il2cpp_3.2.860/dump.cs`（62,906,268 B / 1,631,872 行；Metadata Version 27 → il2cpp 27.1，CodeRegistration `9e53318`、MetadataRegistration `9e54218`）。

> dump.cs 的 `// RVA: / Offset: / VA:` 三值相同（imageBase=0）⇒ 直接当文件内偏移用。

### 4.1 远程攻速：`Gun.<shootingInterval>d__96`

- 方法：`NEON.Game.Gun+<shootingInterval>d__96::MoveNext` @ **0x292AB08**（`01_tools/DumpRva` 在 so 内精确命中该 RVA，非估算）。
- 反汇编要点（capstone 标注）：
  ```
  ldr  x8,[x19,#0x20]        ; <>4__this = Gun
  ldp  x0,x1,[x8,#0x1a8]     ; Gun.RPM（PlayerStateFloat）
  bl   0x30D99A4             ; PlayerStateFloat::op_Implicit → float
  ldr  s0,[0x7823AFC]        ; 常量 60.0f（文件字节 00007042 已验证）
  fdiv s0,s0,s8              ; 60 / RPM
  bl   0x5249C6C             ; UnityEngine.WaitForSeconds::.ctor(float)
  str  x20,[x19,#0x18]       ; <>2__current
  ```
- ⇒ 该协程**唯一** yield 就是 `WaitForSeconds(60/RPM)`。改这一个对象的时长即等效「RPM × 倍率」，且该对象仅该协程持有 ⇒ 写它零副作用。
- `UnityEngine.WaitForSeconds`（TypeDefIndex 4138）唯一字段 `internal float m_Seconds; // 0x10`。
- 负证据：`Gun::UpdateAttr` @0x3962904 只算 ShakeAmplitude，**不写** RPM ⇒ hook 它改不了攻速；`GunAttackRoutine` 的 MoveNext 里没有 `shootingInterval` / `WaitForSeconds` 引用。

### 4.2 近战攻速：`Gun.<MeleeCheck>d__85`

- 方法：`NEON.Game.Gun+<MeleeCheck>d__85::MoveNext` @ **0x2929E78**（精确命中）。
- 字段：`<>1__state 0x10 / <>2__current 0x18 / <>4__this 0x20 / <timer>5__2 0x28`（**timer 只在本状态机里，不在 Gun 上**）。
- 反汇编要点：
  ```
  0x292A0xx  ldrb w8,[x20,#0xc0]     ; GunBase.InstigatorIsPlayer → 只对玩家武器生效
             bl   0x3960208           ; Gun::JudgeCanKnifeAttack
             bl   0x3961F28           ; Gun::Melee
  ...命中后两条路汇合：
  0x292A174  ldr s0,[x20,#0x370]     ; Gun.BaseMeleeCD
             ldr s1,[x20,#0x374]     ; Gun.ExtraMeleeCD
             fadd  s0,s0,s1
  （KanonMelee 路）0x292A1F0 ldr s0,[x20,#0x30]   ; GunBase.kanonBaseMeleeCd
             ldr s1,[x20,#0x374]
             fadd
  0x292A1FC  fcmp s0,#0.0 ; str s0,[x19,#0x28]     ; → <timer>5__2 = 冷却
  0x292A04C/0x292A068  ldr s0,[x19,#0x28] ; Time::get_deltaTime ; fsub ; str  ; 逐帧 yield null
             ; 归零后 mov w0,wzr 结束协程
  ```
- ⇒ **冷却值最终只落在协程局部量 `<timer>5__2`**；倍率取 `/mul` 即缩短挥砍间隔。

### 4.3 为什么不去写 Gun 的字段

`Gun+0x370 BaseMeleeCD` / `+0x374 ExtraMeleeCD` 会被同流程里的 `ResetExMeleeMult` 重置（同一 MoveNext 内写回），改字段要么被冲掉、要么被反复连乘；写协程局部量**零残留、可随时关**，且天然只影响「下一次赋值之后的计时」。同理远程不碰 `Gun.RPM`（那是 PlayerStateFloat 结构体，被技能/遗物/UI 多处读写）。

### 4.4 过滤与门控

- 两处 hook 均先读 `<>4__this`（Gun）→ 校验 `GunBase.InstigatorIsPlayer`（`Gun+0xC0`）为 true 才改，避免波及怪物/召唤物子弹与近战。
- 未做武器类型门控：`WeaponTypeEnum`（None/NormalGun/Glove/Baseball/FingerGlove/Sword/Bow，dump.cs:1513833）只在 Lua/表现层用；近战与远程在 native 层各走各的协程路径（`Melee` 只由 `MeleeCheck` 驱动），互不干扰。

### 7.1 换签修复「卡密已绑定其他设备」（2026-10-01 21:18–21:22）

**现象**：首版（debug 证书）装机后用户输卡密，6 次 `AuthClient: ← 403 (51 bytes)`。

**根因**：菜单 v5 指纹只用 SSAID（`DeviceFingerprint.VERSION="v5"`，`raw="ver=v5|ssaid=…"`），而 Android 8+ 的 **SSAID 按签名证书隔离** ⇒ 同一台机上不同证书的包算出不同 `dev_*`；服务端 `card_keys.device_id` 是**按整张卡**绑一个设备（与 game_id 无关，见 `auth-server/docs/GRANT_AUTH.md` §3.1.1），对不上即 403。实测：

| 包 | 签名哈希 | v5 指纹 | 结果 |
|---|---|---|---|
| 霓虹（首版 debug 签） | `[520f898a]` | `dev_89fd2216081394bf9639e0064f4c8ea5` | 403 ×6 |
| 失落城堡（release 签） | `[6f4dda0b]` | `dev_b2206b052abedaaa2fa35d43e732666b` | `grant ok`（绑定已迁移到该 id） |

**修法**：把霓虹包换成同一把工作区 release 证书（`01_tools/starry_release.jks`），内容不变、只重签 ⇒ SSAID 与其它星光包相同 ⇒ 命中卡绑定。脚本已改造为默认用该证书，并新增「换签模式」（不需要官方底包）：

### 10.2 远程攻速改挂「枪械蓝图协程」

- 新挂钩点：`GunGraph.<AttackRoutineWithEvents>d__46::MoveNext` @ `0x292B190`（TypeDefIndex 23925；`get_Current` 0x292B6F4）。
- 字段：`<>1__state 0x10` / `<>2__current 0x18` / `<>4__this 0x20` / `Instigator 0x28` / `transform 0x30` / `GGEvents 0x38` / `NEONPlayerState <neonPlayerState>5__2 0x50` / `float <timer>5__3 0x58` / `int <meleeTime>5__4 0x5C`。
- timer 写入点在整支函数里**只有一处** `0x292B35C`，来源二选一：`0x292B284`（`fsub` deltaTime，逐帧递减）或 `0x292B354`（`bl GunOutput::get_FireDelay`）。
- `GunOutput::get_FireDelay` `0x3A8F3F4`：`ldr x0,[x19,#0x68]`（`[output+0x68]`）、`ldr s0,[x19,#0x44]`、`bl 0x38BDC34`、`ldr s1,[0x7823AFC]`（常量 `60.0f`）、`fdiv s0,s1,s0` ⇒ **间隔 = 60/RPM**。
- 做法：hook `MoveNext` → 取 `<>4__this` 的 `<timer>`，判「突然变大＝官方刚赋值」（`t > prev+1e-4 && 0 < t < 60`）后 `t /= mul`；玩家门控 `[sm+0x50] != nullptr`。旧 `d__96` 钩保留为后备（日志 `远程攻速(协程)`）。

### 10.3 近战攻速改走同一支枪图协程（用户要求「借鉴远程的改法」）

- d__46 反汇编显示官方自己的分流条件：
  - `0x292B39C ldrb w8,[x21,#0x90]`（`GunGraph.firing`）→ `cbz` 结束；
  - `0x292B3A4 ldr x8,[x19,#0x38]`（`GGEvents.meleeEvent`，`GunGraphEvents` 结构第 0 个字段）→ `cbz` → **开枪路**（`GunOutput::NeedCharge` 0x3A933F8 → 蓄力 yield，或 `MuzzleFlash::Fire` 0x462BBE0 + `GunOutput::Attack` 0x3A93520）；非空 → **近战路**（`meleeTime([+0x5C]) = Time::get_frameCount()+1` → `bl 0x292B4E0` = `GunGraph.meleeDelegate::Invoke()`）。
  - 两支共用同一个 `<timer>5__3`（初值都来自 `FireDelay`）⇒ 按 meleeEvent 选倍率即可，机制与已验证的远程完全一致。
- 做法：同一个 `0x292B190` hook 内 `isMelee = ([sm+0x38] != nullptr)`，近战用 `g_meleeLvl`、远程用 `g_rangedLvl`；日志 `[Neon] 近战攻速(枪图) x%.2f 挥砍间隔 %.3f->%.3f` / `[Neon] 远程攻速(枪图) …`，另加诊断 `[Neon] 枪图近战分支命中(未加速) meleeLvl=%d rangedLvl=%d`（用于确认近战武器是否真走枪图）。
- 旧点 `Gun.<MeleeCheck>d__85`（`0x2929E78`，写 `<timer>5__2`）保留为后备：`Gun::MeleeCheck()` `0x3960168` 在 so 内 **0 个 BL 调用者**，与 `shootingInterval` 同病，疑似不参与实战。

### 10.4 技能无CD：从「挂基类」升级为「35 门全挂」

- 根因：`CanUseSkill` 在 dump 里共 **35 个实现**（全部派生自 `SecSkillPowerUp`）。角色主动技各自 override（如 `Neon_Active_001` 读 `+0x2B0` `_consumableCount < 1` 直接 `return false`）会**绕过基类钩** ⇒ 现象＝只有 CD 动画消失、按技能仍提示「技能还没有准备好」。
- 做法：`kSkillGates[35]{rva,name}`（含基类 `SecSkillPowerUp` 0x2FB6498 与 10 个角色主动技）+ `template<int N> Hooked_SkillGate` 折叠展开逐个 `DobbyHook`；开无CD 时把 `thiz+0x25C`（`CoolingTime`）/`thiz+0x260`（`LastCoolingTime`）写 0 并 `return true`；关时转发 `g_origSkillGate[N]`。
- 新增探针：`SecSkillBegin` `0x2FB6654`（`void(void*, bool isSecSkill, void*)`，日志 `[Neon] probe SkillBegin thiz=%p isSec=%d noCd=%d`）、`SecSkillEnd` `0x2FB70A4`。
- 实测：`[Neon] skill gates hooked 35/35` ⇒ 用户确认技能可用。

### 10.5 新增三项对局内资源（用户 m01057）
