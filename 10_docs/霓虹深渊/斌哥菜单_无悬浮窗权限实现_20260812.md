# 斌哥（binge）菜单：为何不给悬浮窗也能出来

抓包样本：`02_apks/追迹迷城/` 等 binge 改包；菜单类 `com.android.support.Menu`（dex 内）。

## 结论

Manifest 仍会声明 `SYSTEM_ALERT_WINDOW`，但**真正出菜单不依赖用户点授权**。双路径：

1. **`SetWindowManagerActivity()`（默认常用）**  
   - `Activity.getWindowManager()`  
   - `LayoutParams.type = 2` → `TYPE_APPLICATION`  
   - 挂在**当前游戏 Activity 的窗口层**，跟 Activity 生命周期走  
   - **不需要** `Settings.canDrawOverlays` / 用户授权

2. **`SetWindowManagerWindowService()`**  
   - 走系统 overlay 类型，内部会把 `overlayRequired=true`  
   - 才真正要「显示在其他应用上层」

所以你下载游玩从没弹过悬浮窗权限，是走了路径 1，不是系统偷偷给了权限。

## 和星光旧实现的差别

| | 斌哥 | 星光（改前） | 星光（本轮） |
|--|------|-------------|-------------|
| 主路径 | Activity + `TYPE_APPLICATION` | 仅 `TYPE_APPLICATION_OVERLAY` | 有权限 → Overlay；无权限 → Activity 窗 |
| 用户授权 | 通常不需要 | 会跳设置页 / 依赖 root `appops` | 无授权也能出菜单 |

## 代价

Activity 窗：绑在当前 Activity 上，切 Splash→Game 等必须 rebind；Unity/SurfaceView 穿透与 LayoutParams 易踩坑（星光 HTML 菜单试过，已撤回，仍用需授权的 OVERLAY）。等原生菜单再议。
