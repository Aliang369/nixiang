## 2. 攻速（feat 5）

四个缩放点，全部写协程局部量或函数入参，不写武器字段（关掉零残留）：

| 点 | RVA | 做法 |
|---|---|---|
| 枪械节奏 | `GunGraph.<AttackRoutineWithEvents>d__46::MoveNext 0x292B190` | 缩 `<timer>5__3 +0x58` |
| 枪械节奏 | `GunGraph.<AttackRoutine>d__45::MoveNext 0x292AE4C` | 缩刚 yield 出的 `WaitForSeconds.m_Seconds` |
| 开火间隔 | `GunOutput.get_FireDelay 0x3A8F3F4`（= `60.0f/RPM`） | 栈回溯命中 `[0x2929E78,0x292C100)` 才缩返回值 |
| 近战真身 | `DeputyWeaponSlot_MeleeMultiSeg.set_BusyTime 0x3DA9D70` / `set_AsBusyTime 0x3DABB30` | `_busyTime(0x98)` 是剩余忙碌倒计时（满 0.75 s，`OnUpdate 0x3DAB76C` 每帧写回）；**只把上升跳变 ÷ 倍率**，逐帧递减原样透传 |

玩家门控：`GunGraphBase.netPlayer(+0x28)` 非空且 `GunGraph.isActorShadow(+0x68)` 为假。

已知边界：倍率只缩间隔/冷却，不缩挥砍与上膛动画；`get_FireDelay` 与 `<timer>` 在同一发上会叠加（档位 n 手感约 `LvlMul(n)²`），高档位受帧率上限约束。

## 3. 无限跳跃（feat 9）

真凶是「上限」不是「计数」：`PlayerActor.UpdateJump 0x2652DC0` 与 `MultipleJump 0x264FC8C` 都调 `PlayerStateInt.op_Implicit 0x30DABD0` 取 `multipleJumpCountLimit`，无二段跳道具时 limit=0 ⇒ 每次被 `cmp w0,#1; b.lt` 挡住。

- `op_Implicit 0x30DABD0`：栈落在 `0x2652F60–0x2652F90` / `0x264FD90–0x264FDAC` 时返回 999，其它 PlayerStateInt 转换原样透传
- `PlayerActorBase.get_canNotJump 0x3345630` → false
- `BaseMechaControl.CanMultipleJump 0x3CB2AA4` → true
- `get_multipleJumpCount 0x26472BC` → -1000

## 4. 丝血无敌（feat 11）

三处把 `DamageInfo+0x10` 截断到「最多扣剩 1 点」（`tot = 心 + 甲`，`tot == 1` 时写 0 全免伤）：

- `Hearts.DeductHeartFirst 0x3547218`
- `Hearts.DeductArmorFirst 0x35475EC`
- `Hearts.DeductHeart_ApplyApportion 0x3547824`

兜底：`Hearts.ForceDie 0x3547AFC` 在开启时直接不执行，并把心钉回 1。

注意：`Hearts.DeductHP 0x3545ED0` 的第三参在 `0x354609C` 就被 hearts 覆盖，真正扣血用 `w22 = (int)(DamageInfo+0x10)`（`0x3546298`）——不能用第三参判。

## 5. 全屏攻击（feat 12）

**原理**：在 `HitPoints.DoDeductHP` 抓到「玩家打中某只怪」的那一次，复制一份 `DamageInfo`，对同房间其余怪物逐个直调原始 `DeductHP`。

### 5.1 触发点

```
Killable.TakeDamage 0x39F9C48
  → DoDamage 0x39FA608
  → ProcessDamage 0x39F7B14（vtable slot 16）
    → HitPoints.DeductHP 0x346D8C4
        ├─ FixDeductHpValue 0x346B738   ← 伤害在这里算出来
        │     0x346B9C8  str s8, [di, #0x18]   （finalDamage 诞生）
        └─ DoDeductHP 0x346DE04         ← 挂这里
              → SubtractCurrentHp 0x3471030
```

`DeductHP` **入口**读 `+0x18` 恒为 0（还没算）。`DoDeductHP` 是 `FixDeductHpValue` 之后第一站，`+0x18` 已是真实扣血量，且每次伤害只过一趟。

### 5.2 DamageInfo 关键偏移（sizeof 0xD0）

| 偏移 | 字段 | 说明 |
|---|---|---|
| 0x04 | damageOpId | 镜像去重键（80 ms） |
| 0x10 | damage | 有效值，`FixDeductHpValue` 从这里起算 |
| 0x18 | finalDamage | 由 Fix 写入；入口读恒 0 |
| 0x1C | baseDamage | 扣血链里不被读取 |
| 0x30 | damageType | **不能**区分玩家/怪物 |
| 0x64 | SourceType | 同上 |
| 0x70 | _instigater | 玩家判定主依据 |
| 0x78 | instigaterIsPlayer | **死字段**：全 so `STRB [.,#0x78]` 命中 0 次 |
| 0x90 | RealInstigator | 对枪/子弹 == instigator |
| 0x98 | targetFilter | 受击侧过滤，与施放者无关 |

### 5.3 玩家伤害判定

照抄游戏自己的 `ToolCommon.IsMatchInstigaterType 0x2C69F58`（全 so 仅 `HurtGenerateMonsterUse.OnHurt 0x3C8CC1C` 一处调用），其 Player 分支（`0x2C6A054`–`0x2C6A084`）是 il2cpp 的 `is`：

```asm
ldr   x9, [x19]            ; instigator->klass
ldrb  w11, [x9, #0x12c]    ; klass->typeHierarchyDepth
ldrb  w10, [x8, #0x12c]    ; 目标类深度
cmp   w11, w10 / b.hs      ; 深度不足 → false
ldr   x9, [x9, #0xc8]      ; klass->typeHierarchy
ldur  x9, [x9, #-8]        ; typeHierarchy[depth-1]
cmp   x9, x8               ; == PlayerActor klass
```

实现：`OFF_KLASS_DEPTH = 0x12C`、`OFF_KLASS_TYPEH = 0xC8`，沿继承链比类名 `PlayerActor` / `NetPlayerActor`。类型槽（so 内 .got）：PlayerActor `0x9E99068`、NetPlayerActor `0x9EBC1F8`。

**不可用的判据**：`+0x78 instigaterIsPlayer`（死字段）、`+0x98 targetFilter & 2`（受击侧过滤，怪物互伤同样含 Monster 位）、`damageType & 0x20000001`（`Gun`/`Dot`/`IgnoreDefs` 位在全 so 无任何 `MOVZ` 置位，值只来自配置表）。

### 5.4 房间获取（四级兜底）

| 级 | 来源 | 依据 |
|---|---|---|
| ① | `g_curRoom`（钩子捕获） | `MapManager.LateUpdate 0x2CBE5D0` 每帧读 `[this+0x20]`；另挂 `MapManager.RefreshRoom 0x2CBE7CC`、`YiHai.OnEnterRoom 0x26BC52C`、`OnEnterBattle 0x26BD324`、`RoomMB.MonsterListCleanup 0x32F2A34`、`get_ActiveMonsterCount 0x32F2E90` |
| ② | `[mon+0x48]` | `EhiEntity._currentRoomMb`；`EhiEntity.getCurrentRoomMb 0x3E77580` 内部即 `ldr [this+0x48]` |
| ③ | 调 `EhiEntity.getCurrentRoomMb 0x3E77580` | 内部 `GetComponentsInParent` 找 RoomMB 并回写 `+0x48` 缓存 |
| ④ | 调 `NPActor.get_actorCurRoomMB 0x3369A64` | 它是 `GetComponentInParent<RoomMB>()`，本游戏常返回 0，仅兜底 |

### 5.5 怪物列表布局

反汇编 `RoomMB.MonsterListCleanup 0x32F2A34`：

```asm
ldr x21, [x19, #0x78]      ; mons = RoomMB+0x78
ldr w8,  [x21, #0x18]      ; List._size
ldr x8,  [x21, #0x10]      ; List._items
add x8,  x8, x20, lsl #3
ldr x21, [x8, #0x20]       ; T[] 元素从 +0x20 起
```

| 偏移 | 含义 |
|---|---|
| `RoomMB+0x78` | `List<MonsterActor> mons`（常规刷怪） |
| `RoomMB+0x80` | `List<MonsterActor> _buffSpawnMons`（buff 召唤，一起打） |
| `RoomMB+0x109` | `roomIsEnteren`，只是「进房间过场是否播完」，**不能**当在房判据 |
| `List+0x10` / `+0x18` | `_items` / `_size` |
| `T[]+0x18` / `+0x20` | 数组 `max_length` / 元素 0 |

### 5.6 执行与防护

```
① 快照 0x78 / 0x80 的元素指针到本地数组（最多 48，去重，跳过被打的那只）
② 逐个：跳过 CurrentHp<=0 → memcpy 0xD0 字节 DamageInfo 副本 → 直调原始 DeductHP
```

- 必须用副本：原 DamageInfo 按引用传递，改它会污染游戏自己的结算
- 必须快照：每打一只都可能让它死亡并被移出列表，边遍历边用原表会崩
- 递归闸：`thread_local t_mirrorDepth` + RAII
- 去重：同一 `damageOpId(+0x04)` 80 ms 内只镜像一次
- 单次上限 32 目标

### 5.7 托管指针判断

**只判非空。** 所有指针都来自游戏自己维护的数据结构（`HitPoints._monsterActor`、`DamageInfo.instigator`、`RoomMB.mons` 元素），本就必然有效。不要写「klass 必须落在 libil2cpp 映射内」这类校验：so 是分段 mmap（79 段跨 6 GB），`[min,max)` 永远覆盖不全，会把合法对象全判成野指针。
