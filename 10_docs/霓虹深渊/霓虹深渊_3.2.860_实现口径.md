## 2. 无限跳跃（feat 8）

真凶是「上限」不是「计数」：`PlayerActor.UpdateJump 0x2652DC0` 与 `MultipleJump 0x264FC8C` 都调 `PlayerStateInt.op_Implicit 0x30DABD0` 取 `multipleJumpCountLimit`，无二段跳道具时 limit=0 ⇒ 每次被 `cmp w0,#1; b.lt` 挡住。

- `op_Implicit 0x30DABD0`：栈落在 `0x2652F60–0x2652F90` / `0x264FD90–0x264FDAC` 时返回 999，其它 PlayerStateInt 转换原样透传
- `PlayerActorBase.get_canNotJump 0x3345630` → false
- `BaseMechaControl.CanMultipleJump 0x3CB2AA4` → true
- `get_multipleJumpCount 0x26472BC` → -1000

## 2b. RVA 基准（栈判据的生命线，2026-11-26 真机根因）

`NeonStackHit` 用 `rva = pc - g_libBase` 与硬编码 RVA 比较，所以 `g_libBase` **必须**等于钩子解析用的那个基址（= `Abs(RVA_GRAPH_ATTACK_MN) - RVA_GRAPH_ATTACK_MN`，即第一段 LOAD `off == vaddr == 0` 的起始）。

- `/proc/self/maps` 的最小 start 可能是一个**前置保护段**（实测 lo = `0x6ddac2c000`，钩子基准 `0x6f24af4000`，差 `0x46DCB000` ≈ 74 MB）。以它为 base 会让所有 RVA 判据整体偏移、恒不命中：无限跳跃开关为 ON、`round6b jumpChain=1/1/1` 全挂，游戏里却毫无反应（`PlayerStateInt.op_Implicit` 的跳跃上限判据静默失效）。
- 实现规则：base 只由锚点（`Abs(RVA_GRAPH_ATTACK_MN) - RVA`）决定；`NeonRefreshLibRangeFromMaps` 仅扩 `g_libEnd`（max end），锚点缺失时才退回 maps lo。
- 判据日志（必须两行 base 相同）：

```
[Neon] libil2cpp base=0x6f22794000
[Neon] libRange base=0x6f22794000 end=0x6f2cbc1000 size=0xa42d000
[Neon] 无限跳跃：次数上限 -> 999      ← 命中跳跃门槛栈位
```
