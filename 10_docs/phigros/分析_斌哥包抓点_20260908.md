## 2. 斌哥机制全链（实锤，实测差分+反汇编）

```
菜单 WebView Changes("0", true)
  → prefs boolean "0"=true
  → 壳写旗标：壳数据段+0x280 = 1（byte，OFF=0/ON=1，双进程 dump 实测差分验证）
游戏函数入口（libil2cpp RVA 0x1AF0A7C）被壳 patch（启动时无条件，12 字节 3 指令）：
  原: SUB SP,#0x30; STP X30,X21,[SP,#0x10]; STP X20,X19,[SP,#0x20]
  改: ADRP X17,(壳代码段trampoline页); ADD X17,X17,#0x900; BR X17
trampoline（壳匿名 r-x 段 +0x34900，两进程偏移一致）：
  x8 = [壳段+0x97A00]        // 指向旗标（壳数据段+0x280）
  if (*(u8*)x8 & 1)          // 分数增强 ON
     call [壳段+0x97BE0]     // → 增强函数（libil2cpp RVA 0x1AEC318，原生未patch）
  call [壳段+0x97AC8]        // → 原函数副本（壳拷贝到 anon 0x780c5fd000 区）
```

- Hook 点唯一：`文件 so vs 内存 dump` 全 36MB text 段仅此 1 处 diff（0x1AECA7C 文件偏移 / 0x1AF0A7C RVA / dump 内 0x393A7C）。
- ON vs OFF 的 il2cpp text 仅差 4 字节（ADRP 立即数，进程重启基址修正）→ 开关不增删 patch，纯旗标门控。
- 增强函数 0x1AEC318：`[this+0x4C]++`、`[this+0x58]++`（计数器×2），w1 参数 bit0 分支，后续调浮点/字符串链。
- **用户实测效果**：分数直接 10 万分整 + 连击数自动叠高。

## 3. 关键 RVA（3.20.0 vc154）

| RVA (vaddr) | 文件偏移 | 含义 |
|----|----|----|
| `0x1AF0A7C` | `0x1AECA7C` | 计分/判定更新函数（hook 目标；无 BL 调用者→方法指针表调用） |
| `0x1AEC318` | `0x1AE8318` | 增强函数（原生；4 个 BL 调用者：0x1AEC030/0x1AECD54/0x1AED2C4/0x1AEE208） |
| `0x1AEB000-0x1AEE000` | — | 判定集中区（fcmp 判定窗口比较 + 计数 + 计分） |

ELF：vaddr→file = vaddr−0x4000（LOAD2 off=0x17597bc vaddr=0x175d7bc）。

## 4. 方法名混淆（限制）

- global-metadata 方法名被官方混淆为不可见 Unicode；Il2CppDumper 能出 dump.cs 但 ScriptMethod 地址体系损坏（随机 300 样例仅 8% 函数序言，地址 min 0x2853a48 超出代码段逻辑范围）→ 方法名回查不可用。
- 游戏类名/方法名不可读；逆向锚定「字节特征 + 运行时证据」（同音舞光年 §5 方法论）。

## 5. 自动跳攻坚记录（v1→v3，真判定未完成）

用户确认要**全自动**（全程不碰屏幕 AP）。参考 `10_docs/音舞光年/音舞光年_0.300.42_星光菜单_模拟真人_20260822.md`。最终 v3 定稿为「满分」（=斌哥增强链复刻），真判定（带演出动画的自动跳）未完成，过程记录如下供后续重启：

### 5.1 v1 探测包实测（实锤）

- hook `0x1AF0A7C` + ON 时调 `0x1AEC318` → **效果成立**（分数 10 万级 + 连击叠高），与斌哥版一致
- Trace 关键数据：`0x1AF0A7C` **每帧驱动**（60fps，hits=7350/首），`a0` 单例（ScoreManager），`+0x58` 恒速 +100/1.67s（=增强每帧+1）
- **v1 分数上涨的根源 = enhanceFn 调用本身**（它是完整 Perfect 事件处理：计数+对象操作+浮点链，驱动准度积分 `+0x40` 累积）

### 5.2 字段语义（实锤）

| 偏移 | 含义 | 写点 |
|---|---|---|
| `+0x40` | 准度积分（int，原函数每帧累积，分数=f(积分)） | 原函数内部 |
| `+0x4C` | 判定总数（Perfect 链 ++） | `0x1AEC394`（enhanceFn 内）等 |
| `+0x58` | combo | `0x1AEE520` 系列 + `0x1AEC394` |
| `+0x5C` | miss 数 | `0x1AEC550`（0x1AEC4D0 内） |
| `+0x68`/`+0x6C` | miss 分型（early-release / timeout） | `0x1AEC564/0x1AEC578` |

### 5.3 走过的弯路（下次勿重复）

1. **v2 纯字段合并**（miss 并入 Perfect、combo=总数，不调 enhanceFn）→ **分数不动**（积分引擎熄火，`+0x40=0`）。字段只是显示层，积分靠 enhanceFn 事件流驱动。
2. **盲找判定函数 4 轮无果**：`0x1AEC318`（Perfect 计数）自然调用仅 28-70 次/首（特殊事件，非每 note）；`0x1AEC4D0`（miss 分型）1 次；`0x1AE6C48` 是管理器每帧 Update（指针恒定）非 per-note；`0x1AEE3C0` 遍历函数两次打歌均未触发。**真 note 判定点疑似被编译器内联或走输入事件驱动，方法名全混淆无法静态定位**。
3. `0.08f`（判定窗口常量 @0xb61050）交叉引用无 adrp+ldr 对 → 判定比较可能用寄存器加载。
4. `Il2CppDumper` 地址体系损坏（metadata 混淆），ScriptMethod 不可用；Token/RVA 检索不可靠。

### 5.4 后续重启真·自动跳的候选路线

- **谱面驱动触摸注入**（最确定）：phigros 谱面在 Unity Addressables 加密 bundle（APK 内无）；hook 谱面加载（Catalog→Bundle 解析后）dump note (time,track) 表 → 定时注入 MotionEvent → 游戏自判 Perfect（演出完整）。工程量：谱面定位+时间同步+轨道坐标。
- **全函数调用采谱**：对局期间对判定区（0x1AEB000-0x1AF5000）做函数级调用计数（GDB/watchpoint 或分批 Dobby+LR 统计），找每 note 调用 N 次的函数。
