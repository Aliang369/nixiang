# Phigros 3.20.0 — TapTap 强制内嵌网页登录：修复与实机验证

> 日期：2026-09-21
> 上游：`复核_TapTap签名与网页登录_20260921.md` §3.4（游戏内账号登录 `signature not match` 判定）
> 状态：**已修复 + 已装机 + 实机验证通过**

## 1. 根因（实测）

游戏内「账号与统计 → TapTap 登录」走 TapSDK 客户端 SSO：

```
TDSLoginService.startTapLogin
  → com.taptap.sdk.TapLoginHelperActivity
  → com.taptap.sdk.ui.TapTapActivity
  → com.taptap/.common.account.ui.login.CheckOneKeyLoginActivity   （TapTap 客户端侧）
  → 回调 {"code":-1,"msg":"signature not match","error":"permission_result"}
```

改签包证书与 TapTap 后台登记不一致 → **TapTap 客户端拒绝**；游戏把 `code=-1` 显示成
「登录失败，请检查网络」（不是网络问题）。`LoginBlock.onActivityResult` 收到
`resultCode=-1` 直接 `finish()`，**不降级网页**，所以这条链路不修就永远失败。

## 2. 修复

复用 starry 菜单既有的 `TapLoginForceWeb` 旧版路径（本包 SDK 3.30.3 恰好命中）：

| # | 改动 | 位置 |
|---|------|------|
| 1 | 白名单加 `com.PigeonGames.Phigros` | `mod菜单/starry-mod-menu/app/src/main/java/com/starry/magic/sign/TapLoginForceWeb.java` |
| 2 | `onPreCreated` 增调 `forceOldImplWebEarly` | 同上（Java 源码同步） |
| 3 | 注入 `YnttLoginRequest(.$1).smali` | `mod菜单/starry-mod-menu/yntt_smali/com/starry/magic/sign/` |

原理：`TapTapActivity.onCreate` 之前把 intent extra `"request"` 用 Parcel 往返成
`YnttLoginRequest`（`getRequestCode()` 恒抛 `IllegalStateException`）→
`LoginClient.sendLoginRequest` 在 `ActivityHandler.authorize` 处抛异常 →
`catch` → 官方 `WebViewHandler.authorize()` → **包内内嵌网页登录**，不进 TapTap 客户端，
不触发签名校验。

### 2.1 一个必须记下的坑（VerifyError）

第一版钩子用了 `Class.asSubclass(Parcelable.class)` 做泛型造型，装机后校验器直接拒绝：

```
VerifyError: void TapLoginForceWeb.forceOldImplWebEarly(android.app.Activity) failed to verify:
  [0x54] Rejecting invocation, expected 2 argument registers, method signature has 1
```

`0x53` 就是 `invoke-virtual {v3, v4}, Ljava/lang/Class;->asSubclass(Ljava/lang/Class;)`——
泛型擦除签名跨 dex 解析时被校验器判成 1 参。**改法：去掉 `asSubclass`，直接
`Parcel.obtain()` + `Creator.createFromParcel` + `check-cast`**（见 `asYnttRequest`），
校验通过。
