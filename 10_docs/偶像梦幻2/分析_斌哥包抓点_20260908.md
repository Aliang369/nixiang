### Trampoline（壳解密代码段 [anon:.bss] r-x @0x732b6cc000，4 个入口 0xD54B0/0xD5508/0xD5560/0xD55B8）

```
stub（游戏函数入口）：ADRP X17, trampoline ; BR X17
trampoline：
  保存 X0
  X8 = [0x732B7C8000 + {0x3E8|0x410}]   ← 旗标指针表（sdk_rw 段 +0x1000 偏移起）
  W8 = *(u8*)X8                          ← 读旗标
  TBNZ W8,#0 → ON 分支
  OFF：MOVZ W8,#5?（待精确解码）→ 原逻辑
  ON：X8 = [0x732B7C8000+{0x448|0x450|0x458|0x460}] → 增强函数指针 → BLR X8（x0=this 透传）
```

### 旗标与功能对应（运行时验证，实锤）

## 5. 坑与教训

- **斌哥瘦壳变体 memdiff 姿势**：hook 启动时无条件安装（旗标只控行为）→ 三态 ON/OFF 内存 diff **零信息**（只剩 pid 等噪声）；正确姿势 = **内存 so vs 磁盘官包 so diff**（`diff_il2cpp_mem.py`）找 Dobby patch，再解 trampoline。旗标不走 prefs/MMKV，在壳数据段指针表解引用的相邻字节（位域，bit4 语义待精确）
- **并行会话构建污染**（用户观察：多游戏复现）：ndk-build 的 obj 落点由 NDK_PROJECT_PATH 推导（app/src/obj / app/src/main/obj / app/build/intermediates/ndk/obj 三种并存），并行会话各编各的游戏 → 清错位置 = 旧宏 Main.o 参与链接 → undefined symbol。**解法已落地 es2 脚本**：私有 mk（Android_es2.mk）+ NDK_OUT/NDK_LIBS_OUT 锁 obj_es2/libs_es2 专属目录 + 构建前 rm -rf
- **同文件并行 Edit 竞态**：Main.cpp/GameConfig.h 多处并行编辑互相覆盖（8 处丢失后补）——同文件多处修改必须串行
- MIUI 真机 shell 无 input 注入权限（INJECT_EVENTS 拒绝）；OPPO 允许但坐标系要按 ROTATION_90 换算；**用户偏好直接给操作指引不代点**
- 斌哥瘦壳变体：Application 不换名、无嵌套原包、壳逻辑全 native（dex 里搜不到 VBP）、菜单远程 URL 在运行时内存可搜（menu-1255602259/game/87.html）
- MuMu 上此斌哥包启动即崩（initUnitySdk dlsym 失败→NULL 调用），真机正常——不要在模拟器壳崩溃上深挖，先换真机验证
- 大包（>500M）adb install 超时 → push + pm install；memdump64 参数必须带 0x 前缀
- MuMu 上壳崩 ≠ 游戏问题：先真机验证再定路线，不深挖壳模拟器检测
