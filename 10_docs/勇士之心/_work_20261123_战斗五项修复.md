## 2. JS 自举覆盖问题的准确结论（原任务第 3 条）

问：boot self-heal 写的 `main.js` 是否覆盖 battleLogic？

答：**自举不是「只覆盖 main/game」，但它在 1.0.6 事实上覆盖不到 battleLogic**，机理如下：

1. `YsxzBootSelfHealOnce()` 只重写 `files/res/main.js`（一个文件），补丁是**驱动**，不是 bundle 本体。
2. 驱动靠 `window.__require(id)` 挨个取 exports 来反推源码，id 清单写死在 `ysxz_1.0.3_menu/boot_ids.json`（**res 1.1.4.0**）。
3. battleLogic 的模块 id 在 1.1.22.0 是 `$JZ,$KA..$OD`（57 个），与 1.1.4.0 有交集；但**只有该 bundle 被游戏加载后才进 `__require` 注册表**，且驱动那轮只解析到 9/36、`logic=0`。
4. 所以「battleLogic 永远注入不到」在**只走自举**的前提下成立（这就是修复前五项全灭的直接原因）；而**原生 splice 路线本来就会按内容判据覆盖 battleLogic**（`byBody = window.__require + atkEntity + maxApDefRate`），只要 hook 装上就轮到它。
5. 自举驱动里还写死了 1.1.4.0 的兜底名（`hx=hy / isPlayer=bmN / hp=bhd / world=hj / ctx=bnR,fF,ddQ / camp=hE.blx`），1.1.22.0 实为 `hz/bot/biG/hk/bpx,fF,djb/hF.bnd` ⇒ **即便自举跑起来，这组兜底也早已作废**（已登记为待改，见锚点表 §2 末行）。

⇒ 结论：**1.0.6 上不要再把自举当主路线**；主路线必须是原生 splice（现已修好）。自举只作「hook 装不上」时的降级，且需要同步 `boot_ids.json` 与 FIXED 兜底名。
