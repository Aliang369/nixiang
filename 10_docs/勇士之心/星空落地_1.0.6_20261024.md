## 4. 事故与修复：卡在「正在为您加载游戏资源」（本轮最贵一课）

**现象**：真机第二次进游戏，永远停在加载页。

**根因**：`gen_ysxz_boot_js.py --patch-js` 被传了 **`YsxzPatchJs.h`（C++ 头文件）**，该参数只接受纯 JS ⇒ 整段 `#pragma once` + `static const char* kYsxzPatchJs = R"YSXZJS(` 被追加进 `main.js` 尾部。

**证据链**：
- `jswrapper: ERROR: Uncaught SyntaxError: Unexpected identifier, location: main.js:0:0` ＋ `ScriptEngine::evalString script main.js, failed!`；
- 拉回设备 `files/res/main.js`（35,613 B, md5 `cbc6ca67…`）解密后 `node --check` 报 `Private field '#pragma' must be declared in an enclosing class`，拼接点可见头文件原文。

**修法**：
1. boot JS 改由 `ysxz_anticheat/patch_v2_ac.js`（纯 JS）生成，`node --check` 通过；
2. 重生成 `YsxzBootBlob.h`：patched `main.js` 35,365 B（md5 `dd6cd4d8…`），解密明文 86,771 B 再 `node --check` 通过；
3. **两处事故闸门**：`gen_ysxz_boot_js.py` 收到头文件自动抽 `R"YSXZJS(...)"`、抽不到即失败；`ysxz_mainjs_patch.py` 见到 `#pragma once` / `R"YSXZJS(` / `kYsxzPatchJs` 直接拒收；
4. 清设备上坏 `main.js` 让自愈线程重写（`boot self-heal: pristine -> patched (35365 B)`）。

**修复后实测**：`main.js` 35,365 B、无 SyntaxError；`[AC] ac layer v1 loaded`、`[AUTO] auto layer v1 loaded`、`[MODMOD] require trap installed`、`Cocos Creator v2.4.15` 正常起；`[AUTO] gold: 放行 gold 卡判定` 连续命中，`goldKey=monCard.fDq.fDf`、`goldHow=struct+behaviour`。

## 9. 2026-10-24 第二版：战斗加速改「真·全局变速」＋挪回基础功能

**用户反馈原话**：「1.战斗加速没效果，不是全局加速。我的意思就是类似那种变速器的对全局都加速 2.战斗加速的分类也错了，应该在基础功能里」。

### 9.1 为什么第一版没效果（定性）

- 第一版主路线是 battle world 的 `worldTimeScale`：只作用于 `battleLogic update` 的 `fk`，**战斗外的过场/挂机/UI 完全不受影响**；而且 `battleMgr` 下的 world 常常取不到（`battleMgr.bEu.nM()` 是方法不是属性），结构发现落空就整条链不动。
- 第二路线 `cc.director.getScheduler().setTimeScale(k)` 只影响 scheduler 排的定时器，**不影响引擎主循环的 dt**，所以肉眼几乎看不出加速。
- 结论：要「变速器」效果，必须动**引擎每帧 dt**，而不是某个业务字段。

### 9.2 第二版实现

| 项 | 做法 |
|---|---|
| 主路线 | 包装 `cc.director.calculateDeltaTime`，每帧把 `this._deltaTime` **×k**（不碰 `_lastUpdate`，所以只放大本帧间隔、不累积漂移） |
| 生效面 | 引擎 `mainLoop` 在 `calculateDeltaTime` 之后把 dt 喂给 `compScheduler.updatePhase / _scheduler.update / ActionManager / 物理 / 组件 update` ⇒ **一处放大=全局加速**（战斗、过场、挂机、UI 动效） |
| 兜底 1 | dt 装不上时：战斗内写 `worldTimeScale`（BFS 结构发现 `worldTimeScale` 明文名，深度≤3，路径记 `AC.speedPath`） |
| 兜底 2 | 再不行：`scheduler.setTimeScale(k)` |
| 互斥 | 三条路线用 `AC.dtScaled` 判定互斥，**绝不同时生效**（否则 k²，比不加速更糟） |
| 账 | `AC.tick` 的 `wallMs` 除回 k（否则墙钟与逻辑钟同比例放大，结算补偿会误判成"没加速"）；`onReport` 用 `base = useTime / speedMul` 折回真实时长 |
| 可观测 | `__AC_STATE__` 增 `dtScaled / dtHits / speedMul / speedHits / speedPath / schedClock / schedHits`；日志 `battle-speed = kx (useTime clamp armed)`、`battle-speed: engine dt scaling armed (calculateDeltaTime x k)` |
