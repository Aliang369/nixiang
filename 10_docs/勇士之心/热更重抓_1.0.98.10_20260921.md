## 4. 根因：自动战斗指纹写死了会被重命名的混淆名

离线复现注入体的发现逻辑（`04_scripts/勇士之心/simulate_ysxz_discovery.py`）：

| 输入 | 自动战斗指纹 | 结论 |
|---|---|---|
| 旧 res + 旧指纹 | 命中 | `OK`（复现 09-15 可用状态） |
| 新 res + 旧指纹 | **落空** | `MISSING:auto`（复现用户报的失效） |
| 新 res + 新指纹 | 命中 | `OK` |

对照证据（`assets/game/index.js`）：

```js
// 09-15 旧 res
t.prototype.fsl = function() {
    return $fc.buff.bVy.bVs(a.$fe.tblEnum.BuffTableEnum.AUTO_BATTLE);
};
// 1.0.98.10 新 res：$fc→$eZ、bVy→bXV、bVs→bXP、fsl→fwW
t.prototype.fwW = function() {
    return $eZ.buff.bXV.bXP(a.$fb.tblEnum.BuffTableEnum.AUTO_BATTLE);
};
```

旧指纹 `s.indexOf("AUTO_BATTLE")>=0 && s.indexOf("bVs(")>=0` 卡在 `bVs(`，
热更把 buff 管理器方法改名后 tryAuto 全部落空 → `feature5` 开不开都不放行金卡特权，
战斗内点“自动战斗”仍走 `MONTH_CARD_OPEN` 提示。

其余四个功能的指纹**只依赖混淆器不动的明文属性名**（`maxApDefRate`+`baseCritDamage`、
`maxCdTime`+充能自减、`hitDirType`+HP 置零、`finalHurtValue`+`lockMinHP` 减法、
`worldTimeScale`+`hitPauseTimeScale`+`hTimeScale`），热更后仍然命中；混淆名漂移由运行时
发现逻辑自动吸收：

| 语义 | 旧 res | 新 res 1.0.98.10 |
|---|---|---|
| 玩家标记槽/字段 | `hx.bjY` | `hx.bmh` |
| 阵营组件/阵营值 | `hD.biI` | `hD.bkR` |
| 战斗上下文/队伍/阵营 | `blc.fF[0].cXQ` | `bnl.fF[0].dcf` |
| HP 字段 | `beu` | `bgD` |
| world 槽 | `hi` | `hi`（未变） |
| 伤害公式 / 扣血口 / 移动系统所在模块 | `$KL` / `$KP` / `$DPN` | `$KC` / `$KG` / `$OC` |
