## 2. 机制（三层里的第 1+2 层 + 诱饵）

```
出包：payload → XOR(keystream(K_build)) → ct；mac = HMAC(K_build, "sgm1"|ct)
票 ：3|device|game|exp|mask|kid|kx.sig    kx = K_build XOR wrap
      wrap = sha256("sgpay|device|game|exp|mask|kid")   ← 只依赖被签名字段，避开循环
运行：验签 → wrap → K_build = kx XOR wrap → 验 MAC → 解密 → 拼进游戏 bundle
      任一步失败 ⇒ 喂**诱饵**（合法 JS、静默无效、不崩不闪退）
```

关键点：
- **K_build 不在包里**（出包机 `~/.starry-keys/payload/<sha>.key`；主密钥 `payload_master.txt` 与服务器共用同一份）
- 没有私钥 ⇒ 签不出票 ⇒ 算不出 wrap ⇒ 拿不到 K_build ⇒ 只有诱饵
- 只用手上已有的 HMAC-SHA256（Encrypt-then-MAC），不引第三方加密库
- 诚实边界：**有正版卡密的人在自己机器上仍解得开**（用户允许）；要给别人用必须把 K_build 硬编码进改过的包并绕过派发

> 这三条的共性：**"包能出、门禁全绿"不等于功能真的走了新代码**。C7 就是为这个设的。
