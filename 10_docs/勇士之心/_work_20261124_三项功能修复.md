## 2. 解锁金卡

### 2.1 旧名 → 新名

候选过滤复算（`node 13_scratch/gold_scan.js 13_scratch/CGJ.txt`）：

### 2.3 调用点（决定"效果"落在哪）

| 位置 | 代码 | 影响 |
|---|---|---|
| 月卡面板 `$CLA` L251 | `var s = $eZ.monCard.gdk.gcZ("gold"), a = gdc("gold"), u = s && a>0 && a<604800; this.isPurchased.selectedIndex = s && !u ? 1 : 0;` | 面板显示「已购买」、隐藏续费按钮 |

`GOLD_CARD` 枚举在本包**没有**「`ccf(GOLD_CARD)`」这类旁路持有检查（`Select-String GOLD_CARD` 只落在

所以 `gcZ` 是唯一的客户端闸门 —— 包装它就够。

- `GOLD_LEGACY` 补 `gcZ`（只作兜底，仍过 boolean 行为闸）。
- **新增首次调用轨迹**：包装器前 5 次调用打 `gold: 调用 <data>.<fn>(<cardType>) 原值=<bool>`。

## 4. 自动分解

### 4.1 旧名 → 新名

| 项 | 1.1.18.0 | 1.1.22.0 |
|---|---|---|
| 按品质批量分解口 | `bag.<Y>` | **`bag.cbV`**（体内 `this.cak(`） |
| 一跳包装 | — | `cak(t)` → `this.pm(t,…)` |
| 协议 | `Bag.decompose` | 同 |

### 4.2 证据行

```js
e.prototype.cbV = function(t) {                    // L1647
  n.d.beP(function(n) {
    if ((null===(o=n.equip)||void 0===o||!o.isLock) && $eZ.bag.cbk(n)) {
      var r = e.cas(n.itemId); r && -1!=t.indexOf(r.quality) && i.push(n.gridId); } });

e.prototype.cak = function(t) { … this.pm(t, { isBlockEvent: !0 }) … };    // L428
```

### 4.3 结论：发现层没坏，坏的是「驱动层证据」

旧指纹 `gridList+quality+isLock` 在 1.1.22.0 **仍然命中 cbV**（`DECO_FP=true`）。
所以"自动分解无效果"的直接原因不是找不到口，而是：

1. 唯一触发点是 `onResultPanel()`（结算面板 +0.4s），冷启 `panels:0` 时什么都不发；
2. 旧代码的告警文案把这种情况写成「baseline 没钩到面板打开方法 —— 自动化三项都不会触发」，
   **而同一份日志里 baseline 明明打了 `result panel open hook = .prototype.wA` / `panelHook=yes`**
   ⇒ 现场结论被这条误报带偏（上一轮就是照它判的）。

### 4.4 本轮改动

- 发现层不降级：仍是 tier1 协议锚点（2 跳：`cbV`→`cak`→`pm`→`Bag.decompose`），旧指纹降为 tier2。
- baseline 新增一行 `window.__starry_panel_hooked = 1`（`tryPanel` 命中即置位）；
  `auto_layer.panelTick()` 先读它：已装 ⇒ 安静等首次结算；明确没装 ⇒ 才 warn。
- 冷启即做一次 bag 发现探针（只 toString 扫描、不发协议）。

### 5.1 先修构建链坑（否则出 NPE 包）

`mod菜单/starry-mod-menu/scripts/surgical_ysxz_1.0.6.sh`：

