# 勇士之心 登录态不保存 根因与修法（2026-10-04）

> 用户原话（m00001）：「然后就是账号输入登陆，在云机上面登录成功了，但是账号数据无法保存，第二次打开又需要重新登陆」。
> 追加（m00745–m00816 期间）：云机上登录过、也进过游戏，重开就又要重登；要把「以后怎么避免」也一起说清。
> 结论先行：**游戏本身是保存登录态的**，数据丢失发生在「换包重装」这一步，不是游戏逻辑问题。首选修法零成本：**固定签名出包 + `adb install -r` 原地覆盖**。

## 1. 证据：登录态本来就有落盘

云机（MuMu，`127.0.0.1:16384`）上登录成功后，`/data/data/com.fightingstars.games.warrior/shared_prefs/` 共 21 个文件，其中三个是登录相关：

| 文件 | 关键字段（实测命中） | 说明 |
| --- | --- | --- |
| `ymeng_sdk_pref.xml` | `user_name`、`user_id=482759`、`roleName=迪迦`、`roleLevel=9`、`serverName=巨龙山脉14`、`user_token`、`gKey` | 渠道 SDK（萌盟/ymeng）账号票据与角色信息 |
| `joyo_login_info_preference.xml` | `session_code`（JWT）、`session_saved_at`、`phone_num`、`login_code`、**`can_auto_login=true`** | 自动登录开关，`can_auto_login=true` 表示下次启动应当免密进入 |
| `game_device_id.xml` | 设备标识 | 设备级绑定 |

另有 `ymengsdk.xml.xml`（`YMENG_ID`）、`db_bingo_sdk_game.xml`、`com.eg.sdk.*` 等 SDK 侧持久化。

⇒ 「登录成功后不保存」这个前提**不成立**：票据确实写进了 `shared_prefs`，而且 `can_auto_login=true`。所以「第二次打开要重登」只能是**这些文件在两次启动之间被删掉了**。

## 2. 根因：签名不一致 → 只能卸载重装 → 数据目录被清空

- 官方包签名 `CN=shan`；星光包（MOD 包）签名 `CN=StarryMagic`。签名不同，`adb install -r` 会直接失败：
  `Failure [INSTALL_FAILED_UPDATE_INCOMPATIBLE: Package com.fightingstars.games.warrior signatures do not match previously installed version; ignoring!]`
- 于是流程变成 **uninstall → install**，而 `uninstall` 会连同 `/data/data/com.fightingstars.games.warrior` 一起删除，被删掉的东西包括：
  - `shared_prefs/*` —— 登录票据、自动登录开关（本次问题的直接受害者）；
  - `databases/jsb.sqlite` —— 本地存档/进度；
  - `files/res/` —— **831MB 热更资源**（重装后要重新下载/拷贝，首启特别慢）；
  - `files/download`、`files/gamecaches` 等缓存目录。
- 这也解释了另一个现象：换过包之后再打开，不只是要重登，加载也变慢——因为热更资源被清空了。

## 3. 首选修法（零成本，已在云机实测）

出包时**始终使用同一把签名密钥**，安装时**永远用 `adb install -r` 原地覆盖**，数据目录原样保留。

- 既有密钥（仓库内已存在，不要另生成）：`01_tools/starry_release.jks`，alias `starry`，口令 `starry2026`，证书 `CN=StarryMagic`。
- 安装命令：
  ```bash
  adb -s 127.0.0.1:16384 install -r mod_signed.apk
  ```
- 实测验证：用 `CN=StarryMagic` 重新签名并 `install -r` 之后，`shared_prefs` 仍是 **21 个文件**，`ymeng_sdk_pref.xml` 与 `joyo_login_info_preference.xml` 原样存在 ⇒ 登录态未丢，冷启动不需要重登。
- 纪律：**不要**为了「干净」而 uninstall；不要中途换签名密钥；官方包 ↔ 星光包互切时，必须走下面的兜底流程。

## 4. 兜底修法（已经丢过一次数据的场景）

换签名/换包/换底包之前先备份，装完再还原。通用版脚本（真机 `su` 与模拟器 `adb root` 都支持）：

```
04_scripts/勇士之心/ysxz_login_state.sh
```

| 模式 | 命令 | 作用 |
| --- | --- | --- |
| `inspect` | `bash 04_scripts/勇士之心/ysxz_login_state.sh inspect` | 只读体检：包信息、shared_prefs 清单、登录票据关键字段命中情况、数据目录体积、`files/res/version`。判定「登录态是否本来就有保存」 |
| `backup` | `bash 04_scripts/勇士之心/ysxz_login_state.sh backup` | force-stop → 设备端 `tar`（排除 `cache`/`code_cache`/`app_webview`）→ `exec-out` 拉回 → 写 md5、`tar_listing.txt`、`backup_manifest.json` |
| `restore` | `ALLOW_RESTORE=1 bash 04_scripts/勇士之心/ysxz_login_state.sh restore` | `pm path` → force-stop → push → 解包 → `chown -R` + `restorecon -R` 修正属主与 SELinux 标签 → 提示冷启动验证「是否仍需重登录 + 热更资源是否还在」 |

- 环境变量：`SERIAL`（默认 `127.0.0.1:16384`，MuMu 必须用 IP:端口，`emulator-5554` 会卡死）、`PKG`（默认 `com.fightingstars.games.warrior`）、`TAG`（默认当天日期）、`ROOT=auto|su|adbroot`、`ADB_BIN=adb`。
- 产物落在 `09_test/勇士之心/backup_<TAG>/`；远端保留一份 `/data/local/tmp/ysxz_state_<TAG>.tar`，还原时可省一次 push。
- 真机（有 `su`）场景另有历史脚本 `04_scripts/勇士之心/ysxz_backup_data.sh` / `ysxz_restore_data.sh`（依赖 `.device_serial` 与 `su -c`），二者可继续使用。

## 5. 交接清单

1. 出包固定签名 → `adb install -r`；**严禁 uninstall**。
2. 换底包/换签名前：先 `ysxz_login_state.sh backup`，装完 `ALLOW_RESTORE=1 … restore`。
3. 用户报「又要重登」时，先跑 `inspect`：
   - 三个登录文件都在且 `can_auto_login=true` ⇒ 不是保存问题，查安装方式（是否被卸载过）；
   - `shared_prefs` 空或缺失 ⇒ 确认发生过卸载/清数据，走 restore。
4. 重装后首次启动会重新下载热更资源（约 831MB 量级），慢属正常，别误判为卡死。
