## 1. 它是怎么做到的（一句话）

卡密只是菜单门口的一道 JS 判定 `if (!window.__WX_AUTH_OK__) return false;`。
那份菜单 JS 是**运行时从远程拉下来、再由 dex 用 `se::ScriptEngine::evalString` 注入到 Cocos JS 引擎**的。
所以不需要改 APK、不需要碰卡密服务器：**在注入发生的那一瞬间，把脚本参数换掉就行**。

## 3. 跑法

```bash
cd /Users/aliang/Documents/nixiang/03_decompiled/勇士之心_cardkey_20261007
python3.11 drive_bypass.py bypass_cardkey.js bypass_out.txt 180
```

脚本做的事（**必须在游戏启动前装上 hook，这是全部关键**）：

1. `enable_spawn_gating()` → force-stop 游戏
2. `am start -n com.fightingstars.games.warrior/com.ymeng.sdk.channel.egsdk.SplashActivity`
3. 抓到**挂起态的 spawn** → `attach` → `load(bypass_cardkey.js)` → `resume`
4. hook `libcocos2djs.so` 的 `se::ScriptEngine::evalString`（按 **RVA `0x3138e4`** 定位，序言校验 `0xD10543FF`）
5. 等加载器注入补丁 JS（判据：脚本里同时含 `kmlogon` 和 `WX_BOOT_VERSION`），命中后改写 5 处：
   - `skipAuth: false,` → `skipAuth: true ,`（同长度就地改写，兜底）
   - §6 的 `if (WX.skipAuth) {...}` 早退块 → 改为不早退（让 v66 启动层照常走完）
   - 卡密闸门 `__WX_AUTH_OK__ = false` → `= true`
   - 两处「引擎就绪就建卡密窗」→ 加 `!__SKIP_AUTH &&`
6. 等 N 秒后扫内存，打印 `wx_auth_root`/`wx_float_root`/`wx_ball`/`wx_panel_root` 计数

## 5. 已知坑（踩过的，别再踩）

| 现象 | 原因 / 处理 |
|---|---|
| `frida: error: unrecognized arguments: --no-pause` | 本机 frida CLI 17.16.4 不认这个参数；用本仓库的 Python 驱动，别用 CLI |
| `attach` 上去但 hook 一直不触发 | 你 attach 晚了 —— 补丁**只在首次 eval 时注入一次**，之后加载器不会重注入（实测 150s 内只有 tick 求值）。必须冷启动抢 spawn |
| `frida-ps -Uai` 没有 Identifier 列 | frida server 端口不对（phantom 版出厂是随机端口），跑 `start_frida_server.sh` |
| 某几轮完全看不到补丁注入 | 加载器的远程拉取不稳定（看网络）；重跑一次即可 |
| `console.log` 什么都看不到 | 该游戏 JSB 的 `console.log` **不进 logcat**，别指望日志，看内存或返回值 |
| 脚本里 `btoa` 报 `ReferenceError` | frida agent 没有 `btoa`，需手写 base64 |
