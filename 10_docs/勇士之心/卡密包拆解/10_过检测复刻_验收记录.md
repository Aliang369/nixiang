## 3. 我们故意偏离他的三处（都是"照抄会更危险"）

1. **`useTime` 只观测不修改。** `battleTime` 累加的是**缩放后的 dt**（`assets/battleLogic/index.js` 的 `update` 里 `r = this.dt * i.hitPauseTimeScale * i.worldTimeScale * i.mainTimeScale`，再 `e.fk = boP(e.fk + r, 4)`）。而 `worldTimeScale` **是游戏自带的能力**（`assets/game/index.js` 的 `setWorldTimeScale`）。正常玩家用游戏自带加速，`fk` 同样会跑在墙钟前面——这时若照抄他的钳制公式把 `useTime` 钳小，就变成**"客户端上报的对局时长比真实更短"这个全新异常**，比原样上报更容易被盯上。**结论：只把墙钟/逻辑钟两个数记下来，不动值。**将来菜单里真加了"游戏加速"功能，再打开 `clampArmed` 并且**只补偿我们自己那一个倍率**。
2. **闸门层当前在他这份版本上是死代码。** `ANTI_CHEAT_ENABLED` 出厂就是 `false`（`assets/main/index.js @343726` `n.ANTI_CHEAT_ENABLED = !1;`），它的 `if` 分支（`assets/battleLogic/index.js @88940`：`if (B.ANTI_CHEAT_ENABLED) { B.$ib.baM.baW(); B.$ic.bbo.bbB(); B.$_if.bbW.bcb(80); }`，以及 `assets/game/index.js @4641804/@4642947`）本来就不进。**照搬无害但也无收益**，保留它是为了"官方热更把它翻成 true 时"有保险。
3. **模块名靠动态发现，不靠名单。** 理由见第 2 节①。

另外，他写下的**"不做什么"清单我们全部保留**（不包 `computeCheckNum`；不碰 `bEP/bEQ/gV/bDQ` 这些短名重混淆的热路径；不重算 `checkNum`——"改写一个自己无法核实的 checkNum 反而更容易被判异常"；不拦 `exitProgram`）。

### 6.1 真机暴露并修掉的两个缺陷（这两条是本项目最值钱的部分）

**缺陷 A：`§4` 伤害层静默失效 —— 挂到了诱饵，而且一行日志都不打。**

`ac_layer.js` 原逻辑在原型方法里找"同时含 `finalHurtValue`+`lockMinHP`+`finalDamage`"的方法，**首个命中即 `break`**。真机上它挂到了诱饵 `prototype.bgN`（`assets/battleLogic/index.js@120602`，477 B，内容只是字段重置 `this.finalDamage = 0; this.finalHurtValue = 0; this.lockMinHP = 0; …`，**没有 `Math.max`、没有 `bhd`**），于是 `dmgNoted` 涨而 `dmgFixed` 恒为 0。
真机证据：`[AC] hit-dispatch hooked: prototype.bgN`。

修法两步：
1. **打分制取代"首命中即 break"** + **硬门槛** `if (!/Math\.max\([^()]*lockMinHP[^()]*\)/.test(t)) continue;`。实测只有 `hY@114312` 含这个表达式；`bgN@120602`/`gT@104821`/`gU@105076` 都不含 ⇒ 正则唯一命中。
2. **E8 交割**：baseline 的 `tryEntity` 本来就用 `RE_APPLY = /(\w+)\.(\w+)\s*=\s*Math\.max\(\1\.\2\s*-\s*\w+,\s*\1\.lockMinHP\)/` 精确找到真 `hY`，比本层打分更可靠。于是**指纹仲裁权归 baseline**，本层只做"包装次序 + 累加器还原"：baseline 在命中处调 `AC.adoptHit(Cls, hx)`。

**包装次序是承重的**：`adoptHit` 必须发生在 baseline 取走 `var oHX = Cls.prototype[hx];` **之前**，这样 AC 包在**最内层**、baseline 包在**最外层**：
- feature2（秒杀/无敌）**关**：baseline wrapper → AC wrapper → 原 `hY` ⇒ AC 正常记账/还原。
- feature2 **开**：baseline 提前 `return` ⇒ AC 根本不执行 ⇒ **不会凭空写累加器**。
- 反序（AC 在外）且 feature2 开：AC 先加 `pd.orig`、再被 baseline 清零 ⇒ **累加器被写脏**。

> 为什么不能让 `AC.scan` 先跑：baseline 的 `findFn` 会看到 AC 的包装器（源码里没有 `lockMinHP`，也没有 `Math.max(...lockMinHP)`）⇒ `RE_APPLY` 失配 ⇒ **秒杀/无敌直接失效**。

**缺陷 B：`ANTI_CHEAT_ENABLED` 闸门找不到持有模块。**
`sinkHook` 改为"允许套一层"（旧副本没留 `__acOrig`，这是唯一能拿到新计数的办法）；`main` bundle 走 **gate-only scan**（明文 `sealMethods` 只出现在 main 的宿主模块 `$LZ`；`$VN` 也有 `maxApDefRate` + `AUTO_BATTLE`，在 main 里跑功能扫描会误挂 秒杀/无敌/自动战斗）。native 侧 `IsTargetBundle` 放行 `assets/main/index.` 才让这条路可达。

**版本仲裁（真机才暴露）**：引擎先加载可写的 `files/res/main.js`（自举 blob，内嵌本层的一份**旧副本**），原生 `evalString` splice 的**新副本**随后才到。旧守卫写 `window.__starry_ac 存在就 return` ⇒ 旧副本永久胜出。改成版本号仲裁：`var AC_VER = 2; var _prev = window.__starry_ac; if (_prev && (_prev.__v | 0) >= AC_VER) return;`。真机上 `ac layer v1 loaded` 恰好 3 次 —— 1 条孤立行（旧副本） + 1 对配对行（新副本接管），这个**不对称本身**就是接管成功的信号。

### 6.3 结算出口 / `useTime` 的真机实测（**这条推翻了照抄卡密包钳制的前提**）

同一次运行打完整局、走到结算：

```
[AC] report #1: useTime=28038 wallMs=32333 delta=-4295ms tag=gsMgr.cQA clamped=no clampArmed=false reportN=1
```

- **`tag=gsMgr.cQA`** ⇒ 结算走的是 `gsMgr.cQA` 出口（另一条 `battleServer.sendMsg` 本次未触发）⇒ 两条 sink 里这一条**确实被真实结算调到**。
- **`delta = useTime - wallMs = -4295 ms`（负）** ⇒ 客户端自报战斗时长（28.0 s）**比累积帧时长（32.3 s）还短**，**没有虚报**。机理：`wallMs` 累加的是原始 `dt`，而游戏 `fk += dt × hitPauseTimeScale × worldTimeScale × mainTimeScale`，受击停顿让该乘积 <1。
- **由此判定**：卡密包 §3 的钳制式 `want = max(1000, min(realMs, fkMs))` 在本场景下是 `min(32333, 28038) = 28038` ⇒ **即使原样照抄也是 no-op**。我们"只观测不改写"（`clampArmed=false`）的决策被真机数据正面证实；反之若按"加速必然虚报"的直觉硬钳，会造出"上报时长比真实短"的**新异常**。
- **附带证明**：`wallMs=32333 ≠ 0` ⇒ `AC.tick` 确实挂在有 `this.dt` 的 `update` 上，`tickSeen/tickN` 的真机口径同时打通。
- **`useTime` 未被改写**（`clamped=no`），`completeResult.useTime` 原样透传。

### 6.4 仍未观测到的（不许当成"已验证"）

- **服务端**：完全没有。`__AC_STATE__` 在真机上无 JS 控制台可读，**日志是唯一通道**。客户端侧能做的最强断言到此为止 —— 服务端会不会从别的观测量（自算时长、随机种子回放）发现异常，我们**无法证明**。
- **`evHit/evNote/evFix/evReport` 的封顶行为**：离线 T11/T12 已验（各封顶 3 条、计数照常累加）；真机上 `dmg hit`/`dmg boosted`/`dmg fix`/`report` 各只出现 3/3/3/1 条，与封顶一致，未再增长。

**风险口径**：他这套是"把检测该看到的世界改回正常值"。**算错比不算更危险** —— 这也是我们把 `useTime` 改成只观测的另一个理由。

## 9. 「100 遍检查」怎么落地的

你要求"务必按照 100 遍的检查，确保一致无误"。这里没有任何一步是"看着差不多"——每一环都有**可复跑、可失败**的机器判据，而且**每一环都真的挂过一次**：

| 环 | 判据 | 失败会怎样 |
|---|---|---|
| 锚点 | 8 个外科锚点在 baseline 里**各恰好 1 次**，否则 `SystemExit` | 静默改错位置 |
| 合成自检 | 31 项字符串不变量（每个 E 编辑各一条 + 功能关键字不可丢失 + 旧指纹不可残留） | 漏改/多改 |
| 语法 | `node --check` | 运行期才炸 |
| 头文件 | `verify_ysxz_patch_js.py`（含菜单序号与 `YsxzEntry.cpp` 交叉核对） | 菜单错位 |
| so 级 | so 内嵌 patch JS 与 `patch_v2_ac.js` **逐字节比对** + 无 NUL + 特征串 | `strlen` 截断 |
| 包级 | 1005 条逐字节未动 / 新增 0 / 消失 0 / 只有 so + 3 签名文件被换 / `classes4.dex` 与底包一致 | 误动菜单 |
| 逻辑 | `test_ac_layer.js` **66 项断言**，且用的是 dump 里的**真实 `hY` 源码** | mock 自证 |
| 真机 | 设备内 so md5 与本地一致 + 三段证据链 `boosted/hit/fix` 数值可核算 | 装了旧包不自知 |

**"静默失效"是本项目的头号敌人**：挂钩失败不会抛异常、不会有堆栈，只会**什么都不打印**。缺陷 A 就是这么潜伏的（`dmgNoted` 涨、`dmgFixed` 恒 0、AC 一行日志都没有）。因此本轮专门补了四条**一次性证据日志**（各封顶 3 条，不刷屏）：

- `dmg boosted #N` —— 伤害公式确实产出被放大的值（证明滑块作用到了 `GD`）
- `dmg hit #N` —— `hY` 确实被调到，且附 `pending` 配对与命中前值（区分"钩子没跑"与"跑了没放大"，这正是上一轮踩的坑）
- `dmg fix #N` —— 累加器 `A->B->C` 三段可核算（`C` 必须 = `A + 原值`）
- `report #N` —— 结算出口确实被调到，并把**逻辑钟 vs 墙钟**并排打出来（`delta = useTime - wallMs`）。这正是他 §3 补偿公式的输入，也是"将来要不要打开 `clampArmed`"的唯一依据

**没有这几条日志，"补偿链路到底跑没跑"就是一个无法证伪的说法。**

> 这四条日志同时也是**拦截上报**这个能力的最小可观测骨架 —— 将来做通用框架时，"钩子是否真的落在预期函数上、参数是否如预期"必须一样是可打印、可核算的，而不是靠肉眼看游戏表现。
