## 6. `autoSyncTaskInfo`（L6591–L6693）：同步了什么、给谁用

**定位**：注释「任务信息持续同步（不开自动也显示当前主线任务）」（L6589）。它**独立于状态机**，被 `W.__WX_AUTO_ENGINE_TICK__` 每 tick 调用（L7054），**`AUTO.enabled` 为 false 时也跑**，所以是"未开启自动任务时 UI 也有任务信息"的唯一来源。

流程：
1. **角色就绪门禁**（L6594–L6597）：`roleMgr.fBb.fAQ` 不存在 → 直接 `return`（选角色/登录界面不拉任务，避免"角色未初始化"错误）。
2. **5 秒节流**：`AUTO_TASK_LAST_SYNC`（模块级，L6590）+ `if (now - AUTO_TASK_LAST_SYNC < 5000) return;`（L6600）。
3. 注释「不再每 5 秒同步职业列表到 UI（转职推送疑似破坏 UI 刷新）」（L6602–L6603）。
4. `cur = autoGetCurrentTask()`；**读不到**时（L6605–L6633）：按 **30 秒**冷却（`AUTO.__syncCtPLast`）调 `refreshTaskGroup(false)`；把 `roleReady / task / cvg / cvg keys` 写 `wx_sync_diag.txt`；**不覆盖 UI**（保留当前显示，避免误显示"已完成"）后 `return`。
5. 读到任务时组装 patch（L6634–L6648）：
   - `desc = t.desc || autoGetText(cfg.desc) || ("任务 #" + cur.task.id)`
   - `pro = (cur.task.process || 0) + "/" + (typeof cfg.num === "number" ? cfg.num : "?")`
   - `target`：`submit→"提交任务"`、`instance→"副本 #"+instId`、`npc→"NPC 对话"`、`guide→"引导完成"`、`jobChange→"转职"`、`strengthen→"自动强化装备"`、`chapterReward→"领取章节奖励"`、其余 `"未知目标"`
   - `patch = { autoTaskDesc, autoTaskTarget, autoTaskProgress: pro }`
6. **副本显示中文名**（L6650–L6661）：`instance` 类型时用 `InstanceTable.findByKey(t.instId).name` 经 `autoGetText` 覆盖 `autoTaskTarget`。
7. `patch.autoStatus = AUTO.enabled ? ("运行中·" + AUTO.state) : "已停止"`；`patch.autoLog = (AUTO.enabled && AUTO.log) ? AUTO.log : (AUTO.log || "等待自动任务启动")`；`state(patch)`（L6664–L6666）。
8. **30 秒诊断**（L6668–L6673）：`log("[AUTOSYNC] enabled=... state=... log=... ls=" + lsGet("__WX_AUTO_TASK__","?"))`。
9. **每次同步 dump 任务配置**到 `wx_task_cfg.txt`（L6674–L6691），字段：`{ id, name, desc, taskType, num, eventType, param1..param5, jumpId, levelStory, nextId }` + 头部 `taskId/status/process`。

**给谁用**：游戏外 dex 侧的菜单 UI（通过 `W.RemoteUI.mergeState` / `updateState`，L3076–L3077 落到 `W.__WX_AUTO_STATE__`），键名固定为 `autoTaskDesc / autoTaskTarget / autoTaskProgress / autoStatus / autoLog / __WX_AUTO_UI__`。写盘文件用 `jsb.fileUtils`，路径 = `getWritablePath()`（兜底 `/data/user/0/com.fightingstars.games.warrior/files/`）+ 文件名（`wx_auto_log.txt` L3641、`wx_sync_diag.txt` L6621、`wx_task_cfg.txt` L6679）。

`state(patch)`（L3078–L3083）本身就是"合并去重"，只做 `for (var k in p) out[k] = p[k]` 原地合并，**不触发重绘**；重绘靠 `W.RemoteUI.updateState`（= `mergeState`，原地刷 `refreshBoundViews`，见 `wx.uiTest` L3522–L3549 的四种通道对照）。

### 技巧 2：防卡死看门狗（`__cooldownUntil` 统一冷却 + 每分支独立重试上限）

**行号**：`__cooldownUntil` 唯一出口 L5616–L5617；置位处 L5482/L5520/L5647/L5658/L5793/L5807/L5866/L5900/L6018/L6092/L6111/L6154/L6194/L6216/L6222/L6244/L6275/L6290…L6473；`AUTO.__nextStageAt` 加载窗口 L6258–L6261。
三处最关键的原始事故与修法：

- **`setTimeout` 设状态是无效的**（L5896–L5899 原文）：「原来回 IDLE + setTimeout 5s 是无效的！因为下一轮 tick 的 `case "IDLE"` 会立刻把 state 设回 READ_TASK，5000ms 的 setTimeout 根本没机会生效 → 每 300ms 重跑一遍（实测刷屏）。改为：设置"冷却截止时间"，tick 在 READ_TASK 开头统一检查」→ 即 L5616 `if (AUTO.__cooldownUntil && now < AUTO.__cooldownUntil) break;`。
- **重试上限防无限点击**：副本详情挑战 `__fightCount > 5` 放弃（L5476）、塔出战 `__towerCount > 4` 放弃（L5515）、滚动公告 1 秒冷却（L5418）、FuncOpenPanel 1.5 秒冷却（L5401）、未知任务最多跳过 5 个（L6082）。
- **同一面板实例只处理一次**：`AUTO.__finishHandled === panelF`（L5363）、`AUTO.__advHandled === pAny`（L5590）—— 原文「否则 300ms tick 会重复点 → 重复发进副本协议」；面板被销毁/更换（重新弹出）后自动解除。
- **计时起点必须重置**：`IN_BATTLE` 进入时 `AUTO.battleStart = now`（L5669、L6144、L6174 的异常兜底），否则"塔出战"路径沿用旧时间戳 → 立刻误判 180s 超时 → 强退 → 网络异常。
- **场景加载窗口特殊对待**：`loadingNext = __nextStageAt && sinceNext < 20000` 时不判超时，并把 `settleStart = now - Math.min(sinceNext, 5000)` 推后（L6258–L6266），避免"点了下一关"被 25s 超时打断成"打着打着突然回城"。
