### 1.5 `acFixReport(payload)` —— L6975–L6999（**只改一个字段**）

改的字段：**`payload.completeResult.useTime`**（唯一被写的字段）。其余字段（含 `randomSeed` / `checkNum` / `frameId`）**一个都不碰**。

```js

6983: var cur = cr.useTime, want;
6984: if (spd > 1 && ST.riStartWall > 0) {
6985:   var realMs = Date.now() - ST.riStartWall;

6991:   if (!isFinite(want) || want < 0) want = fkMs > 0 ? fkMs : 0;
6992:   else if (fkMs > 0 && want > fkMs) want = fkMs;
```

公式（照抄即可）：

- 前提：`payload.completeResult.useTime` 必须是 number，否则直接 return（不动 payload）。
- `fk` = 本场逻辑时长（秒，来自 `findBattleState().fk`）；`fkMs = floor(fk*1000)`；`spd` = 加速倍率（默认 1）。
- **开加速分支（`spd > 1 && ST.riStartWall > 0`）**：
  - `realMs = Date.now() - ST.riStartWall`（本场真实墙钟耗时）
  - `est = floor(fk / spd * 1000)`（按倍率换算的估计真时长，作为下界补偿）
  - `if (realMs < est) realMs = est` —— **墙钟短于估计值就抬高到估计值**（防止「加速后墙钟反而比逻辑短」这种一眼假）
  - `want = max(1000, min(realMs, fkMs>0 ? fkMs : realMs))` —— 夹在 **[1000, fkMs]** 区间内，且不超墙钟
- **未加速分支**：`want = cur`；非法/负数 → `fkMs>0?fkMs:0`；`fkMs>0 && want>fkMs` → 截到 `fkMs`（**只降不升**）。
- 统一 `want = Math.floor(want)`，写回 `cr.useTime`。
- 计数：`want !== cur` 时 `ST.riFixedUt++`；人读记录 `ST.riNote = 'useTime <旧>-><新> fk=<fkMs> spd=<spd>'`。

> **防封逻辑本质**：开加速时游戏按【逻辑时长 fk】上报，而服务端能看到真实墙钟，两者对不上就是特征；这里把上报值拉到「墙钟与逻辑时长的合理交集」。
