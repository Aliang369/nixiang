## 1. 两条技术路线对照（先看这个，决定"怎么搬"）

我们星空包和这个卡密包，**目标同一个游戏、同一份 bundle，但路线完全不同**：

| 维度 | 卡密包（他） | 星空包（我们，`mod菜单/starry-mod-menu`） |
|---|---|---|
| native 侧 | 只 hook `se::ScriptEngine::evalString` 注入 JS；另有 dex 壳做加载/检测 | 同样是 hook `evalString` 拼 JS：`app/src/main/jni/Games/YsxzMod.cpp`，产物头 `YsxzPatchJs.h` / 入口 `YsxzEntry.cpp` |
| 菜单 UI | **纯 JS 自绘**（`cc.Graphics`+`cc.Label` 手搓悬浮球+面板，挂在游戏 Canvas 上），见 `03_悬浮窗UI.md` | **原生 Android 菜单**（`kYsxz_Features` 在 `YsxzEntry.cpp`），JS 只负责读开关状态 |
| 开关通道 | JS 内部 `CFG` 对象 + `cc.sys.localStorage` | Java 静态桥 `com.starry.magic.cocos.YsxzHooks.getRet/getVal/logStatus`（`RET[8]`/`VAL[8]`） |
| **认游戏内部符号的方式** | **写死当前 build 的混淆名**：`window.$eZ.battleMgr.bEu`、`world().fF`、`ent.hw`、`stat.bhd/bhe/bhf/bhg`、`proto.hY/bil/bij`、`$eZ.monCard.fDn`… | **运行时发现**：正则扫 `Function.prototype.toString()`，用**明文锚点**（`isPlayer`/`lockMinHP`/`finalHurtValue`/`maxApDefRate`/`AUTO_BATTLE`/`worldTimeScale`…）捕获混淆名，再按指纹认函数 |
| 抗热更能力 | **弱**：热更改名即全废 | **强**：改名自动重认；已按硬约束 #6 做到真机新 res / 模拟器旧 res 同一份包双端可用 |
| 功能广度 | 7 个战斗项 + **9 个自动化项（约 1500 行状态机）** + 完整防封层 | 6 个战斗项，**无任何自动化项** |

> **结论（最重要的一条）**：卡密包**唯一真正值钱、且我们完全没有的东西是"自动"那一整套**（自动主线 11 态状态机 + 8 个杂项自动化），以及**反检测里的上报伪装**。
> 他的战斗项我们**已经全有**，而且我们的实现路线（运行时发现）比他的（写死混淆名）更抗热更。
> ⚠️ 他的代码**绝大多数不能直接粘**：写死混淆名直接违反本仓 `10_docs/勇士之心/硬约束.md` **#6「后续换包不得回退到单指纹或写死混淆名（`bVs(` 类）」**。正确做法是**抄机制（chokepoint + 数值）**，符号仍走我们的发现层。

## 4. 三条「必须照抄」的硬核手法

### 4.1 防封：上报时间伪装（`acFixReport` @L6975）

这是他全文件最有价值的"防封"设计，与全局加速**成对存在**：

```js
// 只改一个字段：payload.completeResult.useTime
fkMs = Math.floor(fk * 1000);                                   // 客户端逻辑时间
if (加速中) want = Math.max(1000, Math.min(realMs, fkMs));      // 不让人看出"太快"
else        only 降不升
```

配套：
- `acGateMod(m, tag)` @L6908 — 判据 `'ANTI_CHEAT_ENABLED' in m`，用 `defineProperty` 把 getter 恒 false（把反外挂开关"焊死"）。
- `installAntiCheatGate()` @L6919 — 包 `W.__require`，对 **15 个混淆名** `['$LZ','$KF','$KM','$KK','$KE','$PZ','$WS','$DOB','$DOC','$DOD','$DOE','$hU','$hV','$hW','$hZ']` 逐个套壳。
- `installReportIntegrity()` @L7017 — `acHookSink($eZ.battleServer,'sendMsg')` + `acHookSink($eZ.gsMgr,'cQA')`，在所有上报出口统一改 payload。
- 幂等靠 `__wxAcSink` / `__wxAcLocked`，tick 内 1000ms 节流重装（热更自愈）。
- 同一处防封：`HitBus` 命中后用**原始伤害**回补 `atkStat.finalDamage` / `vicStat.finalHurtValue` @L2615-2623 —— 改了伤害但让"统计值"看起来正常。

### 4.2 打点方式：找"唯一咽喉"而不是遍地黄花

他标出的咽喉，比我们现有的更靠上游，值得记档：

| 咽喉 | 落地 | 为什么好 |
|---|---|---|
| `proto.hY(attacker, damage, hitInfo)` | 唯一命中入口 | 一次挂钩覆盖普攻/技能/DOT；且能拿到 `attacker`/`target`/`damage` 三件套 |
| `proto.bil()` | 技能 CD 判定 | 与 UI 按钮共用 ⇒ 改这里按钮同步亮 |
| `proto.bij(type)` | 移动系统，`type===2` 才是水平位移 | 只放大水平步长，不碰竖直/跳跃 |
| `world().fF` + `b.gi(ref.ddZ)` | 实体列表取法 | 稳定拿全实体（我们的 `update(list)` 参数是另一种拿法） |
| `ent.hz.mainTimeScale` | 全局时间缩放 | 加速的唯一干净入口 |
| `$eZ.monCard.fDn` 原型 `fDj()/fDc(cardType)` | 卡券/金卡门 | 金卡解锁 |

### 4.3 自动化：状态机 + 看门狗（`06_自动任务状态机.md`）

最值得抄的 3 个结构：

1. **全局对象挂 window**（`W.__WX_AUTO_OBJ__` @L3579）——注释写明理由：局部变量在 `remote.js` 热更重注入时会 new 新对象，`enabled` 被复位。**这条我们一定会踩**。
2. **防卡死看门狗** = 全局 `__cooldownUntil`（IDLE 出口统一检查 @L5616）+ 分级重试上限（副本 ≤5 / 塔 ≤4 / 未知任务 ≤5）+ 同面板实例去重 `__finishHandled`。原文特别注明：`setTimeout` 里直接设 state **无效**，会被下一 tick 的 IDLE 覆盖。
3. **面板驱动不写死类名**：`getPanelCandidates` @L6696 三级回退（`$JX.$fb.cvConfig.panels` → `$RJ` → `F().cvConfig.panels`），fguiMgr 四短名 `cTO`(取实例)/`cTU`(顶层)/`cTK`(判开)/`cTE`(关) —— **这一条其实和我们的"运行时发现"哲学一致，可以直接借鉴。**

## 6. 明确不建议照搬的部分

| 项 | 理由 |
|---|---|
| 全部写死的混淆名 | 违反 `10_docs/勇士之心/硬约束.md` #6；我们已有发现层 |
| 纯 JS 自绘悬浮菜单（§3，约 850 行） | 我们走原生 Android 菜单，UI 需求已满足；搬过来还要和原生菜单抢焦点 |
| 卡密协议（§2） | 与本任务无关；用户明确说"不是让你去改这个卡密" |
| `if (WX.skipAuth) { ...; return 'wx-patch-1-skipauth'; }` 这种早退写法 | 会跳过后续启动层（`detectEnv`/`startDrivers`/`watchSceneAuth`）——**只对"进菜单看功能"的测试场景有意义**，不是产品做法 |
| 上报里把 `useTime` 硬改成 `max(1000, ...)` | 数值策略要按我们自己的加速倍率重算，直接抄会导致"未加速时数据也异常" |
