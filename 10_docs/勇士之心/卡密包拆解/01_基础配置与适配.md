## 0.5 平台适配层（L110–L725）

段落头部理由（L111–124 注释，原文声明「这几条是本次改动的全部理由，别删」）：

- a) 悬浮窗画在游戏自己的 Cocos 场景里，**不用 `SYSTEM_ALERT_WINDOW`**；鸿蒙 NEXT(5/6) 没有第三方「显示在其他应用上层」入口，原生 `WindowManager` 悬浮窗在那边永远开不出来。
- b) 环境探测优先读 `/system/build.prop`（普通应用可读），不依赖 Java 反射：鸿蒙兼容层里 `jsb.reflection` 可能被裁剪，反射一失败整个适配就瞎了。
- c) 悬浮窗能不能出来取决于 tick 有没有被调度；dex 没注入 / 被拦 / 引擎吞 `setInterval` 都会导致「球不出现」，故四路驱动并联。
- d) Android 15/16 强制 edge-to-edge、鸿蒙普遍挖孔，球会被顶到状态栏/挖孔下面点不到，所有坐标统一过安全区钳制。

### 2.4 段落边界与文件级事实

- 兼容段标记：`/*<<<WX_COMPAT_BEGIN>>>*/` @L110 ↔ `/*<<<WX_COMPAT_END>>>*/` @L725 —— 整段平台适配可独立摘除/移植。
- 文件头声明（L2–25）：整体 5 段结构 = ①热更新适配 ②卡密网络验证（微验：MD5 签名 + RC4 + 心跳 + 公告）③悬浮窗菜单（纯 Cocos 绘制：球 → 面板 → 功能行，外观照弹壳战机面板）④游戏 Hook（伤害 / 锁血 / 锁蓝 / 金卡与自动战斗 / 人物移速）⑤统一 tick（dex 侧每 300ms 调 `window.__WX_TICK__()`，因引擎里 `setInterval` 不保证被调度）。
- 文件头关键约束（L12–15）：全部在内存里完成、**不改游戏任何文件**（注释称实测过：改文件必被游戏自己退出）；Java 层过检测（`EmutorUtils`/`NativeInfo`/`CocosBridgeAPI` 伪造 + `System.exit` 拦截）放在 dex 里；加密壳（XXTEA/zlib 的 `*ze*` 容器）在 dex 里解密后 `evalString` 注入。
- v66 改动清单（L17–25）：[1] 新增 §0.5 平台适配层（build.prop 环境探测、安全区钳制、四路 tick 驱动、Canvas 挂载点探测、落盘装机指纹、诊断接口 `__WX_DIAG__()`）；[2] 悬浮窗自愈（登录后球/面板丢了会自己重建）；[3] 卡密窗看门狗限速重试（不再 500ms 猛刷）；[4] 坐标全过安全区（Android 15/16 强制 edge-to-edge、鸿蒙挖孔屏）；[5] 设置落盘双写（`localStorage` 不可用时退回 `wx_cfg.json`）；[6] 保持手动登录（不做自动登录，卡密必须手动输入 + 点「立即登录」）。
