# 勇士之心 Mac 出包 → 模拟器可用 规约（2026-10-04）

> 用户原话（m00001）：「然后就是mac做出来的游戏，模拟器玩都会有问题，这个怎么以后让mac出游戏的时候能够避免呢，也一起考虑帮我考虑下。先修复这个游戏。」
>
> 本文回答「以后怎么避免」，不是「这次怎么修」。本次修复链见 §5；复现证据见 `10_docs/勇士之心/` 与 `09_test/_live_log.txt`。

## 0. 一句话结论

Mac 出的包在模拟器坏掉，**不是打包器坏了，是包/工具链里塞了只在真机 + Mac 上成立的假设**：硬编码地址、硬编码路径、依赖可执行段、非 ASCII 构建元数据、不一致签名、以及「用内存注入绕开服务端 md5」这条只在真机成立的路线。本文把这 7 类假设逐条钉死成规约。

## 1. 现象 → 机制对照（本次实测）

| # | 现象 | 机制 | 证据 |
|---|---|---|---|
| A | 模拟器上 MOD 菜单能起、功能全不生效 | `libstarry_magic.so` 硬编码 evalString RVA，模拟器上取不到地址 | `kEvalRvaFallbacks[] = {0x3152dc, 0x3138e4}`（`app/src/main/jni/Games/YsxzMod.cpp:40`）；日志刷屏 `Mod_Menu: [Ysxz] evalString rva 0x3138E4 not mapped` |
| B | 地址「本该能算却算不出来」 | 定位器只认含 `x` 权限的映射行，Houdini 下 ARM 代码段是 `r--p`、真执行在翻译层匿名区 | 原实现 `if (!strchr(perm,'x') ...) continue;`；修复版见 `YsxzMod.cpp:94-108`（`readable-map fallback`） |
| C | Windows/别的机器直接跑不动打包脚本 | 脚本硬编码 Mac 路径与 Mac 专用命令 | `NIXIANG="/Users/aliang/Documents/nixiang"`（`scripts/surgical_ysxz_1.0.4.sh:13`）、`/usr/libexec/java_home`（:26）、darwin NDK 三元组（:23）、`md5 -q`（:33,250）、`aapt2` in `$HOME/Library/Android/sdk/build-tools/36.0.0`（:149） |
| D | NDK 编译报 `The system cannot find the file specified.` | 构建戳把含中文的 `git log -1 --format=%ct` 结果塞进 `-D` 宏 | `Application.mk:8`；修法见 §2.4 |
| E | 重装后又要重新登录、首启极慢 | 签名不一致 → `install -r` 被拒 → 卸载重装清空 `/data/data`（含 831MB 热更资源） | `INSTALL_FAILED_UPDATE_INCOMPATIBLE`；详见《登录态不保存_根因与修法_20261004.md》 |
| F | 改 APK 里的 JS 完全没反应 | 引擎真正加载的是运行时 `files/res`，版本一致时不重拷贝 assets | APK 内 5 个引导脚本打标记 → 冷启动 **0 条** `BOOT_MARK`；改 `files/res/*` → 5 条全中（`D/jswrapper: JS:`） |
| G | 改磁盘上的 bundle 后秒退（`exitProgram`） | 服务端 `version_update_md5` 校验 4 个文件；Mac 端靠**内存注入**不改磁盘字节，所以不撞 | API `https://api-warrior2.fighting-stars.com/common/init/version_update_md5`；`bingo BingoBridge->exitProgram` |

**核心矛盾（必须写进规约）**：Mac 真机链路里 mod 用 native hook 改内存，磁盘字节不变 ⇒ 服务端 md5 通过。一旦换到模拟器，hook 装不上，只剩「改磁盘」这条路 ⇒ 必然撞 md5。所以「Mac 出的包在模拟器有问题」是**路线假设**层面的问题，不是模拟器兼容性问题。

## 2. 规约（出包前逐条自检）

### 2.1 地址必须版本无关
- 禁止硬编码目标函数 RVA 作为唯一手段。首选**特征扫描**：在目标 so 的代码段按指令特征搜索函数入口（本次即 `kEvalInsn = 0xD10543FF` 扫 prologue + 通过 `.dynsym` 定位 JNI 导出再扫 BL imm26）。
- 多个候选地址时必须**逐个校验指令特征**，校验失败只告警不崩，能降级到「本次不挂钩」。
- 出包记录里写清「本包适配哪些游戏版本 / so md5」，换版本必须重新定位。

### 2.2 不许依赖 `x` 权限映射
- 任何 `FileOffToVa` 类换算，映射行筛选条件必须是「可读」，不能要求可执行（模拟器/加固/翻译层下代码常不在 `x` 段）。
- 校验顺序：先找 `x` 段（真机快路径）→ 找不到再退到覆盖该偏移的**最大可读段** → 仍失败才放弃。
- 参考实现：`YsxzMod.cpp:88-110`。

### 2.3 工具链路径全部可发现，不许写死
- 脚本用 `${BASH_SOURCE[0]}` 推导仓库根，禁止 `/Users/<某人>/...`。
- `md5` → 探测 `md5sum`/`shasum -a 256`/`md5 -q` 三者取一（写 `MD5_BIN`）。
- `JAVA_HOME` → 优先环境变量，其次 `command -v java` + `readlink` 反推；`/usr/libexec/java_home` 只作 darwin 分支。
- NDK 三元组 → 按 `uname -s` 选 `darwin-x86_64`/`linux-x86_64`；`ANDROID_HOME`/`ANDROID_SDK_ROOT` 优先，`aapt2`/`apksigner`/`zipalign` 从 `$ANDROID_HOME/build-tools/<ver>` 取最高版本。
- 本次 Windows 侧落地：`E:\nixiang\starry_link`（ASCII junction → `mod菜单/starry-mod-menu`）、NDK `C:\Users\Administrator\AppData\Local\Android\Sdk\ndk\27.0.12077973` 用 `ndk-build.cmd`。

### 2.4 构建元数据必须 ASCII 且可覆盖
- `Application.mk` 里的构建戳一律走「可覆盖 + 过滤」：
  `STARRY_BUILD_EPOCH ?= $(shell git log -1 --format=%ct 2>/dev/null | tr -cd '0-9')`，并在脚本里允许 `STARRY_BUILD_EPOCH=<数字> make`。
- 原因：仓库提交信息含中文/空格时，`-DSTARRY_BUILD_EPOCH=<中文提交信息>` 会让 clang++ 直接把参数当文件路径（报 `The system cannot find the file specified.`），**且报错位置在编译最后一步，极易误判成 NDK 装坏**。
- 推广规则：任何把外部文本（提交信息、主机名、用户名、路径）拼进编译命令的地方，都要先过滤成 ASCII 白名单。

### 2.5 目录与文件路径保持 ASCII
- 仓库目录名含中文时，跨 shell/MSYS 会逐层还原成中文真路径（`cygpath` 反而把 junction 还原）。做法：建 ASCII junction/软链再进。
- 若必须传中文路径给 `bash -lc`，不要内联；写成脚本文件执行（本次踩过：中文 `grep` 交替模式被 PowerShell→git-bash 引号层当作逐词命令执行）。

### 2.6 签名固定 + 只用 `install -r`
- 所有包固定用仓库内 `01_tools/starry_release.jks`（alias `starry`，口令 `starry2026`，证书 `CN=StarryMagic`）。
- 流程里禁止 uninstall；换底包/换签名前先 `04_scripts/勇士之心/ysxz_login_state.sh backup`，装完 `restore`。
- 官方包（`CN=shan…`）与星光包签名不同，二者互转必然触发重装：此时务必先备份。

### 2.7 ABI 策略
- 目标模拟器是 `x86_64 + Houdini`（`ro.dalvik.vm.native.bridge=libnb.so`，`nemud.player_architecture=x86_64`），实际执行的是 **arm64-v8a** 那份 so；x86 副本是死重量。
- 规约：mod 只出 `arm64-v8a`；若确要支持**无翻译层**的纯 x86 模拟器，再另出 x86 并单独验证。不要假设「模拟器 = x86 代码」。

### 2.8 不要碰服务端校验名单里的文件
- 校验名单（`version_update_md5`）：`assets/battleLogic/index.js`、`assets/battleRender/index.js`、`assets/game/index.js`、`assets/main/index.js`（4 个，逐字节 md5）。
- 规约：**出包不得改写这 4 个文件**；需要注入逻辑时改名单外文件（运行时 `files/res/main.js`、`files/res/jsb-adapter/*`、`files/res/src/settings.js` 等），或改成运行时内存注入/数据注入。
- 若必须改这 4 个文件，则不能走联网校验的正式服；实验室环境需在 DNS/iptables 层断掉校验接口并记录。

### 2.9 优先「数据/运行时注入」，而不是重打包
- 本次证明：`files/res` 是唯一有效且免校验的注入面（APK assets 改动在版本一致时根本不生效）。
- 规约：功能注入首选运行时数据（`files/res` 下的引导脚本 / 存档 / 配置），重打包只用于必须改 Manifest/dex/so 的场景。

### 2.10 出包必须在本机模拟器跑一遍
- 出包脚本末尾加「模拟器自检」：安装 → 冷启动 → 抓 logcat 里 mod 与 JS 通道（`Ysxz`、`StarryMagic`、`jswrapper: JS:`）→ 断言无 `not mapped` 刷屏、无 `exitProgram`、无崩溃。
- 真机通过 ≠ 模拟器通过；两个环境都要各跑一次，才算交付。

## 3. 一键自检脚本

`04_scripts/勇士之心/ysxz_mac_portability_check.sh`：静态扫本次踩过的 7 类地雷（硬编码 RVA / 只认 `x` 段 / Mac 绝对路径 / mac-only 命令 / 非 ASCII 构建戳 / 中文路径内联 / 签名与 ABI 配置），输出 `OK/WARN/FAIL` 清单。出包前跑一次。

## 4. 交付定义（本规约的验收口径）

1. 同一份出包脚本在 Mac 与本机都能跑完，不依赖某人主目录；
2. 产物安装到 MuMu（`127.0.0.1:16384`）后冷启动能进游戏，`logcat` 无 `not mapped` 刷屏、无秒退；
3. `install -r` 可覆盖安装且登录态保留；
4. 服务端 `version_update_md5` 的 4 个文件 md5 与列表一致（或明确记录为何不一致）。

## 6. 硬编码路径的批量迁移（本次已执行）

`/Users/<某人>/Documents/nixiang` 这类绝对路径在本仓库 `mod菜单/starry-mod-menu/scripts/`（141 个脚本、168 处）里是历史遗留，是 [3/7] 唯一的 FAIL 来源。已用工具一次性迁移：

```
# 先看要改什么（默认 dry-run）
python3 04_scripts/_common/portable_users_path_migrate.py
# 确认后落盘
python3 04_scripts/_common/portable_users_path_migrate.py --apply
```

替换规则：

| 原形态 | 迁移后 |
|---|---|
| shell 整行赋值 `NIXIANG="/Users/aliang/Documents/nixiang"` | `NIXIANG="${NIXIANG:-$(cd "$(dirname "${BASH_SOURCE[0]}")/../../.." && pwd)}"` |
| `.sh` 行内/heredoc 里的裸 `/Users/aliang/Documents/nixiang/x` | `${NIXIANG}/x`（必要时在 shebang 后补一行 NIXIANG 定义） |
| Python `Path("/Users/aliang/Documents/nixiang/x")` | `Path(__file__).resolve().parents[N] / "x"` |
| JavaScript 引号串 | `(process.env.NIXIANG \|\| require('os').homedir() + '/Documents/nixiang') + '/x'` |
| 不属于本仓库的 `/Users/<某人>/<其它>` | `$HOME/<其它>`（bash）/ `Path.home() / ...`（py） |

迁移后本仓库自检：`FAIL=0 WARN=4`，`bash -n` 全量 0 错、`py_compile`/`node --check` 全通过。

踩过的两个坑（都已修）：

1. **嵌套引号**：`"${VAR:-$(cd "$(dirname "${BASH_SOURCE[0]}")/../../.. && pwd)}"` 少一个收尾 `"`，会让 144 个脚本全部 `bash -n` 报 `unexpected EOF while looking for matching ')'`。正确写法是 `.../../../.." && pwd)}`（`cd "` 那个引号必须闭合）。迁移脚本改完必须全量 `bash -n` 兜一遍。
2. **自匹配**：检查器自己的节标题里含 `/Users/...`，会被 [3/7] 扫到；已把检查器自身排除，并把 `.json/.txt` 记录类文件降级为 WARN（数据快照不算硬编码代码路径），`*.bak/*.orig` 一并排除。
3. 顺带修掉 5 个脚本里孤立的 `|| true` 行（历史上 sed 删行留下的残骸，会让 `bash -n` 直接失败）：`inject_blzz_1.0.30.sh` / `inject_dwct_12.37.sh` / `inject_zhmr.sh` / `inject_zmxy_1.1.0.sh` / `inject_zxr_1.0.3.sh`。
