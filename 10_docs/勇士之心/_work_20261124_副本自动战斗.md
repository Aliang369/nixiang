① **buff 持有查询本体放行**（`hookAutoBuffHold`）
- 事实：`gdg()` → `ccf(800)`（game L223562-223565）→ 叶子 `cce(buffId)`（L223550-223561）。
- 1.1.22.0 自动战斗是一族：`AUTO_BATTLE=800`、`PREMIUM_AUTO_BATTLE_1..6=801..806`（main L36607-36613），另有 `AUTO_BATTLE=107 / PREMIUM_AUTO_BATTLE=109` 的 BuffType 族（L36688-36690）。
- 做法：从 `$eZ.cfgMgr.tbl.BuffChildTable.VOList` 反查 `buffType ∈ [800,806]` 的 childId，在 `$eZ.buff` 子对象上按指纹 `expiredAt + useCount + return !0`（明文服务端字段名）找到 `cce` 本体并包装：命中族内 id 返回 true，其它 id 原样透传。**调用入口换成谁都成立**。

③ 闸门：两处都只在 `FEAT(5)` 开启时生效；关闭即原样透传。菜单项与 Java 源码零改动。

### 9.3 "本地回执兜底"（用户新思路）评估：不建议实施
| 分支 | 代码 | 后果 |
|---|---|---|
| 本地（普通冒险） | `battleMgr.bHh = r; nf.bFS(r)`（battleRender L11005-11006） | `bFS` 把 `{type:$uX.e, autoBattle:r}` 塞进 `bEN` 队列（game L205945-205951）；该队列**只在本地战斗控制器逐帧更新里被取走**：`i.bFT()` → 拼进 `events` → `battleLogic.gi(frames,true)`（game L251788-251801）→ `Gl(i,member,on)` 写成员位 `djr` 并调 `Gk` 启动游戏自己的 AI（battleLogic L1125-1141） |
| 副本（在线局） | `battleMgr.bHy(r)` → `bHw` → RPC `reqAutoBattle`（game L206652-206688） | 服务端回包决定成员位；客户端每次 `$wc.o` 事件用**服务端成员位**回写 `bHh`（battleRender L2206-2210 `bsI`），`bHy` 前置也要求 `bGk`（本局带 connectInfo） |

判断：副本局是**服务端权威**（成员位、帧序列均以服务端为准）。只在本地跑 `bFS` 的后果：
1. 本地 UI/本地 AI 会短暂动起来，但下一次服务端成员同步（`bsI`）会把 `bHh`/`djr` 覆盖回 false ⇒ 又变"没反应"；
2. 本地产生的自动战斗动作进不了服务端的帧序列（线上走 RPC/战斗服帧），可能被判非法输入 / 帧序列异常；
3. 若服务端做动作校验，风险是**异常数据、踢线、封号**；且这已越过硬约束 #11「只放行按钮可点，不接管战斗」。

⇒ 不做本地兜底。若要真正解决，只有服务端授予 `AUTO_BATTLE` 权益（账户/付费/运营侧），不在客户端范畴。
