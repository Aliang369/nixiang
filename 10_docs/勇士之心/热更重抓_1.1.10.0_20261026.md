# 勇士之心 · 热更 res 1.1.10.0 重抓（2026-10-26）

> 触发：雷电 `emulator-5554` 实测 1.0.3 星光包时，用户报「伤害倍率 / 无敌 / 秒杀 / 无限技能 /
> 移动速度都不能用；战斗加速、自动战斗可用」，随后又报「自动出售没效果，自动重复可以」。
> 结论：**都不是补丁逻辑写错，而是 res 从 1.1.9.1 升到 1.1.10.0 后短名整体换语义 + 采集范围失效**。

## 2. 根因 A：短名采集范围被缩成单个模块（战斗五项静默全灭）

实机日志（修复前，pid 3923）：

```
[MODMOD] boot: 57 modules, toString OK          ← 战斗包 57 个模块
[MODMOD] harvest scope: $KC                     ← 只采了 1 个模块（伤害公式）
[MODMOD] names: hx=hy.bnq camp=undefined.undefined ctx=undefined/undefined/undefined hp=undefined world=undefined
[MODMOD] formula call #1 d=311 mineAtk=false mineTgt=false ...
```

`harvestIds` 的旧规则是「模块源码必须同时含 `maxApDefRate` + `baseCritDamage` + `atkEntity`」。
1.1.10.0 里这三者只在伤害公式模块（`$KC`）共现，而**实体阵营 / 血量 / 世界引用都在别的模块**：

| 锚点（全包唯一命中） | 原文位置 |
|---|---|
| `case "isPlayer": return t.hy.bnq` | 敌人筛选模块 |
| `v.hE.bma === y !== f.isPlayerCamp`（`y = this.context.bou.fF[0].dga`） | 技能选怪模块 |
| `o.bhG = Math.max(o.bhG - a, o.lockMinHP)` | 实体扣血口（`hY` 体内，`o = this.hw`） |
| `e.hj.bou...`（129 处） | 实体 → 世界引用 |

⇒ `camp/hp/ctx/world` 全 `undefined` ⇒ `isMine()` 恒 false ⇒ 伤害倍率 / 秒杀 / 无敌 / 无限技能 /
移动速度（走 `isMyHero`）**全部静默失效**；战斗加速与自动战斗不依赖 `isMine`，所以一直正常。

**修法**（`ysxz_anticheat/baseline_patch_from_shipped_so.js`）：
- 采集范围改为**本 bundle 全部模块**，含战斗明文的排前面（`N` 本来就是 per-bundle，跨包串名不会发生）；
- `harvestB` 去掉「模块必须含 `lockMinHP`」的硬门槛，支持 `e.hj.bou.` 这类非 `this.` 前缀；
- `campOf` 删掉 1.1.9.x 写死的 `blW/blX/blY`，改为「类型校验 + 用世界里的队伍阵营值做结构对拍」，
  失败时打 `camp probe fail` + 组件键名清单（下次可在 logcat 直接定位，不必再让用户跑一场）。

修复后实机（pid 4975）：

```

[MODMOD] formula call #1 d=311 mineAtk=true mineTgt=false
         campVals[hD=hE camp=bma world=hj val=number:1 my=1]
```

## 3. 根因 B：自动化层依赖的短名换语义（自动出售/分解/穿戴全灭）

实机日志（修复前）：

```
[AUTO] warn: 结算面板: fguiMgr.cUU.bdG 不可用 —— 拿不到结算时机
[AUTO] warn: 自动重复挑战: localMgr 下没有 autoBattleFlag 容器（cnh/cms 都不在）
[AUTO] state@60s {"panels":0, "sell":0, "deco":0, ...}
```

`panels` 恒 0 ⇒ 出售 / 分解 / 穿戴的触发链一次都没跑（自动重复看着能用，是**游戏自己的
`autoBattleFlag` 位**在起作用，与本层无关）。1.1.10.0 的短名不是改名，而是**换了靶子**：

| 旧依赖（1.1.9.1） | 1.1.10.0 实际含义 |
|---|---|
| `bag.bZw / bZv` 按品质批量出售 / 分解 | 无参的背包红点检查（不发协议） |
| `localMgr.coe / cof` 出售 / 分解品质位 | 音效 / 音乐音量 |
| `localMgr.cod` 自动挑战设置位 | 城镇显示人数 |
| `equip.fFu` 穿戴提交 | 宝石镶嵌（`gemInfoCfg`） |
| `fguiMgr.cUU.bdG(name)` 取面板实例 | 已改作他用（链不存在） |

**修法**：自动化层整体改成**明文锚点 + 结构指纹在真实对象上发现**（`hook-rules §24`），
不写死任何混淆短名；面板时机改吃 baseline 事件 `window.__starry_fin`。

| 用途 | 1.1.10.0 接口 | 指纹（只用明文/UI 子节点名，均离线校验唯一命中） |
|---|---|---|
| 结算面板打开 | `AdventureFinishPanel.prototype.wA` | 含 `battleMgr` + `btnList` + `btn_again` + `btn_toNext` |
| 再次挑战倒计时 | 面板原型上的 `ekx` | 含 `auto_btn_again` |
| 按品质批量出售 | `bag.bZA(qs)` → `pg{bagType:EQUIP, list:[{gridId,num}]}` | 1 参 + `num:` + `.pg(` + `quality` |
| 按品质批量分解 | `bag.bZz(qs)` → `bXQ{bagType:EQUIP, gridList}` | 1 参 + `gridList` + `quality` + `isLock` |
| 一键穿戴候选 | `equip.fDb()` → `[itemUid…]` | 0 参 + `WORE_EQUIP` + `new Map()` + `itemUid` − `SOUL` |
| 一键穿戴提交 | `equip.fFP(uids)` → 按 10 件分批 | 1 参 + `items:` + `.slice(` + `+ 10` |
| 自动重复挑战位读/写 | `localMgr.cog(1)` / `coh(1,on)` | 1/2 参 + 字段 `autoBattleFlag` |
| 出售/分解品质位读 | `localMgr.coi(q)` / `coj(q)` | 1 参 + 字段 `autoSellEquipFlag` / `autoDecomposeEquipFlag` |

游戏自己的 `AdventureFinishPanel.wA` 里也是同一套：
`x=[COMMON,SENIOR,RARE]; N=x.filter(q=>localMgr.coi(q)); N.length&&bag.bZA(N);`
（但它在金卡门内，我们按菜单开关独立调用，不依赖金卡）。
