## 2. 实现点

- 引擎与加载路径：Cocos Creator 2.4.15；`se::ScriptEngine::evalString` splice；
  金卡特权方法位于**独立** `assets/game/index.js` bundle（不在 `battleLogic`）
- Hook 点：金卡管理器的 `AUTO_BATTLE` 谓词原型方法（**禁写死混淆名**；1.1.4.0 热更名为 `fDj`）
  → 开关开启时返回 `true`，由 battleRender 的按钮处理走官方自动战斗链
- 两条装钩路线（**运行时判据互斥，禁机型/模拟器名单分叉**，hook-rules §31）：
  ① 原生 `evalString` splice（真机快路径，截获成功才写 `files/ysxz_native_ok`=pid）；
  ② main.js JS 自举（MuMu/Houdini 下原生挂「影子映射」不命中时接管；读同 pid 证明则让位）
- 开关与默认值：新版菜单 feature #6（旧版 #5），默认 OFF
- 关键文件：`04_scripts/勇士之心/ysxz_1.0.3_menu/{YsxzMod.cpp,YsxzPatchJs.h}`、
  `04_scripts/勇士之心/{gen_ysxz_boot_js.py,ysxz_mainjs_patch.py}`

## 4. NOT PROVEN

- 真机侧「长时间连续自动战斗」稳定性（本轮只验了进战斗开关一次通过，未做长时间压测）
- 服务端对自动战斗行为的风控结论
- 验证所需条件：一局完整长时间战斗 + 服务端侧观察；停止条件：出现回档/封禁迹象即停

## 5. 已知限制

- 现象：热更可能再次改名 buff 管理器方法（历史上已发生两次：`bVs`→`bXP`→`fDj`）
- MuMu/Houdini 下同 so 双映射：Dobby 可能挂在**影子映射**上「成功但永不命中」——
  不要用 `DobbyHook` 返回值当生效证据，只认 `ysxz_native_ok` / `MODMOD` 日志；自举会兜底
- `files/res/main.js` 自愈只认 pristine/patched 两种形态；热更换 res 后变陌生版本则不动（防误伤）
- 适用范围：Cocos JS + evalString splice / main.js 自举路线；本作 feature #6
- 若再失效，下一条最小区分实验：
  1. 读 `files/res/version` 的 `localResVsersion` 判断是否资源漂移；
  2. 看 `!! auto-battle candidate … rejected by fingerprint` 诊断行；
  3. 跑 `simulate_ysxz_discovery.py <新解密目录> --auto-fp NEW --fingerprints`；
  4. 若指纹命中失败 → 按 `skill/re-extract/hotupdate-fingerprint-recheck.md` §4 查漂移形态。
