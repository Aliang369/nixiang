## 4. 构建链缺陷（重要，已绕过并需修链）

现象：第一版重打包（`..._releaseSigned-revertmenu.apk` 初版）装上后**启动即崩**：
`
java.lang.RuntimeException: Unable to start activity ... AppActivity
Caused by: java.lang.NullPointerException: Attempt to read from field 'java.util.HashMap com.bingo.sdklibs.utils.AppInfo.parameters' on a null object reference
  at com.bingo.sdklibs.utils.PluginHelper.getMetaValue(PluginHelper.java:77)
  at com.bingo.sdklibs.utils.PluginHelper.initWithMainActivity(PluginHelper.java:46)
  at com.bingo.cocos.bridge.BingoActivity.onCreate(BingoActivity.java:80)
`

排查（三步对照实验）：
1. 同包 + **把 so 换回已装包字节**（arm64 294,376 / x86 303,428 / v7a 243,328）→ 仍崩 ⇒ 与 so 版本无关。
2. 重装**原始已装包**（`13_scratch/menu_diag/base_installed.apk`）→ 正常 ⇒ 与设备数据/签名无关。
3. 重装**另一条线的 08_output 签名包** → 正常 ⇒ 当前源码树本身没坏。
4. 比对两个包的条目清单，差异只有 7 项，其中 3 项是 `lib/{arm64-v8a,x86,armeabi-v7a}/libc++_shared.so` **只存在于正常包里，我的包里没有**。

根因：`surgical_ysxz_1.0.6.sh` 里 libc++_shared.so 是“有就拷、没有就静默跳过”：
`
[[ -f "$NDK_CXX" ]] && cp "$NDK_CXX" ...
cxx="$(_libcxx_for "$abi")"; [[ -f "$cxx" ]] && cp "$cxx" ...
`
本次这些路径在 MSYS 下取不到（NDK shim `/tmp/ysxz_ndk` 下的 toolchains 软链解析失败），三份 libc++_shared.so 全被跳过。缺了它 libstarry_magic.so 无法 dlopen ⇒ 壳自检失败置 dirty ⇒ Application.onCreate 被跳过 ⇒ bingo SDK 未初始化 ⇒ 上述 NPE（正是 manifest 注释里写的那条失败链）。

最小修法（未实施，避免本轮再动共享脚本）：把三处 `[[ -f ... ]] && cp` 改成**硬失败**：
`
[ -f "$NDK_CXX" ] || { echo "ERROR: libc++_shared.so missing ($NDK_CXX)" >&2; exit 1; }
`
本轮绕过方式：组装后把已装包里的 3 份 libc++_shared.so 按字节写回 zip（不重编任何 so），再 zipalign + apksigner。
