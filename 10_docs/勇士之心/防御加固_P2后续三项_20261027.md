# 勇士之心 · 下一步三项（待排期，2026-10-27 记录）

> 背景：P2-2（载荷加密）已完成并经用户实测通过。以下三项是"再往上顶一层"的待办，
> 目标都是同一个：**别人拿不到真载荷、拿到也追得到人**。

---

## 一、载荷改 OTA 下发（优先级最高）

### 要解决什么
现在 `K_build` 虽然在票里，但**密文和密钥最终都会在运行时同时出现在内存里**。
有正版卡密 + 会逆向的人可以 dump 出明文载荷、硬编码进改过的包发给别人。
**包里有密文就永远有这个空间**。唯一根治办法：**包里不放载荷**。

### 做法
1. 服务端新增 `POST /v1/payload`（需有效 v3 票 + 设备号）：
   - 校验票（复用 `verify_grant_v3`）→ 取 `build_id`/`payload_sha` → 返回该 build 的载荷密文 + 一次性 nonce
   - 响应体积 ~117 KB（≈ 现在的载荷），gzip 后更小
2. 客户端：启动时（`StarryInitProvider` 之后、Cocos 加载 bundle 之前）异步拉取 → 内存解密 → 交给 `HookedEvalString` 拼接
3. **不落地明文**：只在内存里持有，用完（注入完成后）立即清零释放
4. 缓存策略：按票有效期缓存在内存（`offline_cache_seconds` 内断网可用），**不写磁盘**

### 关键设计点
- 密钥改成**每会话一把**（服务端下发时生成，随响应一起返回，用票公钥/RSA 封装）⇒ 没有静态 `K_build` 可硬编码
- 失败降级：拉不到 ⇒ **不注入任何 JS**（游戏本体照常能玩），下次进程再试；**绝不能崩**
- 首次启动多一次请求（~117 KB），需测弱网/断网路径

### 代价与风险
- 工作量：**1–2 天**（服务端接口半天 + 客户端加载链半天 + 联调/降级测试半天）
- 风险：加载时序（必须在 bundle eval 之前拿到载荷）；断网时功能不可用（可接受，游戏能进）

## 二、每卡密水印（防倒卖追溯）

### 要解决什么
现在能防"改包直接用"，但**挡不住有人 dump 出载荷再分发**。既然拦不住，就要能**追到是谁流出的**。

### 做法
- 水印值：`wm = base32( HMAC(server_secret, card_id) )` 取前 8–10 位（不可逆，但服务端可对账反查）
- 载体（都不影响功能，任选其一或组合）：
  1. 菜单面板底部一行小字（12px、半透明）
  2. 启动 toast 文本末尾（现有 toast 机制）
  3. 一处 JS 全局变量名（`window.__w_<wm>`）—— 抓包/dump 就能看到，最隐蔽
- 服务端：签发 v3/v4 票时把 `wm` 放进票里；客户端从票里取（不改载荷、不联网）

### 代价与风险
- 工作量：**半天**（服务端算 wm + 客户端显示 + 后台按 wm 反查卡密）
- 风险：几乎为零（纯展示层）；注意别加进功能列表变更（`menu_template.json` 要同步说明）

## 三、诱饵/异常上报（让后台看见谁在分发）

### 要解决什么
现在诱饵只打本地日志（`payload key absent -> decoy`），**你后台看不到**。

### 做法
1. 服务端新增 `POST /v1/report/anomaly`：字段 = `build_id` + `device_fingerprint` + `reason`（枚举：`no_key` / `unseal_fail` / `integrity_fail` / `decoy_used`）+ `count`
2. 客户端在以下时机上报（**每进程最多一次**，带随机延迟 5–30 s，避免特征明显）：
   - `sginteg` 判决失败
   - `GetPatchJs()` 落到诱饵
   - `sgauth::live()` 三判据任一不满足**且**用户试图开功能
3. 后台：按 `build_id` 聚合，出现"同一 build 大量不同设备上报" ⇒ 该 build 被改了、正在传播
4. 隐私：只报设备号哈希前 12 位 + build_id，不报卡密

### 代价与风险
- 工作量：**半天**（接口 + 客户端上报点 + 后台一个列表页）
- 风险：上报接口要限流（防被刷）；上报失败必须静默（绝不能因上报失败影响游戏）

---

## 建议顺序

1. **水印**（半天，零风险，先能追溯）
2. **上报**（半天，让后台有数据）
3. **OTA 下发**（1–2 天，工作量最大但收益最高：包里没载荷，硬编码 `K_build` 也没东西可解）

> 前两项做完，即使有人 dump 分发，你也能定位到卡密；OTA 做完才是"连 dump 的价值都打折"。
