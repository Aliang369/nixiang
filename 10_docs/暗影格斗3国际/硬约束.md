# 暗影格斗3 国际服 · 硬约束

> 游戏级约束，只对本游戏有效，不对外推。A 区=长期生效，B 区=任务级。

## A 区（长期生效）

### A1 禁止在 InvalidHashes 未消失前启用任何功能

- 来源：2026-11-07 实测事故，两次封号（1 小时 / 1 天），原因 violation of the rules of the game
- 依据：官方包不注入零错误；一旦注入（wrap/frida/改包）即出现 `error=<b>InvalidHashes`，属服务端主动报警
- 做法：注入后**功能必须全关**（倍率=1、上帝=false），先打 3~5 场确认日志零 `InvalidHashes`，才允许开功能
- 范围：本游戏全部渠道、全部版本

### A2 禁止改包（任何内容改动）

- 来源：2026-11-06 实测。改包后签名可伪造通过（10004→10005），但服务端内容哈希校验拒绝
- 依据：官方内容包 sum=`BDA35C9A…`，只加两个 so 即变 `DDA1AF18…`；sum 每次运行还带随机因子（同包四跑四值）
- 范围：本游戏 Google Play 渠道

### A3 禁止 frida 注入

- 来源：2026-11-07 对照实验。官方包+frida 必报 `InvalidHashes`；官方包无注入零错误
- 范围：本游戏全部渠道

### A4 功能倍率上限 2.0，上帝模式默认不开

- 来源：2026-11-07 封号事故。倍率设 10 且 A/C 双路 hook 叠加成 100 倍，日志 `0.020 -> 0.198 -> 1.979`，服务端直接判违规
- 做法：只挂单路 hook；倍率 ≤2；上帝模式（玩家不掉血）最易被识别，非必要不开

## B 区（任务级）

### B1 本游戏当前状态：已停止

- 2026-11-07 用户口径：「这游戏我不再碰了」，收尾清理完成
- 重启条件：必须先解决 `InvalidHashes`（见 games/暗影格斗3国际.md「如果将来还要做」）

## 已知可用但带副作用的做法（D 类，非约束）

- **wrap 注入**：`setprop wrap.<pkg> LD_PRELOAD=<so>` + `chcon u:object_r:system_lib_file:s0 <so>` 可让 so 加载、hook 生效、功能可用；但进程内多出的 so 会被 ACTk 发现 → `InvalidHashes`。self-hide（过滤 maps / dl_iterate_phdr）实测无效
- **root 内存读写**：值可改可读回（0.5→0.1 确认），但血量类数据由服务端下发，改本地无效
- **国服**（com.wanda.sf3.wd，TapTap）无此层校验，可直装；两渠道难度不可类比
