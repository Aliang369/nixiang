## 1. 网络层实现

### 结论
1. **游戏业务流量全程明文，无 sign / 时间戳 / nonce / 加密 / 压缩**。主通道是 **WebSocket 文本帧**，帧内容就是 `api 名 + JSON` 直接字符串拼接。
2. HTTP 通道（`XMLHttpRequest`）**只用于登录** `authorize/login`，唯一自定义头是 `UID`。
3. **token 走 WebSocket 子协议头**（`new WebSocket(url, [token])`），请求体里只有 `Profession` / `BatMode` 两个公共字段。
4. **客户端完全可以在 JS 层按 api 名拦截/改写请求与响应**——注入点极清晰：包 `cc.Service.Network.Send` 改请求、包 `cc.Service.Network.__callbacks`（或 `Register`）改响应。
5. 不存在 `HttpsSend` / `HttpSend` 函数。任务书给的锚点 `main.index.js:45999` `Send: function(e)` **不是网络层**，是聊天弹幕 `message/send`。

## 3. 反外挂 / 风控

### 结论
1. **客户端零本地校验**——没有战斗时长上限、伤害上限、秒杀检测、DPS 比值检测中的任何一项（grep 作弊/外挂/封号/检测/审计/risk/cheat/audit + 时长/秒杀/上限 全部无本地判定命中）。
2. 惩罚**全部由服务端错误码触发**，客户端只负责弹窗/踢回登录。字段名统一是 **`ErrCode`**。
3. 关键错误码：
   - **`errData`** → 只存在于 `chapter/result`：弹「数据异常 / 账号已被审判之眼关注」→ 强制回 `SplashScene`（**最可能被伤害/倍速类改动触发的码**）。
   - **`invalidData`** → 队伍创建/加入：弹「数据异常，无法进入团本」→ `cc.game.end()` 直接杀进程。
   - **`ban` / `tokenBan` / `tokenErr`** → 登录期封禁/失效。
4. **服务端是战斗权威**：每次结算后客户端把自己的 `result` 清零，改用服务端回传的 `Mid / Mlv / Mqe / Mhp` 重建下一波怪——即服务端掌握怪物血量与波次生成，可对上报 `Dam` 做模型比对。

## 4. 存档 / 云存档

### 结论
**不存在本地存档上传接口。** 该游戏是**纯服务端权威存档**：进度（Objects/Equipments/Skills/Mounts/Spoils/Exp/Tasks/Renowns/Mails/Achievements/Trips/Manuals）全部由服务端持有并以 delta 下发，客户端本地只存 token。
- 「屏蔽存档上传」**无需做、也无处可做**（不存在这个功能）。
- `save/cloud/backup/archive/upload` 在 `Send(...)` 中 **0 命中**；
- 全文件「同步」只有两义：**资源热更**（90183/90371）与 **队伍状态同步**（92829）；
- 无版本号/校验字段的存档协议。

### 证据
- 差量同步（`main.index.js:55320` `ProcessObjectDelta`）：服务端→客户端的 `Subs` 增量即「存档」。
- 本地持久化只有 `main.index.js:55782` `Save: function(e,t){ cc.sys.localStorage.setItem(e, JSON.stringify(t)) }`，实际使用点 `main.index.js:56040` `cc.Service.Save("data.user", i)`（**只存账号/token**）。

## 7. 登录 / 鉴权链

### 结论
1. 登录入口 `cc.Service.Network.Login`（`main.index.js:55962`），凭据来源 `GetAccAndPwdAndToken()`（56026），三种形态：`{Opera:"token", Acc:<token>}` / `{Opera:"login", Acc, Pwd}` / SDK 字符串。
2. token 持久化在 **localStorage**（`cc.Service.Save("data.user", i)`，56040），键 `data.user`；`Save` 实现 55782。
3. token 同时作为 **WebSocket 子协议**传递（56079），HTTP 侧靠 `UID` 头（56186）。
4. **没有设备指纹**：游戏自有协议里 grep `deviceId/device_id/imei/oaid/android_id/macAddress/idfa` 的命中**全部**落在 wx/douyin/ks/qq 小游戏 SDK 副本（`main.index.js:48098-50458`）、且 `idfa` 被置空（48660）；Android 真机链路不上报 IMEI/OAID/机型。→ **换机不会因指纹变化被判异常**（置信度 中，因为 native 侧 SDK 可能自行采集 OAID）。
5. 多开：判断依据是**账号（`GetOpenId()` 返回 `__user.Acc`，56134）**，同账号二次登录会走 `Reconnect()`/`reconErr` 互踢（56119、55810-55824），**不是封号**。
6. 「设备/一键登录」分支在 55981（`AppController.loginSDK:` / `AppActivity.loginSDK`）；xipu 渠道额外走 `ProcessCheckData`（55805，疑似实名/合规校验）。
