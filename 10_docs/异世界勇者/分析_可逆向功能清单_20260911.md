## 2. 架构判定：哪些功能真的能改（**本节决定一切**）

### 2.1 明确的服务端权威

- 客户端注册/发送 **300+ 接口**（`Network.Register` / `Network.Send`，完整清单见 y54283 `loadApi`）。
- 开局 `RoleScene` 一次性拉取 36 个 `*/all`（role/skill/equipment/bag/task/chapter/mall/mount/draw/legion/…），
  之后靠 `ProcessObjectDelta`（y55320）**服务端 delta 增量覆盖本地状态**。
- 结论：**背包、货币、等级、装备、解锁、抽卡、任务、邮件、军团、拍卖行全部服务端持有**。
  客户端直改这些字段 → 下一次同步即被覆盖，且大概率触发异常上报。

### 2.2 客户端权威（可改）

- **战斗是本地模拟的**：`chapter/forward` 只下发怪物参数（`Mid/Mlv/Mqe/Mhp`，y32041），
  战斗由本地 `BattleService` 逐帧跑，打完才把 `state.result` 上报（`chapter/result`，y32168）。
- **`.jsc` 全部明文可注入**，JS 层任意覆写。
- `UIHelper`、`Skill`、`Store`（本地特权判定）、`Battle`、`Task`(UI) 等层可自由改。

### 2.3 上报字段（**决定伪装策略**）

`state.result` 结构（y31614）：

```js
{ Mid, Hp, Php, Atk, Patk, Def, Pdef, Mhp, Dam, Score, Score1, Score2,
  Free, Mixed, StrScore, GemScore, MstType, MstLevel, Version }
```

`Php/Patk/Pdef` 由 `node.CheckResult`（y13581 / y14092，调用点 y32551）在结算时写入：
`Php=玩家maxHP、Patk=玩家atk、Pdef=玩家def、Ssm=max(暴击+回避+减伤+增伤)`。

→ **服务器知道你账号的真实面板**（它自己发的 `role/all`），却收到你上报的面板与总伤害 `Dam`。
若 `Patk` 与 DB 不符，或 `Dam / 时长 / Patk` 超阈值 → **`ErrCode: "errData"`**
（y31794 分支：弹「检测到数据异常，账号已被审判之眼关注」并强制回登录页 y31839）。

**这是本游戏唯一真正的反作弊点，也是所有数值类功能必须先解决的设计约束。**

## 4. 星空版建议方案（菜单形态）

### 4.1 注入实现

1. `libcocos2djs.so` 内 `DobbyHook` 导出符号 `_ZN2se12ScriptEngine10evalStringEPKclPNS_5ValueES2_`（RVA 0x75DCE0）。
2. 在 eval 的脚本文本中做**尾部 splice**：注入 `YsjYzHooks` 补丁段（幂等，锚点命中计数）。
   - 补丁段是**纯 JS 覆写**，不改 `.jsc` 文件本体 → 走外科 zip 组装（只加 so / dex），不重打包。
3. 菜单开关 → Java 层 `Preferences` → JS 侧通过 `Cocos2dxJavascriptJavaBridge.evalString`（RVA 0x702A44）
   下发生效，与既有 Cocos 系游戏（无尽探险队 WjtxdMod、造梦无双 ZmwsMod）同构。
4. 建议新增 `Games/YsjYzMod.cpp` + `Android_ysjyz.mk` + `obj_ysjyz/`，game_id 建议 `ysjyz`。

### 4.2 建议菜单项（分档）

- 无限技能 / 零 CD

- 移速 ×N
- 攻速 ×N
- 全局倍速 ×N
- 去弹窗 / 去公告

**第二档（做，但必须带「上报伪装」）**

- 暴击率 100% / 暴伤 ×N / 闪避 100%

**第三档（不建议：服务端权威，做了也只是自欺）**
