# 异世界勇者 8.1.1 —「人物等级 ≥199 后打怪恒 1 滴血」修复分析（v6）

> 2026-09-27 ｜ 目标包 `com.mudamuda.idlewow` 8.1.1 / vc811（Cocos Creator 2.4.2）
> 现象：人物升级到 199 级后，对怪造成伤害恒为 **1**；伤害倍率滑块拉到 N，打出的伤害就恰好是 **N**。
> 结论：**病因在官方 JS 结算链的护甲减法 + 最低伤害钳制**，星空包原有的「AddHp 侧 ×N」放大是作用在已被钳成 1 的值上，所以永远只能打出「1×N」。修复落在**钳制之前的护甲上限**。

## 一、病因链（`06_dumped/异世界勇者/jsc_decrypted/main.index.js`，行号=该明文）

星空包 v5 的放大发生在 `BattleHero.AddHp` 内（`mod菜单/starry-mod-menu/app/src/main/jni/Games/YsjYzMod.cpp` 的 `applyProto`）：`AddHp` 收到的是**已经等于 −1 的 d**，补丁把它乘 `amp=S.dmg` ⇒ 扣血恰好 = 滑块值。所以「拉 1000 倍打 1000」不是巧合，而是 `1 × N`。

**为什么恰好是 199 级**：JS 里**没有**以 199/200 为界的常量（`grep -n 199` 仅 main.index.js:47343/73110/76877 三处无关命中；`Math.pow(.*level` 0 次；`ObjectMaxLevel` 的 60/100/150/200/250/300/350/400 是装备档位）。阈值来自**数据侧交叉**：

- 怪物战斗属性 = 配置表值 × `Ratio`，`Ratio = 1 + .2 × (怪物等级 − 1)`（main.index.js:32228，落点 main.index.js:13638-13640）。怪物等级由服务端下发（main.index.js:31786 / 31815 `this.LoadMonsters(e.Mid, e.Mlv, e.Mqe, e.Mhp, …)`，定义 main.index.js:32171 `this.state.Monster.Level = t`）。
- 设备配置表（`files/packet/assets/resources/import/d0/d0318d86-….json` 内 `cc.TextAsset name="configs"`，156 张表）实测：`ConfigMonster` 的 `Def` 极小（关卡怪 35–185），`ConfigChapter.Chapter35` OpenLevel=195、Levels=196-200（黑暗森林），`Chapter34` OpenLevel=190，`Chapter36` OpenLevel=200。
- 于是 Chapter35（怪等级 ≈200）有效护甲 = cfgDef 49 × 40.8 ≈ **1,999**，怪血 ≈23,134，怪攻 ≈5,508。
- 玩家若靠倍率速升到 199 级、装备（攻强）没跟上，攻强就停在 ≈2,000 量级 ⇒ `d = 攻强 − 护甲 ≤ 0` ⇒ main.index.js:29807 钳成 1。**这就是 199 级的真身：不是等级门槛，是「章节怪护甲 ≈ 2000」撞上「没装备的攻强」。**

## 二、修复（v6）

在 `YsjYzMod.cpp` 的 JS 补丁 `applyProto` 中，于 `AddHp` 包装之后、`Extneds` 包装之前新增两个包装（幂等由 `wrap()` 的 `fn.__ysjz` 保证）：

1. **`Damage` 包装**（仅在我方出刀时记忆本刀攻强）
   ```js
   if (S.dmg > 1 && this && this.grp === 1 && typeof this.GetAtk === "function") {
     av = this.GetAtk(o);   // o = 技能 id，与 main.index.js:29001 同参
   }
   S.ax = av;  // try / finally 还原
   ```
2. **`GetDef` 包装**（只对受击的怪做护甲上限）
   ```js
   if (S.ax > 0 && this && this.grp === 2 && v > S.ax * 0.8) {
     return S.ax * 0.8;   // 前 8 次打 [ysjyz] armor-clip 日志
   }
   ```

反推 main.index.js:29158 之后 `d ≥ 0.2 × 攻强 > 0` ⇒ main.index.js:29807 **永不触发** ⇒ 滑块乘的是真伤害。边界：

- 护甲本来就 < 80% 攻强（正常高攻玩家）→ 上限不生效，官方公式**分毫不差**；
- `S.dmg ≤ 1`（功能关 / 倍率 1）→ 完全不介入，保持官包原味；
- 怪物打我（攻击方 `grp===2`）→ `S.ax=0`，我方的护甲绝不被削；
- 只改护甲这一条路径，`limitDam` / `igrDam`（铁壁）/ `DefenseBuff` 护盾 / `aiScript.OnSubDamage` 等官方旁路原样保留。
