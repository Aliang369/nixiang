## 成功标准（三句话）

### 1. 在哪读签？

**不在 `sub_6EE30` 静态解密输入里，也不在独立 native `checkSign` 函数。**

| 层级 | 结论 | 证据 |
|---|---|---|
| `sub_6EE30` / `sub_91D48` | **不读 APK 签名** | 输入为 so 内嵌 blob `@ 0x100000`（文件偏移 `0xFC000`）；头 32B 明文 + `0x20+` XOR；xxHash 两趟固定种子 |
| native 明文 | **无** `signature` / `Certificate` / `SHA256` / `META-INF` | MCP rodata 全库扫描 |
| Kiwi VM `sub_6897C` | **运行时 JNI** 读 live `PackageManager` / `ApplicationInfo` / APK 路径 | `.rodata` 字符串池 `0x92600–0x92900`（无 direct code xref，VM 字节码索引引用） |
| dex 解压 | VM 用 **`%s/classes.dex`** / **`%s/classes.dex!classes%d.dex`** 从 **当前 APK 路径** 抽 dex | `@ 0x92BB6` / `0x92BC5` |

→ 读签（或「签不对则不抽 dex / 不解 jiagu」）发生在 **VM 解释器运行时**，通过 JNI 链拿到 **已安装 APK** 的 `PackageInfo`/路径后再处理；`SignSpoof` 只能骗 Java PM，**管不到 VM 内 native 路径或 jiagu 链**。

### 2. 和什么比？

| 类型 | 状态 |
|---|---|
| TapTap SHA256 / 证书 DER 硬编码 | **未发现**（so 内无 `57bffb7c…` 前缀） |
| VM 字节码内 compare | **待 dump**（`sub_6EA88` 自定义 LZ 解压后 ~107KB VM 程序；本地 Python 移植未完成） |
| 间接绑定 | 改签后 **零改动仅重签** 同样 `ClassNotFound: com.q1.sdk.*` → 比对对象是 **原版 TapTap 签名下的 APK 完整性**，失败则 jiagu 链不解出 Q1 dex |

### 3. 失败怎么死？

| 阶段 | 机制 | exit/现象 |
|---|---|---|
| native 魔数门槛 | `sub_68598` 解压后 `v7[1]!=0x03000000` / `(v7[2]\|8)!=0x343649` | exit **22117** / **16741**（#4 NOP 已证无效） |
| VM 返回非 0 | `sub_6897C` → `exit(v40)` | 动态 exit（#2 分支 patch 可绕过但仍死） |
| dex 链断裂 | jiagu 未解出 Q1 SDK dex | `ClassNotFoundException: com.q1.sdk.*` |
| 最终 kill | `libKwProtectSDK` 或父进程 | **signal 9**（~200–500ms，#2/#4 均如此） |

## 启动链（native，MCP 实锤）

```
JNI_OnLoad @ 0x2E010
  a1[2] = &unk_100000          // 内嵌 blob（非 APK 动态输入）
  └─ sub_68598 @ 0x68598
       ├─ sub_6EE30 @ 0x6EE30   // xxHash32(0:16) → seed; xxHash32(16:32) → XOR key; 解密 0x20+
       ├─ sub_6EA88 @ 0x6EA88   // 自定义 LZ 解压 → VM 字节码 (~107776 B)
       └─ sub_6897C @ 0x6897C   // VM 解释器（handler 表 off_121580 → sub_6965C…）
```

### `sub_6EE30` 输入结构（修正 2026-08-27 晚）

**文件偏移 `0xFC000` / VA `0x100000`：**

| 偏移 | 内容 |
|---|---|
| `0x00` | `0xDF69` = 57193（加密区长度相关） |
| `0x04` | `0x1A500` = 107776（解压目标大小） |
| `0x10` | `"A64\0"` 壳标识 |
| `0x14` | `0x1A518` = malloc 大小 (= 107776+24) |
| `0x20+` | XOR 密文（key = `xxhash(0:16)` \| `xxhash(16:32)<<32`） |

**重要修正：** 此前「改签改变 xxHash 输入 → 解密错」**不成立**；blob 完全静态，#4 magic NOP 仍 ClassNotFound 与此一致。

### VM 字符串池（ART 拉起真 Application + 抽 dex）

`0x9267F` 起连续 JNI 名（节选）：

```
ActivityThread.currentActivityThread → getPackageName → getClassLoader
→ LoadedApk / Application.attach → getPackageManager → getApplicationInfo
→ metaData / KWS_MAIN_APP / containsKey / getString
→ mPackageInfo（LoadedApk 字段）
```

`0x92BB6` 起 dex 路径格式：

```
%s/classes.dex
%s/classes.dex!classes%d.dex
```

另有：`grep` / `reboot` / `linker` / `ro.enable.native.bridge.exec`（反调试/环境检测 opcode）。

### native 辅助

- `sub_3FFFC`（~21KB）：JNI 方法名 XOR 解密（`byte_1219xx ^= imm`），供 VM 调用 Java
- `sub_91D48`：xxHash32，**仅** `sub_6EE30` 调用
- handler 表 `0x121580` → `sub_6965C`…`sub_696F8`（多数 thunk 到 `sub_8C5xx`，返回常量）
