# 王国大作战：前线 — 实机重验与保护面测绘（2026-08-28）

> 本文档全部结论来自 **2026-08-28 实机 A/B 实验**（设备 f9a116a2），修正 2026-08-27 文档中的推测性结论。
> 旧文档（VM读签/kadp过签/渠道块）仅作线索，多处已被本次实验证伪或收窄。

## 一句话结论

**真正的大门是 `libKwProtectSDK.so` 的启动完整性扫描 + Q1 SDK 的 PM 证书校验，两层都过之后游戏可以进 Unity。**
改签包的正确打开方式 = **root 原地替换安装路径 base.apk 为官方字节**（须 `--no-incremental` 全量安装）+ 解决 PM 证书（未完）。

## 已实锤（PROVEN，全部一手）

| # | 实验 | 结果 |
|---|------|------|
| 1 | 外科包（官方 Manifest + classes5 + starry so + **原版 KwProtect**）装机后 root 替换 base.apk = 官方字节（md5 `c3b11b00…` 一致） | ✅ **Unity 起来了**（libil2cpp 加载），无 signal 9，无 ClassNotFound，进程存活 40s+，停在 Q1 弹窗「当前游戏包不合法，请到应用市场下载！」 |
| 2 | 同上 + `adb install -i com.taptap`（安装来源伪装） | ❌ 弹窗依旧 → 排除安装来源校验 |
| 3 | 官方字节 base.apk **追加 classes5 条目**（CD 搬移重排） | ❌ ~2s 死（KwProtect 拒绝）→ **base.apc 一个字节不能动**（签名块/CD 结构校验） |
| 4 | install-multiple base+split（split 只装 classes.dex） | ❌ ~15s signal 9 → **KwProtect 连 split APK 也扫** |
| 5 | lib 目录把 `libzxprotect.so` 换成 starry so | ⚠️ 链路全通（so 加载→sidecar dex→**SignSpoof installed**→DexInstaller.boot OK→JNI_OnLoad），但 ~15s signal 9 → **KwProtect 对既有 lib 做 MD5 校验** |
| 6 | K1-dlopen 桩版 KwProtect + 改签包（无文件替换） | ❌ `JNI_OnLoad` 主线程死转（`BCSDKApplication.<clinit>`→loadLibrary 内自旋，ANR 栈实锤 pc 0x4798b0），校验失败→neuter kill→死循环 |
| 7 | libc 层 open/openat/mmap 重定向到官方 ref 包 | ❌ 无效 → KwProtect 直连 syscall 读文件或校验非文件内容 |
| 8 | SignSpoof（PackageInfo.CREATOR）在安装来源实验中未装也弹窗 | → 弹窗=**PM 证书校验**（starry cert vs TapTap cert），与 kadp VM 读签无关 |

## 对 2026-08-27 文档的修正

| 旧结论 | 本次判定 |
|---|---|
| 「kadp VM 读签导致渠道 dex 不解出（根因）」 | **证伪**。渠道 dex 缺失/ClassNotFound 是 KwProtect 校验失败的下游症状。base.apk 换官方字节后 kadp/kwsdataenc/KwProtect 全链正常 |
| 「SignSpoof 救不了 = 读签走 native」 | **部分对**。Q1 确实查 PM 证书（Java 层），但 SignSpoof 没机会装（ACF 类在官方文件里不存在）。PM 证书校验需要进程内伪装或系统级处理 |
| 「open 重定向不够」（post_install_swap.sh 注释） | 方向对但**该脚本在本机从未成功过**：大包走 incremental-fs 安装，root 也写不了 `/data/app`。必须 `--no-incremental` |
| 「KwProtect K1 绕过 SIGKILL 推荐底包」 | K1 只是止痛。校验失败后 K1-dlopen 变死转、plain K1 后续 `_exit(0)`。**正解是让校验通过（文件层），不是 patch kill** |

## KwProtect 完整性网（当前测绘）

- `base.apk`：字节级（签名块/CD 结构敏感，追加条目即死）
- split APK：存在即杀
- lib 目录：**新增**文件容忍（libstarry_magic.so 在场时放行）；**替换/修改**既有 lib → MD5 校验 → 杀
- kill 手段：direct `svc` kill（libc hook 不可见，kill 链文档 `0x280314`）；patch kill 只会变死转
- 退出时序：改签包 ~0.5–2s；文件违规 ~15s

## 剩余决策（需用户选择，均为设备级操作）

| 方案 | 内容 | 代价 |
|---|---|---|
| A. packages.xml 证书改写 | root 改 `/data/system/packages.xml` 本包签名记录为 TapTap 原证书 → PM 层全量伪装，弹窗消失，游戏可进 | 需 stop/start framework 或重启 system_server，操作风险中等（备份可回滚） |
| B. Zygisk Next + 注入模块 | SukiSU 装 Zygisk Next，模块在进程 specialize 时 dlopen starry so（lib 目录已有）→ SignSpoof + 菜单全链 | 需装模块+重启手机；KwProtect 可能有 Zygisk 检测（未测） |
| C. 卸载重装官方包 + 备份还原数据 | 卸载（需用户明确同意）→ 装官方 → root 备份/还原数据 → 天然全绿；mod 注入仍需 B | 数据有丢失风险（10GB 热更在 app data 外的 obb/Android/data 需 root 备份） |
| D. 纯分析路线 | 不出可玩改包，以官方包 + KSU `/proc/pid/mem` 做玩法验证（Root 注入 A 线，旧文档标注被禁） | 需用户解除 A 线禁令 |
