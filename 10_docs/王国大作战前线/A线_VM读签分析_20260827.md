## VM 静态新发现（2026-08-27 23:17）

### 1. Handler 表（file `0x9EF0`，64 项）

交替模式：`0x6965C…0x696B0`（native dispatch）与 `0x116D28…0x116DC8`（secondary）及 `0x403`（stub）。

脚本：`work/wgdzz_kadp_vm/kadp_vm_analyze.py`

### 2. JNI 链（VM 字符串表 @ `0x19958`）

```
getPackageName → getPackageManager
→ getApplicationInfo(Ljava/lang/String;I)Landroid/content/pm/ApplicationInfo;
→ metaData / KWS_MAIN_APP
→ getPackageResourcePath → %s/classes.dex / wholedex
→ DexFile.openDexFile / dexElements
```

**无** `getPackageInfo` / `signatures` 明文；读签走 **getApplicationInfo + int flags**。

### 3. PM flags 常量（VM bytecode 内 u32 LE）

| 值 | 含义 | 命中数 |
|---|---|---|
| `0x40` | GET_SIGNATURES | 26 |
| `0x80` | GET_META_DATA | 8 |
| `0xC0` | SIG + META | 5 |
| `0x80000000` | GET_SIGNING_CERTIFICATES | 13 |

→ VM 极可能用 **GET_SIGNATURES / GET_SIGNING_CERTIFICATES** 读安装包签名，与 Java SignSpoof（PM 层）不同路径。

### 4. 渠道 dex

`ChannelApplicationListener` **不在** APK 任何 dex class_defs，也不在 classes.dex 密文串表 → 须 **签名校验通过后** VM/渠道层追加解出。
