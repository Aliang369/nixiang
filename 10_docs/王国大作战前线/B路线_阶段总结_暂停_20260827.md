## A 路线：保渠道 SigningBlock（证伪）

**假设**：改签后渠道 pair `0x42726577` 被截短（1600B→920B），导致 Q1 渠道 dex 不解。

**实锤**：

| 试验 | 结果 |
|---|---|
| 外科渠道 payload **前 920B** | 与官方 **逐字节一致**；官方后 680B 为全 `0x00` padding |
| `apksigner` 重签后再扩 channel | 重签 **截回 920B**，无法「重签保块」 |
| 签后扩至 **1600B**（不重签） | channel md5 = 官方 ✅ |
| 实机启动 | **仍** `ClassNotFound: ChannelApplicationListener` |

**VERDICT**：渠道 SigningBlock **不是根因**。更可疑的是 **APK v2 整包签名校验**（kadp VM / native 读 `base.apk`），`SignSpoof` 只覆盖 Java `PackageManager`。

**脚本 / 产物**：

- `work/wgdzz_b_route/preserve_channel_signblock.py`
- `work/wgdzz_b_route/parse_signing_block.py`
- `mod菜单/starry-mod-menu/scripts/wgdzz_channel_patch.sh`（`NO_RESIGN=1` 才保留 1600B）
- `08_output/…/surgical-kwK1-channelNoResign.apk`（实验包，v2 未重算）
- `08_output/…/surgical-kwK1-channelSigned.apk`（重签后无效，channel 仍 920B）

**SigningBlock 结构备忘**：block 总长 4112B（含 footer+magic）；pairs 从 **block+24** 起，顺序 **v2 (`0x7109871a`) → v3 (`0xf05368c0`) → channel (`0x42726577`)**。
