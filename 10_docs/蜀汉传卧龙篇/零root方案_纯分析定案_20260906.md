### 1.2 判决分发器完整反汇编（0x1E3A114，与旧版 sub_1E38650 同构）

```
函数头 0x1E3A114 (SUB sp,#0x20)
  w3 = 0x79BACE2B                       ← kill 魔数
  x2 = *(GOT槽 0x1E64E20)               ← 对象指针（运行时晚绑定，T+16 时仍为 0）
  x0 = *x2 ; x2 = *x0                   ← 两级解引用 → vtable
  w4 = *(x2 + 0x400 + 0x30)             ← ★判决标志 = vtable+0x430（与旧版同位！）
  CMP w4, w3 ; B.EQ → kill路径
  w3 = 0x4FAF2AEB ; CMP ; B.NE → 正常路径
  [计数路径] w0 = LDRSH [x2+0x2E]       ← ★计数器 = +0x42E（同旧版）
             w0+1 ; STRH 写回
  [正常路径] BLR *(另一GOT槽+0xD60)
kill路径 0x17C:
  w0 = 0
  BL 0x1E51104                          ← exit_group(0) → "exited cleanly (0)"
  B → 正常路径继续                       ← 设计者预期可返回（印证旧观察）
```

### 1.3 三个历史矛盾的最终解释

1. **AB-11 seccomp SIGSYS**：exit_group raw svc 真实发生 ✓
2. **libart/exit 钩子全零命中**：死亡走 raw svc，不经任何 GOT ✓
3. **旧会话「优雅停机无 syscall」**：是他们自己已 patch 掉 wrapper 的伪象（TRAP 自然看不到）✓
4. **重定向喂官方文件仍死（AB-13/16/17）**：checker 双通道读——GOT open（被我们重定向）+ 私有 raw-svc openat/read（读到真文件）；两通道结果不一致（或以 raw 为准）→ 判决失败 ✓
5. **此前 patcher 漏掉 wrapper 的原因**：SVC 扫描模式编码 bug（0xD2800BC0，漏了 Rd=8 的 0xD2800BC8）✓

### 1.4 响应者簇（旧版「12 响应者」的新版对应）

全局槽 0x1E64E20 全镜像 17 处引用：dispatcher（0x1E3A110）+ 反调试响应者（0x1E35B90，调 gettimeofday+ptrace stub）+ 0x1E49CDC~0x1E4A738 簇 11 个小函数（128-204B，纯 BLR 间接调用，无魔数写点、无直调 stub）。**exit_group wrapper 直调仅 1 处**（dispatcher kill 路径）；间接调用无法静态枚举 → 但 **patch wrapper 本体即覆盖直接+间接全部路径**（万能钳点）。

## 二、零root方案——实现规格（分析完结论，待执行）

**核心思想：不追求让检测通过（不需要破 VM 比对），让判决失去行动力。**

### 2.1 libpatcher v5 补丁集（全部进程内，无 root）

| # | 补丁 | 语义模式 | 改法 |
|---|------|---------|------|
| 1 | ★exit_group wrapper 中和 | `MOVZ x8,#94`(0xD2800BC8) + SVC#0(0xD4000001) 相邻 | → `MOV w0,#0`(0x52800000) + NOP；幂等重臂 |
| 2 | kill 分支 NOP（保留） | kill 魔数对后 **≤4 条内**的 b.cond（修复旧扫描器的 18 条窗口误伤计数分支 bug） | → NOP |
| 3 | libc/libart exit/_exit/abort GOT 钩（保留） | 值匹配（含 RELRO 段） | 拦截（已实现） |
| 4 | sigspoof 双路（保留） | signatures 字段 + SigningInfo 代理类 | 官方证书（已实现） |
| 5 | ptrace stub 中和（可选纵深） | `MOVZ x8,#101`+SVC#0 | → `MOV w0,#-1`+NOP（反调试自检失效） |

### 2.2 风险与未知（纯分析不可判定项，需未来真机观察）

- 计数器（+0x42E）的消费方未定位（BLR 间接），wrapper 中和后理论无害，但响应者簇若做其他破坏（如 madvise 代码页）需运行时观察
- FairGuard 是否对自身代码做 checksum（旧版补丁曾长期存续，倾向无，未证）
- 多态重排发生在何时（同运行内布局稳定，跨运行重排；语义扫描天然免疫）
