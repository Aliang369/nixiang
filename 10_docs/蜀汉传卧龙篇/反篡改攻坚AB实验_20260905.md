## 一、结论（TL;DR）

**★根因实锤：新版（FairGuard 4.5MB）做 APK 文件级校验——安装包任何字节改动（含零改动重签）必在 T+15~30s 优雅死亡（clean exit 0）。唯一存活条件 = 安装路径上是位一致的官方原包。**

| 实验 | 内容 | 结果 |
|------|------|------|
| AB-1 | SDK跳过 + getPackageSign 签名桥 patch | ❌ T+20~25 死（签名桥无用：checker 不走游戏 Java 桥） |
| AB-2 | 飞行模式 | 不可判读（离线登录秒退） |
| AB-4/5 | 进程内 kill 分支 NOP（`MOVZ+MOVK 0x79BACE2B` 后第一条 b.cond） | ✅ 补丁生效（多态布局每次漂移，语义扫描可复中）→ 续命至 T+25~30 |
| AB-6 | libFairGuard.so 换空壳桩 | ❌ T+8 SIGSEGV：API 靠运行时注册函数指针（磁盘导出名加密），桩死路 |
| AB-7 | 外部 process_vm 清零标志 | 0 命中：标志魔数不存在于任何 rw 区（除代码立即数）→ 无持久标志可清 |
| AB-8 | iptables 封游戏服务器 | ❌ 死亡时刻不变 → **本地检测**，服务器假说排除 |
| AB-9/11 | seccomp TRAP（exit/exit_group） | ⚠️ 新版 FairGuard 检测 NO_NEW_PRIVS/Seccomp 状态 → T+8 故意 SIGSYS 处决；**seccomp 路线废弃**。AB-11 曾实证死亡=exit_group syscall（非旧版「优雅停机」） |
| AB-10 | **零改动重签** | ❌ T+30 死 → **触发器=签名本身**，与 dex/so 内容无关 |
| AB-11d/12 | GOT 值匹配 hook open/openat/fopen + 重定向官方原包 | REDIRECT 触发（checker 确实开 base.apk）但喂官方文件仍死 |
| AB-13 | + JNI 函数表签名伪装（GetFieldID/GetObjectField 返回官方证书 Signature[]） | ✅ phase1 PM 查询骗过（T+5.9 取官方签名）；T+20 开 base.apk（重定向官方）→ 仍死 |
| **AB-14/15** | **bind mount 官方原包到安装路径**（权限 644 system:system，否则 ART 拒「writable dex」） | ✅✅ **T+140s+ 全程存活（此轮 odex 已被原 dex 重编，一切进程内补丁未生效——纯官方文件即过检）** |

死亡签名（所有失败 run 共有）：死亡前多线程读 `ro.debuggable`/`ro.secure`/`adb_enabled`（~0.5-4s 窗口）→ `Zygote: exited cleanly (0)`。

## 二、已定位的技术资产（可复用）

1. **死亡分支语义扫描**（libpatcher.c `patch_thread`）：rwx 区扫 `MOVZ w?,#0xCE2B + MOVK w?,#0x79BA` 指令对 → 其后第一条 b.cond → mprotect+NOP。多态 dispatcher 每次运行块布局漂移（同偏移指令不同），**固定偏移不可用，语义扫描稳定命中**（rel≈0x1e3a1xx 附近）。
2. **GOT 值匹配 hook**（`hook_module_got`）：按 libc 函数地址值扫模块 rw 段替换槽位——**不需要符号名**（FairGuard/libMyGame 导出名加密）。只 mprotect RW（RWX 在 Android 16 文件背书页 EPERM），只扫 rw 段（写 r-x/r-- 页 SEGV 实锤）。
3. **JNI 函数表签名伪装**（`jni_sigspoof_install`）：JNI_OnLoad 拿 JNIEnv → 改表 GetFieldID/GetObjectField → 查询 `PackageInfo.signatures` 时返回官方证书 DER 构造的 Signature[]。**实测骗过 phase1**。官方证书 DER（775B，MD5=0769ed9f…）已提取：`04_scripts/蜀汉传卧龙篇/shc_cert_bytes.h` + `/tmp/shc_official_cert.der`。
4. **取证工具**：`memdump_vm.c`（process_vm_readv 外部 dump）、`flagpatcher2.c`（语义扫描外部补丁——外部 process_vm_writev 写 r-x 页被拒）、`flagzeroer.c`（标志清零器）。
5. 内存 dump：`07_patched/蜀汉传卧龙篇/ab1_20260905/shc_t8.bin / shc_t16.bin`（31.88MB 解密态，含 RWX 全区；getPackageInfo/signatures 串 @0x1702588/0x17025d0）。

## 三、星空包落地新架构（结论）

**改 APK 的星空包在此游戏 = 死路（文件级校验不可伪装）。可行形态：**

1. **官方原版 APK 直接安装（零改动）** —— 文件校验天然通过（AB-15 实证存活）
2. **root 注入**：Zygisk 模块（SukiSU + Zygisk-Next）加载菜单/hook so —— libpatcher 的全部技术（分支扫描补丁、GOT hook、JNI 表伪装）平移进 Zygisk 模块
3. game_id=`shzwlp`、GameConfig.h 接线等星光协议不变；菜单本体走已装的 `com.starry.magic`
4. 交付要求 root 设备（本游戏特有；其他游戏不受影响）

**挂点现状**：旧版 RVA 全失效。新 dump（shc_t8/t16.bin）已含解密态正文，待 IDA 重建后按 RTTI/字符串区重定位（hurt_num 解析器/血条绘制等同款思路）。

### 6.1 新增实证

| 实验 | 内容 | 结果 |
|------|------|------|
| FairGuard dump | 运行时 4.4MB 全区转储 | 全加密：静态 0 字符串、0 svc 包装器（`shc_fg.bin`） |

| AB-21 sigspoof 日志 | GetMethodID 全量记录 | checker 查询 `signatures`(legacy) + `setSign(Z)V`（阿里认证SDK类）；未查 signingInfo；未查 odex |

| **AB-23 setns 挂载** | **运行时进入游戏 mount ns，bind mount 官方原包到安装路径** | ✅✅✅ **T+135s 全程存活同进程**——改包在装（mod dex 全生效）+ 官方文件视图，双通道自洽 |

### 6.2 死亡机制终版结论

检测器（FairGuard +0x11b5c4 附近）→ 判决 → **协作式线程退场**：无 exit/kill/tgkill 调用（native 钩子+libart RELRO 钩子全部零命中）、无内联 svc、无 Activity.finish。唯一解法=让判决为「通过」，拦截退出不可行。

### 6.3 ★最终架构（星空包 = 双层一切两半）

```
[安装态] 改包 APK（星空菜单 dex/so + 重签）——odex 由改包 dex 编译，mod 全生效
[运行态] root 助手 setns 进入游戏 mount ns → bind mount 官方原包覆盖安装路径
         → checker 文件通道（native/Java 一切读法）只见官方字节
         → ART 已开 fd 仍读改包内容（懒加载类与 odex 一致）
[PM 通道] JNI 表签名伪装（signatures + SigningInfo 代理类双路）
[兜底层] dispatcher kill 分支语义扫描 + exit/kill 钩子族（本轮虽非必需，留作纵深）
```

- odex 交叉校验**不存在**（AB-23 未挂 odex 仍存活）
- 已知残留：本轮 GOT open 钩子 slots=0 未挂上（时序问题），存活靠挂载层——重定向/挂载双保险待合流
- 挂载在进程 ns 内，进程重启即失效 → 交付需 root 守护（SukiSU 模块/daemon：pidof 到游戏 → setns 挂载）
- 官方原包暂存 `/data/local/tmp/shc_orig.apk`（1.6GB；后续可测只伪造签名块+CD 的精简视图以省空间）
- mntbind 工具：`04_scripts/蜀汉传卧龙篇/mntbind.c`（setns + MS_BIND）
