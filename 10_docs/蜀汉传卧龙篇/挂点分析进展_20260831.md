## 5d. 闪退攻坚记录（2026-09-01，首包装机后）

**现象**：游戏启动 ~20-60s 画面消失回桌面。死因取证：`Zygote: Process xxx exited cleanly (0)`（自毁式 exit(0)，无崩溃日志，反逆向特征）或静默 SIGKILL（AMS has died 无 signal 记录）。

**A/B 探测结论**：
| 变量 | 结果 |
|------|------|
| 零改动重签（不改文件只换签名） | ❌ 60s 内被杀 → **签名校验是第一道门** |
| 减配包（官方 dex 不动 + Manifest 替换 + 新增 dex3/so/certs，无 SignSpoof） | ❌ 首启死 |
| 减配包 + SignSpoof 回灌官方证书 | ✅ 二启后长稳（观察中） |

**对策落地（最终版，2026-09-01 18:55 实证：无 root 自洽，存活 10+ 分钟零死亡）**：
1. **seccomp BPF（关键，无 root 可用）**：so constructor 里 `PR_SET_NO_NEW_PRIVS` + `seccomp(SECCOMP_SET_MODE_FILTER, TSYNC)` 安装 BPF——**syscall 层拦 exit(93)/exit_group(94)，RET_ERRNO(EPERM)**。任何检测（含 inline svc 直调）触发退出都会被内核拒绝，进程继续活。内核验证：`/proc/<pid>/status` → `Seccomp: 2`。
2. **SignSpoof（Java 层 PM 签名伪装）**：官方证书回灌（O=Bantus）。⚠️ Android 16 上 `setHiddenApiExemptions` 直接反射被拒（hiddenapi denied 日志实证）——meta-reflection 修复**待做**（当前靠 seccomp 硬扛存活；长线防服务器侧标记需补）
3. **保护 SDK 跳过**：TRGame.smali 删除 `SWProtectSDK.InitEx()` 与 `HTProtect.init` 两行（`patch_skip_protect.py`）——实测 FairGuard/易盾 so 完全不加载（maps 实证 0 条）
4. **Dobby exit/kill 拦截（备用层）**：constructor 里 hook libc exit/_exit/abort + 自杀 kill——**本机 Dobby hook libc 失败（Android 16 内存背书限制，失败静默）**，seccomp 是主力

## 5e. 黑屏阶段（2026-09-01 晚，进行中）

**演进**：闪退（exit 0）→ seccomp 拦 exit_group → **不闪退但 ~20s 黑屏**（截图实证纯黑，Activity 仍前台）。时间点与原闪退一致 → **检测仍触发，换第二处置**。

**黑屏机制（实证推演）**：检测触发 → 调用 exit_group → seccomp/patch 拦截 → **bionic wrapper 的错误分支（b.hi 0x1e4da40）死循环重试** → 主线程 R 状态空转（ps 实证 4 进程全 R）→ 渲染停止 → 黑屏。exit(0) 的调用者**从不预期返回**——拦 exit 只会把死变瘫。

**SignSpoof meta-reflection 修复**：Android 16 上直接反射 setHiddenApiExemptions 被 denied（实证）→ 改元反射（Class.getDeclaredMethod 元身份）→ **denied=0**。但检测仍触发 → **检测不走 PM 路径**（或不止）。

**新实证**：
- 保护跳过版（FairGuard/易盾不加载）依然 20s 触发 → **检测者不是 FairGuard/易盾**，是游戏自身（native 自校验）或服务器指令
- **ptrace attach 后游戏加速死亡**（tracer SEIZE 后进程秒死，疑似反调试或死亡窗口重叠）——tracer 本身有 bug（初始 group-stop 被 CONT，未进 SYSCALL 循环，已修未验证）
- libMyGame 镜像内仅 **1 个 exit_group svc wrapper**（0x1e4e104，bionic 风格）→ 已 patch 为 `mov w0,#0` 假成功返回——但游戏改走 **libc exit**（PLT→真 syscall）死亡
- **无 strace**（设备无、KSU 无模块）；lldb platform/gdb-remote 连接链路不通（adb reverse 端口冲突、attach 挂起）

**工具产物**：`04_scripts/蜀汉传卧龙篇/tracer.c`（mini ptrace syscall tracer v2，静态编译 /tmp/tracer，待修验证）

### 已定位的完整问题链（今晚核心成果）

**闪退/黑屏的统一根源**：游戏侧检测（非 FairGuard/易盾——它们被跳过后检测依然触发）触发 `exit(0)`，且 **exit 有多条逃逸路径**，逐一定位如下：

| # | exit 逃逸路径 | 状态 | 对策 |
|---|--------------|------|------|
| 1 | libMyGame 内嵌 exit_group wrapper（svc @0x1e4e104） | ✅ 已 patch | `mov w0,#0` 假成功返回 |
| 2 | libMyGame 直接调用路径（bl @0x1e386c4，判定：全局结构+0x430 == 0x79BACE2B → 自杀分支） | ✅ 已 nop | 标志命中也跳过自杀，`b 0x1e386a0` 继续正常处理（反汇编实证设计者预期 exit 可返回） |
| 3 | libFairGuard 二次加载（非 InitEx 路径）的 abort@GOT | ✅ 已劫持 | 挂起 stub |
| 4 | **libart GOT 的 `_exit` 槽（vaddr 0xE36BA8）**——Java `System.exit(0)` → art::Runtime::Exit → `_exit` | ✅ 已劫持（build46） | **待验证是否在生效槽内** |
| 5 | 未知的第二处置路径（非 exit——finish/停止渲染） | ❌ 未定位 | 黑屏/退桌面的直接原因 |

**检测触发标志**：全局结构 +0x430 处 DWORD == `0x79BACE2B`（自杀指令）、== `0x4FAF2AEB`（计数）。**写入者在运行时侧**（魔数非静态，可能来自服务器指令/其他线程解密）——**未定位**。

## 5g. 终局认知修正（seccomp TRAP 取证 + 关键推理，2026-09-02 凌晨）

### seccomp TRAP 取证结果

取证版（SHC_EXIT_FORENSICS）实测：`seccomp TRAP armed rc=0`（TSYNC 成功）→ 20s 死亡 → **无 SIGSYS tombstone**、Zygote 报 `exited cleanly (0)` → **exit_group syscall 根本没发生**。

### 关键推理（改变对抗方向）

**进程可以在不调用 exit_group syscall 的情况下以 code 0 终结**：检测触发后游戏**优雅停机**——flag 通知全部线程自然退出 → 最后线程 `pthread_exit` → 内核对"最后一个线程死亡"**自动终结进程**（内核内部 do_exit，无 syscall）→ **seccomp/GOT/patch 拦 exit 全部无效**。这解释了：所有 exit 路径堵死后游戏仍 `exited cleanly (0)`。

**→ 对抗方向必须转向"让检测不触发/让检测逻辑失效"**，而非拦截退出动作。

### 下一会话精确作战计划

1. **枚举标志响应者**：IDA 反编译 `0x1e46f50-0x1e47d88` 的 12 个函数（读全局结构 +0x430 标志的 handler 族）→ 找出其中**所有**自杀/退出/停止渲染调用点 → 汇总 patch 清单（现有 sub_1E38650 已 patch）
2. **定位标志写入者**：IDA 全镜像扫 `str w?, [x?, #0x430]`（x 来自 off_1E5FE60 解引用链）→ 找到写 `0x79BACE2B` 的检测函数 → patch 其写点（标志永不置位）
3. **SignSpoox 元反射替代**：ColorOS 16 连元反射都拦（InvocationTargetException 实证）——PM 伪装改 native 思路或放弃 PM 层（依赖 #1/#2 治本）
4. **Dart 层**：blutter 反编译 libapp.so（`.apk` 字符串线索）——如 #1/#2 治本后仍死再挖

### 现场状态

手机装的是 build51 取证版（seccomp TRAP armed——**对游戏无害**，仅 20s 黑屏现象同前）。下一版应换回正式对抗版（SHC_EXIT_FORENSICS 去掉）并加入 #1/#2 的 patch 清单。

**今晚净结论**：exit 有 5 条路径，4 条已堵死；第 5 条 = 检测后的优雅停机（无 syscall）——**对抗焦点从"拦退出"转为"废检测"**。
