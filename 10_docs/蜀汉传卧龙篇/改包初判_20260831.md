## 2. 引擎架构（实测证据）

**Cocos2d-x C++ 游戏 + Flutter UI 壳的混合体**，游戏主体逻辑全在 native C++：

| 层 | 技术 | 证据 |
|----|------|------|
| 游戏主体 | **Cocos2d-x C++**（自研 SRPG 引擎，cocos2d 命名空间 + 自研类） | `TRGame extends Cocos2dxActivity`（TRGame.java:110）；内存 dump 中 8 万+ 可读字符串全是 cocos2d/自研 C++ 符号 |
| UI 壳 | Flutter（登录/账号/支付 WebView 壳） | `libflutter.so` + `libapp.so`（Dart AOT，.text 7.4MB 完好）；Dart 字符串里**无**游戏战斗逻辑，只有框架与登录 UI |
| Java 桥 | `TRGame` 静态 native 方法 ↔ C++ 字符串桥 | `nativeJavaCallCppBridge(String)`、`nativeInit` 等 14 个 native 声明（TRGame.java:382-421）；C++ 侧有 `jni:initPayCenter not found` 类错误串 |
| 存档 | 本地为主：cocos `Cocos2dxPrefsFile.xml` + `files/archive%d_platform%d_%s` 存档文件 + `achievement.db`；另有阿里云 OSS 云存档（`/oss/downloadArchive`） | 内存 dump 路径格式串 + 真机 files/ 实测 |
| 热更 | `files/patch_dir/GameResources/` 优先于 APK assets（动物餐厅同款模式） | 真机实测 patch_dir 已落地 |
| 统计/风控上报 | ThinkingData/TalkingData、Bugly、`/player/saveCrackingInfo`（**作弊上报端点**） | shared_prefs + 内存 dump URL 串 |

资源清单：`assets/GameResources/`（19227 文件：png/bmp/atlas Spine 骨骼/csb Cocos Studio/json），**全部带 BGT1 头加密**（`function.txt` 明文 `EncryptResource:true`）。BGT1 头格式实测：`"BGT1" + uint32(1) + uint32(原文件大小或标志)` 之后是密文体（1-1.png: offset8=0x300=768=文件大小 ✓；52.bmp: offset8=0x18c4=6340 ✓）。

## 3. 保护面（阶段A识别，阶段B需 A/B 实测）

### 3.1 双商业保护（本次最大风险点）

| 保护 | 载体 | 行为证据 |
|------|------|---------|
| **FairGuard** | `libFairGuard.so`（5.4MB arm64）+ Java `com.swpprotect.sdk.SWProtectSDK`（InitEx 在 XinyueUser.Init 后调用，TRGame.java:718） | 磁盘上 `libMyGame.so` 节表被做反 IDA 处理（.text 仅 16B、重定位 93 条、**符号名全抹空**、正文几乎无可读字符串）；运行后内存 RWX 映射、正文**全部解密** |
| **网易易盾 HTProtect** | `libNetHTProtect.so`（4MB）+ `com.netease.htprotect.HTProtect`（TRGame.java:640 init） | 智能保护 SDK（反调试/反 hook/完整性），心跳 `NetHeartBeat` |

### 3.2 so 加固形态（实测）

- 磁盘 `libMyGame.so`（31.8MB）：ELF 头合法、PT_LOAD 一个 R+E 大段，但节表/符号被手术——静态 IDA 直接打开无意义
- 运行时（pid 699 实测）：`0x775d90a000-0x775f73e000 rwxp` 文件背书映射（**RWX = 运行时解密落页**），r-x/rw 段随后
- **KSU memdump64 外部 process_vm 读内存，无需 ptrace，已成功 dump 31,858,688 B** → `06_dumped/蜀汉传卧龙篇/shhc_mygame_mem.bin`（内存镜像中 80196 个可读字符串，RTTI 类名全量可读）

### 3.3 root 机存活实测（关键好信号）

游戏在 SukiSU root 机上**正常启动存活 37s+**（FairGuard 未因 root 杀进程；KSU 隐藏或游戏容忍，待长时验证）。

## 5. 可行性结论（初判，置信度标注）

| 目标功能 | 结论 | 依据 | 前置工作 |
|----------|------|------|---------|
| 无敌/秒杀 | 🟢 **高可行** | 战斗类 RTTI 全现形、逻辑全本地 C++、单机无战斗服务端校验（服务器只有登录/支付/公告/OSS）；有 `ScriptSetBattleValue` 这类直写数值的脚本命令面 | dump 镜像 IDA 分析定位伤害结算函数（`AttackGainInfo`/`hurt_num` 链） |
| 战斗相关（加速/全屏/回合操控等） | 🟢 高可行 | 同上；`BattleRoundStart`/`ScriptBattleActorTurn` 可控回合流程 | 同上 |
| 解锁皮肤/角色/人物 | 🟡 **中高可行** | 皮肤/武将 UI 齐全，存档本地；但解锁数据结构（dic/存档字段）未验证——**存档字段可能加密**（BGT1 或其变体），且异机登录清档 | 开档后 dump 存档文件分析结构 + 内存差分（同 binge-memdiff 思路：UI 点击 → dump 差分） |
| 星空包落地 | 🟡 **有条件可行，风险面明确** | 见 §6 风险清单；root 机存活是最大利好 | 4 组 A/B 探测（§6）+ IDA 挂点定稿 |

## 6. 星空包落地风险清单（阶段B必须 A/B 实测，逐条过）

1. **FairGuard so-MD5 校验**：替换/修改既有 lib 可能被杀（KwProtect 同款教训）→ 星光**新增** `libstarry_magic.so`（KwProtect 先例：新增容忍）需实测
2. **APK 签名校验**：FairGuard InitEx 可能查 PM 签名 → 零改动重签存活测试（SignSpoof 兜底）
3. **base.apk 文件完整性**：外科组装只 ADD 不 REPLACE（新增 dex/so/assets 不动官方字节）大概率过，需实测
4. **inline hook 检测**：FairGuard/易盾都有 hook 检测能力（ACE 同款风险）→ 首个 Dobby 挂点必须小步实测；失败则走「旗标门控 + 轻量方案」（雷霆战机先例）
5. **反调试**：已验证外部 process_vm 读内存可行；**禁止** Frida 长挂、禁止 ptrace
6. **Application 继承链**：StarryApp 必须继承 `com.bantu.trgame.TRApplication`（官方直接 extends Application，无壳 Stub，比 PCR 简单）
7. **作弊上报**：`/player/saveCrackingInfo` 端点存在——功能量级按 anti-ban 安全线走；该端点触发条件未知，需后续确认是否本地触发
8. **热更 patch_dir**：清数据 = 热更目录丢失 + 存档清空，分发说明写「禁止清数据」

## 7. 下一步（阶段B/C 路线）

1. **dump 镜像修复进 IDA**：`shhc_mygame_mem.bin` 是运行时加载镜像（ELF 头在 offset 0，节表不在内存）→ 用 SoFixer 类工具修复或 IDA 按 raw+基址加载；rwx 段 file_off=VA 直接对齐（PT_LOAD offset=vaddr，无 bias，省心）
2. **定位挂点**：`Script*` 注册表（脚本命令名→函数指针表）优先——它是官方自留的功能面；其次 `AttackGainInfo`/`hurt_num` 引用链找伤害结算
3. **BGT1 解密**：在 dump 中定位解密函数（搜 BGT1 常量引用/循环异或特征），静态解密 126 个 json → 数值配置表全量可读（武将属性/皮肤表/关卡表），比 hook 更稳
4. **存档分析**：用户开档打一局后，拉 `files/archive*` 分析结构
5. **A/B 探测**（§6 清单）：零改动重签 → 新增 dex → 新增 so → 替换 so，逐项最小改动实测
