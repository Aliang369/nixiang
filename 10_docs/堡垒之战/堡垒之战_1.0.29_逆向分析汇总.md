## 3. 静态分析发现

### 3.1 游戏内开发者调试菜单（含“无敌/十倍攻击/解锁全部”）

模块：`chunks:///_virtual/mgrDebug.ts`

- 菜单通过 `showDebugEnters()` 打开：
  - 白名单用户回调 `SDK_CHECK_DEBUG_WHITE_USER_RESULT` 为 true 时自动弹出；
  - 键盘 `Ctrl+E` 可打开；
  - 设置/个人信息界面输入隐藏密码 `12121122`（音乐按钮 = `1`，声音按钮 = `2`），且 `bDebugWhiteUser=true` 时打开调试菜单。
- 菜单能力（节选）：
  - `无敌`：`F.bRoleInvincible = !F.bRoleInvincible`
  - `十倍攻击血量(可重复叠加)`：`j.attackHpScale *= 10`
  - `解锁所有功能`：`v._debugUnlockAll()`
  - `添加装备/符文/宝石/物品`：通过服务器指令 `item_add_for_client` 下发
  - `服务器天+1 / -1`：`server_time_add`
  - `清空火凤币`：`debug_reset_pay_currency`
  - `挖宝层数+5`：`debug_add_floor_5`
  - `开启白名单`：直接 `onMsgSetDebugWhiteUser(true)`
  - 其他：满级、VIP 等级、武魂熟练度、蓄力无 CD、加速、永久倍速等

受伤判定中直接消费该标志：

```js
this.controller.gameContext.mgrFiringRange_bRoleInvincible() || (this.hp -= o, ...)
```

说明 PvE 场景下客户端可无痛获得无敌；服务器存在战斗回放校验（见 3.6），因此 PvP/排行榜场景是否生效需动态验证。

### 3.2 免支付/调试支付路径

模块：`chunks:///_virtual/mgrPay.ts`

```js
static pay(t) {
  ...
  o.getIsTestEnvironment() && e   // e = env.DEBUG
    ? u.send(c.DEBUG_PAY, { payId: t }, ...)   // 直接向服务器请求发放奖励
    : this._preOrder(...)                       // 正常下单流程
}
```

- `env` 模块位于 `assets/src/chunks/bundle.js`：`DEBUG = !1`、`BUILD = !0`。
- 正式包中该分支默认关闭，但代码/服务端指令仍在：
  - `CLIENT_2_SERVER_CMD.DEBUG_PAY = "debug_pay"`
  - 另有 `item_add_for_client`、`server_time_add`、`debug_reset_pay_currency`、`debug_add_floor_5`、`debug_role_*`、`debug_vip_*`、`debug_email_add` 等一批调试指令。
- `isTestEnvironment` 来自服务器存档 `gameSave.data.isTestEnvironment`，并非客户端自设。
- 客户端配置中存在测试网关路由：`s_sdk_online_game_server_route_test = /gatewaytest/game`（`assets/cConfig.json`），正式网关为 `https://og.ultralisk.cn/gateway/game`。

结论：若服务器未对 `debug_*` 指令做严格环境隔离，或测试网关对外可达，则改 `DEBUG=true`（重打包或 Frida Hook）即可尝试免支付购买。是否可打通取决于服务端，需动态验证。

### 3.3 ULSDK 隐藏调试支付（Java 层）

- 位置：`cn/ulsdk/base/ULModuleBaseSdk.java` 的 `E()` 方法
- 逻辑：读取 SharedPreferences `ul_mc_config`：
  - `debugPayPrice`（单位：分）
  - `debugPayCode`（渠道商品 ID）
  - 若 `debugPayPrice > 0`，会把支付商品 JSON 里的 `price` 改成该值，并把 `proName` 标记为 `(测)`
- 隐藏测试界面（`m/f.java`、`m/h.java`、`m/i.java`）支持设置：
  - `isTestAccountOpen` / `testAccountAddr`
  - `isTestCopOpen` / `testCopAddr`
  - `isCopDebugOpen` / `copDebugTemplateId` 等
  - `isSupportDebugPrice` / `debugPayPrice` / `isChannelPMS` / `debugPayCode`
- 设备有 root，可安装后直接改写 `ul_mc_config.xml` 验证“低价支付/测试支付”是否能被服务器接受。

### 3.4 可指定任意游戏服务器地址（开发者登录面板）

模块：`chunks:///_virtual/Server.ts` / `PanelDebugLogin.ts`

- `Server.doDebugChoose()` 弹出 `PanelDebugLogin`，可填 `userId / serverAddr / channelId / gameId`；
- 默认服务器地址从本地存储读取，缺省为 `http://localhost:9998/game`；
- 登录后直接使用该地址 POST JSON：`{cmd, param, version}`，无 token（`loginInfo.token = ""`）。

这意味着可以：

- 用 Frida 直接调用 `Server.doDebugChoose` 或 `Server.url` 指向本地伪造服务器；
- 自建假服返回任意 `gameSave`/奖励，验证“存档/奖励完全由客户端信任的服务器地址决定”。

### 3.5 网络协议与服务器地址

- 游戏网关：`https://og.ultralisk.cn/gateway/game`（生产）
- 测试路由：`/gatewaytest/game`
- 房间 WS：`wss://common.ultralisk.cn/roomserver/ws`
- 协议：HTTP POST JSON（明文可读），未发现 JS 层自定义加密；
- 另存在开发环境地址：`http://192.168.1.199:3456`、`http://127.0.0.1:3456`、`http://localhost:9998/game`。

### 3.6 战斗校验/反作弊

模块：`chunks:///_virtual/mgrVerifyBattle.ts`、`QuickBattleSimulator.ts`、`_GameContextDebuger.ts`

- 服务器指令：`verrify_begin_battle`、`verrify_battle_process`、`verrify_battle_once`
- 客户端会把每帧操作 `{frame, commands}` 和结果摘要 `rInfo` 上报，服务器回传 `VERRIFY_BATTLE_ONCE` 后客户端用 `QuickBattleSimulator` 本地重放并 `compareDebugerInfo` 比对。
- 因此 PvP/世界 Boss 等可能有重放校验，直接改客户端数值容易被发现；PvE 的本地无敌/倍攻则不受影响。

## 4. 漏洞报告

> 范围：仅客户端/协议可见风险；最终可利用性取决于服务端校验

### 4.1 内置开发者调试菜单可被本地开启（高危，可稳定利用）

- 位置：`assets/assets/main/index.js` → `chunks:///_virtual/mgrDebug.ts`
- 入口：
  - 白名单检查 `SDK_CHECK_DEBUG_WHITE_USER_RESULT` 为 true 时自动弹出；
  - 设置界面按隐藏密码 `12121122`（音乐=`1`、声音=`2`）；
  - 键盘 `Ctrl+E`；
  - 也可用 Frida 直接调用 `mgrDebug.showDebugEnters()` 或 `ChannelManager.onMsgSetDebugWhiteUser(true)`。
- 菜单能力：`无敌`、`十倍攻击血量`、`解锁所有功能`、`添加装备/符文/宝石/物品`、`服务器时间±`、`清空火凤币`、`一键满级`、`VIP+1` 等。
- 影响：PvE 无敌/秒杀/资源刷取；服务器调试指令若未严格隔离，可扩展到账号数据。
- 证据：
  - `name:"无敌",callback:()=>{F.bRoleInvincible=!F.bRoleInvincible}`
  - `name:"十倍攻击血量(可重复叠加)",callback:()=>{j.attackHpScale*=10,...}`
  - 受伤判定：`mgrFiringRange_bRoleInvincible() || (this.hp -= o, ...)`
- 动态状态：✅ 已验证，菜单可弹出，无敌/十倍攻击生效（见 5.5）

### 4.2 免支付/调试支付指令仍打包在正式客户端（高危，待服务端验证）

- 位置：`chunks:///_virtual/mgrPay.ts`
- `DEBUG_PAY = "debug_pay"`；当 `env.DEBUG && isTestEnvironment` 时直接向服务器请求发放充值奖励，不走支付。
- 正式包 `env.DEBUG = !1`，需通过 Hook/重打包开启；测试网关路由 `/gatewaytest/game` 也硬编码在配置中。
- 风险：若测试服/测试网关对外可访问且 `debug_pay` 未做账号白名单，即可“0 元购买”任意 `payId` 对应礼包。
- 验证计划：Hook `env.DEBUG=true` 与 `mgrAccount.isTestEnvironment=true`，观察服务器返回。

### 4.3 SDK 支付价格可被客户端覆盖（高危，待验证）

- 位置：`cn/ulsdk/base/ULModuleBaseSdk.java` `E()`
- `ul_mc_config` SharedPreferences 中 `debugPayPrice`（分）> 0 时，所有支付商品价格被替换为任意值，商品名追加 `(测)`。
- root 设备可写该文件，或用隐藏 SDK 测试界面设置。
- 风险：若渠道/服务器只信任客户端上送的支付信息，可 1 分钱/0 元买礼包。
- 验证计划：root 改 `debugPayPrice=1`，走一次真实小面额商品支付流程观察扣款与发货。

### 4.4 任意游戏服务器地址（中危，适合本地复现）

- 位置：`chunks:///_virtual/Server.ts` → `doDebugChoose()`、`PanelDebugLogin`
- 默认地址 `http://localhost:9998/game`，可填任意 `userId/serverAddr/channelId/gameId`，登录后无 token。
- 影响：可自建假服返回任意存档/奖励，复现客户端“服务器数据完全可信”的问题；正式服一般不会使用该路径，但可作为本地研究入口。
- 证据：`this.loginInfo.token=""`、`this.url=...gameServer...`、POST `{cmd,param,version}` 明文 JSON。

### 4.5 一批服务端调试指令暴露在客户端（中危，待服务端验证）

- `debug_pay`、`item_add_for_client`、`server_time_add`、`server_time_reset`、
  `debug_reset_pay_currency`、`debug_add_floor_5`、`debug_role_*`、`debug_vip_*`、
  `debug_email_add`、`DEBUG_GAME_STAGE_CUR_ID` 等。
- 均定义在 `SERVER_CMDS.ts`，调试菜单直接调用。
- 风险：服务端若未校验“调试指令仅限测试服/白名单”，任意登录用户可刷物品/改服务器时间。
- 验证计划：抓包后直接向正式网关重放 `item_add_for_client` / `debug_pay`，观察返回码。

### 4.6 开发/测试基础设施泄露（低危）

- 配置含：`/gatewaytest/game`、`http://192.168.1.199:3456`、`http://localhost:9998/game`、`http://127.0.0.1:3456`
- 测试白名单接口：`https://sdkserver.ultralisk.cn/checkwhiteuser?whiteType=goldFinger`
- 价值：可用于探测测试服、账号白名单机制。

| 漏洞 | 客户端可利用 | 服务端配合 | 动态验证状态 |

### 5.2 签名校验点定位

- TapTap：`TapSignKit.getSign` → 原版证书 MD5 `f5aef50d3b3f626a8512bc1a87cad012`
- ULSDK：`ULTool.y`（`checkValidSign`）→ 比对硬编码哈希
- 改包后 debug 签名无法通过校验，必须固定返回值或直接放行

### 5.3 TapTap 登录卡点（已解决）

- 症状一：WebView 登录页 `ERR_PROXY_CONNECTION_FAILED`
  - 根因：设备系统残留 mitmproxy 代理 `192.168.10.43:8080`（mitmproxy 未运行）
  - 解决：清代理 + 用户重启设备后 TapTap 登录正常
- 症状二（改包后）：卡在“登录：66%”，logcat 报 `TapInitializer: 应用的包名（package name）、签名（certificate fingerprint）未在 TapTap 开发者中心正确配置`
  - 根因：debug 签名包证书指纹与 TapTap 配置不一致
  - 解决：patch `TapSignKit.getSign` 固定返回原版 MD5；`ULTool.y` 直接返回 true

### 5.4 调试菜单触发链路

`MCULDefaultLayout.P(code, isWhiteUser, msg)` → JsonRpcCall `/c/checkDebugWhiteUserResult` → JS `sdkback_checkDebugWhiteUserResult` → `ChannelManager.onMsgSetDebugWhiteUser` → `mgrDebug.onMsgCheckDebugWhiteUser` → `showDebugEnters()`
