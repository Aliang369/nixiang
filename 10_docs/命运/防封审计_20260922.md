## 三、服务端权威判定

- FGO 战斗为**客户端模拟、服务端记录结算**（公开常识，本仓库无服务端样本 → 记为 **NOT PROVEN**，不作为免责依据）。
- 伤害倍率/无敌会改变**结算帧序与伤害总量**：若服务端做重放或伤害上限比对 → 🔴；本仓库无法验证 → 按 §一 铁律「不赌服务端没校验」处理。
- 战斗加速 ×10 会显著缩短单场耗时，若服务端按指令/回合节奏判异常 → 🟡。
- 无限技能改变 NP/技能使用序列，服务端若记录指令卡与 NP 使用 → 🟡。
- 未识别出任何客户端→服务端的作弊上报链（`addCheat`/`onStageCheat`/`BuildPassCheckInfo` 是其他游戏术语，本游戏 dex/metadata 中 0 命中），但**ACE/TSS 自身有独立上报通道**（腾讯侧），这是本方案无法旁路的部分。

## 五、装机决策建议（需用户显式授权）

1. **默认不装机**：`install` 阶段在 `04_scripts/命运/pipeline.json` 中保持 `pending`；脚本 `mygwzd_install.sh` 对异签覆盖**拒绝执行**（退出码 2），需设 `MYGWZD_ALLOW_UNINSTALL=1` 并接受「卸载清本地数据」。
2. **建议先降量级再出包**（可选，用户决定）：
   - 战斗加速上限 `kSpeedMax: 10 → 3`（`Games/MygwzdMod.cpp` + `10_docs/命运/mygwzd_menu_template.json` 的 `Slider_战斗加速:1:10:1` → `1:3:1`）；
   - 攻击倍率默认保持 1。
3. **验证顺序**：优先用小号/游客账号 + 单场战斗验证（伤害倍率 1、无敌开、加速 3），观察是否闪退/结算异常/回滚，再决定是否放开。
4. **备选路线（风险显著更低）**：继续用斌哥 VM 宿主（`com.bilibili.BGfatego`）内跑改包，官方包保持未改签名；本星光包仅作技术验证留档。
5. **回滚**：`pm uninstall com.bilibili.fatego` → 装回 `06_dumped/命运/original_apk/base.apk`（官方 v1+v2+v3 签名，可从设备 `pm path` 现有安装目录取）。
