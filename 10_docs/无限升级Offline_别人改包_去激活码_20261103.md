## 2. 激活机制逆向结论（实测）

链路完整、只有一处闸门，全部在 **Java/前端层**，与游戏本体无关：

1. `AndroidManifest` 的 `launchable-activity` = `local.privategame.infinity.GateActivity`（`aapt2 dump badging` 实测）。
2. `GateActivity.onCreate`：建 WebView（JS＋DOM storage＋file access）→ `loadUrl("file:///android_asset/infinity_gate.html")`，仅此。
3. `assets/infinity_gate.js`：`initialize()` 读 localStorage（键 `infinity-offline-license-v1`）→ `verify()`：
   - 格式 `R1.<issuedAt>.<expiresAt>.<32位hex>.<86字符base64url签名>`，要求 `expiresAt-issuedAt == 86400`；
   - payload `INFINITY-OFFLINE|com.xingzuodaoshi.infinityOffline|R1|…`，**ECDSA P-256 + SHA-256 本地验签**（公钥 SPKI 内嵌在 JS 里）；
   - 首次激活查时间窗（未到期且不早于签发），已存过的码再进不查时间窗。
4. 验签通过 → `window.location.href = 'infinity-activated://launch'` → `GateClient.shouldOverrideUrlLoading` 命中该串 → `startActivity(UnityPlayerActivity)` ＋ `finish()`。

**没有第二处校验**：对 `libil2cpp.so`、`global-metadata.dat`、`assets/offline/core.bundle` 全量搜 `infinity-activated / infinity_gate / GateActivity / GateClient / license / activat(e|ion)` —— **0 命中**。`com.codex.offline.LocalInitializationProviders`（classes2.dex）只把 `assets/offline/*` 解压到 `files/offline`、dll 解到 `files/offline/aot`，**不含任何校验**。

⇒ 纯本地离线签名校验，无服务端、无自校验（改包者自己已整套重签重打）。

## 7. 「单机」是怎么实现的（2026-11-03 追加分析，未做任何改动）

### 7.1 结构证据

```
assets/offline/            17 个文件（改包者新增）
  ├ core.bundle            1,077,253 B  UnityFS v8 / LZ4 / Unity 2022.3.62f2c1
  │                        内含 C# 程序集字符串：CodexOfflineRunner、serverMsgs、
  │                        SyncWithAllServer、Net.Client、ClientEvent、ServerM…
  └ *.dll × 16             7.5 MB：mscorlib / System / System.Core /
                           UnityEngine.CoreModule / UnityEngine.AndroidJNIModule /
                           YooAsset / UniTask / Luban / Obfuz / ACTk(Anti-Cheat Toolkit) /
                           EasySave3 / DOTween / Storage / GameDesignerInUnity
assets/nedata.db         10,606,987 B  熵 1.00、非 SQLite 明文头，AES 级加密的本地库
assets/network.config              「useMemoryStream=True / baseCapacity=1024 /
                                    mainThreadTick=True」= GameDesigner 框架的 NetworkClient 配置
com.codex.offline.LocalInitializationProviders（classes2.dex）
                          启动时把 offline/* 全部解压到 files/offline、
                          dll 单独解到 files/offline/aot（运行时实测已生成 16 个 dll）
```

- `GameDesignerInUnity.dll` 里 `GameDesigner` 出现 400 次、`NetClient` 3 次 —— **这游戏用的是 GameDesigner（客户端/服务端同源的 Unity 网络框架）**。
- `assets/bin/Data/Managed/` 下**只有 Metadata + Resources**（无 Assembly-CSharp.dll）⇒ 运行时是 **IL2CPP**，不是 Mono。
- 运行时 `/proc/17000/maps` 只有 `libil2cpp.so / libunity.so / libmain.so / libnesec-x86.so`，**没有任何 libmono***。
- 运行时 `/proc/net/tcp|tcp6|udp` 中 **uid 10082（本游戏）零 socket**（无 LISTEN、无 ESTABLISHED）。

### 7.2 结论：他不是「屏蔽联网」，是「把服务端搬进客户端」

推断链（标「推断」的为间接证据，其余实测）：

1. 游戏是 IL2CPP，却还要跑 C# 的 `CodexOfflineRunner` ⇒ 必须有 IL 解释器。`files/offline/aot/` 那 16 个 dll 正是**补充元数据 dll 的标准集合**，配合 `YooAsset`（bundle 分发）、`Obfuz`（HybridCLR 官方生态的混淆器）—— 形态与 **HybridCLR** 完全一致（推断，因 `libil2cpp.so` 被易盾壳加密、metadata 头是 `HTPX` 密文，无法静态取证）。
2. `core.bundle` 里既有 `CodexOfflineRunner`/`serverMsgs`/`SyncWithAllServer`，又混着大量游戏侧类名（`TopOnAdsMgr`、`RewardedVideo`、`UIUnLock`、`accountMangaer`、`TianJieShenGe`…）⇒ bundle 里装的是**整套 C# 逻辑 dll（改包者重编版）**，不是补丁片段。
3. 进程零 socket 却能跑 ⇒ 客户端发出的「服务器请求」**在进程内被截住并由本地逻辑直接应答**，根本没走网络（不是连 127.0.0.1，是直调）。
4. `nedata.db`（10.6 MB 加密库）＝ 服务端那侧的配置/数值/掉落数据，被搬到本地给 runner 查。

一句话：**他在客户端里塞了一份会应答的「服务端替身」＋服务端数据**。客户端以为自己在跟服务器说话，其实对面是自己。

### 7.3 与「屏蔽式单机」的本质区别

| 维度 | 屏蔽式（拦请求 / 断网 / DNS 黑洞 / 改 socket 返回） | 他这套（本地服务端） |
|---|---|---|
| 改的是什么 | 让应答**消失** | 让应答**由本地产生** |
| 游戏看到的结果 | 超时、错误码、`INVALID_CLIENT_OR_NETWORK_ERROR` 一类分支 | 正常回包，和真服一致 |
| 功能完整性 | 只保留「客户端自己算得出来」的部分；依赖下发的（配置/结算/匹配/活动/校验）全缺，常见卡加载、界面空白、玩法不可用 | 全量走通，因为服务端逻辑真的在跑 |
| 服务端权威校验 | 无从谈起，客户端自说自话 | 仍在本地按服务端规则算（所以数值/结算更"真"） |
| 数据依赖 | 无 | 必须有服务端配置库（`nedata.db`） |
| 工作量 | 小（几处 hook/改跳转） | 大（拿到/重写服务端逻辑 + 搬数据 + 适配整个协议） |
| 副作用 | 容易留下"半残"体验和异常上报 | 与联网体验等价，难被察觉（也就不容易被判定为改包） |

**为什么"他的更完整、比你屏蔽的还牛"**：屏蔽只能改变「有没有人回答」，创造不出「回答的内容」。他补的恰恰是内容——协议应答 + 数值数据。这两样是改包者手里最值钱的东西（要么脱壳 dump 出来，要么按官方规则重写），所以这类包少见。

### 7.4 对他的修改功能的连带解释

`core.bundle` 里同时能看到 `Unlock`、`Shua_b`、`CheatK`… 一类类名 ⇒ 他的**修改功能和离线化在同一层（C# 热更层）实现**：既然是整套 C# 逻辑重编，加功能、改数值、做离线是同一件事。所以「不影响任何修改功能」在我们只换 `infinity_gate.js` 的方案下天然成立 —— 我们碰的那一层跟他改的那一层完全不相干。
