# 公主连结 11.7.2 — 雷电（x86_64）适配落地（2026-10-31）

> 设备：雷电模拟器 `emulator-5554`（Android 14 / x86_64 宿主 / root）｜包：`com.bilibili.priconne` vc352 / 11.7.2
> 用户口令：「雷电模拟器已root已安装《公主连结》星光包…打开菜单就提示【native未就绪】…先看下问题，并看看 mod 菜单最新源码有没有修复这个问题」
> 结论：**不是菜单版本问题，是 ABI 问题**；框架源码里没有、也不需要「修 x86」，只要按底包 ABI 多出一套 so 即可。

## 1. 根因（设备日志实证）

```
E StarryNativeLoad: java.lang.UnsatisfiedLinkError: dlopen failed: library "libstarry_magic.so" not found
I StarryApp: native ensureLoaded=false path=
I MenuService: native menu shown mode=ACTIVITY          ← Java 菜单照弹
→ 菜单显示「暂无功能列表（native 未就绪）」
```

| 项 | 实况 |
|---|---|
| PCR 官方 11.7.2 包内 ABI | `lib/arm64-v8a` + `lib/armeabi-v7a` + **`lib/x86_64`**（游戏自带 x86_64） |
| 雷电装机后 `primaryCpuAbi` | `x86_64` ⇒ PackageManager **只解出 `lib/x86_64/`** |
| 星光包注入 | 历史上只有 `lib/arm64-v8a/libstarry_magic.so`（`Application.mk` = `APP_ABI := arm64-v8a`） |
| ⇒ | 进程内永远看不到 `libstarry_magic.so`；`/proc/<pid>/maps` 里也没有 |

**注意**：PCR 在雷电上是**原生 x86_64 直跑**，不经过 houdini 转译（maps 里 `libil2cpp.so` 就是 x86_64）。
所以补 arm64 无用、也不需要 houdini 相关的降级方案。

## 2. 做法（一份包两端通用，不是给模拟器单出包）

1. 新增 PCR 私有 mk `app/src/main/jni/Android_pcr.mk`（legacy 入口 `Main.cpp` + `STARRY_GAME_PCR`，
   带 `-fno-emulated-tls` + `-Wl,--exclude-libs,ALL`；**不碰**公共 `Android.mk`）。
   理由：公共 mk 无条件声明 `wxsj_dll_hf2/hf3` 两个 prebuilt，而它们被 `.gitignore` 忽略、本 checkout 没有
   ⇒ 公共 mk 直接 abort。
2. 新增出包脚本 `scripts/pcr_x64_surgical.sh`：
   - `APP_ABIS` 留空 ⇒ 用 `04_scripts/_common/detect_abis.py <底包>` 自动判定（本包 → `arm64-v8a x86_64`）
   - `ndk-build` 一次出两套 so + 各自带 `libc++_shared.so`（x86_64 侧游戏包没有，必须自带）
   - gradle 出最新菜单 → `classes13.dex`（`StarryApp` 改继承 `com/bilibili/priconne/App`）
   - 外科 zip 合并：只换 `classes13.dex` + `lib/*/libstarry_magic.so` + `lib/*/libc++_shared.so`；
     `classes.dex`~`classes12.dex` / `resources.arsc` / `AndroidManifest.xml` **sha256 逐字节断言相等**
   - zipalign + apksigner（`CN=StarryMagic`，与已装同签 ⇒ 覆盖安装，不动 10GB 热更）
3. 底包＝设备现装星光包只读拉取：`02_apks/公主连结/公主连结_11.7.2_device_starry_20261031.apk`
   （1,895,674,685 B，md5 `738da533527ffcfc11e814512c4737b6`）。

> ⚠️ 拉底包**必须用 `adb pull`**：`su -c 'cat base.apk'` 出来的流比原文件大 8.5 MB 且 zip 中央目录损坏
> （`BadZipFile: Bad magic number for central directory`），本文件是世界可读的，不需要 root。
