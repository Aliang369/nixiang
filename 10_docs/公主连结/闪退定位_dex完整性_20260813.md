# 公主连结 11.7.2 — SIGBUS/SIGSEGV 定位（2026-08-13）

## 现象
改包后约 1–2s 被 native 杀掉：`signal 7 (Bus error)` 或 `signal 11 (Segmentation fault)`，无 Java 崩溃栈、无新 tombstone。

## A/B（每次 `pm uninstall` 后干净安装，MT 路径）

| 改动 | 结果 |
|------|------|
| 官方原签 | 活 |
| MT 零改动只重签 | 活 |
| 只加 `assets/starry_probe.txt` | 活 |
| 只改 `AndroidManifest.xml`（加权限） | 活 |
| 往 **`classes12.dex` 新增** `starry.probe.Probe` | **活** |
| 改 `classes8`（Gatekeeper Toast / TapLogger 字符串） | **死** |
| 改 `classes4`（PermissionActivity 字符串） | **死** |

包 diff（toast vs zero）：仅 `classes8.dex` + `META-INF/*`；asset vs zero：仅新 asset + 签名块，dex 哈希全同。

## 结论
1. **不是 apktool 专属问题**；MT 精细改已有「受保护 dex」同样杀进程。  
2. **不是「一改 dex 就死」**：`classes12` 可改/可增类；`classes4`/`classes8` 不可。  
3. 更像是 **部分 dex 完整性/哈希校验**（疑 Tap/tersafe 等），失败后 native 自杀。  
4. Toast/Gatekeeper 本身不是根因；动到受保护 dex 才会闪。

## 过检候选（改包侧）
1. **不要改** `classes4` / `classes8`（及后续实测会死的 dex）。  
2. 菜单/注入类放进 **`classes12`（或继续测可写的 dex / 新 `classes13`）**。  
3. **Manifest** 可改（权限 / Application / Service）。  
4. **只加 so / assets** 可（需再实锤 so）。  
5. 启动加载：用 Manifest 换 `Application` / 注册 `ContentProvider`/`Service` 指向新 dex 类，**避免**改 `PermissionActivity`/`UnityPlayerActivity` 所在受保护 dex。  
6. 备选：官方/纯重签包 + **运行时**注入（Florida/壳）；或跟斌哥 `libSDKloading` 运行时过检。

## 复测注意
脏覆盖安装会误判；务必 `pm uninstall` 后再装。
