# 公主连结 11.7.2 — 星光方案（bilibili 渠道）

> 包名 `com.bilibili.priconne` · vc352 / 11.7.2 · 渠道 bilibili（官方签名 `O=bilibili` / `META-INF/BILIGAME.RSA`）
> `game_id`：`gzlj`（`GameConfig.h` → `STARRY_AUTH_GAME_ID`）
> 正式包：`08_output/公主连结/公主连结_11.7.2_gzlj_双ABI_20261128-releaseSigned.apk`

## 1. 一句话

外科 zip 组装 + 双 ABI（arm64-v8a / x86_64）：官方 `classes*.dex`、`resources.arsc` 逐字节保留，只加一份星光 dex、两套 `libstarry_magic.so`/`libc++_shared.so`，并把**二进制 Manifest** 换成打过补丁的一份（入口 `application@name=com.starry.magic.StarryApp` + `MenuService` + 2 条权限）。雷电 `emulator-5554`（x86_64）实测：native 加载、19 个挂点全命中、菜单与功能正常。

## 2. 三条硬约束

1. **禁止对游戏包 `apktool b`**：整包重建会污染 `resources.arsc`/dex → TSS（`libtersafe2`）在约 1.5 s 内 SIGBUS 杀进程。apktool 只用来解星光小模板。
2. **禁止 `pm uninstall`**：热更约 10.9 GB（`/data/data/com.bilibili.priconne`）。只能用覆盖安装。
3. **受保护条目一个字节都不能变**：`classes.dex`~底包最大序号、`resources.arsc`。出包脚本内含 sha256 全等断言。

## 3. 底包

```bash
adb -s emulator-5554 pull <base.apk> 02_apks/公主连结/公主连结_11.7.2_official_device_20261127.apk
```
- 必须用 `adb pull`：`su -c 'cat base.apk'` 出来的流比原文件大 8.5 MB 且 zip 中央目录损坏（`BadZipFile: Bad magic number for central directory`）。该文件世界可读，不需要 root。
- 事实：1,878,019,712 B｜md5 `ee6b3417d7beb7e0892d381b1cdb8233`｜sha256 `8417c0f5b06e02464612beea9a1c85e4a6a78ac5fce3003ffd25e936e4edfbce`｜zip 条目 22206（`testzip()=None`）
- dex 只有 **4 个**：`classes.dex` 9,501,800 / `classes2.dex` 7,964,224 / `classes3.dex` 171,652 / `classes4.dex` 720
- ABI：`arm64-v8a`(17 so) / `armeabi-v7a`(17) / `x86_64`(14)；雷电 `primaryCpuAbi=x86_64`，`libil2cpp.so` 为 x86_64 原生直跑（不经 houdini）
- `aapt2`/manifest：`application@name=com.bilibili.priconne.App`、`appComponentFactory=androidx.core.app.CoreComponentFactory`、`minSdk 21 / targetSdk 30 / compileSdk 36`
- dex 侧渠道判定：`com/bilibili` 1790 处、`TapSDK`/`TapLogin` = 0，只有 `com/taptapshare`（分享 SDK）⇒ 不需要 TapTap 过签/网页登录那一套

## 4. 静态分析定论（挂点为什么这么写）

`assets/bin/Data/Managed/Metadata/global-metadata.dat`：metadata **version 31**、39.9 MB、240,783 方法 / 29,435 类型；Unity **6000.0.58f2**（`libunity.so` 里是 2018.3.0a1 的旧串，以 `globalgamemanagers` 为准）；`libil2cpp.so` 导出 `il2cpp_class_from_name` / `il2cpp_class_get_method_from_name` / `il2cpp_field_get_offset` ⇒ 运行时按名解析可行（xdl+dynsym）。

| 符号 | 归属（metadata 实证） |
|---|---|
| `get_deltaTime` | 9 个同名，唯一属 `UnityEngine.Time` |
| `get_IsPlayerUnit` | 唯一，属 `Elements.UnitCtrl`（methodIndex 20854） |
| 17 个 `get_Total*` | 全部属 `Elements.UnitData`（如 `get_TotalHp`=31960、`get_TotalAtk`=31962） |
| UnitCtrl→UnitData 通路 | UnitCtrl **没有** UnitData 字段；有 `<UnitParameter>k__BackingField`(field 12673)→`Elements.UnitParameter`，其 `<UniqueData>k__BackingField`(23919) 类型 = `Elements.UnitData` |

运行时实测偏移与静态预测一致：`[Pcr] UnitCtrl.<UnitParameter>k__BackingField @ +0x168 UniqueData=+0x10`、`get_IsPlayerUnit off=0x168 param=1`。

## 5. Manifest 二进制补丁（换官方底包时必做）

官方包的 `application@name` 是 `com.bilibili.priconne.App`，不带星光入口 —— 不改它，star 框架一行日志都不会有（现象：菜单不弹、logcat 无 `StarryApp`）。

```bash
python 04_scripts/公主连结/pcr_manifest_patch.py \
  <底包取出的 AndroidManifest.xml> \
  07_patched/公主连结/surgical/AndroidManifest.xml
```
- 补丁器的取输入方式：`zipfile.ZipFile(apk).read("AndroidManifest.xml")`（不要解整包）
- 唯一允许的 4 类差异：① `application@name` → `com.starry.magic.StarryApp`（原地改值，resId 0x01010003 不变）② `+uses-permission SYSTEM_ALERT_WINDOW` ③ `+uses-permission FOREGROUND_SERVICE_SPECIAL_USE` ④ `</application>` 前 `+service com.starry.magic.menu.MenuService`（`enabled`/`exported=false`/`foregroundServiceType=specialUse`/`stopWithTask=false`）+ 子元素 `property PROPERTY_SPECIAL_USE_FGS_SUBTYPE`
- 官方 279 个元素 / 801 条属性零改动（脚本用 `SequenceMatcher` 逐条比 `(ns,name,resId,type,rawValue)`，白名单外任何差异直接不落盘）
- 两个坑：串池**只能追加**（旧索引不变，原 blob 整块搬移）；**resource map 是稀疏的**（47/347），新属性名的 res id 必须从 `n_ids` 起补 0 填到目标索引，否则 `foregroundServiceType`/`stopWithTask` 读成 0＝属性等于没写
- 不需要 `StarryInitProvider`（入口就是 `application@name`；多一个 provider 只多 authorities 冲突面）

## 6. 出包

```bash
cd mod菜单/starry-mod-menu
STARRY_BASE_APK=02_apks/公主连结/公主连结_11.7.2_official_device_20261127.apk \
PCR_BINARY_MANIFEST=07_patched/公主连结/surgical/AndroidManifest.xml \
bash scripts/pcr_x64_surgical.sh          # 加 STARRY_INSTALL=1 则出包+覆盖安装
```
- ABI 由 `04_scripts/_common/detect_abis.py` 按底包实况判定（本包 → `arm64-v8a x86_64`）；私有 mk `app/src/main/jni/Android_pcr.mk`（公共 `Android.mk` 未动）
- **dex 序号必须按底包实况算**：`DEX_IDX=$(python 04_scripts/_common/next_free_dex.py "$BASE")` → 本包 `classes5.dex`。ART 的 DexPathList 只按 `classes.dex→classes2.dex→…` **连续**扫描，遇第一个缺号即停；在只有 4 个 dex 的底包上写死 `classes13.dex` 会被断层在 5，表现是启动即崩 `ClassNotFoundException: com.starry.magic.StarryApp`
- `StarryApp.smali` 的 `.super` 由脚本 patch 成 `Lcom/bilibili/priconne/App;`，四个父类调用一并改写（否则 GSC/权限链崩）
- 签名：`CN=StarryMagic`（`01_tools/starry_release.jks`），v1/v2/v3 全 true

产物事实（2026-11-28）：1,881,003,029 B；新增条目只有 `classes5.dex`(649,492 B) + `lib/{arm64-v8a,x86_64}/{libstarry_magic.so,libc++_shared.so}`；`classes.dex/2/3/4`、`resources.arsc` 与底包 sha256 全等；Manifest sha256 = 补丁文件 `aadf8630ac1f6ddcdb99b68cc353be28aca1d379a1859fc2489be730a7366cfc`。

## 7. 装机

```bash
adb -s emulator-5554 install -r -d -g 08_output/公主连结/…-releaseSigned.apk
```
- 雷电这台 ROM 上 `su -c 'pm install -r -d /data/local/tmp/x.apk'` 会失败：`INSTALL_FAILED_MEDIA_UNAVAILABLE: Failed to restorecon`（`getenforce`=Permissive、空间充足、无 `/data/app/vmdl*.tmp` 残留）⇒ 走流式 `adb install`
- 异签名（官方 `O=bilibili` vs `CN=StarryMagic`）无法覆盖，必须先处理旧包；**卸载会让 10.9 GB 热更重下**，动手前要用户点头
- 装机期间大包（1.9 GB）会让 `emulator-5554` 短暂 offline，几十秒自愈，装完再抓日志

## 10. 挂点实现（`Games/PcrMod.cpp`）

| 功能 | 挂点 | 说明 |
|---|---|---|
| 全局变速 | `UnityEngine.Time.get_deltaTime` × 倍数 | 标题页即可测 |
| 属性数值 | `Elements.UnitData` 的 `get_TotalHp`/`get_TotalHpWithoutExtra`(i64) + 11 项 i32（Atk/Def/MagicAtk/MagicDef/Critical/MagicCritical/Dodge/Accuracy/PhysPen/MagicPen/LifeSteal） | 输入框 1–999999；进战斗即生效，不必重戴装备 |
| 能量/波次/恢复率 | `TotalHpRecoveryRate`/`TotalEnergyRecoveryRate`/`TotalEnergyReduceRate`/`TotalWaveHpRecovery`/`TotalWaveEnergyRecovery` | **passthrough（只计数不改值）**：改成 9999 会打爆 TP 循环 ⇒ 自动大招连放 |
| 敌我过滤 | `Elements.UnitCtrl.get_IsPlayerUnit` → side 表；`Total*` 只读表 | 未登记单位不改（失败关闭）；表项带 GC 弱句柄，查表先验存活 |

## 11. 已知限制

- **属性开启时进地下城**：服务端回 `错误代码 205`。守门方案实测无效已回退，用户决定先不管。
- `Total*` 同时被面板与战斗读取，属性在角色页也会显示为设定值（属预期）。
- `attrHit` 诊断每 2 s 一行，无命中也会打空汇总。
