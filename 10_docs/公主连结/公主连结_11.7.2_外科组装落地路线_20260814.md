## 1. 受保护 / 可动文件清单（实测）

| 文件 | 状态 | 说明 |
|------|------|------|
| `classes.dex`~`classes11.dex` | **受保护，不可动** | 尤其 classes4（App/AceApplication/ACE）、classes8（com.tencent.tp TSS） |
| `classes12.dex` | **可动/可增** | 文档实证可改可增类 |
| `resources.arsc` | **受保护，不可动** | 系统解析器严格（尾部追加都拒绝，见探针实验）+ TSS 校验（apktool 重建被杀） |
| 新增 `classes13.dex` | **可（新增不在校验清单）** | 建议放全部星光 smali |
| 新增 `libstarry_magic.so` / `libc++_shared.so` | **可** | 文档实证加 so 活 |
| `assets/` | **可** | 文档实证加 assets 活 |
| `AndroidManifest.xml` | **可改** | 文档实证改 manifest 活 |

**校验方**：腾讯 TSS（`libtersafe2.so`/`libtprt.so`）+ ACE 反作弊。
**两条校验路径**：
1. Java：`App extends AceApplication` → attachBaseContext → native `initialize(sourceDir)`（读 APK 校验）
2. Native：`libil2cpp.so`/`libunity.so` DT_NEEDED 依赖 `libtprt.so` → Unity 加载即自动 dlopen，校验与应用无关（这就是"换 Application 后改 arsc 仍死"的根因）

## 2. 外科组装方案（避开受保护文件）

**核心原则：官方受保护文件字节级保留，只增不改。**

### 2.1 打包方式

1. **保留**：官方 `classes.dex`~`classes12.dex`、`resources.arsc` **一个字节都不动**。
2. **新增 `classes13.dex`**：用 `01_tools/smali/smali-2.5.2.jar` 把星光 smali 单独编译成新 dex（不动任何现有 dex）。`com.starry.*` 全部放这里。
3. **Manifest**：用 **MT APK MCP**（手机 MT）只改 manifest——加权限（SYSTEM_ALERT_WINDOW/FOREGROUND_SERVICE…）、注册 `MenuService`、Application 指向 StarryApp（或保持官方 App + 由注入入口启动）。MT 只改 manifest 不碰其他文件。
4. **新增 so**：`libstarry_magic.so` + `libc++_shared.so`。
5. **新增 assets**：花藤 PNG、MagicRes 运行时用到的素材等（assets 校验不敏感）。
6. **重签**：zipalign + apksigner（注意 >2G 包有 apksigner 32 位溢出问题，须保持 <2G；重写 zip 时 AndroidManifest 可 DEFLATED、resources.arsc 必须 STORED 且 header.size 自洽）。

### 2.2 菜单资源去资源化（因 arsc 不能动）

菜单 UI 不再从 `resources.arsc` 取资源，改为代码生成：

| 原资源 | 替代方案 |
|--------|----------|
| `R.color.magic_*` | 代码写死色值常量 |
| `R.drawable.magic_*`（shape/渐变/描边） | `GradientDrawable`/`StateListDrawable` 代码生成 |
| `magic_vine_corner.png` 花藤 | 放 `assets/`，运行时 `BitmapFactory.decodeStream` |
| Switch 五角星滑块/轨道 | 代码 `StateListDrawable`（可能退化用系统 Switch） |
| 矢量图标（toast 对勾/星星/叉、下拉箭头） | 转 PNG 走 assets，或代码 Path 绘制 |

**落地方式**：新增 `MagicRes.java` 集中封装所有资源生成，`NativeMenuController.java` 约 40 处 `R.drawable.*`/`R.color.*` 引用改为调用它。

### 2.3 观感影响评估

- **一致**：配色、面板背景（半透明+双描边+圆角）、按钮（镂空胶囊/红色危险）、分隔线、输入框、下拉菜单、Tab、花藤。
- **可能略变**：Switch 五角星滑块（可能退化系统 Switch）、个别矢量图标（转 PNG 则一致，代码 Path 可能略糙）。
- **不变**：布局、Tab 结构、功能列表、交互、文字、悬浮球逻辑。

### 2.4 可恢复性

- **正式成品**仅为 `…_surgical-releaseSigned.apk`；旧 `inject`/`starry-releaseSigned` 已废弃（TSS 杀）。
- 动手前可备份 `NativeMenuController.java`；`magic_*` 资源可留作参考不引用。
