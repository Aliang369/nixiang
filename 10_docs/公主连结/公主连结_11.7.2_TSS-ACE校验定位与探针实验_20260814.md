## 2. 校验方身份确认（本文结论）

**校验者 = 腾讯 TSS（`libtersafe2.so` + `libtprt.so`）+ ACE 反作弊**，Java 宿主分布：

| dex | 关键包 | 角色 |
|-----|--------|------|
| **classes4** | `com.bilibili.priconne.App`（extends `AceApplication`）、`com.ace.gshell.*`、`com.bilibili.droid.*` | manifest 注册 Application；ACE Java 宿主 |
| **classes8** | `com.tencent.tp.*`（`TssSdk` / `TssInfoPublisher` / `TssIOCtlResult`…） | TSS SDK 本体 |

佐证：
- `libil2cpp.so` 等 so 内**无** `resources.arsc` / `classes4.dex` 明文（校验清单不在 so 明文，疑加密/内置）。
- `libnative.so` 的 `integrity_check` / `IntegrityCk` 实为 **SQLite** 内嵌字符串（`PRAGMA integrity_check`），排除。
- 全 so 仅 `libtersafe2.so` / `libil2cpp.so` 含 `__tp` 相关串；`libtersafe2.so` 有 `tss_recv_sec_signature`、`TssSDKOnRecvSignature`、`kill`、`abort`。
- `assets/__tpinfo.tp` / `__tpinfo.tsc.sig` / `__tpsinfo.t.p.sin` 存在（腾讯保护类标记，具体用途待核）。

## 3. 完整校验链（第一条，已钉死）

```
系统启动 App(com.bilibili.priconne.App，extends com.ace.gshell.AceApplication)
  → AceApplication.attachBaseContext → attachBaseContextShell(context)
      getApplicationInfo() → packageName / nativeLibraryDir / sourceDir / splitSourceDirs
  → native App.initialize(pkg, filesDir, nativeLibraryDir, sourceDir, splitDirs)
  → libtersafe2.so（static 里 loadLibrary("tersafe2")+loadLibrary("tprt")）
      拿 sourceDir(=APK 路径) 读包 → 对受保护文件算哈希/完整性校验
  → 校验失败 → native 自杀 → SIGBUS/SIGSEGV（无 Java 栈）
```

要点：
- `sourceDir` 正是 APK 完整路径 → TSS 直接读**安装目录里的 base.apk 原文件**做校验。
- `AceApplication` 静态块 `loadLibrary("tersafe2"); loadLibrary("tprt");`。
- `TssSdk.init(context, game_id)` 走同一 `libtersafe2.so`（`com.tencent.tp` 原生方法 `getsdkantidata`/`init`/`setappobject` 等）。

### 3.1 第二校验路径（已确认执行者：native `libtprt.so`）

文档 08-13 已实证：**把 Application 换成 StarryApp（绕过 `AceApplication.initialize`）后，改 arsc 仍 1s 后 SIGBUS**。即存在不经过 Application 的第二条触发路径。

**已确认**：用 Python 解析 ELF DT_NEEDED，`libil2cpp.so` **和** `libunity.so` 都依赖 **`libtprt.so`**（腾讯 TP 运行时，1.8MB）：
```
libil2cpp.so: liblog,libm,libdl,libc,libstdc++,libtprt.so
libunity.so : libandroid,liblog,libz,libEGL,libmediandk,libm,libdl,libc,libstdc++,libtprt.so
```
→ **Unity 加载即系统自动 dlopen `libtprt.so`，TP native 完整性校验随引擎加载执行，与应用无关**。这就是"换 Application 改 arsc 仍死"的根因。`libtprt.so` 不依赖 tersafe2（tersafe2 由 Java `loadLibrary` 显式加载）。

| 候选 | 结论 |
|------|------|
| `libtprt.so`（DT_NEEDED 被 il2cpp/unity 依赖） | ✅ **第二路径执行者**：随 Unity 加载自动初始化，读 APK 校验 |
| `OneSDK_Tss`（classes7，`TssSdk.init` 包装） | ❌ 无任何 Java 调用者；il2cpp 无 `OneSDK_Tss`/`TssSdk` 类引用（仅 `tersafe2` 字符串） |
| `GSCPubCommon.applicationAttach`（bilibili GSC SDK） | ❌ 只做 Track/缓存/路由初始化，不碰 TSS/ACE |
| manifest 注册的 3 个 **ACE 独立进程服务**（GP6/GP7，exported=true） | ❌ 无 Java `startService` 调用；native 侧触发证据不足，次要嫌疑 |

**native 侧绕过候选**（后续可选，风险由高到低）：
- **替换 `libtprt.so` 为无害 stub**：保留被 il2cpp/unity 引用的导出符号，逻辑 no-op。前提：stub 符号表覆盖全部被引用符号，且 tprt 无自校验/被其他 so 校验。
- **patch `libtprt.so` 自杀/校验点**：定位读 APK + 算哈希 + kill/abort xref，NOP。
- **改 il2cpp/unity 的 DT_NEEDED 摘除 tprt**：动 124MB/26MB 引擎 so，自身可能在校验清单，风险高。

## 4. 探针实验（决定性，判断 arsc 校验粒度）

**目标**：区分 arsc 校验是"整文件哈希"还是"条目/结构级"。

**构造**：官方 classes*.dex + resources.arsc 原样，仅 **arsc 尾部追加 40 字节 `0x00`**，重签。

**⚠️ 构造要点（实测踩坑 ×2）**：
1. arsc 经解析确认是**单一 ResTable chunk**（`type=0x0002`，`header.size`=文件大小=598808），**无尾部自由区**。仅追加字节会破坏 `header.size` 自洽 → **Android 系统 `ApkAssets.nativeLoadFd` 直接拒绝解析**（系统层，非 TSS）。须同步把 `header.size`（offset **4**，非 8）+40，使 chunk 自洽；尾部的 40 字节落在 packages 之后，解析器按 `packageCount` 精确读取，不会越界读到。
2. **Android 要求 `resources.arsc` 必须 STORED（未压缩）**（官方 arsc `compress_type=0`，offset 0）。用 `zip` 命令追加更新会默认重新 DEFLATE 压缩 arsc → `ApkAssets.nativeLoadFd` 失败。必须用**全 STORE 重写 zip**（Python zipfile 重写，全条目 STORED，APK 1.89G→2.35G 膨胀 1.24x）。

| 装后结果 | 结论 | 菜单意义 |
|----------|------|----------|
| **活** | 非整文件哈希，条目/结构级 | 可二进制增量往官方 arsc 加 magic 资源，菜单 UI 资源全保留，零代码改造 |
| **死** | 整文件哈希（碰 arsc 即篡改） | 需 patch native 校验点，或菜单去资源化 |

实验包：`08_output/公主连结/公主连结_11.7.2_probe_arscAppend40-releaseSigned.apk`

**注意**：脏覆盖安装会误判；必须 `pm uninstall` 后干净装。装探针包会清掉设备当前官方包数据。

## 5. 绕过路线（依探针结果分支）

### 路线 A（活 → arsc 可增量加）
- 外科组装保留官方 dex/arsc 字节；用二进制增量往 arsc 追加 `magic_*` 资源条目（类型池/string pool patch），`R$*.smali` 指向新 ID。
- 菜单资源全可用，无需代码化。工作量：写 arsc 增量 patch 工具（`_merge_starry_res.py` 思路改为直接二进制改 arsc）。

### 路线 B（死 → arsc 不可碰）
1. **菜单去资源化**：`R.color.magic_*` 写死色值、`R.drawable.magic_*` 用 `GradientDrawable`/`StateListDrawable` 代码生成、花藤 PNG 走 `assets/`。配合外科组装（新增 `classes13.dex` 装 starry smali），完全不碰校验清单。**已验证可行**（路径① noArsc 活）。
2. **patch native 校验**：定位 `libtersafe2.so` 校验/自杀点（找 `resources.arsc` 读取、SHA256/MD5、`kill`/`abort` xref），NOP 自杀分支，或 patch `AceApplication.initialize` 恒返回 0。治本但工作量大。
