## 1. 三轮迭代与实证（全部有日志/tombstone 证据）

### v1：GC 弱句柄存活校验 → 敌我误杀
side 条目挂 `il2cpp_gchandle_new(obj,0)` 句柄，查表先 `get_target` 验活。**实测战斗中每个登记 ~10ms 内被判死**（`side stale hit`），0 次 attr 命中，功能全哑。诊断显示 API 创建后立即 `get_target` 返回 OK，但隔一次调用再查就异常 → 建句柄/废句柄 churn 踩中句柄 ID 回收。

### v2：句柄转诊断采样 → 闪退（tombstone 实证）
只留前 3 次登记做 `new→get_target→free` 采样。**战斗初始化时 `il2cpp_gchandle_free` 在 il2cpp 内部 SIGSEGV**（`tombstone_01`：pc 0x2f240c0 libil2cpp，返回地址 0x15ad8 = `blr g_gcFree`；tid UnityMain）。上一场 3 次采样幸存纯属运气。**结论：Unity 2022.3（metadata v31）下从 hook 线程调 gchandle API 是地雷，与返回值/用法无关，整层移除。**

### v3（终版）：信任条目 + 跨局清表
- 敌我瑕疵的防御改由两层承担：**30s 静默清表**（跨局残留主场景）+ **同址重登自愈**（新单位 IsPlayerUnit 会覆盖同址旧标记，且 Total* 未知不改仍兜底）。
- 20:29 战斗实测：10 单位登记（5 我方+5 敌方）n 正常递增、无 stale 误杀——该部分已验证。

### Java 侧：启动状态抹除链（并行发现的框架级坑）
初始化早期一次瞬时授权失败 → `lockAllFeatures → forceFeatureOff` **写偏好**（清掉 key1 开关/key2 数值/key4 变速）→ 60s reapply 忠实推 OFF/默认值 → 用户开关被无声关闭（`ready attrOn=0`，战斗 0 加成）。另：我首版 INPUT 行内推送在偏好为空时把默认值写回偏好（次生 bug，已撤）。
修复：`forceFeatureOff` 去偏好写入（native `nativeSetAuthorized(false)` 仍封死功能，防滥用语义不变）；`NativeMenuController.refreshFeatures` 后挂 **延迟恢复重试**（800ms 起每秒 reapply 直到 session live，上限 30 次）。

## 6. 2026-08-29 深夜追加：两次装机事故与铁律

### 6.1 zip 条目路径 bug（21:03 装机 so 没换成功）
手写 `cd lib && zip -u ../in.apk arm64-v8a/libstarry_magic.so` → 条目名变成 `arm64-v8a/...`，
正确路径 `lib/arm64-v8a/` 下旧 so 原封不动 → 设备一直跑旧 gchandle so；21:08 验证场是侥幸，
22:45 用户进关卡再次踩雷（不开功能也崩，崩在 IsPlayerUnit 钩子的 diag gchandle_free，与开关无关）。
**铁律：打包后必须从成品 APK 里 `unzip -p` 抽 so 做字符串自检 + md5 对比编译产物，只查编译产物不算数。**

### 6.2 共享 Android.mk 单点（22:58 装机装错游戏）
mk 被另一并行会话切到 STARRY_GAME_WHRHX，ndk-build 产出 Whrhx so；打包自检只查了"无 gchandle"
没查"[Pcr] 必须存在"→ 把 Whrhx so 装进了公主连结（会按错游戏 RVA 乱挂钩）。
**铁律：① 打包自检必须双向查——本游戏标签必须存在 + 其他游戏标签必须不存在（pcr_so_only.sh 原有此检查，手搓流程不得绕开脚本）；② mk 是跨会话共享单点，需要特定游戏 so 时用隔离拷贝构建（cp -R jni → 改拷贝内 mk → ndk-build 指向拷贝），不与并行会话抢 mk。本次终版 so 即隔离构建产物（md5 45cb5486...，装机 23:05:57）。**
