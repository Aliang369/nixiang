## 7. 第三轮（b2 运行期）：native 未加载 —— 打包缺依赖

**症状**：菜单打开显示「暂无功能列表（native 未就绪）」。

**日志证据**（`runtime/logcat_20261119_152114.txt`，两次冷启（15:17 / 15:21）完全一致）：

```
I MenuService: onCreate native ensureLoaded=false path=
I MenuService: bootstrap native ensureLoaded=false path=
W MenuService: nativeInit failed: No implementation found for void com.starry.magic.bridge.ModBridge.nativeInit(android.content.Context) - is the library loaded, e.g. System.loadLibrary?
E StarryNativeLoad: load apk lib-dir so failed     （同一进程内 4 次）
```

**静态根因**（Lead 定位，本机独立复现）：b2 的 26 个 `lib/arm64-v8a/*.so` 里**没有 `libc++_shared.so`**，而 `libstarry_magic.so` 的 `.dynstr` 含 `DT_NEEDED` 项 `libc++_shared.so`（偏移 7986）⇒ `System.load` 必然 dlopen 失败。

**源码印证**：`StarryNativeLoad.java:140-153` 的逻辑正是「先 `System.load(<dir>/libc++_shared.so)`，再 `System.load(so)`」，注释明写直接 dlopen 本 so 会报 `cannot locate symbol __emutls_get_address`。

**对照证据**：`08_output` 下 5 个已交付可用的星光包（无限升级 4 个 + 断网版 wxsjdz1）**全部**同时含 `libstarry_magic.so` 与 `libc++_shared.so`。

**定性**：**打包缺依赖**，不是补丁 / 挂点 / 签名问题；dll、dex、Manifest、so 本体都不用改。

**本机复现**：

```
python 13_scratch/冒险战争/install/check_apk_libs.py 07_tmp/mxzz_b2.apk
abi=arm64-v8a  so_count=26
HAS libstarry_magic.so     = True
HAS libc++_shared.so       = False
MISSING: libc++_shared.so        -> exit 5
```
