## A 区 · 长期硬约束（默认生效）

### A#1 实现必须先静态分析 + 代码反推验证

**用户原话（2026-11-19，逐字保留）**：
> 「所有的功能和代码修改全部需要通过静态分析，分析完之后通过代码反推去验证后得出完整的结论在下手」

**执行解读（Lead，与上句分开列）**：
1. 只有「静态分析 + 代码反推验证」得出完整结论之后，才允许改代码/出包；不许先出包装上试、先猜偏移、边试边改。
2. 静态分析 = 读 dump.cs / DummyDll / metadata / 反编译 IL / 壳内资源，凭证据定位；
   代码反推验证 = Cecil 反编译原方法体、xref、IL 栈与分支结构对照、签名与字段核对、字节级 sha/长度比对，
   从成品反推回分析结论，一致才算「完整结论」。
3. 任何「待验证」推断不得进入实现；结论不完整就停下补证据或报 Lead，不许用运行期试错代替静态证据。
4. 顺序固定：静态定位 → 反推验证（证据文件含命令与输出）→ 结论表 → 才写实现 → 出包 → 装机 + precheck → 用户 L3 终审。
5. 已写实现但无静态结论支撑的部分必须回退并在报告说明。

- 检查者：无机器检查（靠复核员/Lead 人工审查 + `实现记录_星光版.md` 的「证据」列）。
- 来源：Lead 2026-11-19 转发用户当轮新增硬要求。
