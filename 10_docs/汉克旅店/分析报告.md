### 1.1 引擎结论对外的影响（最关键一条）

## 6. 下一步实现建议（每功能推荐 hook 方式）

### 6.0 先决：改哪里

热更 DLL 是**明文 PE + 明文 UnityFS 包**，两条路都可行，按风险排序：

| 路线 | 做法 | 优点 | 风险 |
|---|---|---|---|
| **R1（推荐）运行时拦截 DLL 字节** | native hook `MyLoadDll.ReadBytesFromStreamingAssets(string dllName)`（dump.cs:792883 类，方法 RVA `0x433F52C`，返回 `byte[]`），把返回的数组换成补丁后的 DLL 字节 | 不动 APK 内 bundle、不动 manifest hash/crc；签名/完整性面最小 | `s_assetDatas` 走 YooAsset 资源而非 StreamingAssets 时该函数可能不被调用（**待运行时确认命中次数**） |
| **R2 静态替换 bundle 资源** | 改 `951c5741….bundle` 里的 TextAsset → 重算 LZ4 块 + 更新 `PackageManifest_*.bytes` 里的 hash/crc → 重打包 APK | 纯静态，无需 hook | 要同时改 manifest 的 hash/crc/文件大小，YooAsset 会校验；一旦算错直接启动失败。**成本明显高于 R1** |
| **R1b 备选加载边界** | hook `HybridCLR.RuntimeApi.LoadMetadataForAOTAssembly`（dump.cs:914389）或 `System.Reflection.Assembly.Load(byte[])`（AOT 侧有实现） | 更靠底层 | 该 API 只加载 AOT 补充元数据，不是主程序集入口；误挂会白干 |

> 三个加载相关锚点（均在 AOT，**可拿 RVA**）：`MyLoadDll`（dump.cs:792883）、`ReadBytesFromStreamingAssets`（RVA 0x433F52C）、`LoadMetadataForAOTAssemblies`（RVA 0x433F66C）。另有 `HotUpdateStartUp`（dump.cs:827387，字段 `MyLoadDll myLoadDll`）与 `AotGameStartTaskSystem`（dump.cs:826707）。

### 6.1 六功能推荐实现

> 全部按「Cecil 补丁 `Assembly-CSharp.dll` → 由 R1 在加载边界换字节」描述；若选 R2，则补丁相同的 IL、只是注入位置不同。
> **红线（hook-rules §24 指纹铁律）**：定位必须用「类型全名 + 方法名 + 参数签名」三元组做运行时解析，**禁止写死 RVA**（热更 DLL 每次热更都变）。

| 功能 | 补丁目标 | 具体做法 | 备注 |
|---|---|---|---|
| **无敌** | `PlayerManager.RefreshHP(bool,bool,bool)` | 方法**出口**处插入：`this.curHp = this.hp;`（或把 `isPlayerHurt` 置 false 的 `stfld` 提到每个 `RefreshHP` 入口） | 更省事的等价写法：hook `PlayerManager.isPlayerHurt` 的**读取**不现实（字段），因此走方法出口。若想保留"免疫"飘字效果，则改为在 1404 行分支前把 `isPlayerHurt` 置 false |
| **伤害倍率** | `MonsterControl.CustomMonsterHurt(float,bool,int,MonsterManager.MonsterBeHarmedType,int)` | 方法**入口**把 `arg1 (finalDamageNum) *= N`，N 走菜单变量 | 单一收敛点，覆盖普攻/法术/技能/召唤物；**不要**改 `totalAttributes.attack`（法术不经过它） |
| **无限技能** | `SkillUseManager.OnUseSkillEnd(int,int)` + `GameManager.SetCoolingTimeMax(int,int)` | ① `OnUseSkillEnd` 入口把 `mpConsume = 0`；② `SetCoolingTimeMax` 入口把 `cdNum = 0`（或 hook 后直接 return，使 `cdMaxList` 保持 0） | 只改 `SetSkillCoolingTime` 无效：`Clamp(baseCdNum,1f,999f)` 兜底最小 1（`GameManager.cs:363`）。`cdMaxList` 归零后 UI 遮罩自动不显示（366 行） |
| **解锁所有角色** | `SaveDataManager.UnlockNewCharacter(int)` 批量调用；或 hook `Save.MainCharacterInfo.get_isUnlock` | ① 在 `MyLoadDll` 完成热更、进入主菜单后，反射遍历 `curSave.characterInfoDic.Keys` 逐个调 `UnlockNewCharacter(int)`；② 或直接改 `isUnlock` 的 getter 恒返回 true（会影响"新获得角色"弹窗逻辑，需实测） | ①更安全：内部会同步 `treasureUnlockDic`（`SaveDataManager.cs:1052`）并写档。**不要**只改字段不写档 |
| **无限金币** | `PlayerManager.RefreshMoney(bool)` | 方法**入口**：`this.curMoney = 9999; this.lastMoney = 9999;`（同时改 `lastMoney` 避免 EVIL_SEVEN 差值扣血） | 硬上限 9999 来自 1984 行 `Mathf.Clamp`；要突破须先 patch 该 clamp（改成 int.MaxValue），否则写多少都被夹回 |
| **无限钥匙** | `PlayerManager.keyCount` 消费点 `UIPropPanelControl` / 或每帧回填 | 最稳：hook `PlayerManager.RefreshKeyCount()` 入口把 `keyCount = 99`（该函数只刷 UI，副作用最小，且每次数量变化都会调） | 字段无 clamp，可直接回填 |
