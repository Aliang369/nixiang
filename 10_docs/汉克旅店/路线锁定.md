## 1. 路线（为什么不是 native RVA hook）

引擎 = Unity IL2CPP + HybridCLR 热更，**玩法类全在热更程序集**，`libil2cpp.so` 里没有它们的机器码
（分析报告已用 dump.cs 91 万行零命中证明）。因此：

1. **Cecil 打 IL 补丁** → `07_patched/汉克旅店/Assembly-CSharp_hkld.dll`（5,292,544 B，sha256 `ef5f3a89…9eef`）
2. **objcopy 内嵌**进 so（`Games/HkldPatchedDll.a`，符号 `_binary_hkld_patched_dll_bin_start`）
3. **native 在程序集加载边界换字节**：按名解析 AOT 方法
   `System.Reflection.Assembly.Load(byte[])`（dump.cs:185289 / RVA 0x450AC3C，**不写死 RVA**），
   Dobby inline hook；仅当收到的 byte[] 是 MZ 且长度 == `kHkldOfficialLen`(5,328,896) 时，
   用 `il2cpp_array_new` 在托管堆按**补丁真实长度**重新分配容器并替换参数（hotfix 模式 §7）。
   长度不符 ⇒ PASSTHROUGH 官方版（不崩不闪退）。
4. **菜单值通道 = 文件镜像**：native 写 `/data/user/0/com.chillyroom.hanksbar.yw/files/starry_config.ini`，
   补丁版 IL 注入 `Starry.StarryConfig`（2s 缓存）读取。HybridCLR 下解释器调 native 不可靠，
   本仓 HybridCLR 游戏（无限升级 / 境界死神激斗）均为该口径。

> 与上一版分析报告 R1 的**修正**：报告想 hook 的 `MyLoadDll.ReadBytesFromStreamingAssets(string)`
> 在 dump.cs 里只被 `LoadMetadataForAOTAssemblies` 使用（AOT 补充元数据 mscorlib 等）；
> `Assembly-CSharp.dll` 走 YooAsset TextAsset → `Assembly.Load(byte[])`。
> 该结论来自 HybridCLR 官方 sample `LoadDll.cs` 的标准写法 + dump.cs 方法清单，**运行期命中次数仍属 NOT PROVEN**。

## 7. 真机验证记录（2026-11-13，设备 f9a116a2 / OPD2404 / Android 15）

### 7.1 两个必须先修的坑（都已修）

1. **Manifest 的 `<provider>` 被塞进 `<uses-permission>` 里**（静默失效，aapt2 字符串检查看不出）
   - 现象：装上去后 `dumpsys package` 无该 Provider、logcat 零 `StarryInitProvider` 行、游戏照常启动（无崩溃）。
   - 根因：`patch_hkld_binary_manifest.py` 里「补 uses-permission」是插在 `<application>` 之前，
     之后沿用**旧的 `app_start`**算 `elem_attrs_end()` ⇒ 插入点落到最后一个 uses-permission 内部。
   - 修法：插 provider 前重新 `find_element(idx_application)`，并新增父子关系硬断言
     （`provider_at` 必须落在 `[app_start, app_end)`）。**只看 aapt2 有该字符串不够，必须看层级。**

2. **`il2cpp_type_get_name` + `free()` 在真机 SIGABRT**
   - 现象：`Abort message: 'Pointer tag for 0x… was truncated'`，栈 `free ← libstarry_magic.so ← pthread_start`。
   - 根因：按签名挑 `Load` 重载时用类型名匹配，`il2cpp_type_get_name` 返回的指针带 tag，交给 `free` 触发 Scudo 断言。
   - 修法：改用 `il2cpp_type_get_type(pt) == 0x1d`（SZARRAY=byte[]，string=0x0e）判别，**完全不碰字符串**。

3. **导出解析顺序**（首版把 `ResolveExport(il2cpp_type_get_type)` 放在匹配之后）⇒ 首轮判据为空、
   静默退化 `GetMethod(klass,"Load",1)`（可能命中 `Load(string)`）。已把解析块提前，并打印命中项
   `paramType=29` 作为证据。

### 7.2 热更覆盖：补丁基线必须是「运行时那份」

- native 首次运行日志：`[Hkld] 未知程序集长度 5328384（期望 5328896）→ PASSTHROUGH 官方版`
  ⇒ 运行时 `Assembly.Load(byte[])` 收到的是 **5,328,384 B**，与包内 bundle 的 5,328,896 B 不同
  （前 5,328,384 字节比对从偏移 136 起有 3,888,466 字节不同 ⇒ **不同一次构建**）。
- 处置：mod 侧把运行时缓冲一次性落盘（`files/hkld_seen_<len>.dll`，见 `DumpSeenOnce`），拉回后作为新基线重打 IL；
  native 判据改为「运行时基线 5,328,384 优先 + 包内 5,328,896 兜底（命中兜底打 WARN）」。
- 结论：**这类 HybridCLR 包不能拿 APK 内 dump 当补丁基线**，必须先跑一次看运行时长度/内容。

## 9. 解锁角色：为什么换挂点（2026-11-13 用户实测后修）

### 9.1 旧方案失败的真实原因

1. **时机错**：`RepairSaveData` 确实被 `LoadByJson` 调用（runtime 基线 SaveDataManager.cs:224/242/254），
   但它在**存档加载那一刻**执行；菜单开关 `unlock_char` 是用户之后在菜单里打开的 ⇒ 那一刻读到 0，
   `UnlockAll` 直接 return。再加 `s_unlockDone` 每进程一次 ⇒ 开关打开后永远没有第二次机会。
2. **id 靠猜**：`UnlockNewCharacter(id)` 要求 id 已在 `characterInfoDic`（键是字符串 id），
   循环 0..511 属臆造（角色 id 可能稀疏）。设备端也没有本地存档 JSON（走服务端 MainSave），无法读出真实 id 列表。

### 9.2 现方案：判锁读取点统一接闸

- 判锁点确认：UI 判的是**结构体字段** `Save.MainCharacterInfo.isUnlock`（Save.cs:154），
  全模块共 **40 处**读取；关键两处 `PlayerChoicePanel.UpdateCharacter`(:670) 与 `EnterEvent`(:848)。
  没有 `IsUnlock()` 方法、没有 `unlockList` 字段 ⇒ 只能在读取点做。
- 实现：Cecil 遍历全模块，在每个 `ldfld Save/MainCharacterInfo::isUnlock` 之后插一条
  `call Starry.HkldPatch::ForceUnlock(bool)`（`if (GetBool("unlock_char")) return true; return v;`）。
- 优点：开关打开**即刻生效**（下一次 UI 刷新就解锁）、不用重启、不写档、关掉自动恢复；
  **完全不碰角色 id**（稀疏也无妨）。
- 门禁：`Gate` 断言「ForceUnlock 调用点 >= 4」（实测 40）+「PlayerChoicePanel.UpdateCharacter 已接闸」。
- 已知副作用：`已拥有角色数量` 类统计/成就计数会跟着变（本地显示层，不影响存档正确性）。
  如需收敛，改白名单只接 `PlayerChoicePanel.UpdateCharacter/EnterEvent` 两处即可。

### 10.1 移动速度：为什么挂 GetRealMoveSpeed（而非写属性字段）

分析文档曾推荐「`SetBaseAttribution` 里写 `totalAttributes.moveSpeed`」，**已否决**：

- 属性 stfld 方案只在 `SetBaseAttribution` 被调用时生效（升级/换装备/刷新面板），拖完滑条继续走路
  可能「没反应」——正是本仓多次踩过的「用户说没效果」类事故；
- `GetRealMoveSpeed()` 每帧被 `PlayerJoystickControl.cs:227/236` → `PlayerSwipe.GetRealMoveSpeed()` 调用，
  开关即刻生效；`PlayerAnimatorManager.cs:100`（动画 MoveSpeed）走同一个方法，位移与动画自动一致；
- 不写任何字段 ⇒ 无幂等/叠加风险、不改存档、滑块拨回 100 立即恢复。
- **已知未覆盖**（有意）：`HuJiaoRollAbiltiyControl.cs:518/815` 直接读 `totalAttributes.moveSpeed` 算翻滚系数，
  属技能内部公式，不受本补丁影响；属性面板的 % 数字也不跟着变（更诚实）。

### 10.2 参数口径（最终）

| 项 | 值 |
|---|---|
| 配置键 | `move_speed_x`（整数百分比，**100 = 原速 = 默认值**，等价关闭）、`inf_mp`（0/1） |
| 菜单串 | `Slider_移动速度:100:300`（下标 7）、`Toggle_无限蓝`（下标 8） |
