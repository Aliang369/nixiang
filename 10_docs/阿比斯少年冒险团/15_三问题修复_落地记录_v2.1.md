## 1. 问题 1：伤害倍率阵营（报告 `12_修复_伤害倍率阵营.md`）

### 1.1 静态闭环（RVA 全部实测）
- `Unit::BLKEJBDMGAB(EAGEDGNBJHM)` RVA `0x354B388`，返回 `long`，真实边界 `0x354B388..0x354B944`。
- 载荷 `EAGEDGNBJHM`（dump L167250）：`+0x10 int` / `+0x14 int = 攻击者 unit id` / `+0x18 LGONBKNFNAC 阵营` / `+0x24 KCIMFCENEIN 元素` / `+0x28 long` / `+0x38 long` / `+0x40 float`。
- 关键指令：`0x354B4A0 ldr w22,[x20,#0x14]` → `0x354B4B8 bl Unit::BMNEKPDMFCK(0x3541284)` → `0x354B4C4 mov x22,x0` → `0x354B4F8 mov x1,x19`（原 this）→ `0x354B500 bl JMIKMDBLCHB`。
- 扣血落在 **this**：`0x354B510 ldr x0,[x19,#0x120]`（this.state）→ `0x354B51C/0x354B558` 读属性、`0x354B6B4 OBIGMOKECEH`（`0x36A2D28 sub` 减法写回）⇒ **this = 受击者**；阵营门控只在 `JMIKMDBLCHB` 的 `0x354B9E0 ldr w8,[x20,#0x150]; cmp #1`（x20 = 解析出的来源方）。
- 枚举 `LGONBKNFNAC`（dump L185236）= NONE 0 / **PLAYER 1** / ENEMY 2，与 cpp `kFactionPlayer=1` 一致。

### 1.2 改法（`Stub_Dmg`）
1. 新增 `ResolveUnitById()`：按名 `Unit::BMNEKPDMFCK` 取指针，失败退 `base+0x3541284`，全程 `Guarded`。
2. `srcId = *(int32*)(payload+0x14)` → `attacker` → `af = UnitFactionOf(attacker)`。
3. 仅 `af == kFactionPlayer && mult > 1` 才乘；**只乘 `+0x28`/`+0x38`**（移除 `+0x24` —— 它是元素枚举，v2.0 乘它是 bug）。
4. `af < 0`（解析失败）一律透传，绝不猜。

## 2. 问题 2：无敌（报告 `13_修复_无敌.md`）

### 2.1 主因证据链（实测）
- `PHBGLMHPMMC::IFEHBJOMMMB` `0x36A0A20` → `OBKEGLFOOFC` `0x36A0A68`：看 `ldrb w8,[x19,#0x60]`（脏标记），脏则 `bl FGFFAOCKMEG`(`0x36A0AE0`)，最后 `ldr x0,[x19,#0x58]` 返回 ⇒ 我们写的是 **+0x58 生效容器**。
- `FGFFAOCKMEG` `0x36A22BC`：`ldr x0,[x19,#0x50]` + `ldr x1,[x19,#0xc0]` → 虚调用合并 → **`0x36A2374 str x8,[x19,#0x58]` 整对象替换**。
- 读点：`JJFBPGNPMKB::LMBHNAHMDIL` `0x3642390` 内 `0x3642A2C` 取容器（可能触发重算）→ `0x3646840 bl FJMHJMEPFMC(id=0x3E)` → `0x3646850/54/5C csel wzr` 清零伤害分量。
- 写语义：`AGNKCIDBODI::NBOPCNCOKLD` `0x36B6260` → `KPCAFELPGNG` `0x36B62CC`：key = `(this+0x20) XOR idx`，val==0 走 Remove，纯数据写入、**无重算无 clamp** ⇒ 「读回 after=1 却掉血」的原因（校验的是即将被丢弃的对象）。
- 旁证：唯一写 `state+0x50` 的 setter `HEDDFPGMEFH` `0x36A0E00` 静态调用者 **= 0**。

### 2.2 改法
1. **hook 层确定性拦截**（主）：`Stub_Dmg` 中 `godOn && af >= 0 && af != PLAYER` ⇒ 栈副本把 `+0x24/+0x28/+0x38` 清零后透传（与游戏自身 guard 分支 `0x3646CFC/0x3646D04` 清零范围一致）。伤害发生的同一帧生效，**没有 200ms 窗口**。
2. **attr62 加固**（兜环境伤害/无来源伤害）：每 tick 无条件重写 + 读回重试 3 次 + 5s 节流日志（`attr62 tick-write=1 ok` / `tick-write-fail`）。
3. 去掉 `AttrApplyPass` 末尾 `return`，改为覆盖**全部** `faction==PLAYER` 单位。
4. 关闭开关时行为不变：`godOn=false` 直接透传，attr62 走原有还原分支。

## 3. 问题 3：无限技能菜单控制（报告 `14_修复_无限技能.md`）

### 3.1 证据
- `0x35547E4` = `OPFGEEDKKAM::FEJHANBJNCK(Unit, PKFLGAEJICG, int)` static void（dump L167308，IFix 0x971C）：取 `HClock::NMHDPNKKNBP()` 的 now → 对 `Unit+0x128` 技能容器 `[x8+0x328]`（Slot31 `0x360E330`）的一次虚调用 = **写冷却起点**，不是施放流程。
- `0x3006D98` = `ActionButton::NLGNPKOALJP(OIGNPAHJLCC)`：`ldrsw x8,[x19,#0xec]` → `cmp` → `cset lt` → `strb [x19,#0xe8]`；`+0xE8 = 能量是否足够`。
- v2.0 的 `VoidRun`/`SetByteRun` **不读 g_skill** ⇒ 装了就恒生效，关菜单也关不掉。
- Java→native 链路（`FeatureListParser` → `attachToggleListener` → `bridge.onToggleChanged` → `MainModern mb_nativeSetFeature` → `onFeatureChanged`；`Tick` 每 200ms 用 `g_features[]` 回读）**单源闭环，无「点了再反弹」**。

### 3.2 改法
```cpp
static void VoidRun(int i, void* a0, void* a1, void* a2, void* a3) {
    if (!g_skill.load()) { if (s.orig) ((fn_v4_t)s.orig)(a0,a1,a2,a3); return; }
    ...
}
static int SetByteRun(int i, void* a0, void* a1, void* a2, void* a3) {
    if (!g_skill.load()) { if (s.orig) return ((fn_i4_t)s.orig)(a0,a1,a2,a3);
        /* 无 orig 时返回 0，绝不在"关闭态"继续放行 */ return 0; }
    ...
}
```
宏 `HOOK_STUB_S/V` 改为透传 4 参（v2.0 只传 a0，关闭态无法调 orig）。

## 7. 残余风险

- **R1**：`Tick` 200ms 节流 ⇒ 关闭开关后最长 200ms 内旧状态仍可能生效（hook 内已改为每 200ms 同步读 `g_skill`，实际窗口 ≤1 tick）。
- **R2**：`skidC 0x3608534` 等是 virtual 声明体（虚分派走 override），该 hook 可能永不触发 —— 只降低「开启」覆盖面，不破坏「关闭」彻底性。
- **R3**：`AttrApplyPass` 的 `g_grpBefore` 是进程内快照，进程重启后若游戏侧已重算，还原可能带偏差（仅影响"关闭后是否完全回到原值"）。
- **R4**：若游戏走 IFix 补丁（`0x29/0x1981/0x971C/0x970d`），原生体不执行，hook 收益下降。
- **R5**：伤害 hook 依赖 `payload+0x14` 语义；若未来版本布局变动，`af=-1` ⇒ 自动退化为「只透传」，不会误乘。
