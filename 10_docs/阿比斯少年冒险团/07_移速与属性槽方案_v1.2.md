## 1. 已确认事实（来自 recon 反汇编，非推断）

| 项 | 结论 | 证据 |
|---|---|---|
| 属性容器取法 | `state = *(void**)(unit+0x120)` → `class_get_method_from_name(k,"IFEHBJOMMMB",0)` → `runtime_invoke(m,state,NULL)` → `FPIALCOELGG`（=`OKNDCLIKECF` 子类） | 名表 §12.2；`Unit::KKGNKHFDCBG` 0x354A5D4 处 `ldr x0,[x19,#0x120]` → `bl 0x36A0A20` |
| 6 个槽 | 每槽三件套：后备字段 + 只读属性 + **long 最终值属性**；槽址 +0x18/+0x20/+0x28/+0x30/+0x38/+0x40 | 名表 §12.3（实测结构） |
| 额外两个 float | `FACAGOKDJMO` @+0x48、`<CKPNNMFMMKK>k__BackingField` @+0x4C | 名表 §12.3 |

## 2. 探针改造（v1.2 第一件事，仍然零写入）

### 2.1 oknd 走方法而非字段

```c
// 现状（v1.1，错）：把 OKNDCLIKECF 当 Unit 的字段
//   field = class_get_field(unitKlass, "OKNDCLIKECF")   → 恒 miss，oknd=0x0

// v1.2：
void* state = *(void**)((char*)unit + 0x120);            // LAGPMHKOAKN（已有字段，偏移已核对 0x120）
void* k     = object_class(state);                        // 可选符号（已绑定）
void* m     = class_get_method_from_name(k, "IFEHBJOMMMB", 0);
void* oknd  = runtime_invoke(m, state, NULL, NULL);       // 返回 FPIALCOELGG（引用类型）
```

**兜底**：运行时类上取不到 `IFEHBJOMMMB` 时，退到
`class_from_name(image, "", "PHBGLMHPMMC")` 再取同名方法，对 `state` 调用（名表 §12.2 末注）。
两种情况都失败 ⇒ 打 `speed_probe: pending reason=IFEHBJOMMMB miss (runtime-class, base-class)`，不写内存。

### 2.2 6 槽全打（一次进战斗即可定字段）

每 5 秒（沿用现有节流）打一行，字段全部**按偏移直读**（槽是 long，float 槽是 float）：

```text
speed_probe unit=0x.. state=0x.. oknd=0x..
  slots6 long [+0x18=..] [+0x20=..] [+0x28=..] [+0x30=..] [+0x38=..] [+0x40=..]
  floats +0x48=.. +0x4C=..
  ctrl unit=0x.. kpbfh=0x.. (+0x28=..) (+0x30=..)
  hp cur=.. max=..  reason=ok|...
```

- `ctrl`：`Unit+0x38` 取驱动器（GAMJINGNDHM），再读 `+0x20` 校验是否回指本 Unit、读 `+0x28`/`+0x30` 两个 float。
- `hp`：同时打 `+0x190/+0x1A0` 作对照，便于判断槽值与血量是否同步变化。
- 6 个 long 也**可选**用 getter 调（`PDLFCFHOCME/LNIJOMDHEBJ/EHIOBPHENPA/NIKPNLBGKFA/OLBJHLHMLCE/AONEHGPCGKO`，argc=0）与直读值互校；直读与 getter 不一致 ⇒ 说明该槽不是简单字段（打 `slot_mismatch +0xNN direct=.. getter=..`）。

### 2.3 判定方法（用户只需打一场）

| 动作 | 观察 | 结论 |
|---|---|---|
| 站桩不动 | 6 槽基线值 | 记录基线 |
| 走动 / 疾跑 / 换移速装 | 哪个槽随移动速度成比例变化 | **那个槽 = 移速** |
| 被怪打 | 哪个槽与掉血量级相关 | 防御/减伤候选 |
| 打怪 | 哪个槽 ≈ 实际伤害/系数 | 攻击候选 |
| 看 `ctrl +0x28` | 是否随移动变化 | 命中 ⇒ 优先写该 float（见 §3 候选②） |

## 3. 写入候选排序（v1.2 只在 lead 批准后实现一条）

| 序 | 写入点 | 为什么先它 | 安全阀 |
|---|---|---|---|
| ① | `KPBKFHOKGHJ+0x28`（JBNOMHPKBMP float） | 名表标注「最像速度值」、字段就在驱动器上、写入点单一、失败可还原 | 写前：驱动器指针可读 + `+0x20` 回指本 Unit 才写；缓存 base（首次读到的值），写 `base×倍率`；**倍率=1 立即写回 base**；值域钳 `[-50, 200]`；每 5s 打 `speed_write base=.. cur=.. target=..`；还原失败打 `speed_restore fail` |
| ② | 移速槽（§2.3 判定出哪个 long 槽后） | 属性容器是游戏自己的最终数值来源，改它最"官方" | 写前重读：槽址可读 + 值在 `[0, 1e6]` + 与 baseline 比值在 `[0.05, 20]` 内才写；缓存 base；倍率=1 还原；每 5s 日志；**只在战斗内写**（`unit_count>0`） |
| ③ | `Unit+0xA0` CharacterController 位移补偿 | 不依赖属性语义 | 每帧补偿量有上限（`|delta| ≤ 0.5×base`）；连续 3 帧异常即停并打 `speed_abort reason=drift`；退出战斗必须清零补偿 |
| ✗ 不用 | hook `EJGLGAJLLOE` / `OCAAPNNMGAE`（0x35508C8 / 0x34A0E48 / 0x34A0DEC） | 本机 houdini 转译层，inline hook 未验证；v1 已因解析层翻车一次，v1.2 不上新变量 | — |

**通用安全阀（三条写死，不允许绕过）**
1. **写前重读**：`faction` 仍在我方值域（1）、目标地址 8/4 字节可读、`RangePerm` 通过；任一不过 ⇒ `write skip reason=...` 并跳过该单位。
2. **缓存 base 与还原**：任何写入功能都必须能在「关开关 / `ForceClear` / 退出战斗」三个时机还原；还原不了就保持原值不动（宁可不生效，不留脏值）。
3. **值域钳制**：float 槽封顶 200、long 槽封顶 1e6；越界一律跳过并打日志，不做"夹到边界"（夹边界会把角色写飞）。

## 4. 日志清单（一次进战斗即可判定，全部 5s 节流）

| # | 日志 | 判读 |
|---|---|---|
| 1 | `speed_probe ... slots6 long [...] floats ... ctrl ... hp ... reason=ok` | 6 槽 + 2 float + 驱动器 + 血量同屏，**这是判定主证据** |
| 2 | `slot_mismatch +0xNN direct=.. getter=..` | 直读与 getter 不一致 ⇒ 该槽非简单字段，弃用该槽 |
| 3 | `speed_probe: pending reason=IFEHBJOMMMB miss (runtime-class, base-class)` | 链条断在第 2 跳，需换 base 类兜底或放弃 oknd 路线 |
| 4 | `speed_write base=.. cur=.. target=..` | 写入生效且数值关系正确 |
| 5 | `speed_restore base=..` / `speed_restore fail` | 关闭/清空时是否干净 |
| 6 | `write skip reason=recheck failed unit=0x..` | 安全阀拦截（正常现象，说明保护生效） |
| 7 | `speed_abort reason=drift` | 位移补偿漂移，自动停手 |

**PASS 判据（供 lead 决策 v1.2 走哪条）**
- 日志 1 出现且 6 槽有非零值 ⇒ oknd 链通了；
- 走动时某槽/某个 float 与移速同步 ⇒ 该点可行，v1.2 按 §3 ①②③ 优先级实现；
- 6 槽全 0 或全不变 ⇒ 放弃 oknd 路线，直接走 ③（CharacterController 补偿）。

## 5. 与 v1.1 的差异与风险

| 项 | v1.1（已冻结） | v1.2（本文） |
|---|---|---|
| oknd 获取 | 当作 Unit 字段（恒 miss，oknd=0x0） | 走 `IFEHBJOMMMB()` 方法调用（§2.1） |
| 移速 | 只打 cc 的 6 个 float + reason | 6 long 槽 + 2 float + 驱动器 + 血量 + 直读/getter 互校 |
| 写入 | 无 | 仍无（本文不含任何写入实现） |
| 符号 | 8 必需 + 3 可选（object_class/class_method/runtime_invoke） | 不变（正好复用） |
| 风险 | — | `runtime_invoke` 已在本机验证可用（v1.1 技能项的 invoke 路径同款，走保护区）；`IFEHBJOMMMB` 若为 abstract 派发失败 → 降级，不崩 |

**未变项**：解析链（8 符号、`domain_assembly_open`、3s 延迟、domain 两次同值、逐 step 日志、fault guard）、无敌/伤害倍率/技能三项实现、写前重读与 `write skip` 机制。
