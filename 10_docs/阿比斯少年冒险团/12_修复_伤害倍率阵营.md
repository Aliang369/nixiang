# 12 修复：伤害倍率阵营（问题 1）

> 只读静态分析，未接触设备、未改任何源码。
> 证据分级：【实测】= 有可复查的 dump 行号 / RVA / 指令原文；【推断】= 由实测指令推出的语义，未做运行期验证；【待验证】= 缺证据。

> 反汇编脚本：`06_dumped/阿比斯少年冒险团/il2cpp_out/_fix_dmg_analyst.py`（另有 `_fix_dmg_analyst2.py` / `_fix_dmg_analyst3.py` 两个小工具脚本，反汇编血量相关小函数）。导出文本：`_dmg_BLKEJBDMGAB.txt`、`_dmg_JMIKMDBLCHB.txt`、`_dmg_LMBHNAHMDIL.txt`。

## 0. 结论一句话

**`Unit::BLKEJBDMGAB` 的 `this`(a0) 是「受击者」不是「攻击者」；攻击者是载荷里的 `payload+0x14`（unit id），要用 `Unit::BMNEKPDMFCK` 解析出来。现有 `Stub_Dmg` 用「a0 的阵营 ∈[0,2]」当门控 ⇒ 永远为真 ⇒ 敌我双方都吃倍率。改成「解析出攻击者，只有攻击者 faction==1 才乘」即可。**

顺带两个发现：
1. 现有代码把 `payload+0x24` 也乘了倍率，但 `+0x24` 是**元素枚举** `KCIMFCENEIN`，不是伤害分量 ⇒ 多乘一个字段会污染命中特效查表（bug，须一起修）。
2. 既有文档 G1「敌方血量路径未定位」本轮**已关闭**：敌方血量走 `BLKEJBDMGAB` 内部对 `state(Unit+0x120)` 的减法扣血，**不分阵营**；`JMIKMDBLCHB` 只写 `Unit+0x190`（玩家侧累计量），不是血条真值。

### 1.3 `a0` 是受击者（三条独立证据）【实测指令 + 推断语义】

**(a) 扣血是减法，作用在 `this` 的 state 上**
```asm
; BLKEJBDMGAB（0x354B54C 起）：先算修正后伤害 x25，再对 this.state 做减法
0x354B558  bl   PHBGLMHPMMC::MOLEFCNDFDK()   ; 取 state 的当前值（>0 才继续）
0x354B66C  bl   PHBGLMHPMMC::MOLEFCNDFDK()
0x354B690  mov  x0, x25
0x354B694  mov  x1, x24                       ; x24 = 当前值
0x354B69C  bl   Math::Min(long,long)          ; min(伤害, 当前值) —— 不扣穿 0
0x354B6B4  bl   PHBGLMHPMMC::OBIGMOKECEH(long)
; —— OBIGMOKECEH 本体 0x36A2CD4 实测：
0x36A2D1C  tbnz x19, #0x3f, 0x36a2d3c        ; 负数直接 return（不写）
0x36A2D24  bl   0x36A0620                    ; 取当前值
0x36A2D28  sub  x1, x0, x19                  ; ★ 当前值 − 传入值
0x36A2D38  b    0x36A0714                    ; 写回
```
⇒ `this` 的值被**减掉**伤害，且先 `Min(伤害, 当前值)` ⇒ 这是「扣血」，被扣的一方 = 受击者。【实测指令；语义推断强】

**(b) 命中后处理全部挂在 `this` 上**
```asm
0x354B714  cbz  x0, ...            ; this+0x38（KPBKFHOKGHJ 驱动器）
0x354B75C  bl   Unit::BADDJBFFEHG(payload+0x20 类型, ?, false)
0x354B780  bl   Unit::GPEHKHHJKLH(long)      ; this 上再扣一次 + 触发 this+0x1C8
0x354B78C  ldr  x9,[x8,#0x18]      ; this+0x1B8 Action<Unit,Unit,payload,long>
0x354B798  mov  x1, x22            ; 参数1 = 从 payload+0x14 解析出的「另一单位」
0x354B79C  mov  x2, x19            ; 参数2 = this（事件拥有者）
0x354B7BC  bl   get_gameObject     ; this 的受击闪光协程 + 元素命中特效
0x354B80C  ldr  w1,[x20,#0x24]     ; payload+0x24 元素枚举 → 查 this+0x110 字典
```
`GPEHKHHJKLH` 本体（0x354C044）实测：`state 取值 >= 1` 时 `bl 0x36A2D4C`（再扣一次）并 `br` 到 `this+0x1C8`（`Action<Unit,long>`，参数 = **(self, amount)**）⇒ 又是「自己受伤」语义。【实测】

**(c) `JMIKMDBLCHB` 的自我排除检查**
```asm
0x354BA04  mov  x0, x21        ; arg1（受击者）
0x354BA08  mov  x1, x20        ; this（来源）
0x354BA10  bl   Object::op_Inequality
0x354BA14  tbz  w0,#0, 0x354ba24   ; 相等（自己打自己）就不累加
```
若 `payload+0x14` 解析出来就是 `this` 自己，这个检查永远为假、`+0x190` 永远不被写 ⇒ 可反证 `payload+0x14 ≠ 受击者` ⇒ **攻击者**。【推断，强】

### 1.4 `JMIKMDBLCHB` 全文（0x354B944 .. 0x354BA38，0xF4/61 条）【实测】

```asm
0x354B958  mov  x19, x2         ; delta
0x354B95C  mov  x21, x1         ; arg1 = 受击者
0x354B960  mov  x20, x0         ; this = 来源（BLKEJBDMGAB 的 payload+0x14 解析结果）
0x354B9BC  ldr  x8, [x20, #0x1b0]   ; this.JAODIJCPHFL : Action<Unit,Unit,long>
0x354B9D0  mov  x1, x21             ; (受击者, this, delta)
0x354B9DC  blr  x9
0x354B9E0  ldr  w8, [x20, #0x150]   ; ★ 阵营
0x354B9E4  cmp  w8, #1              ; ★ == PLAYER
0x354B9E8  b.ne 0x354ba24           ; 非玩家直接跳过
0x354BA18  ldr  x8, [x20, #0x190]
0x354BA1C  add  x8, x8, x19         ; this+0x190 += delta
0x354BA20  str  x8, [x20, #0x190]
```

**判读**：`+0x190` 的持有者是 `x20` = **伤害来源方**，且门控 `来源方 faction == PLAYER`、并且要求 `受击者 != 来源方`。⇒ `+0x190` 是**玩家侧累计量**（累计造成伤害一类），**不是血条真值**。这也解释了为什么 mod 前四次「写 +0x190 当血量/无敌」全部无效（与 `10_静态闭环_伤害与属性.md` §G0 的实测结论一致，但归因更准确）。【实测指令 + 推断语义】

### 1.5 敌方血量走哪条路（关闭文档缺口 G1）【实测】

- 玩家受伤：`BLKEJBDMGAB` → `state(Unit+0x120)` 减法扣血（§1.3a）**并且** → `JMIKMDBLCHB` 让来源方 `+0x190 += delta`。
- 敌方受伤：同一条 `BLKEJBDMGAB` 的 state 减法，**没有任何阵营分支** ⇒ 敌方照样扣血、照样死。
- 因此 `JMIKMDBLCHB` 里 `faction==1` 的门控**不影响敌方扣血**，只是「玩家侧累计量」不累加而已。

⇒ 文档 `10_静态闭环_伤害与属性.md` §1.4 / §G1 的「敌方血量路径未定位」**至此关闭**；`+0x190/+0x198/+0x1A0` 三连写确实不是敌方血量。真实血量在 `Unit+0x120 → PHBGLMHPMMC` 的 state 字段里（`MOLEFCNDFDK()` 读、`OBIGMOKECEH(long)` 减、`0x36A0714` 写、`ANLJGEHHKLO()` = `state+0x48` 疑似护盾/上限，`0x354B510-0x354B544` 先用它做一次减免虚拟调用 slot 0x548）。

### 3.2 C++ 草案（直接可贴，不改原文件，仅供下一轮实现）

```cpp
// ---- 新增：解析攻击者（payload+0x14 = PFGJMDCJLFG = 攻击者 unit id） ----
typedef void* (*fn_resolve_unit_t)(int32_t id);
static fn_resolve_unit_t g_resolveUnit = nullptr;

static void EnsureResolveUnit() {
    if (g_resolveUnit) return;
    void* mi = nullptr;
    Guarded("resolve_unit_mi", [&] {
        void* k = g_api.class_from_name(g_image, "", "Unit");
        if (k && g_api.class_method) mi = g_api.class_method(k, "BMNEKPDMFCK", 0);
    });
    if (mi) {
        void* mp = nullptr;
        Guarded("resolve_unit_ptr", [&] { mp = ReadPtrAt(mi, 0); });
        if (mp && (uintptr_t)mp >= g_api.base && (uintptr_t)mp < g_api.end) {
            g_resolveUnit = (fn_resolve_unit_t)mp;
        }
    }
    if (!g_resolveUnit && g_api.base)                       // 兜底：RVA 0x3541284
        g_resolveUnit = (fn_resolve_unit_t)(g_api.base + 0x3541284);
    LOGI(ABS_LOG " resolve_unit %s", g_resolveUnit ? "ok" : "null");
}

static const size_t kPayloadOffSrcId   = 0x14;   // EAGEDGNBJHM::PFGJMDCJLFG
static const size_t kPayloadOffDeltaA  = 0x28;   // EAGEDGNBJHM::OOPEJAFCHIF
static const size_t kPayloadOffDeltaB  = 0x38;   // EAGEDGNBJHM::MHIJNMJIKAK

// 返回：攻击者 Unit（失败返回 nullptr）
static void* ResolveAttacker(void* payload) {
    if (!payload || !RangePerm((uintptr_t)payload + kPayloadOffSrcId, 4, 1)) return nullptr;
    int32_t srcId = 0;
    std::memcpy(&srcId, (char*)payload + kPayloadOffSrcId, 4);
    if (srcId <= 0) return nullptr;
    EnsureResolveUnit();
    if (!g_resolveUnit) return nullptr;
    return g_resolveUnit(srcId);            // 等价于游戏自己在 0x354B4B8 的那次调用
}

static bool IsPlayerUnit(void* u) {
    if (!OkPtr(u) || !g_anchors.faction.ok) return false;
    if (!RangePerm((uintptr_t)u + g_anchors.faction.off, 4, 1)) return false;
    return ReadI32(u, g_anchors.faction.off) == kFactionPlayer;   // LGONBKNFNAC.PLAYER == 1
}

static void Stub_Dmg(void* a0, void* a1, void* a2, void* a3) {
    int n = ++g_dmgHookN;
    int mult = g_dmgX.load();
    if (mult > 100) mult = 100;

    void* payload = nullptr;
    if (LooksLikeUnit(a0) && OkPtr(a1) && RangePerm((uintptr_t)a1 + kPayloadOffDeltaB + 8, 8, 1))
        payload = a1;                      // a0 = 受击者，a1 = 载荷

    void* attacker = (payload && mult > 1) ? ResolveAttacker(payload) : nullptr;
    bool playerOut = (attacker && attacker != a0 && IsPlayerUnit(attacker));

    if (payload && mult > 1 && playerOut) {
        unsigned char copy[0x60];
        std::memcpy(copy, payload, sizeof(copy));
        int64_t p28 = 0, p38 = 0;
        std::memcpy(&p28, copy + kPayloadOffDeltaA, 8);
        std::memcpy(&p38, copy + kPayloadOffDeltaB, 8);
        if (p28 == 0 && p38 == 0) {                       // 全 0 不改
            if (g_dmgOrig) g_dmgOrig(a0, payload, a2, a3);
            return;
        }
        const int64_t n28 = p28 * (int64_t)mult;
        const int64_t n38 = p38 * (int64_t)mult;
        std::memcpy(copy + kPayloadOffDeltaA, &n28, 8);
        std::memcpy(copy + kPayloadOffDeltaB, &n38, 8);   // ★ 不动 +0x24（元素枚举）
        uint64_t now = NowMs();
        if (now - g_lastDmgPayloadLog > kDmgLogInterval) {
            g_lastDmgPayloadLog = now;
            LOGI(ABS_LOG " dmgx mult=%d p28=%lld->%lld p38=%lld->%lld victimF=%d attackerF=%d n=%d",
                 mult, (long long)p28, (long long)n28, (long long)p38, (long long)n38,
                 ReadI32(a0, g_anchors.faction.off), ReadI32(attacker, g_anchors.faction.off), n);
        }
        if (g_dmgOrig) g_dmgOrig(a0, copy, a2, a3);
        return;
    }
    if (mult > 1 && n % 50 == 1) {                        // 未放行时也留痕，便于定位
        LOGI(ABS_LOG " dmgx skip mult=%d victimF=%d attacker=%p attackerF=%d n=%d",
             mult, payload ? ReadI32(a0, g_anchors.faction.off) : -1, attacker,
             attacker ? ReadI32(attacker, g_anchors.faction.off) : -1, n);
    }
    if (g_dmgOrig) g_dmgOrig(a0, a1, a2, a3);
}
```

### 3.3 若方向判反（回退方案）

如果实测发现「玩家打怪不翻倍、怪打玩家翻倍」，说明 `a0` 其实是攻击者、`payload+0x14` 是受击者。此时只需把门控换成：
```cpp
bool playerOut = IsPlayerUnit(a0);          // 一行；与上面互斥，不要同时留
```
日志行 `dmgx mult=... victimF=.. attackerF=..` 一次进游戏就能区分这两种情况（玩家出手时：方案 A 下 attackerF=1，方案 B 下 victimF=2 且 attackerF=1）。

## 5. 风险与回归项

### 5.1 风险

| # | 风险 | 说明 / 缓解 |
|---|---|---|
| R1 | 从 hook 里调用托管静态方法 `Unit::BMNEKPDMFCK` | 该调用就是原函数体 0x354B4B8 立刻要做的事（同线程、同对象图），实践安全；仍建议 try 一次、失败即透传（不做限流/不加锁，避免死锁）。**失败 = 不翻倍**（fail-safe） |
| R2 | 每个受击事件多一次字典查找 | 只在 `mult > 1` 时调用 ⇒ 关掉倍率时零开销 |
| R3 | 载荷对象来自池（0x3646BD8 前有池取对象），可能被复用 | 已用 `memcpy` 栈副本（0x60 ≥ 最后一个字段 +0x4C），不污染原件 —— 保留现有做法 |
| R4 | 方向判反（受击者/攻击者） | 用 §3.3 的日志与一行回退；【待验证】项 |
| R5 | 多玩家单位（宠物/召唤物同为 PLAYER=1） | 会一起吃倍率；若只想主角生效，需要进一步区分（Unit 无更细阵营枚举：`LGONBKNFNAC` 只有 3 值）——本轮不做 |

### 5.2 回归项（下一轮装机必看）

1. 玩家打怪：伤害数字与扣血同倍数放大（`delta` 与 `state` 扣减同时变）。
2. 怪打玩家：**不**放大（关键修复点）。
3. 怪打怪（如召唤物/中立互殴）：**不**放大。
4. 持续伤害（DoT）：走同一条 `BLKEJBDMGAB`，应同样只对玩家来源生效。
5. 自伤/反伤（受击者 == 来源）：`attacker != a0` 已排除，不放大。
6. 命中特效仍正常（元素枚举不再被乘坏）。
7. 无敌（`values[62]`）与倍率互不干扰。
