# 阿比斯少年冒险团 2.36 — IL2CPP 锚点与挂点方案（T2）

> 采集：recon / T2，2026-11-15。输入：`06_dumped/阿比斯少年冒险团/libil2cpp.so`（141,085,840 B）+ `global-metadata.dat`（21,127,360 B，md5 与 Lead 实测一致）。
> 分级：【实测】命令/反汇编直接看到；【推断】由实测证据链推出；【待验证】未取证。
> 反汇编工具：capstone 5.0.7（ARM64）+ pyelftools，脚本在 `06_dumped/阿比斯少年冒险团/il2cpp_out/_t2_dis.py`。

## 0. 一句话结论 + 必须先说清的风险

**代码被整体混淆**（类型名/方法名/字段名都是随机串，仅 UI 层可读），并且**每个 C# 方法入口都被 IFix 热更包装**（反汇编里逐方法可见 `WrappersManagerImpl::IsPatched` → `GetPatch` → `ILFixDynamicMethodWrapper::__Gen_Wrap_NN` → 原函数）。

⇒ T2 能给出**可信的结构锚点 + 候选 RVA**，但「HP 字段到底是哪个偏移」「技能 CD 字段在哪」这类唯一化结论，**纯静态在混淆 + IFix 下拿不到 100% 证据**，必须补一轮运行时验证（§7 给了具体脚本要点）。**建议 T3 先在 1 轮 frida 验证后再写死偏移**，否则改出来的 so 可能打空。

## 7. IFix 影响（**T3 必须知道**）【实测】

每个方法入口都是这个形状（以 `Unit::KKGNKHFDCBG` RVA 0x354A5D4 为例）：

~~~asm
0x354A5D4  stp  x30, x19, [sp, #-0x10]!
0x354A5D8  mov  x19, x0
0x354A5DC  mov  w0, #0x1b4          ; ← IFix 方法 id
0x354A5E0  mov  x1, xzr
0x354A5E4  bl   WrappersManagerImpl::IsPatched
0x354A5E8  tbz  w0, #0, #0x354a60c ; 未打补丁 → 走原逻辑
0x354A5EC  ...  bl WrappersManagerImpl::GetPatch
0x354A608  b    ILFixDynamicMethodWrapper::__Gen_Wrap_3   ; 打补丁 → 转发到热更实现
0x354A60C  ldr  x0, [x19, #0x120]    ; ← 原逻辑：取状态对象
~~~

结论与要求：
1. **hook 原始 RVA 仍然有效**（补丁未命中时 tail-call 回原函数），但**一旦游戏下发热更补丁，原逻辑被绕过**，锚点会"看起来失效"。
2. 因此每次游戏热更后必须复核（参考 `skill/hotupdate-fingerprint-recheck.md`），并在报告里记版本。
3. 不要 hook `__Gen_Wrap_N*`（多态、一个 wrapper 服务多个方法）。
4. 更稳的选择：hook 状态对象（OIGNPAHJLCC / OKNDCLIKECF）的方法或直接读写字段 —— 字段不受 IFix 影响。

## 8. 建议的 1 轮运行时验证（T3 动手前，约 10 分钟）

目标：把 A2（+0x190/+0x1A0）、C1（+0x150 阵营）、S4（CD 字段）三个"待验证"变成实测。

1. frida attach（设备已 root，frida-server 走 `01_tools/phantom-frida` 或环境自带）。
2. 进战斗后，枚举 `Unit` 静态表（+0x0 Dictionary）拿到所有 Unit 指针：
   - 读 `*[unit+0x190]` / `*[unit+0x1A0]`（long）→ 与界面血量对比，确认哪个是当前血量；
   - 读 `*[unit+0x150]`（int 枚举）→ 记录玩家 vs 怪物取值 ⇒ 得出阵营判别常量。
3. 对玩家 unit 的 +0x190 下 hardware watchpoint（或 frida `MemoryAccessMonitor`），出招一次 → 抓写入者 PC → 那就是**扣血函数**（A1 的 RVA 落地）。
4. 移动速度：对 +0x240 一类 float 做"关闭/打开"差值扫描；或用 M5 的调试面板反查。
5. 技能 CD：hook ActionButton 的 CD 协程，或对技能对象 float 字段做点击前后差值。

现成工具：`04_scripts/_common/diff_il2cpp_mem.py`（内存 diff）、`04_scripts/_common/find_metadata_device.sh`。

## 9. 给 T3 的实现建议（按优先级）

1. **无敌**：优先 A3（改返回值）→ 退 A2（锁 +0x190）→ 保底 A1（扣血函数置 0）。
2. **伤害倍率**：D2（raise 前放大 long 值）比 D1（改载荷结构）稳；若 D2 不生效再试 D1 的 float@0x40。
3. **无限技能**：必须先做 §8 第 5 步；静态没有可用锚点，**不要凭猜测写死偏移**。
4. **移速**：M1（CharacterController 位移乘算）最通用；M2 只对技能位移有效。
5. 所有 hook 都要带「阵营判别」：用 C1（+0x150）+ C2（AIControllerBase 表）判定我方，**只改我方**，避免把敌人也改强。
6. 每次游戏热更 → 复核 RVA（IFix）。

### 11.4 失败点（**这是本轮的真实结论**）

1. **types 数组元素解引用后拿不到类名**：`types[i]` 读出的是 16 字节步进的地址（0x40002b06e318、+0x10、+0x20 …），其 `+0x10` 不是可读字符串；其 `+0x00` 指向 `0x73f3b7fcxxxx` 段（非 guest 段，疑似翻译层/宿主侧影子结构）。⇒ v29.1 的 `types[]` 布局在这台"arm64 guest + x86_64 host 翻译"环境里**不等于**静态假设的 `Il2CppClass*` 数组。
2. **frida 看不到 guest 映射**：`Process.enumerateRanges("rw-")` 扫完只用了 1.2 秒、对 `"Unit\0"` 命中 **0** 次 ⇒ 枚举到的是宿主侧映射，**guest（arm64）堆与 metadata 不在其中**，所以"字符串→klass 指针"的反查也无从下手。
3. **原生 hook 不可用**：agent 是 x86_64、libil2cpp 是 arm64 代码 ⇒ `Interceptor.attach` / Stalker 无法对 arm64 函数插桩（要 arm64 agent，而 OS 是 x86_64，arm64 frida-server 无法执行）。**⇒ 在这台模拟器上，"hook getter 抓调用栈""watchpoint 抓写入 PC"这两条路当前不可行**（T3 不要在这台机上重复这一尝试）。
4. 因此 §4 的 A2/A3 偏移、§6.1 的 CD 字段、§6.2 的移速字段**仍然只有静态推断**，本轮**没有**新增实证。
