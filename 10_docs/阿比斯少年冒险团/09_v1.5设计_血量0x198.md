## 2. Stage A：语义确认（只读，先于任何写入）

### 2.1 采样点

每 200ms（Tick 周期）对**当前单位集合**采一次：
- `player198 = *(int*)(playerUnit + 0x198)`（`faction == 1` 的首个单位）
- `enemies198[]`：所有 `faction == 2` 单位的同偏移值（上限 64 个）

### 2.2 两类日志

| 触发 | 日志 |
|---|---|
| 值发生变化 或 每 5s 心跳 | `hp198 player=100 enemies=[120,120,80]` |
| 我方值下降 | `hp198 hit prev=100 now=96 delta=4 unit=0x..` |
| 我方值上升（治疗/重开/换角色） | `hp198 up prev=96 now=100（可能是治疗或新战斗）` |

### 2.3 判定条件（三条**同时**成立才允许写）

| # | 条件 | 阈值 | 目的 |
|---|---|---|---|
| A1 | 观察到 ≥1 次我方 `0x198` 下降 | `0 < delta <= 65535` | 证明它与「受损」相关 |
| A2 | 敌方 `0x198` 全部是正整数 | `1 <= v <= 1000000`，且非 `0 / -1 / 0x7FFFFFFF` 之类哨兵 | 证明它是我方与敌方共用的同一语义 |
| A3 | 我方下降时**尚未被我们写过** | 该单位 `wrote==false` | 证明观测到的下降是游戏自己造成的，不是我们的写入 |

### 2.4 状态机

```text
UNKNOWN ──(A1∧A2∧A3)──▶ CONFIRMED ──▶ 允许 Stage B/C 写入
   │
   └──(任一条件被证伪：敌方出现 0/负数、或我方下降但敌方恒为 0)──▶ REJECTED
REJECTED：本局只打日志，**不写任何字节**，等 lead 换选点
```

- 状态一旦 `REJECTED`，本进程内不再尝试写（避免「写坏一点再看」）。
- `CONFIRMED` 也可被推翻：若确认后出现「我方 0x198 下降但写回后又被改成更大值」的异常序列，退回 `REJECTED` 并打 `hp198 reject reason=..`.

### 2.5 新战斗识别（max 重新学习）

满足任一即视为新一轮战斗，重置 `maxCache / lastHp / wrote`：
- 单位集合从空 → 非空（进战斗）；
- 我方 `0x198` 出现「比记录 max 更大的值」且 `delta > 10%`；
- `oknd` 对象变化（换角色/重开）。

## 3. Stage B：无敌（仅 CONFIRMED 后）

**规则**：每 tick 对每个 `faction==1` 单位：`cur = *(int*)(u+0x198)`；若 `cur < maxCache` ⇒ 写 `maxCache`。

**maxCache 学习**
- 首次读到该单位的值即为候选 `max`，(日志 `god198 max learned=100`)；
- 后续读到更大值则更新（单调不减），仅在新战斗重置时清零；
- 若某单位的 `0x198` 一直为 0（加载中），**不学习、不写**。

**写前安全阀（缺一不写）**
1. `faction` 重读仍 == 1；
2. `0x198` 4 字节可读（`RangePerm`）；
3. `0 <= cur <= maxCache`（拒绝把「比 max 还大的外部值」抹掉，避免误伤 buff/护盾机制）；
4. `maxCache > 0`且 `maxCache <= 1000000`。

**幂等**：`cur >= maxCache` 直接跳过，不重复写。

**日志**：`write ok god198 cur=96 max=100`（1s 节流）；跳过时 `god198 skip reason=..`。

**还原策略（重要）**：血量类写入**不做还原**——把血写回旧值等于「把血扣掉」，风险高于收益。
关闭开关 / `ForceClear` 只做「停止写」，并把 `maxCache` 保留到本局结束（便于再次打开时立即可用）。
文档与菜单提示都必须写明：**关掉后已回满的血不会退回**。

## 4. Stage C：伤害倍率（仅 CONFIRMED 后）

**规则**：对 `faction==2` 的单位维护 `lastHp`（128 槽 LRU，键为单位指针）：
`delta = lastHp - cur`；`delta > 0` ⇒ `extra = (mult-1) × delta` ⇒ 写 `cur - extra`（钳 `>= 0`）。

**保护**
- `delta <= 65535`（一次伤害不会超过这个量级；超出视为异常，跳过并打 `dmgx198 skip delta=..`）；
- `cur >= 0`、`extra >= 0`；
- 写前重读 faction == 2；写后读回，不一致打 `dmgx198 drift cur=.. target=.. back=..`；
- **倍率=1 时整段 return**（完全不读不写，零副作用）。

**日志**：`write ok dmgx198 delta=4 extra=4 mult=2.00 cur=96 target=92`（1s 节流）。

**边界情况**：AOE 同时打到多个敌人时逐单位处理，互不影响；敌方被一击秒杀（`cur<=0`）时不补扣（没有可扣对象）。

## 5. 偏移交叉校验（沿用现有安全阀）

- by-name `APPACLOOHNK` 取到字段后取 `field_offset`，**必须 == 0x198**，不等即 `abort: offset mismatch APPACLOOHNK got=0x.. want=0x198` 并整块跳过（`ResolveFieldChecked` 现成实现）。
- 类型不可得（没有 type 相关导出）⇒ 用**值域 + delta 合理性**替代：int 读数的绝对值必须 `<= 1e9`，`delta` 必须 `<= 65535`。
- `0x198` 与 `+0x190/+0x1A0`（long）不共用读写函数：**int 读写单独写 `ReadI32/WriteI32` 版本**，禁止混用 long 版（这是 v1.1 崩溃风险之一）。

## 7. 风险与回退

| 风险 | 说明 | 回退 |
|---|---|---|
| 0x198 是护盾/层数而非血量 | 受击下降但战斗中回升、或敌方值与前排血量不同步 | Stage A 判 REJECTED，全程不写 |
| 写 max 触发游戏自检 | IL2CPP 内部对血量做校验（如「血量不得大于上限」） | 写前读 `0x198` 原值，仅当 `cur < max` 才写；异常序列立刻停写并打 `god198 stop reason=..` |

| 与移速相互干扰 | 两处都改单位对象 | 不同字段、不同函数、独立开关；移速逻辑不改动 |

## 12. **结论作废**：+0x198 不是真血量（2026-11-15 15:35，用户实测）

### 12.1 作废声明

> §11 里「`write ok dmgx198 ... before=27 after=0` ⇒ 倍率生效」的结论**作废**。

**理由（用户实测）**：
1. 伤害倍率设到 **100**，怪**依然打不死**；
2. 无敌开着，玩家**照样掉血**。

那两条 `before=27 after=0` 只能说明「我们写到/读到的那个对象的值归零」，
**不能**说明真实战斗里怪掉血变快 —— 判据必须以用户观感为准。

### 12.2 唯一自洽解释

`Unit+0x198` 是**受击时同步的镜像/显示值**（游戏每帧或每次受击从真血量回写），
因此：我们写进去会被覆盖（无敌写不进）、真实扣血/死亡判定走另一个来源（倍率看不出效果），
而日志里我们自己的读值又「看起来」完全合理（100 / 99 / delta=1）。

### 12.3 v1.7 方向：先证「真血量在哪」，不再往 0x198 写

| 项 | 处置 |
|---|---|
| 0x198 的无敌写入 | **停止**（降级为 10s 一次的诊断探针，只看 `back=`，不再打印 `write ok god198`） |
| 0x198 的倍率写入 | **停止**；只保留只读观测 `dmgx198 observed ... killed=1/0` |
