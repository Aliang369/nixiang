## 1. 结论（一句话）

**我们写的 62 不是"基础值"，而是"重算产物"**：mod 经 `IFEHBJOMMMB()` 拿到的是 `state+0x58`（生效容器）；游戏属性脏标记 `state+0x60` 一旦被置位，下一次属性读取会走 `FGFFAOCKMEG`，用 `state+0x50`(基础) + `state+0xC0`(修正层) **重新合并出一个全新容器对象写回 +0x58**，我们写过的 62 随旧容器作废。而伤害路径恰好是"先重算、再读 62"，于是必然存在掉血窗口（最长 = 下一个 200ms tick），表现为"无敌偶尔失效"。

### 4.1 推荐组合

**F1（主）+ F3（兜底与观测）+ 顺手修 e（遍历全部 player）**。F1 的玩家白名单在 tick 里维护：从 `CollectUnits` 中 `faction==1` 的单位取 `state+0x50`、`state+0x58` 两个容器指针，每 tick 重建（防止指针回收复用误判）。

### 4.2 C++ 草案（仅设计稿，**不改源文件**）

```cpp
// ---- F1: hook OKNDCLIKECF::FJMHJMEPFMC (RVA 0x36A2BA4) ----
// 原签名: int FJMHJMEPFMC(this /*容器*/, KMLFBAENBMH id)
static void*  g_godContainers[512];
static int    g_godContainerN = 0;
static std::atomic<bool> g_godOn{false};

typedef int (*fn_GetAttr)(void* self, int id);
static fn_GetAttr g_origGetAttr = nullptr;

static int HookGetAttr(void* self, int id) {
    if (id == 62 && g_godOn.load(std::memory_order_relaxed)) {
        for (int i = 0; i < g_godContainerN; ++i)
            if (g_godContainers[i] == self) return 1;   // 只保护玩家容器
    }
    return g_origGetAttr ? g_origGetAttr(self, id) : 0;
}
// 安装: DobbyHook((void*)(base + 0x36A2BA4), (void*)&HookGetAttr, (void**)&g_origGetAttr);
```

```cpp
// ---- 白名单维护（每 tick，所有 player 单位）----
static void RememberGodContainers(void* state) {
    if (!OkPtr(state)) return;
    void* cand[2] = { *(void**)((char*)state + 0x50),    // 基础容器
                      *(void**)((char*)state + 0x58) };  // 生效容器
    for (void* c : cand) {
        if (!OkPtr(c)) continue;
        bool dup = false;
        for (int i = 0; i < g_godContainerN; ++i)
            if (g_godContainers[i] == c) { dup = true; break; }
        if (!dup && g_godContainerN < 512) g_godContainers[g_godContainerN++] = c;
    }
}
```

## 5. 回归风险

1. **F1 白名单漏项** ⇒ 该单位无保护（表现为"某些队友/召唤物仍掉血"）；白名单只增不减会因指针回收复用误判 ⇒ 每 tick 重建。
2. **F1 白名单误纳敌方容器** ⇒ 敌人免疫、关卡卡死（最坏）。护栏：白名单只从 `faction==kFactionPlayer` 的单位取，且 hook 内仅对 `id==62` 生效。
3. **F2 若采纳**必须先验证 `state+0x50` 是否每单位独立（用现有 `AttrViewLog` 比较两个不同单位的 `state+0x50` 指针）；共享则**禁用** F2。
4. 关闭还原语义：F1 下"还原"= 停用 hook，**无需写回**，比现状更安全（现状 `attr62 restore` 会把 `before62` 写到"当前 oknd"，若已换对象则写错对象）。
5. 属性面板（`CharacterTotalAttribPanel`，14 宿主之一）会显示 `DAMAGE_GUARD=1`，属可见副作用，需在交付说明写明。
