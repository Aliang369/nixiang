# 阿比斯少年冒险团 2.36（TapTap）— 底包指纹

> 采集：recon / T1，2026-11-15。设备 `emulator-5554`（Android 14 / x86_64 / user build / su 可用）。
> 事实分级：**【实测】**＝本次命令输出可复现；**【推断】**＝由实测证据链推出、未直接观测；**【待验证】**＝尚无证据，仅登记。
> 原始证据全部落在 `02_apks/阿比斯少年冒险团/_evidence/`（每节标文件名）。

## 0. 一句话结论

Unity **IL2CPP** 包（libil2cpp 141 MB + global-metadata.dat 21 MB），**无代码壳**（dex 明文可解析、application 未指向壳类）；渠道 SDK 是 **Titan/U8SDK**，TapTap 侧由 **TapSDK（com/taptap/sdk 共 1862 个 class_def，全在 classes2.dex 明文可读）** + **THEMIS 反作弊组件（libthemis.so / ThemisProvider / app_THEMIS/THEMIS.dat）** 组成。

**给 T4 的结论：可走改包法。** 两条现成挂点——① `ClientLoginHandler.canHandle(...)Z` 改恒 false，让链条自然落到 `LoginActivityImpl.fallbackToWeb()`（网页登录）；② 启动门闩 `TapGatekeeperManager.isSuccess()Z`（读静态字段 `isGatekeeperSuccess:Z`，全包唯一调用点在 `InitializerServiceImpl`）。**注意：本版 TapSDK 没有 `GatekeeperRepository` / `ClientLoginUtils` / `isGatekeeperLoadedSuccessfully`，仙逆那套手法不能照抄。**

**为什么不直接 apktool d 原包**：原包 1.1 GB（assets 1284 条含 1162 个 .ab），apktool 会把 assets/lib 再复制一遍；且 apktool 2.9.3 **不支持 --no-assets**（d 的选项实测只有 -r/-s/-f/-o/-p/-t）。折中：python 摘出"除 assets/、lib/、classes*.dex 之外全保留"的 slim apk 给 apktool，dex 用 baksmali 单独解。**原包未做任何修改**。

### 11.1 事故与恢复记录（真实错误）

1. 首轮把证据目录放在 03_decompiled/阿比斯少年冒险团/_evidence，而 apktool d -f 的输出目录正是其父目录 ⇒ **apktool 先删目标目录**，把 _evidence 连带 slim apk 一起删掉，解包同时因"输入文件在已删目录内"失败（Input file ... was not found or was not readable）。
2. 影响：**原始 APK 未受影响**（只读，md5 复校一致）；丢失的仅是可再生中间证据。
3. 处置：证据迁移到 02_apks/阿比斯少年冒险团/_evidence/（不再被解包动作波及），全部证据重跑重建。
4. 附带发现：java/apktool 直接吃中文路径会乱码（E:\...\?????）⇒ **java 类工具一律走 ASCII 暂存目录**（03_decompiled/_ascii_tmp/，用完即删），产物再 Move-Item 回中文路径。
