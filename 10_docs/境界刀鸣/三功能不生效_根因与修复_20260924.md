# 境界刀鸣：三功能不生效 —— 根因与修复（真机已验证）

- 游戏：`com.blade.bd`（taptap，vc 39 / 1.39.211507）
- 设备：`f9a116a2`（OPD2404 / Android 16 / root，仅分析用）
- 时间：2026-09-24 凌晨
- 结论：**伤害倍率 / 无敌 / 无限技能 三项在直装包（无 root）上全部生效**。此前"菜单全开却没效果"是 **三个我自己引入的 bug** 叠加，全部位于 `mod菜单/starry-mod-menu/app/src/main/jni/Games/JjdmMod.cpp`，与游戏加固/校验无关。

## 2. 四个 bug 的细节

### Bug A：两个互不相连的同步标志
- `g_wantSync`（:58 声明）**只被写**：`Jjdm_OnFeatureChanged` / `Jjdm_OnValueChanged` / `Jjdm_Tick` / `Jjdm_ForceClear`。
- `g_needSync`（:95 声明）**只被读**：`SyncFromLuaEntry` 读、`SyncOnLua` 清、`InstallLuaHooks` 置 true。
- ⇒ 初次同步后 `g_needSync` 恒 false，菜单改动再也到不了 Lua。这是从 il2cpp 路线改写为 Lua hook 路线时引入的回归。
- 修复：删除 `g_needSync`，统一到 `g_wantSync`。

### Bug B：`char buf[1024]` 截断脚本
- 「安装脚本 + 写开关」拼串长 **1823 B**，`snprintf` 截在 1023 B，截断点正好是 `  return et ~= nil and` → 只剩 `an`，与 `loadstring` 报错逐字符吻合。
- 修复：`static const char kInstallScript[]`；`char buf[sizeof(kInstallScript) + 128]`；溢出守卫 `if (n < 0 || n >= (int)sizeof(buf))`；新增 `LogErrThrottled(what, err)`（2 s 限流 + 抑制计数）。

### Bug C：Lua 函数不能挂字段（真正的拦路虎）
- 守卫写成 `CF.DoSubHp.__jjdm`，而 **Lua 的函数不是表，不能索引/挂字段** ⇒ 每次执行都抛 `attempt to index a function value`，脚本第 4 行就死，`patched` 永远 0，补丁**从未安装**。
- 修复：身份比对，状态存在表上：
  ```lua
  local W = __jjdm_wrap
  if not W then W = {}; __jjdm_wrap = W end
  if type(CF.DoSubHp) == 'function' and W.cf == CF and W.sub == CF.DoSubHp then return end
  -- ... 安装 ...
  W.cf, W.sub = CF, CF.DoSubHp
  ```
  并新增 `JJDM.re` 重装计数器、`VerifyState` 探针改判 `__jjdm_wrap.sub == CombatFunc.DoSubHp`。

### Bug D：安装脚本的 `return` 吃掉「写开关」
- `SyncOnLua` 曾把两段拼成**同一个 chunk**：`"%s\nif JJDM then JJDM.dmg=%d … end"`，而安装脚本命中守卫时会**提前 `return`** ⇒ 后面的写开关整段不执行。
- 症状极具迷惑性：`patched=1`、`wrap=yes`、`re` 稳定，但 `dmg/inv/nocd` 永远是安装时的旧值。
- 修复：**拆成两个独立 chunk**（① 守卫式安装、② 写开关），并加限流探针 `[Jjdm] sync dmg=%d inv=%d nocd=%d` 作为「写开关真的在跑」的直接证据。

## 3. 另外两处关键修复（同一条链上）

- **Dobby 16 字节 patch 越界**（早前一轮）：`lua_pcall`@0x512920 size=12，紧随 `lua_tonumber`@0x51292c size=8，patch 尾部覆盖邻居入口 → SIGILL（`Zygote: exited due to signal 4`）。修复：只 hook 本体 ≥16 B 的入口 —— `lua_gettop`@0x515e38(28) 与 `lua_pcallk`@0x518fec(332)；**永不 hook lua_pcall**（Lua 5.4 里它是宏，真实调用走 `lua_pcallk`）。
- **诊断盲区**：`Games/SignalQuarantine.cpp` 的 seccomp 拦 `tgkill/tkill/kill/rt_sigqueueinfo/rt_tgsigqueueinfo`，同步致命信号被内核强制走默认动作 ⇒ 注入包无 tombstone、logcat 无 `[crash]`。SIGILL 是靠 `Zygote:` 行才发现的。

- `loadstring` / `pcall` 报错 **0**；进程全程存活。
- 玩家实测确认（User said, m03522）：「这次打完有效果了」。

## 5. 教训

1. **Lua 的函数不是表** —— 任何「在函数上打标记」的写法都是错的，用 `表.字段 == 函数` 做身份比对。
2. **`snprintf` 拼 Lua 脚本必须按 `sizeof(脚本) + 余量` 算缓冲**，并用返回值守卫。
3. **不要把「会提前 return 的脚本」和「必须执行的脚本」拼进同一个 chunk**。
4. 写者和读者必须是**同一个变量**；双标志是静默失效的温床。
5. 每加一段关键逻辑就加一条**限流探针**（`sync` / `state`），否则只能靠症状间接推断，代价是用户反复配合测试。
6. 迭代期不要用 `adb input` 操控用户真机屏幕（User said, m03361）；需要设备配合先说明再等用户操作。
