## 1. 加固与保护体系（逐项取证）

### 1.1 应用层被第三方接管（重要）
`AndroidManifest.xml` 实测：**`android:name="com.bytedance.thanos.ThanosApplication"`**
→ 游戏的 Application 不是自己写的类，而是**字节 Thanos 运行时容器**。同时 `appComponentFactory=androidx.core.app.CoreComponentFactory`。
**后果**：星光注入的 `StarryApp` 必须继承 **`com.bytedance.thanos.ThanosApplication`**，而不是游戏自身 Application（`skill/starry-mod/surgical-build.md:107`：StarryApp 必须继承官方 Application 类，否则权限链崩）。
**风险**：ThanosApplication 的 `attachBaseContext/onCreate` 里塞满字节 SDK + 反篡改 + MIRA 初始化；代理类一旦继承它，官方初始化逻辑会照跑，签名/完整性判定是否对我们不利 → **待验证**。

### 1.2 DEX 层：无壳、明文（好消息）
- APK 内 `classes.dex` ～ `classes14.dex` 共 14 个，全部拉取实测；六个抽样头部**均为 `dex\n038`、无加密壳 stub**。
- 条目归属：`META-INF/services/com.bytedance.ttgame.*`（crash/monitor/osdk.doulink/thanos.api.IThanosService/pay/godzilla…）→ 字节 TTGame SDK 全家桶。
- **结论**：没有整包 DEX 加壳，dex 可直接 smali/反编译。这是直装包最大的有利条件。

### 1.3 IL2CPP metadata 保护（实测三次失败，判定为「加密式反 dump」）
- `assets/bin/Data/Managed/Metadata/global-metadata.dat` = 17 824 248 B（与 `files/il2cpp/Metadata/global-metadata.dat` 同尺寸）。
- 头特征：偏移 8 处 `sanity af1bb1fa`、`version 31`，前 8 字节为额外前缀 → 初步像「前置 8 字节」。
- 三次 dump 尝试（`01_tools/Il2CppDumper/Il2CppDumper.dll`，注意正确路径无 `bin/`）：
  1. 直接去 8 字节 → 跑通但**结构化乱码**：`// Image N:` 全乱码、`grep -ac namespace`=0；DummyDll 阶段崩 `Mono.ArgumentNullOrEmptyException: Argument null or empty (Parameter 'name')`。
  2. `G = F[8:16]+F[8:]` → `System.ArgumentException: An item with the same key has already been added. Key: 30783`（`Il2Cpp/Metadata.cs:102`）。
  3. v31 头 30 个 offset 字段各 −8 → `Key: 31424` 同一异常。
- 定位性实测：`stringOffset=1082720`、`stringLiteralOffset=256`、`imagesOffset=16033672`；**该 stringOffset 处读出的是随机字节（密文）**；`Assembly-CSharp` 明文出现在 `F[8:]` 偏移 337222、`LuaManager` 在 292672；stringOffset/imagesOffset 各 ±8 的 **9 种组合解 image 名全部乱码**。
- **结论**：名表/结构区在磁盘上就是密文（非单纯偏移平移），标准静态 Il2CppDumper 无法还原。APK 内 `libmeta_reflector.so` = `com.bytedance.mira.plugin.meta.reflector.MetaReflector`（**MIRA 插件，运行时在内存里还原/改写 metadata**），两者互证。
- **反例（好消息）**：`libil2cpp.so` 的 `.dynsym`(64152 B) / `.dynstr`(111877 B) **完好**，`il2cpp_class_from_name` / `il2cpp_domain_get_assemblies` / `il2cpp_runtime_invoke` / `il2cpp_image_get_class` / `il2cpp_method_get_name` / `il2cpp_thread_attach` 等 API 串均在 → **运行时可用 il2cpp API 枚举类/方法并调用**，不必先解决静态 dump。
- `libil2cpp.so` 段表正常（`.text` 5 230 752 + 自定义段 `il2cpp` 53 685 052，Unity 常规布局），另有 2 处 `mira` 字符串。

### 1.4 原生 so 完整性：`hfso` 热更清单（关键约束）
`/sdcard/Android/data/com.blade.bd/files/`：
- `hfso/HfsoStepLog` = `StartTryPatchSo / EnsureInternalHfsoDirectoryExist / NoNewLibUnity / NoNewLibIl2cpp / PatchSoFinish`
- `hfso/originHfso.manifest` 两行 md5 = `d375d31ef5ff39c7e4df41fe52bef4fc`、`459a7e4dc16b151ca25533c49f28f74a`
- **实测核对**：`d375d31e…` = `libunity.so` 的 md5、`459a7e4d…` = `libil2cpp.so` 的 md5
→ **游戏自己记录并巡检这两个核心 so 的哈希**。
**结论**：直装包**绝对不要替换/修改 `libil2cpp.so`、`libunity.so`**（会撞 hfso 校验）；只允许**新增**独立 so（星光 `libstarry_magic.so` 属于新增）。

### 1.5 资源完整性：`Md5List.txt` + 自研打包格式
- `Md5List.txt` 1 174 966 B / **14692 行**，格式 `逻辑路径|md5`，条目含 `Lua/Lua/<32位md5名>`、`Lua/DataSettings/<32位md5名>`、`AssetBundles/xx/<md5>`、`Audio/*.bnk`、`Videos/*.mp4`（另有 `Md5List_Addtive.txt` 984 B）→ 客户端资源完整性清单。
- 资源包格式（只读嗅探）：
  - `dlc.xpk` 2 132 564 366 B：**头部是 JSON**（`"group2AssetsMap":[{"group":0,"assets":[{"path":"Scripts.zip"…`），**尾部**是 `{"subpackageid":0/1/2,"groups":[…]}` 分组表 → 分组资源包，内含 `Scripts.zip` 资产。
  - `dlc` 3 727 872 B：magic **`VFSL002`** → VFS 索引/清单，含 `assetGroup_prev.json`、`eInternalService` 与 UTF-16 哈希串；`dlc1.xpk` 66 640 018 B、`dlc1` 3840 B、`dlc2*` 空。
- 另有 `launchScr.txt`（150 827 B，`version:169526`，热更地址为**反转 Base64** 编码）、`il2cpp/unity.ver=f04c828e-7338-4106-a97a-c59f6df59d24`、`BootConfig=force-disable-vulkan=0`。
→ 改资源（Lua/数值）**理论可行**，但要过「xpk 内层格式」+「Md5List 校验」两关。

## 3. 功能可行性：伤害倍率 / 无敌

**逻辑层分布（实证）**：C# IL2CPP 主逻辑 + **XLua 脚本层**（`libil2cpp.so` 内 24 处 `xlua`、metadata 内 `LuaManager`、日志 `LuaManager.cs:Start:54 luamanager.start`；xpk 内含 `Scripts.zip`；`Md5List.txt` 有 `Lua/Lua/*`、`Lua/DataSettings/*`）。**无 HybridCLR**（metadata/libil2cpp 均 0 命中）。

三条实现路线：

| 路线 | 做法 | 优点 | 风险/代价 |
|---|---|---|---|
| **A. IL2CPP native hook（推荐）** | 运行时 dump 拿 `BattleUnit.TakeDamage/CalcDamage/Hp/IsInvincible` 之类方法偏移 → 星光菜单在 `libstarry_magic.so` 里 hook：伤害倍率＝乘算入参/返回值，无敌＝跳过扣血或强制 HP 不降 | 最稳、最通用、与资源校验无关 | 需先完成运行时 dump（§4） |
| B. Lua 层改 | 替换 xpk 内 `Lua/Lua/*`、`Lua/DataSettings/*` 脚本改数值/跳扣血 | 不用碰 so | 要破 xpk 内层格式 + 处理 `Md5List.txt`；脚本可能被压缩/加密 |
| C. 内存扫描 | 运行时扫血量 float 改伤害 | 无需 dump | 极不稳定，不推荐 |

**判定：可实现**。关键前置是**拿到 C# 方法偏移**；静态 dump 已被 MIRA 挡住，但**运行时内存 dump 路线在本仓库是成熟流程**：
- `04_scripts/明日方舟/dump_runtime_mrfzz.sh`（Unity IL2CPP + 壳，同类场景）：`su -c cat /proc/<pid>/maps` → `04_scripts/_common/dump_binge_shell_mem_device.sh` → 落 `06_dumped/<游戏>/runtime_<label>/`
- 现成可复用件：`_common/memdump64`、`_common/scan_shell_mem.py`、`_common/find_metadata_device.sh`、`_common/diff_il2cpp_mem.py`、`_common/start_frida_server.sh`
- 因为 `.dynsym` 完好（§1.3），也可以在运行时用 `il2cpp_domain_get_assemblies` + `il2cpp_image_get_class` + `il2cpp_method_get_name` **动态枚举全部类/方法名**（等价于一次 dump，不需要解密磁盘 metadata）。

> 说明：运行时 dump 需要 root 的**分析机/分析进程**——这只发生在「研究阶段」，**不影响最终交付给用户的无 root 直装包**（与长期约束不冲突）。

## 4. 「无 root 直装星光包」可行性判断

### 4.1 机械可行性（多为有利）
- ✅ 单 `base.apk`、无 split、无 DEX 壳 → 可直接拆包/重打包注入。
- ✅ `android:extractNativeLibs="true"` → 新增 `lib/arm64-v8a/libstarry_magic.so` 会被系统正常解压加载（若是 `false` 才需另想办法）。
- ✅ 目标为 arm64 真机；APK 内 `x86_64` 一套是冗余，重打包时可只保留 arm64（能顺带压体积，但**非必需**，减少改动更安全）。
- ✅ `targetSdk 30`、`usesCleartextTraffic=true` → 安装与网络策略宽松。
- ⚠️ APK 1.99 GB → 重打包需 zip64 + 对齐；签名走 `_common/rebuild_sign_install.sh` + `01_tools/uber-apk-signer.jar`（本仓库现有流程）。Android 对 targetSdk≥30 要求 v2/v3 签名，须用 apksigner 系工具。
- ⚠️ 装机前置门禁：`04_scripts/_common/pre_install_gate.sh`（AGENTS.md 强制）。

### 4.2 三个真实风险点（按严重度）
1. **签名校验（最高）**：重签名必然改变证书指纹；C1 已证明存在签名校验代码（字节系 + TapTap 系 + native `dvm_signature`）。是否**硬失败**（拒启动/踢下线）目前**未实测** → 这是直装包能否成立的**唯一决定性未知项**。
2. **Application 代理链（高）**：星光 `StarryApp` 必须继承 `com.bytedance.thanos.ThanosApplication`；Thanos 的初始化 + MIRA + 反篡改会跟着跑。需确认「继承 + super 调用」不会触发对我们不利的判定。
3. **Themis/MIRA 环境检测（中）**：TapTap Themis service 独立运行，可能上报/判定改包；MIRA 只管 metadata，理论上不拦新增 so。

### 4.3 判定
**可以做直装星光包**：结构上没有任何「死路」（无壳、单包、extractNativeLibs=true、核心 so 不需改动）。但**不能凭经验直接开做**，必须先过一个最小验证包：
> 只注入**空壳 so + 入口代码**（不实现任何功能），重签名装真机，观察：①能否启动进游戏 ②日志/SDK 是否报签名或篡改 ③联机是否被踢。
> 过了这一关，再上「伤害倍率/无敌」的功能实现。
