## 四、结论（问题 1 判定）

**零 Root × 零操作 × 纯 APK 的进门，在 main.js 热更 / Zeus / pangle / service.json / JSB 直调（System.load NPE、loadLibrary 走 system ns、abqf.g 需 Frankie、abhw.a 需 libdir）全部现有面上闭合无解**——8 月「静态穷尽」结论经本轮动态+新面复核维持，且收窄为单一根因：**我们 JS/插件的唯一执行入口都在「内部 files 写入」或「OSDK init」两个零 Root 不可达的门后。**

### 7.1 热更下载器源码（Constants.ts + HotUpdate 流水线，明文）

```js
class Constants {
  static get cloverEnv() { return window.cloverEnv ?? {channel:"test", env:"dev", cdnBaseUrl:"http://localhost:8080", isOpt:!1} }
  static get HOT_UPDATE_URL() { return `${cloverEnv.cdnBaseUrl}/${cloverEnv.channel}/${cloverEnv.env}` }
  // 实际 = https://wxmini-cdn.jj5agame.com/clover-app/android-tap/prod
  DIR_A="hot-assets-a"; DIR_B="hot-assets-b"
  MAIN_JS="realMain.js"; MAIN_JS_UNUSED="realMain.js.unused"
  MANIFEST_JSON="manifest.json"; TOP_VERSION="top-version.json"; HTTP_REQUEST_TIMEOUT=1e4
}
流程：getRemoteJson(`${URL}/top-version.json`) → publishInfo（含 forceHotUpdate.timestamp/zipSize）
     → getStringFromFile("manifest.json")（search-path 解析=已下载 hot-assets-a 优先，否则 APK 登记件）
     → currentManifest.gitTimestamp < publishInfo.forceHotUpdate.timestamp → 下载 zip 差分 → 写另一目录 → realMain.js 落位
```

**可影响点审计结果 = 零**：
- `window.cloverEnv` 全部引用为**只读**（jsc 内无运行时改写点）；cloverEnv.js = 裸 AssetManager 读登记资产（见 7.2）
- 本地版本状态 = search path 上的 manifest.json（内部 files，零 Root 不可写）；远端状态 = 固定 URL + TLS
- 无客户端 debug/test 旁路（inH5Test 依赖静态空串 h5TestData；isReview 由服务端判定）

### 7.2 cloverEnv/OSDK 判定链（CloverEnv.java，classes2）

- `CloverEnv.parseCloverEnv` = **裸 `context.getAssets().open("cloverEnv.js")`**：不经过 Cocos search path、无 SP 缓存、无服务端覆盖变量 → `channel="android-tap"` 恒定 → `isOSDK()=false` 对一切可存活包**恒成立**

## 八、候选 D：分身容器方案（2026-09-06 定稿讨论，📚 全部未实测）

> 来源：用户三关键字「免 root / 框架 / 分身版本」指向市面已有成品（VirtualApp / VirtualXposed / BlackBox / 太极 系）。本轮仅方案推演，未做任何实验。

### 8.1 为什么分身解决「进门」

- 游戏进程 = 宿主 fork，不是系统 zygote fork → 宿主对自己的孩子有完全控制权：dlopen 菜单 so、注入、重定向全免 Root，且时机早于游戏 ACE/TP 保安启动（保安醒来时我们已在进程内）
- 分身把游戏私有目录重定向到宿主数据目录 → 8 月 Root 种子那套「写 `files/innerVer` + `hot-assets-a/realMain.js`」（§一）在分身里**免 Root 可写**——main.js 热更门控这条进门路与「宿主直接注入」两条路同时打开
- 对分身而言 §四/§七 的「内部 files 零 Root 不可达」根因不成立（重定向后可达）

### 8.2 红线不变（分身只解决进门，不解决存活）

- **Dobby 原生钩子依然必死**（8 月实锤）→ 功能形态仍用轻量 JS 旗标（8 月已验证存活），分身里 hook 引擎反而可不用
- **星光 so maps 伪装仍要做**（问题 2，BSS 串表证实保安扫进程映射）
- 游戏文件零改动 → ACE 1Hz 文件校验天然能过；内存扫描靠伪装方案
