## 4. 未过项要拆的检测面（门3）

静态（官方 `libtersafe2` 可见串，加密多）：

- `/proc/%d/status`、`TracerPid`、`safe_ptrace`、`ptrace`
- `apk_path` / `RecvSignature` / `UnzipSignatureData`
- `dlopen`、`filecrc`、`sectionhash`、`HashBySyscall`、各类 `*crc*` / `*hash*`
- `mmap`/`munmap`（明文 **无** `/proc/self/maps` 路径串 → 多半运行时拼或 tramp 读）

历史动态（§11，残留期结论作线索）：

- libc 层能看到少量 `/proc/self/maps`；**status 等走 svc tramp**，libc hook 不够
- maps 行消毒曾命中，仍挡不住早期自毁；**晚载后 SI_USER** 是另一阶段（星光已在 maps）

**本轮分析任务（按序）**：

1. 干净机基线：官方 zip **不** load 星光，抓 `/proc` open 与存活  
2. 同机 load 星光后至死前：maps 是否含 `starry`/`files/starry_native`、是否 `SI_USER`、死前最后读路径  
3. 对照：是否「路径字符串」触发，还是「匿名可执行段 / 校验和 / 线程」  
4. 有可复现触发条件后，再定解法（隐蔽映射 / 同代过检体 / 短命注入）— **禁止**再盲磁盘 ace*、抄异代 libsdk、吞 BUS
