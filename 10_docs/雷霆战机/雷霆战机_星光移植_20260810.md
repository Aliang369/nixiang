## 2. 斌哥过检搬了什么（现行包内）

整包 decode 自斌哥 APK，下列**原样保留**（不是只抄一段 smali）：

| 组件 | 路径 / 类 | 作用 |
|------|-----------|------|
| MT Killer | `bin.mt.signature.KillerApplication193`（`classes6.dex`） | `<clinit>` 里 `killPM(包名, 原厂证书B64)`；含 HiddenApiBypass |
| Application 继承链 | `CloverApplication` → `AceApplication` → **`KillerApplication193`** → `Application` | Killer 在 Ace/`tersafe` 加载前生效 |
| ACE 壳 | `AceApplication.attachBaseContextShell` → native `initialize` | **保留**，不 nop |
| `libtersafe2` / `libtprt` | `AceApplication.<clinit>` `loadLibrary` | 保留 |
| `libsdk.so` | Ace `<clinit>` 额外 `loadLibrary("sdk")` | 斌哥 native 过检（与该版 ACE 配套） |
| `libSDKloading.so` | 随包存在；菜单壳 | 保留（星光未再走这条菜单） |
| 斌哥菜单 DEX | `classes7.dex` / `com.android.support.Main` | **文件还在**，但启动入口已关掉 |

证书回灌：Killer 静态块里的原厂 DER（CN=clover，MD5 `f0c5671a…`），与官方原包一致。

| 项 | 做法 | 原因 |

## 4. 官方 1.25.31 直注失败清单（勿再踩）

按尝试顺序；**下次 ACE 游戏先对照本表**：

| # | 做法 | 现象 | 根因判断 |
|---|------|------|----------|
| A | 仅 SignSpoof + 重签 | Application 卡死 / 黑屏 | ACE `attachBaseContextShell→initialize` 读 APK 真签 |
| B | SignSpoof 放 Ace super **之后** 或 Application 里 `loadLibrary(starry)` | 更早挂 / 与 tersafe 抢跑 | 时机错误 |
| C | **nop** `attachBaseContextShell` + 跳过 `TP2Sdk.initEx` | 能进 Privacy/AppActivity，但卡在 `loadLibrary("cocos")` | cocos JNI_OnLoad 仍要 native 过检态 |
| D | 连 `tersafe2`/`tprt` 都不加载 | 同上，仍卡 cocos | 不是「卸 ACE」就能过；缺 Killer+sdk 那套 |
| E | 官方底 + 抄斌哥 `Killer` smali + **抄 `libsdk.so`** | 加载 `libsdk` 后进程反复重启 | `libsdk` 与 **1.25.31 的 tersafe/ACE 版本不匹配** |
| F | 仅 Killer、不加载 `libsdk`、保留 initialize | initialize 阶段仍挂/杀 | Killer 只过 Java `PackageInfo`；native 还需配套 sdk |
| G | 斌哥底 + 星光 + **保留斌哥 Main 菜单** | 进游戏后秒崩 | tombstone：`libstarry_magic.so` 线程；双注入冲突 |
| H | 斌哥底 + 星光 early Dobby 钩 `evalString` | 同上崩 | 与 `libsdk` Dobby 叠钩 |
| I | **MT 手机去签**官方 → `KillerApplication643` + `libSignatureKiller643.so`；`tersafe2`/`tprt`/`libcocos` 与官方 **HASH 相同**（未改 SIGDATA） | 去签包 **无有效签名**（`NO_CERTIFICATES`）；uber 重签后可装，卡 `GamePrivacyActivity`，~8–23s 后 **signal 7 (SIGBUS)** 循环；`libcocos` 未映射 | Killer 只过 Java 签；**native tersafe 仍杀**。隐私跳过救不了 |
| J | 官方 + Killer + 官方 tersafe、不带 `libsdk` | initialize 挂 / 卡死 | 同 F |
| K | 官方 + stub `attachBaseContextShell` + skip `TP2Sdk` + Killer + 隐私跳过 | 能进 `AppActivity`，进程稳，黑屏 `dark≈0.97`，**不加载 libcocos** | 与历史「nop ACE → 卡 cocos」一致 |

**对照可开机（非目标）**：斌哥整包底 + Killer193/`libsdk` 不动 + 只换星光（关斌哥 Main）+ 隐私跳过。

## 5. 下次同类游戏复用清单

### 5.1 先判过检类型

1. Manifest `Application` 是否 `AceApplication` / `tersafe2` / `TP2Sdk`  
2. 斌哥包是否有 `KillerApplication193`、`libsdk.so`、`libSDKloading.so`  
3. 对比官方 vs 斌哥：`AceApplication` 的 `.super` 与 `<clinit>` `loadLibrary` 列表  

### 5.2 决策树

```
目标必须是官方原版？
  ├─ 是（本项目）→ MT 去签(Killer643) 不够；还需与官方 tersafe 配套的 native 过检
  │                 · 勿只 nop ACE shell（会卡 cocos）
  │                 · 勿抄别版 libsdk（LMKD）
  │                 · 对照斌哥：SIGDATA / libsdk 差异，找可迁方案
  └─ 否（只要能玩）→ 有 Killer193+libsdk 的斌哥底可注星光作权宜
```
### 5.3 安装（ColorOS）

```bash
# 禁止 adb install（会弹手点确认）
adb push "$APK" /data/local/tmp/x.apk
adb shell su -c "pm uninstall com.a5game.ltzj.jj"   # 可选
adb shell su -c "pm install -r -d --user 0 /data/local/tmp/x.apk"
adb shell su -c "appops set com.a5game.ltzj.jj SYSTEM_ALERT_WINDOW allow"
```

`inject_ltzj_1.25.31.sh` 已改为失败不回退 `adb install`。

### 5.4 开机自检 log

```bash
adb logcat -s StarryMagic:V MenuService:V Ltzj:V XSDK:V Mod_Menu:V
```

期望：`starry skip privacy`（若已跳）→ `libcocos` ok → `星光魔法 MOD 菜单已加载` → `auth game_id=ltzj` → `[Ltzj] init ok`。  
黑屏采样：`screencap` 后 `dark_ratio`；卡 Privacy 时 dark 高且中间有协议弹窗。

## 9. 纠偏（同日深夜）：卡启动 ≠ SignSpoof；apktool 重建即杀

用户现象「黑屏 + 中间 icon」后续诊断见：  
`官方星光_卡启动与打包路线_20260811.md`

要点：

- §8 smoke 之后手测仍卡启动；根因是 **`inject_ltzj_1.25.31.sh` 走 apktool 全量重建**，干净机上 **纯 apktool roundtrip 也会 SIGBUS**。  
- **apktool 不是签名工具**；签名是 uber/MT。换 MT 签名不解决本问题。  
- zip 探针：`assets/` 放 so **可活**；`lib/arm64-v8a/` 新 so / 新 `classesN.dex` / **改已有 dex 内容** → **杀**。  
- 明天：zip 注入脚本 + ACE 过检后再谈改 dex / 菜单 Java 入口。
