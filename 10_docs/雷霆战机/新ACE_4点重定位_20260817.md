## 3. 第 2 点为何不是「同 prologue 搜 sub#0x70」

斌哥 `0x41258`：大函数，`sub sp,#0x70`，被 **8 个 REL_HOOK helper** `bl` 调用。

新官方：

- stub 集群仍在（约 `0x38110` 起 8 个），helper 结构与斌哥同构；
- helper 里对应的 `bl` 目标改为 **`0x37fac`**（仍 **8 个调用点**）；
- `0x37fac` 序言是 `stp x29,x30,[sp,#-0x20]!`，内部校验失败会走 `random` + `br x0`（典型自毁），成功则 `ret`；
- 因此等价 patch 是：**在 `0x37fac` 入口直接 `ret`**，而不是再找 `sub sp,#0x70`。

## 5. 仍未解：载具（怎么 load acepatch）

官方 1.25.31 已证：

- ADD `lib/*.so` → ~10–15s SIGBUS  
- REPLACE `classes2` → SIGBUS  

因此「改 `AceApplication` + ADD `libacepatch.so`」不能直接当交付。载具候选（需单变量实验，未做）：

1. 把 patch 逻辑并进**已会 load 且允许的**薄层（历史 Bugly/shim 多死，慎用）  
2. Root 一次：冷启后早期从已落地路径 `dlopen` + 手调（接近现网晚载，但要赶在完整性窗前）  
3. 等长补丁直接改官方 `libtprt.so`/`libtersafe2.so` 磁盘字节（ACE 自校验风险高，仅作对照）

**B 路线当前进度：偏移已齐；卡在合法早载入口。**
