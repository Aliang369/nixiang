# 路线3 纠偏：错在哪、还有什么没试（2026-08-17）

> 回应：不是「绝对没办法」，是上一轮把解空间收窄到 **JSB → abqf.g → Frankie.mContext** 一条绳上，绳断了就误判整条路线3死了。  
> ACE **不是**百分百；矩阵证明的是「这些改法会死」，不是「一切注入都不可能」。

---

## 1. 上一轮思路错在哪

| 错误假设 | 为何错 |
|----------|--------|
| 零 Root 只能靠纯 JSB 调通 `abqf.g` | 只是**一条** PathCL 入口；把「入口全集」当成了「唯一解」 |
| Tap 上 Frankie 永 null ⇒ 路线3关闭 | 只说明 **abqf.g 这条**在 Tap 冷启不通；没否定 dlopen / 插件 so / 其它 Java 跳板 / 未保护面 |
| 扫完 public+static+String ⇒ 穷尽 | 漏了：**插件包内 so**、**未测完整性的 so（如 cocos）**、**ADD 新插件 apk**、**GameActivity/native dlopen**、**非 String 但可由已有 PathCL 类自发触发的链** |
| disk5-pad 死 ⇒ 改期望值全无意义 | 只证明 **tprt`.data` 不能当写表黑板**；没证明「所有 so / 所有资产槽」同等加锁 |

路线3的真正定义应是：

> **不改（或极少改）受保护的 host `lib/`+`classes*`，用可活的 ADD assets / 热更 files / 未锁载体，让星光进入「能 JNI_OnLoad 或等价」的加载路径。**

不是：「必须用 Frankie」。

## 3. 未充分试验 / 被跳过的假说（按优先级）

### H1 — `libcocos.so` 是否在完整性白名单外？（高优先）

- 库存表 **25 条不含 cocos / tprt**；tprt 另有自检（pad 已死）。  
- **从未**对 `libcocos` 做 Bn 级「翻 1 字节」单变量。  
- 若 cocos **可改**：可做「薄 JNI_OnLoad 包装 → dlopen 原 cocos + starry」（假说 A 旧思路，载体从 Bugly 换到 cocos）。  
- 若也死：cocos 同样锁死，记下即可。  
- ⚠ 待验证；一次安装即可证伪/证实。

### H2 — ADD 新 `gbsdk.plugin.*.apk`（不是 REPLACE）（高优先）

- 已有：`plugins-common.json` / `plugins-datalink.json` + 两个 plugin apk。  
- dex 里有 **`gbsdk.plugin.debug`**（DebugUtils）；官方包**没有**对应 apk。  
- E0 否的是 **REPLACE 已有** plugin；**ADD 第三个 plugin apk + 扩展 json** 未做。  
- Zeus 插件常自带 `lib/`，加载发生在 **plugin 空间**，可能不进 host 库存表。  
- ⚠ 要查：Tap 是否会装 debug 插件；json 是否只读死两份文件名；plugin 内 so 是否仍被 ACE 扫 maps。

### H3 — `assets/service.json` + 已在 PathCL 的「跳板类」（中）

- SDKWrapper 会读 `service.json` → `Class.forName` → `init(Context)`（**这里有 Context**）。  
- 缺的是：PathCL 上是否已有可写的 `SDKInterface` 实现，或能否让 **先加载的 plugin** 把类暴露给 forName。  
- 比 JSB 强：`init(Context)` 里可直接 `System.load(abs)`。  
- ⚠ 取决于类从哪来；纯 ADD service.json 指一个不存在的类会静默失败，不致命但无菜单。

### H4 — 重测 `Runtime.load0(PathCL, abs)`（中）

- 已知 `System.load` 绑 JSB CL。  
- 未系统重测：`Class.forName("android.app.ActivityThread")` / 游戏 Application 类 → `getClassLoader()` → `load0` 是否在**当前** cocos bridge 下可多步完成（或是否有遗漏的 jsb 重载）。  
- ⚠ 历史偏悲观；应用**新桥接假设**再打一次日志，而不是直接写「不可能」。

### H5 — `files/libso` / SafelyLibraryLoader 时序（中低）

- 失败后从 APK `lib/` 解压到 `files/libso` 再 `System.load`。  
- 若能对「APK 中不存在的 so 名」走出「不解压、直接 load 已有 files 文件」分支，则 JS 预置 so 即可。  
- ⚠ 需把 SafelyLibraryLoader 控制流画清再做；可能根本不存在该分支。

### H6 — 不经 Java：已加载 so 内 dlopen（低/依赖 H1）

- libcocos 含 `GameActivity dlopen("%s")` 与通用 `dlopen`。  
- 若能控制路径字符串或 hook 点在**可改且未检**的段上，可原生拉起 starry。  
- 依赖 H1 或其它可写 RX 段。
