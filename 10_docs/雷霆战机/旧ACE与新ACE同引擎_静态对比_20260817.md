# 新旧 ACE 同引擎 — tersafe2 静态对比（2026-08-17）

> 日期：2026-08-17
> 结论：**五个包的 `libtersafe2.so` 是同一个检测引擎**，MD5 不同只是按游戏/版本定制。「旧官方 ACE 更弱」假设**不成立**。
> 关联：`libsdk脱壳分析_RC4壳_20260817.md`（斌哥过检靠 libsdk，不靠 tersafe 代际差异）

---

## 1. 一句话

旧官方 1.20.13 的 tersafe2（`0e9f1de1`）和新官方 1.25.31（`ba597b32`）是**同一代检测引擎**，字符串和检测关键词几乎一字不差。所以「下载旧版官方包做零 Root 整包代换」这条路**在 tersafe 层面走不通**——换旧包 = 没换。

---

| 包 | tersafe2 MD5 | 字符串数 | 大小 |

五个包 tersafe2 都是 **5979312 字节**，字符串数 13118~13124（差异仅 3~6 条随机字节，非语义字符串）。

---

## 4. 结论

1. 五个包的 tersafe2 **是同一个检测引擎**，检测能力内置统一，跨大版本未变。
2. 斌哥能过检**不是** tersafe 更弱，而是自带 `libsdk`（native 过检体）+ Killer（签回灌）+ 配套旧代 tprt/cocos（见 `斌哥ACE如何认了_分析_20260816.md`）。
3. 「零 Root 纯 APK 整包代换」在雷霆战机上**走不通**：ADD lib / ADD dex / REPLACE so / REPLACE assets 均被同一引擎杀（见 `纯APK自启_全新分析_20260816.md` §6）。
4. 可行路线只剩：
   - Root 一次 + abhw 自动晚载（已验收）
   - 设备端 inject（已验收）
   - 复用斌哥整包底 + libsdk + Killer（需先脱壳 libsdk，见 `libsdk脱壳分析_RC4壳_20260817.md`）

# 提取 tersafe2
