## 1. 一句话

官方 ACE 的磁盘完整性是**多层调度**（filecrc / sectionhash / HashBySyscall / tprt 侧多枚期望摘要），不是「改 4 条指令就能放行」。  
历史 ace3–ace14 + 本轮 disk4 都在「等长改 ACE so」上失败；零 Root 必须先把**官方自己的校验链**钉全，再谈补丁。

## 3. 已定位的检测相关落点（静态）

### 3.1 `libtersafe2` 明文调度串 → 代码

| 字符串 | file off | 相关代码（仍有效） | 语义 |
|--------|----------|-------------------|------|
| `sectionhash is call` | `0x46a70c` | `0x37a730` 打日志后 **`blr x8` @`0x37a750`** | section 哈希，结果走 vtable |
| `filecrc is call` | `0x46a7bd` | `0x37ad8c` 一带，**`blr x8` @`0x37adb0`** | 文件 CRC，vtable |
| `HashBySyscall is call` | `0x46adc8` | （同簇 ioctl/hash 调度） | syscall 侧哈希 |

> → 只掐这两个 BLR **不够**。

## 4. disk4 对照（本轮，官方四点+MD5 同步）

改动：仅磁盘改官方 4 指令（重定位自 libsdk 语义）+ 改写 `0x16956c` 为新 tersafe 整文件 MD5。

| 结果 | |
|------|--|
| 死 | SIGSEGV ~20–33s，后变 SIGBUS ~11s |
| cocos | 未 load |
| 副作用 | 改 1 条 `.text` 指令 → **`.text` section MD5 变**（`676dc231…` → `ebf4ade3…`） |

含义：

1. 即使同步了 **整文件** MD5（`0x16956c`），**段级摘要 / filecrc / sectionhash** 仍可能判失败。  
2. 四点里至少有一处（尤其 `0x37fac` 闸门直接 `ret`）可能导致 **SIGSEGV**（逻辑被砍坏），与纯完整性 SIGBUS 要分开看。  
3. 不能把「libsdk 在旧包上的四点」当成官方检测全集。

## 5. 历史官方磁盘刀（避免重复盲打）

| 实验 | 改动摘要 | 结果 |
|------|----------|------|
| ace3–9 | 多簇 tersafe 等长 | 早死 |
| ace10/11 | filecrc 调度 early-ret ± 叠簇 | 早死 |
| ace12 | 仅 sectionhash+filecrc 两处 `blr→mov x0,0` | DEAD ~7s（曾见 cocos） |
| ace13 | ace3 tersafe + 改 tprt 内嵌 MD5 | 隐私页轮转 |
| ace14 | stock tersafe + tprt 比较函数 early-ret | 隐私页轮转 |
| **disk4** | 官方四点 + MD5 同步 | SIGSEGV/SIGBUS，无 cocos |

共同结论：**单层或少点磁盘旁路过不了官方包装闸门。**

## 6. 官方检测面分层（当前模型）

```
冷启 AceApplication
  ├─ load tersafe2 / tprt
  ├─ A. tprt：多 ABI 整文件 MD5 + 文件大小 +（疑）section 摘要表
  ├─ B. tersafe：filecrc / sectionhash / HashBySyscall（vtable，非死常量）
  ├─ C. 签名 / apk_path / RecvSignature
  └─ D. 其它（maps/模块/延迟杀）— 改 so 后常 10–30s 死
```

零 Root 要活，需要 **A+B（至少）在官方布局上被完整旁路**，且不能把 init 必需路径 `ret` 断掉。

## 10. 摘要表记录格式（`0x19b7xx`）

每条约 `0x50` 字节，字段顺序：

`va(u32) | file_off(u32) | size(u32) | crc32(u32) | md5_ascii(32) | pad`

已用 `.text/.rodata/.plt/.dynstr` 验证：`crc32` = zlib，`md5` = 对应 file 区间。  
`.data` 条目（`@0x19b750` / MD5 `@0x19b760`）元数据指向 tprt `.data`，但 **CRC/MD5 与裸文件不符**（摘要表自身也落在 `.data` 内，存在自引用问题）。

tersafe `.text` 条目元数据从 **`0x19b8b4`** 起（前有 `#F#` 标记），MD5 在 **`0x19b8c4`**。

---

## 11. filecrc / sectionhash / HashBySyscall 调度（官方 tersafe）

均在同一 JNI 调度簇，日志串 → `blr` 走 vtable（非死常量）：

| 串 | 日志点 | vtable load | BLR |
|----|--------|-------------|-----|
| `sectionhash is call` | `0x37a730` | `[obj+0x20]` | `0x37a750` |
| `filecrc is call` | `0x37ad8c` | `[obj+0x70]` | `0x37adb0` |
| `HashBySyscall is call` | `0x37b948`（`add x0,#0xdc8`） | `[obj+0x2a8]` | `0x37b968` |
| `enchash` | `0x37ae58` | （同簇） | |
| `enckeyhash` | `0x37aa40` | （同簇） | |

> ace12 只掐 sectionhash+filecrc 两处 BLR 仍 DEAD；HashBySyscall 是同簇第三条已钉死的调度口。

`ADD #0xdc8` 候选（tersafe）：`0x1386b4` `0x271c84` `0x344b88` `0x344c60` **`0x37b94c`** `0x3ee90c` —— 其中 `0x37b94c` = HashBySyscall 串。
