## 4. 官方-only 过检候选（按优先级）

不抄 binge `libsdk`。

| 秩 | 方案 | 理由 | 风险 |
|----|------|------|------|
| **1** | **KernelSU App Profile**：对 `com.a5game.ltzj.jj` 隐藏 root / umount modules（先环境隔离） | 官方原签仍崩 → 先排除环境误伤；dmesg 曾有该包 profile | 不改 APK；若 profile 不全仍死 |
| **2** | **Frida spawn**：hook `openat`/`faccessat`/`stat` 挡 `/data/adb`、`/proc/self/maps` 敏感段、su 探测；hook `tp2_*` / `is_root` 上报路径 | 明文路径少，需动态抓探测目标 | ACE 反 Frida；须 spawn 极早 |
| **3** | **官方 `libtersafe2` 定点 patch**：跟 `is_root` 格式串 / `mt2_no_root` / `tracer_scanner` xref，把 root 结果恒 0 或 nop 杀进程分支 | 不依赖 binge sdk；与官方 ACE 版本匹配 | 需 IDA+运行验证；易校验失败 |
| **4** | **保留 `initialize` + 延后/弱化 `initEx`/`login007`**：smali 里 lobby 前不 `setuserinfoex`/`AllowAPKCollect` | 针对「开始游戏」第二阶段；本次死在更早，单独不够 | 历史 nop ACE 会卡 cocos；只能弱化、不能卸壳 |
| **5** | **官方底 + 自研轻量 SignSpoof（仅当必须重签时）+ 3 的 native patch** | 重签场景；Killer 只过 Java 签 | 勿抄 binge libsdk（曾 LMKD） |
| **6** | **对比官方 vs binge 的 `TSS_SDK_SIGDATA` / tersafe 版本差**，做「同版本 ACE 配套」而非搬 so | 中长期正确路径 | 工作量大 |

**明确不做**：装 binge/mod APK；抄 binge `libsdk.so` 进官方 1.25.31。

### 7.2 故障地址（ptrace 全线程 SEIZE）

工具：`ltzj_ptrace_bus2`（只吞 SIGBUS，放行 SIGSEGV 给 ART）。

| 项 | 值 |
|----|-----|
| 信号 | **SIGBUS (7)** |
| 故障 PC | **`libc.so`（bionic）**，PC **非 4 对齐**（例 `libc+0x7dxxx` 以 `…baf` 起，每次 +4 滑动） |
| lr | 常落 **vdso** |
| 寄存器 | 例 `x0=0xb x1=<buf> x2=0x18 x8=2` |
| 含义 | 更像 **毒化/截断映射后在 libc 内取指或访问**，不是 tersafe 明文 `brk`/`udf` 主路径 |
| PC+4 吞 BUS | 可连跳数千次，最终仍死（例 `MAIN signaled 11`）— **不能当过检** |

Frida `setExceptionHandler` 大量命中的是 **ART NPE**（`boot*.oat` `ldr x21,[x21]` `mem=0`），**几乎看不到** tersafe/tprt 模块内 fault → 与 ptrace 结论一致。

### 7.3 tprt `exit_group(7)` 线

静态：`libtprt` 约 **108** 处 `mov x8,#94; svc`，其中 **100** 处为 `mov w0,#7` + `b.eq` 成功旁路（`tprt_exit7_sites.json`）。

| 手法 | cocos | ≥60s |
|------|-------|------|
| 磁盘 `passcheck` / `exit7_nop`（改 tprt） | **否**（卡 `GamePrivacyActivity`） | 否 — **tprt 完整性** |
| cocos 后 `/proc/pid/mem` NOP 全部 exit_group + beq→pass | 是 | **否（~11s）** |
| Frida late attach 同补丁 | 是 | **否（~8–11s）** |

结论：磁盘改 tprt 会卡启动；内存 NOP exit_group **挡不住** 真 SIGBUS。

## 9. 启动 bypass — **REVOKED 可玩声明（2026-08-10 深夜复验）**

> **撤销**一切「可玩 / SUCCESS / inplace success」口径。仅凭 screencap 大小或同 pid 存活 **不算** 可玩；须连续帧/UI 差分，或多次 tap 后仍可点。

### 9.0 复验结论（官方 12531，无 binge/libsdk）

| 方案 | ≥60s+cocos | 启航后可点 | 证据 |

### 9.1 启航冻结根因（当前判断）

1. **第一阶段（~10s）**：ACE 自毁，常见 Zygote **signal 7 (SIGBUS)**；偶发 11。ace3 挡不住。  
2. **吞 SIGBUS 路线**（inplace / ptrace / Frida skip）：进程可「活」，但 ACE 持续抢 `sigaction(SIGBUS/ILL)`（`sa_block` 风暴）或 fault 风暴 → **主线程/渲染饿死 → 点不动**，再崩。用户点启航后的表现与此一致。  
3. **启航第二阶段**（`CloverUtils.login007` → `onUserLogin` + `ioctl("AllowAPKCollect")`）会再强化；当前多数跑法 **到不了稳定启航屏**，或到了也因 fault 风暴不可点。  
4. Frida `setExceptionHandler` 大量命中的是 **ART NPE**（`read@0`），**不是** 致命 unaligned-libc BUS；log-only 诊断勿与真杀混淆。  
5. 一次性 ptrace 捕获：停在 **libart 对齐 PC**，LR/`x8` 呈污染形态；交付 SIGBUS 会污染现场。真正的「毒 PC 写点」**仍未落到可等长磁盘补丁坐标**。

### 9.1b ptrace（禁止当过检）

### 10.4 一次性 BUS 捕获（立刻 DETACH）

- PC 在 **`libart.so`（对齐）**；**LR / x8 为垃圾未映射**  
- 与「libc 非对齐 PC」历史形态同类：**寄存器/返回址被污染**，未必是当前线程主动 `svc` 投 SIGBUS  
- 证据：`08_output/雷霆战机/ltzj_ace9_bus_once.txt`

### 10.5 明确下一 blocker（具体偏移）

2. **`nanosleep(101)` 跳板循环**（约 1Hz）与死前最后 1s 的 syscall/open 路径对齐。  
3. 若完整性因 ace8/9 改 PLT 走旁路：在 **未改 PLT** 的 orig/ace3 上只做 **late mem** 过滤，并在死前对 trampoline 打点（已有脚本可扩）。

### 11.1 Phase 1 — LOG ONLY `/proc` 轨迹
