## 1. XXTEA key（本次实测取法，可复现）

Cocos 3.8.7 的脚本 key 不在 `.jsc` 明文、不在 dex（御安全加固后搜不到）、不在 `engine-adapter.js`，
而是运行时写进 `libcocos.so` 的静态变量 `_ZL8xxteaKey`（`.bss`）。取法：

1. 解析 ELF symtab：`_ZL8xxteaKey` @ vaddr **0x1c11390**（size 24，section 23 = .bss）
2. maps 里取 `libcocos.so` **offset 0 段**的起始地址作加载基址（不要用带 offset 的 r-x 段）
3. 运行时地址 = base + 0x1c11390；读 24 字节，libc++ SSO 布局：**byte0 = size << 1**（bit0 = is_long）
4. 本次实测：`0x20 61 38 4b 61 55 64 61 4a 64 4a 34 5a 33 78 63 6b` ⇒ size=16 ⇒ **key = `a8KaUdaJdJ4Z3xck`**

解密：`xxtea.decrypt(data, key, padding=False)` → 直接是 JS 明文（本包**不 gzip**，与 2.x 的 `XXTEA+gzip` 不同）。
7 个 `.jsc` 全部解开，主脚本 `assets/assets/script/index.jsc` 1,427,060 B → 185 个 `System.register` 模块。
产物：`09_test/_batch_binge6/修仙王朝模拟器/js_104/dec/`、按模块切分在 `js_104/modules/`。

## 6. TapTap 改包法（2026-11-03 实测，新 SDK：ClientLoginUtils + GatekeeperRepository）

本包 TapSDK 4.9.5 为**新 SDK**（无旧版 `ActivityHandler`/`ClientLoginHandler`），改签后表现为
「每次启动弹签名校验提示 + 快速认证流程卡住、点不动」。官方 `classes.dex` 五处 smali 补丁（脚本
`04_scripts/修仙王朝模拟器/xxwc_patch_taptap_login.py`，产物 `13_scratch/xxwc_taptap/classes.patched.dex`，
是**唯一被改的官方 dex**）：

| # | 类.方法 | 改动 | 作用 |
|---|---|---|---|
| 1 | `login.impl.utils.ClientLoginUtils.isClientLogin(Activity,Actions)Z` | `const/4 v0,0x0` | 不走客户端 SSO，fallback WebView 网页授权 |
| 2 | `initializer.repository.GatekeeperRepository.isGatekeeperLoadedSuccessfully()Z` | 恒 `true` | 完整性/签名门闩放行（上层 InitializerServiceImpl / TapTapSdkInitializer 全透传） |
| 3 | 同类 `showGatekeeperError()V` | `return-void` | 掐掉验签失败弹窗 |
| 4 | `compliance.internal.TapComplianceInternal.goTapFastAuth(Activity)V` | `canPlay=1`、`noticeGameCanPlay=1` → 调 `noticeGamePlayable()` | **放行**防沉迷（派发 500「可玩」消息 + enterGame），不是跳过 |
| 5 | 同 #2 类 `showErrorToast(TapNetworkException)V` | `return-void` | 掐掉初始化失败时服务端 msg 的 Toast（`access$showErrorToast` 的唯一出口） |

**关键教训（一坑一解）**：
- 第 4 处先做成 `return-void`（弹窗不弹）⇒ **游戏画面正常但完全点不动**。原因是合规流程停在半路，
  SDK 在游戏界面上留了一个**全屏、可触摸、抢焦点的透明 Dialog**（`dumpsys input` 里 frame `[0,0][2120,3000]`、
  `inputConfig=0x0`、`mCurrentFocus` 指向它），触摸全被它吞掉。改成「设标志位 + noticeGamePlayable() 放行」后
  `mCurrentFocus` 回到游戏主窗口，触摸恢复正常。
- 因此**删弹窗 ≠ 跳流程**：凡 `goXxx` 型弹窗入口，要"模拟用户点击的正向结果（放行）"，不要空实现。

**验证证据（本机 OPD2404 / Android 16）**：
- 启动 25 s 内 `logcat` 无 `TapSDK-Dialog: authorization web content`、无 `Window{... Toast}`（改前每次启动有 771×113 Toast）
- `dumpsys input` 中全屏可触摸窗口只剩游戏主窗口，`mCurrentFocus` = `com.cocos.game.AppActivity` 主窗口
- 屏幕实拍：直接进 Lv1 灵气复苏主界面，可正常点按（物资弹窗、战力/仙玉数值随操作变化）
