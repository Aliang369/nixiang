# 游戏 MOD 设备无关注入规约（可复用）

> 建立：2026-10-04 · 适用：`mod菜单/starry-mod-menu` 全体游戏 MOD（含以后新增的每一个）
> 触发：用户 m02848 原话「之前通过 mac 改的游戏，在模拟器上功能全部无效；**我要的是功能在任意设备——真机、模拟器、云机——都能用**」＋ m02851#6「现在勇士之心已经完成，**我说的是以后的所有游戏**」
> 实证来源：①勇士之心（ysxz，Mac 出包 → 模拟器全灭）②冒险与征途（mxyzt，Win/MuMu 出包 → 真机全灭）
> 配套代码：`mod菜单/starry-mod-menu/app/src/main/jni/Includes/StarPtr.h`

## 0. 一句话结论

MOD 功能「在某个环境有用、换环境全无效」**几乎从不是功能逻辑写错，而是注入面/判据把某个运行环境的性质写死进了代码**：写死地址偏移、写死映射权限、写死指针取值范围、写死设备标识来源、写死 ABI。**判据必须由运行时事实推导，且判否必须留下可读的日志**——静默全灭是最贵的故障形态（本次两次事故各烧掉一整轮装机验证）。

---

## 1. 病类定义（三条判据，中任一条即有病）

| 编号 | 病征 | 为什么会「换环境就废」 |
|---|---|---|
| P1 | **写死绝对地址 / RVA** | 地址只对某一个具体二进制有效。换 ABI（arm64↔x86_64）、换渠道包、换游戏热更版本、换加固壳，同一 RVA 就落到别的函数中间 |
| P2 | **判据依赖某环境的实现细节** | 映射权限位（模拟器 Houdini 呈 `r--p`）、指针顶字节标签（真机 Scudo/TBI 呈 `0xb4000076…`）、页大小、PAC/BTI 指令、`/proc/self/maps` 布局 |
| P3 | **判据绑定设备/身份来源** | 设备指纹取自易变字段（SSAID / Build.*）、会话只存进程内存、存档票有效期过短 ⇒ 云机/重装/换实例即失效 |

**判定口诀**：写完一行判据先问——「这台设备换一台（或换成模拟器）还是成立吗？」答不上来就把判据挪到运行时。

## 2. 两个实证案例（正反两面，同一病类）

### 2.1 案例 A：勇士之心（ysxz）—— 原生钩子路线在模拟器全灭

- 现象：Mac 侧做出的原生 hook 在 MuMu 上**功能全部无效**。
- 根因（P2）：
  - `jni/Games/YsxzMod.cpp::FileOffToVa()` 只接受**含 `x` 权限**的映射行：`if (!strchr(perm,'x') || end <= start) continue;`
  - MuMu = x86_64 + Houdini 翻译层，**所有映射呈现 `r--p`**（代码在匿名区经翻译执行）⇒ 钩子目标 RVA `0x3138E4` 恒 `not mapped`，日志刷屏 `[Ysxz] evalString rva 0x3138E4 not mapped`。
- 修法：**换注入面**——不再依赖「原生代码段可钩」，改为往运行时 JS 资源注入自举补丁。
  - 落点 `/data/data/com.fightingstars.games.warrior/files/res/main.js`（免重打包、免原生 hook，且不在服务端 4 文件 md5 白名单内：`assets/{battleLogic,battleRender,game,main}/index.js`，动这 4 个必被 `BingoBridge->exitProgram` → `System.exit(0)` 杀）。
- 结果：**同一份补丁在真机（arm64）与模拟器（x86_64+Houdini）都生效** ⇒ JS 层注入天然设备无关（无指针算术、无地址假设）。
- 附带教训（P3 边缘）：补丁曾在真机上「无限技能/移速/自动战斗」三项静默失效，根因是**菜单序号**写死 1.0.4 表却装在 1.0.3 包上 ⇒ 已改为运行时自适应 `lay()`（按「滑块行会把值槽写成 ≥1、开关行恒 0」判表）。**能查就别写死**同样适用于菜单索引。

### 2.2 案例 B：冒险与征途（mxyzt）—— 指针判据在真机全灭（本轮新修）

- 现象：在 Windows/MuMu 上做的包，**真机（小米 11 / arm64 / Android 14）四项功能全无效**。
- 根因（P2，铁证）：
  - `jni/Games/MxytzMod.cpp:159-162`：
    ```cpp
    static inline bool LivePtr(const void* p) {
        const uintptr_t u = reinterpret_cast<uintptr_t>(p);
        return u >= 0x100000000ull && u < 0x800000000000ull;   // ← 拿原始指针判区间，没清顶字节
    }
    ```
  - 真机（arm64 + Android 12 以上）堆由 Scudo 分配在 **`0xb4…` 段**，指针形如 `0xb4000076c1646d58`（硬件 TBI 使访问时忽略顶字节，**解引用完全合法**）。
  - `0xb4000076c1646d58 ≥ 0x800000000000` ⇒ `LivePtr()` **恒 false**；该函数被 **约 45 处**调用点使用，其中包含解释器入口的实参解码与伤害策略 ⇒ 全部路径静默早退 ⇒ 四项功能在真机全灭。
  - 模拟器侧（x86_64 + Houdini）地址落不到 `0xb4…` 之上 ⇒ 同一份代码在 MuMu 上一切正常。**这就是「模拟器有效、真机没效果」的完整解释。**
- 仓库内同类实证（此前已各自踩过）：境界守望者 `IsValidHeapPtr()` 拒真机 tagged 指针 ⇒ 63 个程序集全判空；无悔华夏日志 `mi=0xb4000076c1646d58`；境界刀鸣 lua state `0xb4000076…`。
- 修法：抽出唯一判据入口 `Includes/StarPtr.h`（**先清顶字节，再判 `4GiB ~ 128TiB` 用户态区间**），11 个游戏文件迁移。
- 仍存在的隐患（已修）：Family B 六个文件虽然掩码了，但上界写成 `0x8000000000`（512GiB）——真机堆清标签后可达 `0x76…/0x78…`（≈509.6 / 517.9 GiB），**越界与否取决于堆落点**，属随机复现的隐雷。

## 3. 环境差异矩阵（必须逐环境验收）

| 维度 | 真机（小米 11 / arm64 / Android 14） | MuMu（x86_64 + Houdini / Android 15） | 云机（推断，未直接验证） |
|---|---|---|---|
| ABI 执行方式 | 原生 arm64 | 翻译执行 arm64 代码 | 多为 x86_64 模拟器实例 |
| 堆指针 | `0xb4000076…`（顶字节带标签） | `0x7…` 段（无标签） | 视实现；多为无标签 |
| `/proc/self/maps` 权限位 | 正常 `r-xp` | **全 `r--p`** | 视实现 |
| 代码段能否 inline hook | 能（注意 PAC/BTI） | **不能**（代码不在 x 段） | 多为能 |
| SSAID / Build.* | 稳定 | 稳定 | **可能每实例变化**（本规约 §7） |
| 会话持久化 | 进程内存 + 存档票 | 同左 | 实例重建可能清 `/data/data` |

> 结论：**任何只在一个环境验证过的 MOD，都不得声称「完成」。** 至少真机 + MuMu 双环境过一遍；涉及授权/身份的功能追加云机。

## 4. 注入面分层与选择规则

优先级从高到低，**能用上层就不用下层**：

| 层 | 形态 | 设备无关性 | 代价 |
|---|---|---|---|
| L1 JS / 资源层 | 往运行时脚本、配置、bundle 注入 | **最好**（无地址/指针假设，只需资源路径稳定） | 需游戏有脚本层（Cocos/Lua/态机 JS） |
| L2 Java / 框架层 | `ContentProvider` / `Application` / 生命周期回调 + `System.loadLibrary` | 好（Android 契约稳定） | 只能做加载与桥接，改不了游戏逻辑 |
| L3 原生层 | `Dobby` inline hook、`evalString`、读进程内存 | **最差**，必须按 §5/§6 做运行时解析 | 能力最强，风险最高 |

**L3 三条硬性要求**：
1. 目标地址**只能**由运行时事实推导（符号表 / 特征码扫描 / 结构遍历 / 已加载模块基址 + 版本校验），并在挂钩前用「目标处指令形态」做一次自证；推导失败就**放弃并打日志**，不做「猜一个地址硬钩」。
2. 禁止依赖映射**权限位**做定位（Houdini 下 `x` 位不存在）。
3. 挂钩必须在**已确认 `x` 可执行**的区间内进行；不可执行时先 `mprotect` 或改走 L1/L2。

## 5. 指针判据铁律（本规约最重要的一节）

`mod菜单/starry-mod-menu/app/src/main/jni/Includes/StarPtr.h` 是**全框架唯一**允许判断「这个指针像不像堆指针」的地方。

| 铁律 | 内容 |
|---|---|
| R1 | 任何游戏 `Games/*.cpp` **不得**再手抄区间判定（`u < 0x…` / `u > 0x…`）。历史事故全部来自手抄。 |
| R2 | 比较区间前**必须**先清顶字节：`kTopByteMask = 0x00FFFFFFFFFFFFFFull`。 |
| R3 | 合法用户态区间统一为 `kUserVaMin = 0x100000000ull`（4GiB）～ `kUserVaMax = 0x800000000000ull`（128TiB）。**不得**用 512GiB（`0x8000000000`）之类过窄上界。 |
| R4 | 热路径用 `LiveFast()` / `LiveFastCounted()`（只判区间、零 I/O、不查 maps）；需要「确实可读」再叠加 `Il2Cpp::IsValidHeapPtr()` / `IsReadableRange()`（走 maps 快照，慢）。 |
| R5 | 需要「对齐 + 像对象」用 `LiveObj()`（= `IsAligned && LiveFast`）。 |
| R6 | **判否必须可观测**：在启动或首次用到钩子后调一次 `starptr::Verdict("tag")`，日志形如
`[Ptr] mxyzt verdict: checks=… ok=… rejected=… tagged=… untag_saved=… mode=tagged-heap|plain-va`；`ok==0` 时额外 WARN。看到 `mode=tagged-heap` 就说明该设备必须靠清标签才能活。 |
| R7 | **区间上下界也必须来自 `StarPtr.h`**。历史事故里 6 个 `SoftPtr` 写下界 `0x1000000000ULL`（=64GiB，与旁边注释「4GiB」自相矛盾，疑抄多一个 0）⇒ 一律改回 `starptr::kUserVaMin`。下界的作用只是滤掉小数/截断值，放宽到 4GiB 不会放行真机堆指针（真机堆实测 ≥100GiB）。 |
| R8 | 新增游戏/改注入面后，必须跑一次 `bash 04_scripts/_common/starptr_compile_probe.sh`（见 §9）：它既编 11 个 TU，也**全仓扫描**是否有人又手抄了 `0x800000000000` / `0x00FFFFFFFFFFFFFF`（注释行豁免）。 |

**API 速查**（`StarPtr.h`）：`starptr::Untag(u|p)` / `InUserVa(u|p)` / `LiveFast(u|p)` / `IsAligned(p, align=8)` / `LiveObj(p)` / `LiveFastCounted(p)` / `stats()` / `Verdict(const char*)` / 兼容别名 `CompatLivePtr(p)`；常量 `kTopByteMask` `kUserVaMin` `kUserVaMax` `kTagHintTop=0xb4`；诊断可 `-DSTARPTR_STATS=0` 关掉。

## 6. 禁止写死清单（P1）

1. 目标函数的 RVA / 文件偏移 / 绝对地址（含「从斌哥包抓来的偏移」——它只对那一份二进制有效）。
2. 映射权限位（尤其要求 `x`）。
3. 指针取值范围（必须走 §5）。
4. ABI / 页大小 / 指令集特性（PAC、BTI、MTE）假设。
5. 模块加载顺序、`/proc/self/maps` 行序、`dl_iterate_phdr` 返回顺序。
6. 菜单/功能**序号索引**（必须运行时自适应；ysxz 已实证）。
7. 设备标识 = 易变字段直算（见 §7）。
8. 输出路径含非 ASCII 时的工具链假设（本仓库路径含「mod菜单」，Windows clang 需 ASCII 暂存目录，见 `mxyzt_build_so.sh` 的 `STAGED` 分支）。

## 7. 身份 / 授权类功能的附加要求（云机专项，P3）

云机的两条失效路径（`10_docs/勇士之心/菜单授权_二次打开未授权_根因与修法_20261004.md` 有完整推导）：

1. **设备指纹漂移**：SSAID / `Build.*` 每实例变化 ⇒ 服务端 `heartbeat` 判「会话与设备不匹配 / 设备绑定已变更」⇒ 客户端 `isHardAuthFailureJson()` 命中「设备」⇒ `hardKickAuth()` ⇒ 菜单显示**未授权**。（重新输卡密即恢复，与用户现象一致。）
2. **实例重建**：`/data/data` 被重置 ⇒ `shared_prefs` 里的 `auth_*` 全丢。

因此：
- 设备标识**首次生成后必须持久化并优先复用**，不得每次调用重算；重算结果只能作为迁移候选（`legacy_device_ids`）上报。
- 会话不能只活在进程内存；存档票有效期不得短到「二次打开必然过期」。二次打开时必须存在**静默自愈路径**（用已存卡密/refresh token 重签），而不是弹回登录。
- 只有**权威失败**（封禁 / 过期 / 次数用尽 / 卡不存在）才允许清会话；设备不匹配、网络错误一律**不踢**。
- 关键节点必须留 verdict 日志（如 `[auth] cold-start self-heal: reason=… → relogin ok/fail`），否则云机侧无法远程定位（云机通常拿不到）。

## 8. 验收矩阵（每个新游戏/每次改注入面都要走）

| # | 环境 | 必查 |
|---|---|---|
| 1 | 真机（arm64，Android 12+） | 功能逐项生效；`[Ptr] … mode=tagged-heap`；无 SIGSEGV |

## 9. 新增游戏 checklist（开工模板）
