## 0. 一句话结论

**官方原包没有百度壳 / 斌哥 `libSDKloading` / RootBeer `toolChecker`，也没有腾讯 ACE/`tersafe`。**  
有的是 4399 FN 渠道 Application、Cocos 引擎，以及 **设备风控/活体/数美类 SDK**（`turingmfa` / `smsdk` / `secsdk`），属于登录与风控，**不是 PCR 那种整包 dex/arsc 完整性自杀校验**。  
星光注入相对斌哥底包更「干净」；仍需处理 **重签后的渠道签名 API**（FN `getApkSign` 等）与 Application 继承链。

## 2. Native 库：加固 / 反作弊对照

### 2.2 仅斌哥有（官方无）

| so | 含义 |
|----|------|
| `libSDKloading.so` | 斌哥玩法壳（Dobby / 菜单） |

### 2.3 官方有、需归类的「安全相关」so

| so | 归类 | 说明 |
|----|------|------|
| `libcocos2djs.so` | 引擎 | 玩法主逻辑；`se::evalString` @文件 `+0xbd9328`（与斌哥同符号） |
| `libturingmfa.so` | **腾讯图灵 MFA/风控** | `TuringFdNative` / `riskCheckWup` / `turingRiskDetect` — 设备/人脸风控，非 APK 字节校验 |
| `libsmsdk_mirror.so` | 数美类设备指纹 | dex 有 `smsdk init` / load failed 串 |
| `libsecsdk.so` | 渠道附属安全库 | 字符串极少（`JNI_OnLoad`/`dlopen`）；**未见** frida/root/apk-integrity 明文；更像加固/混淆的小库，**非**独立整包校验壳 |
| `libYT*Liveness` | 活体检测 | 实名/人脸，与改包完整性无关 |
| `libmsaoaid*` | MSA OAID | 广告标识 |

**未发现：** `libtersafe*` / `libtprt` / `libqkcheck` / 爱加密/乐固/梆梆等典型整包加固名。

## 4. 对星光改包的含义

| 风险 | 等级 | 做法 |
|------|------|------|
| 百度壳解密链 | **无（官方）** | 不必保 Sagittarius |
| 斌哥壳依赖 | 无 | 玩法自己挂 `se::evalString`（见抓点定稿） |
| FN `getApkSign` / 重签 | **中** | SignSpoof 或对齐造梦西游渠道过检 |
| Turing / 数美风控 | **低～中（账号侧）** | 可能影响登录/风控分，一般不致「改 so 秒杀进程」；真机观察即可 |
| `libsecsdk` | **低（待动态）** | 静态几乎无校验明文；若装星光异常再动态看 `JNI_OnLoad` |
| ACE / dex·arsc 字节校验 | **未见** | 不必默认走 PCR 外科避 arsc；仍建议 **zip 外科、少动官方 dex** 稳妥 |
