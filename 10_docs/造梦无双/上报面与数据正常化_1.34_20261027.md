## 2. 三处「不正常」与对应修法

| 症状（改前） | 为什么会被盯 | 修法（`Games/ZmwsMod.cpp` splice） |
|---|---|---|
| 秒杀返回 `9999999999999` ⇒ `mUidDamageRecord` 累加到 **1e13 级**，并原样进 `uidDamages` | 单场伤害远超任何真实配装；与怪物血量、击杀数完全不自洽 | **`starry_zmws_nocap`**：在 `mUidDamageRecord` 累加前把单次伤害夹到**目标当前血量**（`-e > 1e6` 才触发，且仅在秒杀开启时）。效果 = 上报伤害恰好等于「正常打死这些怪所需的血量」 |
| 3–10 秒通关 ⇒ `settleTime` / `time` 极小 | 关卡最短通关时间服务端一定有基线 | **`starry_zmws_timepad`**：`gameSettle` 入口把 `mGameTimeSumFrame` / `mGameTimeFrame` / `mGameDealFrameCount` **三个计数器同步**补到最短 90 秒（只改一个反而更矛盾），并把 `mSingleOperaReconrd` 用**空帧补齐**到 `90×30=2700` 帧（空帧＝挂机帧） |
| `killTime`（Boss 击杀时间）1–2 秒 + 总时长 90 秒 | 自相矛盾 | **`starry_zmws_killtime`**：结算时若 `killTime < 总时长×0.7` 则抬到 70%；顺带打一行只读摘要日志供取证 |

最短时长默认 **90 秒**，运行时可用 `window.__starryZmwsMinSettle = 60` 之类改（未做菜单项，避免功能越界）。

### 4.1 两处工具/流程坑（本轮新增，已固化）

1. **注入串括号不配平 ⇒ 整包黑屏**（实锤）：往 18 MB `index.jsc` 插 JS 时多打一个 `}`，整段 eval 抛 SyntaxError ⇒ 引擎不渲染，**而 splice 日志全是成功**。
   修法两件套：
   - 运行期：`Games/ZmwsMod.cpp` 新增 `BracesBalanced()`，7 段注入串逐段自检，**不配平就不注入**（`LOGE ... brace check FAILED`）。
   - 构建期：`04_scripts/造梦无双/zmws_splice_syntax_check.py`——从**已构建的 so** 抠出注入串（`%s`→真实包名），按同一锚点插进**探针明文 index.js**，`node --check` 全量过。改 C++ 必须同步改该脚本的锚点表。
2. **`pre_install_gate.sh` 查5 只查 `classes*.dex`**：so 里的门禁串（`starry_zmws_timepad` 等）走 `--apk` 会假 FAIL。正确姿势是拆两次：
   ```bash
   bash 04_scripts/_common/pre_install_gate.sh --apk <apk>  --needle 'ZmwsHooks' --needle 'get_ret'
   bash 04_scripts/_common/pre_install_gate.sh --dex <so>   --needle 'starry_zmws_timepad' ...
   ```
3. **`post_install_precheck.sh` 的崩溃判定仍会误报** `E libsigchain: Setting SIGSEGV to SIG_DFL`（Dobby 改信号处理器的常态）：判据是「pid 存活 + 该行之后日志继续」，本轮两次都是良性。

## 5. 结论与残余风险（不吹）

- **做得到的**：伤害/时长/Boss 击杀时间/回放帧数四处**互相自洽**，数值落在正常玩家区间；客户端自报作弊（`addCheat`）继续空掉。
- **做不到的**：`frames` 里真实操作只有 1 条（`[1,[162000000]]`）——这是「秒杀挂」最本质的特征，客户端无法伪装成真人操作轨迹；服务端若做**输入回放重放对账**，仍可能复现不出同样的击杀顺序。
- **服务端阈值不可见**：本版客户端自检 `calcLogic` 已是空桩，判定完全在服务端，只能靠「数据自洽 + 时长合理」降风险，**不保证不封**。
- 若要进一步降风险，可选项（未实现，需用户点名）：① 关掉秒杀只用无敌+技能（伤害轨迹完全真实）；② 把最短时长抬到该关卡的真实平均通关时间（需按 stageId 统计）。
