## 2. SecShell 整体校验与分体结论

### 2.1 AB 矩阵

每次只改一处，安装后启动，观察启动约 1 秒时的结果：

| 改动 | 结果 |
|---|---|
| 只重签，非 `META-INF` 载荷不动 | 通过，能进入 Unity 启动链 |
| 新增 `assets/zzz_test.txt` | `SIGBUS` |
| 新增 `classes2.dex` | `SIGBUS` |
| 新增 `lib/arm64-v8a/libstarry_magic.so` | `SIGBUS` |
| 向 `assets/classes0.jar` 追加 16 字节 | `SIGBUS` |
| 向 `lib/arm64-v8a/libSecShell.so` 追加 12 字节 | `SIGBUS` |

崩溃形态：`signal 7 (SIGBUS)`、`BUS_ADRALN`、`fault addr 0xa01`、`pc=0xa01`、`sp=0`、`lr=0`，崩溃线程名等于进程名，地址落在 `libSecShell.so` 的运行时解密段。结论是 SecShell 校验的是 base 的非 `META-INF` 整体载荷，不是只校验单个官方 so。

### 2.2 分体方案

- `base.apk`：官方包只重签，非 `META-INF` 条目逐字节不变，并通过构建脚本硬校验。
- `split_starry.apk`：承载星光 `classes.dex`、`libstarry_magic.so`、`libc++_shared.so`、`assets/certs/starlight.crt`，以及 `StarryInitProvider` / `MenuService` 的 split Manifest。
- base 与 split 同签名安装，ART 将 split dex 合并进同一应用 classloader，native 库也进入同一应用库路径，Provider / Service 由合并清单拉起。
- split 中星光 dex 为 455,816 B；包含 `StarryInitProvider`、`MenuService`、`SignSpoof`、`TapLoginForceWeb` 和 `com.qxjc.hxwjmlq` 两张白名单/证书表。
- 官方 `classes.dex`、`resources.arsc`、`libil2cpp.so` 在 base 中保持原样。

## 3. 地址坐标系与玩法锚点

ELF LOAD 实测 **`VirtAddr = FileOffset + 0x4000`**；运行时地址 = `dl_iterate_phdr` 的 `dlpi_addr + dump.cs RVA`。不能用 `/proc/self/maps` 的文件偏移直接当 RVA。

| 方法 | RVA | 序言 | 用途 |
|---|---|---|---|
| `FightGwItem::AttackDamage` | `0x1A733C8` | `0xD10143FF` | 秒杀 |
| `FightGwItem::AttackDamageOnce` | `0x1A756B8` | `0xF81D0FFE` | 秒杀 |
| `FightGwItem::SkillDamage` | `0x1A7695C` | `0xD10183FF` | 秒杀 |
| `UnityEngine.Random::Range(int,int)` | `0x35BD284` | `0xA9BE57FE` | 掉落 |
| `ToponVideo::showAd` | `0x1A91F08` | `0xA9BE57FE` | 免广告 |
| `ToponVideo::isReady` | `0x1A91FA0` | `0xA9BE57FE` | 免广告 |
| `ToponVideo::onReward` | `0x1A923EC` | `0xF81C0FFE` | 免广告 |

关键字段（dump.cs 实测）：`FightGwItem`（TypeDefIndex 3495）`useZbGwInfo@0x30`、`fightType@0x64`；`XxGwInfo` `curHp@0x80`、`hp@0x84`；`FightType` player=1 / gw=2；`ToponVideo` `topon_video_id_CSJ@0x20`、`topon_video_id_TX@0x28`；`ATAdEventArgs` `placementId@0x10`。

方法签名实测：`FightGwItem::AttackDamageOnce(FightGwItem xxOtherGw)` ⇒ `self` = 被打者（victim），`xxOtherGw` = 攻击者（attacker）。

## 4. 三功能实现

### 4.1 秒杀（`HXWJ_FEAT_DMG`）

Hook `AttackDamage` / `AttackDamageOnce` / `SkillDamage`。命中「attacker.fightType==player && victim.fightType==gw」时把 `victim.useZbGwInfo.curHp` 写成 **1**，随后调 orig。

- **为什么写 1 不写 0**：反汇编 `AttackDamageOnce` 尾段是「`curHp<=0` 才走 `showGwInfoHp(0)`」；若先写 0，原函数在序言早退，反而跳过官方死亡/结算链。写 1 后原函数继续执行，任何 ≥1 的伤害都会把 `curHp` 钳到 ≤0 并走完整死亡路径。
- 仅写 player→gw 方向，不做 gw→player，避免玩家被秒。
- 仅在 `curHp>1` 时写，避免残血重复触发。

### 4.2 百分百掉落（`HXWJ_FEAT_DROP`）

Hook `UnityEngine.Random::Range(int,int)`，仅当调用方返回地址落在 `GetSuccessWuPing` 的 5 个白名单内时返回下界 0：

| 返回地址 | 调用点 |
|---|---|
| `0x1A7C3A4` | 主权重池 `Range(0,100000)`，`weight > rand` 必中首个正权重候选 |
| `0x1A7D634` | `Range(0,10000)`，结果当前反汇编未见使用 |
| `0x1A7D714` | `Range(0,10000)`，`rand > 99` 跳过 ⇒ 返回 0 必过 |
| `0x1A7DDB0` | `Range(0,1000)`，难度相关闸门 |
| `0x1A7E94C` | 第二权重池 `Range(0,100000)`，同上必中 |

其余所有 `Random.Range` 全部放行。**边界说明**：本实现只保证「配置中非零概率的候选必中」，不伪造权重 0 条目，也不保证主池所有候选全部发放（与先例一致）。

### 4.3 免广告（`HXWJ_FEAT_AD`）

- `ToponVideo::isReady` 命中即返回 `true`。
- `ToponVideo::showAd` 命中时不调 orig（不拉起真实广告 SDK），改为构造栈上假 `ATAdEventArgs`（`klass = object_class(placement)`、`placement@0x10` 填 `topon_video_id_TX` 或 `_CSJ`），直接调官方 `ToponVideo::onReward` 走官方发奖链。
- `onReward` 实测只读 `erg+0x10`（placementId 字符串）并与 `self+0x20/+0x28` 比对，假 event 生命周期覆盖该读取路径。

## 5. 去签名与强制网页登录

- **去签名**：`SignSpoof` 加入 `HXWJ_PKG="com.qxjc.hxwjmlq"` + 官方证书 `HXWJ_CERT_B64`（回灌 `CN=sy` 证书）。纯重签的 `CheckSignature()` 失败路径和回灌后继续路径都已在旧分体组合中实测；最终安装 pair 因未启动，未重新采集该证据。
- **强制网页登录**：`TapLoginForceWeb` 的 `PKG_WHITELIST` 加入 `com.qxjc.hxwjmlq`。本作与凡尘西游修真记同为 TapSDK 新版路径（`TapTapLoginActivity` + `LoginRequest` + `LoginTypes$WEB`），现有 `sanitize()` / 新版反射路径可复用。最终包已由用户实机进入游戏并确认功能可用，判定通过；未单独保存登录页日志。
- 两张表（SignSpoof 证书表 + TapLoginForceWeb 白名单）在 surgical / build_split 脚本内均有硬门禁校验。
