## 4. 架构层根因（非猜测，来自静态分析 + 技能文档）

| 层级 | 事实 | 对 Mod 的影响 |
|---|---|---|
| 战斗逻辑 | `luagame.assetpkg`（RSA 签名 Lua），非 IL2CPP 导出类 | C# `BattleDamageMono.ShowDamage` **仅飘字**，hook 无效 |
| 网络 | `HjTcpNetwork` TCP 服务端权威 | 即使本地 Lua 改伤害，**结算可能被服务端回滚** |
| xLua 环境 | 禁止 `lua_setglobal` 写 `_G`；须 `xlua_setglobal` / `declare` | C++ 写 `STARRY_AN_*` OK；Lua 脚本内不能写 `_G` |
| 成功先例 | `Match2Mod`：等 `CFightSystem` 就绪 + **具名函数** patch | 当前 `ZmxsMod` **泛化扫描**不符合 `skill/SKILL.md`「数据先于行动」 |

**结论：当前实现属于「未 Trace 的猜测式 wrap」，不是「证实挂点后的精确 patch」。**

## 9. 2026-08-25 14:55 无敌终测 + 架构定稿

用户反馈（无敌开 30 分钟）：
- 血条可满、可走动、不弹复活
- **无法攻击**；怪停手；数秒后战斗自动结束  
→ 服务端已判死，客户端只是挡了复活 UI / 本地血条。**客户端无敌 FAILED（假活）**

架构（dump 实锤，非猜测）：

```
客户端放技能 → gModule.Game:sendAttack(skillId, pos, targets)
     ↓  HjTcpNetwork 上传「我放了什么/打谁」
服务端算伤害/死亡/胜负
     ↓  下发 CMD_HIT / HP 包 / CMD / 结算
客户端 onHpMpChange / handleHurt / execDie  → 只做表现
```

本地 **没有** 权威伤害结算；`handleHurt`/`HeroDamage` 是飘字与受击表现。  
挂 `onHpMpChange` 只改 UI，方法对表现层是对的，对「真无敌/真秒杀」方向错了。

真要生效：协议层（伪造/改写结算包或攻击结果）——成本高、有封号风险，需你明确授权再开。
