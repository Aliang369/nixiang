## 1. 网络栈（C# / IL2CPP）

命名空间：`YF.Net`

```
HjNetworkBase (abstract)
  ReceivePkgHandle : Action<byte[]>   // 收包回调（Lua 可挂）
  SendMessage(byte[] msgObj)          // 发包（虚方法，基类空实现）
  DoReceive(...)                      // 粘包拆包
  mMaxBytesOnceSent / 接收缓冲很大（~0.5MB / 数 MB）

HjTcpNetwork : HjNetworkBase
  独立发送线程 + 信号量队列
  ReverseBytes(ushort/uint/ulong)     // 长度/字段端序处理 → 有多字节头
  override DoReceive / SendMessage
```

xLua 包装：`YFNetHjTcpNetworkWrap`（Lua 侧可 `new` / `SendMessage` / 设 `ReceivePkgHandle`）。

**含义**：C# 只做「套接字 + 粘包 + 把 byte[] 交给 Lua」。  
**协议号、字段、伤害数值不在 C# 业务类里**（至少 dump 未见 protobuf/FlatBuffers 战斗 Msg）。

## 2. 战斗上行（已有 Lua 实锤）

```lua
-- SkillManager:handleCast
gModule.Game:sendAttack(skillId, selfPosition, {
  {paramType, param},
  {paramType3, param3}
})
```

上传内容语义：

- 技能 ID（普攻也是 skillId）
- 自身位置
- 目标/方向类参数  

**不是** `damage=99999`。

组好的二进制最终应进 `HjTcpNetwork:SendMessage(bytes)`（具体 Lua 封装名待 dump `Game`/`Net` 模块确认）。

## 3. 战斗下行（已有 Lua 实锤）

服务器 → 客户端指令/同步，例如：

| 下行 | 客户端动作 |
|---|---|
| HP 包 | `onHpMpChange` → `setCurHp(data.curHP)` |
| `CMD_HIT` | 受击表现 |
| `CMD_DIE` | `changeStateDie` / `execDie` |
| 属性包 | `onAttrChange` → `setAttrArray(objprops)` |

本地改这些 = 改显示器；服务器记分牌不变。

## 4. 加密相关（静态）

`CRYPTO.Crypto`（`[LuaCallCSharp]`）：

- `aesEncode` / `aesDecode`（字符串）
- `AesEncryptECB` / `AesDecryptECB`（字节）
- `encryptXXTEA`
- `md5`

→ **Lua 有能力对消息体做 AES/XXTEA**。  
是否对战斗 TCP 包启用：**本阶段未抓流量，不能下结论**。

另有 `libEncryptorP.so`（README：AppLog），**不宜当作战斗协议加密证据**。

## 5. 协议层若继续，三条路与预期效果

| 路线 | 做法（概念） | 预期效果 | 现状判断 |
|---|---|---|---|
| A 改下行 HP/DIE | hook `ReceivePkgHandle` 改字节或吞 DIE | 假满血/不弹复活 | **已证不够**（不能攻击、战斗结束） |
| B 改上行 Attack | 改 skillId/目标 | 通常无效（伤害在服） | **已证无效方向** |
| C 找协议漏洞 | 重复包、缺校验、客户端字段被服信任等 | 才可能真效果 | **未知，需抓包+对照** |

只读下一阶段目标：**把 C 的「未知」变成「有洞 / 无洞」**，而不是直接做 A/B。
