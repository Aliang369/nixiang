# 弓箭传说2 功能失效根因诊断（2026-08-30）

> 📍 `10_docs/弓箭传说2/诊断_失效根因_20260830.md`
> 🎯 回答两个问题：① 问题到底是什么；② 为什么 8-17 生效的方案现在不行了。
> 证据来自：`功能排查_20260830.md`、`斌哥功能对照_20260817.md`、`Archero2Mod.cpp`（starry-mod-menu 仓库）、`version-update-relocate.md` 阶段 D。

## 一句话结论

最开始的方案没"坏"，是**游戏在你 8-30 全新安装时重新下载了一个 HotFixBattle.dll 热更（3923 类）**，把"授予技能"和"扣血/伤害"两条调用链**整体换到了别的方法上**。

你 8-17 的挂点 `AddSkillToCharacter` / `UpdateHp` 符号还在、hook 装得上、但**一次都不被调用（hits=0）**——所以两个功能静默失效，**不报错也不崩**。隐身挂在 `SetTarget`/`TrySetTarget` 上，这条链热更没动，所以还活着。

## 调用链对照（铁证）

| 功能 | 8-17 落地挂点（已死） | 8-30 热更实际路径（现役） | 状态 |
|------|----------------------|--------------------------|------|
| 偷技能 | `BattleWorldContext.AddSkillToCharacter(entity,id,addToComponent)` | `HeroComponentRandomSkill.AddSkill(this, int id, c=静态指针, d=0)`（重载2） | ❌ 旧 0 命中 / ✅ 新 hits>0 |

| 隐身 | `SetTarget`/`TrySetTarget` 过滤英雄 | 同左（热更未动） | ✅ 仍命中 |

## 为什么 8-17 生效、现在不行

- HybridCLR 热更是 **C# 层重新分发**，native `libil2cpp.so` 里的旧方法符号**没被删除**。
- 于是 `FindClass`→`GetMethod`→`MethodPointer`→`DobbyHook` 全程成功（无 "method missing"、无崩溃），但运行时走的是**新链** → 旧钩 **0 命中**。
- 这正好命中 `version-update-relocate.md` **阶段 D**：不是"偏移搬迁"，而是"路径变了"。旧方法名还在，所以比单纯 offset 漂移更隐蔽——你看着 hook 装成功了，功能却没动静。

## 为什么修了 5 小时没修好（关键陷阱）

不是"找不到新挂点"——你的 diag2–23 早就把新链钉死了（`PushHurtDataArray`、`AddSkill` 重载2 都 `hits>0`，probe7/probe11 就是为它们建的）。

问题在 **`Archero2Mod.cpp` 真正干活的钩子至今还钩在旧方法上**：

- `Hooked_AddSkillToCharacter` / `Hooked_UpdateHp` 仍绑定 `AddSkillToCharacter` / `UpdateHp`（死链）。
- `probe7` / `probe11` 只是在"看"新链、**没接进功能逻辑**。
- 中间你拐去试 `GMAddSkillCommand`（需命令管理器注册，裸对象调用被忽略）、Dictionary 直写（hash 算法未知）——都是在绕，没回到"**把功能钩子改指到新方法**"这条主干。

> 即：诊断数据（doc）和落地代码（cpp）脱节了。文档里说"新链在这"，代码里还钩着旧链。

## 更深的坑（偷技能专属）

新授予点 `AddSkill(this, id, c, d)` 有**内部状态机 / 三选一 pending 前置**：非选中 id 补授会被拒（新局静默无效、恢复局崩）。

所以即使把钩子挪到 `AddSkill`，**也不能像 8-17 那样"对其它候选 id 再调一次 AddSkillToCharacter"**——8-17 那个方法是无条件的，新这个不是。偷技能必须换思路（改 pending 候选数组 / `AddPlayerSkill` 签名验证 / 直写 `_skills` Dictionary 且先在选中 Entry 上只读验证）。

## 修复路线

1. **全屏（低阻）**：把 `Hooked_UpdateHp` 整段逻辑迁到新伤害通道——钩 `PushHurtDataArray(a=GameProxy, b=伤害对象)`，在 `b` 上识别目标怪物集合 + HP 字段，对其它怪物 push 同类伤害。probe7 已验证该链活、b 结构已在 dump 中。
2. **偷技能（高阻）**：先别急着直写 Dictionary。优先验证「同一三选一事务内、对其它候选 id 调 orig AddSkill 是否被状态机放通」；不放通则退 `AddPlayerSkill` 签名验证或 `_skills` Dictionary 直写（hash 先破译，先在选中 Entry 上只读验证）。
3. **构建红线**：确认从 `starry-mod-menu`（非 `_111`）出包，mk 为 `STARRY_GAME_GJC2`；`starry-mod-menu_111` 的 `Android.mk` 当前停在 `STARRY_GAME_SELF`/`Main.cpp`，若从那构建 gjc2 代码**根本没编进去**（`gjc2_so_only.sh` 有 grep 校验会拦，surgical 脚本不一定拦）。
