## 二、8-30 热更换链全景（运行时枚举实锤）

- 伤害：旧 `EntityCharacter.UpdateHp/ChangeHp/BeforeHurtTarget` 全 0 命中（方法还在、无人调用）；**`PushHurtDataArray` 是确定性帧管线**（FrameData/DeterministicAnimationEvent/LlcResponse），不是伤害通道——全屏最初挂它=方向错误
- 每实体伤害核心：`CharacterComponentOnHit`（OnHitByBullet / CheckHurt / OnHitUpdateHP / CheckDying）
- EC 直接持 `CurrentHp:Int64`（f[13]），组件：OnHitCom/TriggerCom/_shield/AIStateController
- 技能授予：现役 `HRS.AddSkill(Int32)`（m[10]，带状态机门）；`AddSkill(Skill_Main)`（m[11]）真实授予时不被调用；`BWC.AddSkillToCharacter(EntityCharacter,Int32,Boolean)` = 无门直授原语（m[246]）
- 候选源：普通三选一 = `RandomSkillResult.get_ShowSkills`（展示期调用，orig 后数组被清空）；继续局选择不走 getter → 直读 `RSR.<ShowSkills>k__BackingField` 数组；女武神 = `BoxSkillResult.SkillId1/SkillId2` 或 HRS 组件 +0x5c/0x60 相邻字段；天使 = 技能包结构（未破解）
- `_skills` = **OrderedDictionary\`2**（非普通 Dictionary——8-30 hash 破译失败的结构性原因）

## 三、铁律（本游戏实证，普适）

1. **解释器方法合成调用必须完整重放实参寄存器**：HybridCLR 桩签名 = (this, params..., MethodInfo*, ...)。只传声明参数 → x2+ 为垃圾 → 解释器崩（tombstone_03 fault 0x70）/静默 no-op（GM Exec）。正确姿势=宽签名 8 参透传，只换目标槽位
2. **热路径钩子群=卡死源**：26 探针钩（含 8 万次/局热方法）叠加恢复局窗口 → 命令系统停摆。钩子总量控制在个位数，探针用完即拆
3. **回填写堆对象前必须确认对象存活**：向疑似被 GC 回收/替换的数组写入 → 堆损坏 → 迟发卡死（第 17 轮）
4. **跨对局对象过期**：g_lastHero/g_worldCtx 缓存必须绑定实例或按类名校验，新对局的英雄是新建的（tombstone_04）
5. **继续局选择不走 get_ShowSkills**：候选直读 `RSR.ShowSkills` 数组（FieldOffset 解析 `<ShowSkills>k__BackingField`）
6. **首次三选一早于首次索敌**：英雄从 AddSkill 的 `a`（HRS 组件）反查（0x10~0x60 扫 Hero 类对象），不依赖 SetTarget 先发生
7. 诊断落盘文件（`/data/data/<pkg>/files/gjc2_tables.txt`、`gjc2_steal_log.txt`）——logcat 缓冲 ~2 分钟即轮转，一次性普查必须走文件
