## 4. 客户端反作弊（重要）

均在 `main/index.js` 内，**会直接影响“改战斗是否有用”**：

1. **`BattleIntegrityGuard`**  
   - 给怪物打影子快照（hp/atk/def/skills/attributes/`damage_adjustment` 等）  
   - 后台轮询校验；篡改则**回滚影子值**，标记 `_battleCompromised`，**锁定本局结算**  
   - 杀怪上报前 `canReportMonsterDeath` 再校验  

2. **`SpeedHackDetector`**  
   - 对比 performance/Date 墙钟与游戏 dt；窗口比率 >1.25 等 → 限速并可将 `_battleCompromised=true`  
   - `enabled=true` 默开  

3. **`SdkRewardAdGuard` + `AdSkipService`**  
   - 激励广告统一入口；免广告走特权 `privilege id=1` 或道具 `base_id=110002`（发 `c2s_use_item`）  

4. **结算权威在服务端**  
   - `BattleProtoHandler`：`s2c_main_stage_reward` / 杀怪奖励 list / 双倍奖励等  
   - 本地改掉血若不同步协议，最多本地好看，奖励仍看服务器

## 6. 可实现功能（优先级建议）

### 建议优先（客户端可控、收益稳）

| 功能 | 可行性 | 路径 | 风险 |
|------|--------|------|------|
| 星光悬浮菜单落地 | 高 | 外科注入 + Cocos evalString | 低 |
| 永久免广告 / 广告领奖直领 | 高 | `AdSkipService` 恒 true，或激励回调伪造成功 | 中（广告任务可能服务端计数） |
| 关闭插屏等 | 高 | `InterstitialAdService` | 低 |
| 本地 UI 倍速（表现） | 中高 | 先关 `SpeedHackDetector` 再改 `timeScale` | 中（仍可能被协议侧察觉） |
| 自动战斗辅助增强 | 中 | 已有 `AutoBattleService`，可扩一键穿装/分解 | 低–中 |

### 可做但必须过 Integrity + 结算（中等）

| 功能 | 可行性 | 条件 |
|------|--------|------|
| 秒杀 / 高伤 | 中 | 改伤害链路 + **短路/同步** `BattleIntegrityGuard` + 验证杀怪协议仍 `ret` 成功 |
| 无敌 / 锁血 | 中 | 改玩家 `HealthComponent`；注意服务端是否校验受伤 |
| 弱化怪 / 改波次 | 中 | 改 `base_monster`/`base_waves` 或生成时属性，并避免触发影子校验 |
| 掉落展示增强 | 中低 | 本地 `DropItemSpawner`/`BattleRewardCollector` 只影响表现，真奖励看 `s2c_*` |

### 不建议当目标 / 很难持久（服务端权威）

| 功能 | 说明 |
|------|------|
| 直接加钻石/金币/背包装备 | 玩家数据经 `PlayerProtoHandler` / pref，服务端权威 |
| 竞技场排名、矿场排行、邮件福利直领 | 强联网 |
| 伪造通关领奖不打怪 | `BattleIntegrityGuard` + 结算协议双重拦 |
| 无脑全局加速挂机 | `SpeedHackDetector` 会锁局 |

## 7. “能不能改”一句话

**能改，且适合星光 + Cocos JS hook 落地。**  
无 ACE/加固，包体可外科组装；玩法在明文 JS，挂点清晰。  
真正难点不在壳，而在 **`BattleIntegrityGuard` + `SpeedHackDetector` + 服务端奖励协议**：战斗类外挂必须“改伤害/属性 ↔ 同步影子或禁校验 ↔ 验证结算”，经济类以广告/特权类功能更稳。
