## 三、偏离与不确定（不隐藏）

1. **`num` 符号约定未静态确证**：按「负值＝掉血」实现（`changeHp` 返回 float，`nowHp+=num` 推断）。若实测「无敌挡不住/倍率无效果」，说明符号相反，改判入口在 `Hook_ChangeHp` 的 `applied < 0` 两处；日志 `无敌 @rva 生效：hero hp=…` 会给出实际收到的 `num`。

## 五、资源按钮崩溃与「主线程泵」修复（2026-11-02 23:36 实测）

**现象**：无敌 / 伤害倍率 / 加速正常；点 **金币 / 钻石 / 体力 → 游戏重启**（进程死）。
**证据**：`logcat -b crash` 三条 —— `Fatal signal 11 (SIGSEGV), code 1 (SEGV_MAPERR), fault addr 0xb8`，时间 23:35:28 / 23:35:43 / 23:35:59（正好三次点击，每次一个新 pid）；同时 `install pass: 2/2 hooks`、两个战斗 hook 已挂（所以不是 hook 的问题）。tombstone 未落盘（`/data/tombstones` 最新仍是 10-31 的 dex2oat），只能靠 addr=0xb8（空基址+字段偏移）与「只在按钮路径出现」定因。
**根因**：资源按钮在执行时跑在**菜单 Tick 线程**（非 Unity 主线程），`changePlayer*` 内部触达 Unity/UI 侧状态 ⇒ 非主线程直调 IL2CPP 必然崩。对照：修仙2 也是「`GameMgr::Update` 里排空动作队列」才稳。
**修复**：加**常驻主线程泵** —— hook `Root::Update`（`Root : MonoBehaviour`，RVA `0x115D364`，每帧 Unity 主线程）：
- 按钮点击只入队（`g_pendingAction`），`Hook_RootUpdate` 里排空并执行 `changePlayer*`，然后 `orig` 必调；
- Tick 里**不再**执行按钮（并加注释钉死，防回退）；
- 泵在 `TryInit` / Tick 兜底时无条件安装（与开关无关），失败只记日志降级。
**产物**：so `8e7abc13b20e545cedbd361754cb13dc`（191,096 B）、包 md5 `4ea197cea74c1f3e86eef6d9cf1f8602`；**覆盖安装**（无 `--clean`，登录态保留）。
**待实测**：三个资源按钮是否不再重启、数值是否上涨。
