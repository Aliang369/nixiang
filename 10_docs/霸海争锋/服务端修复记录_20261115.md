## 一、问题与根因（实测）
- 现象：霸海争锋 7 日活跃 375、全站今日活跃 1170+、游客 660+，远超「自己测试 + 一个人使用」。
- 根因 1：看板「活跃」是**设备数**（`online_presence` 按 device_id 去重），「游客」只是 `card_id IS NULL` 的行，不是人数。
- 根因 2：`GET /v1/bootstrap` 公开无鉴权且**不校验 device_id 形态**，任何请求带 device_id 即写一行 presence。2026-11-15 19:49 单分钟写入 327 条。
- 根因 3：375 台中 **357 台（95.2%）device_id 是 SQL 注入载荷**（含 `'` `(` `)` `;` 或 sleep/union/generate_series 等词，长度 4–127）；客户端只可能产出 `^dev_[0-9a-f]{32}$` 或 `{40}`，故必然非客户端产生。
- 真实规模：375 中符合客户端格式仅 3 台（含机主自测机）；卡密许可证 2 张。
- 附带发现：`auth_events.detail` 长期写入**明文卡密**（813,443 条）；`admin_audit_logs` 删除卡密时也写明文（72 条）。

## 二、代码修复（metrics-code-reviewer，已冻结）
- bootstrap 非法 device_id：不写 presence、仍返回 200（旧包不断服），记 `bootstrap_reject` 事件（device 指纹化 `bad_<sha256前12>`）。
- `touch_presence` 三条纪律：只收合法 device_id；只有认证过的调用才写 card_id/card_verified_at；任何地方不清 card_id 表示游客。
- 事件审计扩列：`result/reason/ip/ip_forwarded/ua/request_id/suppressed/last_occurred_at` + `X-Request-Id` 中间件（服务端生成，不接受客户端伪造）。
- `detail` 不再写卡密（改 `card#<id>`）；删除卡密审计只记 `ID=`。
- 代理可信：nginx `X-Forwarded-For $remote_addr`（覆盖）、uvicorn `--no-proxy-headers`、应用层 `TRUSTED_PROXY_IPS` + `X-Real-IP`。
- 测试：新增 17 项 + 旧回归 24 项全绿；`preflight` 19 项 PASS。

## 九、游客统计根治 + 设备日志 UI 完善（2026-11-16 00:44）

### 9.1 方案（两层，均不改 APK）
- **需卡游戏**：`GET /v1/bootstrap` 只返回配置、**不再写 `online_presence`**（`auth_service.bootstrap_with_grant` 里 `open_mode = not card_auth_enabled` 才写）。活跃只认 `login` 成功 / 带 token 的 `heartbeat` 成功。
- **新增 durable 字段** `online_presence.last_authenticated_at`：服务端认证通过时写 `now()`；**解绑/撤销不清**（与 `card_verified_at` 的关键区别）。
- **免卡游戏**（当前 0 个）：保留 bootstrap 的 `last_seen` 观察值，明确标注不可信；将来若要匿名可信采集需客户端 guest session，属另案。

### 9.2 历史回填
- 三源 `GREATEST(当前值, card_verified_at(<=now), max(login_ok))`，NULL 用 `-infinity` 哨兵；`WHERE best > cur` 保证**不倒退、幂等**；只采已登记 `game_id` + 合法 device 形态；`created_at <= now()` future guard。
- 采样（**三次独立查询，非原子**）：pre `with_auth=3`；changed `UPDATE 7030`；post `with_auth=7044`、`unknown=2698`、`total=9742`、`future=0`。差额 11 为期间新并发认证，**不可由 3+7030 直接推得**。
- **第二/三遍 UPDATE 0**（幂等）。
- 集合区分：`with_auth=7044` 是**全表**计数；下文「历史有认证 3949」是**已登记 game_id + 合法 shape + 需卡游戏**过滤后的不同集合，两者不可互相印证。
- 并发说明：第二遍断言曾触发 RAISE。根因是 `now()` 返回**事务开始快照**，事务期间新写入的 heartbeat 时间戳相对该快照「看似未来」，并非数据脏。已改用 `clock_timestamp()`（真实当前时刻）+ `+5s` 容差；UPDATE 当时已为 0，回滚无副作用。
