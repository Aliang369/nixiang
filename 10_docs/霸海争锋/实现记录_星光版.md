# 霸海争锋 1.1.036 星光版实现记录（无敌 / 秒杀）

> 状态：**b8 已装机、机器预检通过、效果未验证**。唯一写者：game-executor。

## 一、路线

HybridCLR 热更（玩法在 `mygame` 程序集，解释执行）⇒ 不走 native 方法 hook，走**离线 IL 补丁 + 程序集加载边界换字节**：

1. Cecil 补丁 `Battle.Life::AddHP(JInt,Life,int)`（`04_scripts/霸海争锋/ilpatch/`）。
2. native 在 `System.Reflection.Assembly.Load(byte[])` 边界按 **sha256 白名单**替换为补丁体（`Games/BhzfMod.cpp`）。
3. 开关通道 = ini 文件（native 写 / C# 读，同一路径 `/data/user/0/com.bhzf.zbml/files/starry_config.ini`）。

## 二、补丁语义

| 功能 | 补丁 | 条件 |
|---|---|---|
| 无敌 | `AddHP` 入口早退 | `god=1` 且 `value<0` 且 `victim.GetPlayer().GetCamp()==FRIEND(1)` |
| 秒杀 | `value = -(int)victim._curHP - 1` | `kill=1` 且 `value<0` 且 `CampOf==ENEMY(0)` |

- `CampOf` 空/未初始化返回 -1 ⇒ 两个功能都不触发（fail-safe，走原逻辑）。
- 只作用于负向扣血；治疗（value>0）永不改。
- 无敌为**早退**，会跳过 `_curHP` 写入与 HPValue 记录（:2416）与 `OnLifeHPChange`，属已知副作用。
- 秒杀走正常伤害/死亡流程，但 `Deification`/`ProhibitReceiveDamageAndCure`/`DESPERATION_STATE`（保 1 HP）/护盾等守卫**不保证一击必死**。

## 七、真机失败与修复（b5/b7 → b8）

| build | 事件 | 结果 |
|---|---|---|
| b5 | 首次装机，god=1 实测 | 用户反馈「双方都不掉血」，功能无效 |
| b7 | 仅加诊断（BhzfDbg/原值 long） | 用户反馈「没开任何功能也双方无伤」⇒ 默认路径被破坏的强证据 |
| b8 | 修 4 个已证静态缺陷后覆盖安装 | 安装 Success、precheck EXIT=0/PASS_TO_HUMAN、换字节命中 81f79639；**效果未验证** |

已修静态缺陷（均为代码/引用级实证，非效果推断）：
1. 补丁器用 `typeof(...)` 导入 net10 类型 ⇒ 产物新增 `System.Private.CoreLib` AssemblyRef（目标 Unity 只有 mscorlib）⇒ 改为按 `_mod.TypeSystem.CoreLibrary` 手建引用；现 AssemblyRef 31 条与原集合一致、无 CoreLib。
2. 全关时仍无条件做 `(int)value → JInt` 往返 ⇒ 改为 `AllOff()` 直接跳原方法首条，**零 JInt 读写/转换/无 starg**。
3. helper 返回值丢失、`Incompatible stack heights 0 vs 1` ⇒ 改为 retVal 局部 + leave 单一出口，告警计数 0。
4. 秒杀构造失败回落 default JInt(0) 会覆盖原值 ⇒ 改为 `TryAdjust(self,value,launcher,out adjusted)` 返回 bool，**仅成功才 starg，失败保留原 value**。

仍未验证：战斗内双方是否恢复掉血、无敌仅己方、秒杀仅敌方、开关即时生效、后台 game_id 全功能。**不再请求用户第三次配合**。

## 九、原方法体对照（Cecil compare，b8 rc）

- 工具：`04_scripts/霸海争锋/verification/compare/`（独立 csproj，只读；按签名 `Battle.Life::AddHP(JInt,Life,int32)->void` 精确匹配）。
- dev：`mygame_runtime.dll`(f44f75b8) 245 IL / locals 6 / EH 0 → `rc_b8 dev`(81f79639) 261 IL / locals 7 / EH 0；自动推定 prefix=16；去前缀 245==245，op/operand/branch 差异均 0。
- base：`mygame_baseline.dll`(e58aa7ef) 245 → `rc_b8 base`(7f2d3811) 261；同上，差异 0。
- 结构结论（**限定**）：原 `AddHP` 的**指令后缀/locals 前缀/EH 结构**在补丁后保持一致；新增内容仅“16 条前缀 + 1 个 `JInt` out 局部(index 6)”。
- **不等同**默认行为 100% 等同：`AllOff()` 仍要读配置（1s 缓存，失败 fail-open 走原逻辑），运行期语义仍需实测；本条只覆盖结构层面。
- 证据：`09_test/霸海争锋/offline_b8/compare_body_dev.txt`、`compare_body_base.txt`（及同目录两份 MemberRef 报告）。
- **工具限度（归档必读）**：① 前缀 16 是 `patched−original` 的 pure-length 推定，工具**不校验前缀内容**（前缀内容另由文本对照确认：AllOff/brtrue/BlockGod/brfalse/ret/nop/ldarg.0-2/ldloca.s 6/TryAdjust/brfalse/ldloc.s 6/starg.s value）；② **MaxStack / InitLocals 未参与比较**；③ opcode 归一化刻意抹平 short/long 分支差异，分支长度变化不会出现在计数里；④ 两版 EH 均为 0，EH 映射逻辑本次未被实际用例覆盖。
- **MaxStack / InitLocals（本次补测，只读）**：两组均为 original `maxstack=8 / initlocals=True` → patched `maxstack=8 / initlocals=True`（Cecil 直接读 `MethodBody.MaxStackSize/InitLocals`）；即补丁未降低栈额度、`initlocals` 未翻转。仍未做运行时栈峰值校验，仅记录同名数值相等这一事实。
