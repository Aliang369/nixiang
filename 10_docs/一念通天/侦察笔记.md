## 收官期发现的状态机/脚本卫生缺陷（2026-10-12）

- `04_scripts/一念通天/pipeline.json` 的**陈旧哈希**：`pull_official.artifacts[official_apk.json]=910fa724…`（739 时代）与 `dump_official.inputs[official_apk.json]=82621adb…` 均 ≠ 现状 `cd5c5ac12cdd8d9c541920c93d58b28b`（747）。后果＝`run archive` 被 `check_stale` 拦死：`dump_official: 上游产物已变化 04_scripts/一念通天/official_apk.json`。根因＝今天 01:31 用 `fetch_installed_official_yntt.sh` 重写了该 json，但没刷新对应阶段记录。**教训：任何「重跑上游脚本但走的是脚本直调、没走 `pipeline.sh run`」的动作，都会留下陈旧 inputs/artifacts 快照，收尾前必须全表核对。**
- **产物记录指向已不存在文件**：`dump_static.artifacts` 指 `binge_719/il2cpp_dump/dump.cs|script.json`（2026-09-28 起被 `.gitignore` + 已清理）、`surgical.artifacts` 指本轮裁剪掉的 `-unsigned.apk`、`build_so.artifacts` 指本轮删除的 `libs_yntt/arm64-v8a/libstarry_magic.so` ⇒ `verify <阶段>` 假报「产物指纹变化（读取失败）」。处理＝删除这些记录（产物已按设计清理），并把 `dump_static.verify` 从已消失的 `dump.cs/script.json` 改指现存 `binge_719|official_720|official_728/static/summary.txt`。
- `04_scripts/一念通天/archive_yntt_747.sh` 的**静默死**：`CUR_DIFF="$(git diff --cached … | grep -E '^[+-]' | grep -vE '^(\+\+\+|---)')"`，当「本无本行暂存内容」时 grep 无匹配返回 1，配合 `set -euo pipefail` 让赋值语句直接失败 ⇒ `rc=1` 且**零输出**（pipeline.log 里只有「命令失败 rc=1」）。修复＝管道尾加 `|| true`，并把 `10_docs/_state/current.md` 纳入 `git add` 清单（该文件仅本作一行变更，随后由「暂存行必须全部含『一念通天』」守卫复核）。

## 待修的共享脚本缺陷（留证据，不擅改）

- `04_scripts/_common/pre_install_gate.sh` 的 `dex_literal_count`：未强制 `LC_ALL=C`。macOS BSD grep 在 `C.UTF-8` 下对二进制文件里的多字节字面量匹配失败（`grep -c -F -a -- 'Toggle_秒杀' libstarry_magic.so` → 默认 **0**，`LC_ALL=C` → **1**）。
  - 规避：调用时前置 `LC_ALL=C`。
  - 建议修复：在 `dex_literal_count` 内部对每次 grep 加 `LC_ALL=C`（一行改动），否则所有「二进制里的非 ASCII 门禁串」都会假 FAIL。
  - **本轮不改**：`archive_yntt.sh` 只提交本作路径，改 `_common/` 会留脏树。
