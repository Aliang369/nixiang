# 追迹迷城 · 技能先例（入口形态 / dex 目标 / TapTap 白名单）

> 用途：本文件承接从 `skill/starry-mod/SKILL.md` 迁出的**单游戏实例细节**（技能只留通用机制，实例落本文件）。
> 来源：1.0.20261009 会话（复盘 §4 P0-1/P1-2）与 0912→1009 换版本实测；迁出日 2026-10-15（用户 m00007）。

## 1. `<application android:name>` 入口形态：本机实测**不采用**

- 属性经 aapt2 复读**合法**：`name#3 resid=0x1010003`、`type=string`、值正确。
- 但运行时 `StarryApp` **从未实例化**：logcat 无任何 StarryApp 行、`/proc/<pid>/maps` 无 `libstarry_magic.so`。
- 反证闭环：若 className 生效而类缺失，**必然** `Unable to instantiate application` 崩溃 —— 实测未崩 ⇒ 该属性根本没被平台采用。
- 结论（已升格为技能侧通用判据）：首选 ContentProvider 入口。

## 2. dex 合并目标：换版本会变布局，禁止硬编码 `classesN`

- 0912 → 1009 实测：**由 6 dex 变 4 dex**，且 `classes3.dex` 已顶到 **65533/65536** 的 ART 方法数上限。
- 故一律先跑 `_lib/dex_target.sh --apk <底包> --need-methods <星光方法数>` 取余量表，按「余量最大且 ≥ 待合并方法数」选定；无候选 ⇒ rc=2 回退重建 dex。

## 3. TapTap 强制网页登录：`PKG_WHITELIST` 漏配的实测表现

- 漏配本包名 ⇒ 5 处 `if (!PKG_WHITELIST.contains(activity.getPackageName())) return;` 静默 return、**零日志**。
- 实测表现：被强制走**网页登录**（不是客户端 SSO），构建与运行全程无报错 ⇒ 属静默失败类。

## 4. Provider 顺序的参考实现

- 必须排在其它 Provider（TapTap `TapTapKitInitProvider` / `TapUpdateFileProvider`）**之前**（Provider 顺序＝平台实例化顺序，先回灌官方证书再让 SDK 读）。
- 参考：`04_scripts/追迹迷城/patch_zjmc_binary_manifest_v3.py`。
