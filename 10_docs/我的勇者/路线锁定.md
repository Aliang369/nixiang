## 2. 无CD 4B 补丁与 `hook-rules.md` §21「禁改序言」的例外说明

- §21 原文禁的是「**手写字节 patch 改函数序言**」，理由：序言被改会让 Dobby/inline hook 与栈展开失效、RVA 漂移后写错位置即闪退。
- 本补丁改的是 **函数中部 `entry+0x60`**（`orr w0,w0,w19`），不动序言（`stp x30,x19,[sp,#-0x10]!` 保持原样），函数仍可被正常调用/展开；写前 `Patch4At` 做**双态校验**（`cur` 必须等于 `kOff`/`kOn` 之一，其余值一律 `drift (skip)` 不写），写后 `ClearCache`，页权限 RESTORE 为 `R|X`。
- 历史口径：7.6.3 已用户终审落地并实测生效（无 CD 生效、未出现倒计时卡死）；7.6.4 该点 8B 与 357 口径完全一致 ⇒ 沿用，不另立方案。
- 仍未做：对该函数的 inline hook（该函数属加固保护簇，有 SIGILL 自杀史）。
- **2026-10-23 修订（原「357 终审不加按名兜底 ⇒ 保持纯 RVA」作废）**：7.6.4 热更副本上硬编码 RVA `0x485B26C` 已落到无关代码，`entry+0x60` 每 ~200ms 读回 `0x94388E9F`（`nocd patch expect drift`），无CD 从未生效且构成二次崩溃风险。现改为**按名解析补丁入口**（`Battle.Skill.SKillBase::CheckSkill` argc=1，短名兜底，thunk 跟随保留）→ 校验入口序言 `0xA9BF4FFE` → `entry+0x60` 双态校验；解析失败或失配即置**闩锁**，同一开关状态不再重试，仅开关切换时清闩重试一次。性质澄清：这**不是** inline hook（无 Dobby、不改序言，SIGILL 前提不适用），只是把补丁目标的解析方式从硬编码 RVA 改为元数据按名；原「不加按名兜底」针对的正是补丁入口解析，故按本轮实测更新本行，§2 其余条款不变。
