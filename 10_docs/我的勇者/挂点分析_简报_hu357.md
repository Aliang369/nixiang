## 2. 地址口径（铁律）

- dump.cs 里每方法注释形如 `// RVA: 0x4779EE0 Offset: 0x4775EE0 VA: 0x4779EE0 Slot: N`。
- `FileOffToVa` 入参用 **`Offset` 字段**（文件偏移），**不是 RVA/VA**。
- 序言字节：读 `/tmp/wdyz357/libil2cpp.so` 前 4 字节，小端记录（用于 RVA 挂点的序言校验）。
  - **`xxd -l 4 -s <Offset>` 用文件 Offset（正确）**。
  - **`llvm-objdump -d --start-address=<RVA/VA>` 用 RVA/VA（= Offset + 0x4000），不是 Offset**（历史教训：误用 Offset 会反汇编到 0x4000 字节前的错误函数）。

## 3. 已知红线（必须遵守，写进结论）

1. **不挂任何技能/CD 簇函数**：`SKillBase.TryEnterCd` 等被保护，inline hook 会触发 SIGILL 自杀（旧 §10.1-1 实锤）。CD 只能走「安全热路径 piggyback + 字段直写」。
2. **不直调 IL2CPP 方法**（frida 期 `GoDeath` 等回调内必崩；native hook 回调同理，只读字段/改参数，不 runtime_invoke）。
3. **ObscuredFloat 字段谨慎**：HP/MP/暴击相关字段若为 `ObscuredFloat`（如 `resitCrit // 0x198`），直接写明文会触发校验，优先找「非加密的路径/参数」或「结算入口改参数」。
4. 现有安全热路径：`BattleObjectCore.SettleDamage(value, shield, toughness, energy, fromgroup)`（新 dump `Offset 0x4775EE0`）已被证实 hook 安全；`MonsterCore.SettleDamage` / `HeroCore.SettleDamage` 覆盖入口同理。
