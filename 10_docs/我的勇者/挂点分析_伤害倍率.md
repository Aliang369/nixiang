## 1. 结论（先给死）

**`shield` = 「本次对护盾造成的伤害量」，正数 = 扣盾，负数 = 加盾（回盾）。不是「护盾剩余值」，也不是「盾伤负数」。**

- 与 `value`（HP 伤）同号同义：正=伤害分量、负=回复分量；两者都是「要被扣掉的量」。
- 管线内 `shield` 恒为 **≥0 的承伤分量**：`context.shield = min(目标当前盾, 护盾系数 × context.curValue)`，同时把 `curValue` 扣掉被吸收的部分。
- 落地时基类执行的是 **`ATTR_CUR_SHIELD(62) -= shield`**（再按 `ATTR_MAX_SHIELD(61)` 上限与下限夹取），**不是赋值**。
- 因此 **符号不要翻转**；「穿盾」＝`shield` 与 `value` 同乘 N，且 `shield` 的放大必须独立判断（`value==0` 的全吸收情形下 `value` 的 if 不成立）。

`N× 同时穿盾` 的最小正确改法（**两个钩子都要改**）：

```c
/* 敌 core（tag==1）：基类钩子 + MonsterCore 类型 7 分支 */
if (value  > 0.0f) value  *= N;   // HP 伤
if (shield > 0.0f) shield *= N;   // ★ 护盾伤，独立 if；不能塞进 if(value!=0)
// toughness / energy 不动
```

| 项 | 值 |
|---|---|
| 挂点① | `Wdyz_HookedBaseSettle` ← `BattleObjectCore.SettleDamage`，Offset 0x4775EE0 / **RVA 0x4779EE0** |
| 挂点② | `Wdyz_HookedMonsterSettle` ← `MonsterCore.SettleDamage`，Offset 0x47C08B0 / **RVA 0x47C48B0** |
| ABI | s0=value s1=shield s2=toughness s3=energy w1=fromgroup（w1，不是 w4） |
| 形态 | Slider 1–10×，默认 1×=关；与既有「五倍攻击」独立、可叠加（5×N） |

## 3. 为什么现在「五倍攻击」穿不了盾

现状（`mod菜单/starry-mod-menu/app/src/main/jni/Games/WdyzMod.cpp`，`Wdyz_HookedBaseSettle` / `Wdyz_HookedMonsterSettle`）：

```c
if (value != 0.0f) value *= 5.0f;   // 只乘 HP 伤，shield 原样
```

原因链（A→B→C）：

1. 钩子在 `SettleDamage` **入口**，此刻 `value` 已经是**护盾结算之后**的残余 HP 伤（A 的 `0x4897b14`、B 的 `0x47fb7ec`）。
2. 盾够大时 `ShieldStep` 给出 `shield = 系数×curValue`、`curValue = 0` → 钩子收到 **`value = 0`**，`5 × 0 = 0`。
3. 同一发里 `shield` 仍是原值，基类只扣那么多盾（C）→ 盾按原速减少，剩余盾继续把后续每一发吃成 `value = 0`。
4. 部分吸收时：`value` 被放大，但扣盾量不变 → 破盾速度不变，只有「盾破之后」的收益被放大。

与既有的实测口径一致：「Boss **破盾后** 1 管血即穿」= 倍率只作用在盾吸收剩下的那部分。
**一句话：倍率只作用在「盾扣完剩下的残伤」，盾的消耗完全没被倍率影响，所以穿不了盾。**

## 4. 推荐改法（N× 同时穿盾）

```c
/* 敌方伤害倍率 N（Slider 1–10，默认 1.0 = 关闭） */
static inline void ScaleEnemyDamage(float* value, float* shield, float n) {
    /* value/shield 都是「承伤分量」：正=伤害、负=回复。
       只放大正向量，避免把敌方回血/回盾也一起放大。*/
    if (*value  > 0.0f) *value  *= n;
    if (*shield > 0.0f) *shield *= n;   /* ★ 穿盾关键；必须独立 if ★ */
    /* toughness / energy 不动 */
}
```

- 挂点①：`Wdyz_HookedBaseSettle`，`tag == 1 && g_dmg` 分支 → `ScaleEnemyDamage(&value,&shield,N)`。
- 挂点②：`Wdyz_HookedMonsterSettle`，`monsterType == 7 && g_dmg` 分支 → 同样调用。
  类型 7 在该入口内提前返回、不落基类：`0x47c4a64 cmp w0,#7` / `0x47c4a68 b.eq 0x47c4b4c`。

> **必须两处都改**：普通怪最终走基类落地点（`0x47c4a88 bl 0x4779ee0`），类型 7 走 override 早退分支。只改一处 = 「小怪穿盾、Boss 不穿」。

### 4.1 逐参数怎么改

| 参数 | 语义（证据） | N× 怎么改 | 理由 |
|---|---|---|---|
| `value` | HP 伤，扣 `ATTR_HP_CUR(13)` | **× N** | 直接放大 HP 伤 |
| `shield` | 护盾伤，扣 `ATTR_CUR_SHIELD(62)` | **× N，符号不翻转** | 基类是减法，放大即加速破盾；翻转成负数会**给敌人加盾** |
| `toughness` | 韧性伤，扣 `ATTR_TOUGHNESS_CUR(88)`（上限 89） | **不动** | 独立条（破韧/硬直）；同乘会让 Boss 提前破韧、行为异常，与「伤害倍率」目标无关 |
| `energy` | 能量条伤，扣 `ATTR_M_ENERGY_CUR(201)`（上限 200） | **不动** | 同上 |
| `fromgroup` | 来源分组（w1，取自 `fromObject`） | 不动 | 与伤害量无关 |

**不要做**：不要为「破盾快」把 `shield` 写成 `maxShield`/大常数（过冲且丢信息）；不要取反；不要把 `value` 改成 `value*N + shield*N`（HP 与飘字重复计）。

### 4.2 副作用与护栏

1. **绕过单发封顶（实测）**：管线内 `DamageLimitStep.BeginCalculateStep`（**RVA 0x48964A4**，dump.cs:612568）把 **`value + shield`** 合计限制在「目标 `ATTR_HP_MAX` 的 pct%」（pct 取自受击方整型字段 `+0x48`，代码 `cmp w22,#0x63; b.hi` 即 **0–99**，再除一个静态 `ObscuredInt` 配置）：
   `0x4896704 ldp s2,s1,[x19,#0x28]`（s2=curValue,s1=shield）→ `0x4896718 fadd s3,s1,s2`（合计）→ `0x489671c fcmp s0,s3` / `0x4896720 b.pl`（未超跳过）→ 超了先砍 `curValue`（`0x4896758 str s0,[x19,#0x28]`），仍有余量再砍 `shield`（`0x4896740 str s0,[x19,#0x2c]`）到 0。
   **钩子在管线之后 → N× 结果不受该封顶约束**，单发可超设计上限。常态无害（float 足够），但属可观测偏差，需知情。
2. **盾量过冲（推断，待实测）**：`shield*N` 可能大于当前盾，写回时 `min(当前盾−shield, 上限)` 再与下限 `mm0` 取大（`0x477a124/0x477a12c`）。HP 分支用的是**同一套下限逻辑**，而击杀必然让 HP 过冲，故推断 `mm0` 实际为 0（否则 HP 会被卡在 mm0 上）→ 盾最多扣到 0、不会为负。**未真机验证**；验收看盾条是否停在 0 后正常回满（§7-1）。
3. **溢出**：32 位 float，N≤10 与正常量级无风险；仅当 N 极大（≳1e30）出现 `inf`，随后 `fsub/fmax` 写进属性 → 血条/盾条异常。建议 `if (!(N > 0.0f)) return;` 并对 N 设上限（Slider 1–10 已天然满足）。
4. **回复被放大（低风险，建议规避）**：`DamageSettleData` 构建时 HP 伤被 `0x47fb7f0 fmax` 夹到 ≥0，伤害管线里不会出现负 `value`；但 `SettleDamage` 本身有「负值=回血」分支（`0x4779f90 fcmp s13,#0.0` 后走回血钳制），若将来有 Buff/直调路径带负值进来，`!= 0` 会放大回复。用 `> 0.0f` 即免疫。
5. **误伤/误判**：`tag` 依赖 `ClassTagOf` 的 `object_class` + 类名兜底（`Monster|Boss|mob|Mob`→1）。名称兜底命中友方召唤物会连盾一起放大。上线前用 12 条采样日志（`BASE raw`/`MON raw`）核对 `name/class/tag`。
6. **飘字一致**：`MonsterCore` 用 `value+shield` 作展示总伤（`0x47c49f4`），两参同乘后飘字与实伤同倍率，不会「数字 5×、掉血不变」。
7. **与既有五倍攻击并存**：用户定「伤害倍率 Slider 1–10× 独立于 #2 五倍攻击」，同开时叠加（5×N），菜单注释写明「叠加」即可。

### 4.3 备选（不推荐，仅记录）

若目标是「无视护盾直接打血」而非「更快破盾」，应在**护盾步之前**让伤害不被吸收（hook `ShieldStep`/`ShieldInnerTriggerStep` 把 `context.shield` 置 0）。但这三处是 `struct` 的 `IDamageCalculateStep` 热路径，内含静态 `ObscuredInt` 配置与 `AttributeObj` 虚调用，风险显著高于 `SettleDamage` 入口，本轮不采用。

## 5. 语义速查（给 hook 代码用）

```
SettleDamage(self, value, shield, toughness, energy, fromgroup)   // w1 = fromgroup
  s0 value    : HP 伤   → ATTR_HP_CUR(13)        -= value      （负 = 回血）
  s1 shield   : 护盾伤  → ATTR_CUR_SHIELD(62)    -= shield     （负 = 加盾）
  s2 toughness: 韧性伤  → ATTR_TOUGHNESS_CUR(88) -= toughness  （上限 89）
  s3 energy   : 能量伤  → ATTR_M_ENERGY_CUR(201) -= energy     （上限 200）
  w1 fromgroup: 来源分组（不动）
```
全部是「扣分量」，**正=伤害 / 负=回复**，没有任何一项是「剩余值」。

## 7. 未闭环项（明确标注，不得当已确认）
