## 1. 结论摘要（推荐挂点）

**暴击判定的唯一落点是 `Battle.Step.Skill.DamageCriticalStep.BeginCalculateStep`。**
最安全的落地方式＝**在该函数体内的「随机值 vs 暴击率」比较点做 1 条 4 字节 `b <stub>` 跳转 + 自建 stub 门控**，
stub 内按 `ClassTagOf(context->fromObj)` 决定「强制走暴击分支」还是「原样比较」。
既拿到**真实暴伤倍率**（不碰 ObscuredFloat、不调托管方法），又能只对英雄生效、菜单可开关。

| 项 | 值 |
|---|---|
| 类（命名空间） | `Battle.Step.Skill.DamageCriticalStep`（struct，TypeDefIndex 16806） |
| 方法 | `public void BeginCalculateStep(CalculateContext context)`（Slot 4，`IDamageCalculateStep`） |
| **函数入口 Offset** | **0x4890218** |
| 入口 RVA/VA | 0x4894218 |
| argc | **2**（`x0`=this 结构体指针，实际未用；`x1`=CalculateContext*，序言 `mov x19,x1`） |
| 序言前 4 字节（小端） | **`e8 0f 1d fc`**（`str d8, [sp, #-0x30]!`），其后 `fe 57 01 a9`（`stp x30,x21,[sp,#0x10]`） |
| 推荐改写点 Offset | **0x4890350**（VA 0x4894350） |
| 该点原字节（8B） | `00 20 28 1e  65 02 00 54` = `fcmp s0, s8` ; `b.pl 0x48943a0` |
| 建议改写 | 只把 0x4890350 的 4 字节改成 `b <stub>`（stub 落在 ±128MB 内的 mmap），0x4890354 保留不动（已被跳过） |
| dump.cs 行号 | 612496（类型）、612500–612501（方法+Offset） |

> 为什么不是「入口 hook 改参数」：本函数**没有可改的入参能决定暴击**——暴击率是函数内部
> 从 `fromObj` 属性 106 减 `targetObj` 属性 107 现算的，且**暴伤倍率就地乘进 `context->curValue`**（见 §2-C）。
> 入口 hook 只能后置改 `isCrite` 标记，拿不到暴伤 → 不完整（见候选 D）。

## 2. 证据链：`DamageCriticalStep.BeginCalculateStep` 逐段反汇编（VA 0x4894218–0x4894424，长度 0x20C）

`CalculateContext` 字段布局（dump.cs:589130 起，实测与反汇编完全吻合）：

| 字段 | 偏移 | dump.cs 行 |
|---|---|---|
| `IBattleObjectCore fromObj` | 0x10 | 589133 |
| `IBattleObjectCore targetObj` | 0x18 | 589134 |
| `float curValue` | 0x28 | 589137 |
| `bool isCrite` | **0x3C** | 589142 |
| `BattleLog log` | 0x48 | 589144 |

### A. 取「攻击方暴击率」= 属性 106（VA 0x489424C–0x48942B8）
```
0x489424c  ldr  x20, [x19, #0x10]      ; x19=context → x20 = context->fromObj
0x48942b0  mov  w1, #0x6a              ; 106 = CommonEnum.RoleAttrEnum.ATTR_CRI_RATE (dump.cs:588881)
0x48942b8  blr  x8                     ; 虚调用 fromObj.GetAttr(106) → v0 = 暴击率(已归一到 0..1)
```
### B. 取「受击方抗暴」= 属性 107，并夹到 [0,1]（VA 0x48942BC–0x489433C）
```
0x48942bc  ldr  x20, [x19, #0x18]      ; x20 = context->targetObj
0x489431c  mov  w1, #0x6b              ; 107 = ATTR_RESIST_CRI_RATE (dump.cs:588882)
0x4894324  blr  x8                     ; s0 = 抗暴
0x4894328  fsub s0, s8, s0             ; s0 = 暴击率 - 抗暴
0x489432c  fmov s1, #1.0
0x4894330  fmin s1, s0, s1
0x4894334  fcmp s0, #0.0
0x489433c  fcsel s8, s1, s0, pl        ; ★ s8 = clamp01(暴击率-抗暴)
```
### C. 掷骰并二分支（VA 0x4894340–0x4894420）
```
0x4894340  fmov s0, #0.0
0x4894344  fmov s1, #1.0
0x489434c  bl   0x789a524             ; = UnityEngine.Random::Range(System.Single,System.Single)  ← 实证
0x4894350  fcmp s0, s8                ; s0 = r ∈ [0,1)
0x4894354  b.pl 0x48943a0             ; r >= 暴击率 → 非暴击

; ---- 非暴击分支 0x48943A0 ----
0x48943a0  ldr  x8, [x19, #0x48]      ; context->log
0x48943a8  ldr  x9, [x8, #0x258]
0x48943b0  mov  w8, wzr
0x48943b8  str  w10, [x9, #0x8c]      ; log 暴击倍率槽 = 1.0f
0x48943bc  b    0x4894410

; ---- 暴击分支 0x4894358 ----
0x4894358  ldr  x20, [x19, #0x10]
0x48943d4  mov  w1, #0x6c             ; 108 = ATTR_CRL_DELDAMAGE (dump.cs:588883)
0x48943dc  blr  x8                    ; 取暴伤
0x48943ec  ldr  x8, [x19, #0x48]
0x48943f4  ldr  x8, [x8, #0x258]
0x48943fc  str  s0, [x8, #0x8c]       ; log 暴击倍率槽 = 暴伤倍率
0x4894400  ldr  s1, [x19, #0x28]      ; curValue
0x4894408  fmul s0, s0, s1            ; ★ curValue *= 暴伤（就地在本文函数内完成）
0x489440c  str  s0, [x19, #0x28]

; ---- 汇合 0x4894410 ----
0x4894410  strb w8, [x19, #0x3c]      ; ★ context->isCrite = (暴击?1:0)
```

**三条关键结论（均有实测字节/反汇编支撑）**：
1. 暴击率来源＝属性 **106**（攻击方）− 属性 **107**（受击方），夹 [0,1]；**不是** `ObscuredFloat` 字段直读，也不是 `BattleAttrTools.GetCritRate`。
2. 判定＝ `UnityEngine.Random.Range(0f,1f) < 暴击率`；随机函数身份用 so 内字符串实证：
   文件名偏移 `0x16B59A9` 处 ASCII = `UnityEngine.Random::Range(System.Single,System.Single)`。
3. **暴伤倍率就在本函数内乘进 `curValue`**（0x4894408），同时写 `log[+0x258][+0x8c]` 倍率槽、写 `isCrite`。
   ⇒ 任何「只置 `isCrite`」的入口 hook 都无法得到真实暴击伤害。

## 4. 推荐落地（方案 A）细则

### 4.1 需要的信息（全部已实测，可直接写码）
- 函数入口序言校验：`e8 0f 1d fc fe 57 01 a9`（8 字节，双击防错位）。
- 改写点：VA 0x4894350 起 `fcmp s0,s8`（`00 20 28 1e`）+ `b.pl`（`65 02 00 54`），共 8 字节；**只覆盖第 1 条**为 `b <stub>`。
- 两支恢复点（stub 内 `b` 回去即可，无需搬指令）：
  - 非暴击：**0x48943A0**（该处只依赖 x19）
  - 暴击：**0x4894358**（该处 `ldr x20,[x19,#0x10]` 自行重载 x20，依赖 x19/x21；x21 在 0x489425C 已设好，stub 不得破坏 x21）
- 寄存器约束：进入 0x4894350 时活跃值 = `x19`(context)、`x21`(类指针)、`s0`(r)、`s8`(暴击率)、`sp`。
  stub **必须保持 x19/x21/s8 及 sp 不变**，可自由用 x0–x10 与 s1–s7（调用自家 helper 前自行保存）。

### 4.2 stub 逻辑（伪码）
```c
void crit_stub(void) {                    // 由 0x4890350 的 b 跳进来
    if (g_crit100_on && ClassTagOf(*(void**)((char*)ctx_x19 + 0x10)) == 2 /*HeroCore*/)
        goto force_crit;                  // 英雄作为攻击方 → 恒暴击
    asm("fcmp s0, s8");
    if (r >= rate) goto non_crit; else goto crit;
force_crit:
crit:      goto (void*)0x4894358;         // 真实暴击分支：乘真暴伤、写 log 槽、isCrite=1
non_crit:  goto (void*)0x48943A0;
}
```
- `ClassTagOf` 直接复用 `mod菜单/starry-mod-menu/app/src/main/jni/Games/WdyzMod.cpp` 里已在 3 个 SettleDamage hook 上验证过的实现（MonsterCore=1 / HeroCore=2），**不新增托管调用**。
- 只在「安装 hook 时」做一次 `mprotect` + 4 字节写入，**不做每击写内存**，无并发/性能风险。

### 4.3 红线对照
| 红线 | 本方案 |
|---|---|
| 不挂技能/CD 簇 | ✅ `DamageCriticalStep` 属 `Battle.Step.Skill` 命名空间但**不是** `SKillBase.TryEnterCd` 那类 CD 簇函数，位于伤害结算管线（与已证安全的 SettleDamage 同一条热路径） |
| 不 runtime_invoke / 不直调 IL2CPP 方法 | ✅ stub 内只做内存读 + 跳转；不调用任何 il2cpp 托管方法 |
| 避开 ObscuredFloat | ✅ 完全不读写属性内存，暴击率/暴伤由原函数自己经虚 getter 取 |
| 一轮一个变量 | ✅ 唯一改动＝1 条 4 字节跳转 + 1 个 stub |

## 5. 未闭环项（明确「待验证 / 读不懂」）

1. **待验证**：怪物→英雄伤害是否也走同一个 `DamageCriticalStep`（`SkillDamageFromMonsterPipeline` dump.cs:589345 与 `SkillDamagePipeline` dump.cs:589360 是两条独立管线）。
   已尝试在两条 `Creat()/.ctor()` 里搜 `DamageCriticalStep` 的方法指针字面量 0x4894218（boxed struct 的 vtable 在 .data.rel.ro，ctor 里不出现字面量）——**本次两种反汇编搜索均 0 命中，结论不成立，不能据此认为「只有玩家管线用」**。
   ⇒ 这正是方案 A 必须做 `ClassTagOf` 门控、而不建议直接用方案 B/C 的原因。
2. **待验证**：客户端强制暴击是否被服务端二次结算/校验（若服务端重算伤害，飘字会变成假暴击）。需要真机日志判定。
3. **读不懂**：暴击分支里 `0x48943E8 bl 0x4896428`（`x1=0`）这层封装未展开（推测是把属性 108 经某个 helper 换算成最终倍率），未逐行确认，不影响挂点选择。
4. **待验证**：`GetAttr` 虚槽（`[klass+0xB0]` 方法表、`[x8+0x12E]` 槽数、`[x0+0x138]` 接口表）为 IL2CPP 通用虚分派结构，未做完整交叉验证。
5. **待验证**：`log[+0x258][+0x8C]` 倍率槽被哪些下游消费（UI 飘字 / 其他 step）——若后续还有一步按此槽再乘一次，则方案 B/C 会重复计伤，A 不受影响。

## 6. 一句话给实现方

> 打 `0x4890350`（文件偏移）的 4 字节：`fcmp s0,s8; b.pl` 序列只换第 1 条为 `b <stub>`，
> stub 里读 `[x19+0x10]` 判 HeroCore，英雄→直接跳 `0x4894358`（真暴击分支），否则恢复 `fcmp` 后按原条件跳 `0x48943A0`。
> 入口序言 `e8 0f 1d fc fe 57 01 a9` 做校验；不做入口 hook、不碰任何字段、不调托管方法。
