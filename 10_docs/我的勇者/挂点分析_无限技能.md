## 0. 红线（本功能最高危，先立规矩）

1. **不挂任何技能/CD 簇函数**：`SKillBase.TryEnterCd` 等被保护，inline hook 会 SIGILL 自杀（旧 §10.1-1 实锤）。CD 只能走「已证安全的热路径 piggyback + 字段直写」。
2. **不 runtime_invoke / 不直调 IL2CPP 托管方法**：只读字段、改参数/字段。
3. 已证安全的热路径：`BattleObjectCore.SettleDamage`（含 Hero/Monster 覆盖入口，现有 3 个 hook 在用）；`settleMp`（旧 §10.1 曾证 frida attach 安全）。

## 3. 免蓝挂点

- `BattleObjectCore.settleMp(int value)` Offset **0x47762D8** / RVA 0x477A2D8（dump.cs:587175，virtual）
- `HeroCore.settleMp(int value)` override Offset **0x47960F0** / RVA 0x479A0F0（dump.cs:589570，Slot 119）
- 扣蓝路径（推测）：`GetExpendMpSettle`（596044）→ `settleMp` → `ProcessExpendMp(SettleMpItem)`（587515 virtual / 588112 override）。
- **推荐**：hook `HeroCore.settleMp`，`value<0` 时把 value 归 0（`value=0`）。判定敌我：`settleMp` 的 self 即扣蓝对象，hook HeroCore 版本天然只影响己方。

## 5. 未闭环项（待实现/实测验证）

1. **CD 频率限制**：`HeroSettle` 只在「玩家承伤」时触发（无敌 ON 时仍会被调用，因 value 在 hook 内才归零）。若玩家长时间不承伤、技能 CD 会照常走。战斗中承伤频繁→CD 近似恒 0；站桩期 CD 会回涨。是否需要「每次攻击（MonsterSettle）也走链」或「缓存 skillBase 指针 + Tick 周期清」由实现阶段定（Tick 里遍历有性能/并发风险，优先用 HeroSettle piggyback 首版）。
2. **Dictionary<int,MSkill> 枚举布局**：IL2CPP `Dictionary<TKey,TValue>` 内部 `entries`/`count` 字段偏移随 Unity 版本不同，**实现时需先核对本 so 的 Dictionary 布局**（Metadata v31）。或改用 `SkillContainer.skillDic` 旁的其他可达 List（若存在）。这是本功能唯一技术风险点。
3. **真实扣蓝路径**：旧 §10 实测 `settleMp` 冷路径（观测窗仅 1 次、`v=+1` 符号未定）→ 扣蓝可能主走 `ProcessExpendMp(SettleMpItem)`。首版 hook `settleMp` 后必须真机看 logcat 确认「放技能蓝量不掉」；若不掉则改挂 `ProcessExpendMp`（需先确认其不在保护簇）。
4. **`settleMp` 是否在保护簇**：旧 §10.1 曾证 frida attach 安全，但本次热更(357)未重新实测 native inline hook 安全性——装机前按 L2 机器预检确认无 SIGILL。

---

## 6. 一句话给实现方

> 无CD：在现有 `Wdyz_HookedHeroSettle`（self=HeroCore）内，当开关 ON 时走 `self+0x30 → +0x18 → +0x18(Dictionary) → value → +0x18 → SKillBase`，对每个 `skillBase` 写 `CDTime(0x38)=0.0f`、`cding(0x3C)=0`；全程判空、不调托管方法。
> 免蓝：另 hook `HeroCore.settleMp`（Offset 0x47960F0，序言待 xxd 取），`value<0` 归 0。
> 首版先验证 settleMp 是否真扣蓝、以及 HeroSettle piggyback 是否触发 CD 清零，再决定要不要加 MonsterSettle 侧清 CD。
