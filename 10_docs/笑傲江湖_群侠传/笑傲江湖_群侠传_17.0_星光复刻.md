## 2. 业务在 Lua（复现路径）

C# 层（`Il2CppDumper` 出的 dump.cs 353,715 行）只有 DH 框架类（DHGameMain / DHAssetManager / DHTimer / DHProjectileMgr…），**无 Damage/Hp/Battle 方法** ⇒ 玩法逻辑全在 Lua。

### 2.1 `assets/src/all.lua` 容器格式（7,851,321 B）

```text
[0x00] "LZ4HC0108"                ; 10 字节头
[0x0A] u32BE 原始长度 = 33940574
[0x0E] u32BE 压缩长度 = 7851303
[0x12] 裸 LZ4 block（单块）        ; 解压后 33,940,574 B

解压后：u16=0 | u8 名长 | 名字 | u24BE chunk 长度 | Lua 5.4 chunk
共 1896 个 chunk，chunk 名明文（如 common/module/jiazu/soldier.lua）
```

复现（python 3.11 + python-lz4）：

```python
import zipfile, lz4.block, struct
d = zipfile.ZipFile('02_apks/笑傲江湖：群侠传.apk').read('assets/src/all.lua')
raw = lz4.block.decompress(d[18:], uncompressed_size=struct.unpack_from('>I', d, 10)[0])
```

### 2.2 Lua 5.4 反汇编要点（下次直接照做）

- 需自写解析器（标准 luac 5.4 头：`1b 4c 75 61 54 00 | 19 93 0d 0a 1a 0a | 04 08 08 | LUAC_INT 8B | LUAC_NUM 8B | sizeupvalues | source`）；自证用 `assets/src/boot/preload.lua`（24,621 B，77 proto / 2,222 指令）。
- 三个坑：① `SETFIELD` 是 `R(A)[K(B)] := R(C)`，key 在 **B**；② size_t 是**大端 7bit varint**（末字节置 0x80）；③ 按 `\x1bLua` 切 chunk 会被数据里的巧合字节截断，**必须**走容器头的 u24 长度。
- `SETFIELD` 的 key 名就是类方法名 ⇒ 从 main proto 的 `CLOSURE Bx=N` 可直接定位每个方法的子 proto（例：`clsSoldier` 的 `DoDecHp` = main.p74）。

## 3. 战斗模型与权威性（核心结论）

| 概念 | 落点 | 要点 |
|---|---|---|
| 单位 | 全局表 `clsSoldier`（common/module/jiazu/soldier.lua） | `TeamIndex` 0=我方 / 1=敌方 |
| 伤害主流程 | `clsSoldier:DoDamage(self, damage)`（main.p76，290 指令） | `CheckState("ImmuneDamage")` → `DoDecHp` → `GetHp` → `DoDie` |
| 扣血咽喉 | `clsSoldier:DoDecHp(self, dec)`（main.p74，16 指令） | `SetHp(max(GetHp()-dec, 0))`，返回实扣 |
| 伤害公式 | `battle_utils.calcDamage`（5 参 / 113 指令） | `PhysicAtt*skillRate*(1-0.7def/(0.7def+1000)+穿-抗) * max(0.05, 1+增伤-减伤) ×2 段` |
| 推进 | `battle_field.Update(dt)` 内 `dt *= GetStepMultiplier()` → `Step()` | `SetStepMultiplier` 只写 `self.stepMultiplier` |

### 3.1 判定：服务器权威重放制

```text
客户端上传（battle_check_result p2 checkArgs）：
  jiazuWarTypeId / fubenId / randomSeed / commandData({{cmdId,arg0},…}) /
  soldiersOCI / extraParam / clientFubenInfo / ClntLogMd5 / roleTypeIdMap / menpaiIdMap / ForceLog
  ⇒ 零 damage / 零 hp / 零 win 字段

服务器：
  jiazuWarTypeId2ImplClass[type] → clsJiazuBattleField:New{CommandRecord=getCommandRecord(commandData)}
  + SetRandomSeed(randomSeed) + CreateDummyPresenter()
  → FastStartGame → CoFastCheckOnce(300) × N → GetGameResult().checkSuccess

客户端校验：
  battle_check_log.p4 CheckClientResult2 → 直接用 serverResult.checkSuccess 定胜负
  自算 sLogMd5 与 ClntLogMd5 不符只推 JZWCHECK_BattleLog 告警（不改结论）
```

判据细节：`battle_field.p78/p80` 证明 `CommandRecord` 是**本地录制**的玩家输入时间线（`UICMD_CastUltra` / `UICMD_AutoCastUltra` / `UICMD_ExitGame` / `UICMD_SetInitFlow` / `UICMD_ClientOnly`），`p37 GetCommandRecord` 只返回本地容器；`p44 FastStartGame` 把 GameMode 置 `GameMode_FastCheck`（无渲染快进），`p54 FastCheck` 上限 36,000 步。

### 3.3 类到底放在哪（诊断实测，必须照这个取）

clsSoldier / clsJiazuBattleField **不在全局 `_G`**：运行时扫 `_G` 里含 Soldier|BattleField 的表命中 **0**（xLua 全局是白名单式 `__index`，裸读恒 nil）。

真实位置是**模块表**：

```text
JIAZU_SOLDIER.clsSoldier                  (soldier.lua, DoDecHp @line706)        ← 3 个 soldier 表
JIAZU_BATTLE_FIELD(clsJiazuBattleField)   (battle_field.lua, SetStepMultiplier @line360) ← 8 个战斗场类
```

⇒ 任何 Lua payload 要 hook 战斗类，必须**按 `JIAZU_` 前缀枚举模块表**（先 `rawget(_G, "JIAZU_SOLDIER")` 再取 `.clsSoldier`），逐个 `rawset` 表字段；`rawget(_G, "clsSoldier")` 恒 nil —— 取错位置时日志会"全绿"（payload 不报错、开关同步成功），但**一次都没包装**，表现就是"功能没效果"。

### 3.2 由此得到的功能边界

| 功能 | 结论 | 原因 |
|---|---|---|
| 无敌（改 `DoDecHp` / `damage.Value`） | **客户端无效** | 只改本地表现，服务器用自己的属性快照重放裁决 |
| 秒杀（放大伤害） | **客户端无效** | 同上；且改本地日志会让 `ClntLogMd5` 与服务器重放不符，触发 `JZWCHECK_BattleLog` |
| 战斗加速（`SetStepMultiplier` 倍率） | **可行**（只快进表现） | 不改变 `StepCounter` 序列与指令时间线，md5 不变 |
| 必赢（若能做） | 只能在**上传前挑输入**：`randomSeed` 与 `commandData` 由客户端生成，可用本地重放器（`FastStartGame`/`FastCheck`/`GetGameResult`）先跑候选、挑 `checkSuccess==true` 的组提交；服务器重放同一组输入必然同结论。**本项目未继续推进（用户判停）** | 属输入选择，不伪造服务器结果 |

### 3.4 「必赢」路线取证结论（已摸到底，用户判停不做）

改结果的唯一合法缝是**在提交前挑输入**，且已逐指令证实三点：

1. `randomSeed` 与 `commandData` **100% 客户端产生、客户端上传**：种子三处生成点全在 Lua（`battle_field.onInit` 的 `SetRandomSeed(args.RandomSeed or math.random(0,65535))`、`bfdctrl_fuben_base.genBaseBattleFieldOCI` 每波重掷），生成→打包→发送链路无校验、无夹取、无回读。
2. **本地重放器客户端本来就在跑**：`bfdctrl_lilian_base.FastGenBattleResult`（开战即启动的后台预校验）与 `battle_check_result.GenCheckDataSafe`（`GIsServer()` 双向共用），可直接复用，无 native 依赖。
3. 因此必赢 = 提交前用同一套引擎把候选输入跑一遍（最省是只换种子，65537 个可能值），再用本地重放重算 `LogMd5` / `StepCounter` 让整包自洽 —— 连"md5 不符告警"都不会留。**代价**：每轮需 `FastCheck` 分帧跑（`CoFastCheckOnce(300)`），不能一次同步跑完，否则卡死主线程。

## 4. 改包必然遇到的签名校验（实测）

改包重签后登录弹「环境存在风险」：SDK 把**新证书**上报给服务器判定。

```text
TanWanReport: signatureSHA256=83C5CC0B…(星光证书) signatureSHA1=821C92E4… signatureMD5=161FCA32…
teatanwan(AppLog): sig_hash=161fca32…
底包官方证书（META-INF/TANWAN.RSA）：subject C=gz,CN=gz，SHA-256 0020e89c4aac5d589d8fd0353b1d188b9acfc06e87f80dd00c987a87cd4e63f5
```

处理（已实测生效）：动态代理 `ActivityThread.sPackageManager`（`IPackageManager`），在 `getPackageInfo*` 返回上把 `signatures` 换官方证书；挂载点 `android:appComponentFactory`（早于 `TWApplication.attachBaseContext`）。处理后 `signatureSHA256` 上报值变为 `0020E89C…63F5`。

已知缺口：API 34 上 `SigningInfo.setSignatures` 不存在、`SigningDetails` 构造器被 hidden API 过滤（`visible ctors=0`）⇒ `GET_SIGNING_CERTIFICATES` 一路伪造不可行；本作实测 TanWan / Pangle 均读 `signatures` 路。
