### 2.1 客户端「环境检测」能力（IL2CPP 侧）

metadata 字符串实测含：`GameProtectSDKManager.{InitSDK,OnEvent,ReportRiskInfo}`、`isEmulator`、`m_bEmulator`、`IsEmulator/IsEmulatorX86/IsEmulatorGraphic`、`CheckEmulator`。
即：**环境风险由 GameProtect 采集并上报服务端，客户端本身不做“检测到 root 就退出”的硬拦截**。
`libgp.so` 内部字符串实测：`frida`×2、`xposed`×1、`debugger`×1、`hook`×1，而 `magisk`/`su`/`supersu`/`busybox`/`root`/`selinux`/`ptrace`/`emulator` **均为 0**；路径串只有 `/system/bin/linker64`、`/system/build.prop`。⇒ 该风控库的强项是**反 Hook / 反调试 / 反 Frida-Xposed**，**不包含经典 root 文件扫描**。
⇒ 「游戏检测 root」这一假设在本包里**没有找到直接实现**；更准确的风险面是「**注入/hook 行为会被 GameProtect 发现并上报**」，这一点直接影响 mod 菜单的落地方式与封号风险（写功能前按 `anti-ban-analysis.md` 评估）。
（元数据中 `/system/bin/su`、`magisk`、`busybox`、`rootbeer` 命中数均为 0；`frida/xposed` 命中项经上下文核对为 .NET/Unity 无关同形词，非检测串。）

## 4. ★ 诊断结论：登录被**服务端**以 `-37` 拒绝（实测）

### 4.1 证据链

游戏自带日志目录 `…/files/dragon2019/Flog/`（已归档到 `06_dumped/潮汐守望者/device_logs/Flog/`，6 份）显示：

```
[Info]-QuickSdkListener.onLoginSuccess:{"userName":"szn696n1s15","userId":"6258729", ...  "msg":"success"}
[Info]-CNChannelName:and_cntaptap
[Info]-job ConnectServer start
[Info]-job Login_Auth start
[Info]-SelectZoneId: 0,nameEncode:c3puNjk2bjFzMTU=
<--[LoginServer]2 | 0 | -37
[Debug]-[xjy] Push ---> Name:Form_SystemTips        ← 弹窗就是这条
```

- **6 次登录尝试（23:46:17 / 23:48:01 / 23:48:53 / 23:49:12 / 23:49:34 / 23:49:53）全部返回 `-37`**，每次紧接着弹 `Form_SystemTips`。
- 同段日志中客户端自检为 `IsEmulator:False`；SDK 登录（TapTap→QuickSDK）**成功**，失败发生在**游戏登录服务器**这一跳。
- 弹窗文案**不在客户端**：15 份 dex、`resources.arsc`、全部 assets、`liblogic.bytes`(187 MB)、`global-metadata.dat`(22 MB) 逐字节搜 `角色被限制登录`/`游戏数据异常`/`限制登录`/`检测到您的` 全部 0 命中（metadata 全库仅 436 条中文串，含 `登录成功`/`正在登录中`，无封禁类文案）。
  ⇒ **提示文本由服务端下发**，客户端只负责显示。

### 4.2 判定

- **CLAIM**：本次「数据异常/限制登录」是**服务端对该账号的登录拒绝（错误码 -37）**，不是客户端 root 检测导致的启动/登录拦截。
- **VERDICT**：证据支持（日志 6/6 一致 + 文案不在客户端 + 客户端自检未报模拟器）。
- **未覆盖**：`-37` 的**触发条件**尚未区分（账号级 vs 设备/环境级）。GameProtect 会把环境风险上报服务端，所以「root 触发的服务端风控」仍是**待验证**候选，不能排除，但也不是「客户端检测 root 就拦」这一形态。

### 4.3 待做的区分实验（需用户配合）
### 4.3.1 实验结论（2026-09-30 用户实测）

- **实验 B 已做：同一账号在本机（root）被 `-37` 拒，换到非 root 设备可正常登录游玩。**
- ⇒ **账号未被限制**（已排除账号级封禁）；限制是**设备/环境级**的：同一个账号、同一份官包，只因设备不同就结果不同。
- ⇒ 下一步方向＝找出本机被采集到的风险信号（root / 反 Hook / 包扫描 / 设备指纹）并处理，不再往“账号”方向查。
- 仍未区分的子问题：是「本机设备指纹已被列入拒绝名单」还是「本机环境的实时风控信号触发拒绝」——前者换账号也会被拒，后者可用干净环境登录。

| 实验 | 若成功 | 若仍失败 | 说明 |
|---|---|---|---|
| A. 同一台 root 设备换**另一个账号**登录 | 账号级限制（该账号已被风控/封禁） | 设备/环境级（root 或设备指纹被标记） | 最省事、结论最强 |
| B. 同一账号换**非 root 设备**登录 | 设备/环境级 | 账号级 | 需另一台机 |

结论未定时，**不应**先改客户端去找「root 检测绕过」——当前证据指向服务端裁决，客户端改动无法改变服务端已下的判定。

## 5. 与用户目标的差距 / 下一步（环境阶段）

用户目标顺序：**先过环境（去签名 + 网页强制登录 + mod 菜单装进游戏、能正常玩）→ 再做无敌/伤害倍率**。

已识别的环境工作项：

1. **去签名（QuickSDK 签名校验）**
   - 路径 A：星光框架 `SignSpoof` 回放官包证书（`CN=LF… / MD5 cae2157529a81b6839e0a76ca90a49a4`），使 `getSignInfo`/`getAPKCharacteristic` 仍返回原厂值（QuickSDK 侧比对的是这两个返回值）。
   - 路径 B：native 侧 `libqkcheck.so` `deal_check_fail` 入口 RET（工作区既有先例：物质与魔法）。
   - 需同时核对 `assets/com.gf.cxswz.cert.pem` 的消费方。
2. **登录链路（"网页强制登录"）**
   - 现状：官包下 TapTap→QuickSDK 客户端登录**可用**；改签后需按工作区先例（`skill/re-analyze/login/taptap-web-login.md`）确认本作 TapSDK 版本是「新版 `ClientLoginUtils`」还是「旧版 `ClientLoginHandler.canHandle`」，再决定强制 WebView 登录的落点。
   - ✅ **已确认版本（2026-09-30 实测）**：`classes14.dex` 含 `com/taptap/sdk/login/impl/utils/ClientLoginUtils`，**不含** `com/taptap/sdk/login/internal/handlers/client/ClientLoginHandler`，也不含 `com/taptap/sdk/ui/TapTapActivity` ⇒ 属**新版 SDK 路径**，对应 skill 文档「版本 1」：patch `ClientLoginUtils.isClientLogin(...)` 恒返回 `false` → fallback 到 `WebLoginFragment`。
   - `TapSignKit` 在 `classes2.dex` / `classes14.dex`，需一并处理（固定返回原版 cert MD5 `cae2157529a81b6839e0a76ca90a49a4`）。
   - 注意：本作登录是 QuickSDK 聚合（`com.quicksdk.*`），需先确认 TapTap 分支真实路由，不能直接照搬只改 TapSDK 的做法。
3. **Mod 菜单落地**：走星光 modern 注册表（`new_game_mod.sh`），`game_id` 按全名首字母推导 = **`cxswz`**（潮汐守望者）；hook 目标库是**运行时解压出来的 `liblogic.so`**（非包内 `libil2cpp.so`），加载时机/路径需单独确认。
   - 参考 `DynamicSOLoader.CopyUnityIL2CPPLibResources`：真库来源 `assets/comlibs/{arch}/liblogic.bytes` → 复制到持久目录后由运行时 `dlopen`；抓点/挂点必须针对这条路径，不能按常规 `libil2cpp.so` 处理。
4. **风险口径（写功能前必读）**：本作是**服务端权威 + 风控心跳上报**的在线游戏；`无敌/伤害倍率` 属服务端可对账项，且**当前账号在未改包的官包上就已被服务端拒绝**。功能阶段须先按 `skill/re-implement/anti-ban-analysis.md` 出结论。
