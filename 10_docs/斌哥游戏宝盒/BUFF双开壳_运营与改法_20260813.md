# 长生-BUFF / 嘎嘎射击-BUFF — 运营逻辑与改法（2026-08-13）

> 真机已装，静态 + 数据目录实锤。用户口中「嘎嘎设计-buff」对应桌面名 **嘎嘎射击-BUFF**。

## 是什么

| 桌面名 | 包名 | 体积 | versionCode |
|--------|------|------|-------------|
| 长生-BUFF | `com.netkuu.changsheng.BGtjjs` | ~66MB | `999999` |
| 嘎嘎射击-BUFF | `com.Sofunny.BGShootingDuck` | ~66MB | `999999` |

对照真游戏：

| 真游戏 | 包名 | 体积 |
|--------|------|------|
| 长生：天机降世 | `com.netkuu.changsheng.tjjs` | ~2GB（含 Unity） |

**BUFF 包里没有 Unity 资源 / `libil2cpp`**，不是「改好的整包游戏」，而是换皮后的 **多开/克隆壳**。

## 运营 / 产品形态

1. **同源壳**：两 APK 文件清单几乎相同（~2168 同名文件，约 2136 内容一致）；入口都是 `com.pengyou.cloneapp.SplashActivity`（朋友多开 / VirtualApp 系）。
2. **虚拟环境目录 `chaos/`**：内嵌 guest 数据区 `chaos/data/user/0/<guest包名>/`，外置 `Android/data/<BUFF包>/files/External/0/<guest>/`。
3. **microG**：`files/microG.apk`，给虚拟空间补 Google/Play 能力。
4. **免责声明**（`dialog_close_log`）：写明「与**斌哥游戏宝盒**和作者无关」，邮箱 `bg888@188.com` → 与仓内已分析的斌哥改包/宝盒同一生态。
5. **同机还有** `com.yf.yuji.bgyxbh`（斌哥游戏宝盒）；BUFF 是「按游戏名换皮」的双开壳发行物，不是宝盒本体。

当前真机快照：`长生-BUFF` 的 `chaos` 里已克隆过 **魂坠深境** `com.chillyroom.containerofsoul.yw`（含 `starry_magic_prefs`），说明壳可跑任意选中的 guest，不限于「长生」。

## 对游戏的修改形式（机制分层）

```
用户打开「xxx-BUFF」
  → pengyou.cloneapp 壳 UI（选应用 / 下载资源 / 多开）
  → Chaos 虚拟空间安装并启动 guest APK
  → guest 进程跑在壳 UID 下（非系统独立安装的同名包）
  → 壳侧 so：libSDKloading / libchaos / libbaiduprotect 等
  → Dex 侧可见 LGL 菜单痕迹：Category_ / Toggle_ / Floating / SYSTEM_ALERT_WINDOW
```

| 层 | 作用 | 证据 |
|----|------|------|
| 双开容器 | 隔离安装、改签/多开、带 microG | `chaos/`、`cloneapp`、`plugs.ini`、入口 Activity |
| 悬浮菜单壳 | LGL 风格开关 UI（远程 HTML 一类） | Dex 字符串 `Category_`/`Toggle_`/`Floating` |
| Native 加载器 | `libSDKloading.so`（本代约 3.9MB）+ chaos | 与斌哥整包改里更大的 SDKloading 同名；具体 Dobby 点需 **进 guest 对局再 dump** |
| 百度加固 | `libbaiduprotect` + `assets/baiduprotect*.dex` | 静态难直接读业务 |

**和我们星光做法的差别：**

- 星光：改 **游戏包本身**（注入 `libstarry_magic` + SignSpoof），系统里看到的就是游戏包名。
- BUFF：游戏跑在 **虚拟空间 guest**；桌面图标是壳；改法依赖壳对 guest 的注入/预置插件，而不是你系统里那份原版 APK。

## 能抓到吗？

**已经抓到的（本轮）：** 包名、同源壳、Chaos 双开、斌哥免责、无 Unity 的壳本质、与真游戏对照。

**还能继续抓（需要你开着 BUFF 进对应游戏一局）：**

1. guest 进程 maps / `libSDKloading` 是否 Dobby 跳板（同追迹迷城 memdiff 流程）
2. guest `shared_prefs` 里 `"0"`/`"1"`… 开关与菜单 HTML URL
3. 若预置了改包 guest：从 `chaos/data/app` 或下载缓存抠 APK 再 Il2CppDumper

未进局时只能定到「双开壳 + 菜单壳 + 加固」，**不能**捏造具体秒杀/无敌 RVA。

## 构建/分析注意

- 静态拆壳 APK：`apktool` 可拆，但业务在加固 + native。
- 动态：对 **guest 包名** attach（虚拟空间里的进程），不要只 hook 壳包名。
- 真机残留：分析完跑 `04_scripts/_common/cleanup_device_re_residue.sh`。
