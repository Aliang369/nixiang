## 二、封号判定依据（确证 / 推断分离）

### A. 确证
1. 服务端专用码 **`BattleCheat=117`、`BattleCheatData=121`、`UserBeSealed=113`、`VerifyLoginFailed=120`**（75861/75864/75857/75863），并以大写键落在 metadata（0x182bbd3 / 0x182bc20）。
2. 完整重放对账链：帧命令 → `RDoCombatReq.battleRecords_+battleEndByteIndex_+startCombatResp_`(86723) → `ValidateBattleRequest.verifyData_`(86255) → 校验器重跑 → 失败码 `BsVerifyRunFrameError=6805/6810/6809`。
3. **服务端数值合理性校验存在**：`GuildBossDamageAbnormal=300114`(76039)、`MonsterGoldTooMuch=1722`(75956)。
4. 埋点 payload 有显式布尔 **`is_cheat`**（`SinglePlayerBattleEndMsg` offset **0x8**，dump.cs:236183；字面量 0x9A34B60）。
5. `RenderEvent`(400401) 无字段、`BattleEndEvent`(403804-403870) 亦**无 cheat 字段** → 该布尔不由战斗事件携带。
6. 客户端不做本地反调试/反注入；主判在服务端。
7. 封号 UI 通道确证（`ServerBanTipsKey="Server_8"`、`AccountBanKey`、`UserBeSealed=113`）。
8. 上传素材含可重放 `battle.rec` + `worldinitinfo.dat` + 周期 save data，`BattleFrameMask=666` 位掩码保护。

### B. 推断
1. **【推断】`CombatResult.statics_` 键名** = snake_case 短名，与 Tracker 字段同名（`damage_total/damage_max/hit_times/monsters_killed/final_atk/final_hp/is_revive/duration_game/average_fps/owned_skills/death_by/session_id/is_cheat/challenge_times/clear_status/boss_id/exp_earn`）。
2. **【推断】`is_cheat` 由客户端本地启发式置位**（无对应事件字段、无任何 `*Cheat*` 方法名），或由上一场服务端回包 `RDoCombatResp.code_==121` 回灌。
3. **【推断】`BattleCheatData(121)`≈数据面（重放不一致）、`BattleCheat(117)`≈行为面**；连续命中 → `UserBeSealed(113)`。
4. **【推断】`ProtocolRateLimiter.TriggerAlarm`** 为客户端上报频率自检，触发后是否上报未知。
