## 结论速览

1. **【确证】** 注入链三件套：新增 `classes5.dex`(10,792 B) + `assets/dshk_payload.bin`(19,776 B 加密引导 dex) + `lib/arm64-v8a/libunityhelper.so`(13,440 B)；官方 dex/so/manifest 全未改，触发点 = 多 dex 自动加载 + `FileProviderImpl` 静态块 `loadLibrary("unityhelper")`。
2. **【确证】** 引导 dex 再 `InMemoryDexClassLoader` 挂载**云端下发**的面板 dex（`http://js.sheng15.site/dshk_helper.bin` → `com.unity.plugin.CloudPanel`），面板走三方卡密 `wy.llua.cn`（`app=67134`，成功码 `95497`）。
3. **【确证】** 卡密只锁**面板的推值动作**（`o/Q.java:1260-1268` 的 `x0` 判断）；`dshk.cfg` 的配置值由引导层**在鉴权之前无条件直推 native**（LoaderEntry.java:87/101）⇒ 纯客户端鉴权。
4. **【确证】** 卡密包比星光版多 3 项真功能：**一键胜利 `nativeTriggerWin()`**、**全屏吸取 `nativeSetPick`**、**全局加速 1~10 倍 `nativeSetSpeed`**；另多 2 项形态能力（Android 悬浮窗菜单、云端 rows/theme 规格）。
5. **【确证】** 星光版独有「偷盗技能」，且伤害上限更保守（100 且饱和乘法防溢出 vs 卡密包面板**不设上限**）。
6. **【确证】** 卡密包**零过检测、零上报拦截、零反调试**——so 无 `socket`/`mprotect`/`ptrace` 导入，物理上不可能挂上报出口。
7. **【确证】** 它只有三项**不属于反作弊**的隐蔽动作：内存 dex + 加密载荷（抗静态）、`purgeAnonymousVdex()` 删落盘 vdex 缓存（抗取证）、root 静默 `appops` 授悬浮窗权限（权限绕过）；反而把 `dshk_panel.log` 双写到公共 `Download/` 目录（自曝）。
8. **【确证】** 真正的反作弊在游戏侧（`BattleVerifier` + `BattleRecordManager.Upload` + `RDoCombatReq` 重放对账 + `BATTLE_CHEAT` 错误码），卡密包完全没碰。

## 0. 一句话结论

这是一个**第三方卡密平台壳**（非官方、非斌哥、非本仓星光版）：三件注入物（加密引导 dex + 加密载荷 + 单个原生 so）把游戏做成「出厂原版」，卡密验证通过后由**云端下发的悬浮面板**把开关值推给原生 so，原生 so 用 il2cpp 反射改游戏数值。**它没有任何过检测/上报拦截**——反作弊压力全在原版游戏侧。
