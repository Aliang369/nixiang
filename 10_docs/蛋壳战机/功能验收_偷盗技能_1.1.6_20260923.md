# 功能验收卡：偷盗技能（1.1.6 根因重做）

- 游戏 / 版本：蛋壳战机（应用名「弹壳战机」）/ 1.1.6 / vc27
- 菜单项：`Toggle_偷盗技能`
- 用户预期：三选一选择技能后，获得其余未选技能；**相同技能重复出现时应升级**。
- 用户反馈（m00001）：*"盗技能，这个功能好像没效果，不能升级，选了的那些技能实际也没效果，好像是纯 ui 修改"*
- 当前状态：**根因已定位并重做；真机 Hook 全部命中，局内效果待用户进局验收。**

---

## 1. 根因：1.1.5 走的是「列表路径」，不是「授予路径」

1.1.5 的实现是 Hook `HeroComponentRandomSkill.OnAddSkill(int)`，然后对
`RandomSkillResult.ShowSkills` 里的其余候选逐项调用 `AddSkillSurvior(int)`。

反汇编 1.1.6 的同名方法后确认，`HeroComponentRandomSkill` 上这一对方法
（1.1.6 RVA / file offset）：

```text
HeroComponentRandomSkill.AddSkill(int)          RVA 0x6C99AD0  file 0x6C95AD0  首字 0xF81D0FFE
HeroComponentRandomSkill.AddSkillSurvior(int)   RVA 0x6C99BBC  file 0x6C95BBC  首字 0xF81D0FFE
```

两者函数体**逐指令等价**，语义只有两句：

```text
_allSkills.Add(id);      // _allSkills 在 HeroComponentRandomSkill +0x58 (List<int>)
OnAddSkill(id);          // 尾调用 b，不是 bl
```

也就是说：

- 它们只往 `_allSkills`（技能选择 UI 读取的那份列表）里塞了一个 id，
  再尾调 `OnAddSkill` 触发 UI 刷新；
- **完全不经过**真正的授予漏斗：没有 `checkIfReplaced`（重复/升级判定）、
  没有 `PostProcessLearnedSkill`（技能实例化 + flags + `DispatchAddSkill`
  + `entity.OnSkillLearned`）。

因此表现正好是用户描述的「纯 UI 修改」：

| 现象 | 原因 |
|---|---|
| 技能出现在选择面板/列表里 | `_allSkills` 被写入了 id，UI 读的就是它 |
| 选了的技能实际没效果 | 从未实例化到 entity，战斗系统不认识这些技能 |
| 不能升级 | 升级逻辑在 `checkIfReplaced` 里，旧路径根本没走到 |

1.1.5 文档把它记成「重复同名技能不升级」的已知限制，实际上范围更大：
**整条补授都是无效的**，不只是升级缺失。

## 2. 真正的授予链（1.1.6 静态确认）

```text
BaseSkillSelectViewModule.OnSelectSkill(id)
  └─ SelectSlotCommand.Exec                       RVA 0x6A19944
       └─ BattleWorldContext.ApplySelectedSkillsToPlayer   RVA 0x6E7ADA0
            └─ BattleWorldContext.AddSkillToCharacter      RVA 0x6E67534  file 0x6E63534
                 └─ BattleWorldContext.AddSkillToCharacterInSTG  RVA 0x6E675D4  file 0x6E635D4
                      ├─ HeroComponentRandomSkill.checkIfReplaced   RVA 0x6E76C44  ← 重复/升级判定
                      └─ BattleWorldContext.PostProcessLearnedSkill RVA 0x6E76E40  file 0x6E72E40
                           ├─ HeroComponentRandomSkill.AddSkill / AddSkillSurvior   （仅 _allSkills + OnAddSkill）
                           ├─ AddSkillFlags / AddSkillRejectFlags / AddNeedSkill / AddRejectSkills
                           ├─ BattleWorldContext.DispatchAddSkill   RVA 0x6E75B88  ← 真正派发
                           └─ EntityCharacter.OnSkillLearned         RVA 0x6BC7478  ← 技能生效
```

`PostProcessLearnedSkill` 签名（dump.cs:398779）：

```csharp
private void PostProcessLearnedSkill(EntityCharacter entity, int skillId,
        Skill_Main skillData, bool addToComponent, HeroComponentRandomSkill heroSkill)
```

序言 `sub sp, sp, #0xc0`，寄存器映射 x0=this / x1=entity / w2=skillId /
x3=skillData / w4=addToComponent / x5=heroSkill。

它的直接调用者**只有 1 个**：`AddSkillToCharacterInSTG` 内的 `bl 0x6E67AD4`。
所以 Hook 它等于挂在整个授予链的**收敛点**上。

## 3. 1.1.6 新方案

Hook 点从 `HeroComponentRandomSkill.OnAddSkill` 换成
**`BattleWorldContext.PostProcessLearnedSkill`**（file `0x6E72E40`，首字
`0xD10303FF`，argc 5），逻辑：

```text
Hooked_PostProcessLearnedSkill(self, entity, skillId, skillData, addToComponent, heroSkill, method)
  1. ++t_stealDepth，调 g_origPostProcessLearnedSkill(...) 放行原版（原版先把所选技能走完整授予）
  2. 若 !g_stealSkill 或 t_stealDepth != 1 → 返回        （嵌套授予直接放行，防重入）
  3. ReadShowSkillIds(heroSkill)                          （heroSkill +0x88 → RandomSkillResult
                                                           → +0x60 List<int> ShowSkills）
  4. 若候选 < 2 或 skillId ∉ 候选 → 返回                   （排除 InitSkills / 读档等非选择场景）
  5. ShouldInjectOnce(randomResult, 候选集合)              （FNV-1a 签名 + 3 秒窗口去重）
  6. 对其余每个候选 id：
        AddSkillToCharacter(self, entity, id, /*addToComponent=*/true, methodInfo)
```

**为什么这样能升级**：回灌走的是 `AddSkillToCharacter` 而不是
`AddSkillSurvior`，因此每个候选都会重新经过 `AddSkillToCharacterInSTG` →
`checkIfReplaced`（重复判定）→ `PostProcessLearnedSkill`。重复的同名技能
由游戏自己的升级逻辑处理，不再由 mod 手工跳过或去重。

`AddSkillToCharacter` 的 MethodInfo 用 `ResolveMethodPtr(
"HotFix.BattleLogic","BattleWorldContext","AddSkillToCharacter",3, &mi)` 解析
（运行时按名解析，规避混淆改名；file offset 只用于 Hook 落点）。

关键字段偏移（1.1.6 dump.cs）：

```text
HeroComponentRandomSkill._randomSkillResult   +0x88   (RandomSkillResult*)
HeroComponentRandomSkill._allSkills           +0x58   (List<int>)
HeroComponentRandomSkill._replaceSkillDic     +0x40   (Dictionary<int,int>)
RandomSkillResult.<ShowSkills>k__BackingField +0x60   (List<int>)
RandomSkillResult.<AllSkills>k__BackingField  +0x30
RandomSkillResult.<OwnSkills>k__BackingField  +0x58
List<int>: items +0x10 / size +0x18 ；数组 length +0x18 / data +0x20
```

## 4. 防误伤设计

- **只在最外层授予生效**：`t_stealDepth == 1` 才补授；补授自身触发的嵌套
  `PostProcessLearnedSkill` 直接放行，不会递归爆炸。
- **只在真·三选一场景生效**：要求 `skillId` 出现在 `ShowSkills` 候选里。
  这样 `EntityHero.InitSkills`、读档、`TryApplyWorldBossSelection` 等
  同样走 `AddSkillToCharacter` 的路径不会被误判成一次技能选择。
- **同一次选择只补授一次**：`ShouldInjectOnce` 用
  `randomResult 指针 + 候选 id 集合` 做 FNV-1a 哈希，3 秒窗口内同签名只放行一次，
  避免同一次选择里 `PostProcessLearnedSkill` 被多次调用导致重复补授。
- 诊断计数：`g_stealHits` / `g_grantedSkills` / `g_stealNoSelection`，
  日志上限 8 条（`kMaxDiagnosticLogs`）。
