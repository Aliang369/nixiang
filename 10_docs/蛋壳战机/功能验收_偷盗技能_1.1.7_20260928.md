- 游戏 / 版本：蛋壳战机（应用名「弹壳战机」）/ **1.1.7 / vc32**
- 菜单项：`Toggle_偷盗技能`（feat #3）
- 用户预期：三选一选 1 个后获得其余未选技能；**同名技能重复出现时应升级**
- 上一轮结论（1.1.6）：选 1 得其余 = PASS；重复同名不升级 = FAIL
- 本轮结论：实现已重做 + 出包 + 装机；启动链 **PROVEN**；局内升级 **NOT PROVEN**（见 §4）

## 1. 1.1.6 为什么没修好

1.1.6 的假设是「回灌走 `AddSkillToCharacter` → `checkIfReplaced`，重复同名会由游戏
自己升级」。真机否定了这条假设：补授确实成功（`granted=N`），但同名重复没有升级。

1.1.7 的结论（静态 + 反汇编确认）：

- `checkIfReplaced(heroSkill, skillId)` 只负责算出**替换后的 id**；
- 真正写技能表的那一步会**跳过已拥有的 id**（`_allSkills` / `OwnSkills` 里已有该 id
  ⇒ 直接 return，不再授予）；
- 所以把**同一个** `requestedId` 反复交回 `AddSkillToCharacter`，第二次起就是空操作。

同时 1.1.6 的候选循环里显式 `skip 已拥有 id`，正好把升级场景整条挡掉了。

## 2. 1.1.7 的改动

源码：`mod菜单/starry-mod-menu/app/src/main/jni/Games/DkzjMod.cpp`

### 2.1 授予前先做「升级映射」`ResolveGrantId`

```c
int32_t ResolveGrantId(void* hrs, void* skillMain, int32_t requestedId,
                       const int32_t* owned, int ownedCount)
```

- 读 `Skill_Main.UpgradeSkillId`（偏移 `+0x30`，`Il2CppArray<int32_t>`）；
- 若 `requestedId` **已拥有**（在 `owned` 快照里），返回**第一个未拥有的升级 id**；
- 没有下一级 ⇒ 原样返回 `requestedId`，让完整授予链自行拒绝；
- 命中时计数 `g_upgradeRewrites`，日志 `[dkzj] upgrade requested=%d -> granted=%d`。

### 2.2 补授不再跳过「已拥有候选」

候选循环只保留**同一轮候选内的去重**（`if (i > 0 && ContainsSkillId(candidates, i, requestedId)) continue;`）。
已拥有的候选照常进 `ResolveGrantId`，于是走升级映射而不是被丢掉。

### 2.3 owned 快照容量放大

`_allSkills` 快照由 1.1.6 的 32 扩到 `kMaxOwnedSkills = 256`（长局技能数多时
原来的 32 会截断，`ContainsSkillId` 因此漏判）。

### 2.4 日志格式（本轮）

| 场景 | 行 |
|---|---|
| 补授成功 | `[dkzj] steal picked=%d granted=%d first=%d last=%d` |
| 升级命中 | `[dkzj] upgrade requested=%d -> granted=%d` |
| 无额外技能 | `[dkzj] steal picked=%d candidates=%d no extra skills granted` |

诊断日志上限 `kMaxDiagnosticLogs = 8`。

### 4.2 NOT PROVEN 细节

本轮**没有**再进局造「重复同名技能」场景，所以：

- `[dkzj] upgrade requested=… -> granted=…` **未在真机出现过**；
- 不能声称升级链已在真机验证。

用户口述（2026-09-28，逐字）：**"拿全部技能好像可以对强化有效果，武器的升级没效果，先这样吧。"**
⇒ 用户按现状收下本轮，升级效果只作「用户观察」记录，不作 PROVEN。

### 4.3 已知边界（用户决定不继续）

- **武器升级不受本功能影响**：`Toggle_偷盗技能` 只改技能授予链
  （`BattleWorldContext.PostProcessLearnedSkill`）；武器强化/升级走各自入口，本功能不介入。
  用户明确「先这样吧」，本轮不再扩展。
