## 1. 删除「立即胜利」

### 1.1 为什么删（背景事实）

上一轮（m00392）要求「立即胜利改用卡密包的一键胜利挂点」。逆向 `libunityhelper.so` 的结论是：**卡密包的「一键胜利」早已被其作者停用，根本没有挂点可抄**——

- 三个导出变体 `nativeTriggerWin` / `nativeTriggerWin__` / `nativeTriggerWin__I` **都只有 0x2C 字节**，是空日志桩（`w0=0; ret`）；
- so 内明文串：`一键通关已停用（按钮保留，不做任何事）`；
- 云端面板 `o/r.smali` 的 `onClick` 调完 `nativeTriggerWin()` 后**无条件**把按钮文案改成「已触发」，2.5 秒后复位 —— 纯骗 UI。

星光版当时只能自研替代（`BattleWorldContext.SetWinPlayerId` 钉胜方 + `BaseSurvivalBattleManager.OnUpdateHook/CheckEnemyAllDie` 波次驱动）。用户本次直接决定**不做了**，故整体撤除，不留死代码。

## 2. 偷盗技能完善（4 项调整）

现状机制（1.1.6 起）：Hook `BattleWorldContext.PostProcessLearnedSkill`，在玩家选中一个技能后把**同一次三选一的其余候选**逐个回灌 `AddSkillToCharacter`；已拥有的候选走升级链解析。候选来源＝4 个 `set_ShowSkills` 实现（`RandomSkillResult` 0x60 / `AngleViewData` 0x30 / `ContractDevilData` 0x50 / `PunchboardViewData` 0x48）；**宝箱 `BoxSkillResultData` 故意不接**（1.1.7 按用户要求撤掉「宝箱全拿」）。

| # | 调整 | 原因 |
|---|---|---|
| 1 | `PickNextTier` 升级链**补 `UpgradeSkillId_B`(0x150)**，顺序变为 `upgrade(0x30) → upgradeB(0x150) → unlock(0x158) → repeat(0x168) → next(0x84) → cover(0x80)` | `Skill_Main` 有**两条升级链**（`IsUpgrade 0x28/UpgradeSkillId 0x30` 与 `IsUpgrade_B 0x14C/UpgradeSkillId_B 0x150`，dump.cs:309778），双形态技能只填后者 ⇒ 之前这类升级会被漏掉。**不**加 `UnlockUpgradeNeddSkill(0x160)`：那是「解锁所需前置技能」，当升级目标授予会授错技能 |
| 2 | 去重窗口 `ShouldInjectOnce` **3000ms → 800ms**（新常量 `kStealDedupeMs`） | 原意只是压掉同一次三选一的 pre/post/snap 多路重复回调；3s 太宽，技能池连续两次抽到相同候选集合时会被误判重复而**整轮漏给** |
| 3 | 快照有效期 `kSnapshotMaxAgeMs` **30000 → 120000** | 一局内两次三选一间隔常超 30s，超时后候选快照失效 ⇒ 后续选择可能拿不到候选而漏给 |
| 4 | 授予成功日志由 `first/last` 改为**全量 id 列表** `ids=[a,b,c]` | 便于区分「本轮只补了 1 个」与「候选被去重/升级链解析成同一个 id」 |
| 5 | 候选诊断日志增加 `uB=[…]` 与 `upB=` 字段 | 现场确认 `UpgradeSkillId_B` 是否真的被填充 |
