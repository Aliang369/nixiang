## 3. 1.1.8 锚点（现场重抓）

抓点方式：`06_dumped/蛋壳战机/il2cpp_dump_1.1.8/dump.cs`（1,653,151 行）取 RVA，
再按 `file = rva - 0x4000` 换算，最后回读 so 首 4 字节比对 1.1.7 的期望序言
（比中即证明「函数体未被改写」）。归档见 `10_docs/蛋壳战机/抓点_锚点_1.1.8_20261014.json`。

## 7. 装机（关键卡点）

设备上现装的是**官方 `O=gorilla` 签名**的 1.1.8，而星光包是 `CN=StarryMagic`，
二者证书不同 ⇒ `pm install -r -d` 必然 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`。

按 AGENTS 分发红线（§9）本轮**不自动卸载**：
`04_scripts/蛋壳战机/install_dkzj_1.1.8.sh` 默认只做覆盖尝试，失败即打印报告并 `exit 1`。

已实测（2026-10-14 01:40:33，`bash 04_scripts/pipeline.sh 蛋壳战机 run install_1.1.8`；
`pipeline.log` 自第 144048 行）：

```text
[install] push …/蛋壳战机_1.1.8_starry-releaseSigned.apk (46fbc345e2c6a6c29266be39c009074d)
[install] try same-signature cover install
Failure [INSTALL_FAILED_UPDATE_INCOMPATIBLE: Existing package com.survivor.acecn
         signatures do not match newer version; ignoring!]
```

失败后设备**未被改动**：`pm path` 仍指向原
`/data/app/~~lxh-LVyFBsw7xDQ0UTMCZg==/com.survivor.acecn-DFGfh7N5lPKg7p_ceeVYYg==/base.apk`，
`versionName=1.1.8 / versionCode=35` 原版可正常启动；推送的临时包
`/data/local/tmp/dkzj_starry_1.1.8.apk` 已由脚本 trap 自动清理。
除「卸载官方包」外无第二条路——星光包用的是自有 keystore（`01_tools/starry_release.jks`），
拿不到 `O=gorilla` 的私钥，无法做同签重签。

需用户**明确授权**（「允许卸载官方包再装星光包，本地数据清零」）后才执行：

```bash
DKZJ_ALLOW_UNINSTALL=1 INSTALL_GUARD_ALLOW_UNINSTALL=1 \
  bash 04_scripts/蛋壳战机/install_dkzj_1.1.8.sh
```

- 该游戏本地数据在卸载后**清零**（1.1.8 是设备上的全新安装，`firstInstallTime == lastUpdateTime`，
  尚无进度可丢）；按 AGENTS 约定**不建** `09_test/**/backup_*` 备份目录。
- 回退包＝`02_apks/蛋壳战机/蛋壳战机_1.1.8_official_from_device.apk`（`inputs` 已登记 md5）。
- `pipeline.json` 已补 `"install_policy": "overlay_only"`：任何 `adb uninstall` 都被
  `install_guard.sh` 拦住，除非显式 `INSTALL_GUARD_ALLOW_UNINSTALL=1`。
