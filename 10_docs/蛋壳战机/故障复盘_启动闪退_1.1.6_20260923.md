# 故障复盘：1.1.6 星光包「启动即闪退」

- 游戏 / 版本：蛋壳战机 / 1.1.6 / vc27
- 真机：`f9a116a2`（OPPO OPD2404 / OnePlus OP5D77L1, Android 16, arm64）
- 包名：`com.survivor.acecn`
- 用户报障（m00474，逐字）：*"我现在打开游戏闪退，刚装好还可以玩，但是我对局玩了，直接闪退，后面就打不开了"*
- 结论：**mod 自身缺陷（启动期调用 il2cpp 运行时 API），非反外挂误杀、非存档损坏。已修复并在真机验证通过。**

---

## 1. 现象

| 观察项 | 结果 |
|---|---|
| 进程存活 | 启动后 **0.2 ~ 0.7s** 整进程消失 |
| `dumpsys activity exit-info` | `reason=2 (SIGNALED)`，`status=11 (SIGSEGV)`；偶发 `reason=5 (APP CRASH(NATIVE))`，`status=6 (SIGABRT)` |
| `/data/tombstones/` | **无新文件**（最新仍为 `tombstone_31` @2026-09-22 21:16） |
| dropbox | 只有 20:46 那条 `data_app_native_crash`（6607B），其余崩溃**无条目** |
| logcat | **无 `Fatal signal` / 无 `DEBUG` / 无 tombstone 行** |
| events buffer | **无 `am_crash`、无 `am_kill`**（只有 `am_proc_start` / `am_proc_died`） |
| Unity | `Unity   :` 一行都没有 —— Unity 从未真正起来 |

复现次数：20:36 / 20:48 / 20:52 / 20:55 / 20:56 共 5 次，全部同构。

## 2. 关键判据：崩溃点固定紧跟 `[Il2Cpp] api loaded`

MOD 后台线程（tid 25408 / 26112）的应用日志**每次都停在这两行**：

```text
09-23 20:56:37.598 Mod_Menu: [dkzj] AddSkillToCharacter resolved @0x78c99dc534
09-23 20:56:37.598 Mod_Menu: [Il2Cpp] api loaded from libil2cpp.so (xdl+dynsym)
```

然后 **10 ~ 30ms 内进程整体消失**。而 `Dkzj_TryInit()` 末尾那行

```text
[dkzj] lib ready; hooks file-offset + by-name fallback
```

**从未打印** —— 说明死在 `SyncHooks()` 内部的 `ResolveSkillAux()` 里。

四个 file-offset Hook 在此之前全部安装成功（`hooked file=0x...` × 4）。

## 3. 根因

1.1.6 新增的 `ResolveSkillAux()`（`Games/DkzjMod.cpp`）在**每次启动**都无条件多做了一步：

```cpp
ResolveMethodPtr("HotFix.BattleLogic", "BattleWorldContext",
                 "AddSkillToCharacter", 3, &methodInfo);
```

调用链：

```text
ResolveSkillAux()
 └─ ResolveMethodPtr()          → EnsureApi() 打印 "[Il2Cpp] api loaded"
     └─ FindClassNs()
         └─ Api::Assemblies(&count)      ← 第一个真正的 il2cpp 运行时调用
             └─ il2cpp_domain_get_assemblies(domain, count)
```

而这条链有两个致命前提不成立：

1. **`il2cpp_init` 还没跑完**。20:46 那次 tombstone 的调用栈证明 `il2cpp_init`
   是 libunity 在**渲染循环**里调的，不是进程启动早期调的：

   ```text
   #22 com.unity3d.player.U0.run+48
   #17 com.unity3d.player.T0.handleMessage+244
   #15 com.unity3d.player.UnityPlayer.-$$Nest$mnativeRender+0     ← Java 渲染循环
   #12..#09 libunity.so  0x8022d0 / 0x7ea064 / 0x7e9118 / 0x765248
   #08 libil2cpp.so (il2cpp_init+28)  0x3cc0dac
   #07..#01 libil2cpp.so  0x3c7f824 … 0x3d25a18
   #00 libc.so (abort+160)
   ```

   `il2cpp_domain_get_assemblies` 内部要 `Array::New(il2cpp_defaults.assembly_class, …)`，
   运行时尚未就绪时 `il2cpp_defaults` 是空的 → 踩空指针。

2. **MOD 后台线程是裸 `std::thread`，没有 attach 到 il2cpp 运行时**
   （`Il2CppApi.h:46` 的 `thread_attach_t` 注释就写了「非 il2cpp 线程 invoke 前必须」）。
   在未 attach 的线程上做托管分配/线程状态查询同样会踩空。

两者任一成立都会产生**静默 SIGSEGV**：进程没设置成可 dump，debuggerd 不落
tombstone，AMS 也看不到 `am_crash` —— 这正是本次「无任何崩溃痕迹」的原因。

### 为什么 1.1.5 不崩

1.1.5 **从不做启动期 il2cpp 调用**。它的按名解析（`HookResolvedMethod`）只在
file-offset Hook 失败时才走，而实际 4 个点全部 file-offset 命中 → 这条路径从未执行。
1.1.6 把它变成了**无条件启动期调用**，于是「装完第一次能玩（竞态侥幸），
之后每次启动必崩」。

## 4. 修复

原则：**启动期只允许 `/proc/self/maps` 换算，绝不碰 il2cpp 运行时 API。**

`mod菜单/starry-mod-menu/app/src/main/jni/Games/DkzjMod.cpp`：

| # | 改动 |
|---|---|
| 1 | `ResolveSkillAux()` 只保留 `FileOffToVa(kFileAddSkillToCharacter)`，删掉 `ResolveMethodPtr` |
| 2 | 新增 `EnsureAddSkillMethodInfo()`：MethodInfo **惰性解析**，只在 `Hooked_PostProcessLearnedSkill` 里调（游戏线程，il2cpp 必已就绪）；解析不到传 `nullptr`（`AddSkillToCharacter` 非泛型，生成的代码不使用 `method` 参数） |
| 3 | 新增 `AttachCurrentThreadToIl2Cpp()`：`EnsureApi()` → `Domain()` 判空 → `thread_attach(domain)`；所有 il2cpp API 调用前统一走它 |
| 4 | 新增 `g_il2cppRuntimeUp` 门控：`HookResolvedMethod`（by-name 回退）只在它置位后执行 |
| 5 | 置位点：任一 Hook 被游戏线程调到（托管代码在跑），或首次 `Dkzj_Tick`（≥15s） |
| 6 | `InvokeActionBool()` 的 `EnsureApi()` 换成 `AttachCurrentThreadToIl2Cpp()` |
| 7 | 文件头补写本次根因/修复说明 |

## 6. 排查过程中排除的假设（避免下次重复走）

| 假设 | 判定 | 依据 |
|---|---|---|
| 腾讯反外挂静默击杀 | **排除** | `/proc/<pid>/maps` 轮询显示进程死亡时 **`libsecsdk/libsgcore/libthemis` 尚未装载**；且死亡时刻是固定的「紧跟 `[Il2Cpp] api loaded`」而非固定延迟 |
| 存档损坏 | **排除** | `Unity   :` 一行都没有，Unity 从未启动 |
| AMS / 系统击杀 | **排除** | events buffer 无 `am_kill` |
| Java 异常崩溃 | **排除** | events buffer 无 `am_crash`，且是 native SIGSEGV |
| `NoAceStubs.cpp` 去掉 seccomp | **排除** | 崩溃时序与信号屏蔽无关；且 1.1.5 也没有该模块却能跑 |

> ⚠️ 订正：`星空落地_1.1.6` 早期版本写的「蛋壳战机无 ACE」**不准确**。原包确实
> 含腾讯安全组件 `libsecsdk.so`(442K) / `libsgcore.so`(88K) / `libthemis.so`(853K)
> 与字节加固 `libpanglearmor.so`(264K)。只是**本次故障与它们无关**。
> `NoAceStubs.cpp` 的 B 类修法仍然成立（本作无 `libtprt.so`，且菜单类已在
> `classes5.dex`），但理由要改成「无 tprt 系 ACE，不需要 seccomp 信号隔离」。

## 7. 下次会话入口

- 先读本文 §3、§4、§5；不要重新通读全部 logcat。
- 若再遇到「启动即死 + 无 tombstone + exit-info `status=11`」，第一件事是看应用日志
  最后停在哪一行，并用 `/proc/<pid>/maps` 轮询确认死亡时已装载哪些 so。
- 通用铁律：**启动期只允许 `/proc/self/maps` 换算；任何 il2cpp 运行时 API 必须
  等到托管代码已在跑（Hook 被调到 / Tick≥15s），且调用线程必须 `thread_attach`。**
