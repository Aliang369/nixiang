## 3. 借鉴的 TapTap 定案（七条，逐项对照落实）

出处：`10_docs/弹力果冻/TapTap最终收敛_20260912.md`。根因＝mod 后台线程 `Tick` 直接调用热更 `get_Stuff()` / `FindBattleUnitByTeam()`，跨章节对象失效时托管异常穿过 native 边界 → `libc++abi: terminating with uncaught exception of type Il2CppExceptionWrapper` → SIGABRT（`tid=12376, name=m.ginicat.sweet`）。

| # | TapTap 整改条 | 4399 落实方式 | 代码位置 |
|---|---|---|---|
| 1 | 后台线程只设 `refreshWanted`，不再调热更方法 | **同源复用**：`TlgdTapTap_Tick` 只置 `g_refreshWanted` | `Games/TlgdTapTapMod.cpp:917` |
| 2 | `RefreshBattleCache()` 移到解释器 Hook 的游戏线程上下文执行 | 同源：`Hooked_Trampoline` 内 `g_refreshWanted.exchange(false)` → 调 `RefreshBattleCache()` | `:562-603`、`:728` |
| 3 | 游戏线程刷新期间 RAII 重入标记隔离；`get_Stuff()`/`FindBattleUnitByTeam()`/`BattleServer.get_Stuff()` 全部异常兜底 | 同源：`TrampDepthGuard`（`L135-137`）+ 3 处 `catch(...)` | `:292/486/684` |
| 4 | 主目标秒杀只改 `DamageInfo` 后调一次原 `CreateDamage`，不二次 invoke | 同源 | `:586-601` |
| 5 | 全屏秒杀其余敌人走已反汇编确认的 `HpHandle` 原生桥，标 `isBuff + isFromNet` | 同源（`blob.isBuff=1; blob.isFromNet=1;`，`kOffIsFromNet=37`） | `:496-514` |
| 6 | `DamageInfo` 增加完整字段范围校验 | 同源（`kOffInfoIsReal=56`） | 源码 |
| 7 | 敌我 EID 缓存用发布序号快照 | 同源（`CacheReadBegin/CacheReadEnd(seq)`，4 次重试） | `:516-558` |

**唯一需要因渠道而异的改动 = `libil2cpp` 解释器公共点文件偏移。**

## 4. 4399 / TapTap 的唯一差异：偏移 0xBAAB0C vs 0xBABB0C

- 4399 定稿偏移 **`0xBAAB0C`**（历史「斌哥 memdiff 实锤」，2026-08-20/24 用户验收）。
- TapTap 2.4.0 对应函数**前移 0x1000** → `0xBABB0C`。`TlgdTapTapMod.cpp` 原有注释：两包逐指令比对，**26 条中 25 条完全一致，仅一条内部相对分支不同**。

### 4.1 本轮对 4399 底包的独立复核（不信记忆）

`llvm-readelf -l libil2cpp.so`（md5 `b3c74d18e4111fed2d0049088ae21c6d`）：只有两个 LOAD —— ① `off 0x0 / vaddr 0x0 / filesz 0x33A3420 / R E`，② `off 0x33A3420 / vaddr 0x33B3420 / RW`。→ **可执行段 file offset == vaddr**（mod 用「文件偏移」定位的前提成立），`0xBAAB0C < 0x33A3420` ✓。

`llvm-objdump -d --start-address=0xBAAB00 --stop-address=0xBAAB60`：

```
baab08: 17fffff6  b  0xbaaae0            ; 上一函数尾分支
baab0c: a9bd57f6  stp x22, x21, [sp, #-0x30]!   ; ← 干净函数入口
baab10: stp x20, x19, [sp, #0x10]
baab14: stp x29, x30, [sp, #0x20]
baab18: add x29, sp, #0x20
```

✅ `0xBAAB0C` 是干净函数入口（不是函数中部）。

### 4.2 实现方式：编译期宏切换，不复制文件

`Games/TlgdTapTapMod.cpp`（**唯一改动**）：

```cpp
#if defined(STARRY_TLGD_M4399)
static constexpr uintptr_t kFileTrampoline = 0xBAAB0C;   // 4399 定稿
#else
static constexpr uintptr_t kFileTrampoline = 0xBABB0C;   // TapTap 定稿
#endif
```

理由：两渠道共用一份 949 行的稳定实现，**避免复制文件后双份维护漂移**（复制会让下一次修复只打一边）。

### 4.3 产物内 so 反汇编实锤（核验宏真的生效）

```
0x11b14:  mov  w27, #0xab0c
0x11b28:  movk w27, #0xba, lsl #16      → 0xBAAB0C ✓
0x11cd8 / 0x11ecc:  mov #0xab0c + movk #0xba   （日志用）
grep -cE 'movz [wx]+, #0xbb0c'  =  0    → 无 TapTap 偏移残留 ✓
```

## 8. 菜单模板变更（**需用户在后台同步**）

`10_docs/弹力果冻/tlgd_menu_template.json` 已更新：

- `template_id = tlgd`（**未变**）
- `package = com.ginicat.sweet.m4399`
- features 顺序改为 **1 秒杀 / 2 全屏秒杀 / 3 无敌 / 4 无限技能**
- **旧顺序（1秒杀 2无敌 3全屏秒杀 4无限技能）**：即 2026-08-20 定稿顺序，本轮废弃。之所以改，是为了与 TapTap 渠道（`tlgdtt`，1秒杀 2全屏秒杀 3无敌 4无限技能）**逐位对齐**，两渠道同一份功能语义。
- ⚠️ 模板 JSON **只保留规范 5 键**（`template_id`/`name`/`package`/`source`/`features`）—— 早前草稿里额外加的 `note_20261007` 与 `old_order_20260820` 两个键已被移除，因为 `finalize_game_delivery.sh` 的模板校验器断言 `set(d) == {template_id,name,package,source,features}`，多余键会让收尾直接 AssertionError 失败。旧顺序与注意事项改记在本文件（即本节），不再写进模板。

⚠️ **后台模板不同步的后果**：用户买「全屏秒杀」实际开到「无敌」。**这是本次唯一需要用户手工做的事**。
