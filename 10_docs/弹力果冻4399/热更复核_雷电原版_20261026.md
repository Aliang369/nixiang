### 首测失败 → 根因：雷电转译环境下 libil2cpp 没有可执行段（硬约束 G15）

首装后用户实测「所有功能都无效果」。日志实测（不是猜测）：

```
W Mod_Menu: [Tlgd] 解释器公共点解析失败 file=0xbaab0c        # 每秒 ~5 次刷屏
状态 秒杀=1 全屏=1 无敌=1 无限技能=1 hook=0 | tramp=0 … | units=0
```

`/proc/<pid>/maps` 实测（雷电 = x86_64 + ARM 转译）：

```
400023600000-4000269a4000 r--p off=0        .../lib/arm64/libil2cpp.so
4000269b3000-400026d9d000 rw-p off=33a3000  .../lib/arm64/libil2cpp.so
```

**只有 `r--p` / `rw-p`，没有任何 `r-xp` 段**（ARM64 guest 代码由转译器执行）。
旧 `FileOffToVa()` 要求段权限含 `x` ⇒ 恒返回 null ⇒ 钩子零安装；
而 `RefreshBattleCache()` 只在钩子回调里跑（`TlgdTapTapMod.cpp:568`）⇒ **数据型的「无限技能」也一起死**（`units` 恒 0）。
⇒ 四个功能同一个根因，不是各坏各的。**这也解释了 2026-10-07 真机（arm64 直跑、有 r-xp 段）为什么正常。**

**修法**（`Games/TlgdTapTapMod.cpp`）：`FileOffToVa` 改为三段式选段——① 段范围包含 `g_anchorCode`
（= `HpHandle` 的 `methodPointer`，真正被执行的那份 guest 代码视图）优先；② 否则回退覆盖 `fileOff` 的
非可写段；③ 拒绝 `w` 段。首次调用把候选段表与首 16B 打进 logcat。

修复后实测：

```
maps[0] 400023600000-4000269a4000 r--p off=0 base=400023600000 va=4000241aab0c [covers]
FileOffToVa libil2cpp.so off=0xbaab0c anchor=0x40002418e8a0 -> 0x4000241aab0c
公共点首16B a9bd57f6 a9014ff4 a9027bfd 910083fd     ← 与 2026-10-07 真机记录逐字节一致
解释器入口已挂：file=0xbaab0c va=0x4000241aab0c orig=0x7252a61a5000
```

⇒ **houdini 转译环境下 inline hook 可用**（补丁打在 guest 段上、trampoline 生效），前提是取址必须经 anchor 反推。
