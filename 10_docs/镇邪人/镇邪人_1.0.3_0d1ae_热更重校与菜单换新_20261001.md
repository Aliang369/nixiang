# 镇邪人 1.0.3 · 0d1ae 热更重校 + 菜单源码换新（2026-10-01）

## 结论

两件事一次做完：

1. **热更战斗功能再次失效**，与 2026-09-29 同因：服务器 `src` 又从 `e4278` 漂到 `0d1ae`，包内只钉了 `e4278/ca0d4/d5507`，引擎「包内命中优先」落空后走热更缓存，运行时执行的是**未修补**的 `0d1ae` ⇒ `window.__starryZxrOn` 未定义 ⇒ 秒杀/无敌/攻速/全屏秒杀静默失效（免广告与游戏加速走菜单与 Java 层，故看起来「只有战斗功能坏」）。
   修复：`0d1ae` 用同一套 `zxr_patch_spec_b5278.json` 重新打补丁后钉进包内，包内现在四份 pin（`0d1ae/e4278/ca0d4/d5507`）齐全；引擎优先级补丁保持 09-29 形态不变。
2. **native 兜底去版本化**：`Games/ZxrMod.cpp` 的 `se::evalString` 兜底原来只认 5 个固定 bundle 文件名（`index.d5507`/`assets/src/index`/`assets/assets/src`/`index.b5278`/`assets/remote/src/index`）。而热更缓存落盘名是 `gamecaches/<数字>.jsc`（本轮 `17908529187922.jsc`）⇒ **按文件名永远匹配不上，兜底从未生效过**。已整块删掉文件名白名单，改为**内容指纹**判定（1MB~48MB 体积窗口 + 不含 `starry_zxr_safe_v2` + 三个战斗符号名齐全），并新增「补丁脚本 eval 失败就重跑原脚本」的回退分支。这条修的是**这一类漂移**，不只是这一次。
3. **菜单源码换新**：包内 `classes8.dex`/`libstarry_magic.so` 是 09-29 那次构建的产物；本轮用工作区当前 HEAD 的 `mod菜单/starry-mod-menu` 重编，换进游戏。

真机 `f9a116a2` 已同签覆盖安装（`firstInstallTime` 保持不变），冷启动 35s 无崩溃；用户进战斗实测**四项战斗功能全部正常**（G2 证据见「真机验证」一节）。
