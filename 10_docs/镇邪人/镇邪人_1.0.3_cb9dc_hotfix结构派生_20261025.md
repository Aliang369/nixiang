# 镇邪人 1.0.3 · 热更兜底改「结构派生 + 变体表 + 显式告警」（2026-10-25）

## 结论

上一轮留下的残留问题——`Games/ZxrPatchJs.h` 里的**字面锚点**随混淆器改名逐版失效，导致
native 热更兜底从 2026-10-01 起**从未真正命中过**，且 miss 时只打一行 WARN 就放行原脚本
（战斗四项静默失效）——本轮按 **A（结构派生）+ C（显式告警）** 彻底改掉：

1. **结构派生（根治）**：新增 `Games/ZxrDerive.h`，不再写死任何标识符，只认「语义形状」：
   - 定点函数名 `FightChangeEntityHp` / `DamageCommonCalcFinal` / `CalcFinalAtkSpeedValue`（6 个历史版本全在）；
   - 形参位置 + 语句模板；**混淆名与模块别名一律从 bundle 现取**；
   - 命中前先校验「锚点全文在脚本里恰好 1 次」，不赌多命中。
2. **变体表（二级兜底）**：`gen_zxr_patch_header.py` 改为吃**多份 spec**，生成
   `kZxrVariants_<hook>[]`（每钩子 1 条 insert + N 条历史锚点；insert 多份 spec 必须一致才放行）。
   本轮装入 3 条全屏秒杀锚点形状（`b5278` 一代 / `d5507@vc11` / `cb9dc`），伤害与攻速各 1 条。
3. **显式告警（C）**：`BuildHotPatch` 三个钩子任一失败即
   - `W/Mod_Menu: [Zxr] hot-patch MISS: hooks failed: …`（写明哪个钩子、为什么）；
   - 同时经 `ZxrHooks.logStatus` 打一条中文告警：「战斗补丁未命中热更脚本，四项战斗功能将静默失效（请重新出包）」；
   - 从此每条功能日志带 `hot=` 探针：`hot=1` = 兜底已挂上、`hot=2` = 锚点全 miss（功能静默失效）、`hot=0` = 从未介入。

## 后续复查口径（重要）

- 功能日志：`[Zxr] feature #N=… splice=<n> hot=<0|1|2>`
  - `hot=1` 且 `splice=0` = 包内 pin 命中（正常首选路径）；`hot=1` 且 `splice≥1` = 兜底补的（也正常）；
  - `hot=2` = **锚点全 miss**，战斗四项必然静默失效 ⇒ 直接看 `hot-patch MISS` 那行里的钩子名。
- 若 miss：先 `python3 04_scripts/镇邪人/gen_zxr_patch_header.py --out … <新spec> …` 补变体表；
  若派生也失败，说明**函数名或语句形状变了**（不是改名），需要按新明文改 `ZxrDerive.h` 的模板。

## 已知边界（未做，均有原因）

1. **菜单 UI 不会自动置灰**：`hot=2` 目前只有日志 + `logStatus` 告警；要让菜单把 #1~#4 标红/置灰需要新增 Java 方法（`ZxrHooks.notifyHotUnpatched`）并重编 `classes8.dex`——本轮刻意不碰 dex（工作区有他会话未提交的 Java 改动，重编会把半成品带进来）。**建议下次因任何原因必须重编 dex 时顺手加上。**
2. 派生依赖三个函数名不变（6/6 历史版本稳定，但服务端若改函数名 ⇒ 只能靠告警暴露）。
3. 变体表只覆盖见过的锚点形状；未见过的形状靠派生兜住，派生也兜不住就靠 `hot=2` 暴露。
4. **构建产物非逐字节幂等**：`apksigner` 与 `smali` 序列化都会让重复构建产出不同 sha256（大小稳定）。上一轮文档里 `classes7.dex` 记的是首次构建的 `42ac267c…`，**实际交付包是 `79f21a9e…`**（本轮已核，两版包内 classes7 一致）。
