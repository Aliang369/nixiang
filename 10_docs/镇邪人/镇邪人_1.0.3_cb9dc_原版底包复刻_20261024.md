# 镇邪人 1.0.3(vc11) · 官方原版底包 → 星空版复刻（2026-10-24）

## 结论

设备上装的是**官方原版**（TapTap 渠道，1.0.3 / vc11，官方证书 MD5 `8fa00ae1…`），不是星光包。
本轮从**纯原版底包**重建星空版，把 2026-08~10 三轮积累的机制全部复刻回来：

1. **菜单入口**（原版没有）：二进制 Manifest 加 `MenuService` + 悬浮窗/前台服务权限（**保留官方 `JMYBTApplication`，不替换成 StarryApp**）；
   `classes7.dex` 外科补丁 `JMYBTApplication.attachBaseContext` 早期 `loadLibrary("starry_magic")`、`JMYBTActivity` 的
   `onCreate/onResume/onPause/onUserLeaveHint` + `get_ret/set_ret` 静态桥；`classes8.dex` + `libstarry_magic.so` 用 `07_patched/镇邪人/menu_latest` 留档产物（= 2026-10-01 已上机验证的同一份菜单）。
2. **免广告**：`SdkManager.SdkShowAdReward` 前置 `ZxrHooks.shouldSkipAd()` 分支（菜单 `#6` 才有落点）。
3. **TapSign 签名固定**：`assets/sq_plugin_*.apk` 内 `classes4.dex` 的 `TapSignKit.getSign()` 固定回原版证书 MD5 `8fa00ae1…`（插件 `META-INF` 按 apktool b 同口径丢弃）。
4. **战斗四功能**：服务器热更 `src` 又漂了（`0d1ae` → **`cb9dc`**），本轮按新锚点重打补丁并钉进包内（`d5507` + `cb9dc` 双 pin），引擎保持「包内命中优先」。

真机 `f9a116a2` 已**卸载官方原版 → 全新安装**（签名不同无法覆盖），冷启动零崩溃、菜单弹出、`grant` 由用户输卡密后放行；用户实测战斗四项功能**确认没问题**。

## 装机与真机证据

- **装机方式**：签名从官方 `8fa00ae1…` 换成 StarryMagic `83c5cc0b…` ⇒ 覆盖安装必失败，
  经用户确认后 `pm uninstall` → 全新 `pm install`（**干净安装**，符合装机验收口径）。
  脚本：`04_scripts/镇邪人/install_fresh_zxr.sh`（`CONFIRM_UNINSTALL=1` 才动设备）。
  证据：`09_test/镇邪人_cb9dc_20261024/install_fresh.log`（`Success` ×2、设备 base.apk md5 == 本地、
  运行 so md5 `c2b9bf52…` == 包内）。安装后 `firstInstallTime=2026-10-24 23:52:23`，
  `signatures=… version:3 signatures:[6f4dda0b]`。
- **装机预检**：`post_install_precheck.sh --game 镇邪人` → **PASS_TO_HUMAN**，
  证据 `09_test/镇邪人_cb9dc_20261024/precheck_20261024_235310/logcat.txt`：
  `JNI_OnLoad 菜单已加载` → `RegisterNatives 20/20` → `[Zxr] hooked se::evalString for hot-update fallback`
  → `[Zxr] init ok se=1 splice=0` → `[Zxr] 初始化成功` → `MenuService: native menu shown mode=ACTIVITY`
  → `overlayVisible=true` → 空转 2 分钟 `FATAL EXCEPTION|Fatal signal|DEBUGGERD` 计数 **0**。
- **热更路径判据**：启动后设备 `files/gamecaches/src/` **为空**、`cacheList.json` 只有 `resources.8f250`
  条目 ⇒ `src` bundle 没走网络下载 = **包内 pin 命中**（`assets/assets/src/index.cb9dc.jsc`），
  与 09/10 两轮「引擎包内命中优先」预期路径一致。快照：`…/device/cacheList_after_launch.json`。
- **授权墙**：冷启动日志 `[验证] flag=false live=0` → `[验证] grant rejected`（菜单未授权时拒绝开功能），
  需用户在菜单「账号」页用卡密登录；用户完成登录并实测后确认「功能没问题」。
  战斗四项 + 免广告 + 加速为用户终审结论（L3 / G2）。
- **未测场景（NOT PROVEN，显式留白）**：同一局内关→再开、换章节/重开战斗（对象池复用）、
  跨进程开→关→再开、登录/登出切账号、TapTap 登录失败态。

## 复现

```bash
# 0) 底包：设备仍是官方原版时只读拉取（APK 不留本地，用完即删）
adb -s f9a116a2 shell pm path com.zxr.dlxmz.zxrwz37zgx10.gg9b   # → /data/app/.../base.apk
adb -s f9a116a2 exec-out "su -c 'cat <上面返回的路径>'" > /tmp/zxr_orig.apk
#   核 md5 = 0dab73812162a2cab8541431fb972af5

# 1) 热更样本（远端当前版本每次都要重取）
adb -s f9a116a2 exec-out "su -c 'tar -cf - -C /data/data/com.zxr.dlxmz.zxrwz37zgx10.gg9b/files gamecaches'" > /tmp/hot.tar
#   解出 gamecaches/src/*.jsc + cacheList.json，读出 …/remote/src/index.<ver>.jsc 的 version

# 2) 解密 → 打补丁 → 重加密（锚点若变先改 spec）
/opt/homebrew/bin/python3.11 - <<'PY'
# 见 07_patched/镇邪人/<ver>/index.<ver>.json 的哈希与 04_scripts/镇邪人/zxr_patch_spec_<ver>.json
PY
node 04_scripts/镇邪人/test_zxr_patch.js 04_scripts/镇邪人/zxr_patch_spec_<ver>.json   # 7/7

# 3) 出包（原版底包全量注入）
ZXR_BASE_APK=/tmp/zxr_orig.apk ZXR_PIN_VERS="d5507 <ver>" bash 04_scripts/镇邪人/build_star_origbase_zxr.sh

# 4) 静态验收
bash 04_scripts/镇邪人/verify_apk_cb9dc_zxr.sh 08_output/镇邪人/镇邪人_1.0.3_cb9dc_star-releaseSigned.apk /tmp/zxr_orig.apk

# 5) 干净安装（签名变更：卸载 → 全新安装；需用户确认）
CONFIRM_UNINSTALL=1 SERIAL=f9a116a2 bash 04_scripts/镇邪人/install_fresh_zxr.sh \
  08_output/镇邪人/镇邪人_1.0.3_cb9dc_star-releaseSigned.apk

# 6) 装机预检
bash 04_scripts/_common/post_install_precheck.sh --game 镇邪人 --serial f9a116a2
```

管线阶段：`04_scripts/镇邪人/pipeline.json` 的 `cb9dc_origbase_build` / `cb9dc_origbase_install`。
