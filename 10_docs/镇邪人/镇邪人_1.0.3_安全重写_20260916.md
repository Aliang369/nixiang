## 本次重写

### 战斗静态化

不再把旧版运行时字符串拼接作为唯一路径：

1. 解密主逻辑 JS。
2. 在真实函数边界插入带 `try/catch` 的功能块。
3. 重新 `gzip + XXTEA` 成 `assets/assets/src/index.d5507.jsc`。
4. 外科替换回 APK。
5. 静态脚本带 `starry_zxr_safe_v2` 标记，native 看到标记就不改脚本。

离线回归：`node 04_scripts/镇邪人/test_zxr_patch.js`，7/7 通过；完整 patched JS 通过 `node --check`。

### native 热更兜底

`ZxrMod.cpp` 仍保留 `se::ScriptEngine::evalString` hook，但只在以下条件同时满足时工作：

- 脚本不含安全版本标记；
- 文件名或内容匹配主逻辑；
- `DamageCommonCalcFinal`、`CalcFinalAtkSpeedValue`、`FightChangeEntityHp` 三组锚点全部存在。

任何构造异常、锚点缺失或 patched eval 失败都会立即禁用热更兜底并回原脚本，不再反复尝试。

### 菜单防闪退

- `MenuService` / `NativeMenuController` 改用 `MenuSafeHandler`，菜单主线程回调异常被隔离并写 crash log，不再直接带崩游戏。
- heartbeat 用 `finally` 保证单次异常后继续自愈调度。
- 菜单重新生成当前 `classes8.dex`，旧包的 2026-08 菜单框架不再使用。
- `ZxrHooks` 状态改为 `AtomicIntegerArray`，避免菜单线程与游戏线程读写竞争。
