## 1. 事故：打开游戏弹「菜单崩溃！日志：…」

### 现象
用户真机启动星光包，立刻弹 toast「菜单崩溃！日志：/Android/media/<pkg>/files/crash_logs/…」，游戏起不来。

### 根因（游戏自带 cocos2d-x 引擎，不是菜单）
```
java.lang.NullPointerException: Attempt to invoke virtual method
  'boolean java.lang.String.startsWith(java.lang.String)' on a null object reference
    at org.cocos2dx.lib.Cocos2dxDownloader$3.run(Cocos2dxDownloader.java:154)
```
- smali 实证（baksmali classes5.dex）：`.line 133-134` 的 `new URI(val$url).getHost()` 被 `catch URISyntaxException / catch NullPointerException` 覆盖（try 区间 `a..17` **仅**这 2 条），`.line 154` 的 `iget-object domain` + `startsWith("www.")` 落在 try 区间**之外**，NPE 直接冒到主线程 Handler → FATAL。
- 触发条件 = **落盘路径非空 + URL 无 host（相对路径）**。
- 09-16 包的两条路由补丁把远端热更 `src` 强制改成相对路径 `assets/remote/src`（`patch_jsb_engine_zxr.py` / `patch_main_zxr.py`）；当时服务器 src 版本恰好等于包内 `b5278`，走 `inLocal` 从不进原生下载。热更把 src 漂到 **ca0d4** 后包内无此版本 → 落盘路径 + 相对 URL → NPE。
- 菜单 `CrashHandler`（`mod菜单/starry-mod-menu/app/src/main/java/com/starry/magic/crash/CrashHandler.java:181-193`，`MENU_BUILD=framework-20260906`）只是**兜住任何 Java 层异常并弹通用文案**，与崩溃本身无关。

### 证据
`09_test/镇邪人_crash_20260923/`：两份崩溃日志（`crash_2026_09_23-15_18_18.txt` 用户首次反馈、`crash_2026_09_23-15_24_23.txt` 复现）、`apk/base.apk`（md5 与星光包一致）、`jadx_out/`、`smali5/`、`logcat_buffer_dump1.txt`。

## 3. 星空面板回补（用户要求：以后都用这个）

### 问题
2026-09-22 星光紫美化 commit `ed61bcd` 的信息写了「面板底：纯色 → 夜空对角渐变 + 46 颗静态星尘」，但 `--stat` 只改了 `NativeMenuController.java` 与 4 个 md —— **`MagicRes.java` 漏提交**。于是：
- 装机在用的那套菜单（含星空面板）只存在于定型模板 `mod菜单/starry-mod-menu/templates/wxsj_menu_20260922/classes2.dex`（453,036B，含 `MagicRes$PanelBgDrawable`），其后 `build_wxsj_12.10701.sh:136-139` 留有事故注释；
- 仓库源码 `MagicRes.java` 缺 `PanelBgDrawable`、配色也还停在旧紫 `0xFF9B7ED8` ⇒ 用源码重编菜单会丢星空底（这正是"移植新版菜单没有星空背景"的原因）。

### 处理
以定型模板为准重建 `mod菜单/starry-mod-menu/app/src/main/java/com/starry/magic/menu/MagicRes.java`（1099 行）：
- 回补 `private static final class PanelBgDrawable extends Drawable`：夜空对角渐变 `0xF2302A62 → 0xF21E1A44` + **46 颗静态星尘**（`Random(20260922L)` 固定种子，白 `0xFFFFFFFF`/淡紫 `0xFFD8CCFF`/淡蓝 `0xFFBFCFFF`，半径 `rnd*1.2+0.6` dp、alpha `rnd*0.6+0.22`，按 bounds 归一化）；外描边 `1.5dp BRAND_GLOW`、内描边 `max(1f,0.5dp) 0x33A78BFA`；`panelBg()` 由纯色三层 LayerDrawable 改为 `new PanelBgDrawable(dp(ctx,1.0f))`。
- 新紫配色一并回写：`BRAND 0xFF8B5CF6`、`BRAND_DEEP 0xFF7C3AED`、`BRAND_GLOW 0x668B5CF6`、`BRAND_SOFT 0xFFA78BFA`、`LINE 0x268B5CF6`（`0x??9B7ED8→0x??8B5CF6`、`0x??C4B0ED→0x??A78BFA` 全量替换；`switchThumb` 按模板保留旧值）。
- 保留仓库独有内容：`vineCorner(Context,int gravity)` 重载 + `vineFlipH/V/HV`（`NativeMenuController.java:1115` 在调）。

### 核对与提交
- 新 `classes8.dex` 中旧紫 `9b7ed8` 命中 **0**、新紫 `8b5cf6` 命中 **33**；`MagicRes$PanelBgDrawable` 十六进制常量多重集与模板同名类完全一致（仅 `accessFlags 0x1a→0x19`）。

## 7. 后续注意

1. **服务器热更 src 版本变化**（超过 ca0d4）：引擎会改用带 host 的远端 URL 正常下载，**不会再崩**；但下到的是官方未打补丁的 src ⇒ 战斗功能**静默失效**，需按新版本用 `04_scripts/镇邪人/zxr_patch_spec_b5278.json` 重打（该 spec 在 ca0d4 上三锚点全部命中）。
2. **官方发新版客户端 APK**：必须重抓原版包重建（锚点可能漂移）。
3. `CrashHandler` 的「菜单崩溃！」是兜任何 Java 层异常的通用文案，**不能**用它判断崩溃来源。
4. 构建入口：`mod菜单/starry-mod-menu/scripts/surgical_zxr_ca0d4_menu_latest.sh`
   - `ZXR_USE_RELEASE_KS=1` → 正式签名（默认 uber-debug）
   - `ZXR_SKIP_MENU_BUILD=1` → 复用 `07_patched/镇邪人/menu_latest` 菜单留档
   - `ZXR_OUTPUT_NAME=…` → 自定义输出名
5. **每次改菜单源码后必须重编**（`classes8.dex` + `libstarry_magic.so`），否则菜单仍是底包里的旧二进制——本次「菜单不是最新版」就是复用旧底包产物导致的。改完顺手 `git commit && git push`，避免再次出现"模板有、源码没有"的分叉。
