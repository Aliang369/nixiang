## 3. 掉落必掉首轮无效根因

首版实现按 `/proc/self/maps` 顺序取 `libil2cpp.so` 的第一个 `off=0` 映射作为 base。真机上同时存在：

- OPPO 预加载残留的不可执行只读副本（`r--p`），被错误选中；
- 真正由 linker 加载的可执行映射。

结果是 `RandomRange` / `RemoveAt` 的 RVA 序言校验读到错误字节，钩子从未安装。

修复方式：

- 主路径改用 `dl_iterate_phdr` 的 `dlpi_addr` 取真实 load bias；
- maps 兜底按同 inode 的可执行段与 `off=0` 映射配对；
- `VaInLib()` 只认可执行映射；
- 同时清理了上一轮补丁残留的重复 `LibBaseAddr()` 定义。

## 4. 真机验证（2026-09-13）

用户开启“掉落必掉”并完成一局副本，logcat 实测：

```text
[fcxyxzj] libil2cpp base=0x733389C000 (dl_iterate_phdr)
[fcxyxzj] RandomRange hooked @rva 0x35ED058
[fcxyxzj] drop-rate forced @0x1AA07B8 range=[0,100000)
```

同一进程内 `isReady/showAd/getXianjing/addData/subData/RemoveAt` 均成功 `hooked`；
未发现 SIGSEGV / FATAL EXCEPTION。该局命中第 1 个权重概率闸门，其余 5 个分支只有对应掉落分支走到时才会出现日志。

**第二版（2026-09-13 16:11，收官版）**：同副本实测

```text
[fcxyxzj] drop-rate forced @0x1AA07B8 range=[0,100000)   ×3
[fcxyxzj] drop-all replay idx=1/2 (first=0)
```

一局 3 次主池随机 = 首次 1 次 + replay 1 次（index 0 被掩 0 后多走一步）= 掩码设计一致；
无 SIGSEGV / FATAL。但用户实测“还是有问题” → 见 §2 状态与 §7 遗留。

**灵玉（2026-09-14）**：灵玉不是普通字段 —— `PlayerData+0x2A0`（元数据名 `allAdCount`，与用途不符）存的是 **Base64 加密串**
（样例 `JUpLVpp6/yNat62V7etG5Q==`），显示值 = `(解密值−100)/3`、上限 30；全库唯一读值出口 = getter `0x1A58174`。
开启「灵玉不减」后该 getter 恒返回 `9999`（不碰密文），用户确认“确实变大了，也可以兑换”，无崩溃。

**积分（2026-09-14）**：积分是 `PlayerData+0x260`（元数据名 `allShitou`，与用途不符）的 Base64 密文，显示值 = **解密值 − 214**
（实测 raw 216 → 显示 2，与面板“积分：2”完全一致）；唯一读值出口 = getter `0x1A57F74`，3 个调用点里包括
`XxShopItemView::buyBtn` 购买判定。开启「积分不减」后该 getter 恒返回 `9999`，用户确认“功能没问题”。

## 6. 边界

- 本作战斗为本地单机，掉落结算在客户端；未发现运行中的封号/反作弊检测器。
- TapTap 云存档为手动上传 / 下载，不自动回写本地存档。
- `uninstall_official` 阶段因上游变更被自动回退 pending；官方包早已移除，本轮有意不重跑，避免删除当前星光包与本地数据。
- **更新方式（本功能只需换 so）**：新功能全部逻辑与菜单项名都只在 `libstarry_magic.so`（150KB）里，dex 侧无改动；
  菜单运行时从 native 读功能表（`ModBridge.nativeGetFeatureList()` + `FeatureListParser`），所以换 so 后会自动多出第 6 项。
  两条路选一：① 只发 so → 放到 `files/starry_ota/fcxyxzj/libstarry_magic.so`（重启生效）；② 发整包 → 同签名覆盖安装。
  ⚠️ 框架在**覆盖安装新 APK 后会清掉旧 OTA**（防旧补丁 so 挡新包），先推 OTA 再装包 = 白推。
