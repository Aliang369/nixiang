### 5.1 唯一 FAIL：12 字节序言常量没编进 so（**v2 已修，见 §10**）

- **现象**：`kPrologueChangeLife = ff8303d1 e83b00fd fd7b08a9` 在成品 so 全域字节搜索 **0 命中**。
- **根因（源码级实锤）**：`Sf3Mod.cpp:153` 的 `kPrologueChangeLife` 与 `:229` 的 `VaAtFileOffBytes()` 都只有定义、**没有任何调用点** ⇒ clang 把未引用的 static 数组/函数整体丢弃。因此实际生效的只有 `HookSlot.expectInsn` 的 **4 字节首字校验**（`0xD10383FF` 等，§3 已逐个验证）。
- **假阳性提醒**：`0xA9BE57FE` 的字节序列在 so 内有 4 处命中，那是指令自身编码（`stp x30,x21,[sp,#-0x20]!`），不能当常量证据。
- **影响**：启动与三项功能都不受影响；损失的是「挂点真的没漂移」的 12 字节强校验，只剩首字 4 字节。
- **最小修法（只描述，本轮未实施）**：二选一 —— ① 在 `SyncHooks` 的伤害槽安装路径里调用 `VaAtFileOffBytes("ChangeLife", kFileChangeLife, kPrologueChangeLife, 12)`；② 或删掉这两处死代码声明，让文档与产物一致。两条都要**重编 so + 重签 + 重过门禁**，属另开一轮。

## 9. 本轮踩到的 Windows / MSYS 环境坑（下次直接照做）

1. **`pipeline.sh` 指纹自检在本机必失败**：裸 shell 无 `md5` / `shasum`、GNU `stat` 不支持 `-f` ⇒ 统一加前缀 `BASH_ENV=$HOME/.nx_shims.sh`。
2. **`pipeline.json` 里是 mac 绝对路径**（`/Users/aliang/Documents/nixiang/...`）：本机靠 NTFS junction `E:\Users\aliang\Documents\nixiang → E:\nixiang` 兜住；删 junction 的命令只删链接、不删工作区。
3. **`sf3_install.sh` 两处硬缺口**：① 需 `MSYS2_ARG_CONV_EXCL=/data`（否则 `/data/local/tmp/...` 被改写成 `C:/Program Files/Git/data/...`，push 失败且脚本静默退出）；② 本模拟器卸载后 `pm install` 必报 `INSTALL_FAILED_MEDIA_UNAVAILABLE (restorecon)`，只能用 `adb install -r -d --user 0`（Streamed）。
4. **`apksigner` 在本机只有 `.bat`**：MSYS 对 `.bat` 的 `[ -x ]` 恒假 ⇒ 一律用 `[ -f ]` 探测（否则签名者读取与斌哥包拦截整段静默跳过）。另 `apksigner.bat` 经 cmd 转发会拆断含空格的 `JAVA_HOME`，优先 `java -jar lib/apksigner.jar`。
5. **MSYS 会改写 argv 里的远端路径、`exec-out` 会注入 CRLF**：拉 2.7 GB 包必须 `adb pull`（主路径），且 `exec-out su -c cat` 回退在 Git Bash 下比设备端多出 144 B `\r\n` ⇒ 不能当大包的校验来源。
