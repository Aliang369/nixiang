## 2. 签名校验怎么过：MT「ApkSignatureKillerEx」改父类注入

被改的两处官方 dex 差异极小：

```
androidx/multidex/MultiDexApplication.smali
-  .super Landroid/app/Application;
+  .super Lbin/mt/signature/KillerApplication193;
```

游戏 Application 是 `com.accesssdkwrapper.AccessSDKApplicationWrapper` → 继承 `MultiDexApplication`，所以**只改父类**就把杀手插进了 Application 继承链，App 一启动静态块就跑，Manifest 不用动（也就不用 appComponentFactory，绕开了 Android 14 隐藏 API 限制）。

继承链与实现：
```
MultiDexApplication → bin.mt.signature.KillerApplication193 → com.wanda.sf3.wd.PkjNluikmwxGUJv(伪装成游戏包名的壳) → android.app.Application
```
`KillerApplication193.<clinit>`：
```smali
const-string v0, "MIIDSTCCAjGgAwIBAgIEJhYcejANBgkqhkiG9w0B…"   # ← 官方证书 DER 的 base64（CN=sagely）
const-string v1, "com.wanda.sf3.wd"
invoke-static {v1, v0}, Lbin/mt/signature/KillerApplication193;->killPM(String,String)V
invoke-static {v1, "", "", ""}, …->killOpen(String,String,String,String)V
```
`killPM` 的机制（源码常量 `URL = https://github.com/L-JINBIN/ApkSignatureKillerEx`）：
1. `Base64.decode(官方证书, 0)` → `new android.content.pm.Signature(bytes)`；
2. 反射把 `PackageInfo.CREATOR` 字段替换成自定义 `Parcelable.Creator`（内部类 `$l`），构造 PackageInfo 时把**本包**的 `signatures` 换成就地伪造的官方 Signature；
3. 清 `ActivityThread.sPackageInfoCache`（`a(Class,"sPackageInfoCache")` + `getMethod("clear")`）；
4. `killOpen(...)` 顺带处理多开/开放校验路径。

⇒ 所有取签名的路径（Java `PackageManager`、以及 **native 通过 JNI 读 PM** 的 `ConvertUtil::appSignatures`）拿到的都是官方证书，于是：
- C# 侧 `global-metadata.dat` 里那条官方 SHA-1 常量比对通过（无需改 metadata）；
- hoolai `HNDynamic::CongfigSignature` 上报给服务端的签名值＝官方值 ⇒ 服务端校验通过（这正是我们静态补丁过不去的那道门）；
- `HNAccessCore::checkCopyright` 自然返回正版（无需 hook）。

## 3. TapTap 验签与登录怎么过：只改一个 action 常量

```
com/taptap/sdk/login/internal/handlers/client/IntentHelper.smali
-  const-string p1, "com.taptap.sdk.action"
+  const-string p1, "com.tap12tap.sdk.action"
```
把唤起 TapTap 客户端的 action 改成一个不存在的名字 ⇒ 客户端 intent 永远匹配不到 ⇒ login 入口自动落到 **网页（H5）登录**，也就完全避开了 TapTap 客户端侧的调用方签名校验。
（对照：我们改的是 `LoginActivityImpl` 里把 `ClientLoginHandler/PhoneLoginHandler` 换成 `WebHandler`——目标相同，但他的改法改动面更小、不动 handler 语义、也不依赖 `instance-of` 判定链。）

## 4. 菜单与 native 框架

- 注入点：`com/unity3d/player/UnityPlayerActivity.smali` 的 `onCreate` 第一行插
  `invoke-static {p0}, Lcom/android/support/Main;->StartWithoutPermission(Landroid/content/Context;)V`；
- 菜单本体：`classes9`(`com.android.support.Menu/Preferences/BUFF`) + `classes10`(混淆包 `MpYB6`/`mcMWG`/`mini`…) + `classes11`(`j$`/`java` 支撑库)；
- 壳 `PkjNluikmwxGUJv` 里带 `public static webSocketClient (LhcMWG/…/t3;)` ⇒ 菜单配置/开关通过 **WebSocket** 走远端（云端配置型菜单）；
- `libSDKloading.so` = **Dobby 内联 hook 引擎 + Capstone**（伪装名），含 `il2cpp_api_get` / `il2cpp_runtime_class_init` / `il2cpp_thread_detach` ⇒ 玩法 hook 走 il2cpp 原生钩子（与我们框架同路线）；
- `libtoolChecker.so` = RootBeer（root 检测，`Java_com_scottyab_rootbeer_*`）。

## 5. 结论 / 对我们的启示

1. 这个包的验签**必须让"取签名"返回官方值**才能过服务端；纯静态改本地开关/常量都不行（与我们本轮实测一致）。
2. 正确机制＝**在 Application 继承链上装签名替换器**（改 `MultiDexApplication.super`），比 v2 的 `SignSpoof`（appComponentFactory + 隐藏 API 改 PM）更稳，Android 14 用户版可用。
3. 采用该机制后，我们本轮加的三项静态补丁（metadata 签名常量替换、`TapSignKit.getSign` 恒官方 MD5、`libcpp.so checkCopyright` 静态置 1）**全部可以回退**，包体回到"官方字节 + 只加菜单"，改动面最小、也最不容易踩上游 hotfix。
4. TapTap 登录优先采用 `IntentHelper` action 改名（比换 handler 更小）；网页登录链路一致。
