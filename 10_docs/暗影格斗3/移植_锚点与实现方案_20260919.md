### 1.2 TapSDK 结构（反编译实测）

登录 Activity 在 Manifest 中声明：`com.taptap.sdk.login.ui.TapTapLoginActivity`（`exported=false`）。

```
TapTapLoginActivity
  private final LoginActivityImpl impl;      // 构造器内 new，preCreated 时已非空
  public void fallbackToWeb(LoginRequest)    // 转调 impl.fallbackToWeb

LoginActivityImpl
  public static final String FRAGMENT_TAG = "login_fragment";
  public static final String PARAM_REQUEST = "request";
  private final LoginHandler[] loginHandlers = {
        CloudLoginHandler,      // [0] 云游戏
        ClientLoginHandler,     // [1] 拉起 TapTap 客户端 SSO（改签包必失败点）
        PhoneLoginHandler       // [2] 手机号快登
  };
  private final WebHandler webHandler;       // WebLoginFragment 载体

  onCreate(Activity):
    LoginRequest req = activity.getIntent().getParcelableExtra("request");
    for (h : loginHandlers) {
        if (h.canHandle(activity, req)) { ...挂 h.getFragment()...; return; }
    }
    fallbackToWeb(activity, req);            // ← 目标路径
```

- `ClientLoginHandler.canHandle` = `Intent(action).resolveActivity(pm) != null`，**设备装了 TapTap 客户端即为 true**（实测反汇编）。
- `WebHandler.canHandle` 恒 `true`（仅用于 fallback）。
- `LoginRequest` 是 `Parcelable`，位于 `com.taptap.sdk.login.internal.bean.LoginRequest`。

### 1.3 强制网页登录方案（与既有 `TapLoginForceWeb` 的差异）

既有实现里针对该 SDK 形态的两条路都**不适配本包**：

| 既有路径 | 本包实测结果 |
|---|---|
| `forceOldImplWebEarly` 要求 `com.taptap.sdk.ui.TapTapActivity` | 本包无此类 ⇒ 不命中 |
| `forceOldImplWeb` 反射 `activity.request` 字段 | 本包 Activity **没有** `request` 字段（request 在 intent extra） ⇒ `NoSuchFieldException` |
| `sanitize` 把 `ClientLoginHandler` 换成 `CloudLoginHandler` | 能命中 [1]，但 **漏掉 [2] `PhoneLoginHandler`**（`canHandle` 同样可能为 true） |

**本包正确做法（新增分支）**：在 `onActivityPreCreated`（`impl` 已在构造器中就绪）反射取
`impl.loginHandlers`，把数组**每个元素换成 canHandle 恒 false 的代理**，使 `onCreate` 的循环
一个都不命中 → 直接落到 `fallbackToWeb`：

```
Class<?> itf = Class.forName("com.taptap.sdk.login.internal.handlers.LoginHandler", false, cl);
Object noop = Proxy.newProxyInstance(cl, new Class[]{itf}, (p,m,a) ->
        m.getReturnType() == boolean.class ? Boolean.FALSE : null);
Object[] handlers = (Object[]) field(impl, "loginHandlers").get(impl);
for (i) handlers[i] = noop;               // 就地改数组元素（引用是 final，元素不是）
```

理由：`onCreate` 的循环体包在 `try { } catch (Exception) { … }` 里，异常/不命中都会走
`fallbackToWeb`；用恒 false 的代理比「塞 null 靠 NPE 兜底」更干净，也比「换成 CloudLoginHandler」
更完整（后者只清一个槽位）。同时保留 `onCreated` 的 `fallbackToWeb` 兜底与 API<29 的老路径。

### 1.4 签名伪装

`SignSpoof` 已是「按包名回灌原厂证书 DER」的通用设施（killPM）。本包新增一组常量：

## 2. 三项新功能锚点（本轮实测）

### 2.1 战斗速度 —— `UnityEngine.Time.set_timeScale`

| 项 | 值 |
|---|---|
| 目标 | `UnityEngine.Time.set_timeScale(float)` |
| RVA | `0x6BB9C6C` |
| 序言 | `?`（icall thunk，调用约定：`s0`=float，`x0`=MethodInfo*） |

**调用面实测（全 .so 只有 5 处直接调用）**：

| 调用点 | 所属 | 说明 |
|---|---|---|
| `0x6206610` | `LHOBAHKKIDA.HABGLAMIMLP(float)` | 游戏自带时间管理器，**唯一的正常入口** |
| `0x62066A0` | `LHOBAHKKIDA.LPHHCOCCPOB()` | 暂停（置 0） |
| `0x62066CC` | `LHOBAHKKIDA.HOBFGCDFGFC()` | 恢复 |
| `0x5F35424/0x5F354C4` | `Demo.OnGUI` | Unity 示例脚本，与本作逻辑无关 |

`LHOBAHKKIDA.HABGLAMIMLP(float v)` 实测语义：

```c
float c = clamp(v, 0.0f, 1.0f);     // 只接受 [0,1]：游戏侧只能减速，不能加速
this->field_0x30 = c; this->field_0x1C = c;
Time.set_timeScale(c);
Time.set_fixedDeltaTime(this->field_0x18 * c);
if (c < K) Time.set_fixedDeltaTime(this->field_0x18);
```

`HABGLAMIMLP` 的调用者（12 处）全部是表现层：`TimeScaleSlider`（调试 UI）、
`DollyZoomEffect`、`PMCKHGEMPCL`、`SkeletonRagdollController`（布娃娃慢动作）、`LHOBAHKKIDA` 自身。

**实现决策**：**hook `Time.set_timeScale`**，而不是 hook `HABGLAMIMLP`。
- 后者自带 `[0,1]` 钳制，从它入手会被钳回 1.0，加速无效。
- hook 底层 setter 可覆盖游戏的一切设置路径（含暂停 0、布娃娃慢动作），
  且 `v == 0` 时原样放行 ⇒ **暂停语义不受影响**。
- 滑块变更时由 mod 线程直接用原函数指针重放 `last_base * speed`，避免依赖游戏再调一次。

### 2.2 无限体力 —— `IGCAMALALAJ` 能量 API

`IGCAMALALAJ : DHFECDHHIEH, IDisposable`（TypeDefIndex 3962 区段的 3947）是**体力数据管理器**，
由服务定位器 `BCIOEFJGMMA.GPMNAMPACOE()`（`0x5FF868C`）取出。

| 方法 | RVA | 实测语义 |
|---|---:|---|
| `long HJJFFHOJJFB()` | `0x6016A88` | **当前体力**（读 `this+0x10` → `Raids` proto） |
| `long DGCHCFKPNGL()` | `0x6016CE0` | **体力上限**（转调 `FBOABGKBPJP.CBFEAOGHIHE()`） |
| `bool OBPEJEPEJMF(long cost)` | `0x6016CF0` | `当前体力 >= cost`（**够不够花**） |
| `bool EIPOOCIBMBO()` | `0x6016BAC` | `当前体力 < 上限`（是否在回复） |
| `TimeSpan HLBLHGDCPJO()` | `0x6016BD0` | 距下一点体力的剩余时间 |
| `void HJCDGPFOKHM(long)` | `0x6016D0C` | 体力写入 |

**`HJJFFHOJJFB()` 的全部调用点（实测 8 处）**，含关键业务入口：

| 调用点 | 所属 | 说明 |
|---|---|---|
| `0x5C73444` | `EnergyPresenter.Init()` | HUD 体力显示 |
| `0x5C74964` | `FightButtonRaidInfoBattleModule.JKEJGBHIKKB()` | **战斗按钮的体力判定** |
| `0x6016BB0/0x6016CF8` | `EIPOOCIBMBO()` / `OBPEJEPEJMF()` | 内部自用 |
| `0x6015690/0x60156C0/0x601574D8` | `IGCAMALALAJ` 自身 | 刷新/买体力 |
| `0x61A29A8` | `PLCNHKCJCLJ.NIKIFHBPODP()` | 通用「这个价格能否用体力支付」 |

`EnergyPresenter` 的显示口径实测为 `_energyMax = DGCHCFKPNGL()`、
`_energyCount = 钱包[SavedEnergy(11)] + HJJFFHOJJFB()`（`0x5C734D0` 内转调钱包 getter）。

**实现决策**：hook `HJJFFHOJJFB()`（返回大值）+ `OBPEJEPEJMF(cost)`（恒 true）+ `EIPOOCIBMBO()`（恒 false），
开关关闭时全部走 orig。

### 2.3 无限货币 —— `JKJBPEKEBLN` 钱包

`JKJBPEKEBLN : DHFECDHHIEH, IDisposable`（TypeDefIndex 3962）是**钱包**，
由服务定位器 `BCIOEFJGMMA.CEALLPMMJOJ()`（`0x5FF7F0C`）取出。

| 字段 | 偏移 | 说明 |
|---|---:|---|
| `Dictionary<int,long> KKIPKKIIKKE` | `+0x18` | **余额字典**（键 = `CurrencyType`） |
| `List<PJFHFAHJCJC> EOBMDHHJLFE` | `+0x28` | 展示用条目 |

| 方法 | RVA | 实测语义 |
|---|---:|---|
| `long KLFPIPINPKN(int type)` | `0x6016F04` | **取余额**（`this+0x18` 字典 `get_Item`） |
| `bool DEJFONIJAAJ(int type, long need)` | `0x6026A28` | `余额 >= need`（**够不够花**） |
| `bool DEJFONIJAAJ(Currency)` | `0x6018748` | 同上（DTO 版本） |
| `void IGNLJCDGCPB(int,long,event)` | `0x6017008` | 余额变更（含通知） |
| `void CJGNBJPMOOE(int,long,event)` | `0x6019F08` | 余额变更 |
| `long CMBHKKGJBDO(int)` | `0x6027398` | 变更前的旧值（做数字滚动动画用） |

`KLFPIPINPKN(int)` 在整包有 **46 处调用**，覆盖：`CurrencyPresenter`（HUD 货币条）、
`PriceLabel.Init`、`InventoryController`、`PerkListItem`、`SetUpgradeResource.InitCurrency`、
`QuestChestPresenter` / `RaidChestInfoPresenter` / `QuestChestInfoPresenter`、
`CurrencyAdditionalUIInfo`、`BuffSelection`、`EnergyPresenter`（体力显示口径）等。

`CurrencyType` 枚举（实测）：`Coin=1, Bonus=2, Shadow=3, Token=4, RareKey=5, EpicKey=6,
LegendaryKey=7, Ticket=8, Promotoken=9, RaidKey=10, SavedEnergy=11, PerkLvlUp=12,
SuperLvlUp=13, SuperRarityUp=14, StoryPoints=15, RaidKey2=16, BoosterCoin=30, WebCurrency=50,
Clan=60, ArtifactShard=70`。

**实现决策**：hook `KLFPIPINPKN(int)`（命中货币白名单时返回大值）+ `DEJFONIJAAJ(int,long)`（恒 true）。
`SavedEnergy(11)` **归 无限体力** 管，不进货币白名单，避免两个开关互相串味。

### 2.4 服务端权威性（必须写清的边界）

`JKJBPEKEBLN` 的构造器吃一个 `JObject`（Newtonsoft），`IGCAMALALAJ` 持有 `Raids` protobuf DTO
⇒ **余额与体力都是服务端下发的本地镜像**。本方案的「无限」是**客户端口径**：

- 客户端 UI/门槛判定会认（HUD 显示、按钮可点、本地价格判定放行）；
- 真正扣款/扣体力的服务端裁决**未验证**，标记 `NOT PROVEN`；
- 不做任何服务端写操作，也不发 `CHEAT_*` 协议（包内确有整套 `CHEAT_ADD_RAID_ENERGY`
  等 GM 请求定义，但那属于服务端写操作，超出授权范围，本轮不碰）。

  ② 战斗速度在战斗内的实际体感；③ 无限体力/无限货币的客户端生效与服务端接受度；
