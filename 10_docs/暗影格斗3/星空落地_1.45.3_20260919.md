## 3. 实现（native：`Games/Sf3Mod.cpp`）

| 功能 | 挂点（file offset = vaddr − 0x4000） | 语义 |
|---|---|---|
| 伤害倍率 / 上帝模式 | `IKHOBFONGIE.OGFLOMPOMCI` @ `0x5F51968` | 与斌哥同入口：受作用单位 == `self+0x68`（玩家）→ 清零；== `self+0x70`（敌人）→ ×倍率。伤害值容器 `LJMJLLJNEMK` 走 XOR 加解密 getter/setter（`0x5F3AAE8`/`0x5F3AB5C`），**不直写 `+0x10`** |
| 战斗速度 | `UnityEngine.Time.set_timeScale` @ `0x6BB5C6C` | 游戏自带时间管理器 `LHOBAHKKIDA.HABGLAMIMLP` 只接受 `[0,1]`（只能减速）⇒ hook 底层 setter；`value==0` 暂停语义原样放行；改滑块后用 orig 重放 `base×speed`，不等游戏再调 |
| 无限体力 | `IGCAMALALAJ.{HJJFFHOJJFB, OBPEJEPEJMF, EIPOOCIBMBO}` @ `0x6012A88 / 0x6012CF0 / 0x6012BAC` | 当前体力恒 9999 / 够不够恒 true / 是否在回复恒 false |

防闪退设施（骨架强制，均已落盘）：默认 0 hook（开关全关不安装）→ 懒装；file offset 查 `/proc/self/maps` 的 RX 段 + 序言首字/12 字节校验，漂移即拒绝并转按名；幂等（`*orig` 非空 = 已挂，防双 Dobby 叠钩）；orig 必调；`thread_local` + RAII 重入保护（v2 升级，提前 return 不再残留标志）；容器类与单位类指针运行时校验，类型不符宁可不改；菜单桥 Java 侧 `safeCall` 兼底（v2 扩到 `Throwable`）。逐项审查见 §10。

### 3.1 伤害/上帝模式入口的 ABI 推导（静态实证，2026-09-19）

`OGFLOMPOMCI` 的 dump 签名只有 5 个参数，但**实际寄存器位是 8 个**——这是本入口最容易写错的地方：

- 第 1 个参数 `AJJGHOHIMGI` 是**按值结构体**：`AJJGHOHIMGI { HAHPPPNKIGP }`、`HAHPPPNKIGP { int @0x0, AKNBGHNHLAD @0x8 }` ⇒ 共 **16 B**，AAPCS64 下占 **两个**整型寄存器（x1 + x2）。
- 实参落位：`x0=self`、`x1/x2=p1 两半`、`x3=unit`、`x4=value 容器`、`x5=string`、`x6=Action`、`x7=MethodInfo`。hook 侧必须按 **8 参**声明；写成 7 参会把「容器指针」当成 `value` 落到错位位置。
- 交叉印证：函数把 `(Action, self, unit, container)` 存成闭包后 `ldr x0,[closure+0x28]` 调 `0x5F3EA60 = LJMJLLJNEMK.BAALGFECCBG(容器)` → float 与 0 比较（⇒ x4 确为伤害容器）；两个调用点（`AELNHOJJINC` / `BPEFACODFLO`）都是 tail-branch，`x1..x6` 原样透传。
- 容器取值/设值另走实例方法 `JDMGBLEBMAJ` / `JBEFILOFEKD`（非虚调，同一实例），**不直写 `+0x10`**（值经 XOR 加解密）。
- 该推导已写进 `Games/Sf3Mod.cpp` 的类型声明注释，并加「首次 5 次命中」诊断日志（`[sf3]`）供真机核实落位；**运行态命中 = NOT PROVEN**（未装机）。

## 9. 复现链与已知坑

```bash
bash 04_scripts/pipeline.sh 暗影格斗3 status
bash 04_scripts/pipeline.sh 暗影格斗3 next           # 逐阶段
# 装机（需用户授权；卸载官方包要 SF3_ALLOW_UNINSTALL=1）
bash 04_scripts/pipeline.sh 暗影格斗3 reset install   # 上次失败残留 done 时先回退
SF3_ALLOW_UNINSTALL=1 bash 04_scripts/pipeline.sh 暗影格斗3 next   # 用户点名授权卸载官方包+清数据
```

- **>2G 包 zip64 坑（本次实测复现）**：python `zipfile` 的 ZIP64_LIMIT 是 `2^31-1`，输出 2.71 GB 会被写上
  zip64 EOCD + 晚期条目 zip64 extra（`hoff=0xFFFFFFFF`/`vneed=45`）；`zipalign 36.0.0` 走 zip64 路径直接
  `Unable to open ... as zip archive`。修法照搬 Phigros 3.20.0 已实证方案：剥离逐条目 zip64 extra 还原真实 hoff、
  `vneed` 回填本地头版本、尾部改纯经典 EOCD（cdoff < 4G，合法）。本次归一化 726 条后 zipalign/apksigner 全通。
- 该游戏 Manifest 的 `<uses-sdk>` 会被 apktool 重排到最前 ⇒ 逐行 diff 会误报"丢节点"，本脚本已改为**结构化多重集比对**（元素路径 + 属性全值，顺序无关）。
- RVA 通用性来自两包同源（libil2cpp/metadata 同哈希）；斌哥壳独有的 `libSDKloading.so` 原版没有，本方案不依赖它。
- **共用骨架改动的影响面**：`MainModern.cpp` 是所有现代入口游戏共用的 so 源码（sf3 的 `Android_sf3.mk` 只编 `MainModern`，legacy `Main.cpp` 不参与）。本轮已把它加进 sf3 管线 `impl_mod` 的输入快照，之后改共用骨架会被陈旧度门禁拦下并要求重跑构建链。
- **`classes8.dex` md5 非同源可复现**：同一份 Java 源码（mtime 01:29/01:31 未变）两次出包得到 `9fb37170…` / `3e8f4362…` 两个 md5 ⇒ 跨会话比对别用 dex md5，用「含哪些类/常量」与 §5 的声明交叉校验（本包已逐项复验 `com.wanda.sf3.wd` / `PhoneLoginHandler` / 证书 base64 / `TapLoginForceWeb` / `SignSpoofAppComponentFactory` 全在）。
- **install 假成功坑（2026-09-19 首次装机实测）**：`sf3_install.sh` 原 58 行把变量写成 `$PKG（数据…）`，bash 3.2 会把紧跟的多字节字符当成变量名一部分 ⇒ `set -u` 报 `PKG�: unbound variable`，脚本在卸载分支前崩溃；EXIT trap 末条命令成功又把退出码吞成 0 ⇒ 管线把 install 误标 done（实际设备仍是官方包）。修复=`${VAR}` 括号写法 + trap 保码（`rc=$?; …; exit $rc`）+ 只有闭环校验通过才写 `.install_ok` 成功戳，管线 install 的 `verify` 改为 `file_exists .install_ok`。
- legacy 入口 `Main.cpp` 里同款 `Preferences.Changes` 空桩**未动**（存量游戏仍走该文件，本轮范围只到 sf3 所用骨架）。
