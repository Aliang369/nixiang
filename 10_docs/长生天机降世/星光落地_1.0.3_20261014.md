## §2 挂点重定位（增量核对，非全量重逆向）

挂点 = HybridCLR `InterpFrameGroup::EnterFrameFromInterpreter`。

**1.0.3 结论：file `0x2657350` / VA `0x265b350`，与 1.0.2 同址。**

历史链：

| 版本 | file 偏移 |
|---|---|
| 0.9.10 | `0x2656920` |
| 1.0.1 | `0x2657084`（VA `0x265b084`） |
| 1.0.2 | `0x2657350`（VA `0x265b350`） |
| **1.0.3** | **`0x2657350`（VA `0x265b350`）** |

判据（1.0.3 官方 so 逐指令复核，四处同址即定案；寄存器分配差异不影响判定）：

```
265b350  str  x30, [sp, #-0x30]!   ← 函数入口（上一 prologue 0x265b008，下一函数 0x265bb50）
265b368  mov  x20, x1              ← MethodInfo 存档
265b36c  bl   0x26cf1f4            （1.0.2 记为 bl 0x26cf0ac，该 helper 移位 +0x148）
265b370  ldr  x8, [x20, #0x58]     ★ 与 1.0.2 同址同指令（InterpMethodInfo）
265b378  ldr  w9, [x8, #0x2c]      ★ 同址同指令（maxStack）
265b37c  ldr  w11, [x9, #0x20]     （1.0.2 文档记为 ldr w8,[x8,#0x20]＝argStackObjectSize）
265b384  sub  w15, w15, w8
265b388  bl   0x265b3c4            ★ 同址同目标（AllocStackSlot）
265b390  bl   0x265b430            ★ 同址同目标
265b3a0  stp  x20, x19, [x0]       ★ 帧压入 {MethodInfo, argBase}，不拷参数
```

旁证：

- `0x265b350` 全 so **有且仅有 6 个 BL 引用**：`0x2667f08 / 0x26685f0 / 0x2668700 / 0x2668930 / 0x2668af0 / 0x2668b48`，**全部**落在 `Interpreter::Execute` 候选体 `0x265d1a8 + 0xd618`（上界 `0x266a7c0`）之内 ⇒ 符合「被 Execute 内部稀疏引用」语义（1.0.1 时为 16 处）。
- `Interpreter::Execute` 候选 VA `0x265d1a8` 与 1.0.2 记录**完全相同**（`04_scripts/_common/find_hybridclr_interp_entries.py --region 0x2600000:0x2700000` 独立列出）⇒ 解释器区域布局稳定。
- 全 `.text` 严格签名（`ldr xT,[xN,#0x58]` 后 +8 为 `ldr wA,[xT,#0x2c]`）扫描**全仓仅 4 处**，其中只有 `0x265b370` 在 +12 处带 `[?, #0x20]` 偏移，其余 3 处（`0x4ff825c` / `0x51f5bcc` / `0x580a79c`）立即排除 ⇒ `0x265b370` 唯一命中。
- 1.0.2 文档里 `ldr w8,[x8,#0x20]` / `sub w1,w9,w8` 两条系从 1.0.1 记录沿用，非逐字反汇编；1.0.3 实测**寄存器分配不同（x9 中转）但语义与偏移完全一致**，不影响挂点判定。

反汇编手段说明：该 so 被剥掉 section header（仅存 `.note.gnu.build-id` / `.dynstr` / `.dynamic` / `.shstrtab`），`llvm-objdump --start-address` 不可用，须走 `04_scripts/_common/so_inspect.py disasm <so> --off 0x2657350 --va 0x265b350 --n 28`（内置 capstone）。
