### 挂点复核证据（1.0.3 官方 `libil2cpp.so`，`so_inspect.py disasm`）

```
265b350  str  x30, [sp, #-0x30]!   ← 函数入口（上一函数入口 0x265b008，下一函数 0x265bb50）
265b368  mov  x20, x1              ← x1 = MethodInfo 存档
265b370  ldr  x8, [x20, #0x58]     ★ 与 1.0.2 同址同指令
265b378  ldr  w9, [x8, #0x2c]      ★ 与 1.0.2 同址同指令
265b388  bl   0x265b3c4            ★ 与 1.0.2 同址同目标（AllocStackSlot）
265b390  bl   0x265b430            ★ 与 1.0.2 同址同目标
265b3a0  stp  x20, x19, [x0]       ★ 帧压入 {MethodInfo, argBase}，与 1.0.2 同址
```

- `0x265b350` 被 Execute 体内 **6 处** BL 引用：`0x2667f08 / 0x26685f0 / 0x2668700 / 0x2668930 / 0x2668af0 / 0x2668b48`（全部落在 `Interpreter::Execute` 候选体 `0x265d1a8 + 0xd618` 内）
- `Interpreter::Execute` 候选 VA `0x265d1a8` 与 1.0.2 记录**完全相同**（`find_hybridclr_interp_entries.py` 独立列出）
- 相邻两个 callee（`0x265b3c4` / `0x265b430`）反汇编为 HybridCLR 解释器手写风格（用 `x28` 作值栈指针、`str x27,[x28,#-0x20]!`），确认该函数属解释器核心
- ⚠ 1.0.2 文档记的 `ldr w8,[x8,#0x20]` / `sub w1,w9,w8` 两条，在 1.0.3 上实测为 `ldr w11,[x9,#0x20]` / `sub w15,w15,w8`（**寄存器分配不同，地址相同**）；文档那两条系从 1.0.1 记录沿用，不影响挂点判定 —— 判定依据是函数入口 + 两处 `bl` 目标 + `stp x20,x19,[x0]` 帧压入四处同址
