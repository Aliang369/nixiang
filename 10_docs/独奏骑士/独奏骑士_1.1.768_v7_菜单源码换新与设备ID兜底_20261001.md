## 设备ID问题定位（本轮真正修的东西）

`auth/DeviceFingerprint.smali` 新旧差异只有两处：新增字段 `VERSION_LEGACY_V4 = "v4"`、新增方法 `getV4()`（转调 `computeLegacyV4HardwareId()`）。其余（`VERSION="v5"`、`SHARED_REL_DIRS`/`ABS_SHARED_DIRS`、`BROKEN_SSAIDS`、`getLegacyIds()`、`readIdsFromOtherPrefsViaSu()`、`isValidDevId()`）完全相同。

`menu/Preferences.getOrCreateDeviceId()` 新旧对照：

| 分支 | 旧 dex（机身 v6） | 新 dex（v7，本轮换入） |
|---|---|---|
| 首选 | `DeviceFingerprint.get()`（v5 SSAID） | 同左 |
| 命中缓存 | `stable.equals(cached) && "v5".equals(version)` → 直接返回 | 同左 |
| 落盘 | `auth_device_id=stable`、`auth_device_id_version="v5"` | 走 `saveDeviceId(id, version, legacy)`，版本按实际来源写 `v5` 或 `v4` |
| **SSAID 不可用时** | **直接抛** `IllegalStateException("设备标识不可用：系统 ANDROID_ID 缺失或无效")` ⇒ 菜单/卡密不可用 | **回落到 `getV4()`**（`sha256("ver=v4|board=|hw=|manu=|brand=|model=|device=|product=")` 前 32 位），以 `v4` 版本落盘并继续登录 |
| 两路均不可用 | — | 抛 `IllegalStateException("设备标识不可用：v5/v4 均缺失，需要解绑设备后重新绑定")` |

新增私有方法：`legacyCandidates(cached, preferred)`（= `getLegacyDeviceIds()` ∪ `{cached}` ∪ `getLegacyIds()` \ `{preferred}`）、`saveDeviceId(id, version, legacy)`。`legacy_device_ids` 仍随 `/v1/auth/login` 上报，供 auth-server 把历史绑定迁移到当前主 ID —— 这条链路新旧一致，**本轮的差异只在「SSAID 拿不到时不再砸场子，而是退到 v4」**。
