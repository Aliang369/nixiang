## 2. 斌哥壳 hook 机制（核心）

- **hook 点**：libil2cpp.so RVA `0x20b840c`（file_off `0x20b440c`），HybridCLR 方法调用/解释器入口
- 原指令 `LDR X0,[X8,#0x3F8]` → Dobby 改为 `B veneer`（内存中拆分出 4KB 页）
- veneer 跳转到斌哥壳 replacement：`0x7575a613a4`（在斌哥壳 r-xp anon:.bss 段，偏移 `0x443A4`）
- **replacement 逻辑**：
  1. 校验参数指针（`0x7575a693a0`）
  2. 从 x1（MethodInfo）提取方法名 → x22（`0x7575a693c4`）
  3. 运行时 XOR 解密字符串表（每字节异或 key，key 内嵌代码中）
  4. `strcmp(方法名, 目标)` 过滤（`0x7575a5c4c0` = strcmp PLT）
  5. 命中 → 按功能 flag 改参数/返回值
  6. 最后 `ldr x8,[GOT+0xfd0]; br x3` 调用**原函数 orig**

## 3. 功能 ↔ 方法名 ↔ 行为 对照表（完整）

| 功能 | flag | 拦截方法 | 判定 | 行为 |
|------|------|---------|------|------|
| 百倍伤害 | `[0x728]` | `calTotalDamage` | 敌方 `[obj+0x80][*0xa8] != 1` | 伤害缓冲 `x2+0x18` ← `0x469C3E00`（20000.0f）或 `w8-1.0` |
| 百倍伤害 | `[0x728]` | `calDamageBuffer` | w4(0xa8) ∈ [2,8] | 伤害 `x2` ← `0x4CBEBC20`（≈1e8） |
| 无敌 | `[0x72c]` | `calDamageBuffer` | w4 == 1（友方） | 伤害 `x2` ← `0.0f`（归零） |
| 无敌 | `[0x72c]` | `AddRtHPTo` | 友方 `[0xa8]==1` | `x2+8` ← `0x497423F0`（1,000,000.0f 加血） |
| 无限技能 | `[0x730]` | `isCdOK` | 友方 | 技能对象 `+0x2ac` ← 0（CD 清零）；条件 `[+0x18]>=0x52` |
| 无限技能 | `[0x738]` | `isManaOk` | 友方 | 技能对象 `+0x5c` ← 1（蓝量够用） |

- flag 区：斌哥壳数据段 `0x7575b1e000`（偏移 `0x728/0x72c/0x730/0x738` 等字节）
- 计数器：`0x768/0x76c/0x770/0x774/0x778`（每 5-10 次调用打一次日志）
- 敌我判定字段：对象 `+0x80` → 结构 `+0xa8`（1=友方/玩家，2-8=怪物类型）

## 5. 抓取路径复盘（工具/方法）

1. 原包 551MB 从设备拉取；斌哥容器 63MB 拉取
2. 静态初判：Unity IL2CPP + HybridCLR（`HybridCLR_Loader`/`Solo.GameCode.dll`），斌哥容器 = cloneapp 双开
3. `dump_binge_shell_mem.sh` 抓内存 → `diff_il2cpp_mem.py` 找到 Dobby hook 点 RVA `0x20b840c`
4. 反汇编 veneer（4KB anon r-xp）→ 定位 replacement `0x7575a613a4`（斌哥壳 r-xp anon:.bss 段 = dump 脚本的 `shell_rx_bss.bin`，**此前误判为加密数据，实为可执行代码**）
5. 反汇编 replacement + 从数据段（`bg_data.bin`，0x7575b1d000 起 160KB）提取明文方法名
6. 确认 flag/判定/行为
