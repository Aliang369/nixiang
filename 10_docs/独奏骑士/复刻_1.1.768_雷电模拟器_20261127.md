## 结论

1. **官方 1.1.768 底包在 Windows 侧完成了全链路外科复刻**：底包 `02_apks/独奏骑士_1.1.768.apk`（578,593,691 B / md5 `ccf1b28bf7b4b9d9a950bc7a86fbaf9e`，与 2026-09 那轮用的底包**字节级同一份**）→ 产物 `08_output/独奏骑士/独奏骑士_1.1.768_surgical-releaseSigned.apk`（579,659,984 B / md5 `02fa2e0f2edfa96cf96d2b799bb35baf`），1879 个 zip 条目逐条审计通过，签名证书 `83c5cc0b…`（v2+v3）。

4. **证据分级**：产物哈希、dex/so 指纹、挂点偏移、crcCode 复算、运行期日志＝实测；「houdini 对已改写代码块会重译」＝**推断**（hook 生效本身是实测，重译机制未单独验证）。

## 静态复核

### 挂点

| 项 | 值 | 判据 |
|---|---|---|
| 文件偏移 | `0x20B5A40`（`FILE_ENTER_INTERP`） | `DzqsMod.cpp` 枚举常量 |
| 段 | `.text` off `0x1C5B274` / addr `0x1C5F274` | `p_vaddr − p_offset = 0x4000` |
| VA | `0x20B9A40` = `0x20B5A40 + 0x4000` | 同段内换算，与 `dump.cs` 的 `Offset`/`RVA` 口径一致 |
| 函数性质 | HybridCLR 建帧 helper，函数长 `0x70`，被解释器分发函数 **16 处** `bl` 调用 | 反汇编统计调用点 |
| 参数语义 | `a1 = Il2CppMethodInfo*`（`name` @ `+0x18`）、`a2 = 8 字节参数槽数组` | 结构读取 + 运行期按名过滤生效 |

函数性质决定实现方式：这是**公共入口**，所以三项功能都靠 `a1->name@+0x18` 做方法名过滤后分流（`isCdOK` / `isManaOk` / `calDamageBuffer` / `AddRtHPTo`），而不是各挂一个具体方法。

复现（命令 + 判据）：

```bash
# 1) 确认 `.text` 的 p_vaddr − p_offset（本例 0x4000），不要当通用常数
readelf -lW libil2cpp.so | grep ' LOAD '     # 取 Offset / VirtAddr 两列，两者之差即 p_vaddr − p_offset（本例 0x4000）
readelf -SW libil2cpp.so | grep -w .text     # 判据：off=0x1C5B274 addr=0x1C5F274

# 2) 按文件偏移取函数体，判据：起 0x70 字节是完整函数（结尾是 ret/br），
#    且该地址在全镜像里被 16 处 bl 指向
python -c "import sys;f=open('libil2cpp.so','rb').read();o=0x20B5A40;print(f[o:o+0x70].hex())"
```

判据是三件同时成立：偏移落在 `.text` 内、`off+0x4000` 处的序言能被反汇编成合法函数、该地址的 `bl` 引用数为 16。三者任一不符即说明拿到的是别的构建，**不要装机试**。

## 环境差异：houdini 转译层里 arm64 库没有可执行段

雷电模拟器 `emulator-5554`：Android 14 / SDK 34，**x86_64 + houdini 转译**，root。arm64 的 `libil2cpp.so` 在 `/proc/self/maps` 里只有 `r--p` 与 `rw-p` 两种权限——**没有 `x` 段**，因为执行是 x86_64 侧对译文的执行，guest 代码段本身不可执行。

`FileOffToVa()` 原实现只在命中带 `x` 的段时返回候选，于是每次都返回 `nullptr`，日志每 200 ms 刷一行 `[Dzqs] resolve enter-interp failed file=0x20B5A40`，`g_hooked` 永不置位、功能自然全哑。

修法（`Games/DzqsMod.cpp`）：**可执行段优先，无 `x` 段时退回只读段**——遍历时遇到带 `x` 的命中立刻返回（真机行为不变），否则记住第一个「区间覆盖 fileOff」的候选，扫完后返回它。判据从「必须有 x 段」放宽为「区间覆盖即可」，因为真正决定正确性的是 `off ≤ fileOff < off + (end-start)` 这个区间关系，权限位只是排序偏好。

修后日志：

```
[Dzqs] hooked enter-interp @ 0x4000254b9a40 TRACE=0 DMG_WRITE=1
```

三点可复用的结论：

1. **按文件偏移换算 VA 的代码不能把 `x` 段当必要条件**；权限只用于「多命中时选哪个」。
2. **Dobby inline hook 在该环境下实测有效**（钩上后 patch 计数持续增长），即转译层并不阻止对 guest 代码段的改写；「改写后 houdini 会重译该块」属推断，本轮未单独验证。
3. 该环境的失败形态是**静默的**：不崩溃、不报错，只有一条循环日志。看到「功能没反应 + 某 resolve 行反复刷」先查段权限，别先怀疑挂点。

## 本轮两处构建修复

### ① 公共 `Android.mk` 的 wxsj 预编译残留

`app/src/main/jni/Android.mk` 里仍声明 `wxsj_dll_hf2` / `wxsj_dll_hf3` 的 `PREBUILT_STATIC_LIBRARY` 并挂进 `LOCAL_STATIC_LIBRARIES`，而磁盘上的 `.a` 早已改名为 `WxsjVc1637Hf2Dll.a` / `WxsjVc1637Hf3Dll.a`（工作区里已不存在旧名的 `.a`，只有带前缀的新名）⇒ 本机 `ndk-build` 在解析阶段就 abort，**与做哪个游戏无关**。

处置：删掉这两个声明与引用，让各游戏自己的 mk 负责——`Android_wxsj_vc1637.mk` 声明 `wxsj_vc1637_dll_hf2/hf3/hf4`（带前缀名），`Android_wxsj_legacy.mk` 声明 `wxsj_dll_hf2…hf6`。公共文件只留「按 `STARRY_GAME_*` 选源文件」的职责。

判据：`Android.mk` 全文不再出现 `dll_hf` 的 `LOCAL_MODULE`/`LOCAL_STATIC_LIBRARIES` 行（只剩注释里对历史命名的一句说明）；`Android_wxsj_legacy.mk` 仍有 6 处、`Android_wxsj_vc1637.mk` 有 3 处自己的声明；`STARRY_GAME_DZQS=1 ndk-build` 能跑到编译而不是 abort。

### ② DZQS 覆盖段的 game 宏过滤

`Android.mk:291` 原为：

```make
LOCAL_CFLAGS := $(filter-out -DSTARRY_GAME_WDYZ,$(LOCAL_CFLAGS)) -DENABLE_UNITY_HOOK -DSTARRY_GAME_DZQS
```

问题：公共段第 143 行会加 `-DSTARRY_GAME_ZHMR`，只滤 `WDYZ` 就把它漏了过去，`LOCAL_CFLAGS` 里同时存在 `ZHMR` 与 `DZQS`；`GameConfig.h:60` 的 ZHMR 分支在前，先命中 ⇒ 鉴权 `game_id = "zhmr"`。

修法：改成通配 `-DSTARRY_GAME_%`，一次性滤掉所有 game 宏再只加 `DZQS`：

```make
LOCAL_CFLAGS := $(filter-out -DSTARRY_GAME_%,$(LOCAL_CFLAGS)) -DENABLE_UNITY_HOOK -DSTARRY_GAME_DZQS
```

判据（so 字节计数，已写进构建脚本做回归断言）：`dzqs=1 / zhmr=0 / [Dzqs]≥1 / Toggle_=3`。修前实测是 `dzqs=0 / zhmr=1`——**「功能看着能用」不能代替这条断言**，因为 `game_id` 错只会影响鉴权链，不报错。

## 边界

- 本轮只交付「官方 1.1.768 复刻」，功能集固定为 `百倍伤害 / 无敌 / 无限技能` 三项，未新增菜单项（`Toggle_` 计数 = 3 即门禁）。

- 环境结论（无 `x` 段 + Dobby 有效）只对「雷电 + houdini + 该包」成立，跨模拟器（MuMu/BlueStacks）需另行取证。
