# 星光菜单热更方案（魂坠 / 通用）

> 目标：游戏热更后由我们适配，玩家在设置里**手动点更新**下载小补丁，**不用重装整包游戏**。  
> 锁定规则：JSON + so **兼容共存**（合并进同一份 latest）；**均须完全划掉游戏再开**；服务端每 `game_id` 只保留 **一份 latest**。

---

## 能力分层

### L1 — Bootstrap（已有）

公告 / 功能上下架 / QQ / 是否强制卡密 — 重开菜单或心跳即生效，不换包。

### L2 + L3 — 游戏补丁 OTA（已落地）

| 产物 | 路径（服务端） | 本机 |
|------|----------------|------|
| 清单 | `data/ota/{game_id}/latest/manifest.json` | `files/starry_ota/{game_id}/manifest.json` |
| 小补丁 JSON | `…/patch.json` | 同名 |
| 玩法 so | `…/libstarry_magic.so` | 同名（有则优先于 APK 内 so） |

**JSON 与 so 不是二选一**：

| 今天 | 明天 | latest 结果 |
|------|------|-------------|
| 只发 so | 只发 JSON（ver+1） | **两边都有**（so 保留 + JSON 更新） |
| 只发 JSON | 只发 so | **两边都有** |
| 两个一起发 | — | 两边都更新 |

客户端按 **ver** 判断有无更新；下载后重启，同时加载 so + 应用 JSON。

---

## 后台上传

管理网页 `/admin/` → 侧栏 **游戏补丁**：选游戏 → 看当前 latest → 填更大 ver → 选 JSON 和/或 so → 发布。

也可用脚本：`scripts/publish_play_ota.sh`。

---

## 玩家流程

1. 设置 → **游戏补丁** → **检查更新**  
2. 有新版本 → 确认 → 合并下载到 `files/starry_ota/{game_id}/`  
3. Toast：**请完全划掉游戏再开**  

---

## 运营流程

1. 等游戏官方热更先上  
2. 我们适配后发 OTA（只发改动的一侧即可）  
3. 游戏未热更则不要发  

`manifest.sig` = HMAC-SHA256(`grant_hmac_secret`, `game_id|ver|json_sha|so_sha|note`)。

## 防重复 / 限流

| 层 | 措施 |
|----|------|
| 客户端 | `ver` 已最新不下文件；本地 sha 一致跳过该文件；下载中互斥锁 |
| 服务端 IP | manifest ≈40次/分；**JSON ≈20次/时**；**so ≈8次/时**（可配） |
| so 鉴权 | 默认需有效卡密会话 `Authorization: Bearer <token>`；仅联网游戏可设 `OTA_SO_REQUIRE_TOKEN=false` |

环境变量示例：`OTA_SO_MAX=8` `OTA_JSON_MAX=20` `OTA_SO_REQUIRE_TOKEN=true`

## 删除补丁（省磁盘）

后台 **游戏补丁** 页：删 JSON / 删 so / **清空全部补丁**。  
API：`DELETE /v1/admin/ota/{game_id}?what=all|json|so`  
换整包分发后建议 `what=all`，玩家检查会显示暂无补丁。
