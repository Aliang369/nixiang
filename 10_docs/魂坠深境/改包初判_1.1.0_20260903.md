## 1. 引擎 / 壳 / 保护面变化（关键）

| 检查项 | 1.0.5（旧） | 1.1.0（新） | 结论 |
|--------|------------|------------|------|
| 引擎 | Unity IL2CPP + HybridCLR | 同（`HybridCLR.RuntimeApi::PreJitClass` 等串仍在 so 内） | 引擎未变 |
| 壳 so | `libSDKloading.so`≈3.9MB（运行时解密 il2cpp 到 BSS） | **已无** `libSDKloading.so` | ⚠️ 壳形态变化，见下 |
| `libil2cpp.so` | — | 99,308,240 B（未加密体积） | — |
| 新 native 清单 | — | `libnative-lib.so`(1.3MB)、`libmain.so`(6.7KB)、`libsgcore.so`(88KB)、`libti-monitor.so`(快手 perf/xhook)、`libtapsdkcore.so`(4.2MB) 等 18 个 so | 需逐一识别反调/壳 |
| dex | classes..classes4 | 同 classes..classes4（共 4 个） | 结构未变 |
| Il2CppDumper | — | **`ERROR: This file may be protected.`** + `WARNING: find JNI_OnLoad` | ⚠️ 静态 dump 失败，需运行时 dump |
| metadata 头 | — | magic `AF1BB1FA`（标准 il2cpp v31） | metadata 未被加密 |
| 便签名校验 | TapSign MD5 `a3e3c07b…` | 新包 cert MD5 **`A3:E3:C0:7B:81:AA:32:22:15:F6:31:5D:7E:60:B1:51`** → `a3e3c07b81aa322215f6315d7e60b151` | **与 1.0.5 完全一致**，SignSpoof 表项不变 |
| TapTap SSO | `ClientLoginUtils` 存在 → 需强制 WebLogin | 同（`ClientLoginUtils` 已在 dex） | 注入脚本的 WebLogin patch 可沿用 |
| TapSignKit | 存在 | 存在 | getSign patch 可沿用 |
| RootBeer | 1.0.5 有 `RootBeerNative` | **dex 内 RootBeerNative = 0**（未找到） | root 检测可能已换实现 |
| ACE/TSS | 无 | `AceApplication=0`、`TencentPackageHelper=0` | 无强 ACE/TSS |
| Application | 无自定义 | `<application>` 无 `android:name`（默认 Application），`extractNativeLibs=true` | 注入点沿用 activity onCreate 路线 |

### 关键结论

1. **证书没变**：官方 cert MD5 与 1.0.5 相同 → SignSpoof 的 DER/回灌表项不用改。
2. **壳形态变了**：1.0.5 的 `libSDKloading.so` 没了，但 `libil2cpp.so` 静态下 Il2CppDumper 仍判「protected」。两种可能：
   - (a) il2cpp 代码段做了静态加密，改由别的 so（`libnative-lib` / `libsgcore`？）运行时解密；
   - (b) 符号/注册表被 strip 到 Il2CppDumper 启发式失效（非真加密）。
   → 这是 B 阶段第一优先事项，**必须真机跑起来 dump 运行时 il2cpp** 才能定论。
3. **`libti-monitor.so`（快手 ART TI monitor）内有 `xhook_enable_sigsegv_protection`、Jdwp/Jvmti 控制** —— 疑似新增反调试/崩溃保护信号处理，B 阶段需评估是否干扰自注入。

## 2. 玩法锚点与偏移（复用基础）

HzsjMod.cpp 已是「运行时按名解析字段 + 12 字节 ProtectedInt 自洽写入」，字段名不变即自适应。
小版本换包后需要重定位的只有 **native invoke 跳板 RVA**：

| 项 | 1.0.5 值 | 1.1.0 状态 |
|----|----------|------------|
| `FILE_INVOKE` | `0x28B90B0`（+ELF bias `0x4000` → RVA `0x28BD0B0`） | ⚠️ **待重定位**（旧偏移处已是无关代码） |
| ELF_BIAS | `0x4000` | 待实测（新版 PT_LOAD 取 p_vaddr-p_offset） |
| 字段锚点 | `DamageCommand`/`BattleFieldTransform`/`PlayerGameStateInfo`/`ItemRequirement`/`Item`/`GameSkill` 等 | AOT metadata 内**搜不到**（`strings` 计数=0，`ItemContainer`=2 例外）→ 与 1.0.5 一致，玩法类在 HybridCLR 热更 DLL，**不指望 dump.cs 出这些类** |
| 货币单例链 | `SceneInfoSingleton→gameState→playerState` | 同样的类名在 AOT 也搜不到 → 运行时解析 |

### 与 version-update-relocate 方法论的适配

- 阶段 B（静态 diff 找新 file_off）依赖一份**旧的 1.0.5 libil2cpp.so**。
- 本地磁盘已无旧 so（`06_dumped/` 无魂坠 1.0.5 产物；`02_apks/魂坠深境` 旧官方包也已不在盘上）。
- → 无法走「two-version diff」；只能走：
  - (a) **运行时 dump**（装机进游戏，从内存抓解密后的 il2cpp 后扫 invoke 桩结构）；或
  - (b) 静态在 1.1.0 so 里按 1.0.5 桩的**结构特征**（stp 头 + 3×BL + RET 的 116B 函数）做唯一匹配。
