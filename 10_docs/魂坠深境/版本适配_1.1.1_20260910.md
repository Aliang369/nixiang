### 8.4 工程教训（本次踩坑）

- **同一文件多个 Edit 并行 = 读改写竞争互相覆盖**：声明行插入两次「成功」两次丢失，浪费 3 轮构建。铁律：同文件多处改动必须串行编辑或一次 MultiEdit。
- **管线 reset 只回退单阶段，下游 done 不会自动重跑**：改完 so 必须 `reset build_so` 后连跑，且确认 surgical/install 是否也要 reset（本轮旧 APK 混装一次，靠包内 so md5 与 libs_hzsj 比对发现）。
- 验证 so 入包：`unzip -p final.apk lib/arm64-v8a/libstarry_magic.so | md5` 对照 `libs_hzsj/.../libstarry_magic.so`。
- **ndk-build 相对路径落点陷阱**：`ndk-build -C jni && NDK_LIBS_OUT=../../libs_hzsj` 实际落到 `app/libs_hzsj`（相对 make cwd），而脚本校验 `starry-mod-menu/libs_hzsj`（14:18 旧产物）→ **构建假成功、旧 so 进包**。修复=OUT 全部用绝对路径；「用户看到旧菜单」即此因（14:24 装机为旧 so 包）。
- **`strings` 默认 ASCII 会漏报 UTF-8 中文字符串**：so 内「Toggle_自动胜利」必须 `LC_ALL=C grep -ac` 按字节搜。防呆检查本身要防呆。
- 构建防呆双保险落地：产物 so 必须含 `Toggle_自动胜利` 字节串，否则 build_so FAIL。
