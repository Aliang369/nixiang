## 4. 两轮重构

### 4.1 货币：值域锁 999 + 仅在不足时回填

**为什么不能直写大值（IL 证据，`Assembly-CSharp.dll`）**：局内金币/魂晶的合法上限是 **999（0x3E7）**，四处独立钳制 —— `ChangeCoinAction::Update` `Mathf.Clamp(coin+Δ, lb, 999)`（IL 45917-45940）、`ChangeCrystalAction::Update`（46031-46059）、`SetCoinAction::Update` `Mathf.Min(value,999)`（54004-54040）、`SetCrystalAction::Update`（54076-54110）；全 IL 不存在 999999 这个整数常量。任何一次货币动作都会把余额钳回上限并按 `delta = 钳后值 − 钳前值` **重算** delta：若余额被写成远大于上限的值，delta 会变成 −999000 这一量级，随后经 `GameEventManager::TriggerCoinChange(value, delta, notCountAsGain)`（IL 505039-505066）进入事件链随结算上报，结算侧 `GameOverSettlementError::IsBlocked` 认 `106001`（作弊）/ `106007`（频率）并阻断。作弊判定在服务端（结算走 `GameOverRequest → GameOverResult → ApplyServerSettlementRewards`），客户端只看到结果码。

**实现**：`CURRENCY_VAL = 999`；`WriteCurrencyAt()` 先 `ReadProtectedInt` 读现值，**coin / crystal 各自独立、仅 `cur < 999` 才回填**（日志 `CURR#… =999 cap=999`、`CURR_REFILL# coin a->b cry a->b`）；回读失败按原行为兜底并打 `rdfail`；偏移为 0 时跳过写入（防往对象头写三元组）。写入不经游戏动作 ⇒ 不触发 `TriggerCoinChange`，不产生假 delta。

### 4.2 无敌：写 `health = maxHealth`

血量域没有常量上限（写入点都是 `Min(值, maxHealth)`/`Clamp(值,0,maxHealth)`；`0x3e7` 只出现在货币四件套），合法域 `CombatValueLimit.Max = 10,000,000`。但受击时游戏按 `clamped = Min(health+Δ, maxHealth)` 计算并把 `Max(clamped,0) − 钳前health` 记进 `InGameRecorderManager::RecordPlayerRealHealthDamage`（塔模式 `RecordAppliedDamage`）：若 health 远大于 maxHealth，每次受击都会记下约 −99.9 万的假承伤，污染统计/成就/回放并随结算上报。

**实现**：读 `g_offBftMaxHp` 并解码，守卫 `0 < maxHp ≤ 10,000,000`（异常打 `INV_SKIP` 跳过），再读 `health`，**仅 `health < maxHp` 时写 `health = maxHp`**（`ApplyBattleTick` 每 tick 200 ms 执行，不额外节流），日志 `INV#… health=<maxHp> maxHp=<maxHp>` 与 `INV_REFILL#… health a->b (maxHealth)`。`DMG_CAP`、秒杀、卡牌、自动胜利逻辑零改动。
