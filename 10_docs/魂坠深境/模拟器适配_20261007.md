# 魂坠深境 模拟器适配 + 菜单换新（2026-10-07，win 端）

> 症状：真机（OnePlus `f9a116a2`，历史）五功能全部有效；MuMu 模拟器（`127.0.0.1:16416`）菜单能弹但**五功能全部无效**。
> 结论：**根因 = so 内 `SoftPtr` 指针判据硬编码 `64GiB~512GiB`，判否模拟器/现代真机的 48-bit VA 堆指针（≈123~124TiB）**。
> 修复 = 用已入库的设备无关判据（`Includes/StarPtr.h`，10-04 `bfd04c4f`）重编 so；真机不受影响（旧区间是新区间子集）。
> 同轮完成用户要求的**菜单换新**（旧 smali 注入 → 新 provider 路线 classes6.dex）。

## 1. 证据链（按时间）

### 1.1 症状期（旧 so，09-21 交付包 `f191e461` 内的 so `45a4fcfd`）

- 菜单可弹、`[Hzsj] ready v14` 正常，但功能全哑：

- 三层判定（hook-rules §30.1）：① 菜单装载 ✅ ② 基址/字段解析 ✅ ③ 运行时取对象链 ❌

## 2. 根因与修复

| 项 | 旧（09-21 交付 so `45a4fcfd`） | 新（本轮 so `1c7d4e2a`） |
|---|---|---|
| 判据 | `v >= 0x1000000000 && v <= 0x8000000000`（64GiB~512GiB 硬编码） | `starptr::Untag(p)` + `[kUserVaMin, kUserVaMax)`（4GiB~128TiB）|
| 来源 | `HzsjMod.cpp` SoftPtr 手抄区间 | `Includes/StarPtr.h` 全框架唯一判据入口（10-04 `bfd04c4f`「MOD 设备无关指针判据收口」）|
| 模拟器 123TiB 指针 | 判否 ⇒ 全链 return nullptr ⇒ 功能全哑 | 放行 ✅ |
| 真机 124TiB 指针 | 越界（同上） | 放行 ✅ |

- 修复动作本身 = **重编 so**（源码早已入库，交付包落后于修复提交）。
- `Android_hzsj.mk` 同步补 `Games/NoAceStubs.cpp`（B 类 no-op 桩；缺它则 `Jd.lld: undefined SignalQuarantine_Start / FgoBoot_InjectEarlyFromOnLoad`，链接失败）。
- Windows 构建要点（照 `zzz_build_so.sh`）：本机 NDK 27 只有 `ndk-build.cmd` → 走 `prebuilt/windows-x86_64/bin/make.exe -f build/core/build-local.mk SHELL=cmd`；仓库路径含中文（`mod菜单`）→ ASCII 暂存目录构建后回拷。

## 3. 菜单换新（旧 smali 注入 → 新 provider 路线）

### 3.1 为什么换

- 旧包（`f191e461`，09-10 gradle+smali 注入路线）把菜单 smali 混进了 `classes5.dex`（与 kotlin/okhttp/okio/org 库类同 dex 共存），靠 **Activity onCreate 插桩** 拉起；换菜单要重跑 gradle 整包 + apktool b 全量重建。
- HEAD 源码已内化全部旧补丁：`StarryInitProvider.java` 一处在 onCreate 里完成
  `SignSpoof.install()`（签名回灌）/ `StarryNativeLoad.ensureLoaded()`（so 加载）/
  `MenuService.start()`（菜单拉起）/ `TapLoginForceWeb`（TapTap 强制网页登录，lifecycle 回调）
  ⇒ 此后换菜单只需换 `classes6.dex`。

### 3.2 新包手术（surgical_hzsj_1.1.1.sh，照 surgical_zzz_3.2.0.sh）

底包 `02_apks/魂坠深境/魂坠深境_1.1.1_device.apk`（**实测 md5=f191e461…，为星光正式包**；官方原包不在本地）。
四件手术，其余 2460 条目 CRC 透传保真：

1. `classes5.dex` **重建为去 com/starry**：baksmali(`fat.jar`) 反编 916 文件 → 删 `com/starry`（127 文件，旧菜单）→ smali 重汇编 = 789 类保留（kotlin/okhttp3/okio/org）。缓存 `07_patched/魂坠深境/surgical/classes5_nostarry.dex`。
2. `classes6.dex` **新增**：`templates/hzsj_menu_20261007/classes6.dex`（`hzsj_build_dex.sh`，javac+d8 离线构建自 HEAD 源码；449,348 B）。
3. `AndroidManifest.xml` **加** `<provider com.starry.magic.StarryInitProvider>`（MenuService/权限旧包已有；`application`/`ComponentFactory` 零改动）→ 二进制回读 aapt2 校验。缓存 `07_patched/魂坠深境/surgical/AndroidManifest.xml`。
4. `lib/arm64-v8a/libstarry_magic.so` 替换为新构建。

- **旧 Activity 插桩保留不动**：classes5 的旧 `com/starry` 删除后，插桩引用自动解析到 classes6 新类；`MenuService.start` 幂等（`instance!=null` 即 skip，实测日志 `start skipped: already running`），与 Provider 双启动无副作用。
- 不注入 `libc++_shared.so`（官包自带）。
