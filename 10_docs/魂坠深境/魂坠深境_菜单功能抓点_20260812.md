## 1. 机制结论

| 检查 | 结果 |
|------|------|
| 引擎 | Unity IL2CPP + **HybridCLR 热更**（设备有 `files/Asset/hotfix`、`HybridCLR*.dll`；AOT `dump.cs` **搜不到**玩法方法名） |
| 壳 | **小壳** `libSDKloading.so`≈3.9MB 高熵；运行时解密到旁路 `[anon:.bss] r-xp`≈972KB（含 Dobby + 完整 `il2cpp_*`） |
| 开关持久化 | `*_preferences.xml` boolean `"0"`–`"2"` |
| BSS 旗标 | 菜单 rw BSS（SDKloading 旁大块 rw）相对偏移 **+0x1728 / +0x172C / +0x1730**：OFF=`0` → ON=`1`（三旗标） |
| `libil2cpp` mem vs APK | **OFF=ON=仅 1 处** prologue 改写（`file_off=0x28B90B0` / 报告 VA `0x28BD0B0`） |
| 玩法符号来源 | **壳 BSS 运行时解析出的方法/类名**（非 AOT dump 直出 RVA） |

单处 stub 更像 **HybridCLR/公共 invoke 跳板**（或壳自用入口），**不是**三个功能各打一个 inline hook。玩法主要靠：解析方法名 → 绑 MethodPointer → handler 内读三旗标。

壳调试串旁证：

```text
[魂坠] isPlayer=%d base=%d hp=%d/%d tmp=%d
[魂坠] targetBFT=NULL base=%d
[魂坠公告] SetActive 真实类名=%s active=%d
```

## 2. BSS 绑定表（开功能后补齐）

菜单 rw BSS 中，方法/类名槽位：

| 偏移附近 | OFF | ON | 角色推定 |
|----------|-----|-----|----------|
| `GenerateDamage` | 已有 | 已有 | **秒杀 / 无敌** 共用伤血入口（`isPlayer` 分支） |
| `Item` | 空 | **写入** | **无限卡牌** 相关 |
| `ItemRequirement` | 空 | **写入** | **无限卡牌** 相关（消耗/条件） |
| `GameSkill` | 空 | **写入** | **无限卡牌 / 技能牌** 相关 |
| `SetActiveAndDirtyWithFadeAnim` | 已有 | 已有 | 挂在 `AnnouncementPanel`（公告/面板；非三项主玩法） |
| `AnnouncementPanel` | 已有 | 已有 | 同上 |

→ 开齐三项后，卡牌向三个符号才从空槽变成明文，与 prefs/旗标同时变化，**强相关**。

AOT `dump.cs`（APK metadata 与设备 `global-metadata.dat` 各 dump 一次）均 **无** `GenerateDamage` / `ItemRequirement` / `GameSkill` 字符串 → 这些类型在 **热更程序集** 里，星光必须 **运行时按名解析**（或先从热更 bundle 脱 DLL 再对 RVA）。

唯一 memdiff stub：

| 项 | 值 |
|----|-----|
| file_off | `0x28B90B0` |
| 报告 VA（+0x4000） | `0x28BD0B0` |
| OFF/ON | 相同 |
| dump.cs | **未命中**该方法槽（保护/热更导致 CodeReg 与玩法方法表不对齐） |

## 3. 玩法语义（星光复刻）

> 只借玩法；推荐 **运行时解析方法名 + DobbyHook + 星光 Toggle**，不要死绑本表唯一 stub。

### 3.1 秒杀 + 无敌 ≈ `GenerateDamage`

- 壳日志按 `isPlayer` / `hp` 改临时值。  
- 推定：  
  - **秒杀**：对非玩家目标，放大伤害或把扣血改极大；  
  - **无敌**：对玩家目标，伤害改 `0` / 不扣血。  
- 两个菜单开关应对应 handler 内两个 flag（prefs `"0"`/`"1"`），**共钩一个方法**。

### 3.2 无限卡牌 ≈ `Item` / `ItemRequirement` / `GameSkill`

- 开功能后才写入 BSS → 绑定成功才生效。  
- 推定：绕过卡牌消耗/数量/`ItemRequirement` 检查，或让 `GameSkill` 可用次数不减。  
- 明早原版需在热更 DLL / 局内 Frida 把三个符号的 **具体 Method 签名** 钉死（当前只有类/方法名级情报）。

### 3.3 公告面板（附带）

- `AnnouncementPanel.SetActiveAndDirtyWithFadeAnim`：改包可能用来压公告 UI；星光可不移植，除非原包有挡操作的公告。
