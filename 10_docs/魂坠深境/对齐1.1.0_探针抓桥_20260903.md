## 2. 1.1.0 桥地址（探针实抓，12 轮一致）

探针 v2：星光包内枚举热更方法 `MethodInfo.methodPointer`，按名直搜目标方法，`fileoff = abs - (r-xp.start - r-xp.fileoff)` 换算。

| 方法 | 类 | 桥 file_off | VA(+0x4000) | 共享情况 |
|------|-----|-------------|-------------|----------|
| **GenerateDamage** | Damage | **0x26B0F0C** | 0x26B4F0C | 样本内独占 |
| **IsCooldownCastAble** | Item | **0x26A3E0C** | 0x26A7E0C | 与 IsManualSelectCost 共享（(this,?,int)→bool 桥） |
| **GetFinalCostValue** | ItemRequirement | **0x268B660** | 0x268F660 | 与 GetDisplayFinalCost 共享（→int 桥） |
| **IsCastAble** 等 | GameSkill | **0x26A3A28** | 0x26A7A28 | bool(this,ref) 桥（需类名过滤） |
| 货币单例链 | SceneInfoSingleton | get_gameState @ 0x26A8054（共享 ref-getter 桥，不 hook） | | 单例直写沿用 |

签名桥参数约定（所有桥 BL 同一核心 `0x2738F50` VA）：

```
GD   桥: (x0=this(Damage), x1=cmd(DamageCommand*), w2=int, x3=MethodInfo) -> ref
ICCA 桥: (x0=this(Item),  x1, w2, x3=MethodInfo) -> bool
GFCV 桥: (x0=this(Req),   x1, w2, x3=MethodInfo) -> int
GS   桥: (x0=this(Skill), x1, x2=MethodInfo) -> bool   ← mi 恒为最后一个参数寄存器
```

`x1` = 第一个业务参数 = `DamageCommand*`，与 1.0.5 公共跳板 `params[0]` 语义对齐。

## 3. HzsjMod 1.1.0 改动（本版）

1. `FILE_INVOKE` 单桩 → **4 桥组**（`BRIDGE_FILE_GD/ICCA/GFCV/GS`，OTA 键 `bridge_gd/bridge_icca/bridge_gfcv/bridge_gs`）
2. 晚挂保留：秒杀/无敌 → GD 桥；卡牌 → ICCA+GFCV+GS 三桥；纯货币永不挂
3. **挂点换算弃用 `getAbsoluteAddress`**（双映射下 dli_fbase 可能指只读占位区）→
   `ResolveExecBase()` 解析 maps r-xp 行：`abs(file_off) = (start - fileoff) + file_off`
4. mi 过滤沿用 `MiClassify`（MethodInfo* 指针缓存）；GS 桥读 **x2**，其余读 x3
5. 字段偏移仍运行时按名解析（`DamageCommand.baseDamage/targetBFT` 等），1.1.0 热更若再重排自动适配
6. 货币：单例直写 + ProtectedInt 12 字节自洽写入，未动

## 4. 关键坑（复现必备）

### 4.1 libil2cpp 双映射（1.1.0 新）

maps 中同一 so 出现两组映射：
```
75f3e9a000-75f9d50000 r--p 00000000  ← 占位映射（整个文件大小，只读）
76a68ea000-76a8bc3000 r--p 00000000  ← 正式 ELF 段1
76a8bc6000-76ac04b000 r-xp 022d8000  ← 代码段（执行域）
76ac04e000-76ac470000 r--p 0575c000
76ac473000-76ac7ab000 rw-p 05b7d000
```
- 探针 v1 用「maps 最低行」当 base → 算出 0xF0D1D804 这种超界 rva（错）
- xdl `dli_fbase` / `getAbsoluteAddress` 语义在双映射下不可靠 → hook 必须用 r-xp 行换算
- **教训**：换包后凡涉及基址换算，先 `su -c cat /proc/<pid>/maps` 看映射布局

### 4.2 探针方法（无旧包可 diff 时）

1. 星光包 + `STARRY_HZSJ_PROBE` 编译，`Hzsj_StartProbe()` 延迟 75s 起线程
2. `il2cpp_domain_get_assemblies → image → class → il2cpp_class_get_methods` 全枚举
3. methodPointer 重复聚集 → 桥族；按名直搜目标方法 → 精确桥地址
4. 注意 `il2cpp_method_get_name` 需先 dlsym（探针 v1 样例没打出来就是这个原因）
5. 进程会重启（游戏崩溃或用户重开），日志按 PID 分组分析；logcat %lX 是大写十六进制

### 4.3 签名冲突装机

官方包 → 星光包（不同签名）必须卸载重装；本次 /data/data 仅 11K（未进过游戏）零损失。
星光包 → 星光包同签名可直接 `pm install -r` 覆盖（v2/v3 就是这么换的）。

## 8. 终版方案（v19，纯 tick 直写）——方法 hook 路线全灭后的正解

### 8.1 为什么 hook 路线失败（v2~v12，10 版教训）

1.1.0 热更方法的调用路径与假设完全不符：
- **签名桥（methodPointer）只在 AOT↔热更边界走**，热更 DLL 内部互调不经过它 → GenerateDamage/DealDamage 桥零命中
- **Execute 主循环 hook**（file 0x2730F50）能拦 200 万+ 调用，但目标方法本体仍不出现（DamageAction.Update 是虚调用，另有派发入口），且 args 槽混有非对象值 → 观测代码 chase 崩溃（v12/v13 SIGSEGV）
- 结论：**1.1.0 无法用 1.0.5 的「拦公共跳板改参数」模式**

### 8.2 破局：抽热更 DLL 反编译（正道，1.0.5 已验证却被遗忘）

`files/Asset/hotfix`（UnityFS bundle，未加密）→ UnityPy 解出 42 个 DLL → **ilspycmd 反编译 Assembly-CSharp.dll（5.4MB）→ 直接读 C# 源码**：
- `DamageAction.Update()`（虚调用）→ GenerateDamage → DealDamage 的真实链路
- `Item.IsCoolDowning => (int)cooldown > 0`（CD 唯一判定源）
- `BattleFieldTransform`：health/maxHealth/extraHealthPoint 全 ProtectedInt，isPlayer 判敌我
- 敌方 BFT 链：`gameState.UIManager(GameUIManager).battlePanel.enemyBftUIDisplay(BftUIDisplay).bft`
- 费用：`GetFinalCostValue = Max(0, costCount + deltaCost + 事件修正)`

### 8.3 v19 直写实现（全部运行时 FieldOffset 按名解析）

| 功能 | 链路 | 写入 |
|------|------|------|
| 货币 | SceneInfoSingleton.instance→_gameState→playerState | coinCount/crystalCount = 999999（ProtectedInt 12B 自洽）|
| 无敌 | playerState.**bft**（isPlayer 校验）| health = 999999 |
| 秒杀 | gameState.**UIManager**.**battlePanel**.**enemyBftUIDisplay**.**bft**（isPlayer==false 校验）| health = **1**（一碰即死；写 0 会因 CheckDeath 事件连动「有动作就死」，v15 教训）|
| 无限卡牌 | 己方 bft 五容器（table/companion/draw/waste/exile）→ items | Item.cooldown=0 + deltaCost=-99999（免费+免 CD）|

### 8.4 Item 类自学习（v19 关键创新）

按名找 Item 类不可靠（ClassFromName 撞杂类 type/data、get_field_from_name 对热更类返回 0）——
**从己方容器 items[0] 实例反查 klass**，用 `il2cpp_class_get_field_from_name` 验证（cooldown+deltaCost+owner 三字段齐全才认），再迭代字段拿真实偏移：
```
[Hzsj] Item class self-learned @0x7634310ff0 (from container[2][0])
[Hzsj] Item self-learn offsets cd@32 delta@108
[Hzsj] CARD#1 patched=13 (cd=0 delta=-99999)
```
**教训：实例驱动 > 名字驱动。有活对象在手时，永远从实例反查类与偏移。**

- ProtectedInt 直写有 ReportTamper 内存态标记风险（重启清零）
- 秒杀语义 = 敌人 1 血（任意伤害致死）；非攻击动作不会误杀
