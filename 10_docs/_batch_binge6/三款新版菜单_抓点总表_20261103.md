## 二、新版菜单框架（三款完全同构）

| 层 | 组件 | 职责 |
|---|---|---|
| Java | `bin.wb.WB` | 悬浮球（fab）+ 面板 UI + 功能派发；`init(Activity)`、`showPanel()`、`cheatNative(int)`、`cheatValue(int,int)`、`callJs(String)` |
| Java | `bin.wb.WBText` | 96 条文案的 AES 解密与完整性校验（`get(int)`） |
| Native | `libwbtext.so` | `Java_bin_wb_WBText_wbKeyPart`（密钥分片）、`wbSync`（HMAC 全表校验） |
| Native | `libwbmod.so` | 功能实现：Cocos 款仅写统计日志（7.9 KB stub～32 KB）；Unity 款 1.75 MB，内含 DobbyHook |
| 注入点 | 游戏主 Activity | `onCreate` 内插一行 `invoke-static {p0}, Lbin/wb/WB;->init(Landroid/app/Activity;)V`；实测于 `org.cocos2dx.javascript.AppActivity`（挂机包 `smali_classes3`） |

**与老版（六款批次）的差异**：老版是「每游戏一套 `isChecked_RETn` 内联注入 + 明文文案」；新版统一为「`bin.wb` 菜单框架 + 加密文案表 + 每游戏一份 native/JS 派发」，改包只需换文案表与派发实现。

## 三、文案加密机制（实测，可离线复现）

- 载体：`WBText` 类静态常量 `PART_A`(16B) / `BLOB`(6505B) / `OFF`(97×int32)，共 96 条文案。
- 记录格式：16B IV ‖ 密文 ‖ 32B HMAC-SHA256。
- 算法：AES-256-CTR；`encKey = SHA256(PART_A ‖ wbKeyPart() ‖ "WBText/enc/v1")`；`macKey = SHA256(PART_A ‖ wbKeyPart() ‖ "WBText/mac/v1")`。
- `wbKeyPart()` 实现（libwbtext.so，同一段循环）：`key[i] = ((i*29+7) & 0xFF) ^ S[A[i]] ^ C[i]`，其中 `S`/`A`/`C` 为 so 内 `.data` 相邻三表（`A = S+0x10`、`C = S+0x20`）。
- 三款实测密钥分片（静态推导值，**与运行时校验值是否一致待复核**）：
  - 挂机打怪兽 `a1e8a5d913eab22ccacc661f5ea4ddb5`（S@0x2d570）
  - 修仙大陆 `202109d5d511d4e05b25cb3f55c3b128`（S@0x2d2e0）
  - 黎明前20分钟 `53f58fad48bb9f350516971b1e28bf7d`（S@0x2d530）
- **结论：不要自己解 BLOB**。本轮验证静态推导值与运行时不符（HMAC 不过），直接走 frida `Java.use('bin.wb.WBText').get(i)` 全量导出即可（本轮即用此法取得全部文案，脚本 `_dyn/` 下可复用）。

## 四、逐款锚点

### 1. 修仙大陆模拟器（Cocos Creator 3.x，JS 注入）

| 菜单项 | JS 调用（实测文案表还原） | 说明 |
|---|---|---|
| 资源 | `window.__wbCheat(1,1)` | toggle，开=1 |
| 灵石 | `window.__wbCheat(2,1)` | toggle |
| 仙晶 | `window.__wbCheat(3,1)` | toggle |
| 体力 | `window.__wbCheat(4,1)` | toggle |

- 派发链：`WB.cheatNative(i)` → `callJs("window.__wbCheat&&window.__wbCheat(" + i + ",1)")` → `Class.forName("com.cocos.lib.CocosHelper").runOnGameThread(Runnable)` → `com.cocos.lib.CocosJavascriptJavaBridge.evalString(js)`；老引擎回退 `org.cocos2dx.lib.Cocos2dxHelper.runOnGLThread`。
- 状态回读：`WB.statNative()` 拼 `开/关` 串刷新 Toggle。

| 菜单项 | 参数键 | 默认/上限 | JS 调用 |
|---|---|---|---|

- 派发链：`Cocos2dxHelper.runOnGLThread` → `Cocos2dxJavascriptJavaBridge.evalString`。
- **`__wbCheat` 实现已在原版对比中拿到全文**（斌哥把 15 KB 明文 JS 追加进 `assets/main.js`，见 `三款原版基线_与斌哥包差异_20261103.md` §三.1，源文件 `_dyn/guaji_assets_main_mod.js`）：

  - 无敌：`hpLv=99999` + `Object.defineProperty(juese,'nowHp')` 读写锁（读恒 999999999）+ 120 ms 轮询强制满血、`ProgressBar.progress=1`、`kszzplayer` 组件 `maxHp/def/addHp=999999`。
  - 加速：`director.getScheduler().setTimeScale(n)` → `setAnimationInterval(1/(60n))` → 包装 `director.tick` 放大 dt，三级降级，上限 10。
  - 百倍伤害：`atkLv = round(atkBase × v)`，首次记 `__wbAtkBase`，关闭还原、不累乘。
  - 统计落盘 `/data/data/org.cocos2d.guajidaguaishou.tap/files/wb_stat.txt`。

### 3. 黎明前20分钟（Unity IL2CPP，native）

菜单 3 项：无敌（toggle）、百倍伤害（1–100）、战斗加速（1–5）。

`libwbmod.so` 在 `il2cpp` 完成前用 Dobby 打了 4 个桩（**frida 实测 RVA**，方法名由 il2cpp 元数据反查）：

| 挂点 RVA（libil2cpp.so） | 方法 | 对应菜单项 |
|---|---|---|
| 0x0DC08C0 | `UnityEngine.Time::get_time` | 战斗加速（时间流速） |
| 0x0DC08F4 | `UnityEngine.Time::get_deltaTime` | 战斗加速 |
| 0x0DC0A2C | `UnityEngine.Time::set_timeScale` | 战斗加速 |
| 0x21E9CCC | `flanne.Health::HPChange` | 无敌（玩家侧不改血）/ 百倍伤害（敌方侧倍率） |

- 替换函数（`libwbmod.so` 内偏移）：`+0xFC20`、`+0xF894`、`+0xFD94`、`+0x10094`；`DobbyHook` 本体在 `libwbmod.so+0x10408`。
- Java 侧 `WB.cheatNative(int)` / `WB.cheatValue(int,int)` 为 native 方法，直接进 `libwbmod.so`，**不经过 JS**。

## 五、移植到「星空版」的建议路径

1. 三款共用一套菜单壳：`bin.wb.WB`（UI/派发）+ `WBText`（文案）+ `libwbtext.so`（校验）。星空版可整体替换文案表与图标，保留派发接口。
2. Cocos 两款：目标只需在游戏 JS 上下文暴露同名入口 `window.__wbCheat(key, value)`，或直接把派发改到自家 hook（存档读写点）；改包时把 `WB.init` 从 `AppActivity.onCreate` 换成自家入口即可。
3. Unity 一款：目标无 JS 层，直接复用 4 个 il2cpp 锚点（`Time::get_time` / `get_deltaTime` / `set_timeScale` / `flanne.Health::HPChange`）。**注意 RVA 是 1.0.106 的，换版本必须重定位**；方法名稳定，优先按「类名+方法名」重定位而非写死 RVA。
4. 文案表：不要在星空版沿用斌哥的加密 BLOB（含 HMAC 与本机 key 绑定），改为明文或自家加密，避免被 `wbSync` 校验逻辑牵连。
