# 三款原版（TapTap 渠道）基线 & 与斌哥包的逐文件差异

> 用途：移植「星空版」的基线对照。原版＝真机 TapTap 渠道包（2026-11-03 下载），斌哥包＝`02_apks/斌哥改包_20261103/`。
> 方法：`zipfile` 逐条目 (size,CRC) 比对 + 关键文件字节级 diff + aapt2 badging + smali/JS 阅读。全部实测。

## 一、原版基线

| 游戏 | 包名 / 版本 | APK | SHA-256（前 16） | 原签名块 |
|---|---|---|---|---|
| 修仙大陆模拟器 | `com.sky.xxdl.dlt` 1.0.5 (6) | 109 MB | `c9b21a661115c5a2` | `META-INF/CL_SINGL.RSA` |
| 黎明前20分钟 | `com.nanostudios.games.twenty.minutes` 1.0.106 (106) | 119 MB | `75eb533790401190` | `META-INF/20FENZHO.RSA` |
| 挂机打怪兽 | `org.cocos2d.guajidaguaishou.tap` 1.1.65 (78) | 53 MB | `4e76808d0c7ca5da` | `META-INF/CERT.RSA` |

洁净度核验：三款均 **无** `libwbmod.so` / `libwbtext.so` / `bin.wb` 任何痕迹（grep 计数 0）；launchable-activity 与斌哥包一致（修仙 `com.kuoyou.clsdk.SplashActivity`、二十 `com.nano.privacy.PrivacyActivity`、挂机 `org.cocos2d.guajidaguaishou.tap.MainActivity`）。

## 二、差异总览

| 游戏 | 条目 | 仅斌哥 | 仅原版 | 内容不同 |
|---|---|---|---|---|
| 修仙大陆模拟器 | 2593 vs 2584 | 11 | 2 | 5 |
| 黎明前20分钟 | 3424 vs 3438 | 12 | 26 | 3 |
| 挂机打怪兽 | 2638 vs 2635 | 9 | 6 | 6 |

### 三款共性改动

1. **新增 dex**：每款追加 3–4 个 `classesN.dex`（内含 `bin.wb.WB/WBText` 及框架类），接在原 dex 序列尾部。修仙另有 `classes8.dex`(13 KB)、`classes9`(52 KB)、`classes10`(3.4 MB)、`classes11`(460 KB)。
2. **新增 so**：`lib/arm64-v8a/libwbmod.so` + `libwbtext.so`；三款统一再带一份 `libtoolChecker.so`（5512 B，**三款 sha256 完全相同**：`eeb2317e649e287b…`）。
   - `libtoolChecker.so` 是 **RootBeer** 的 native 部分（导出 `Java_com_scottyab_rootbeer_RootBeerNative_checkForRoot/setLogDebugMessages`，日志串 "LOOKING FOR BINARY: %s PRESENT!!!"）。原版三款都没有 ⇒ 斌哥统一加的 root 检测件。
3. **删掉 armeabi-v7a**：二十包与挂机包把整个 `lib/armeabi-v7a/` 删了（二十少 50 MB 的 `libil2cpp.so`、挂机少 22 MB 的 `libcocos2djs.so`）；修仙原本只有 arm64。
4. **图标/署名**：统一加 `assets/wb_logo.png`(75416 B)、`assets/声明.txt`(95 B)；`AndroidManifest.xml` 均变小（修仙 56700→45400、二十 91016→71144、挂机 51848→40104，主要是 v7a 与部分 SDK 组件声明被裁）。
5. **菜单挂载**：游戏主 Activity `onCreate` 插入 `invoke-static {p0}, Lbin/wb/WB;->init(Landroid/app/Activity;)V`（挂机包实测于 `smali_classes3/org/cocos2dx/javascript/AppActivity.smali`；另两款 Activity 未逐一确认）。

## 三、逐款关键差异（移植落点）

### 1. 挂机打怪兽 —— **JS 功能层是明文追加，已完整提取**

- `assets/main.js`：原版 5149 B → 斌哥 15062 B。原版末尾 144 行之后追加了 292 行 IIFE，注释即写明设计：
  `挂机打怪兽 · JS 功能层 / Java 菜单通过 Cocos2dxJavascriptJavaBridge.evalString 调 window.__wbCheat / 存档：cc.sys.localStorage['data'] 明文 JSON，角色数据在 data.juese`
- 完整实现已存 `02_apks/斌哥改包_20261103/_dyn/guaji_assets_main_mod.js`。核心锚点：

| 菜单项 | 键 | 实现（实测代码） |
|---|---|---|
| 金币 | `g` | `juese.gold += v` |
| 宝石 | `b` | `juese.baoshi += v` |
| 碎片 | `s` | `juese.suip += v` |
| 攻击等级 | `a` | `juese.atkLv += v` |
| 生命等级 | `h` | `juese.hpLv += v`，且 `nowHp<999999 → nowHp=999999` |
| 战斗加速 | `sp` | 三级降级：`director.getScheduler().setTimeScale(n)` → `setAnimationInterval(1/(60n))` → 包装 `director.tick` 放大 dt；上限 10 |
| 无敌 | `god` | `hpLv=99999` + `Object.defineProperty(juese,'nowHp')` 读写锁（读恒 999999999）+ 120 ms 轮询强制 `nowHp`、血条 `ProgressBar.progress=1`、`kszzplayer` 组件 `maxHp/def/addHp=999999` |
| 百倍伤害 | `dm` | `atkLv = round(atkBase × v)`（首次记录 `__wbAtkBase`，关闭还原，不累乘） |

- 存档对象获取：hook `JSON.parse` / `JSON.stringify` 捕获游戏持有的**活对象** `data.juese`（避免"改存档→重启"的体验损失）；抓不到时回退 `applySave`（写 localStorage + `cc.game.restart()`）。
- 统计落盘 `/data/data/<pkg>/files/wb_stat.txt`。
- 结论：**这一款移植只需复制这段 JS 并替换包名/校验，不需要动 native**。

### 2. 修仙大陆模拟器 —— 注入在加密脚本内，源码不可静态读

- 唯一实质改动：`assets/assets/main/index.jsc` 1911336 B → 1915876 B（+4540 B），且**首字节起即不同** ⇒ 斌哥是把改后脚本重新编译加密（XXTEA），不是尾部追加明文。
- 其余：新增 dex/so/图标同上；`classes6.dex` 由 8239396 → 6124392 B（原版某 SDK dex 被裁）。
- 影响：`window.__wbCheat(1..4,1)` 的实现细节无法从包里直接读出。移植时两条路：① 解 jsc（需 XXTEA key，待取）② 在斌哥包运行时用内存扫描取源码（上一轮对挂机包已验证此法可行，需重装斌哥包或另装一台设备）。

### 3. 黎明前20分钟 —— **native 完全没改，功能全在运行时**

- `lib/arm64-v8a/libil2cpp.so` 与 `assets/bin/Data/Managed/Metadata/global-metadata.dat` 与原版**逐字节相同**（diff 未列 ⇒ CRC 一致）。
- 全部功能由 `libwbmod.so`（1.75 MB，另在 `assets/wbmod.bin` 放了一份同尺寸副本供 assets 回退加载）运行时用 Dobby 打桩：
  `UnityEngine.Time::get_time`(0x0DC08C0) / `get_deltaTime`(0x0DC08F4) / `set_timeScale`(0x0DC0A2C) / `flanne.Health::HPChange`(0x21E9CCC)。
- 结论：这一款移植**只需重做 native 层**（或换 hook 框架），il2cpp 侧零改动，RVA 按 1.0.106 有效。

## 四、TapTap 渠道对出包的影响（现行口径，2026-10-29 双轨制）

| 环节 | 走哪一轨 |
|---|---|
| 签名 / 完整性校验（验签弹窗、Gatekeeper） | **运行时签名替换**（换 `PackageInfo.CREATOR` 的签名杀手形态 + `MultiDexApplication.super` 挂载 + 清 `Parcel.mCreators`/`sPairedCreators`/`PackageManager.sPackageInfoCache`） |
| 登录方式 / 渠道分支（强制网页登录） | **改包法**（如 `InitializerServiceImpl.checkInitialize` 恒 true、`GatekeeperRepository.showErrorToast` → `return-void`、登录入口恒 `WebHandler`） |
| 加固壳 / 「直读 APK 文件·签名块摘要」类校验 | 改包法 |

**同一链条禁止双修**；`SignSpoof` 与 `TapLoginForceWeb` 白名单已停用不得复活。锚点必须按**当前 TapSDK 版本**现取，不能抄别的游戏的。
机器关：`framework_entry_audit.sh [G]` + `pre_install_gate.sh` 查12。
