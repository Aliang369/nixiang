## 9. ① 暗影猎手（S 家族 Unity IL2CPP）抓点：3 处 patch 已定位并反查到方法名

链路（全部实测通过）：
1. `dump_binge_shell_mem.sh` 抓进程 `libil2cpp` r-xp 段 → `04_scripts/_common/diff_il2cpp_mem.py` 与 APK 内 `lib/arm64-v8a/libil2cpp.so` 比对 → **patch_regions=4**（其中 `va=0x0` 为 ELF 头页叠加伪差，忽略）。
2. 三处真 patch（内存侧均为 `B` 跳桩）：

| RVA(file_off=va) | 内存原指令 | 反查方法名（DumpRva） |
|---|---|---|
| 0x191C9CC | `90 01 00 16` (B) | `SH.464203032.sh_cyaz1::sh_bgqd1` |
| 0x191CC14 | `06 01 00 16` (B) | `SH.464203032.sh_cyaz1::sh_bgqq1` |
| 0x191CD08 | `d1 00 00 16` (B) | `SH.464203032.sh_cyaz1::sh_bgqt1` |

3. **关键突破：APK 内 `global-metadata.dat` 是加密的**（头 `8f10a8e5`，非 `FAB11BAF`）→ Il2CppDumper/DumpRva 直接喂 APK 会 abort。
   解法：运行时找解密后的 metadata —— frida `Memory.scanSync` 扫 `rw-` 段找 `af 1b b1 fa` → 命中 `0x71f5600000`（anon rw，30 MB 段内）→ 读 16 MB 存 `09_test/_batch_binge6/暗影猎手/il2cpp/metadata_mem.bin`（头恢复为 `af1bb1fa`，版本 24 = Unity 2019.4.37f1）。
4. RVA→方法名：`01_tools/DumpRva/bin/Release/net10.0/DumpRva libil2cpp.so metadata_mem.bin 2019.4.37f1 <rva...>`
   （需 `DOTNET_ROOT=/Users/aliang/.dotnet`，本机 .NET 10 已装；同时产出全量 `il2cpp/method_ptrs.txt`，117313 条方法指针，后续任何 RVA 可直接查表）

**方法名已确证但被游戏自身混淆**（`sh_cyaz1::sh_bgqd1/bgqq1/bgqt1`，同族类内还有 `sh_bgpu1..sh_bgqx1`、`Update`@0x191C7D8）→ 星空版 hook 必须按"方法名+字节序言"双锚定，不能只按 RVA。
待做：3 个 patch ↔ 菜单 3 个按钮（超级定怪/超级恢复/超级秒杀）的对应关系（需开旗标后二次 diff 或多点采样）。

**附**：壳导出 `feature1..feature15` 是 **byte 变量**（非函数），即 15 位旗标存储，与 `mod_sw.txt` 的 15 字符一一对应；`patchOffset/patchOffsetSymm/string2Offset/get64AbsAddr`、`伤害1..47`+`old_伤害*`、`IsInvincible1..3`、`addDamage`、`checkEnemy`、`GetGameRole` 等 63 个可挂导出已枚举。

## 11. ③ W 家族（不一样西游 / 我的技能无限触发 / 不一样修仙2）— 机制已定位

**结论：W 家族是另一套框架，不是 S 家族的壳。**

| 项 | 实测结果 |
|---|---|
| 引擎/元数据 | 三款 Unity IL2CPP，**global-metadata 明文**（`af1bb1fa`，与暗影猎手的加密元数据不同），Unity **2020.3.27f1**；libil2cpp 45–63 MB |
| mod 载体 | `libwbmod.so`（进程内实际加载仅 241 KB）+ `libwbtext.so`，**内含 frida-gum**（`Interceptor`/`features` 符号），导出 `DobbyHook`/`DobbyCodePatch`/`DobbyInstrument` → 即"frida/Dobby 二合一" cheat 层 |
| 无 Java 桥 | APK 内无 `com.android.support.*`、无 `get_ret/kaiguan` → 菜单不走 S 家族的 WebView 桥 |
| 无远程菜单串 | `libwbmod` 内无菜单 URL、无中文菜单串（不一样修仙2 只有 `等待进入存档/金币/声望/贡献` 等少量明文） |
| 运行时行为 | il2cpp API 调用**全部来自 libunity.so**（`il2cpp_runtime_invoke` 50214 次），**libwbmod 一次都不调 il2cpp API** → 不走 API 调用，走**直接改内存/RVA 调用** |
| 唯一函数级 hook | 不一样修仙2 内存 vs APK diff：`patch words=3`，单个 12 字节跳桩 @ `va=0xF6F788` → **`Immortal.GameMgr::Update`**（DumpRva 实查）。桩体 = `ADRP x17; ADD x17,x17,#imm; BR x17`（标准 Dobby trampoline） |

**含义（对移植很关键）**：W 家族的「功能」不是逐方法 hook，而是**一个 `GameMgr::Update` 每帧回调 + 回调里按硬编码 RVA/偏移读写游戏内存**。所以抓点要做的是：**解出 `GameMgr::Update` 跳板目标（libwbmod 内回调）→ 反汇编该回调，提取它访问的 RVA 集合 → 逐个用 DumpRva 反查方法名**。

工具已就位：`capstone 5.0.7`（python）可反汇编；`DumpRva` 可直接用**明文元数据**（不需要像暗影猎手那样 dump 内存元数据）。

> 三款共用同一框架 → 一次逆完，三款复用（与 S 家族同理）。

## 17. 不一样西游：菜单实测 + 属性机制定型（2026-11-02 真机）

### 17.1 菜单实际内容（用户口述，唯一一项）
> 「菜单只有一个功能：**愿、体、缘、毅**，分别改成 99999」

即整款只做一个功能：**四项主角属性一次性加成**。菜单不再是老版多开关面板，只有这一项。

### 17.2 机制（mod 自身 WBMOD 日志实测，非推断）

```
xy GetAttr self=0x71c0a93540 type=0..4 lock=0
xy attrs[before] t0=199998 t1=200002 t2=200087 t3=199999 t4=100
xy SetAttr t=0 +99999 player=0x71c0a93540
xy SetAttr t=1 +99999
xy SetAttr t=2 +99999   (先 GetAttr type=4/2 lock=1 读原值)
xy SetAttr t=3 +99999
xy attrs[after]  t0=299997 t1=300001 t2=300086 t3=299998 t4=100
xy lock=1 player=0x71c0a93540
```

关键结论：
1. **只改 t0..t3 四个槽，t4 不动**（t4 前后恒为 100）→ 四项 = 愿/体/缘/毅，t0..t3 依菜单顺序对应（顺序按菜单排列推定，未逐项核验）。
2. **是"＋99999"累加，不是"赋值 99999"**：before≈200000 → after≈300000。每开关一次叠加一层。
3. 写值前用 **`GetAttr(type, lock=1)`** 读真实值（lock=1 绕过自己的 GetAttr hook），写完再回读校验 → **移植必须保留 lock 机制**，否则读到自己伪造的返回值会算出错误基数。
4. 落点方法全名：`ToWest.Logic.CharacterLogic::SetAttr(int type, int value)` @ **RVA 0xE0CC30**；读取 `GetAttr` @ 0xE0CF18（`GetAttrLimitValue` @ 0xE0CF08 为上限值）。
5. 抓实例路径：`ToWest.Mgr.GameMgr::get_Player`(0x10469EC) 拿 `CharacterLogic`，`GameMgr::Init`(0x1046A10) 后实例才有效；`ConfirmPanel::OnOpen`(0x101FE18) 是 mod 用来触发重算的时机。

### 17.3 移植要点（星空版）
- 只需一处能力：`SetAttr(t, GetAttr(t,lock=1)+N)`，t∈{0,1,2,3}；N 做成可配置（斌哥用固定 99999）。
- 必须做**幂等保护**：斌哥没有做，反复点会一直叠加（before 200000 说明已被点过两次）；移植时按需加"只加一次"标记，避免误触改崩存档。
- 老菜单的 `isChecked_RET` 那套（百倍伤害/秒杀/免广告）**在这款没有出现**，不要照抄。

## 18. 我的技能无限触发：菜单实测 + 全部落点（2026-11-02）

### 18.1 菜单实际内容（用户口述）

### 18.2 mod 自身 WBMOD 日志实测
`@
cheatNative type=1
cheat type=1 inv=1 mult=1 speed=0
dataMgr=0x71f19ef3f0  nativeData=0x741cdb2540
obsCls=0xb4000073a93a0e00 getValue=0x0 ctor=0xb4000071cfc8f4f0
`@
→ 分发结构：Java `WB_statNative` 传 `type`（1=无敌 / 2=伤害倍率 / 3=加速 / 4=加资源），native 侧 `cheat type=%d inv=%d mult=%d speed=%d` 统一执行后 `readback=%d` 回读校验。

### 18.3 落点（方法名级，全部实测）

| 菜单项 | 落点 | 说明 |
|---|---|---|
| 无敌（开关） | **`BattleData::changeHp` @ RVA 0xDEB660**（唯一 Dobby hook） | 日志 `chg camp=%d in=%d out=%d inv=%d mult=%d`，无敌＝改 inv 分支 |

| 金币（数值） | **`NativeData::changePlayerGold` @ RVA 0xDF088C** | |

| 体力（数值） | **`NativeData::changePlayerPower` @ RVA 0xDF0934** | |
| **免广告（斌哥未做，需新增）** | **`NativeData::SetPlayerIgnoreAds` @ RVA 0xDF0B5C** | 游戏自带"忽略广告"存档位，置 1 即可；也可 hook `CSJHelper::ShowRewardAd` |

### 18.4 移植陷阱（重要）
金币/钻石/体力 **全部是 `CodeStage.AntiCheat.ObscuredTypes.ObscuredInt`**（内存存加密值 + 每实例随机 key），**禁止直接写 int**。必须走：
- 读：`ObscuredInt::get_Value` / `op_Implicit`（RVA 0x15538DC / 0x155FA8C）或 `InternalDecrypt`(0x155F988)
- 写：构造新的 `ObscuredInt`（`.ctor` @ 0x155F830），或直接用游戏自带 `changePlayerGold/Crystal/Power`（推荐，带内部校验与 UI 刷新）
