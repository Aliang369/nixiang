## 一、真机 memdump 全流程（可复用，含两个坑）

1. 启动游戏（monkey 拉起即可，**无需登录**，壳解密在 Unity 初始化前完成）
2. `su -c 'cat /proc/<pid>/maps'` —— libil2cpp.so 是**文件映射**，7 段 r--p/r-xp/rw-p + **6 段 `[anon:.bss]`**（LOAD#1 的 bss 尾 0x5A98000..0x6480000，VA 空洞处，grep 'il2cpp' 会漏掉它！）
3. dump：`dd if=/proc/$PID/mem bs=4096 skip=<VA/4096 十进制> count=<len/4096>`
   - ⚠️ **坑①：设备端 shell 算术是 32 位**，`$((0x7746a40000/4096))` 溢出成负数 → dd 静默读出全零页（rc=0！）。**skip/count 必须本地 64 位算好传十进制字面量**（脚本见 `dump_regions.sh` 生成方式）
   - ⚠️ **坑②：ELF 头被壳抹了**（`7f 45 4c 46`→`7f b2 b3 0f`，Ehdr 字段清零，反 dump）
4. 重建：以磁盘 so 为底，把各段内存内容按 **maps 的 file offset** 回填（bss 段按 VA）。Ehdr/phdrs/节表保留磁盘版（内存版已被抹）
   - 程序头：LOAD#1 va==off；LOAD#2/3/4 Δ=0x9e8000/0x9ec000/0x9f0000（换算 VA↔file 注意）
5. 验证：`.text` 熵 7.96→6.3；`mscorlib.dll`/`Assembly-CSharp.dll` 字符串出现（磁盘态全无）；`targetfuntional.dll` 不在（热更程序集不进 AOT codegen，正常）

## 二、Il2CppDumper 为何失效 & 方法地址怎么拿（免 IDA 实用路线）

- auto 模式 `CodeRegistration 0 / MetadataRegistration 0`：**壳把 CodeRegistration/MetadataRegistration 结构搬进了 `[anon:.bss]`**（运行时构建），文件映射段 `.data` 指针密度 0%（绝对/裸 VA 均无），`.dynsym` 无 `il2cpp_*` 导出（2577 符号全无）
- **实测可用的定向路线**（不动 IDA）：
  1. bss 里搜「指向 rodata 模块名字符串的**运行时绝对指针**（基址 0x7746a40000+VA）」→ 命中 bss3 → `Il2CppCodeGenModule` 结构体（name, methodPointerCount, methodPointers）
     - 实测：mscorlib 结构体 @VA 0x5da25b0（count=16011）；Assembly-CSharp @bss3 off 0x3dd58（count=1494, methodPointers @VA 0x5f71b80）
     - 模块名字符串块在 rodata ~0x1115000（'Coffee.UIEffect.dll'/'mscorlib.dll'@0x1116888/'Assembly-CSharp.dll'@0x113fea8 相邻）
  2. methodPointers 数组本体也在 bss5（VA 0x5f71b80），存**运行时绝对指针**，`- 0x7746a40000` = 文件偏移/VA
  3. 自写 v31 metadata 解析（typeDef=88B/methodDef=36B/fieldDef=12B/imageDef=40B，布局见 resolve 脚本注释）拿方法 token rid → `methodPointers[rid-1]`
- 脚本：`04_scripts/无限升级/resolve_il2cpp_method_va.py`
- **YooAssetAesCrypto 15 方法 VA 全拿到**（.text 内，VA==file offset）：
  `.cctor=0x2b51254 CreateAesKey=0x2b51048 CreateDeterministicIv=0x2b50c0c DecryptBytes=0x2b50290 TryReadPayloadBytes=0x2b4fe10 EncryptBytes=0x2b4f6a8 ComputeSha256=0x2b50e54 NormalizeBundleName=0x2b50dbc Encrypt=0x2b4f5d4`

## 三、YAES（YooAssetAesCrypto）算法全还原 ✅ 已验证

- **格式**：`[4B "YAES"][1B version=1][16B IV][AES-CBC 密文]`（解密侧 IV 取自 payload 内嵌；magic 逐字节比对，不符 throw；密文 ≥ len(magic)+17）
- **Key** = `PBKDF2-HMAC-SHA1("gamemen2026", "c698rish2210", 10000, 32)`
  = `3357971e9dff4567533a29ec5a955756d839d15ad3db393e1e135bf474e8a449`
  - 10000 是**代码硬编码立即数 0x2710**；metadata 字段默认值 Pbkdf2Iterations=20000 未被使用
  - AesKey 在 cctor 由 CreateAesKey 算出存 statics[8]；**live 内存直读 statics[8] 与 PBKDF2 复算完全一致**（实锤，且 SHA1 非 SHA256——metadata 名字骗人）
- **Padding**：set_Padding(2)=PKCS7；set_Mode(1)=CBC；Aes.Create() 默认 256
- IV 派生（加密侧）= `SHA256( nameBytes ‖ SHA256(参数2) ‖ GetBytes("c698rish2210") )[0:16]`，name 经 NormalizeBundleName；解密不依赖它
- 字符串常量经 **v29+ zigzag 压缩编码**（长度=2×len；0x16→11 字符）。字段默认值解码：AesPassword="gamemen2026"（0x598 statics，live 实锤）AesSalt="c698rish2210"（0x588，live 实锤）KeySize=32（zigzag；GetBytes(0x20) 代码实锤）IvSize=16
- 脚本：`04_scripts/无限升级/yae_crypto.py`（decrypt/encrypt/key）
- 静态字段布局实锤：`[klass(=[0x5eb8210] 处的 slot 二级解引用) +0xb8]=static_fields`；statics[0]=HeaderMagic byte[4]，statics[8]=AesKey byte[32]；字符串对象 layout：len@+0x10(i32)，UTF-16LE chars@+0x14；数组 layout：len@+0x18(i32)，data@+0x20

## 四、关键分界发现：APK 内置包 ≠ YAES

- **APK 内置 rawfile（283207f9 等 18 个）头部是明文 `UnityFS`**，不穿 YAES（DecryptBytes 管的是 CDN 下载 bundle）
- 堆里 dump 出的 targetfuntional.dll 明文字节**不在** rawfile 中（BSJB+48B / dll 中段 64B 均搜不到）→ APK 内置包的数据块混淆是**爱加密自有方案**（更深层，Unity 引擎侧或壳内解密），未逆
- 映射表（wxsj_bundle_map.txt，138 条，疑 CDN manifest）里 28417c03=targetfuntional 是 **YAES 格式的 CDN 包名**；APK 内置同名文件是 283207f9
- **推论**：
  - ①重封路线若走「APK 内置 rawfile」→ 必须再逆爱加密数据块混淆（工作量未知）
  - ①变体「CDN 缓存替换」→ YAES 已破可加密，但需动 CDN manifest+校验，且游戏要登录，风险高
  - **②starry 按名 hook 热更 dll 字节加载边界 → 完全绕开 bundle 加密，仍然是最优主路线**（可按名 hook 的目标现已被 metadata+dump 锁定）
- 283207f9 的爱加密数据块方案留待 ②完成后视需要再逆（runtime dump 方法已就绪，可对 libUnity/壳 so 同样操作）

## 五、会话踩坑沉淀（下次会话必读）

1. 设备端 shell 32 位算术 → /proc/pid/mem dump 全零页假成功（rc=0！必须抽验非零字节）
2. `[anon:.bss]` 命名匿名段要单独 grep（'il2cpp' 过滤会漏掉壳搬进去的注册结构）
