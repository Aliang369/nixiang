## 七、下一步（最小动作，按优先级）

### ① 复测「rawfile 是否真加密」（5 分钟读操作，优先做）

- `flags=0x243` = `0x40`（BlocksAndDirectoryInfoCombined）+ `0x200`（BlockInfoNeedPaddingAtStart）+ `0x3`（LZ4HC）
- **没有 `0x1400`（UsesAssetBundleEncryption 加密位）** → 疑似标准 LZ4HC 容器，未加密
- 之前 UnityPy/手工解析失败，疑因：blocksInfo 解压后有 **16 字节 `uncompressedDataHash` 打头**，我漏读了这个字段，把 hash 前 4 字节当 blockCount → 得到垃圾块
- 复测：解 blocksInfo 后先 `skip 16` 再读 blockCount

> **① 复测结果（2026-09-05）：数据区确认为自定义加密，走 IDA 分支。**
> - 18/18 rawfile：头 + blocksInfo 均为标准 UnityFS v8（ve=2022.3.62f2c1）未加密；skip-16-hash 后解析 100% 干净（consumed==blob 长、数据区起点+sum(cs) 与文件尾严丝合缝），skip-0 全失败 → 16 字节 hash 字段实锤
> - **数据块非标准 LZ4**：三种解法全失败（python-lz4 按块、手工宽容解码器、整区单流）；手工解码恰在 SerializedFile 头（版本串 `2022.3.62f2c1` 透出、输出含 node size 大端值 0d70/195754/27e938）后撞高熵区；深处仍有明文字面量（BSJB/mscorlib/Mono/'":'）→ **局部分段自定义加密，非整体加密**
> - UnityPy 1.25.2 亦无法读（同一 LZ4BlockError）；其枚举实锤 `UsesAssetBundleEncryption = 0x1400` 确实不存在于 flags → 加密来自游戏自身（YooAssetAesCrypto），不是 Unity 官方加密位
> - **YooAssetAesCrypto 不在热更 dll**：反编译 1006 cs 与 16 个 dll 二进制均无该类名/`gamemen2026`/`c698rish2210` → AOT 类，方法体在 libil2cpp.so，需 IDA
> - **新情报**：映射表 hash `28417c03`(targetfuntional)/`2b9822d2`(mscorlib) 不在 APK 内置 andres/ 中；实际存在 `283207f9`(1.22MB, node=2,615,608≈主 dll 1,955,840+开销)、`8d1b50e6`(734KB, node=1,660,756) → 内置文件与映射表 hash 对不上（表疑来自 CDN manifest/另一构建），替换目标 = 283207f9 ⚠️ 待解密后验证
> - 复测脚本：`04_scripts/无限升级/retest_rawfile_blocksinfo.py`、`diag_rawfile_data.py`、`diag_rawfile_lz4mode.py`（rawfile 解包在 /tmp/wxsj/rawfile_apk/，tmp 会清，可用 unzip 一条命令重解）
