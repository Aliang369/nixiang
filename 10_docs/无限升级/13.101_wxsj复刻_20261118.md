## 2. 换代判定：13.101 是**大版本逻辑换代**，但 hook 挂点未漂移

- **PE 四项完整性判据全过**（残页排除依据）：① `MZ` + e_lfanew 0x80 处 `PE\0\0`；② NumberOfSections=3、SizeOfImage=2,768,896 自洽；③ 三段 raw 和 = 2,738,688 = 实际可读长度；④ `BSJB`@0x161fdc，dnfile 解析 `Module=targetfuntional.dll` / `Assembly=targetfuntional` / 1939 types。
- 落盘证据：`06_dumped/无限升级/13101/targetfuntional_NEW_13101.dll`。

### 2.2 HybridCLR 静态推断被真机日志推翻（**这段是教训，务必看**）
静态阶段我从解密后的 metadata（段 `76f2c00000`，13,791,232 B，明文含 `RuntimeAssemblyLoader`@0xe8a64 / `ExecuteRuntimeAssembly`@0xe8dda）解析出：
- `RuntimeAssemblyLoader.ExecuteRuntimeAssembly` 全局方法索引 **16150**，token `0xFFFFFFFF`；
- methodPointers 表（bss1 `va=0x771a9bbde8`，实测长 117,524 项）idx 16150 → `va=0x77190a3f14`；
- capstone：该处是 `mov x1,xzr ; b #0x7719cc2600`（目标是 3 个连续 `ret` 的填充）；
- 内存命中 `HybridCLR` 29 处、`LoadMetadataForAOTAssembly`@0x76f2e326f1、string heap 里 `PreJitMethod`/`GetInterpreterThreadObjectStackSize`。

据此我判「AOT 空桩 ⇒ 旧挂点失效，必须换 Assembly.Load(byte[])」——**这个结论是错的**。

**真机日志（2026-11-18 17:37:55 与 17:44:27 两次冷启）直接推翻它**：
```
[Wxsj] hook installed @base=0x7715e66000 +0x2b890d8 orig=0x7945fac000 variants=hf2:2024960B+hf3:2023424B+hf4:2752000B
[Wxsj] Exec call len=2738688 head=4d5a9000 armed=1
[Wxsj] patched dll injected (hit #1 mode=selfarray loaded=official-2738688 fnv=d31dc94b29a8bb0d patched=2752000 pad=13312 buf=0xb400007735200000)
```
`hook installed +0x2b890d8` 能装上（说明 16B 序言 `fe0f1cf8f85f01a9f65702a9f44f03a9` 仍逐字节相等）、`Exec call len=2738688` 能命中（说明确实是我们以为的那个装载函数）。

**错在哪**：我 dump 内存那会儿（17:12–17:17）目标进程的 il2cpp 代码页还**没有被壳按页解密**（`base+0x2b890d8` 当时读出来是 `a1000000` 填充），而 methodPointers 表也在另一个进程状态（后续 base 也不同：17:37 之后是 `0x7715e66000`）。拿「未解密快照」推「函数搬到别处」是错误推理——**填充 ≠ 不存在**。另外 `0x2b890d8 + base` 的算术我在消息里也算错过一次（`0x7715e66000+0x2b890d8 = 0x7718A0F0D8`，不是别的值），结论不受影响但记录在此。

**定稿结论**：
- **`kExecRva = 0x2b890d8` 不变**，`kExecPrologue` 16B 不变；
- 13.101 确实引入了 HybridCLR（游戏逻辑解释执行），但**热更 dll 的字节装载点仍是 `RuntimeAssemblyLoader::ExecuteRuntimeAssembly`**，hook 依旧有效；
- 教训：**壳的「按页按需解密」会让静态快照与运行时刻判若两版；判定必须以真机 hook 日志为准**。

## 7. 已知偏差（2 条）与风险

**偏差 1（载荷面）**：δ 防封层剔除了 `GetMiFaInventory` 一条补丁 —— 13.101 对该类做了 Obfuz 混淆 + 逻辑改写，按方法名无法确信定位（surgery 裁决）。**影响**：该单点上报未屏蔽，其余 19 个出站通道门与 11 条 v1 上报屏蔽全在。功能面 11 项一条未动。

**偏差 2（形态面）**：`pre_install_gate` 的 TapTap 方案查为 SKIP，因为 `_sig` 模板里没有 TapSDK 门闩类（登录不靠「改 TapSDK 类」，而靠 `games/wxsj/GameHookImpl`(core.TapTapWebLogin) + `SigReplace` 运行时签名替换）。属预期形态，不是缺陷，但收尾报告须写明。

**遗留风险**
1. **L3 未做**：11 项功能与「内嵌网页登录」都等用户实测；`经验倍率滑块 1–10` 上限是否仍按 10 需实测确认。
2. **selfarray 的存活语义**：新数组在 malloc 区、不在 GC 堆，靠「不 free + 静态指针」保活；若后续版本 il2cpp 改成 GC 扫描堆外或解释器缓存 array 指针，需要复核（当前日志 `buf=0xb400007735200000` 正常）。
3. **壳按页解密**：任何「静态 so 分析法」在 13.101 上都不牢靠（本轮已踩），后续升级判定一律以真机 hook 日志为准。
4. **脱壳（用户问过）**：13.101 反调试挡住 frida attach/spawn（`agent connection closed`），且不落盘 dex、内存无明文 dex 镜像（`dex\n0` 扫描 0 命中，`Anonymous-DexFile@….vdex` 仅 92 B）⇒ 本版**脱不了壳**，最终形态确定为「保留壳 + 星空注入」。
5. 官方若再推热更（`Exec call len/fnv` 变化）按固定动作重走：DIAG 抓明文 → ilpatch/ilpatch_delta 重放 → 换 hf 载荷 + 三元组 → 重编重出。
