## 3. 离线（断网）机制

`LocalInitializationProviders.onCreate()`（进程启动即跑）：
```
assets.list("offline") → 逐项复制
  core.bundle  → filesDir/offline/core.bundle
  其余 *.dll   → filesDir/offline/aot/*.dll
  写 .part 后 rename（原子落盘）；日志 tag = OfflineBootstrap
```
- `offline/aot/` + `Obfuz.Runtime.dll` + 全套 AOT 程序集 ⇒ **HybridCLR（解释执行热更程序集）+ Obfuz 混淆**形态：aot/*.dll 是 AOT 补充元数据，真正的游戏逻辑程序集（`targetfuntional`）装在 `core.bundle` 的 serialized 文件里。
- 因此「断网版」= 把官方热更链（联网拉 DLL/bundle）改成包内自带，**不联网也能启动**。
- 待验证（`dllhunt` 专攻中）：core.bundle 内那份程序集是**官方 vc1644 同一份**还是 **vc1647 的另一份**。当前观测：节点 1,998,680 B，前 131,072 B 全 0x00，其后是合法 IL 字节（`28 0A 00 00 0A` = call）、BSJB（.NET metadata 根）在 913,080、`TextAsset`/`Assembly` 等元数据串在 1.5–1.7 MB ⇒ 不是标准 PE（无 MZ..PE），像「PE 头被置零/剥离」或加密裸流。

## 5. 我方（Starry 框架）注入面评估

| 项 | 结论 |
|---|---|
| 注入方式 | 沿用 `com.starry.magic.StarryInitProvider` + `android:initOrder=2147483647`，**不替换 Application**（易盾壳，硬约束 §A#9）；本包 manifest 已有 10+ provider，追加一个不与 `LocalInitializationProviders` 冲突 |
| dex 位次 | 本包已占 `classes.dex/classes2.dex/classes3.dex` ⇒ 我方菜单 dex 从 **`classes4.dex`** 起 |
| 挂点 | **已实测确认可沿用 `0x2b890d8`**（2026-11-15 20:25）：本包磁盘上的 libil2cpp.so 是易盾加密态，但运行时 base `0x77176d7000` + `0x2b890d8` 读出的 16 字节 = `fe0f1cf8f85f01a9f65702a9f44f03a9`，**与官方 vc1644 逐字节相同** ⇒ kExecRva 不需重解 |
| 载荷 | 若 core.bundle 内程序集 = 官方 vc1644 那份，现有 `wxsjdz2` 补丁 DLL（2,023,424 B）可直接用；若是 vc1647 新版，需以它为基线重跑 ilpatch 链 |
| 游戏 ID | 本轮按用户指令用 `wxsjdz1`（16 项菜单）；**与官方 `wxsj`、定制 `wxsjdz2` 严格隔离** |
