## 两个必须知道的坑

1. **小米 Android 14 的 `sun.misc.Unsafe` 没有 `staticFieldOffset`/`staticFieldBase`**（只有 `getObject`/`putObject`），
   Java 侧无法改 `PackageInfo.CREATOR` 这个 static final。修法：`WxsjVc1637Mod.cpp` 导出
   `Java_com_starry_magic_sign_SigReplace_nativeSetStaticField`，用 JNI `SetStaticObjectField` 直接写；
   Java 侧起线程轮询等 so 加载（实测 `ok=true wait=50ms`）。
2. **`GET_SIGNATURES`（deprecated）那条读法走「已缓存对象」，不经过 CREATOR**：只换 CREATOR 时
   `GET_SIGNING_CERTIFICATES` 已是官方值，`GET_SIGNATURES` 仍是真实值，而 TapSDK 正好读后者。
   修法：hook 成功后主动 `getPackageInfo(pkg, GET_SIGNATURES)` 一次并把对象上的 `signatures` 就地改写
   （缓存里那份随之变官方）。

## 边界

- 只是「让本进程读到的签名＝官方值」，**不改变 APK 实际签名**；服务端若拿 APK 文件直接算摘要（直读文件类校验）不在覆盖范围。
- 官方包换代（证书变更）需重取 DER 重编 `SigReplace.java`。
- 包内仍残留 `Lcom/starry/magic/sign/SignSpoof;` 类（旧模板遗留，运行期不再依赖）；按 `framework_entry_audit [B]` 要求应清，留待下一轮连模板一起换。
