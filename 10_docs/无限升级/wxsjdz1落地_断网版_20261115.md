## 3. 载荷超长与注入方式（本轮关键技术决策）

### 3.1 为什么不能 memcpy

| 步骤 | 长度 |
|---|---|
| 官方基线 | 1,995,776 |
| **空补丁**走一遍 Cecil 读写（不改任何 IL） | 2,003,456（**+7,680**，Cecil 重写固有膨胀） |
| ilpatch_dz1（30 patches） | 2,006,528 |
| + delta | 2,008,576 |
| + feat 13/14/15/16 | **2,011,648（+15,872）** |

⇒ 即使**一个补丁都不打**也放不进官方数组 ⇒ 瘦身路线（`FileAlignment`/压缩节）
**物理上不可行**，只能让装载器读一块更大的内存。

### 3.2 为什么不能按「改指针」做（lead 原方案①已作废）

运行时 `data` 是 **Il2CppArray（byte[]）**，布局：

    +0x00 klass | +0x08 monitor | +0x10 bounds | +0x18 max_length(int32) | +0x20 内联数据…

日志 `head=4d5a9000` 证明 **`+0x20` 就是数据起点本身（MZ 头）**，不是指针字段 ——
往 `+0x20` 写指针会覆盖 DOS 头，必崩。

### 3.3 本轮做法：自建同布局数组对象

```c
fake = malloc(0x20 + patchedLen + 8);
memcpy(fake, data, 0x20);              // klass/monitor/bounds 原样拷
*(int32_t*)(fake + 0x18) = patchedLen; // 只改 max_length
memcpy(fake + 0x20, payload, patchedLen);
orig(self, fake, outP, mi);            // 把新对象当 data 传给原函数
```

* 放在 **GC 堆外**（malloc 区）：Boehm 保守 GC 只处理堆内指针 ⇒ 不扫描/不回收；
* 指针留在静态变量里 **永不 free**（解释器按指针惰性读 IL，移动/回收 = 读野内存）；
* 同一 `(len,fnv)` 二次装载直接复用缓存（`mode=selfarray-cached`）。

**为什么不用 `il2cpp_array_new_specific`**：本包 `libil2cpp.so` 被易盾重写 dynsym，
静态 `readelf --dyn-syms` **看不到任何 `il2cpp_*`**；运行时逐个探名实测只有
`il2cpp_gchandle_new/weakref/free`、`il2cpp_domain_get`、`il2cpp_runtime_invoke` 导出，
`il2cpp_array_new*` / `object_new` / `class_from_name` / `string_new` **全部 MISSING**。

### 3.4 变体表（`Wxsjdz1Mod.cpp`）

    {1995776, 0xaca5988be25f5119, patchedFnv 0xf325dbc7f111b15f, "dz1", payload, 2011648}  ← 主行

## 8. 已知限制 / 风险

| # | 项 | 说明 |
|---|---|---|
| R1 | **自建数组是堆外对象** | Boehm GC 不管理它，因此不会回收（内存永久占 ~2 MB，进程生命周期内可接受）。若后续 Unity 换用移动式 GC（压缩 GC），需改回运行时 API 分配。 |
| R2 | **feat 4 免广告的网络门** | 本构建 `Show` 已删登录/网络判定，但 `AdsFree` **本体**仍要求 `isLogin && Helper.IsNetworkReachability()`；delta 侧 `AdsFree` 直发（`free_ads` 门）已把发奖路径绕开该判定。若断网包 `isLogin` 恒 false 且 `free_ads` 关，玩家会看到「未连接服务器」。 |
| R3 | **feat 13 只清「次数」不清「奖励」** | 清零的是 `dailyData` 的 10 个每日计数域，奖励发放链（`OnAdsSuccessed` 等）未改；若某个商店入口用别的判据（如服务器回包）限制，本项无效。 |
| R4 | **feat 14 排除 8 处调用点** | 存档链 2 处 + 库存驱动循环 6 处，见 §4.3；反增对「材料消耗类」生效，对上述 8 处不生效（有意为之，防卡死/防写坏存档）。 |
| R5 | **未做用户侧点屏实测** | 本轮只做冷启 + 日志（按纪律不截图不点屏）。功能生效需人工进游戏点开关验证；IL 层与装载层均已机器验证。 |
