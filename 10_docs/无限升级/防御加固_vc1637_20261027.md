## 13. 「功能全失效、只有防封生效」的根因与修法（2026-10-27 00:1x 用户实测反馈）

**现象**：用户登录后开玩，菜单 17 项全失效，只有撤出菜单的防封生效；重启后又正常。

**根因（日志实锤，不是功能坏）**：那一局是在**登录完成之前**启动的。程序集装载（`Exec call`）发生在拿到 v3 票之前 ⇒ 走了「防封基线」路径（只含防封、无功能代码），而 DLL 一个进程只装载一次，所以整局都是基线。

```
00:09:33.226 hook installed …
00:09:36.256 antiban baseline unsealed 2021376 B (hf4): 防封 on / 功能 off (no v3 ticket)
00:09:36.256 patched dll injected (… patched=2021376 pad=7168)
00:09:47.701 [V2] s=1 m=ffffffff          ← 票 11 秒后才到位，已经晚了
```

**修法（本轮两个改动，native-only）**：

1. **装载时等票，最多 3 秒**（`GetPatchedPlain`，50 ms 一轮）：缓存票据正常在进程启动后几秒内就绪，等一下就够，避免"票马上到、整局却只有防封"。等到会打 `payload key arrived after N ms wait`。
2. **真没票时不再静默**：落基线时弹一次性 toast「防封已生效；功能需登录卡密后重启游戏一次」。
3. **首次登录/换号/清票后的那一次启动**仍必须重启一次——票是登录后才签发的，那时 DLL 早已装载；这是机制限制，靠 toast 告知，不再让用户以为是功能坏了。

**验证（新包 `e64407a0…`，装机后冷启）**：`precheck_20261027_001459` → `payload decrypted 2025984 B` + `patched dll injected … patched=2025984 pad=2560`（全量补丁，功能可用）。

**规律记牢**：`antiban baseline` 只应出现在「本进程启动时还没有票」的场景；正常启动应看到 `payload decrypted` / `patched=2025984`，此时 `pad=2560`（基线是 `pad=7168`），这两个 `pad` 值是最快的肉眼判据。

## 14. 「点御灵升级必闪退」根因与修法（2026-10-27 01:0x~01:2x，用户 L3 已通过）

**现象**：进御灵界面点「升级」100% 闪退（`SIGSEGV / SEGV_ACCERR`，`fault addr` 页对齐，`UnityMain`，**只有 1 帧可解**：`libil2cpp.so +0x299c9d0`，`x29` 是垃圾值）。12 线同功能不崩。

**根因（IL 级实证）**：`AngleDetialWindow::Upgrade` 里 `Enough(...)` 之后那条 **`brfalse.s` 官方位移 +126 字节，正好卡在 ±127 极限**；`item_reverse` 在该 `MinusItem` 调用点插 8 条 IL（25 B）后位移变 **+150**，短跳转操作数溢出 → 写出的分支落进指令中间 → 执行乱码。12 线该版方法体更短，同量插入没顶破 127。

**修法（工具级，非绕过）**：`ilpatch_vc1637/Program.cs` 新增 `BranchRelax.WidenOutOfRange()`——写出前先「干写」一次让 Cecil 算真实 `Offset`，凡短跳转目标越界的自动升级为长跳转，循环到 0；三条写出路径（增量 / 幂等复制 / 非增量）全部接上。实测 `[relax] 短跳转越界升级为长跳转：13 处`，hf4 补丁 DLL 2,025,984 → **2,026,496 B**（余量 2,048）。修后 `IL_0022: brfalse IL_00BD`（长跳转，目标正确）。

**同时修掉的第二个缺陷（用户当场指出）**：`GetPatchedPlain()` 原来只在「完全没票」时落防封基线；**「有票但解不开」（旧 payload sha 铸的票 / 票据吊销 / 损坏）直接 decoy → 官方 DLL 原样跑 ⇒ 防封消失**。已抽成 `TryAntibanBaseline()`，两条失败路径都先落基线：防封密钥只由载荷 sha 派生，**与票/卡密彻底解耦**。

**验收**：正式包 md5 `c8cbc99843b992cb4a738359a8e7411c`（121,888,473 B，载荷 sha `0973366…` 未变，门禁 7 项 FAIL=0，凭证 `09_test/无限升级/harden/c8cbc998….stamp`）；装机后 `patched dll injected (patched=2026496 pad=2048)` + `block_report=1`；用户实操「御灵升级」**不崩**（L3 终审通过）。证据 `09_test/无限升级/crash_20261027_0046/`（tombstone_24/25 + crash buffer）。

**通用教训（已并入路线图 §7）**：① IL 插入前必须做跳转放宽，短跳转越界是「单帧 + 页对齐 ACCERR」这类谜之闪退的常见根因；② 防封类补丁的解封失败回退链**不得经过任何授权判定**。
