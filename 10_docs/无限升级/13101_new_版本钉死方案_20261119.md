### 3.5 边界（必须说清，别当保证）

`ResVersionApi::TryGetVersion` 读的是 **YooAsset 包内资产** `Assets/Bundles/res/res_version.txt`（IL_003D / IL_004A 明文串），即「已下载资源包的版本」，**不是触发下载的版本源**。因此：

- 钉死 `GetVersion()` **能确定**挡住：`检测到版本更新,请重启游戏` 提示、`hasResUpdate` 标记、`UpdateTestResVersion` 比较结果、`推荐更新`族；

## 9. 「禁止热更」在本项目的准确语义 + 本次失效根因（lead 2026-11-19 裁决口径）

### 9.1 语义：不是「骗过客户端」，而是「命中变体后强制覆写」

本项目的「禁止热更」**既有实现**＝`HookExec` 命中变体后走 `mode=selfarray` / `memcpy`，把官方热更那份字节**顶掉**，换成本地补丁 DLL。12.x 日志原文：

```
[Wxsj] patched dll injected (hit #1, ... pad=5632 [HOTFIX MISMATCH -> FORCED PATCH: hot-update neutralized, save safe])
```

对应代码 `mod菜单/starry-mod-menu/app/src/main/jni/Games/WxsjMod.cpp`：

- `PickDllVariant()`（:90-98）**两轮**：先 `(len, hash)` 精确匹配，再**只比长度** `officialLen == len`；
- 命中即强制覆写（:240-245），日志尾 :271 打 `hot-update neutralized`；
- 两轮都不命中 → :233-238 `no variant for len=… : PASSTHROUGH official` + 一次 toast「游戏热更版本未识别…新功能请等人工更新安装包」。

⇒ 它**不依赖**任何版本号补丁；版本号只影响「强制更新 UI 弹不弹」，与装载无关。

### 9.2 本次失效根因（纯长度匹配失败，与版本面无关）

| 环节 | 事实 |
|---|---|
| 官方换代 | 2,738,688 → **2,746,368 B**（+7,680），fnv `0xd31dc94b29a8bb0d` → `0xd303f1e9c7154db9` |
| `kDllVariants` 现有行 | 2738688 / 2030080 / 2028544×3 —— **无 2,746,368** |
| 第一轮精确匹配 | len 不符 ⇒ miss |
| 第二轮长度匹配 | 仍然 len 不符 ⇒ miss（历史 FORCED PATCH 只救「同长度不同字节」） |
| 结果 | `PASSTHROUGH official`：跑官方新 DLL，菜单在、功能全无、**不报错**（存档安全） |

> 结论：**修法就是补一行变体 + 用新官方重打载荷**（方案 A）。这与 11-10 那次「同长度换代靠 FORCED PATCH 兜住」是两种情形，不能混用。
