### 存疑（不影响装机，装后据日志收敛）

1. 对照方是「调 setter」还是「裸写字段」：`libwbmod.so` 只泄漏 `set_Money` 等**方法名字符串**，未见 `il2cpp_*` 调用（进度 §11：libwbmod 一次都不调 il2cpp API）⇒ **更可能是裸写字段**。我们走 setter 属**实现手段偏离**（目标状态一致、且能拿到 UI 刷新），已在本次向用户说明并获同意。
2. 对照方 setter 实参常量（+99999 还是置 999999）：其日志只打 `verified before/after`，未打增量 ⇒ 未解析；我们用可配置累加。

## 五、第 2 轮增补（2026-11-02）：免广告 + 寿元自增符号修复

### 5.1 寿元自增曾经把角色弄死（事故 → 修复，已闭环）

| 项 | 内容 |
|---|---|
| 现象 | 用户报「寿元自增为什么会成为负数？导致直接死了」 |
| 根因日志 | `LifeTimeIncSpeed ON orig=-1.00 x1000 -> -1000.00` + 游戏自身 `陌杰 获得寿元自增速度 : -1000` |
| 判定 | `LifeTimeIncSpeed` **不是增速而是寿元流逝速度**，默认 **-1**（每秒扣 1）。按名字当增速 ×1000 ⇒ 每秒扣 1000 ⇒ 寿元见底暴死。**属实现侧语义错误**，对照方未提供该项语义证据（其菜单项叫"寿元自增"，同样无法从字符串判定） |
| 修复 | `IncSlot.forcePositive=true`：取绝对值放大（-1→+1000），OFF 按 `orig` 精确还原；`target` 加 ±1e6 钳制 |
| 修复后实测 | `LifeTimeIncSpeed ON orig=-1.00 -> x1000 = 1000.00 (now 1000.00) [取正:…]`，用户实测寿元上涨、「功能都没问题了」 |
| 已落经验 | `10_docs/_state/pending_experience.md`「`*IncSpeed` 类字段名不可信——可能是流逝/递减速度」 |
