## 2. 落点（方法名级 + RVA + ABI 事实）

实例获取：`Immortal.GameMgr::get_Player` @0xF74998 = `ldr x0,[x0,#0x68]; ret` ⇒ 钩 `GameMgr::Update` @**0xF6F788**（`sub sp,sp,#0xe0`，序言字 `0xD10383FF`）拿 `this`，再读 +0x68 得玩家对象。

### ABI 结论（易踩）
1. **managed argc 不含 `MethodInfo*`**：`PlayerLogic::AddExp` = `mov x1,xzr; b CharacterLogic::AddExp` —— x1 是 IL2CPP 生成的 `const MethodInfo*` 槽，**不是** bool 参数。按 `(double,bool)` 解析必 miss。
2. `PlayerLogic` 只覆盖 12 个方法（`.ctor/AddApoItem/AddExp/AddLifeTime/AddMoney/AddRelationship/ClearAction/Dead/NaturalDead/RefreshPetMood/RemoveRelationship/ResetApoAttr`），**setter 全在 `CharacterLogic`** ⇒ 类句柄必须取 `CharacterLogic`。
3. 所有数值 **double**（`ldr d0` / `str d0`），不是 float 也不是 int。

## 3. 实现要点（Byyxx2Mod.cpp）

- 挂点：`HookAtRva(0xF6F788, 序言 0xD10383FF)` → 失败转 by-name（`Immortal.GameMgr.Update(argc=0)`）。
- 字段偏移**不写死使用**：`DeriveImmOff()` 从 getter 首指令 `ldr dN,[x0,#imm]` 反推（要求首指令形态 + 次指令 `ret` + Rn=x0），与静态值不符只打 W 日志并采反推值。
- 动作排队：菜单点击只置位 `g_pending`，真正执行发生在**游戏线程的 Update 钩子里**（避免跨线程碰 il2cpp）。
- 读值：直接按偏移读 double；写值：`runtime_invoke` 调 setter/Add*（拿 UI 刷新与变更事件）。
- 自增：Toggle 记原值，ON=`原值×倍率`（原值为 0 时给倍率本身），OFF=还原。
- 每次动作打 `before/after`，与对照方的 `verified %s before=%.2f after=%.2f` 对齐，便于回归比对。
