# 《999秒幸存者》V0.0866 功能风险与验收清单（analyst，2026-11-15）

> 用途：给 L3 实测用。每项给「用户一眼能看出来的现象」= 生效判据；「已知副作用」= 看到也属预期，不算失败。
> 前提：六项均为**菜单开关**，全关时应与原版无差异（0 hook 懒装）。

## ① 无敌

| 项 | 内容 |
|---|---|
| 生效判据（一眼可见） | 被小怪/Boss/子弹命中时，**左上血条数值与血条长度不再下降**；死亡结算（复活/结算面板）不出现 |
| 半生效表现 | 血条在掉但人死不了 → 说明只钩到 hpcheck 未钩 playerhurt（正常中间态，可接受） |
| 已知副作用 | 受击白闪/受击音效可能消失（playerhurt 被整段 return 时）；吸血、反伤、受击回能等依赖「受伤事件」的机制失效；部分关卡「濒死触发」类天赋永不触发 |
| 不该出现 | 人物卡在原地不动、敌人也不动（说明误 hook 到 player.move 或全局 hurt） |
| 撤销验证 | 关闭开关后 10 秒内恢复掉血，无需重启 |

## ② 伤害倍率

| 项 | 内容 |
|---|---|
| 生效判据 | 同一把武器打同一只小怪，**击杀所需子弹数明显减少**（建议 5x）；敌人头顶飘字数字变大 |
| 半生效表现 | 平A变快但元素/技能伤害没变 → 只覆盖了 enemyhurt 主路径，元素族 8 个函数未钩 |
| 已知副作用 | 数字溢出（int 取整）可能出现异常小值或负数；击杀统计/金币结算数值暴涨；Achievement 计数疯涨可能一次性刷出大量成就红点 |
| 不该出现 | 玩家自己也被秒（说明 hook 到共用 hurt 且未区分玩家/敌人）；游戏卡顿（每帧遍历失败） |
| 撤销验证 | 关闭后 1 次攻击即恢复原伤害 |

## ③ 移动速度

| 项 | 内容 |
|---|---|
| 生效判据 | 同一方向按住，**角色位移明显变快**，摄像机跟随正常不抖 |
| 半生效表现 | 只有面板数值变、实际速度不变 → 说明写的是 stat 副本而非 stat.sp，或写点被 recountstat 每帧覆盖 |
| 已知副作用 | 速度过高会穿透碰撞/卡进墙（引擎穿透检测按固定步长）；冲刺/位移技能可能超模；怪物 AI 追不上导致「刷不出怪」的错觉 |
| 不该出现 | 角色抖动/瞬移回原位（说明同时改了 movev 输入向量）；敌方也变快 |
| 建议倍率 | 1.5x–2.5x，**不建议 >4x**（穿透风险） |
| 撤销验证 | 关开关后立刻恢复原速 |

## ④ 解锁所有皮肤

| 项 | 内容 |
|---|---|
| 生效判据 | 皮肤面板里**原本灰锁的皮肤全部变为可选/可装备**，装备后进关外显生效 |
| 已知副作用 | ①成就/图鉴红点集中弹出（一次几十个）②商店里「已拥有」条目变多、购买按钮消失 ③**付费内容被本地判定为已拥有**（仅本地视觉，不改服务端资产）④解锁动画/奖励弹窗可能连播 |
| 不该出现 | 进入皮肤面板闪退（说明 haveac 返回类型/调用约定错，返回了非 bool）、主界面卡死 |
| 撤销验证 | 关闭后重进面板，锁定态恢复（不写存档则无残留） |

## ⑤ 无限解锁券

| 项 | 内容 |
|---|---|
| 生效判据 | 用券解锁成就/皮肤时，**券数量不减少**（或解锁不再弹「券不足」），且解锁成功 |
| 半生效表现 | 券显示不减少但解锁失败 → 余额回写在 calculhave 之后才生效，需要改到扣减前 |
| 已知副作用 | 若同时改了 needcoupon=0，可能出现「0 券解锁」文案异常；存档文件中券数值与显示可能不一致（本方案不写盘，重启回滚属预期） |
| 不该出现 | 券变成负数、界面显示乱码数字（int 溢出） |
| 撤销验证 | 关闭后正常扣券；重启游戏后余额为原始值（**这是预期**，不是 bug） |

## ⑥ 免广告

| 项 | 内容 |
|---|---|
| 生效判据 | 点「看广告复活 / 免广告购买 / 双倍经验」按钮，**不弹广告直接到账**（奖励弹窗/数值立刻变化） |
| 半生效表现 | 按钮可点但点了没反应 → 只 hook 了 getadcheck，未接三个业务入口；奖励到账但界面不刷新 → 业务函数体被跳过、UI 回调丢失 |
| 已知副作用 | 广告 SDK 未初始化时日志可能出现 Dirichlet/Pangle error（属正常，不影响功能）；首次进入广告按钮可能仍短暂置灰（SDK 加载态） |
| 不该出现 | 卡在加载转圈（业务函数被 return 但 UI 等回调）、点广告按钮闪退 |
| 撤销验证 | 关闭后点按钮能正常拉起广告（**需要网络与广告库存**，离线环境拉起失败属正常） |

## 通用观察项（六项共用）

| 观察点 | 期望 |
|---|---|
| 菜单全关启动 | 与原版无差异，logcat 无 Mod_Menu 相关崩溃 |
| 单项开关切换 | 立即生效（≤1 帧~1 秒），不需重启、不需重进关卡 |
| 关卡内切换 | 不闪退；切场景（结算→主菜单）后开关状态保持 |
| 崩溃特征 | 若出现 SIGSEGV 且栈落在 libil2cpp.so 的 hook 目标 RVA 附近 → 序言校验失败/双钩，需回滚该槽位 |

## 已知全局风险

1. **Themis（libthemis.so）运行时校验未验证**：若对 libil2cpp.so 有完整性校验，native hook 可能被拦（表现为启动即退或 hook 后立即崩）。当前无证据表明启用，标**待验证**。
2. **存档回读**：任何写 Savedata 字段的方案在重启后可能回滚（loaddata 从文件重建），只有 hook 消费点才稳定。
3. **服务端权威**：本作有 TapTap 云存档（taptapmanager/pctaptapmanager），若云端覆盖本地，部分数值改动可能被拉回。
