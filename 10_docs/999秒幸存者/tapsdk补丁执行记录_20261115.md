## 5. 风险与交接

**R1（中）dex 版本 039 → 035**：smali 2.5.2 默认按 API 级 0x035 输出。035 是全平台通用 dex 版本，ART 正常加载；且两 dex 均能完整回读说明其中**不含** 038/039 才有的 `invoke-polymorphic` / `const-method-handle` 指令。若 builder 要求与底包严格一致，可在汇编时加 `-a 29`（输出 039）再复验——**当前版本按 035 交付**，理由：改动面更小、已验证回读闭环。
**R2（低）体积增大**：classes2 +93,068 B、classes3 +71,140 B（重汇编后 map_list/对齐与原始 dex 优化差异）。不影响加载；打包时按常规 deflate 或 store+4 字节对齐均可。
**R3（低）预装门禁**：classes2.dex 现已与底包不同 → 查12「TapTap 方案」应转 PASS。若门禁还校验 `TapSignKit`/`Provider` 的具体特征，本记录可作证据。
**R4（待实测）**：本补丁**只保证客户端放行**，TapTap 服务端仍按 appId/包名/签名三元组校验；能否登录须装机 + 用户 L3 实测。
**未做**：未改 `.so`、未改 `AndroidManifest.xml`、未打包、未装机、未签名（全部留给 builder 的组装/签名阶段）。

## 6. 交给 builder 的落位说明

1. 用 `07_patched/999秒幸存者/tapsdk/patched/classes2.dex`、`classes3.dex` **替换**APK 内同名条目（外科 zip 替换，其它条目字节不动）。

3. 替换后重签（工作区 `01_tools/starry_release.jks`），**不要**再动 dex 内容，否则 md5 与本记录不符。
4. 装机后若仍被 TapTap 拒绝：先看 logcat 是否有 `signature not match` / 门闩 1001，再决定是否加 `-a 29` 重汇编或改 `showGatekeeperError`。
