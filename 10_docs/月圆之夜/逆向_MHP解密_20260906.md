## 三、libil2cpp 定案（P2，本轮最重要结论）

**CLAIM**：libil2cpp.so 运行时内存与 APK 内文件逐字节一致（代码区零修改），MHP 对 il2cpp 零运行时补丁，"静态融合"实锤——纯静态分析该文件即运行代码。

**EVIDENCE**（真机 f9a116a2，frida 17.16.4，三次会话）：
1. 双 FNV-1a 逐 MB 哈希全 r-x/r-- 区（171 块）：**仅 6 块差异**，且全部位于 .data.rel.ro/.data 指针区（文件内相对值 vs 内存运行时指针，如 `0x000525a9` vs `0x774f12b9`）→ 加载重定位，非补丁。
2. .text / plt / il2cpp节(生成代码) / .rodata / .eh_frame **差异为 0**。
3. dynsym 仅 2273 项（libc++ 残留 + zlib WriteZStream 族），il2cpp 内部符号全剥；`.gnu_debuglink` 指向 `libil2cpp.sym.so`（包内不存在）。
4. 首轮报 164 块差异系 JS 哈希精度 bug（普通乘法超 2^53），已修（Math.imul），作废重测。

**辅助事实**：
- "global-metadata.dat" 字符串不在文件内，运行时以明文出现在匿名堆（0x764001f831，带指针表）→ 路径运行时构造。
- 热更以解释器内部格式驻留：堆中出现 `yyzy_hotfix`、`hotfixMainScriptName` 等 HybridCLR 串 → **解释器模式无 PE/BSJB 形态**（解释先前 BSJB 全扫 0 命中）。
- GG_ 相关加密 blob 在堆中出现两份（0x74e01df795 等同内容双份）。
- `.game_info` 节：`idHYuYAsyBOSkCDM|1|3560|<uuid>|com.ztgame.yyzy|1.6.30.1` + 188B 签名。

### 8. 路线决策点（待用户选定）

- **路线 A 静态改包**：解密 .ZTG → IL patch → 重加密（LZMA+XXTEA 可逆链已通）→ 外科 zip 回 APK。
- **路线 B 运行时内存补丁**（解释器 hook，符合工作区「轻量 JS 旗标」惯例）：星光 so 在 ZTG 映射进内存后，按方法体字节签名搜索→内存 patch IL（解释器逐条读取内存 IL，改字节即生效）。不依赖重加密，天然免疫热更新覆盖；需处理 ZTG 加载完成时机。
