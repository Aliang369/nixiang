## 二、关键技术定案（全部实测）

### 2.1 YooAsset 定制版（1.5.x 系，解释器侧）
- 二进制清单字段：`u16len(BundleName) + u16len(FileHash=md5hex32) + u16len(FileCRC=crc32LE-hex8) + i64(FileSize)`；DefaultPackage 清单中 hotfix bundle 记录 @ **0x18d**（BundleName=`defaultpackage_assets_hybridclrdata_hotfix_bytes.rawfile`）
- APK 内 rawfile 条目**必须 STORED**（原包即 STORED；DEFLATED 时游戏读取失败回退下载）
- rawfile 解密链：XXTEA(key=`yyzy_hotfix`, 标准 delta) → LZMA_ALONE(5B props 沿用原流) → 容器(int32 count + 7bitlen name + int32 len + data)。自研 encrypt 与游戏**位级兼容**（re-encrypt(original)==original 全等验证）
- base_* 补充程序集 = **标准 PE DLL**（dnfile 可解析）；hotfix_* = .ZTG（ztg_dump.py 解析，opcode 重映射 0x65=neg/0x6B=conv.r4/0x5A=mul）
- 判定链（HostPlayModeImpl::GetDownloadListByAll，IL 实证）：`IsDeliveryPackageBundle(恒false, DefaultDeliveryQueryServices 桩) → IsCachedPackageBundle → IsBuildinPackageBundle(QueryStreamingAssets) → 否则下载`
- `__info` 格式（CacheFileInfo::WriteInfoToFile IL + 真机样本互证）：`u16(8) + crc32hex8 + i64(文件大小)`，共 18B；CRC 实证 = 对 __data 的 crc32

### 2.2 沙箱缓存注入（模拟器有效，真机被 MHP 拦）
- 目标：`/sdcard/Android/data/com.ztgame.yyzy/files/yoo/DefaultPackage/CacheRawFiles/<md5前2>/<md5>/`
- 文件：`__data.rawfile`（补丁容器密文）+ `__info`（18B）
- 缓存 GUID 必须与**生效清单**的 FileHash 一致（清单在 NeedCheckPatch=false 时 = APK 内置补丁清单）
- 真机注输方式：无需 root——apktool 重编译 ZTApplication（注入 `starryRun` 静态方法 @ attachBaseContext 开头）→ 移植 classes.dex（**不**改 manifest、**不**加 dex 条目；Provider+manifest 移植方案会引入额外变量且同样被 MHP 拦，弃用）

### 2.3 MHP 白名单崩溃（真机）
- 签名：SIGSEGV strlen(NULL)，fault addr 0x1，线程名 `Catch Jack`（MHP catch 线程）
- 帧链（tombstone）：`libc __strlen_aarch64 ← libil2cpp 0x1264a84 ← 0x1254c00 ← 0x122745c ← libunity 0x3a4e50（UnityPlayer onCreate JNI 链）`
- 触发条件：进程启动时沙箱 `CacheRawFiles` 存在**任何**条目（原版容器 ccdda854 也崩；fc4ca91d 与沙箱清单一致也崩；内容/命名/GUID 全部无关）
- 注入代码本身无罪：同款注入代码 + 不写缓存时正常启动；无注入代码 + adb 手工塞缓存同样崩
- 注入代码已验证工作：真机启动即建目录写文件（Provider 版与 ZTApplication smali 版均验证）

### 2.4 需要澄清的历史误判
- 早期「FileOverflow」根因 = rawfile 用了 DEFLATED + 清单三字段未同步（非 MHP）
- 模拟器矩阵第一轮「存活」假阳性 = 沙箱清单被 APK 清单覆盖（游戏每次启动重刷）+ root 建目录属主错误导致 UnauthorizedAccessException 循环
- T5(all_fixed) 模拟器 SIGABRT 与真机 strlen 崩溃是**两种不同机制**；模拟器 SIGABRT 的触发条件后来未复现（当时脚手架污染）

## 四、UpdateGold 上下文（供下次直接使用）

- 签名 `UpdateGold(int delta, bool x) → bool`，MethodDef rid=33736，fat 体 195B，代码起点 dll 0x383968（容器内 base+0x383968）
- 逻辑：+0x41 喂 `neg` 后 `bge.s 0x68` 跳过扣费失败分支；+0x79 喂 `add` 更新余额

- bool 方法：rid 3152（tiny 26B @0x32dc8，代码@0x32dc9）/ rid 9339（fat 56B，代码@0x8cf04）
