## 2. 引擎判定：Cocos Creator 3.7.1

- [实测] `assets/src/settings.json` 首字段 `"CocosEngine":"3.7.1"`，`platform=android`。
- [实测] `lib/arm64-v8a/libcocos.so` 23,259,680 B；`lib/armeabi-v7a/libcocos.so` 15,432,084 B。
- [实测] **无** `libil2cpp.so`、**无** `global-metadata.dat`、**无** `bin/Data/Managed` ⇒ 不是 Unity IL2CPP，不走 Il2CppDumper/RVA 那条路。
- [实测] Manifest 内 `<meta-data android:name="android.app.lib_name" android:value="cocos"/>`。

### 2.1 脚本形态（决定「改什么层」）

| 载体 | 状态 | 说明 |
|---|---|---|
| `assets/main.js`（4,970 B） | **明文** | Cocos 启动入口，含 `gg-hot-update` 热更注入段（见 §6） |
| `assets/src/chunks/bundle.js`（1,026,924 B） | **明文** | 只有 8 个模块：cjs-loader / env / javascript / proto / babel-helpers / **tdanalytics**；**不含玩法逻辑** |
| `assets/src/cocos-js/cc.js`（1,318,355 B） | 明文 | 引擎 |
| `assets/assets/*/index.jsc` × **30** | **加密** | 每个 bundle 一份；`main/index.jsc` 2,627,980 B 最大 |
| `assets/src/settings.json` 资源清单 | 明文 | 含 bundle 版本表 |

- [推断] jsc 加密方式：逐文件头部互不相同（`9b32da51…` / `7568 3aec…` / `9292 b96b…`），文件长度全为 4 的倍数（132 / 124 / 2,627,980）⇒ 32-bit 分组密码 + 每文件独立初值，符合 **XXTEA（Cocos「加密脚本」）** 形态。
- [实测] `libcocos.so` 内 **搜不到** `xxtea` 字样（`grep -a -c -i xxtea` = 0）⇒ 符号已剥离，**密钥不能靠 strings 拿**，必须静态反编译定位解密入口或运行时 hook。
- 影响：**玩法 JS 静态读不到**。改包要么先解 jsc（拿密钥/算法），要么改明文层的 `main.js` 注入，要么走 native `evalString` 注入（skill `re-extract/cocos-js-from-scratch.md`）。

## 5. 登录方式与签名

### 5.1 登录 [实测]

- **账号体系 = 喜扑 XP SDK**：`Application` 就是 `com.xipu.msdk.XiPuSDKApplication`，`xp_appid = 4462d9dba7dfe4c277ba120cdd5e028a`，UI 全在 `com.xipu.msdk.ui.*`（WelcomeActivity / PrivacyPolicyActivity / BrowserActivity 等），`SDK_UI: 13`。
- **第三方登录 = TapTap**（`tapClientId` 已登记，`isUseThirdLogin: true`）。
- **一键登录 = 阿里号码认证**：`com.mobile.auth.gatewayauth.*` + `libpns-2.14.17-LogOnlineStandardCuumRelease_alijtca_plus.so`；`number_auth_secret` 已内置。
- `onlyShowAccountLogin: false`、`autoBackgroundLogin: false`。

### 5.2 TapTap 验签门闩存在（改包要处理）[实测]

`classes2.dex` 内可见：`GatekeeperRepository`(8)、`GatekeeperManager`(16)、`GatekeeperStorage`(11)、`GatekeeperApiService`、`GatekeeperError`、`InitializerServiceImpl`(2)、`GatekeeperLoadedSuccessfully`。
⇒ 与「绿梦/蛋壳战机」同类结构，锚点须**按 4.10.4 现取**，不能跨版本抄（skill 明写）。

### 5.3 签名 [实测]

⇒ 注入类**不要**塞 `classes.dex`（只剩 1,821）；首选 `classes7.dex` 或新建 `classes8.dex`。

### 6.2 资源与热更

- 30 个 Cocos bundle：`internal, resources, main, ab_base, ab_home, ab_audio, ab_cn, ab_long_text, uiImages, ab_mini_home, ab_mini_merge, ab_act_*`（约 18 个活动包）。
- 资源服务器：`"server": "https://res.ginkgogames.fun/android/"`。
- 热更机制：`assets/main.js` 内 `gg-hot-update` 插件，热更根 `writablePath/gg-hot-update/`，通过 `localStorage.GGHotUpdateSearchPaths` + `jsb.fileUtils.setSearchPaths` **把热更目录挂到搜索路径首位**。
- 内置版本：`assets/build-in.version.manifest = {"version":"c2a1f3be53e6ff98702dad73ce2b8b37"}`；`build-in.project.manifest`(456,070 B) 记录了全量资源 md5/size。
- [推断] 因为热更目录优先级更高，**改包内的 `main.js`/`index.jsc` 一旦远端下发同名文件就会被覆盖**（同 `re-lessons` 里餐厅游戏「热更整文件替换 index.jsc」的坑）。改包方案必须先确认远端是否下发 `main.js` 与对应 `index.jsc`。

## 7. 待验证清单与下一步建议（给 lead 决策用）

| # | 问题 | 建议动作 | 代价 |
|---|---|---|---|
| 1 | jsc 到底能不能解 | `libcocos.so` 静态找解密入口（cocos 3.7.1 的 jsc key 通常以常量形式在 so 里，符号已剥离，需 IDA 交叉引用）；退路＝运行时 hook 解密函数 dump 明文 | 中 |
| 2 | 明文层能不能直接注入 | 试改 `assets/main.js`（明文、启动最早）注入一小段 JS，看能否跑起来并打到日志 | 低（**建议第一个做**） |
| 3 | 热更会不会覆盖改动 | 真机跑一次，`adb shell ls /data/user/0/com.wbxxm.wbxxm/files/gg-hot-update/` 看落地文件清单 | 低 |
| 4 | TapAD 宿主指纹是否拒绝改包 | 最小改包（仅换一张 res 图）冒烟，看广告是否报错、游戏主体是否正常 | 低 |
| 5 | 登录实际走哪条路径 | 真机 logcat 抓 `TapTapLogin`/`XiPu`/`gatewayauth` 关键字（用户操作，AI 不截图不乱点） | 低 |
| 6 | 强制网页登录要不要做 | 若需改签，按 4.10.4 现取门闩锚点（`GatekeeperRepository`/`InitializerServiceImpl`/`LoginActivityImpl`） | 中 |

**可行路线倾向（[推断]，未验证）**：Cocos 3.7.1 + 无壳 + TapSDK 明文 ⇒ 优先「明文层注入（main.js / Java 侧）」这条低成本路线；jsc 解密只在必须改玩法 JS 时才投入。

**设备注意**：包内只有 arm64-v8a / armeabi-v7a，**没有 x86**；雷电等 x86 模拟器要靠 houdini 转译（native hook 会踩坑，见历史经验）。真机 f9a116a2 为 arm64，作为主测试机。
