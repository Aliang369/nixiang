> 锚点口径（2026-10-30 用户纠正后）：**方法名是稳定锚点，指令特征不稳定**（版本/热更会改代码）。
> 特征码只能当"安全校验/兜底"，不得当复刻主锚点。

## 2. 五个修改点（语义 + 地址）

| ID | 语义 | 文件偏移 | 原指令 | MOD 改法 |
|---|---|---|---|---|
| A | 某取值接口直接返回 **999999** | `0x1DBCC88` | `bl` | → `bl` code cave，返回 999999 |
| B | 字段 `+0x15C` 夹取上限 **99999 → 999999** | `0x1F62088` | `csel w8,w8,w9,lt` | → `b` code cave（或直接改常量 `0x869F/1` → `0x423F/0xF`） |
| C | `bool (this.+0x15C >= 参数)` **恒真** | `0x1F6903C` | `cset w0,ge` | → `mov w0,#1` |
| D | `bool (f() > 0)` **恒真** | `0x1DBD5B4` | `cset w0,gt` | → `mov w0,#1` |
| E | 浮点条件 `(s9 <= s8)` **恒真** | `0x2059C14` | `cset w0,ls` | → `mov w0,#1` |
| F | `CharacterStats::UpdateFocusPoints` 扣点变空操作（**专注点不消耗**）<br>metadata 全局方法索引 **1040** → vaddr `0x1F5DA0C` | `0x1F5CA80` | `adds w8, w22, w21`（`focus += delta`，随后 `min(...,max)` 并夹 0） | → `b` cave：`cmp w21,#0; csel w9,w21,wzr,gt; adds w8,w22,w9; b 0x1F5DA84`（delta 夹成 ≥0，扣点无效、加点照旧） |

B/C 指向同一实例字段 `+0x15C`（int，带 99999 上限 + 参与"够不够"判定）⇒ 货币/资源计数一类。

但**除 stringLiteral 外全部明文**。已用「名字偏移合法性 + 计数互校」定表（`07_tmp/name_map_v6.py` 一族脚本）：

## 4. 差的一环：方法名 → 函数地址

`Il2CppCodeGenModule.methodPointers` 在文件里**全是 0**，要靠 `.rela.dyn`（591,195 条 `R_AARCH64_RELATIVE`，
其中 527,927 条指向代码段）在加载时填充；且 **`Assembly-CSharp.dll` 这个 module 名字符串在 .so 里被抹掉了**
（三份包都搜不到，`mscorlib.dll` 等 66 个名字还在）⇒ 无法按名字定位整个 module 数组。

结论：**静态做不出可靠的名字→地址表**（不是 metadata 难，是 .so 侧被加固/抹除）。
正解＝**运行中解析**：进程内 il2cpp 已建好 CodeRegistration/codeGenModules、TP 也已解密，
在进程内读 `CodeRegistration → codeGenModules[i].methodPointers` + 明文 metadata → 得到完整 `名字 → 地址`。
这需要一次设备上的进程内读取（frida 或自写 so）；LDPlayer 是 x86_64+ARM 翻译，arm64 frida-server 起不来，
要在 arm64 真机或换注入方式上做。

### F 点的定位链路（2026-10-30 22:35，可复现）

1. 明文 metadata 在手：`07_tmp/mz.bin`（24.2 MB，运行时 `MetadataCache` 指针所指，上一轮 dump）。
2. 表结构用「typeDef.methodStart 区间内 method.declaringType 必须等于 typeIndex」这条不变式反推：
   `typeDefinitions` 步长 88、`methodStart` 在 **+36**、`method_count` 在 **+68**；`methods` 步长 36、`declaringType` 在 **+4**、名字索引在 +0（指向 `names` blob `0x46DC58`）。
   注意：`+40` 不是 methodStart（按标准 v27 套会读到 0xFFFFFFFF）。
3. `CharacterStats` = typeIndex **164**，方法区间 970..1069；`UpdateFocusPoints` = **1040**（邻居：`ResetSpentFocus`=1039、`CanFocus`=1008、`get_MaxFocus`=981、`get_SpentFocus`=973）。
4. 运行时地址：`/proc/<pid>/mem` 整段 dump 出 libil2cpp（base `0x400023000000`，`0x44E9000` 连续四段）；
   `codeGenModules` 指针数组在 `base+0x40F7F30`；`[8]` 即 `Assembly-CSharp.dll`（38115 个方法），
   其 `methodPointers`（struct 偏移：name +0、count +8、pointers +0x10）**索引就等于全局方法索引**
   ——用 `SkillRoll::Roll`（1148，函数体 vaddr `0x205AA9C`）做锚点校验，命中索引正好 1148。
5. ⇒ `methodPointers[1040]` = `0x400024F5DA0C`，即 vaddr `0x1F5DA0C`（文件偏移 `0x1F5CA0C`）。
6. 设备侧读内存要用 `toybox dd`（本机 `/system/bin/dd` 是 toolbox 空壳，会报 `no such tool`）。
