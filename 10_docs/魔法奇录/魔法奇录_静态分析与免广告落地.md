# 魔法奇录（com.shw.mfqlm1 1.0.1 vc2）· 静态分析与免广告落地

> **状态：L3 终审 2026-11-26 通过**（用户原话『功能没问题了』）。
> 本文件是该游戏**唯一现行技术文档**。范围：官方原版底包 → 星光菜单包 → 免广告（唯一功能）落地 → 热更层同源补丁 → 装机验证。

## 1. 结论

1. **引擎与权限分层**：Cocos Creator 2.x（`libcocos2djs.so` + `assets/assets/Game/index.js` **明文 JS**，8.97M 字符）。战斗是**服务器权威**（客户端只上报 `c_damage_entity_3{handle,skill_id,range_idx,grid,pos}`，无伤害字段；`s_damage_other_val` 只做飘字）⇒ 秒杀改不动，本轮因此按用户 21:21 收窄指令**只做免广告**。
2. **免广告有三条客户端路径，本作实际走第二条**（真机日志实证，见 §4.1）：
   - 平台层 `_playAD` + `callNative("showAd")`（`insideAd != 1` 时）；
   - **内置广告** `BuiltInAd.showAd`（`AppConfig.insideAd == 1`，本作即此，底层挂 sigmob/穿山甲聚合）；
   - 外层 `SdkManger.showAd` 的次数/冷却/特权判断。
3. **实现**：JS 侧三处短路（外层入口 + 内置广告 + 平台层），开关经 `jsb.reflection.callStaticMethod("com/starry/magic/cocos/MfqlHooks","getRet","(I)Z",1)` 查询；Java 侧三层判据（后台允许 → bootstrap 单项门控 → 本地开关）与框架口径一致，不做「装上即用」。
4. **热更层必须同源打补丁**：本作 Android 端 `AssetsManager` 热更启用，游戏实际加载 `files/develop/cocosgame/assets/Game/index.js`（比包内大 2.1MB 的新版本），包内改动会被绕过 ⇒ 包内 + 热更两份都打同一套补丁。

## 3. 挂点表（`04_scripts/魔法奇录/mfql_patch_js.py`）

判据＝**全文字面计数必须恰好 1**（0 且标 `optional` 才允许跳过；>1 直接非零退出）。

| 钩子 | 锚点（逐字，含换行） | 命中（包内 / 热更） | 作用 |
|---|---|---|---|
| `outer_sdk` | `e.prototype.showAd = function(t, e, n, o, i) {\nvoid 0 === i && (i = !1);\n`（SdkManger） | 1 / 1 | 开关 ON 时**在次数/CD 检查之前**直接 `e.call(n)`，等价官方「终身免广告」特权分支 |
| `builtin_ad`（optional） | `t.prototype.showAd = function(t, e, n) {\nvar i = c.default.getTime();`（BuiltInAd） | 0 / 1 | 内置广告弹窗短路；老 bundle 无此类 ⇒ 跳过 |
| `free_ad` | `this._playAD.show(t, n, o, i);`（平台层） | 1 / 1 | 第三层兜底：照常发 `c_start_see_asd`，150ms 后手动 `SDKADRewardCanGet()+SDKADClosed()`（等价上报 `c_end_see_asd` 并走 successFun），不播原生 SDK |

- prefix 注入的桥：`window.__starryMfqlOn(i)` 先读 `window.__starryMfqlCache`，再 `jsb.reflection.callStaticMethod` 调 **斜杠格式** `com/starry/magic/cocos/MfqlHooks`，失败再试点分格式，异常全 catch 并记 `window.__mfqlBridgeErr`。
  **踩过的坑**：只写点分类名时 Cocos 2.x 桥抛异常 → 静默 false → 开关 ON 但广告照弹（v1 现象）。
- 版本识别日志：`[mfql] patch loaded v3`（加载即打，唯一的「补丁是否生效」探针）。

## 4. 出包链（复现入口）

### 4.1 三步可复现（Windows 实测）

```bash
# 1) 包内 index.js 打补丁（含语法自检）
python 04_scripts/魔法奇录/mfql_patch_js.py \
  --src 03_decompiled/魔法奇录/js/Game.index.js \
  --out 03_decompiled/魔法奇录/build/Game.index.v3.js
node --check 03_decompiled/魔法奇录/build/Game.index.v3.js

# 2) so（0 hook 模块）+ 菜单 dex
cd "mod菜单/starry-mod-menu/app/src/main/jni" && \
  HOST_OS=windows "<NDK>/ndk-build.cmd" NDK_PROJECT_PATH=../.. APP_BUILD_SCRIPT=./Android_mfql.mk \
  APP_APPLICATION_MK=./Application.mk APP_ABI=arm64-v8a,x86_64 \
  NDK_OUT="<starry根>/obj_mfql" NDK_LIBS_OUT="<starry根>/libs_mfql" -j8
cd "mod菜单/starry-mod-menu" && cmd /c "scripts\\win_build.cmd assembleRelease --offline"

# 3) 外科组装 + 签名（内部含 Manifest 注入、dex6、so、libc++_shared、index.js 替换）
python 04_scripts/魔法奇录/mfql_build_pkg.py \
  --base 02_apks/魔法奇录.apk --dec 03_decompiled/魔法奇录/apktool_1.0.1 \
  --menu-apk "mod菜单/starry-mod-menu/app/build/outputs/apk/release/app-release.apk" \
  --so-dir "mod菜单/starry-mod-menu/libs_mfql" \
  --index 03_decompiled/魔法奇录/build/Game.index.v3.js \
  --out "08_output/魔法奇录/魔法奇录_1.0.1_star_20261126b.apk" --java "<JDK17>/bin/java.exe"
```

- Windows 三个坑（都已内建在脚本里）：`ndk-build.cmd` 需要 `HOST_OS=windows` + PATH 含 `C:\Windows\System32`；`apksigner.bat` 经 `cmd /c` 必须传**绝对 + 反斜杠**路径，且其 GBK 输出要按 `utf-8/replace` 解码；中间产物一律落 ASCII 的 `%TEMP%\mfql_build`（java/cmd 在中文路径下会乱码）。
- `mfql_build_pkg.py` 的 Manifest 段用 `apktool d -f` 的文本 Manifest 改完再 `apktool b` **只取回二进制 AndroidManifest.xml**，zh 外科替换，不做整包重建。

### 4.2 热更层同源补丁（**每次热更换代都要重做**）

```bash
adb -s <serial> shell su 0 cp /data/user/0/com.shw.mfqlm1/files/develop/cocosgame/assets/Game/index.js /sdcard/mfql_index.js
adb -s <serial> pull /sdcard/mfql_index.js 03_decompiled/魔法奇录/hot/index.hot.js
python 04_scripts/魔法奇录/mfql_patch_js.py --src 03_decompiled/魔法奇录/hot/index.hot.js --out .../index.hot.v3.js
adb -s <serial> push .../index.hot.v3.js /sdcard/mfql_v3.js
adb -s <serial> shell su 0 cp -f /sdcard/mfql_v3.js <热更 index.js 全路径>
adb -s <serial> shell su 0 md5sum <热更 index.js 全路径>   # 必须 == 本地 md5
```

- 判据：重启后日志出现 `[mfql] patch loaded v3`；热更自身日志出现 `已经更新到远程最新版本` ⇒ 不会被回滚覆盖。
- 目标文件属主是 `u0_a81:u0_a81`、`600`；`cp -f` 会保留属主，**不要再 chown/chmod**（该路径 SELinux 会拒，白费一轮）。

## 6. 已知边界

1. **热更换代即失效**：服务端版本号上调会覆盖热更 `index.js`，按 §4.2 重打；包内那份不受影响（清数据/无热更时兜底）。
2. **后台依赖**：`game_id=mfql` 必须在后台「启用游戏」并「从菜单模板同步功能」（`features` 至少 `feat_num=1`）。实测未启用时 bootstrap 返回 `features: [] / menu_enabled: false`，native 掩码 `[V2] f=0` ⇒ 菜单开关点开也不生效（框架口径，非 bug）。
3. **异签名**：正式包用 `01_tools/starry_release.jks`（alias `starry`），官方包覆盖安装必报 `UPDATE_INCOMPATIBLE` ⇒ 需先卸载（原版 APK 在 `02_apks/`，可随时回装）。
4. **只做免广告**：秒杀/无敌/无限技能/多目标均未实现（用户 2026-11-26 21:21 收窄）。战斗服务器权威的技术事实见 §1，相关挂点分析保留在硬约束 D 区，不构成待办。
