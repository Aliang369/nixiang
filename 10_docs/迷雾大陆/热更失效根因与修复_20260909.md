## 二、锚点失配逐条核对（当前 `code` 6355d，Python 精确匹配）

| MwdlMod 锚点 | 结果 | 后果 |
|---|---|---|
| `function KH(t, e, i, o) {` / `function KH(t,e,i,o){` | **MISS**（新签名 `function KH(t,e,i)`） | 百倍伤害/无敌**不拼接** |
| `...getAttr(mS.MOV_SPEED)*t}` | **MISS**（新 `vS.MOV_SPEED`） | 移动速度**不拼接** |
| `qA.Hero`/`qA.Monster`/`qA.Summon`/`qA.Guardian`/`qA.Player`/`qA.ParasyteGuardian` | **MISS**（枚举改名 `qA`→`jA`） | 拼进去的判定引用死符号 |
| `scene.playerHandler.addCheat` | **MISS**（新版已无此客户端上报） | 反作弊屏蔽空转（无副作用） |
| `hex_md5(MUtil.Utf8Encode(...))` | **MISS**（新版已无聊天 md5） | 同上 |
| `this.isDormant\|\|(this.SkillComponent.tick(t)` | HIT | 无限技能仍拼接，但引用了死 `qA` |
| `t.prototype.onStageCheat=function(t){C(v.ShowErrorTips,p.EErrorTips.FightCheat)}` | HIT | 反作弊屏蔽仍有效 |

仍放行，所以现象是**静默部分失效**而非崩溃；若用户开着「无限技能」，拼接串里的
`this.unitType===qA.Hero` 会抛 ReferenceError，反而可能影响 tick。

## 三、新锚点（当前 6355d 实测，均唯一）

| 功能 | 新锚点 | 新实现要点 |
|---|---|---|
| 百倍伤害 | `i.target.damage=P}`（KH 尾，1 处） | `i.sourceUnit.unitType` ∈ {Hero,Summon,Guardian,Player,ParasyteGuardian} → `P*=100` |
| 无敌 | 同上 | `i.sourceUnit.unitType===jA.Monster` → `P=0`（怪打玩家归零） |
| 移动速度 | `return t=Math.max(0,t),this.AttributeComponent.getAttr(vS.MOV_SPEED)*t}`（1 处） | getter 内 `.call(this, 原值*m)`，玩家方 ×get_val(3) |
| 无限技能 | `this.isDormant\|\|(this.SkillComponent.tick(t)`（2 处，取首处） | 同旧逻辑，`qA`→`jA` |
| 反作弊 | `t.prototype.onStageCheat=function(t){C(v.ShowErrorTips,p.EErrorTips.FightCheat)}` | 原样保留 |

- 新 `KH(t,e,i)`：`t`=攻击方单位、`e`=受击方单位、`i`=伤害上下文
  （`i.sourceUnit`/`i.targetUnit`/`i.addPart`/`i.target.damage`）；最终伤害
  `P=Math.max(1, y*S*b*C*k*A*w*I*T*B*l*(1+E))`，落 `i.target.damage=P`。
- 单位类型枚举 `jA`：Hero=1,Summon=2,Monster=3,Missile=4,Guardian=5,Player=6,
  SceneObj=7,SceneRole=8,Corpse=9,ParasyteGuardian=10。
- 属性枚举改名 `mS`→`vS`（`vS.MOV_SPEED=310`）。

## 七、登录「指纹签名无效」修复（2026-09-09 晚，追加）

### 1. 现象
TapTap 网页登录成功、确认登录后游戏平台登录失败：
`errCode:10011, "[重定向请求返回业务失败], detail: code: 10045, msg: 指纹签名无效"`
（日志 `track.apmLog`，任务【平台登录】进度 98%）。消息来自**游戏平台服务器**——客户端把应用签名指纹上报，服务器校验不符 → 拒绝。

### 2. 根因（两级）
1. **伪装表缺 mwdl**：SignSpoof（`Games/../java/com/starry/magic/sign/SignSpoof.java`）的
   `fakeByPkg` 只含同厂 `com.hortor.yqzd`，无 `com.hortor.mwdl` → PGL 读到星光真实签名。
   - 读签路径实锤：PGL SDK（`ms.bz.bd.c.Pgl/j|b1.smali`）Java 层
     `PackageManager.getPackageInfo(pkg, 0x40=GET_SIGNATURES)` → `PackageInfo.signatures[]`。
   - 正是 SignSpoof `PackageInfo.CREATOR` 伪装能覆盖的路径。
2. **该 MuMu ROM 黑名单硬隐藏 `VMRuntime.setHiddenApiExemptions`**：
   - Java 元反射 / getDeclaredMethod / getMethod 三路全部 `NoSuchMethodException`；
   - JNI `GetStaticMethodID` 同样被拦（`exempt hidden apis via JNI 失败`）；
   - 后果=`PackageManager.sPackageInfoCache` 清不掉（`blocked, reflection, denied`），
     getPackageInfo 可能返回缓存里的真实签名。
   - app_process(root) 环境三条反射都能成功（68 个 declared methods 含
     `setHiddenApiExemptions`）→ 证实是**应用进程级** hiddenapi 黑名单，非方法缺失。

### 3. 修复
1. `SignSpoof.java`：新增 `MWDL_PKG=com.hortor.mwdl` + 官方证书（CN=1，
   SHA-256=67cf2df1…，2026-09-09 从官方 APK `apksigner --print-certs-pem` 导出 DER 778B）；
   `exemptHiddenApis()` 加多路回退（meta→declared→public）。
2. `MainModern.cpp`：`JNI_OnLoad` 增加 `TryExemptHiddenApis()`（JNI 直调，本 ROM 被拦但保留作通用兜底）。
3. `surgical_mwdl_14.0.0.sh`：classes3 注入顺序改为**先 loadLibrary 再 SignSpoof.install**
   （native 豁免先于 Java 安装）。
4. **设备级放行（关键）**：`adb shell settings put global hidden_api_policy 1`
   （root，模拟器通用，可逆：恢复 `… 0`）。设后重启游戏：
   `StarrySignSpoof: exemptHiddenApis(meta) OK`，伪装表含 `com.hortor.mwdl`。

### 4. 验证状态
- SignSpoof 豁免 OK + 伪装表含 mwdl（logcat 实测）
- 待用户：重新 TapTap 登录 → 确认 10045 是否消除 → 卡密 → 战斗实测

### 5. 注意事项
- `hidden_api_policy=1` 是**全局**设置，影响该 MuMu 上所有应用；模拟器验证环境可接受，
  恢复 `settings put global hidden_api_policy 0` 即还原。已记入本文档，勿忘。
- JNI 豁免与多路回退为通用兜底（其它 ROM 可能 Java 反射直接可用）。
