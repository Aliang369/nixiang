## 三、本轮必须修的一处工程问题（否则装机即崩）

`surgical_mwdl_15.0.0.sh` 仍在 `GameApplication.attachBaseContext` 注入 `invoke-static {}, Lcom/starry/magic/sign/SignSpoof;->install()V`。
`sign/SignSpoof` 已于 **2026-10-28 按用户指令整体删除且禁止复活**（依赖隐藏 API 豁免，Android 14 user 版必失败）；smali 汇编不校验类型存在性，只会产出一个**指向不存在类的硬引用** ⇒ 启动 `NoClassDefFoundError`。

处置：删除该 `invoke-static`（保留 `System.loadLibrary("starry_magic")`，菜单走 `JNI_OnLoad` + `MenuService` 拉起），并在脚本内写明禁止复活的原因。改后 `check_deleted_class_injection.sh` 对 `04_scripts` 零命中的前提保持成立，产物 5 个 dex 中 `SignSpoof` 字符串计数全为 0。
登录侧不用运行时伪装：`ActivityHandler.authorize` 抛 `ActivityNotFoundException` 强制 WebView 网页登录（改包法 A 轨，未变）。


## 三之二、登录「请求返回业务失败」→ 补签名轨（2026-10-31 15:0x）

**现象**：用户 TapTap 网页登录确认后，游戏平台登录失败，toast 只有「请求返回业务失败」。

**定位**：该文案＝平台服务器外层消息；`10_docs/迷雾大陆/热更失效根因与修复_20260909.md` §七 已定案同一链条
`errCode 10011 [重定向请求返回业务失败] detail: 10045 指纹签名无效`。客户端把**应用签名指纹**上报（PGL SDK 走
`PackageManager.getPackageInfo(pkg, GET_SIGNATURES)`），服务器比对官方指纹不符即拒。
本轮相对 10-17 唯一的功能性差异是 `SignSpoof` 已按 10-28 指令删除（该类曾改写 `PackageInfo.CREATOR`），
因此指纹校验重新暴露。**这不是 TapTap SSO 失败，也不是 root 检测。**

**处置（2026-10-29 双轨制的签名轨 B：运行时签名替换，不改官方 dex 一个字节）**：

| 步 | 做法 |
|---|---|
| 1 | 官方签名证书 DER 从**本底包 v2 签名块**现取（778 B，md5 `648d86c8901e786f79cfd7e73b727133`，与 `apksigner` 报的 Signer #1 MD5 断言相等）；`assets/com.hortor.mwdl.cert.pem` 是 hortorgames 的另一把证书（CN=com.hortor.mwdl，2025-12-30 到期），**不能**拿来喂 killer |
