## 十、首包「六项全失效」根因与修复（2026-11-14，用户实测驱动）

### 10.1 事实（用户观察为准，不改写）
首包 `85e2cbc9…` 装机后用户进游戏、六项全开 ⇒ 全部无效。预检 PASS 只覆盖「so 加载/菜单弹出/不崩」，**不覆盖开关值通路**，故预检通过不构成反证。

### 10.2 现场证据（pid 28367，logcat 按 TAG 切片，未整读）
```
W/System.err: java.lang.NoClassDefFoundError: Failed resolution of: Lcom/starry/magic/cocos/MwdlHooks;
Caused by: java.lang.ClassNotFoundException: com.starry.magic.cocos.MwdlHooks
```
自 14:35 起持续刷（每秒数十条）。调用链：注入 JS `get_ret/get_val` → `AppActivity` 补丁 `invoke-static Lcom/starry/magic/cocos/MwdlHooks;->getRet(I)Z` → **类不可解析** ⇒ 六项全部拿不到开关值。

### 10.3 根因（首次丢失点＝R8 混淆，不是 16.0.0 换代）
- 源码在：`app/src/main/java/com/starry/magic/cocos/MwdlHooks.java`（15 方法）。
- 产物 classes/2/3/5 无原名定义；classes4 只有 1 处**引用**。baksmali classes5 后找到 `com/starry/magic/o/Z`：方法 `b(I)Z`/`c(I)F`/`e(IZ)V`/`f(IF)V`、字段 `[Z b`(RET)/`[F c`(VAL) ⇒ **类名与方法名一起被混淆**，类本身被 repackage 到 `com.starry.magic.o`。
- 规则来源：`proguard-rules.pro` 的 `-keep,allowobfuscation class com.starry.magic.** { *; }` + `-repackageclasses 'com.starry.magic.o'`，由 commit **4476426c（2026-11-10「注入 dex 混淆」）**引入，**晚于 15.0.0 出包（10-31）** ⇒ 15.0.0 未暴露、16.0.0 必断。
- 交叉核对（login-reviewer 独立解析）：`o/Z` 与 `o/U0`（cocos 反射桥）在 5 个 dex 中均只有自身 class_def、**无外部引用** ⇒ 恢复类名不会打断其它类。

### 10.4 修复（单一方案，仅动游戏私有打包步骤）
`surgical_mwdl_16.0.0.sh` [3a]：用**现有真源** `MwdlHooks.java` 经 `javac`（android-36 android.jar）+ `d8`(--min-api 24) + `baksmali` 编成 `com/starry/magic/cocos/MwdlHooks.smali` 注入 classes5（**原类名 + 原方法名**，不经 R8）。
- 不改共享 `proguard`、不广 keep、**不删除/不改名** R8 产出的 `o/Z`（无引用，残留无害）。
- 状态同一性：classes4 的 `get_ret/set_ret/get_val/set_val` 与 JS 调用都指向同一个 `Lcom/starry/magic/cocos/MwdlHooks;`（classes4 引用 + classes5 定义），不存在两份状态。
- [3a-断言]：smali_in 内该 `.class` 声明恰好 1 处；classes5 汇编后 **baksmali 回读**，断言文件存在且 `getRet(I)Z`/`getVal(I)F`/`setRet(IZ)V`/`setVal(IF)V` 四原型齐（用的是 encoded_methods 定义，不是字符串计数——首包正是「有引用无定义」漏检）。
