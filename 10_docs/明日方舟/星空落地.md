## 2. 分析方法

### 2.1 磁盘原件的弱混淆与三步修复

包内 `global-metadata.dat` 不是强加密：**前 8 字节固定标记 + 每 64 KiB 内 16 KiB 窗口异或 0x66**。磁盘原件首 16 字节 `94437212 184b9eec 76676666 86eb6266`，其中前 8 字节是固定标记（覆盖 `sanity`+`version` 两个字段），其余按周期混淆。

修复三步（确定性，无猜测）：

1. 对满足 `i % 65536 ∈ [4096, 20480)` 的字节 `XOR 0x66`（每周期 16 KiB 窗口）；
2. 首块 `[0, 4096)` 同样 `XOR 0x66`（覆盖 272 字节头部与 stringLiteral 表前段）；
3. 首 8 字节写回 `af1bb1fa` + `18000000`（`sanity=0xFAB11BAF`、`version=24`）。

修复后头部字段全部落在合法区间：`stringOffset=1,716,496`、`stringCount=8,271,112`、`methodsOffset=10,938,344`、`methodsCount=9,851,744`（= 307,867 × 32）、`parametersOffset=27,016,180`、`nestedTypesOffset=34,818,852`、`typeDefinitionsOffset=37,456,824`、`typeDefinitionsCount=4,650,416`（= 50,548 × 92）。

### 2.2 反证：只补 magic 不够

| 处理 | `Il2CppTypeDefinition` 自洽率 | 判定 |
|---|---|---|
| 只补首 4 字节 magic | 237/402 = **59%** | 不可用 |
| 执行 §2.1 三步 | **50548/50548 = 100%** | 唯一解 |

- `td_size` 只有 `0x5c` 成立：`0x5c` 402/402 = 100%，`0x58` 3.2%、`0x60` 3.2%。
- 全表校验：类型 token 全 `0x02xxxxxx`、方法 token 全 `0x06xxxxxx`（异常 0），`method_count` 与 `declaringType` 分组一致 402-402、44081-44081。
- 汇总：`types=50548`、`methods=307867`、`td_size=0x5c`。

## 6. 环境技术事实（houdini 翻译层）

该环境（x86_64 + `libhoudini`）下，所有 arm64 guest so 只映射 `r--p` / `rw-p`、**无 `r-xp`**（指令执行走 houdini 翻译缓存）。在此前提下 **Dobby inline hook 实测生效**——6 项 `hit` 即直接证据。因此「houdini 下 inline hook 不可用」不成立；跨游戏可直接沿用该结论。
