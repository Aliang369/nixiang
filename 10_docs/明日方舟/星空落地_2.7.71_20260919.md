## 2. ACE 启动闪退修复

旧候选包同时替换了：

- `com.u8.sdk.U8Application -> com.starry.magic.StarryApp`
- `androidx.core.app.CoreComponentFactory -> com.starry.magic.sign.SignSpoofAppComponentFactory`

真机连续两轮分别出现：

- PID `19058`：约 12 秒后 `SIGSEGV(11)`
- PID `19854`：约 11 秒后 `SIGBUS(7)`，并有
  `F libc: Pointer tag for 0x80 was truncated`

两轮均先加载 ACE `libtprt.so`，没有对应 tombstone、Java FATAL、DropBox native
crash 或 `crash_dump`。这与终末地已实锤的 ACE `Application` 类名校验属同类问题。

最终方案改为 provider-only：

- 官方 `com.u8.sdk.U8Application` 原样保留
- 官方 `androidx.core.app.CoreComponentFactory` 原样保留
- 只新增 `StarryInitProvider`、`MenuService` 与 FGS 权限
- 星光 native 加载、菜单启动和 `SignSpoof.install()` 由 Provider 执行

结果：

- provider-only 九功能过渡包冷启动存活 `156` 秒。
- 最终七功能包同签名覆盖安装后冷启动 `30` 秒存活。
- 日志确认 `StarryInitProvider: native ensureLoaded=true`、
  `RegisterNatives 19/19 全部成功`、`MOD 已就绪 tag=mrfzz ready=1`。
- 未见 `SIGSEGV`、`SIGBUS`、`F libc`、FATAL、ANR 或新 tombstone。
