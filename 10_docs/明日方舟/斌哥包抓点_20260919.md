## 4. 四个 replacement 语义

以下语义均由本次运行态 RX 内存反汇编确认；开关关闭时统一 tail-call 原函数。

### 4.1 `btn_0` 超级攻速 -> `CalculateAttackInterval`

- replacement：`0x79dca90778`
- 开关：`0x79dcb4a000`
- 原函数 trampoline：`0x79dcb4a048`

语义：

```c
if (*(uint8_t *)0x79dcb4a000 != 0)
    return 0;
return orig_CalculateAttackInterval(...);
```

### 4.2 `btn_1` 超级无敌 -> `Entity.get_isInvincible`

- replacement：`0x79dca90798`
- 开关：`0x79dcb4a004`
- `get_side`：`0x79dcb4a040`
- 原函数 trampoline：`0x79dcb4a050`

语义：

```c
int side = get_side(this);
if (side == 1 && *(uint8_t *)0x79dcb4a004 != 0)
    return true;
return orig_get_isInvincible(this);
```

即无敌只对 `get_side(this) == 1` 的阵营生效。

### 4.3 `btn_2` 基地锁血 -> `Enemy.get_lifePointReduce`

- replacement：`0x79dca907f0`
- 开关：`0x79dcb4a008`
- 原函数 trampoline：`0x79dcb4a058`

语义：

```c
if (*(uint8_t *)0x79dcb4a008 != 0)
    return 0;
return orig_get_lifePointReduce(this);
```

### 4.4 `btn_3` 十倍伤害 -> `Entity.get_atk`

- replacement：`0x79dca90810`
- 开关：`0x79dcb4a00c`
- 原函数 trampoline：`0x79dcb4a060`

语义：

```c
uint64_t original = orig_get_atk(this);
return *(uint8_t *)0x79dcb4a00c ? original * 10 : original;
```

反汇编中的乘法为整数 `x0 + x0 * 4` 后再左移一位，即 `10 * original`。

## 6. 证据分类

### 实测事实

- 斌哥包从真机完整拉取，设备 base APK 与本机文件大小/哈希一致。
- 斌哥壳内存在四组 Dobby hook 安装调用，四个 trampoline 槽均非空。
- 四个 replacement 的反汇编语义、开关地址、原函数 trampoline 均已读取。
- `get_side` 指针已解析，`get_isInvincible` 只在 side 为 `1` 且开关开启时返回真。
- 菜单 `267.html` 的四个按钮文案由本地隔离解码确认，与 native `w3=0..3` 顺序一致。
- 抓取瞬间 `a000/a004/a008/a00c` 全部为 `0`。

### 证据支持的推断

- 该壳使用 Dobby inline hook，而不是修改 APK 内 `libil2cpp.so` 文件。
- “超级攻速”通过让 `CalculateAttackInterval` 返回 `0` 实现；“基地锁血”通过让 `get_lifePointReduce` 返回 `0` 实现。
- “超级无敌”限定玩家侧；“十倍伤害”对 `get_atk` 返回值做整数乘 10。

### NOT PROVEN

- 四个功能开启后的实际战斗效果、关闭后的恢复行为、长时间稳定性。
- 游戏服务端是否接受对应战斗结果，以及是否存在风控/封号风险。
- 官方同版本包与斌哥包内 `libil2cpp.so`、metadata 是否逐字节一致。
- 官方包内同名方法是否可用同样方式解析；这要在拿到原版 APK 后对照确认。
