### 3.1 a. dex 改包法（4 处 Tap 锚点，跨 2 个 dex）

| # | 类 | 方法 | dex | 改法（整段替换方法体） |
|---|---|---|---|---|
| P1 | `com.taptap.sdk.initializer.repository.GatekeeperRepository` | `showErrorToast(TapNetworkException)V` | `classes.dex` | `.registers 5` + `return-void`（掐掉「初始化信息错误」Toast 与 `TapLogger.loge`） |
| P3 | `com.taptap.sdk.kit.internal.utils.TapSignKit` | `getSign(Context)String` | `classes.dex` | `.registers 5` + `const-string v0, "360c78f563dd471fa6df02cc68045a31"` + `return-object v0`（整段删原 try/catch，避免悬空标签） |
| P2 | `com.taptap.sdk.login.impl.ui.fragment.DefaultTapLoginFragmentProvider` | `provide(LoginRequest)Landroid/app/Fragment;` | `classes2.dex` | 在本类**唯一**的 `aget v2, v3, v2` 之后插一行 `const/4 v2, 0x3` |
| P4 | `com.xiefeng.game2d.PrivacyActivity` | `getVerifiedVersionCode(Context)J` | `classes2.dex` | `.registers 3` + `const-wide/16 v0, 0x24` + `return-wide v0` |

- **P2 为什么是 0x3**：`DefaultTapLoginFragmentProvider$WhenMappings` 实测 `CLIENT=1 / CLOUD_GAME=2 / WEB=3`。插 `v2=3` 后三个比较全不跳 ⇒ 直落 `WebLoginFragment`。枚举变了先重读 `WhenMappings.<clinit>`。
- **P4 的两个要点**：① 包内原方法**不含烘焙版本号**，返回的是「已安装包的真实 versionCode」，失败才返回 `-1`；所以常量必须等于当前 versionCode 的十进制 —— vc36 ⇒ **0x24**（`BuildConfig` 类在本包不存在，别去找）。② 原方法带签名 pinning：`OFFICIAL_SIGNER_SHA256 = base64("Cjt4JZH…") = 0a3b7825…048f`，不匹配时 `-1`（自杀）/ `0`（弹「无法启动游戏」后退出）；`PrivacyActivity` 在 `:privacy` 独立进程，killer 覆盖不到这道门 ⇒ **P4 必须打**。
- **P1 是「只掐提示」**：`isGatekeeperLoadedSuccessfully` 全 dex **0 个外部调用点**，属死补丁，不打。

**步骤**

1. 反汇编（baksmali 2.5.2，两个 dex 约 20 s）：
   ```bash
   bash 01_tools/smali/baksmali d <解包目录>/classes.dex  -o <工作区>/dis1 --jobs 6
   bash 01_tools/smali/baksmali d <解包目录>/classes2.dex -o <工作区>/dis2 --jobs 6
   ```
2. 只改副本（`dis1 → work1`、`dis2 → work2`）：按方法签名定位到 `.end method` 整段替换（P2 额外断言「最近一条 `.method` 是 `provide(`」）。
3. 汇编：`bash 01_tools/smali/smali assemble -a 24 <work1> -o out_classes.dex`（classes2 同理）。
   **必须 `-a 24`**：默认 `-a 15` 出 DEX 035，底包是 037。

**验证五步（一条不过就不算完成）**

| 步 | 命令 | 判据（3.6 实测） | 失败怎么办 |
|---|---|---|---|
| 1 checksum | `dexdump -c out_classes.dex` | `Checksum verified` | 重汇编；文件被截断 |
| 2 头字段 | `dexdump -f out_classes.dex` | `DEX version ' 037'`；`classes.dex` method_ids **64,080**（**必须 ≤65536**）、class_defs **8,089**；`classes2.dex` method_ids **36,845**、class_defs **4,455** | 掉到 035 ⇒ 忘了 `-a 24`；超 65536 ⇒ 换引用更少的写法 |
| 3 类集合 | 两侧 `baksmali list classes` 排序后 `diff` | 两个 dex 类集合 **差异 0 行** | 类丢了 ⇒ 汇编 `-o` 指错了目录 |
| 4 整 dex 重反汇编 diff | 新产物再 `baksmali d` → `diff -rq dis work_out \| wc -l` | **37**（= 4 个目标类 + 33 个汇编器归一化类） | 远大于 37 ⇒ 改动跑出了目标方法 |
| 5 归一化等价 | 去掉字段默认值、`:try_start_*`/`:try_end_*`/`.catch*` 行后逐行比 | 非目标类归一化后**差异 0** | 有残留差异 ⇒ 那不是归一化，真改了别的类 |

- **为什么第 4 步不是「只有 4 个文件不同」**：smali 会合并相邻同 handler 的 try 区间、省略静态字段默认值，这会碰一批无关类。可执行判据 = 「4 目标 + 33 归一化，归一化后 0 差异」。第 5 步是机器证明，别肉眼下结论。
- 3.6 产物：`classes.dex` **9,091,848 B** / sha256 `f2474b73acbfdd814348cdd02437abbe316bb95664215059673827acdde91270`；`classes2.dex` **6,375,044 B** / sha256 `bceaabfc76ae475d909ae20f9bb1b0e373c7f22002bd3486fd0b5bd1b8504e21`。两者都是 DEX **037**。

### 3.2 b. native 四挂点重定位

**方法：RVA 经段表换算 file offset，不是一律减 0x4000。**

1. 段表（3.6 实测，4 个 PT_LOAD，文本段 `delta = va - file` 依次 **0x0 / 0x4000 / 0x8000 / 0xC000**；四个挂点全落在 +0x4000 段，RVA = file offset + 0x4000）。
2. 生成 dump（Il2CppDumper；日志里 `WARNING: find JNI_OnLoad` / `ERROR: This file may be protected.` 属正常噪音）：
   ```bash
   01_tools/dotnet/sdk-9/dotnet 01_tools/il2cppdumper/Il2CppDumper.dll \
     <解包目录>/lib/arm64-v8a/libil2cpp.so \
     <解包目录>/assets/bin/Data/Managed/Metadata/global-metadata.dat \
     <工作区>/dump
   ```
   3.6 产物：dump.cs **25,820,143 B** / sha256 `5fdc56e7…`；**12,080** 类型 / **98,662** 条带 RVA 方法 / **94** image；`CodeRegistration 0x3AAEE38` / `MetadataRegistration 0x3BCF928`（两者是 VA 口径，换算 file offset 同样走段表）。
3. 四挂点表（3.6 实测）：

   | 用途 | 目标 | **file offset** | RVA | 序言（小端字） |
   |---|---|---|---|---|
   | 免广告 | `Dirichlet.Ad.DirichletRewardAdBase::ShowInternal` | **0x1D050FC** | 0x1D090FC | `0xF81E0FFE` |
   | 免广告原生事件 | 同类 `HandleNativeEvent`（**只记录不挂**） | **0x1D04E74** | 0x1D08E74 | `0xD10183FF` |
   | 游戏加速 | `UnityEngine.Time::set_timeScale` | **0x37CC0F8** | 0x37D00F8 | `0xFC1E0FE8` |
   | 无敌/百倍 | `InterpFrameGroup::EnterFrameFromInterpreter`（HybridCLR 帧入口，无托管符号） | **0x19FE82C** | 0x1A0282C | `0xF81D0FFE` |

4. **帧入口没有符号，靠拓扑证据认人**（缺一条就别挂）：
   - `bl 帧入口` 共 **16 处**（`bl` 操作数是 VA）：首 **0x1A0FC30** / 末 **0x1A10C38**，跨度 **0x1008**；入口 file 0x19FE82C → 首调用 file 0x1A0BC30 = **+0xD404**（对不上 0x4000 差值就是忘了 bl 操作数是 VA）；
   - 同区两个伴随函数：分配器 **0x1A028A0**（VA）、`PushFrame` **0x1A0290C**（VA）；
   - 前一条指令是上一函数的 `ret`（干净函数头），33 条指令同构（`str x30,[sp,#-0x30]!` → `sub w1,w9,w8` → `bl AllocStackSlot` → `bl PushFrame` → 写 frame → `ret`）。
5. 版本探针三元组（写进 `DetectLibVersion()`，三取二才命中）：`{show 0x1D050FC == 0xF81E0FFE}`、`{interp 0x19FE82C == 0xF81D0FFE}`、`{size == 66,383,744}`；接受条件 `① && (② || ③)` 或 `② && ③`。**文件大小是主判据**（不受段内偶然序言影响）。
6. 要改的分支（`Games/旷野征途Mod.cpp`）：
   - `kSlots` 免广告槽：`kOff36Show = 0x1D050FCu`、`expectInsn = 0xF81E0FFEu`、按名三要素 `Dirichlet.Ad / DirichletRewardAdBase / ShowInternal`；
   - `InitSlotAddrs()` 的 `ver == 36`：interp 0x19FE82C / noad 0x1D050FC / handleNative 0x1D04E74（只记录）；
   - `DetectLibVersion()` 探针表**首项** `{36, kOff36Show}`（判定按版本号从高到低顺序匹配，36 必须在最前），日志 `" verprobe 3.6 cond show=%d interp=%d size=%d/%llu"`；
   - **战斗装钩门**：`verHook == 36`；**经济版本门**：`g_libVer == 36`；地址一律取单一 `kRvaEnterInterp` / `kOff36*` 常量，不写重复字面量（防同址双叠钩）。
7. 门禁：`python 04_scripts/旷野征途/check_battle_contract.py` ⇒ **24 项全 PASS**、结论「一致」、exit 0（该门同时锁 `kSize36Lib = 66383744ull`、`{36, kOff36Show}` 在探针表最前、`if (ver != 36)` 版本门、`integrity hooks: ok=%d dead=%d ver=%d` 日志串）。

- **失败**：探针全不中 ⇒ `ver=0`，四个 RVA 归零，免广告退按名、战斗/加速显式关闭（不会野指针）。排查顺序：段表对不对 → 读的是 file offset 还是 VA → so 是否被改过（改了就先重算文件大小）。

### 3.3 c. 热更层 HotUpdate.dll（加密封装 + 两份合同）

**这一步纯离线读 APK，不需要设备。**

1. **按容器路径找 bundle，别按文件名**：3.6 的承载 bundle 是 `assets/yoo/DefaultPackage/8586a488fb86085c65cd45a58fe1df92.bundle`（**3,796,197 B** / sha256 `663e3f2c…`），里面只有一个 TextAsset，容器路径 `Assets/Bundles/CodeHot/HotUpdate.dll.bytes`。用 UnityPy 遍历 119 个 bundle 的容器表按路径反查（文件名随构建变）。
2. 取出封装字节：**3,794,337 B**。
3. **包格式自证**（长度公式对上就说明布局没错）：
   ```text
   [1B version=2][16B IV][N*16 密文][384B RSA]
   17 + 16*237121 + 384 == 3,794,337
   ```
4. **找 AES 密钥：按 (offset,length) 逐条读 metadata 字面量表，禁止正则扫 blob**（字面量首尾相连，贪婪正则会吞相邻条目）。候选 = 原始字节长度或 base64 解码后长度 ∈ {16,24,32}；判据 = **AES-256-CBC + PKCS7 解出的明文以 `MZ` 开头**，才唯一。
   - 3.6 命中：字面量 `MUTuHPa4moJngx5gmKtcxz+6hqvmmKoSt4qpjwsDAL8=`（**32 B**）。**按值取、不写序号** —— 字面量表会随版本扩容位移，密钥值本身不变。
5. 解密：AES-256-CBC，IV = `pkg[1:17]`，PKCS7 去填充。判据：
   - 明文 **3,793,920 B** / sha256 `5514bd76…`（16 B 填充差）；
   - PE 自检：`MZ`、machine `0x14C`（PE32 IL-only）、Assembly `HotUpdate 0.0.0.0`、MVID `a2b18370-f278-4760-999c-aa05f50021f6`、TypeDef **2,609** / MethodDef **14,948** / Field **18,929**。
   - **失败**：解得乱码 ⇒ 密钥取错（长度合法 ≠ 正确）或 IV 位置错；PKCS7 过但无 `MZ` ⇒ 那个候选不是钥匙。
6. **战斗合同（全是锚点，3.6 实测）**：

   | 项 | 3.6 值 |
   |---|---|
   | `Battle.BattleRoleActor.ApplyHp` 参数 | **4**（不含 this ⇒ argBase **5 槽**：+0 this 受击者 / +8 atker / +16 atkSeatNum / +24 dmgInfo / +32 OnDie） |
   | RVA / body | **0x10D5C0** / **1,681 B** |
   | IL 锚点 | `get_isGod@0x239`；早退 `ret@0x215 / 0x229 / 0x24D`；首个 `set_curHp@0x266`；`OnDie.Invoke@0x589` |
   | 伤害符号 | `curHp = get_curHp() + intDmg`（**加法**）⇒ 掉血必须 `intDmg<0`；`ApplyHp` 内**没有 `neg`**，负值来自调用方 |
   | 稳定访问器（比 IL 偏移抗版本） | `get_curHp` 0x110846 / body 7；`set_curHp` 0x11084E / body 8；`get_isGod` 0x10FBDD / body 24；`get_maxHp` 0x1106E0 / body 15 |
   | 多人 | `BattleRoleMgr.Instance` 是 public static 字段（**无** `get_Instance`）；`get_LocalSeatNum` 按名取 |

7. **经济合同（全部按名取，别背偏移）**：

   | 项 | 3.6 值 |
   |---|---|
   | `MemoryValueEncoding.RotateKey` | `Int32` RVA **0x44864** / body **26**（`x^=x<<13; x^=x>>>17; x^=x<<5`）；`Int64` RVA **0x4487F** / body **37**（13 / >>>7 / <<17） |
   | 金币 | `AccountInfo.encodedGold` / `goldKey`；`sharedGold` 是 **`Nullable<long>` 属性**（get 0x4B38C / set 0x4B3BD），**没有同名字段** |
   | 钻石 | `ItemSaveData.encodedCount` / `countKey` / `baseItemid`（`baseItemid == 2` 即钻石） |
   | 积分 | `AccountInfo.encodedPoints` / `pointsKey`（字段 XOR 编码） |
   | 改金币 | `PlayerInfo.ChangeGold` RVA **0x5A610** / body **120**（写账号共享金币 + `SaveLedger`）；前置判定 `CanChangeGold` **0x5A574** |
   | 写法规约 | `key = RotateKey(key); enc = value ^ key;` 写回；只改已有条目，不造新物品；`ChangeGold` 首参是 **int64**，按 int32 传会把数值写成乱数 |

- **失败**：IL 偏移每个版本整体位移，**偏移不能跨版本复用**；改用访问器锚点（`get_curHp`/`set_curHp`/`get_isGod` 的 body 字节数很稳）。若 hook 打的是 libil2cpp 里的 AOT 版 `ApplyHp`，那是 §3.2 的活，RVA 要重新定位。

### 3.4 d. 反篡改（3.6 机制：内容索引 + 签名双校验 ⇒ 必须 native detour）

3.6 的反篡改面 = **签名校验 + 包内容索引**双校验：索引把 `classes*.dex` 与 `global-metadata.dat` 全纳入哈希面，签名走 `signingInfo` 路径（killer 覆盖不到）⇒ 签名伪装单独过不去，必须在 native 侧把两个校验函数改成恒真。

**包里有什么（静态事实）**

| 项 | 值 |
|---|---|
| `ET.AndroidPackageIntegrity` | TypeDefIndex **10254**，**7 个方法**：`VerifyInstalledPackageAsync` 0x2B80130、`ExitModifiedPackage` 0x2B81218、`ReadInstalledIdentity` 0x2B802B8、`VerifyCurrentSigner` 0x2B81518、`VerifyPackageContents` 0x2B81D40、`ReadSignedHashes` 0x2B827BC、`GetUniqueEntry` 0x2B82D30 |
| `ET.AndroidPackageFileIndex` | TypeDefIndex **10251**：`Verify` 0x2B7F048、`IsCovered` 0x2B7FF84 |
| 索引文件 | `assets/NativeIntegrity/package.files` **16,966 B**：**129** 条 `path\tsha256` + **384 B** RSA |
| `IsCovered` 覆盖范围 | `global-metadata.dat`、或 `\Aclasses[0-9]*\.dex\z`、或 `assets/yoo/DefaultPackage/` 前缀 |
| `assets/NativeIntegrity/arm64-v8a.bin` | **480 B**，前 **96 B** = `libmain` / `libunity` / `libil2cpp` 的 sha256（WHITELIST 三个 so，必须字节不变） |
| `assets/NativeIntegrity/arm64-v8a.audit` | **512 B** = 96 B 哈希 + 32 B manifest 摘要 + 384 B 签名 |
| `ExitModifiedPackage` | **只 killProcess，不删档** |

- **killer 的边界**：killer 只覆盖 `PackageInfo.signatures`，**不覆盖 `signingInfo.getApkContentsSigners()`（API≥28 路径）** ⇒ 3.6 靠签名伪装单独过不去，必须靠 native detour。
- 这也解释了为什么只能改两个函数：`IsCovered` 把 `classes*.dex` 和 `global-metadata.dat` 全纳入哈希面，改 dex 必然使 `VerifyPackageContents` 失败；而签名面因 `signingInfo` 路径不受 killer 影响，`VerifyCurrentSigner` 也必然失败。

**绕过方案（已实测）**：两个恒返回 `true` 的 Dobby detour。

| 目标 | file offset | 序言 | 语义 |
|---|---|---|---|
| `VerifyPackageContents` | **0x2B7DD40** | `0xD10203FF` | 内容哈希校验 ⇒ 恒 true |
| `VerifyCurrentSigner` | **0x2B7D518** | `0xD10183FF` | 当前签名校验 ⇒ 恒 true |

- 装在 `InstallIntegrityHooks()`，由 `TryInit` 在 `g_libReady` 之后、`SyncHooks()` **之前**调用 —— 这样**绕开 `AnyFeatureOn` 门控**（功能全关也装），并走**独立槽表 `kIntegritySlots`**（不与功能槽混算 `ok/dead`）。3.6 分支在调用**前**先 `sleep(2)`（日志 `integrity: defer 2000ms (houdini-safe)`，原因见 §7.6；35 分支不延迟）。
- **三重幂等**：`g_integrityDone` 标志 / `origPtr` 已存在即跳过 / `g_installMutex` 互斥（`TryInit` 并发两次不会双叠钩）。
- **判据**：`integrity: defer 2000ms (houdini-safe)` → `integrity hooks: ok=2 dead=0 ver=36` → `integrity: post-delay ok=2 dead=0`（各 1 行）+ `MODHIT tag=IntegrityContents`、`MODHIT tag=IntegritySigner` 各 `n=1`（证明两个校验真的被调用且放行）；反证 = `killProcess` 出现 / 启动页弹「无法启动游戏」后 `finish()`。
- **失败**：`ok<2` ⇒ 序言对不上（offset 或版本门错了，先跑 §3.2 的探针确认 `ver=36`）；`ok=2` 但 `dead>0` ⇒ 有槽位没装上，看 `MODHOOK` 行的 `installed/origExec`。

## 7. 已知坑（每条都给判据 + 修法）

1. **houdini（雷电模拟器）把 arm64 库全映射成 `r--p` / `rw-p`，整库没有任何 `x` 段。** `FileOffToVa` 若写成「无 `x` 段即 `continue`」，就会把所有挂点判成无效 ⇒ `ver=0`、反篡改钩子被跳过（表现为启动被拦或功能全失效）。**判据**：`verprobe 3.6 cond show=1 interp=1 size=1/66383744`，三项不全是 1 就是踩了这个坑。**修法**：`FileOffToVa` 必须「可执行段优先、无 `x` 段时退回首个覆盖该 offset 的只读段」（`/proc/self/maps` 天然按 start 升序，首个命中即 start 最低者；span 只在 `x` 段里比）。
2. **功能钩子懒装：全关态 `SyncHooks()` 直接 `return`。** 新装设备首次启动（功能默认全关）**不会**打 `slot addrs` / `install pass`，看起来像没装。**判据**：有 `lib ready (dual-path, lazy hooks)` 而没有 `install pass` = 全关态正常；**打开任一开关后仍无这两行才是真故障**。注意 `integrity hooks` 行不受此门控（它装在 `SyncHooks()` 之前），全关态也必须有。
3. **菜单入口依赖 Activity attach + 悬浮窗权限。** 熄屏 / 锁屏 / 无悬浮窗授权时 `nativeInit` 不触发，菜单不弹、`slot addrs` 也不打。**判据**：`post_install_precheck.sh` 的「菜单弹出 `native menu shown mode=ACTIVITY`」失败且日志无 `Activity attach`。**修法**：这是行为约束不是 bug —— 先点亮屏幕、确认 `SYSTEM_ALERT_WINDOW` 已授权，再请用户从游戏内进入。
4. **killer 不覆盖 `signingInfo.getApkContentsSigners()`（API≥28 路径）。** 只打 killer 不打 native detour ⇒ 3.6 启动仍被拦。**判据**：`integrity hooks: ok=0` 或没有该行，同时启动页出现「无法启动游戏 / 请从官方渠道获取完整安装包后再试」并 `finish()`，或日志出现 `killProcess`。**修法**：按 §3.4 装两个恒真 detour；别试图在 Java 侧补签名伪装。
5. **`MODHOOK` 的 `origExec=0` 是启发式告警，不是失败。** houdini 下 Dobby 返回的 trampoline 不在可执行映射段，`origExec` 天然为 0。**判据**：以 `MODHIT tag=… n=1` 为准 —— 有 `installed=1` 且后续有 `MODHIT` 就是真生效；只有 `installed=1` 长期无 `MODHIT` 才是假阳性（挂到同构序言的假地址）。
6. **houdini 下 `libil2cpp` 刚映射完就装钩，patch 会被翻译覆盖。** early-init 线程在 `lib appeared +18ms` 就调 `TryInit` 时装的两个 detour，装是装上了（`ok=2 dead=0`）但 `MODHIT=0`，6.0s 后 `nativeRender` 栈自杀（`killProcess`）。**判据**：`integrity hooks: ok=2 dead=0 ver=36` 与 `integrity: defer 2000ms (houdini-safe)` 之间**没有** ~2s 间隔，或 `MODHIT tag=Integrity*` 一条都没有而 `killProcess` 出现。**修法**：3.6 分支装钩前 `sleep(2)`（`旷野征途Mod.cpp` 的 `verGate == 36` 分支，日志 `integrity: defer 2000ms (houdini-safe)`）；2s 不够就改 3s 再复测一轮（一轮只改这一个变量）。装钩时刻应**晚于 `early-init: lib appeared` 约 2s、早于 `Unity splash observed finished`**。
