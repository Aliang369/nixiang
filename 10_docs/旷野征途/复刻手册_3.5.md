### 2.1 dex 改包法：四锚点，跨两个 dex

| 锚点 | 所在 dex | 方法 | 改法 | 判据 |
|---|---|---|---|---|
| P1 | `classes.dex` | `GatekeeperRepository.showErrorToast(TapNetworkException)V` | 体压成 `.registers 5` + `return-void` | `dexdump -d` 该法 `insns 1` |
| P2 | `classes2.dex` | `DefaultTapLoginFragmentProvider.provide(LoginRequest)Fragment` | 本类**唯一** `aget v2,v3,v2` 后插 `const/4 v2, 0x3` | 反汇编见 `aget` 紧跟 `const/4 v2, #int 3` |
| P3 | `classes.dex` | `TapSignKit.getSign(Context)String` | `.registers 3` + `const-string v0, "360c78f563dd471fa6df02cc68045a31"` + `return-object` | 常量 = 官方证书 DER md5（§1.1） |
| P4 | `classes2.dex` | `PrivacyActivity.getVerifiedVersionCode(Context)J` | `.registers 3` + `const-wide/16 v0, 0x23` + `return-wide v0` | 常量 = versionCode 十进制 35 = `0x23` |

各锚点为什么这么打：

- **P1 是活补丁**：外部调用点 **1 处**（`GatekeeperRepository$initialize$1.smali:315`，上游条件是 `ApiErr.INVALID_CLIENT` 相等）⇒ 必须打；打完该法只剩 `return-void`，`.registers` 仍 5、`ins=2` 不变。
- **P2 打的是枚举 switch**：`WhenMappings.<clinit>` 里 CLIENT=1 / CLOUD_GAME=2 / WEB=3，把 `aget` 出来的值改成 3 ⇒ 三条 `if` 全不跳 ⇒ 直落 `WebLoginFragment`（进程内 WebView）。标签重编号（`cond_6f→cond_70` 等）是汇编器必然结果，不是手改。
- **P3 返回官方签名 MD5 字面量**，抹掉原体的 `getPackageInfo(GET_SIGNATURES)` + `ArraysKt.firstOrNull` + `try/catch` 整段；原 `:try_start_6 … :catch_41` 只在本方法体引用，整段删除后无悬空标签。
- **P4 的消费点**在 `PrivacyActivity.smali:1472`：`cmp-long v1, v1, v3(0x0)` + `if-gez :cond_37` ⇒ **<0 才** `killProcess`。35 > 0 即过闸。**升版本必须把 0x23 改成新 versionCode 的十进制**——这个硬编码就是版本号本身，允许写死。

产物指纹（可直接作 `KYZT_CLASSES_SHA256_EXPECT` / `KYZT_CLASSES2_SHA256_EXPECT`）：

| 产物 | 字节 | sha256 |
|---|---|---|
| `out_classes.dex` | 9,091,848 | `4fcdf53f9681aeb019b7c85caa99c3ff4f806976a4bf2c487c89c276a5404b77` |
| `out_classes2.dex` | 6,373,140 | `64599e6f13de0267ce2749cca6a2fa139397c4021a5567d96c48b0d264566adf` |

五步验证（每步都可独立复跑）：

| 步 | 命令 | 通过判据 |
|---|---|---|
| a | `dexdump -c out_classes.dex` / `dexdump -c out_classes2.dex` | 两者均 `Checksum verified` |
| b | `dexdump -f` | `DEX version '037'`；`method_ids` **64080 / 36831**（≤65536）；`class_defs` **8089 / 4455** |
| c | `baksmali list classes` 改前/改后两侧排序后 `diff` | 8089 vs 8089、4455 vs 4455，均 **0 行** |
| d | 新 dex 再 baksmali → `diff -rq dis1 dis_out1 \| wc -l` | 合计 **37**（dex1 30 = 2 目标 + 28 归一化；dex2 7 = 2 目标 + 5 归一化） |

归一化只抹两类无损重写，不抹任何指令行：① 静态字段默认值后缀（`.field … = false/0x0/0x0L/null`，smali 汇编器不落 init）；② `:try_start_*` / `:try_end_*` / `.catch` 行（标签按地址命名，往返重编号）。

两个 dex 都必须换。ART 遇 dex 序号缺口即停扫 ⇒ 包内必须 1..4 连续；`classes.dex` 里 **0 个** `com/xf/*` / `com/xiefeng/*` 类（21 + 14 全在 `classes2.dex`），TapSDK 也是跨两个 dex 切的（core/initializer/kit 在 dex1，login/… 在 dex2）——只换一个会漏两个锚点。

### 2.2 native 四挂点

**先查段表，再谈偏移。** 判据：`e_phnum = 10`、`PT_LOAD` 共 4 段。

| 段 | file off | VA | va−file | filesz | flags |
|---|---|---|---|---|---|
| LOAD#1 | 0x0 | 0x0 | **+0x0** | 0x179AF6C | R |
| LOAD#2 | 0x179AF6C | 0x179EF6C | **+0x4000** | 0x230A794 | RE |
| LOAD#3 | 0x3AA5700 | 0x3AAD700 | **+0x8000** | 0x26E0E0 | RW |
| LOAD#4 | 0x3D137E0 | 0x3D1F7E0 | **+0xC000** | 0x2395B8 | RW |

可执行区 = VA 0x179EF6C–0x3AA9700（LOAD#2 整段），四个挂点全在 LOAD#2 ⇒ **一律 −0x4000**。四个 delta 是结构常量，但**段边界每版都移**，所以每次都要按本表重算，禁止沿用上一版的 file offset。

| 用途 | 托管符号（dump.cs） | RVA | file offset | 首字（小端） |
|---|---|---|---|---|
| 免广告 | `Dirichlet.Ad.DirichletRewardAdBase::ShowInternal`（TypeDefIndex 11174） | 0x1D08B30 | **0x1D04B30** | **0xF81E0FFE** |
| 免广告原生事件（只记录） | 同类 `HandleNativeEvent` | 0x1D088A8 | 0x1D048A8 | 0xD10183FF |
| 游戏加速 | `UnityEngine.Time::set_timeScale` | 0x37CE8F0 | **0x37CA8F0** | **0xFC1E0FE8** |
| 无敌/百倍 | `InterpFrameGroup::EnterFrameFromInterpreter`（无托管符号，靠拓扑认） | 0x1A02258 | **0x19FE258** | **0xF81D0FFE** |

认人自洽：`ShowInternal − HandleNativeEvent = 0x288`。取类必须取 `DirichletRewardAdBase`(11174)，`DirichletAd`(11173) 的 `ShowInternal` 是 RVA = −1 的抽象方法，取错直接拿到 −1。

**接受条件**：`① show && (② interp || ③ size)` 或 `② && ③`，其中 ③ = 文件字节数 **66,377,504**。文件大小是唯一的版本票：三个首字跨版本同值，只能证明「该地址上是指定函数」，不能证明「这是 3.5」；字节数一变就整体降级为「未知」（归零 RVA、免广告退按名），这是最保守的一票。

**帧入口拓扑（四条证据，缺一条就不要认这个地址）**

① 字符串 `AllocStackSlot` 在 **file 0xA3079F**，全库出现 1 次；adrp/add 扫描唯一 xref = `0x1A02324` + `0x1A02328`，落在函数头 **0x1A022CC**（前一条 0x1A022C8 是上一函数的 `ret`）。函数体即分配器语义（`ldp w8,w10,[x0,#0xc]` → `add w9,w8,w1` → `cmp` → 缺则 `bl 0x1A13B60` 扩容 → `str w9,[x19,#0xc]`）。

② `bl 0x1A022CC`（分配器）**2 处**：0x1A02290（帧入口内，前有 `sub w1,w9,w8`）、0x1A023C4（另一变体，`ldr w1,[x24,#0x2c]` 直传）。`bl 0x1A02338`（PushFrame 本体）**2 处**：0x1A02298 / 0x1A023D4。

③ 入口 **0x1A02258**（前一条 0x1A02254 = `ret`），共 **29 条指令**；关键链：

```
+0x00 str x30,[sp,#-0x30]!      +0x20 ldr x8,[x20,#0x58]
+0x04 stp x22,x21,[sp,#0x10]    +0x28 ldr w9,[x8,#0x2c]      ; maxStackSize
+0x08 stp x20,x19,[sp,#0x20]    +0x2c ldr w8,[x8,#0x20]      ; argStackSize
+0x0c mov x21,x0                +0x34 sub w1,w9,w8
+0x1c bl  0x1B19868             +0x38 bl  0x1A022CC          ; AllocStackSlot
                                +0x40 bl  0x1A02338          ; PushFrame
                                +0x50 stp x20,x19,[x0]
                                +0x54 str w22,[x0,#0x10]
                                +0x60 stur q0,[x0,#0x18]
                                +0x64 stur q0,[x0,#0x28]
                                +0x68 str w8,[x0,#0x38]      ; localPoolBottomIdx
                                +0x6c ldr x30,[sp],#0x30

```

**判据写成「入口 +0x38 处必须是 `bl <分配器>`」，不要数指令条数**——条数随编译器/版本变（本轮 29），链上关键点与 +0x38 距离才是稳定指纹。

④ `bl 0x1A02258`（入口）**16 处**：首 **0x1A0F65C**、末 **0x1A10664**，跨度 **0x1008**，入口→首调用 **+0xD404**。

内存布局自证：PushFrame `add x0, x9, x8, lsl #6` ⇒ **InterpFrame = 0x40**；AllocStackSlot `add x0, x10, w8, sxtw #3` ⇒ **StackObject = 8 B**。

| `assets/NativeIntegrity/<abi>.bin` | **480 B** = 96 B 哈希 + 384 B RSA | 3 个 so 的 sha256（顺序 libmain / libunity / libil2cpp） |
| `assets/NativeIntegrity/<abi>.audit` | **512 B** = **128 B 哈希**（3 so + **AndroidManifest.xml**）+ 384 B RSA | 4 个条目解压后的字节 |

`ReadSignedHashes` 的硬判据：条目长度必须 = `hashesLength(0x60) + 0x180`；被签名的载荷 = `"\\n" + "com.xf.kyzt" + "\\n" + versionCode + "\\n" + abi + "\\n"` 之后再拼上 hashes，由 `ET.HotUpdateCodePackage::VerifyReleaseSignature`（RSA-2048）保护。

**关键点：`AndroidManifest.xml` 的 sha256 进了 `.audit` 哈希清单（第 4 段 [96:128]）。** 我们的 manifest 注入恰好改了它 ⇒ 任何改 manifest 的包都会让 `.audit` 校验失败，native 侧放过是唯一出路（Java 侧回灌签名救不了这一条）。

**失败链**（每条都是 bl 实测）：

```
GameManagerMono.<Start>d__41::MoveNext (0x2BB8644)
  +0x5B4  bl VerifyInstalledPackageAsync            → 0x2BB8BF8
  +0x664  get_IsFaulted 真 → ShowPackageIntegrityError(0x2BB8C8C) → ShowBlockingError（只弹 UI，不杀）

  +0x740  tbz w0,#0 → 0x2BB8E0C → ExitModifiedPackage()  → killProcess(myPid())
```

表现：**无 FATAL / 无 tombstone / SIG:9**，logcat 只有 `Process … Quit itself` + 栈 `com.unity3d.player.UnityPlayer.nativeRender` ⇒ 进程自杀，不是崩溃。

**修法：三处放行钩，缺一不可。**

| 钩 | 返回 | 为什么必须 |
|---|---|---|
| `ReadInstalledIdentity` | true，并补齐 out `apkPath` / `vc=35` | 它自己 false 就 `Task.FromResult(false)`，后面两个判定点根本跑不到 |
| `VerifyCurrentSigner` | true | 仍为 false ⇒ MoveNext 走 kill 分支 |
| `VerifyPackageContents` | true | 仍为 false ⇒ 同上（改 manifest 必 false） |

三个都是 static、参数全为值/引用入参、无托管副作用 ⇒ 直接返回即可，不需要调 orig。配套**仍保留 killer dex（classes4.dex）**：`VerifyCurrentSigner` 读的是 PackageManager 的真实返回值，钩子只是兜底；killer 让读到的 DER 就是官方 DER。

**不要**只把 `ExitModifiedPackage` 改成 no-op 收工：MoveNext 在其后直接结束协程，`GameManagerMono::Init` 不会执行，游戏停在加载页。

#### 2.4.1 时序：必须早于 Unity `<Start>`

校验由游戏自己的启动协程发起，时机早于框架线程：`mod_thread` 的 `initDelay` 路径比校验晚 **340 ms**（实测）⇒ 走框架时机必然全落空（现象：钩子 installed=1、MODHIT=0、照样自杀）。

实现（`Games/旷野征途Entry.cpp` 的 `onLoad` → `Games/旷野征途Mod.cpp` §⑦-c）：起 detached 线程，**每 5 ms** 轮询 `isLibraryLoaded`，为真立刻 `TryInit`（装 §⑥-b 放行钩 + §⑥-c 探针），最多 2000 次（10 s）。实测时序（同一次冷启的 logcat 时间戳）：02:16:27.648 `lib appeared after 31 ms` → 02:16:27.669 两个放行钩装好 → 02:16:30.450 `MODHIT tag=AntiTamper which=signer` 首次命中，即校验在装钩后约 2.8 s 才发起。

并发保护：`TryInit` 内 `g_initStarted` CAS，框架线程进来只会看到「已在初始化」直接返回 ⇒ 不会同址双 `DobbyHook`（那会 SIGSEGV）。

放行钩**无条件安装**（只判 `ver==35`），不受「功能全关就不装钩」的懒装门控制，也不占 kSlots 名额；否则玩家一个功能都不开时冷启必被自杀。

#### 2.4.2 日志判据（冷启即够）

```
MODHOOK tag=AntiTamper … installed=1                 # 两行，rva 0x2B7BE58 / 0x2B7C680
MODHIT  tag=AntiTamper which=signer   n=1
MODHIT  tag=AntiTamper which=contents n=1
exit-probe ReadInstalledIdentity ret=1 apk="…/base.apk" vc=35 force=0
```

反例：`ExitModifiedPackage` 命中 ≥ 1，或 `ShowPackageIntegrityError` / `ShowBlockingError` 命中 ⇒ 放行没生效；两条 AntiTamper 只中 signer ⇒ 卡在 contents；一条都不中 ⇒ 装钩地址漂移或还有第三个判定点。

### 2.5 每次都要核的「稳定判据」：codesize > RVA

合同不是一次定死：`ApplyHp` body **1610 B**、`RotateKey` **26 / 37 B**、各访问器 codesize（7 / 8 / 24 / 15 …）**比 RVA 稳**——RVA 每版必移，codesize 不变。升级时先按名取方法、比 codesize，再取 RVA；RVA 对不上是正常现象，codesize 对不上才是危险信号。

## 5. 装机与验收

### 5.1 装机（统一入口，禁裸敲 adb install）

```bash

  --apk 08_output/旷野征途/旷野征途_3.5_starry-releaseSigned.apk \
```

**必须带 `--clean`**：备胎/卸载/归位整段包在 `CLEAN==1` 分支内，不加 `--clean` 时异签名只在覆盖安装报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE` 后 rc=1，**不会**走备胎链。

异签名路径（官方 `O=xiefeng` vs 星光 `CN=StarryMagic`）：预判 `UPDATE_INCOMPATIBLE` → 同卷 rename 落备胎 → **核对备胎非空才允许卸载** → 卸载 → 装 → 数据归位 + `chown` + `restorecon`（重装后 uid 会变，实测 11199→11200）。root 设备可另做内部数据兜底；无 root 时备胎是唯一保险，脚本默认拒绝「备胎失败仍继续卸载」。

### 5.2 预检


首启会停在官方隐私页：`PrivacyActivity` 跑在 **`:privacy`** 独立进程（`dumpsys` 里该进程活着），**必须用户点「同意」**才进 Unity。这是正常流程，不是授权墙，别按授权失败处理。

```
MODHIT tag=GameUpdate / tag=NoAd / tag=TimeScale        # 资源三项 + 免广告 + 加速
```

- `slot addrs` 三个 file offset 与 §2.2 表一致且 `ver=35` ⇒ 版本识别正确（最省事的错版信号）。
- 战斗两项（无敌 / 百倍伤害）的 `MODHIT tag=Battle` 只在进战斗时打，本轮以用户 L3 为终审。
- `code=1001` 报错计数必须 **0**（有就是服务端/登录链路异常，与 hook 无关，别混诊）。

## 6. 坑（每条都给判据）

1. **锚点跨 dex**：只换 `classes.dex` 会漏 P2/P4。判据 = 断言输出里两个 dex 都在，且 `classes2.dex` 含 `PrivacyActivity`。
2. **dex 序号不能有缺口**：ART 遇缺口停扫 ⇒ 框架 `classes3.dex`、killer `classes4.dex`；killer 撞号会被脚本拒绝（前两个号已被官方占用）。
3. **`DEX version` 判据别带空格**：dexdump 35.0.0 输出 `DEX version '037'`，grep 写 `037`。
4. **首字不能单独判版本**：`0xF81E0FFE` / `0xFC1E0FE8` / `0xF81D0FFE` 跨版本同值 ⇒ 必须「地址 + 文件大小」双绑；size 变即降级未知。
5. **段 delta 是常量，段边界不是**：每次重算 `va−file`，禁沿用上一版 file offset（打上去会读到 `0x1400010A` 这类垃圾值，而且不报错）。
6. **入口条数会变**：判据写「+0x38 = `bl 分配器`」，不写「29 条」。
7. **取错类拿到 RVA=−1**：`DirichletRewardAdBase`(11174) 才是 concrete override。
8. **.audit 是 128+384（512 B）**，不是 96+384+32；480 B 那条是 `.bin`。
9. **改 manifest 必触发反篡改**：manifest 的 sha256 在 `.audit` 里 ⇒ 只有 native 放过能过，killer 补签名救不了。
10. **modern 分支**：`targetSdk 35` + SDK_INT>27 ⇒ `VerifyCurrentSigner` 读 `signingInfo.getApkContentsSigners()`，**不是** `PackageInfo.signatures`；只回灌 signatures 的 killer 在这里必 false。
11. **别把 `ExitModifiedPackage` 改 no-op 当修好**：协程会直接结束，`GameManagerMono::Init` 不跑，停在加载页。
12. **`ItemSaveData` 字段 32 个**：按字段序号访问会错位，一律按名。
13. **`ApplyHp` 里的 `neg` 不代表伤害取反**：IL_04BE 只服务训练假人 `reallyDmg`；curHp 路径是加法，掉血靠负 `intDmg`。
14. **热更三层都不能按名/按序号写死**：bundle 按容器路径 `Assets/Bundles/CodeHot/HotUpdate.dll.bytes` 反查（按文件名 grep 0 命中）；密钥按值 + PKCS7/`MZ` 双判据；RVA 按名取再比 codesize。
15. **组包别强改压缩方式**：so 保持底包 deflate，否则整包膨胀 70 MB 量级。
16. **路径**：apktool 的 aapt2 打不开中文目录 ⇒ 解码目录落 ASCII（组包脚本用的就是一个 ASCII 临时目录，如 `/tmp/kyzt_mf_dec`）。
17. **装机不带 `--clean` 不会走卸载链**（异签名直接 rc=1）；预检的「启动即退」在隐私页阶段是误判。
18. **首启隐私页不是故障**：`:privacy` 进程活着、页面停着，等用户点同意。
19. **禁拿模拟器结论替代真机**：雷电/Houdini 下 inline hook 可信度未验（§8）。
