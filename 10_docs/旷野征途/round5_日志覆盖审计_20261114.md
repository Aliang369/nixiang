# 第5轮 只读审计：日志覆盖与 SPI 事实更正（2026-11-14）

## 1. 实装与设备（未重新拉包）
- 设备侧 `sha256sum base.apk` 前缀 `9b0100ea217174c7` ＝ 锁包 `9b0100ea…772e`（未变化，未重新拉取）。
- 进程模型：`ps -A | grep com.xf.kyzt` → **单进程** `u0_a1140 23377`（无 `:xxx` 子进程）⇒ 不存在“多进程各自打日志”的漏采场景。

## 2. 日志覆盖（关键：证明窗口是否覆盖 Provider 注册）
- 缓冲区：`logcat -d -g` → main 16 MiB（已用 15 MiB）；`crash` 仅 4 KiB 可读。
- 按 pid 取：`adb logcat -d --pid=23377` 首行为 `--------- beginning of main`，末行 `20:25:27.667` ⇒ **覆盖了进程启动段**。
- 覆盖证据：`20:20:20.518 W StarryInitProvider`（ContentProvider.onCreate 早期日志）出现 ⇒ **Provider 注册阶段在窗口内**，不是“没覆盖所以没日志”。
- **tag 分布**（同一 pid 窗口前 12）：Unity 336、AdrenoVK-0 24、VRI 24、**StarryInitProvider 23**、DynamicFramerate 21、BLASTBufferQueue 20、**MenuService 18**、WindowOnBackDispatcher 14、**TapInitializer 14**、ExtensionsLoader 14…
  ⇒ 既有 Unity 也有 **Java/系统 tag**，**不是**“只过滤 Unity tag 漏掉 Java”的问题。

## 3. ★事实更正：SPI 并非“无证据”，是**已装载**
```
11-14 20:20:20.519 23377 23377 I GameHooks: game hook 已装载: com.starry.magic.games.kyzt.GameHookImpl
```
- 我上一轮写“SPI 无证据”是**错误的**：当时用 `-t 6000`（最近 6000 行）取窗口，该行已滑出窗口，导致漏检。
- 包内也确实编入了该类：`dex3` 字符串含 `Lcom/starry/magic/games/kyzt/GameHookImpl;`（与 dwct/dwdlm/hxwj/ncsh/wbxxm/yntt 等同类并列）。
- 因此当前事实应表述为：**SPI 已装载并打了装载日志；但未见其后续登录流程日志（如网页登录路由/TapSDK 回调处理），且 TapSDK Init 在 20:20:25 先失败（1001）**。

## 4. 与 Tap 1001 的关系（只陈述，不推断绕过）
- 时间序：20:20:20.518 Provider → 20:20:20.519 GameHooks 装载 → 20:20:24.417 TapSDK Init begin → 20:20:25.035 TapInitializer 配置错误 → 20:20:25.125 code=1001。
- 即：**SPI 早于 TapSDK Init 装载**；1001 是 TapSDK 自身对「包名+证书指纹」的判定，发生在 SPI 装载之后。
- 本审计**不**据此断言 SPI 是否应拦截 TapSDK Init（那是代码问题，需 review 读 Java 侧），只把时间序与事实列出。
