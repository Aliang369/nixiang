## 七-d、官方源码事实 vs 本地猜测（2026-11-14 18:45）

**源码事实（来源 13_scratch/kyzt22_login/source_evidence/Interpreter_Execute.cpp:1379-1391，公开 main，非目标版本）**
- `PREPARE_NEW_FRAME_FROM_INTERPRETER(newMethodInfo, argBasePtr, retPtr)` 宏体顺序固定：
  1. `imi = newMethodInfo->interpData ? (InterpMethodInfo*)newMethodInfo->interpData : InterpreterModule::GetInterpMethodInfo(newMethodInfo);`
  2. `RuntimeInitClassCCtorWithoutInitClass(newMethodInfo);`
  3. `frame = interpFrameGroup.EnterFrameFromInterpreter(newMethodInfo, argBasePtr);`
  4. `frame->ret = retPtr; ip = ipBase = imi->codes; frame->ip = (byte*)ip; localVarBase = frame->stackBasePtr;`
- ⇒ **EnterFrameFromInterpreter 是「两参 + this」**：本机 ABI 上 x0=this(interpFrameGroup)、x1=newMethodInfo、x2=argBasePtr；**没有第三参 argsPkt**。
- ⇒ 返回 `frame`，其可写字段至少含 `ret`、`ip`、`stackBasePtr`；`imi` 来自 `methodInfo->interpData`（**惰性缓存**）。
- `LEAVE_FRAME()` 对应 `interpFrameGroup.LeaveFrame()`，返回上一帧或退出求值循环。

**本地观测与该事实的对应**
- 0x1af52c0（双检锁 + 对象 +4 完成标志 + 记忆化）与 `methodInfo->interpData ?: GetInterpMethodInfo()` 的**惰性缓存语义吻合** ⇒ 该链判为 `GetInterpMethodInfo` 形态（仍属**源码语义吻合**，非符号确证）。
- 0x19c6954（写 [x0]=x1、[x0+8]=x2、[x0+0x10]=x3、[x0+0x18]=w0）**形态**像结构初始化；但源码中 EnterFrame 的返回值是由 group 内部产生，故它**不是** EnterFrameFromInterpreter，最多是「结构构造」。
- 0x1af5068 仍**只是形态**像槽位分配（未确证 AllocStackSlot）；「帧分配器在区外/内联」仍是**假设**。

**未决**
- EnterFrameFromInterpreter 的 native 实现**仍未定位**；已知判据更新为：紧跟 `GetInterpMethodInfo` 形态之后、以 (group, methodInfo, argBasePtr) 三寄存器进入、**返回 frame 指针**且随后被写 `ret/ip` 与读 `stackBasePtr` 的函数。
- 目标版本可能与公开 main 有差异（源码仅参考），故必须再用「返回帧 + 上述字段写入」在目标 so 上交叉一次。

**下一步（有界）**
1. 在 0x1b2293c 的下游/同级找「以 x0=group 传入、返回 x0=frame、随后 str 到 frame+ret/ip」的函数（用现有 funcs.txt 边界 + 定向反汇编，不邻近猜身份）。

## 七-e、战斗接入最小设计（2026-11-14 19:20，私有实现前的定稿草案）

**已证事实**
- 帧入口：`EnterFrameFromInterpreter = 0x19a9004`（file 0x19a5004），ABI `(InterpFrameGroup*, const MethodInfo*, StackObject*) -> InterpFrame*`；`InterpFrame=0x40`、`StackObject=8`（目标代码自证）；仅 0x19a903c / 0x19a9170 两处调用分配器 ⇒ 全仓仅两个帧入口。
- `ApplyHp` 签名（review IL 实证）：`ApplyHp(BattleRoleActor atker, int32 atkSeatNum, BattleDamageResult dmgInfo, Action<BattleRoleActor> OnDie)`，argc=4，this=受击者。
- 阵营来源（HotUpdate 源码切片 Battle_BattleRoleActor.cs:6228-6234）：
  `int num = (LocalSeatNum = localSeatNum); group = num;` 然后 `if (battleMode == PVP) group = BattleController.instance.GetPlayerByLocalSeatNum(localSeatNum).group;`
  ⇒ **`LocalSeatNum` 是「本客户端玩家座位」，`group` 在非 PVP 直接等于座位、PVP 走控制器换算**。玩家侧判定应基于 `LocalSeatNum == 本机座位`（或 `group` 比较），**不是**旧 1.8 的偏移。

**不采纳的两条 review 建议（lead 已指出，本文档留痕）**
- ✗ 在 EnterFrame hook 里用 RAII pin `dmgInfo`：EnterFrame 只创建 frame，返回时方法**尚未执行**，guard 早已释放 ⇒ 不能防同一 DamageResult 后续多次 ApplyHp。
- ✗ 用 `WasApplied == true` 判定重复：入口首行就 `WasApplied=false`，历史值 true 不等价「本次重复」。

**最小设计（保持 orig 先行/必调，失败关闭）**
1. 挂点仍是 **ApplyHp 入口**（精确 ns `Battle` / 类 `BattleRoleActor` / 名 `ApplyHp` / argc=4 + 参数类型校验），不在 set_curHp 全局拦截（关卡切换/复活/换血会走它）。
2. 无敌：仅在 ApplyHp **入口**判断「受击者 LocalSeatNum == 本机座位」且 `dmgInfo` 非空，则把本次伤害字段置 0（或记下并在之后恢复 HP），**只影响本次结算**；不阻断任何审计/保存。
3. 百倍：只在入口对 `dmgInfo` 的伤害字段乘一次，用 **thread_local 标记 + 对象地址**记录「本次已乘」，但**不假设跨调用有效**；实现上用「入口乘、出口恢复原值」而非 pin 阻断，避免影响后续调用。
4. 重入 guard：仅保护**我们自己的** runtime_invoke 查询（MethodInfo/FieldInfo/getter），**不能**据此跳过 orig；orig 在所有分支都调用。
5. 字段/枚举一律运行时解析：`class_from_name` 精确 ns+name（不 shortname）、`class_get_field` + `field_get_value`；不使用任何 1.8 偏移。

## 七-f、战斗合同（第三次校正，2026-11-14 19:35，review IL 实证 + 本文档复核）

**调用链事实**
- `ApplyHp` 的唯一直接调用点是闭包 `Battle.BattleRoleActor/<AddHp>b__0`（il.txt:643873-643887），由 `AddHp` 捕获 `(atker, atkSeatNum, dmgInfo, OnDie)` 后回调；`AddHp` 之前还有 `CombatDamageAudit.Observe(dmgInfo)`。
- ⇒ 倍率改写与 HP 恢复都只能发生在 **ApplyHp 自身 hook 内**（进入前改 dmg、返回后按需恢复 HP），**不能**放在 EnterFrame（它只建帧、不执行）。
- `newobj BattleDamageResult` 全 IL 16 处，未见 pool/Rent 复用 ⇒ 每次 AddHp 新建（推断；闭包实例是否复用未证）。幂等键只能用 `(dmgInfo 指针, 本次 hook 作用域)`，不能用对象存在性或 `WasApplied`（入口即被置 false）。

**无敌（保原语义，不改 dmg）**
- hook 内：`oldHp = get_curHp()` → 调 orig → `newHp = get_curHp()`；仅当 `newHp < oldHp` 且目标是本机玩家 ⇒ `set_curHp(oldHp)`。
- 不改 dmg、不做全局 set_curHp 钳制（复活/换血/关卡切换都会走它）；治疗（`newHp > oldHp`）天然不受影响。

**百倍（入口一次，作用域内去重）**
- orig **之前**乘一次；`dmg <= 0`（伤害为负值约定，见下）或 `atker == null` 不乘；乘积 clamp 到 int32 可表示范围，避免 `intDmg` 的 `CeilToInt` 走 `-2.1474835E+09` 边界分支。
- pin = thread_local `unordered_set<void*>`（键 dmgInfo），RAII 在 hook 作用域释放；**不跨调用假设**。

**玩家侧判定（静态已解）**
- 首选 `role == PartyBattleRuntime.get_LocalPlayer()`（il.txt:81179/85285 直接返回本机 actor）；
- 备选 `role.get_LocalSeatNum() == BattleMgr.selfLocalSeatNum`（public 字段，il.txt:18337；官方 `IsSlefFriend` 同型比较 il.txt:18329-18342）；
- 另有 `BattleRoleMgr.Instance.player`（HotUpdate 源码 5434/7964/9520 使用）可作第三佐证。

**dmg 符号约定**
- `dmgInfo.dmg` 对伤害为**负值**（`dmg < 0f` 才进入加成/易伤等分支）；`intDmg` 是 `CeilToInt(dmg)` 的计算属性；扣血为 `curHp += intDmg`。

**未决风险（写清不掩盖）**
- 同一 dmgInfo 是否会被 AoE 多次 ApplyHp：静态未见复用证据，但未证排除；若发生，入口乘倍会叠加。缓解：pin 集合键 dmgInfo + 作用域，仅防同一次 hook 内重入，不防跨调用。
- `set_curHp` 恢复是否会触发依赖 curHp 变化的 UI/触发器：未证，需在启用观测时看日志。

**第四次校正（2026-11-14 19:50）：槽位与对象生命周期**
- argsBase 槽序（源码 Interpreter_Execute.cpp:5250-5256：`_argBasePtr = localVarBase + __argBase`，仅 `IS_CLASS_VALUE_TYPE` 才 `obj += 1`）⇒ 引用类型实例方法 slot0=this。
