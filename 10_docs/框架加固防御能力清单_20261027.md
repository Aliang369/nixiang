## I. 明确**没有**的（现状缺口，别当成已有）

1. **无反调试**：无 `ptrace` / `TracerPid` / 反 frida / 反 xposed / seccomp（框架 native 层 0 命中；唯一 `/proc/self/maps` 出现在 `Unity/Il2CppApi.h:191`，用途是读 dynsym/dynstr，与反调试无关）。
2. **无 root/模拟器检测**（框架层）。逆向者可以随意 attach、dump 内存。
3. **dex 不混淆**（`-dontobfuscate`）、无类名重写、无 dex 字符串加密 ⇒ Java 侧逻辑与字符串完全可读。
4. **无每卡密水印**（票里没有 per-buyer 标识 ⇒ 倒卖不可溯源）。
5. **无异常上报**：诱饵只打本地日志（`payload key absent -> decoy`），后台看不见谁在分发。
6. **后台无"build 黑名单/白名单"**：`build_id` 未绑进票（P2-1b 未做），`SgBuildManifest.h` 的清单未上传服务器、未接进 App。
7. **OTA 无原子槽/无回滚/无变体路由/无撤销下发**；启动不自动拉取（只有设置页手动按钮），所以要"重启才能生效"。
8. **完整性清单只覆盖 2 个游戏**（勇士之心 3 条、冒险与征途 2 条）；无限升级两条线 `integ=None` ⇒ C2/C5 记 N/A。
9. **私钥未离线**：`payload_master.txt` 与 `rsa2048.txt` 在出包机 `~/.starry-keys/` + 服务器各一份（用户 2026-10-26 定的口径），不是 HSM/冷存储。

## J. 一句话定位

现在这套是「**抬高改包分发的成本 + 可定位到包**」的防护，不是「**防提取、防调试**」：
- 强项：授权非对称（签不出票）、载荷密文＋票派生钥、诱饵静默失效、自完整性、去路标、出包门禁 C1–C9。
- 弱项：dex/so 完全不混淆、无反调试反 root、载荷最终仍在内存可 dump、无溯源水印、无异常上报、OTA 仍要重启。

> 强度属于"对**会改包重签但不会逆向 native**的人有效"；对**会逆向+调试**的人只是"多花时间"，靠诱饵让其拿不到功能代码、靠门禁保证不误发。
