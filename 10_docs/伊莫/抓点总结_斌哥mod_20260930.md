## 2. ★注入机制：劫持 xLua 的 Lua 块加载，整份替换 `Core/Common/Time.lua`

**斌哥对伊莫的改动不是 native hook 游戏逻辑**，而是把整份 Lua MOD 源码以**明文**内嵌在 `libSDKloading.so` 的 `.rodata`，运行时由 native 侧注入 xLua。

```
① DobbyHook(libdl.so 的 dlopen)            → 替换函数 @0x45890，原函数存 .bss 0x139878
② strstr(so_path, "libxlua") 命中
③ bl 0x4b5f8("libxlua", 1) → libxlua 内存基址
④ 指纹校验：*(u32*)base == 0x464c457f（ELF 魔数）
             *(u32*)(base+0x010a41a8) == 0xd103c3ff（ARM64 sub sp,sp,#0xf0）
⑤ lua_pushboolean = base + 0x01094430 → .bss 0x139828
   lua_setglobal   = base + 0x009a8ed4 → .bss 0x139830
⑥ DobbyHook(base + 0x010a41a8 = luaL_loadbuffer, 替换函数 @0x455f0, 原函数 → .bss 0x139818)
⑦ 加载钩子 @0x455f0：strlen(chunkname)==17 && strcmp(chunkname,"@Core/Common/Time")==0
   不等 → 原样转发原函数；相等 → 把 .rodata 里那段源码当 chunk 交给 Lua
```

`.rodata` 布局（两段**首尾相接**，`0xaf087+0x65f==0xaf6e6`）：

- `0xaf087..0xaf6e6`（1,631 B）= **wrapper**：`Time.lua` 的实现体 + 头部 ` AN_1 =false; AN_2 =false; AN_3 =false;`（只声明 3 个），**末尾没有 `return Time`**。
- `0xaf6e6..0xd0328`（134,210 B）= **IMO MOD 载荷**，末尾 `\n\nreturn Time`。
- `.data` 起始 `0x138000` 一条 `R_AARCH64_RELATIVE`，addend `0xaf087` ⇒ 全局指针指向 wrapper 首址。
- `AN_1\0…AN_7\0` 名字表在 `.rodata 0xd1f13..0xd1f31`（每个 5 字节），代码用 `0xd1f13 + 5*(i-1)` 寻址。
- chunkname 串 `@Core/Common/Time` @`0xd1e7a`。

**壳的日志**：tag 全是 `调试`（`.rodata 0xae988/0xae990/0xae998` 的密文 8 字节步长存放，运行时拷进 `.bss` 原地 XOR 解密；密钥 `73a9d5254bf31b` / `b15ba7735f9f1d` / `d5759533db8d93`）。命中时打 `替换成功:%s`，**把整份替换源码打进 logcat**（所以能直接看到源码行）。`.so` 里除 Lua 载荷注释外**没有任何 lua API 名字符串**，无法靠 `strings` 定位。

ELF：`LOAD1 off=0 vaddr=0`（★vaddr==file offset 无需换算）；`.text 0x408e0..0xae6fc`、`.rodata 0xae6f0..0x1159dd`、`.data 0x138000(+0xc0)`、`.bss 0x139000..0x186f30`；`.init_array` 7 项。

## 4. 六个功能的抓点（逐个）

### ① AN_1 百倍伤害 = RPC 重发

- **白名单 `DMG_OUT`**：`RPC_CS_DoActOnActorActions` / `RPC_CS_DoActOnSweepTargetsActions` / `RPC_CS_OnAbilityCollisionHitTarget` / `RPC_CS_ProjectileHitTarget`；可单独关闭项 `DMG_OUT_SWITCH = { RPC_CS_ProjectileHitTarget = "ampProjectileHit" }`。
- **包装点**：`class.Component("ClientAoiComponent")` 的方法 `serverMsg`（每个实体类各有一份独立拷贝）。`wrapServerMsg(orig)`：`name=="RPC_CS_CastAbilityOnTarget" and isMine(self)` → `_castResend=0`；命中 `dmgOutOn(name) and isMine(self)` → `resendBudget(dmgMul-1)` 次 `pcall(orig,self,name,...)`，最后 `return orig(...)`。
- **完整 wrapper 只装 4 个类**（顺序重要）：`ClientMainPlayer` / `ClientPet` / `ClientPuppet` / `ClientCreation`；其余实体类只上 `wrapTraceOnly` 只读追踪（上一版全量包装导致「技能百倍失效」，实机 traceOnly 33 个类）。取方法必须 `rawget(vt,"serverMsg") or cls.serverMsg`（退回 `__index` 拿继承那份，否则漏掉 `ClientPet` —— 而宠物才是本作主输出）。
- **安全阀 `resendBudget`**：`maxResendPerCast = 500`，每秒 tick 清一次 `_castResend` ⇒ 语义 = 每秒最多 500 个重发包（`projHit=64 × dmgMul=100 = 6400`，不限制会一瞬间上万包打死连接）。
- **为什么可行**：伤害数值 100% 服务器算（客户端连 `processInstantDmgV` 都不存在，`attrProcessFun[instant_dmg_v=402]` 恒 nil，`modifyAttrib` 直接 `return false,0`）⇒ 放大任何本地数值都是**死码**；而命中判定 100% 客户端算并上报（游戏自己的「翻滚无敌帧」就是这么实现的）⇒ **多报一次 = 服务器多算一次**。
- **①-b 投射物多段命中**：`RPC_CS_ProjectileHitTarget(self.instanceId, …)` 第一参是投射物实例 id，命中后紧跟 `RPC_CS_ProjectileDestroy`（同 id）⇒ 同颗弹重发只认第一次。**正解 = 改行为不改上报**：把我方投射物改成穿透 + 可重复命中。三个闸门（全是游戏自己的字段）：`destroyOnHit`（`@Common_Ability_Projectile_Projectile.lua:35`，置 false）、`maxHitNum`（`:767` 默认 1，上限 `ProjectileConst.MAX_PROJECTILE_HIT_COUNT_LIMIT = 64`）、`checkCanHitTarget`（`:971` `return self.hitTargetSet[hitActorId] == nil` → 直接 `return true`）。打补丁 3 个类：`Common.Ability.Projectile.Projectile` / `GameApp.Ability.ClientProjectile` / `GameApp.Ability.EditorProjectile`（LiteClass 继承缓存，三个都要各打一遍）。
- **判死**：`RPC_CS_SetHitActionTimeline` 放大已删除 —— 实测重发 100 遍无连击，服务器不按每条算伤害 ⇒ **普攻不走可放大的上报通道**。

### ③ AN_3 移速 x3

- **挂点**：`ActorCombatAttribute:getAttribRatioValue(attributeId)` `@Common_Ability_Attribute_ActorCombatAttribute.lua:576`，`attributeId == ATTR.speed_ratio_load_adjustment_v` 且 `isMine(self.entity)` → `return v * MOD.speedMul`。
- **为什么是这个 id**：它在全部 11 个 `*SpeedRatio` getter 和 6 个绝对速度 getter 的公式里**各出现恰好一次**（同文件 `:335~531`）⇒ 乘一次 = 精确 xN，覆盖走/跑/冲刺/游泳/滑翔/冲刺闪避/蹲伏。
- ☠**不要按 `speed_ratio_run_v`/`dash_v` 做白名单**（宠物冲刺是 `ratio(sprint)*ratio(load)*ratio(dash)`，会叠成 xN²）。
- 只改 getter 返回值不写属性 ⇒ 不过 `checkAttributeValue` 钳制、不污染服务器同步的 `entity.baseAttr`。
- **实测结案**：`probe:motionAttr:getRunSpeedRatio = 3`（5 条全是它，没有 `getRunSpeed`）⇒ C# 只拉倍率这一项，精确 x3，`speedMul` 不用改成 `sqrt(3)`。改完必须 `refreshSpeed()`（`me:onMotionAttrChange()` + `AICU.refreshAllSpeed(me)`）让 C# 重新拉一次缓存。

### ⑥ AN_6 跳跃瞬移 + 自动开箱/拾取

**(6-a) 自动开宝箱 / 自动拾取 —— 借游戏自己的自动交互系统**

- ☠AN_6 必须同时管住自动开箱（`tpToChest` 故意不自己开箱）。

**(6-b) 跳跃瞬移到最近宝箱（`tpToChest(pawn)`）**

- **触发点**：在 `performJump` wrapper 内、`infJump` **之前**（否则空中按跳会被无限跳吃掉）；`AN_6 and MOD.jumpToChest and not inFly`；☠`inFly` 时不接管（会抢掉 `StopFly`）。
- **用游戏自己的合法传送流程**（照抄 `@GameApp_Sandbox_LevelItem.lua:302-317`）：
  1. `pg.me:forbidPositionCheck({ Const.FORBID_POSITION_REASON.LEVEL_ITEM_INTERACT, ent.id, target })`（★报备走 `pg.me`，挪位置走 `pg.pawn`；参数是**位置数组**不是键值表）
  2. 可选 `DialogueGraphUtils.forceChangeToIdle(pawn)`（退化 `pawn.eModel:ForceChangeToState(COMP, CSC2.IDLE)`）
  3. `pawn:forceSetPosRot(target, rot, true)`（退化 `pawn:forceSetPos(target,false)`）—— ☠第三参 `instant` 只喂 `setRotation`，对位置是**死参数**
  4. `p.world:setIsSyncPosThisFrame(pawn.actorId, true)` 强制本帧上传位置
  4-b 可选浮空 `pawn:forceUngrounded(true, CONST.ForceUnGroundReasons.Ability)` + `tickFloat` 倒计时配对清除
- **坐标计算**（与 `InteractionUnitBase:getInteractPos()` `:297-345` 逐字同构）：`dir = normalize(playerPos - entPos)`（y 清零）；落点 `tx,ty,tz = ex+ux*stand, ey+up, ez+uz*stand`；朝向 `Quaternion.LookRotation(Vector3(-ux,0,-uz), Vector3.up)`。
- ☠`ent:getPosition()` 返回**共享引用** `self.posRef`（`@...ClientPosRotComponent.lua:112`）⇒ 绝不能调 `:Sub()/:Mul()` 等原地改写方法，只读 x/y/z 标量再造新的。
- **落点参数（已实机验证的边界）**：`stand=1.5 / up=0` 已验证可用（22:38 `[tpcheck] kept offset=1.0`）；`stand=0 + up=2.5`（正上方）**已证伪** → 服务器回 `1002 ERROR_POSITION_VALID` → 人被弹回原地（用户原话「瞬移过去 瞬间返回原地 说位置不行」）；`stand=0.8`（2026-09-30 按用户要求改小）**未经实机**；`jumpToChestStandMin=0.3` 硬下限。调参判据 = `[tpcheck]` 打 `kept`（成）还是 `SNAPPED-BACK`（太近，往上调 0.8→1.0→1.2，每次只改一个数）。
- **目标搜索（★22:24 实机根因修正）**：上一版搜交互 unit，而交互 unit 只在实体靠近时才创建 ⇒ 远处箱子没有 unit ⇒ 永远找不到 ⇒ 静默返回 false（用户现象「距离很近的话 跳过去 就开箱子了」）。**改成搜宝箱实体本身**：源A `pg.me:GetRangeEntsChest()`（游戏自己的宝箱追踪器，范围 110 米）；源B `pawn:entitiesInRange(range, Const.SEARCH_USR_TYPE_INTERACTOR=64, 0)`（**返回 actorId 数组**不是实体数组 → 需 `pg.getEntityByActorId` 解一次）。
- `chestEntOk(ent)` 实体级过滤返回 `true/false + 原因串`：`needItem[1] > 0` → `"cost"`；`Utils.isChest` → 再查 `ent:isChestOpened()`（`"opened"`）与 `Utils.isChestVisible(pg.me, ent)`（含 `openChestLimit` 与归属判断，`@Common_Utils_Utils.lua:8907`，`"invisible"`）。☠不调 `ent:checkCanInteract(nil)`（`ClientEnvObject` 实现会解引用 unit 参数直接崩）。
- **`_tpWatch` + `tpVerify()`**：★必须记**出发点**，否则「落地滑了两步」会被误报成 SNAPPED-BACK（上一版把 14034 开箱成功误标）。判据：`remainH<3` → 「到位 kept」；`movedH<2` → 「☠弹回原地 SNAPPED-BACK」；否则「△滑走了 DRIFTED」。

**(6-c) 强制开箱（`forceOpenChest`，默认 false）**

- `tickForceOpen()` 由 0.3 秒快定时器 + 主 tick 各兜一次，**第 2 个 tick（约 0.6 秒）才发第一次**（留时间给 C# 触发体积注册 + 人从 2.5 米落地），`forceOpenTries = 6`；直接调 `p.me:startInteract(...)` 绕过 `canInteractive` 整套客户端门。
- **价值 = 回调能拿到服务器返回码**（`1002 位置不通过` / `1026 距离不够` / `10022 开箱次数上限` / `10024 前置条件不满足` / `200143 归属者太远` / `103005 动作被锁` …）。
- ☠**强开是「位置不通过」的最大嫌疑，已关**：22:38（无强开，只走游戏自己的 `actWhenArrive`）= 开箱成功；23:09 / 23:47（加强开）= 服务器回 `1002`。结构上也说得通：强开绕掉的门里包含 `checkAirBlock`（`@GameApp_Interaction_InteractionUnitBase.lua:587`，`airBlock==1 且 pawn:FALL_ST()` 时拒交互），而强开在落地后第 2 个 tick 就发包，人还在下落 ⇒ 服务器判位置不合法。**结论：「绕客户端的门」在这里是有害的，因为那扇门不是在限制你，是在帮你等到服务器会同意的时刻**。要用需配 `jumpToChestFloat = true`。
- ☠消耗型宝箱在上游 `chestEntOk` 就被挡掉，所以强开不会抽体力。

## 5. 本作 6 个框架坑（Lua 侧实测）

1. `_G` 严格 `__newindex`（`@Core_Framework_Global.lua:105-122`）⇒ 导出开关表必须 `rawset`，且必须先声明 `AN_1..AN_6`。
2. 取模块用 `package.loaded[...]`（`local function L(name) return package.loaded[name] end`），**不用 require**（本文件加载极早，require 会造成半成品/循环依赖）。
3. `Class.Class` 实体类 `__newindex` 遇重名 key 会 `error("has repeat attr")`（`@Core_Framework_Class.lua:402-420`）⇒ 必须走 `cls.getVtbl()`(`:431`) 或先 `cls.forceAttrRepeat(cls,key)`(`:496`)；且 `rawset` 到类本体实例**看不见**（实例元表 `classType.__objMetatable.__index = vtbl`，`:303-305`）。
4. `Class.LiteClass` 继承是**读一次就 rawset 缓存进子类表**(`:739-745`) ⇒ 只改父类会被已缓存的子类屏蔽（`PawnController` → `PlayerController` 两个都要写）。
5. `Component` 方法在 `AddComponents` 时**按值拷贝**进实体类 vtbl(`:904-906`) ⇒ 改 Component 模块表对已建好的实体类零效果，必须改实体类。
6. ☠框架把 Config 里的 **RPC 参数类型表按同名 key 放到类表上**（`@Config_Config.lua:11722`），类表 rawget 优先于 `__index` ⇒ `cls[key]` 拿到的是表不是函数；**拿不到函数时必须再问一次 `cls.getVtbl()`**。

**宿主选择**：`Core.Common.Time`（1.7KB，被 373 个文件 require，启动必加载，全库只有一种 require 写法无重名副本）；`@Main.lua:40` 每帧调 `Time.getTickSecond()` ⇒ 白得启动探测器。就绪判据 = `pg.me` 与 `pg.global` 存在且 `ACA/ATTR/CONST/PC/IC/CMP` 六个模块都在 `package.loaded`。

## 8. 星空版移植建议（等原版到手后执行）

1. **不需要复刻斌哥的「替换 `Time.lua`」机制**，但可以复用同一宿主：同样注入 xLua，命中 `@Core/Common/Time` 时注入星空载荷。
2. **更稳的取地址方式**：用 dlopen 钩子拿到的 handle + `dlsym("luaL_loadbuffer")`，**不硬编码 `base + 0x010a41a8`**（壳硬编码是因为 libxlua 可能以 RTLD_LOCAL 加载，而我们有自己的 dlopen 钩子）。同理 `lua_pushboolean`/`lua_setglobal` 走 `dlsym`，不抄 `0x01094430`/`0x009a8ed4`。
3. **开关通道换星空自己的**（Java 静态数组 + `lua_setglobal`），不依赖斌哥的壳字节。
4. **移植优先级建议**：⑤无限体力（零服务器风险）→ ④无限跳跃 → ③移速 → ②无敌（5 条通道）→ ①百倍伤害（含投射物多段）→ ⑥瞬移开箱（最依赖服务器位置校验，`stand` 需实机调）。
5. **不要带**：`libtoolChecker.so`（RootBeer）；`forceOpenChest`（已证有害）；`RPC_SC_NotifyResetPositionInfo` 包装（拿不到函数）。
