## 3. 真实运行程序集获取（本轮方法论修正）

**旧判据错在哪**：3.6.0 记录里「拉 CDN `GameLogic.dll.bytes` 比 md5 ⇒ 零漂移」这条只在 CDN 文件被更新时有效。3.7.0 的 CDN 文件 `last-modified` 仍是 **2025-01-22**、md5 与 3.6.0 记录的 `7ecee205f25de60af3abec8796339994` 完全一致 —— **它是陈旧基线，不是游戏实际加载的那份**。热更逻辑改成从 Addressables/远端拉取新程序集后，旧 CDN 路径仍在但不再参与。

**现行取法（可复用）**：

1. frida 17.16.4（`01_tools/phantom-frida/ipcmodule-server-17.16.4-android-arm64`）spawn 游戏，进程名是 **`Otherworld Legends`**（不是包名）；frida 17 无 `Module.getExportByName`，用 `enumerateExports()` 自建 name→addr 表。
2. hook `System.Reflection.Assembly.Load(byte[])`（按**参数类型 `System.Byte[]` 选重载**，早期按名字选会命中 `Load(string)` 抓空）。
3. 在 `Load` 入口把 `byte[]` 长度 + 内容落盘；本次得到 `asm_0_20034048.bin`（20,034,048 B，MZ 头）→ `/tmp/GameLogic_370.dll`。
4. `ilspycmd -p` 反编译出 **6726 个 .cs**（陈旧 CDN 版只有 4680 个）—— 差异本身就是漂移证据。
5. 运行中再扫 PE 无用：`Assembly.Load(byte[])` 之后原始字节被释放，内存里只剩小 AOT 程序集，**必须 hook 加载时刻**。

## 4. 三处硬差异（本轮全部失效的根因）

| # | 表层现象 | 真程序集里的事实 | 修法 |
|---|---|---|---|
| **A** | 无敌 / 秒杀 失效 | `Character.isBlockDamage` / `_currentHealth` / `_currentShield`（Character.cs:780/807/827）在 `!hasOriginProperties` 时**转发到 `NetworkBodyOwl`**（`Character._networkBody`，字段偏移 312） | 新增 `NetOff{char_netbody,nb_block,nb_hp,nb_shield}` + `SyncNetBody()`；无敌/秒杀同时写 Character 本体与 NetworkBodyOwl 三字段 |
| **B** | 解锁全皮肤失效 | 旧法「枚举 → 值」用 `il2cpp_field_get_value_object` 取枚举字面量，**解释器类返回 null**（日志 `皮肤枚举映射 0 项 / 名字缺失=165`） | 改为直写 `_resourceDic[HeroSkin]` 内层 dict：遍历 165 个 id，`EvWrite(ev, 1, …)` 写 `_showValue/mValue/encryptKey` 三字段一致 → 日志 `皮肤重放(直写dic) ok=165 失败=0 总数=165` |
| **C** | 无限道具缺 净化之水 / 催熟剂 / 扭蛋币 | `ResourceId` 真程序集 **27 项**（含 `GachaCoin`/`Fertilizer`/`SeasonCoin`/`ESROrbUpgradeTicket`），陈旧基线只有 19 项 ⇒ 清单按旧枚举写必漏 | `kDicItems` 补 `{50,"GachaMachine202510_GachaCoinAmount"}`（扭蛋币）；`ApplyItems` 补 `_fertilizer`（催熟剂）；净化之水 = `ResourceDic[SixCycleOrb]("OrbRefineTicketCount")`（`SixCycleOrbArchive.cs:67`） |

**另一处行为差异**：`Archive.LoadResourceData`（Archive.cs:2123）用 `playerPrefs` 读出的内层 dict **整体替换** `_resourceDic[tag]`；登录/云存档同步（`ResourceDic` setter）也会整体换表 ⇒ 一次性写入会被回滚。对策：道具/皮肤重放周期 **60 s → 5 s**（`tick % 25`）。

**秒杀的第二层问题**：`LevelProcess.singleton.<AllMonster>` 在菜单/换房间时为 null 或空表，旧实现**静默 return**（前两轮日志里连一条 `ApplyOneHit` 都没有，正是「没效果」的形态）。现改为双路：主路径 `AllMonster`，兜底 `NetworkBodyOwl.netIDtoBody`（全局 `Dictionary<uint,Body>`，跨房间不丢），逐 Body 按 `Character._camp`（1=玩家侧/2=敌方）过滤，两处血量/护盾都写，且**每次调用必有节流日志**（`lp=.. allMonster(size,hit) netDict(size,hit)`，带失败码）。
