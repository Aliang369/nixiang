## 2. 本次修改与踩坑记录

1. **扫描权限位 bug**：`/proc/self/maps` 权限串是 `rw-p`，写权限是第 2 个字符，原代码检查第 3 个字符，导致所有内存扫描 0 命中。
2. **假对象崩溃**：扫描命中堆里大量假对象，改成逐对象 `SafeProbe`（信号级容错，崩一个跳过继续）。
3. **主伤害路径**：普通攻击走 `Character.GetDamage(DamageMessage)`，额外 Hook 并写 `DamageMessage.finalDamage`（运行偏移 44）。
4. **CPU 拖卡**：全量扫描 + 无条件 Hook 曾把进程 CPU 拉到 120%，游戏按钮无响应；改为开关全关时 Hook 零开销、扫描按需且低频（战斗 1s，货币 5s）。
5. **READ_LOGS 权限**：热更/SDK 每次启动会问“访问所有设备日志”，直接删 manifest 权限会导致黑屏/初始化卡死；恢复权限声明，用 root `pm grant ... READ_LOGS` + `appops set ... 116 allow` 预授权。
6. **存档污染导致二次进不去**：全量改所有 `EncryptValue` 会把冒险等级等数据改成 999999，重启后点“开始游戏”抛 `NullReferenceException`（`AdventureLevelArchive.TryUnlockOldPlayerCharacterEffectByCurrentLevel_2601`）。改为只调三个货币 setter 后，重启正常。
7. **getter Hook 无效**：`EncryptValue.GetShowValue()`、`HeroArchive.get_isUnlock` 等热更内部调用不经过 `il2cpp_runtime_invoke`，Hook 拦不到；最终货币走 setter，解锁走 setter+回退直写。
8. **启动解析时序**：libil2cpp 刚加载时调用 `il2cpp_domain_get` 会 SIGSEGV（Main.cpp:273），解析改为 `SafeProbe` + 每 2s 重试 + 初始等待 2s。
9. **Android.mk 去 strip**：为符号定位临时去掉 `-s`/`--strip-all`（最终 APK 仍会被 AGP strip），保留 obj/local 符号版本便于回溯。

## 3. 关键偏移与方法

- 运行偏移：`Character.body=72 camp=68 hp=484 shield=488 block=360`；`HeroArchive name=24 unlock=40 exp=44`；`DamageMessage.finalDamage=44`。
- HybridCLR 热更字段偏移 = `il2cpp_field_get_offset + 8`；对象定位 = 匿名 rw- 映射中 klass 指针槽 - 8。
- Hook 方法：`GetDamage(1)`、`GetHealthDamage(2)`、`GetShieldDamage(2)`、`GetHujuDamage(3)`、`set_SoulStoneCount/BlueStoneCount/RedStoneCount(1)`、`set_isUnlock(1)`。
