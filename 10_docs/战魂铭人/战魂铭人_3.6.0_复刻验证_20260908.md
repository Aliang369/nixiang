## 5. 3.6.0 修复记录（相对 3.5.0 复刻版的增量）

### 5.1 重开闪退 SIGABRT（根因修复，ZhmrMod.cpp）

- 现象：首启正常、重开 4s 内 UnityMain 在 `il2cpp_init+28` SIGABRT（DropBox `data_app_native_crash` 三次同型：13:36/14:01/14:08；mod 自写 tombstone_00–02）
- 根因：mod 线程先于 libil2cpp 加载创建，Boehm GC 线程表无登记；重开会话 `il2cpp_init` 变慢，mod Tick 首探在 init 中途触碰 il2cpp API → GC 扫到未知线程 abort（断言 "Collecting from unknown thread"）
- 修复：Dobby 挂引擎函数 `il2cpp_init`（非游戏逻辑函数），原函数返回后才放行本线程 attach+探测；挂钩失败退化为 10s 盲等兜底；与既有两阶段 `g_classesSettled`（类齐先缓存 → 2s 后读偏移）组合
- 边界说明：闪退与悬浮窗权限/菜单入口无关（Java 菜单层当日 DropBox `data_app_crash` 为 0）

### 5.2 僵尸悬浮球（MenuService.java）

- 现象：游戏进程崩溃后，系统按 `START_STICKY` 复活一个只有菜单壳的服务进程（pid 21740 从 14:08:32 存活至装机），悬浮球+公告持续显示
- 修复：`onStartCommand` 返回 `START_NOT_STICKY`；游戏进程死亡后服务不重建

### 5.3 公告错峰（NativeMenuController.java）

- 需求：远程公告、startup toast、悬浮球不再同屏叠出
- 实现：有公告时 toast（gate/startup 两类）挂起、悬浮球 `setVisible(false)` 视觉收起（挂载状态保留）；全部公告关闭后按原节奏补放 toast 并恢复悬浮球
- 释放点覆盖：公告正常关闭 / 公告降级 toast / 公告全被 once_device 过滤（幂等，不卡死）
- 堵复活路径：`show()` 挂载出口、heartbeat 的 re-addView-after-hide、Activity 切换 full reattach、OVERLAY 模式 reattach——公告期间重挂后立即收起
- 无公告时行为与旧版完全一致

### 5.4 附带审查（外部用户反馈"无悬浮窗权限入口偶发闪退"）

- 逐点核对悬浮球/toast/公告全部 12 处窗口操作（addView/removeView/updateViewLayout）：均有 try-catch，高风点带 token 失效自动重挂
- JNI 回调仅 ShowToast 一处，Java 侧 mainHandler.post 化，线程安全
- 未发现可致进程闪退的未防护点；反馈闪退判定为旧包 il2cpp 崩溃误归因（详见 5.1）
