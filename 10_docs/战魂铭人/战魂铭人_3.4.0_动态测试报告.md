# 战魂铭人 3.4.0 动态测试报告（真机）

> 日期：2026-08-06
> 设备：OPD2404（Android 16，已 root）/ frida-server 17.16.4（root）
> 热更版本：3.4.0.7（运行中 GameLogic.dll 与 CDN 2025-01-22 版本不同）
> 测试账号：13778037848（TapTap 渠道）

## 1. 确认可利用的漏洞（动态实证）

### 1.1 货币修改（魂石/蓝石/红石） — 已确认
- 载体：`EncryptValue`（`_showValue` / `mValue` / `encryptKey`，XOR 混淆）。
- 运行版真实字段偏移（对象头 24 字节）：
  - `_showValue @ +0x18`
  - `mValue @ +0x1C`
  - `encryptKey @ +0x20`
- 操作：堆扫描定位 108 个 `EncryptValue` 对象，同步写三字段并保持 `show == mval ^ key`。
- 结果：商店顶栏三种货币全部显示 `999999`，游戏未退出。
- 反作弊：`IsLegal()` 只校验三字段 XOR 一致；非原子写入（逐字段写）会触发
  “检测到作弊行为”并 `Application.Quit()`（本次测试中已通过 hook `Application.Quit` 拦截观察）。
- 结论：XOR“加密”可被内存修改绕过；正式包改法应 patch `EncryptValue.SetValue` IL 直接放行。

### 1.2 免支付购买（伪造支付成功回调） — 已确认
- 路径：Java `PingXXPayAgent.sendPaySuccess(orderId, productId, "")` → Unity `recvPaySuccess`
  → C# `IapProductIdEx.OnPurchasesSuccess(productId)` 按商品 ID 直接发奖。
- 操作：Frida 调用 `sendPaySuccess('frida_order_2','zhmr_jew_soulstone_988','')`。
- 证据：
  - logcat：`Unity: sendPaySuccess : frida_order_2;zhmr_jew_soulstone_988;`
  - CryptoPrefs 文件从 7KB 增长到 382KB（`Archive.SaveAll()` 被触发，账号前缀 `64580072_5493905_` 的加密键全部落盘）
  - 商店顶栏货币增加（999999 → 约 1000987，OCR 识别为 989999/1000999）
- 结论：客户端对支付成功消息无票据/签名校验，伪造回调即可入账；服务端新流程有
  `Payment.ClaimOrder` 校验，但本地发奖点信任回调字符串。

### 1.3 角色/皮肤解锁（购买回调伪造） — 已确认
- 操作：`sendPaySuccess('frida_order_hero','zhmr_hero_akaisha','')`。
- 结果：大厅角色列表出现“艾凯莎”（Akaisha），logcat 确认回调送达。
- 同一路径可解锁技能/风格/皮肤/礼包（`zhmr_heroskill_*`、`zhmr_herostyle_*`、`zhmr_heroskin_*`）。

### 1.4 无敌（主角免伤） — 已确认
- 定位：`Character` 对象，`body` 字段校验类名（`QuanhuyingBody`），主角 camp=1。
- 字段：`_currentHealth @ +484`，`_isBlockDamage @ +360`。
- 操作：`hp=999999`、`isBlockDamage=true`。
- 结果：玩家确认主角不掉血。

### 1.5 秒杀 — 已确认
- 定位：全部 camp=2 敌人（`Body` 及子类）。
- 字段：`_currentHealth @ +484`、`_currentShield @ +488`、`_isBlockDamage @ +360`。
- 操作：每 1.5s 循环把敌人 `hp=0.1 + shield=0 + block=0`（覆盖新刷怪）。
- 结果：玩家确认普通怪一碰就死，boss 也被秒杀并通关。

### 1.6 免广告（广告完成回调伪造） — 部分确认
- 定位：AOT `CoreKit.Agent.BaseAdAgent.recvAdComplete(adId)`，RVA `0x22BB134`。
- 操作：通过 `AgentHub.get_Instance → get_Ad` 拿到广告代理，调用 `recvAdComplete('reborn')`，无异常。
- 说明：广告成功回调可被直接触发；本次玩家点击广告后退出，UI 奖励弹窗未做最终确认。

### 1.7 技能 CD — 静态确认，动态未完成
- 静态：`SkillManager.TryAddSkillExecution(info, ignoreCd)` 自带 ignoreCd 参数；
  `Ive.Countdown.m_Interval=0` 即 `isCountdownOver=true`；`Character.coolDown` 是 CD 倍率。
- 动态：英雄 `Skill` 对象未能在可扫描堆区定位（热更解释器对象布局特殊），待继续。

## 2. 技术要点（HybridCLR 热更限制）

- `il2cpp_runtime_invoke` 调用带参数的热更方法会崩溃（AOT 方法正常）。
- 热更类静态字段通过 `il2cpp_field_get_value(field,NULL,...)` 拿不到（class->static_fields 为空）。
- 热更类实例字段真实偏移 = 元数据 `field_get_offset` + 8（对象头 24 字节而非 16）。
- 堆扫描 `klass 指针` 会命中大量假对象（预制体/数组/静态表），必须再做
  `Character.body → Body 子类` 等对象图校验，否则批量写会 SIGSEGV（见 `09_test/战魂铭人/20260806/combat_crash_1.md`）。

## 3. 改包路线（静态 Patch）

### AOT 层（libil2cpp.so）
- 地址：`模块基址 + script.json RVA`；文件偏移≈RVA。
- 示例：`UnityEngine.Application.Quit` RVA `0x43A3360` → ARM64 `ret`（`C0 03 5F D6`）即可永久禁止退出。
- 工具：IDA + Keypatch / 十六进制编辑器。

### 热更层（GameLogic.dll，HybridCLR）
1. 获取解密后的真实 v3.4.0.7 DLL（真机加密文件：`/sdcard/Android/data/com.chillyroom.zhmr.yw/files/bpewsmdwurww`）。
2. 用 dnlib/Mono.Cecil 改 IL：
   - `EncryptValue.SetValue/OffSetValue` → 直接返回 true；
   - `Character.GetHealthDamage` / `GetDotDamage` → `ret`（无敌）；
   - `Character.GetDamage` 对非玩家强制 `finalDamage=MAX`（秒杀）；
   - `SkillManager.TryAddSkillExecution` → `ignoreCd=true`（零 CD）；
   - `IapProductIdEx.OnPurchasesSuccess` → 全商品直接发奖（免支付/解锁）。
3. 替换真机文件并同步 `hotfixVersion` MD5，或 patch `LoadSceneLauncher` 跳过校验/直接加载本地 DLL。
