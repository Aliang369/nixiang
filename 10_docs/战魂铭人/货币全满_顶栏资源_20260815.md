# 战魂铭人 · 货币全满（商城顶栏）2026-08-15

## 结论

菜单「货币全满」除三石外，需覆盖商城顶栏票券/碎片/宠物/钥匙/净化/扭蛋。  
**禁止** `PlayerArchive.AddResource` 周期调用（会累加 → 出现 `1999999`）。只用绝对值 API。

## 路径（Frida 已验 → 已合入 `ZhmrMod.cpp`）

| UI | API |
|---|---|
| 魂石/蓝石/红石 | `set_*StoneCount` |
| 武器升级票/重生卡/催化剂/试用票 | `set_WeaponUpgradeTicket` / `set_RebornCard` / `set_Fertilizer` / `set_ProbationTicket` |
| 皮肤碎片 | `ArchiveUtility.SetResourceCount(_resourceDic, exchangeablePieces=14, "SkinPiecesCount")` + `SkinPiecesCount.set_Value` |
| 通用英雄碎片 | `HeroPieceComponent.set_HeroCommonPieceCount` + dic `"HP_HeroCommonPiece"` @14 |
| 宠物食品/玩具 | dic `"PP_FoodCount"` / `"PP_ToyCount"` @ petParadise=17 |
| 历练之钥 | dic `"BattlePassLevelKey"` @ battlePass=16 |
| 扭蛋币 | `ActivityIntegrationComponent.SetGachaCoinAmount(52/58)` + dic `GachaMachine*_GachaCoinAmount` @50 |
| 净化之水 | dic `orb_refine_ticket` / `OrbRefineTicket`（Misc/14） |
| 赛季币 | dic `"SeasonCoin"` @43 + `SeasonCoinCount.set_Value` |

## 修正（2026-08-15 续）

- 周期 `AddResource` / `SetGachaCoinAmount` 会导致显示涨到 200万+；改为 **dic EncryptValue 直写 + SetResourceCount**，ResourceId 仅开关开启时 **Sub+Add 一次**。
- 菜单拆分：**无限货币**（仅三石 9999，feat 4）/ **无限道具（高封号操作）**（其它 999，feat 5）；角色 feat 7、皮肤 feat 8。
- **皮肤稳路径**：`SetResourceCount(_resourceDic, HeroSkin=1, HeroSkinName.ToString(), 1)`，跳过默认皮；**不再**批量 `UnlockHeroSkinByAchievement`（易闪退）。模板：`zhmr_menu_template.json`。

## 封号观察（2026-08-15 晚）

- **同日复测**：清档后按当前数值（三石 9999 / 道具 999）**全开功能未再封号**。
- **早前封号**：同日清档后货币+角色+皮肤，皮肤批量闪退后设备封；用户侧更倾向当时 **数量过高（曾 999999 / 累加到 200万+）或多项同时猛开**，具体触发条件未复现，不能单归因「道具开关本身」。
- 云侧仍有 `CheckForbid`（gem/item）风险；实操建议：先货币再解锁，道具按需开，避免异常暴涨与闪退瞬间上传脏档。

## Bugfix（2026-08-15）：涨到 200万+ / 别人变负数

| 现象 | 根因 | 修复 |
|---|---|---|
| 三石涨到约 237万、钳不住 9999 | `InvokePaSetter` 误把 **boxed Int32** 传给 `il2cpp_runtime_invoke`（值类型应传 `&int32`）→ setter 实际未生效，旧大数/奖励继续堆 | 改为传 `&vv`；并 RAU 双写三石 |
| 别人开道具后变负数 | `ForceResourceIdAbs` 先 `Sub(2000000000)`：当前值较小时 **int32 下溢**，再 `Add(999)` 仍为负 | **删除** Sub+Add 路径；道具只走 setter / dic / RAU 绝对值 |
