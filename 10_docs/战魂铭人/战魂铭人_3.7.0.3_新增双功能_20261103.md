## 2. 热更程序集：本轮取法与上轮不同的两个坑

上轮记录写的是「frida hook System.Reflection.Assembly.Load(byte[]) 落盘」。**这一版 hook 不到**（钩子装上、100 s 零调用）：

1. 加密热更包落盘在 /sdcard/Android/data/com.chillyroom.zhmr.yw/files/bpewsmdwurww（随机名、内容非 MZ），游戏解密后从内存直接进 HybridCLR，Assembly.Load 的 AOT thunk 未被走到（或发生在 hook 生效前的 <1.2 s 窗口）。
2. 上一轮 crash 与「attached 但 timeout」的根因不是游戏，是**外部线程没 attach il2cpp**：任何 class 级 API 调用都会 access violation accessing 0x135。加 il2cpp_thread_attach(il2cpp_domain_get()) 后全部正常。

**可复用的现行取法（本次实锤）**：

1. frida spawn/attach → il2cpp_thread_attach（必须第一步）。
2. Process.enumerateRanges('r--') 只扫 size ≥ 12 MB 的段 → Memory.scanSync(…, '4D 5A') → 校验 e_lfanew 处 PE 头与 SizeOfImage；本次命中 0x7630001030（SizeOfImage 20,078,592）。
3. 从该地址按 64 KB 分块 rpc 回传（尾部两块读失败先补 0，重试 5 次），得 20,078,592 B 的 PE。
4. ilspycmd -p 反编译（少数方法 Read out of bounds 属缺块影响，不影响字段定位）。

## 3. 新增功能①：无限技能

**真程序集事实**：

- Skill.<countdown>k__BackingField@120 → Ive.Countdown（class）
- Ive.Countdown 私有字段：**_m_LastFlushTime@16**（带下划线）、m_Interval@20
- isCountdownOver => NowTime >= _m_LastFlushTime + m_Interval
- Body.<skillList>k__BackingField@296（List<Skill>，**属性 backing field，没有 skillList 字段**）
- Skill.<currentUseableCount>@52、<maxUseableCount>@56

**实现**：每个 Tick（200 ms）遍历 body.skillList，把每个 Skill 的 countdown._m_LastFlushTime 写 -1e7f（CD 恒判结束），并把 currentUseableCount 补到 maxUseableCount。**不动 m_Interval**（CD 进度条 timeLeftRatio 依赖它）。

**首版为什么坏（两个字段名错误，已修）**：

| 错误 | 后果 |
|---|---|
| 写成 m_LastFlushTime（真实是 _m_LastFlushTime） | FieldOffset 返回 0 ⇒ SafeWriteF32(cd, 0, …) 直接覆盖 Countdown 对象的 **klass 指针**（会把技能对象写坏） |
| 用 skillList 当字段名 | Body 无此字段（是属性）⇒ 偏移 0 ⇒ 整段静默 return，日志里连「无限技能」一行都没有 |

现加守卫：cd_last == 0 直接跳过，不会再写坏对象。

## 4. 新增功能②：局内无限金币

- 局内金币不是 NetworkPlayer.myCoinCount（SyncVar，只有 SharedSkillFatWish 读它），也不是 BankComponent.savedCoinCount（银行存档）。
- 真实载体：GameProcess.heroRunningData.heroBackpack（Dictionary<ItemID,int>），金币 = heroBackpack[ItemID.coin_base]，coin_base = 0。
- 实现：字典条目 stride 0x10（hash@0 / next@4 / key@8 / value@0xC，hash<0 为空槽），key 命中即写 value=9999；每 5 s 重放（捡钱/买东西会改这个值）。
- 双 bias 方案（raw / raw+8）自适应，命中即锁定并打印「金币 bias 方案实证」。
