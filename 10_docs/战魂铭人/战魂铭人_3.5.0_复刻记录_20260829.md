## 5. 装机过程中实锤并修复的两个坑（重要经验）

### 5.1 首包卡加载：zip 条目名 UTF-8 flag 被改（已修）

- **现象**：星光包装机后卡死在「开始加载游戏资源」，Unity 报 `Unable to open archive file: jar:file://base.apk!/assets/aa/.../星星.png_*.bundle`（全部中文命名 bundle）。
- **根因**：原包 17421 条目**全部 flag=0**，其中 28 个中文命名条目是「UTF-8 字节但不带 UTF-8 flag」。python zipfile 重组时把名字按 cp437→UTF-8 重编码并**强设 flag=0x800**，Unity/Android zip 读取器对 flag 置位名字的解析与路径查找不一致 → 读取失败 → 资源加载死等。
- **修复**：合并脚本用 `RawNameZipInfo`（重写 `_encodeFilenameFlags`）对「无 flag 的非 ASCII 名」按原始字节写、flag 保持 0；并加全量自检断言 `raw_mismatch=0 flag_mismatch=0`。修复后 bundle 错误 0，游戏正常进标题画面。
- **推广**：所有 Unity 游戏外科组装都要做「条目名字节 + flag 全量对齐」自检（含中文资源名的游戏必踩）。

### 5.2 so_only 签名漂移（已修）

`zhmr_so_only.sh` 原先优先走 uber-apk-signer（不带 `--ks` → debug key），与已装 starry 签名不一致 → `INSTALL_FAILED_UPDATE_INCOMPATIBLE`，还把 08_output 成品签名改坏。已改为**优先 apksigner + starry keystore**（与外科包同证书 SHA-256 `83c5cc0b…`），uber 仅作无 keystore 兜底。

### 5.3 初始化日志暴露 bias 双方案（已修）

`offsets raw: body=64 camp=60 final=36 unlock=32`：战斗组（Character/DamageMessage）raw+8 才命中 3.4.0 运行值（72/68/44），存档组（HeroArchive）raw 原值命中（unlock=32）。单一全局 bias 方案会让两组互相覆盖，已拆成 `g_combatScheme` / `g_archScheme` 独立实证。

### 8.2 本次沉淀的硬结论（后续游戏直接复用）

1. **HybridCLR MethodPointer hook 无效**：Dobby 装在真函数序言上（prologue 校验通过），
   游戏全程命中=0——游戏内调用走解释器分发，不经过 MethodInfo.methodPointer。
   挂点有效性必须用「命中计数」证实，不能只看「装上了」。
2. **runtime_invoke 调热更方法从外部线程=解释器 SIGSEGV**（tombstone：#0-9 libil2cpp
   解释器，#10-12 starry 线程）。即使 il2cpp_thread_attach 之后也不要对热更方法用 invoke。
3. **单例实例禁止跨局缓存**：换角色/新开一局换 LevelProcess/Hero 实例，同 klass
   的旧指针能通过 klass 校验 → 秒杀写旧对象「没效果」（用户换角色实测实锤）。
   每秒 StaticRefField 重新解析；未 attach 时高频调用会随机崩（两局同栈实锤）。
4. **跨对象读一律 process_vm_readv 安全读**（__NR_process_vm_readv 直调）：
   区间检查挡不住映射外的指针，场景销毁期读 Hero.singleton 就是 SIGSEGV。
5. **il2cpp 字典 Entry stride 因 TValue 类型而异，禁止假设 0x18**：
   - TValue=引用类型 → 0x18（key@0x8 value@0x10）
   - TValue=bool（4+4+4+1→对齐）→ **0x10**（value@0xC）
   - TValue=大结构体（HeroSkinConfig 是 struct！）→ 实测 **0x78**
   - 通用解法：**步长自检**（key 集合全落在合理值域且互异）。
6. **值类型闭包泛型的 set_Item 直调=解释器桩=无效执行**（返回真但没写入）。
   已有条目→**原地翻转 value 字节**；缺条目→仅 ref 类型 TValue 的字典
   （如 Dictionary<string,EncryptValue>，AOT 共享实现）可用 set_Item 直调创建。
7. **派生类识别用 il2cpp_class_is_assignable_from**（本地 dlsym，不动共享 Il2CppApi）；
   Hero._body 装的是 QuanhuyingBody 等派生实例，精确类名匹配全漏。
8. **il2cpp_field_get_offset 原值即真偏移**：旧文档「+8」是旧工程堆扫描基址偏差
   （运行值 484/360 vs 原值 476/352，恒差 8）；unlock@32 与 Frida 精测一致。
9. **皮肤/技能/风格全部配置表驱动**（DataManager.HeroSkinConfigData /
   Archive.HeroBodySkillNameLibrary / HeroSkillStyleNameLibrary）——运行时枚举配置，
   禁止硬编码枚举名表（基础 CDN dll 与线上热更差 52 个皮肤）。
10. **游戏存档会重载英雄字典**：解锁/填充必须「开关开着持续重放」，不能只做一次。
11. EncryptValue 不变式自校验（_showValue==mValue^key）可安全验证偏移方案；
    3.5.0 起 IsLegal 失败会上报 ram_cheat_detected + Quit，直写必须三字段一致。
