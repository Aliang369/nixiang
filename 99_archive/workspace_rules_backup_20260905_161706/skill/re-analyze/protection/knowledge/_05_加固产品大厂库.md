## 第一部分：✅ 已实战（本工作区踩过）

### 1. 百度加固（DexProtector / Sagittarius）

- **别名**：百度壳、`libbaiduprotect.so`、`libDexHelper.so`、Sagittarius
- **特征**：`assets/baiduprotect/`、`libDexHelper.so`、StubApplication `com.baidu.protect.*`
- **手感**：标准整体加密壳；脱壳走 frida-dexdump/FART
- **本工作区记录**：`protection/baidu-shell.md`（指数）
- **状态**：✅ 分析过，重打包可绕（新增 dex 不动壳）

### 2. 腾讯 ACE / TSS（三重校验，最硬）

- **特征**：
  - ACE：`libace.so`、`ztg_net`、`..stitch`、`+-,` 切割名、扫描 frida/maps
  - TSS：`libtersafe2.so` + `libtprt.so` 多层校验（filecrc / sectionhash / HashBySyscall / 多 ABI MD5 / 段摘要表）
- **手感**：
  - 磁盘旁路全败（改了官方字节也会被内存校验抓出来）→ 校验对象是**内存**不是磁盘
  - `libtprt@0x19bc10` 段摘要表（25 条 size+CRC+tail）钉死除 `libcocos`/`libtprt` 外全部 arm64 so
  - 零 Root 冷启菜单已通（CaveBoot + xDL），但存活窗短（~2s SIGBUS / ~11s 跳过 AceSoft）
  - exit_group / _exit GOT 拦截无效 → 「拦 kill」方向死；正解是内存校验网全量测绘
- **关键教训**：
  - patch 结论（kill/exit）→ 死转/死循环
  - 让校验通过（内存槽同步官方值）唯一正解，但需全量测绘校验点
- **本工作区记录**：`ace-tss.md`、`starlight_engine.md`（雷霆战机相关文档）
- **状态**：✅ 雷霆战机，攻坚中（存活窗）

### 3. Kiwi VM + KwProtect + Q1（王国大作战）

- **特征**：
  - KwProtect：APK 字节级、MD5、lib 校验（启动完整性网）
  - Kiwi VM：`libkadp.so`（`kadp0/1/2` 资料地址签名，点密集）
  - Q1 PM 证书：终局门——Unity 起来后弹「当前游戏包不合法」
- **手感**：
  - KwProtect 完整性网测绘完（v1 全图）；「patch kill」死转实锤（K1 教训）
  - v2 签名校验绕过是恢复第一优先；kwK1 是稳定底包
  - root 原地换官方 base.apk → Unity 起，仅 Q1 弹窗 → 真门在 Q1 PM 证书
- **关键教训**：改包（官方字节保留）能过 KwProtect，但 Q1 是设备级 PM 校验 → 需 SignSpoof/设备级
- **本工作区记录**：`kwprotect.md`、`jiagu_q1_linker.md`（王国大作战前线文档）
- **状态**：✅ 王国大作战，卡 Q1（方案 A-D 待选）

### 4. 网易易盾 nesec（旧版 vs 签名绑定新版）

- **特征**：`libnesec.so`、`libprotectClass.so`、`libmobisec.so`；so 含高熵数据段
- **手感**：
  - **旧版**：签名后可正常解密 dex（九游版已过）
  - **新版（7.6.1_857）**：dex 解密密钥绑签名 → 任何重签静默退出；脱壳重建是正解
- **关键教训**：
  - 改 `application` 名（stub→真 Application）+ 换 dump 出来的 dex → 需重建无壳包
  - 二进制同源性判断（metadata 字节一致、libil2cpp 游戏区一致）→ 低风险移植初判
- **本工作区记录**：`netease_nesec.md`（无悔华夏：九游版成功 / 好游快爆版进行中）
- **状态**：✅ 无悔华夏九游版已过；✅ 好游快爆版脱壳重建半路

### 5. FairGuard + HTProtect（蜀汉传卧龙，已终止）

- **特征**：FairGuard `libfairguards.so` / 反调试；HTProtect 保护
- **手感**：
  - 游戏侧自研反篡改检测，触发后**优雅停机**（无 exit_group syscall，线程自然退出）
  - 反-反调试（`/proc/self/status` fopen hook）设计但未验证完
  - 检测代码**运行时生成**（静态不可见，写 `0x79BACE2B` 到 +0x430）
- **关键教训**：优雅停机 = seccomp/GOT 拦截 exit 全无效 → 正解是「废检测源头」而非「拦停机」
- **本工作区记录**：`fairguard.md`、`htprotect.md`（蜀汉传卧龙，项目已终止）
- **状态**：❌ 已终止（极限 + 反-反调试未解）

### 6. 乐变热更 / 热更新壳

- **特征**：`libshell.so`、热更仓库 URL、`bsdiff`/`bspatch` 相关
- **手感**：多用于热更，非强校验；过法常规（改资源/新增 dex）
- **状态**：✅ 指数简单过

### 7. 斌哥壳 / BUFF 壳

- **特征**：小众壳，轻度保护
- **手感**：专版商人打包，通常无强校验
- **状态**：✅ 已过（轻量）

## 第二部分：⚠️ 理论库（未实战，已知特征与思路）

### 12. 腾讯乐固（legu）

- **特征**：`libshella-*-*.so`、`libshellx-*-*.so`、`libtup.so`、`libexec.so`、`libBugly.so`（注意区分不是壳）
- **思路**：整体加密 + 资源加密；`libshell` 系列是关键；脱壳后常规绕
- **状态**：⚠️ 待验证

### 13. 阿里聚安全 / 阿里钱盾

- **特征**：`libsgmain.so`（聚安全）、`libsgmainbody.so`、`libsgmiddletier.so`、`libsgsecuritybody.so`
- **思路**：安全 SDK 全家桶（签名/完整性/环境检测一体）；`libsgmain` 是核心，`libsgmainbody` 是壳
- **状态**：⚠️ 待验证

### 14. DexProtector（海外，Licel 出品，与百度无关）

- **特征**：Licel 公司的独立商业产品，**和百度壳没有任何关系，别按「同名」混淆**。最大区别：**无 Stub Application**——Manifest 里 Application 仍是真实游戏类名；dex 整体 AES 加密后藏 assets/重名资源，运行时 InMemoryDexClassLoader 内存加载；配套字符串加密、API 隐藏、资源加密、自带签名/完整性/环境检测
- **识别**：没有明显壳特征所以最容易被漏判——「Application 类名正常但 jadx 里方法体几乎全空 / 类大量缺失 + assets 有大加密文件」→ 怀疑 DexProtector（Telegram 等海外大厂在用）
- **思路**：运行时内存 dump 明文 dex（本区主用路子，天然适配）；静态 patch 走不通
- **状态**：⚠️ 待验证（特征为模型知识，本区未实机命中）

### 15. VMProtect（海外）

- **特征**：so 层虚拟化而非 dex；IDA 里核心函数变成 VM 解释器
- **思路**：so VMP；**别还原，绕**（改它管不到的层）
- **状态**：⚠️ 待验证

### 16. 腾讯御安全（yu）—— 与乐固（legu）区分

> 腾讯有两条产品线，常被混：**乐固（legu）** 与 **御安全（御点/御加固）**。特征是「libshell 系列」但内部结构不同，别按 legu 打。

- **特征**：
  - 乐固：`libshella-*-*.so` / `libshellx-*-*.so`（见 §12），多为整体加密 + 资源加密
  - 御安全：`libtosprotection.so` / `libszstone.so` / `assets/7ZipLib.dat` 或带 `tos` 字样；部分版本带 `assets/ysMeta`、源码走 `com.tencent.y*`
- **区分判据**：
  - 有 `libtosprotection.so` / `libszstone.so` → 御安全，非 legu
  - 有 `libshella-*` / `libshellx-*` → 乐固
  - 两者都能有 `libBugly.so`（Bugly 不是壳，排除）
- **思路**：整体加密 + 资源加密 + 环境检测；先脱壳，环境检测点按 04 规则摸
- **状态**：⚠️ 待验证（本工作区未实机命中御安全，legu/御别判反会走错层）

### 17. ApkProtect

- **特征**：`libapkprotect.so` / `libsofixer.so` / `assets/apkprotect.dat`；部分版本脱壳还原点带 `dexprotect` 字样
- **思路**：整体加密 + 抽取；校验点多在 `libapkprotect.so` 的入口函数，重点查 native 读 `base.apk`（见 03 §1.5）
- **状态**：⚠️ 待验证

### 18. 网易云盾（cloud）—— 与易盾 nesec 区分

- **特征**：易盾＝`libnesec.so` / `libprotectClass.so` / `libmobisec.so`（§4，本工作区已实战）；云盾＝`libNetEngine.so` / `libsecexe.so`（撞梆梆名注意）/ `assets/cloudlib.dat`，签名/环境检测 SDK 全家桶更像网关
- **区分判据**：
  - `libnesec.so` → 易盾（dex 加密，签名绑定可能）
  - `libNetEngine.so` + 云端校验 / 网关类 → 云盾（偏设备+接口风控，不全在 dex）
- **思路**：云盾多为运行时/风控校验，先定位「联网校验点」再决定下不下 dex 层
- **状态**：⚠️ 待验证（本工作区只实战过易盾，云盾别按 nesec 脱壳打）
