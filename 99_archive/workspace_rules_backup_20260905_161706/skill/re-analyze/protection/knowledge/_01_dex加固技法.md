## 0. 先分清一件事：壳 ≠ 校验

- **壳**：把真实 dex 藏起来，防止你静态反编译。核心是「藏」。
- **校验**：检测 dex 是否被改 / 是否被 dump 后回灌。核心是「查」。
- 一个游戏可能只上壳（好脱）、也可能壳+校验都有（脱了还要过校验）。
- 脱壳成功 ≠ 能改。**先看有没有校验类保护**（见总纲死法分类），再决定下一步。

### 学习地图：DEX 壳三代 × 七技法

| 三代 | 加载链 | 对应技法 |
|---|---|---|
| 一代壳 | Java `DexClassLoader` 解密落盘/内存 | §1 整体加密 |
| 二代壳 | native 解密 + `InMemoryDexClassLoader` / 自定义 ClassLoader | §1 整体加密 |
| 三代壳 | native `OpenMemory` 钩子，ART 无感还原 | §1 + §4（半 VMP 化） |
| 抽取类 | 方法体存 so，运行时填回 | §2 / §3 |
| 校验类 | dex 内嵌校验和 / 外部 hash | §5 / §6 |

> 先按这张表定位「壳在哪一代、有没有校验」，再跳对应小节动手，避免上来就脱壳全量。

## 1. DEX 整体加密壳

### 特征（怎么认）
- `AndroidManifest.xml` 的 `application android:name` 指向 `StubApplication` / `com.stub.*` / 各家壳入口（`com.qihoo.util.StubApp`、`com.tencent.StubShell` 等）
- `classes.dex` 很小（几十 KB），jadx 打开只有壳代码，看不到业务
- `assets/` 下有大文件（几十 MB 的 `*.dat` / `classes.dgc` / `libjiagu.so` 同目录文件）
- 或 so 里有含大量高熵数据的自定义段（见 02 native 层）

### 动手（怎么做）
1. **首选：不改壳，绕过**。本工作区铁律：壳链完全不动，新代码放新 dex（壳本来就不加载你的新 dex 时另说，要 A/B 测）。
2. 必须改加密业务时，才脱壳：
   - frida-dexdump（先跑到目标代码被触发再 dump）
   - FART（主动调用所有方法，逼壳还原）
   - 内存搜 `dex\n035\0`（dex magic，后接版本号）
3. 脱出的 dex 通常要**修复**（见 §7 内嵌校验 + 工具链 06）

### 坑（哪里翻车）
- **加载链原生化**：二代/三代壳用 native `OpenMemory` 钩子还原 dex，frida-dexdump 依赖 ART 的 dex 加载回调，可能脱不干净 → 用内存扫 magic 兜底
- **脱完重打包**：删壳 stub 换真 dex，注意 `application` 名要从 stub 改回真 `Application` 类（无悔华夏脱壳重建就是这个动作）
- **壳里藏校验**：有些壳 stub 还承担签名/完整性校验，脱壳重打包反而触发 → 脱之前先评估壳是否绑定签名

### 状态
- ✅ 百度壳已实战（`baidu-shell.md`）
- ✅ 网易易盾 nesec 新旧版差异已实战（无悔华夏：旧版不绑签名、新版绑签名）
- ⚠️ 其余品牌整体加密壳理论，待命中转正

## 2. DEX 抽取加固

### 特征（怎么认）
- jadx 打开方法体是 `nop` / `return 0` / 或被替换成 `throw`
- 关键方法（尤其是核心逻辑）体被抽走，只有壳调用 `NativeHijack.B` / invoke 之类
- `class_data` 里 code_item offset 指向同一个空壳方法

### 动手（怎么做）
1. **FART**（主动调用）：逐个 invoke 所有方法，触发壳把真实指令填回，再 dump
2. **frida-dexdump** 在方法执行后 dump（覆盖率高但漏不被调用的方法）
3. dump 出的 dex 是"半修复"态：部分方法体已填回、部分还是空 → **必须修复**

### 坑（哪里翻车）
- **修复不全**：dump 回的 dex `class_def` / 方法偏移被抹，直接反编译会出现方法体错乱、交叉引用断 → 用 dexfixer 之类补偏移
- **不可逆抽取**：有些壳根本不把指令存 dex 里，而是运行时解释器执行（半 VMP），dump 也 dump 不回 → 升级为 §4 虚拟化处理

### 状态
- ⚠️ 理论 + 工具链准备，未在本工作区实机命中完整抽取壳

## 3. 函数级抽取 + VMP 混合

### 特征
- 大部分方法正常，只有**核心/收费/战斗结算**几个函数被抽取或虚拟化
- jadx 里这些函数体是壳调用或空
- 常见于爱加密/梆梆的企业版

### 动手
- 正常方法用常规 dump 覆盖
- 被抽取/虚拟化的少个函数：**别还原逻辑，改它管不到的层**（数值落地、UI 显示、出分路径）——这是本工作区「借玩法不借壳」原则
- 万不得已 pahole：动态 hook 函数输入输出，抓行为做黑盒替代

### 坑
- 函数级保护分散，patch 一个触发另一个校验 → 先 A/B 定性它属于「抽取」还是「抽取+校验」

### 状态
- ⚠️ 待验证

## 4. DEX 虚拟化 VMP

### 特征
- 关键方法转自定义字节码，运行时由 VM 解释器执行
- jadx 里这些方法体是 `call VM入口`，静态逻辑全失
- 动态堆栈全是解释器帧（大量 `switch(programCounter)` 循环）

### 动手（怎么做）
- **永远别试图还原 VM 字节码语义**——王国大作战 VM 字节码 dump 已证是坑（代价巨大、产出低）
- 正解是**绕过去**：找到 VM 管不到的层——数值落地、网络包、UI 更新、外部 SDK 回调，在这些层 hook
- 实在要定位 VM 行为：hook 解释器入口抓输入/输出，做黑盒

### 坑
- 还原 VM = 掉进时间黑洞；patch 解释器 = 大概率触发完整性校验
- 王国大作战实锤：kadp VM `ret=0` 之后读签名，patch VM 簇全 FAIL

### 状态
- ✅ Kiwi VM / kadp `libkadp.so` 已实战（王国大作战，见 `kwprotect.md`）
- ⚠️ 其他品牌 VMP 待验证

## 5. DEX 内嵌校验（壳防 dump 回灌）

### 特征
- 脱壳 dump 出来的 dex，回灌重打包后游戏启动即死
- 表现类似"被改了 dex 死"，但其实是壳在 dex 里埋了**校验和**

### 动手
- 先分清：是「dex 里埋校验和」还是「外部 native 对 dex 文件做哈希」（后者见 03 完整性）
- A/B：dump 出的 dex 原样回灌（不改）→ 若仍死，是校验和/头信息错；若活着，是后续改动触发
- 修复器补回 code_item / class_def 偏移后再回灌
- 绕过：菜单/新代码放**新 dex**（壳不校验新增），不动被校验的原 dex

### 坑
- 把「回灌 dump dex 死」误判为「脱壳失败」→ 其实是 dump 未修复 + 校验同时存在

### 状态
- ⚠️ 理论；工作中判断依据见 `dex-integrity.md`

## 6. DEX 合法性清单校验

### 特征
- 改某个 dex 死、改另一个 dex 活
- 常见：壳只对 `classes.dex`/`classes2.dex` 做哈希，新增 `classes4.dex` 不被查

### 动手
- **A/B 最小改动定位清单**（决策树 §③）：逐个改/新增 dex，二分锁定受保护名单
- 菜单代码放到**不受保护**的那个 dex
- 公主连结实锤：`classes4/8` 是安全 dex（`dex-integrity.md`）

### 坑
- 命名跳号 → ART 不加载（连续加载规则）
- 清单校验会随版本更新而变 → **换游戏/换版本必复测**（不能沿用上次结论）

### 状态
- ✅ 公主连结 classes4/8 已实战

---

## 7. DEX 连续加载规则（ART 铁律）

### 特征
- 新增 dex 命名跳号（如 `classes.dex` → `classes3.dex`）不加载
- 必须以 `classes.dex`、`classes2.dex`、`classes3.dex`... 连续编号

### 动手
- 新 dex 紧接最后一个官方 dex 编号
- 多 dex 依序排；星光菜单 dex 排最后或并入

### 坑
- 无壳包重建时，把 dump 出的多 dex 文件名排错 → 启动即 ClassNotFound（无悔华夏重建步骤里明确要求依序排）

### 状态
- ✅ 已实战（多游戏）

## 8. 完整脱壳 → 重建无壳包闭环（选做，最后手段）

> 适用：壳绑定签名密钥、或必须改壳内业务 dex（无悔华夏好游快爆版走的就是这条）。能「新增 dex 绕」就不走这条。

### 步骤
1. **dump**：frida-dexdump / FART / 内存搜 magic，拿到真体 `classes*.dex`
2. **修复**：`dexfixer` 补 `class_def` / `code_item` / 方法偏移（dump 的多是"半修复"态）
3. **验货**：jadx 打开能反编译出业务代码；pick 少量样本反编译正常才算过
4. **重建**：
   - 删壳 stub（`StubApplication` / 壳 so / 壳 assets）
   - 把真 Application 名写回 `AndroidManifest.xml`
   - 真 dex 依序排（§7 连续加载）+ 依赖 so 补齐
5. **重签**：新证书 v2+v1，直装
6. **验证**：若崩，按「改 A 崩 / 改 B 崩」二分到具体条目

### 坑
- Step 4 的 `application` 名必须从 stub 改回真 `Application`（无悔华夏重建步骤明确）
- 删壳前先评估壳是否兼完整性校验（§5）：删壳重签可能触发「非官方」弹窗
- 重建产物对应 `dex-integrity.md` 的清单校验（改 A 死改 B 活），A/B 复测清单
- 命名顺序、依赖 so、签名 v2+v1 三者缺一即 ClassNotFound / 签名失败

### 状态
- ✅ 无悔华夏九游版（整体加密壳绕壳包）
- ✅ 无悔华夏好游快爆版（脱壳重建进行中，见 `_05_加固产品大厂库.md` §4 网易易盾）
- ⚠️ Step2 修复器细节待验证（本工作区未实机命中完整修复流程）

## 总结对照卡

| 技法 | 一句话识别 | 一句话对策 | 状态 |
|---|---|---|---|
| 整体加密 | StubApplication + assets 巨文件 | 先绕壳；必改才脱壳 | ✅部分 |
| 抽取加固 | 方法体 nop/被抽 | FART + 修复 | ⚠️ |
| 函数抽取+VMP | 只核心函数被抽 | 改别的层 | ⚠️ |
| 虚拟化 VMP | 堆栈全是解释器帧 | 绕，不还原 | ✅Kiwi |
| 内嵌校验 | dump 回灌即死 | 新 dex 放新代码 | ⚠️ |
| 合法性清单 | 改 A dex 死改 B 活 | A/B 测清单 | ✅公主连结 |
| 连续加载 | 跳号不加载 | 紧接末号 | ✅ |
| 重建闭环 | 壳绑签名密钥 | dump→修复→重建无壳 | ✅部分 |
