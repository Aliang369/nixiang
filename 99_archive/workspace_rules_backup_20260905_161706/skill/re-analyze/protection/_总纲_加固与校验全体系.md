## 〇、分层思维模型（最重要，先建立）

保护不是一层，是**每一层都可能埋校验**。拿到新游戏，拆包后对着这张表把每一层过一遍，确认「有哪些层在保护」，再决定在哪层动手：

```
第 0 层  包体外层：签名(Sig v1/v2/v3)、APK 文件哈希、Zip 结构、资源 arsc
第 1 层  Java/ART 层：DEX 加密 / 抽取 / 虚拟化（壳）
第 2 层  Native/ELF 层：so 加壳 / UPX / OLLVM、so 文件哈希、注入检测、符号隐藏（剥符号 / dynsym 名字层+地址层改写）
第 3 层  脚本引擎层：Lua/JS/dll.bytes 加密（cocos jsc、xLua、HybridCLR）、IL2CPP metadata 加密（爱加密 HTPX）
第 4 层  设备环境层：Root / Frida / ptrace / Xposed / 模拟器 / 残留检测
第 5 层  服务端层：登录 token、重放校验、数值校验、反作弊上报
```

**核心认知**：一个「搞不定的加固游戏」，90% 是因为把战斗打在了错误的层。比如根本不是防你改 DEX，而是 ACE 在 native 层读 APK 哈希——apktool 重建必然死，与签名无关。**先确认是哪一层在杀你，再选武器。**

**分析总路线——拿到包先答三问，答案没落地前不动手**：
1. **谁在杀我？**（死法现象 → 按 §六 映射表反推层位和产品）
2. **它校验什么数据、数据从哪来？**（读磁盘字节 / 读内存槽 / 走系统接口 / 问服务端——用三板斧找校验点，看它 open 了什么、比对什么）
3. **这段数据我能控哪一段？**（能控 → 从 §四E 武器库选套路口；控不了 → 换层或放弃）

## 一、DEX 加固（壳）大全

> 📚 代际演进：**整体加密（一代）→ 方法抽取（二代）→ VMP/dex2c（三代）→ 混合 + native 化（四代）**。代际越高静态越死，但有一条不变：**运行时内存里一定是明文**（要执行就得解密）——dump 时机决定成败，dump 不到就等类加载/方法 attach 后再 dump。
> 📚 代际对应攻击面：一代 → 内存 dump 明文 dex（BlackDex/frida-dexdump）；二代 → FART/Youpk 主动调用补方法体；三代 → **不啃 VM**，hook 解释器入口或打出分行为层；四代（native 化）→ IDA + dynsym 自解析 + 运行时 hook 热点函数。
> 📚 三代还有 **dex2c（Java→Native 转译）**：关键方法体转译成 C++ 编进 so，dex 里只剩桩。**判定法**：FART dump 后方法体仍是空/桩 = dex2c 或 VMP（so 里是普通 native 函数 = dex2c，switch 解释循环 = VMP）。**别当抽取壳硬抽**——指令根本不在 dex 里，抽不出（时间黑洞）。解法：hook 转译函数入参/返回（转译方法与 dex 桩间仍走 JNI 调用，在 JNI 边界抓数据）或绕层打。⚠️ 本区未实机
> 📚 各家壳的 Stub 包名 / so / assets 特征速查 → `knowledge/_05_加固产品大厂库.md` §产品识别脑图（360=`libjiagu.so`、梆梆=`libDexHelper.so`、爱加密=`libexecmain.so`、乐固=`libshella-*`、易盾=`libnesec.so`、百度=`libbaiduprotect.so`）。

### 1. DEX 整体加密壳（最老最常见）
- 典型产品：梆梆(篡改)、爱加密、腾讯乐固(legu)、360 加固、网易易盾、娜迦
- 特征：Manifest Application 是 `StubApplication`；`classes.dex` 只有壳 stub；真实 dex 加密藏在 `assets/`（大文件）或 so 里
- 加载链：`attachBaseContext → 解密 → DexClassLoader / InMemoryDexClassLoader 内存加载`
- 静态：jadx 只看到壳代码
- 动态：frida-dexdump / FART 主动调用 dump
- 对策（本工作区铁律）：壳链完全不动，新增 dex 放外面；只有必须改被加密业务时才需要 dump 修复
- 状态：百度壳已实战（`baidu-shell.md`）；其余品牌 ⚠️ 待验证

### 2. DEX 抽取加固（壳 + 指令抽走）
- 典型产品：梆梆企业版、爱加密、乐固高级版、360 高级
- 特征：静态方法体是 `nop` 或只有壳调用；关键指令运行时由壳填回
- 解决：FART（主动调用）运行时 dump 完整 dex 后修复；Youpk / 蘑菇脱壳机 / frida-dexdump（内存搜 dex magic `dex\n035\0`）
- 注意：dump 出的 dex 要「修复」——补回被抹的 class_def / method 偏移，否则反编译不全
- 状态：⚠️ 待验证

### 3. DEX 虚拟化 VMP（静态最难）
- 典型产品：娜迦 VMP、乐固/爱加密 VMP、几维 Kiwi/kadp VM（已实战，见 `kwprotect.md`）
- 特征：关键方法转自定义字节码，运行时由解释器执行；静态逻辑消失、动态堆栈全是解释器帧
- 分析：只能动态黑盒（hook 解释器入口 / 抓行为）。**别试图还原 VM 字节码语义**（王国大作战 VM 字节码 dump 已证是坑）
- 解决：绕过去——不逆向 VM 里的代码，改它管不到的层（数值落地、出分路径、外部 SDK）
- 状态：Kiwi/kadp 已实战；其余 VMP ⚠️ 待验证

### 4. DEX 铁律（已实战）
- ART 连续加载：跳号不加载 → 新 dex 紧接最后一个官方 dex
- DEX 完整性清单：改某个 dex 就死 → A/B 测出受保护清单，菜单进可改的那个（`dex-integrity.md`）

### 5. 脱壳工具选择（📚 模型知识，本区未全部实机）

| 工具 | 适用壳 | 前置条件 | 备注 |
|---|---|---|---|
| 内存 dump（/proc/pid/mem） | 一切内存加载壳 | root | **本区主用**：无限升级 HTPX metadata ✅、终末地 dynsym ✅；壳无关、最通用 |
| frida-dexdump | 整体加密壳 | root + frida 存活 | 仅无反 frida 的游戏；内存搜 dex magic + 修 size |
| BlackDex | 整体加密壳 | **免 root**，Android 5~12 | 虚拟化加载自 dump；抽取壳/VMP 效果差 |
| FART / Youpk | 抽取壳（方法体 nop） | 专用 ROM | 主动调用补全方法体；dump 后需修复 class_def/method 偏移 |
| frida 内存扫 BSJB | .NET 热更 dll | root | 无限升级实锤 ✅（MZ 头被抹时以 BSJB 反查重建） |

- dump 后**必做修复**：dex header checksum/signature、被抹的 class_def；修完用 jadx 抽查冷门类完整度，别直接信 dump 结果 📚
- 新壳 InMemoryDexClassLoader 不落盘 → 磁盘路径等落盘的老方法（odex/data/app）全部失效，只能内存拿 📚
- **dump 时机**📚：壳链时序 = `attachBaseContext → ContentProvider → Application.onCreate → 首个 Activity`，dex 解密在 attachBaseContext 前后完成——窗口 = 「解密完成 + 目标类已加载」（先跑到目标页面再 dump，没加载过的类不在内存里）
- **内存 dump 手段**📚：root 下 ①`dd if=/proc/<pid>/mem`（地址从 maps 换算；`bs=4096` 别用 bs=1）②`gdb -p <pid>` + `gcore` ③自注入 so 里 `process_vm_readv`；ptrace_scope=1 会挡 dd；产物是裸段必修头（dex 修 size/校验和、metadata 修头、so 用 SoFixer 重建段表）

## 二、so 层保护

| 保护 | 特征 | 识别 | 解决 | 状态 |
|---|---|---|---|---|
| so 整体加密壳 | so 是壳骨架，真 so 运行时解密 | 静态 IDA 只有 stub；maps 有怪异映射 | 内存 dump r-x 段 / 行为替代 | ⚠️ 待验证 |
| UPX 压缩 | `strings` 见 `UPX!` 魔数 | 段名 `.UPX0/.UPX1` | `upx -d`（需原版本；magic 被魔改时先修回再 -d，或直接内存 dump 运行时镜像） | 📚 |
| OLLVM 混淆 | 控制流平坦化（大量 switch + state 变量）+ 不透明谓词 + 字符串加密；套件谱系 OLLVM/Hikari/Armariris/Pluto | IDA 看混淆循环 | D-810（IDA microcode）/ deflat（angr）解平；游戏 so 实战一般「绕」不「解」 | 📚 |
| 反调试自检 | TracerPid 自查（/proc/self/status）/ fork 子进程 ptrace 父（占坑防 attach）/ 单步陷阱（brk+SIGTRAP handler）/ 时间差 | 调试器一挂就死或行为异常 | 不调试，改运行时 hook；或 hook 文件读喂假 TracerPid=0 | 📚 |
| 内联 syscall 检测 | 不走 libc，直接 `SVC #0` 裸指令做 open/read/ptrace 检测 | libc hook 全无效但仍异常；IDA 见 SVC 指令（arm64 `01 00 00 D4`）聚集 | 消除特征源优先（根本别留 frida/su 残留），伪造读取此路不通 | 📚 |
| 字符串加密 | 静态搜不到 URL/类名/关键词，运行时才解密 | IDA 字符串窗口空、.rodata 高熵 | 运行时 dump .rodata / hook 解密函数拿明文 | 📚 |
| so dump 修复 | 内存 dump 的 so 无 section header、地址错位进不了 IDA | SoFixer / LIEF 重建 section headers + 基址归零，再进 IDA 📚 | 📚 |
| so 哈希校验 | 改 so 就死 | A/B：改一字节 so 测 | 不碰 so / patch 校验点（每次 A/B 验证） | 部分实战 |
| Anti-inline hook | so 代码段自校验 | 一改就死（雷霆战机 ACE） | 旗标门控（只改 BSS 数据区，不 inline hook） | ✅ 雷霆战机 |
| PLT/GOT hook 对抗 | 校验 GOT 表项是否被重定向 | 旗标门控不打代码；必须 hook 时等长跳板+调原函数 | ✅部分 |
| seccomp/优雅停机 | 无 exit_group 却进程终结 | 拦停机=死路；废检测源头 | ✅ 蜀汉 |
| ELF 结构死面 | 改 .dynamic/.init_array 秒杀 | ADD 新 so，不改既有 | ✅ 雷霆 |
| 符号隐藏（剥符号/dynsym 改写） | dlsym/xdl_sym 必死；readelf/IDA 读到空名；st_name=终止符偏移、st_value 大端真址 | 进程内 dynsym 自解析：PT_DYNAMIC 线性扫 + bswap32 真址 + strtab 回扫取名（详见 `ace-tss.md` 终末地案例） | ✅ 终末地 |
| .text 磁盘加密（加密岛） | 磁盘偏移处是密文，hook 装进去 = SIGILL | 运行时 dynsym 地址（垫片后仍有效）；**磁盘静态偏移一律不可用** | ✅ 终末地 |

> 全 12 块（含整体加密/UPX/OLLVM/自校验/反调试 6 技/JNI_OnLoad/环境检测/注入他杀）见 `knowledge/_02_native层保护.md`。

## 三、脚本引擎层资源加密（本工作区实战最多）

| 引擎 | 加密形态 | 解法 |
|---|---|---|
| Cocos JS `.jsc` | jsc 头 / XXTEA | 反混淆 sococos2dx + 密钥提取（雷霆：官方 jsc XXTEA） |
| xLua `.bundle` | 可自定义 | `re-extract/xlua-from-scratch.md` |
| HybridCLR `dll.bytes` | 可自定义 | 运行时 dump 解密后 dll（战魂铭人/魂坠深境） |
| Unity `global-metadata.dat` | 明文 / 自定义加密（爱加密 HTPX：仅头 8 字节水印，主体明文） | 运行时 `/proc/pid/mem` dump mmap 段拿明文 metadata，修头后 Il2CppDumper 可读；热更 dll 堆搜 BSJB 重建（MZ 头被 Obfuz 抹时以 BSJB 反查 PE 头） ✅ 无限升级 |

**关键区分**：资源加密 ≠ 保护壳。它只挡静态，不挡运行时。**只要运行时蜜点（evalString / DoString / 出分路径）能 hook，资源加密就是纸老虎。**

## 四、校验点全景（死法分类学）——闪退/退/弹窗先对号

### A. 签名类校验
| 平台 | 死法 | 对策 | 工作区 |
|---|---|---|---|
| Java 层签名 | 弹「非官方正版」/闪退 | SignSpoof（attachBaseContext hook PackageInfo.CREATOR）或 MT Killer（静态块更早）；**PM 有签名缓存 → hook 时机必须早于首次查询**（ContentProvider 注入天然最早）📚 | ✅ |
| Native 层签名（libqkcheck 等） | 闪退 | IDA 找 `deal_check_fail` 入口 RET / 回灌原签 MD5 | ✅ 物质与魔法 |
| Sig v2/v3 | 安装/启动被杀 | 读取路径两分：①PM/binder 查询 → spoof 可过；②**native 自解析 base.apk 的 APK Signing Block**（EOCD 搜 `PK\x05\x06` → 中央目录偏移 → 其前 16 字节 magic `APK Sig Block 42` → ID-value 对：v2=0x7109871a / v3=0xf05368c0）→ spoof 无效，只能字节保真 📚 | ✅ 已踩坑 |
| Sig v2 digest 覆盖范围 | 搬移/追加/改条目都破 | 1MB chunk（CHUNKED_SHA256）覆盖「Signing Block 前字节 + 中央目录 + EOCD 的 CD 偏移字段」三区；自检：写脚本按结构重算 digest 与官方包比对，定位哪段字节破了 📚 | ⚠️ |
| Janus（CVE-2017-13156） | —— | v1-only 包可在 APK 头前拼字节不破 v1 签；被 v2 封堵 + 新装载器拒收，仅上古包+旧系统可用，实战价值低 📚 | ⚠️ |
| Sig v4（.idsig） | **增量安装**改包必死（fs-verity 树校验） | 装机一律全量安装，禁 `--incremental` 📚 | ⚠️ |

### B. 文件/字节完整性校验（最凶）
| 校验目标 | 死法 | 对策 | 工作区 |
|---|---|---|---|
| `base.apk` 字节级哈希 | 加一条 dex 就 ~2s 死 | **让校验通过**：官方字节原地保留，只新增不修改 | ✅ KwProtect |
| `split APK` 存在 | ~15s signal 9 | 不装 split | ✅ KwProtect |
| 指定 dex 哈希 | 改那个 dex 死 | A/B 测受保护清单，菜单放安全 dex | ✅ 公主连结 classes4/8 |
| `lib/` 已有 so 被替换 | MD5 杀 | 只新增 so，不替换既有 | ✅ KwProtect |
| `resources.arsc` | 整体替换/压缩方式错 → 死 | STORED 不压缩、字节级保留 | ✅ 公主连结 |
| Zip 结构/对齐（外科组装自伤） | 安装失败 `INSTALL_FAILED_INVALID_APK` / 起来就崩 | 重打包跑 `zipalign -p 4`；`extractNativeLibs=false` 时未压缩 so 必须 4K 对齐；Android 15 的 16KB page 机型需 16K 对齐 📚 | ⚠️ |
| APK 体积 + 黑名单路径 | 登录弹「非法登录」 | 双条件：控体积、不含黑名单文件 | ✅ 长生天机降世 |
| 官方 dex 被修改（ACE） | 改 smali 重组装 1.2s 闪退（进程起不来） | 官方 dex 原样字节保留；新代码全走运行时 hook / 新增 dex | ✅ 终末地 |

> **金银教训（KwProtect 实锤）**：`patch kill 校验失败点 = 死转`。校验失败后减少的不是 exit，是主线程自旋/自杀；正确路永远是**让校验通过**，不是 patch 掉结论。ACE 同理。

### D. 服务端/防作弊（客户端过不了）
| 校验 | 死法/损失 | 结论 |
|---|---|---|
| 服务端战斗重放 | 结算失败/封号 | 堡垒之战：伪造战斗过不了官方服 → 禁止再做 ✅ |
| 战斗数值服务端下发 | 本地改了，服务端写回不一致 | 只改「服务端同样会读的显示路径」，或放弃 |
| 反作弊 SDK 上报 | 云端分析封号 | 上报前 hook 摘字段；量级控制（`anti-ban-analysis.md`）✅ |
| 登录 token 鉴权 | 免登失效 | 长 token 永不过期 / sso 绕过 ✅ |
| 请求签名+防重放（timestamp/nonce/HMAC） | 抓包重放/伪造请求无效 | 联机流禁伪造请求（堡垒之战教训 ✅）；单机流不受影响 |
| TLS 证书锁定（pinning） | 抓包看不到明文 | okhttp pinning 可 hook 摘除；native 自实现 pin 难，抓包绕过非本区主线 📚 |
| 设备指纹/风控引擎 | 行为画像云端封号 | 客户端摘上报字段治标不治本，主线是量级控制（`anti-ban-analysis.md`）📚 |
| Play Integrity / SafetyNet / attestation | integrity token 服务端验签，本地伪造极难 | 先分「本地生成 token」（可 hook 伪造，短期有效，SDK 升级即失效）vs「Google 签发 attestation」（客户端无解 → 单机流/量级控制）；特征串 `play.core.integrity` / `attestation` / `nonce` 📚 |

### E. 对策武器库（解决办法就这五个套路；选套路口诀：先看校验读什么）

| 套路 | 原理 | 适用 | 实锤 |
|---|---|---|---|
| ① 字节保真 | 校验读**文件字节** → 官方字节原地保留，只新增不修改，外科组装 | 完整性网全家族（APK/dex/so/arsc 哈希） | ✅ KwProtect / ACE |
| ② 喂假数据 | 校验走**系统接口**读 → hook 接口喂官方值（PM 签名查询、/proc 文件、系统属性） | 签名类 / 环境检测类 | ✅ SignSpoof 回灌证书 |
| ③ 回灌官方值 | 校验比对**内存槽** → 把官方应得的哈希/CRC 同步写进校验槽（校验对象是内存不是磁盘） | 内存校验网（ACE 段摘要表类） | ✅ 雷霆（测绘进行中） |
| ④ 时机规避 | 校验有**发生时刻** → 抢在前 / 躲在后（注入早于校验：ContentProvider 早于 Application；签名缓存首次查询前装 spoof） | 有缓存或一次性的校验 | ✅ 终末地（Provider 注入 + SignSpoof 时机） |
| ⑤ 绕层打 | VM/加密/自校验层啃不动 → 改它**管不到的层**（数值落地路径、出分行为、BSS 旗标门控、外部 SDK） | VMP / OLLVM / 代码段自校验 | ✅ 雷霆（旗标门控） |

> **反面套路（默认禁用）**：patch 校验结论（kill 校验失败点 / 拦 exit / RET 掉校验函数）= 死转——KwProtect/ACE 实锤，校验失败后的处理是自旋/毒丸/多自杀点。**唯一例外**：孤立、无自校验、无状态的单点校验函数可直接 RET（libqkcheck `deal_check_fail` ✅物质与魔法）——必须先 A/B 证明它孤立再用。

> **组合使用是常态**：终末地 = ①字节保真（官方 dex 不动）+ ②喂假数据（SignSpoof）+ ④时机规避（Provider 注入）三层叠加 ✅。一个游戏往往要 2-3 个套路组合，别指望一招吃遍。

## 六、卡点排查决策树（思路错了按此救）

遇到「加固壳/校验点搞不定」，按顺序走，**每一步产出数据，不许跳**：

```
① 拆包 → 保护初判表（re-analyze/SKILL.md §3）对号 → 分出「哪些层有保护」
     静态只见壳代码 → 先脱壳再分析：内存 dump（本区主用）→ frida-dexdump → BlackDex（免root）→ FART（抽取壳）
② 判死法 → logcat（-v threadtime 全量）+ 死法分类：
     SIGBUS(哈希/清单) / SIGSEGV(我们代码) / SIGILL(磁盘偏移打进加密代码段) /
     SIGTRAP(断点/反调试自陷) / SIGSYS(seccomp RET_KILL，tombstone 有记录) / signal 9(完整性网) / 弹窗(证书/登录) /
     黑屏无信号(毒丸/优雅停机/主线程自旋) / 静默退出(签名绑密钥类) / 闪退无栈(native 校验)
③ A/B 最小改动定位：
     零改动重签 → 存活？   （基线）
     加一个 asset → 存活？
     改 classes.dex → 死？ （dex 校验）
     改 so 一字节 → 死？   （so 哈希）
     新增 so/lib → 死？    （新增容忍？）
     4-6 组做完，受保护清单就出来
④ 抓栈再看一层：root 下 kill -3 <pid> 抓 ANR trace；/data/tombstones 抓 native 栈
⑤ 结论分层：能外科就外科；能 hook 就 hook；服务器校验 → 放弃
⑥ 老规矩：同一卡点最多 2 种方法，第 2 种不行 → 更新 current.md 再问
```

**死法 → 首嫌疑 → 第一动作（分析思路的反推表，现象直接对号）**：

| 死法 | 首嫌疑层/产品 | 第一动作 |
|---|---|---|
| SIGBUS ~2s 内 | 第 0 层包体哈希（native 读 APK，ACE/KwProtect 类） | A/B 定位改了哪个字节；确认官方字节是否原样 |
| SIGILL | 磁盘偏移打进加密代码段 / 跳板错 | 停用磁盘偏移，改运行时地址（dynsym 自解析）✅终末地 |
| SIGSEGV（栈里有我们 so） | 自己的 hook 代码 | 走 code-review 边界②四条红线，别怀疑壳 |
| SIGSEGV（无我们 so 帧） | native 校验毒杀 / TP 毒杀 / 垃圾指针 | 抓 tombstone；A/B 回滚定位触发点 |
| SIGTRAP | 反调试自陷（brk 陷阱/单步）📚 | 删断点别调试，改运行时 hook |
| SIGSYS | seccomp RET_KILL（壳自装 BPF）📚 | tombstone 查触发 syscall；与优雅停机区分（后者无任何信号） |
| signal 9 | 完整性网判死 / LSPosed、残留被系统清 | 清环境残留重测；查完整性网命中项 |
| 黑屏无信号 | 毒丸 / 主线程自旋 / 优雅停机 | `kill -3 <pid>` 抓主线程栈看卡在哪📚 |
| 静默退出 | 签名绑密钥（易盾新版）/ 网关校验 | logcat 抓壳 banner → `_05` 产品库对号 |
| 弹窗 | 证书门 / 登录门 | 对应产品页（kwprotect Q1 / taptap 等） |

**校验点定位三板斧（回答「谁在杀我」的具体手法）**：
1. **静态交叉引用**📚：IDA 里拿特征常量反查引用——zip 头 `PK\x03\x04`、"APK Sig Block 42"、证书 DER 字节、哈希算法 CR 常量（MD5=`0x67452301`、SHA-256=`0x6a09e667`、CRC32 表头 `0xEDB88320`）→ 命中的函数就是校验函数
2. **动态 trace**📚：自注入 Trace 拦 `open/read`、syscall、`memcmp` → 看校验**在什么时机读什么**——被读的文件名/内存段就是校验对象
3. **二分 A/B**（即上面③）：改哪块死 = 校验哪块，受保护清单这么测出来

**防「思路是错的」四个自我审查**：
1. 是不是在打错层？（改 DEX 死 → 不一定是 DEX 内容问题，是别的层在数 DEX 哈希）
2. 是不是在 patch 结论而不是让校验通过？（KwProtect 已证明 patch kill = 死转）
3. 是不是顺着「上次成功的路」走了？（每个游戏保护栈不同，A/B 必须重做——`kwprotect.md` 已写「换游戏必复测」）
4. 是不是在硬啃密文？（运行时内存里一定有明文——metadata/dex/so/符号都逃不过加载，先 dump 再分析，别在磁盘密文上耗）📚
